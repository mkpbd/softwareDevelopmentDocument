### ১. Repository Pattern কি? (What is Repository Pattern?)

খুব সহজ ভাষায়, **Repository Pattern** হলো তোমার অ্যাপ্লিকেশনের **লজিক (Service/Controller)** এবং **ডাটাবেস (Database)** এর মাঝখানে একজন **"মধ্যস্থতাকারী" বা "Middleman"**।

আমরা সরাসরি ডাটাবেসে হাত না দিয়ে, এই রিপোজিটরির মাধ্যমে ডাটা চাইবো বা সেভ করবো।

👉 **এক লাইনে সংজ্ঞা:**
> "Repository Pattern হলো ডাটা এক্সেস করার এমন একটি লেয়ার, যা ডাটাবেসের জটিলতা লুকিয়ে রাখে এবং আমাদের কোডকে ক্লিন রাখে।"

**ডেভেলপাররা কেন এটি ব্যবহার করে?**
কোড যাতে বারবার লিখতে না হয় এবং ভবিষ্যতে যদি ডাটাবেস পরিবর্তনও হয়, যেন পুরো প্রজেক্টের কোড চেঞ্জ করতে না হয়।

### ২. কেন এটি এত গুরুত্বপূর্ণ? (Why is it Important?)

রিপোজিটরি প্যাটার্ন না থাকলে আমরা কন্ট্রোলারের ভেতরেই সরাসরি ডাটাবেস কোড লিখে ফেলতাম। এতে ৩টি বড় সমস্যা হতো:

1.  **Code Duplication:** একই কুয়েরি (যেমন: `GetAllProducts`) ৫ জায়গায় লাগলে ৫ বার লিখতে হতো।
2.  **Hard Testing:** টেস্টিংয়ের সময় আসল ডাটাবেস ছাড়া টেস্ট করা খুব কঠিন হয়ে যেতো।
3.  **Tight Coupling:** তোমার কোড ডাটাবেসের (EF Core) সাথে খুব শক্তভাবে জড়িয়ে যেতো।

**উপকারিতা:**
*   কোড ক্লিন থাকে।
*   **Unit Testing** করা পানির মতো সহজ হয়ে যায়।
*   এক জায়গায় কোড পরিবর্তন করলে সব জায়গায় ঠিক হয়ে যায়।

### ৩. বাস্তব জীবনের উদাহরণ (Real-life Analogy)

> 💊 **ফার্মেসির এনালজি:**
>
> মনে করো তুমি ওষুধ কিনতে ফার্মেসিতে গেছো।
>
> *   **তুমি (Controller/Service):** ওষুধ দরকার।
> *   **ফার্মেসির তাক/র‍্যাক (Database):** যেখানে হাজার হাজার ওষুধ আছে।
> *   **ফার্মাসিস্ট/দোকানদার (Repository):** তুমি কি নিজে গিয়ে তাকে ওষুধ খুঁজো? না! তুমি দোকানদারকে বলো, *"ভাই, নাপা দিন।"*
>
> দোকানদার জানে ওষুধটা কোন র‍্যাকের কোন তাকে রাখা আছে। সে খুঁজে এনে তোমাকে দেয়। তুমি জানো না সে কোথা থেকে আনলো, তোমার শুধু ওষুধ পেলেই হলো।
>
> এখানে **দোকানদারই হলো Repository**। সে তোমাকে ডাটাবেসের জটিলতা (কোন তাকে রাখা আছে) থেকে আড়াল করে রেখেছে।

### ৪. EF Core এর সাথে এটি কিভাবে কাজ করে?

সাধারণত আমরা সরাসরি কন্ট্রোলার থেকে `DbContext` কল করি। কিন্তু রিপোজিটরি প্যাটার্নে ফ্লো-টা এমন হয়:

**Workflow:**
`Controller/Service` ➡️ `Repository` ➡️ `DbContext` ➡️ `Database (SQL)`

1.  **Service:** রিপোজিটরিকে বলে "ডাটা দাও"।
2.  **Repository:** `DbContext` ব্যবহার করে ডাটাবেস থেকে ডাটা আনে।
3.  **Repository:** সেই ডাটা সুন্দরভাবে সার্ভিসকে ফেরত দেয়।

### ৫. কোড উদাহরণ — Generic Repository (Code Example)

আমরা এখন একটি **Generic Repository** বানাবো, যাতে বারবার একই কোড (CRUD) প্রতিটা টেবিলের জন্য লিখতে না হয়।

#### A) Base Entity (সব টেবিলের কমন প্রপার্টি)
```csharp
// সব ক্লাসের বস, সবার একটা Id থাকবেই
public class BaseEntity
{
    public int Id { get; set; }
}
```

#### B) IGenericRepository Interface (কাজের লিস্ট)
এখানে আমরা বলে দেবো আমাদের রিপোজিটরি কি কি কাজ করতে পারবে।

```csharp
using System.Linq.Expressions;

public interface IGenericRepository<T> where T : BaseEntity
{
    Task<IEnumerable<T>> GetAllAsync();
    Task<T?> GetByIdAsync(int id);
    Task AddAsync(T entity);
    Task UpdateAsync(T entity);
    Task DeleteAsync(int id);
    
    // কাস্টম সার্চের জন্য (যেমন: নাম দিয়ে খোঁজা)
    Task<IEnumerable<T>> FindAsync(Expression<Func<T, bool>> predicate);
}
```

#### C) GenericRepository Implementation (আসল কাজ)
এখানে আমরা `DbContext` ব্যবহার করে ইন্টারফেসের কাজগুলো করবো।

```csharp
using Microsoft.EntityFrameworkCore;

public class GenericRepository<T> : IGenericRepository<T> where T : BaseEntity
{
    protected readonly AppDbContext _context;
    internal DbSet<T> dbSet;

    public GenericRepository(AppDbContext context)
    {
        _context = context;
        this.dbSet = _context.Set<T>(); // ডাইনামিকালি টেবিল সেট হচ্ছে
    }

    public async Task<IEnumerable<T>> GetAllAsync()
    {
        return await dbSet.ToListAsync();
    }

    public async Task<T?> GetByIdAsync(int id)
    {
        return await dbSet.FindAsync(id);
    }

    public async Task AddAsync(T entity)
    {
        await dbSet.AddAsync(entity);
        await _context.SaveChangesAsync(); // ডাটাবেসে সেভ করা
    }

    public async Task UpdateAsync(T entity)
    {
        dbSet.Update(entity);
        await _context.SaveChangesAsync();
    }

    public async Task DeleteAsync(int id)
    {
        var entity = await dbSet.FindAsync(id);
        if (entity != null)
        {
            dbSet.Remove(entity);
            await _context.SaveChangesAsync();
        }
    }

    public async Task<IEnumerable<T>> FindAsync(System.Linq.Expressions.Expression<Func<T, bool>> predicate)
    {
        return await dbSet.Where(predicate).ToListAsync();
    }
}
```

#### D) Product Entity & Repository
এখন ধরি আমাদের `Product` নামে একটি টেবিল আছে।

```csharp
public class Product : BaseEntity
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

এর জন্য আলাদা ইন্টারফেস বানাই (যদি স্পেশাল কিছু দরকার হয়, নইলে Generic ই যথেষ্ট):

```csharp
// ১. ইন্টারফেস
public interface IProductRepository : IGenericRepository<Product>
{
    // স্পেশাল মেথড যদি লাগে
    Task<IEnumerable<Product>> GetExpensiveProductsAsync(decimal minPrice);
}

// ২. ইমপ্লিমেন্টেশন
public class ProductRepository : GenericRepository<Product>, IProductRepository
{
    public ProductRepository(AppDbContext context) : base(context)
    {
    }

    public async Task<IEnumerable<Product>> GetExpensiveProductsAsync(decimal minPrice)
    {
        return await dbSet.Where(p => p.Price > minPrice).ToListAsync();
    }
}
```

#### E) Service Layer এ ব্যবহার (Usage)
দেখো কত ক্লিন ভাবে আমরা এটি ব্যবহার করবো।

```csharp
public class ProductService
{
    private readonly IProductRepository _productRepo;

    // কনস্ট্রাক্টরে রিপোজিটরি ইনজেক্ট করছি (Dependency Injection)
    public ProductService(IProductRepository productRepo)
    {
        _productRepo = productRepo;
    }

    public async Task CreateNewProduct(string name, decimal price)
    {
        var newProduct = new Product { Name = name, Price = price };
        
        // রিপোজিটরিকে বললাম, সেভ করো
        await _productRepo.AddAsync(newProduct);
    }
    
    public async Task<IEnumerable<Product>> GetAllProducts()
    {
        return await _productRepo.GetAllAsync();
    }
}
```

#### F) Program.cs এ রেজিস্ট্রেশন (Dependency Injection)
এটা না করলে কোড রান করবে না।

```csharp
// DbContext কানেকশন (আগে থেকেই থাকে)
builder.Services.AddDbContext<AppDbContext>(options => ... );

// রিপোজিটরি রেজিস্ট্রেশন (Scoped মানে প্রতি রিকোয়েস্টে নতুন করে তৈরি হবে)
builder.Services.AddScoped(typeof(IGenericRepository<>), typeof(GenericRepository<>));
builder.Services.AddScoped<IProductRepository, ProductRepository>();
builder.Services.AddScoped<ProductService>();
```

### ৬. ছোট রিয়েল লাইফ ইউজ-কেস (Small Use-Case)

ধরো তোমার একটি ই-কমার্স সাইট আছে।

1.  **ইউজার রিকোয়েস্ট:** ইউজার `/api/products` এ হিট করলো।
2.  **Controller:** রিকোয়েস্ট রিসিভ করে `ProductService` কে কল দিলো।
3.  **Service:** `_productRepo.GetAllAsync()` কল করলো।
4.  **Repository:** ডাটাবেস থেকে সব প্রোডাক্ট এনে দিলো।
5.  **Output:** ইউজার লিস্ট দেখতে পেলো।

কোনো SQL কোডিং কন্ট্রোলারে লিখতে হলো না! 😎

### ৭. বেস্ট প্র্যাকটিস (Best Practices)

একজন সিনিয়রের পরামর্শ হিসেবে এই নিয়মগুলো মনে রাখবে:

*   ✅ **কিপ ইট ক্লিন:** রিপোজিটরির ভেতরে জটিল বিজনেস লজিক (যেমন: `if (user.IsAdmin)`) লিখবে না। রিপোজিটরির কাজ শুধুই ডাটা আনা-নেওয়া। লজিক থাকবে সার্ভিস লেয়ারে।
*   ✅ **Async/Await:** সবসময় `Task` এবং `async/await` ব্যবহার করবে, এতে অ্যাপ্লিকেশন ফাস্ট থাকে।
*   ✅ **IQueryable রিটার্ন করবে না:** রিপোজিটরি থেকে সরাসরি `IQueryable` রিটার্ন করা খারাপ প্র্যাকটিস (কারণ লজিক লিক হয়ে যায়)। `IEnumerable` বা `List` রিটার্ন করবে।
*   ✅ **নামকরণ:** ক্লাসের নাম সবসময় `Repository` দিয়ে শেষ করবে (যেমন: `UserRepository`, `OrderRepository`)।

### ৮. ফাইনাল সামারি (Summary)

আজকে আমরা যা শিখলাম:

*   📌 **Repository** হলো ডাটাবেসের বিশ্বস্ত **ম্যানেজার বা দোকানদার**।
*   📌 এটি ব্যবহার করলে কোড **ডুপ্লিকেশন কমে** এবং **টেস্টিং সহজ হয়**।
*   📌 **Generic Repository** আমাদের জীবন সহজ করে দেয় (বারবার CRUD কোড লিখতে হয় না)।
*   📌 **Service Layer** সবসময় রিপোজিটরির সাথে কথা বলবে, সরাসরি ডাটাবেসের সাথে নয়।
