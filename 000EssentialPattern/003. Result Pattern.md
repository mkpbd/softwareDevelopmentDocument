### ১. Result Pattern কি? (What is Result Pattern?)

সোজা বাংলায়, **Result Pattern** হলো মেথড থেকে ডাটা রিটার্ন করার এমন এক স্মার্ট উপায়, যা বলে দেয়—"কাজটা সফল হয়েছে কি না, আর যদি না হয়, তবে কেন হয়নি।"

👉 **এক লাইনে সংজ্ঞা:**
> "Result Pattern হলো একটি 'ম্যাজিক বক্স' বা কন্টেইনার, যার ভেতরে হয় তোমার কাঙ্ক্ষিত ডাটা থাকে (Success), অথবা কেন কাজটা হয়নি তার কারণ লেখা থাকে (Failure)।"

**আমরা কেন এটি ব্যবহার করি?**
সাধারণত মেথড ফেইল করলে আমরা `null` রিটার্ন করি অথবা `Exception` ছুঁড়ে মারি।
*   `null` রিটার্ন করলে বোঝা যায় না ডাটা নেই নাকি এরর হয়েছে।
*   `Exception` ব্যবহার করা হলো মশা মারতে কামান দাগার মতো (System heavy হয়ে যায়)।

এই সমস্যাগুলো মেটাতেই Result Pattern এর জন্ম।

### ২. সহজ ও মজাদার এনালজি (Funny Real-Life Analogy) 📦

> 🍕 **অনলাইন ফুড ডেলিভারি এনালজি:**
>
> মনে করো তুমি পিজ্জা অর্ডার করেছো।
>
> **Scenario A (Result Pattern ছাড়া):** ডেলিভারি বয় এসে তোমার মুখের ওপর দরজা বন্ধ করে চলে গেল (Null) অথবা তোমার জানালায় পাথর ছুঁড়ে মারলো (Exception)। তুমি বুঝলে না পিজ্জা শেষ, নাকি তার বাইক নষ্ট হয়েছে!
>
> **Scenario B (Result Pattern সহ):** ডেলিভারি বয় একটা **বক্স** নিয়ে এল।
> *   তুমি বক্স খুললে।
> *   হয় ভেতরে গরম পিজ্জা আছে (**Success + Data**)।
> *   অথবা ভেতরে একটা সুন্দর চিঠি আছে: *"স্যার, পিজ্জা পুড়ে গেছে, তাই আনা যায়নি"* (**Failure + Error Message**)।
>
> এখানে কোনো ধোঁয়াশা নেই। তুমি বক্স (Result Object) চেক করলেই সব ক্লিয়ার!

### ৩. ডেভেলপাররা কেন এটি এত ভালোবাসে? ❤️

১. **No More Guesswork:** মেথড কল করার পর ভাবতে হয় না `null` মানে কি। `IsSuccess` চেক করলেই কেল্লাফতে!
২. **Exception এর অপব্যবহার কমে:** ভ্যালিডেশন এরর (যেমন: পাসওয়ার্ড ছোট) এর জন্য কোড ক্র্যাশ করানোর দরকার নেই।
৩. **Clean Code:** কন্ট্রোলারে `try-catch` এর জঞ্জাল থাকে না। কোড পড়তে গল্পের মতো লাগে।

### ৪. কখন এটি ব্যবহার করবো? (Use-cases)

*   ✅ **Service Layer:** যখন ডাটাবেস থেকে কিছু আনছো বা সেভ করছো।
*   ✅ **Business Logic:** যেমন—টাকা ট্রান্সফার করার সময় ব্যালেন্স আছে কি না চেক করা।
*   ✅ **Validations:** ইউজার ইনপুট ঠিক আছে কি না দেখার জন্য।
*   ✅ **API Endpoints:** ফ্রন্টএন্ডকে সুন্দর করে স্ট্যাটাস কোড পাঠানোর জন্য।

### ৫. কোড উদাহরণ (Code Example - .NET 8 Style)

চলো আমরা শূন্য থেকে একটি Result Pattern বানাই। কোনো লাইব্রেরি লাগবে না!

#### A) Basic Result Class (Void টাইপ কাজের জন্য)
এটা ব্যবহার করবো যখন কোনো ডাটা রিটার্ন করার দরকার নেই, শুধু জানা দরকার কাজ হয়েছে কি না (যেমন: Update/Delete)।

```csharp
public class Result
{
    public bool IsSuccess { get; }
    public string Error { get; }

    // প্রাইভেট কনস্ট্রাক্টর যাতে বাইরে থেকে ভুলভাল অবজেক্ট না বানায়
    protected Result(bool isSuccess, string error)
    {
        IsSuccess = isSuccess;
        Error = error;
    }

    // কাজ সফল হলে এটা কল করবো
    public static Result Success() => new Result(true, null);

    // কাজ ফেইল করলে এটা কল করবো
    public static Result Failure(string error) => new Result(false, error);
}
```

#### B) Generic Result`<T> Class (ডাটা রিটার্ন করার জন্য)
এটা ব্যবহার করবো যখন কাজের সাথে ডাটাও ফেরত চাই (যেমন: GetUser, GetProduct)।

```csharp
public class Result<T> : Result
{
    public T Value { get; }

    private Result(bool isSuccess, T value, string error) : base(isSuccess, error)
    {
        Value = value;
    }

    // সাকসেস হলে ডাটা সহ রিটার্ন
    public static Result<T> Success(T value) => new Result<T>(true, value, null);

    // ফেইল হলে এরর সহ রিটার্ন
    public static new Result<T> Failure(string error) => new Result<T>(false, default, error);
}
```

#### C) Service Layer এ ব্যবহার (Service Usage) 🛒

ধরি, আমাদের একটি মেথড আছে যা অর্ডার প্লেস করবে।

```csharp
public class OrderService
{
    public Result<int> PlaceOrder(string productName, int quantity)
    {
        // ১. ভ্যালিডেশন লজিক
        if (string.IsNullOrWhiteSpace(productName))
        {
            // এক্সেপশন না দিয়ে সুন্দর করে ফেইল রিটার্ন করছি
            return Result<int>.Failure("Product name cannot be empty.");
        }

        if (quantity <= 0)
        {
            return Result<int>.Failure("Quantity must be at least 1.");
        }

        // ২. আসল কাজ (Business Logic)
        // ধরো ডাটাবেসে সেভ হলো এবং একটা OrderId (101) পেলো
        int newOrderId = 101; 

        // ৩. সাকসেস রিটার্ন
        return Result<int>.Success(newOrderId);
    }
}
```

#### D) Controller এ ব্যবহার (Controller Usage) 🎮

কন্ট্রোলারে কোড কত ক্লিন হয়ে যায় দেখো!

```csharp
[ApiController]
[Route("api/orders")]
public class OrderController : ControllerBase
{
    private readonly OrderService _orderService;

    public OrderController()
    {
        _orderService = new OrderService(); // DI ব্যবহার করা উচিত, এখানে সিম্পল রাখলাম
    }

    [HttpPost]
    public IActionResult CreateOrder(string product, int qty)
    {
        var result = _orderService.PlaceOrder(product, qty);

        // রেজাল্ট প্যাটার্নের আসল ম্যাজিক এখানে!
        if (result.IsSuccess)
        {
            // সফল হলে 200 OK
            return Ok(new { OrderId = result.Value, Message = "Order placed! 🎉" });
        }

        // ফেইল হলে 400 Bad Request এবং কারণটা বলে দিচ্ছি
        return BadRequest(new { Error = result.Error });
    }
}
```

### ৬. ভ্যালিডেশন উদাহরণ (Validation Example)

Result Pattern ভ্যালিডেশনের জন্য বেস্ট ফ্রেন্ড।

```csharp
public Result RegisterUser(string email, string password)
{
    if (!email.Contains("@"))
        return Result.Failure("Invalid email address ❌");

    if (password.Length < 6)
        return Result.Failure("Password is too short (min 6 chars) 🔒");

    // All good
    return Result.Success();
}
```
*খেয়াল করো:* এখানে আমরা কোনো `try-catch` ব্যবহার করিনি, ফ্লো কন্ট্রোল কত সহজ!

### ৭. Error vs Exception: কখন কোনটা? 🤔

অনেক জুনিয়র ডেভেলপার এই জায়গায় ভুল করে।

*   **Error (Result Pattern ব্যবহার করো):** যেই ভুলগুলো হওয়ার কথা বা ইউজার করতে পারে।
    *   *উদাহরণ:* "Login failed" (ভুল পাসওয়ার্ড), "Insufficient Balance" (টাকা নেই), "Product not found".
    *   *Action:* `Result.Failure("Message")` রিটার্ন করো।

*   **Exception (System Crash):** যেই ভুলগুলো হওয়ার কথা না, সিস্টেমের সমস্যা।
    *   *উদাহরণ:* Database connection failed, Server out of memory, NullReferenceException (বাগ)।
    *   *Action:* এখানে `Exception` থ্রো হতে দাও (বা গ্লোবাল এরর হ্যান্ডলারে ধরো)। Result Pattern দিয়ে ডাটাবেস ক্র্যাশ হ্যান্ডেল করার দরকার নেই।

### ৮. বেস্ট প্র্যাকটিস (Best Practices) 🌟

1.  **Immutable:** Result ক্লাসের প্রপার্টিগুলো `set` করা যাবে না (Constructor দিয়েই সব সেট হবে)। একবার রেজাল্ট তৈরি হলে তা আর বদলানো যাবে না।
2.  **Generic Name:** মেথডের নাম `GetProduct` রাখো, `GetProductResult` রাখার দরকার নেই। রিটার্ন টাইপ দেখলেই বোঝা যাবে।
3.  **Meaningful Error:** "Error occurred" লিখবে না। লিখবে "User with this email already exists" — যাতে ফ্রন্টএন্ড ডেভেলপার খুশি হয়ে যায়।
4.  **Don't Mix:** Result এর ভেতরে আবার Exception ভরো না। সিম্পল রাখো।

### ৯. ফাইনাল সামারি (Summary) 📝

চলো পুরো বিষয়টা রিভাইজ করি:

*   ✅ **Result Pattern** হলো মেথডের আউটপুট পাঠানোর একটি **স্মার্ট প্যাকেট (Container)**।
*   ✅ এটি আমাদের বলে দেয় অপারেশন **Success** নাকি **Failure**।
*   ✅ **Exception** এর ব্যবহার কমিয়ে কোডকে ফাস্ট এবং ক্লিন রাখে।
*   ✅ **Service Layer** থেকে কন্ট্রোলারে ডাটা পাঠানোর সবচেয়ে স্ট্যান্ডার্ড উপায়।
*   ✅ **Result.Success(data)** অথবা **Result.Failure("Error msg")** — জীবন সুন্দর!

এখন থেকে আর `return null` দিয়ে কনফিউশন নয়, **Result Pattern** দিয়ে প্রফেশনাল কোড লিখো! হ্যাপি কোডিং! 🚀💻
