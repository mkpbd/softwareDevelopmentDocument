
হ্যালো ফিউচার আর্কিটেক্টস! 👋 আমি তোমাদের সিনিয়র .NET আর্কিটেক্ট ভাইয়া।

আজকে আমরা এমন একটা টপিক শিখবো যেটা না জানলে তোমার বানানো API হবে **"ছিদ্রযুক্ত ছাতা"**—বৃষ্টি এলেই ইউজার ভিজে যাবে! টপিকটি হলো **Global Error Handling**। চলো, একদম সহজ বাংলায় এবং রিল্যাক্সে শিখি। ☕

### ১. Global Error Handling কি? (What is Global Error Handling?)

সহজ কথায়, তোমার পুরো অ্যাপ্লিকেশনের যেকোনো জায়গায় যদি কোড "ফেটে যায়" (Error/Exception), তবে সেটাকে **এক জায়গা থেকে** সামলানোর নামই হলো Global Error Handling।

👉 **এক লাইনে সংজ্ঞা:**
> "এটি হলো অ্যাপ্লিকেশনের **নিরাপত্তা জাল (Safety Net)**—কোথাও কোনো এরর হলে এটি ক্যাচ করে এবং ইউজারকে সুন্দর করে বলে, 'সরি ভাই, একটু সমস্যা হয়েছে', কিন্তু ভিতরের ভয়ংকর এরর মেসেজ দেখায় না।"

**কেন এটি সুপার ইম্পর্টেন্ট?**
এটা না থাকলে, কোনো এরর হলে ইউজার দেখবে এক বিশাল বিদঘুটে লেখা (Stack Trace), যা দেখে ইউজার ভয় পাবে আর হ্যাকাররা খুশি হবে (কারণ তারা ডাটাবেসের নাম জেনে যাবে!)। তাছাড়া প্রতিটা কন্ট্রোলারে হাজার হাজার `try-catch` লেখার প্যারা থেকে এটি বাঁচায়।

### ২. মজার এনালজি (Funny & Relatable Analogy) 🤣

> 🏨 **হোটেল ম্যানেজার এনালজি:**
>
> মনে করো তুমি এক ফাইভ স্টার রেস্টুরেন্টের কিচেনে শেফ (Controller)। হঠাৎ রান্না করতে গিয়ে কড়াইয়ে আগুন ধরে গেল (Exception)!
>
> **Scenario A (Error Handling ছাড়া):** তুমি দৌড়ে কাস্টমারের টেবিলে গিয়ে চিৎকার করে বললে—*"আগুন! আগুন! আমার কড়াই পুড়ে ছাই! ডাটাবেস কানেকশন লস্ট!"* কাস্টমার ভয়ে পালাবে।
>
> **Scenario B (Global Error Handling সহ):** কিচেনে আগুন লাগলে তুমি চুপচাপ **ম্যানেজারকে (Middleware)** জানাবে।
> *   ম্যানেজার কাস্টমারের কাছে যাবে।
> *   হেসে বলবে: *"স্যার, টেকনিক্যাল কারণে আপনার অর্ডারটি সার্ভ করতে একটু দেরি হচ্ছে। আমরা আন্তরিকভাবে দুঃখিত।"*
> *   কাস্টমার কিছুই বুঝলো না, কিন্তু শান্ত থাকলো।
>
> এখানে **ম্যানেজার** হলো Global Error Handler। সে ভিতরের খবর বাইরে লিক হতে দেয় না, সব সুন্দরভাবে হ্যান্ডেল করে।

### ৩. এটি কেন দরকার? (Why is it useful?)

১. **Centralized Control:** সব এরর এক জায়গায় হ্যান্ডেল হয়। হাজারটা `try-catch` লেখার দরকার নেই।
২. **Clean Code:** তোমার কন্ট্রোলার একদম পরিষ্কার থাকে, শুধু বিজনেস লজিক থাকে।
৩. **Security:** হ্যাকারদের কাছে তোমার কোডের নাড়ি-নক্ষত্র (Stack Trace) প্রকাশ পায় না।
৪. **Consistent Response:** এরর হলে সবসময় একই ফরম্যাটে (JSON) উত্তর যায়, ফ্রন্টএন্ড ডেভেলপাররা খুশি থাকে।

### ৪. .NET এ এটি করার উপায় (Techniques)

.NET এ মূলত ৩ ভাবে এটি করা যায়:
1.  **Middleware (সবচেয়ে জনপ্রিয়):** একটা কাস্টম মিডলওয়্যার যা সব রিকোয়েস্ট মনিটর করে।
2.  **UseExceptionHandler:** .NET এর বিল্ট-ইন মেথড।
3.  **IExceptionHandler (.NET 8 New Feature):** এটি নতুন এবং আরো ক্লিন উপায়।

আজ আমরা **Middleware** দিয়ে শিখবো কারণ এটি কনসেপ্ট ক্লিয়ার করার জন্য সেরা।

### ৫. কোড উদাহরণ (Full Code Example - .NET 8)

আমরা একটা কাস্টম মিডলওয়্যার বানাবো যা অ্যাপের সব এরর ধরবে।

#### A) Custom Error Handling Middleware
এই ক্লাসটি অ্যাপ্লিকেশনের "দারোয়ান" বা "ম্যানেজার" হিসেবে কাজ করবে।

```csharp
using System.Net;
using System.Text.Json;

public class ExceptionHandlingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionHandlingMiddleware> _logger;

    public ExceptionHandlingMiddleware(RequestDelegate next, ILogger<ExceptionHandlingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            // রিকোয়েস্ট কন্ট্রোলারের দিকে যেতে দাও
            await _next(context);
        }
        catch (Exception ex)
        {
            // ওহ নো! কেউ এক্সেপশন খেয়েছে! ধরা যাক তাকে।
            _logger.LogError(ex, "Something went wrong: {Message}", ex.Message);
            
            // এবার ইউজারকে সুন্দর মেসেজ পাঠাই
            await HandleExceptionAsync(context, ex);
        }
    }

    private static Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        context.Response.ContentType = "application/json";
        
        // ডিফল্ট স্ট্যাটাস কোড 500 (Internal Server Error)
        var statusCode = (int)HttpStatusCode.InternalServerError;
        var message = "An unexpected error occurred.";

        // কাস্টম এরর লজিক (Optional)
        if (exception is ArgumentException) // যেমন: ভুল আইডি দিয়েছে
        {
            statusCode = (int)HttpStatusCode.BadRequest; // 400
            message = exception.Message;
        }

        context.Response.StatusCode = statusCode;

        // স্ট্যান্ডার্ড ProblemDetails ফরম্যাট
        var response = new
        {
            status = statusCode,
            title = "Something went wrong!",
            detail = message, // প্রোডাকশনে এখানে exception.Message সরাসরি না দেওয়াই ভালো
            timestamp = DateTime.UtcNow
        };

        var jsonResponse = JsonSerializer.Serialize(response);
        return context.Response.WriteAsync(jsonResponse);
    }
}
```

#### B) Program.cs এ রেজিস্ট্রেশন
মিডলওয়্যার বানালে হবে না, পাইপলাইনে বসাতে হবে।

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// 🚨 রেজিস্ট্রেশন করতে হবে একদম শুরুতে!
// যাতে সে সবার আগে এরর ধরতে পারে।
app.UseMiddleware<ExceptionHandlingMiddleware>();

app.MapControllers();
app.Run();
```

#### C) কন্ট্রোলার থেকে Exception ছোঁড়া (Example)

```csharp
[ApiController]
[Route("api/demo")]
public class DemoController : ControllerBase
{
    [HttpGet("{id}")]
    public IActionResult GetProduct(int id)
    {
        if (id < 0)
        {
            // আমি এখানে try-catch ব্যবহার করছি না!
            // সরাসরি Exception ছুঁড়ে দিচ্ছি, Middleware এটা ধরবে।
            throw new ArgumentException("Product ID cannot be negative!");
        }

        if (id == 0)
        {
            // ধরো কোনো অজানা এরর হলো
            throw new Exception("Database connection failed!");
        }

        return Ok(new { ProductId = id, Name = "Laptop" });
    }
}
```

### ৬. প্রো টিপস (Validation & Sensitive Info)

*   **Validation:** যদি `ModelState` ইনভ্যালিড হয় (যেমন ইমেইল ফরম্যাট ভুল), .NET অটোমেটিক্যালি 400 রিটার্ন করে। কিন্তু কাস্টম লজিকের জন্য উপরের `ArgumentException` এর মতো লজিক মিডলওয়্যারে রাখা ভালো।
*   **Sensitive Info:** প্রোডাকশন এনভায়রনমেন্টে কখনো `ex.StackTrace` ইউজারের কাছে পাঠাবে না। ডেভেলপমেন্টে পাঠাতে পারো।

```csharp
// Middleware এর ভিতরে লজিক হতে পারে এমন:
var detail = _env.IsDevelopment() ? exception.StackTrace : "Internal Server Error";
```

### ৭. রিয়েল লাইফ সিনারিও (Real-life Use Case)

ধরো তোমার একটি **ব্যাংকিং অ্যাপ** আছে।
একজন ইউজার টাকা ট্রান্সফার করতে গেল, কিন্তু সার্ভারে একটা বাগ (Bug) এর কারণে কোড ক্র্যাশ করলো।

*   **Global Error Handling ছাড়া:** ইউজার দেখবে— `NullReferenceException at BankApi.Services.TransferService line 42`. হ্যাকার বুঝবে এখানে বাগ আছে।
*   **Global Error Handling সহ:** ইউজার দেখবে— `Status: 500, Message: "Something went wrong. Please try again later."`
    *   ব্যাকগ্রাউন্ডে তোমার লগে (Log) আসল এরর সেভ হয়ে থাকবে, যাতে তুমি পরে ফিক্স করতে পারো।

### ৮. বেস্ট প্র্যাকটিস (Best Practices) 🏆

১. **No Try-Catch Everywhere:** কন্ট্রোলারে বিজনেস লজিক ছাড়া `try-catch` ব্যবহার করবে না। সব নোংরা কাজ মিডলওয়্যারকে করতে দাও।
2.  **Use ProblemDetails:** এরর রেসপন্সের জন্য স্ট্যান্ডার্ড ফরম্যাট (RFC 7807) ব্যবহার করো। নিজের মতো আজগুবি ফরম্যাট বানাবে না।
3.  **Hide Secrets:** প্রোডাকশনে কখনোই আসল এরর মেসেজ বা স্ট্যাক ট্রেস ক্লায়েন্টকে দেখাবে না।
4.  **Logging:** এরর শুধু ধরলেই হবে না, `ILogger` বা `Serilog` দিয়ে সেটা ডাটাবেস বা ফাইলে সেভ করে রাখতে হবে।

### ৯. ফাইনাল সামারি (Summary) 📝

*   ✅ **Global Error Handling** হলো তোমার অ্যাপের **সিকিউরিটি গার্ড**।
*   ✅ এটি অ্যাপকে **ক্র্যাশ** হওয়া থেকে বাঁচায় না, কিন্তু ক্র্যাশ হলে **সম্মান বাঁচায়**।
*   ✅ **Middleware** ব্যবহার করে এটি ইমপ্লিমেন্ট করা সবচেয়ে সহজ।
*   ✅ এটি হ্যাকারদের থেকে সিস্টেমের গোপন তথ্য লুকিয়ে রাখে।
*   ✅ তোমার API কে করে তোলে **প্রফেশনাল এবং প্রোডাকশন রেডি**।

এখন থেকে তোমার API আর কখনো "চিৎকার" করবে না, বরং ভদ্রভাবে সমস্যা জানাবে! হ্যাপি কোডিং! 🚀💻

### ১. UseExceptionHandler (দ্য ক্লাসিক উপায়) 🏛️

এটা .NET এর বিল্ট-ইন মেথড। এটার কাজ হলো অ্যাপের কোথাও এরর হলে ট্রাফিক ঘুরিয়ে একটা স্পেশাল রাউটে (যেমন: `/error`) পাঠিয়ে দেওয়া।

> 🚑 **এনালজি:**
> মনে করো তোমার অফিসে আগুন লেগেছে (Exception)।
> *   **Custom Middleware:** তুমি নিজেই বালতি নিয়ে আগুন নেভাতে গেলে।
> *   **UseExceptionHandler:** তুমি **৯৯৯** এ কল দিলে। তারা তোমাকে একটা সেইফ জোনে (Error Controller) নিয়ে গেল এবং আগুন নেভানোর ব্যবস্থা করলো। তুমি নিজে আগুন ধরলে না।

#### কিভাবে ব্যবহার করবো?

**ধাপ ১: Program.cs এ সেটআপ**
```csharp
var app = builder.Build();

// অ্যাপকে বলো: "ভাই, কোথাও ক্র্যাশ করলে সোজা /error রাউটে পাঠিয়ে দিও।"
app.UseExceptionHandler("/error"); 

app.MapControllers();
app.Run();
```

**ধাপ ২: Error Endpoint তৈরি করা**
এখন আমাদের একটা কন্ট্রোলার বা API লাগবে যা `/error` রাউটে আসা রিকোয়েস্ট হ্যান্ডেল করবে।

```csharp
[ApiController]
public class ErrorController : ControllerBase
{
    [Route("/error")]
    [ApiExplorerSettings(IgnoreApi = true)] // সোয়াগারে দেখানোর দরকার নেই
    public IActionResult HandleError()
    {
        // ১. কি এরর হয়েছে সেটা বের করা
        var context = HttpContext.Features.Get<IExceptionHandlerFeature>();
        var exception = context?.Error; // আসল এরর এখানে আছে

        // ২. সুন্দর রেসপন্স পাঠানো
        return Problem(
            detail: exception?.Message, 
            title: "An error occurred inside the server (Classic Way)"
        );
    }
}
```
**ব্যাস!** এখন যেখানেই এরর হোক, ইউজার অটোমেটিক `/error` থেকে সুন্দর JSON রেসপন্স পাবে।

### ২. IExceptionHandler (.NET 8 এর নতুন হিরো) 🦸‍♂️

.NET 8 এ মাইক্রোসফট বললো, "কন্ট্রোলার দিয়ে এরর হ্যান্ডেল করা একটু পুরনো স্টাইল। চলো আরো মডুলার এবং ক্লিন কিছু আনি।" জন্ম হলো **`IExceptionHandler`** এর।

> 👨‍⚕️ **এনালজি (স্পেশালিস্ট ডাক্তার):**
> *   আগে একজন ডাক্তারই (Middleware/Controller) সব রোগীর চিকিৎসা করতো—জ্বর, হাড় ভাঙা, হার্ট অ্যাটাক।
> *   **IExceptionHandler** হলো স্পেশালিস্ট ডাক্তার। তুমি আলাদা আলাদা হ্যান্ডলার বানাতে পারো:
>     *   `TimeoutHandler` শুধু টাইমাউট দেখবে।
>     *   `ValidationHandler` শুধু ভ্যালিডেশন দেখবে।
>     *   `GlobalHandler` বাকি সব দেখবে।
> 
> কোড থাকে একদম ঝকঝকে! ✨

#### কিভাবে ব্যবহার করবো? (.NET 8 Style)

**ধাপ ১: হ্যান্ডলার ক্লাস তৈরি করা**
আমাদের `IExceptionHandler` ইন্টারফেস ইমপ্লিমেন্ট করতে হবে।

```csharp
using Microsoft.AspNetCore.Diagnostics;

public class GlobalExceptionHandler : IExceptionHandler
{
    private readonly ILogger<GlobalExceptionHandler> _logger;

    public GlobalExceptionHandler(ILogger<GlobalExceptionHandler> logger)
    {
        _logger = logger;
    }

    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext, 
        Exception exception, 
        CancellationToken cancellationToken)
    {
        // ১. এরর লগ করো
        _logger.LogError(exception, "Exception occurred: {Message}", exception.Message);

        // ২. রেসপন্স রেডি করো
        var problemDetails = new ProblemDetails
        {
            Status = StatusCodes.Status500InternalServerError,
            Title = "Server Error (.NET 8 Style)",
            Detail = "Something went wrong! We are fixing it."
        };

        httpContext.Response.StatusCode = problemDetails.Status.Value;

        // ৩. রেসপন্স পাঠিয়ে দাও
        await httpContext.Response.WriteAsJsonAsync(problemDetails, cancellationToken);

        // ৪. return true মানে: "আমি হ্যান্ডেল করেছি, আর কারো দেখার দরকার নেই।"
        return true; 
    }
}
```

**ধাপ ২: Program.cs এ রেজিস্টার করা**
এখানে একটু ম্যাজিক আছে। ভালো করে খেয়াল করো।

```csharp
var builder = WebApplication.CreateBuilder(args);

// ১. সার্ভিস কন্টেইনারে আমাদের হ্যান্ডলার যোগ করো
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
builder.Services.AddProblemDetails(); // এটা দরকারি ফরম্যাটের জন্য

var app = builder.Build();

// ২. পাইপলাইনে এটা চালু করো
// কোনো পাথ ("/error") দেওয়ার দরকার নেই! সে অটোমেটিক হ্যান্ডলার খুঁজে নেবে।
app.UseExceptionHandler(); 

app.MapControllers();
app.Run();
```

### 🤔 কোনটা কখন ব্যবহার করবো? (Comparison)

| বৈশিষ্ট্য | Custom Middleware | UseExceptionHandler (Classic) | IExceptionHandler (.NET 8) |
| :--- | :--- | :--- | :--- |
| **সহজতা** | একটু কোড লিখতে হয় | খুব সহজ | মাঝারি, তবে খুব ক্লিন |
| **কন্ট্রোল** | পূর্ণ নিয়ন্ত্রণ (Full Control) | আলাদা কন্ট্রোলার লাগে | সবচেয়ে বেশি মডুলার |
| **Clean Architecture** | ভালো | মোটামুটি | **সেরা (Best)** |
| **Multiple Handlers** | কঠিন (if-else দিয়ে ভরতে হয়) | কঠিন | **খুব সহজ** (চেইন করা যায়) |

### 🏆 আর্কিটেক্টের পরামর্শ (Best Practice)

তুমি যদি **.NET 8** বা তার পরের ভার্সন ব্যবহার করো, তবে চোখ বন্ধ করে **`IExceptionHandler`** ব্যবহার করো।

কেন?
1.  **Single Responsibility:** এরর হ্যান্ডলিং লজিক আলাদা ক্লাসে থাকে।
2.  **No Controller needed:** এরর হ্যান্ডেল করার জন্য আলাদা কন্ট্রোলার বানানোর দরকার নেই।
3.  **Future Proof:** মাইক্রোসফট এখন এটাই রেকমেন্ড করে।

**Example Scenario:**
তুমি চাইলে `TimeoutExceptionHandler` নামে একটা ক্লাস বানাতে পারো যেটা শুধু `TimeoutException` হ্যান্ডেল করবে, আর `GlobalExceptionHandler` বাকি সব হ্যান্ডেল করবে। `Program.cs` এ জাস্ট পর পর অ্যাড করে দিলেই হবে:

```csharp
builder.Services.AddExceptionHandler<TimeoutExceptionHandler>();
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
```

আশা করি **UseExceptionHandler** এবং **IExceptionHandler** এর পার্থক্য এখন পানির মতো পরিষ্কার! হ্যাপি কোডিং! 🚀😎
