
চমৎকার! 🤩 তুমি এখন কোডিংয়ের **"Avengers"** টিম তৈরি করতে চাচ্ছো।
১. **Repository:** (The Worker) - যে ডাটা আনে।
২. **Unit of Work:** (The Manager) - যে ট্রানজ্যাকশন ম্যানেজ করে।
৩. **Result Pattern:** (The Messenger) - যে সুন্দর করে খবর পৌঁছায়।

যখন এই তিনজনকে একসাথে মেলাবে, তোমার আর্কিটেকচার হবে **বুলেটপ্রুফ**। চলো, একদম সহজ গল্পের মাধ্যমে এবং কোড দিয়ে এই "ট্রিনিটি" (Trinity) সেটআপ করি।

---

### 🎬 সিনারিও: "সুপার শপ শপিং"

> ১. **Repository:** শপের সেলসম্যান। তুমি বললে "আইফোন দিন", সে র‍্যাক থেকে আইফোন এনে দিলো।
> ২. **Unit of Work:** ক্যাশ কাউন্টার। তুমি ফোন নিলে, কভার নিলে। কাউন্টারে গিয়ে সব **একসাথে** পেমেন্ট করলে (Commit)। টাকা না থাকলে পুরো কেনাকাটাই বাতিল (Rollback)।
> ৩. **Result Pattern:** পেমেন্ট স্লিপ/রশিদ। কাউন্টার থেকে তোমাকে একটা সুন্দর প্যাকেটে পণ্য + স্লিপ দিলো "সাকসেস" (Success), অথবা স্লিপে লিখে দিলো "কার্ডে টাকা নেই" (Failure)।

### 🛠️ কোড ইমপ্লিমেন্টেশন (Step-by-Step)

আমরা দেখবো কিভাবে **Service Layer**-এ এই তিনজনকে একসাথে ব্যবহার করা হয়।

#### ধাপ ১: The Messenger (Result Pattern)
সবার আগে আমাদের "ম্যাজিক বক্স" বা খাম বানাই, যা দিয়ে ডাটা পাঠাবো।

```csharp
// Result.cs
public class Result<T>
{
    public bool IsSuccess { get; }
    public T? Data { get; }
    public string? ErrorMessage { get; }

    private Result(bool isSuccess, T? data, string? error)
    {
        IsSuccess = isSuccess;
        Data = data;
        ErrorMessage = error;
    }

    // কাজ হলে এটা কল করবো
    public static Result<T> Success(T data) => new(true, data, null);

    // ফেইল হলে এটা কল করবো
    public static Result<T> Failure(string error) => new(false, default, error);
}
```

#### ধাপ ২: The Worker & Manager (Repository & Unit of Work)
ধরি, আমাদের `Product` এবং `Order` নিয়ে কাজ করতে হবে।

**Interface Definition:**
```csharp
public interface IUnitOfWork : IDisposable
{
    IProductRepository Products { get; }
    IOrderRepository Orders { get; }
    Task<int> CompleteAsync(); // SaveChanges
}
```
*(ধরে নিচ্ছি Repository গুলো আগে থেকেই বানানো আছে, যেমনটা আমরা আগের লেসনে শিখেছি)*

#### ধাপ ৩: The Coordinator (Service Layer) 🔥 **(সবচেয়ে গুরুত্বপূর্ণ)**
এখানেই আমরা তিনজনকে বিয়ে দেবো! 😄
আমরা একটা `OrderService` বানাবো যা অর্ডার প্লেস করবে।

লক্ষ্য করো কিভাবে:
1.  **Repository** ডাটা আনছে/নিচ্ছে।
2.  **Unit of Work** ফাইনাল সেভ করছে।
3.  **Result** রিটার্ন করছে।

```csharp
public class OrderService
{
    private readonly IUnitOfWork _unitOfWork;
    private readonly ILogger<OrderService> _logger;

    public OrderService(IUnitOfWork unitOfWork, ILogger<OrderService> logger)
    {
        _unitOfWork = unitOfWork;
        _logger = logger;
    }

    // মেথড রিটার্ন করছে Result<int> (মানে OrderId অথবা Error)
    public async Task<Result<int>> PlaceOrderAsync(int productId, int quantity)
    {
        try
        {
            // ১. ভ্যালিডেশন (Repository ব্যবহার করে চেক)
            var product = await _unitOfWork.Products.GetByIdAsync(productId);
            
            if (product == null)
                return Result<int>.Failure("দুঃখিত! প্রোডাক্ট পাওয়া যায়নি। ❌");

            if (product.Stock < quantity)
                return Result<int>.Failure($"স্টক শেষ! আছে মাত্র {product.Stock} টি। ⚠️");

            // ২. লজিক (Repository তে মেমোরি আপডেট)
            // স্টক কমালাম
            product.Stock -= quantity; 

            // নতুন অর্ডার বানালাম
            var newOrder = new Order 
            { 
                ProductId = productId, 
                Quantity = quantity, 
                OrderDate = DateTime.UtcNow 
            };
            
            await _unitOfWork.Orders.AddAsync(newOrder);

            // ৩. ট্রানজ্যাকশন (Unit of Work দিয়ে সেভ)
            // এই লাইনের আগে ডাটাবেসে কিছুই চেঞ্জ হবে না
            await _unitOfWork.CompleteAsync();

            // ৪. সাকসেস রেজাল্ট রিটার্ন (Result Pattern)
            return Result<int>.Success(newOrder.Id);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Order failed");
            // এক্সেপশন খেয়ে অ্যাপ ক্র্যাশ করবে না, সুন্দর ফেইল মেসেজ যাবে
            return Result<int>.Failure("সার্ভারে সমস্যা হয়েছে। পরে চেষ্টা করুন। 🔥");
        }
    }
}
```

#### ধাপ ৪: The Presenter (Controller) 🎮
কন্ট্রোলার এখন দেখবে রেজাল্ট বক্সে কি আছে।

```csharp
[ApiController]
[Route("api/orders")]
public class OrderController : ControllerBase
{
    private readonly OrderService _orderService;

    public OrderController(OrderService orderService)
    {
        _orderService = orderService;
    }

    [HttpPost]
    public async Task<IActionResult> Create(int productId, int qty)
    {
        // সার্ভিস কল করলাম
        var result = await _orderService.PlaceOrderAsync(productId, qty);

        // বক্স খুলে চেক করছি
        if (result.IsSuccess)
        {
            // কাজ হয়েছে! 🥳
            return Ok(new { Message = "অর্ডার কনফার্ম!", OrderId = result.Data });
        }

        // কাজ হয়নি! 😢 (Result Pattern এরর মেসেজ দিচ্ছে)
        return BadRequest(new { Error = result.ErrorMessage });
    }
}
```

### 🧩 কিভাবে সব একসাথে কাজ করলো? (Workflow Summary)

1.  **Controller** সার্ভিসকে কল দিলো।
2.  **Service** লজিক চেক করলো।
    *   স্টক না থাকলে `Result.Failure` রিটার্ন দিলো (Controller `400 Bad Request` দেখালো)।
3.  **Service** সব ঠিক থাকলে `_unitOfWork` দিয়ে ডাটা সেভ করলো।
    *   `CompleteAsync()` কল হলো, মানে ডাটাবেসে ট্রানজ্যাকশন কমিট হলো।
4.  **Service** সাকসেস হলে `Result.Success` রিটার্ন দিলো।
5.  **Controller** সেই ডাটা নিয়ে ইউজারকে `200 OK` দেখালো।

### ✨ বেনিফিট (কেন এই কম্বিনেশন সেরা?)

1.  **Clean Code:** কন্ট্রোলারে কোনো `try-catch` নেই, ডাটাবেস লজিক নেই।
2.  **Safety:** Unit of Work নিশ্চিত করছে যে টাকা কাটলে অর্ডার হবেই (Transaction)।
3.  **Predictability:** Result Pattern নিশ্চিত করছে যে ফ্রন্টএন্ড সবসময় জানবে কি হয়েছে (Success/Failure)।
4.  **Separation:** Repository ডাটা আনছে, Service লজিক দেখছে, Controller কথা বলছে। সবাই সবার কাজ করছে।
