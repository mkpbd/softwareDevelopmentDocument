
অবশ্যই! TypeScript-এর Mapped Types কীভাবে কাজ করে তা খুব সহজ করে নিচে বোঝানো হলো।

### Mapped Type কী?

সহজ কথায়, Mapped Type হলো TypeScript-এর একটি ফিচার যা দিয়ে আপনি একটি আগে থেকে থাকা Type (যেমন একটি `interface` বা `object` type) থেকে নতুন একটি Type তৈরি করতে পারেন। এটা অনেকটা একটি কারখানার মতো, যেখানে আপনি একটি পুরোনো মডেলের উপর ভিত্তি করে নতুন মডেল তৈরি করেন, কিন্তু কিছু নিয়ম পরিবর্তন করে দেন।

এর মূল কাজ হলো, একটি টাইপের প্রত্যেকটি প্রপার্টি (property) নিয়ে সেগুলোর উপর একটি নির্দিষ্ট নিয়ম বা পরিবর্তন (transformation) প্রয়োগ করে একটি নতুন টাইপ তৈরি করা।

### একটি সহজ উদাহরণ দিয়ে বোঝা যাক

ধরুন, আপনার কাছে একটি ফটোকপি মেশিন আছে।
*   **মূল ডকুমেন্ট:** এটা হলো আপনার পুরোনো বা অরিজিনাল Type (`interface User`)।
*   **ফটোকপি মেশিন:** এটাই হলো Mapped Type।
*   **মেশিনের সেটিংস:** আপনি মেশিনে কিছু সেটিং করে দিতে পারেন, যেমন "সবগুলো পেজ শুধু-পড়ার-জন্য (read-only) করে দাও" অথবা "সবগুলো লেখাকে ঐচ্ছিক (optional) করে দাও"।
*   **ফটোকপি করা ডকুমেন্ট:** এটাই হলো আপনার নতুন তৈরি হওয়া Type।

### কোডের মাধ্যমে বুঝি

#### ধাপ ১: আমাদের মূল Type

প্রথমে, আমাদের একটি সাধারণ `interface` আছে। ধরা যাক, এটি একজন ব্যবহারকারীর তথ্য ধারণ করে।

```typescript
interface User {
  id: number;
  name: string;
  email: string;
}
```

এই `User` টাইপের অবজেক্টে `id`, `name`, এবং `email` থাকতেই হবে।

#### ধাপ ২: একটি Mapped Type তৈরি করা

এখন আমরা চাই এই `User` টাইপের সবগুলো প্রপার্টিকে `readonly` (শুধু পড়া যাবে, পরিবর্তন করা যাবে না) বানিয়ে একটি নতুন টাইপ তৈরি করতে।

এর জন্য আমরা TypeScript-এর বিল্ট-ইন `Readonly` Mapped Type ব্যবহার করতে পারি।

```typescript
type ReadonlyUser = Readonly<User>;
```

এখন এই `ReadonlyUser` টাইপটি দেখতে ঠিক এইরকম হবে:

```typescript
// TypeScript ভেতরে ভেতরে যা তৈরি করেছে:
// type ReadonlyUser = {
//   readonly id: number;
//   readonly name: string;
//   readonly email: string;
// };
```

দেখুন, `User` টাইপের সবগুলো প্রপার্টির আগে `readonly` যুক্ত হয়ে গেছে!

**ব্যবহার:**

```typescript
const user: ReadonlyUser = {
  id: 1,
  name: "Rahim",
  email: "rahim@example.com",
};

user.name = "Karim"; // Error! ❌ Cannot assign to 'name' because it is a read-only property.
```
আপনি `user.name` পরিবর্তন করতে পারবেন না কারণ `ReadonlyUser` টাইপের সবগুলো প্রপার্টি এখন `readonly`।

### Mapped Type-এর সিনট্যাক্স (Syntax) ভেঙে দেখি

আপনি চাইলে নিজের মতো করেও Mapped Type তৈরি করতে পারেন। `Readonly<T>` আসলে ভেতরে ভেতরে এভাবেই কাজ করে:

```typescript
type MyReadonly<T> = {
  readonly [Property in keyof T]: T[Property];
};
```

আসুন এই অদ্ভুত সিনট্যাক্সটি ভেঙে দেখি:

1.  `type MyReadonly<T> = { ... };`
    *   `T` হলো একটি জেনেরিক টাইপ (generic type)। এখানে আমরা যেকোনো টাইপ পাস করতে পারব (যেমন `User`)।

2.  `[Property in keyof T]`
    *   এটাকে একটি `for...in` লুপের মতো ভাবতে পারেন।
    *   `keyof T`: এটা `T` টাইপের সবগুলো key (প্রপার্টির নাম) নিয়ে একটি union type তৈরি করে। যেমন, `keyof User` মানে হলো `'id' | 'name' | 'email'`।
    *   `Property in ...`: এই লুপটি `'id'`, `'name'`, এবং `'email'`-এর উপর দিয়ে এক এক করে চলবে এবং `Property` ভ্যারিয়েবলে প্রতিটি key-এর নাম রাখবে।

3.  `readonly ...`
    *   এটি একটি মডিফায়ার (modifier)। এখানে আমরা বলে দিচ্ছি যে নতুন টাইপের প্রত্যেকটি প্রপার্টি `readonly` হবে।

4.  `: T[Property]`
    *   `:` এর পরে আমরা নতুন প্রপার্টির টাইপ বলে দিই।
    *   `T[Property]`: এটাকে "lookup type" বলে। এর মানে হলো, অরিজিনাল `T` টাইপে `Property` নামের key-টির যে টাইপ ছিল, সেটাই এখানে বসবে।
        *   যখন `Property` হবে `'id'`, তখন `T['id']` মানে হবে `number`।
        *   যখন `Property` হবে `'name'`, তখন `T['name']` মানে হবে `string`।

### আরও কিছু জনপ্রিয় বিল্ট-ইন Mapped Type

1.  **`Partial<T>**: একটি টাইপের সবগুলো প্রপার্টিকে optional (ঐচ্ছিক) বানিয়ে দেয় (প্রপার্টির শেষে `?` যুক্ত করে)।

    ```typescript
    type PartialUser = Partial<User>;
    // ফলাফল:
    // {
    //   id?: number;
    //   name?: string;
    //   email?: string;
    // }

    const userUpdate: PartialUser = { name: "New Name" }; // বৈধ, কারণ id এবং email এখন optional
    ```
    

2.  **Required`<T>`**: Partial`<T>` এর ঠিক উল্টো। একটি টাইপের সবগুলো optional প্রপার্টিকে আবশ্যক (required) করে দেয়।

3.  **Pick`<T, K>`**: একটি টাইপ থেকে শুধুমাত্র নির্দিষ্ট কিছু প্রপার্টি বেছে নিয়ে নতুন টাইপ তৈরি করে।

    ```typescript
    type UserIdentity = Pick<User, "name" | "email">;
    // ফলাফল:
    // {
    //   name: string;
    //   email: string;
    // }
    ```

### সারসংক্ষেপ: কেন Mapped Type ব্যবহার করবেন?

*   **Don't Repeat Yourself (DRY):** আপনাকে একই রকম দেখতে কিন্তু সামান্য ভিন্ন টাইপ বারবার লিখতে হয় না।
*   **Maintainability:** যদি আপনার মূল `User` টাইপে নতুন কোনো প্রপার্টি (যেমন `age`) যোগ করেন, তাহলে `ReadonlyUser`, `PartialUser` ইত্যাদি ম্যাপ করা টাইপগুলো নিজে থেকেই আপডেট হয়ে যাবে। আপনাকে আলাদা করে সব জায়গায় পরিবর্তন করতে হবে না।
*   **Flexibility:** এটি আপনাকে খুব সহজে একটি টাইপের বিভিন্ন সংস্করণ (যেমন readonly, optional, ইত্যাদি) তৈরি করার ক্ষমতা দেয়।

আশা করি, এখন আপনি বুঝতে পেরেছেন যে TypeScript-এর Mapped Types কীভাবে কাজ করে



অবশ্যই! TypeScript-এর Built-in (আগে থেকে তৈরি) এবং Custom (নিজেদের তৈরি) Mapped Type-এর মধ্যে পার্থক্য এবং ব্যবহার খুব সহজভাবে নিচে আলোচনা করা হলো।

এটাকে আপনি একটি রেস্টুরেন্টের মেনুর সাথে তুলনা করতে পারেন।

*   **Built-in Mapped Types:** এগুলো হলো রেস্টুরেন্টের "Set Menu"-এর মতো। সাধারণ এবং জনপ্রিয় চাহিদাগুলো মেটানোর জন্য এগুলো আগে থেকেই তৈরি করা থাকে। যেমন: `Readonly`, `Partial` ইত্যাদি।
*   **Custom Mapped Types:** এটা হলো "À la carte" বা "Make your own meal"-এর মতো। যখন আপনার এমন কিছু দরকার যা Set Menu-তে নেই, তখন আপনি নিজের প্রয়োজন অনুযায়ী উপকরণ দিয়ে নিজের ডিশ তৈরি করে নেন।

### পর্ব ১: Built-in Mapped Types (তৈরি করা টুলবক্স)

TypeScript আমাদের কিছু সাধারণ কাজের জন্য কয়েকটি Mapped Type তৈরি করে দিয়েছে। এগুলো ব্যবহার করা খুব সহজ।

আমাদের মূল `interface` টি আবার দেখি:
```typescript
interface User {
  id: number;
  name: string;
  email?: string; // email ঐচ্ছিক
}
```

কিছু জনপ্রিয় Built-in Mapped Type হলো:

#### 1. `Readonly<T>`
সবগুলো প্রপার্টিকে `readonly` (শুধু-পঠনযোগ্য) করে দেয়।

```typescript
type ReadonlyUser = Readonly<User>;
// ফলাফল:
// {
//   readonly id: number;
//   readonly name: string;
//   readonly email?: string;
// }
```

#### 2. `Partial<T>`
সবগুলো প্রপার্টিকে `optional` (ঐচ্ছিক) করে দেয় (`?` যোগ করে)।

```typescript
type PartialUser = Partial<User>;
// ফলাফল:
// {
//   id?: number;
//   name?: string;
//   email?: string;
// }
```
এটি খুব কাজের যখন আপনি একটি অবজেক্টের কিছু অংশ আপডেট করতে চান।

#### 3. `Required<T>`
`Partial` এর ঠিক উল্টো। সবগুলো ঐচ্ছিক প্রপার্টিকে `required` (আবশ্যক) করে দেয়।

```typescript
type RequiredUser = Required<User>;
// ফলাফল:
// {
//   id: number;
//   name: string;
//   email: string; // `?` চিহ্নটি চলে গেছে
// }
```

#### 4. `Pick<T, K>`
একটি টাইপ থেকে আপনার পছন্দের কয়েকটি প্রপার্টি বেছে (pick) নিয়ে নতুন টাইপ তৈরি করে।

```typescript
type UserLoginInfo = Pick<User, 'name' | 'email'>;
// ফলাফল:
// {
//   name: string;
//   email?: string;
// }
```

#### 5. `Omit<T, K>`
`Pick` এর উল্টো। একটি টাইপ থেকে কয়েকটি প্রপার্টি বাদ (omit) দিয়ে বাকিগুলো দিয়ে নতুন টাইপ তৈরি করে।

```typescript
type UserProfileInfo = Omit<User, 'id'>;
// ফলাফল:
// {
//   name: string;
//   email?: string;
// }
```

### পর্ব ২: Custom Mapped Types (নিজের টুলস নিজে বানান)

যখন বিল্ট-ইন টাইপগুলো আপনার প্রয়োজন মেটাতে পারে না, তখন আপনি নিজের Mapped Type তৈরি করতে পারেন।

#### উদাহরণ ১: সব প্রপার্টিকে `nullable` করা

ধরুন, আমরা এমন একটি টাইপ চাই যেখানে `User`-এর প্রত্যেকটি প্রপার্টির মান তার নিজের টাইপ অথবা `null` হতে পারবে। TypeScript-এ এর জন্য কোনো বিল্ট-ইন টাইপ নেই। তাই আমরা নিজেরা বানাবো।

```typescript
type Nullable<T> = {
  [Property in keyof T]: T[Property] | null;
};
```
**ব্যাখ্যা:**
*   `[Property in keyof T]`: আগের মতোই, `T` টাইপের প্রতিটি key-এর উপর লুপ চালাবে।
*   `T[Property] | null`: মূল টাইপের প্রপার্টির যা টাইপ ছিল (যেমন `number` বা `string`), তার সাথে `| null` যোগ করে দেওয়া হচ্ছে।

**ব্যবহার:**
```typescript
type NullableUser = Nullable<User>;
// ফলাফল:
// {
//   id: number | null;
//   name: string | null;
//   email: string | null | undefined; // email আগে থেকেই optional ছিল (string | undefined)
// }

const partialUserData: NullableUser = {
  id: 1,
  name: null,       // এখন এটা বৈধ
  email: "user@example.com"
};
```

#### উদাহরণ ২: `readonly` তুলে দেওয়া (Mutable করা)

`Readonly<T>` এর বিপরীত কাজ করার জন্য আমরা একটি কাস্টম টাইপ বানাতে পারি।

```typescript
type Mutable<T> = {
  -readonly [Property in keyof T]: T[Property];
};
```
**ব্যাখ্যা:**
*   `-readonly`: এই `-` চিহ্নটি `readonly` মডিফায়ারকে সরিয়ে দেয়।

**ব্যবহার:**
```typescript
interface LockedConfig {
  readonly apiUrl: string;
  readonly apiKey: string;
}

type UnlockedConfig = Mutable<LockedConfig>;
// ফলাফল:
// {
//   apiUrl: string;
//   apiKey: string;
// }

const config: UnlockedConfig = { apiUrl: "...", apiKey: "..." };
config.apiKey = "new-key"; // এখন পরিবর্তন করা সম্ভব!
```

#### উদাহরণ ৩: প্রপার্টির Key পরিবর্তন করা (Key Remapping)

এটি একটি আরও শক্তিশালী ফিচার। আপনি চাইলে প্রপার্টির নামও পরিবর্তন করে ফেলতে পারেন।

ধরুন, আমরা `User` টাইপ থেকে এমন একটি নতুন টাইপ বানাতে চাই যেখানে প্রতিটি প্রপার্টির জন্য একটি `getter` ফাংশন থাকবে। যেমন, `name` হয়ে যাবে `getName`, `id` হয়ে যাবে `getId`।

```typescript
type Getter<T> = {
  [Property in keyof T as `get${Capitalize<string & Property>}`]: () => T[Property];
};
```
**ব্যাখ্যা:**
*   `as \`get${Capitalize<string & Property>}\``: এটাই হলো Key Remapping।
    *   `as` keyword ব্যবহার করে আমরা পুরোনো `Property` নামকে একটি নতুন নামে ম্যাপ করছি।
    *   `Capitalize`: এটি একটি বিল্ট-ইন টাইপ যা স্ট্রিং-এর প্রথম অক্ষর বড় হাতের করে দেয়।
    *   `` `get...` ``: Template literal ব্যবহার করে আমরা `get` প্রিফিক্স যোগ করছি।
*   `: () => T[Property]`: নতুন প্রপার্টির টাইপ হবে একটি ফাংশন যা অরিজিনাল প্রপার্টির টাইপ রিটার্ন করে।

**ব্যবহার:**
```typescript
type UserGetters = Getter<User>;
// ফলাফল:
// {
//   getId: () => number;
//   getName: () => string;
//   getEmail: () => string | undefined;
// }
```

### সারসংক্ষেপ

| বিষয়                   | বিল্ট-ইন ম্যাপড টাইপ (Built-in)                                        | কাস্টম ম্যাপড টাইপ (Custom)                                           |
| ---------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **ব্যবহার**            | সাধারণ ও বারবার লাগে এমন কাজের জন্য।                                   | যখন কোনো বিশেষ বা জটিল পরিবর্তনের প্রয়োজন হয়।                         |
| **উদাহরণ**             | `Readonly`, `Partial`, `Pick`, `Omit`, `Required`                      | `Nullable<T>`, `Mutable<T>`, `Getter<T>`                              |
| **সুবিধা**             | লেখা সহজ, কোড সংক্ষিপ্ত এবং পড়া সহজ।                                   | সম্পূর্ণ নিয়ন্ত্রণ এবং ফ্লেক্সিবিলিটি। যেকোনো ধরনের টাইপ বানানো যায়।  |
| **কখন ব্যবহার করবেন?** | যখন আপনার কাজ `Readonly` বা `Partial` এর মতো সাধারণ কিছু দিয়ে হয়ে যায়। | যখন বিল্ট-ইন টাইপ দিয়ে কাজ হয় না এবং আপনার নিজের লজিক প্রয়োগ করতে হয়। |

অবশ্যই! Mapped Types এবং Conditional Types-এর সংমিশ্রণ TypeScript-এর অন্যতম শক্তিশালী ফিচার। এটি আপনার টাইপগুলোকে সাধারণ রূপান্তর (transformation) থেকে "বুদ্ধিমান" (intelligent) রূপান্তরে নিয়ে যায়।

চলুন, এটাকে একটি স্মার্ট ফ্যাক্টরির সাথে তুলনা করি।

*   **সাধারণ Mapped Type:** একটি সাধারণ ফ্যাক্টরি মেশিনের মতো, যা কনভেয়র বেল্টের উপর আসা প্রত্যেকটি জিনিসের উপর একই কাজ করে (যেমন, প্রত্যেকটি বক্সে একটি স্টিকার লাগানো)।
*   **Conditional Type:** এটা হলো ফ্যাক্টরির একজন কোয়ালিটি কন্ট্রোল ইন্সপেক্টর। সে প্রতিটি জিনিস পরীক্ষা করে এবং একটি শর্তের উপর ভিত্তি করে সিদ্ধান্ত নেয় (যেমন, "এই বক্সটি কি ভাঙার মতো? হ্যাঁ হলে, 'Fragile' স্টিকার লাগাও, না হলে কিছু করো না")।

**Mapped Type + Conditional Type:** এখন কল্পনা করুন, আপনি আপনার ফ্যাক্টরি মেশিনটির ভেতরেই কোয়ালিটি কন্ট্রোল ইন্সপেক্টরকে বসিয়ে দিয়েছেন। মেশিনটি এখন আর অন্ধভাবে কাজ করে না। এটি প্রত্যেকটি জিনিস প্রসেস করার সময় একটি শর্ত পরীক্ষা করে এবং সেই অনুযায়ী ভিন্ন ভিন্ন কাজ করে। এটাই হলো এদের সম্মিলিত শক্তি!

---

### কীভাবে এটি কাজ করে?

এর মূল ভিত্তি হলো একটি Mapped Type-এর লুপের (`[P in keyof T]`) ভেতরে একটি Conditional Type (`... extends ... ? ... : ...`) ব্যবহার করা।

এটির মাধ্যমে আমরা দুটি প্রধান কাজ করতে পারি:

1.  শর্তের উপর ভিত্তি করে **প্রপার্টি ফিল্টার** করা (কিছু প্রপার্টি রাখা, কিছু বাদ দেওয়া)।
2.  শর্তের উপর ভিত্তি করে **প্রপার্টির টাইপ পরিবর্তন** করা।

---

### উদাহরণ ১: শর্ত অনুযায়ী প্রপার্টি ফিল্টার করা (Filtering Properties)

ধরুন, আমাদের একটি `interface` আছে এবং আমরা সেখান থেকে শুধুমাত্র `string` টাইপের প্রপার্টিগুলো নিয়ে একটি নতুন টাইপ বানাতে চাই।

**আমাদের মূল টাইপ:**
```typescript
interface UserProfile {
  id: number;
  username: string;
  email: string;
  followers: number;
  isVerified: boolean;
}
```

**আমাদের লক্ষ্য:** এমন একটি টাইপ তৈরি করা যা দেখতে এইরকম হবে:
```typescript
// {
//   username: string;
//   email: string;
// }
```

**সমাধান:**
আমরা একটি Mapped Type তৈরি করব যা প্রতিটি প্রপার্টির টাইপ পরীক্ষা করবে।

```typescript
type FilterByType<T, U> = {
  [Property in keyof T as T[Property] extends U ? Property : never]: T[Property];
};
```

**আসুন এই জটিল কোডটি ভেঙে দেখি:**

1.  `[Property in keyof T as ... ]`: এখানে আমরা Mapped Type-এর সাথে **Key Remapping** (`as` keyword) ব্যবহার করছি। এর মানে হলো, আমরা প্রপার্টির মূল নাম (`Property`) পরিবর্তন করে একটি নতুন নাম দিতে পারি।

2.  `T[Property] extends U ? Property : never`: এটাই হলো আমাদের কন্ডিশনাল লজিক।
    *   `T[Property]`: লুপে থাকা বর্তমান প্রপার্টির টাইপ (যেমন `number`, `string`, `boolean`)।
    *   `extends U`: আমরা পরীক্ষা করছি, ঐ টাইপটি কি আমাদের দেওয়া `U` টাইপের সাথে মেলে?
    *   `? Property`: যদি শর্ত সত্যি হয় (অর্থাৎ, টাইপ মিলে যায়), তাহলে প্রপার্টির নামটি (`Property`) অপরিবর্তিত রাখো।
    *   `: never`: **এটাই সবচেয়ে গুরুত্বপূর্ণ অংশ।** যদি শর্ত মিথ্যা হয়, তাহলে প্রপার্টির নামটিকে `never` টাইপে ম্যাপ করো। TypeScript-এ যখন কোনো key-কে `never`-তে ম্যাপ করা হয়, তখন সেই key-টি চূড়ান্ত টাইপ থেকে **সম্পূর্ণ বাদ হয়ে যায়**।

**ব্যবহার:**
```typescript
type StringPropertiesOnly = FilterByType<UserProfile, string>;

// StringPropertiesOnly টাইপটি এখন দেখতে এইরকম:
// {
//   username: string;
//   email: string;
// }

const userStrings: StringPropertiesOnly = {
  username: "rahim_codes",
  email: "rahim@example.com",
  // id: 123, // Error! ❌ 'id' does not exist in type 'StringPropertiesOnly'.
};
```
দেখুন, আমরা কত সহজে একটি টাইপ থেকে আমাদের প্রয়োজনীয় প্রপার্টিগুলো ছেঁকে বের করে আনলাম!

---

### উদাহরণ ২: শর্ত অনুযায়ী প্রপার্টির টাইপ পরিবর্তন করা (Transforming Property Types)

এখন আমরা এমন একটি টাইপ বানাবো যেখানে একটি অবজেক্টের `function` টাইপের প্রপার্টিগুলো থেকে তাদের রিটার্ন টাইপ (return type) নেওয়া হবে এবং বাকি প্রপার্টিগুলো অপরিবর্তিত থাকবে।

**আমাদের মূল টাইপ:**
```typescript
interface Actions {
  getUserId: () => number;
  getUsername: () => string;
  config: { theme: string };
}
```

**আমাদের লক্ষ্য:** এমন একটি টাইপ বানানো যা ফাংশনগুলোর রিটার্ন টাইপ এবং অন্য প্রপার্টিগুলো সরাসরি রাখবে।
```typescript
// {
//   getUserId: number;
//   getUsername: string;
//   config: { theme: string };
// }
```

**সমাধান:**
```typescript
type UnpackFunctions<T> = {
  [Property in keyof T]: T[Property] extends () => infer R ? R : T[Property];
};
```
**এই কোডটি ভেঙে দেখি:**

1.  `[Property in keyof T]`: আমরা `Actions`-এর প্রতিটি প্রপার্টির উপর দিয়ে লুপ চালাচ্ছি।

2.  `T[Property] extends () => infer R ? R : T[Property]`: এখানে কন্ডিশনাল লজিকটি প্রপার্টির **ভ্যালুর টাইপের** উপর কাজ করছে।
    *   `T[Property] extends () => infer R`: আমরা পরীক্ষা করছি, "প্রপার্টির টাইপটি কি কোনো আর্গুমেন্ট ছাড়া একটি ফাংশন?"
    *   `infer R`: `infer` keyword-টি এখানে জাদুর মতো কাজ করে। এটি TypeScript-কে বলে, "যদি এটি একটি ফাংশন হয়, তাহলে এর রিটার্ন টাইপটি কী তা খুঁজে বের করো এবং তাকে `R` নামের একটি অস্থায়ী ভেরিয়েবলে রাখো।"
    *   `? R`: যদি শর্ত সত্যি হয়, তাহলে নতুন টাইপে ঐ প্রপার্টির টাইপ হবে `R` (অর্থাৎ, ফাংশনের রিটার্ন টাইপ)।
    *   `: T[Property]`: যদি শর্ত মিথ্যা হয় (অর্থাৎ, এটি ফাংশন না হয়), তাহলে প্রপার্টির টাইপ যা ছিল তাই থাকবে (`T[Property]`)।

**ব্যবহার:**
```typescript
type ActionResults = UnpackFunctions<Actions>;

// ActionResults টাইপটি এখন দেখতে এইরকম:
// {
//   getUserId: number;
//   getUsername: string;
//   config: { theme: string };
// }

const results: ActionResults = {
  getUserId: 101,
  getUsername: "Karim",
  config: { theme: "dark" },
};
```

### সারসংক্ষেপ

Mapped Types এবং Conditional Types একসাথে ব্যবহার করে আপনি অত্যন্ত গতিশীল এবং বুদ্ধিমান টাইপ তৈরি করতে পারেন যা আপনার কোডকে আরও নিরাপদ এবং সহজে রক্ষণাবেক্ষণযোগ্য করে তোলে।

*   **Property ফিল্টার করতে:** Key remapping (`as`) এবং `never` ব্যবহার করুন।
*   **Property-র টাইপ পরিবর্তন করতে:** Conditional type (`extends`) এবং `infer` (প্রয়োজনে) ব্যবহার করুন।

অবশ্যই! Mapped Types এবং Conditional Types-এর সংমিশ্রণ TypeScript-এর অন্যতম শক্তিশালী ফিচার। এটি আপনার টাইপগুলোকে সাধারণ রূপান্তর (transformation) থেকে "বুদ্ধিমান" (intelligent) রূপান্তরে নিয়ে যায়।

চলুন, এটাকে একটি স্মার্ট ফ্যাক্টরির সাথে তুলনা করি।

*   **সাধারণ Mapped Type:** একটি সাধারণ ফ্যাক্টরি মেশিনের মতো, যা কনভেয়র বেল্টের উপর আসা প্রত্যেকটি জিনিসের উপর একই কাজ করে (যেমন, প্রত্যেকটি বক্সে একটি স্টিকার লাগানো)।
*   **Conditional Type:** এটা হলো ফ্যাক্টরির একজন কোয়ালিটি কন্ট্রোল ইন্সপেক্টর। সে প্রতিটি জিনিস পরীক্ষা করে এবং একটি শর্তের উপর ভিত্তি করে সিদ্ধান্ত নেয় (যেমন, "এই বক্সটি কি ভাঙার মতো? হ্যাঁ হলে, 'Fragile' স্টিকার লাগাও, না হলে কিছু করো না")।

**Mapped Type + Conditional Type:** এখন কল্পনা করুন, আপনি আপনার ফ্যাক্টরি মেশিনটির ভেতরেই কোয়ালিটি কন্ট্রোল ইন্সপেক্টরকে বসিয়ে দিয়েছেন। মেশিনটি এখন আর অন্ধভাবে কাজ করে না। এটি প্রত্যেকটি জিনিস প্রসেস করার সময় একটি শর্ত পরীক্ষা করে এবং সেই অনুযায়ী ভিন্ন ভিন্ন কাজ করে। এটাই হলো এদের সম্মিলিত শক্তি!

---

### কীভাবে এটি কাজ করে?

এর মূল ভিত্তি হলো একটি Mapped Type-এর লুপের (`[P in keyof T]`) ভেতরে একটি Conditional Type (`... extends ... ? ... : ...`) ব্যবহার করা।

এটির মাধ্যমে আমরা দুটি প্রধান কাজ করতে পারি:

1.  শর্তের উপর ভিত্তি করে **প্রপার্টি ফিল্টার** করা (কিছু প্রপার্টি রাখা, কিছু বাদ দেওয়া)।
2.  শর্তের উপর ভিত্তি করে **প্রপার্টির টাইপ পরিবর্তন** করা।

### উদাহরণ ১: শর্ত অনুযায়ী প্রপার্টি ফিল্টার করা (Filtering Properties)

ধরুন, আমাদের একটি `interface` আছে এবং আমরা সেখান থেকে শুধুমাত্র `string` টাইপের প্রপার্টিগুলো নিয়ে একটি নতুন টাইপ বানাতে চাই।

**আমাদের মূল টাইপ:**
```typescript
interface UserProfile {
  id: number;
  username: string;
  email: string;
  followers: number;
  isVerified: boolean;
}
```

**আমাদের লক্ষ্য:** এমন একটি টাইপ তৈরি করা যা দেখতে এইরকম হবে:
```typescript
// {
//   username: string;
//   email: string;
// }
```

**সমাধান:**
আমরা একটি Mapped Type তৈরি করব যা প্রতিটি প্রপার্টির টাইপ পরীক্ষা করবে।

```typescript
type FilterByType<T, U> = {
  [Property in keyof T as T[Property] extends U ? Property : never]: T[Property];
};
```

**আসুন এই জটিল কোডটি ভেঙে দেখি:**

1.  `[Property in keyof T as ... ]`: এখানে আমরা Mapped Type-এর সাথে **Key Remapping** (`as` keyword) ব্যবহার করছি। এর মানে হলো, আমরা প্রপার্টির মূল নাম (`Property`) পরিবর্তন করে একটি নতুন নাম দিতে পারি।

2.  `T[Property] extends U ? Property : never`: এটাই হলো আমাদের কন্ডিশনাল লজিক।
    *   `T[Property]`: লুপে থাকা বর্তমান প্রপার্টির টাইপ (যেমন `number`, `string`, `boolean`)।
    *   `extends U`: আমরা পরীক্ষা করছি, ঐ টাইপটি কি আমাদের দেওয়া `U` টাইপের সাথে মেলে?
    *   `? Property`: যদি শর্ত সত্যি হয় (অর্থাৎ, টাইপ মিলে যায়), তাহলে প্রপার্টির নামটি (`Property`) অপরিবর্তিত রাখো।
    *   `: never`: **এটাই সবচেয়ে গুরুত্বপূর্ণ অংশ।** যদি শর্ত মিথ্যা হয়, তাহলে প্রপার্টির নামটিকে `never` টাইপে ম্যাপ করো। TypeScript-এ যখন কোনো key-কে `never`-তে ম্যাপ করা হয়, তখন সেই key-টি চূড়ান্ত টাইপ থেকে **সম্পূর্ণ বাদ হয়ে যায়**।

**ব্যবহার:**
```typescript
type StringPropertiesOnly = FilterByType<UserProfile, string>;

// StringPropertiesOnly টাইপটি এখন দেখতে এইরকম:
// {
//   username: string;
//   email: string;
// }

const userStrings: StringPropertiesOnly = {
  username: "rahim_codes",
  email: "rahim@example.com",
  // id: 123, // Error! ❌ 'id' does not exist in type 'StringPropertiesOnly'.
};
```
দেখুন, আমরা কত সহজে একটি টাইপ থেকে আমাদের প্রয়োজনীয় প্রপার্টিগুলো ছেঁকে বের করে আনলাম!

### উদাহরণ ২: শর্ত অনুযায়ী প্রপার্টির টাইপ পরিবর্তন করা (Transforming Property Types)

এখন আমরা এমন একটি টাইপ বানাবো যেখানে একটি অবজেক্টের `function` টাইপের প্রপার্টিগুলো থেকে তাদের রিটার্ন টাইপ (return type) নেওয়া হবে এবং বাকি প্রপার্টিগুলো অপরিবর্তিত থাকবে।

**আমাদের মূল টাইপ:**
```typescript
interface Actions {
  getUserId: () => number;
  getUsername: () => string;
  config: { theme: string };
}
```

**আমাদের লক্ষ্য:** এমন একটি টাইপ বানানো যা ফাংশনগুলোর রিটার্ন টাইপ এবং অন্য প্রপার্টিগুলো সরাসরি রাখবে।
```typescript
// {
//   getUserId: number;
//   getUsername: string;
//   config: { theme: string };
// }
```

**সমাধান:**
```typescript
type UnpackFunctions<T> = {
  [Property in keyof T]: T[Property] extends () => infer R ? R : T[Property];
};
```
**এই কোডটি ভেঙে দেখি:**

1.  `[Property in keyof T]`: আমরা `Actions`-এর প্রতিটি প্রপার্টির উপর দিয়ে লুপ চালাচ্ছি।

2.  `T[Property] extends () => infer R ? R : T[Property]`: এখানে কন্ডিশনাল লজিকটি প্রপার্টির **ভ্যালুর টাইপের** উপর কাজ করছে।
    *   `T[Property] extends () => infer R`: আমরা পরীক্ষা করছি, "প্রপার্টির টাইপটি কি কোনো আর্গুমেন্ট ছাড়া একটি ফাংশন?"
    *   `infer R`: `infer` keyword-টি এখানে জাদুর মতো কাজ করে। এটি TypeScript-কে বলে, "যদি এটি একটি ফাংশন হয়, তাহলে এর রিটার্ন টাইপটি কী তা খুঁজে বের করো এবং তাকে `R` নামের একটি অস্থায়ী ভেরিয়েবলে রাখো।"
    *   `? R`: যদি শর্ত সত্যি হয়, তাহলে নতুন টাইপে ঐ প্রপার্টির টাইপ হবে `R` (অর্থাৎ, ফাংশনের রিটার্ন টাইপ)।
    *   `: T[Property]`: যদি শর্ত মিথ্যা হয় (অর্থাৎ, এটি ফাংশন না হয়), তাহলে প্রপার্টির টাইপ যা ছিল তাই থাকবে (`T[Property]`)।

**ব্যবহার:**
```typescript
type ActionResults = UnpackFunctions<Actions>;

// ActionResults টাইপটি এখন দেখতে এইরকম:
// {
//   getUserId: number;
//   getUsername: string;
//   config: { theme: string };
// }

const results: ActionResults = {
  getUserId: 101,
  getUsername: "Karim",
  config: { theme: "dark" },
};
```

### সারসংক্ষেপ

Mapped Types এবং Conditional Types একসাথে ব্যবহার করে আপনি অত্যন্ত গতিশীল এবং বুদ্ধিমান টাইপ তৈরি করতে পারেন যা আপনার কোডকে আরও নিরাপদ এবং সহজে রক্ষণাবেক্ষণযোগ্য করে তোলে।

*   **Property ফিল্টার করতে:** Key remapping (`as`) এবং `never` ব্যবহার করুন।
*   **Property-র টাইপ পরিবর্তন করতে:** Conditional type (`extends`) এবং `infer` (প্রয়োজনে) ব্যবহার করুন।
