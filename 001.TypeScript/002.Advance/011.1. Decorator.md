


### Decorator আসলে কী? (What is a Decorator?)

সহজ কথায়, ডেকোরেটর হলো একটি বিশেষ ধরণের ফাংশন। এর কাজ হলো আপনার কোডের ক্লাস (Class), মেথড (Method), প্রোপার্টি (Property) বা প্যারামিটারকে (Parameter) বাইরে থেকে সাজানো বা তার মধ্যে নতুন কোনো ক্ষমতা যোগ করা।

একটা উদাহরণ দিয়ে চিন্তা করুন:
আপনি একটি উপহারের বাক্স (Gift Box) তৈরি করেছেন। এখন সেটিকে সুন্দর করার জন্য আপনি বাইরে থেকে একটি র‍্যাপিং পেপার (Wrapping paper) দিয়ে মুড়িয়ে দিচ্ছেন বা উপরে একটি রিবন লাগিয়ে দিচ্ছেন।

এখানে:
*   **উপহারের বাক্স** = আপনার মূল Class বা Method।
*   **র‍্যাপিং পেপার বা রিবন** = আপনার Decorator।

Decorator আপনার মূল ক্লাস বা মেথডের কোড পরিবর্তন না করেই তার সাথে যুক্ত হয়ে নতুন কাজ করতে পারে। Decorator গুলোকে `@` চিহ্ন দিয়ে শুরু করা হয়। যেমন: `@log`, `@Component` ইত্যাদি।

---

### Decorator কেন ব্যবহার করা হয়? (Why use Decorators?)

এর মূল উদ্দেশ্য হলো কোডকে আরও পরিষ্কার (clean) এবং পুনর্ব্যবহারযোগ্য (reusable) করে তোলা। কিছু সাধারণ ব্যবহার হলো:

1.  **লগিং (Logging):** কোনো মেথড কখন কল করা হলো, বা কী ডেটা দিয়ে কল করা হলো, তা ট্র্যাক করার জন্য।
2.  **ভ্যালিডেশন (Validation):** কোনো মেথডে আসা ডেটা সঠিক কি না, তা চেক করার জন্য।
3.  **পারমিশন চেক (Permission Check):** কোনো ব্যবহারকারীর নির্দিষ্ট কাজ করার অনুমতি আছে কি না, তা মেথড চালানোর আগেই যাচাই করার জন্য।
4.  **কোড মডিফিকেশন (Code Modification):** কোনো ক্লাসের ক্ষমতা বা মেথডের আচরণ পরিবর্তন করার জন্য। (অনেকটা র‍্যাপিং পেপার দিয়ে বাক্স সাজানোর মতো)।

---

### Decorator ব্যবহারের আগে একটি জরুরি কাজ

TypeScript-এ Decorator ফিচারটি এখনও পরীক্ষামূলক (experimental) পর্যায়ে আছে। তাই এটি ব্যবহার করার জন্য আপনাকে `tsconfig.json` ফাইলে একটি অপশন চালু করতে হবে।

আপনার `tsconfig.json` ফাইলটি খুলে `"compilerOptions"` এর ভেতরে এই লাইনটি যোগ করুন:

```json
{
  "compilerOptions": {
    "target": "ES5",
    "experimentalDecorators": true, // এই লাইনটি যোগ করতে হবে
    "emitDecoratorMetadata": true // এটিও যোগ করা ভালো
  }
}
```

### উদাহরণের মাধ্যমে বুঝি

আমরা দুটি সবচেয়ে জনপ্রিয় ডেকোরেটর দেখব: **Class Decorator** এবং **Method Decorator**।

#### ১. ক্লাস ডেকোরেটর (Class Decorator)

এটি পুরো একটি ক্লাসের উপর কাজ করে। এটি ক্লাসটিকে সাজাতে বা তার মধ্যে নতুন কিছু যোগ করতে ব্যবহৃত হয়।

**উদাহরণ:** ধরুন আমরা এমন একটি ডেকোরেটর বানাতে চাই যা কোনো ক্লাসের সাথে একটি নতুন প্রোপার্টি (`createdAt`) যোগ করে দেবে।

```typescript
// ১. প্রথমে আমরা ডেকোরেটর ফাংশনটি বানাবো
function addCreationDate(constructor: Function) {
  // এই ডেকোরেটরটি ক্লাসের prototype-এ একটি নতুন প্রোপার্টি যোগ করবে
  constructor.prototype.createdAt = new Date();
  console.log("Decorator has added a property!");
}

// ২. এবার ক্লাসটির উপরে ডেকোরেটরটি ব্যবহার করবো
@addCreationDate
class User {
  name: string;

  constructor(name: string) {
    this.name = name;
  }
}

// ৩. এখন ক্লাসের একটি ইন্সট্যান্স তৈরি করে দেখি
const user = new User("Alice");

// ডেকোরেটরের কারণে আমরা এখন createdAt প্রোপার্টিটি অ্যাক্সেস করতে পারবো
console.log(user); // আউটপুটে user অবজেক্টটি দেখাবে
console.log((user as any).createdAt); // আউটপুটে আজকের তারিখ ও সময় দেখাবে
```

**কীভাবে কাজ করলো?**
যখনই `User` ক্লাসটি তৈরি হলো, TypeScript দেখলো এর উপরে `@addCreationDate` ডেকোরেটরটি আছে। তখন সে `addCreationDate` ফাংশনটিকে কল করলো এবং `User` ক্লাসটিকে আর্গুমেন্ট হিসেবে পাঠিয়ে দিলো। ফাংশনটি তখন `User` ক্লাসের `prototype`-এ `createdAt` নামে একটি নতুন প্রোপার্টি যোগ করে দিলো।

#### ২. মেথড ডেকোরেটর (Method Decorator)

এটি ক্লাসের কোনো নির্দিষ্ট মেথডের উপর কাজ করে। এর মাধ্যমে আমরা মেথড কল হওয়ার আগে বা পরে কোনো কাজ করতে পারি।

**উদাহরণ:** ধরুন আমরা একটি `@log` ডেকোরেটর বানাতে চাই যা কোনো মেথড কল হলে কনসোলে একটি মেসেজ দেখাবে।

```typescript
// ১. মেথড ডেকোরেটর ফাংশনটি বানাবো
// এটি তিনটি আর্গুমেন্ট পায়: target, propertyKey, এবং descriptor
function log(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value; // আসল মেথডটিকে আমরা সেভ করে রাখলাম

  // আসল মেথডটির আচরণ আমরা পরিবর্তন করছি
  descriptor.value = function(...args: any[]) {
    console.log(`Calling method: "${propertyKey}" with arguments: ${JSON.stringify(args)}`);
    
    // আসল মেথডটিকে কল করছি
    const result = originalMethod.apply(this, args);
    
    console.log(`Method "${propertyKey}" returned: ${result}`);
    return result;
  };

  return descriptor;
}

// ২. এবার একটি ক্লাসের মেথডের উপরে ডেকোরেটরটি ব্যবহার করবো
class Calculator {
  @log // add মেথডটিকে log ডেকোরেটর দিয়ে সাজালাম
  add(a: number, b: number): number {
    return a + b;
  }
}

// ৩. এখন মেথডটি কল করে দেখি
const calc = new Calculator();
calc.add(5, 3);
```

**আউটপুট:**

```
Calling method: "add" with arguments: [5,3]
Method "add" returned: 8
```

**কীভাবে কাজ করলো?**
`@log` ডেকোরেটরটি `add` মেথডের আসল কোডটিকে প্রথমে একটি ভ্যারিয়েবলে (`originalMethod`) রেখে দেয়। তারপর সে `add` মেথডের কাজকে পরিবর্তন করে নতুন একটি ফাংশন বসিয়ে দেয়। এই নতুন ফাংশনটি প্রথমে একটি লগ মেসেজ প্রিন্ট করে, তারপর আসল `add` মেথডটিকে কল করে, এবং শেষে রেজাল্টটি প্রিন্ট করে।

অর্থাৎ, ডেকোরেটরটি `add` মেথডকে একটি মোড়কের (wrapper) মধ্যে রেখে দিয়েছে, যা মেথডটি চলার আগে ও পরে অতিরিক্ত কাজ করছে।

### সারসংক্ষেপ (Summary)

*   **Decorator** হলো একটি `@` চিহ্নযুক্ত ফাংশন।
*   এটি ক্লাস, মেথড বা প্রোপার্টিকে সরাসরি পরিবর্তন না করে তার ক্ষমতা বাড়ায়।
*   এটি কোডকে পরিষ্কার রাখে এবং একই কাজ বারবার লেখা থেকে বাঁচায়।
*   এটি Angular, NestJS এর মতো ফ্রেমওয়ার্কগুলোতে ব্যাপকভাবে ব্যবহৃত হয়।

আশা করি, এই সহজ ব্যাখ্যা এবং উদাহরণগুলোর মাধ্যমে আপনি ডেকোরেটরের ধারণাটি পরিষ্কারভাবে বুঝতে পেরেছেন


ঠিক আছে, কোনো সমস্যা নেই। আমি আরও সহজ করে, একটি বাস্তব জীবনের উদাহরণ দিয়ে বোঝাচ্ছি।

ধরুন, আপনার একটি ঘর আছে।

**মূল জিনিসটা হলো:** **`ঘর`** (এটাকে আপনার Class বা Method মনে করুন)।

এখন, আপনি এই ঘরের দরজায় একজন **`সিকিউরিটি গার্ড`** বসালেন।

এই **সিকিউরিটি গার্ড**-টাই হলো একটি **ডেকোরেটর (Decorator)**।

এবার ভাবুন তো, সিকিউরিটি গার্ড কী করে?
1.  ঘরে কেউ ঢোকার **আগে** সে চেক করে (যেমন: আইডি কার্ড দেখে)।
2.  ঘর থেকে কেউ বের হওয়ার **পরেও** সে খেয়াল রাখতে পারে।
3.  কিন্তু গার্ড কিন্তু ঘরের ভেতরের কোনো কিছু পরিবর্তন করে না। ঘরের ভেতরে যা কাজ হওয়ার, তা তেমনই হয়।

**ডেকোরেটর ঠিক এই সিকিউরিটি গার্ডের মতোই কাজ করে:**

*   **ডেকোরেটর** হলো একটি বাইরের ফাংশন (ঐ গার্ডের মতো)।
*   আপনি যখন কোনো মেথড বা ক্লাসের উপরে `@` চিহ্ন দিয়ে ডেকোরেটরের নাম লেখেন, তার মানে হলো আপনি ঐ মেথডের দরজায় একজন গার্ড বসিয়ে দিলেন।
*   ফলে, আপনার মূল মেথডটি কল হওয়ার **আগে** ডেকোরেটরটি তার নিজের কাজ সেরে নিতে পারে।

### চলুন কোডের উদাহরণ দেখি (সিকিউরিটি গার্ডের উদাহরণ দিয়ে)

আমরা একটি ক্লাস বানাবো যার নাম `SecretRoom`। এর ভেতরে একটি মেথড থাকবে `enter()`। আমরা চাই, কেউ `enter()` মেথড কল করার আগে যেন কনসোলে একটি মেসেজ দেখায় "Checking credentials..."।

এই "Checking credentials..." মেসেজটি দেখানোর কাজটাই করবে আমাদের ডেকোরেটর।

**ধাপ ১: আমাদের ডেকোরেটর ফাংশন (সিকিউরিটি গার্ড)**

এই ফাংশনটার নাম দিলাম `checkAccess`।

```typescript
// এই ফাংশনটাই আমাদের সিকিউরিটি গার্ড
function checkAccess(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value; // ঘরের আসল কাজটা (enter) এখানে সেভ করে রাখলাম

  // এখন আমরা আসল কাজটাকে একটু ಬದಲಾಯ করছি
  descriptor.value = function(...args: any[]) {
    // >> মূল কাজ শুরু হওয়ার আগের কাজ <<
    console.log(`গার্ড: ভেতরে ঢোকার আগে আপনার পরিচয় চেক করা হচ্ছে...`);
    
    // এবার ঘরের আসল কাজটা (enter) করতে দিচ্ছি
    originalMethod.apply(this, args); 
  };
}
```

**ধাপ ২: আমাদের ক্লাস (গোপন ঘর)**

এবার আমরা আমাদের ক্লাস আর মেথড বানাবো এবং তার দরজায় গার্ড বসিয়ে দেব।

```typescript
class SecretRoom {
  
  // `@checkAccess` দিয়ে আমরা enter() মেথডের দরজায় গার্ড বসিয়ে দিলাম
  @checkAccess 
  enter() {
    console.log("আপনি এখন গোপন ঘরের ভেতরে আছেন।");
  }
}
```

**ধাপ ৩: প্রোগ্রাম চালানো**

এখন যদি কেউ `SecretRoom`-এর `enter()` মেথডটিকে কল করে, তাহলে কী হবে দেখুন।

```typescript
const room = new SecretRoom();
room.enter();
```

**আউটপুট:**

```
গার্ড: ভেতরে ঢোকার আগে আপনার পরিচয় চেক করা হচ্ছে...
আপনি এখন গোপন ঘরের ভেতরে আছেন।
```

**কী হলো এখানে?**

1.  আমরা `room.enter()` কল করেছি।
2.  কিন্তু `enter()` মেথডের নিজের কোড চলার আগে, TypeScript দেখলো এর মাথায় `@checkAccess` ডেকোরেটর (গার্ড) বসে আছে।
3.  তাই সে প্রথমে `@checkAccess` ডেকোরেটরের ভেতরের কোডটি চালাল। ফলে, "গার্ড: ভেতরে ঢোকার আগে আপনার পরিচয় চেক করা হচ্ছে..." লেখাটি প্রিন্ট হলো।
4.  তারপর ডেকোরেটরটি মূল `enter()` মেথডটিকে চলার অনুমতি দিলো। তখন "আপনি এখন গোপন ঘরের ভেতরে আছেন।" লেখাটি প্রিন্ট হলো।

**মূল কথা:**

আমরা কিন্তু `SecretRoom` ক্লাসের ভেতরের কোডে `console.log("গার্ড...")` এই লাইনটা লিখিনি। এই ক্ষমতাটা বাইরে থেকে যোগ করেছে আমাদের **ডেকোরেটর**।

**সারসংক্ষেপ:**

*   **ডেকোরেটর** হলো একটি সাহায্যকারী ফাংশন।
*   একে `@` চিহ্ন দিয়ে কোনো ক্লাস বা মেথডের উপরে বসানো হয়।
*   এটি মূল কোডকে না বদলিয়ে তার আগে বা পরে নতুন কাজ যোগ করার ক্ষমতা দেয়।

================================================

অবশ্যই! ডেকোরেটরে প্যারামিটার (Parameter) কীভাবে ব্যবহার করতে হয়, সেটা আরও সহজ একটি উদাহরণ দিয়ে বোঝাচ্ছি।

### প্যারামিটার কেন দরকার? (Why do we need parameters?)

আগের উদাহরণে আমাদের সিকিউরিটি গার্ড সবার জন্য একই কাজ করছিল—শুধু ভেতরে ঢোকার আগে একটি মেসেজ দেখাচ্ছিল।

কিন্তু যদি এমন দরকার হয়:
*   শুধুমাত্র **"Admin"** রোল থাকলে একজন ইউজার একটি নির্দিষ্ট কাজ করতে পারবে।
*   অন্য কোনো কাজের জন্য **"Editor"** রোল হলেই চলবে।

এখানে ডেকোরেটরকে বলে দিতে হবে যে সে কোন রোলের জন্য চেক করবে ("Admin" নাকি "Editor")। এই তথ্যটিই আমরা **প্যারামিটার** হিসেবে পাঠাবো।

যখন কোনো ডেকোরেটরে প্যারামিটার ব্যবহার করা হয়, তখন সেটি একটি সাধারণ ফাংশন থাকে না। এটি একটি **"ডেকোরেটর ফ্যাক্টরি" (Decorator Factory)** হয়ে যায়।

**সহজ ভাষায়, ডেকোরেটর ফ্যাক্টরি হলো এমন একটি ফাংশন যা আপনার দেওয়া প্যারামিটার অনুযায়ী আপনার জন্য একটি নতুন ডেকোরেটর ফাংশন তৈরি করে এবং রিটার্ন করে।**

এটা অনেকটা বিস্কুট তৈরির ছাঁচের মতো। আপনি ছাঁচকে (ফ্যাক্টরি) বলে দিচ্ছেন কী আকারের বিস্কুট (ডেকোরেটর) বানাতে হবে, আর সে সেই অনুযায়ী বিস্কুট বানিয়ে দিচ্ছে।

---

### কীভাবে কাজ করে?

একটি প্যারামিটারসহ ডেকোরেটরের দুটি অংশ থাকে:
1.  **বাইরের ফাংশন (The Factory):** এটি আপনার প্যারামিটারগুলো গ্রহণ করে (যেমন: `role: "admin"`)।
2.  **ভেতরের ফাংশন (The Actual Decorator):** বাইরের ফাংশনটি এই ভেতরের ফাংশনটিকে `return` করে, আর TypeScript এই রিটার্ন করা ফাংশনটিকেই আসল ডেকোরেটর হিসেবে ব্যবহার করে।

---

### উদাহরণের মাধ্যমে বুঝি

চলুন, আমরা একটি `@hasRole` ডেকোরেটর বানাবো। এই ডেকোরেটরটি একটি রোল (role) প্যারামিটার হিসেবে নেবে এবং চেক করবে যে বর্তমান ইউজারের সেই রোল আছে কি না। যদি থাকে, তাহলেই শুধু মেথডটি কাজ করবে।

**ধাপ ১: ডেকোরেটর ফ্যাক্টরি তৈরি করা (`hasRole`)**

```typescript
// একটি ডামি ইউজার অবজেক্ট, যার রোল আমরা চেক করবো
const currentUser = {
  name: "Bob",
  role: "editor" // এখন ইউজারের রোল "editor"
};

// এটি আমাদের ডেকোরেটর ফ্যাক্টরি
function hasRole(requiredRole: string) {
  console.log(`ডেকোরেটর ফ্যাক্টরি কল হয়েছে। প্রয়োজনীয় রোল: ${requiredRole}`);
  
  // এই ফ্যাক্টরি একটি নতুন ডেকোরেটর ফাংশন রিটার্ন করছে
  return function(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;

    descriptor.value = function(...args: any[]) {
      // আসল মেথড কল করার আগে আমরা রোল চেক করবো
      if (currentUser.role === requiredRole) {
        console.log(`অনুমতি আছে! ইউজার "${currentUser.name}" এর রোল "${currentUser.role}"।`);
        // ইউজারের রোল ঠিক থাকলে আসল মেথডটি কল হবে
        originalMethod.apply(this, args);
      } else {
        // রোল না মিললে, একটি error দেখানো হবে এবং মেথডটি কাজ করবে না
        console.error(`অনুমতি নেই! এই কাজটি করার জন্য "${requiredRole}" রোল প্রয়োজন।`);
      }
    };
  };
}

// এবার ক্লাস তৈরি করি
class ContentManager {
  
  // এই মেথডটি শুধুমাত্র "admin" রোল থাকলেই চলবে
  @hasRole("admin")
  deletePost() {
    console.log("পোস্ট ডিলিট করা হয়েছে।");
  }

  // এই মেথডটি "editor" রোল থাকলেই চলবে
  @hasRole("editor")
  editPost() {
    console.log("পোস্ট এডিট করা হয়েছে।");
  }
}
```

**ধাপ ২: প্রোগ্রাম চালানো**

এবার আমরা `ContentManager` ক্লাসের মেথডগুলো কল করে দেখি কী হয়।

```typescript
const manager = new ContentManager();

console.log("\n--- ডিলিট করার চেষ্টা করা হচ্ছে ---");
manager.deletePost(); // এটি কাজ করবে না, কারণ ইউজারের রোল "editor"

console.log("\n--- এডিট করার চেষ্টা করা হচ্ছে ---");
manager.editPost();   // এটি কাজ করবে, কারণ ইউজারের রোল "editor"
```

**আউটপুট:**

```
ডেকোরেটর ফ্যাক্টরি কল হয়েছে। প্রয়োজনীয় রোল: admin
ডেকোরেটর ফ্যাক্টরি কল হয়েছে। প্রয়োজনীয় রোল: editor

--- ডিলিট করার চেষ্টা করা হচ্ছে ---
অনুমতি নেই! এই কাজটি করার জন্য "admin" রোল প্রয়োজন।

--- এডিট করার চেষ্টা করা হচ্ছে ---
অনুমতি আছে! ইউজার "Bob" এর রোল "editor"।
পোস্ট এডিট করা হয়েছে।
```

**কীভাবে কাজ করলো?**

1.  যখন TypeScript `ContentManager` ক্লাসটি তৈরি করছিল, তখন সে দেখলো:
    *   `deletePost()` এর উপরে `@hasRole("admin")` আছে। সে সাথে সাথে `hasRole` ফাংশনটিকে `"admin"` প্যারামিটার দিয়ে কল করলো। এই ফাংশনটি একটি নতুন ডেকোরেটর ফাংশন তৈরি করে `deletePost`-এর উপর লাগিয়ে দিলো।
    *   `editPost()` এর উপরে `@hasRole("editor")` আছে। একইভাবে, সে `hasRole` ফাংশনটিকে `"editor"` প্যারামিটার দিয়ে কল করলো এবং রিটার্ন হওয়া ডেকোরেটরটিকে `editPost`-এর উপর লাগিয়ে দিলো।
2.  যখন আমরা `manager.deletePost()` কল করলাম, তখন `deletePost`-এর গায়ে লাগানো ডেকোরেটরটি কাজ শুরু করলো। সে দেখলো প্রয়োজনীয় রোল `"admin"`, কিন্তু `currentUser.role` হলো `"editor"`। তাই সে একটি error মেসেজ দেখালো।
3.  যখন আমরা `manager.editPost()` কল করলাম, তখন এর ডেকোরেটরটি দেখলো প্রয়োজনীয় রোল `"editor"` এবং `currentUser.role`-ও `"editor"`। তাই সে মূল `editPost` মেথডটিকে কাজ করতে দিলো।

### সারসংক্ষেপ

*   ডেকোরেটরে প্যারামিটার ব্যবহার করতে হলে আপনাকে একটি **ডেকোরেটর ফ্যাক্টরি** বানাতে হবে।
*   ডেকোরেটর ফ্যাক্টরি হলো একটি **ফাংশন যা আরেকটি ফাংশন রিটার্ন করে**।
*   **বাইরের ফাংশনটি** আপনার প্যারামিটারগুলো নেয়।
*   **ভেতরের (রিটার্ন হওয়া) ফাংশনটি** আসল ডেকোরেটরের কাজ করে।
*   এভাবে আপনি একটি ডেকোরেটরকে বিভিন্ন পরিস্থিতিতে বিভিন্নভাবে ব্যবহার করার জন্য কনফিগার করতে পারেন।
