# 🧩 Module 1: Introduction - স্থাপত্য কি এবং কেন?

### Lesson 1.1: Monolith আসলে কি? (সেই খিচুড়ি রান্না)
**Explanation:** মনোলিথিক (Monolithic) হলো ব্যাচেলর মেসের খিচুড়ি রান্নার মতো। চাল, ডাল, আলু, মশলা সব এক পাতিলে দিয়ে রান্না করা। সব কোড এক জায়গায়, এক ফোল্ডারে বা এলোমেলো ভাবে থাকে। ছোট প্রজেক্টের জন্য এটা সেরা, কিন্তু প্রজেক্ট বড় হলে? তখন কোন আলুটা পচা তা খুঁজে বের করা অসম্ভব হয়ে যায়!

**Analogy:** বিয়ে বাড়ির বড় ডেকচিতে রান্না। যদি লবণে সমস্যা হয়, পুরো ডেকচির খাবার নষ্ট।

### Lesson 1.2: Modular Monolith কি? (বুফে সিস্টেম)
**Explanation:** মডুলার মনোলিথ হলো একই বিয়ে বাড়ি (Single Repository/Server), কিন্তু খাবারগুলো আলাদা আলাদা বাটিতে সাজানো (Buffet System)। ভাতের জন্য আলাদা স্টেশন, মাংসের জন্য আলাদা, ডেজার্টের জন্য আলাদা। কিন্তু সবাই এক ছাদের নিচেই আছে।

**Analogy:** আপনার ওয়ারড্রোব। শার্টের তাকে শার্ট, প্যান্টের তাকে প্যান্ট। শার্ট খুঁজতে গিয়ে প্যান্টের ভাঁজ নষ্ট হয় না।

### Lesson 1.3: কেন Microservices এখনই নয়?
**Explanation:** অনেকে শুরুতেই Microservices (আলাদা আলাদা রেস্টুরেন্ট) দিতে চায়। ভাই, আপনার ইউজার মাত্র ১০০ জন, আপনি কেন ১০টা সার্ভার ভাড়া করবেন? Modular Monolith আপনাকে Microservices এর "স্বাদ" দেয়, কিন্তু Monolith এর "সহজ" সেটআপ রাখে। যখন কোম্পানি বড় হবে (Google/Netflix লেভেল), তখন মডিউলগুলো ছিঁড়ে আলাদা করা সহজ হবে।

# 🧩 Module 2: Node.js + Express Architecture Basics

### Lesson 2.1: The Perfect Folder Structure (ঘর সাজানো)
**Explanation:** একটা ভালো ফোল্ডার স্ট্রাকচার হলো আর্কিটেকচারের মেরুদণ্ড। আমরা `src` এর ভেতর `modules` নামে ফোল্ডার রাখব।

**Analogy:** একটা অফিস বিল্ডিং।
- `modules/` = আলাদা ডিপার্টমেন্ট (HR, Accounts, IT)।
- `shared/` = কমন এরিয়া (লিফট, ক্যান্টিন)।

**Code Example (Folder Structure):**
```text
src/
├── app.ts              # মেইন এন্ট্রি পয়েন্ট
├── config/             # কনফিগারেশন (env vars)
├── shared/             # যা সবার লাগবে (Logger, Errors)
│   ├── middlewares/
│   ├── utils/
└── modules/            # আসল খেলা এখানে
    ├── User/           # ইউজার ডিপার্টমেন্ট
    │   ├── user.controller.ts
    │   ├── user.service.ts
    │   ├── user.model.ts
    │   ├── user.routes.ts
    │   └── user.interface.ts
    ├── Product/        # প্রোডাক্ট ডিপার্টমেন্ট
    └── Order/          # অর্ডার ডিপার্টমেন্ট
```

# 🧩 Module 3: Creating Modules (User Module)

### Lesson 3.1: Separation of Concerns (কে কোন কাজ করবে?)
**Analogy:** রেস্টুরেন্ট ম্যানেজমেন্ট।
1.  **Route:** রিসিপশনিস্ট। কাস্টমারকে সঠিক টেবিলে পাঠায়।
2.  **Controller:** ওয়েটার। অর্ডার নেয় এবং খাবার সার্ভ করে। নিজে রান্না করে না।
3.  **Service:** শেফ (Chef)। আসল রান্না (Business Logic) ইনি করেন।
4.  **Model/Repository:** স্টোর কিপার। ফ্রিজ থেকে মাছ-মাংস বের করে দেয় (Database Query)।

### Lesson 3.2: Creating User Controller & Service
**Code Example:**

```javascript
// src/modules/User/user.controller.js
// ওয়েটার মামা: অর্ডার নিবে (req), শেফকে দিবে, খাবার এনে দিবে (res)

const userService = require('./user.service');

const registerUser = async (req, res, next) => {
    try {
        // ওয়েটার: স্যার কি কি খেতে চান? (Body থেকে ডাটা নেওয়া)
        const userData = req.body;
        
        // ওয়েটার: শেফ (Service), এই ডাটা দিয়ে ইউজার বানাও
        const result = await userService.createUserIntoDB(userData);
        
        // ওয়েটার: স্যার, আপনার খাবার (Response)
        res.status(201).json({
            success: true,
            message: "User registered successfully!",
            data: result
        });
    } catch (error) {
        next(error); // সমস্যা হলে ম্যানেজারকে (Global Error Handler) ডাকো
    }
};

module.exports = { registerUser };
```

```javascript
// src/modules/User/user.service.js
// শেফ মামা: আসল রান্না ইনি করবেন

const User = require('./user.model'); // স্টোর কিপার

const createUserIntoDB = async (userData) => {
    // শেফ: মশলা চেক করা (Business Logic)
    if (userData.role === 'admin') {
        throw new Error("Direct admin creation not allowed!"); // ঝারি দেওয়া
    }

    // শেফ: স্টোর কিপার, ডাটাবেসে রাখো
    const result = await User.create(userData);
    return result;
};

module.exports = { createUserIntoDB };
```

**Explanation:** দেখেছেন? কন্ট্রোলার জানে না কিভাবে ডাটা সেভ হয়, সে শুধু রিকোয়েস্ট আর রেসপন্স চিনে। সার্ভিস জানে না রিকোয়েস্ট কোথা থেকে এলো, সে শুধু লজিক বুঝে। একেই বলে **Separation of Concerns**।

# 🧩 Module 4: Core Module Architecture (Shared Kernel)

### Lesson 4.1: The Utility Belt (SendResponse)
**Explanation:** বারবার `res.status(200).json(...)` লেখা বিরক্তিকর। আমরা একটা কমন ফাংশন বানাবো।

**Analogy:** সিল মারা। বারবার হাতে না লিখে একটা সিল (Stamp) বানিয়ে নেওয়া।

**Code Example:**
```javascript
// src/shared/utils/sendResponse.js
const sendResponse = (res, data) => {
    res.status(data.statusCode).json({
        success: data.success,
        message: data.message,
        data: data.data,
    });
};

module.exports = sendResponse;
```

# 🧩 Module 5: Database Integration

### Lesson 5.1: Mongoose Setup & Connection
**Explanation:** আমরা `server.js` বা `app.js` এ ডাটাবেস কানেক্ট করব। মডুলার সিস্টেমে একটাই ডাটাবেস কানেকশন থাকে, কিন্তু স্কিমাগুলো আলাদা ফোল্ডারে থাকে।

**Analogy:** পুরো বিল্ডিংয়ের মেইন পাওয়ার সাপ্লাই একটাই (DB Connection), কিন্তু প্রতিটা রুমে (Module) আলাদা সুইচবোর্ড (Schema) আছে।

**Code Example:**
```javascript
// src/modules/User/user.model.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
    email: { type: String, required: true, unique: true },
    password: { type: String, required: true },
    role: { type: String, enum: ['user', 'admin'], default: 'user' }
});

// মডেল এক্সপোর্ট
const User = mongoose.model('User', userSchema);
module.exports = User;
```

# 🧩 Module 6: Communication Between Modules (Most Important!)

### Lesson 6.1: Service to Service Call (Direct Communication)
**Explanation:** ধরুন `Order Module` কে জানতে হবে `User` ভ্যালিড কিনা। সে সরাসরি `User Service` কল করতে পারে। কিন্তু সাবধান! Circular Dependency (A ডাকে B কে, B ডাকে A কে) যেন না হয়।

**Analogy:** পাশের ফ্ল্যাটের ভাবীর কাছ থেকে চিনি ধার চাওয়া।

### Lesson 6.2: Logical Independence (index.js export pattern)
প্রতিটা মডিউলের একটা `index.js` থাকবে যেটা হবে ওই মডিউলের দরজা (Public API)।

**Code Structure:**
```text
src/modules/User/
├── index.js  <-- এই ফাইলটা ঠিক করবে বাইরের দুনিয়া কি দেখবে
```

```javascript
// src/modules/User/index.js
const userService = require('./user.service');
const userController = require('./user.controller');
const userRoutes = require('./user.routes');

// বাইরের মডিউল শুধু সার্ভিস বা নির্দিষ্ট ফাংশন এক্সেস করতে পারবে
module.exports = {
    UserRoutes: userRoutes,
    UserService: {
        findUserById: userService.findUserById // শুধু দরকারি জিনিস এক্সপোর্ট
    }
};
```

# 🧩 Module 7: Middleware & Cross-cutting Concerns

### Lesson 7.1: Global Error Handler (The Cleaner)
**Analogy:** রেস্টুরেন্টে প্লেট ভাঙলে বা কাস্টমার বমি করলে "ক্লিনার মামা" এসে পরিষ্কার করে। কোডে এরর হলে এই মিডলওয়্যার সেটা হ্যান্ডেল করে সুন্দর মেসেজ দিবে।

**Code Example:**
```javascript
// src/shared/middlewares/globalErrorHandler.js
const globalErrorHandler = (err, req, res, next) => {
    // ডিফল্ট স্ট্যাটাস ও মেসেজ
    let statusCode = 500;
    let message = 'Something went wrong!';

    // যদি এররটা আমাদের পরিচিত হয়
    if (err.name === 'ValidationError') {
        statusCode = 400;
        message = 'Data Validation Error Boss!';
    }

    res.status(statusCode).json({
        success: false,
        message,
        errorMessages: err.message,
        stack: process.env.NODE_ENV === 'development' ? err.stack : undefined
    });
};

module.exports = globalErrorHandler;
```

# 🧩 Module 8: Authentication + Authorization

### Lesson 8.1: Auth is a Module too!
**Explanation:** অথেনটিকেশন নিজেই একটা মডিউল হতে পারে, অথবা `User` মডিউলের অংশ হতে পারে। আমরা এটাকে আলাদা `Auth` মডিউল হিসেবে বানাবো যাতে ফিউচারে আলাদা করা যায়।

**Analogy:** অফিসের সিকিউরিটি চেকপোস্ট। আইডি কার্ড (Token) দেখা ছাড়া ঢুকতে দিবে না।

**Process:**
1.  User login করে -> Server `Access Token` (JWT) দেয়।
2.  পরের বার User সেই Token নিয়ে আসে।
3.  `authMiddleware` চেক করে টোকেন আসল কিনা।

# 🧩 Module 9: Real Modular Project (E-Commerce)

### Lesson 9.1: Building the "Order" Module
এখন আমরা `User` এবং `Product` মডিউলের সাথে `Order` মডিউল কানেক্ট করব।

**Scenario:** ইউজার একটা প্রোডাক্ট অর্ডার করবে।
1.  **Order Service:** প্রথমে `Product Service` কে কল করে চেক করবে স্টক আছে কিনা।
2.  **Order Service:** স্টক থাকলে অর্ডার ক্রিয়েট করবে।
3.  **Order Service:** `Product Service` কে বলবে স্টক কমাতে (Database Transaction জরুরি এখানে)।

**Code Example (Order Service Logic):**
```javascript
// src/modules/Order/order.service.js
const mongoose = require('mongoose');
const { ProductService } = require('../Product'); // মডিউল থেকে ইমপোর্ট
const Order = require('./order.model');

const createOrder = async (orderData) => {
    const session = await mongoose.startSession();
    try {
        session.startTransaction();

        // ১. প্রোডাক্ট চেক করা (অন্য মডিউল থেকে)
        const product = await ProductService.getProductById(orderData.productId);
        if(product.stock < orderData.quantity) {
            throw new Error('Not enough stock mama!');
        }

        // ২. অর্ডার বানানো
        const newOrder = await Order.create([orderData], { session });

        // ৩. স্টক কমানো (অন্য মডিউল কল করে)
        await ProductService.decreaseStock(orderData.productId, orderData.quantity, session);

        await session.commitTransaction();
        return newOrder;
    } catch (error) {
        await session.abortTransaction();
        throw error;
    } finally {
        session.endSession();
    }
};
```
**Explanation:** এখানে `session` ব্যবহার করা হয়েছে যাতে অর্ডার ফেইল হলে স্টক কমে না যায়। একে বলে **ACID Property**।


### Lesson 10.3: When to scale?
যখন দেখবেন আপনার `User Module` এ ১ মিলিয়ন রিকোয়েস্ট আসছে কিন্তু `Product Module` এ মাত্র ১০টা, তখন পুরো অ্যাপ কপি না করে শুধু `User Module` টাকে আলাদা সার্ভারে নিয়ে যাবেন। এটাই Modular Monolith এর সৌন্দর্য— **Microservices Ready!**

# 🏁 সমাপ্তি কথা (Conclusion)

বন্ধুরা, আমরা দেখলাম কিভাবে একটা জগাখিচুড়ি কোডবেস থেকে বের হয়ে একটা সুন্দর, গোছানো **Modular Monolithic** আর্কিটেকচার বানাতে হয়।

**মনে রাখবেন:**
1.  **DRY (Don't Repeat Yourself):** একই কোড বারবার লিখবেন না, `Shared` এ রাখুন।
2.  **KISS (Keep It Simple, Stupid):** জটিল করবেন না।
3.  **Consistency:** সব মডিউলে একই প্যাটার্ন ফলো করুন।

এই প্যাটার্ন ফলো করলে আপনার প্রজেক্ট হবে স্কেলেবল, ক্লিন এবং মেইনটেনেবল। এখন বস, এক কাপ চা নিন আর কোড করা শুরু করুন! হ্যাপি কোডিং! 💻☕️
