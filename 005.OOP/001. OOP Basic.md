অবশ্যই! Python-এর Object-Oriented Programming (OOP) এর মূল ধারণাগুলো একটি স্কুল ম্যানেজমেন্ট সিস্টেমের উদাহরণের মাধ্যমে বাংলায় নিচে ব্যাখ্যা করা হলো।

এখানে আমরা ধাপে ধাপে এনক্যাপসুলেশন, ইনহেরিট্যান্স, পলিমরফিজম, অ্যাবস্ট্রাকশন এবং প্রপার্টি ডেকোরেটর সম্পর্কে জানব।

### ভূমিকা: OOP এবং স্কুল ম্যানেজমেন্ট

OOP (Object-Oriented Programming) হলো প্রোগ্রামিং করার একটি পদ্ধতি যেখানে আমরা বাস্তব জগতের জিনিসগুলোকে (Object) কোডিং-এর মাধ্যমে তুলে ধরি। একটি স্কুল ম্যানেজমেন্ট সিস্টেমে, ছাত্র (Student), শিক্ষক (Teacher), বা কর্মচারী (Staff) হলো একেকটি অবজেক্ট। আর এই অবজেক্টগুলো তৈরির জন্য যে নকশা বা ব্লুপ্রিন্ট (blueprint) ব্যবহার করা হয়, তাকে বলে ক্লাস (Class)।

### ১. Encapsulation (এনক্যাপসুলেশন)

**ধারণা:** এনক্যাপসুলেশন মানে হলো ডেটা (attributes) এবং সেই ডেটাকে পরিবর্তন বা ব্যবহার করার পদ্ধতিগুলোকে (methods) একটি ক্লাসের মধ্যে আবদ্ধ করে রাখা। এর মূল উদ্দেশ্য হলো ডেটাকে বাইরের হস্তক্ষেপ থেকে সুরক্ষিত রাখা এবং শুধুমাত্র নির্দিষ্ট পদ্ধতির মাধ্যমে ডেটা অ্যাক্সেস করার অনুমতি দেওয়া।

**স্কুলের উদাহরণ:** একজন ছাত্রের আইডি কার্ড। ছাত্রের নাম, আইডি নম্বর (ডেটা) এবং তার তথ্য দেখার পদ্ধতি (মেথড) সবকিছু আইডি কার্ডের (অবজেক্ট) মধ্যে আবদ্ধ থাকে। আপনি সরাসরি ছাত্রের আইডি নম্বর পরিবর্তন করতে পারবেন না, আপনাকে একটি নির্দিষ্ট প্রক্রিয়ার (যেমন: অফিসের মাধ্যমে আবেদন করা) মধ্য দিয়ে যেতে হবে।

**Python কোড:**

```python
class Student:
    def __init__(self, name, student_id, grade):
        # এই ভ্যারিয়েবলগুলো private, তাই ডাবল আন্ডারস্কোর (__) ব্যবহার করা হয়েছে
        self.__name = name
        self.__student_id = student_id
        self.__grade = grade

    # ডেটা বাইরে দেখানোর জন্য public মেথড (Getter)
    def get_details(self):
        print(f"নাম: {self.__name}, আইডি: {self.__student_id}, ক্লাস: {self.__grade}")

    # ডেটা পরিবর্তন করার জন্য public মেথড (Setter)
    def update_grade(self, new_grade):
        if new_grade > 0 and new_grade <= 12:
            self.__grade = new_grade
            print(f"{self.__name}-এর ক্লাস সফলভাবে আপডেট করা হয়েছে।")
        else:
            print("ভুল ক্লাস নম্বর।")

# একটি Student অবজেক্ট তৈরি করা হলো
s1 = Student("রহিম শেখ", 101, 5)

# আমরা সরাসরি private ডেটা অ্যাক্সেস করতে পারবো না
# print(s1.__name) # এটি Error দেবে

# আমরা public মেথড ব্যবহার করে ডেটা দেখতে পারি
s1.get_details() # আউটপুট: নাম: রহিম শেখ, আইডি: 101, ক্লাস: 5

# public মেথড ব্যবহার করে ডেটা পরিবর্তন করতে পারি
s1.update_grade(6) # আউটপুট: রহিম শেখ-এর ক্লাস সফলভাবে আপডেট করা হয়েছে।
s1.get_details() # আউটপুট: নাম: রহিম শেখ, আইডি: 101, ক্লাস: 6
```
**ব্যাখ্যা:** এখানে `__name`, `__student_id` হলো private ডেটা। এগুলোকে ক্লাসের বাইরে থেকে সরাসরি অ্যাক্সেস করা যায় না। `get_details()` এবং `update_grade()` মেথডগুলো হলো public ইন্টারফেস, যার মাধ্যমে আমরা ঐ private ডেটাগুলোকে নিরাপদে ব্যবহার করতে পারছি। এটাই এনক্যাপসুলেশন।

### ২. Inheritance (ইনহেরিট্যান্স)

**ধারণা:** ইনহেরিট্যান্স মানে হলো "উত্তরাধিকার"। যখন একটি ক্লাস (Child Class) অন্য একটি ক্লাসের (Parent Class) সমস্ত বৈশিষ্ট্য (attributes এবং methods) পেয়ে যায়, তখন তাকে ইনহেরিট্যান্স বলে। এতে কোড পুনরায় ব্যবহার করা যায়।

**স্কুলের উদাহরণ:** স্কুলে 'শিক্ষক' (Teacher) এবং 'ছাত্র' (Student) দুজনেই এক একজন 'ব্যক্তি' (Person)। তাই তাদের কিছু সাধারণ বৈশিষ্ট্য থাকবে, যেমন - নাম, বয়স ইত্যাদি। আমরা একটি `Person` ক্লাস তৈরি করতে পারি এবং `Student` ও `Teacher` ক্লাস সেই `Person` ক্লাসের বৈশিষ্ট্যগুলো ইনহেরিট বা উত্তরাধিকার সূত্রে পেতে পারে।

**Python কোড:**

```python
# Parent Class
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def show_info(self):
        print(f"নাম: {self.name}, বয়স: {self.age}")

# Child Class (Student)
class Student(Person): # Person ক্লাসকে ইনহেরিট করছে
    def __init__(self, name, age, student_id):
        super().__init__(name, age) # Parent ক্লাসের __init__ কে কল করা
        self.student_id = student_id

    def show_info(self): # Parent এর মেথডকে ওভাররাইড করা যায়
        print(f"আমি একজন ছাত্র। নাম: {self.name}, আইডি: {self.student_id}")

# Child Class (Teacher)
class Teacher(Person): # Person ক্লাসকে ইনহেরিট করছে
    def __init__(self, name, age, subject):
        super().__init__(name, age)
        self.subject = subject
    
    def show_info(self):
        print(f"আমি একজন শিক্ষক। নাম: {self.name}, বিষয়: {self.subject}")

# অবজেক্ট তৈরি
student1 = Student("করিম", 12, 102)
teacher1 = Teacher("জনাব রফিক", 35, "গণিত")

student1.show_info() # আউটপুট: আমি একজন ছাত্র। নাম: করিম, আইডি: 102
teacher1.show_info() # আউটপুট: আমি একজন শিক্ষক। নাম: জনাব রফিক, বিষয়: গণিত
```
**ব্যাখ্যা:** `Student` এবং `Teacher` ক্লাস দুটি `Person` ক্লাস থেকে `name` এবং `age` বৈশিষ্ট্যগুলো পেয়েছে। ফলে আমাদের একই কোড বারবার লিখতে হয়নি। `super().__init__()` ব্যবহার করে আমরা Parent ক্লাসের কনস্ট্রাকটরকে কল করেছি।

### ৩. Polymorphism (পলিমরফিজম)

**ধারণা:** Polymorphism শব্দটি এসেছে দুটি গ্রিক শব্দ থেকে: "Poly" (অনেক) এবং "Morph" (রূপ)। এর মানে হলো "বহুরূপ"। OOP-তে পলিমরফিজম মানে হলো, একই নামের মেথড বিভিন্ন ক্লাসে বিভিন্ন রকম কাজ করতে পারে।

**স্কুলের উদাহরণ:** স্কুলে 'পরিচয় দেওয়া' (introduce) কাজটি ছাত্র এবং শিক্ষক ভিন্নভাবে করে। ছাত্র বলবে, "আমি একজন ছাত্র, আমার ক্লাস..." আর শিক্ষক বলবেন, "আমি একজন শিক্ষক, আমি এই বিষয় পড়াই..."। কাজটি একই (`introduce`), কিন্তু রূপ ভিন্ন।

**Python কোড:**
(আমরা উপরের Inheritance এর উদাহরণটিই ব্যবহার করব)

```python
# আগের Person, Student, Teacher ক্লাসগুলো এখানে আছে ধরা যাক

def print_introduction(person_obj):
    person_obj.show_info()

# অবজেক্ট তৈরি
student1 = Student("করিম", 12, 102)
teacher1 = Teacher("জনাব রফিক", 35, "গণিত")

# একই ফাংশন ভিন্ন ভিন্ন অবজেক্টের জন্য ভিন্ন কাজ করছে
print_introduction(student1) # Student এর show_info() কল হবে
print_introduction(teacher1) # Teacher এর show_info() কল হবে
```
**ব্যাখ্যা:** এখানে `print_introduction` ফাংশনটি জানে না যে তাকে `Student` অবজেক্ট দেওয়া হচ্ছে নাকি `Teacher` অবজেক্ট। সে শুধু `show_info()` মেথডটিকে কল করছে। অবজেক্টের ধরণের ওপর ভিত্তি করে Python নিজে থেকেই সঠিক `show_info()` মেথডটি (ছাত্রের জন্য ছাত্রের, শিক্ষকের জন্য শিক্ষকের) কল করছে। এটাই পলিমরফিজম।

### ৪. Abstraction (অ্যাবস্ট্রাকশন)

**ধারণা:** অ্যাবস্ট্রাকশন মানে হলো কোনো জটিল বিষয়কে আড়াল করে শুধুমাত্র প্রয়োজনীয় তথ্যগুলো ব্যবহারকারীর কাছে তুলে ধরা। ব্যবহারকারীকে জানতে হয় না ভেতরে কী ঘটছে, সে শুধু জানে কীভাবে এটি ব্যবহার করতে হয়।

**স্কুলের উদাহরণ:** একজন প্রিন্সিপাল যখন সফটওয়্যারে "সকল ছাত্রের রেজাল্ট তৈরি কর" বাটনে ক্লিক করেন, তখন তার জানার দরকার নেই যে সফটওয়্যারটি কীভাবে ডেটাবেস থেকে তথ্য আনছে, কীভাবে গ্রেড গণনা করছে বা কীভাবে PDF তৈরি করছে। তার কাছে শুধু বাটনটিই (প্রয়োজনীয় ইন্টারফেস) গুরুত্বপূর্ণ। এই পুরো জটিল প্রক্রিয়াটি তার কাছ থেকে আড়াল (abstract) করা হয়েছে।

**Python কোড:**
Python-এ অ্যাবস্ট্রাকশন `abc` (Abstract Base Classes) মডিউল দিয়ে实现 করা হয়।

```python
from abc import ABC, abstractmethod

# Abstract Class
class SchoolActivity(ABC):
    @abstractmethod
    def perform(self): # এটি একটি abstract মেথড
        pass

# Concrete Class
class Exam(SchoolActivity):
    def perform(self): # Abstract মেথডকে এখানে implement করতে হবে
        print("পরীক্ষা অনুষ্ঠিত হচ্ছে...")

# Concrete Class
class SportsDay(SchoolActivity):
    def perform(self): # Abstract মেথডকে এখানে implement করতে হবে
        print("বার্ষিক ক্রীড়া প্রতিযোগিতা চলছে...")

# আমরা Abstract ক্লাসের অবজেক্ট তৈরি করতে পারবো না
# activity = SchoolActivity() # এটি Error দেবে

exam = Exam()
sports = SportsDay()

exam.perform()   # আউটপুট: পরীক্ষা অনুষ্ঠিত হচ্ছে...
sports.perform() # আউটপুট: বার্ষিক ক্রীড়া প্রতিযোগিতা চলছে...
```
**ব্যাখ্যা:** `SchoolActivity` হলো একটি Abstract ক্লাস। এটি একটি নিয়ম বা কাঠামো তৈরি করে দিয়েছে যে, যে কোনো স্কুল অ্যাক্টিভিটির একটি `perform()` মেথড থাকতেই হবে। `Exam` এবং `SportsDay` ক্লাসগুলো সেই নিয়ম মেনে নিজেদের মতো করে `perform()` মেথডটি তৈরি (implement) করেছে।

### ৫. Property Decorator (@property)

**ধারণা:** `@property` ডেকোরেটর একটি মেথডকে সাধারণ অ্যাট্রিবিউট বা ভ্যারিয়েবলের মতো ব্যবহার করার সুযোগ দেয়। অর্থাৎ, আপনি মেথডকে কল করার সময় `()` ব্যবহার না করে সরাসরি ভ্যারিয়েবলের মতো অ্যাক্সেস করতে পারবেন। এটি ডেটা ভ্যালিডেশন এবং ক্যালকুলেটেড প্রপার্টি তৈরির জন্য খুব উপকারী।

**স্কুলের উদাহরণ:** একজন ছাত্রের পরীক্ষার মোট নম্বর এবং তার পাশের স্ট্যাটাস (Pass/Fail)। স্ট্যাটাসটি সরাসরি সেট করা হয় না, এটি নম্বরের ওপর নির্ভর করে গণনা করা হয়। কিন্তু আমরা যখন ছাত্রের স্ট্যাটাস জানতে চাই, তখন `student.status` লিখলেই যেন পেয়ে যাই, `student.calculate_status()` কল করতে না হয়।

**Python কোড:**

```python
class StudentResult:
    def __init__(self, name, marks):
        self.name = name
        self.__marks = marks # marks-কে private রাখা হলো

    @property
    def status(self):
        # এই মেথডটি একটি অ্যাট্রিবিউটের মতো কাজ করবে
        if self.__marks >= 40:
            return "Pass"
        else:
            return "Fail"
    
    @property
    def marks(self):
        # Getter: marks দেখার জন্য
        return self.__marks

    @marks.setter
    def marks(self, value):
        # Setter: marks সেট করার সময় ভ্যালিডেশন
        if 0 <= value <= 100:
            self.__marks = value
        else:
            print("ভুল নম্বর। নম্বর ০ থেকে ১০০ এর মধ্যে হতে হবে।")

# অবজেক্ট তৈরি
result = StudentResult("আরিফ", 75)

# status-কে অ্যাট্রিবিউটের মতো করে অ্যাক্সেস করা হচ্ছে, মেথডের মতো নয় (result.status() নয়)
print(f"{result.name}-এর স্ট্যাটাস: {result.status}") # আউটপুট: আরিফ-এর স্ট্যাটাস: Pass

# marks পরিবর্তন করা
result.marks = 35 # Setter কল হবে
print(f"নতুন নম্বর: {result.marks}") # Getter কল হবে
print(f"{result.name}-এর স্ট্যাটাস: {result.status}") # আউটপুট: আরিফ-এর স্ট্যাটাস: Fail

result.marks = 110 # Setter ভ্যালিডেশন কাজ করবে
# আউটপুট: ভুল নম্বর। নম্বর ০ থেকে ১০০ এর মধ্যে হতে হবে।
```
**ব্যাখ্যা:** এখানে `status` একটি মেথড হলেও `@property` ডেকোরেটরের কারণে আমরা এটিকে `result.status` হিসেবে অ্যাক্সেস করতে পারছি। একইভাবে, `marks` অ্যাট্রিবিউটের জন্য getter (`@property`) এবং setter (`@marks.setter`) তৈরি করা হয়েছে, যা ডেটাকে আরও নিয়ন্ত্রিত এবং ব্যবহারবান্ধব করে তুলেছে।
