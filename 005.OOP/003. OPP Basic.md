
প্রোগ্রামিং শেখার প্রাথমিক ধাপেই আমরা বিভিন্ন ডেটা টাইপের সঙ্গে পরিচিত হই — যেমন string, list, dictionary, tuple ইত্যাদি। এই ডেটা টাইপগুলো আমাদের বিভিন্ন ধরনের তথ্য সংরক্ষণ ও প্রক্রিয়াকরণের সুবিধা দেয়। কিন্তু সময়ের সাথে প্রোগ্রামের জটিলতা বাড়তে থাকলে শুধু এই বেসিক ডেটা টাইপ দিয়ে সবকিছু সামলানো কঠিন হয়ে পড়ে।

কেন OOP প্রয়োজন?

ধরুন, আপনি একটি মেশিন লার্নিং প্রজেক্ট করছেন যেখানে ছাত্রছাত্রীদের তথ্য, তাদের স্কোর, এবং মডেল ট্রেইনিং ডেটা নিয়ে কাজ করতে হচ্ছে। যদি সব তথ্য আলাদা আলাদা list, dict, বা variable-এ রাখেন, তাহলে কোডটি খুব দ্রুত জটিল হয়ে যাবে।

উদাহরণস্বরূপ:

student_names = ["রিমন", "সাবিনা", "অনিক"]
student_marks = [85, 90, 78]
student_ids = [101, 102, 103]

এভাবে ডেটা রাখা গেলেও, যদি কোনো ছাত্রের সমস্ত তথ্য একসাথে দরকার হয়, তখন একাধিক তালিকা থেকে সেই তথ্য সংগ্রহ করতে হবে। এটা শুধু সময়সাপেক্ষ নয়, বরং কোডের ভুল হওয়ার সম্ভাবনাও বাড়ে।

এখানেই Object-Oriented Programming (OOP) আমাদের সাহায্য করে।

OOP ধারণা অনুযায়ী, আমরা ডেটা ও ডেটার ওপর কাজ করা ফাংশনগুলোকে একসাথে একটি “অবজেক্ট”-এর মধ্যে বাঁধতে পারি। ফলে প্রোগ্রামটি হয় আরো সংগঠিত, সহজবোধ্য, এবং পুনঃব্যবহারযোগ্য (reusable)।

মেশিন লার্নিং (ML)-এর সাথে OOP-এর সম্পর্ক

মেশিন লার্নিং শেখার সময় আমরা মূলত বিভিন্ন মডেল, ডেটা প্রসেসিং পাইপলাইন, ও ট্রেনিং প্রক্রিয়া নিয়ে কাজ করি। এই প্রতিটি উপাদানকে OOP-এর ধারণা ব্যবহার করে আলাদা class ও object হিসেবে তৈরি করা যায়।

উদাহরণস্বরূপ:

1. Dataset class ডেটা লোড ও প্রিপ্রসেস করে
2. Model class মডেল ট্রেইন ও প্রেডিক্ট করে
3. Trainer class পুরো ট্রেইনিং লুপ পরিচালনা করে

এভাবে প্রজেক্টের প্রতিটি অংশ আলাদা হলেও তারা পরস্পরের সাথে সুন্দরভাবে যুক্ত থাকে।


8.2 Class and Objects Theory

প্রথম মডিউলে আমরা আলোচনা করেছি কেন OOP প্রয়োজন, এবং কীভাবে এটি কোডকে আরও সংগঠিত ও পুনঃব্যবহারযোগ্য করে তোলে।

এবার আমরা OOP-এর দুইটি মূল স্তম্ভের দিকে আসব — **Class** এবং **Object**।
এই দুই ধারণাই OOP-এর ভিত্তি। একটিকে না বুঝলে অন্যটি কখনো পূর্ণভাবে বোঝা যায় না।

**ক্লাস (Class) কী?**

সহজভাবে বলতে গেলে, **ক্লাস হলো কোনো কিছুর নকশা বা ছক (Blueprint)**।
এটা এমন একটা ছাঁচ, যার উপর ভিত্তি করে আমরা বাস্তব জগতের জিনিসগুলোকে প্রোগ্রামে তৈরি করি।
উদাহরণস্বরূপ, ধরুন আমরা একটি **Phone** নিয়ে ভাবছি।
যে কোনো ফোনের কিছু সাধারণ বৈশিষ্ট্য থাকে — যেমন:

1. ব্যাটারি ক্যাপাসিটি
2. প্রসেসর টাইপ
3. র&zwj;্যাম ও স্টোরেজ
4. ক্যামেরা স্পেসিফিকেশন

এগুলো হলো ফোনের **গুণাবলি (Attributes)**।
তাছাড়া ফোনের কিছু কাজও থাকে, যেমন:

1. ফোন চালু করা বা বন্ধ করা
2. চার্জ দেওয়া
3. কল করা বা মেসেজ পাঠানো

এগুলো হলো ফোনের **কার্যক্ষমতা বা আচরণ (Behaviors/Methods)**।

এখন, “Phone” নামের একটি ক্লাস তৈরি করলে সেটি এই সমস্ত বৈশিষ্ট্য ও আচরণের একটি **ধারণাগত কাঠামো** হিসেবে কাজ করবে।
অর্থাৎ, ক্লাস কেবল বলে দেয় — “একটি ফোনে কী কী থাকা উচিত, এবং সে কী করতে পারবে।”
কিন্তু ক্লাস নিজে কোনো বাস্তব ফোন নয়; এটি শুধু তার ডিজাইন।

**অবজেক্ট (Object) কী?**

**অবজেক্ট হলো সেই ক্লাসের বাস্তব রূপ (Instance)**।
যখন আমরা “Phone” ক্লাস থেকে একটি আসল ফোন তৈরি করি — যেমন “Samsung Galaxy S24” বা “iPhone 15” — তখন সেটি একটি অবজেক্ট।
অর্থাৎ,

1. **Class = নকশা (Design)**
2. **Object = বাস্তব রূপ (Real Entity)**

প্রত্যেকটি অবজেক্ট একই ক্লাসের নকশা অনুসরণ করে তৈরি হয়, কিন্তু তাদের মান (value) ভিন্ন হতে পারে।
যেমন,

1. Samsung ফোনে ব্যাটারি 5000mAh
2. iPhone-এ ব্যাটারি 3500mAh

দু’টোই “Phone” ক্লাস থেকে এসেছে, কিন্তু তাদের নির্দিষ্ট বৈশিষ্ট্য আলাদা।

### ক্লাস ও অবজেক্টের সম্পর্ক
ক্লাস এবং অবজেক্টের মধ্যে সম্পর্কটা অনেকটা **“ব্লুপ্রিন্ট ও বিল্ডিং”-এর মতো**।

1. ব্লুপ্রিন্ট ছাড়া বিল্ডিং বানানো যায় না (অর্থাৎ, ক্লাস ছাড়া অবজেক্ট হয় না)।
2. আবার ব্লুপ্রিন্ট থাকলেই বিল্ডিং তৈরি হয়ে যায় না (অর্থাৎ, ক্লাস লিখলেই প্রোগ্রামে কাজ শুরু হয় না; অবজেক্ট তৈরি করতে হয়)।

তাই,
**ক্লাস** হলো ধারণা (concept)।
**অবজেক্ট** হলো বাস্তব রূপ (instance)।


8.3 Class and Object implementation

আগের মডিউলে আমরা শিখেছিলাম, ক্লাস হচ্ছে কোনো কিছুর নকশা (Blueprint) এবং অবজেক্ট সেই নকশা অনুসারে তৈরি বাস্তব বস্তু (Instance)।

এবার আমরা দেখব, কিভাবে সেই ধারণাটি Python কোডের মাধ্যমে বাস্তবায়ন করা যায়।

**ক্লাস: Phone**

চলুন আমরা একটি ফোন কোম্পানির উদাহরণ নিই।
আমাদের প্রতিটি ফোনের কিছু সাধারণ গুণাবলি থাকবে — যেমন ব্যাটারি, ক্যামেরা, মডেল ইত্যাদি।
এছাড়াও ফোন কিছু কাজ করতে পারবে — যেমন চার্জ নেওয়া বা ছবি তোলা।

```python
class Phone:
    category = "Electronics"     # Class Attribute

    # Constructor
    def __init__(self, model, battery, camera, battery_percentage=100):
        self.model = model                    # Instance Attribute
        self.battery = battery                # Instance Attribute
        self.camera = camera                  # Instance Attribute
        self.battery_percentage = battery_percentage  # Instance Attribute

    # Methods
    def charge(self, hour):
        print(f"charge completed by {hour}")

    def capture(self, photo):
        if self.battery_percentage <= 0:
            print("No charge")
        else:
            self.battery_percentage -= photo
            print(f"photo captured in {self.model}")
```

### **ক্লাস অ্যাট্রিবিউট (Class Attribute)**

`category = "Electronics"`

1.  এটি একটি **ক্লাস অ্যাট্রিবিউট** — অর্থাৎ এটি পুরো ক্লাসের জন্য একবারেই নির্ধারিত হয়।
2.  সমস্ত অবজেক্ট (যেমন apple, blueberry, motorola) এই একই মানটি ভাগাভাগি করে ব্যবহার করে।
3.  কোনো একটি অবজেক্টের জন্য এই মান পরিবর্তন করলে সেটি শুধুমাত্র ঐ অবজেক্টে প্রযোজ্য হয় না, বরং ক্লাসের উপর নির্ভরশীল থাকে।

যে কোনো ফোনই হোক না কেন — Samsung, Apple, Motorola — সবগুলোই “Electronics” শ্রেণির অন্তর্ভুক্ত।
তাই এটি ক্লাসেরই একটি বৈশিষ্ট্য, আলাদা আলাদা ফোনের নয়।

**ইনস্ট্যান্স অ্যাট্রিবিউট (Instance Attribute)**

```python
def __init__(self, model, battery, camera, battery_percentage=100):
    self.model = model
    self.battery = battery
    self.camera = camera
    self.battery_percentage = battery_percentage
```

1.  \_\_init\_\_() হলো **constructor method** — যা অবজেক্ট তৈরি হওয়ার সময় স্বয়ংক্রিয়ভাবে চালু হয়।
2.  এখানে self প্রতিটি অবজেক্টের নিজস্ব (unique) রেফারেন্স বোঝায়।
3.  self.model, self.battery, self.camera ইত্যাদি হলো **ইনস্ট্যান্স অ্যাট্রিবিউট** — অর্থাৎ প্রতিটি অবজেক্টের জন্য আলাদা মান সংরক্ষণ করে।

Apple ফোনের ব্যাটারি 3000mAh হতে পারে, কিন্তু Motorola-র ব্যাটারি 3500mAh — তাই এই মানগুলো অবজেক্টভেদে আলাদা থাকে।

**মেথড (Methods)**

### **charge() মেথড**

```python
def charge(self, hour):
    print(f"charge completed by {hour}")
```

এটি ফোনের একটি **action** বা আচরণ বোঝায়।
যখন ফোন চার্জ নেয়, তখন এটি একটি বার্তা প্রিন্ট করে।
এই মেথড ফোনের কাজের মধ্যে পড়ে।

### **capture() মেথড**

```python
def capture(self, photo):
    if self.battery_percentage <= 0:
        print("No charge")
    else:
        self.battery_percentage -= photo
        print(f"photo captured in {self.model}")
```

এই মেথডের মাধ্যমে ফোন ছবি তোলে।
প্রতিবার ছবি তোলার সময় ব্যাটারির কিছু শতাংশ কমে যায়।
যদি ব্যাটারি শেষ হয়ে যায়, তাহলে ফোন “No charge” বার্তা দেয়।

self.battery\_percentage প্রতি অবজেক্টে আলাদা মানে পরিবর্তিত হয়।

**অবজেক্ট তৈরি করা (Creating Objects)**

```python
apple = Phone("Iphone17", 3000, 40)
blueberry = Phone("B-17", 4000, 30)
motorola = Phone("M-17", 3500, 35)
```

এখন আমরা “Phone” ক্লাস থেকে তিনটি **অবজেক্ট** তৈরি করলাম।
প্রতিটি অবজেক্টের নিজস্ব model, battery, এবং camera আছে।

### ধাপ ৫: মেথড কল করা ও মান দেখা

```python
apple.capture(10)
print(motorola.battery_percentage)
```

1.  apple.capture(10) মানে হলো Apple ফোন 10% ব্যাটারি ব্যবহার করে একটি ছবি তুলেছে।
2.  motorola.battery\_percentage দেখাবে Motorola ফোনের বর্তমান ব্যাটারি মান (এখনও 100%, কারণ এটি কোনো ছবি তোলে নি)।


8.4 OOP Inheritance

**ইনহেরিটেন্স কী?**

**Inheritance** শব্দের মানে হলো “উত্তরাধিকার সূত্রে পাওয়া।”
OOP–এ ইনহেরিটেন্স মানে হলো — **একটি ক্লাস অন্য একটি ক্লাসের বৈশিষ্ট্য (attributes) ও ফাংশনালিটি (methods) উত্তরাধিকার সূত্রে পায়**।
অর্থাৎ, আমরা আগের কোনো ক্লাসের কোড পুনরায় না লিখে, সেটি থেকে নতুন একটি ক্লাস তৈরি করতে পারি।
এটি কোডকে **পরিষ্কার (clean)**, **সংগঠিত (organized)**, এবং **পুনঃব্যবহারযোগ্য (reusable)** করে।

### **কেন ইনহেরিটেন্স দরকার?**

আমরা ইতিমধ্যেই একটি Phone ক্লাস লিখেছি, যেখানে ব্যাটারি, ক্যামেরা, এবং চার্জ দেওয়ার ফিচার আছে।

এখন আমরা “SmartPhone” নামে নতুন একটি ক্লাস বানাতে চাই — যেখানে আগের সব ফিচার থাকবে, তবে কিছু নতুন ক্ষমতাও যোগ হবে, যেমন **প্রসেসর** এবং **ফাস্ট চার্জিং**।

এক্ষেত্রে আমাদের Phone ক্লাসের কোড আবার লেখার দরকার নেই।
আমরা চাইলে সেটি **ইনহেরিট** করতে পারি।

**Single Inheritance**

একক ইনহেরিটেন্সে একটি **child class (derived class)** একটি **parent class (base class)**–এর বৈশিষ্ট্য ও মেথড পায়।
চলুন দেখি উদাহরণটি:

```python
# Parent class
class Phone:
    category = "Electronics"

    def __init__(self, model, battery, camera, battery_percentage=100):
        self.model = model
        self.battery = battery
        self.camera = camera
        self.battery_percentage = battery_percentage

    def charge(self, hour):
        print(f"charge completed by {hour}")

    def capture(self, photo):
        if self.battery_percentage <= 0:
            print("No charge")
        else:
            self.battery_percentage -= photo
            print(f"photo captured in {self.model}")
```

এখন আমরা একটি **child class** তৈরি করব — SmartPhone, যা Phone ক্লাস থেকে ইনহেরিট করছে।

```python
# Child / Derived class
class SmartPhone(Phone):
    def __init__(self, model, battery, camera, processor):
        super().__init__(model, battery, camera)   # parent class constructor call
        self.processor = processor                 # new attribute for SmartPhone

    # Modified method
    def charge(self, hour):
        print("fast charging in process")
        super().charge(hour)  # parent class-এর charge মেথডও ডাকা হচ্ছে
```

এখন আমরা একটি অবজেক্ট তৈরি করি:

```python
pro = SmartPhone("X", 5000, 100, "SnapDragon")

print(pro.model)    # Phone ক্লাস থেকে পাওয়া
pro.charge(1)       # SmartPhone-এর modified মেথড
```

### এখানে কী হচ্ছে:
1.  SmartPhone ক্লাস Phone–এর সব attributes ও methods ইনহেরিট করছে।
2.  আমরা চাইলে নতুন attribute (processor) যোগ করতে পারি।
3.  চাইলে পুরনো method (charge) পরিবর্তন বা override করতে পারি।
4.  super() ব্যবহার করে parent class–এর method–ও একসাথে ডাকা যায়।

**এভাবেই Single Inheritance আমাদের কোড পুনরায় ব্যবহার ও উন্নয়ন করতে সাহায্য করে।**

**Multiple Inheritance**

Python–এ একাধিক ক্লাস থেকেও ইনহেরিট করা যায়।
এটিকে বলা হয় **Multiple Inheritance**।
ধরুন, আমরা চাই ফোনে **Cooling Mechanism** নামের আরেকটি সিস্টেম যোগ করতে।
এই সিস্টেমের জন্য আমরা আলাদা একটি ক্লাস তৈরি করব:

```python
class Cooling_Mechanism:
    def __init__(self, cooling_method):
        self.cooling_method = cooling_method

    def cooling_on(self):
        return "Cooling system activated"
```

এখন আমরা চাই, SmartPhone–এর ফিচার এবং Cooling\_Mechanism–এর ফিচার একত্রে একটি নতুন ক্লাসে থাকুক।
সেটি হবে SmartPhone\_CoolingMode।

```python
class SmartPhone_CoolingMode(SmartPhone, Cooling_Mechanism):
    def __init__(self, model, battery, camera, processor, cooling_method):
        SmartPhone.__init__(self, model, battery, camera, processor)
        Cooling_Mechanism.__init__(self, cooling_method)
```

এখন আমরা নতুন অবজেক্ট তৈরি করব:

```python
pro_cooling = SmartPhone_CoolingMode("Y", 5000, 100, "SD", "Nitrogen")

print(pro_cooling.processor)        # SmartPhone class থেকে
print(pro_cooling.battery)          # Phone class থেকে
print(pro_cooling.cooling_method)   # Cooling_Mechanism class থেকে
print(pro_cooling.cooling_on())     # Cooling_Mechanism-এর method
print(pro_cooling.charge(1))        # SmartPhone-এর modified charge
```

### এখানে কী ঘটছে:

1.  SmartPhone\_CoolingMode ক্লাস দুটি parent ক্লাস থেকে ইনহেরিট করছে:
2.  SmartPhone
3.  Cooling\_Mechanism
4.  তাই এটি উভয় ক্লাসের গুণাবলি ও মেথড পায়।
5.  এটি আমাদের দেখায় কিভাবে OOP–এ **বহুমুখী বৈশিষ্ট্য একত্রে যুক্ত করা যায়**।


8.5 OOP Polymorphism

**Polymorphism কী?**

**Polymorphism** শব্দটি এসেছে গ্রিক ভাষা থেকে — “Poly” মানে অনেক, আর “Morph” মানে রূপ।
অর্থাৎ, **একই জিনিসের একাধিক রূপ**।
প্রোগ্রামিং–এ Polymorphism মানে হলো —**একই নামের মেথড বা ফাংশন বিভিন্ন ক্লাসে ভিন্নভাবে কাজ করতে পারে।**

এভাবে আমরা একই ইন্টারফেস ব্যবহার করে বিভিন্ন অবজেক্টের ভিন্ন আচরণ পেতে পারি।

### **কেন Polymorphism দরকার?**

ধরুন, আমাদের কাছে তিন ধরনের ক্যামেরা আছে:
1.  **Smart Phone**
2.  **DSLR**
3.  **Drone**

তিনটিই ছবি তুলতে পারে — কিন্তু প্রত্যেকে নিজস্ব পদ্ধতিতে।
এই তিনটি ডিভাইসের জন্য আমরা আলাদা ক্লাস তৈরি করতে পারি,
কিন্তু তাদের সবার মধ্যে একটি সাধারণ মেথড থাকবে — capture()।
এখন Polymorphism–এর মাধ্যমে আমরা সেই capture() মেথডকে প্রতিটি ক্লাসে ভিন্নভাবে ব্যবহার করতে পারব।

**Types of Polymorphism**

Python–এ মূলত দুই ধরনের Polymorphism দেখা যায়:

| Term | Description |
| :--- | :--- |
| **Compile-time Polymorphism (Method Overloading)** | একই নামের একাধিক মেথড, যেগুলো প্যারামিটারের সংখ্যায় বা ধরনে আলাদা হয়। |
| **Run-time Polymorphism (Method Overriding)** | চাইল্ড ক্লাসে প্যারেন্ট ক্লাসের মেথড নতুনভাবে সংজ্ঞায়িত করা হয়। |

**Method Overloading**

Python সরাসরি method overloading সাপোর্ট করে না (যেমন Java বা C++–এ করে)।
তবে আমরা এটি default arguments বা variable arguments (*args, **kwargs) ব্যবহার করে অনুকরণ করতে পারি।
ধরুন, আমরা একটি ক্যামেরার zoom() মেথড তৈরি করি:

```python
class Camera:
    def zoom(self, level=1):
        print(f"Zoomed {level}x")
```

এখানে যদি আমরা zoom() মেথডে প্যারামিটার না দিই, তাহলে এটি 1x জুম করে,
আর যদি মান দিই, তাহলে সেটি অনুযায়ী কাজ করে।
এভাবে একই মেথড ভিন্নভাবে কাজ করছে — এটিই **method overloading-এর ধারণা।**

**Method Overriding**

এখন আসুন মূল উদাহরণে যাই — এখানে তিনটি ক্লাস রয়েছে: Smart\_Phone, DSLR, এবং Drone,
যেগুলো Camera ক্লাস থেকে ইনহেরিট করছে।

### কোড:
```python
class Camera:
    def __init__(self, name):
        self.name = name

    # parent method
    def capture(self):
        print("A photo is captured")

# child classes
class Smart_Phone(Camera):
    def __init__(self, name, resolution):
        super().__init__(name)
        self.resolution = resolution

    # method overriding
    def capture(self):
        print("Photo is captured by a Smart Phone")

class DSLR(Camera):
    def __init__(self, name, resolution):
        super().__init__(name)
        self.resolution = resolution

    def capture(self):
        print("Photo is captured by a DSLR")

class Drone(Camera):
    def __init__(self, name, resolution):
        super().__init__(name)
        self.resolution = resolution

    def capture(self):
        print("Photo is captured by a Drone")
```
এখন আমরা অবজেক্ট তৈরি করি:
```python
phone = Smart_Phone("Phone", 30)
dslr = DSLR("DSLR", 200)
drone = Drone("Drone", 150)

phone.capture()
dslr.capture()
drone.capture()
```
### আউটপুট:
```
Photo is captured by a Smart Phone
Photo is captured by a DSLR
Photo is captured by a Drone
```

### **কী ঘটছে এখানে?**
সব ক্লাসেই একই মেথডের নাম capture(),
কিন্তু প্রতিটি ক্লাসে সেই মেথডের আচরণ আলাদা।
এটাই **Polymorphism-এর আসল শক্তি** —একই মেথডের নাম, কিন্তু অবজেক্ট অনুযায়ী আলাদা রূপ।

এখন ধরুন আমরা একটি সাধারণ ফাংশন লিখি, যা যে কোনো ক্যামেরা অবজেক্ট গ্রহণ করবে:
```python
def take_photo(camera):
    camera.capture()
```
এখন আমরা একই ফাংশন ব্যবহার করব তিনটি আলাদা অবজেক্টের জন্য:
```python
for device in [phone, dslr, drone]:
    take_photo(device)
```
আউটপুট:
```
Photo is captured by a Smart Phone
Photo is captured by a DSLR
Photo is captured by a Drone
```
একই ফাংশন, একই মেথডের নাম — কিন্তু ফলাফল সম্পূর্ণ ভিন্ন।
এটাই Polymorphism-এর সবচেয়ে বড় সুবিধা।


8.6 OOP Encapsulation

**Encapsulation কী?**

Encapsulation মানে হলো **“তথ্যকে সুরক্ষিত রাখা এবং নির্দিষ্ট নিয়ন্ত্রণের মাধ্যমে অ্যাক্সেস করা।”**
অর্থাৎ, অবজেক্টের ডেটা (attributes) এবং কাজ (methods) একসাথে একটি “সংবদ্ধ ইউনিট”-এর মধ্যে রাখা —
এবং বাইরের কেউ যেন সরাসরি সেই ডেটা পরিবর্তন করতে না পারে।
এই ধারণাটি অনেকটা **মোবাইল ফোনের ভিতরের সার্কিট বোর্ডের মতো** —
আপনি ফোন ব্যবহার করতে পারেন, কিন্তু ভিতরের সার্কিটে সরাসরি হাত দিতে পারেন না।
তেমনই, ক্লাসের অভ্যন্তরীণ ডেটা আমরা **getter** এবং **setter** মেথডের মাধ্যমে নিয়ন্ত্রিতভাবে ব্যবহার করি।

**Encapsulation-এর মূল উদ্দেশ্য**
1.  ডেটাকে অনাকাঙ্ক্ষিত পরিবর্তন থেকে রক্ষা করা
2.  অবজেক্টের অভ্যন্তরীণ বাস্তবায়ন (implementation) গোপন রাখা
3.  কোডকে আরও নিরাপদ ও নিয়ন্ত্রিত করা

**উদাহরণ - Mobile ক্লাস**
```python
class Mobile:
    def __init__(self, name, model, imei):
        self.__name = name      # private attribute
        self.__model = model    # private attribute
        self.__imei = imei      # private attribute

    def charge(self):
        print("phone is charging")

    # getter methods
    def imei_getter(self):
        return self.__imei

    def model_getter(self):
        return self.__model

    def name_getter(self):
        return self.__name

    # setter method
    def name_setter(self, name):
        self.__name = name
```

#### **প্রাইভেট অ্যাট্রিবিউট (\_\_attribute)**
```python
self.__imei = imei
```
*   দুটি আন্ডারস্কোর (`__`) দিয়ে শুরু হওয়া অ্যাট্রিবিউটগুলো **private** বা **ব্যক্তিগত** হিসেবে বিবেচিত হয়।
*   এগুলো ক্লাসের বাইরে থেকে সরাসরি অ্যাক্সেস করা যায় না।
*   এর ফলে ডেটা নিরাপদ থাকে, কারণ বাইরের কেউ এটি অনিচ্ছাকৃতভাবে পরিবর্তন করতে পারে না।

উদাহরণস্বরূপ:
```python
iphone = Mobile("Phone", "17", "1xkaf1")
print(iphone.__imei)  # Error: Attribute not accessible
```
এভাবে সরাসরি প্রাইভেট ডেটা দেখা যাবে না।

#### **Getter Methods**
```python
def imei_getter(self):
    return self.__imei
```
*   Getter মেথড কোনো প্রাইভেট ভ্যারিয়েবলের মান **নিয়ন্ত্রিতভাবে পড়ার সুযোগ** দেয়।
*   এটি একটি **read-only interface** তৈরি করে।

এভাবে আপনি চাইলে বাইরে থেকে IMEI দেখতে পারেন:
```python
print(iphone.imei_getter())  # "1xkaf1"
```

#### **Setter Methods**
```python
def name_setter(self, name):
    self.__name = name
```
*   Setter মেথড ডেটা **নিয়ন্ত্রিতভাবে পরিবর্তনের সুযোগ** দেয়।
*   আপনি চাইলে ডেটা পরিবর্তন করতে পারেন, কিন্তু ক্লাসের নির্ধারিত নিয়মের মাধ্যমে।

উদাহরণ:
```python
print(iphone.name_getter())   # "Phone"
iphone.name_setter("Phitron")
print(iphone.name_getter())   # "Phitron"
```

### **ব্যবহার**
```python
# Registration
iphone = Mobile("Phone", "17", "1xkaf1")

print(iphone.name_getter())  # → Phone

iphone.name_setter("Phitron")  # controlled modification
print(iphone.name_getter())  # → Phitron
```
এখানে ইউজার অবজেক্ট ব্যবহার করছে,
কিন্তু সে জানে না ভিতরে ডেটা কীভাবে রাখা হয়েছে বা পরিবর্তন হচ্ছে —
এই নিয়ন্ত্রণই হলো **Encapsulation-এর মূল দর্শন**।

8.7 OOP Abstraction

**Abstraction কী?**

**Abstraction** মানে হলো —
“জটিল বাস্তবতা লুকিয়ে রেখে শুধু প্রয়োজনীয় অংশটি ব্যবহারকারীর সামনে উপস্থাপন করা।”
সহজভাবে বললে —
আপনি **কাজটা কীভাবে হচ্ছে তা না জেনেই, শুধু কাজটা ব্যবহার করছেন।**
উদাহরণ হিসেবে ভাবুন —
আপনি মোবাইল ফোনে “Call” বোতাম চাপেন।
কিন্তু আপনি জানেন না ভিতরে কীভাবে নেটওয়ার্ক সংযোগ, ডায়ালিং সিগন্যাল, বা ট্রান্সমিশন কাজ করছে।
আপনি শুধু **“ফোন কল করা”** এই কাজটা ব্যবহার করছেন।
এটাই হচ্ছে **Abstraction** — ব্যবহারকারী থেকে অপ্রয়োজনীয় জটিলতা লুকানো।

**কেন Abstraction প্রয়োজন?**
1.  কোডকে সহজবোধ্য ও ব্যবহারযোগ্য রাখা
2.  বাস্তবায়নের জটিলতা লুকিয়ে রাখা
3.  বিভিন্ন অবজেক্টকে একটি সাধারণ ইন্টারফেসে কাজ করার সুযোগ দেওয়া
4.  বড় প্রজেক্টে “design contract” বজায় রাখা — অর্থাৎ, কে কোন কাজ করবে তা আগে থেকেই নির্ধারণ করা

**উদাহরণ — Telephone ক্লাস**
```python
from abc import ABC, abstractmethod

class Telephone(ABC):

  @abstractmethod
  def make_call(self):
    pass
```

### **class Telephone(ABC)**
### ABC মানে Abstract Base Class
### এটি এমন একটি ক্লাস, যাকে সরাসরি অবজেক্ট তৈরি করা যায় না।
### এটি কেবলমাত্র অন্যান্য ক্লাসের জন্য ব্লুপ্রিন্ট বা নকশা হিসেবে কাজ করে।

### **@abstractmethod**
### এটি এমন একটি মেথড, যার কোনো নির্দিষ্ট বাস্তবায়ন নেই।
### যেসব ক্লাস Telephone থেকে ইনহেরিট করবে, তাদের এই মেথড অবশ্যই বাস্তবায়ন করতে হবে।
### এটি অনেকটা “contract”–এর মতো —
### “তুমি আমার সন্তান ক্লাস হলে, তোমাকে make_call() মেথড দিতে হবেই।”

**বাস্তব উদাহরণ**
```python
class Sphone(Telephone):
  def make_call(self):
    print("Making a call using SPhone")

class Iphone(Telephone):
  def make_call(self):
    print("Making a call using IPhone")
```
এখানে দুটি ক্লাস (Sphone, Iphone) Telephone থেকে ইনহেরিট করেছে
এবং নিজেদের মতো করে make\_call() মেথড বাস্তবায়ন করেছে।
এভাবে আমরা একই “ফোন কল” ধারণাকে বিভিন্নভাবে বাস্তবায়ন করতে পারি,
যা **Abstraction + Polymorphism**–এর একটি দুর্দান্ত উদাহরণ।

**ব্যবহার**
```python
ip = Iphone()
ip.make_call()  # Output: Making a call using IPhone
```
এখানে ইউজার শুধু make\_call() মেথড কল করছে —
কিন্তু সে জানে না, ভিতরে কীভাবে Telephone ক্লাস কাজ করছে বা “call” কিভাবে হয়।
এই **বাস্তবায়ন গোপন রেখে ব্যবহার করা**–ই Abstraction।

**সারসংক্ষেপ**

| Term | Description | Example |
| :--- | :--- | :--- |
| **Abstraction** | জটিল বাস্তবায়ন লুকিয়ে রেখে কেবল প্রয়োজনীয় অংশ দেখানো | Telephone |
| **Abstract Class (ABC)** | এমন ক্লাস যাকে সরাসরি অবজেক্ট করা যায় না | class Telephone(ABC) |
| **Abstract Method** | বাধ্যতামূলকভাবে সাবক্লাসে বাস্তবায়ন করতে হবে এমন মেথড | make_call() |
| **Implementation Class** | যে ক্লাসে ওই মেথড বাস্তবায়ন করা হয় | Sphone, Iphone |
