স্বাগতম ছাত্র-ছাত্রী ভাই ও বোনেরা! আজকের ক্লাসে আমি আপনাদের **"Domain Driven Design (DDD) এর বস"** বা **Aggregate** নিয়ে গল্প করব।

সবাই রিল্যাক্স হয়ে বসেন। মনে করেন আমরা প্রোগ্রামিং শিখছি না, আমরা শিখছি **"কিভাবে সংসার বা ফ্যামিলি সামলাতে হয়!"**

---

# 🕵️‍♂️ Aggregate কী? (What is Aggregate?)

সহজ বাংলায়, **Aggregate** হলো কয়েকটি অবজেক্টের (Object) একটা **"প্যাকেট"** বা **"গ্যাং"**। এই গ্যাং-এর একজন লিডার থাকে, যাকে বলা হয় **Aggregate Root**।

**মজার উদাহরণ:**
চিন্তা করেন একটা **"ফ্যামিলি"**।
*   বাবা (Father) হলেন **Aggregate Root** (লিডার)।
*   মা, ছেলে, মেয়ে—এরা হলো ভেতরের **Entity** বা **Value Object**।

বাইরের কোনো লোক (ধরি, পিৎজা ডেলিভারি বয়) যদি এসে ছোট বাচ্চার গাল টিপতে চায়, সে কি সরাসরি বাচ্চার গাল টিপবে? না! সে আগে বাবার (Root) পারমিশন নেবে। বাবা যদি বলে "ওকে", তবেই সে পারবে।

প্রোগ্রামিংয়েও তাই। `Order` (অর্ডার) হলো বাবা। `OrderItem` (অর্ডারের আইটেম) হলো বাচ্চা। আপনি সরাসরি `OrderItem` ডিলিট করতে পারবেন না, আপনাকে `Order`-এর কাছে রিকোয়েস্ট করতে হবে।

# 🛠️ অ্যাগ্রিগেটের ভেতরের খুটিনাটি বিষয়গুলো

আসুন অ্যাগ্রিগেটের মেইন টপিকগুলো বিস্তারিত দেখি।

## ১. Aggregate Root (গ্যাং লিডার)
**What it does:** এটি হলো পুরো অ্যাগ্রিগেটের গেট-কিপার। বাইরের জগত শুধু এর সাথেই কথা বলতে পারে।
**Why important:** এটি ডাটা বা সিস্টেমের **Integrity** (সততা/শুদ্ধতা) রক্ষা করে।

**Example:**
ধরুন `Order` হলো রুট। আপনি যদি `Order.Items` লিস্টে সরাসরি `Add` করে দেন, তাহলে `Order` জানবেও না তার পেটে নতুন আইটেম ঢুকেছে! তাই `Order` ক্লাসের ভেতরে `AddItem()` মেথড কল করতে হবে, যাতে সে দাম (Price) ক্যালকুলেট করতে পারে।

## ২. Transaction Boundary (লেনদেনের সীমানা)
**What it does:** একটি অ্যাগ্রিগেট ডাটাবেসে সেভ হওয়ার সময় **"সব একসাথে সেভ হবে, নাহলে কিছুই হবে না"**—এই নীতিতে চলে।
**Why important:** অর্ধেক ডাটা সেভ হলে সিস্টেম ক্র্যাশ করবে।

**Bangla Example:**
বিয়ে বাড়িতে বিরিয়ানি রান্না হচ্ছে। মাংস সেদ্ধ হলো কিন্তু চাল হলো না—এটা কি বিরিয়ানি হবে? না! মাংস আর চাল একসাথে পারফেক্ট হলেই সেটা বিরিয়ানি। Aggregate এনশিওর করে পুরো প্যাকেটটা একসাথে ডাটাবেসে কমিট হবে।

## ৩. Reference by ID (আইডি দিয়ে চেনা, অবজেক্ট দিয়ে না)
**What it does:** এক অ্যাগ্রিগেট অন্য অ্যাগ্রিগেটকে সরাসরি অবজেক্ট হিসেবে ধরে রাখে না, শুধু তার **ID** মনে রাখে।

**Why important:** মেমোরি এবং পারফরম্যান্স বাঁচাতে।

**Fun Example:**
আপনার বন্ধু "রাহিম"। আপনি আপনার মোবাইলে রাহিমের **ফোন নাম্বার (ID)** সেভ রাখেন। আপনি কি রাহিমকে পকেটে নিয়ে ঘুরে বেড়ান? না!
ঠিক তেমনি, `Order` এর ভেতরে `Customer` অবজেক্ট পুরোটা লোড না করে, শুধু `CustomerId` রাখা হয়।

# ⚠️ সমস্যা ও সমাধান (Problems & Solutions)

অ্যাগ্রিগেট ব্যবহার করতে গিয়ে ডেভেলপাররা কিছু কমন গর্তে পড়েন। চলুন দেখি সেগুলো কী এবং বাঁচার উপায় কী।

### সমস্যা ১: The "Monster" Aggregate (দানব অ্যাগ্রিগেট)
**Problem:** অনেকে এক অ্যাগ্রিগেটের ভেতরে দুনিয়ার সব কিছু ঢুকিয়ে ফেলে।
যেমন: `User` অ্যাগ্রিগেটের ভেতরে তার হাজার হাজার `Role`, `Log`, `History` সব লিস্ট আকারে ঢুকিয়ে দেওয়া।
**Result:** যখনই আপনি ইউজার লোড করবেন, র‍্যাম (RAM) ভরে যাবে, সিস্টেম স্লো হয়ে যাবে।

**✅ সমাধান (Keep it Small):**
অ্যাগ্রিগেট ছোট রাখুন। `User` আলাদা অ্যাগ্রিগেট, `UserLog` আলাদা অ্যাগ্রিগেট। তাদের শুধু ID দিয়ে কানেক্ট করুন।
> **মন্ত্র:** "যত ছোট, তত ভালো।"

### সমস্যা ২: Data Consistency (ডাটার মিল থাকা)
**Problem:** এক অ্যাগ্রিগেটে চেঞ্জ করলে অন্য অ্যাগ্রিগেটে এফেক্ট পড়ে। কিন্তু আপনি তো একসাথে দুইটা অ্যাগ্রিগেট সেভ করতে পারবেন না (DDD রুল)।
**Example:** কাস্টমার টাকা জমা দিলে তার ব্যালেন্স বাড়বে এবং ব্যাংকের মোট ভল্টের টাকাও বাড়বে।

**✅ সমাধান (Eventual Consistency):**
Domain Events ব্যবহার করুন।
১. কাস্টমার টাকা জমা দিল -> `DepositCompleted` ইভেন্ট ফায়ার হলো।
২. অন্য একটা হ্যান্ডলার সেই ইভেন্ট শুনে ব্যাংকের ভল্ট আপডেট করল।
(একটু দেরি হতে পারে, কিন্তু দিনশেষে সব মিলে যাবে)।

---

# 🚀 সুবিধাসমূহ (Advantages)

১. **Business Logic Centralized:** সব নিয়ম-কানুন এক জায়গায় (Root-এর ভেতরে) থাকে। কোড ছড়িয়ে ছিটিয়ে থাকে না।
২. **Easy Testing:** ইউনিট টেস্ট করা খুব সহজ হয় কারণ এটি অন্য লেয়ারের ওপর নির্ভর করে না।
৩. **No Invalid State:** অ্যাগ্রিগেট গ্যারান্টি দেয় যে, ডাটাবেসে যা আছে তা ভ্যালিড। ভুলভাল ডাটা ঢোকার চান্স নেই।

# 💻 Real-World Code Example (মজার কোড)

আমরা একটি **"E-commerce Cart"** বানাব।

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

// 1. এটা হলো বাচ্চা (Child Entity)
public class CartItem
{
    public Guid ProductId { get; private set; }
    public int Quantity { get; private set; }

    public CartItem(Guid productId, int quantity)
    {
        ProductId = productId;
        Quantity = quantity;
    }

    public void AddQuantity(int amount) => Quantity += amount;
}

// 2. এটা হলো বাবা বা বস (Aggregate Root)
public class Cart
{
    public Guid Id { get; private set; }
    
    // বাইরে থেকে কেউ সরাসরি লিস্টে হাত দিতে পারবে না
    private readonly List<CartItem> _items = new List<CartItem>();
    
    // বাইরে শুধু দেখার অনুমতি আছে
    public IReadOnlyCollection<CartItem> Items => _items.AsReadOnly();

    public Cart() { Id = Guid.NewGuid(); }

    // বস-এর মেথড (Business Logic)
    public void AddProduct(Guid productId, int quantity)
    {
        // লজিক ১: কোয়ান্টিটি ০ বা তার কম হতে পারবে না
        if (quantity <= 0) throw new Exception("ভাই, ফাজলামি করেন? ০ টা প্রোডাক্ট কেনা যায়?");

        // লজিক ২: এক কার্টে ১০ আইটেমের বেশি নেওয়া যাবে না (বিজনেস রুল)
        if (_items.Count >= 10) throw new Exception("ঝুড়ি ভরে গেছে! আর নেওয়া যাবে না।");

        var existingItem = _items.FirstOrDefault(x => x.ProductId == productId);
        if (existingItem != null)
        {
            existingItem.AddQuantity(quantity);
        }
        else
        {
            _items.Add(new CartItem(productId, quantity));
        }
    }
}
```

### এই কোড কেন নিরাপদ?
কেউ চাইলেই `Cart.Items.Add(...)` করতে পারবে না। তাকে অবশ্যই `Cart.AddProduct(...)` মেথড কল করতে হবে। ফলে "নেগেটিভ কোয়ান্টিটি" বা "১০টার বেশি আইটেম"—এই ভুলগুলো সিস্টেমে কখনোই হবে না।

# 📝 সারাংশ (Summary)

আজকের ক্লাসের **"Take Home"** পয়েন্টগুলো হলো:

১. **Aggregate** = ডাটা ও লজিকের একটি প্যাকেট।
২. **Aggregate Root** = ফ্যামিলির কর্তা। পারমিশন ছাড়া কিচ্ছু হবে না।
৩. **Reference by ID** = বন্ধুকে পকেটে না রেখে, বন্ধুর ফোন নাম্বার পকেটে রাখুন।
৪. **Keep it Small** = অ্যাগ্রিগেট ছোট রাখুন, নাহলে লোড হতে খবর হয়ে যাবে।
৫. **Transaction Boundary** = এক অ্যাগ্রিগেট = এক ডাটাবেস সেভ অপারেশন।

# 🏗️ অধ্যায় ১: Aggregate আসলে কী? (The Core Concept)

সহজ কথায়, **Aggregate** হলো ডাটা এবং লজিকের একটি **"অখণ্ড প্যাকেট"**।

চিন্তা করুন একটি **ঔষধের ক্যাপসুল**।
*   ক্যাপসুলের ভেতরে অনেক ছোট ছোট দানা (Ingredients) থাকে।
*   আপনি কি দানাগুলো আলাদা করে খান? না! আপনি পুরো ক্যাপসুলটি একসাথে খান।
*   ক্যাপসুলটি হলো **Aggregate Root** (প্যাকেটের বডি), আর ভেতরের দানাগুলো হলো **Child Entities** বা **Value Objects**।

সফটওয়্যারে, আমরা চাই না বাইরের কেউ আমাদের ডাটার ভেতরের অংশে সরাসরি হাত দিক। ক্যাপসুলের খোলস (Root) ঠিক করবে ভেতরে কী ঢুকবে আর কী বের হবে।

# 💻 অধ্যায় ৩: কোডিং – ই-কমার্স অর্ডার সিস্টেম

আমরা একটি **Order (অর্ডার)** সিস্টেম বানাব।
এখানে:
*   `Order` হলো **Aggregate Root** (বস)।
*   `OrderItem` হলো ভেতরের আইটেম (পণ্য)।

**নিয়ম:** একটি অর্ডারে পণ্য যোগ করতে হলে সরাসরি পণ্যের লিস্টে হাত দেওয়া যাবে না। `Order`-এর অনুমতি নিয়ে যোগ করতে হবে।

### ধাপ ১: Child Entity তৈরি করা (OrderItem)

প্রথমে আমরা অর্ডারের ভেতরের আইটেম ডিফাইন করব।

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

// এটা হলো অর্ডারের ভেতরের খুচরা অংশ (Child Entity)
public class OrderItem
{
    public Guid ProductId { get; private set; }
    public string ProductName { get; private set; }
    public decimal UnitPrice { get; private set; }
    public int Quantity { get; private set; }

    // কনস্ট্রাক্টর: আইটেম তৈরির সময় সব তথ্য দিতে হবে
    public OrderItem(Guid productId, string productName, decimal unitPrice, int quantity)
    {
        if (quantity <= 0) throw new Exception("পণ্যের পরিমাণ অবশ্যই ১ বা তার বেশি হতে হবে।");

        ProductId = productId;
        ProductName = productName;
        UnitPrice = unitPrice;
        Quantity = quantity;
    }

    // বিজনেস লজিক: আইটেমের পরিমাণ বাড়ানো
    public void AddQuantity(int amount)
    {
        Quantity += amount;
    }

    // মোট দাম বের করা
    public decimal TotalPrice => UnitPrice * Quantity;
}
```

### ধাপ ২: Aggregate Root তৈরি করা (Order)

এখন আমরা "বস" ক্লাসটি লিখব। লক্ষ্য করুন কিভাবে আমরা **Encapsulation** ব্যবহার করছি।

```csharp
// এটা হলো Aggregate Root (বস)
public class Order
{
    public Guid Id { get; private set; }
    public DateTime OrderDate { get; private set; }
    public string CustomerName { get; private set; }
    
    // 🔥 গুরুত্বপূর্ণ: স্ট্যাটাস। পেমেন্ট হয়ে গেলে অর্ডার এডিট করা যাবে না।
    public string Status { get; private set; } // "New", "Paid", "Shipped"

    // 🔒 Encapsulation: বাইরের কেউ এই লিস্টে সরাসরি .Add() করতে পারবে না।
    private readonly List<OrderItem> _items = new List<OrderItem>();
    
    // বাইরে শুধু দেখার অনুমতি (Read-Only)
    public IReadOnlyCollection<OrderItem> Items => _items.AsReadOnly();

    public Order(Guid id, string customerName)
    {
        Id = id;
        CustomerName = customerName;
        OrderDate = DateTime.Now;
        Status = "New"; // ডিফল্ট স্ট্যাটাস
    }

    // ✅ বিজনেস লজিক: আইটেম যোগ করা (বস-এর পারমিশন মেথড)
    public void AddItem(Guid productId, string name, decimal price, int quantity)
    {
        // ১. রুল চেক: অর্ডার যদি পেইড হয়ে যায়, তাহলে নতুন আইটেম নেওয়া যাবে না
        if (Status == "Paid")
        {
            throw new InvalidOperationException("পেমেন্ট হয়ে গেছে ভাই! এখন আর আইটেম যোগ করা যাবে না।");
        }

        // ২. রুল চেক: একই প্রোডাক্ট থাকলে নতুন আইটেম না বানিয়ে কোয়ান্টিটি বাড়াও
        var existingItem = _items.FirstOrDefault(x => x.ProductId == productId);
        if (existingItem != null)
        {
            existingItem.AddQuantity(quantity);
        }
        else
        {
            _items.Add(new OrderItem(productId, name, price, quantity));
        }
    }

    // ✅ বিজনেস লজিক: অর্ডার পেমেন্ট করা
    public void MarkAsPaid()
    {
        if (_items.Count == 0)
        {
            throw new Exception("খালি ঝুড়ি পেমেন্ট করা যাবে না!");
        }
        Status = "Paid";
        Console.WriteLine($"অর্ডার {Id} পেমেন্ট সাকসেসফুল! টোটাল বিল: {_items.Sum(i => i.TotalPrice)} টাকা।");
    }
}
```

# 🧠 অধ্যায় ৪: কোডের পেছনের লজিক (Logic Explanation)

কেন আমি কোডটি এভাবে লিখলাম? এর পেছনে ৩টি প্রধান কারণ আছে:

১. **Public `List` নেই কেন?**
   *   যদি আমি `public List<OrderItem> Items { get; set; }` দিতাম, তাহলে যে কেউ `order.Items.Add(...)` করে ইচ্ছামতো আইটেম ঢুকাতে পারত।
   *   **সমস্যা:** সে হয়তো `Status == "Paid"` চেক করত না। ফলে পেমেন্ট করার পরেও আইটেম যোগ হয়ে যেত, যা একটি মারাত্মক বাগ।
   *   **সমাধান:** `private List` এবং `AddItem` মেথড ব্যবহার করায়, আইটেম যোগ করার আগে আমি `Status` চেক করতে বাধ্য করেছি।

২. **IReadOnlyCollection কেন?**
   *   যাতে বাইরের কোড (যেমন UI বা API) আইটেমগুলো দেখতে পারে, লুপ চালাতে পারে, কিন্তু লিস্টটি ক্লিয়ার বা ডিলিট করতে না পারে।

৩. **Aggregate Root-এর দায়িত্ব:**
   *   `Order` ক্লাসটি এখানে ট্রাফিক পুলিশের মতো কাজ করছে। সে নিশ্চিত করছে যে তার ভেতরের ডাটা (Items) সবসময় ভ্যালিড বা শুদ্ধ থাকবে।

# ⚠️ অধ্যায় ৫: সাধারণ সমস্যা ও সমাধান (Common Pitfalls)

নতুনরা অ্যাগ্রিগেট নিয়ে কাজ করতে গিয়ে কিছু ভুল করেন।

### সমস্যা ১: দানব অ্যাগ্রিগেট (The Giant Aggregate)
অনেকে `Customer` অ্যাগ্রিগেটের ভেতরে তার সমস্ত `Order` লিস্ট আকারে লোড করে।
*   **ফলাফল:** ১০০০টি অর্ডার থাকা কাস্টমারকে লোড করতে গেলে সিস্টেম হ্যাং করবে।
*   **সমাধান:** `Customer` এবং `Order` দুটি আলাদা অ্যাগ্রিগেট হবে। `Order` এর ভেতরে শুধু `CustomerId` থাকবে, পুরো কাস্টমার অবজেক্ট নয়। (**Reference by ID**)।

### সমস্যা ২: ট্রানজেকশন ফেইল করা
আপনি `Order` সেভ করলেন কিন্তু `OrderItem` সেভ হলো না।
*   **সমাধান:** অ্যাগ্রিগেটকে সবসময় **"One Transaction"**-এ সেভ করতে হয়। ডাটাবেসে হয় পুরো অর্ডার (আইটেমসহ) সেভ হবে, নাহলে কিছুই সেভ হবে না। Entity Framework Core বা MongoDB তে এটি অটোমেটিক হ্যান্ডেল করা সহজ।

# 🌍 অধ্যায় ৬: রিয়েল-লাইফ ব্যবহার (Practical Execution)

আসুন `Program.cs` ফাইলে কোডটি চালিয়ে দেখি।

```csharp
class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("--- দারাজ (Daraz) অর্ডার সিস্টেম ---");

        // ১. একটি নতুন অর্ডার তৈরি করলাম
        var myOrder = new Order(Guid.NewGuid(), "রাহিম কুদ্দুস");

        try
        {
            // ২. আইটেম যোগ করছি
            Console.WriteLine("Adding items...");
            myOrder.AddItem(Guid.NewGuid(), "Gaming Mouse", 1500, 1);
            myOrder.AddItem(Guid.NewGuid(), "Keyboard", 2000, 1);

            // ৩. পেমেন্ট করছি
            myOrder.MarkAsPaid();

            // ৪. পেমেন্টের পর আবার আইটেম যোগ করার চেষ্টা (এরর খাওয়ার কথা)
            Console.WriteLine("Trying to add item after payment...");
            myOrder.AddItem(Guid.NewGuid(), "Monitor", 15000, 1);
        }
        catch (Exception ex)
        {
            Console.ForegroundColor = ConsoleColor.Red;
            Console.WriteLine($"\n🚨 এরর: {ex.Message}");
            Console.ResetColor();
        }
    }
}
```

**আউটপুট:**
```text

Adding items...
অর্ডার ... পেমেন্ট সাকসেসফুল! টোটাল বিল: ৩৫০০ টাকা।
Trying to add item after payment...

🚨 এরর: পেমেন্ট হয়ে গেছে ভাই! এখন আর আইটেম যোগ করা যাবে না।
```

# 📝 অধ্যায় ৭: সারাংশ (Summary)

আজকের ক্লাসের মূল টেক-অ্যাওয়ে (Key Points):

১. **Aggregate Root ই সব:** রুটের পারমিশন ছাড়া ভেতরের কোনো ডাটায় হাত দেওয়া যাবে না।
২. **Business Rules Protection:** আমরা `AddItem` মেথডের ভেতরে লজিক লিখে ডাটাকে ভুল হওয়া থেকে বাঁচিয়েছি।
৩. **Real World Impact:** দারাজ, অ্যামাজন, বা ফুডপান্ডায় যখন আপনি অর্ডার দেন, ব্যাকএন্ডে ঠিক এভাবেই অ্যাগ্রিগেট কাজ করে যাতে পেমেন্টের পর পণ্যের দাম বা পরিমাণ বদলানো না যায়।

এই সেটআপ এবং কোড প্র্যাকটিস করলে আপনি এমন সফটওয়্যার বানাতে পারবেন যা সহজে ভাঙবে না এবং মেইনটেইন করা পানির মতো সহজ হবে।

কোডটি কপি করে রান করুন এবং `MarkAsPaid` মেথডটি কমেন্ট-আউট করে দেখুন কী হয়! শুভ কামনা! 🚀
