
স্বাগতম ফিউচার সফটওয়্যার আর্কিটেক্টরা! 🎓

আজকের ক্লাসে আমরা শিখব **Repository Pattern**। নামটা শুনলে মনে হয় কোনো "গোপন অস্ত্রাগার" বা "টাকার সিন্দুক"। আসলে সফটওয়্যার দুনিয়ায় এটা হলো আমাদের ডাটার **"বিশ্বস্ত স্টোরকিপার"** বা **"দোকানদার মামা"**।

আজ আমরা একদম সহজ বাংলায়, হাসতে হাসতে রিপজিটরির নাড়ি-নক্ষত্র জেনে নেব। খাতা-কলম (বা নোটপ্যাড) নিয়ে রেডি হন! 🚀

# 🏪 Repository আসলে কী? (What is Repository?)

সহজ বাংলায়, **Repository** হলো আপনার **বিজনেস লজিক (Code)** এবং **ডাটাবেস (Database)**-এর মাঝখানের একজন **মিডলম্যান (Middleman)** বা দালাল।

**মজার উদাহরণ:**
ধরুন আপনি একটি রেস্টুরেন্টে গিয়েছেন।
১. আপনি হলেন **Business Logic** (ক্ষুধার্ত)।
২. কিচেন হলো **Database** (যেখানে খাবার/ডাটা আছে)।
৩. ওয়েটার হলো **Repository**।

আপনি কি সরাসরি কিচেনে গিয়ে বাবুর্চিকে বলেন—"এই যে, পেঁয়াজ কাটেন, তেল গরম করেন, তারপর ডিম ভাজেন"? না!
আপনি ওয়েটারকে শুধু বলেন: **"মামা, এক প্লেট ফ্রাইড রাইস আনো।"**
ওয়েটার কিচেনে গিয়ে কীভাবে সেটা আনল, বাবুর্চি চাইনিজ নাকি বাঙালি—সেটা আপনার জানার দরকার নেই। আপনি খাবার পেলেই খুশি।

সফটওয়্যারেও তাই। আমরা কোডের ভেতরে `SELECT * FROM Users WHERE...` এসব লিখব না। আমরা রিপজিটরিকে বলব, `GetUserById(1)`—ব্যাস! সে ডাটা এনে দেবে।

# 🛠️ রিপজিটরির খুটিনাটি বিষয়গুলো

রিপজিটরি প্যাটার্নের মেইন পার্টগুলো চলুন ভেঙে দেখি।

## ১. The Interface (মেনু কার্ড) 📜
**What it does:** এটি একটি কন্ট্রাক্ট বা চুক্তি। এখানে শুধু বলা থাকে "কী কী পাওয়া যাবে", কিন্তু "কিভাবে পাওয়া যাবে" তা বলা থাকে না।
**Bangla Example:** রেস্টুরেন্টের মেনু কার্ড। লেখা আছে "চিকেন ফ্রাই", কিন্তু রেসিপি লেখা নেই।

## ২. The Implementation (আসল বাবুর্চি) 👨‍🍳
**What it does:** এটি ইন্টারফেসের মেথডগুলো আসলে কোড করে ইমপ্লিমেন্ট করে (যেমন: Entity Framework বা Dapper দিয়ে ডাটাবেস থেকে ডাটা আনা)।
**Bangla Example:** কিচেনের ভেতরের কাজ। কড়াইয়ে তেল ঢালা, রান্না করা।

## ৩. Decoupling (আলাদা থাকা) 💔
**What it does:** এটি আপনার অ্যাপের মেইন কোডকে ডাটাবেস টেকনোলজি থেকে আলাদা রাখে।
**Why important:** আজ আপনি SQL Server ব্যবহার করছেন, কাল বস বলল "না, MongoDB চালাব"। রিপজিটরি থাকলে মেইন কোডে হাত দিতে হবে না, শুধু রিপজিটরির পেছনের কোড পাল্টালেই হবে।

# 💻 কোড দিয়ে বুঝি (Code Example)

আমরা একটি **স্কুল ম্যানেজমেন্ট** সিস্টেমের উদাহরণ দেখব।

### ধাপ ১: ইন্টারফেস (মেনু কার্ড)
ডোমেইন লেয়ারে আমরা ইন্টারফেস বানাব।

```csharp
// IStudentRepository.cs
public interface IStudentRepository
{
    // শুধু মেথডের নাম, কোনো কোড নেই
    Student GetById(int id);
    void Save(Student student);
    List<Student> GetAllSmartStudents(); // যারা জিপিএ ৫ পেয়েছে
}
```

### ধাপ ২: ইমপ্লিমেন্টেশন (কিচেন)
ইনফ্রাস্ট্রাকচার লেয়ারে আমরা আসল কাজ করব।

```csharp
// StudentRepository.cs
public class StudentRepository : IStudentRepository
{
    private readonly AppDbContext _db; // ডাটাবেস কানেকশন

    public StudentRepository(AppDbContext db)
    {
        _db = db;
    }

    public Student GetById(int id)
    {
        // ডাটাবেস থেকে ছাত্র খুঁজে আনা
        return _db.Students.Find(id);
    }

    public void Save(Student student)
    {
        _db.Students.Add(student);
        _db.SaveChanges();
    }

    public List<Student> GetAllSmartStudents()
    {
        // লজিক: যাদের জিপিএ ৫
        return _db.Students.Where(s => s.GPA == 5.0).ToList();
    }
}
```

### ধাপ ৩: ব্যবহার (কাস্টমার)
সার্ভিস বা কন্ট্রোলার লেয়ারে আমরা এটি ব্যবহার করব।

```csharp
public class StudentService
{
    private readonly IStudentRepository _repo;

    // ডিপেন্ডেন্সি ইনজেকশন (Dependency Injection)
    public StudentService(IStudentRepository repo)
    {
        _repo = repo;
    }

    public void ShowStudentInfo(int id)
    {
        // আমি জানি না ডাটা SQL থেকে আসছে নাকি এক্সেল থেকে
        var student = _repo.GetById(id); 
        Console.WriteLine($"Name: {student.Name}");
    }
}
```

# ⚠️ সমস্যা ও সমাধান (Problems & Solutions)

রিপজিটরি ব্যবহার করতে গিয়ে কিছু কমন প্যারা (সমস্যা) হতে পারে।

### সমস্যা ১: The "Leak" Problem (লিক হওয়া অ্যাবস্ট্রাকশন)
**Problem:** অনেকে রিপজিটরি থেকে `List` রিটার্ন না করে `IQueryable` রিটার্ন করে।
**Why bad:** `IQueryable` রিটার্ন করা মানে হলো আপনি রান্না না করে "কাঁচা বাজার" কাস্টমারের হাতে ধরিয়ে দিলেন। কাস্টমার (কন্ট্রোলার) যদি সেখানে আবার `.Where()` বা `.Filter()` চালায়, তবে ডাটাবেসের লজিক সব জায়গায় ছড়িয়ে গেল। রিপজিটরির উদ্দেশ্যই মাটি হয়ে গেল!

**✅ সমাধান:** রিপজিটরি থেকে সবসময় ফাইনাল ডাটা (`List`, `Array`, বা `IEnumerable`) রিটার্ন করুন। ডাটাবেসের লজিক রিপজিটরির ভেতরেই শেষ করুন।

### সমস্যা ২: N+1 Problem (অলস লোডিং)
**Problem:** আপনি ১০০০ স্টুডেন্ট আনলেন, তারপর লুপ চালিয়ে প্রত্যেকের "অভিভাবকের নাম" আনতে গেলেন। এতে ১০০০ বার ডাটাবেস কল হবে। সার্ভার ক্র্যাশ খাবে!

**✅ সমাধান:** রিপজিটরির ভেতরেই জয়েন (Join) বা `Include` ব্যবহার করে সব ডাটা একবারে নিয়ে আসুন।

### সমস্যা ৩: Generic Repository Trap (সবজান্তা রিপজিটরি)
**Problem:** অনেকে কুড়েমি করে একটা `GenericRepository<T>` বানায় যা সব টেবিলের জন্য কাজ করে। কিন্তু জটিল কোয়েরি (যেমন: "গত মাসে যারা ফেইল করেছে তাদের লিস্ট দাও") জেনেরিক রিপজিটরি দিয়ে করা খুব পেইনফুল।

**✅ সমাধান:** জেনেরিক রিপজিটরি শুধু বেসিক (CRUD) কাজের জন্য রাখুন। স্পেশাল কাজের জন্য আলাদা রিপজিটরি (যেমন: `IStudentRepository`) বানান।

# 🚀 সুবিধা এবং রিয়েল-লাইফ ব্যবহার (Advantages)

১. **Testing is Easy:** ইউনিট টেস্ট করার সময় আপনি আসল ডাটাবেস ব্যবহার না করে একটি "ফেইক/মক রিপজিটরি" ব্যবহার করতে পারেন। টেস্টিং সুপার ফাস্ট হয়।
২. **Centralized Logic:** "স্মার্ট স্টুডেন্ট কারা"—এই লজিকটা যদি রিপজিটরিতে থাকে, তবে অ্যাপের ১০ জায়গায় এই কোড লিখতে হবে না। একবার লিখলেই সবাই ব্যবহার করতে পারবে।
৩. **Clean Code:** আপনার কন্ট্রোলার বা সার্ভিস লেয়ারে বিদঘুটে SQL কোয়েরি থাকে না। কোড দেখতে খুব সুন্দর ও ক্লিন লাগে।

**Real-World Scenario:**
বড় বড় কোম্পানি (যেমন: পাঠাও, চালডাল) যখন মাইক্রোসার্ভিস বা ক্লিন আর্কিটেকচার ব্যবহার করে, তখন রিপজিটরি প্যাটার্ন মাস্ট! কারণ তাদের বিজনেস লজিক অনেক জটিল, তারা চায় না ডাটাবেসের ঝামেলার সাথে বিজনেস লজিক মিশে যাক।

# 📝 সারাংশ (Summary)

আজকের ক্লাসের **"Take Home"** পয়েন্টগুলো হলো:

১. **Repository = Storekeeper:** সে ডাটা এনে দেয়, কিন্তু সোর্স নিয়ে মাথা ঘামাতে হয় না।
২. **Interface & Implementation:** মেনু কার্ড এবং আসল রান্না আলাদা রাখা হয়।
৩. **Don't Return IQueryable:** আধা-সেদ্ধ খাবার (Queryable) কাস্টমারকে দেবেন না, রান্না শেষ করে (List/Collection) দিন।
৪. **Testing Hero:** রিপজিটরি থাকলে কোড টেস্ট করা পানির মতো সহজ।

ব্যাস! এখন আপনি রিপজিটরি প্যাটার্নের বস। পরের প্রজেক্টে আর সরাসরি ডাটাবেস কল করবেন না, একটা সুন্দর "স্টোরকিপার মামা" (Repository) রেখে দেবেন! 😎👨‍💻

আজকের ক্লাসে আমরা সফটওয়্যার ডেভেলপমেন্টের অন্যতম গুরুত্বপূর্ণ পিলার **Repository Pattern (রিপজিটরি প্যাটার্ন)** শিখব। আপনি যদি ক্লিন আর্কিটেকচার বা ডোমেইন ড্রিভেন ডিজাইন (DDD) ফলো করতে চান, তবে রিপজিটরি বোঝা ফরজ!

আজ আমরা একদম শূন্য থেকে সেটআপ করে, কোড লিখে এবং রান করে দেখব রিপজিটরি আসলে কীভাবে কাজ করে।

# 🏗️ অধ্যায় ১: রিপজিটরি কী এবং কেন? (The Concept)

সহজ বাংলায়, **Repository** হলো আপনার **Code (Business Logic)** এবং **Database**-এর মাঝখানের **"বিশ্বস্ত দেয়াল"**।

*   আপনার মেইন কোড (যেমন Controller বা Service) সরাসরি ডাটাবেস চেনে না।
*   সে শুধু রিপজিটরিকে চেনে।
*   সে রিপজিটরিকে বলে, *"মামা, আমাকে ১ নম্বর প্রোডাক্টটা দাও।"*
*   রিপজিটরি সেটা SQL থেকে আনল নাকি ফাইল থেকে আনল—সেটা মেইন কোডের জানার দরকার নেই।

**কেন দরকার?**
১. **Decoupling:** ডাটাবেস টেকনোলজি পরিবর্তন করলে মেইন কোডে হাত দিতে হয় না।
২. **Testing:** আসল ডাটাবেস ছাড়াই ইউনিট টেস্ট করা যায়।

# 🛠️ অধ্যায় ২: সেটআপ এবং প্রস্তুতি (Setup & Prerequisites)

আমরা C# এবং Entity Framework Core (EF Core) ব্যবহার করে এটি ইমপ্লিমেন্ট করব। তবে আমরা শেখার সুবিধার্থে **In-Memory Database** ব্যবহার করব, যাতে আপনার পিসিতে SQL Server ইন্সটল করা না থাকলেও কোড রান করে।

### ১. প্রয়োজনীয় টুলস
*   Visual Studio বা VS Code.
*   .NET SDK (6.0, 7.0 বা 8.0).

### ২. প্রজেক্ট সেটআপ (Steps)
টার্মিনাল বা CMD ওপেন করে নিচের কমান্ডগুলো দিন:

```bash
# ১. নতুন কনসোল অ্যাপ তৈরি
dotnet new console -n Repository_Demo
cd Repository_Demo

# ২. Entity Framework Core এর প্যাকেজ ইন্সটল (ডাটাবেস নিয়ে কাজের জন্য)
dotnet add package Microsoft.EntityFrameworkCore
dotnet add package Microsoft.EntityFrameworkCore.InMemory
```

**কেন In-Memory?**
রিয়েল লাইফে আমরা SQL Server বা Postgres ব্যবহার করি। কিন্তু প্র্যাকটিসের জন্য `InMemory` বেস্ট, কারণ এটি র‍্যাম (RAM)-কে ডাটাবেস হিসেবে ব্যবহার করে। কোনো কনফিগারেশনের ঝামেলা নেই।

# 💻 অধ্যায় ৩: কোডিং – ই-কমার্স প্রোডাক্ট স্টোর

আমরা একটি সিম্পল প্রোডাক্ট ম্যানেজমেন্ট সিস্টেম বানাব।

### ধাপ ১: ডোমেইন এনটিটি (Domain Entity)
প্রথমে আমাদের বিজনেস অবজেক্ট বা এনটিটি বানাতে হবে।

```csharp
using System;

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }

    // কনস্ট্রাক্টর
    public Product(int id, string name, decimal price)
    {
        Id = id;
        Name = name;
        Price = price;
    }
}
```

### ধাপ ২: রিপজিটরি ইন্টারফেস (The Contract) 📜
এটি হলো আমাদের "মেনু কার্ড"। এখানে শুধু বলা থাকবে কী কী অপারেশন সম্ভব।

```csharp
using System.Collections.Generic;

public interface IProductRepository
{
    // ডাটা আনার মেথড
    Product GetById(int id);
    IEnumerable<Product> GetAll();

    // ডাটা সেভ করার মেথড
    void Add(Product product);
    
    // ডাটা ডিলিট করার মেথড
    void Remove(int id);
}
```

### ধাপ ৩: ডাটাবেস কনটেক্সট (Database Context)
EF Core ব্যবহার করার জন্য `DbContext` লাগে। এটি ডাটাবেসের সাথে কানেকশন তৈরি করে।

```csharp
using Microsoft.EntityFrameworkCore;

public class AppDbContext : DbContext
{
    public DbSet<Product> Products { get; set; }

    // কনফিগারেশন: আমরা In-Memory ডাটাবেস ব্যবহার করব
    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        optionsBuilder.UseInMemoryDatabase(databaseName: "MyShopDB");
    }
}
```

### ধাপ ৪: রিপজিটরি ইমপ্লিমেন্টেশন (The Real Worker) 👨‍🍳
এবার ইন্টারফেসের মেথডগুলো আসলে কোড করব।

```csharp
using System.Linq;

public class ProductRepository : IProductRepository
{
    private readonly AppDbContext _context;

    public ProductRepository()
    {
        _context = new AppDbContext();
    }

    public void Add(Product product)
    {
        _context.Products.Add(product);
        _context.SaveChanges(); // ডাটাবেসে সেভ হলো
    }

    public Product GetById(int id)
    {
        return _context.Products.Find(id);
    }

    public IEnumerable<Product> GetAll()
    {
        // 🚨 খেয়াল করুন: আমি এখানে .ToList() ব্যবহার করে ডাটা মেমোরিতে নিয়ে আসছি।
        // IQueryable রিটার্ন করছি না। কেন? নিচে ব্যাখ্যা আছে।
        return _context.Products.ToList();
    }

    public void Remove(int id)
    {
        var product = _context.Products.Find(id);
        if (product != null)
        {
            _context.Products.Remove(product);
            _context.SaveChanges();
        }
    }
}
```

# 🧠 অধ্যায় ৪: লজিক এবং কমন সমস্যা (Logic & Pitfalls)

### কেন `IEnumerable` বা `List` রিটার্ন করলাম? (`IQueryable` নয় কেন?)
অনেক ডেভেলপার রিপজিটরি থেকে `IQueryable` রিটার্ন করে। এটি একটি **বিশাল ভুল**।
*   `IQueryable` রিটার্ন করা মানে হলো আপনি রান্না না করে কাঁচা বাজার কাস্টমারকে দিয়ে দিলেন।
*   কাস্টমার (সার্ভিস লেয়ার) যদি সেখানে `.Where()` বা `.Filter()` চালায়, তাহলে ডাটাবেসের লজিক রিপজিটরি থেকে বের হয়ে সব জায়গায় ছড়িয়ে পড়ল (**Leaky Abstraction**)।
*   তাই রিপজিটরির দায়িত্ব হলো কোয়েরি এক্সিকিউট করে ফাইনাল ডাটা ফেরত দেওয়া।

### N+1 সমস্যা
যদি আপনার `Product` এর সাথে `Category` থাকত, আর আপনি লুপ চালিয়ে ক্যাটাগরি লোড করতেন, তবে সিস্টেম স্লো হয়ে যেত।
**সমাধান:** রিপজিটরির ভেতরেই `.Include(p => p.Category)` ব্যবহার করে সব ডাটা একবারে আনতে হবে (Eager Loading)।

# 🌍 অধ্যায় ৫: রিয়েল-লাইফ এক্সিকিউশন (Main Program)

এখন আমরা দেখব একজন ইউজার (Program.cs) কিভাবে রিপজিটরি ব্যবহার করে।

```csharp
class Program
{
    static void Main(string[] args)
    {
        // ১. রিপজিটরি ইনিশিলাইজ করলাম (বাস্তব প্রজেক্টে এটা DI কন্টেইনার দিয়ে হবে)
        IProductRepository repo = new ProductRepository();

        Console.WriteLine("--- পণ্য যোগ করা হচ্ছে ---");
        repo.Add(new Product(1, "Gaming Mouse", 1500));
        repo.Add(new Product(2, "Mechanical Keyboard", 3500));
        repo.Add(new Product(3, "Monitor", 12000));

        Console.WriteLine("--- সব পণ্যের লিস্ট ---");
        var allProducts = repo.GetAll();
        foreach (var p in allProducts)
        {
            Console.WriteLine($"ID: {p.Id} | Name: {p.Name} | Price: {p.Price} Taka");
        }

        Console.WriteLine("\n--- একটি পণ্য খোঁজা (ID: 2) ---");
        var product = repo.GetById(2);
        Console.WriteLine($"Found: {product.Name}");

        Console.WriteLine("\n--- পণ্য ডিলিট করা (ID: 1) ---");
        repo.Remove(1);
        Console.WriteLine("Delete Successful!");

        Console.WriteLine("\n--- আপডেটেড লিস্ট ---");
        foreach (var p in repo.GetAll())
        {
            Console.WriteLine($"- {p.Name}");
        }
    }
}
```

# 📝 অধ্যায় ৬: সারাংশ (Summary)

আজকের ক্লাসের **Key Points**:

১. **Abstraction:** রিপজিটরি ব্যবহার করায় `Program.cs` জানতেই পারল না ডাটাবেসটা কোথায় বা কিভাবে কাজ করছে। সে শুধু `Add` বা `GetAll` মেথড কল করেছে।
২. **Interface Power:** আমরা `IProductRepository` ইন্টারফেস ব্যবহার করেছি। ভবিষ্যতে যদি আমরা `SQL Server` থেকে `MongoDB`-তে শিফট করতে চাই, শুধু `ProductRepository` ক্লাসটা পাল্টে দিলেই হবে, `Program.cs`-এ কোনো চেঞ্জ করতে হবে না।
৩. **Testing:** ইন-মেমোরি ডাটাবেস ব্যবহার করে আমরা প্রমাণ করলাম যে ডাটাবেস সার্ভার ছাড়াই কোড লজিক টেস্ট করা সম্ভব।

**Real-World Scenario:**
বড় এন্টারপ্রাইজ অ্যাপ্লিকেশনে (যেমন: ব্যাংক বা ই-কমার্স) সরাসরি কন্ট্রোলারে ডাটাবেস কল করা নিষিদ্ধ। সেখানে সবসময় এই রিপজিটরি প্যাটার্ন ব্যবহার করা হয় যাতে কোড ক্লিন, টেস্টেবল এবং মেইনটেইনযোগ্য থাকে।

আজই কোডটি রান করুন এবং নিজেকে একজন **"Repository Master"** হিসেবে গড়ে তুলুন! 🚀😎
