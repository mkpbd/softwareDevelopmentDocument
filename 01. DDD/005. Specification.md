স্বাগতম ফিউচার কোডারস! 🎓

আজকের ক্লাসে আমরা শিখব **Specification Pattern**। নামটা শুনলে মনে হয় কোনো রকেটের যন্ত্রাংশ, কিন্তু আসলে এটা হলো আমাদের কোডের **"ছাঁকনি"** বা **"ফিল্টার মেশিন"**।

আমরা যখন রিপজিটরি প্যাটার্ন ব্যবহার করি, তখন মাঝে মাঝে আমাদের রিপজিটরিটা **"মোটা"** হয়ে যায়। এই মোটা রিপজিটরিকে ডায়েট করিয়ে স্লিম করার জন্যই স্পেসিফিকেশন প্যাটার্ন ব্যবহার করা হয়।

চলুন, হাসতে হাসতে এবং মজার সব উদাহরণ দিয়ে এই টপিকটা শিখে ফেলি! 🚀

# 🕵️‍♂️ Specification আসলে কী? (What is it?)

সহজ বাংলায়, **Specification** হলো এমন একটি ছোট ক্লাস, যার কাজ হলো বলে দেওয়া—কোনো ডাটা **"সিলেকশন লিস্টে টিকবে কি টিকবে না"**।

### 🤣 মজার উদাহরণ: "ঘটক পাখি ভাই"
ধরুন আপনি বিয়ের জন্য পাত্র/পাত্রী খুঁজছেন। আপনি ঘটককে বললেন:
১. পাত্রকে সরকারি চাকরি করতে হবে।
২. উচ্চতা ৫ ফুটের বেশি হতে হবে।
৩. বয়স ৩০-এর নিচে হতে হবে।

এই যে ৩টি শর্ত দিলেন—এটাই হলো **Specification**।
ঘটক (Repository) হাজার হাজার বায়োডাটা (Database) থেকে এই শর্ত (Specification) দিয়ে ফিল্টার করে আপনাকে রেজাল্ট দেবে।

# 📚 স্পেসিফিকেশনের বিস্তারিত বিষয়গুলো

আমরা কোড এবং লজিক দিয়ে প্রতিটি অংশ বুঝব।

## ১. The Problem: The "Fat" Repository (মোটা রিপজিটরি সমস্যা) 🍔

**What happens:** স্পেসিফিকেশন না থাকলে আমরা রিপজিটরিতে অদ্ভুত সব মেথড লিখি।

**Bad Code Example:**
```csharp
public interface IProductRepository
{
    // স্বাভাবিক মেথড
    List<Product> GetAll();
    
    // সমস্যা শুরু এখান থেকে...
    List<Product> GetByCategory(string category);
    List<Product> GetByPriceRange(decimal min, decimal max);
    List<Product> GetByCategoryAndPrice(string category, decimal min, decimal max);
    List<Product> GetByCategoryAndPriceAndColor(string category, decimal min, decimal max, string color);
    // ...এভাবে চলতেই থাকবে! এটা একটা জগাখিচুড়ি! 🤯
}
```

**Why it's a problem:** প্রতিবার নতুন ফিল্টার দরকার হলে আপনাকে রিপজিটরিতে হাত দিতে হচ্ছে এবং নতুন মেথড বানাতে হচ্ছে। এটা **Open/Closed Principle** এর লঙ্ঘন।

---

## ২. The Solution: Specification Pattern 💡

**What it does:** আমরা ফিল্টারের লজিকটা রিপজিটরি থেকে বের করে আলাদা ক্লাসে নিয়ে যাই।

**How it works:** আমরা একটি রুল বা নিয়ম বানাই।
ধরি, আমাদের নিয়ম হলো: **"দামি প্রোডাক্ট"** (যাদের দাম ১০০০ টাকার বেশি)।

**Simple Code Example:**

```csharp
using System.Linq.Expressions;

// ১. স্পেসিফিকেশনের বেসিক কাঠামো (জেনেরিক)
public interface ISpecification<T>
{
    // এটা একটা এক্সপ্রেশন রিটার্ন করে যা LINQ তে 'Where' এর মধ্যে ঢুকবে
    Expression<Func<T, bool>> ToExpression();
}

// ২. আমাদের স্পেশাল রুল: "দামি প্রোডাক্ট"
public class ExpensiveProductSpec : ISpecification<Product>
{
    public Expression<Func<Product, bool>> ToExpression()
    {
        // লজিক: দাম ১০০০ এর বেশি হতে হবে
        return product => product.Price > 1000;
    }
}
```

## ৩. রিপজিটরিতে ব্যবহার (Integration) 🔌

**Why it works:** এখন রিপজিটরিতে আমাদের ১০০টা মেথড লাগবে না। শুধু **একটা** মেথড দিয়েই দুনিয়ার সব ফিল্টার করা যাবে।

**The Magic Repository Code:**

```csharp
public class ProductRepository
{
    private readonly AppDbContext _context; // ডাটাবেস

    // ... কনস্ট্রাক্টর ...

    // এই একটা মেথডই সব কাজ করবে!
    public List<Product> Find(ISpecification<Product> spec)
    {
        // স্পেসিফিকেশনের লজিকটা 'Where' এর মধ্যে বসিয়ে দিলাম
        return _context.Products
                       .Where(spec.ToExpression())
                       .ToList();
    }
}
```

**Real-Life Usage:**
```csharp
var repo = new ProductRepository(context);

// ১. শুধু দামি প্রোডাক্ট চাই
var expensiveSpec = new ExpensiveProductSpec();
var results = repo.Find(expensiveSpec);

// ২. ইলেকট্রনিক্স প্রোডাক্ট চাই (আরেকটা স্পেসিফিকেশন বানালেই হবে)
var electronicsSpec = new CategorySpec("Electronics");
var electronics = repo.Find(electronicsSpec);
```
**Advantage:** রিপজিটরি ফাইলে আর হাত দেওয়া লাগছে না! নতুন ফিল্টার দরকার? নতুন `Class` বানান, রিপজিটরিতে পাঠিয়ে দিন। ব্যাস!

---

## ৪. Combining Specifications (একের ভেতর অনেক) 🔗

**Topic:** AND, OR, NOT অপারেশন।
**Real-World Use:** ই-কমার্স সাইটে আমরা যেমন ফিল্টার করি— *"কালার লাল **এবং** সাইজ মিডিয়াম **অথবা** ব্র্যান্ড বাটা"*।

**Code Logic:**
আমরা স্পেসিফিকেশনগুলোকে জোড়া লাগাতে পারি।
```csharp
var spec = new ExpensiveProductSpec()
               .And(new CategorySpec("Electronics")); 
               // অর্থাৎ: দামিও হতে হবে এবং ইলেকট্রনিক্সও হতে হবে।

var finalResult = repo.Find(spec);
```
*(নোট: এর জন্য ছোট একটি হেল্পার ক্লাস বা লাইব্রেরি লাগে যা এক্সপ্রেশন কম্বাইন করে।)*

# ⚠️ সমস্যা ও সমাধান (Problems & Solutions)

সব কিছুরই সাইড ইফেক্ট আছে। স্পেসিফিকেশনেরও আছে।

### সমস্যা ১: Over-Engineering (মশা মারতে কামান দাগা)
**Problem:** আপনি যদি শুধু `GetById` বা খুব সাধারণ কাজের জন্য স্পেসিফিকেশন প্যাটার্ন ব্যবহার করেন, তবে কোড অহেতুক জটিল হয়ে যাবে।
**Solution:** সাধারণ CRUD অপারেশনের জন্য সিম্পল মেথড ব্যবহার করুন। যখন লজিক জটিল হবে (যেমন: অনেকগুলো `Where` ক্লজ লাগবে), তখনই কেবল স্পেসিফিকেশন ব্যবহার করুন।

### সমস্যা ২: Debugging Difficulty
**Problem:** যেহেতু লজিকটা অন্য ক্লাসে (`Expression` আকারে) থাকে, মাঝে মাঝে ডিবাগ করা বা বোঝা কঠিন হতে পারে যে ডাটাবেসে আসলে কী কোয়েরি যাচ্ছে।
**Solution:** `ToString()` বা লগিং ব্যবহার করে জেনারেট হওয়া SQL কোয়েরি চেক করে নেওয়া।

# 📝 সারাংশ (Summary)

আজকের ক্লাসের **"Take Home"** পয়েন্টগুলো হলো:

১. **What:** স্পেসিফিকেশন হলো লজিক বা ফিল্টারের আলাদা ক্লাস।
২. **Why:** এটি রিপজিটরিকে স্লিম রাখে এবং কোড ডুপ্লিকেশন কমায়।
৩. **Power:** আপনি ছোট ছোট রুল (Rules) বানিয়ে সেগুলোকে `AND`, `OR` দিয়ে জোড়া লাগিয়ে বিশাল লজিক বানাতে পারেন।
৪. **Advice:** ছোটখাটো কুয়েরির জন্য এটি ব্যবহার করবেন না, জটিল ফিল্টারিং-এর জন্য এটি জাদুর মতো কাজ করে!

আশা করি স্পেসিফিকেশন প্যাটার্ন এখন আপনাদের কাছে **"পানির মতো পরিষ্কার"**! নেক্সট প্রজেক্টে আর লম্বা লম্বা `Where` ক্লজ না লিখে, সুন্দর করে স্পেসিফিকেশন ক্লাস বানিয়ে ফেলুন! 😎🚀

=======================================================

স্বাগতম ফিউচার কোড-মাস্টাররা! 🎓

আজকের ক্লাসে আমরা সফটওয়্যার আর্কিটেকচারের একটি **"জাদুকরী টুল"** নিয়ে আলোচনা করব, যার নাম **Specification Pattern**।

ধরুন আপনি একটি বিশাল ই-কমার্স সাইট বানাচ্ছেন (যেমন দারাজ বা অ্যামাজন)। সেখানে হাজার হাজার প্রোডাক্ট। ইউজাররা সার্চ বক্সে এসে বলল:
*"আমাকে এমন মোবাইল দেখাও যা স্যামসাং ব্র্যান্ডের, দাম ৫০ হাজারের নিচে, র‍্যাম ৮ জিবি এবং রং কালো।"*

এখন, এই এতগুলো শর্ত যদি আপনি **Repository**-র ভেতরে `if-else` বা আলাদা আলাদা মেথড দিয়ে লিখতে যান, তবে রিপজিটরি হয়ে যাবে **"জগাখিচুড়ি"**। এই সমস্যা সমাধান করতেই আসে **Specification Pattern**।

এটি মূলত লজিক বা ফিল্টারগুলোকে ছোট ছোট ক্লাসে ভাগ করে ফেলার টেকনিক। চলুন, ল্যাব ক্লাসের মতো স্টেপ-বাই-স্টেপ শিখে ফেলি!

# 💻 অধ্যায় ২: কোডিং – মোবাইল ফোনের দোকান

আমরা একটি মোবাইলের দোকানের উদাহরণ নেব। আমাদের লক্ষ্য হলো বিভিন্ন শর্তে (যেমন: ব্র্যান্ড, দাম) মোবাইল খুঁজে বের করা।

### ধাপ ১: ডোমেইন এনটিটি (Mobile Class)
প্রথমে আমরা আমাদের প্রোডাক্ট বা মোবাইল ক্লাসটি বানাই।

```csharp
public class Mobile
{
    public string Name { get; set; }
    public string Brand { get; set; }
    public decimal Price { get; set; }
    public string Color { get; set; }

    public Mobile(string name, string brand, decimal price, string color)
    {
        Name = name;
        Brand = brand;
        Price = price;
        Color = color;
    }
}
```

### ধাপ ২: স্পেসিফিকেশন ইন্টারফেস (The Contract) 📜
এটি হলো স্পেসিফিকেশনের মেইন ব্লু-প্রিন্ট।

```csharp
using System;
using System.Linq.Expressions;

// T হলো জেনেরিক টাইপ (যেমন এখানে Mobile)
public interface ISpecification<T>
{
    // এই মেথডটি একটি 'শর্ত' রিটার্ন করবে যা True বা False হতে পারে
    // Expression<Func<...>> ব্যবহার করা হয় যাতে এটি SQL-এ কনভার্ট করা যায়
    Expression<Func<T, bool>> ToExpression();
}
```

**🔍 লজিক ব্যাখ্যা:**
আমরা কেন শুধু `Func<T, bool>` ব্যবহার করলাম না? কেন `Expression` লাগালাম?
কারণ, আমরা যদি Entity Framework ব্যবহার করি, তবে EF Core সাধারণ C# কোড বোঝে না। `Expression` ব্যবহার করলে EF Core সেটাকে পড়ে **SQL Query** (`WHERE Brand = 'Samsung'`) তে রূপান্তর করতে পারে।

### ধাপ ৩: ফিল্টার বা রুলস তৈরি করা (Concrete Specifications)
এখন আমরা আলাদা আলাদা শর্তের জন্য আলাদা ক্লাস বানাব।

**শর্ত ১: শুধু স্যামসাং ব্র্যান্ডের মোবাইল চাই**
```csharp
public class SamsungMobileSpec : ISpecification<Mobile>
{
    public Expression<Func<Mobile, bool>> ToExpression()
    {
        // লজিক: ব্র্যান্ড হতে হবে Samsung
        return mobile => mobile.Brand == "Samsung";
    }
}
```

**শর্ত ২: সস্তা মোবাইল চাই (৩০,০০০ টাকার নিচে)**
```csharp
public class BudgetMobileSpec : ISpecification<Mobile>
{
    public Expression<Func<Mobile, bool>> ToExpression()
    {
        // লজিক: দাম হতে হবে ৩০০০০ এর কম
        return mobile => mobile.Price < 30000;
    }
}
```

### ধাপ ৪: জেনেরিক রিপজিটরি (যে ফিল্টার ব্যবহার করবে)
এখন আমরা এমন একটি মেথড লিখব যা যেকোনো স্পেসিফিকেশন গ্রহণ করতে পারে।

```csharp
using System.Collections.Generic;
using System.Linq;

public class MobileRepository
{
    private readonly List<Mobile> _mobiles;

    public MobileRepository()
    {
        // কিছু ডামি ডাটা
        _mobiles = new List<Mobile>
        {
            new Mobile("Galaxy S23", "Samsung", 85000, "Black"),
            new Mobile("Galaxy A04", "Samsung", 15000, "Blue"),
            new Mobile("iPhone 14", "Apple", 120000, "White"),
            new Mobile("Redmi Note 12", "Xiaomi", 22000, "Black"),
            new Mobile("Pixel 7", "Google", 60000, "Green")
        };
    }

    // 🔥 ম্যাজিক মেথড!
    public IEnumerable<Mobile> Find(ISpecification<Mobile> spec)
    {
        // এখানে আমরা স্পেসিফিকেশনের লজিক (Expression) দিয়ে ডাটা ফিল্টার করছি
        return _mobiles.AsQueryable().Where(spec.ToExpression()).ToList();
    }
}
```

# 🌍 অধ্যায় ৩: রিয়েল-লাইফ এক্সিকিউশন (Main Program)

এখন দেখি প্রোগ্রামটি বাস্তবে কীভাবে কাজ করে।

```csharp
class Program
{
    static void Main(string[] args)
    {
        var repo = new MobileRepository();

        Console.WriteLine("--- ১. সব স্যামসাং মোবাইল খুঁজছি ---");
        var samsungSpec = new SamsungMobileSpec();
        var samsungMobiles = repo.Find(samsungSpec);

        foreach (var m in samsungMobiles)
        {
            Console.WriteLine($"- {m.Name} ({m.Price} Taka)");
        }


        Console.WriteLine("\n--- ২. বাজেট মোবাইল (৩০k এর নিচে) খুঁজছি ---");
        var budgetSpec = new BudgetMobileSpec();
        var cheapMobiles = repo.Find(budgetSpec);

        foreach (var m in cheapMobiles)
        {
            Console.WriteLine($"- {m.Name} ({m.Brand}) - {m.Price} Taka");
        }
    }
}
```

# ⚠️ অধ্যায় ৪: সমস্যা ও সমাধান (Common Problems)

### সমস্যা ১: অনেকগুলো ছোট ক্লাস (Class Explosion)
**সমস্যা:** প্রতিটি ছোট শর্তের জন্য (যেমন: কালার লাল, কালার নীল, র‍্যাম ৪ জিবি, র‍্যাম ৮ জিবি) আলাদা ক্লাস বানাতে গেলে প্রজেক্টে হাজার হাজার ক্লাস হয়ে যাবে।
**সমাধান:** **Parameterized Specification** ব্যবহার করুন। আলাদা `RedColorSpec`, `BlueColorSpec` না বানিয়ে একটি `ColorSpec(string color)` ক্লাস বানান।

```csharp
public class ColorSpec : ISpecification<Mobile>
{
    private readonly string _color;
    public ColorSpec(string color) { _color = color; }
    
    public Expression<Func<Mobile, bool>> ToExpression()
    {
        return x => x.Color == _color;
    }
}
```

### সমস্যা ২: একাধিক শর্ত যোগ করা (Combining Rules)
**সমস্যা:** ইউজার চাইল "Samsung" **AND** "Black"। এটার জন্য আলাদা `SamsungAndBlackSpec` বানানো বোকামি।
**সমাধান:** একটি বেস ক্লাস বা এক্সটেনশন মেথড ব্যবহার করে `And`, `Or`, `Not` লজিক ইমপ্লিমেন্ট করা যায়। (যেমন: `samsungSpec.And(blackSpec)`).

# 📝 অধ্যায় ৫: সারাংশ (Summary)

আজকের চ্যাপ্টারের **Key Points**:

১. **Separation of Logic:** আমরা রিপজিটরির ভেতরে `if (brand == "Samsung")` টাইপ কোড না লিখে, লজিকটা `SamsungMobileSpec` ক্লাসে সরিয়ে নিয়েছি। রিপজিটরি এখন ক্লিন।
২. **Reusability:** একবার `BudgetMobileSpec` বানালে আপনি সেটা প্রোডাক্ট লিস্ট, কার্ট পেজ বা অফার পেজ—যেকোনো জায়গায় ব্যবহার করতে পারবেন।
৩. **Testing Friendly:** আপনি খুব সহজেই টেস্ট করতে পারবেন আপনার "বাজেট লজিক" ঠিক আছে কিনা, পুরো ডাটাবেস টেস্ট করার দরকার নেই।

**Real-World Scenario:**
বড় এন্টারপ্রাইজ অ্যাপ্লিকেশনে (ERP, Banking Software) যেখানে শত শত ভ্যালিডেশন এবং ফিল্টারিং রুল থাকে, সেখানে **Specification Pattern** ব্যবহার করে কোডকে মেইনটেইনযোগ্য রাখা হয়। এটি **Domain Driven Design (DDD)**-এর একটি অবিচ্ছেদ্য অংশ।

কোডটি রান করুন এবং নতুন একটি স্পেসিফিকেশন (যেমন: `AppleMobileSpec`) বানিয়ে প্র্যাকটিস করুন! হ্যাপি কোডিং! 🚀😎
