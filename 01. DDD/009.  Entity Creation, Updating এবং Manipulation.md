স্বাগতম ফিউচার সফটওয়্যার আর্কিটেক্টরা! 🎓

আজকের ক্লাসে আমরা শিখব **Entity Creation, Updating এবং Manipulation**।

সহজ কথায়, একটা এনটিটি (Entity)-কে **কীভাবে জন্ম দেবেন (Create)**, তাকে **কীভাবে বড় করবেন (Update)** এবং তাকে দিয়ে **কীভাবে কাজ করাবেন (Manipulate)**—সেটাই আজকের পড়ার বিষয়।

অনেকে মনে করে এনটিটি হলো **"আলুর বস্তা"** (Data Bag)—যাতে ইচ্ছেমতো ডাটা ভরা যায় আর বের করা যায়। **ভুল!** এনটিটি হলো জীবন্ত মানুষের মতো। এর জন্ম সুন্দরভাবে হতে হয় এবং এর গায়ে হাত দেওয়ার নির্দিষ্ট নিয়ম আছে।

আজ আমরা শিখব কীভাবে "আলুর বস্তা" না বানিয়ে একটি **"স্মার্ট এনটিটি"** বানাতে হয়। খাতা-কলম রেডি? 🚀

# ১. Entity Creation (এনটিটির জন্ম) 👶

### 🔍 এটা কী? (What it does)
এনটিটি ক্রিয়েশন হলো এনটিটি ক্লাসের একটি অবজেক্ট তৈরি করার প্রক্রিয়া। সাধারণত আমরা `new ClassName()` দিয়ে এটা করি।

### 🛠️ সমস্যা: The "Zombie" Object (জম্বি অবজেক্ট)
অনেকে এনটিটি বানায় এভাবে:
```csharp
// ভুল পদ্ধতি ❌
var user = new User(); // জন্ম হলো, কিন্তু নাম নাই, ইমেইল নাই! (জম্বি)
user.Name = "Boltu";   // পরে নাম দিলাম
user.Email = "boltu@gmail.com";
```
**সমস্যা:** আপনি যদি লাইন ২ আর ৩ লিখতে ভুলে যান? তাহলে সিস্টেমে একটা নাম-পরিচয়হীন ইউজার ঘুরে বেড়াবে। এটা ডেঞ্জারাস!

### ✅ সমাধান: Constructor (জন্মেই সব দিতে হবে)
আমরা ডিফল্ট বা খালি কনস্ট্রাক্টর (`public User() {}`) বন্ধ করে দেব। অবজেক্ট তৈরির সময় যা যা **"মাস্ট"** লাগবে, তা কনস্ট্রাক্টরেই চেয়ে নেব।

**Bangla Example:**
বাচ্চা যখন জন্মায়, তার কি হাত-পা পরে লাগানো হয়? না! সে হাত-পা, কলিজা-ফুসফুস নিয়েই জন্মায়। এনটিটিও তাই।

**Code Example:**
```csharp
public class User
{
    public string Name { get; private set; }
    public string Email { get; private set; }

    // কনস্ট্রাক্টর
    public User(string name, string email)
    {
        // ভ্যালিডেশন (গার্ড)
        if (string.IsNullOrEmpty(name)) throw new Exception("নাম ছাড়া ইউজার হয় না মামা!");
        
        Name = name;
        Email = email;
    }
}

// ব্যবহারের নিয়ম:
var user = new User("Boltu", "boltu@gmail.com"); // ✔️ পারফেক্ট জন্ম
```

# ২. Entity Validation (গার্ড বা সিকিউরিটি) 🛡️

### 🔍 এটা কী? (What it does)
এনটিটি তৈরি বা আপডেট করার সময় চেক করা যে ডাটা ভ্যালিড কি না। একে **Guard Clause** বলা হয়।

### 🛠️ কেন জরুরি? (Why important)
**Garbage In, Garbage Out.** আপনি যদি ডাটাবেসে ভুল ভাল ডাটা ঢুকতে দেন, তবে পুরো সিস্টেম পচে যাবে।

### 🤣 মজার উদাহরণ:
আপনি কি বাজারে গিয়ে পচা মাছ কেনেন? না! মাছের কানকো উল্টে দেখেন। এনটিটিও ডাটা রিসিভ করার সময় চেক করে নেবে ডাটা টাটকা (Valid) কি না।

**Code Example:**
```csharp
public User(string name, string email)
{
    // গার্ড: নাম খালি হতে পারবে না
    if (string.IsNullOrWhiteSpace(name)) 
        throw new ArgumentException("নাম দেন ভাই!");

    // গার্ড: ইমেইলে @ থাকতে হবে
    if (!email.Contains("@")) 
        throw new ArgumentException("এটা কেমন ইমেইল?");

    Name = name;
    Email = email;
}
```

# ৩. Manipulation & Updating (পরিবর্তন ও নড়াচড়া) 🏃‍♂️

### 🔍 এটা কী? (What it does)
এনটিটির ভেতরের ডাটা (Properties) পরিবর্তন করার নিয়ম।

### 🛠️ সমস্যা: Public Setters (খোলা দরজা) 🚪
বেশিরভাগ ডেভেলপার এনটিটির প্রপার্টিগুলো `public set;` করে রাখে।
```csharp
// ভুল পদ্ধতি ❌
public class User 
{ 
    public int Age { get; set; } // যে কেউ বাইরে থেকে বদলাতে পারে
}

// কেউ একজন দুষ্টামি করে লিখল:
user.Age = -500; // মানুষের বয়স কি মাইনাস হয়?
```
**সমস্যা:** এনটিটির কোনো কন্ট্রোল থাকে না। যে কেউ এসে ডাটা নষ্ট করে দিতে পারে। একে বলে **Anemic Domain Model** (রক্তশূন্য এনটিটি)।

### ✅ সমাধান: Encapsulation & Domain Methods
আমরা সেটার (Setter) `private` করে দেব। আর ডাটা বদলানোর জন্য নির্দিষ্ট অর্থপূর্ণ মেথড বানাব।

**Bangla Example:**
আপনার হার্টবিট কি আপনি হাত দিয়ে পাম্প করে বাড়ান? না! আপনি দৌড় দিলে হার্টবিট একা বাড়ে।
তেমনি, `user.Age = 25` না লিখে আমরা লিখব `user.CelebrateBirthday()`।

**Code Example:**
```csharp
public class User
{
    public int Age { get; private set; } // 🔒 প্রাইভেট সেটার

    public string Address { get; private set; }

    // মেথড ১: বয়স বাড়ানো
    public void CelebrateBirthday()
    {
        Age++; // লজিক এনটিটির ভেতরে
    }

    // মেথড ২: বাসা বদলানো
    public void MoveToNewCity(string newAddress)
    {
        if (string.IsNullOrEmpty(newAddress)) throw new Exception("ঠিকানা কই?");
        Address = newAddress;
        // এখানে চাইলে আরও লজিক দেওয়া যায় (যেমন: ইমেইল পাঠানো)
    }
}
```

# ৪. Static Factory Methods (স্পেশাল জন্ম প্রক্রিয়া) 🏭

### 🔍 এটা কী? (What it does)
মাঝে মাঝে কনস্ট্রাক্টর দিয়ে অবজেক্ট বানানো কনফিউজিং হতে পারে। তখন আমরা `static` মেথড ব্যবহার করি যা অবজেক্ট তৈরি করে রিটার্ন করে।

### 🤣 কেন জরুরি?
ধরুন `User` ক্লাসের দুটি কনস্ট্রাক্টর আছে। কোনটা "Admin" তৈরির জন্য আর কোনটা "Customer" তৈরির জন্য—বোঝা কঠিন।
ফ্যাক্টরি মেথড দিয়ে আমরা নাম দিয়ে দিতে পারি: `User.CreateAdmin(...)`।

**Code Example:**
```csharp
public class User
{
    private User(string name, string role) { ... } // কনস্ট্রাক্টর প্রাইভেট

    // ফ্যাক্টরি মেথড ১
    public static User CreateAdmin(string name)
    {
        return new User(name, "Admin");
    }

    // ফ্যাক্টরি মেথড ২
    public static User CreateGuest()
    {
        return new User("Guest", "Visitor");
    }
}

// ব্যবহার:
var admin = User.CreateAdmin("Chowdhury Saheb");
```

# ⚠️ কমন সমস্যা ও সমাধান (Summary of Problems)

| সমস্যা | কেন হয়? | সমাধান |
| :--- | :--- | :--- |
| **Invalid Object** | খালি কনস্ট্রাক্টর ব্যবহার করলে। | সব রিকোয়ার্ড ডাটা **Constructor**-এ নিন। |
| **Invalid State** | ভ্যালিডেশন না থাকলে (যেমন: বয়স -৫)। | কনস্ট্রাক্টরে **Guard Clause** ব্যবহার করুন। |
| **Anemic Model** | সব প্রপার্টির `public set;` থাকলে। | **Private Setter** ব্যবহার করুন এবং ডাটা বদলাতে **Method** ব্যবহার করুন। |
| **Confusing Creation** | অনেক কনস্ট্রাক্টর থাকলে। | **Static Factory Method** ব্যবহার করুন। |

আজ আমরা শিখব কীভাবে "আলুর বস্তা" না বানিয়ে একটি **"স্মার্ট এনটিটি"** বানাতে হয়। খাতা-কলম আর ল্যাপটপ নিয়ে রেডি হয়ে যান! 🚀

# 💻 অধ্যায় ২: কোডিং – গেম প্লেয়ার তৈরি (Entity Creation)

### 🧐 ভুল পদ্ধতি: The "Zombie" Object (জম্বি প্লেয়ার) 🧟‍♂️
বেশিরভাগ নতুন ডেভেলপার এনটিটি বানায় এভাবে:

```csharp
// ❌ ভুল পদ্ধতি (Anemic Model)
public class BadPlayer
{
    public string Name { get; set; } // দরজা খোলা
    public int Health { get; set; }
}

// ব্যবহারের সময়:
var p1 = new BadPlayer(); // নাম নাই, হেলথ নাই—একটা জম্বি জন্ম নিল!
p1.Name = "ProKiller";
p1.Health = -100; // 😱 হেলথ মাইনাস! এটা কি সম্ভব?
```
**সমস্যা:** এখানে `p1` শুরুতে জম্বি ছিল (কোনো ডাটা ছিল না)। পরে কেউ তার হেলথ `-100` করে দিল, যা গেমে অসম্ভব। এই অবজেক্টের ওপর কোনো কন্ট্রোল নেই।

---

### ✅ সঠিক পদ্ধতি: The "Smart" Entity (স্মার্ট প্লেয়ার) 🤖
এখন আমরা এমন এনটিটি বানাব যে জন্মের সময় সব ডাটা চাইবে এবং ভুল ডাটা নিতে অস্বীকার করবে।

```csharp
using System;

public class Player
{
    // ১. Private Setter: চাবি আমার কাছে, কেউ বাইরে থেকে সেট করতে পারবে না
    public Guid Id { get; private set; }
    public string Username { get; private set; }
    public int Health { get; private set; }
    public int Level { get; private set; }

    // ২. Constructor (The Birth): জন্মের সময় সব ভ্যালিড ডাটা দিতে হবে
    public Player(string username)
    {
        Id = Guid.NewGuid(); // অটো আইডি
        
        // ভ্যালিডেশন (Guard Clause)
        if (string.IsNullOrWhiteSpace(username))
        {
            throw new ArgumentException("নাম ছাড়া প্লেয়ার হয় না মামা!");
        }
        if (username.Length < 3)
        {
            throw new ArgumentException("নাম অন্তত ৩ অক্ষরের হতে হবে।");
        }

        Username = username;
        Health = 100; // জন্মের সময় সবাই ১০০% ফিট থাকে
        Level = 1;    // লেভেল ১ দিয়ে শুরু
    }

    // ৩. Manipulation Methods (আচরণ): ডাটা পাল্টানোর নির্দিষ্ট নিয়ম
    
    // ড্যামেজ খাওয়া (Health কমানো)
    public void TakeDamage(int damage)
    {
        if (damage < 0) throw new Exception("ড্যামেজ নেগেটিভ হয় না!");
        
        Health -= damage;
        if (Health < 0) Health = 0; // মরে গেছে, কিন্তু মাইনাস হবে না
        
        Console.WriteLine($"{Username} গুলি খেয়েছে! হেলথ বাকি: {Health}");
    }

    // হিল করা (Health বাড়ানো)
    public void Heal(int amount)
    {
        if (Health <= 0) throw new Exception("মরা মানুষ হিল করা যায় না!");
        
        Health += amount;
        if (Health > 100) Health = 100; // ১০০ এর বেশি হেলথ হবে না

        Console.WriteLine($"{Username} মেডিকিট নিয়েছে! হেলথ: {Health}");
    }
}
```

# 🧠 অধ্যায় ৩: লজিক এবং কেন এভাবে লিখলাম?

### ১. কেন `private set`? (Encapsulation)
`public set` থাকলে যে কেউ কোডের যেকোনো জায়গা থেকে `player.Health = 5000` করে হ্যাক করতে পারত। `private set` দিয়ে আমরা দরজা বন্ধ করে দিলাম। এখন হেলথ কমাতে হলে `TakeDamage()` মেথড দিয়েই আসতে হবে, যেখানে আমাদের লজিক (0 এর নিচে নামবে না) বসানো আছে।

### ২. কেন Constructor-এ ভ্যালিডেশন? (Invariants)
একটি এনটিটি সব সময় **Valid State**-এ থাকতে হবে। কনস্ট্রাক্টরে চেক করার কারণে, নাম ছাড়া কোনো `Player` অবজেক্ট মেমোরিতে তৈরিই হতে পারবে না। সিস্টেম নিরাপদ থাকল।

### ৩. Manipulation Methods (Rich Domain Model)
আমরা `SetHealth()` বা `SetLevel()` টাইপ বোকা মেথড ব্যবহার করিনি। আমরা ব্যবহার করেছি **বিজনেস ল্যাঙ্গুয়েজ**—`TakeDamage`, `Heal`, `LevelUp`। এতে কোড পড়লেই বোঝা যায় গেমে কী হচ্ছে।

# ⚠️ অধ্যায় ৫: সমস্যা ও সমাধান (Common Problems)

### সমস্যা ১: Constructor Hell (অনেক বেশি প্যারামিটার)
**Problem:** এনটিটি বড় হলে কনস্ট্রাক্টরে ১০-১৫টা প্যারামিটার হয়ে যায়। `new User(name, email, phone, address, age, gender...)`—এটা ম্যানেজ করা কঠিন।
**Solution:**
১. **Static Factory Method:** `User.CreateWithEmail(...)` এমন মেথড ব্যবহার করুন।
২. **Builder Pattern:** অবজেক্ট তৈরির জন্য বিল্ডার ক্লাস ব্যবহার করুন।

### সমস্যা ২: ORM (Entity Framework) এর কান্নাকাটি
**Problem:** EF Core ডাটাবেস থেকে ডাটা লোড করার সময় খালি কনস্ট্রাক্টর খোঁজে (অনেক ক্ষেত্রে)।
**Solution:** একটি `protected` বা `private` খালি কনস্ট্রাক্টর রেখে দিন। EF Core রিফ্লেকশন ব্যবহার করে সেটা খুঁজে নেবে, কিন্তু পাবলিকলি কেউ এক্সেস করতে পারবে না।
```csharp
// EF Core এর জন্য
protected Player() { }
```

# 📝 অধ্যায় ৬: সারাংশ (Summary)

আজকের ক্লাসের **Key Points**:

১. **Creation:** এনটিটির জন্ম হতে হবে পরিপূর্ণভাবে। কনস্ট্রাক্টর ব্যবহার করে নিশ্চিত করুন যে অবজেক্টটি ভ্যালিড (নাম-ধাম সব আছে)।
২. **Protection:** প্রপার্টির দরজা (`set`) বন্ধ রাখুন (`private`)। চোর যাতে ঢুকতে না পারে।
৩. **Manipulation:** ডাটা পরিবর্তনের জন্য `SetSomething()` না লিখে অর্থপূর্ণ মেথড (`DoSomething`) লিখুন।
৪. **Logic Inside:** লজিক (যেমন: হেলথ ০-এর নিচে যাবে না) এনটিটির ভেতরেই রাখুন। সার্ভিস লেয়ারে লজিক ছড়াবেন না।

**Real-World Scenario:**
ব্যাংকিং অ্যাপে `Balance` প্রপার্টি কখনোই পাবলিক থাকে না। `Deposit()` এবং `Withdraw()` মেথড থাকে। `Withdraw()` মেথডের ভেতরে চেক করা হয় ব্যালেন্স আছে কি না। এভাবেই হাজার কোটি টাকার সফটওয়্যার নিরাপদ থাকে।
