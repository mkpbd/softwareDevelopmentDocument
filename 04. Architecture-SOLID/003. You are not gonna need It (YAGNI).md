স্বাগতম আর্কিটেকচার ক্লাসে! 👷‍♂️🎓

আমি আপনাদের সেই আর্কিটেকচার গুরু। আজ আমরা এমন একটা টপিক নিয়ে কথা বলব, যেটা না মানলে আপনার প্রজেক্ট হয়ে যাবে **"দোকানদারের গুদাম ঘর"**—যেখানে শুধু অপ্রয়োজনীয় মালামাল পড়ে থাকে।

টপিকটা হলো **YAGNI**।
পুরো নাম: **You Aren't Gonna Need It**।
যার খাটি বাংলা অনুবাদ: **"ওহে বাপু, তোমার এটা লাগবে না! হুদাই প্যারা নিও না।"** ✋😎

ভাবুন তো, আপনি ৩ দিনের জন্য কক্সবাজার যাচ্ছেন। আপনি ব্যাগে কী নিলেন?
১. টি-শার্ট আর হাফপ্যান্ট। (ঠিক আছে)

এটাকে বলে পাগলামি! কক্সবাজার গিয়ে আপনার পিঠ ব্যথা হবে এত বোঝা টানতে গিয়ে। সফটওয়্যার আর্কিটেকচারেও আমরা এই কাজটা করি—ভবিষ্যতে কী লাগবে সেটা ভেবে এখনই কোড লিখে ভরাই ফেলি।

চলুন, YAGNI-এর বিস্তারিত সব টপিক মজার ছলে শিখে ফেলি।

### YAGNI আর্কিটেকচারের প্রধান বিষয়বস্তু (Topics/Objects of YAGNI)

YAGNI মূলত ডেভেলপারদের **"জ্যোতিষী" (Astrologer)** হওয়া থেকে আটকায়। এর প্রধান কনসেপ্টগুলো নিচে দেওয়া হলো:

#### ১. Speculative Features (কাল্পনিক ফিচার বা জ্যোতিষী কোড)

**What (এটা কী):**
ভবিষ্যতে ইউজারের কী লাগবে, সেটা আন্দাজ করে এখনই বানিয়ে রাখা।

**Why it works (কেন এটা বাদ দিতে হবে):**
আপনি ভাবলেন, "আমার ই-কমার্স সাইটে ইউজাররা হয়তো বিটকয়েন দিয়ে পেমেন্ট করতে চাইবে।" আপনি ১ মাস ধরে বিটকয়েন পেমেন্ট গেটওয়ে বানালেন।
লঞ্চ করার পর দেখলেন—ইউজাররা **"ক্যাশ অন ডেলিভারি"** ছাড়া কিছুই বোঝে না। আপনার ১ মাসের কষ্ট পুরোটাই জলে গেল!

**Bangla Example:**
রিকশা ওয়ালা মামার জন্য অ্যাপ বানাচ্ছেন। আপনি সেখানে "Helicopter Booking" অপশন রাখলেন, এই ভেবে যে—"বলা তো যায় না, মামা যদি বড়লোক হয়ে হেলিকপ্টার কিনে!" এটা হলো YAGNI ভায়োলেশন।

**Problem (সমস্যা):**
অপ্রয়োজনীয় ফিচার কোডবেসকে ভারী করে ফেলে। আসল ফিচার বানানোর সময় পাওয়া যায় না।

**Solution:**
বর্তমানে (Today) যেটা দরকার, শুধু সেটাই বানান। কালকের চিন্তা কালকে।

---

#### ২. Over-Abstraction (অতিরিক্ত জেনেরিক কোড)

**What (এটা কী):**
কোড এমনভাবে লেখা যেন সেটা দিয়ে দুনিয়ার সব সমস্যা সমাধান করা যায়। খুব বেশি ইন্টারফেস বা লেয়ার ব্যবহার করা।

**Why it works (কেন এটা বাদ দিতে হবে):**
আপনি একটা ফাংশন লিখলেন যেটা শুধু ২টা সংখ্যা যোগ করে। কিন্তু আপনি ভাবলেন, "যদি ভবিষ্যতে এটা দিয়ে রকেটের গতিবেগ মাপা হয়?" তাই আপনি ফাংশনটাকে এত জটিল করলেন যে এখন ২+২ করতেও ১০ লাইন কোড লাগে।

**Bangla Example:**
আপনি বাজারে যাবেন আলু কিনতে। আপনি ভাড়া করলেন একটা **ট্রাক**। কেন? যদি ভবিষ্যতে পুরো বাজারের সব আলু কেনা লাগে! অথচ আপনার পকেটে টাকা আছে মাত্র ১ কেজির।

**Problem:**
কোড বোঝা কঠিন হয়ে যায়। ছোট পরিবর্তনের জন্য অনেক জায়গায় হাত দিতে হয়।

**Solution:**
সাধারণ কোড লিখুন। যখন প্রয়োজন হবে, তখনই কেবল কোড এক্সপান্ড (Refactor) করবেন।

### কেন YAGNI এত গুরুত্বপূর্ণ? (Why is it Important?)

১. **Cost Saving (টাকা বাঁচায়):**
ডেভেলপারের সময়ের দাম অনেক। যে ফিচার কেউ ব্যবহার করবে না, সেটা বানানোর জন্য বেতন দেওয়া বোকামি।

২. **Faster Delivery (দ্রুত রিলিজ):**
১০টা ফিচারের বদলে ৩টা প্রয়োজনীয় ফিচার বানালে অ্যাপ ১ মাস আগেই রিলিজ দেওয়া যায়।

৩. **Better Quality (ভালো কোয়ালিটি):**
মনোযোগ ১০ দিকে ভাগ না করে ১ দিকে দিলে সেটার কোয়ালিটি ভালো হয়।

### সমস্যা ও সমাধান (Problems & Solutions) ⚠️

YAGNI শুনতে খুব ভালো লাগে, কিন্তু এটা ভুলভাবে ব্যবহার করলে বিপদ আছে।

**সমস্যা ১: No Design at all (কোনো প্ল্যান না থাকা)**
অনেকে YAGNI-র দোহাই দিয়ে আর্কিটেকচার বা প্ল্যানিং কিছুই করে না। তারা বলে, "পরে লাগলে দেখব"। এর ফলে কোড **Spaghetti (জগাখিচুড়ি)** হয়ে যায়।
*   **সমাধান:** YAGNI মানে প্ল্যান না করা নয়। YAGNI মানে হলো **অপ্রয়োজনীয়** জিনিস না বানানো। বেসিক স্ট্রাকচার ঠিক রাখতেই হবে।

**সমস্যা ২: Refactoring is Hard (পরে চেঞ্জ করা কঠিন)**
"এখন দরকার নেই" বলে খুব বাজে কোড লিখলে, ভবিষ্যতে যখন সত্যি দরকার হবে, তখন পুরো কোড ফেলে দিতে হতে পারে।
*   **সমাধান:** কোড ক্লিন (Clean Code) লিখুন। ফিচার কম হোক, কিন্তু কোডের মান যেন ভালো থাকে যাতে পরে সহজেই বাড়ানো যায়।

```csharp
// ❌ BAD Code (Violating YAGNI)
using System;

// আপনি ভবিষ্যতের চিন্তায় ইন্টারফেস বানালেন
public interface INotificationService
{
    void Send(string message);
}

// ইমেইল সার্ভিস (এটা এখন দরকার)
public class EmailService : INotificationService
{
    public void Send(string message) => Console.WriteLine($"Email sent: {message}");
}

// এসএমএস সার্ভিস (এটা কেউ চায়নি, তাও বানালেন)
public class SmsService : INotificationService
{
    public void Send(string message) => Console.WriteLine($"SMS sent: {message}");
}

// কবুতর সার্ভিস (এটা তো হাস্যকর!)
public class PigeonCarrierService : INotificationService
{
    public void Send(string message) => Console.WriteLine($"Pigeon flew away with: {message}");
}

// ফ্যাক্টরি প্যাটার্ন (অপ্রয়োজনীয় জটিলতা)
public class NotificationFactory
{
    public static INotificationService GetService(string type)
    {
        if (type == "sms") return new SmsService();
        if (type == "pigeon") return new PigeonCarrierService();
        return new EmailService();
    }
}

class Program
{
    static void Main(string[] args)
    {
        // এত কিছু করার পর, আমরা শুধু ইমেইলটাই ব্যবহার করছি
        var service = NotificationFactory.GetService("email");
        service.Send("Hello YAGNI!");
    }
}
```

**সমস্যা:**
*   আপনি SMS আর কবুতরের কোড লিখতে ২ দিন নষ্ট করেছেন।
*   ক্লায়েন্ট বলল, "SMS এর দরকার নেই।" ব্যাস! আপনার পরিশ্রম ডাস্টবিনে।
*   কোড জটিল হয়ে গেছে, নতুন কেউ এসে ভয় পাবে।

#### দৃশ্যপট ২: YAGNI মানলে (স্মার্ট কোড) ✅

এখন আমরা জ্যোতিষী হব না। বর্তমানে যেটা দরকার, শুধু সেটাই করব।

```csharp
// ✅ GOOD Code (Applying YAGNI)
using System;

// এখন শুধু ইমেইল দরকার, তাই সিম্পল ক্লাস। নো ইন্টারফেস, নো ফ্যাক্টরি।
public class EmailSender
{
    public void SendEmail(string message)
    {
        // লজিক খুব সিম্পল
        Console.WriteLine($"Email sent to customer: {message}");
    }
}

class Program
{
    static void Main(string[] args)
    {
        // সোজা সাপটা ব্যবহার
        EmailSender sender = new EmailSender();
        sender.SendEmail("Welcome to YAGNI principles!");
    }
}
```

**লজিক ও সুবিধা:**
*   **সময় বাঁচলো:** ২ দিনের কাজ ২ ঘণ্টায় শেষ।
*   **ক্লিন কোড:** কোনো জগাখিচুড়ি নেই।
*   **ভবিষ্যৎ:** যদি ৬ মাস পর ক্লায়েন্ট SMS চায়? তখন আমরা কোড আপডেট (Refactor) করব। কিন্তু আজ কেন প্যারা নেব?

### ৩. সাধারণ সমস্যা ও সমাধান (Common Problems & Resolutions) ⚠️

YAGNI মানতে গিয়ে কিছু ভুল বোঝাবুঝি হতে পারে।

**সমস্যা ১: "No Design" Trap (কোনো প্ল্যান না থাকা)**
অনেকে YAGNI-র দোহাই দিয়ে খুব বাজে কোড লেখে। তারা বলে, "আর্কিটেকচার পরে দেখব"।
*   **রেজোলিউশন:** YAGNI মানে *বাজে কোড* লেখা নয়। YAGNI মানে *অপ্রয়োজনীয় ফিচার* না লেখা। কোড ক্লিন এবং মডুলার রাখতে হবে যাতে ভবিষ্যতে ফিচার যোগ করা সহজ হয়।

**সমস্যা ২: "But It's Cheaper Now" (এখনই করে ফেলি)**
ডেভেলপাররা ভাবে, "এখনই ডাটাবেস সেটআপ করে ফেলি, পরে করতে গেলে ঝামেলা হবে।"
*   **রেজোলিউশন:** ৯০% ক্ষেত্রে আপনার অনুমান ভুল হবে। আপনি হয়তো SQL Server সেটআপ করলেন, কিন্তু পরে দেখা গেল প্রজেক্টের জন্য MongoDB দরকার ছিল। তাই রিকোয়ারমেন্ট না আসা পর্যন্ত অপেক্ষা করাই বুদ্ধিমানের কাজ।

### ৪. বাস্তব জীবনের উদাহরণ (Real-Life Scenario) 🌍

ধরুন আপনি একটা **Startup** এর জন্য ই-কমার্স ওয়েবসাইট বানাচ্ছেন।

**জ্যোতিষী ডেভেলপার (YAGNI Violator):**
1.  প্রথম দিনেই ভাবছে: "যদি ১ কোটি ইউজার আসে?" -> তাই মাইক্রোসার্ভিস (Microservices) বানাচ্ছে।
2.  "যদি ইউজার চাইনিজ ভাষায় কথা বলে?" -> তাই মাল্টি-ল্যাঙ্গুয়েজ সাপোর্ট বানাচ্ছে।
3.  "যদি ইউজার বিটকয়েন দেয়?" -> ক্রিপ্টো পেমেন্ট গেটওয়ে বানাচ্ছে।
**ফলাফল:** ৩ মাস পার, অ্যাপ রিলিজ হয়নি। স্টার্টআপের টাকা শেষ। কোম্পানি বন্ধ। 😭

**YAGNI ডেভেলপার:**
1.  "এখন ইউজার কত?" -> ০ জন। তাহলে সাধারণ একটা সার্ভারেই হবে।
2.  "ভাষা?" -> শুধু বাংলা।
3.  "পেমেন্ট?" -> ক্যাশ অন ডেলিভারি।
**ফলাফল:** ৭ দিনেই অ্যাপ লাইভ! ইউজাররা অর্ডার করছে, কোম্পানি লাভ করছে। ৬ মাস পর যখন ইউজার বাড়ল, তখন সার্ভার আপগ্রেড করল। 🚀

### ৫. সারাংশ (Summary) 📝

আজকের ক্লাসের মূল কথা:

1.  **ভবিষ্যৎবাণী করবেন না:** আপনার কোড ক্রিস্টাল বল নয়। কাল কী লাগবে, তা ভেবে আজ কোড জটিল করবেন না।
2.  **খরচ কমান:** যে ফিচার কেউ ব্যবহার করবে না, সেটা বানানোর জন্য আপনার মূল্যবান সময় নষ্ট করবেন না।
3.  **Refactoring:** কোড এমনভাবে লিখুন যেন ভবিষ্যতে নতুন ফিচার যোগ করা সহজ হয়, কিন্তু ফিচারটা আগেই যোগ করবেন না।

**গুরুত্ব:**
সফটওয়্যার ইন্ডাস্ট্রিতে পরিবর্তনই একমাত্র সত্য। রিকোয়ারমেন্ট বদলাবেই। তাই YAGNI আপনাকে অপ্রয়োজনীয় বোঝা থেকে বাঁচায় এবং আপনাকে **Agile** (দ্রুতগামী) হতে সাহায্য করে।

তাই মনে রাখবেন: **"দরকার হলে ডাকবো, এখন তুমি আসবো না!"** 😂
