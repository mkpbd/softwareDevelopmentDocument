### ১. পটভূমি: Starbuzz Coffee-র সমস্যা 😫

ভাবুন, **Starbuzz Coffee** নামে একটা বিখ্যাত কফি শপ আছে। তাদের কফি খুব জঘন্য ছিল, কিন্তু এখন তারা নিজেদের আপগ্রেড করছে।

শুরুতে তাদের সিস্টেম ছিল খুব সিম্পল:
একটা `Beverage` (পানীয়) অ্যাবস্ট্রাক্ট ক্লাস ছিল, আর তার নিচে `HouseBlend`, `DarkRoast`, `Espresso`, `Decaf` ইত্যাদি সাব-ক্লাস ছিল। সব ঠিকঠাক চলছিল।

**ঝামেলার শুরু:**
মানুষ শুধু কফি খায় না। কেউ চায় **দুধ (Milk)**, কেউ **সয়া (Soy)**, কেউ **মোকা (Mocha/Chocolate)**, আবার কেউ **হুইপ ক্রিম (Whip)**।
স্টারবাজ প্রথমে ভাবল, "আরে প্যারা নাই! আমরা সব কম্বিনেশনের জন্য আলাদা ক্লাস বানাব।"

ফলাফল?
*   `HouseBlendWithMilk`
*   `HouseBlendWithMilkAndMocha`
*   `DarkRoastWithSoyAndWhip`
*   `EspressoWithDoubleMochaAndWhip`

এভাবে চলতে থাকলে হাজার হাজার ক্লাস তৈরি হয়ে যাবে! একে বলা হয় **"Class Explosion"** বা ক্লাসের বিস্ফোরণ। 🤯

**দ্বিতীয় ভুল চেষ্টা:**
তারা ভাবল, "ঠিক আছে, এত ক্লাস বানাব না। আমরা `Beverage` প্যারেন্ট ক্লাসেই `hasMilk`, `hasMocha` ইত্যাদি বুলিয়ান ভেরিয়েবল রাখব।"

**কেন এটাও খারাপ?**
১. যদি চায়ের (Tea) দাম বাড়ে, আপনাকে `Beverage` ক্লাসে হাত দিতে হবে।
২. যদি ভবিষ্যতে নতুন কোনো টপিংস আসে (যেমন: ভ্যানিলা), আবার `Beverage` ক্লাসে হাত দিতে হবে।
৩. আইস টি (Ice Tea)-এর সাথে কেউ হুইপ ক্রিম নেয় না, কিন্তু প্যারেন্ট ক্লাসে মেথড থাকায় আইস টির সাথেও `hasWhip` মেথড চলে আসবে।

### ২. ডিজাইন প্রিন্সিপাল: Open-Closed Principle 🚪

এখানেই আসে আমাদের নতুন ডিজাইনের মূলমন্ত্র:
> **"Classes should be open for extension, but closed for modification."**

সহজ বাংলায়: **"ক্লাস এমনভাবে বানাতে হবে যেন নতুন ফিচার যোগ করা যায় (Extension), কিন্তু পুরানো কোডে হাত দেওয়া বা কাটাছেঁড়া করা না লাগে (Closed for Modification)।"**

ভাবুন আপনার শরীরের কথা। আপনি যদি পকেটে মোবাইল রাখতে চান, আপনি কি আপনার গায়ের চামড়া কেটে পকেট বানাবেন? 😱 না! আপনি একটা জ্যাকেট পরবেন (Extend করবেন), শরীরে কোনো কাটাছেঁড়া করবেন না। **Decorator Pattern** ঠিক এই কাজটিই করে।

### ৩. সমাধান: The Decorator Pattern 🎁

**ডেকোরেটর প্যাটার্ন**-এর মূল আইডিয়া হলো **"র‍্যাপার" (Wrapper)** বা মোড়ক।

*   আমরা মূল কফিকে (যেমন `DarkRoast`) একটা অবজেক্ট হিসেবে নিব।
*   যদি কাস্টমার মোকা (Mocha) চায়, আমরা কফিটাকে মোকা অবজেক্ট দিয়ে **র‍্যাপ (Wrap)** বা মুড়িয়ে দিব।
*   যদি কাস্টমার হুইপ (Whip) চায়, আমরা পুরো জিনিসটাকে আবার হুইপ দিয়ে মুড়িয়ে দিব।

**মজার বিষয়:** র‍্যাপার বা মোড়ক (Decorator) দেখতে অবিকল ভেতরের অবজেক্টের মতোই (একই টাইপ বা ইন্টারফেস)। তাই কাস্টমার বুঝতেই পারবে না সে কি শুধু কফি খাচ্ছে নাকি মোড়কসহ কফি খাচ্ছে!

### ৪. ডেকোরেটর প্যাটার্ন কিভাবে কাজ করে? (Step-by-Step) 🛠️

ধরি, আপনি অর্ডার দিলেন: **Dark Roast with Mocha and Whip.**

১. প্রথমে একটা `DarkRoast` অবজেক্ট তৈরি হবে।
২. তারপর একটা `Mocha` অবজেক্ট তৈরি হবে, যা `DarkRoast`-কে পেটের ভেতর রাখবে (Wrap করবে)।
৩. তারপর একটা `Whip` অবজেক্ট তৈরি হবে, যা `Mocha`-কে পেটের ভেতর রাখবে।

**হিসাব-নিকাশ (cost মেথড):**
যখন আপনি `Whip`-এর কাছে দাম জানতে চাইবেন (`cost()`):
1. `Whip` তার ভেতরের অবজেক্টকে (`Mocha`) দাম জিজ্ঞেস করবে।
2. `Mocha` তার ভেতরের অবজেক্টকে (`DarkRoast`) দাম জিজ্ঞেস করবে।
3. `DarkRoast` বলবে: "আমার দাম ১০০ টাকা।"
4. `Mocha` বলবে: "১০০ + আমার দাম ২০ = ১২০ টাকা।"
5. `Whip` বলবে: "১২০ + আমার দাম ১০ = ১৩০ টাকা।"

ফাইনাল দাম: **১৩০ টাকা।**

### ৫. কোড উদাহরণ (সহজ বাংলায়) 💻

```java
// ১. মূল ইন্টারফেস বা অ্যাবস্ট্রাক্ট ক্লাস
public abstract class Beverage {
    String description = "Unknown Beverage";
    public String getDescription() {
        return description;
    }
    public abstract double cost(); // সবার এই মেথড থাকতেই হবে
}

// ২. কনক্রিট কম্পোনেন্ট (আসল কফি)
public class DarkRoast extends Beverage {
    public DarkRoast() {
        description = "ডার্ক রোস্ট কফি";
    }
    public double cost() {
        return 100.0; // কফির বেস প্রাইস
    }
}

// ৩. ডেকোরেটর ক্লাস (র‍্যাপারদের সর্দার)
public abstract class CondimentDecorator extends Beverage {
    // ডেকোরেটরদের অবশ্যই অরিজিনাল বেভারেজের রেফারেন্স রাখতে হবে
    public abstract String getDescription();
}

// ৪. কনক্রিট ডেকোরেটর (মোকা)
public class Mocha extends CondimentDecorator {
    Beverage beverage; // এখানে আমরা আসল কফিকে লুকিয়ে রাখব

    public Mocha(Beverage beverage) {
        this.beverage = beverage;
    }

    public String getDescription() {
        return beverage.getDescription() + ", সাথে মোকা";
    }

    public double cost() {
        return 20.0 + beverage.cost(); // নিজের দাম + ভেতরেরটার দাম
    }
}
```

**ব্যবহার:**
```java
Beverage myCoffee = new DarkRoast(); // শুধু কফি
myCoffee = new Mocha(myCoffee); // মোকা দিয়ে মুড়ালাম
myCoffee = new Whip(myCoffee);  // হুইপ দিয়ে মুড়ালাম

System.out.println(myCoffee.cost()); // আউটপুট আসবে সব যোগ করে
```

### ৬. সমস্যা ও সমাধান (Common Problems) ⚠️

**সমস্যা ১: অনেক ছোট ছোট ক্লাস**
ডেকোরেটর প্যাটার্ন ব্যবহার করলে প্রচুর ছোট ছোট ক্লাস তৈরি হয় (`Mocha`, `Soy`, `Whip`, `Milk`...)। কেউ কোড দেখলে প্রথমে ভয় পেয়ে যেতে পারে।
*   **সমাধান:** এটা মেনে নিতে হবে। কারণ ফ্লেক্সিবিলিটি চাইলে একটু জটিলতা আসবেই। তবে ক্লাসগুলোর নাম সুন্দর করে দিলে বুঝতে সুবিধা হয়।

**সমস্যা ২: টাইপ চেকিং (Type Checking)**
আপনি যদি কোডে চেক করেন `if (beverage instanceof DarkRoast)`, তবে ডেকোরেটর প্যাটার্নে এটা কাজ করবে না। কারণ `DarkRoast` এখন `Mocha`-র পেটের ভেতর ঢুকে আছে। বাইরের অবজেক্টটা এখন `Mocha`।
*   **সমাধান:** ডেকোরেটর প্যাটার্ন ব্যবহার করলে সাধারণত নির্দিষ্ট টাইপ চেক করার দরকার হয় না। আমরা ইন্টারফেসের ওপর কাজ করি।

**সমস্যা ৩: ইনিশিয়েলাইজেশন জটিলতা**
অবজেক্ট তৈরি করার সময় কোড দেখতে বিদঘুটে হতে পারে:
`new Whip(new Mocha(new Soy(new DarkRoast())))`
*   **সমাধান:** এর জন্য আমরা পরবর্তীতে **Factory** বা **Builder** প্যাটার্ন ব্যবহার করতে পারি।

### ৭. রিয়েল-লাইফ ব্যবহার: Java I/O 🌍

আপনি যদি জাভাতে ফাইল রিড করতে গিয়ে থাকেন, তবে নিচের কোডটি নিশ্চয়ই দেখেছেন:

```java
InputStream in = new BufferedInputStream(new FileInputStream("test.txt"));
```
এখানে:
*   `FileInputStream` হলো মূল কফি (`ConcreteComponent`)।
*   `BufferedInputStream` হলো মোকা বা হুইপ (`Decorator`)।

জাভার পুরো I/O সিস্টেম এই ডেকোরেটর প্যাটার্নের ওপর দাঁড়িয়ে আছে। `LineNumberInputStream`, `PushbackInputStream`—এরা সবাই এক একটা ডেকোরেটর যা ইনপুট স্ট্রিমের ক্ষমতা বাড়ায়।

### ৮. একনজরে সারাংশ (Summary) 📝

*   **Decorator Pattern:** ইনহেরিটেন্স ব্যবহার না করে ডায়নামিক্যালি অবজেক্টের দায়িত্ব বা ফিচার বাড়ানোর পদ্ধতি।
*   **Design Principle:** Open-Closed Principle (Extension-এর জন্য খোলা, Modification-এর জন্য বন্ধ)।
*   **Wrapper:** ডেকোরেটররা মূল অবজেক্টকে জড়িয়ে রাখে বা wrap করে।
*   **Inheritance vs Composition:** এখানে আমরা টাইপ মিলানোর জন্য ইনহেরিটেন্স ব্যবহার করি (যাতে কফির জায়গায় মোকা পাস করা যায়), কিন্তু আচরণ (Behavior) পাওয়ার জন্য কম্পোজিশন ব্যবহার করি।
*   **Real World:** কফি শপ, পিৎজা মেকিং, জাভা I/O লাইব্রেরি।

ব্যাস! এখন আপনিও চাইলে স্টারবাজের মতো নিজের কোডকে সাজুগুজু করাতে পারবেন! হ্যাপি কোডিং! ☕🎉

### ☕ আসল ঘটনা (The Scenario): Starbuzz Coffee

ভাবুন, **Starbuzz** নামে একটা কফি শপ আছে। তাদের কফি খুবই জনপ্রিয়। কিন্তু তাদের কোডিং আর্কিটেকচার খুবই জঘন্য।

**সমস্যা:**
প্রথমে তাদের `Beverage` নামে একটা ক্লাস ছিল। তারপর তারা বানালো `HouseBlend`, `DarkRoast`, `Espresso`। ভালো কথা।
কিন্তু কাস্টমাররা তো শুধু ব্ল্যাক কফি খায় না। কেউ চায় **দুধ (Milk)**, কেউ **চিনি (Sugar)**, কেউ **হুইপ ক্রিম (Whip)**, আবার কেউ **মোকা (Mocha)**।

এখন ডেভেলপাররা যদি প্রতিটা কম্বিনেশনের জন্য আলাদা ক্লাস বানায়, অবস্থাটা কেমন হবে ভাবুন:
*   `HouseBlendWithMilk`
*   `HouseBlendWithMilkAndSugar`
*   `DarkRoastWithWhipAndMocha`
*   ... `DarkRoastWithMilkAndSugarAndWhipAndMocha` (উফ! দম বন্ধ হয়ে যাচ্ছে 😵)

এটাকে বলে **"Class Explosion"**। মানে ক্লাসের বিস্ফোরণ। হাজার হাজার ক্লাস তৈরি হয়ে যাবে।

### 💡 সমাধান: The Decorator Pattern

আমরা ইনহেরিটেন্স (Inheritance) ব্যবহার করে ক্লাস বাড়াবো না। আমরা ব্যবহার করব **Composition** এবং **Wrappers**।

**আইডিয়া:**
১. প্রথমে একটা খালি কফি নিব (যেমন `Espresso`)।
২. যদি কাস্টমার মোকা চায়, আমরা কফিটাকে `Mocha` অবজেক্ট দিয়ে মুড়িয়ে (Decorate) দিব।
৩. যদি হুইপ ক্রিম চায়, ওটার ওপর আবার `Whip` অবজেক্ট দিয়ে মুড়িয়ে দিব।
৪. শেষমেশ বাইরের অবজেক্টকে জিজ্ঞেস করব—"ভাই, টোটাল দাম কত?" সে তখন চেইন ধরে ভেতরের সবার দাম যোগ করে বলে দিবে।

**ডিজাইন প্রিন্সিপাল (সোনালী নিয়ম):**
> **Open-Closed Principle:** Classes should be open for extension, but closed for modification.
> (ক্লাস এমন হতে হবে যেন নতুন ফিচার যোগ করা যায়, কিন্তু পুরনো কোড কাটাছেঁড়া করা না লাগে।)

### 💻 .NET (C#) কোড ইমপ্লিমেন্টেশন

চলুন কোড দিয়ে কফি বানাই।

#### ১. বেস ক্লাস (Beverage)
এটা হলো সব পানীয়ের বাপ-দাদা।

```csharp
public abstract class Beverage
{
    // কফির নাম বা বর্ণনা
    public virtual string Description { get; protected set; } = "Unknown Beverage";

    // দাম কত? এটা সাব-ক্লাসরা ঠিক করবে
    public abstract double Cost();
}
```

#### ২. আসল কফি (Concrete Components)
এগুলো হলো মূল কফি, যাকে আমরা সাজাবো।

```csharp
// এসপ্রেসো কফি
public class Espresso : Beverage
{
    public Espresso()
    {
        Description = "এসপ্রেসো";
    }

    public override double Cost()
    {
        return 1.99; // ডলারের রেট, তাই একটু বেশি!
    }
}

// ডার্ক রোস্ট কফি
public class HouseBlend : Beverage
{
    public HouseBlend()
    {
        Description = "হাউজ ব্লেন্ড কফি";
    }

    public override double Cost()
    {
        return .89;
    }
}
```

#### ৩. ডেকোরেটর অ্যাবস্ট্রাক্ট ক্লাস (The Decorator)
এটাই হলো সেই জাদুকরী র‍্যাপার। খেয়াল করুন, **ই নিজেও একজন `Beverage`** (ইনহেরিটেন্স), আবার **এর পেটের ভেতর আরেকজন `Beverage` থাকে** (কম্পোজিশন)।

```csharp
public abstract class CondimentDecorator : Beverage
{
    // আমরা চাই ডেকোরেটররা ডেসক্রিপশন মেথডটা নতুন করে লিখুক
    public abstract override string Description { get; }
}
```

#### ৪. মসলাপাতি বা টপিংস (Concrete Decorators)
এখন আমরা মোকা, হুইপ ক্রিম ইত্যাদি বানাব।

```csharp
// মোকা (চকলেট ফ্লেভার)
public class Mocha : CondimentDecorator
{
    Beverage _beverage; // পেটের ভেতর আসল কফিটা রাখবে

    public Mocha(Beverage beverage)
    {
        this._beverage = beverage;
    }

    public override string Description
    {
        get { return _beverage.Description + ", মোকা"; }
    }

    public override double Cost()
    {
        // নিজের দাম (.20) + পেটের ভেতরের কফির দাম
        return .20 + _beverage.Cost();
    }
}

// হুইপ ক্রিম
public class Whip : CondimentDecorator
{
    Beverage _beverage;

    public Whip(Beverage beverage)
    {
        this._beverage = beverage;
    }

    public override string Description
    {
        get { return _beverage.Description + ", হুইপ ক্রিম"; }
    }

    public override double Cost()
    {
        return .10 + _beverage.Cost();
    }
}
```

#### ৫. কফি শপ ওপেন (Main Method)

```csharp
class Program
{
    static void Main(string[] args)
    {
        // ১. একটা সাধারণ এসপ্রেসো অর্ডার করি
        Beverage beverage = new Espresso();
        Console.WriteLine($"{beverage.Description} ৳{beverage.Cost()}");

        // ২. এবার একটা স্পেশাল কফি বানাই: ডার্ক রোস্ট + ২ বার মোকা + ১ বার হুইপ
        Beverage beverage2 = new HouseBlend(); // প্রথমে শুধু কফি
        beverage2 = new Mocha(beverage2);      // মোকা দিয়ে মুড়ালাম
        beverage2 = new Mocha(beverage2);      // আরেকবার মোকা দিলাম (ডাবল চকোলেট!)
        beverage2 = new Whip(beverage2);       // হুইপ ক্রিম দিলাম

        // এখন দেখি বিল কত আসলো
        Console.WriteLine($"{beverage2.Description} ৳{beverage2.Cost()}");
    }
}
```

### 🤔 লজিক এবং গুরুত্ব (Logic)

**কেন `beverage2 = new Mocha(beverage2)` এভাবে লিখলাম?**
এটা অনেকটা পেঁয়াজের খোসার মতো।
*   সবচেয়ে ভেতরে আছে `HouseBlend`।
*   তার ওপর `Mocha` এর আস্তরণ।
*   তার ওপর আরেকটা `Mocha`।
*   সবার বাইরে `Whip`।

যখন আপনি `Cost()` কল করেন, `Whip` তার নিজের ১০ পয়সা যোগ করে কল পাস করে দেয় `Mocha`-র কাছে। সে ২০ পয়সা যোগ করে কল দেয় পরেরজনকে। এভাবে চেইন রিয়েকশন হয়ে আসল কফি পর্যন্ত যায় এবং টোটাল দাম রিটার্ন করে।

### ⚠️ সাধারণ সমস্যা ও সমাধান (Common Problems)

১. **ছোট ক্লাসের বন্যা:** ডেকোরেটর প্যাটার্ন ব্যবহার করলে অনেকগুলো ছোট ছোট ক্লাস তৈরি হয় (যেমন Milk, Soy, Mocha)। নতুন কেউ প্রজেক্টে আসলে ভয় পেতে পারে।
    *   *সমাধান:* ফোল্ডার স্ট্রাকচার ঠিক রাখুন, যাতে এলোমেলো না লাগে।

২. **টাইপ চেনা দায়:** একবার ডেকোরেট করে ফেললে আপনি আর সহজে বুঝতে পারবেন না আসল অবজেক্টটা `Espresso` নাকি `HouseBlend`।
    *   *সমাধান:* যদি আপনার কোড নির্দিষ্ট টাইপের (যেমন Espresso-এর বিশেষ কোনো মেথড) ওপর নির্ভর করে, তবে ডেকোরেটর ব্যবহার করবেন না। ডেকোরেটর শুধু কমন ইন্টারফেসের জন্য।

৩. **Initialization Ugly:** `new Whip(new Mocha(new Espresso()))` — এই কোড দেখতে একটু বিশ্রী লাগে।
    *   *সমাধান:* ফ্যাক্টরি (Factory) বা বিল্ডার (Builder) প্যাটার্ন ব্যবহার করে এই অবজেক্ট তৈরির প্রসেসটা লুকিয়ে ফেলা যায়।

### 🌍 বাস্তব জীবনের উদাহরণ (.NET Real Life Scenario)

আপনারা যারা .NET-এ ফাইল নিয়ে কাজ করেছেন, তারা `System.IO.Stream` এর সাথে পরিচিত। এটাও ডেকোরেটর প্যাটার্ন!

```csharp
// FileStream হলো মূল কম্পোনেন্ট (যেমন Espresso)
FileStream fileStream = new FileStream("data.txt", FileMode.Create);

// BufferedStream হলো ডেকোরেটর (যেমন Mocha) - এটা বাফারিং ফিচার যোগ করে
BufferedStream bufferedStream = new BufferedStream(fileStream);

// GZipStream হলো আরেকটা ডেকোরেটর (যেমন Whip) - এটা কমপ্রেশন ফিচার যোগ করে
GZipStream compressor = new GZipStream(bufferedStream, CompressionMode.Compress);

// আমরা লিখছি compressor-এ, কিন্তু কাজ হচ্ছে ধাপে ধাপে একদম ফাইলে গিয়ে।
compressor.Write(dataBuffer, 0, dataBuffer.Length);
```

এখানে আমরা `FileStream` এর কোড পরিবর্তন না করেই তাকে **বাফারিং** এবং **কমপ্রেশন** এর ক্ষমতা দিয়ে দিলাম। এটাই ডেকোরেটরের ম্যাজিক!

### 📝 একনজরে সারাংশ (Summary)

১. **Decorator Pattern** ইনহেরিটেন্সের বিকল্প। এটি রানটাইমে অবজেক্টের ক্ষমতা বাড়ায়।
২. **Open-Closed Principle:** আমরা মেইন `Beverage` ক্লাসে হাত না দিয়েই নতুন টপিংস (যেমন `Milk`, `Soy`) যোগ করতে পারছি।
৩. ডেকোরেটররা মূল অবজেক্টের মতোই একই টাইপের হয় (Is-A relationship), তাই এদের একে অপরের জায়গায় ব্যবহার করা যায়।
৪. এটি **Wrapper** হিসেবে কাজ করে। বাইরের লেয়ার থেকে কল ভেতরে পাস করতে করতে মূল অবজেক্টে যায়।
