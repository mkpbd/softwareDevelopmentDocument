আজকের টপিক হলো **Command Pattern**।
সহজ বাংলায় এর নাম দিলাম: **"হুকুমের গোলাম প্যাটার্ন"**। 🧞‍♂️

কেন? কারণ এই প্যাটার্নে আমরা একটা অবজেক্টের হাতে একটা চিরকুট ধরিয়ে দেই, আর বলি—"যখন সময় হবে, শুধু এই চিরকুটে লেখা কাজটা করে দিবি। তোর জানার দরকার নাই কাজটা কী বা কে করবে, তুই শুধু এক্সিকিউট করবি!"

### ১. সমস্যা: ইউনিভার্সাল রিমোট কন্ট্রোল (The Universal Remote) 🎮

ধরুন, আপনাকে একটা **ইউনিভার্সাল রিমোট** বানাতে বলা হলো। এই রিমোটে ৭টা স্লট আছে। আপনি চাইলে ১ নম্বর বোতামে "লাইট" সেট করতে পারেন, ২ নম্বরে "ফ্যান", ৩ নম্বরে "গ্যারেজ ডোর"।

**ভুল অ্যাপ্রোচ:**
আপনি যদি রিমোটের ক্লাসে এভাবে কোড লেখেন:
```csharp
if (slot1 == Light) { light.On(); }
else if (slot1 == Fan) { fan.High(); }
else if (slot1 == Garage) { garage.Open(); }
```
তাহলে মহাবিপদ! 😱
১. ভবিষ্যতে যদি নতুন ডিভাইস আসে (যেমন: স্মার্ট টয়লেট 🚽), তাহলে রিমোটের কোড ভাঙতে হবে।
2. রিমোটকে সব ডিভাইসের ডিটেইলস জানতে হচ্ছে। এটা **Loose Coupling**-এর বারোটা বাজিয়ে দেয়।

### ২. সমাধান: The Command Pattern 💡

আমরা রিমোটকে বোকা বানিয়ে রাখব। রিমোট জানবে না সে লাইট জ্বালাচ্ছে নাকি গ্যারেজ খুলছে। সে শুধু জানে তার একটা বাটন আছে, আর সেটা চাপলে `Execute()` মেথড কল করতে হয়।

**হোটেলের ওয়েটার এনালজি (The Diner Analogy):** 🍽️
১. **কাস্টমার (Client):** আপনি অর্ডার দিলেন "এক প্লেট বিরিয়ানি"।
২. **ওয়েটার (Invoker):** সে অর্ডার স্লিপটা নিল। সে কিন্তু রান্না করতে জানে না। সে শুধু জানে স্লিপটা কিচেনে দিতে হবে।
৩. **অর্ডার স্লিপ (Command Object):** এতে লেখা আছে কী করতে হবে।
৪. **বাবুর্চি (Receiver):** সে স্লিপ দেখে বিরিয়ানি রাঁধল।

এখানে **কমান্ড প্যাটার্ন** হলো সেই **অর্ডার স্লিপ**। এটি আপনার অনুরোধকে (Request) একটা অবজেক্টে মুড়িয়ে ফেলে।

### ৩. কোডিং ও ডিজাইন (.NET/C#) 🛠️

চলুন আমরা কোড দিয়ে রিমোট আর লাইট বানাই।

#### ধাপ ১: কমান্ড ইন্টারফেস (The Command Interface)
সব কমান্ডের একটাই কাজ—এক্সিকিউট করা।

```csharp
public interface ICommand
{
    void Execute();
}
```

#### ধাপ ২: রিসিভার (The Receiver)
যে আসলে কাজটা করবে। যেমন: লাইট।

```csharp
public class Light
{
    public void On()
    {
        Console.WriteLine("বাত্তি জ্বলে উঠছে! 💡");
    }

    public void Off()
    {
        Console.WriteLine("অন্ধকার হয়ে গেল! 🌑");
    }
}
```

#### ধাপ ৩: কনক্রিট কমান্ড (Concrete Command)
এটা হলো সেই অর্ডার স্লিপ, যা রিমোট আর লাইটের মধ্যে সেতু।

```csharp
public class LightOnCommand : ICommand
{
    Light _light;

    public LightOnCommand(Light light)
    {
        _light = light;
    }

    public void Execute()
    {
        _light.On(); // রিমোট বাটন চাপলে এই মেথড লাইটকে অন করবে
    }
}
```

#### ধাপ ৪: ইনভোকার বা রিমোট (The Invoker)
রিমোট জানে না সে কী করছে, সে শুধু কমান্ড এক্সিকিউট করে।

```csharp
public class SimpleRemoteControl
{
    ICommand _slot;

    public void SetCommand(ICommand command)
    {
        _slot = command;
    }

    public void ButtonWasPressed()
    {
        _slot.Execute(); // রিমোট বলছে: "যাই সেট করা আছে, চালু হও!"
    }
}
```

#### ধাপ ৫: ক্লায়েন্ট বা মেইন প্রোগ্রাম (The Client)

```csharp
class Program
{
    static void Main(string[] args)
    {
        // ১. রিসিভার তৈরি (লাইট)
        Light livingRoomLight = new Light();

        // ২. কমান্ড তৈরি (লাইটের সুইচ অন করার কমান্ড)
        LightOnCommand lightOn = new LightOnCommand(livingRoomLight);

        // ৩. ইনভোকার তৈরি (রিমোট)
        SimpleRemoteControl remote = new SimpleRemoteControl();

        // ৪. রিমোটে কমান্ড সেট করা
        remote.SetCommand(lightOn);

        // ৫. বাটন চাপা
        remote.ButtonWasPressed(); 
    }
}
```

### ৪. আনডু বাটন (The Undo Button) ↩️

হঠাৎ মনে হলো, "ভুল করেছি!" তখন কি হবে? কমান্ড প্যাটার্নে **Undo** করা খুব সহজ। ইন্টারফেসে শুধু একটা `Undo()` মেথড যোগ করুন।

```csharp
public interface ICommand
{
    void Execute();
    void Undo(); // নতুন সংযোজন
}

public class LightOnCommand : ICommand
{
    Light _light;
    // ... constructor ...
    
    public void Execute() => _light.On();
    
    public void Undo() => _light.Off(); // অন-এর উল্টো অফ
}
```
রিমোট তার শেষ কমান্ডটা মনে রাখবে। যখনই Undo বাটন চাপবেন, সে `Undo()` মেথড কল করে আগের অবস্থায় ফিরে যাবে। ফ্যানের স্পিড বা ভলিউম কমানোর ক্ষেত্রে এটা জীবন রক্ষাকারী!

### ৫. ম্যাক্রো কমান্ড (Party Mode) 🎉

আপনি চান এক ক্লিকে লাইট ডিম হবে, গান বাজবে, আর এসি চালু হবে। একে বলে **Macro Command**।
সিম্পল! একটা কমান্ডের ভেতর অনেকগুলো কমান্ডের লিস্ট (List) থাকবে। `Execute` করলে লুপ চালিয়ে সব রান করে দিবে।

```csharp
public class PartyCommand : ICommand
{
    ICommand[] _commands;

    public PartyCommand(ICommand[] commands)
    {
        _commands = commands;
    }

    public void Execute()
    {
        foreach (var command in _commands)
        {
            command.Execute(); // ধুমধাম সব চালু!
        }
    }
    
    public void Undo() { /* সব উল্টো লুপে বন্ধ হবে */ }
}
```

### ৬. সমস্যা ও সমাধান (Problems & Fixes) ⚠️

**সমস্যা ১: অনেক বেশি ক্লাস (Class Explosion)**
*   **সমস্যা:** লাইট অন করার জন্য একটা ক্লাস, অফ করার জন্য একটা, ফ্যানের জন্য আরেকটা... এভাবে হাজারটা ক্লাস হয়ে যেতে পারে।
*   **সমাধান:** আধুনিক C# বা Java তে আমরা **Lambda Expressions** ব্যবহার করতে পারি। তখন আর আলাদা `LightOnCommand` ক্লাস লাগে না।
    ```csharp
    // C# Example without extra class
    remote.SetCommand(() => light.On()); 
    ```

**সমস্যা ২: স্মার্ট কমান্ড বনাম ডাম্ব কমান্ড**
*   **সমস্যা:** মাঝে মাঝে ডেভেলপাররা কমান্ড ক্লাসেই সব লজিক লিখে ফেলে (রিসিভার ব্যবহার না করে)।
*   **সমাধান:** কমান্ড ক্লাসকে যথাসম্ভব "বোকা" (Dumb) রাখা উচিত। তার কাজ শুধু রিসিভারকে ডাকা। লজিক থাকবে রিসিভারে।

### ৭. বাস্তব জীবনের ব্যবহার (Real-World Uses) 🌍

১.  **GUI Buttons & Menu Items:** ওয়ার্ড ফাইলে যখন "Copy" বা "Paste" বাটনে ক্লিক করেন, তখন পেছনের কোড জানে না টেক্সট কপি হচ্ছে নাকি ইমেজ। সে শুধু কমান্ড এক্সিকিউট করে।
২.  **Transactional Systems (Database):** ব্যাংকের ট্রানজেকশন। টাকা পাঠানোর পর যদি এরর হয়, তখন `Undo()` বা `Rollback()` করে টাকা ফেরত আনা হয়।
৩.  **Job Queues:** আপনি প্রিন্টারে ১০টা ডকুমেন্ট প্রিন্ট দিলেন। প্রিন্টার একটা কিউ (Queue) বা লাইনে কমান্ডগুলো জমা রাখে এবং একটার পর একটা `Execute()` করে।
৪.  **Text Editors:** `Ctrl+Z` (Undo) এবং `Ctrl+Y` (Redo) ফিচার এই প্যাটার্ন দিয়েই বানানো হয়।

২. এটি **Invoker** (রিমোট) এবং **Receiver** (লাইট)-এর মধ্যে সম্পর্ক বিচ্ছিন্ন করে (Decoupling)।
৩. এটি দিয়ে **Undo/Redo**, **Queuing**, এবং **Logging** এর মতো জটিল কাজ সহজে করা যায়।

### 🎮 আসল ঘটনা (The Scenario): ইউনিভার্সাল রিমোটের যন্ত্রণা

ধরুন, আপনাকে একটা **স্মার্ট হোম রিমোট** বানাতে বলা হলো। এই রিমোটে ৭টা স্লট আছে। আপনি চাইলে ১ নম্বর বোতামে "লাইট" সেট করতে পারেন, ২ নম্বরে "ফ্যান", ৩ নম্বরে "গ্যারেজ ডোর"।

**ভুল অ্যাপ্রোচ (যা সবাই প্রথমে করে):**
আপনি যদি রিমোট ক্লাসের ভেতর এভাবে কোড লেখেন:
```csharp
if (slot1 == Light) { light.On(); }
else if (slot1 == Fan) { fan.High(); }
else if (slot1 == Garage) { garage.Open(); }
```
তাহলে মহাবিপদ! 😱
১. ভবিষ্যতে যদি নতুন ডিভাইস আসে (যেমন: **স্মার্ট টয়লেট** 🚽), তাহলে রিমোটের কোড ভেঙে আবার নতুন `if-else` লিখতে হবে।

### 💡 সমাধান: The Command Pattern

আমরা রিমোটকে **বোকা** বানিয়ে রাখব। রিমোট জানবে না সে লাইট জ্বালাচ্ছে নাকি গ্যারেজ খুলছে। সে শুধু জানে তার একটা বাটন আছে, আর সেটা চাপলে সে `Execute()` মেথড কল করবে। বাকিটা ম্যাজিক।

**হোটেলের ওয়েটার এনালজি (The Diner Analogy):** 🍽️
১. **কাস্টমার (Client):** আপনি অর্ডার দিলেন "এক প্লেট কাচ্চি"।
২. **ওয়েটার (Invoker):** সে অর্ডার স্লিপটা নিল। সে কিন্তু রান্না করতে জানে না। সে শুধু জানে স্লিপটা কিচেনে দিতে হবে।
৩. **অর্ডার স্লিপ (Command Object):** এতে লেখা আছে কী করতে হবে (কাচ্চি রাঁধতে হবে)।
৪. **বাবুর্চি (Receiver):** সে স্লিপ দেখে কাচ্চি রাঁধল।

এখানে **কমান্ড প্যাটার্ন** হলো সেই **অর্ডার স্লিপ**।

### 💻 .NET (C#) কোড ইমপ্লিমেন্টেশন

চলুন কোড দিয়ে রিমোট আর লাইট বানাই।

#### ধাপ ১: কমান্ড ইন্টারফেস (The Command Interface)
সব কমান্ডের একটাই ধর্ম—এক্সিকিউট করা।

```csharp
// এটা সেই চিরকুট
public interface ICommand
{
    void Execute();
    void Undo(); // ভুল করলে শুধরানোর জন্য (পরে ব্যাখ্যা করছি)
}
```

#### ধাপ ২: রিসিভার (The Receiver)
যে আসলে কাজটা করবে। যেমন: লাইট।

```csharp
public class Light
{
    public void On()
    {
        Console.WriteLine("বাত্তি জ্বলে উঠল! 💡");
    }

    public void Off()
    {
        Console.WriteLine("অন্ধকার হয়ে গেল! 🌑");
    }
}
```

#### ধাপ ৩: কনক্রিট কমান্ড (Concrete Command)
এটা হলো সেই মিডলম্যান, যে রিমোট আর লাইটের মধ্যে সেতু বন্ধন করবে।

```csharp
public class LightOnCommand : ICommand
{
    Light _light;

    // কনস্ট্রাকটরে বলে দিতে হবে কোন লাইটটা জ্বালাবে
    public LightOnCommand(Light light)
    {
        _light = light;
    }

    public void Execute()
    {
        _light.On(); // রিমোট বাটন চাপলে এই মেথড লাইটকে অন করবে
    }

    public void Undo()
    {
        _light.Off(); // অন-এর উল্টো কাজ (ভুল শুধরানো)
    }
}
```

#### ধাপ ৪: ইনভোকার বা রিমোট (The Invoker)
রিমোট জানে না সে কী করছে, সে শুধু কমান্ড এক্সিকিউট করে।

```csharp
public class SimpleRemoteControl
{
    ICommand _slot; // রিমোটের একটা বাটন

    public void SetCommand(ICommand command)
    {
        _slot = command;
    }

    public void ButtonWasPressed()
    {
        // রিমোট বলছে: "যাই সেট করা আছে, চালু হও!"
        _slot.Execute(); 
    }
}
```

#### ধাপ ৫: ক্লায়েন্ট বা মেইন প্রোগ্রাম (The Client)

```csharp
class Program
{
    static void Main(string[] args)
    {
        // ১. রিসিভার তৈরি (লাইট)
        Light livingRoomLight = new Light();

        // ২. কমান্ড তৈরি (লাইটের সুইচ অন করার কমান্ড)
        LightOnCommand lightOn = new LightOnCommand(livingRoomLight);

        // ৩. ইনভোকার তৈরি (রিমোট)
        SimpleRemoteControl remote = new SimpleRemoteControl();

        // ৪. রিমোটে কমান্ড সেট করা (ওয়েটারকে অর্ডার দেওয়া)
        remote.SetCommand(lightOn);

        // ৫. বাটন চাপা (অর্ডার কিচেনে পাঠানো)
        Console.WriteLine("রিমোটের বাটন চাপা হলো...");
        remote.ButtonWasPressed(); 
    }
}
```

### ↩️ আনডু বাটন (The Undo Button)

হঠাৎ মনে হলো, "ভুল করেছি! লাইট জ্বালানো ঠিক হয়নি।" তখন কি হবে? কমান্ড প্যাটার্নে **Undo** করা খুব সহজ। আমরা ইন্টারফেসে আগেই `Undo()` মেথড রেখেছিলাম।

রিমোট ক্লাসে শুধু একটা ভেরিয়েবল রাখতে হবে `lastCommand` নামে।

```csharp
// রিমোট ক্লাসের আপডেট
public class RemoteWithUndo
{
    ICommand _slot;
    ICommand _lastCommand; // ইতিহাস মনে রাখার জন্য

    public void ButtonPressed()
    {
        _slot.Execute();
        _lastCommand = _slot; // সেভ করে রাখলাম কি কাজ করেছি
    }

    public void UndoButtonPressed()
    {
        _lastCommand.Undo(); // আগের কাজ উল্টে দাও
    }
}
```
ফ্যানের স্পিড হাই থেকে লো করার ক্ষেত্রে বা ভুল ট্রানজেকশন রিভার্স করার ক্ষেত্রে এটা জীবন রক্ষাকারী!

### 🎉 ম্যাক্রো কমান্ড (Party Mode)

আপনি চান এক ক্লিকে লাইট ডিম হবে, গান বাজবে, আর এসি চালু হবে (পার্টি মুড)। একে বলে **Macro Command**।
সিম্পল! একটা কমান্ডের ভেতর অনেকগুলো কমান্ডের লিস্ট (List) থাকবে।

```csharp
public class PartyCommand : ICommand
{
    ICommand[] _commands;

    public PartyCommand(ICommand[] commands)
    {
        _commands = commands;
    }

    public void Execute()
    {
        foreach (var command in _commands)
        {
            command.Execute(); // ধুমধাম সব চালু!
        }
    }
    
    public void Undo()
    {
        // উল্টো লুপ চালিয়ে সব বন্ধ করতে হবে
        for (int i = _commands.Length - 1; i >= 0; i--)
        {
            _commands[i].Undo();
        }
    }
}
```

### ⚠️ সাধারণ সমস্যা ও সমাধান (Problems & Fixes)

**সমস্যা ১: ক্লাস এক্সপ্লোশন (Class Explosion)**
*   **সমস্যা:** লাইট অন করার জন্য একটা ক্লাস, অফ করার জন্য একটা, ফ্যানের জন্য আরেকটা... এভাবে হাজারটা ক্লাস হয়ে যেতে পারে।
*   **সমাধান:** C#-এ আমরা **Lambda Expressions** ব্যবহার করে ক্লাস কমানোর ম্যাজিক করতে পারি। তখন আর আলাদা `LightOnCommand` ক্লাস লাগে না।
    ```csharp
    // C# Magic: কোনো আলাদা ক্লাস ছাড়াই কমান্ড সেট করা
    remote.SetCommand(new RelayCommand(() => light.On())); 
    ```

**সমস্যা ২: স্মার্ট কমান্ড বনাম ডাম্ব কমান্ড**
*   **সমস্যা:** মাঝে মাঝে ডেভেলপাররা কমান্ড ক্লাসেই সব লজিক লিখে ফেলে (রিসিভার ব্যবহার না করে)।
*   **সমাধান:** কমান্ড ক্লাসকে যথাসম্ভব "বোকা" (Dumb) রাখা উচিত। তার কাজ শুধু রিসিভারকে ডাকা। লজিক থাকবে রিসিভারে।

### 🌍 বাস্তব জীবনের উদাহরণ (Real-World Scenario)

১.  **Text Editors (MS Word/VS Code):** আপনি যখন `Ctrl+Z` চাপেন, এডিটর জানে না আপনি শেষ কাজটা কী করেছিলেন (টাইপ করেছেন নাকি ডিলিট করেছেন)। সে শুধু স্ট্যাক (Stack) থেকে লাস্ট কমান্ডটা বের করে `Undo()` মেথড কল করে দেয়।

২.  **Task Scheduling / Job Queues:** আপনি প্রিন্টারে ১০টা ডকুমেন্ট প্রিন্ট দিলেন। প্রিন্টার একটা কিউ (Queue) বা লাইনে কমান্ডগুলো জমা রাখে এবং একটার পর একটা `Execute()` করে। এখানে কমান্ড প্যাটার্ন ব্যবহার করে রিকোয়েস্টগুলোকে অবজেক্ট হিসেবে স্টোর করা হয়।

### 📝 একনজরে সারাংশ (Summary)

১. **Command Pattern** কোনো রিকোয়েস্টকে একটা অবজেক্টে রূপান্তর করে (**Encapsulate a request as an object**)।
২. এটি **Invoker** (রিমোট) এবং **Receiver** (লাইট)-এর মধ্যে সম্পর্ক বিচ্ছিন্ন করে (**Decoupling**)। রিমোট জানেই না সে আসলে কী কাজ করছে।
৩. এটি দিয়ে **Undo/Redo**, **Queuing**, এবং **Logging**-এর মতো জটিল ফিচার খুব সহজে ইমপ্লিমেন্ট করা যায়।
৪. **Macro Command** দিয়ে একসাথে অনেকগুলো কাজ এক ক্লিকে করা সম্ভব।
