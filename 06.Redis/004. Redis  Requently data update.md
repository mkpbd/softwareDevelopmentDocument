
দারুন প্রশ্ন করেছ ব্রাদার! এটাই হলো সেই জায়গা যেখানে Redis আসলে **সুপারহিরো** হয়ে যায়। 🦸‍♂️

যখন কোনো ডেটা **খুব ঘন ঘন পরিবর্তন (High Frequency Update)** হয় (যেমন: ইউটিউব ভিডিওর ভিউ কাউন্ট, ফেসবুকের লাইক, শেয়ার মার্কেটের দাম, বা উবারের গাড়ির লাইভ লোকেশন), তখন প্রতিবার ডাটাবেসে (SQL Server) হিট করলে ডাটাবেস **আগুন হয়ে যাবে**। 🔥

এই সমস্যার সমাধানের নাম হলো **"Write-Behind"** বা **"Write-Back"** প্যাটার্ন।

সহজ বাংলা অ্যানালজি:
> মনে করো তুমি চায়ের দোকানদার। ভিড়ের সময় প্রতিটা কাপ চা বিক্রির পর কি তুমি মেইন ক্যাশখাতায় হিসাব লেখো? না! তুমি একটা **ছোট কাগজে (Redis)** টপাটপ দাগ দিয়ে রাখো। দিন শেষে বা দোকান ফাঁকা হলে মেইন **ক্যাশখাতায় (SQL Database)** তুলে নাও।

চলো দেখি .NET 10 এ এটা কীভাবে ইমপ্লিমেন্ট করব।

### মেথড ১: অ্যাটমিক কাউন্টার (লাইক/ভিউ কাউন্টের জন্য) 👍

ধরো একটা ভাইরাল ভিডিও। প্রতি সেকেন্ডে ৫০০ মানুষ লাইক দিচ্ছে।

**কৌশল:**
১. আমরা লাইকগুলো সরাসরি SQL এ সেভ করব না।
২. Redis এ একটা কাউন্টার বাড়াব (Atomic Increment)। এটা ১০০% নিরাপদ, কোনো রেস কন্ডিশন (Race Condition) হবে না।
৩. একটা **Background Service (Worker)** কিছুক্ষণ পর পর Redis থেকে ভ্যালু নিয়ে SQL এ আপডেট করে দেবে।

#### ধাপ ১: লাইক API (Controller/Endpoint)

এখানে আমরা শুধু Redis আপডেট করব। SQL এর ধার দিয়েও যাব না। সুপার ফাস্ট! ⚡

```csharp
app.MapPost("/video/{videoId}/like", async (string videoId, IConnectionMultiplexer redis) =>
{
    var db = redis.GetDatabase();
    
    // Key: video:likes:105
    string key = $"video:likes:{videoId}";

    // INCR command: এটা অটোমেটিক ভ্যালু ১ বাড়িয়ে দেয়। আগে রিড করার দরকার নেই।
    // যদি key না থাকে, ০ থেকে ১ বানাবে।
    long newLikeCount = await db.StringIncrementAsync(key);

    return Results.Ok(new { VideoId = videoId, TotalLikes = newLikeCount });
});
```

#### ধাপ ২: ডাটাবেসে সিঙ্ক করা (Background Worker)

এখন আমাদের একটা "চায়ের দোকানের ছোট কর্মচারী" লাগবে যে কিছুক্ষণ পর পর খাতা মেইনটেইন করবে। .NET এ এটাকে বলে `BackgroundService`।

```csharp
public class LikeSyncWorker : BackgroundService
{
    private readonly IConnectionMultiplexer _redis;
    private readonly IServiceProvider _serviceProvider; // SQL DB access এর জন্য

    public LikeSyncWorker(IConnectionMultiplexer redis, IServiceProvider serviceProvider)
    {
        _redis = redis;
        _serviceProvider = serviceProvider;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var db = _redis.GetDatabase();

        while (!stoppingToken.IsCancellationRequested)
        {
            // ১. প্রতি ১০ সেকেন্ড পর পর কাজটা করব
            await Task.Delay(TimeSpan.FromSeconds(10), stoppingToken);

            Console.WriteLine("Syncing Likes to SQL Database...");

            // ২. Redis থেকে সব ভিডিওর লাইক খুঁজে বের করা (Pattern Matching)
            // রিয়েল লাইফে SCAN কমান্ড ব্যবহার করা ভালো, এখানে সহজ করার জন্য Keys দেখাচ্ছি
            var server = _redis.GetServer("localhost", 6379);
            var keys = server.Keys(pattern: "video:likes:*");

            foreach (var key in keys)
            {
                // লাইক কাউন্ট নিয়ে আসো
                string? countStr = await db.StringGetAsync(key);
                if (int.TryParse(countStr, out int likes))
                {
                    // ৩. SQL ডাটাবেস আপডেট করো
                    // (এখানে ডামি কোড, আসলে তুমি EF Core বা Dapper দিয়ে আপডেট করবে)
                    Console.WriteLine($"Updating DB -> Key: {key}, Likes: {likes}");
                    
                    // ৪. অপশনাল: আপডেট শেষ হলে Redis থেকে মুছে দিতে পারো 
                    // অথবা রেখে দিতে পারো ক্যাশ হিসেবে।
                    // await db.KeyDeleteAsync(key); 
                }
            }
        }
    }
}
```

**রেজিস্ট্রেশন (`Program.cs` এ):**
```csharp
builder.Services.AddHostedService<LikeSyncWorker>();
```

### মেথড ২: লেটেস্ট স্টেট (লাইভ লোকেশন/স্টক প্রাইস) 📍

উবারের ড্রাইভার বা ফুডপান্ডার রাইডার মুভ করছে। প্রতি সেকেন্ডে তার লোকেশন পাল্টাচ্ছে।
এখানে আমাদের **হিস্ট্রি** দরকার নেই, শুধু **সর্বশেষ** লোকেশনটা দরকার।

**কৌশল:**
আমরা শুধু Redis এর ভ্যালুটা `SET` (Overwrite) করে দেব। আগেরটা মুছে যাক, সমস্যা নেই।

```csharp
record GeoLocation(double Latitude, double Longitude);

app.MapPost("/driver/{driverId}/location", async (string driverId, GeoLocation loc, IConnectionMultiplexer redis) =>
{
    var db = redis.GetDatabase();
    
    // শুধু লেটেস্ট ডাটা সেভ করছি
    // লাইফটাইম দিচ্ছি ১ মিনিট। কারণ ১ মিনিট পর ড্রাইভারের 
    // পুরনো লোকেশনের কোনো দাম নেই।
    await db.StringSetAsync(
        $"driver:loc:{driverId}", 
        JsonSerializer.Serialize(loc),
        TimeSpan.FromMinutes(1) 
    );

    return Results.Ok("Location Updated");
});

// কাস্টমার অ্যাপ থেকে ড্রাইভার কোথায় আছে দেখবে
app.MapGet("/driver/{driverId}/location", async (string driverId, IConnectionMultiplexer redis) =>
{
    var db = redis.GetDatabase();
    var locJson = await db.StringGetAsync($"driver:loc:{driverId}");

    if (locJson.IsNullOrEmpty) return Results.NotFound("Driver offline");

    return Results.Ok(JsonSerializer.Deserialize<GeoLocation>(locJson!));
});
```

### মেথড ৩: থ্রটলিং (Throttling) - বেশি আপডেট আটকাতে 🚧

মাঝে মাঝে ক্লায়েন্ট সাইড থেকে এত বেশি রিকোয়েস্ট আসে যা আমাদের দরকার নেই।
যেমন: ইউজার মাউস মুভ করছে, বা স্লাইডার নাড়াচ্ছে। প্রতি মিলি-সেকেন্ডে আপডেট পাঠানোর দরকার নেই।

**কৌশল:**
আমরা Redis এ একটা ফ্ল্যাগ সেট করব। "আমি আপডেট নিয়েছি, পরের ৫ সেকেন্ড আর আপডেট নেব না"।

```csharp
app.MapPost("/update-status", async (string userId, string status, IConnectionMultiplexer redis) =>
{
    var db = redis.GetDatabase();
    string throttleKey = $"throttle:{userId}";

    // চেক করি "কুলডাউন" পিরিয়ড চলছে কিনা
    if (await db.KeyExistsAsync(throttleKey))
    {
        return Results.StatusCode(429); // "ভাই একটু জিরান, এত ফাস্ট না"
    }

    // আসল আপডেট কাজ (DB Save etc.)
    Console.WriteLine($"User {userId} status updated to {status}");

    // ফ্ল্যাগ সেট করলাম ২ সেকেন্ডের জন্য। 
    // এই ২ সেকেন্ড এই ইউজার আর আপডেট করতে পারবে না।
    await db.StringSetAsync(throttleKey, "busy", TimeSpan.FromSeconds(2));

    return Results.Ok("Status Updated");
});
```

### সারসংক্ষেপ (Quick Recap) 🧠

১. **Write-Behind (Background Sync):** যখন ডাটা খুব দ্রুত বাড়ে (Likes, Views), তখন Redis এ `INCR` করো, আর ব্যাকগ্রাউন্ডে ধীরে সুস্থে SQL এ পাঠাও।
২. **Overwrite (Fire & Forget):** যখন শুধু বর্তমান অবস্থা দরকার (GPS, Stock), তখন পুরনো ডাটা দেখার দরকার নেই, জাস্ট `SET` করে দাও।
৩. **Data Loss Risk:** মনে রাখবে, যদি কারেন্ট চলে যায় বা সার্ভার ক্রাশ করে, Redis এর মেমোরির ডাটা কিন্তু হারিয়ে যেতে পারে (যদি না Persistence অন থাকে)। তাই পেমেন্ট বা ব্যাংকিং ডাটার জন্য শুধু Redis এর ওপর ভরসা করবে না, সাথে সাথে DB তেও লিখবে। কিন্তু লাইক/ভিউ বা লোকেশনের জন্য Redis বেস্ট!
