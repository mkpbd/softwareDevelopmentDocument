
হ্যালো ব্রাদার/সিস্টার! 👋 স্বাগতম **"ডকার মামার দুনিয়ায়"**। আমি তোমার সেই অভিজ্ঞ ডকার ইঞ্জিনিয়ার যে কঠিন জিনিসকে "ডাল-ভাত" বানিয়ে ছাড়ব।

আজ আমরা **Docker** শিখব একদম শূন্য থেকে হিরো লেভেল পর্যন্ত। কিন্তু বোরিং লেকচার দিয়ে না, গল্পের ছলে। সিট বেল্ট বেঁধে নাও! 🚀

### **পর্ব ১: ডকার জিনিসটা আসলে কী? (The "Why")**

**সমস্যা:**
ধরো, তুমি দারুণ একটা অ্যাপ বানিয়েছ। তোমার ল্যাপটপে (Local Machine) সেটা মাখনের মতো চলছে। খুশিতে তুমি সেটা তোমার বসের সার্ভারে বা বন্ধুর ল্যাপটপে পাঠালে।
হঠাৎ খবর এল— *"দোস্ত, তোর কোড তো চলে না! এরর দেয়!"* 😡
তুমি বললে, *"আরে! আমার পিসিতে তো ঠিকই চলে (It works on my machine)!"*

এই সমস্যা সমাধানের জন্যই **Docker**-এর জন্ম।

**সহজ উদাহরণ (The Analogy):**
ধরো তুমি বাসা বদলাচ্ছ। তোমার খাট, আলমারি, টিভি, ল্যাপটপ, জামাকাপড় সব আলাদা আলাদা করে ট্রাকে তুললে ভেঙে যাওয়ার ভয় থাকে। ট্রাক ড্রাইভার জানে না কোনটার যত্ন কীভাবে নিতে হবে।

কিন্তু তুমি যদি সব কিছু একটা **বড় লোহার কন্টেইনারে (Shipping Container)** ভরে তালা মেরে দাও? তাহলে জাহাজ হোক, ট্রেন হোক বা ট্রাক—কেউ জানবে না ভিতরে কী আছে, তারা শুধু কন্টেইনারটা এক জায়গা থেকে আরেক জায়গায় নিয়ে যাবে। ভিতরের জিনিস একদম সেফ!

**Docker** ঠিক এই কাজটাই করে সফটওয়্যারের জন্য। তোমার কোড, লাইব্রেরি, সেটিংস সব একটা "বাক্সে" (Container) ভরে দেয়। এই বাক্সটা দুনিয়ার যেকোনো কম্পিউটারে সেম টু সেম চলবে।

### **পর্ব ২: বেসিক কনসেপ্ট (Image vs Container)**

ডকার বুঝতে হলে দুটো শব্দ মাথার মধ্যে গেঁথে নাও:

১. **Image (ইমেজ):** এটাকে মনে করো **"বিরিয়ানির রেসিপি"**। এটা একটা ফিক্সড ফাইল, যেটা তুমি পড়তে পারবে কিন্তু খেতে পারবে না।
২. **Container (কন্টেইনার):** এটা হলো রেসিপি দেখে রান্না করা **"গরম গরম বিরিয়ানি"**। যেটা তুমি ব্যবহার করতে পারবে।

> **মজার ব্যাপার:** একটা রেসিপি (Image) দিয়ে তুমি হাজার প্লেট বিরিয়ানি (Container) বানাতে পারো।

### **পর্ব ৩: হাতেখড়ি (Practical Start)**

আগে ডকার ইন্সটল করে নাও (Docker Desktop)। ধরে নিলাম ইন্সটল করা শেষ। এবার টার্মিনাল বা CMD ওপেন করো।

**Step 1: হ্যালো ওয়ার্ল্ড!**
আমরা একটা রেডিমেড ইমেজ নামাব এবং চালাব। কমান্ড দাও:

```bash
docker run hello-world
```

**কী হলো?**
১. ডকার প্রথমে তোমার পিসিতে `hello-world` ইমেজ খুঁজল।
২. পেল না? সে ইন্টারনেট থেকে (Docker Hub) ডাউনলোড করল।
৩. তারপর সেই ইমেজ (রেসিপি) দিয়ে একটা কন্টেইনার (খাবার) বানিয়ে তোমাকে সার্ভ করল।

---

### **পর্ব ৪: নিজের ইমেজ বানাবো (Dockerfile Magic)**

অন্যের ইমেজে আর কতদিন? এবার নিজের অ্যাপকে বক্সে ভরব। এর জন্য একটা ফাইল লাগে, যার নাম **Dockerfile** (কোনো এক্সটেনশন নাই, শুধু এই নাম)।

মনে করো, আমরা একটা ছোট Python অ্যাপ বানাব।

**Dockerfile-এ আমরা কম্পিউটারকে ধাপে ধাপে ইনস্ট্রাকশন দিই:**

```dockerfile
# ১. বেইজ: ভাই একটা হালকা লিনাক্স এবং পাইথন রেডি করো
FROM python:3.9-slim

# ২. ডিরেক্টরি: সব কাজ /app ফোল্ডারে হবে
WORKDIR /app

# ৩. কপি: আমার পিসির সব কোড কন্টেইনারের ভিতরে ঢুকাও
COPY . /app

# ৪. ইন্সটল: প্রয়োজনীয় লাইব্রেরি নামাও
RUN pip install -r requirements.txt

# ৫. স্টার্ট: কন্টেইনার চালু হলে এই কমান্ড চালাবে
CMD ["python", "app.py"]
```

এখন এই রেসিপি দিয়ে ইমেজ বানাতে হবে। কমান্ড:
```bash
docker build -t my-first-app .
```
*(এখানে `-t` মানে নাম দেওয়া, আর শেষের `.` মানে হলো Dockerfile টা এই ফোল্ডারেই আছে)*

### **পর্ব ৫: পোর্ট ম্যাপ (দরজা খোলা)**

তোমার অ্যাপ কন্টেইনারের ভেতরে চলছে, কিন্তু তুমি ব্রাউজার দিয়ে এক্সেস করতে পারছ না। কেন?
কারণ কন্টেইনার একটা **বন্ধ ঘর**। তোমাকে দরজা (Port) খুলে দিতে হবে।

কমান্ড:
```bash
docker run -p 8080:5000 my-first-app
```

**ব্যাখ্যা:**
*   `8080`: এটা তোমার ল্যাপটপের পোর্ট (ঘরের বাইরের দরজা)।
*   `5000`: এটা কন্টেইনারের ভেতরের পোর্ট (ঘরের ভেতরের দরজা)।
*   এখন তুমি ব্রাউজারে `localhost:8080` দিলেই কন্টেইনারের `5000` পোর্টে হিট করবে। **ম্যাজিক!** 🎩

---

### **পর্ব ৬: ডাটা হারিয়ে যাচ্ছে? (Volumes)**

কন্টেইনারের একটা বড় সমস্যা হলো, কন্টেইনার ডিলিট করলে ভেতরের ডাটাও ডিলিট হয়ে যায়। (Temporary Memory)।
ধরো ডাটাবেস কন্টেইনারে অনেক ডাটা রাখলে, কন্টেইনার রিস্টার্ট দিল, সব গায়েব! 😭

**সমাধান: Volume (ভলিউম)**
ভলিউম হলো একটা পেনড্রাইভ বা এক্সটারনাল হার্ডডিস্কের মতো। কন্টেইনার মরে গেলেও ডাটা সেফ থাকবে।

```bash
docker run -v my_data:/var/lib/mysql mysql
```
মানে, কন্টেইনারের `/var/lib/mysql` ফোল্ডারের সব ডাটা আমার পিসির `my_data` তে সেভ থাকবে। কন্টেইনার মরুক, ডাটা অমর!

### **পর্ব ৭: বস লেভেল (Docker Compose)**

ধরো তোমার অ্যাপে ৩টা জিনিস লাগে:
১. রিয়েক্ট ফ্রন্টএন্ড
২. নোডজেএস ব্যাকএন্ড
৩. মংগোডিবি ডাটাবেস

তিনটার জন্য ৩ বার `docker run` কমান্ড দেওয়া বিরক্তিকর। এদের কানেক্ট করা আরও পেইন।
এখানেই আসে **Docker Compose**। এটা হলো অর্কেস্ট্রার কন্ডাক্টর।

একটা ফাইল বানাও `docker-compose.yml`:

```yaml
version: '3'
services:
  frontend:
    image: my-react-app
    ports:
      - "3000:3000"
  
  backend:
    image: my-node-app
    ports:
      - "5000:5000"
  
  database:
    image: mongo
    volumes:
      - db-data:/data/db

volumes:
  db-data:
```

এখন জাস্ট একটা জাদুকরী কমান্ড দাও:
```bash
docker-compose up
```
ব্যস! সব সার্ভিস একসাথে চালু হয়ে যাবে এবং একে অপরের সাথে কথা বলতে পারবে। 😎

### **সামারি (TL;DR)**

১. **Dockerfile:** রান্নার রেসিপি।
২. **Image:** রেসিপি অনুযায়ী প্যাকেটজাত খাবার।
৩. **Container:** প্যাকেট খুলে খাবার প্লেটে দেওয়া (Running App)।
৪. **Volume:** খাবার খেয়ে ফেললেও প্লেট যাতে থেকে যায় (Data Persistence)।
৫. **Docker Compose:** ফুল কোর্সের ডিনার সেট (Frontend + Backend + DB)।
