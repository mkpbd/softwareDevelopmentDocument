### **১. সমস্যাটা কী? (The Amnesia Problem)** 🧠

ডকার কন্টেইনারগুলো হলো **"গজনী"** সিনেমার আমির খানের মতো। এদের মেমোরি খুব শর্ট।
*   আপনি একটা কন্টেইনার চালু করলেন।
*   সেখানে ডাটাবেসে কিছু ডাটা রাখলেন বা ফাইলে কিছু লিখলেন।
*   কন্টেইনারটা ডিলিট করলেন বা ক্র্যাশ করল।
*   **বুম!** আপনার সব ডাটা চিরতরের জন্য ডিলিট। নতুন কন্টেইনার চালু করলে সে আর আগের ডাটা চিনবে না।

এই সমস্যা সমাধানের জন্যই **Volume**-এর জন্ম।

### **২. ভলিউম আসলে কী? (The Immortal Locker)** 🔒

ভলিউম হলো আপনার পিসির হার্ডডিস্কের একটা **"সুরক্ষিত লকার"**।
আমরা কন্টেইনারকে বলি: *"দেখ ভাই, তুই মর বা বাঁচ, সেটা তোর ব্যাপার। কিন্তু ডাটাগুলো নিজের পেটে না রেখে এই লকারে (Volume) রাখবি।"*

ফলে, কন্টেইনার ডিলিট হয়ে গেলেও লকার (Volume) ঠিকই থেকে যায়। নতুন কন্টেইনার এসে ওই লকার ব্যবহার করে আবার আগের ডাটা পেয়ে যায়। **ডাটা অমর হয়ে যায়!**

### **৩. সিনট্যাক্স (সূত্র)**

ভলিউম কানেক্ট করার সূত্র খুবই সহজ:
```bash
-v [আমার_পিসির_জায়গা] : [কন্টেইনারের_ভেতরের_জায়গা]
```
মাঝখানে একটা কোলন (`:`) থাকবে। বাম পাশে **হোস্ট (Host)**, ডান পাশে **কন্টেইনার (Container)**।

---

### **৪. প্র্যাকটিক্যাল উদাহরণ (হাতে-কলমে)**

আমরা দুই ধরনের ভলিউম দেখব।

#### **Type A: Named Volume (ডকার ম্যানেজড ভলিউম)**
এটা প্রোডাকশন বা ডাটাবেসের (MySQL/Postgres) জন্য বেস্ট। এখানে আমরা পিসির কোনো ফোল্ডার সিলেক্ট করি না, ডকার নিজের মতো একটা জায়গা বানিয়ে নেয়।

**Step 1: একটা ভলিউম বানাই**
```bash
docker volume create my-secret-vault
```

**Step 2: ভলিউম সহ কন্টেইনার চালাই**
আমরা একটা `nginx` সার্ভার চালাব এবং তার html ফোল্ডারটা ভলিউমে রাখব।
```bash
docker run -d -p 8080:80 \
  -v my-secret-vault:/usr/share/nginx/html \
  --name my-website nginx
```

**Step 3: ডাটা তৈরি করি**
কন্টেইনারে ঢুকে একটা ফাইল বানাই।
```bash
docker exec -it my-website bash
# ভেতরে ঢুকে:
echo "<h1>Volume is working!</h1>" > /usr/share/nginx/html/index.html
exit
```
এখন ব্রাউজারে `localhost:8080` দিলে দেখবে "Volume is working!"।

**Step 4: কন্টেইনার খুন করি (Test Persistence)**
```bash
docker stop my-website
docker rm my-website
```
কন্টেইনার নাই! কিন্তু ভলিউম `my-secret-vault` এখনো আছে।

**Step 5: নতুন কন্টেইনারে পুরাতন ভলিউম লাগাই**
```bash
docker run -d -p 9090:80 \
  -v my-secret-vault:/usr/share/nginx/html \
  --name my-new-website nginx
```
এখন ব্রাউজারে `localhost:9090` চেক করো।
**ম্যাজিক!** 😲 সেই আগের "Volume is working!" লেখাটাই দেখাচ্ছে। ডাটা হারায়নি!

---

#### **Type B: Bind Mount (ডেভেলপারদের জন্য)**
কোড করার সময় আমরা চাই, আমার ল্যাপটপের ফোল্ডারে কোড চেঞ্জ করলে কন্টেইনারেও চেঞ্জ হয়ে যাক। এটাকে বলে **Bind Mount**।

**সূত্র:**
`-v [ল্যাপটপের_ফুল_পাথ]:[কন্টেইনার_পাথ]`

**Example:**
ধরো তুমি এখন `C:\Projects\MyApp` বা `/home/user/MyApp` ফোল্ডারে আছ।

```bash
docker run -d -p 8080:80 \
  -v $(pwd):/usr/share/nginx/html \
  nginx
```
*(এখানে `$(pwd)` মানে বর্তমান ফোল্ডার)*
এখন তুমি তোমার পিসিতে বসে `index.html` এডিট করলে, সাথে সাথে ব্রাউজারে আপডেট দেখতে পাবে। কন্টেইনার রিস্টার্ট দেওয়ার দরকার নাই!

### **৫. Docker Compose-এ ভলিউম (Best Practice)** 🍱

রিয়েল লাইফে আমরা কমান্ড লিখে ভলিউম বানাই না। `docker-compose.yml` এ লিখে দিই। বিশেষ করে ডাটাবেসের জন্য এটা মাস্ট।

**Example: SQL Server with Volume**

```yaml
version: '3.8'

services:
  db:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: root
    volumes:
      # সূত্র: ভলিউমের নাম : কন্টেইনারের ভেতরের ফোল্ডার
      - db_data:/var/lib/mysql

  web:
    image: nginx
    ports:
      - "8080:80"
    volumes:
      # Bind Mount: পিসির ফোল্ডার কানেক্ট করা
      - ./my-code:/usr/share/nginx/html

# নিচে বলে দিতে হবে db_data নামে একটা ভলিউম বানাতে হবে
volumes:
  db_data:
```

### **৬. ভলিউম ম্যানেজমেন্ট কমান্ড (Tools)** 🛠️

কাজের শেষে জঞ্জাল সাফ করার জন্য এই কমান্ডগুলো লাগবে:

| কমান্ড | কাজ |
| :--- | :--- |
| `docker volume ls` | পিসিতে কয়টা ভলিউম আছে দেখা। |
| `docker volume create [name]` | নতুন ভলিউম বানানো। |
| `docker volume inspect [name]` | ভলিউমটা পিসির ঠিক কোন ফোল্ডারে সেভ হচ্ছে তা দেখা। |
| `docker volume rm [name]` | ভলিউম ডিলিট করা (যদি কোনো কন্টেইনার এটা ইউজ না করে)। |
| `docker volume prune` | **Danger Zone:** যেসব ভলিউম কেউ ব্যবহার করছে না, সব ডিলিট করা। |

### **সামারি (TL;DR)**

১. **Container** = টেম্পোরারি (অস্থায়ী মেমোরি)।
২. **Volume** = পার্মানেন্ট (স্থায়ী হার্ডডিস্ক)।
৩. **Database** এর জন্য সবসময় **Named Volume** ব্যবহার করবে।
৪. **Code Development** এর জন্য **Bind Mount** (পিসির ফোল্ডার ম্যাপ) ব্যবহার করবে।

### **উদাহরণ ১: ডাটাবেস বাঁচানো (PostgreSQL) 🐘**
সবচেয়ে কমন ইউজ কেস। ধরো তুমি `Postgres` ডাটাবেস ব্যবহার করছ।

**সমস্যা:** কন্টেইনার ডিলিট হলে ডাটাবেসের সব টেবিল গায়েব হয়ে যায়।
**সমাধান:** Named Volume ব্যবহার করা।

```bash
# ১. একটা ভলিউম বানাই
docker volume create pg-data

# ২. কন্টেইনার রান করি
docker run -d \
  --name my-postgres \
  -e POSTGRES_PASSWORD=mysecretpassword \
  -v pg-data:/var/lib/postgresql/data \
  postgres
```
**ব্যাখ্যা:**
*   Postgres তার সব ডাটা রাখে `/var/lib/postgresql/data` ফোল্ডারে।
*   আমরা ওই ফোল্ডারটাকে `pg-data` নামক ভলিউমের সাথে "গিট" (knot) বেঁধে দিলাম।
*   এখন `my-postgres` কন্টেইনার ডিলিট করে দিলেও, নতুন কন্টেইনারে এই একই ভলিউম মাউন্ট করলে সব ডাটা ফেরত পাবে।

### **উদাহরণ ২: লগ ফাইল মনিটরিং (The CCTV Camera) 📹**
ধরো তোমার পাইথন বা ডটনেট অ্যাপ কন্টেইনারের ভেতরে চলছে এবং একটা ফাইলে লগ লিখছে (`app.log`)। তুমি কন্টেইনারে না ঢুকেই সেই লগ দেখতে চাও।

**টেকনিক:** Bind Mount (Host to Container)।

**স্টেপ ১: পিসিতে একটা ফোল্ডার বানাও**
```bash
mkdir my-logs
```

**স্টেপ ২: কন্টেইনার রান (Log ম্যাপিং)**
```bash
docker run -d \
  -v $(pwd)/my-logs:/app/logs \
  my-app-image
```

**ব্যাখ্যা:**
*   অ্যাপ যখন কন্টেইনারের ভেতর `/app/logs/error.log` এ কিছু লিখবে...
*   সাথে সাথে সেটা তোমার পিসির `my-logs/error.log` ফাইলে চলে আসবে।
*   তুমি পিসিতে বসে `VS Code` বা Notepad দিয়ে লগ চেক করতে পারবে। কন্টেইনারে ঢোকার দরকার নেই!

### **উদাহরণ ৩: কনফিগারেশন ফাইল ইনজেকশন (The Cheating Slip) 📝**
এটা আমার ফেভারিট। ধরো তুমি `Nginx` ব্যবহার করছ। ডিফল্ট Nginx এর কনফিগারেশন তোমার ভালো লাগছে না। তুমি নিজের কাস্টম `nginx.conf` ব্যবহার করতে চাও।

কিন্তু এর জন্য পুরো ইমেজ আবার রিবিল্ড (Rebuild) করা বোকামি। আমরা শুধু একটা **ফাইল** মাউন্ট করব।

**কমান্ড:**
```bash
docker run -d -p 80:80 \
  -v $(pwd)/my-custom.conf:/etc/nginx/nginx.conf \
  nginx
```

**কি হলো এখানে?**
*   আমরা পুরো ফোল্ডার না, শুধু একটা ফাইল (`my-custom.conf`) কে কন্টেইনারের কনফিগারেশন ফাইলের (`nginx.conf`) জায়গায় বসিয়ে দিলাম।
*   এখন Nginx তোমার নিয়ম মেনে চলবে।

### **উদাহরণ ৪: রিয়েল-টাইম কোডিং (NodeJS/React Hot Reload) 🔥**
ডেভেলপারদের জন্য এটা লাইফ সেভার। কোড চেঞ্জ করব, আর ব্রাউজারে অটো আপডেট হবে। বারবার বিল্ড করার প্যারা নাই।

**ফাইল:** `docker-compose.yml`

```yaml
version: '3'
services:
  web:
    image: node:18-alpine
    working_dir: /app
    # পুরো প্রজেক্ট ফোল্ডার কন্টেইনারে ম্যাপ করলাম
    volumes:
      - ./:/app
      # node_modules ফোল্ডারটা যেন আমার পিসির সাথে মিক্স না হয়, তাই এটা আলাদা রাখলাম
      - /app/node_modules
    ports:
      - "3000:3000"
    command: npm start
```

**ব্যাখ্যা:**
*   `- ./:/app`: আমার পিসির বর্তমান ফোল্ডারের সব কোড কন্টেইনারের `/app` ফোল্ডারে লাইভ দেখা যাবে।
*   আমি পিসিতে কোড সেভ করলেই কন্টেইনারের ভেতরেও ফাইল সেভ হয়ে যাবে এবং `npm start` সেটা ডিটেক্ট করে সার্ভার রিলোড দিবে।

### **বোনাস: Read-Only Volume (শুধুমাত্র দেখার জন্য) 👀**
মাঝে মাঝে তুমি চাও কন্টেইনার তোমার ফাইল পড়তে পারবে, কিন্তু **ডিলিট বা এডিট** করতে পারবে না। (সিকিউরিটির জন্য)।

**কমান্ডে শুধু `:ro` (Read Only) লাগিয়ে দাও:**

```bash
docker run -d \
  -v $(pwd)/important-data:/app/data:ro \
  my-app
```
**ম্যাজিক:**
*   অ্যাপ `/app/data` থেকে ফাইল পড়তে পারবে।
*   কিন্তু অ্যাপ যদি `rm` বা এডিট করার চেষ্টা করে, ডকার বলবে: **"Permission Denied! হাত দিবি না!"** 🚫

### **ভলিউম চেনার সহজ চার্ট**

| কী চাও? | কোন ভলিউম? | উদাহরণ |
| :--- | :--- | :--- |
| **ডাটাবেস সেভ রাখতে** | Named Volume | `-v my-db:/var/lib/mysql` |
| **কোড লাইভ এডিট করতে** | Bind Mount | `-v ./code:/app` |
| **কনফিগারেশন ফাইল বদলাতে** | File Mount | `-v ./config.json:/app/config.json` |
| **লগ ফাইল দেখতে** | Bind Mount | `-v ./logs:/var/log/app` |

ওস্তাদ, এই উদাহরণগুলো প্র্যাকটিস করলে ভলিউম নিয়ে আর কোনো কনফিউশন থাকবে না! আর কিছু লাগবে? 🐳🚀

ওস্তাদ, ডাটাবেসের ডাটা সেভ রাখা হলো সবচেয়ে জরুরি কাজ। কারণ কন্টেইনার উড়ে গেলে ডাটাবেসও উড়ে যাবে, যদি না আপনি **Volume** ব্যবহার করেন।

SQL Server (MSSQL) এর জন্য ভলিউম সেটআপ করার নিয়মটা একদম সহজ করে দিচ্ছি।

আপনার শুধু একটা জিনিস মুখস্থ রাখতে হবে:
SQL Server তার সব ডাটা (mdf, ldf, logs, secrets) রাখে কন্টেইনারের **`/var/opt/mssql`** ফোল্ডারে। আমাদের এই ফোল্ডারটাকেই ব্যাকআপ রাখতে হবে।

নিচে ৩টি উপায় দিচ্ছি, আপনার যেটা সুবিধা হয় ব্যবহার করুন।

### **পদ্ধতি ১: Named Volume (সবচেয়ে নিরাপদ ও সহজ) ⭐**
এখানে ডকার নিজের দায়িত্বে ডাটা ম্যানেজ করবে। প্রোডাকশনের জন্য এটাই বেস্ট।

**কমান্ড:**
```bash
docker run -d --name my-sql-server \
  -e "ACCEPT_EULA=Y" \
  -e "SA_PASSWORD=YourStrong!Pass123" \
  -p 1433:1433 \
  -v sql_volume:/var/opt/mssql \
  mcr.microsoft.com/mssql/server:2022-latest
```

**ব্যাখ্যা:**
*   **`-v sql_volume:/var/opt/mssql`**: এখানে `sql_volume` হলো ভলিউমের নাম। ডকার অটোমেটিকলি এই নামে একটা স্টোরেজ বানিয়ে নিবে এবং কন্টেইনারের `/var/opt/mssql` এর সাথে জুড়ে দিবে।

### **পদ্ধতি ২: Bind Mount (আপনার পিসির নির্দিষ্ট ফোল্ডারে) 📂**
আপনি যদি চান ডাটাগুলো আপনার পিসির `D:\DockerData` ড্রাইভে সেভ থাকবে, যাতে আপনি চোখে দেখতে পান।

**কমান্ড (Windows CMD/PowerShell):**
```bash
docker run -d --name my-sql-server \
  -e "ACCEPT_EULA=Y" \
  -e "SA_PASSWORD=YourStrong!Pass123" \
  -p 1433:1433 \
  -v D:\DockerData:/var/opt/mssql \
  mcr.microsoft.com/mssql/server:2022-latest
```
*(নোট: `D:\DockerData` ফোল্ডারটি আগে বানিয়ে নিবেন)*

### **পদ্ধতি ৩: Docker Compose (প্রফেশনাল ওয়ে) 👔**
বারবার এত বড় কমান্ড না লিখে একটা ফাইলে সেভ করে রাখা ভালো।

**ফাইল:** `docker-compose.yml`

```yaml
version: '3.8'

services:
  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    container_name: sql_server_container
    environment:
      ACCEPT_EULA: "Y"
      # পাসওয়ার্ড অবশ্যই স্ট্রং হতে হবে (বড় হাতের, ছোট হাতের, সংখ্যা, স্পেশাল ক্যারেক্টার)
      SA_PASSWORD: "YourStrong!Pass123" 
    ports:
      - "1433:1433"
    volumes:
      # ভলিউম ম্যাপিং
      - mssql_data:/var/opt/mssql

# ভলিউম ডিক্লারেশন
volumes:
  mssql_data:
```

**রান করার নিয়ম:**
```bash
docker-compose up -d
```

### **পরীক্ষা করে দেখুন (Test it!)** 🧪

সত্যিই ডাটা সেভ হচ্ছে কিনা বুঝবেন কীভাবে?

১. কন্টেইনার চালু করুন।
২. SQL Server Management Studio (SSMS) বা Azure Data Studio দিয়ে কানেক্ট করুন (`localhost, 1433` - `sa` - `YourStrong!Pass123`)।
৩. একটা নতুন ডাটাবেস বানান, নাম দিন `TestDB`।
৪. এবার কন্টেইনারটি ডিলিট করে দিন:
   ```bash
   docker rm -f my-sql-server
   ```
৫. আবার আগের কমান্ড দিয়ে **একই ভলিউমসহ** নতুন কন্টেইনার চালু করুন।
৬. আবার কানেক্ট করুন। দেখবেন `TestDB` এখনো আছে! ম্যাজিক! 😎
