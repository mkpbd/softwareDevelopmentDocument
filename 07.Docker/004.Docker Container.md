
ওস্তাদ! ডকারের **হার্ট বা হৃদপিণ্ড** হলো এই **Container**। আমরা এতক্ষণ যা যা শিখলাম (Image, Volume, Dockerfile)—সবকিছুর মূল উদ্দেশ্য একটাই: একটা সুস্থ-সবল **Container** জন্ম দেওয়া।

চলো, কন্টেইনারের নাড়ি-নক্ষত্র খুলে দেখি! 🕵️‍♂️

---

### **১. কন্টেইনার জিনিসটা আসলে কী? (The Soul)**

সহজ বাংলায়:
*   **Image** হলো মৃত (Dead)। এটা শুধুই একটা ফাইল বা নকশা।
*   **Container** হলো জীবিত (Alive)। ইমেজ যখন মেমোরিতে লোড হয়ে চলতে শুরু করে, তখন তাকে কন্টেইনার বলে।

**উদাহরণ:**
> **Image** = সিডি/ডিভিডি ডিস্ক (CD)। এটা আলমারিতে পড়ে থাকে, গান বাজে না।
> **Container** = ডিভিডি প্লেয়ারে ডিস্ক ঢুকিয়ে "Play" বাটন চাপা। এখন গান বাজছে, মেমোরি খাচ্ছে, প্রসেসর গরম হচ্ছে।

---

### **২. ভার্চুয়াল মেশিন (VM) vs কন্টেইনার (Container)**

অনেকে ভাবে কন্টেইনার আর VM একই। একদম না!

*   **VM (ভার্চুয়াল মেশিন):** মনে করো একটা ১০ তলা বিল্ডিং। প্রত্যেক ফ্ল্যাটে আলাদা আলাদা পানির পাম্প, আলাদা জেনারেটর, আলাদা দারোয়ান। এটা ভারী এবং খরুচে।
*   **Container:** একই বিল্ডিং। পানির পাম্প, জেনারেটর, দারোয়ান সব কমন (Shared OS Kernel)। শুধু ফ্ল্যাটের ভেতরের আসবাবপত্র আলাদা। এটা হালকা এবং সুপার ফাস্ট! 🚀

### **৩. কন্টেইনারের জীবনচক্র (Lifecycle)** 🌱➡️💀

একটা কন্টেইনারের জীবনে এই ঘটনাগুলো ঘটে:

1.  **Create:** ইমেজ থেকে কন্টেইনার বানালাম (কিন্তু চালু করিনি)।
2.  **Start:** কন্টেইনার চালু হলো (Play button)।
3.  **Run:** একবারে বানিয়ে চালু করে দেওয়া (Create + Start)।
4.  **Pause:** ভিডিও পজ করার মতো, কন্টেইনার ফ্রিজ হয়ে থাকবে।
5.  **Stop:** শাটডাউন করা (ভদ্রভাবে)।
6.  **Kill:** ডাইরেক্ট পাওয়ার ক্যাবল খুলে দেওয়া (অভদ্রভাবে)।
7.  **Remove:** লাশ গুম করে ফেলা (ডিলিট)।

### **৪. কন্টেইনার চালানোর ২টা স্টাইল (Modes)** 😎

কন্টেইনার রান করার সময় এই দুইটা মুড খুব গুরুত্বপূর্ণ:

#### **A. Detached Mode (`-d`) - "নীরব ঘাতক"**
কন্টেইনার ব্যাকগ্রাউন্ডে চলবে। টার্মিনাল আটকে রাখবে না। ওয়েব সার্ভার বা ডাটাবেসের জন্য এটা লাগে।

```bash
docker run -d --name my-web nginx
```
*   আউটপুট: শুধু একটা লম্বা ID দিবে। কন্টেইনার ব্যাকগ্রাউন্ডে চলছে।

#### **B. Interactive Mode (`-it`) - "সামনাসামনি কথা"**
তুমি কন্টেইনারের ভেতরে ঢুকে কমান্ড চালাতে চাও। লিনাক্স বা ইউটিলিটি কন্টেইনারের জন্য লাগে।

```bash
docker run -it ubuntu bash
```
*   এখন তুমি উবুন্টুর ভেতরে ঢুকে গেছ। `exit` লিখলে কন্টেইনার বন্ধ হয়ে তুমি বের হয়ে আসবে।

### **৫. কন্টেইনারের প্র্যাকটিক্যাল অপারেশন (Operation Theatre)** 🔪

চলো একটা `nginx` কন্টেইনার নিয়ে খেলি।

**১. জন্ম দেওয়া (Run):**
```bash
docker run -d -p 8080:80 --name my-server nginx
```
*   ব্রাউজারে `localhost:8080` চেক করো।

**২. চেকআপ (List):**
```bash
docker ps
# সব (বন্ধগুলোসহ) দেখতে: docker ps -a
```

**৩. ভেতরে ঢোকা (Exec):**
চলমান কন্টেইনারের ভেতরে ঢুকতে:
```bash
docker exec -it my-server bash
# কাজ শেষ হলে 'exit' দাও
```

**৪. থামানো (Stop):**
```bash
docker stop my-server
```

**৫. আবার চালু করা (Start):**
```bash
docker start my-server
```

**৬. মৃত্যু (Remove):**
থেমে থাকা কন্টেইনার ডিলিট করতে:
```bash
docker rm my-server
# যদি রানিং থাকে, জোর করে ডিলিট করতে: docker rm -f my-server
```

### **৬. কিছু স্পেশাল ফ্ল্যাগ (Pro Tips) 🔥**

কমান্ডের সাথে এই ছোট ছোট অপশনগুলো জীবন সহজ করে দেয়:

*   **`--rm`**: কন্টেইনার বন্ধ হওয়ার সাথে সাথে অটো ডিলিট হয়ে যাবে। (ওয়ান-টাইম কাজের জন্য বেস্ট)।
    ```bash
    docker run --rm hello-world
    ```
*   **`--restart always`**: পিসি রিস্টার্ট দিলে বা কন্টেইনার ক্র্যাশ করলে একা একাই আবার চালু হবে। (প্রোডাকশনে মাস্ট!)
    ```bash
    docker run -d --restart always nginx
    ```
*   **`--name`**: কন্টেইনারের একটা সুন্দর নাম দেওয়া। না দিলে ডকার `naughty_einstein` টাইপ আজগুবি নাম দিবে।

### **৭. কন্টেইনার ডিবাগিং (যখন কন্টেইনার স্টার্ট হয় না)** 🚑

মাঝে মাঝে কন্টেইনার রান করলেই ধুপ করে বন্ধ হয়ে যায় (Exited)। তখন গোয়েন্দাগিরি করতে হবে।

**Step 1: লগ দেখো**
```bash
docker logs my-server
```
লগ ফাইল পড়লে ৯৯% সময় বোঝা যায় কেন সে মারা গেল।

**Step 2: ডিটেইলস দেখো (Inspect)**
```bash
docker inspect my-server
```
এখানে আইপি এড্রেস, ভলিউম পাথ, এনভায়রনমেন্ট ভেরিয়েবল সব দেখা যায়।

---

**ওস্তাদ, চ্যালেঞ্জ:**
তোমার টার্মিনালে নিচের কমান্ডটা চালাও তো:
```bash
docker run -it --rm alpine echo "I am a temporary container!"
```
দেখবে মেসেজটা প্রিন্ট করেই কন্টেইনারটা গায়েব হয়ে গেছে (`docker ps -a` তেও পাবে না)। এটাকে বলে **Ephemeral Container**।

কোনো স্টেপে আটকে গেলে জানাও! 🐳

### **উদাহরণ ১: ওয়ান টাইম ওয়ার্কার (One-Time Job Container) 🏃‍♂️💨**
সব কন্টেইনার যে সারাদিন চলতে হবে এমন না। কিছু কন্টেইনার আছে—আসবে, কাজ করবে, মরে যাবে এবং লাশও গায়েব হয়ে যাবে!

আমরা একটা **Python** কন্টেইনার দিয়ে একটা ছোট অংক করাব এবং কাজ শেষে সেটা অটো ডিলিট হয়ে যাবে।

**কোড:**
```bash
docker run --rm python:3.9-slim python -c "print('The result is:', 125 * 8)"
```

**কী হলো এখানে?**
*   `python:3.9-slim`: পাইথনের ইমেজ নামাল (যদি না থাকে)।
*   `python -c "..."`: কন্টেইনারের ভেতরে পাইথন স্ক্রিপ্ট চালাল।
*   **`--rm`**: এটাই আসল ম্যাজিক! কাজ শেষ হওয়ার সাথে সাথে কন্টেইনারটি নিজেকে ডিলিট করে ফেলল। `docker ps -a` তেও একে পাবে না। ক্লিন এন্ড ক্লিয়ার! ✨

### **উদাহরণ ২: এনভায়রনমেন্ট ভেরিয়েবল (Customized Container) 🛠️**
ধরো তুমি একটা MySQL ডাটাবেস কন্টেইনার চালু করতে চাও। কিন্তু পাসওয়ার্ড ছাড়া MySQL চালু হয় না। কন্টেইনারকে পাসওয়ার্ড দিবে কীভাবে? **`-e`** বা Environment Variable দিয়ে।

**কোড:**
```bash
docker run -d \
  --name my-db \
  -e MYSQL_ROOT_PASSWORD=super_secret_pass \
  -e MYSQL_DATABASE=test_db \
  mysql:5.7
```

**ব্যাখ্যা:**
*   **`-e`**: কন্টেইনারের কানে কানে বলে দিলাম—"তোর পাসওয়ার্ড হলো `super_secret_pass` আর ডাটাবেস নাম `test_db`"।
*   কন্টেইনার এই তথ্যগুলো নিয়ে নিজেকে কনফিগার করে চালু হলো।

### **উদাহরণ ৩: "জম্বি" কন্টেইনার (Restart Policy) 🧟‍♂️**
প্রোডাকশন সার্ভারে মাঝে মাঝে অ্যাপ ক্র্যাশ করে। আমরা চাই কন্টেইনার মরে গেলে যেন অটোমেটিক আবার জ্যান্ত হয়ে যায়।

**কোড:**
```bash
docker run -d --restart always --name zombie-app nginx
```

**পরীক্ষা (Test the Magic):**
১. কন্টেইনার চলছে কিনা দেখো: `docker ps`
২. এবার ম্যানুয়ালি এটাকে মেরে ফেলো (Kill):
   ```bash
   docker kill zombie-app
   ```
৩. সাথে সাথে আবার `docker ps` দাও।
   **ম্যাজিক!** দেখবে এটা আবার চালু হয়ে গেছে (STATUS এ দেখবে `Up Less than a second`)। একে মেরে ফেলা অসম্ভব!

### **উদাহরণ ৪: র‍্যাম/মেমোরি লিমিট (Diet Control) 🥗**
কিছু অ্যাপ আছে যা পিসির সব র‍্যাম খেয়ে ফেলে (যেমন Chrome বা Java App)। কন্টেইনারকে আমরা বলে দিতে পারি—"তুই ২০০ এমবির বেশি র‍্যাম খাবি না!"

**কোড:**
```bash
docker run -d --memory="256m" --name diet-nginx nginx
```

**ব্যাখ্যা:**
*   **`--memory="256m"`**: এই কন্টেইনার এখন ২৫৬ মেগাবাইটের বেশি র‍্যাম ব্যবহার করতে পারবে না। যদি করার চেষ্টা করে, ডকার তাকে শাটডাউন করে দিবে (OOM Kill)। এতে তোমার মেইন পিসি স্লো হবে না।

### **উদাহরণ ৫: আলপাইন লিনাক্স (The Tiny Warrior) 🐜**
আমরা সাধারণত `ubuntu` ইমেজ ব্যবহার করি যা প্রায় ৭০-৮০ মেগাবাইট। কিন্তু **Alpine** লিনাক্স মাত্র **৫ মেগাবাইট**! বিশ্বাস হচ্ছে না?

**কোড:**
```bash
docker run -it alpine sh
```
*(Alpine এ `bash` থাকে না, `sh` থাকে)*

**ভেতরে ঢুকে চেক করো:**
```bash
# লিনাক্স ভার্সন দেখো
cat /etc/os-release
# পিং করে দেখো ইন্টারনেট আছে কিনা
ping google.com
```
এত ছোট সাইজ, অথচ দুনিয়ার সব কাজ করা যায়। প্রোডাকশনে আমরা ইমেজের সাইজ ছোট রাখতে এই Alpine ব্যবহার করি।

### **বোনাস: কন্টেইনারের নাম বদলানো (Rename) 🏷️**
ধরো তুমি তাড়াহুড়ো করে কন্টেইনার বানিয়েছ, ডকার নাম দিয়েছে `sad_newton`। তুমি নাম পাল্টাতে চাও।

```bash
# পুরনো নাম -> নতুন নাম
docker rename sad_newton my-super-server
```

---

**সামারি প্র্যাকটিস:**
ওস্তাদ, এখন তোমার কাজ হলো **উদাহরণ ৩ (জম্বি কন্টেইনার)** টা টেস্ট করা।
১. একটা কন্টেইনার বানাও `--restart always` দিয়ে।
২. ওটাকে `docker stop` বা `docker kill` দিয়ে মারার চেষ্টা করো।
৩. দেখো সে ফিরে আসে কিনা।

মজা পেলে জানাও! 😎🐳
