
স্বাগতম ওস্তাদ! ডকারের **নেটওয়ার্কিং (Networking)** হলো সেই জাদুকরী সুতা, যা এক কন্টেইনারকে আরেক কন্টেইনারের সাথে, অথবা কন্টেইনারকে বাইরের দুনিয়ার সাথে কথা বলতে সাহায্য করে।

নেটওয়ার্কিং না থাকলে কন্টেইনারগুলো হলো **"জনমানবহীন দ্বীপ"**-এর মতো। একা একা বসে থাকবে, কারো সাথে যোগাযোগ করতে পারবে না। 🏝️

ডকার নেটওয়ার্কিং প্রধানত **৩ প্রকার**। চলো সহজ উদাহরণের মাধ্যমে শিখি।

---

### **১. Bridge Network (ডিফল্ট / প্রাইভেট ফ্লাট) 🌉**
তুমি যখন `docker run` দিয়ে কোনো কন্টেইনার বানাও, ডকার অটোমেটিক তাকে এই নেটওয়ার্কে ফেলে দেয়।

*   **কনসেপ্ট:** মনে করো একটা বিল্ডিংয়ের ভেতরে ইন্টারকম সিস্টেম। ফ্ল্যাটের ভেতরের মানুষ একে অপরের সাথে কথা বলতে পারে, কিন্তু বাইরের মানুষ সরাসরি পারে না (গেটম্যান বা পোর্ট ফরোয়ার্ডিং লাগে)।
*   **বৈশিষ্ট্য:** কন্টেইনারগুলো নিজেদের আলাদা আইপি (IP) পায়।
*   **সমস্যা:** এখানে এক কন্টেইনার আরেক কন্টেইনারকে নাম ধরে চিনতে পারে না, আইপি এড্রেস দিয়ে ডাকতে হয় (যা বারবার বদলায়)।

**উদাহরণ:**
```bash
docker run -d --name my-web nginx
```
এখন `docker inspect my-web` দিলে দেখবে তার একটা আইপি আছে (যেমন `172.17.0.2`)।

---

### **২. Host Network (ওপেন মেঠো পথ) 🛣️**
এখানে কন্টেইনারের কোনো প্রাইভেসি নাই।

*   **কনসেপ্ট:** তোমার বাসার দেয়াল ভেঙে দেওয়ার মতো। তোমার পিসি (Host) আর কন্টেইনার একই নেটওয়ার্কে থাকে।
*   **বৈশিষ্ট্য:** কন্টেইনারের আইপি আর তোমার পিসির আইপি একই হবে। পোর্ট ম্যাপ (`-p`) করার দরকার নাই।
*   **লিমিটেশন:** এটা লিনাক্সে দারুণ কাজ করে, কিন্তু উইন্ডোজ/ম্যাকে ঠিকঠাক কাজ করে না।

**উদাহরণ:**
```bash
docker run -d --network host --name open-web nginx
```
এখন তোমার পিসির `localhost:80` তে সরাসরি Nginx চলবে।

---

### **৩. None Network (নিঃসঙ্গ শেরপা) 🧘**
এখানে কোনো ইন্টারনেট নাই, কোনো সংযোগ নাই।

*   **কনসেপ্ট:** কন্টেইনারকে একটা লোহার সিন্দুকে ভরে সাগরে ফেলে দেওয়া।
*   **ব্যবহার:** যখন তুমি চাও কন্টেইনারে শুধু সিকিউর কিছু ক্যালকুলেশন হবে, বাইরের কেউ ডিস্টার্ব করবে না।

**উদাহরণ:**
```bash
docker run -d --network none alpine
```

### **🔥 আসল খেলা: Custom Bridge Network (User Defined)**

ওস্তাদ, রিয়েল লাইফ প্রজেক্টে আমরা **Custom Bridge Network** ব্যবহার করি। কেন?
কারণ ডিফল্ট ব্রিজে কন্টেইনাররা একে অপরের **নাম** চিনে না। কিন্তু কাস্টম নেটওয়ার্কে নাম ধরে ডাকা যায় (DNS Resolution)।

**দৃশ্যপট:** আমাদের একটা ওয়েবসাইট (Web) এবং একটা ডাটাবেস (DB) আছে। তারা একে অপরের সাথে কথা বলবে।

**Step 1: একটা নিজস্ব নেটওয়ার্ক বানাই**
```bash
docker network create my-app-net
```

**Step 2: এই নেটওয়ার্কে ডাটাবেস চালু করি**
```bash
docker run -d \
  --name my-mongo \
  --network my-app-net \
  mongo
```

**Step 3: একই নেটওয়ার্কে ওয়েবসাইট (অ্যাপ) চালু করি**
```bash
# আমরা টেস্ট করার জন্য একটা ছোট লিনাক্স (alpine) নিচ্ছি
docker run -it \
  --name my-website \
  --network my-app-net \
  alpine sh
```

**Step 4: নাম ধরে ডাকি (Ping)**
এখন আমরা `my-website` এর পেটের ভেতর আছি। এখান থেকে ডাটাবেসকে পিং করব।
```bash
# কন্টেইনারের ভেতরে লিখো:
ping my-mongo
```
**রেজাল্ট:** দেখবে পিং পাচ্ছে! 😲
`64 bytes from ...`

**ম্যাজিক:** আমরা আইপি এড্রেস জানি না, শুধু নাম (`my-mongo`) দিয়েছি, ডকার অটোমেটিক তাকে খুঁজে বের করেছে। এটাই **Service Discovery**।

### **কমন ভুল: `localhost` এর গোলকধাঁধা 🌀**

সবচেয়ে বেশি মানুষ যেখানে ধরা খায়:

ধরো তোমার পিসিতে একটা SQL Server চলছে। তুমি কন্টেইনারের ভেতর থেকে সেটা কানেক্ট করতে চাও। তুমি কানেকশন স্ট্রিং এ দিলে `Server=localhost`।

*   **সমস্যা:** কন্টেইনারের কাছে `localhost` মানে **সে নিজে**। সে তোমার পিসিকে চিনে না।
*   **সমাধান:** তোমাকে বিশেষ একটা ডোমেইন ব্যবহার করতে হবে: `host.docker.internal`

**কোড উদাহরণ:**
```bash
# কন্টেইনার থেকে পিসির লোকালহস্ট এক্সেস করতে
docker run -it alpine ping host.docker.internal
```
*(এটা উইন্ডোজ আর ম্যাকে কাজ করে, লিনাক্সে `--add-host` ফ্ল্যাগ লাগে)*

### **নেটওয়ার্কিং কমান্ড চিটশিট 📜**

| কমান্ড | কাজ |
| :--- | :--- |
| `docker network ls` | তোমার পিসিতে কয়টা নেটওয়ার্ক আছে দেখা। |
| `docker network create [name]` | নতুন নেটওয়ার্ক বানানো। |
| `docker network inspect [name]` | নেটওয়ার্কের ডিটেইলস দেখা (কে কে কানেক্টেড)। |
| `docker network connect [net] [container]` | চলমান কন্টেইনারকে নতুন নেটওয়ার্কে জোড়া লাগানো। |
| `docker network disconnect [net] [container]`| নেটওয়ার্ক থেকে বের করে দেওয়া। |
| `docker network prune` | অব্যবহৃত সব নেটওয়ার্ক ডিলিট করা। |

ওস্তাদ, **Bridge Network** হলো ডকারের "ডিফল্ট সেটিং"। আপনি যদি ডকারকে কিছু না বলেন যে কন্টেইনারটা কোন নেটওয়ার্কে চলবে, ডকার চোখ বন্ধ করে তাকে এই **Bridge Network**-এ ফেলে দেয়।

সহজ কথায়: এটা হলো কন্টেইনারদের জন্য একটা **"প্রাইভেট জগত"**।

---

### **১. রিয়েল লাইফ উদাহরণ (The Apartment Analogy) 🏢**

মনে করুন, **আপনার ল্যাপটপ** হলো একটা বিশাল **১০ তলা অ্যাপার্টমেন্ট বিল্ডিং**।

*   **Bridge Network:** বিল্ডিংয়ের ভেতরের **করিডোর বা লবি**।
*   **Containers:** একেকটা **ফ্ল্যাট বা রুম**।
*   **Port Mapping:** মেইন গেটের **দারোয়ান**।

**ঘটনা ১ (Internal Communication):**
ফ্ল্যাট ১০১-এর বাসিন্দা (Container A) যদি ফ্ল্যাট ১০২-এর বাসিন্দার (Container B) সাথে কথা বলতে চায়, সে করিডোর দিয়ে হেঁটে গিয়ে নক করতে পারে। বাইরের কারো অনুমতির দরকার নাই।
*(অর্থাৎ: একই ব্রিজ নেটওয়ার্কে থাকা কন্টেইনাররা একে অপরের সাথে আইপি দিয়ে কথা বলতে পারে।)*

**ঘটনা ২ (Isolation):**
রাস্তা দিয়ে হাঁটা কোনো লোক (User/Internet) চাইলেই ১০১ নাম্বার ফ্ল্যাটে ঢুকে পড়তে পারবে না। কারণ ফ্ল্যাটের দরজা বন্ধ।
*(অর্থাৎ: বাইরের জগত থেকে কন্টেইনারের আইপিতে সরাসরি ঢোকা যায় না।)*

**ঘটনা ৩ (Access):**
বাইরের লোক যদি ১০১-এ ঢুকতে চায়, তাকে দারোয়ানকে (Port Mapping `-p`) বলতে হবে। দারোয়ান তাকে নির্দিষ্ট ফ্ল্যাটে পৌঁছে দিবে।

### **২. টেকনিক্যাল ব্যাপারটা কী? ⚙️**

আপনি যখন ডকার ইন্সটল করেন, তখন আপনার পিসির ভেতরে একটা **কাল্পনিক ওয়াইফাই রাউটার** (Virtual Router) তৈরি হয়। এটার নাম `docker0`।

*   আপনি যখনই নতুন কন্টেইনার বানান, এই রাউটার তাকে একটা **গোপন আইপি** (Private IP) দেয় (যেমন: `172.17.0.2`)।
*   এই আইপি শুধু আপনার পিসির ভেতর থেকেই চেনা যায়। বাইরের ইন্টারনেট বা অন্য পিসি এই আইপি চিনে না।

### **৩. কোড এবং উদাহরণ (Hands-on)** 👨‍💻

চলো প্রমাণ করে দেখি কন্টেইনাররা আসলেই আলাদা আইপি পায় কিনা।

**Step 1: দুইটা কন্টেইনার চালু করি**
আমরা ছোট দুটি `alpine` (হালকা লিনাক্স) কন্টেইনার চালাব। আমরা কোনো নেটওয়ার্কের নাম দিব না, তাই এরা ডিফল্ট **Bridge**-এ কানেক্ট হবে।

```bash
# প্রথম কন্টেইনার
docker run -it -d --name flat-101 alpine sh

# দ্বিতীয় কন্টেইনার
docker run -it -d --name flat-102 alpine sh
```

**Step 2: ফ্ল্যাট ১০১-এর গোপন আইপি বের করি**
```bash
docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' flat-101
```
*   **আউটপুট:** ধরো আসলো `172.17.0.2`

**Step 3: ফ্ল্যাট ১০২-এর গোপন আইপি বের করি**
```bash
docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' flat-102
```
*   **আউটপুট:** ধরো আসলো `172.17.0.3`

**Step 4: এক ফ্ল্যাট থেকে আরেক ফ্ল্যাটে কল (Ping) করি**
এখন আমরা `flat-101` এর ভেতরে ঢুকব এবং `flat-102` কে পিং করব।

```bash
docker exec -it flat-101 sh

# এখন কন্টেইনারের ভেতরে...
# 172.17.0.3 হলো flat-102 এর আইপি
ping 172.17.0.3
```
**রেজাল্ট:** দেখবে পিং রিপ্লাই আসছে! `64 bytes from...`
তার মানে তারা একই করিডোরে (Bridge Network) আছে এবং কথা বলতে পারছে।

### **৪. সমস্যা ও সমাধান (Problem with Default Bridge)** ⚠️

ডিফল্ট ব্রিজ নেটওয়ার্কের একটা বড় সমস্যা হলো, এখানে কন্টেইনাররা একে অপরের **নাম** চিনে না।

*   তুমি যদি `flat-101` এর ভেতর থেকে `ping flat-102` দাও, সে বলবে: `bad address` (চিনে না)।
*   তোমাকে অবশ্যই **IP Address** মুখস্থ রাখতে হবে।

কিন্তু আইপি মনে রাখা তো কষ্টের কাজ! তাই প্রোডাকশনে আমরা **User-Defined Bridge Network** (কাস্টম ব্রিজ) বানাই। সেখানে নাম ধরে ডাকা যায়।

**কাস্টম ব্রিজ বানানোর নিয়ম:**
```bash
# ১. নিজের নেটওয়ার্ক বানাও
docker network create my-society

# ২. কন্টেইনার ঢুকাও
docker run -d --name flat-101 --network my-society alpine
docker run -d --name flat-102 --network my-society alpine

# ৩. এখন নাম দিয়েই পিং পাবে!
docker exec -it flat-101 ping flat-102
```

---

### **সামারি**
*   **Bridge Network** = কন্টেইনারদের নিজস্ব প্রাইভেট জগত।
*   বাইরের কেউ সরাসরি ঢুকতে পারে না (Security)।
*   ভেতরের সবাই আইপি দিয়ে একে অপরের সাথে কথা বলতে পারে।

ওস্তাদ! **Host Network** হলো ডকারের সবচেয়ে "খোলামেলা" নেটওয়ার্কিং মুড। এখানে কোনো লুকোছাপা নাই, কোনো প্রাইভেসি নাই।

সহজ কথায়: **Bridge Network** যদি হয় "অ্যাপার্টমেন্টের বন্ধ ফ্লাট", তবে **Host Network** হলো একদম "রাস্তার মাঝখানে তাবু খাটানো"। ⛺

### **১. কনসেপ্ট (Concept): দেয়াল ভাঙার গল্প** 🧱🔨

সাধারণত (Bridge মুডে), কন্টেইনারের চারদিকে একটা **সুরক্ষা দেয়াল (Network Isolation)** থাকে। কন্টেইনারের নিজস্ব আইপি থাকে, বাইরের জগত থেকে আলাদা থাকে।

কিন্তু **Host Network (`--network host`)** দিলে:
১. কন্টেইনারের সেই সুরক্ষা দেয়াল ভেঙে ফেলা হয়।
২. কন্টেইনারটি আপনার পিসির (Host Machine) **আইপি এবং নেটওয়ার্ক কার্ড** সরাসরি দখল করে ব্যবহার করে।
৩. কোনো **পোর্ট ম্যাপ (`-p`)** করার দরকার হয় না।

---

### **২. রিয়েল লাইফ উদাহরণ (The Roommate Analogy) 🏠**

মনে করুন, আপনার পিসি হলো একটা **বাড়ি**।

*   **Bridge Network:** আপনার বাড়িতে একজন অতিথি (Container) এল। আপনি তাকে একটা আলাদা গেস্ট রুমে ঢুকিয়ে দরজা বন্ধ করে দিলেন। তার সাথে কথা বলতে হলে ইন্টারকম (Port Mapping) লাগে।
*   **Host Network:** অতিথি এসে সোজা আপনার ড্রইংরুমে সোফায় বসে পড়ল। সে আপনার ওয়াইফাই, আপনার টিভি, আপনার ল্যান্ডফোন—সব সরাসরি ব্যবহার করছে। বাইরে থেকে কেউ কল দিলে সে নিজেই ফোন রিসিভ করতে পারে। আপনার আর তার লোকেশন (IP) এখন একটাই!

---

### **৩. কোড এবং উদাহরণ (Hands-on)** 👨‍💻

*(বিদ্র: এই ল্যাবটা **লিনাক্স** মেশিনে ১০০% কাজ করবে। উইন্ডোজ বা ম্যাক-এ ডকার ভার্চুয়াল মেশিনে চলে বলে একটু ভিন্ন আচরণ করতে পারে।)*

আমরা একটা **Nginx** সার্ভার চালাব।

**দৃশ্যপট ১: সাধারণ নিয়ম (Bridge) - মনে করিয়ে দেওয়ার জন্য**
```bash
docker run -d -p 8080:80 nginx
```
*   এখানে আমরা পোর্ট ৮০৮০ দিয়ে পোর্ট ৮০-কে ম্যাপ করেছি। ব্রাউজারে `localhost:8080` তে হিট করতে হয়।

**দৃশ্যপট ২: হোস্ট নেটওয়ার্ক (The Open Field)**
```bash
docker run -d --network host --name my-open-web nginx
```
*   খেয়াল করুন, আমি কোনো `-p` বা পোর্ট ফ্ল্যাগ দিইনি! 😲

**টেস্ট করুন:**
আপনার ব্রাউজার বা টার্মিনাল ওপেন করুন।
```bash
curl localhost:80
# অথবা ব্রাউজারে শুধু http://localhost লিখুন
```
**ম্যাজিক:** পোর্ট ম্যাপ না করার পরেও ওয়েবসাইট চলছে! কারণ কন্টেইনারটি আপনার পিসির পোর্ট ৮০ সরাসরি দখল করে নিয়েছে।

---

### **৪. কেন ব্যবহার করব? (Why Use It?)** 🚀

১. **সুপার ফাস্ট:** যেহেতু কোনো পোর্ট ম্যাপিং বা ব্রিজ পার হতে হয় না, তাই নেটওয়ার্ক স্পিড সামান্য ফাস্ট হয়।
২. **জটিলতা কম:** হাজার হাজার পোর্ট ম্যাপ করার ঝামেলা থাকে না।
৩. **IoT ডিভাইস:** ছোট ডিভাইস বা রাউটার কনফিগারেশনের সময় এটা খুব লাগে।

### **৫. বড় সমস্যা (The Big Problem: Port Conflict) ⚠️**

হোস্ট নেটওয়ার্কের সবচেয়ে বড় বিপদ হলো **"চেয়ার দখল"**।

ধরুন, আপনার পিসিতে আগে থেকেই একটা ওয়েবসাইট চলছে পোর্ট ৮০-তে (যেমন IIS বা Apache)।
এখন যদি আপনি `--network host` দিয়ে Nginx (যেটাও পোর্ট ৮০ চায়) চালাতে যান, তবে **মারামারি বেধে যাবে**।

**এরর:** `Bind for 0.0.0.0:80 failed: port is already allocated.`

**Bridge মুডে** আমরা পোর্ট বদলাতে পারতাম (`-p 8080:80`), কিন্তু **Host মুডে** পোর্ট বদলানোর সুযোগ নাই। কন্টেইনার যেই পোর্ট চাইবে, পিসির সেই পোর্টই খালি থাকতে হবে।

| বৈশিষ্ট্য | Bridge Network | Host Network |
| :--- | :--- | :--- |

| **পোর্ট ম্যাপিং** | লাগে (যেমন: `-p 8080:80`) | লাগে না (ডাইরেক্ট এক্সেস) |
| **পারফর্মেন্স** | একটু স্লো (Natting হয়) | খুব ফাস্ট (Direct) |
| **আইসোলেশন** | নিরাপদ (দেয়াল আছে) | ওপেন (দেয়াল নাই) |
