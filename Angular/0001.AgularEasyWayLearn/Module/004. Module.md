

### **মডিউল ৫: কম্পোনেন্ট কমিউনিকেশন (পারিবারিক সম্পর্ক)**
*এক কম্পোনেন্ট আরেকজনের সাথে কীভাবে কথা বলে?*

+++++++++++++++++++++++++++++++++++++++
===============================================================
-+-+-+-+-+-+-+-+-+-+-+-+-+_+-=-+-+_+-+-=-+-+-=-+-+_=-+-+_=-+-+_=-+-+-=-+-=_=-+-+=+=+
স্বাগতম **"Angular মাস্তানি"** সিরিজের ২২তম পর্বে! 🎁

আমরা এখন **মডিউল ৫: কম্পোনেন্ট কমিউনিকেশন**-এ প্রবেশ করছি। এটা Angular-এর অন্যতম গুরুত্বপূর্ণ পার্ট।
এতদিন আমাদের কম্পোনেন্টগুলো ছিল "দ্বীপের মতো"—কেউ কারোর সাথে কথা বলত না। আজ আমরা তাদের মধ্যে আত্মীয়তার সম্পর্ক তৈরি করব।

আমাদের আজকের টপিক: **Parent to Child Communication**।
সোজা বাংলায়: **বাবা (Parent) কীভাবে সন্তানকে (Child) উপহার বা ডাটা দেবে?**

---

### **১. দৃশ্যপট: ফ্যামিলি ড্রামা 👨‍👦**

ধরুন, আপনার একটা কম্পোনেন্ট আছে `UserCard`।
এর কাজ হলো শুধু নাম আর ছবি দেখানো।
এখন, নামটা কি `UserCard` নিজে ঠিক করবে? না!
**বাবা কম্পোনেন্ট (`AppComponent`)** তাকে বলে দেবে: *"শোনো খোকা, তোমার নাম হলো 'রহিম' আর এই নাও তোমার ছবি।"*

ছেলে (Child) শুধু সেই ডাটা রিসিভ করবে এবং ডিসপ্লে করবে।
এই ডাটা রিসিভ করার জন্য ছেলের যে "হাত" বা "পকেট" দরকার, তাকেই Angular-এর ভাষায় বলে **Input**।

---

### **২. আধুনিক যুগ: Signal Inputs (`input()`) 🚀**

Angular 21-এ আমরা আর পুরোনো আমলের `@Input` ডেকোরেটর ব্যবহার করব না (যদিও সেটা এখনো কাজ করে)। আমরা শিখব লেটেস্ট **Signal Inputs**। এটা অনেক বেশি ফাস্ট এবং স্মার্ট।

চলুন হাতে-কলমে করি!

#### **ধাপ ১: সন্তান তৈরি (Child Component)**
আমরা একটা রিইউজেবল কার্ড বানাব। টার্মিনালে লিখুন:
```bash
ng g c user-card
```

#### **ধাপ ২: সন্তানের হাত পাতা (Receive Data)**
`user-card.component.ts` ফাইলে যান।
এখানে আমরা `input` ফাংশন ব্যবহার করে ডাটা রিসিভ করব।

```typescript
import { Component, input } from '@angular/core'; // ১. input ইমপোর্ট করুন

@Component({
  selector: 'app-user-card',
  standalone: true,
  templateUrl: './user-card.component.html',
  styleUrl: './user-card.component.css'
})
export class UserCardComponent {
  // ২. ইনপুট সিগন্যাল ডিক্লেয়ার করা
  // নাম (অপশনাল, ডিফল্ট ভ্যালু 'Guest')
  userName = input('Guest'); 

  // বয়স (বাধ্যতামূলক বা Required) - এটা না দিলে এরর খাবেন!
  age = input.required<number>(); 
  
  // ছবি (অপশনাল)
  avatar = input('https://i.pravatar.cc/150');
}
```
*   `input('Guest')`: যদি বাবা কিছু না দেয়, তবে 'Guest' দেখাবে।
*   `input.required()`: বাবাকে এটা দিতেই হবে, না দিলে অ্যাপ রান করবে না!

#### **ধাপ ৩: সন্তানের টেমপ্লেট সাজানো (Child HTML)**
`user-card.component.html` এ যান।
যেহেতু এগুলো **Signal**, তাই ভ্যালু পড়ার জন্য `()` দিতে ভুলবেন না।

```html
<div class="card">
  <img [src]="avatar()" alt="User Avatar" width="100">
  
  <h3>নাম: {{ userName() }}</h3>
  <p>বয়স: {{ age() }} বছর</p>
</div>
```
*(একটু CSS দিয়ে কার্ডটাকে সুন্দর করে নিয়েন, যেমন বর্ডার আর প্যাডিং দিয়ে)*

### **৩. বাবার ভূমিকা (Parent Component) 🎅**

এখন `AppComponent` (বাবা) এই কার্ডটি ব্যবহার করবে এবং ডাটা পাঠাবে।

#### **ধাপ ১: সন্তানকে চেনা (Import)**
`app.component.ts` ফাইলে `UserCardComponent` কে ইমপোর্ট করুন।

```typescript
import { Component } from '@angular/core';
import { UserCardComponent } from './user-card/user-card.component'; // ইমপোর্ট

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [UserCardComponent], // লিস্টে নাম তোলা
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  // বাবার কাছে থাকা ডাটা
  users = [
    { name: 'আরিফ', age: 25, img: 'https://i.pravatar.cc/150?img=1' },
    { name: 'লিলি', age: 22, img: 'https://i.pravatar.cc/150?img=5' },
    { name: 'বব', age: 30, img: 'https://i.pravatar.cc/150?img=12' },
  ];
}
```

#### **ধাপ ২: উপহার পাঠানো (Passing Data)**
`app.component.html` ফাইলে যান। আমরা লুপ চালিয়ে ৩টা কার্ড বানাব এবং প্রতিটাকে আলাদা ডাটা দেব।

```html
<h1>টিম মেম্বারস</h1>

<div class="container">
  
  @for (user of users; track $index) {
    <!-- 
      [userName] = চাইল্ডের ইনপুট নাম
      "user.name" = প্যারেন্টের ডাটা 
    -->
    <app-user-card 
      [userName]="user.name" 
      [age]="user.age"
      [avatar]="user.img">
    </app-user-card>

  }

</div>
```

### **৪. আউটপুট ও মজা ✨**

ব্রাউজারে যান।
কি দেখছেন? ৩টা কার্ড, কিন্তু ৩টার নাম, বয়স আর ছবি আলাদা!
আমরা `UserCard` কম্পোনেন্ট বানিয়েছি **একবার**, কিন্তু ব্যবহার করেছি **তিনবার** আলাদা আলাদা ডাটা দিয়ে।

একেই বলে **Reusability**।
বাবা (Parent) ডাটা সাপ্লাই দিয়েছে `[property]` বাইন্ডিংয়ের মাধ্যমে, আর সন্তান (Child) সেটা `input()` দিয়ে রিসিভ করে দেখিয়েছে।

### **৫. Alias বা ডাকনাম (অপশনাল টিপস) 🏷️**

মাঝে মাঝে ইনপুটের নাম অনেক বড় হতে পারে, কিন্তু আপনি HTML এ ছোট নাম ব্যবহার করতে চান।
```typescript
// TS: পুরো নাম
userOfficialPhoneNumber = input('', { alias: 'phone' });
```
```html
<!-- HTML: ডাকনাম -->
<app-user-card [phone]="'01711...'">
```
তবে এটা খুব একটা দরকার পড়ে না, জেনে রাখা ভালো।

### **১. ঘটনাটা কী ঘটবে? (The Scenario) 🎬**

আমাদের `UserCard` (Child) কম্পোনেন্টে একটা **❌ Delete** বাটন থাকবে।
কিন্তু সমস্যা হলো:
1.  ইউজারদের লিস্ট (`users` array) আছে বাবার (`AppComponent`) কাছে।
2.  ছেলে (`UserCard`) চাইলেই নিজেকে নিজে লিস্ট থেকে ডিলিট করতে পারে না (কারণ লিস্ট তার কাছে নেই)।

**সমাধান:**
ছেলে বাটনে ক্লিক করবে 👉 সে একটা ইভেন্ট (নালিশ) পাঠাবে 👉 বাবা সেই ইভেন্ট শুনবে 👉 বাবা তার লিস্ট থেকে ওই ছেলেকে ডিলিট করে দেবে।

### **২. আধুনিক অস্ত্র: `output()` ফাংশন 🔫**

Angular 21-এ আগের `@Output` ডেকোরেটরের দিন শেষ (প্রায়)। এখন আমরা মডার্ন `output()` ফাংশন ব্যবহার করব। এটা `input()` এর মতোই ক্লিন।

#### **ধাপ ১: ছেলের হাতে মাইক দেওয়া (Child Setup)**

`user-card.component.ts` ফাইলে যান।
এখানে আমরা একটা ইভেন্ট জেনারেটর তৈরি করব।

```typescript
import { Component, input, output } from '@angular/core'; // ১. output ইমপোর্ট করুন

@Component({
  ...
})
export class UserCardComponent {
  // আগের ইনপুটগুলো
  userName = input.required<string>();
  
  // ২. আউটপুট বা নালিশ বক্স তৈরি
  // <string> মানে আমরা নালিশের সাথে একটা মেসেজ (নাম) পাঠাব
  onDelete = output<string>(); 

  // ৩. বাটনে চাপ দিলে এই ফাংশন কল হবে
  deleteClicked() {
    // বাবাকে ইভেন্ট পাঠানো (Emit)
    this.onDelete.emit(this.userName()); 
    // মানে: "বাবা, এই নামের ইউজারকে ডিলিট করো!"
  }
}
```

#### **ধাপ ২: ছেলের টেমপ্লেটে বাটন (Child HTML)**

`user-card.component.html` এ একটা লাল বাটন যোগ করুন।

```html
<div class="card">
  <img src="..." alt="avatar">
  <h3>{{ userName() }}</h3>
  
  <!-- ডিলিট বাটন -->
  <button (click)="deleteClicked()" style="background: red; color: white;">
    ❌ মুছে ফেলুন
  </button>
</div>
```

### **৩. বাবার অ্যাকশন (Parent Setup) 👮‍♂️**

এখন বাবা (`AppComponent`) এই ইভেন্ট শুনবে এবং ব্যবস্থা নেবে।

#### **ধাপ ১: বাবাকে ইভেন্ট লিসেনার বানানো (Parent HTML)**

`app.component.html` ফাইলে যান।
মনে আছে?
*   `[]` = বাবা দেয় (Input)
*   `()` = বাবা শোনে (Output)

```html
<div class="container">
  @for (user of users(); track user.name) {
    
    <app-user-card 
      [userName]="user.name"
      [age]="user.age"
      
      (onDelete)="removeUser($event)"> 
      <!-- 
         (onDelete) = ছেলের পাঠানো ইভেন্টের নাম
         removeUser($event) = বাবার ফাংশন, $event মানে ছেলের পাঠানো ডাটা (নাম)
      -->

    </app-user-card>

  }
</div>
```

#### **ধাপ ২: বাবার একশন ফাংশন (Parent TS)**

`app.component.ts` ফাইলে যান। আমাদের ইউজার লিস্টটাকে সিগন্যাল অ্যারে বানিয়ে ফেলি (Angular 21 স্টাইল), তাহলে আপডেট করা সহজ হবে।

```typescript
import { Component, signal } from '@angular/core';
import { UserCardComponent } from './user-card/user-card.component';

@Component({
  ...
})
export class AppComponent {
  // লিস্ট এখন সিগন্যাল
  users = signal([
    { name: 'আরিফ', age: 25 },
    { name: 'লিলি', age: 22 },
    { name: 'বব', age: 30 },
  ]);

  // নালিশ শোনার ফাংশন
  removeUser(nameReceived: string) {
    console.log('নালিশ পেয়েছি! ডিলিট করা হচ্ছে:', nameReceived);

    // লিস্ট আপডেট করা (Filter করে ওই নাম বাদ দেওয়া)
    this.users.update(currentList => 
      currentList.filter(u => u.name !== nameReceived)
    );
  }
}
```

### **৪. আউটপুট ও মজা ✨**

ব্রাউজারে যান।
1.  ৩টা কার্ড দেখতে পাবেন।
2.  "আরিফ" এর কার্ডের **Delete** বাটনে ক্লিক করুন।
3.  সাথে সাথে কার্ডটি গায়েব হয়ে যাবে! 😲

**কী ঘটল পর্দার আড়ালে?**
1.  আপনি বাটনে ক্লিক করলেন (Child)।
2.  Child `emit('আরিফ')` কল করল।
3.  Parent দেখল `(onDelete)` ইভেন্ট ফায়ার হয়েছে।
4.  Parent `removeUser('আরিফ')` ফাংশন চালাল।
5.  সিগন্যাল আপডেট হলো, লিস্ট থেকে আরিফ বাদ পড়ল।

### **৫. `output()` এর সুবিধা কী? 🤔**

আগে আমরা লিখতাম:
`@Output() onDelete = new EventEmitter<string>();`

এখন লিখছি:
`onDelete = output<string>();`

*   **সুবিধা ১:** কোনো `EventEmitter` ইমপোর্ট করতে হয় না।
*   **সুবিধা ২:** টাইপ সেফটি ভালো পাওয়া যায়।
*   **সুবিধা ৩:** কোড কম লিখতে হয়।

---

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **Child to Parent** ডাটা পাঠাতে **Output** ব্যবহার হয়।
2.  Angular 21-এ **`output()`** ফাংশন ব্যবহার করে ইভেন্ট তৈরি করতে হয়।
3.  ইভেন্ট পাঠানোর জন্য **`.emit(data)`** কল করতে হয়।
4.  Parent কম্পোনেন্ট `(eventName)="handlerFunction($event)"` দিয়ে সেই ইভেন্ট ধরে।

### **🎯 আগামী ক্লাসের প্রস্তুতি:**
আমরা ইনপুট (One-way) শিখলাম, আউটপুট (One-way) শিখলাম।
কিন্তু এমন যদি হয়—বাবা ডাটা দেবে, সন্তান সেটা চেঞ্জ করবে, আর সাথে সাথে বাবার কাছেও আপডেট হয়ে যাবে? মানে **দুমুখী রাস্তা**?

একে বলে **Two-way Binding**। Angular 21-এ এর জন্য এসেছে এক জাদুকরী ফিচার **Model Inputs**।
কোড হবে অর্ধেক, কাজ হবে দ্বিগুণ!

**Lesson 24: Model Inputs (Two-way Binding)** - দেখা হবে ম্যাজিক শো-তে! 🎩✨👋

স্বাগতম **"Angular মাস্তানি"** সিরিজের ২৪তম পর্বে! 🎩✨

গত দুই পর্বে আমরা দেখেছি:
১. **Input:** বাবা ডাটা দেয়, সন্তান শুধু তাকিয়ে দেখে (Read-only)।
২. **Output:** সন্তান নালিশ করে, বাবা ডাটা চেঞ্জ করে।

কিন্তু যদি এমন হয়—বাবা আর সন্তান দুজনেই একটা **"জয়েন্ট ব্যাংক অ্যাকাউন্ট"** ব্যবহার করবে?
বাবা টাকা জমালে সন্তানের ব্যালেন্স বাড়বে, আবার সন্তান খরচ করলে বাবার ব্যালেন্স কমবে। মানে ডাটা যে-ই চেঞ্জ করুক, দুই জায়গাতেই আপডেট হবে।

একে বলে **Two-way Data Binding**।
আর Angular 21-এ এই কাজটা পানির মতো সহজ করে দিয়েছে নতুন ফিচার **`model()`**।

---

### **১. `model()` আসলে কী? (The Joint Account) 🤝**

আগে (v17.2 এর আগে) টু-ওয়ে বাইন্ডিং করতে গেলে আমাদের ম্যানুয়ালি একটা Input আর একটা Output বানাতে হতো। কোড হতো দিস্তা দিস্তা।

এখন Angular 21 বলছে:
*"ভাই, `input` আর `output` আলাদা করার দরকার নেই। `model()` ব্যবহার করো। এটা এমন এক সিগন্যাল, যেটা বাবাও চেঞ্জ করতে পারে, ছেলেও পারে।"*

*   **`input()`**: সন্তান ভ্যালু চেঞ্জ করতে পারে না। ❌
*   **`model()`**: সন্তান ভ্যালু চেঞ্জ করতে পারে এবং সেটা বাবাকেও জানিয়ে দেয়। ✅

### **২. প্রজেক্ট: "শপিং কার্ট কোয়ান্টিটি" 🛒**

আমরা একটা `QuantitySelector` কম্পোনেন্ট বানাব।
সেখানে `+` আর `-` বাটন থাকবে। সন্তান (কম্পোনেন্ট) সংখ্যা বাড়াবে, আর বাবা (Main Page) সাথে সাথে টোটাল প্রাইস আপডেট করবে।

#### **ধাপ ১: সন্তান তৈরি (Child Component)**

প্রথমে একটা কম্পোনেন্ট বানাই: `ng g c quantity-selector`
`quantity-selector.component.ts` এ যান।

```typescript
import { Component, model } from '@angular/core'; // ১. model ইমপোর্ট করুন

@Component({
  selector: 'app-quantity-selector',
  standalone: true,
  templateUrl: './quantity-selector.component.html',
  styles: [`
    button { padding: 5px 10px; font-size: 1.2rem; cursor: pointer; }
    span { font-size: 1.5rem; margin: 0 10px; font-weight: bold; }
  `]
})
export class QuantitySelectorComponent {
  // ২. ইনপুট না নিয়ে 'model' নিচ্ছি (শুরুতে ১টা আইটেম)
  quantity = model(1); 

  // ৩. মান বাড়ানোর ফাংশন
  increase() {
    this.quantity.update(q => q + 1);
    // ম্যাজিক: এখানে আপডেট করলেই বাবার কাছে খবর চলে যাবে! কোনো emit লাগবে না।
  }

  // ৪. মান কমানোর ফাংশন
  decrease() {
    this.quantity.update(q => q > 1 ? q - 1 : 1);
  }
}
```

**টেমপ্লেট (Child HTML):**
```html
<div style="border: 2px dashed #555; padding: 10px; display: inline-block;">
  <button (click)="decrease()">➖</button>
  
  <span>{{ quantity() }}</span>
  
  <button (click)="increase()">➕</button>
</div>
```

### **৩. বাবার সাথে কানেকশন (Banana in a Box) 🍌📦**

এখন বাবা (`AppComponent`) এই কম্পোনেন্ট ব্যবহার করবে।
টু-ওয়ে বাইন্ডিং লেখার সিনট্যাক্স হলো **`[()]`**।
*   বক্স `[]` (ইনপুট) + ব্যানানা `()` (আউটপুট) = **Banana in a Box**।

#### **ধাপ ১: বাবার প্রস্তুতি (Parent TS)**

`app.component.ts` এ যান:

```typescript
import { Component, signal, computed } from '@angular/core';
import { QuantitySelectorComponent } from './quantity-selector/quantity-selector.component';

@Component({
  ...
  imports: [QuantitySelectorComponent]
})
export class AppComponent {
  // বাবার কাছে মেইন ডাটা
  itemCount = signal(1); // শুরুতে ১টি
  pricePerItem = 500;    // একটার দাম ৫০০ টাকা

  // টোটাল দাম অটোমেটিক বের হবে (Computed Signal মনে আছে তো?)
  totalPrice = computed(() => this.itemCount() * this.pricePerItem);
}
```

#### **ধাপ ২: কানেকশন দেওয়া (Parent HTML)**

`app.component.html` এ যান:

```html
<div class="card">
  <h2>🛍️ শপিং কার্ট</h2>
  <p>প্রতি পিস: ৫০০ টাকা</p>

  <!-- 
    [(quantity)]="itemCount"
    এর মানে: itemCount এর মান quantity তে যাবে।
    আবার quantity বদলালে itemCount ও বদলে যাবে।
  -->
  <app-quantity-selector [(quantity)]="itemCount"></app-quantity-selector>

  <hr>

  <!-- রেজাল্ট -->
  <h3>আপনি সিলেক্ট করেছেন: {{ itemCount() }} টি</h3>
  <h2 style="color: green;">মোট দাম: {{ totalPrice() }} টাকা</h2>
  
  <!-- বাবার ক্ষমতা পরীক্ষা -->
  <button (click)="itemCount.set(0)">রিসেট (বাবা চেঞ্জ করছে)</button>
</div>
```

### **৪. আউটপুট ও ম্যাজিক ✨**

ব্রাউজারে যান।
1.  **Child Action:** `+` বাটনে ক্লিক করুন। দেখবেন `QuantitySelector` এ সংখ্যা বাড়ছে, আবার নিচে বাবার `totalPrice` ও বাড়ছে।
2.  **Parent Action:** বাবার বানানো "রিসেট" বাটনে ক্লিক করুন। দেখবেন `QuantitySelector` এর মাঝখানের সংখ্যাটাও ০ বা ১ হয়ে গেছে।

মানে **সিঙ্ক (Sync)** একদম ১০০%।
সন্তান বাড়ালে বাবা দেখে, বাবা কমালে সন্তান দেখে।

### **৫. `input` vs `model` - কখন কোনটা? 🤔**

| বৈশিষ্ট্য | `input()` | `model()` |
| :--- | :--- | :--- |
| **ডাটা ফ্লো** | One-way (Parent ➡️ Child) | Two-way (Parent ↔️ Child) |
| **চাইল্ডে পরিবর্তন?** | চাইল্ড ভ্যালু চেঞ্জ করতে পারে না ❌ | চাইল্ড `update/set` করতে পারে ✅ |
| **ব্যবহার** | নাম, ছবি, টাইটেল দেখানোর জন্য | চেকবক্স, ইনপুট ফিল্ড, কাউন্টার, টগল সুইচ |

---

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **`model()`** ব্যবহার করা হয় **Two-way Binding** এর জন্য।
2.  এটি একই সাথে ইনপুট নেয় এবং আউটপুট ইভেন্ট হ্যান্ডেল করে।
3.  চাইল্ড কম্পোনেন্টে `.update()` করলেই প্যারেন্ট সিগন্যাল অটোমেটিক আপডেট হয়।
4.  HTML সিনট্যাক্স হলো **`[(propName)]="signalName"`** (Banana in a Box)।

### **🎯 আগামী ক্লাসের প্রস্তুতি:**
আমরা কম্পোনেন্ট কমিউনিকেশনের প্রায় সব রাস্তা চিনে ফেলেছি।
কিন্তু মাঝে মাঝে আমাদের HTML টেমপ্লেটের ভেতরের কোনো এলিমেন্টকে (যেমন একটা ইনপুট বক্স বা ভিডিও প্লেয়ার) সরাসরি কোড (TS) থেকে কন্ট্রোল করতে হয়।

যেমন: পেজ লোড হলেই ইনপুট বক্সে কার্সর ফোকাস হয়ে থাকবে। বা বাটন টিপলে ভিডিও প্লে হবে।
এর জন্য আমাদের শিখতে হবে **`ViewChild`**। এটা হলো কোডের ভেতর থেকে টেমপ্লেটকে "উঁকি মেরে দেখা"।

যেমন:
*   পেজ লোড হলে ইনপুট বক্সে অটোমেটিক কার্সর (Focus) বসে থাকবে।
*   বাটনে চাপ দিলে ভিডিও প্লে হবে।
*   বাবা (Parent) সরাসরি ছেলের (Child Component) কোনো ফাংশন কল করবে (যেমন: `reset()`)।

এই কাজগুলো করার জন্য আমাদের দরকার **CCTV ক্যামেরা**। Angular-এ এই ক্যামেরার নাম **`viewChild`**। এটি দিয়ে আমরা টেমপ্লেটের ভেতর লুকিয়ে থাকা এলিমেন্টকে কোড (TS) থেকে এক্সেস করতে পারি।

### **১. টেমপ্লেট রেফারেন্স ভেরিয়েবল (`#`) 🏷️**

প্রথমে আমাদের টার্গেট এলিমেন্টকে মার্ক করতে হবে।
HTML-এ কাউকে মার্ক করার জন্য হ্যাশট্যাগ **`#`** ব্যবহার করা হয়। এটাকে বলে **Template Reference Variable** বা "ডাকনাম"।

```html
<!-- ইনপুট বক্সের নাম দিলাম 'searchBox' -->
<input #searchBox type="text" placeholder="খুঁজুন...">
```

এখন এই `#searchBox` কে আমরা TS ফাইল থেকে ধরব।

### **২. আধুনিক উপায়: Signal-based `viewChild` 📡**

Angular 21-এ আমরা পুরানো `@ViewChild` ডেকোরেটর ব্যবহার না করে নতুন **`viewChild`** সিগন্যাল ফাংশন ব্যবহার করব। এটা অনেক বেশি স্মার্ট।

#### **মিশন ১: বাটন টিপলে ইনপুট ফোকাস করা**

আমরা চাই, "Search" বাটনে ক্লিক করলে মাউসের কার্সর অটোমেটিক ইনপুট বক্সে গিয়ে বসে পড়বে।

**Step A: HTML (ডাকনাম দেওয়া)**
`user-profile.component.html` এ যান:

```html
<div class="card">
  <!-- ইনপুট বক্সে নাম দিলাম 'myInput' -->
  <input #myInput type="text" placeholder="এখানে নাম লিখুন...">
  
  <br><br>

  <button (click)="focusInput()">
    🔍 ফোকাস করো
  </button>
</div>
```

**Step B: TS (ক্যামেরা বসানো)**
`user-profile.component.ts` এ যান:

```typescript
import { Component, viewChild, ElementRef } from '@angular/core'; // ১. ইমপোর্ট

@Component({ ... })
export class UserProfileComponent {
  
  // ২. সিগন্যাল দিয়ে এলিমেন্টটাকে ধরলাম
  // <ElementRef> মানে এটা একটা সাধারণ HTML ট্যাগ
  inputEl = viewChild<ElementRef>('myInput'); 

  focusInput() {
    // ৩. সিগন্যাল থেকে এলিমেন্ট বের করা (ব্র্যাকেট দিয়ে কল করতে হয়)
    const el = this.inputEl();

    // ৪. যদি এলিমেন্ট পাওয়া যায়, তবে ফোকাস করো
    if (el) {
      el.nativeElement.focus(); // সরাসরি DOM ম্যানিপুলেশন
      el.nativeElement.style.backgroundColor = 'lightyellow'; // বোনাস: রং চেঞ্জ
    }
  }
}
```

**আউটপুট:**
বাটনে ক্লিক করুন। দেখবেন কার্সর ইনপুট বক্সে লাফাচ্ছে এবং বক্সের রং হলুদ হয়ে গেছে! 🟡

### **৩. মিশন ২: চাইল্ড কম্পোনেন্টের ফাংশন কল করা 📞**

এখন আমরা DOM এলিমেন্ট না, সরাসরি একটা **কম্পোনেন্টকে** ধরব।

ধরুন, আমাদের `CounterComponent` (Child) আছে, যার ভেতরে `resetCounter()` নামে একটা মেথড আছে। বাবা (Parent) চায় বাইরে থেকে ওই মেথড কল করতে।

**Step A: চাইল্ড কম্পোনেন্ট (`CounterComponent`)**
```typescript
@Component({ ... })
export class CounterComponent {
  count = signal(0);

  // এই ফাংশনটা বাবা কল করবে
  resetCounter() {
    this.count.set(0);
    console.log("রিসেট করা হয়েছে!");
  }
}
```

**Step B: প্যারেন্ট HTML**
```html
<!-- চাইল্ডকে বসালাম এবং নাম দিলাম 'childRef' -->
<app-counter #childRef></app-counter>

<button (click)="resetChild()">Reset From Parent</button>
```

**Step C: প্যারেন্ট TS (`viewChild` দিয়ে ধরা)**
```typescript
import { CounterComponent } from './counter/counter.component';

export class ParentComponent {
  // এবার আমরা ElementRef না, সরাসরি কম্পোনেন্ট টাইপ বলে দেব
  childComponent = viewChild<CounterComponent>('childRef');

  resetChild() {
    // চাইল্ডের ফাংশন কল করছি
    this.childComponent()?.resetCounter();
  }
}
```

**ম্যাজিক:** বাবা বাটনে চাপ দিল, আর ছেলের ভেতরের `count` ০ হয়ে গেল! 🤯

### **৪. `viewChild` vs `contentChild` - পার্থক্য কী? 🤔**

নাম শুনলেই বোঝা যায়:
1.  **`viewChild`:** আপনার **নিজের টেমপ্লেটের** (View) ভেতরের জিনিস দেখার জন্য। (যেমন আমরা উপরে করলাম)।
2.  **`contentChild`:** অন্য কেউ যদি আপনার কম্পোনেন্টের পেটের ভেতর কিছু ঢুকিয়ে দেয় (Content Projection), সেটা দেখার জন্য।

**উদাহরণ:**
```html
<!-- Parent ব্যবহার করছে -->
<app-card>
  <h1 #title>আমি বাইরে থেকে এসেছি</h1> <!-- এটা Content -->
</app-card>
```
`AppCard` কম্পোনেন্ট যদি এই `#title` কে ধরতে চায়, তখন তাকে `contentChild` ব্যবহার করতে হবে। কারণ এটা তার নিজের টেমপ্লেটের অংশ না, বাইরে থেকে প্রোজেক্ট হয়ে এসেছে। (এটা নিয়ে বিস্তারিত লেসন ৪৮-এ দেখব)।

---

### **৫. সাবধানতা (Warning) ⚠️**

`viewChild` দিয়ে সরাসরি DOM ম্যানিপুলেশন (যেমন `style.color = 'red'`) করা Angular-এ **Best Practice না**।
*   স্টাইল চেঞ্জ করার জন্য `ngClass` বা `ngStyle` ব্যবহার করা ভালো।
*   `viewChild` ব্যবহার করবেন তখন, যখন ফোকাস করা, স্ক্রল করা বা ভিডিও প্লে করার মতো কাজ দরকার হয়, যা বাইন্ডিং দিয়ে করা যায় না।

---

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **`#variableName`** দিয়ে HTML এলিমেন্টকে ট্যাগ করতে হয়।
2.  Angular 21-এ **`viewChild('name')`** সিগন্যাল ব্যবহার করে সেই এলিমেন্টকে TS ফাইলে ধরা হয়।
3.  **`nativeElement`** দিয়ে সরাসরি HTML ট্যাগ অ্যাক্সেস করা যায়।
4.  এটি দিয়ে চাইল্ড কম্পোনেন্টের ভেতরের মেথডও কল করা যায়।

### **🎯 আগামী ক্লাসের প্রস্তুতি:**
আমাদের **কম্পোনেন্ট মডিউল** শেষ! 🎓
আমরা কম্পোনেন্ট বানানো, সাজানো, কথা বলা (Input/Output/Model/ViewChild)—সব শিখেছি।

কিন্তু একটা বড় অ্যাপে ডাটা কি শুধু কম্পোনেন্টের ভেতর থাকে?
ধরুন, আপনার ইউজার লগইন ইনফরমেশন বা শপিং কার্টের ডাটা ১০টা পেজ মিলে শেয়ার করতে হবে।
কম্পোনেন্ট ধ্বংস হয়ে গেলে তার ডাটাও মুছে যায়। তাহলে ডাটা স্থায়ীভাবে রাখবেন কোথায়?

এর জন্য আমাদের লাগবে **"একজন বিশ্বস্ত ম্যানেজার"**। Angular-এ তার নাম **Service**।
আগামী ক্লাসে আমরা শিখব সার্ভিস এবং ডিপেনডেন্সি ইনজেকশন (DI)।
