
### **মডিউল ৭: রাউটিং (এক পেজ থেকে আরেক পেজে)**
*ওয়েবসাইট তো আর এক পৃষ্ঠার বই না!*
+++++++++++++++++++++++++++++++++++++++
===============================================================
-+-+-+-+-+-+-+-+-+-+-+-+-+_+-=-+-+_+-+-=-+-+-=-+-+_=-+-+_=-+-+_=-+-+-=-+-=_=-+-+=+=+
স্বাগতম **"Angular মাস্তানি"** সিরিজের ২৯তম পর্বে! 🗺️

অভিনন্দন! আমরা **মডিউল ৭: রাউটিং (Routing)** শুরু করছি।
এতদিন আমরা যা বানিয়েছি, সব ছিল এক পেজের মধ্যে (Single Component)। কিন্তু একটা প্রফেশনাল ওয়েবসাইট তো আর এক পৃষ্ঠার রচনা না! সেখানে `Home`, `About`, `Contact`—নানা পেজ থাকে।

কিন্তু দাঁড়ান! **Angular হলো SPA (Single Page Application)**।
এর মানে হলো, টেকনিক্যালি আমাদের পেজ একটাই (`index.html`)। আমরা ব্রাউজারকে বোকা বানিয়ে এক পেজের ভেতর শুধু কন্টেন্ট বদলে দেব, আর ইউজার ভাববে সে নতুন পেজে এসেছে।

এই জাদুর ট্রাফিক পুলিশ হলো **Angular Router**। আজ আমরা রাউটিংয়ের ম্যাপ বা নকশা তৈরি করব।

---

### **১. দৃশ্যপট: আমাদের প্ল্যান 📝**

আমরা ৩টা আলাদা "পেজ" বা ভিউ বানাব:
1.  **Home:** যেখানে ড্যাশবোর্ড থাকবে।
2.  **About:** যেখানে আমাদের ইনফো থাকবে।
3.  **Contact:** যেখানে যোগাযোগের ঠিকানা থাকবে।

ব্রাউজারের এড্রেস বারে যখন `/home` লিখব, হোম আসবে। `/about` লিখলে এবাউট আসবে।

---

### **২. পেজগুলো তৈরি করা (Components) 🛠️**

রাউটিং সেটআপ করার আগে আমাদের গন্তব্যস্থল (Components) রেডি করতে হবে।
আমরা `pages` নামে একটা ফোল্ডারে এগুলো রাখব যাতে ঘর অগোছালো না হয়।

টার্মিনালে লিখুন:
```bash
ng g c pages/home
ng g c pages/about
ng g c pages/contact
```
এখন আমাদের হাতে ৩টা নতুন কম্পোনেন্ট আছে।

---

### **৩. ম্যাপ তৈরি (app.routes.ts) 🗺️**

Angular 21-এ প্রজেক্ট বানালে দেখবেন `src/app` ফোল্ডারে **`app.routes.ts`** নামে একটা ফাইল অটোমেটিক তৈরি হয়ে আছে।
এটাই হলো আমাদের **রাস্তা-ঘাটের মানচিত্র**।

ফাইলটি ওপেন করুন এবং নিচের মতো কনফিগার করুন:

```typescript
import { Routes } from '@angular/router';
// আমাদের কম্পোনেন্টগুলো ইমপোর্ট করতে হবে
import { Home } from './pages/home/home';
import { About } from './pages/about/about';
import { Contact } from './pages/contact/contact';

export const routes: Routes = [
  
  // ১. ডিফল্ট রুট (Default Route)
  // কেউ যদি শুধু localhost:4200 লেখে, তাকে ধাক্কা দিয়ে 'home'-এ পাঠাব
  { path: '', redirectTo: 'home', pathMatch: 'full' },

  // ২. সাধারণ রুট (Normal Routes)
  { path: 'home', component: Home },
  { path: 'about', component: About },
  { path: 'contact', component: Contact },

  // ৩. ওয়াইল্ডকার্ড রুট (Wildcard Route) - 404 Not Found
  // কেউ যদি উল্টাপাল্টা লিংক লেখে (যেমন: /biriyani), তাকে হোম পেজে পাঠাব
  // (বা চাইলে আলাদা 404 পেজও দেখাতে পারেন)
  { path: '**', redirectTo: 'home' }
];
```

**ব্যাখ্যা:**
*   **`path`**: ব্রাউজারের লিংকে কী লেখা থাকবে (যেমন: `about`)। স্ল্যাশ `/` দেওয়ার দরকার নেই।
*   **`component`**: ওই লিংকে গেলে কোন কম্পোনেন্ট দেখাবে।
*   **`redirectTo`**: এক রাস্তা থেকে আরেক রাস্তায় পাঠিয়ে দেওয়া।
*   **`**`**: এর মানে "বাকি সব রাস্তা"। এটা সবার শেষে রাখতে হয়।

---

### **৪. কানেকশন চেক (app.config.ts) 🔌**

ম্যাপ তো বানালাম, কিন্তু অ্যাপ কি জানে এই ম্যাপের কথা?
Angular 21 (Standalone) এ `app.config.ts` ফাইলে রাউটার প্রোভাইড করা থাকে। একটু চেক করে নিন।

`src/app/app.config.ts` ফাইলটি খুলুন:

```typescript
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router'; // <--- এটা আছে তো?

import { routes } from './app.routes'; // আমাদের ম্যাপ ফাইল

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes) // <--- ম্যাপটা ড্রাইভারের হাতে ধরিয়ে দেওয়া হলো
  ]
};
```
সাধারণত এটা `ng new` করার সময়ই সেট হয়ে থাকে। তাই হাত দেওয়ার দরকার পড়ে না।

---

### **৫. এখনই কি কাজ করবে? 🤔**

আপনি যদি ব্রাউজারে গিয়ে `http://localhost:4200/about` লেখেন...
কিছুই হবে না! বা আগের পেজটাই দেখাবে।

**কেন?**
কারণ আমরা ম্যাপ বানিয়েছি, কিন্তু ম্যাপ অনুযায়ী **টিভি স্ক্রিন (Display Area)** সেট করিনি।
Angular কনফিউজড— *"ভাই, আমি `AboutComponent` লোড করব বুঝলাম, কিন্তু সেটা দেখাব কোথায়? হেডার এর নিচে? নাকি ফুটারের নিচে?"*

এই "জায়গা" ঠিক করার জন্য আমাদের লাগবে **`<router-outlet>`**। এটা আমরা আগামী ক্লাসে সেট করব।

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **Routing** দিয়ে আমরা পেজ চেঞ্জ করি (URL চেঞ্জ হয়)।
2.  **`app.routes.ts`** ফাইলে আমরা বলে দিই কোন পথে (`path`) গেলে কোন কম্পোনেন্ট (`component`) লোড হবে।
3.  **`redirectTo`** দিয়ে ডিফল্ট পেজ সেট করা হয়।
4.  **`**`** (Wildcard) দিয়ে ভুল লিংকের সমাধান করা হয়।

### **🎯 আগামী ক্লাসের প্রস্তুতি:**
ম্যাপ রেডি। গন্তব্য রেডি।
আগামী ক্লাসে আমরা অ্যাপের মেইন HTML ফাইলে একটা **"ম্যাজিক ফ্রেম"** বসাব, যেখানে পেজগুলো লোড হবে। এবং মেনু বারে লিংক সেট করব যাতে ক্লিক করলেই পেজ বদলে যায়।

স্বাগতম **"Angular মাস্তানি"** সিরিজের ৩০তম পর্বে! 🚌

গত ক্লাসে আমরা **রাউটিং ম্যাপ** (`app.routes.ts`) বানিয়েছি। মানে কোন রাস্তায় গেলে কোন এলাকা পাওয়া যাবে, তা ঠিক করেছি।
কিন্তু সমস্যা হলো, আমরা এখনো গাড়িতে স্টার্ট দিইনি। আপনি যদি ব্রাউজারে লিংক টাইপ করেন, হয়তো পেজ লোড হচ্ছে না।

আজ আমরা দুটি জাদুকরী জিনিস শিখব:
১. **`RouterOutlet`**: যেখানে পেজগুলো লোড হবে (আমাদের টিভি স্ক্রিন)।
২. **`RouterLink`**: বাটন বা মেনু, যা টিপলে পেজ বদলাবে (কোনো রিফ্রেশ ছাড়া)।

### **১. `RouterOutlet` (ম্যাজিক ফ্রেম) 🖼️**

Angular যেহেতু **SPA (Single Page Application)**, তাই এর হেডার (Header) আর ফুটার (Footer) সাধারণত ফিক্সড থাকে। পাল্টায় শুধু মাঝখানের অংশটুকু।
এই "মাঝখানের অংশ" কোথায় বসবে, সেটা Angular-কে বলে দিতে হয়।

#### **ধাপ ১: ইমপোর্ট করা (Import)**
`app.component.ts` ফাইলে যান। যেহেতু এটা Standalone কম্পোনেন্ট, তাই রাউটিং ফিচারগুলো ইমপোর্ট করতে হবে।

```typescript
import { Component } from '@angular/core';
import { RouterOutlet, RouterLink, RouterLinkActive } from '@angular/router'; // ১. ইমপোর্ট করুন

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, RouterLink, RouterLinkActive], // ২. লিস্টে নাম তুলুন
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent { ... }
```

#### **ধাপ ২: প্লেসমেন্ট (Placement)**
`app.component.html` ফাইলে যান। আগের সব কোড মুছে (বা সাজিয়ে) নিচের মতো লিখুন:

```html
<!-- ফিক্সড হেডার বা মেনু -->
<nav class="navbar">
  <h1>আমার অ্যাপ</h1>
  <ul>
    <!-- মেনু আইটেমগুলো এখানে আসবে -->
  </ul>
</nav>

<!-- আসল ম্যাজিক! পেজগুলো এখানে লোড হবে -->
<div class="content-box">
  <router-outlet></router-outlet> 
</div>

<!-- ফিক্সড ফুটার -->
<footer>
  <p>© ২০২৫ Angular মাস্তানি সিরিজ</p>
</footer>
```

**`@Note:`** `<router-outlet>` ট্যাগটা যেখানে দেবেন, ঠিক সেখানেই আপনার `Home`, `About` বা `Contact` কম্পোনেন্টগুলো লোড হবে।

### **২. `RouterLink` (রিফ্রেশ ছাড়া ভ্রমণ) 🚀**

সাধারণ HTML-এ আমরা এক পেজ থেকে অন্য পেজে যেতে `<a href="/about">` ব্যবহার করি।
কিন্তু এটা করলে কী হয়?
পুরো পেজটা **সাদা হয়ে যায় (White Flash)** এবং ব্রাউজার **রিফ্রেশ** নেয়। এতে অ্যাপ স্লো হয়ে যায় এবং SPA-র মজাই নষ্ট হয়ে যায়।

Angular-এ আমরা ব্যবহার করি **`routerLink`**।

#### **মেনু তৈরি করা**
`app.component.html` এর `<nav>` অংশের ভেতরে কোড লিখুন:

```html
<ul>
  <!-- ভুল পদ্ধতি (HTML Style) ❌ -->
  <!-- <li><a href="/home">Home (Bad)</a></li> -->

  <!-- সঠিক পদ্ধতি (Angular Style) ✅ -->
  <li>
    <a routerLink="/home" routerLinkActive="active-link">হোম</a>
  </li>
  
  <li>
    <a routerLink="/about" routerLinkActive="active-link">আমাদের কথা</a>
  </li>
  
  <li>
    <a routerLink="/contact" routerLinkActive="active-link">যোগাযোগ</a>
  </li>
</ul>
```

---

### **৩. `routerLinkActive` (আমি কোথায় আছি?) 📍**

UX ডিজাইনার হিসেবে এটা খুব জরুরি। ইউজারকে বোঝাতে হবে সে এখন কোন পেজে আছে।
`routerLinkActive="class-name"` ব্যবহার করলে, আপনি যে লিংকে থাকবেন, Angular অটোমেটিক সেই লিংকে ওই CSS ক্লাসটা বসিয়ে দেবে।

চলুন একটু স্টাইল দিই (`app.component.css`):

```css
.navbar {
  background: #333;
  color: white;
  padding: 1rem;
  display: flex;
  justify-content: space-between;
}

ul {
  list-style: none;
  display: flex;
  gap: 15px;
}

a {
  color: white;
  text-decoration: none;
  font-weight: bold;
  padding: 5px 10px;
  border-radius: 5px;
}

/* যখন লিংক অ্যাক্টিভ থাকবে, তখন এই স্টাইল পাবে */
.active-link {
  background-color: #ff9800; /* কমলা রং */
  color: black;
}
```

### **৪. আউটপুট ও টেস্ট 🧪**

ব্রাউজারে যান (`localhost:4200`)।

1.  **Home** লিংকে ক্লিক করুন।
    *   URL চেঞ্জ হয়ে `/home` হবে।
    *   নিচে হোম পেজের কন্টেন্ট আসবে।
    *   মেনু বারে "হোম" লেখাটা **কমলা** রঙের হয়ে যাবে।
    *   **সবচেয়ে বড় কথা:** পেজ রিফ্রেশ হবে না! চোখের পলকে কন্টেন্ট চেঞ্জ হবে।

2.  **Contact** লিংকে ক্লিক করুন।
    *   সাথে সাথে কন্টাক্ট পেজ আসবে।
    *   এখন "যোগাযোগ" লেখাটা কমলা হয়ে যাবে।

### **৫. এক নজরে পার্থক্য**

| সাধারণ HTML | Angular Router |
| :--- | :--- |
| `href="/about"` | `routerLink="/about"` |
| পেজ রিলোড হয় (ফ্ল্যাশ মারে) 🐌 | রিলোড হয় না (স্মুথ) ⚡ |
| স্টেট হারিয়ে যায় | মেমোরি ঠিক থাকে |
| UX খারাপ | UX মাখনের মতো |

---

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **`<router-outlet>`**: এটি একটি প্লেসহোল্ডার বা টিভি স্ক্রিন, যেখানে রাউটার কম্পোনেন্ট লোড করে।
2.  **`routerLink`**: এটি পেজ রিফ্রেশ না করে URL চেঞ্জ করে এবং নেভিগেট করে।
3.  **`routerLinkActive`**: বর্তমান পেজ অনুযায়ী মেনুতে স্টাইল বা ক্লাস অ্যাড করে।
4.  এই সব ফিচার ব্যবহার করতে `AppComponent` বা প্যারেন্ট কম্পোনেন্টের `imports` এ `RouterOutlet`, `RouterLink` যোগ করতে হয়।

অবশ্যই না! আমরা একটা পেজ বানাব, আর URL-এর ওই পেছনের নম্বরটা (ID) ধরে ডাটা দেখাব।

আজ আমরা হবো **প্রাইভেট ডিটেকটিভ**।
ফেসবুকের কথা ভাবুন। সবার প্রোফাইল পেজ দেখতে কিন্তু একই রকম (একটা কাভার ফটো, একটা গোল প্রোফাইল পিক, নিচে পোস্ট)।
কিন্তু `facebook.com/shakib75` এ গেলে সাকিবের ডাটা আসে, আর `facebook.com/tamim28` এ গেলে তামিমের ডাটা আসে।

ফেসবুক কি কোটি কোটি ইউজারের জন্য কোটি কোটি পেজ বানিয়েছে? 😱
অবশ্যই না! পেজ একটাই, শুধু URL-এর শেষের নাম বা আইডি ধরে ডাটা লোড হয়।

একে বলে **Dynamic Routing**। আজ আমরা শিখব কীভাবে `:id` বা প্যারামিটার দিয়ে ডাইনামিক পেজ বানাতে হয়।

### **১. ম্যাপে পরিবর্তন (Route Setup) 🗺️**

প্রথমে আমাদের রাউটারকে বলতে হবে যে, লিংকের শেষে একটা পরিবর্তনশীল অংশ (Variable) থাকবে।

ধরি, আমরা একটা `UserDetail` পেজ বানাব।
টার্মিনালে লিখুন: `ng g c pages/user-detail`

এবার `app.routes.ts` ফাইলে যান এবং নতুন রুট যোগ করুন:

```typescript
import { UserDetailComponent } from './pages/user-detail/user-detail.component';

export const routes: Routes = [
  // আগের রুটগুলো...
  
  // ডাইনামিক রুট
  { path: 'user/:id', component: UserDetailComponent },
];
```

**খেয়াল করুন:** `user/` এর পর কোলন **`:`** দিয়ে `id` লিখেছি।
এই `:` মানে হলো— *"এখানে যা ইচ্ছা বসতে পারে (1, 50, abcd), সেটাকে আমি `id` নামে চিনে নেব।"*

### **২. কনফিগারেশন আপডেট (সবচেয়ে জরুরি!) ⚙️**

Angular 21-এ URL-এর আইডি সরাসরি কম্পোনেন্টের `input` হিসেবে পাওয়ার জন্য একটা ছোট্ট সেটিং অন করতে হয়।

`app.config.ts` ফাইলে যান:

```typescript
import { provideRouter, withComponentInputBinding } from '@angular/router'; // ১. এটা ইমপোর্ট করুন

export const appConfig: ApplicationConfig = {
  providers: [
    // ২. withComponentInputBinding() ফাংশনটা রুটের ভেতর ঢুকিয়ে দিন
    provideRouter(routes, withComponentInputBinding()) 
  ]
};
```
*এটা না করলে কিন্তু ইনপুট কাজ করবে না!*

### **৩. আইডি ধরা (Component Setup) 🎣**

এখন `user-detail.component.ts` ফাইলে যান।
আমরা URL থেকে আইডিটা ধরব। আগে `ActivatedRoute` দিয়ে অনেক কোড লিখতে হতো। এখন `input` সিগন্যাল দিয়েই কাজ শেষ!

```typescript
import { Component, input, OnInit, inject } from '@angular/core';
import { UserService } from '../../services/user.service'; // ধরুন আমাদের সার্ভিস আছে

@Component({
  selector: 'app-user-detail',
  standalone: true,
  template: `
    <div class="card">
      <h2>ইউজার ডিটেইলস</h2>
      
      <p>আইডি নম্বর: <strong>{{ id() }}</strong></p>
      
      <!-- বাস্তবে আমরা এই আইডি দিয়ে সার্ভার থেকে ডাটা আনতাম -->
      <p>স্ট্যাটাস: ডাটা খোঁজা হচ্ছে...</p>
      
      <a routerLink="/home">🔙 ব্যাকে যান</a>
    </div>
  `,
  styles: ['.card { padding: 20px; border: 1px solid #ccc; }']
})
export class UserDetailComponent implements OnInit {
  
  // ১. ইনপুট হিসেবে আইডি ধরছি (নাম হুবহু রুটের :id এর মতো হতে হবে)
  id = input.required<string>();

  ngOnInit() {
    // ২. কনসোলে চেক করুন আইডি পেলেন কিনা
    console.log("URL থেকে আইডি পেয়েছি:", this.id());
    
    // এখানে আপনি সার্ভিসের মেথড কল করতে পারেন
    // this.userService.getUserById(this.id());
  }
}
```

### **৪. লিংক তৈরি করা (RouterLink with Params) 🔗**

এখন হোম পেজ বা লিস্ট পেজ থেকে এই ডিটেইল পেজে যাওয়ার লিংক বানাতে হবে।

`home.component.html` (বা যেখানে আপনার লিস্ট আছে):

```html
<h2>ইউজার লিস্ট</h2>

<ul>
  <!-- সাধারণ লিংক -->
  <li><a routerLink="/user/1">ইউজার ১ (ফিক্সড)</a></li>
  <li><a routerLink="/user/500">ইউজার ৫০০ (ফিক্সড)</a></li>

  <!-- ডাইনামিক লিংক (লুপের ভেতর) -->
  @for (u of users; track u.id) {
    <li>
      <!-- [routerLink] এ অ্যারে পাস করতে হয় -->
      <!-- প্রথম অংশ: মেইন রুট ('/user') -->
      <!-- দ্বিতীয় অংশ: ডাইনামিক আইডি (u.id) -->
      
      <a [routerLink]="['/user', u.id]">
        {{ u.name }} এর প্রোফাইল দেখুন
      </a>
    </li>
  }
</ul>
```

**[routerLink] অ্যারে কেন?**
`['/user', u.id]`
Angular এটাকে জোড়া লাগিয়ে বানাবে: `/user/101` (যদি id 101 হয়)।

### **৫. আউটপুট ও টেস্ট 🧪**

ব্রাউজারে যান।
১. `ইউজার ১` এ ক্লিক করুন।

একই কম্পোনেন্ট, কিন্তু আইডি অনুযায়ী কন্টেন্ট (আইডি) আলাদা দেখাচ্ছে। এখন আপনি চাইলে এই আইডি ব্যবহার করে সার্ভিসে কল করে ওই ইউজারের নাম, ধাম, ছবি সব নিয়ে আসতে পারেন।

এর সমাধান হলো **Lazy Loading**। মানে—"যখন দরকার, তখন লোড করো। এর আগে না।"

### **১. Eager vs Lazy (পার্থক্যটা কী?) ⚖️**

*   **Eager Loading (স্বাভাবিক):** অ্যাপ চালুর সাথে সাথে সব কম্পোনেন্টের কোড ডাউনলোড হয়ে যায়। (ছোট অ্যাপের জন্য ঠিক আছে, বড় অ্যাপের জন্য বিপদ)।
*   **Lazy Loading (অলস):** অ্যাপ চালু হলে শুধু হোম পেজ লোড হবে। ইউজার যখন "Settings" লিংকে ক্লিক করবে, **ঠিক তখনই** ইন্টারনেট থেকে সেটিং পেজের কোড নামবে।

Angular 21-এ (Standalone Component দিয়ে) এটা করা পানির মতো সহজ।

### **২. কোড পরিবর্তন (app.routes.ts) 🛠️**

ধরুন, আমাদের একটা ভারী পেজ আছে নাম **`AdminComponent`**। আমরা এটাকে লেজি লোড করব।

`app.routes.ts` ফাইলটি খুলুন।

#### **আগের নিয়ম (Eager Loading - যা করবেন না)**
```typescript
// ❌ সবার উপরে ইমপোর্ট করা থাকে
import { AdminComponent } from './pages/admin/admin.component';

export const routes: Routes = [
  // কম্পোনেন্ট সরাসরি দেওয়া
  { path: 'admin', component: AdminComponent } 
];
```
*সমস্যা:* ফাইলটা উপরে ইমপোর্ট করা মানেই অ্যাপ লোড হওয়ার সময় এটাও লোড হবে।

#### **নতুন নিয়ম (Lazy Loading - যা করবেন) ✅**
```typescript
import { Routes } from '@angular/router';
// ⚠️ উপরে কোনো AdminComponent ইমপোর্ট থাকবে না!

export const routes: Routes = [
  { 
    path: 'admin', 
    // ম্যাজিক ফাংশন
    loadComponent: () => import('./pages/admin/admin.component')
      .then(m => m.AdminComponent) 
  }
];
```

**ব্যাখ্যা:**
*   **`loadComponent`**: এটা বলে, "এখনই লোড করো না।"
*   **`import(...)`**: যখন ইউজার এই পাথে আসবে, তখন ফাইলটা ইমপোর্ট করবে।
*   **`.then(...)`**: ফাইল আনার পর কম্পোনেন্টটা বের করে দেখাবে।

৬. এবার মেনু থেকে **Admin** লিংকে ক্লিক করুন।
    *   👀 তাকিয়ে দেখুন! নিচ দিয়ে নতুন একটা ফাইল ডাউনলোড হলো (যেমন: `src_app_pages_admin...js`)।

এটাই প্রমাণ! আপনার অ্যাপ শুরুতে হালকা ছিল, ক্লিক করার পর ভারী ফাইলটা নামল।

### **৪. কেন এটা মাস্ট? (Benefits) 🚀**

1.  **Fast Initial Load:** অ্যাপ ওপেন হতে সময় কম লাগে।
2.  **Data Saving:** ইউজার যদি "Admin" পেজে নাই যায়, তার মেগাবাইট খরচ করে ওই কোড নামানোর দরকার কী?
3.  **Browser Happy:** ব্রাউজারের মেমোরি কম খরচ হয়।

### **৫. ডিফল্ট এক্সপোর্ট শর্টকাট (Pro Tip) 😎**

যদি আপনি কম্পোনেন্ট ফাইলে `export default class AdminComponent` লেখেন (ক্লাসের আগে `default` কিওয়ার্ড), তাহলে রাউটিংয়ে কোড আরও ছোট হয়ে যায়।

**Admin Component:**
```typescript
@Component({...})
export default class AdminComponent {} // default লাগালাম
```

**Routes:**
```typescript
{ 
  path: 'admin', 
  loadComponent: () => import('./pages/admin/admin.component') 
  // .then(...) আর লেখা লাগে না!
}
```

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **Lazy Loading** অ্যাপের লোডিং স্পিড বাড়ায়।
2.  `app.routes.ts`-এ `component:` এর বদলে **`loadComponent:`** ব্যবহার করতে হয়।
3.  উপরে ফাইল ইমপোর্ট করা যাবে না।
4.  Network ট্যাবে চেক করলে দেখা যায় ফাইলটা পরে লোড হচ্ছে (Chunk file)।

### **১. গার্ড তৈরির নিয়ম (The Guard Function) 🛡️**

আগে ক্লাস-বেসড গার্ড লাগত, এখন শুধু একটা সিম্পল ফাংশন দিয়েই কাজ হয়।

আমরা একটা ফাইল বানাব `auth.guard.ts` নামে (সাধারণত `guards` ফোল্ডারে)।
টার্মিনালে লিখুন:
```bash
ng g g guards/auth
```
*(CLI জিজ্ঞেস করবে কোন টাইপ? `CanActivate` সিলেক্ট করুন)*

অথবা ম্যানুয়ালি `src/app/guards/auth.guard.ts` ফাইল বানিয়ে নিচের কোড লিখুন:

```typescript
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { UserService } from '../services/user.service'; // আমাদের সেই পুরানো সার্ভিস

// এটা আমাদের দারোয়ান ফাংশন
export const authGuard: CanActivateFn = (route, state) => {
  
  // ১. দারোয়ানের হাতে টুলস দিচ্ছি
  const userService = inject(UserService); // লগইন চেক করার জন্য
  const router = inject(Router);           // ঘাড় ধাক্কা দেওয়ার জন্য

  // ২. চেকিং পর্ব
  if (userService.isLoggedIn()) {
    return true; // ✅ সব ঠিক আছে, ভেতরে যান।
  } else {
    alert('⛔ দাঁড়ান! আগে লগইন করুন।');
    router.navigate(['/login']); // ❌ ঘাড় ধাক্কা দিয়ে লগইন পেজে পাঠানো
    return false; // ভেতরে ঢুকতে দেওয়া হবে না
  }
};
```

*(বিঃদ্রঃ `UserService`-এ `isLoggedIn` নামে একটা সিগন্যাল বা মেথড থাকতে হবে যা true/false রিটার্ন করে। আমরা ধরে নিচ্ছি সেটা আছে।)*

---

### **২. রুটে গার্ড বসানো (Deploying the Guard) 🚧**

দারোয়ান তো রেডি, এখন তাকে গেটে দাঁড় করাতে হবে।
`app.routes.ts` ফাইলে যান।

```typescript
import { authGuard } from './guards/auth.guard'; // গার্ড ইমপোর্ট

export const routes: Routes = [
  { path: 'home', component: HomeComponent },
  
  // এই পেজে সবাই ঢুকতে পারবে না
  { 
    path: 'admin', 
    loadComponent: () => import('./pages/admin/admin.component'),
    
    // 🚧 দারোয়ান বসালাম
    canActivate: [authGuard] 
  },
  
  { path: 'login', component: LoginComponent }
];
```

**`canActivate: [authGuard]`** — এই লাইনটাই আসল। আপনি চাইলে কমা দিয়ে একাধিক গার্ড বসাতে পারেন (যেমন: একবার লগইন চেক, তারপর রোল চেক)।

---

### **৩. টেস্টিং পরিবেশ তৈরি (Mocking Login) 🧪**

এটা টেস্ট করার জন্য আমাদের `UserService`-এ একটা নকল লগইন সিস্টেম বানাতে হবে।

`user.service.ts`:
```typescript
@Injectable({ providedIn: 'root' })
export class UserService {
  // শুরুতে ইউজার লগআউট অবস্থায় আছে
  isLoggedInSignal = signal(false);

  // চেক করার ফাংশন
  isLoggedIn() {
    return this.isLoggedInSignal();
  }

  // লগইন করার ফাংশন
  login() {
    this.isLoggedInSignal.set(true);
  }

  // লগআউট করার ফাংশন
  logout() {
    this.isLoggedInSignal.set(false);
  }
}
```

### **৪. বাস্তবে প্রয়োগ (Real Action) 🎬**

এখন `app.component.html`-এ একটা লগইন বাটন রাখি টেস্ট করার জন্য।

```html
<nav>
  <a routerLink="/home">হোম</a> | 
  <a routerLink="/admin">অ্যাডমিন (রেস্ট্রিক্টেড)</a>
</nav>

<hr>

<p>স্ট্যাটাস: {{ userService.isLoggedIn() ? 'লগইন করা ✅' : 'লগআউট ❌' }}</p>

<button (click)="userService.login()">লগইন করুন</button>
<button (click)="userService.logout()">লগআউট করুন</button>

<router-outlet></router-outlet>
```

**টেস্ট ধাপ:**
1.  **লগআউট থাকা অবস্থায়:** "অ্যাডমিন" লিংকে ক্লিক করুন।
    *   অ্যালার্ট আসবে "দাঁড়ান! আগে লগইন করুন"।
    *   পেজ অ্যাডমিনে যাবে না, লগইন পেজে (বা হোমে) আটকে থাকবে।
2.  **"লগইন করুন" বাটনে চাপ দিন।** (স্ট্যাটাস সত্য হলো)।
3.  **এবার "অ্যাডমিন" লিংকে ক্লিক করুন।**
    *   ম্যাজিক! এবার আপনাকে ভেতরে ঢুকতে দেবে।

### **৫. আরো কিছু গার্ড (Types of Guards) 👮‍♀️**

শুধু `CanActivate` নয়, আরো কিছু গার্ড আছে:

1.  **`CanActivateChild`**: প্যারেন্ট রুটে ঢুকতে দিয়েছে, কিন্তু চাইল্ড রুটে দেবে কিনা?
2.  **`CanDeactivate`**: পেজ ছেড়ে বের হওয়ার সময় আটকানো।
    *   *উদাহরণ:* ইউজার ফর্ম ফিলাপ করছিল, হুট করে ব্যাক বাটন চাপল। তখন গার্ড বলবে: *"আপনি কি নিশ্চিত? ডাটা কিন্তু সেভ হয়নি!"*
3.  **`CanMatch`**: এটা লেজি লোডিং ফাইল নামানোর আগেই চেক করে। (এটা `CanActivate` এর চেয়ে বেশি স্মার্ট এবং ফাস্ট)।

### **📝 আজকের সারসংক্ষেপ (Recap):**

1.  **Route Guards** নির্দিষ্ট রুটে এক্সেস কন্ট্রোল করে।
2.  Angular 21-এ **Functional Guard** (`CanActivateFn`) ব্যবহার করা হয়।
3.  গার্ড `true` রিটার্ন করলে ঢোকা যায়, `false` রিটার্ন করলে আটকে দেয়।
4.  `app.routes.ts`-এ `canActivate: [guardName]` দিয়ে এটা সেট করতে হয়।
