

### মূল ধারণা (Core Concept)

ভাবুন, একটি অ্যাঙ্গুলার কম্পোনেন্ট (Component) হলো একজন ছাত্রের মতো। একজন ছাত্র যেমন স্কুলে ভর্তি হওয়া থেকে শুরু করে পড়াশোনা করে পাশ করে বেরিয়ে যায়, তার জীবনে কয়েকটি নির্দিষ্ট ধাপ বা পর্যায় থাকে। ঠিক তেমনি, একটি অ্যাঙ্গুলার কম্পোনেন্ট তৈরি হওয়া (creation) থেকে শুরু করে ওয়েবসাইট থেকে মুছে যাওয়া (destruction) পর্যন্ত কয়েকটি নির্দিষ্ট ধাপের মধ্যে দিয়ে যায়।

এই ধাপগুলোকেই **অ্যাঙ্গুলার লাইফসাইকেল হুক (Angular Lifecycle Hook)** বলা হয়। এগুলো হলো বিশেষ কিছু মেথড (method) যা অ্যাঙ্গুলার নিজে থেকেই সঠিক সময়ে কল বা চালু করে দেয়। আমরা এই মেথডগুলোর ভেতরে আমাদের প্রয়োজনীয় কোড লিখতে পারি।

### ছাত্রের জীবনচক্র (Student's Lifecycle) vs কম্পোনেন্টের জীবনচক্র (Component's Lifecycle)

আসুন, ছাত্রের জীবনের প্রতিটি ধাপের সাথে অ্যাঙ্গুলারের লাইফসাইকেল হুকগুলো মিলিয়ে দেখি।

#### আমাদের উদাহরণ: `StudentProfileComponent`
ধরে নিচ্ছি, আমাদের একটি কম্পোনেন্ট আছে যার নাম `student-profile.component.ts`। এই কম্পোনেন্টটি একজন ছাত্রের নাম ও ক্লাস দেখাবে।

---

**১. `constructor` (কনস্ট্রাক্টর)**

*   **ছাত্রের জীবনে:** এটা হলো স্কুলে ভর্তির জন্য আবেদনপত্র জমা দেওয়ার মতো। ছাত্রের একটি ফাইল তৈরি হলো, কিন্তু তাকে এখনও কোনো ক্লাস বা রোল নম্বর দেওয়া হয়নি। শুধু প্রাথমিক প্রস্তুতি নেওয়া হচ্ছে।
*   **অ্যাঙ্গুলারে:** কম্পোনেন্ট তৈরি হওয়ার সর্বপ্রথম ধাপ। এই ধাপে মূলত Dependency Injection (অন্যান্য সার্ভিস যোগ করা) এর কাজ করা হয়। এখানে `@Input` ডেটা পাওয়া যায় না।

---

**২. `ngOnChanges`**

*   **ছাত্রের জীবনে:** স্কুল কর্তৃপক্ষ ছাত্রের ফাইলে তার নাম এবং ক্লাস (`name: 'Rahim'`, `class: 5`) যোগ করলো। এরপর যখন ছাত্রটি নতুন ক্লাসে উঠবে (`class: 6`), তখনও এই তথ্য আপডেট করা হবে। অর্থাৎ, যখনই ছাত্রের কোনো **প্রাথমিক তথ্য পরিবর্তন** হবে, তখনই এই ধাপটি আসবে।
*   **অ্যাঙ্গুলারে:** যখনই কোনো `@Input()` property-র মান পরিবর্তন হয়, তখন এই মেথডটি কল হয়। কম্পোনেন্ট চালু হওয়ার সময় প্রথমবার এবং এরপর যতবার `@Input` ডেটা বদলাবে, ততবার এটি কল হবে।

---

**৩. `ngOnInit` (ng-On-Init)**

*   **ছাত্রের জীবনে:** ছাত্রের **স্কুলে প্রথম দিন**! সে তার নাম, ক্লাস সব জানে। এখন তার প্রথম কাজ হলো বইপত্র নেওয়া, নিজের ক্লাসরুম খুঁজে বের করা, বা কোনো দরকারি জিনিসপত্র গুছিয়ে নেওয়া। অর্থাৎ, প্রাথমিক সেটআপের পর প্রথম গুরুত্বপূর্ণ কাজগুলো করা।
*   **অ্যাঙ্গুলারে:** `ngOnChanges` প্রথমবার কল হওয়ার পর এটি মাত্র **একবারই** কল হয়। কম্পোনেন্টের প্রাথমিক ডেটা লোড করার জন্য (যেমন: API থেকে ডেটা আনা) এটি সবচেয়ে উপযুক্ত জায়গা।

---

**৪. `ngDoCheck`**

*   **ছাত্রের জীবনে:** ক্লাসের শিক্ষক শুধু আনুষ্ঠানিক ঘোষণার (যেমন ক্লাস পরিবর্তন) জন্য অপেক্ষা করেন না, তিনি **ক্রমাগত ছাত্রছাত্রীদের পর্যবেক্ষণ** করেন। যেমন: কেউ মনোযোগ দিচ্ছে কিনা, কেউ হোমওয়ার্ক করেছে কিনা ইত্যাদি। এটা একটা নিয়মিত এবং সূক্ষ্ম চেকিং।
*   **অ্যাঙ্গুলারে:** অ্যাঙ্গুলার যখনই কোনো পরিবর্তন শনাক্ত করার চেষ্টা করে (Change Detection), তখনই এই মেথডটি কল হয়। এটি খুব ঘন ঘন কল হয়। যদি এমন কোনো পরিবর্তন ট্র্যাক করতে হয় যা অ্যাঙ্গুলার নিজে থেকে ধরতে পারে না, তখন এটি ব্যবহার করা হয়।

---

**৫. `ngAfterContentInit`**

*   **ছাত্রের জীবনে:** ধরুন, `StudentProfileComponent` এর ভেতরে বাইরে থেকে আরেকজন "বন্ধু" (অন্য কম্পোনেন্ট) এসে বসলো। যেমন, ছাত্রের প্রোফাইলের পাশে তার "বেস্ট ফ্রেন্ডের" তথ্য দেখানো হচ্ছে। যখন ছাত্রটি প্রথমবার তার পাশে বন্ধুকে দেখতে পায়, সেই মুহূর্তটি হলো `ngAfterContentInit`।
*   **অ্যাঙ্গুলারে:** যখন কোনো 외부 কন্টেন্ট (external content) `<ng-content>` ব্যবহার করে কম্পোনেন্টের ভেতরে দেখানো হয়, সেই কন্টেন্ট দেখানোর পর এটি মাত্র একবার কল হয়।

---

**৬. `ngAfterViewInit`**

*   **ছাত্রের জীবনে:** ছাত্র এবং তার বন্ধুরা সবাই ক্লাসে বসার পর পুরো **ক্লাসরুমটি সম্পূর্ণরূপে প্রস্তুত**। এখন ছাত্রটি তার ডেস্ক, ব্ল্যাকবোর্ড, জানালা—সবকিছু দেখতে পাচ্ছে। অর্থাৎ, ক্লাসের সম্পূর্ণ দৃশ্য (view) তৈরি হয়ে গেছে।
*   **অ্যাঙ্গুলারে:** কম্পোনেন্টের নিজস্ব টেমপ্লেট (HTML) এবং তার চাইল্ড কম্পোনেন্টগুলোর টেমপ্লেট পুরোপুরি লোড হওয়ার পর এটি মাত্র **একবার** কল হয়। DOM এলিমেন্ট (যেমন: কোনো div বা button) নিয়ে কাজ করার জন্য এটি সেরা জায়গা।

---

**৭. `ngOnDestroy` (ng-On-Destroy)**

*   **ছাত্রের জীবনে:** ছাত্রের **স্কুল জীবন শেষ**। সে পাশ করে স্কুল থেকে বিদায় নিচ্ছে (Transfer Certificate) বা গ্র্যাজুয়েট হচ্ছে। বিদায় নেওয়ার আগে তার কিছু দায়িত্ব আছে, যেমন: লাইব্রেরির বই ফেরত দেওয়া, নিজের লকার পরিষ্কার করা। এই কাজগুলো না করলে পরে সমস্যা হতে পারে।
*   **অ্যাঙ্গুলারে:** কম্পোনেন্টটি ওয়েবসাইট থেকে মুছে ফেলার (destroy) ঠিক আগের মুহূর্তে এটি কল হয়। এখানে "পরিষ্কার-পরিচ্ছন্নতার" কাজ করা হয়। যেমন: Observable থেকে unsubscribe করা, ইভেন্ট লিসেনার সরানো ইত্যাদি। এটি করলে মেমোরি লিক (memory leak) হওয়ার সম্ভাবনা থাকে না।

### সহজ কোডের উদাহরণ (Easy Code Example)

আসুন, উপরের ধারণাগুলো কোডের মাধ্যমে দেখি।

#### `student-profile.component.ts` (ছাত্রের প্রোফাইল)

```typescript
import { Component, Input, OnChanges, OnInit, OnDestroy, SimpleChanges } from '@angular/core';

@Component({
  selector: 'app-student-profile',
  template: `
    <div style="border: 2px solid green; padding: 10px; margin: 10px;">
      <h3>ছাত্রের প্রোফাইল</h3>
      <p>নাম: {{ studentName }}</p>
      <p>ক্লাস: {{ studentClass }}</p>
    </div>
  `
})
export class StudentProfileComponent implements OnInit, OnChanges, OnDestroy {
  @Input() studentName: string = '';
  @Input() studentClass: number = 0;

  constructor() {
    console.log('constructor: ছাত্র ভর্তির জন্য আবেদন করেছে।');
  }

  ngOnChanges(changes: SimpleChanges) {
    console.log('ngOnChanges: ছাত্রের তথ্য পরিবর্তন হয়েছে।', changes);
  }

  ngOnInit() {
    console.log('ngOnInit: ছাত্রের স্কুলে আজ প্রথম দিন! সে ডেটা লোড করছে।');
    // যেমন: ছাত্রের পরীক্ষার রেজাল্ট API থেকে আনা যেতে পারে।
  }

  ngOnDestroy() {
    console.log('ngOnDestroy: ছাত্র স্কুল থেকে বিদায় নিচ্ছে। সবকিছু পরিষ্কার করছে।');
    // এখানে unsubscribe বা cleanup কোড লেখা হবে।
  }
}
```

#### `app.component.ts` (স্কুল কর্তৃপক্ষ)

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `
    <h1>স্কুল ম্যানেজমেন্ট সিস্টেম</h1>

    <button (click)="changeClass()">ছাত্রকে নতুন ক্লাসে ওঠাও</button>
    <button (click)="removeStudent()">ছাত্রকে স্কুল থেকে বাদ দাও</button>
    
    <hr>
    
    <app-student-profile 
      *ngIf="studentExists"
      [studentName]="currentStudentName" 
      [studentClass]="currentStudentClass">
    </app-student-profile>
  `
})
export class AppComponent {
  currentStudentName: string = 'রহিম';
  currentStudentClass: number = 5;
  studentExists: boolean = true;

  changeClass() {
    this.currentStudentClass++; // ক্লাস এক বাড়ানো হলো
  }

  removeStudent() {
    this.studentExists = false; // ছাত্রকে অদৃশ্য করে দেওয়া হলো
  }
}
```

### কীভাবে কাজ করবে?

1.  **প্রথমে:** যখন অ্যাপটি লোড হবে, Console-এ আপনি দেখবেন:
    *   `constructor: ছাত্র ভর্তির জন্য আবেদন করেছে।`
    *   `ngOnChanges: ছাত্রের তথ্য পরিবর্তন হয়েছে।` (প্রথমবার তথ্য পাওয়ার জন্য)
    *   `ngOnInit: ছাত্রের স্কুলে আজ প্রথম দিন! সে ডেটা লোড করছে।`

2.  **"ছাত্রকে নতুন ক্লাসে ওঠাও" বাটনে ক্লিক করলে:**
    *   `currentStudentClass`-এর মান পরিবর্তন হবে। সাথে সাথে Console-এ দেখবেন:
    *   `ngOnChanges: ছাত্রের তথ্য পরিবর্তন হয়েছে।` (কারণ `@Input` বদলেছে)

3.  **"ছাত্রকে স্কুল থেকে বাদ দাও" বাটনে ক্লিক করলে:**
    *   `*ngIf="studentExists"` false হয়ে যাবে এবং `StudentProfileComponent` টি DOM থেকে মুছে যাবে। ঠিক তার আগেই Console-এ দেখবেন:
    *   `ngOnDestroy: ছাত্র স্কুল থেকে বিদায় নিচ্ছে। সবকিছু পরিষ্কার করছে।`

এই উদাহরণটি আপনাকে ছাত্রের জীবনের ধাপগুলোর সাথে মিলিয়ে অ্যাঙ্গুলার লাইফসাইকেল বুঝতে সাহায্য করবে।



# Part - 2

ঠিক আছে, কোনো সমস্যা নেই। চলুন আরও সহজ করে, একেবারে গল্প বলার মতো করে বুঝি।

ভাবুন, আপনার ওয়েবসাইটে একটি নতুন জিনিস দেখাচ্ছেন, যেমন একজন ছাত্রের প্রোফাইল কার্ড। এই কার্ডটি হলো একটি **অ্যাঙ্গুলার কম্পোনেন্ট**।

এই কার্ডটি স্ক্রিনে আসা থেকে শুরু করে চলে যাওয়া পর্যন্ত কয়েকটি ধাপে কাজ করে। এই ধাপগুলো অটোমেটিক বা নিজে থেকেই হয়। আমরা শুধু প্রতিটি ধাপে কী কাজ করতে হবে, তা বলে দিই।

আসুন, আমাদের কম্পোনেন্টের নাম দিই **"রানা"**।

### রানার জীবন কাহিনী (অ্যাঙ্গুলার লাইফসাইকেল)

**ধাপ ১: জন্ম হওয়ার আগের প্রস্তুতি (`constructor`)**

*   **গল্প:** রানা এখনও জন্মায়নি। ডাক্তার এবং নার্সরা ওর জন্মের জন্য সবকিছু প্রস্তুত করছেন (যেমন: যন্ত্রপাতি, বেড ইত্যাদি)। এটা হলো মূল কাজের আগের প্রস্তুতি।
*   **অ্যাঙ্গুলারে:** কম্পোনেন্ট (`রানা`) তৈরি হওয়ার ঠিক আগের মুহূর্ত। এই সময়ে অ্যাঙ্গুলার শুধু প্রয়োজনীয় জিনিসপত্র (সার্ভিস) গুছিয়ে নেয়। রানা এখনও তার কোনো তথ্য (যেমন নাম, ক্লাস) জানে না।

---

**ধাপ ২: নাম রাখা (`ngOnChanges`)**

*   **গল্প:** রানার বাবা-মা বাইরে থেকে ওর জন্য একটি নাম ঠিক করলেন: "রানা"। যদি পরে তারা নাম পরিবর্তন করে "রানা আহমেদ" রাখেন, তখনো এই ধাপটি কাজ করবে। অর্থাৎ, **বাইরে থেকে যখনই কোনো তথ্য পরিবর্তন হয়**, তখনই এই ধাপটি আসে।
*   **অ্যাঙ্গুলারে:** যখনই প্যারেন্ট কম্পোনেন্ট থেকে `@Input()` দিয়ে কোনো ডেটা আসে বা সেই ডেটা পরিবর্তন হয়, তখন `ngOnChanges` মেথডটি কল হয়।

---

**ধাপ ৩: প্রথমবার চোখ খোলা (`ngOnInit`)**

*   **গল্প:** রানা জন্মে গেছে, তার নামও রাখা হয়েছে। এখন সে **জীবনের প্রথমবার চোখ খুললো**। এই কাজটা জীবনে মাত্র একবারই হয়। চোখ খুলে সে প্রথমবার দুনিয়াটা দেখছে।
*   **অ্যাঙ্গুলারে:** কম্পোনেন্ট তৈরি হওয়ার পর এই মেথডটি **মাত্র একবার** কল হয়। এখানেই আমরা কম্পোনেন্টের প্রথম এবং সবচেয়ে জরুরি কাজগুলো করি। যেমন: সার্ভার থেকে ডেটা নিয়ে আসা।

---

**ধাপ ৪: বিদায় নেওয়া (`ngOnDestroy`)**

*   **গল্প:** রানার জীবন শেষ। সে এখন চলে যাবে। চলে যাওয়ার আগে তার ঘর, তার জিনিসপত্র পরিষ্কার করে গুছিয়ে রাখতে হয়, যাতে কোনো আবর্জনা না থাকে।
*   **অ্যাঙ্গুলারে:** যখন কম্পোনেন্টটি স্ক্রিন থেকে মুছে ফেলা হয় (যেমন: অন্য পেইজে চলে গেলে), তখন `ngOnDestroy` কল হয়। এখানে আমরা "পরিষ্কার করার" কোড লিখি, যাতে মেমোরিতে কোনো আবর্জনা (memory leak) না থাকে।

---

### এক নজরে ৪টি প্রধান ধাপ

| জীবনের ধাপ | অ্যাঙ্গুলার হুক | সহজ কথায় কাজ |
| :--- | :--- | :--- |
| **১. প্রস্তুতি** | `constructor` | জন্ম হওয়ার আগের প্রস্তুতি। |
| **২. তথ্য পরিবর্তন** | `ngOnChanges` | বাইরে থেকে নাম বা অন্য তথ্য পরিবর্তন হলে। |
| **৩. প্রথম কাজ** | `ngOnInit` | জন্মানোর পর প্রথম এবং জরুরি কাজ (শুধু একবার)। |
| **৪. বিদায়** | `ngOnDestroy` | স্ক্রিন থেকে চলে যাওয়ার আগে সব পরিষ্কার করা। |

---

### খুব সহজ কোডের উদাহরণ

ধরে নিন, একটি বাটন ক্লিক করলে "রানা" স্ক্রিনে আসবে এবং আরেকটি বাটনে ক্লিক করলে চলে যাবে।

**rana.component.ts:**

```typescript
import { Component, Input, OnInit, OnDestroy, OnChanges } from '@angular/core';

@Component({
  selector: 'app-rana',
  template: `<h2>আমার নাম {{ studentName }}</h2>`
})
export class RanaComponent implements OnInit, OnDestroy, OnChanges {
  
  @Input() studentName: string = '';

  constructor() {
    console.log('কনস্ট্রাক্টর: রানা এখনও জন্মায়নি, শুধু প্রস্তুতি চলছে।');
  }

  ngOnChanges() {
    console.log('ngOnChanges: রানার নাম পরিবর্তন করা হয়েছে!');
  }

  ngOnInit() {
    console.log('ngOnInit: রানা জন্মানোর পর প্রথমবার চোখ খুললো। (শুধু একবার হয়)');
  }

  ngOnDestroy() {
    console.log('ngOnDestroy: রানা চলে যাচ্ছে, ওর ঘর পরিষ্কার করা হচ্ছে।');
  }
}
```

**app.component.html (যেখানে রানাকে দেখানো হবে):**

```html
<h1>লাইফসাইকেল টেস্ট</h1>

<button (click)="isRanaVisible = !isRanaVisible">
  রানা কে দেখাও / সরাও
</button>

<button (click)="changeName()">
  রানার নাম পরিবর্তন করো
</button>

<!-- *ngIf দিয়ে রানাকে দেখানো বা সরানো হচ্ছে -->
<app-rana 
  *ngIf="isRanaVisible" 
  [studentName]="name">
</app-rana>
```

**app.component.ts:**

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  isRanaVisible: boolean = false;
  name: string = "রানা";

  changeName() {
    this.name = "রানা আহমেদ";
  }
}
```

**কীভাবে কাজ করবে:**
1.  **"রানা কে দেখাও" বাটনে ক্লিক করলে:** Console-এ পরপর দেখবেন:
    *   `কনস্ট্রাক্টর: ...`
    *   `ngOnChanges: ...`
    *   `ngOnInit: ...`

2.  **"রানার নাম পরিবর্তন করো" বাটনে ক্লিক করলে:** Console-এ দেখবেন:
    *   `ngOnChanges: ...` (কারণ `@Input` এর `name` পরিবর্তন হয়েছে)

3.  **আবার "রানা কে দেখাও / সরাও" বাটনে ক্লিক করলে:** রানা স্ক্রিন থেকে চলে যাবে এবং Console-এ দেখবেন:
    *   `ngOnDestroy: ...`

আশা করি, এই গল্পের মতো উদাহরণটি আপনাকে বিষয়টি সহজে বুঝতে সাহায্য করেছে


# Part - 3

অবশ্যই! চলুন, অ্যাঙ্গুলারের সমস্ত লাইফসাইকেল হুককে একটি গল্পের মাধ্যমে ধাপে ধাপে বুঝি।

গল্পের প্রধান চরিত্র হলো **"কম্পোনেন্ট ভাই"**। যখনই আমরা ওয়েবসাইটে নতুন কোনো অংশ (যেমন: একটি প্রোফাইল কার্ড) দেখাই, তখনই একজন "কম্পোনেন্ট ভাই" জন্ম নেয়। তার জন্ম থেকে বিদায় পর্যন্ত পুরো জীবনটাই হলো অ্যাঙ্গুলার লাইফসাইকেল।

---

### অ্যাঙ্গুলার লাইফসাইকেল হুকগুলোর তালিকা (জন্ম থেকে মৃত্যু পর্যন্ত)

1.  `constructor` (জন্মের প্রস্তুতি)
2.  `ngOnChanges` (বাইরে থেকে নতুন তথ্য পাওয়া)
3.  `ngOnInit` (প্রথমবার চোখ মেলে তাকানো)
4.  `ngDoCheck` (বারবার খোঁজ নেওয়া)
5.  `ngAfterContentInit` (অতিথির প্রথম আগমন)
6.  `ngAfterContentChecked` (বারবার অতিথির খোঁজ নেওয়া)
7.  `ngAfterViewInit` (নিজের ঘর গোছানো শেষ)
8.  `ngAfterViewChecked` (বারবার নিজের ঘর পরীক্ষা করা)
9.  `ngOnDestroy` (বিদায় বেলা)

---

### প্রতিটি ধাপের বিস্তারিত ব্যাখ্যা

#### ১. `constructor()` - জন্মের প্রস্তুতি
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** "কম্পোনেন্ট ভাই" এখনও জন্মায়নি। ডাক্তাররা (অ্যাঙ্গুলার) তার জন্মের জন্য প্রয়োজনীয় জিনিসপত্র (সার্ভিস) প্রস্তুত করছেন। এটা হলো একেবারে প্রথম ধাপ।
*   **অ্যাঙ্গুলারে এর কাজ:** কম্পোনেন্ট ক্লাস তৈরি হওয়ার সাথে সাথেই এটি কল হয়। এর প্রধান কাজ হলো Dependency Injection, অর্থাৎ অন্যান্য সার্ভিসকে এখানে যুক্ত করা। এই ধাপে `@Input` থেকে কোনো ডেটা পাওয়া যায় না।

#### ২. `ngOnChanges()` - বাইরে থেকে নতুন তথ্য পাওয়া
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** বাবা-মা (Parent Component) "কম্পোনেন্ট ভাইকে" নতুন জামা বা খেলনা (`@Input` ডেটা) দিলেন। যতবারই নতুন কিছু দেবেন, ততবারই সে খেয়াল করবে।
*   **অ্যাঙ্গুলারে এর কাজ:** যখনই কোনো `@Input` property-র মান পরিবর্তন হয়, তখন এটি কল হয়। কম্পোনেন্ট চালু হওয়ার সময় প্রথমবার এবং এরপর যতবার `@Input` ডেটা বদলাবে, ততবার এটি কল হবে।

#### ৩. `ngOnInit()` - প্রথমবার চোখ মেলে তাকানো
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** "কম্পোনেন্ট ভাই" জন্মেছে এবং জীবনের **প্রথমবারের মতো চোখ খুললো**। এই বিশেষ মুহূর্তটি তার জীবনে আর আসবে না। এই সময়ে সে তার চারপাশটা প্রথম চিনে নেয়।
*   **অ্যাঙ্গুলারে এর কাজ:** কম্পোনেন্ট তৈরি হওয়ার পর এটি **মাত্র একবার** কল হয়। কম্পোনেন্টের প্রাথমিক ডেটা লোড করার জন্য (যেমন: API থেকে ডেটা আনা) এটিই সবচেয়ে উপযুক্ত জায়গা।

#### ৪. `ngDoCheck()` - বারবার খোঁজ নেওয়া
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** তার মা (অ্যাঙ্গুলারের Change Detection) কিছুক্ষণ পরপরই এসে দেখে যাচ্ছেন সে ঠিক আছে কিনা। কোনো আনুষ্ঠানিক কারণ ছাড়াই তিনি এই খোঁজটা নিচ্ছেন।
*   **অ্যাঙ্গুলারে এর কাজ:** অ্যাঙ্গুলার যখনই কোনো পরিবর্তন শনাক্ত করার চেষ্টা করে, তখনই এই মেথডটি কল হয়। এটি খুব ঘন ঘন কল হয়। যদি এমন কোনো পরিবর্তন ট্র্যাক করতে হয় যা অ্যাঙ্গুলার নিজে থেকে ধরতে পারে না, তখন এটি ব্যবহার করা হয়। তবে সাবধানে ব্যবহার করতে হয়, কারণ এটি পারফরম্যান্সে প্রভাব ফেলতে পারে।

#### ৫. `ngAfterContentInit()` - অতিথির প্রথম আগমন
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** "কম্পোনেন্ট ভাইয়ের" ঘরে একজন অতিথি (বাইরে থেকে আসা HTML কন্টেন্ট) প্রথমবার এসে ঢুকলেন। সে এই প্রথমবার অতিথিকে দেখলো।
*   **অ্যাঙ্গুলারে এর কাজ:** যখন `<ng-content>` ব্যবহার করে কোনো 외부 কন্টেন্ট কম্পোনেন্টের ভেতরে প্রজেক্ট করা হয়, সেই কন্টেন্ট দেখানোর পর এটি মাত্র **একবার** কল হয়।

#### ৬. `ngAfterContentChecked()` - বারবার অতিথির খোঁজ নেওয়া
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** মা যেমন তার খোঁজ নিচ্ছিলেন, তেমনি তিনি এখন অতিথিরও খোঁজ নিচ্ছেন যে সে ঠিক আছে কিনা। এই খোঁজটা বারবার নেওয়া হচ্ছে।
*   **অ্যাঙ্গুলারে এর কাজ:** প্রতিবার `ngDoCheck` চলার পর এবং অ্যাঙ্গুলার যখন বাইরের কন্টেন্ট চেক করে, তখন এটি কল হয়।

#### ৭. `ngAfterViewInit()` - নিজের ঘর গোছানো শেষ
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** "কম্পোনেন্ট ভাই" এবং তার অতিথি সহ পুরো ঘর (কম্পোনেন্টের নিজস্ব টেমপ্লেট) পুরোপুরি সাজানো-গোছানো শেষ। সে **প্রথমবার** তার সাজানো ঘরটিকে দেখছে।
*   **অ্যাঙ্গুলারে এর কাজ:** কম্পোনেন্টের নিজস্ব টেমপ্লেট (View) এবং তার চাইল্ড কম্পোনেন্টগুলোর টেমপ্লেট পুরোপুরি লোড হওয়ার পর এটি মাত্র **একবার** কল হয়। DOM এলিমেন্ট নিয়ে কাজ করার জন্য (যেমন `@ViewChild` ব্যবহার করে) এটি সেরা জায়গা।

#### ৮. `ngAfterViewChecked()` - বারবার নিজের ঘর পরীক্ষা করা
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** ঘর গোছানো শেষ হওয়ার পরেও "কম্পোনেন্ট ভাই" বারবার তার ঘর পরীক্ষা করে দেখছে সবকিছু ঠিকঠাক আছে কিনা।
*   **অ্যাঙ্গুলারে এর কাজ:** প্রতিবার `ngDoCheck` চলার পর এবং অ্যাঙ্গুলার যখন কম্পোনেন্টের View চেক করে, তখন এটি কল হয়।

#### ৯. `ngOnDestroy()` - বিদায় বেলা
*   **কম্পোনেন্ট ভাইয়ের জীবনে:** "কম্পোনেন্ট ভাইয়ের" বিদায় নেওয়ার সময় হয়েছে। সে তার ঘর ছেড়ে চলে যাচ্ছে। যাওয়ার আগে সে তার ঘর পরিষ্কার করে, লাইট বন্ধ করে, সব গোছগাছ করে রেখে যাচ্ছে।
*   **অ্যাঙ্গুলারে এর কাজ:** কম্পোনেন্টটি ওয়েবসাইট থেকে মুছে ফেলার (destroy) ঠিক আগের মুহূর্তে এটি কল হয়। এখানে "পরিষ্কার-পরিচ্ছন্নতার" কাজ করা হয়। যেমন: Observable থেকে unsubscribe করা, ইভেন্ট লিসেনার সরানো। এটি না করলে মেমোরি লিক (memory leak) হতে পারে।

### কোডের উদাহরণ

এই কোডটি চালালে আপনি ব্রাউজারের Console-এ দেখতে পারবেন কোন হুক কখন কল হচ্ছে।

**lifecycle-test.component.ts (আমাদের "কম্পোনেন্ট ভাই")**
```typescript
import { Component, Input, OnChanges, OnInit, DoCheck, AfterContentInit, AfterContentChecked, AfterViewInit, AfterViewChecked, OnDestroy, SimpleChanges } from '@angular/core';

@Component({
  selector: 'app-lifecycle-test',
  template: `
    <div style="border: 2px solid blue; padding: 15px; margin-top: 10px;">
      <h3>আমি "কম্পোনেন্ট ভাই"! আমার নাম: {{ name }}</h3>
      <h4>বাইরে থেকে আসা অতিথি:</h4>
      <ng-content></ng-content>
    </div>
  `
})
export class LifecycleTestComponent implements OnChanges, OnInit, DoCheck, AfterContentInit, AfterContentChecked, AfterViewInit, AfterViewChecked, OnDestroy {
  @Input() name: string = '';

  constructor() {
    console.log('1. constructor: জন্মের প্রস্তুতি চলছে...');
  }

  ngOnChanges(changes: SimpleChanges) {
    console.log('2. ngOnChanges: বাইরে থেকে নতুন তথ্য পেলাম!', changes);
  }

  ngOnInit() {
    console.log('3. ngOnInit: প্রথমবার চোখ খুললাম! (শুধু একবার)');
  }

  ngDoCheck() {
    console.log('4. ngDoCheck: মা এসে খোঁজ নিয়ে গেলেন...');
  }

  ngAfterContentInit() {
    console.log('5. ngAfterContentInit: অতিথি প্রথমবার ঘরে এলেন! (শুধু একবার)');
  }

  ngAfterContentChecked() {
    console.log('6. ngAfterContentChecked: মা অতিথির খোঁজ নিলেন...');
  }

  ngAfterViewInit() {
    console.log('7. ngAfterViewInit: আমার নিজের ঘর গোছানো শেষ! (শুধু একবার)');
  }

  ngAfterViewChecked() {
    console.log('8. ngAfterViewChecked: নিজের ঘর আবার পরীক্ষা করলাম...');
  }

  ngOnDestroy() {
    console.log('9. ngOnDestroy: বিদায়! ঘর পরিষ্কার করে যাচ্ছি।');
  }
}
```

**app.component.html (যেখানে "কম্পোনেন্ট ভাইকে" নিয়ন্ত্রণ করা হবে)**
```html
<h1>অ্যাঙ্গুলার লাইফসাইকেল টেস্ট</h1>

<button (click)="toggleComponent()">
  কম্পোনেন্ট ভাইকে দেখাও / সরাও
</button>
<button (click)="changeName()">
  নাম পরিবর্তন করো
</button>
<hr>

<app-lifecycle-test *ngIf="isVisible" [name]="componentName">
  <!-- এই অংশটি অতিথি হিসেবে যাবে -->
  <p>আমি একজন অতিথি!</p>
</app-lifecycle-test>
```

**app.component.ts (বাবা-মা)**
```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
})
export class AppComponent {
  isVisible: boolean = false;
  componentName: string = 'রহিম';

  toggleComponent() {
    this.isVisible = !this.isVisible;
  }

  changeName() {
    this.componentName = 'করিম';
  }
}
```
