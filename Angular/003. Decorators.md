


### সহজ উপমা (Easy Analogy)

ডেকোরেটরকে (Decorator) আপনি একটা "ট্যাগ" বা "পোস্ট-ইট নোট" এর মতো ভাবতে পারেন।

ধরুন, আপনার একটা সাধারণ TypeScript ক্লাস আছে। এখন এই ক্লাসটা কি একটা Component, নাকি একটা Service, নাকি একটা Directive হবে, সেটা Angular বুঝবে কীভাবে?

এಲ್ಲೆಲ್ಲಿ ডেকোরেটরের কাজ। আপনি যখন ক্লাসের উপরে `@Component` ট্যাগ বা লেবেল লাগিয়ে দেন, তখন Angular বুঝে যায়, "ওহ, আচ্ছা! এটা একটা সাধারণ ক্লাস নয়, এটা একটা কম্পোনেন্ট। এর একটা HTML টেমপ্লেট থাকবে এবং একে আমি DOM-এ দেখাতে পারব।"

অর্থাৎ, **ডেকোরেটর হলো এক ধরনের ফাংশন যা আপনার ক্লাস, প্রপার্টি বা মেথডকে অতিরিক্ত তথ্য (metadata) দিয়ে সাজিয়ে তোলে, যাতে Angular বুঝতে পারে তাকে নিয়ে কী করতে হবে।**

চলুন, সবচেয়ে বেশি ব্যবহৃত কয়েকটি বিল্ট-ইন ডেকোরেটর কোডের মাধ্যমে দেখি।

---

### প্রধান ডেকোরেটরগুলোর ব্যাখ্যা (Explanation of Major Decorators)

আমরা ডেকোরেটরগুলোকে কয়েকটি ভাগে ভাগ করতে পারি:

1.  **Class Decorators:** যেগুলো পুরো ক্লাসের উপর কাজ করে। (`@Component`, `@NgModule`, `@Injectable`, `@Directive`, `@Pipe`)
2.  **Property Decorators:** যেগুলো ক্লাসের ভেতরের প্রপার্টির (ভেরিয়েবল) উপর কাজ করে। (`@Input`, `@Output`, `@ViewChild`, `@ContentChild`)
3.  **Method Decorators:** যেগুলো ক্লাসের মেথডের (ফাংশন) উপর কাজ করে। (`@HostListener`)
4.  **Parameter Decorators:** যেগুলো মেথডের প্যারামিটারের উপর কাজ করে। (`@Inject`)

### ১. Class Decorators

#### ক) `@Component`
এটা Angular-এর সবচেয়ে গুরুত্বপূর্ণ ডেকোরেটর। এটা একটা সাধারণ ক্লাসকে UI কম্পোনেন্টে পরিণত করে।

**উদ্দেশ্য:** Angular-কে বলা যে এই ক্লাসটি একটি UI কম্পোনেন্ট এবং এর সাথে কোন HTML, CSS এবং selector যুক্ত থাকবে।

**Code Example (`user-profile.component.ts`):**
```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-user-profile', // এই নামে HTML-এ কম্পোনেন্টটি ব্যবহার করা হবে <app-user-profile></app-user-profile>
  templateUrl: './user-profile.component.html', // এই কম্পোনেন্টের HTML ফাইল
  styleUrls: ['./user-profile.component.css'] // এই কম্পোনেন্টের CSS ফাইল
})
export class UserProfileComponent {
  userName: string = 'শাওন আহমেদ';
  userAge: number = 32;

  constructor() { }
}
```
**ব্যাখ্যা:**
*   `@Component` ডেকোরেটরটি `UserProfileComponent` ক্লাসকে বলছে যে সে এখন আর সাধারণ ক্লাস নয়।
*   `selector`: HTML-এ `<app-user-profile>` ট্যাগ লিখলে Angular এই কম্পোনেন্টটি সেখানে রেন্ডার করবে।
*   `templateUrl`: এই কম্পোনেন্টের চেহারা কেমন হবে, তা এই HTML ফাইলে লেখা আছে।
*   `styleUrls`: এই কম্পোনেন্টের স্টাইলিং এখানে করা আছে।

#### খ) `@Injectable`
এটা কোনো ক্লাসকে Dependency Injection (DI) সিস্টেমের জন্য উপলব্ধ করে। সহজ কথায়, এই ক্লাসটিকে অন্য কোনো কম্পোনেন্ট বা সার্ভিসে "inject" বা ব্যবহার করা যাবে।

**উদ্দেশ্য:** একটি সার্ভিস (Service) তৈরি করা যা অ্যাপের বিভিন্ন জায়গায় শেয়ার করা যায়।

**Code Example (`auth.service.ts`):**
```typescript
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root' // এর মানে হলো, Angular এই সার্ভিসের একটি মাত্র instance তৈরি করবে এবং পুরো অ্যাপে সেটি ব্যবহার করবে (Singleton Pattern)।
})
export class AuthService {

  isLoggedIn(): boolean {
    // এখানে লগইন চেক করার লজিক থাকবে
    return true;
  }
}
```
**ব্যাখ্যা:**
`@Injectable` ডেকোরেটরটি `AuthService` ক্লাসকে একটি সার্ভিস হিসেবে চিহ্নিত করছে। এখন আমরা যেকোনো কম্পোনেন্টের `constructor`-এ এই সার্ভিসটি খুব সহজে ব্যবহার করতে পারব।

```typescript
// UserProfileComponent এর ভেতরে...
import { AuthService } from './auth.service';

export class UserProfileComponent {
  // ...
  constructor(private authService: AuthService) {
    if (this.authService.isLoggedIn()) {
      console.log('ব্যবহারকারী লগইন করা আছেন।');
    }
  }
}
```

### ২. Property Decorators

#### ক) `@Input`
এই ডেকোরেটরটি Parent Component থেকে Child Component-এ ডেটা পাস করার জন্য ব্যবহৃত হয়।

**উদ্দেশ্য:** একটি কম্পোনেন্টের প্রপার্টিকে বাইরের জগৎ (Parent Component) থেকে ডেটা গ্রহণ করার জন্য উন্মুক্ত করা।

**Code Example (`user-card.component.ts` - Child Component):**
```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-user-card',
  template: `
    <div class="card">
      <h3>{{ user.name }}</h3>
      <p>বয়স: {{ user.age }}</p>
    </div>
  `
})
export class UserCardComponent {
  @Input() user: { name: string, age: number }; // 'user' প্রপার্টিটি এখন বাইরে থেকে ডেটা গ্রহণ করতে পারবে।
}
```

**Parent Component (`app.component.html`)-এ ব্যবহার:**
```html
<app-user-card [user]="userDataFromParent"></app-user-card>
```

**Parent Component (`app.component.ts`):**
```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  userDataFromParent = { name: 'করিম রহমান', age: 40 };
}
```
**ব্যাখ্যা:** `@Input()` ডেকোরেটরটি `user` প্রপার্টিকে একটি গেটওয়ে বানিয়ে দিয়েছে, যার মাধ্যমে `AppComponent` তার নিজের ডেটা (`userDataFromParent`) `UserCardComponent`-এর ভেতরে পাঠাতে পারছে।

#### খ) `@Output`
এটি `@Input`-এর ঠিক উল্টো কাজ করে। Child Component থেকে Parent Component-এ কোনো ইভেন্ট বা ডেটা পাঠানোর জন্য এটি ব্যবহার করা হয়।

**উদ্দেশ্য:** চাইল্ড কম্পোনেন্ট থেকে কোনো ঘটনা (event) প্যারেন্টকে জানানো।

**Code Example (`user-card.component.ts` - Child Component):**
```typescript
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-user-card',
  template: `
    <div class="card">
      <h3>{{ user.name }}</h3>
      <button (click)="notifyParent()">Delete</button> 
    </div>
  `
})
export class UserCardComponent {
  @Input() user: { name: string, age: number };
  @Output() userDeleted = new EventEmitter<string>(); // একটি ইভেন্ট তৈরি করা হলো।

  notifyParent() {
    // বাটনে ক্লিক করলে 'userDeleted' ইভেন্টটি emit হবে এবং ইউজারের নাম প্যারেন্টের কাছে চলে যাবে।
    this.userDeleted.emit(this.user.name);
  }
}
```

**Parent Component (`app.component.html`)-এ ব্যবহার:**
```html
<app-user-card [user]="userDataFromParent" (userDeleted)="handleUserDelete($event)"></app-user-card>
```

**Parent Component (`app.component.ts`):**
```typescript
export class AppComponent {
  userDataFromParent = { name: 'করিম রহমান', age: 40 };

  handleUserDelete(userName: string) {
    console.log(`${userName} কে ডিলিট করার জন্য অনুরোধ এসেছে।`);
    // এখানে ডিলিট করার লজিক থাকবে।
  }
}
```
**ব্যাখ্যা:** `@Output()` এবং `EventEmitter` একসাথে কাজ করে। চাইল্ডের বাটনে ক্লিক করলে `userDeleted` ইভেন্টটি ফায়ার হয় এবং প্যারেন্ট কম্পোনেন্টের `handleUserDelete` মেথডটি কল হয়।

### ৩. Method Decorators

#### `@HostListener`
এই ডেকোরেটরটি দিয়ে DOM ইভেন্ট (যেমন: click, mouseover, keydown) সরাসরি কম্পোনেন্টের কোনো মেথডের সাথে বাইন্ড করা যায়।

**উদ্দেশ্য:** হোস্ট এলিমেন্ট বা গ্লোবাল কোনো ইভেন্ট (যেমন window, document) শোনা।

**Code Example:**
```typescript
import { Component, HostListener } from '@angular/core';

@Component({
  selector: 'app-event-tracker',
  template: '<p>Click anywhere on the page!</p>'
})
export class EventTrackerComponent {

  @HostListener('window:click', ['$event'])
  onWindowClick(event: MouseEvent) {
    console.log('Window clicked at:', event.clientX, event.clientY);
  }

  @HostListener('keydown.enter', ['$event'])
  onEnterPress(event: KeyboardEvent) {
    console.log('Enter key was pressed!');
  }
}
```
**ব্যাখ্যা:** এখানে, `@HostListener` ব্যবহার করে আমরা পুরো `window`-এর `click` ইভেন্ট এবং `keydown.enter` ইভেন্ট ট্র্যাক করছি। যখনই এই ঘটনাগুলো ঘটবে, সংশ্লিষ্ট মেথড (`onWindowClick`, `onEnterPress`) নিজে থেকেই কল হয়ে যাবে।

### সারসংক্ষেপ

*   **`@Component`**: ক্লাসকে কম্পোনেন্ট বানায়।
*   **`@Injectable`**: ক্লাসকে সার্ভিস বানায়, যা অন্য জায়গায় ইনজেক্ট করা যায়।
*   **`@Input`**: Parent থেকে Child-এ ডেটা পাঠায়।
*   **`@Output`**: Child থেকে Parent-এ ইভেন্ট পাঠায়।
*   **`@HostListener`**: DOM ইভেন্ট শোনার জন্য মেথডকে তৈরি করে।

আশা করি, এই সহজ বাংলা ব্যাখ্যা এবং কোড উদাহরণগুলো আপনাকে Angular ডেকোরেটরের ধারণাটি আরও ভালোভাবে বুঝতে সাহায্য করেছে


# =========  Easy Explanation ============

**চলুন একটা নাটকের উদাহরণ দিই।**

ধরুন, আপনি একটা নাটক করছেন। নাটকে অনেক সাধারণ মানুষ আছে।

1.  **সাধারণ ক্লাস (Normal Class):**
    নাটকের জন্য আপনি কিছু সাধারণ মানুষকে (ধরা যাক, 'করিম', 'রহিম') জোগাড় করলেন। এরা এখনও কোনো চরিত্র না, শুধু সাধারণ মানুষ।
    TypeScript-এ এটা হলো একটা সাধারণ ক্লাস:
    ```typescript
    class Karim {
      // করিমের কিছু বৈশিষ্ট্য
    }
    ```
    এই `Karim` ক্লাসটা দিয়ে Angular কিছুই করতে পারবে না। সে জানেই না এটা কী।

2.  **ডেকোরেটর (Decorator):**
    এখন, নাটকের পরিচালক এসে করিমের মাথায় একটা **রাজার মুকুট (Crown)** পরিয়ে দিলেন।

    এই **মুকুটটাই হলো ডেকোরেটর (`@Decorator`)**।

    মুকুটটা পরানোর সাথে সাথে সবাই বুঝে গেল যে, করিম আর সাধারণ মানুষ নয়, সে এখন নাটকের **"রাজা"**। তার একটা বিশেষ ভূমিকা আছে।

### Angular-এর ভাষায় ডেকোরেটর

Angular-এ ডেকোরেটর ঠিক এই মুকুটের মতোই কাজ করে। এটা একটা সাধারণ ক্লাসকে বিশেষ পরিচয় বা ক্ষমতা দেয়।

#### `@Component` ডেকোরেটর (এটা হলো "অভিনেতার মুকুট")

আপনি যখন একটা ক্লাসের উপরে `@Component` লিখে দেন, আপনি আসলে Angular-কে বলছেন:
"ওহে Angular, এই সাধারণ ক্লাসটা এখন থেকে একজন **অভিনেতা (Component)**। ওকে তুমি UI-তে দেখাতে পারবে।"

**কোড দেখুন:**

```typescript
import { Component } from '@angular/core';

// @Component ডেকোরেটর (মুকুট) পরানো হলো
@Component({
  selector: 'app-raja', // এটা হলো তার স্টেজের নাম। HTML-এ <app-raja> লিখলে সে আসবে।
  template: '<h1>আমি এই নাটকের রাজা!</h1>' // এটা তার ডায়লগ বা কাজ।
})
export class RajaComponent { // এটা ছিল সাধারণ ক্লাস
  // ক্লাসের ভেতরের জিনিস
}
```

**সহজ কথায়:**
*   **`class RajaComponent`**: এটা ছিল একজন সাধারণ মানুষ।
*   **`@Component({...})`**: এটা হলো তার মাথায় পরানো "মুকুট"। এই মুকুটটা দেখেই Angular বুঝল যে সে একজন অভিনেতা এবং তাকে স্টেজে পারফর্ম করতে হবে।
*   **`selector`**: এটা অভিনেতার নাম, যা ধরে তাকে ডাকা হবে।
*   **`template`**: এটা তার অভিনয় বা ডায়লগ।

### আরও দুটি সহজ উদাহরণ

#### `@Input()` ডেকোরেটর (বাইরে থেকে জিনিসপত্র দেওয়া)

নাটকের "রাজা" যখন অভিনয় করছে, তখন মন্ত্রী এসে তার হাতে একটা **তরোয়াল** দিল। এই তরোয়ালটা কিন্তু রাজার নিজের ছিল না, তাকে বাইরে থেকে দেওয়া হয়েছে।

`@Input()` ডেকোরেটর ঠিক এই কাজটাই করে। এটা একটা কম্পোনেন্টকে (রাজা) বাইরে থেকে ডেটা (তরোয়াল) গ্রহণ করার ক্ষমতা দেয়।

**কোড:**
```typescript
// RajaComponent এর ভেতরে
export class RajaComponent {
  @Input() torowal: string; // @Input মানে, 'torowal' জিনিসটা বাইরে থেকে আসবে
}
```

#### `@Injectable()` ডেকোরেটর (মেকআপ আর্টিস্ট)

নাটকের একজন **মেকআপ আর্টিস্ট** আছে। সে নিজে অভিনয় করে না, কিন্তু রাজা, রানী, মন্ত্রী সবার যখন দরকার হয়, তখন তাকে ডেকে নেয়। সে একজন সাহায্যকারী।

`@Injectable()` ডেকোরেটর একটা ক্লাসকে এইরকম **সাহায্যকারী (Service)** বানিয়ে দেয়। যেকোনো অভিনেতা (Component) তাকে দরকার হলেই ডেকে ব্যবহার করতে পারে।

**কোড:**
```typescript
@Injectable() // এই মুকুট পরানোর মানে হলো, সে এখন একজন সাহায্যকারী
export class MakeupArtistService {
  // মেকআপ করার কাজ এখানে লেখা থাকবে
}
```

### সারকথা:

**ডেকোরেটর হলো একটা "ট্যাগ" বা "মুকুট" যা একটা সাধারণ TypeScript ক্লাসকে বলে দেয় যে Angular-এ তার ভূমিকা কী হবে।**

*   `@Component` -> তুমি একজন অভিনেতা।
*   `@Input` -> তুমি বাইরে থেকে জিনিস নিতে পারবে।
*   `@Injectable` -> তুমি একজন সাহায্যকারী।

আশা করি, নাটকের এই উদাহরণটা বুঝতে সাহায্য করেছে। এইবার কি কিছুটা সহজ মনে হচ্ছে?


# ====== Input Decorator =========

অবশ্যই! চলুন `@Input` ডেকোরেটরকে একটা খুবই সহজ, বাস্তব জীবনের উদাহরণ দিয়ে বুঝি।

### সহজ উপমা: বাবা এবং ছেলে (Parent and Child)

ধরুন, একটি **Parent Component** হলো "বাবা" এবং একটি **Child Component** হলো তার "ছেলে"।

বাবার কাছে টাকা আছে। বাবা তার ছেলেকে কিছু পকেট মানি দিতে চান।

এখন, ছেলের তো টাকাটা নেওয়ার জন্য একটা ব্যবস্থা থাকতে হবে, তাই না? যেমন, তার একটা **পকেট** থাকতে হবে।

`@Input()` ডেকোরেটরটি হলো চাইল্ড কম্পোনেন্টের সেই **"পকেট"**। এই পকেটটা সে বাইরের পৃথিবীর (অর্থাৎ, প্যারেন্ট কম্পোনেন্টের) জন্য খুলে রাখে, যাতে বাবা সেখানে টাকা (ডেটা) রাখতে পারে।

**মূল কথা:** `@Input` ডেকোরেটর একটি চাইল্ড কম্পোনেন্টের প্রপার্টিকে একটি "রিসিভার" বা "গেটওয়ে" বানিয়ে দেয়, যার মাধ্যমে প্যারেন্ট কম্পোনেন্ট থেকে ডেটা গ্রহণ করা যায়।

### কোড উদাহরণ (Code Example)

আমরা দুটি কম্পোনেন্ট তৈরি করব:
1.  **`SontanComponent` (Child):** এর একটা `pocketMoney` নামের পকেট থাকবে।
2.  **`AppComponent` (Parent):** ইনি `SontanComponent`-কে পকেট মানি দেবেন।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট তৈরি (`sontan.component.ts`)

প্রথমে আমরা ছেলের কম্পোনেন্ট বানাব এবং তার জন্য একটা "পকেট" তৈরি করব।

```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-sontan', // এই নামে HTML-এ ছেলেকে ডাকা হবে
  template: `
    <div style="border: 2px solid green; padding: 10px; margin-top: 20px;">
      <h3>আমি হলাম ছেলে (Child Component)</h3>
      <h4>বাবার কাছ থেকে পাওয়া আমার পকেট মানি: {{ pocketMoneyFromBaba }} টাকা</h4>
    </div>
  `
})
export class SontanComponent {

  // এই @Input() ডেকোরেটরটিই হলো আসল জিনিস!
  // এটা 'pocketMoneyFromBaba' প্রপার্টিকে একটি "পকেট" বানিয়ে দিচ্ছে।
  @Input() pocketMoneyFromBaba: number;

  constructor() { }
}
```

**ব্যাখ্যা:**
*   আমরা `SontanComponent` নামে একটি ক্লাস তৈরি করেছি।
*   `@Input()` ডেকোরেটরটি `pocketMoneyFromBaba` নামের প্রপার্টির ঠিক আগে বসানো হয়েছে।
*   এর মানে হলো, `pocketMoneyFromBaba` প্রপার্টিটি এখন বাইরে থেকে (প্যারেন্ট থেকে) ডেটা গ্রহণ করার জন্য প্রস্তুত।
*   Template-এর ভেতরে আমরা `{{ pocketMoneyFromBaba }}` দিয়ে সেই পাওয়া টাকাটা দেখাচ্ছি।

#### ধাপ ২: প্যারেন্ট কম্পোনেন্টে ব্যবহার (`app.component.ts` ও `app.component.html`)

এবার বাবা তার ছেলেকে ডাকবে এবং তাকে পকেট মানি দেবে।

**`app.component.ts` (বাবার ডেটা):**
```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  // বাবার কাছে এই টাকাটা আছে, যেটা তিনি ছেলেকে দেবেন
  amarKacherTaka: number = 500;
}
```

**`app.component.html` (বাবা ছেলেকে টাকা দিচ্ছেন):**
```html
<div style="border: 2px solid blue; padding: 10px;">
  <h1>আমি হলাম বাবা (Parent Component)</h1>
  <p>আমার কাছে আছে: {{ amarKacherTaka }} টাকা</p>

  <!-- এখানে আসল কাজটি হচ্ছে -->
  <!-- <app-sontan> ট্যাগ দিয়ে ছেলেকে ডাকা হচ্ছে -->
  <!-- [pocketMoneyFromBaba] দিয়ে ছেলের "পকেটে" টাকা পাঠানো হচ্ছে -->
  <app-sontan [pocketMoneyFromBaba]="amarKacherTaka"></app-sontan>

</div>
```

**ব্যাখ্যা:**
1.  `<app-sontan ...>`: এখানে আমরা চাইল্ড কম্পোনেন্টকে (ছেলেকে) ব্যবহার করছি।
2.  **`[pocketMoneyFromBaba]`**: এই অংশটি খুব গুরুত্বপূর্ণ।
    *   `pocketMoneyFromBaba` হলো চাইল্ড কম্পোনেন্টের সেই `@Input` প্রপার্টির নাম।
    *   স্কয়ার ব্র্যাকেট `[]` (একে Property Binding বলে) দিয়ে Angular-কে বোঝানো হচ্ছে যে আমরা ডান পাশের ভ্যালুটি বাম পাশের প্রপার্টিতে পাঠাতে চাই।
3.  **`="amarKacherTaka"`**: `amarKacherTaka` হলো প্যারেন্ট কম্পোনেন্টের (বাবার) নিজের প্রপার্টি, যার ভ্যালু `500`।

### পুরো প্রক্রিয়াটা কীভাবে কাজ করে?

1.  Angular প্রথমে `AppComponent` (বাবা) রেন্ডার করে।
2.  `AppComponent`-এর HTML-এ সে `<app-sontan>` ট্যাগটি দেখতে পায়।
3.  Angular তখন `SontanComponent` (ছেলে) তৈরি করতে যায়।
4.  তৈরি করার সময় সে দেখে যে, প্যারেন্ট তার `[pocketMoneyFromBaba]` প্রপার্টিতে `amarKacherTaka`-এর ভ্যালু (`500`) পাস করেছে।
5.  ফলে, `SontanComponent`-এর `pocketMoneyFromBaba` প্রপার্টির মান `500` হয়ে যায়।
6.  অবশেষে, `SontanComponent`-এর টেমপ্লেটে `{{ pocketMoneyFromBaba }}` এর জায়গায় `500` দেখায়।

### কখন ব্যবহার করবেন?

যখনই আপনার একটি **পুনঃব্যবহারযোগ্য (reusable)** কম্পোনেন্ট থাকবে এবং আপনি বাইরে থেকে সেটিকে ভিন্ন ভিন্ন ডেটা দিয়ে কনফিগার করতে চাইবেন, তখনই `@Input` ব্যবহার করবেন।

**উদাহরণ:**
*   একটি `UserProfileCardComponent` বানালেন। বাইরে থেকে একেকবার একেক ইউজারের তথ্য (`@Input() user`) দিয়ে কার্ডটি দেখাবেন।
*   একটি `ButtonComponent` বানালেন। বাইরে থেকে বাটনের টেক্সট, কালার ইত্যাদি `@Input` দিয়ে কন্ট্রোল করবেন।

আশা করি, বাবা-ছেলের এই উদাহরণটি `@Input` ডেকোরেটরের কাজকে পুরোপুরি পরিষ্কার করে দিয়েছে।

# ====== Output Decorator ==========

`@Input`-এর বাবা-ছেলের উপমাটাই আমরা এখানে ব্যবহার করব, তবে এবার ঘটনাটা উল্টো হবে।

`@Input` ছিল বাবা ছেলেকে টাকা দেওয়ার মতো (Parent to Child)।
`@Output` হলো ছেলে বাবাকে কোনো খবর দেওয়ার মতো (Child to Parent)।

### সহজ উপমা: ছেলে বাবাকে ডাকছে

আগের উদাহরণে বাবা ছেলেকে ৫০০ টাকা পকেট মানি দিয়েছিলেন। এখন ধরুন, ছেলের সেই টাকা খরচ হয়ে গেছে এবং তার আরও টাকা দরকার।

ছেলে তো আর সরাসরি বাবার পকেট থেকে টাকা নিতে পারবে না। তাকে কী করতে হবে?

তাকে তার বাবাকে **ডাকতে হবে** বা একটা **অনুরোধ** জানাতে হবে। যেমন, ছেলে চিৎকার করে বলল, "বাবা! আমার আরও ১০০ টাকা লাগবে!"

এই **"চিৎকার করা"** বা **"অনুরোধ জানানো"**-ই হলো `@Output`।

*   **Child (ছেলে):** সে একটি ঘটনা (event) ঘটায়।
*   **Parent (বাবা):** সে সেই ঘটনা শোনার জন্য কান পেতে থাকে এবং শুনলে কিছু একটা করে।

`@Output` ডেকোরেটর চাইল্ড কম্পোনেন্টকে এই "চিৎকার করার" বা "ইভেন্ট পাঠানোর" ক্ষমতা দেয়। এটি সবসময় `EventEmitter`-এর সাথে কাজ করে, যা ইভেন্টটি তৈরি করে এবং পাঠায়।

### কোড উদাহরণ (Code Example)

আমরা আগের `SontanComponent` এবং `AppComponent`-কেই ব্যবহার করব।

#### ধাপ ১: চাইল্ড কম্পোনেন্টকে "ডাকা"র ক্ষমতা দেওয়া (`sontan.component.ts`)

আমরা `SontanComponent`-এ একটি বাটন যোগ করব। বাটনে ক্লিক করলে সে তার বাবাকে (Parent Component) একটি মেসেজ পাঠাবে।

```typescript
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-sontan',
  template: `
    <div style="border: 2px solid green; padding: 10px; margin-top: 20px;">
      <h3>আমি হলাম ছেলে (Child Component)</h3>
      <h4>বাবার কাছ থেকে পাওয়া আমার পকেট মানি: {{ pocketMoneyFromBaba }} টাকা</h4>

      <!-- এই বাটনে ক্লিক করলে বাবার কাছে অনুরোধ যাবে -->
      <button (click)="takaChao()">বাবার কাছে আরও টাকা চাও</button>
    </div>
  `
})
export class SontanComponent {
  @Input() pocketMoneyFromBaba: number;

  // এই @Output() ডেকোরেটরটিই হলো আসল জিনিস!
  // 'takaChaiEvent' নামে একটি ইভেন্ট তৈরি করা হচ্ছে, যা বাইরে বার্তা পাঠাতে পারবে।
  @Output() takaChaiEvent = new EventEmitter<string>(); // আমরা string টাইপের মেসেজ পাঠাব।

  constructor() { }

  // এই মেথডটি কল হবে যখন বাটনে ক্লিক করা হবে
  takaChao() {
    // emit() ফাংশন দিয়ে আমরা বাবার কাছে মেসেজটি "চিৎকার" করে পাঠাচ্ছি
    this.takaChaiEvent.emit('বাবা, আমার আরও ১০০ টাকা লাগবে!');
  }
}
```

**ব্যাখ্যা:**
*   `@Output()` ডেকোরেটরটি `takaChaiEvent` প্রপার্টিকে একটি ইভেন্ট এমিটার (EventEmitter) হিসেবে ঘোষণা করছে। সহজ কথায়, এটি ছেলের "মুখ" যা দিয়ে সে চিৎকার করতে পারবে।
*   `EventEmitter<string>` মানে হলো, এই মুখ দিয়ে শুধু `string` বা টেক্সট জাতীয় মেসেজ পাঠানো যাবে।
*   `takaChao()` মেথডের ভেতরে `this.takaChaiEvent.emit(...)` লাইনটিই আসল কাজটা করছে। `emit` মানে হলো "পাঠানো" বা "প্রচার করা"। এখানে আমরা একটি মেসেজ প্রচার করছি।

#### ধাপ ২: প্যারেন্ট কম্পোনেন্টকে "কান পেতে" রাখা (`app.component.ts` ও `app.component.html`)

এবার বাবাকে (Parent Component) ছেলের ডাক শোনার জন্য প্রস্তুত থাকতে হবে এবং শুনলে কিছু একটা করতে হবে।

**`app.component.html` (বাবা ছেলের ডাক শুনছেন):**
```html
<div style="border: 2px solid blue; padding: 10px;">
  <h1>আমি হলাম বাবা (Parent Component)</h1>

  <!-- বাবা ছেলেকে টাকা দিচ্ছেন (@Input এর উদাহরণ) -->
  <app-sontan 
    [pocketMoneyFromBaba]="amarKacherTaka"
    (takaChaiEvent)="sontanErDakeSaraDeo($event)"> 
    <!-- এখানে আসল কাজটি হচ্ছে -->
    <!-- (takaChaiEvent) দিয়ে বাবা ছেলের ডাক শোনার জন্য কান পেতে আছেন -->
  </app-sontan>

  <h3 style="margin-top: 20px;">ছেলের কাছ থেকে পাওয়া মেসেজ: {{ sontanErMessage }}</h3>
</div>
```

**ব্যাখ্যা:**
1.  **`(takaChaiEvent)`**: এই অংশটি খুব গুরুত্বপূর্ণ।
    *   `takaChaiEvent` হলো চাইল্ড কম্পোনেন্টের সেই `@Output` প্রপার্টির নাম।
    *   প্রথম বন্ধনী `()` (একে Event Binding বলে) দিয়ে Angular-কে বোঝানো হচ্ছে যে আমরা এই নামের কোনো ইভেন্টের জন্য অপেক্ষা করছি।
2.  **`="sontanErDakeSaraDeo($event)"`**:
    *   `sontanErDakeSaraDeo` হলো প্যারেন্ট কম্পোনেন্টের একটি মেথড, যা ইভেন্টটি ঘটলে কল হবে।
    *   `$event` একটি বিশেষ ভেরিয়েবল। চাইল্ড কম্পোনেন্ট `emit()` করার সময় যে ডেটা (`'বাবা, আমার আরও ১০০ টাকা লাগবে!'`) পাঠিয়েছিল, সেই ডেটা এই `$event`-এর মধ্যে থাকে।

**`app.component.ts` (বাবা ছেলের ডাকে সাড়া দিচ্ছেন):**
```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  amarKacherTaka: number = 500;
  sontanErMessage: string = 'এখনও কোনো মেসেজ আসেনি।'; // শুরুতে কোনো মেসেজ নেই

  // এই মেথডটি কল হবে যখন ছেলে 'takaChaiEvent' ইভেন্টটি পাঠাবে
  sontanErDakeSaraDeo(messageFromSontan: string) {
    console.log('ছেলের কাছ থেকে মেসেজ পেয়েছি:', messageFromSontan);
    this.sontanErMessage = messageFromSontan;
    // এখানে বাবা টাকা পাঠানো বা অন্য কোনো লজিক লিখতে পারেন।
  }
}
```

### পুরো প্রক্রিয়াটা কীভাবে কাজ করে?

1.  ব্যবহারকারী চাইল্ড কম্পোনেন্টের "বাবার কাছে আরও টাকা চাও" বাটনে ক্লিক করে।
2.  `SontanComponent`-এর `takaChao()` মেথডটি কল হয়।
3.  `takaChao()` মেথডটি `takaChaiEvent.emit()` ব্যবহার করে একটি `string` মেসেজ বাইরে পাঠিয়ে দেয়।
4.  `AppComponent`-এর HTML-এ `(takaChaiEvent)` এই ইভেন্টটি শোনার জন্য প্রস্তুত ছিল।
5.  ইভেন্টটি শোনামাত্র সে `sontanErDakeSaraDeo()` মেথডটি কল করে এবং `emit` করা ডেটাটি (`$event`) প্যারামিটার হিসেবে পাস করে দেয়।
6.  `sontanErDakeSaraDeo` মেথডটি সেই মেসেজ পেয়ে `sontanErMessage` প্রপার্টি আপডেট করে, যা সাথে সাথে UI-তে দেখানো হয়।

### কখন ব্যবহার করবেন?

যখন চাইল্ড কম্পোনেন্টে কোনো ঘটনা ঘটে (যেমন: বাটনে ক্লিক, ফর্ম সাবমিট, ডেটা ডিলিট) এবং সেই খবরটি প্যারেন্ট কম্পোনেন্টকে জানাতে হয়, তখন `@Output` ব্যবহার করা হয়।


# ==== Model Decorator =======
দারুণ প্রশ্ন! আপনি যেহেতু `@Input` এবং `@Output` বুঝে গেছেন, `@model` ডেকোরেটরটি বোঝা আপনার জন্য খুবই সহজ হবে। কারণ `@model` হলো ঐ দুটি ডেকোরেটরের একটি আধুনিক এবং স্মার্ট কম্বিনেশন।

এটি Angular v17.3-এ নতুন যুক্ত হয়েছে এবং Two-way Data Binding-কে আরও সহজ করে দিয়েছে, বিশেষ করে Signals-এর সাথে।

### সহজ উপমা: ম্যাজিক মানিব্যাগ (Magic Wallet)

আগের উদাহরণে ফিরে যাই:
*   **`@Input`**: বাবা ছেলেকে টাকা দিচ্ছেন (একমুখী: Parent -> Child)।
*   **`@Output`**: ছেলে বাবাকে জানাচ্ছে তার টাকা লাগবে (একমুখী: Child -> Parent)।

এই দুটিকে একসাথে ব্যবহার করে আমরা Two-way Binding তৈরি করতাম, যা একটু কষ্টকর ছিল।

এখন `@model` ডেকোরেটরের কথা ভাবুন। এটা একটা **"ম্যাজিক মানিব্যাগ"**-এর মতো।

বাবা এই ম্যাজিক মানিব্যাগটা ছেলেকে দেন।
1.  **বাবা টাকা রাখতে পারেন:** বাবা যখন মানিব্যাগে টাকা রাখেন, ছেলে সাথে সাথে সেই টাকা দেখতে ও ব্যবহার করতে পারে (এটা `@Input`-এর মতো কাজ)।
2.  **ছেলে টাকা খরচ করতে পারে:** ছেলে যখন মানিব্যাগ থেকে টাকা খরচ করে, বাবার কাছে থাকা মূল টাকার পরিমাণও **অটোমেটিক্যালি কমে যায়** (এটা `@Output`-এর মতো কাজ)।

ছেলেকে আর চিৎকার করে বাবাকে বলতে হয় না, "বাবা, টাকা খরচ হয়ে গেল!"। ম্যাজিক মানিব্যাগ নিজেই সেই খবরটা বাবাকে জানিয়ে দেয়।

`@model` ঠিক এই কাজটিই করে। এটি একটি প্রপার্টি তৈরি করে যা প্যারেন্ট এবং চাইল্ড উভয়ের মধ্যে সিঙ্ক্রোনাইজড (synchronized) থাকে। একজন পরিবর্তন করলে অন্যজন স্বয়ংক্রিয়ভাবে আপডেট হয়ে যায়।

---

### কোড উদাহরণ: আগের দিনের পদ্ধতি বনাম নতুন পদ্ধতি

আমরা একটি কাস্টম কাউন্টার কম্পোনেন্ট বানাব, যেখানে প্যারেন্ট থেকে ভ্যালু কন্ট্রোল করা যাবে এবং চাইল্ড থেকেও ভ্যালু পরিবর্তন করা যাবে।

#### ১. আগের দিনের পদ্ধতি (`@Input` ও `@Output` দিয়ে)

**Child Component (`old-counter.component.ts`):**
```typescript
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-old-counter',
  template: `
    <div>
      <p>Old Counter: {{ count }}</p>
      <button (click)="increment()">+</button>
    </div>
  `
})
export class OldCounterComponent {
  @Input() count: number = 0;
  @Output() countChange = new EventEmitter<number>(); // নামটা খেয়াল করুন: "property name" + "Change"

  increment() {
    this.count++;
    this.countChange.emit(this.count); // প্যারেন্টকে জানাতে হচ্ছে
  }
}
```

**Parent Component (`app.component.html`):**
```html
<!-- পুরো Two-way binding লিখতে হতো এভাবে -->
<app-old-counter [count]="parentCount" (countChange)="parentCount = $event"></app-old-counter>

<!-- অথবা শর্টকাট [(...)] sintax ব্যবহার করে -->
<app-old-counter [(count)]="parentCount"></app-old-counter>
```
**`app.component.ts`:**
```typescript
export class AppComponent {
  parentCount: number = 10;
}
```
**সমস্যা:** এখানে `count` এবং `countChange` নামে দুটি জিনিস ম্যানেজ করতে হচ্ছে এবং `emit` করতে হচ্ছে। এটা অতিরিক্ত কোড।

---

#### ২. নতুন এবং সহজ পদ্ধতি (`@model` দিয়ে)

`@model` ডেকোরেটরটি Angular Signals-এর উপর ভিত্তি করে তৈরি। তাই আমরা এখন সিগন্যাল ব্যবহার করব।

**Child Component (`new-counter.component.ts`):**
```typescript
import { Component, model, ModelSignal } from '@angular/core';

@Component({
  selector: 'app-new-counter',
  template: `
    <div>
      <p>New Counter (using @model): {{ count() }}</p> <!-- সিগন্যাল তাই () দিয়ে ভ্যালু পড়তে হয় -->
      <button (click)="increment()">+</button>
    </div>
  `
})
export class NewCounterComponent {
  // শুধু এই একটি লাইনই @Input এবং @Output উভয়ের কাজ করে দিচ্ছে!
  count = model.required<number>(); // অথবা model(0) দিয়ে ডিফল্ট ভ্যালু দেওয়া যায়

  increment() {
    // সিগন্যালের ভ্যালু আপডেট করা আরও সহজ
    this.count.update(currentValue => currentValue + 1);
  }
}
```

**ব্যাখ্যা:**
*   `count = model.required<number>()`: এই একটি লাইনই Angular-কে বলে দিচ্ছে:
    1.  `count` একটি ইনপুট প্রপার্টি, যা বাইরে থেকে ভ্যালু নেবে।
    2.  `count`-এর ভ্যালু যখন চাইল্ডের ভেতরে পরিবর্তন হবে, তখন সেই পরিবর্তনটা অটোমেটিক্যালি প্যারেন্টের কাছে চলে যাবে।
*   `@Input` বা `@Output` লেখার কোনো প্রয়োজন নেই! `EventEmitter` বা `emit()` করারও দরকার নেই।

**Parent Component (`app.component.ts` ও `app.component.html`):**

Parent-কেও अब সিগন্যাল ব্যবহার করতে হবে।

**`app.component.ts`:**
```typescript
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  // ...
})
export class AppComponent {
  // প্যারেন্টের ভ্যালু এখন একটি সিগন্যাল
  parentCountSignal = signal(10);
}
```

**`app.component.html`:**
```html
<h2>Parent Count Signal Value: {{ parentCountSignal() }}</h2>

<!-- ব্যবহার করা আগের মতোই সহজ -->
<app-new-counter [(count)]="parentCountSignal"></app-new-counter>
```

**কীভাবে কাজ করে:**
যখন `NewCounterComponent`-এর ভেতরের বাটনে ক্লিক করা হয়, `this.count.update()` কল হয়। যেহেতু `count` একটি `model` সিগন্যাল, এটি নিজের ভ্যালু পরিবর্তন করার সাথে সাথে প্যারেন্টের `parentCountSignal`-কেও আপডেট করে দেয়। কোনো `emit`-এর ঝামেলা নেই।

### সারসংক্ষেপ: `@model` বনাম `@Input`/`@Output`

| বৈশিষ্ট্য | `@Input` + `@Output` | `@model` |
| :--- | :--- | :--- |
| **কোড** | দুটি প্রপার্টি (`value`, `valueChange`) এবং `EventEmitter` লাগে। | মাত্র একটি লাইন: `prop = model()`। |
| **জটিলতা** | বেশি, কারণ `emit` করতে হয়। | খুবই কম, সব স্বয়ংক্রিয়ভাবে হয়। |
| **নির্ভরশীলতা** | যেকোনো কিছুর সাথে কাজ করে। | Angular Signals-এর উপর ভিত্তি করে তৈরি। |
| **উদ্দেশ্য** | একমুখী ডেটা ফ্লো। | দ্বিমুখী (Two-way) ডেটা বাইন্ডিংকে সহজ করা। |
| **আধুনিকতা** | পুরনো এবং স্ট্যান্ডার্ড পদ্ধতি। | আধুনিক, সিগন্যাল-ভিত্তিক নতুন পদ্ধতি। |

একজন অভিজ্ঞ ডেভেলপার হিসেবে আপনি বুঝতেই পারছেন, `@model` কতটা কোড কমিয়েছে এবং Two-way binding-এর উদ্দেশ্যকে কতটা পরিষ্কারভাবে প্রকাশ করছে। এখন থেকে কাস্টম ফর্ম কন্ট্রোল বা যেকোনো state শেয়ারিং কম্পোনেন্ট বানানোর জন্য `@model`-ই সেরা উপায়।



# === Host binding =====


অবশ্যই! `@HostBinding` ডেকোরেটরটি খুবই কাজের, বিশেষ করে যখন আপনি একটি কম্পোনেন্টকে আরও বেশি self-contained বা স্বয়ংসম্পূর্ণ করতে চান।

চলুন, এটাকে একটা সহজ উপমা দিয়ে শুরু করি।

### সহজ উপমা: গিরগিটি (Chameleon)

ভাবুন, আপনার কম্পোনেন্টটি একটি **গিরগিটি**।

গিরগিটির একটি বিশেষ ক্ষমতা আছে: সে তার ভেতরের অবস্থা বা মেজাজ (mood) অনুযায়ী নিজের **গায়ের রঙ** পরিবর্তন করতে পারে। যেমন, বিপদে পড়লে এক রঙ, শান্ত থাকলে আরেক রঙ।

এখানে:
*   **গিরগিটি নিজে** = আপনার Component Class (TypeScript ফাইল)।
*   **গিরগিটির ভেতরের মেজাজ** = কম্পোনেন্টের ভেতরের কোনো প্রপার্টি (e.g., `isActive = true`, `state = 'error'`)।
*   **গিরগিটির গায়ের রঙ** = কম্পোনেন্টের **হোস্ট এলিমেন্ট** (Host Element) বা নিজের ট্যাগ (`<app-my-component>`)।

`@HostBinding` ডেকোরেটরটি হলো সেই "ম্যাজিক ক্ষমতা" যা গিরগিটির ভেতরের মেজাজকে তার গায়ের রঙের সাথে সরাসরি যুক্ত করে দেয়। যখনই মেজাজ পরিবর্তন হয়, গায়ের রঙও নিজে থেকেই পরিবর্তন হয়ে যায়।

**মূল কথা:** `@HostBinding` একটি কম্পোনেন্টের **ভেতরের প্রপার্টির ভ্যালুকে** তার **হোস্ট এলিমেন্টের** (যেমন: class, style, attribute) সাথে বাইন্ড করে দেয়। এর ফলে, কম্পোনেন্ট নিজেই নিজের বাইরের চেহারা নিয়ন্ত্রণ করতে পারে।

### কোড উদাহরণ (Code Example)

আমরা একটি কাস্টম বাটন কম্পোনেন্ট বানাব। বাটনটি যখন `disabled` থাকবে, তখন তার উপর একটি বিশেষ CSS ক্লাস যুক্ত হবে এবং তার বর্ডার বদলে যাবে। এই কাজটি আমরা কম্পোনেন্টের ভেতর থেকেই করব, বাইরে থেকে নয়।

#### ধাপ ১: কম্পোনেন্ট তৈরি (`custom-button.component.ts`)

```typescript
import { Component, Input, HostBinding } from '@angular/core';

@Component({
  selector: 'app-custom-button',
  template: `
    <ng-content></ng-content> <!-- এটি দিয়ে বাটনের ভেতরের লেখা দেখানো হয় -->
  `,
  styleUrls: ['./custom-button.component.css']
})
export class CustomButtonComponent {

  @Input()
  disabled: boolean = false;

  // --- @HostBinding এর ব্যবহার ---

  // ১. CSS ক্লাস বাইন্ড করা
  // যখন 'disabled' প্রপার্টির ভ্যালু true হবে,
  // তখন হোস্ট এলিমেন্টে (<app-custom-button>) 'disabled-button' ক্লাসটি যুক্ত হবে।
  @HostBinding('class.disabled-button')
  get isDisabled() {
    return this.disabled;
  }

  // ২. স্টাইল বাইন্ড করা
  // 'disabled' প্রপার্টির উপর ভিত্তি করে বর্ডারের স্টাইল পরিবর্তন হবে।
  @HostBinding('style.border')
  get borderStyle() {
    return this.disabled ? '2px solid red' : '2px solid green';
  }

  // ৩. ARIA এট্রিবিউট বাইন্ড করা (Accessibility এর জন্য ভালো)
  // হোস্ট এলিমেন্টের 'aria-disabled' এট্রিবিউটের ভ্যালু 'disabled' প্রপার্টির ভ্যালুর সমান হবে।
  @HostBinding('attr.aria-disabled')
  get ariaDisabled() {
    return this.disabled;
  }
}
```

**ব্যাখ্যা:**
*   **`@HostBinding('class.disabled-button')`**:
    *   `'class.disabled-button'` মানে হলো, আমরা হোস্ট এলিমেন্টের `class` লিস্টে `disabled-button` নামে একটি ক্লাস যোগ বা বিয়োগ করতে চাই।
    *   `get isDisabled()` একটি getter ফাংশন। যখন `this.disabled`-এর মান `true` হবে, এই ফাংশন `true` রিটার্ন করবে এবং ক্লাসটি যুক্ত হবে। `false` হলে ক্লাসটি সরে যাবে।
*   **`@HostBinding('style.border')`**:
    *   আমরা সরাসরি হোস্ট এলিমেন্টের `style.border` প্রপার্টির সাথে বাইন্ড করছি।
    *   `get borderStyle()` ফাংশনটি একটি স্ট্রিং রিটার্ন করে, যা CSS বর্ডারের ভ্যালু হিসেবে সেট হয়ে যায়।
*   **`@HostBinding('attr.aria-disabled')`**:
    *   `attr` উপসর্গ দিয়ে আমরা যেকোনো HTML attribute বাইন্ড করতে পারি। এখানে আমরা accessibility-র জন্য `aria-disabled` এট্রিবিউট সেট করছি।

#### ধাপ ২: কম্পোনেন্টের স্টাইল (`custom-button.component.css`)

আমাদেরকে `:host` selector ব্যবহার করতে হবে হোস্ট এলিমেন্টকে স্টাইল করার জন্য।

```css
/* :host দিয়ে <app-custom-button> ট্যাগকে স্টাইল করা হয় */
:host {
  display: inline-block;
  padding: 10px 20px;
  border-radius: 5px;
  cursor: pointer;
  background-color: #f0f0f0;
  transition: all 0.3s ease;
  user-select: none;
}

/* যখন 'disabled-button' ক্লাসটি যুক্ত হবে, তখন এই স্টাইল কাজ করবে */
:host(.disabled-button) {
  cursor: not-allowed;
  opacity: 0.5;
  background-color: #e0e0e0;
}
```

#### ধাপ ৩: প্যারেন্ট কম্পোনেন্টে ব্যবহার (`app.component.html`)

```html
<h1>@HostBinding Example</h1>

<p>একটি সাধারণ বাটন:</p>
<app-custom-button>Click Me</app-custom-button>

<hr>

<p>একটি Disabled বাটন:</p>
<!-- এখানে disabled ইনপুটকে true করে দিচ্ছি -->
<app-custom-button [disabled]="true">Cannot Click Me</app-custom-button>
```

### ফলাফল

1.  **প্রথম বাটনটি** সাধারণ দেখাবে, এর বর্ডার সবুজ হবে এবং এতে `disabled-button` ক্লাস থাকবে না।
2.  **দ্বিতীয় বাটনটি** `disabled` হওয়ায়:
    *   `@HostBinding('class.disabled-button')` কাজ করবে এবং `disabled-button` ক্লাসটি যুক্ত হবে, যার ফলে CSS থেকে বাটনটি ফ্যাকাসে (opacity 0.5) হয়ে যাবে।
    *   `@HostBinding('style.border')` কাজ করবে এবং বাটনের বর্ডার লাল হয়ে যাবে।
    *   `@HostBinding('attr.aria-disabled')` কাজ করবে এবং HTML ট্যাগটি হবে `<app-custom-button aria-disabled="true">...</app-custom-button>`।

### কখন `@HostBinding` ব্যবহার করবেন?

যখন কোনো কম্পোনেন্টের **ভেতরের অবস্থার** উপর ভিত্তি করে তার **নিজের বাইরের চেহারা** পরিবর্তন করার প্রয়োজন হয়, তখন `@HostBinding` ব্যবহার করা উচিত। এটি কম্পোনেন্টকে আরও encapsulated (স্বয়ংসম্পূর্ণ) করে তোলে, কারণ স্টাইলিংয়ের লজিক বাইরে না রেখে কম্পোনেন্টের ভেতরেই রাখা হয়। এটি reusable কম্পোনেন্ট বানানোর জন্য খুবই কার্যকরী।



ওকে, একদম চিন্তা করবেন না। আগের সব উদাহরণ ভুলে যান। আমি আরও সহজ, মাত্র এক লাইনের একটা উপমা দিচ্ছি।

**`@HostBinding` মানে হলো "ভেতরের সুইচ দিয়ে বাইরের বাতি জ্বালানো।"**

ধরুন, আপনার একটা কম্পোনেন্ট আছে, যেটা একটা **ঘর (`<app-my-room>`)**।

*   **ঘরের ভেতরের সুইচ** = এটা হলো আপনার কম্পোনেন্টের TypeScript ক্লাসের একটা ভেরিয়েবল (যেমন: `isLightOn = true;`)।
*   **ঘরের বাইরের দেয়ালের বাতি** = এটা হলো আপনার কম্পোনেন্টের ট্যাগ বা Host Element (`<app-my-room>`)।

এখন, আপনি চান **ভেতরের সুইচটা অন করলে যেন বাইরের বাতিটা জ্বলে ওঠে** (যেমন: বাইরের দেয়ালে একটা `glowing-light` ক্লাস যোগ হয়)।

আপনাকে তো ঘর থেকে বের হয়ে বাইরের বাতিটা জ্বালাতে হবে না, তাই না? আপনি ভেতর থেকেই কন্ট্রোল করতে চান।

**`@HostBinding` ঠিক এই কাজটাই করে।**

`@HostBinding` আপনার TypeScript ক্লাসের **ভেতরের সুইচকে (`isLightOn` ভেরিয়েবল)** সরাসরি **বাইরের বাতির (`<app-my-room>`-এর ক্লাস)** সাথে কানেক্ট করে দেয়।

**একদম সহজ কোড:**

```typescript
import { Component, HostBinding } from '@angular/core';

@Component({
  selector: 'app-my-room',
  template: `
    <button (click)="toggleLight()">
        সুইচ অন/অফ করো
    </button>
  `
})
export class MyRoomComponent {
  
  // এটা হলো "ভেতরের সুইচ"
  isLightOn: boolean = false; 

  // @HostBinding দিয়ে "বাইরের বাতি" কানেক্ট করা হলো
  @HostBinding('class.glowing-light') 
  get isGlowing() {
    return this.isLightOn; 
  }

  toggleLight() {
    this.isLightOn = !this.isLightOn; // সুইচ অন/অফ করছি
  }
}
```

**এখন কী হবে?**

1.  প্রথমে, `isLightOn` এর মান `false`। তাই `<app-my-room>` ট্যাগে `glowing-light` ক্লাসটি **থাকবে না**।
2.  আপনি যখন বাটনে ক্লিক করবেন, `isLightOn` এর মান `true` হয়ে যাবে।
3.  `@HostBinding` সাথে সাথে দেখবে "ওহ! সুইচ তো অন হয়েছে!"। সে নিজে থেকেই `<app-my-room>` ট্যাগের উপর `glowing-light` ক্লাসটি **লাগিয়ে দেবে**।
4.  আবার ক্লিক করলে, `isLightOn` `false` হয়ে যাবে এবং `@HostBinding` ক্লাসটি **খুলে নেবে**।

**HTML-এ এটা দেখতে কেমন হবে:**

*   সুইচ অফ থাকলে: `<app-my-room></app-my-room>`
*   সুইচ অন থাকলে: `<app-my-room class="glowing-light"></app-my-room>`

**মূল কথা:**
`@HostBinding` আপনার কম্পোনেন্টের **ভেতরের প্রপার্টিকে** ব্যবহার করে **কম্পোনেন্টের নিজের ট্যাগের (Host Element)** চেহারা (class, style ইত্যাদি) কন্ট্রোল করে।

এইবার কি উপমাটা পরিষ্কার হয়েছে?



# ======  @ViewChild =====
অবশ্যই! `@ViewChild` ডেকোরেটরটি বোঝার জন্য আমরা একটা খুব বাস্তবধর্মী উপমা ব্যবহার করব।

### সহজ উপমা: টিভির রিমোট কন্ট্রোল

ধরুন, আপনার **Parent Component** হলো **আপনি নিজে**, যে সোফায় বসে আছেন।
আপনার Parent Component-এর **Template (HTML)** হলো আপনার **পুরো বসার ঘরটা**।

আপনার বসার ঘরে অনেক জিনিস আছে—একটা টিভি, একটা সাউন্ডবার, একটা ফ্যান ইত্যাদি। এগুলোর প্রত্যেকটি হলো এক-একটি **Child Component** বা **DOM Element**।

এখন, আপনি সোফায় বসে **সাউন্ডবারের ভলিউম বাড়াতে** চান। আপনি কী করবেন?

আপনি সরাসরি সাউন্ডবারের কাছে হেঁটে যাবেন না। আপনি **সাউন্ডবারের রিমোট কন্ট্রোলটা** হাতে নেবেন এবং সেখান থেকে ভলিউম বাড়াবেন।

`@ViewChild` ডেকোরেটরটি হলো ঠিক সেই **"রিমোট কন্ট্রোল"**।

এটি Parent Component-কে তার নিজের Template-এর ভেতরে থাকা কোনো নির্দিষ্ট Child Component বা DOM Element-এর একটি সরাসরি রেফারেন্স বা "কন্ট্রোল" এনে দেয়। ফলে Parent Component সেই Child-কে সরাসরি নির্দেশ দিতে পারে (যেমন: "ভলিউম বাড়াও", "ভিডিও প্লে করো")।

**মূল কথা:** `@ViewChild` ব্যবহার করে একটি প্যারেন্ট কম্পোনেন্ট তার টেমপ্লেটের ভেতরের কোনো চাইল্ড কম্পোনেন্ট বা HTML এলিমেন্টকে সরাসরি অ্যাক্সেস এবং কন্ট্রোল করতে পারে।

---

### কোড উদাহরণ (Code Example)

আমরা একটি `VideoPlayerComponent` (Child) বানাব, যেটাতে `play()` এবং `pause()` করার মেথড থাকবে। এরপর `AppComponent` (Parent) থেকে বাটন ক্লিক করে সেই ভিডিও প্লেয়ারকে কন্ট্রোল করব।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট তৈরি (`video-player.component.ts`)

এটা হলো আমাদের "সাউন্ডবার" বা "ভিডিও প্লেয়ার", যার নিজস্ব কিছু ক্ষমতা আছে।

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-video-player',
  template: '<h3>ভিডিও প্লেয়ার: {{ status }}</h3>'
})
export class VideoPlayerComponent {
  status: string = 'Stopped';

  play() {
    this.status = 'Playing... ▶️';
    console.log('Video started playing.');
  }

  pause() {
    this.status = 'Paused ⏸️';
    console.log('Video paused.');
  }
}
```
**ব্যাখ্যা:**
এই কম্পোনেন্টের দুটি পাবলিক মেথড আছে: `play()` এবং `pause()`, যা প্যারেন্ট কম্পোনেন্ট থেকে কল করা যাবে।

#### ধাপ ২: প্যারেন্ট কম্পোনেন্টে `@ViewChild` ব্যবহার করা

এটা হলো "আপনি", যে রিমোট কন্ট্রোল দিয়ে ভিডিও প্লেয়ারকে চালাবে।

**`app.component.html` (আপনার বসার ঘর):**
```html
<h1>আমি Parent Component (রিমোট আমার হাতে)</h1>

<!-- এখানে ভিডিও প্লেয়ারটিকে রাখা হয়েছে -->
<!-- #player হলো একটি টেমপ্লেট রেফারেন্স ভেরিয়েবল, যা রিমোটকে বলে দেয় কোন ডিভাইসটি কন্ট্রোল করতে হবে -->
<app-video-player #player></app-video-player>

<hr>

<!-- এই বাটনগুলো হলো রিমোটের বাটন -->
<button (click)="playVideo()">Play</button>
<button (click)="pauseVideo()">Pause</button>
```
**ব্যাখ্যা:**
`#player` খুবই গুরুত্বপূর্ণ। এটা একটা লেবেলের মতো, যা দিয়ে আমরা `@ViewChild`-কে বলব যে ঠিক এই `app-video-player`-এর কন্ট্রোল আমাদের চাই।

**`app.component.ts` (আপনার হাতে থাকা রিমোট):**
```typescript
import { Component, ViewChild, AfterViewInit, ElementRef } from '@angular/core';
import { VideoPlayerComponent } from './video-player.component';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent implements AfterViewInit {

  // --- @ViewChild এর ব্যবহার ---
  // '#player' নামের চাইল্ড কম্পোনেন্টের রেফারেন্সটি videoPlayerRef প্রপার্টিতে রাখো।
  @ViewChild('player') videoPlayerRef: VideoPlayerComponent;

  constructor() {
    // এখানে this.videoPlayerRef ব্যবহার করলে undefined দেখাবে!
    // কারণ constructor চলার সময় HTML টেমপ্লেট এখনও তৈরি হয়নি।
  }

  // এই lifecycle hook-টি তখনই চলে যখন টেমপ্লেট পুরোপুরি তৈরি হয়ে যায়।
  // তাই এখানে আমরা প্রথমবার রেফারেন্সটি ব্যবহার করতে পারি।
  ngAfterViewInit() {
    console.log('ভিডিও প্লেয়ারের রেফারেন্স পাওয়া গেছে:', this.videoPlayerRef);
    // এখন আপনি চাইলে শুরুতেই কিছু একটা করতে পারেন
    // this.videoPlayerRef.play();
  }

  // প্যারেন্টের মেথড, যা চাইল্ডের মেথডকে কল করবে
  playVideo() {
    console.log('Play বাটন চাপা হয়েছে।');
    this.videoPlayerRef.play(); // রিমোট দিয়ে প্লেয়ারকে চালানো হচ্ছে
  }

  pauseVideo() {
    console.log('Pause বাটন চাপা হয়েছে।');
    this.videoPlayerRef.pause(); // রিমোট দিয়ে প্লেয়ারকে পজ করা হচ্ছে
  }
}
```

**ব্যাখ্যা:**
1.  **`@ViewChild('player') videoPlayerRef: VideoPlayerComponent;`**:
    *   `@ViewChild` ডেকোরেটরকে আমরা বলছি, "HTML-এর মধ্যে `#player` নামের এলিমেন্টটা খুঁজে বের করো।"
    *   যখন সে খুঁজে পাবে, তখন সেই `VideoPlayerComponent`-এর পুরো ইনস্ট্যান্সটা (`play`, `pause` মেথডসহ) `videoPlayerRef` নামের ভেরিয়েবলের মধ্যে রেখে দেবে।
    *   এখন `videoPlayerRef`-ই হলো আমাদের "রিমোট কন্ট্রোল"।
2.  **`ngAfterViewInit`**: এটা একটা গুরুত্বপূর্ণ বিষয়। কম্পোনেন্টের `constructor` যখন চলে, তখন HTML টেমপ্লেট বা "বসার ঘর" তৈরিই হয়নি। তাই রিমোট (`videoPlayerRef`) কাজ করবে না। `ngAfterViewInit` হলো সেই মুহূর্ত যখন ঘর সাজানো শেষ এবং আপনি রিমোট হাতে পেয়েছেন। তাই `@ViewChild` দিয়ে পাওয়া রেফারেন্স প্রথমবার এখানেই ব্যবহার করা নিরাপদ।
3.  **`playVideo()` এবং `pauseVideo()`**: এই মেথডগুলো `this.videoPlayerRef`-এর মাধ্যমে সরাসরি চাইল্ড কম্পোনেন্টের `play()` এবং `pause()` মেথডকে কল করছে, ঠিক যেমন রিমোটের বাটন চাপলে টিভির ফাংশন কাজ করে।

### কখন ব্যবহার করবেন?

1.  **চাইল্ডের মেথড কল করতে:** যেমন, একটি কাস্টম ফর্ম কন্ট্রোলের `reset()` মেথড কল করা।
2.  **চাইল্ডের প্রপার্টি পড়তে:** যেমন, চাইল্ড কম্পোনেন্টে কোনো calculation-এর রেজাল্ট প্যারেন্ট থেকে দেখতে চাওয়া।
3.  **সরাসরি DOM এলিমেন্ট অ্যাক্সেস করতে:** যেমন, একটি `<input>` এলিমেন্টকে ফোকাস করার জন্য (`@ViewChild('myInput') myInputRef: ElementRef;` ব্যবহার করে)।

আশা করি, টিভির রিমোটের এই উপমাটি `@ViewChild`-এর কাজকে একদম পরিষ্কার করে দিয়েছে।


# ====== @ViewChildren =======

চমৎকার!既然 আপনি `@ViewChild` (একটি টিভির রিমোট) বুঝে গেছেন, `@ViewChildren` বোঝা আরও সহজ হবে। এটা হলো একই ধারণার একটি বহুবচন বা plural form।

### সহজ উপমা: ক্লাসের শিক্ষক এবং ছাত্রছাত্রীরা

আগের উপমায়, `@ViewChild` ছিল একটি নির্দিষ্ট টিভির জন্য একটি রিমোট।

এখন ভাবুন, আপনি একজন **শিক্ষক (Parent Component)** এবং আপনার সামনে একটি **ক্লাসরুম (Template)** আছে। ক্লাসরুমে অনেক **ছাত্রছাত্রী (Child Components)** বসে আছে।

*   **`@ViewChild`**: এটা হলো特定の কোনো ছাত্রকে নাম ধরে ডাকা। যেমন: "করিম, তুমি দাঁড়াও!"। আপনি শুধুমাত্র একজনকে কন্ট্রোল করছেন।

*   **`@ViewChildren`**: এটা হলো ক্লাসের **সব ছাত্রছাত্রীকে** বা একটি নির্দিষ্ট সারির **সব ছাত্রছাত্রীকে** একসাথে কোনো নির্দেশ দেওয়া। যেমন: "সবাই বই খোলো!" বা "প্রথম সারির সবাই দাঁড়াও!"।

`@ViewChildren` আপনাকে একটি ছাত্রের রেফারেন্স দেয় না, বরং একাধিক ছাত্রের একটি **রস্টার খাতা বা লিস্ট (`QueryList`)** এনে দেয়। আপনি সেই লিস্ট ধরে প্রত্যেককে একই নির্দেশ দিতে পারেন।

**মূল কথা:** `@ViewChildren` ব্যবহার করে একটি প্যারেন্ট কম্পোনেন্ট তার টেমপ্লেটের ভেতরের **একাধিক** চাইল্ড কম্পোনেন্ট বা DOM এলিমেন্টের একটি লিস্ট পায় এবং তাদের সবাইকে একসাথে কন্ট্রোল করতে পারে।

### কোড উদাহরণ (Code Example)

আমরা একটি `SlideComponent` (Child) বানাব। এরপর `AppComponent` (Parent) এর মধ্যে একাধিক স্লাইড রেখে "Play All" ও "Pause All" বাটন দিয়ে সবগুলো স্লাইডকে একসাথে কন্ট্রোল করব।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট তৈরি (`slide.component.ts`)

এটা হলো আমাদের ক্লাসের একজন "ছাত্র"। তার নিজস্ব কিছু ক্ষমতা আছে।

```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-slide',
  template: '<h4>{{ title }}: <span style="color: blue;">{{ status }}</span></h4>'
})
export class SlideComponent {
  @Input() title: string;
  status: string = 'Paused';

  play() {
    this.status = 'Playing... ▶️';
  }

  pause() {
    this.status = 'Paused ⏸️';
  }
}
```
**ব্যাখ্যা:**
প্রতিটি স্লাইডের `play()` এবং `pause()` মেথড আছে, যা প্যারেন্ট থেকে কল করা যাবে।

#### ধাপ ২: প্যারেন্ট কম্পোনেন্টে `@ViewChildren` ব্যবহার করা

এটা হলো "শিক্ষক", যিনি সব "ছাত্রদের" (স্লাইড) কন্ট্রোল করবেন।

**`app.component.html` (ক্লাসরুম):**
```html
<h1>আমি Parent (শিক্ষক)</h1>
<p>আমার ক্লাসে এই স্লাইডগুলো আছে:</p>

<!-- এখানে একাধিক স্লাইডকে একই টেমপ্লেট রেফারেন্স (#slide) দেওয়া হয়েছে -->
<app-slide #slide title="স্লাইড ১"></app-slide>
<app-slide #slide title="স্লাইড ২"></app-slide>
<app-slide #slide title="স্লাইড ৩"></app-slide>

<hr>

<!-- এই বাটনগুলো দিয়ে শিক্ষক সবাইকে নির্দেশ দেবেন -->
<button (click)="playAllSlides()">Play All</button>
<button (click)="pauseAllSlides()">Pause All</button>
```
**ব্যাখ্যা:**
এখানে আসল জাদুটা হলো `#slide`। আমরা একাধিক এলিমেন্টকে একই টেমপ্লেট রেফারেন্স ভেরিয়েবল দিয়েছি। `@ViewChildren` এই নামের সব এলিমেন্টকে খুঁজে বের করবে।

**`app.component.ts` (শিক্ষকের নির্দেশ):**
```typescript
import { Component, ViewChildren, QueryList, AfterViewInit } from '@angular/core';
import { SlideComponent } from './slide.component';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent implements AfterViewInit {

  // --- @ViewChildren এর ব্যবহার ---
  // '#slide' নামের সব চাইল্ড কম্পোনেন্টের একটি লিস্ট slidesList প্রপার্টিতে রাখো।
  @ViewChildren('slide') slidesList: QueryList<SlideComponent>;

  // ভিউ তৈরি হওয়ার পর এই লিস্ট পাওয়া যাবে।
  ngAfterViewInit() {
    console.log('সবগুলো স্লাইডের লিস্ট পাওয়া গেছে:', this.slidesList);
    // this.slidesList একটি অ্যারের মতো, কিন্তু এটি একটি QueryList অবজেক্ট।
  }

  playAllSlides() {
    console.log('সবাইকে Play করার নির্দেশ দেওয়া হলো।');
    // লিস্টের প্রত্যেকটি আইটেমের উপর লুপ চালিয়ে play() মেথড কল করা হচ্ছে।
    this.slidesList.forEach(currentSlide => currentSlide.play());
  }

  pauseAllSlides() {
    console.log('সবাইকে Pause করার নির্দেশ দেওয়া হলো।');
    this.slidesList.forEach(currentSlide => currentSlide.pause());
  }
}
```
**ব্যাখ্যা:**
1.  **`@ViewChildren('slide') slidesList: QueryList<SlideComponent>;`**:
    *   `@ViewChildren` ডেকোরেটরকে বলা হচ্ছে, "HTML-এর মধ্যে যতগুলো `#slide` নামের এলিমেন্ট আছে, তাদের সবাইকে খুঁজে বের করো।"
    *   ফলাফল হিসেবে একটি `QueryList` পাওয়া যায়, যা `slidesList` ভেরিয়েবলের মধ্যে রাখা হয়। `QueryList` একটি বিশেষ ধরনের লিস্ট যা DOM-এর পরিবর্তনের সাথে সাথে নিজে থেকেই আপডেট হয় (যেমন, নতুন স্লাইড যোগ হলে লিস্টে চলে আসবে)।
2.  **`playAllSlides()`**:
    *   এই মেথডটি `this.slidesList`-এর উপর `forEach` লুপ চালায়।
    *   লুপের ভেতরে প্রতিটি `currentSlide` (যা `SlideComponent`-এর একটি ইনস্ট্যান্স) এর `play()` মেথডকে কল করা হয়। ফলে সবগুলো স্লাইড একসাথে প্লে হওয়া শুরু করে। `pauseAllSlides()`-ও একইভাবে কাজ করে।

### `@ViewChild` বনাম `@ViewChildren`

| বৈশিষ্ট্য | `@ViewChild` | `@ViewChildren` |
| :--- | :--- | :--- |
| **কী খুঁজে বের করে** | একটি মাত্র এলিমেন্ট বা কম্পোনেন্ট। | একাধিক এলিমেন্ট বা কম্পোনেন্ট। |
| **কী রিটার্ন করে** | সরাসরি সেই কম্পোনেন্টের রেফারেন্স। | `QueryList` (কম্পোনেন্টগুলোর একটি লিস্ট)। |
| **উদাহরণ** | একটি নির্দিষ্ট টিভির রিমোট। | ক্লাসের সব ছাত্রের রস্টার খাতা। |
| **কখন ব্যবহার করবেন**| যখন একটি নির্দিষ্ট চাইল্ডকে কন্ট্রোল করতে হবে। | যখন একই ধরনের একাধিক চাইল্ডকে একসাথে কন্ট্রোল করতে হবে। |

### কখন ব্যবহার করবেন?

*   একটি ক্যারোসেলের (Carousel) সবগুলো স্লাইড ম্যানেজ করতে।
*   একটি ট্যাব গ্রুপের সবগুলো ট্যাবকে কন্ট্রোল করতে।
*   একটি লিস্টের সবগুলো আইটেমকে একসাথে সিলেক্ট বা আনসিলেক্ট করতে।
*   ফর্মের মধ্যে কাস্টম ভ্যালিডেশনের জন্য একাধিক কন্ট্রোল অ্যাক্সেস করতে।


# ==== @ContentChild ======

চমৎকার প্রশ্ন! `@ViewChild`-এর সাথে `@ContentChild`-এর পার্থক্যটা বোঝা খুবই জরুরি। চলুন, এটার জন্যও একটা সহজ উপমা ব্যবহার করি।

### সহজ উপমা: ছবির ফ্রেম (Picture Frame)

`@ViewChild` এবং `@ContentChild` 둘とも "খোঁজা"র কাজ করে, কিন্তু তারা ভিন্ন জায়গায় খোঁজে।

1.  **`@ViewChild` (ফ্রেমের নিজের অংশ খোঁজা):**
    ধরুন, আপনার কাছে একটি **ছবির ফ্রেম** আছে (`<app-picture-frame>`)। এই ফ্রেমের পেছনে একটি **স্ট্যান্ড** লাগানো আছে, যেটা ফ্রেমের সাথেই তৈরি হয়েছে।
    `@ViewChild` হলো সেই ক্ষমতা যা দিয়ে ছবির ফ্রেমটি তার **নিজের ভেতরের অংশ** (যেমন: ওই স্ট্যান্ডটা) খুঁজে বের করতে পারে। কারণ স্ট্যান্ডটা ফ্রেমের নিজস্ব টেমপ্লেটের অংশ।

2.  **`@ContentChild` (ফ্রেমের ভেতরে রাখা জিনিস খোঁজা):**
    এখন, আপনি ওই ফ্রেমের ভেতরে একটি **ছবি** রাখলেন। এই ছবিটা কিন্তু ফ্রেমের অংশ নয়। এটা আপনি **বাইরে থেকে এনে ফ্রেমের ভেতরে দিয়েছেন**।
    `@ContentChild` হলো সেই ক্ষমতা যা দিয়ে ছবির ফ্রেমটি তার ভেতরে **বাইরে থেকে দেওয়া জিনিসটা (ছবি)** খুঁজে বের করতে পারে।

এই "বাইরে থেকে জিনিস দেওয়া"র প্রক্রিয়াটাকে Angular-এ বলা হয় **কন্টেন্ট প্রজেকশন (Content Projection)**, এবং এটা `<ng-content>` ব্যবহার করে করা হয়।

**মূল কথা:**
*   **`@ViewChild`**: কম্পোনেন্ট তার **নিজের** Template (`.html` ফাইল)-এর ভেতরের এলিমেন্ট খোঁজে।
*   **`@ContentChild`**: কম্পোনেন্ট তার `<ng-content>` স্লটের ভেতরে **বাইরে থেকে পাঠানো (projected)** এলিমেন্ট খোঁজে।

### কোড উদাহরণ (Code Example)

আমরা একটি `CardComponent` (ছবির ফ্রেম) বানাব, যা একটি কন্টেইনার হিসেবে কাজ করবে। প্যারেন্ট কম্পোনেন্ট এই কার্ডের ভেতরে একটি বাটন (ছবি) পাঠাবে। `CardComponent` `@ContentChild` ব্যবহার করে সেই বাটনটিকে খুঁজে বের করবে এবং তার সাথে ইন্টারেক্ট করবে।

#### ধাপ ১: একটি ডিরেক্টিভ তৈরি (এটা দিয়ে আমরা বাটনকে চিহ্নিত করব)

এই ডিরেক্টিভটি শুধু একটি মার্কার বা লেবেল হিসেবে কাজ করবে, যাতে `@ContentChild` সহজেই বাটনটিকে খুঁজে পায়।

**`card-button.directive.ts`:**
```typescript
import { Directive } from '@angular/core';

@Directive({
  selector: '[cardButton]' // আমরা এই এট্রিবিউট দিয়ে বাটনকে খুঁজব
})
export class CardButtonDirective {
  constructor() { }
  // এই ডিরেক্টিভে আমরা কোনো লজিক রাখছি না, শুধু মার্কার হিসেবে ব্যবহার করছি।
}
```

#### ধাপ ২: চাইল্ড/র‍্যাপার কম্পোনেন্ট তৈরি (`card.component.ts`)

এটা হলো আমাদের "ছবির ফ্রেম"। এর ভেতরে একটি `<ng-content>` স্লট থাকবে।

```typescript
import { Component, ContentChild, AfterContentInit } from '@angular/core';
import { CardButtonDirective } from './card-button.directive';

@Component({
  selector: 'app-card',
  template: `
    <div class="card">
      <div class="card-header">
        Card Header
      </div>
      <div class="card-body">
        <!-- এই <ng-content> হলো সেই "খালি জায়গা" যেখানে বাইরে থেকে কন্টেন্ট আসবে -->
        <ng-content></ng-content>
      </div>
      <div class="card-footer">
        <!-- এই বাটনটি কার্ডের নিজের, তাই একে @ViewChild দিয়ে পাওয়া যাবে -->
        <button (click)="highlightProjectedButton()">Highlight the Projected Button</button>
      </div>
    </div>
  `,
  styles: [`.card { border: 1px solid #ccc; border-radius: 5px; padding: 10px; }`]
})
export class CardComponent implements AfterContentInit {

  // --- @ContentChild এর ব্যবহার ---
  // <ng-content>-এর ভেতরে 'cardButton' ডিরেক্টিভসহ কোনো এলিমেন্ট আছে কিনা খোঁজো।
  @ContentChild(CardButtonDirective, { read: ElementRef }) projectedButtonRef: ElementRef;

  constructor() { }

  // ngAfterViewInit এর মতো, ngAfterContentInit তখনই চলে যখন projected content লোড হয়ে যায়।
  ngAfterContentInit() {
    if (this.projectedButtonRef) {
      console.log('বাইরে থেকে পাঠানো বাটনটি পাওয়া গেছে:', this.projectedButtonRef.nativeElement);
    } else {
      console.log('বাইরে থেকে কোনো বাটন পাঠানো হয়নি।');
    }
  }

  highlightProjectedButton() {
    if (this.projectedButtonRef) {
      // আমরা সরাসরি projected content-এর স্টাইল পরিবর্তন করছি
      this.projectedButtonRef.nativeElement.style.backgroundColor = 'yellow';
    }
  }
}
```

**ব্যাখ্যা:**
*   **`<ng-content>`**: এটাই সেই "স্লট" বা খালি জায়গা। প্যারেন্ট কম্পোনেন্ট `<app-card>` ট্যাগের ভেতরে যা কিছু লিখবে, তা এই `ng-content`-এর জায়গায় দেখাবে।
*   **`@ContentChild(CardButtonDirective, ...)`**: আমরা Angular-কে বলছি, "প্রজেক্ট করা কন্টেন্টের মধ্যে `CardButtonDirective` আছে এমন এলিমেন্টকে খোঁজো।"
*   **`ngAfterContentInit`**: `@ViewChild`-এর জন্য যেমন `ngAfterViewInit` ব্যবহার হয়, `@ContentChild`-এর জন্য `ngAfterContentInit` ব্যবহার করা নিরাপদ। কারণ এই lifecycle hook-এর সময়েই projected content পুরোপুরিভাবে লোড হয়।

#### ধাপ ৩: প্যারেন্ট কম্পোনেন্টে ব্যবহার (`app.component.html`)

এবার আমরা `CardComponent` (ফ্রেম) ব্যবহার করব এবং তার ভেতরে একটি বাটন (ছবি) পাঠাব।

```html
<h1>@ContentChild Example</h1>

<!-- এই <app-card> এর ভেতরে আমরা একটি বাটন প্রজেক্ট করছি -->
<app-card>
  <!-- এই বাটনটি app.component.html এর অংশ, card.component.html এর নয় -->
  <!-- 'cardButton' ডিরেক্টিভটি এখানে ব্যবহার করা হয়েছে -->
  <button cardButton>Projected Action Button</button>
  <p>This is some other projected content.</p>
</app-card>

<hr>

<!-- এই <app-card> এর ভেতরে আমরা কোনো বাটন পাঠাচ্ছি না -->
<app-card>
  <p>This card has no special button.</p>
</app-card>
```

### ফলাফল

1.  **প্রথম কার্ডে:**
    *   `CardComponent` তার `ngAfterContentInit`-এ `projectedButtonRef` খুঁজে পাবে এবং কনসোলে লগ করবে।
    *   আপনি যখন কার্ডের ভেতরের "Highlight..." বাটনে ক্লিক করবেন, তখন `CardComponent` `@ContentChild` দিয়ে পাওয়া রেফারেন্স ব্যবহার করে বাইরে থেকে পাঠানো বাটনটির الخلفية হলুদ করে দেবে।
2.  **দ্বিতীয় কার্ডে:**
    *   যেহেতু কোনো বাটন প্রজেক্ট করা হয়নি, `projectedButtonRef` `undefined` থাকবে এবং কনসোলে সেই মেসেজটি দেখাবে।

### `@ViewChild` বনাম `@ContentChild`

| বৈশিষ্ট্য | `@ViewChild` / `@ViewChildren` | `@ContentChild` / `@ContentChildren` |
| :--- | :--- | :--- |
| **কোথায় খোঁজে?** | কম্পোনেন্টের **নিজের** টেমপ্লেটে। | কম্পোনেন্টের `<ng-content>` স্লটের ভেতরে। |
| **কী খোঁজে?** | কম্পোনেন্টের নিজস্ব কন্টেন্ট। | **বাইরে থেকে প্রজেক্ট করা** কন্টেন্ট। |
| **উপমা** | ছবির ফ্রেম তার **নিজের স্ট্যান্ড** খুঁজছে। | ছবির ফ্রেম তার ভেতরে রাখা **ছবিটি** খুঁজছে। |
| **Lifecycle Hook** | `ngAfterViewInit` | `ngAfterContentInit` |

### কখন ব্যবহার করবেন?

যখন আপনি এমন Reusable Wrapper কম্পোনেন্ট তৈরি করছেন (যেমন: Card, Modal, Tab, Accordion) এবং আপনি চান যে আপনার Wrapper কম্পোনেন্টটি বাইরে থেকে পাঠানো কন্টেন্টের সাথে ইন্টারেক্ট করুক বা তাদের সম্পর্কে জানুক।


# ===== @ContentChildren =======

খুবই ভালো! আপনি Angular-এর একটি অন্যতম শক্তিশালী ডেকোরেটর সম্পর্কে জানতে চাইছেন। `@ContentChild`-এর ছবির ফ্রেমের উপমাটি মনে আছে? `@ContentChildren` হলো ঠিক তারই বহুবচন (plural) সংস্করণ।

### সহজ উপমা: ছবির গ্যালারি (Photo Gallery)

আগের উপমায়, `@ContentChild` ছিল একটি ছবির ফ্রেম, যা তার ভেতরে রাখা **একটি মাত্র ছবিকে** খুঁজে বের করতে পারত।

এখন, `@ContentChildren`-কে একটি বড় **"ছবির গ্যালারি"** বা **"ফটো অ্যালবাম"** হিসেবে ভাবুন (`<app-photo-gallery>`)।

এই গ্যালারিতে আপনি **একাধিক ছবি** রাখতে পারেন। ছবিগুলো আপনি **বাইরে থেকে** এনে গ্যালারির ভেতরে সাজিয়ে রাখছেন।

`@ContentChildren` হলো সেই গ্যালারির ক্ষমতা, যা দিয়ে সে তার ভেতরে রাখা **সবগুলো ছবিকে** খুঁজে বের করে একটি **লিস্ট** তৈরি করতে পারে। এরপর গ্যালারিটি সেই লিস্টের উপর ভিত্তি করে বিভিন্ন কাজ করতে পারে। যেমন:
*   কতগুলো ছবি আছে তা গণনা করা।
*   সবগুলো ছবির উপর একসাথে একটি বর্ডার যুক্ত করা।
*   একটি ছবি দেখালে বাকিগুলোকে লুকিয়ে রাখা।

**মূল কথা:**
*   **`@ContentChild`**: `<ng-content>`-এর ভেতরে বাইরে থেকে পাঠানো **একটি** এলিমেন্টকে খোঁজে।
*   **`@ContentChildren`**: `<ng-content>`-এর ভেতরে বাইরে থেকে পাঠানো **একাধিক** এলিমেন্টকে খুঁজে তাদের একটি লিস্ট (`QueryList`) তৈরি করে।

### কোড উদাহরণ: একটি ট্যাব সিস্টেম (Tab System)

ট্যাব সিস্টেম `@ContentChildren`-এর একটি ক্লাসিক এবং পারফেক্ট উদাহরণ। আমরা একটি `TabGroupComponent` (গ্যালারি) বানাব এবং এর ভেতরে একাধিক `TabComponent` (ছবি) প্রজেক্ট করব।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট তৈরি (`tab.component.ts`)

এটা হলো আমাদের "ছবি" বা একটি একক ট্যাব।

```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-tab',
  template: `
    <!-- এই কন্টেন্টটি শুধু তখনই দেখাবে যখন active = true -->
    <div [hidden]="!active">
      <ng-content></ng-content>
    </div>
  `
})
export class TabComponent {
  @Input() tabTitle: string = '';
  active: boolean = false;
}
```
**ব্যাখ্যা:**
প্রতিটি ট্যাবের একটি `tabTitle` থাকবে এবং একটি `active` অবস্থা থাকবে। `active` হলেই কেবল ট্যাবের ভেতরের কন্টেন্ট দেখা যাবে।

#### ধাপ ২: র‍্যাপার কম্পোনেন্ট তৈরি (`tab-group.component.ts`)

এটা হলো আমাদের "গ্যালারি" বা `TabGroup`, যা সবগুলো ট্যাবকে ম্যানেজ করবে।

```typescript
import { Component, ContentChildren, QueryList, AfterContentInit } from '@angular/core';
import { TabComponent } from './tab.component';

@Component({
  selector: 'app-tab-group',
  template: `
    <div class="tab-group">
      <!-- (১) এখানে আমরা ট্যাবগুলোর টাইটেল দেখাব -->
      <ul class="tab-headers">
        <li *ngFor="let tab of tabs" 
            (click)="selectTab(tab)"
            [class.active]="tab.active">
          {{ tab.tabTitle }}
        </li>
      </ul>

      <!-- (২) এখানে বাইরে থেকে পাঠানো <app-tab> গুলো রেন্ডার হবে -->
      <div class="tab-body">
        <ng-content></ng-content>
      </div>
    </div>
  `,
  styleUrls: ['./tab-group.component.css']
})
export class TabGroupComponent implements AfterContentInit {

  // --- @ContentChildren এর ব্যবহার ---
  // <ng-content>-এর ভেতরে যতগুলো <app-tab> কম্পোনেন্ট পাঠানো হয়েছে, তাদের সবাইকে খুঁজে বের করো।
  @ContentChildren(TabComponent) tabs: QueryList<TabComponent>;

  // কন্টেন্ট লোড হওয়ার পর এই মেথডটি চলবে
  ngAfterContentInit() {
    // ডিফল্টভাবে প্রথম ট্যাবটিকে active করে দাও
    if (this.tabs.length > 0) {
      this.selectTab(this.tabs.first);
    }
  }

  // কোনো ট্যাবের হেডারে ক্লিক করলে এই মেথডটি কল হবে
  selectTab(tabToSelect: TabComponent) {
    // প্রথমে সব ট্যাবকে inactive করে দাও
    this.tabs.forEach(tab => tab.active = false);

    // তারপর শুধুমাত্র সিলেক্ট করা ট্যাবটিকে active করো
    tabToSelect.active = true;
  }
}
```

**ব্যাখ্যা:**
1.  **`@ContentChildren(TabComponent) tabs: QueryList<TabComponent>;`**: এটাই আসল জাদু। `TabGroupComponent` তার `<ng-content>`-এর ভেতরে প্রজেক্ট করা সবগুলো `TabComponent`-এর একটি `QueryList` পেয়ে যাচ্ছে `tabs` প্রপার্টিতে।
2.  **`ngAfterContentInit()`**: কন্টেন্ট লোড হয়ে যাওয়ার পর, আমরা `tabs` লিস্টের প্রথম আইটেমটিকে ডিফল্ট হিসেবে সিলেক্ট করে দিচ্ছি।
3.  **`selectTab(tabToSelect)`**: এই মেথডটি `tabs` লিস্টের উপর লুপ চালিয়ে সব ট্যাবকে প্রথমে `inactive` করে, তারপর যেটিতে ক্লিক করা হয়েছে শুধু সেটিকে `active` করে। `TabGroup` নিজেই তার ভেতরের কন্টেন্টকে ম্যানেজ করছে!

#### ধাপ ৩: প্যারেন্ট কম্পোনেন্টে ব্যবহার (`app.component.html`)

এবার আমরা `TabGroupComponent` ব্যবহার করব এবং তার ভেতরে কয়েকটি `TabComponent` প্রজেক্ট করব।

```html
<h1>@ContentChildren Example: Tab System</h1>

<app-tab-group>

  <!-- প্রথম ট্যাব -->
  <app-tab tabTitle="প্রোফাইল">

    <p>এখানে ব্যবহারকারীর বিস্তারিত তথ্য থাকবে।</p>
  </app-tab>

  <app-tab tabTitle="সেটিংস">

    <p>এখানে পাসওয়ার্ড পরিবর্তন বা অন্যান্য সেটিংস থাকবে।</p>
  </app-tab>

  </app-tab>
```

### ফলাফল

আপনি ব্রাউজারে একটি সম্পূর্ণ কার্যকরী ট্যাব সিস্টেম দেখতে পাবেন। যখন আপনি "প্রোফাইল", "সেটিংস", বা "সাহায্য" হেডারে ক্লিক করবেন, তখন `TabGroupComponent` `@ContentChildren` দিয়ে পাওয়া লিস্ট ব্যবহার করে সঠিক ট্যাবটির কন্টেন্ট দেখাবে এবং বাকিগুলো লুকিয়ে রাখবে।

### `@ContentChild` বনাম `@ContentChildren`

| বৈশিষ্ট্য | `@ContentChild` | `@ContentChildren` |
| :--- | :--- | :--- |
| **কী খুঁজে বের করে** | একটি মাত্র প্রজেক্টেড এলিমেন্ট। | একাধিক প্রজেক্টেড এলিমেন্ট। |
| **কী রিটার্ন করে** | সরাসরি সেই এলিমেন্টের রেফারেন্স। | `QueryList` (এলিমেন্টগুলোর একটি লিস্ট)। |
| **উপমা** | ছবির ফ্রেম তার ভেতরের **একটি ছবি** খুঁজছে। | ছবির গ্যালারি তার ভেতরের **সবগুলো ছবি** খুঁজছে। |
| **কখন ব্যবহার করবেন**| যখন একটি নির্দিষ্ট প্রজেক্টেড এলিমেন্টকে টার্গেট করতে হয়। | যখন একই ধরনের একাধিক প্রজেক্টেড এলিমেন্টকে একসাথে ম্যানেজ করতে হয় (Tabs, Accordion, Stepper)। |

# === @Inject ====

অবশ্যই! `@Inject` ডেকোরেটরটি একটু অন্যরকম, কিন্তু এর পেছনের ধারণাটা খুবই সহজ।

### সহজ উপমা: বিশেষ চাবি (Special Key)

সাধারণত, Angular-এর Dependency Injection (DI) সিস্টেম কীভাবে কাজ করে?

আপনি যখন কোনো সার্ভিসের প্রয়োজন হয়, তখন `constructor`-এ তার **টাইপ (Type)** বলে দেন:
`constructor(private authService: AuthService) {}`

এটা অনেকটা একটা দোকানে গিয়ে বলার মতো: "আমাকে একটা **কোকাকোলা** দিন।" দোকানদার জানে "কোকাকোলা" কী, তাই সে আপনাকে সঠিক জিনিসটা দিতে পারে। এখানে `AuthService` হলো "কোকাকোলা"-র মতো একটি পরিচিত টাইপ।

**কিন্তু সমস্যাটা কখন হয়?**

ধরুন, আপনি দোকানে গিয়ে বললেন: "আমাকে একটা **স্ট্রিং (string)** দিন।"
দোকানদার বিভ্রান্ত হয়ে যাবে। কোন স্ট্রিং? দোকানের নাম? ঠিকানা? নাকি কোনো গোপন বার্তা? কারণ "স্ট্রিং" কোনো নির্দিষ্ট জিনিস নয়।

Angular-এর DI সিস্টেমও ঠিক একইভাবে বিভ্রান্ত হয় যখন আপনি কোনো primitive type (like `string`, `number`) বা কোনো সাধারণ অবজেক্ট ইনজেক্ট করতে চান। সে জানে না কোন স্ট্রিং বা কোন অবজেক্ট দিতে হবে।

**`@Inject` হলো সেই সমস্যার সমাধান।**

`@Inject` হলো একটি **"বিশেষ চাবি"** বা **"গোপন কোড"**। আপনি আর শুধু টাইপ দিয়ে কিছু চাইছেন না, বরং একটি নির্দিষ্ট চাবি দিয়ে লকার খোলার মতো করে বলছেন: "আমাকে 'API_URL' নামের চাবি দিয়ে যে জিনিসটা রাখা আছে, সেটা দিন।"

এই "বিশেষ চাবি" বা "গোপন কোড" টিকে Angular-এ বলা হয় **`InjectionToken`**।

**মূল কথা:** যখন কোনো dependency-কে তার Type দিয়ে eindeutigভাবে চেনা যায় না, তখন আমরা একটি `InjectionToken` (চাবি) তৈরি করি এবং `@Inject` ডেকোরেটর ব্যবহার করে সেই চাবি দিয়ে dependency-টি চাই।

---

### কোড উদাহরণ: API URL ইনজেক্ট করা

সাধারণত, একটি অ্যাপের API URL সব জায়গায় একই থাকে। এই URL-টি একটি `string`, যা আমরা সরাসরি কোনো সার্ভিসে ইনজেক্ট করতে চাই।

#### ধাপ ১: "বিশেষ চাবি" তৈরি করা (`app.tokens.ts`)

প্রথমে আমরা আমাদের `InjectionToken` বা চাবিটি তৈরি করব। এটা সাধারণত একটি আলাদা ফাইলে রাখা হয়।

```typescript
import { InjectionToken } from '@angular/core';

// আমরা একটি InjectionToken তৈরি করছি। এটি একটি স্ট্রিং ভ্যালু ধারণ করবে।
// 'API_URL' হলো শুধু একটি বর্ণনামূলক নাম, ডিবাগিং-এর জন্য।
export const API_URL_TOKEN = new InjectionToken<string>('API_URL');
```
**ব্যাখ্যা:**
`API_URL_TOKEN` হলো আমাদের সেই "বিশেষ চাবি"।

#### ধাপ ২: চাবির সাথে ভ্যালু যুক্ত করা (Provide the Value)

এবার আমাদের Angular-কে বলে দিতে হবে যে, কেউ যদি এই চাবি দিয়ে কিছু চায়, তাহলে তাকে কোন ভ্যালুটি দিতে হবে। এই কাজটি আমরা মডিউলের `providers` অ্যারেতে করি।

**`app.module.ts`:**
```typescript
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { AppComponent } from './app.component';
import { DataService } from './data.service';
import { API_URL_TOKEN } from './app.tokens'; // আমাদের টোকেন ইম্পোর্ট করলাম

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule],
  providers: [
    DataService,
    // এখানে আমরা Angular-কে বলছি:
    // "যখন কেউ API_URL_TOKEN চাবিটি ব্যবহার করবে,
    // তখন তাকে 'https://api.myawesomeapp.com' এই ভ্যালুটি দেবে।"
    { provide: API_URL_TOKEN, useValue: 'https://api.myawesomeapp.com' }
  ],
  bootstrap: [AppComponent]
})
export class AppModule { }
```

#### ধাপ ৩: `@Inject` ব্যবহার করে ভ্যালুটি গ্রহণ করা

এখন `DataService`-এ আমরা টাইপ দিয়ে নয়, বরং আমাদের "বিশেষ চাবি" দিয়ে API URL-টি চাইব।

**`data.service.ts`:**
```typescript
import { Injectable, Inject } from '@angular/core';
import { API_URL_TOKEN } from './app.tokens'; // আমাদের টোকেন ইম্পোর্ট করলাম

@Injectable()
export class DataService {

  // --- @Inject এর ব্যবহার ---
  // এখানে আমরা বলছি: "আমাকে API_URL_TOKEN চাবি দিয়ে যে ভ্যালুটি রেজিস্টার করা আছে, সেটি দাও।"
  constructor(@Inject(API_URL_TOKEN) private apiUrl: string) {
    console.log('API URL received via @Inject:', this.apiUrl);
  }

  fetchData() {
    // এখন আমরা apiUrl ব্যবহার করতে পারি
    console.log(`Fetching data from ${this.apiUrl}/users`);
    // return this.http.get(`${this.apiUrl}/users`);
  }
}
```

**ফলাফল:**
যখন `DataService` তৈরি হবে, তার `constructor`-এ `apiUrl` প্রপার্টির ভ্যালু হিসেবে `'https://api.myawesomeapp.com'` চলে আসবে, কারণ `@Inject(API_URL_TOKEN)` ডেকোরেটরটি Angular-কে সঠিক ভ্যালুটি খুঁজে বের করতে সাহায্য করেছে।

### `@Injectable` বনাম `@Inject`

এই দুটি ডেকোরেটরের মধ্যে পার্থক্য বোঝা খুব জরুরি।

| বৈশিষ্ট্য | `@Injectable` | `@Inject` |
| :--- | :--- | :--- |
| **কী ধরনের ডেকোরেটর?**| **Class Decorator** (ক্লাসের উপরে বসে)। | **Parameter Decorator** (`constructor`-এর প্যারামিটারের আগে বসে)। |
| **কী কাজ করে?** | একটি ক্লাসকে Dependency Injection সিস্টেমের জন্য **উপলব্ধ** করে। এটি বলে, "এই ক্লাসটিকে ইনজেক্ট করা যেতে পারে।" | `constructor`-এর ভেতরে নির্দিষ্ট করে দেয় যে **কোন** dependency-টি ইনজেক্ট করতে হবে, বিশেষ করে যখন টাইপ যথেষ্ট নয়। |
| **উপমা** | একটি সার্ভিসকে "দোকানের তাক"-এ রাখা, যাতে ক্রেতারা নিতে পারে। | একটি বিশেষ "প্রোডাক্ট কোড" বা "চাবি" দিয়ে তাক থেকে সঠিক জিনিসটি চাওয়া। |

সহজ কথায়, `@Injectable` একটি ক্লাসকে ইনজেকশনের জন্য তৈরি করে, আর `@Inject` সেই ইনজেকশন প্রক্রিয়াটিকে আরও সুনির্দিষ্ট (specific) করে তোলে।

### কখন ব্যবহার করবেন?
1.  **Primitive Values ইনজেক্ট করতে:** `string`, `number`, `boolean`।
2.  **কনফিগারেশন অবজেক্ট ইনজেক্ট করতে:** যেমন `AppConfig` অবজেক্ট।
3.  যখন একই টাইপের একাধিক প্রোভাইডার থাকে এবং আপনাকে তাদের মধ্যে একটি নির্দিষ্ট প্রোভাইডার বেছে নিতে হয়।

# =======  @Host ===========

অবশ্যই! `@Host` ডেকোরেটরটি Dependency Injection (DI) এর একটি খুব নির্দিষ্ট এবং শক্তিশালী ফিচার। এর কাজ বুঝতে হলে আমাদের DI সিস্টেম কীভাবে খোঁজে (resolution) সেটা আগে জানতে হবে।

### সহজ উপমা: পরিবারের মধ্যে সাহায্য খোঁজা

ভাবুন, Angular-এর কম্পোনেন্ট ট্রি (component tree) একটি **বংশ বা পরিবার**।

*   **`AppComponent` (Root)**: পরিবারের সবচেয়ে বয়স্ক সদস্য (যেমন, দাদু)।
*   **`ParentComponent`**: আপনার বাবা/মা।
*   **`ChildDirective`**: আপনি নিজে (এখানে আমরা ডিরেক্টিভকে চাইল্ড ধরছি, কারণ `@Host` ডিরেক্টিভের সাথে সবচেয়ে বেশি ব্যবহৃত হয়)।

এখন, আপনার (ChildDirective) কিছু একটা দরকার (ধরা যাক, `WalletService` নামে একটি সার্ভিস)। আপনি কী করবেন?

**সাধারণ নিয়ম (Default DI):**
আপনি প্রথমে আপনার নিজের কাছে (self) খুঁজবেন। না পেলে, আপনি আপনার **বাবা/মা (`ParentComponent`)**-এর কাছে চাইবেন। তারাও যদি দিতে না পারেন, তাহলে তারা তাদের বাবা/মা অর্থাৎ আপনার **দাদু (`AppComponent`)**-এর কাছে চাইবেন। এভাবে একদম রুট পর্যন্ত খোঁজা চলতে থাকে।

**@Host এর নিয়ম:**
`@Host` ডেকোরেটরটি এই নিয়মের উপর একটি **সীমারেখা** টেনে দেয়। `@Host` ব্যবহার করার মানে হলো, আপনি বলছেন:
"আমার যা দরকার, তা আমি **শুধুমাত্র আমার বাবা/মা (`ParentComponent`)**-এর কাছেই চাইব। তারা দিতে পারলে ভালো, না পারলে আমি আর দাদুর কাছে যাব না। আমি ধরে নেব যে জিনিসটা নেই এবং একটি এরর (error) দেখাব।"

এখানে "বাবা/মা" বা Parent Component-কেই বলা হচ্ছে **হোস্ট (Host)**। একটি ডিরেক্টিভের জন্য, হোস্ট হলো সেই এলিমেন্ট বা কম্পোনেন্ট যার উপর ডিরেক্টিভটি লাগানো হয়েছে।

**মূল কথা:** নির্ভরতা (dependency) খোঁজার সময় `@Host` ডেকোরেটরটি বলে, "উপরে যেও না, শুধুমাত্র নিজের হোস্ট কম্পোনেন্টের Injector-এর মধ্যেই খোঁজো। সেখানে না পেলে থেমে যাও।"

---

### কোড উদাহরণ: একটি বিশেষ কন্ট্রোলারের অধীনে থাকা বাটন

আমরা একটি `MessageBoxComponent` (Host) বানাব, যার একটি বিশেষ `close()` মেথড থাকবে। এরপর আমরা একটি `CloseButtonDirective` বানাব, যা `@Host` ব্যবহার করে নিশ্চিত করবে যে সে শুধুমাত্র `MessageBoxComponent`-এর ভেতরেই কাজ করতে পারবে।

#### ধাপ ১: Host Component তৈরি (`message-box.component.ts`)

এই কম্পোনেন্টটি একটি সার্ভিস হিসেবে কাজ করবে তার ভেতরের ডিরেক্টিভের জন্য। লক্ষ্য করুন, আমরা কম্পোনেন্ট ক্লাসটিকেই `providers`-এ দিচ্ছি।

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-message-box',
  template: `
    <div class="message-box">
      <h3>This is a special message box!</h3>
      <p>Only buttons inside me can close me.</p>
      
      <!-- এই বাটনের উপর আমাদের ডিরেক্টিভটি বসবে -->
      <button closeButton>Close Me</button>
    </div>
  `,
  styles: [`.message-box { border: 2px solid orange; padding: 15px; }`],
  // এখানে কম্পোনেন্টটি নিজেকেই একটি প্রোভাইডার হিসেবে ঘোষণা করছে।
  // এর ভেতরের যেকোনো চাইল্ড এখন MessageBoxComponent-কে ইনজেক্ট করতে পারবে।
  providers: [{ provide: MessageBoxComponent, useExisting: MessageBoxComponent }]
})
export class MessageBoxComponent {
  
  close() {
    console.log('MESSAGE BOX IS CLOSING... (called from the host)');
    // এখানে বক্সটি hide করার লজিক থাকবে।
  }
}
```

#### ধাপ ২: Directive তৈরি (`close-button.directive.ts`)

এই ডিরেক্টিভটি `@Host` ব্যবহার করে তার হোস্টকে (`MessageBoxComponent`) খুঁজবে।

```typescript
import { Directive, HostListener, Host, Optional } from '@angular/core';
import { MessageBoxComponent } from './message-box.component';

@Directive({
  selector: '[closeButton]'
})
export class CloseButtonDirective {

  // --- @Host এর ব্যবহার ---
  // আমরা MessageBoxComponent টাইপের একটি dependency চাইছি।
  // @Host বলছে: "শুধুমাত্র এই ডিরেক্টিভের হোস্ট এলিমেন্টের Injector-এ খোঁজো।"
  // @Optional বলছে: "যদি না পাও, তাহলে এরর দিও না, null সেট করে দিও।" (Good practice)
  constructor(@Host() @Optional() private messageBox: MessageBoxComponent) {
    if (!this.messageBox) {
      // যদি MessageBoxComponent-কে হোস্ট হিসেবে না পাওয়া যায়
      console.error('[closeButton] directive must be used inside an <app-message-box>.');
    }
  }

  @HostListener('click')
  onClick() {
    if (this.messageBox) {
      console.log('Close button clicked! Calling host to close.');
      // হোস্ট কম্পোনেন্টের close() মেথডকে কল করা হচ্ছে
      this.messageBox.close();
    } else {
      console.warn('Cannot close because I am not inside a message box.');
    }
  }
}
```

#### ধাপ ৩: প্যারেন্ট কম্পোনেন্টে ব্যবহার (`app.component.html`)

এবার আমরা দেখব কোথায় এটি কাজ করে এবং কোথায় করে না।

```html
<h1>@Host Decorator Example</h1>

<!--シナリオ ১: সঠিক ব্যবহার (এটা কাজ করবে) -->

  <!-- closeButton ডিরেক্টিভটি তার হোস্ট হিসেবে MessageBoxComponent-কে পাবে -->
</app-message-box>

<hr>

<!--シナリオ ২: ভুল ব্যবহার (এটা কাজ করবে না) -->

<!-- এখানে closeButton ডিরেক্টিভটি তার হোস্ট হিসেবে MessageBoxComponent-কে পাবে না -->
```

### ফলাফল

1.  **প্রথম ক্ষেত্রে:** আপনি যখন `MessageBoxComponent`-এর ভেতরের "Close Me" বাটনে ক্লিক করবেন, কনসোলে দেখবেন:
    *   `Close button clicked! Calling host to close.`
    *   `MESSAGE BOX IS CLOSING... (called from the host)`
    এটি সফলভাবে কাজ করেছে কারণ `@Host` তার হোস্টকে (`MessageBoxComponent`) খুঁজে পেয়েছে।

2.  **দ্বিতীয় ক্ষেত্রে:** যখন পেজ লোড হবে, কনসোলে একটি এরর মেসেজ দেখাবে:
    *   `[closeButton] directive must be used inside an <app-message-box>.`
    আপনি যখন বাইরের বাটনে ক্লিক করবেন, কনসোলে একটি ওয়ার্নিং দেখবেন:
    *   `Cannot close because I am not inside a message box.`
    এটি কাজ করেনি কারণ `@Host` ডেকোরেটরটি তার হোস্টের বাইরে আর dependency খুঁজতে যায়নি।

### কখন ব্যবহার করবেন?

`@Host` ব্যবহার করা হয় যখন আপনি একটি চাইল্ড ডিরেক্টিভ বা কম্পোনেন্টকে তার প্যারেন্ট কম্পোনেন্টের সাথে **শক্তভাবে যুক্ত (tightly coupled)** করতে চান। এটি নিশ্চিত করে যে আপনার ডিরেক্টিভটি শুধুমাত্র একটি নির্দিষ্ট ধরনের প্যারেন্টের সাথেই ব্যবহৃত হবে, যা আপনার কোডকে আরও অনুমানযোগ্য (predictable) এবং সুরক্ষিত করে তোলে।

যেমন:
*   `mat-form-field`-এর ভেতরের `mat-label` বা `mat-error`।
*   `formGroup`-এর ভেতরের `formControlName` ডিরেক্টিভ।
