
অবশ্যই! আপনি যেহেতু একজন অভিজ্ঞ ডেভেলপার, আমি Angular Signal-এর মূল ধারণা এবং এর পেছনের কারণগুলো সহজভাবে বাংলাতে ব্যাখ্যা করছি, সাথে একটি সম্পূর্ণ উদাহরণও দিচ্ছি।

### Angular Signal কী?

সহজ ভাষায়, **Signal হলো state (ডেটা) ম্যানেজ করার জন্য Angular-এর একটি নতুন এবং অনেক বেশি কার্যকরী (efficient) সিস্টেম।**

এখন পর্যন্ত আমরা state ম্যানেজ করার জন্য সাধারণ variable, RxJS (যেমন `BehaviorSubject`), বা `Input()` ডেকোরেটর ব্যবহার করতাম। যখন কোনো ডেটা পরিবর্তন হতো, তখন Zone.js পুরো কম্পোনেন্ট ট্রি (component tree) চেক করে দেখত কোথায় কী পরিবর্তন হয়েছে এবং সেই অনুযায়ী DOM আপডেট করত। এই প্রক্রিয়াকে বলা হয় Change Detection।

Signal এই প্রক্রিয়াকে পুরোপুরি বদলে দিয়েছে।

**Signal-এর মূল ধারণা হলো:**
*   এটি একটি **"wrapper"** বা ধারক, যার ভেতরে আপনার ডেটা থাকে।
*   যখন Signal-এর ভেতরের ডেটা পরিবর্তন হয়, তখন Signal নিজে থেকেই Angular-কে জানিয়ে দেয়, "আমার মান পরিবর্তন হয়েছে।"
*   Angular তখন শুধুমাত্র সেই নির্দিষ্ট জায়গাটিই আপডেট করে, যেখানে ওই Signal ব্যবহার করা হয়েছে। পুরো কম্পোনেন্ট ট্রি চেক করার প্রয়োজন হয় না।

একেই বলা হয় **Fine-grained Reactivity**। এর ফলে অ্যাপ্লিকেশনের পারফরম্যান্স বহুগুণে বেড়ে যায়।

### Signal-এর প্রধান তিনটি অংশ

Signal ইকোসিস্টেমে মূলত তিনটি জিনিস আছে:

#### 1. `signal()` - The Source of Truth
এটি হলো মূল state বা ডেটা রাখার জায়গা।

*   **তৈরি করা (Create):** `const mySignal = signal('initial value');`
*   **মান পড়া (Read):** `mySignal()` - একে ফাংশনের মতো কল করতে হয়।
*   **মান পরিবর্তন করা (Write):**
    *   `.set(newValue)`: পুরো মান বদলে ফেলার জন্য। `mySignal.set('new value');`
    *   `.update(currentValue => ...)`: আগের মানের ওপর ভিত্তি করে নতুন মান সেট করার জন্য। `count.update(value => value + 1);`

#### 2. `computed()` - Derived Values
যখন একটি Signal-এর ওপর নির্ভর করে অন্য কোনো ডেটার মান তৈরি হয়, তখন `computed` ব্যবহার করা হয়।

*   **উদাহরণ:** আপনার কাছে `firstName` এবং `lastName` নামে দুটি Signal আছে। এদেরকে মিলিয়ে `fullName` নামে আরেকটি Signal তৈরি করতে `computed` ব্যবহার করবেন।
*   **সুবিধা:** `computed` signal শুধুমাত্র তখনই তার মান নতুন করে حساب (recalculate) করে, যখন তার ওপর নির্ভরশীল (dependent) কোনো signal-এর মান পরিবর্তন হয়। এটি lazy এবং memoized (ফলাফল মনে রাখে), যা পারফরম্যান্সের জন্য খুবই ভালো।

#### 3. `effect()` - Side Effects
যখন কোনো Signal-এর মান পরিবর্তনের ফলে আপনি UI বা state-এর বাইরে কোনো কাজ করতে চান (যেমন: console-এ লগ করা, Local Storage-এ ডেটা সেভ করা, কোনো API কল করা), তখন `effect` ব্যবহার করা হয়।

*   **গুরুত্বপূর্ণ:** `effect()` সরাসরি অন্য কোনো signal-কে আপডেট করার জন্য ব্যবহার করা উচিত নয়। এর মূল কাজ হলো বাইরের জগতের সাথে সংযোগ স্থাপন করা। এটি component render হওয়ার *পরে* রান হয়।

### কেন Signal ব্যবহার করবেন? (আপনার ১২ বছরের অভিজ্ঞতার আলোকে)

1.  **Zone.js থেকে মুক্তি:** Signal-এর মূল লক্ষ্য হলো Angular-কে Zone.js-এর ওপর থেকে নির্ভরশীলতা কমানো। Zone.js অনেক সময় পারফরম্যান্সের জন্য বাধা হয়ে দাঁড়ায়, কারণ এটি সব ধরনের asynchronous ইভেন্ট (যেমন: `setTimeout`, `fetch`, button click) ট্র্যাক করে এবং অপ্রয়োজনীয় change detection চালু করে। Signal-এর মাধ্যমে Angular ঠিক জানতে পারে কখন এবং কোথায় DOM আপডেট করতে হবে।
2.  **পারফরম্যান্স:** যেহেতু পুরো কম্পোনেন্ট ট্রি চেক করতে হয় না, তাই বড় এবং জটিল অ্যাপ্লিকেশনগুলোতে পারফরম্যান্স নাটকীয়ভাবে উন্নত হয়।
3.  **সরল কোড (Simpler Code):** কম্পোনেন্টের ভেতরের সাধারণ state ম্যানেজমেন্টের জন্য artık RxJS-এর `Subject` বা `BehaviorSubject` ব্যবহার করার জটিলতা কমে যায়। কোড আরও বেশি ঘোষণামূলক (declarative) এবং পড়তে সহজ হয়।
4.  **ভবিষ্যৎ:** Signal হলো Angular-এর ভবিষ্যৎ। নতুন সব ফিচার এবং অপটিমাইজেশন Signal-কে কেন্দ্র করে তৈরি হবে।

### একটি সম্পূর্ণ এবং সহজ উদাহরণ (A Simple Counter Component)

ধরুন আমরা একটি কাউন্টার কম্পোনেন্ট তৈরি করব যেখানে একটি সংখ্যা বাড়বে, কমবে এবং আমরা সেই সংখ্যার দ্বিগুণ মানও দেখাব।

#### ধাপ ১: কম্পোনেন্ট তৈরি করুন

```bash
ng generate component counter
```

#### ধাপ ২: `counter.component.ts` ফাইল এডিট করুন

এখানে আমরা `signal`, `computed`, এবং `effect` তিনটিই ব্যবহার করব।

```typescript
// src/app/counter/counter.component.ts

import { Component, signal, computed, effect, WritableSignal, Signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true, // Signal-ভিত্তিক কম্পোনেন্ট standalone হওয়া ভালো
  imports: [],
  templateUrl: './counter.component.html',
  styleUrl: './counter.component.css'
})
export class CounterComponent {

  // ১. signal() ব্যবহার করে state তৈরি করা
  // WritableSignal টাইপটি বলে দেয় যে এই signal-এর মান পরিবর্তন করা যাবে।
  public count: WritableSignal<number> = signal(0);

  // ২. computed() ব্যবহার করে একটি derived value তৈরি করা
  // Signal টাইপটি বলে দেয় যে এই signal-এর মান শুধু পড়া যাবে, পরিবর্তন করা যাবে না।
  public doubleCount: Signal<number> = computed(() => this.count() * 2);

  constructor() {
    // ৩. effect() ব্যবহার করে side effect তৈরি করা
    // যখনই count signal-এর মান পরিবর্তন হবে, এই কোডটি রান হবে।
    effect(() => {
      console.log(`The current count is: ${this.count()}`);
      // এখানে আপনি localStorage.setItem('count', this.count()) এর মতো কাজ করতে পারেন।
    });
  }

  // মান বাড়ানোর জন্য একটি মেথড
  increment() {
    // .update() ব্যবহার করে আগের মানের ওপর ভিত্তি করে নতুন মান সেট করা
    this.count.update(currentValue => currentValue + 1);
  }

  // মান কমানোর জন্য একটি মেথড
  decrement() {
    this.count.update(currentValue => currentValue - 1);
  }

  // মান রিসেট করার জন্য একটি মেথড
  reset() {
    // .set() ব্যবহার করে সরাসরি নতুন মান দেওয়া
    this.count.set(0);
  }
}
```

#### ধাপ ৩: `counter.component.html` ফাইল এডিট করুন

এখানে দেখুন আমরা কীভাবে টেমপ্লেটে Signal-এর মান পড়ছি। ফাংশন কল `()` ব্যবহার করতে হচ্ছে।

```html
<!-- src/app/counter/counter.component.html -->

<div class="counter-container">
  <h2>Angular Signal Counter</h2>

  <!-- Signal-এর মান পড়তে হলে () ব্যবহার করতে হবে -->
  <p class="count-display">Current Count: {{ count() }}</p>

  <!-- computed signal-এর মানও একইভাবে পড়তে হয় -->
  <p class="computed-display">Double of Count: {{ doubleCount() }}</p>

  <div class="buttons">
    <button (click)="increment()">Increment (+)</button>
    <button (click)="decrement()">Decrement (-)</button>
    <button (click)="reset()">Reset</button>
  </div>
</div>
```

#### ধাপ ৪: `app.component.ts` এ কম্পোনেন্টটি ব্যবহার করুন

```typescript
// src/app/app.component.ts
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';
import { CounterComponent } from './counter/counter.component'; // Import করুন

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, CounterComponent], // এখানে যোগ করুন
  template: `
    <h1>Welcome to Angular Signals!</h1>
    <app-counter></app-counter>
  `,
  styleUrls: ['./app.component.css']
})
export class AppComponent {
  title = 'angular-signal-demo';
}
```

এখন অ্যাপ্লিকেশনটি রান করলে আপনি একটি কাউন্টার দেখতে পাবেন। Increment বা Decrement বাটনে ক্লিক করলে দেখবেন:
1.  UI তে "Current Count" এবং "Double of Count" সাথে সাথে আপডেট হচ্ছে।
2.  ব্রাউজারের console-এ `effect` থেকে আসা লগ মেসেজ দেখা যাচ্ছে।

এই উদাহরণটি Signal-এর তিনটি মূল অংশকেই সুন্দরভাবে তুলে ধরেছে। আশা করি এটি আপনাকে Angular Signal সম্পর্কে একটি পরিষ্কার ধারণা দিয়েছে।


# === input  output  model  ======


অবশ্যই! Angular-এ কম্পোনেন্টের মধ্যে ডেটা আদান-প্রদান করার জন্য `@Input()`, `@Output()` এবং `[(ngModel)]`-এর আধুনিক এবং Signal-ভিত্তিক বিকল্প হলো `input()`, `output()` এবং `model()`।

আপনি যেহেতু একজন অভিজ্ঞ ডেভেলপার, আমি সরাসরি পুরোনো পদ্ধতির সাথে তুলনা করে নতুন পদ্ধতির সুবিধাগুলো তুলে ধরব।

---

### ১. `input()` Signal (বিকল্প: `@Input()` ডেকোরেটর)

`input()` ফাংশনটি `@Input()` ডেকোরেটরের আধুনিক Signal-ভিত্তিক বিকল্প। এটি প্যারেন্ট কম্পোনেন্ট থেকে চাইল্ড কম্পোনেন্টে ডেটা পাস করার জন্য ব্যবহৃত হয়।

**আগের পদ্ধতি (`@Input()`):**

```typescript
// child.component.ts
import { Component, Input } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Input() message: string = ''; // একটি সাধারণ প্রপার্টি
}
```

**নতুন পদ্ধতি (`input()`):**

```typescript
// child.component.ts
import { Component, input, InputSignal } from '@angular/core';

@Component({...})
export class ChildComponent {
  // message এখন একটি Signal (read-only)
  public message: InputSignal<string> = input(''); // ডিফল্ট মান
  
  // অথবা ইনপুটটিকে required হিসেবে চিহ্নিত করা যায়
  public requiredMessage: InputSignal<string> = input.required();
}
```

**প্রধান পার্থক্য ও সুবিধা:**

1.  **Reactivity:** `input()` দিয়ে পাওয়া প্রপার্টি একটি Signal। এর মানে হলো, যখনই প্যারেন্ট থেকে এর মান পরিবর্তন হবে, এই Signal-এর উপর নির্ভরশীল `computed()` বা `effect()` স্বয়ংক্রিয়ভাবে আপডেট হবে।
2.  **Required Inputs:** `input.required()` ব্যবহার করে খুব সহজেই একটি ইনপুটকে বাধ্যতামূলক করা যায়। যদি প্যারেন্ট থেকে মান পাস না করা হয়, Angular একটি এরর দেবে।
3.  **Type-Safe:** এটি আরও বেশি টাইপ-সেফ।
4.  **Transform:** আপনি ইনপুট ডেটাকে কম্পোনেন্টে ব্যবহারের আগে পরিবর্তন করতে পারেন।

```typescript
// ইনপুটকে boolean-এ রূপান্তর করা
public disabled = input(false, { transform: booleanAttribute }); 
```

---

### ২. `output()` Signal (বিকল্প: `@Output()` ও `EventEmitter`)

`output()` ফাংশনটি `@Output()` ডেকোরেটর এবং `EventEmitter`-এর একটি সহজ ও আধুনিক বিকল্প। এটি চাইল্ড কম্পোনেন্ট থেকে প্যারেন্ট কম্পোনেন্টে ইভেন্ট পাঠানোর জন্য ব্যবহৃত হয়।

**আগের পদ্ধতি (`@Output()`):**

```typescript
// child.component.ts
import { Component, Output, EventEmitter } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Output() valueChange = new EventEmitter<string>();

  sendData() {
    this.valueChange.emit("Hello from Child!");
  }
}
```

**নতুন পদ্ধতি (`output()`):**

```typescript
// child.component.ts
import { Component, output, OutputEmitterRef } from '@angular/core';

@Component({...})
export class ChildComponent {
  // EventEmitter এর আর প্রয়োজন নেই
  public valueChange: OutputEmitterRef<string> = output<string>();

  sendData() {
    this.valueChange.emit("Hello from Child!");
  }
}
```

**প্রধান পার্থক্য ও সুবিধা:**

1.  **সরলতা:** `EventEmitter` ক্লাস ইম্পোর্ট এবং ইনস্ট্যান্স তৈরি করার আর প্রয়োজন নেই। কোড অনেক পরিষ্কার এবং সংক্ষিপ্ত হয়।
2.  **Type-Safe:** এটিও সম্পূর্ণ টাইপ-সেফ। আপনি কী ধরনের ডেটা পাঠাবেন তা জেনেরিক (`<string>`) দিয়ে নির্দিষ্ট করে দিতে পারেন।

---

### ৩. `model()` Signal (বিকল্প: Two-way Binding `[(ngModel)]`)

`model()` হলো two-way data binding-এর জন্য Signal-ভিত্তিক সবচেয়ে শক্তিশালী ফিচার। এটি `[(ngModel)]` বা `@Input()` ও `@Output()`-এর সমন্বয়ের একটি আধুনিক বিকল্প।

সহজ কথায়, `model()` একটি `input()` এবং একটি `output()`-এর সম্মিলিত রূপ।

**আগের পদ্ধতি (Two-way Binding):**

ম্যানুয়ালি করতে হলে আমাদের একটি `@Input` এবং একটি `@Output` (যেটির নাম হবে `inputNameChange`) তৈরি করতে হতো।

```typescript
// child.component.ts
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Input() count: number = 0;
  @Output() countChange = new EventEmitter<number>();

  increment() {
    this.count++;
    this.countChange.emit(this.count);
  }
}
```
**প্যারেন্টে ব্যবহার:** ` <app-child [(count)]="parentCount"></app-child>`

**নতুন পদ্ধতি (`model()`):**

```typescript
// child.component.ts
import { Component, model, ModelSignal } from '@angular/core';

@Component({...})
export class ChildComponent {
  // একটি লাইনেই input এবং output এর কাজ হয়ে গেল!
  public count: ModelSignal<number> = model(0); // ডিফল্ট মান 0

  increment() {
    // .update() ব্যবহার করে model signal এর মান পরিবর্তন করা
    this.count.update(current => current + 1);
  }
  // অথবা .set() দিয়েও করা যায়
  // this.count.set(this.count() + 1);
}
```
**প্যারেন্টে ব্যবহার:** ` <app-child [(count)]="parentCountSignal"></app-child>`

**প্রধান পার্থক্য ও সুবিধা:**

1.  **অনেক কম কোড:** Two-way binding তৈরি করার জন্য `@Input` এবং `@Output` আলাদাভাবে লেখার প্রয়োজন নেই। একটি `model()` ফাংশনই যথেষ্ট।
2.  **Signal-ভিত্তিক:** `model()` একটি `WritableSignal` রিটার্ন করে। তাই আপনি এর মান পড়তে (`count()`) এবং পরিবর্তন করতে (`count.set()` বা `count.update()`) পারেন। এই পরিবর্তন স্বয়ংক্রিয়ভাবে প্যারেন্ট কম্পোনেন্টে পৌঁছে যায়।
3.  **Required Model:** `model.required<number>()` ব্যবহার করে একে বাধ্যতামূলক করা যায়।

---

### সম্পূর্ণ উদাহরণ: একটি প্যারেন্ট ও চাইল্ড কম্পোনেন্ট

এখানে আমরা একটি `ProductEditor` চাইল্ড কম্পোনেন্ট তৈরি করব, যা প্যারেন্ট থেকে পণ্যের নাম (`input`), স্টকের পরিমাণ (`model` দিয়ে two-way binding) এবং একটি সেভ ইভেন্ট (`output`) ম্যানেজ করবে।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট (`product-editor.component.ts`)

```typescript
import { Component, input, output, model, InputSignal, OutputEmitterRef, ModelSignal } from '@angular/core';
import { FormsModule } from '@angular/forms'; // ngModel ব্যবহারের জন্য

@Component({
  selector: 'app-product-editor',
  standalone: true,
  imports: [FormsModule],
  template: `
    <div class="editor">
      <h4>Product Editor (Child Component)</h4>
      
      <!-- 1. input() Signal এর ব্যবহার (Read-only) -->
      <p>Editing Product: <strong>{{ productName() }}</strong></p>

      <!-- 2. model() Signal এর ব্যবহার (Two-way binding) -->
      <div>
        <label for="stock">Stock Count: </label>
        <!-- model signal কে সরাসরি ngModel এর সাথে বাইন্ড করা যায় -->
        <input type="number" id="stock" [(ngModel)]="stockCount">
      </div>
      
      <!-- 3. output() Signal এর ব্যবহার -->
      <button (click)="onSave()">Save Changes</button>
    </div>
  `,
  styles: `.editor { border: 1px solid blue; padding: 10px; margin-top: 15px; }`
})
export class ProductEditorComponent {
  // প্যারেন্ট থেকে শুধু ডেটা আসবে (read-only signal)
  public productName: InputSignal<string> = input.required<string>();
  
  // প্যারেন্টের সাথে two-way binding হবে
  public stockCount: ModelSignal<number> = model.required<number>();

  // প্যারেন্টকে ইভেন্ট পাঠানো হবে
  public saved: OutputEmitterRef<{ name: string; stock: number }> = output();

  onSave() {
    // বর্তমান মানগুলো দিয়ে একটি অবজেক্ট তৈরি করে emit করা
    const productData = {
      name: this.productName(), // input signal পড়া
      stock: this.stockCount()  // model signal পড়া
    };
    this.saved.emit(productData);
    console.log('Child component emitted save event:', productData);
  }
}
```

#### ধাপ ২: প্যারেন্ট কম্পোনেন্ট (`app.component.ts`)

```typescript
import { Component, signal, WritableSignal } from '@angular/core';
import { ProductEditorComponent } from './product-editor/product-editor.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [ProductEditorComponent],
  template: `
    <div class="parent">
      <h1>Parent Component</h1>
      <p>Product Name: {{ currentProduct() }}</p>
      <p>Current Stock: {{ productStock() }}</p>
      
      <hr>

      <!-- চাইল্ড কম্পোনেন্ট ব্যবহার এবং Signal বাইন্ডিং -->
      <app-product-editor
        [productName]="currentProduct()"   
        [(stockCount)]="productStock"
        (saved)="onProductSaved($event)">
      </app-product-editor>

      <div *ngIf="savedMessage" class="message">{{ savedMessage }}</div>
    </div>
  `,
  styles: `
    .parent { border: 2px solid green; padding: 20px; }
    .message { margin-top: 15px; color: green; font-weight: bold; }
  `
})
export class AppComponent {
  // প্যারেন্টের state signal হিসেবে রাখা
  public currentProduct: WritableSignal<string> = signal('Angular Pro Book');
  public productStock: WritableSignal<number> = signal(50);
  
  public savedMessage: string = '';

  // চাইল্ড থেকে আসা ইভেন্ট হ্যান্ডেল করা
  onProductSaved(product: { name: string; stock: number }) {
    this.savedMessage = `Product "${product.name}" with stock ${product.stock} has been saved!`;
    console.log('Parent received event:', product);
  }
}
```

এই উদাহরণে:
1.  **`[productName]="currentProduct()"`:** প্যারেন্টের `currentProduct` Signal-এর মান চাইল্ডের `productName` `input()`-এ পাস করা হচ্ছে।
2.  **`[(stockCount)]="productStock"`:** প্যারেন্টের `productStock` Signal-টি চাইল্ডের `stockCount` `model()`-এর সাথে two-way bind করা হয়েছে। চাইল্ডে স্টকের মান পরিবর্তন করলে প্যারেন্টেও তা আপডেট হবে।
3.  **`(saved)="onProductSaved($event)"`:** চাইল্ডের `saved` `output()` থেকে আসা ইভেন্ট প্যারেন্টের `onProductSaved` মেথড দিয়ে ধরা হচ্ছে।

এই নতুন API গুলো Angular-এ কম্পোনেন্ট কমিউনিকেশনকে আরও বেশি শক্তিশালী, সংক্ষিপ্ত এবং Signal-এর reactivity মডেলের সাথে সামঞ্জস্যপূর্ণ করে তুলেছে।


# ===== Resource signal ============

চমৎকার প্রশ্ন! "Resource Signal" অ্যাঙ্গুলারে কোনো বিল্ট-ইন ফাংশন নয়, বরং এটি একটি **ডিজাইন প্যাটার্ন**। অ্যাসিঙ্ক্রোনাস ডেটা (যেমন API থেকে আনা ডেটা) ম্যানেজ করার জন্য সিগন্যাল ব্যবহার করে এই প্যাটার্নটি তৈরি করা হয়। এটি ডেটা লোডিং, সফলভাবে ডেটা পাওয়া, এবং এরর অবস্থা—এই তিনটি অবস্থাকে একটি মাত্র সিগন্যালের মধ্যে খুব সুন্দরভাবে ম্যানেজ করে।

সহজ কথায়, একটি Resource Signal হলো এমন একটি সিগন্যাল যা একটি অ্যাসিঙ্ক্রোনাস অপারেশনের সম্পূর্ণ জীবনচক্র (lifecycle) ধারণ করে।

---

### কেন এই প্যাটার্নটি দরকার?

সাধারণত, যখন আমরা API থেকে ডেটা আনি, তখন আমাদের তিনটি অবস্থা ম্যানেজ করতে হয়:

1.  **Loading:** ডেটা এখনো আসছে, ব্যবহারকারীকে একটি লোডার বা স্পিনার দেখাতে হবে।
2.  **Success:** ডেটা সফলভাবে চলে এসেছে, এখন UI-তে দেখাতে হবে।
3.  **Error:** কোনো কারণে ডেটা আনা সম্ভব হয়নি, একটি এরর মেসেজ দেখাতে হবে।

এই তিনটি অবস্থা ম্যানেজ করার জন্য আমরা আলাদা আলাদা ভ্যারিয়েবল বা সিগন্যাল ব্যবহার করতে পারি:

```typescript
isLoading = signal(true);
data = signal<User[] | null>(null);
error = signal<any | null>(null);
```

**সমস্যা:** এই পদ্ধতিতে বেশ কিছু সমস্যা আছে।
*   একসাথে একাধিক সিগন্যাল ম্যানেজ করা জটিল।
*   ভুলবশত `isLoading` `true` থাকা অবস্থায় `data`-তে মান চলে আসতে পারে, যা একটি অসামঞ্জস্যপূর্ণ অবস্থা (inconsistent state)।
*   কোড অগোছালো হয়ে যায়।

**সমাধান:** Resource Signal প্যাটার্ন এই তিনটি অবস্থাকে একটি মাত্র সিগন্যালের মধ্যে একটি অবজেক্ট হিসেবে রাখে, যা কোডকে অনেক বেশি পরিষ্কার, নিরাপদ এবং পরিচালনাযোগ্য করে তোলে।

---

### Resource Signal প্যাটার্নের গঠন

আমরা একটি `Resource` টাইপ তৈরি করব যা এই বিভিন্ন অবস্থাগুলোকে ধারণ করবে। TypeScript-এর Discriminated Unions ব্যবহার করে এটি খুব সুন্দরভাবে করা যায়।

**ধাপ ১: State Type গুলো ডিফাইন করা**

আমরা তিনটি অবস্থার জন্য আলাদা আলাদা টাইপ ডিফাইন করব:

```typescript
// যখন ডেটা লোড হচ্ছে
interface LoadingState {
  status: 'loading';
}

// যখন ডেটা সফলভাবে লোড হয়েছে
interface SuccessState<T> {
  status: 'success';
  value: T; // আমাদের আসল ডেটা এখানে থাকবে
}

// যখন কোনো এরর হয়েছে
interface ErrorState {
  status: 'error';
  error: unknown; // এরর অবজেক্ট
}

// এই তিনটি স্টেটকে একত্রিত করে একটি Union টাইপ তৈরি করা
export type Resource<T> = LoadingState | SuccessState<T> | ErrorState;
```

এই `Resource<T>` টাইপটি ব্যবহার করে আমরা এখন আমাদের সিগন্যাল তৈরি করতে পারব।

---

### একটি সম্পূর্ণ উদাহরণ: API থেকে Post ফেচ করা

ধরুন আমরা একটি API থেকে কিছু ব্লগ পোস্ট ফেচ করে দেখাব।

#### ধাপ ১: Resource টাইপ তৈরি করুন

উপরের টাইপ ডেফিনিশনগুলো একটি ফাইলে (`resource.model.ts`) রাখতে পারেন।

#### ধাপ ২: একটি সার্ভিস তৈরি করুন ডেটা আনার জন্য (`post.service.ts`)

সার্ভিসের মধ্যে আমরা Resource Signal রাখব এবং API কল করব।

```typescript
// src/app/post.service.ts
import { Injectable, signal, WritableSignal } from '@angular/core';
import { Resource } from './resource.model'; // আমাদের তৈরি করা টাইপ ইম্পোর্ট করুন

// পোস্টের ডেটার জন্য একটি ইন্টারফেস
export interface Post {
  id: number;
  title: string;
  body: string;
}

@Injectable({
  providedIn: 'root'
})
export class PostService {
  // আমাদের মূল Resource Signal। শুরুতে এটি 'loading' অবস্থায় থাকবে।
  public posts: WritableSignal<Resource<Post[]>> = signal({ status: 'loading' });

  constructor() {
    this.fetchPosts(); // সার্ভিস তৈরি হওয়ার সাথেই ডেটা আনা শুরু হবে
  }

  async fetchPosts(): Promise<void> {
    // পুনরায় ডেটা আনার আগে 'loading' state সেট করা
    this.posts.set({ status: 'loading' });

    try {
      const response = await fetch('https://jsonplaceholder.typicode.com/posts?_limit=10');
      
      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }
      
      const data: Post[] = await response.json();
      
      // সফল হলে 'success' state সেট করা
      this.posts.set({ status: 'success', value: data });

    } catch (err) {
      // এরর হলে 'error' state সেট করা
      this.posts.set({ status: 'error', error: err });
    }
  }
}
```

#### ধাপ ৩: কম্পোনেন্টে সার্ভিসটি ব্যবহার করুন (`posts.component.ts`)

এখন আমরা একটি কম্পোনেন্টে এই সার্ভিসটি ইনজেক্ট করব এবং UI তে ডেটা দেখানোর জন্য প্রস্তুত হব।

```typescript
// src/app/posts/posts.component.ts
import { Component, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { PostService } from '../post.service';

@Component({
  selector: 'app-posts',
  standalone: true,
  imports: [CommonModule],
  templateUrl: './posts.component.html',
  styleUrls: ['./posts.component.css']
})
export class PostsComponent {
  // সার্ভিস ইনজেক্ট করা
  private postService = inject(PostService);

  // সার্ভিস থেকে posts সিগন্যালটি কম্পোনেন্টে অ্যাক্সেস করা
  public posts = this.postService.posts;

  // ডেটা রিফ্রেশ করার জন্য একটি মেথড
  refresh() {
    this.postService.fetchPosts();
  }
}
```

#### ধাপ ৪: টেমপ্লেটে (`posts.component.html`) ডেটা দেখানো

এখানেই Resource Signal প্যাটার্নের আসল সৌন্দর্য প্রকাশ পায়। আমরা Angular-এর নতুন `@switch` কন্ট্রোল ফ্লো ব্যবহার করে খুব সহজেই তিনটি অবস্থা দেখাতে পারি।

```html
<!-- src/app/posts/posts.component.html -->

<div class="container">
  <h2>Blog Posts (Loaded with Resource Signal)</h2>
  <button (click)="refresh()">Refresh Posts</button>

  <div class="content">
    <!-- এখানে posts() সিগন্যালের status প্রপার্টির ওপর ভিত্তি করে UI দেখানো হচ্ছে -->
    @switch (posts().status) {

      <!-- কেস ১: যখন স্ট্যাটাস 'loading' -->
      @case ('loading') {
        <div class="loader">Loading posts...</div>
      }

      <!-- কেস ২: যখন স্ট্যাটাস 'success' -->
      @case ('success') {
        <!-- posts().value থেকে ডেটা অ্যাক্সেস করা হচ্ছে -->
        <ul class="post-list">
          @for (post of posts().value; track post.id) {
            <li>
              <h3>{{ post.title }}</h3>
              <p>{{ post.body }}</p>
            </li>
          }
        </ul>
      }

      <!-- কেস ৩: যখন স্ট্যাটাস 'error' -->
      @case ('error') {
        <div class="error">
          <p>Failed to load posts. Please try again.</p>
          <!-- posts().error থেকে এরর মেসেজ দেখানো যায় -->
          <pre>{{ posts().error | json }}</pre>
        </div>
      }
    }
  </div>
</div>
```

### Resource Signal প্যাটার্নের সুবিধা:

1.  **Single Source of Truth:** লোডিং, ডেটা এবং এরর—সবকিছু একটি মাত্র সিগন্যালের মধ্যে থাকে।
2.  **Type Safety:** TypeScript-এর Discriminated Union ব্যবহার করার কারণে, আপনি যখন `status` চেক করবেন, তখন টাইপস্কিপ্ট স্বয়ংক্রিয়ভাবে জানবে ওই ব্লকের মধ্যে কোন প্রপার্টিগুলো (`value` বা `error`) অ্যাভেইলেবল আছে। যেমন, `success` কেসে `error` প্রপার্টি অ্যাক্সেস করতে গেলে টাইপস্কিপ্ট এরর দেবে।
3.  **Declarative UI:** `@switch` ব্যবহার করে টেমপ্লেটের কোড অনেক বেশি ঘোষণামূলক (declarative) এবং পরিষ্কার থাকে। একাধিক `*ngIf` ব্যবহার করার ঝামেলা থেকে মুক্তি পাওয়া যায়।
4.  **No Inconsistent States:** `isLoading` `true` এবং `error` একই সাথে থাকার কোনো সুযোগই নেই, কারণ `status` একবারে কেবল একটি মান (`loading`, `success`, বা `error`) ধারণ করতে পারে।
5.  **Reusable and Clean:** এই প্যাটার্নটি পুরো অ্যাপ্লিকেশন জুড়ে যেকোনো অ্যাসিঙ্ক্রোনাস ডেটা লোডিং-এর জন্য পুনরায় ব্যবহার করা যেতে পারে।

আশা করি, এই ব্যাখ্যা এবং উদাহরণটি আপনাকে Resource Signal প্যাটার্নটি বুঝতে সাহায্য করেছে। এটি সিগন্যালের সাথে অ্যাসিঙ্ক্রোনাস কোড ম্যানেজ করার একটি অত্যন্ত কার্যকর এবং আধুনিক উপায়।
