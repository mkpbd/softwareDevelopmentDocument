
অবশ্যই! আপনি যেহেতু একজন অভিজ্ঞ ডেভেলপার, আমি Angular Signal-এর মূল ধারণা এবং এর পেছনের কারণগুলো সহজভাবে বাংলাতে ব্যাখ্যা করছি, সাথে একটি সম্পূর্ণ উদাহরণও দিচ্ছি।

### Angular Signal কী?

সহজ ভাষায়, **Signal হলো state (ডেটা) ম্যানেজ করার জন্য Angular-এর একটি নতুন এবং অনেক বেশি কার্যকরী (efficient) সিস্টেম।**

এখন পর্যন্ত আমরা state ম্যানেজ করার জন্য সাধারণ variable, RxJS (যেমন `BehaviorSubject`), বা `Input()` ডেকোরেটর ব্যবহার করতাম। যখন কোনো ডেটা পরিবর্তন হতো, তখন Zone.js পুরো কম্পোনেন্ট ট্রি (component tree) চেক করে দেখত কোথায় কী পরিবর্তন হয়েছে এবং সেই অনুযায়ী DOM আপডেট করত। এই প্রক্রিয়াকে বলা হয় Change Detection।

Signal এই প্রক্রিয়াকে পুরোপুরি বদলে দিয়েছে।

**Signal-এর মূল ধারণা হলো:**
*   এটি একটি **"wrapper"** বা ধারক, যার ভেতরে আপনার ডেটা থাকে।
*   যখন Signal-এর ভেতরের ডেটা পরিবর্তন হয়, তখন Signal নিজে থেকেই Angular-কে জানিয়ে দেয়, "আমার মান পরিবর্তন হয়েছে।"
*   Angular তখন শুধুমাত্র সেই নির্দিষ্ট জায়গাটিই আপডেট করে, যেখানে ওই Signal ব্যবহার করা হয়েছে। পুরো কম্পোনেন্ট ট্রি চেক করার প্রয়োজন হয় না।

একেই বলা হয় **Fine-grained Reactivity**। এর ফলে অ্যাপ্লিকেশনের পারফরম্যান্স বহুগুণে বেড়ে যায়।

### Signal-এর প্রধান তিনটি অংশ

Signal ইকোসিস্টেমে মূলত তিনটি জিনিস আছে:

#### 1. `signal()` - The Source of Truth
এটি হলো মূল state বা ডেটা রাখার জায়গা।

*   **তৈরি করা (Create):** `const mySignal = signal('initial value');`
*   **মান পড়া (Read):** `mySignal()` - একে ফাংশনের মতো কল করতে হয়।
*   **মান পরিবর্তন করা (Write):**
    *   `.set(newValue)`: পুরো মান বদলে ফেলার জন্য। `mySignal.set('new value');`
    *   `.update(currentValue => ...)`: আগের মানের ওপর ভিত্তি করে নতুন মান সেট করার জন্য। `count.update(value => value + 1);`

#### 2. `computed()` - Derived Values
যখন একটি Signal-এর ওপর নির্ভর করে অন্য কোনো ডেটার মান তৈরি হয়, তখন `computed` ব্যবহার করা হয়।

*   **উদাহরণ:** আপনার কাছে `firstName` এবং `lastName` নামে দুটি Signal আছে। এদেরকে মিলিয়ে `fullName` নামে আরেকটি Signal তৈরি করতে `computed` ব্যবহার করবেন।
*   **সুবিধা:** `computed` signal শুধুমাত্র তখনই তার মান নতুন করে حساب (recalculate) করে, যখন তার ওপর নির্ভরশীল (dependent) কোনো signal-এর মান পরিবর্তন হয়। এটি lazy এবং memoized (ফলাফল মনে রাখে), যা পারফরম্যান্সের জন্য খুবই ভালো।

#### 3. `effect()` - Side Effects
যখন কোনো Signal-এর মান পরিবর্তনের ফলে আপনি UI বা state-এর বাইরে কোনো কাজ করতে চান (যেমন: console-এ লগ করা, Local Storage-এ ডেটা সেভ করা, কোনো API কল করা), তখন `effect` ব্যবহার করা হয়।

*   **গুরুত্বপূর্ণ:** `effect()` সরাসরি অন্য কোনো signal-কে আপডেট করার জন্য ব্যবহার করা উচিত নয়। এর মূল কাজ হলো বাইরের জগতের সাথে সংযোগ স্থাপন করা। এটি component render হওয়ার *পরে* রান হয়।

### কেন Signal ব্যবহার করবেন? (আপনার ১২ বছরের অভিজ্ঞতার আলোকে)

1.  **Zone.js থেকে মুক্তি:** Signal-এর মূল লক্ষ্য হলো Angular-কে Zone.js-এর ওপর থেকে নির্ভরশীলতা কমানো। Zone.js অনেক সময় পারফরম্যান্সের জন্য বাধা হয়ে দাঁড়ায়, কারণ এটি সব ধরনের asynchronous ইভেন্ট (যেমন: `setTimeout`, `fetch`, button click) ট্র্যাক করে এবং অপ্রয়োজনীয় change detection চালু করে। Signal-এর মাধ্যমে Angular ঠিক জানতে পারে কখন এবং কোথায় DOM আপডেট করতে হবে।
2.  **পারফরম্যান্স:** যেহেতু পুরো কম্পোনেন্ট ট্রি চেক করতে হয় না, তাই বড় এবং জটিল অ্যাপ্লিকেশনগুলোতে পারফরম্যান্স নাটকীয়ভাবে উন্নত হয়।
3.  **সরল কোড (Simpler Code):** কম্পোনেন্টের ভেতরের সাধারণ state ম্যানেজমেন্টের জন্য artık RxJS-এর `Subject` বা `BehaviorSubject` ব্যবহার করার জটিলতা কমে যায়। কোড আরও বেশি ঘোষণামূলক (declarative) এবং পড়তে সহজ হয়।
4.  **ভবিষ্যৎ:** Signal হলো Angular-এর ভবিষ্যৎ। নতুন সব ফিচার এবং অপটিমাইজেশন Signal-কে কেন্দ্র করে তৈরি হবে।

### একটি সম্পূর্ণ এবং সহজ উদাহরণ (A Simple Counter Component)

ধরুন আমরা একটি কাউন্টার কম্পোনেন্ট তৈরি করব যেখানে একটি সংখ্যা বাড়বে, কমবে এবং আমরা সেই সংখ্যার দ্বিগুণ মানও দেখাব।

#### ধাপ ১: কম্পোনেন্ট তৈরি করুন

```bash
ng generate component counter
```

#### ধাপ ২: `counter.component.ts` ফাইল এডিট করুন

এখানে আমরা `signal`, `computed`, এবং `effect` তিনটিই ব্যবহার করব।

```typescript
// src/app/counter/counter.component.ts

import { Component, signal, computed, effect, WritableSignal, Signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true, // Signal-ভিত্তিক কম্পোনেন্ট standalone হওয়া ভালো
  imports: [],
  templateUrl: './counter.component.html',
  styleUrl: './counter.component.css'
})
export class CounterComponent {

  // ১. signal() ব্যবহার করে state তৈরি করা
  // WritableSignal টাইপটি বলে দেয় যে এই signal-এর মান পরিবর্তন করা যাবে।
  public count: WritableSignal<number> = signal(0);

  // ২. computed() ব্যবহার করে একটি derived value তৈরি করা
  // Signal টাইপটি বলে দেয় যে এই signal-এর মান শুধু পড়া যাবে, পরিবর্তন করা যাবে না।
  public doubleCount: Signal<number> = computed(() => this.count() * 2);

  constructor() {
    // ৩. effect() ব্যবহার করে side effect তৈরি করা
    // যখনই count signal-এর মান পরিবর্তন হবে, এই কোডটি রান হবে।
    effect(() => {
      console.log(`The current count is: ${this.count()}`);
      // এখানে আপনি localStorage.setItem('count', this.count()) এর মতো কাজ করতে পারেন।
    });
  }

  // মান বাড়ানোর জন্য একটি মেথড
  increment() {
    // .update() ব্যবহার করে আগের মানের ওপর ভিত্তি করে নতুন মান সেট করা
    this.count.update(currentValue => currentValue + 1);
  }

  // মান কমানোর জন্য একটি মেথড
  decrement() {
    this.count.update(currentValue => currentValue - 1);
  }

  // মান রিসেট করার জন্য একটি মেথড
  reset() {
    // .set() ব্যবহার করে সরাসরি নতুন মান দেওয়া
    this.count.set(0);
  }
}
```

#### ধাপ ৩: `counter.component.html` ফাইল এডিট করুন

এখানে দেখুন আমরা কীভাবে টেমপ্লেটে Signal-এর মান পড়ছি। ফাংশন কল `()` ব্যবহার করতে হচ্ছে।

```html
<!-- src/app/counter/counter.component.html -->

<div class="counter-container">
  <h2>Angular Signal Counter</h2>

  <!-- Signal-এর মান পড়তে হলে () ব্যবহার করতে হবে -->
  <p class="count-display">Current Count: {{ count() }}</p>

  <!-- computed signal-এর মানও একইভাবে পড়তে হয় -->
  <p class="computed-display">Double of Count: {{ doubleCount() }}</p>

  <div class="buttons">
    <button (click)="increment()">Increment (+)</button>
    <button (click)="decrement()">Decrement (-)</button>
    <button (click)="reset()">Reset</button>
  </div>
</div>
```

#### ধাপ ৪: `app.component.ts` এ কম্পোনেন্টটি ব্যবহার করুন

```typescript
// src/app/app.component.ts
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';
import { CounterComponent } from './counter/counter.component'; // Import করুন

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, CounterComponent], // এখানে যোগ করুন
  template: `
    <h1>Welcome to Angular Signals!</h1>
    <app-counter></app-counter>
  `,
  styleUrls: ['./app.component.css']
})
export class AppComponent {
  title = 'angular-signal-demo';
}
```

এখন অ্যাপ্লিকেশনটি রান করলে আপনি একটি কাউন্টার দেখতে পাবেন। Increment বা Decrement বাটনে ক্লিক করলে দেখবেন:
1.  UI তে "Current Count" এবং "Double of Count" সাথে সাথে আপডেট হচ্ছে।
2.  ব্রাউজারের console-এ `effect` থেকে আসা লগ মেসেজ দেখা যাচ্ছে।

এই উদাহরণটি Signal-এর তিনটি মূল অংশকেই সুন্দরভাবে তুলে ধরেছে। আশা করি এটি আপনাকে Angular Signal সম্পর্কে একটি পরিষ্কার ধারণা দিয়েছে।


# === input  output  model  ======


অবশ্যই! Angular-এ কম্পোনেন্টের মধ্যে ডেটা আদান-প্রদান করার জন্য `@Input()`, `@Output()` এবং `[(ngModel)]`-এর আধুনিক এবং Signal-ভিত্তিক বিকল্প হলো `input()`, `output()` এবং `model()`।

আপনি যেহেতু একজন অভিজ্ঞ ডেভেলপার, আমি সরাসরি পুরোনো পদ্ধতির সাথে তুলনা করে নতুন পদ্ধতির সুবিধাগুলো তুলে ধরব।

---

### ১. `input()` Signal (বিকল্প: `@Input()` ডেকোরেটর)

`input()` ফাংশনটি `@Input()` ডেকোরেটরের আধুনিক Signal-ভিত্তিক বিকল্প। এটি প্যারেন্ট কম্পোনেন্ট থেকে চাইল্ড কম্পোনেন্টে ডেটা পাস করার জন্য ব্যবহৃত হয়।

**আগের পদ্ধতি (`@Input()`):**

```typescript
// child.component.ts
import { Component, Input } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Input() message: string = ''; // একটি সাধারণ প্রপার্টি
}
```

**নতুন পদ্ধতি (`input()`):**

```typescript
// child.component.ts
import { Component, input, InputSignal } from '@angular/core';

@Component({...})
export class ChildComponent {
  // message এখন একটি Signal (read-only)
  public message: InputSignal<string> = input(''); // ডিফল্ট মান
  
  // অথবা ইনপুটটিকে required হিসেবে চিহ্নিত করা যায়
  public requiredMessage: InputSignal<string> = input.required();
}
```

**প্রধান পার্থক্য ও সুবিধা:**

1.  **Reactivity:** `input()` দিয়ে পাওয়া প্রপার্টি একটি Signal। এর মানে হলো, যখনই প্যারেন্ট থেকে এর মান পরিবর্তন হবে, এই Signal-এর উপর নির্ভরশীল `computed()` বা `effect()` স্বয়ংক্রিয়ভাবে আপডেট হবে।
2.  **Required Inputs:** `input.required()` ব্যবহার করে খুব সহজেই একটি ইনপুটকে বাধ্যতামূলক করা যায়। যদি প্যারেন্ট থেকে মান পাস না করা হয়, Angular একটি এরর দেবে।
3.  **Type-Safe:** এটি আরও বেশি টাইপ-সেফ।
4.  **Transform:** আপনি ইনপুট ডেটাকে কম্পোনেন্টে ব্যবহারের আগে পরিবর্তন করতে পারেন।

```typescript
// ইনপুটকে boolean-এ রূপান্তর করা
public disabled = input(false, { transform: booleanAttribute }); 
```

---

### ২. `output()` Signal (বিকল্প: `@Output()` ও `EventEmitter`)

`output()` ফাংশনটি `@Output()` ডেকোরেটর এবং `EventEmitter`-এর একটি সহজ ও আধুনিক বিকল্প। এটি চাইল্ড কম্পোনেন্ট থেকে প্যারেন্ট কম্পোনেন্টে ইভেন্ট পাঠানোর জন্য ব্যবহৃত হয়।

**আগের পদ্ধতি (`@Output()`):**

```typescript
// child.component.ts
import { Component, Output, EventEmitter } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Output() valueChange = new EventEmitter<string>();

  sendData() {
    this.valueChange.emit("Hello from Child!");
  }
}
```

**নতুন পদ্ধতি (`output()`):**

```typescript
// child.component.ts
import { Component, output, OutputEmitterRef } from '@angular/core';

@Component({...})
export class ChildComponent {
  // EventEmitter এর আর প্রয়োজন নেই
  public valueChange: OutputEmitterRef<string> = output<string>();

  sendData() {
    this.valueChange.emit("Hello from Child!");
  }
}
```

**প্রধান পার্থক্য ও সুবিধা:**

1.  **সরলতা:** `EventEmitter` ক্লাস ইম্পোর্ট এবং ইনস্ট্যান্স তৈরি করার আর প্রয়োজন নেই। কোড অনেক পরিষ্কার এবং সংক্ষিপ্ত হয়।
2.  **Type-Safe:** এটিও সম্পূর্ণ টাইপ-সেফ। আপনি কী ধরনের ডেটা পাঠাবেন তা জেনেরিক (`<string>`) দিয়ে নির্দিষ্ট করে দিতে পারেন।

---

### ৩. `model()` Signal (বিকল্প: Two-way Binding `[(ngModel)]`)

`model()` হলো two-way data binding-এর জন্য Signal-ভিত্তিক সবচেয়ে শক্তিশালী ফিচার। এটি `[(ngModel)]` বা `@Input()` ও `@Output()`-এর সমন্বয়ের একটি আধুনিক বিকল্প।

সহজ কথায়, `model()` একটি `input()` এবং একটি `output()`-এর সম্মিলিত রূপ।

**আগের পদ্ধতি (Two-way Binding):**

ম্যানুয়ালি করতে হলে আমাদের একটি `@Input` এবং একটি `@Output` (যেটির নাম হবে `inputNameChange`) তৈরি করতে হতো।

```typescript
// child.component.ts
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({...})
export class ChildComponent {
  @Input() count: number = 0;
  @Output() countChange = new EventEmitter<number>();

  increment() {
    this.count++;
    this.countChange.emit(this.count);
  }
}
```
**প্যারেন্টে ব্যবহার:** ` <app-child [(count)]="parentCount"></app-child>`

**নতুন পদ্ধতি (`model()`):**

```typescript
// child.component.ts
import { Component, model, ModelSignal } from '@angular/core';

@Component({...})
export class ChildComponent {
  // একটি লাইনেই input এবং output এর কাজ হয়ে গেল!
  public count: ModelSignal<number> = model(0); // ডিফল্ট মান 0

  increment() {
    // .update() ব্যবহার করে model signal এর মান পরিবর্তন করা
    this.count.update(current => current + 1);
  }
  // অথবা .set() দিয়েও করা যায়
  // this.count.set(this.count() + 1);
}
```
**প্যারেন্টে ব্যবহার:** ` <app-child [(count)]="parentCountSignal"></app-child>`

**প্রধান পার্থক্য ও সুবিধা:**

1.  **অনেক কম কোড:** Two-way binding তৈরি করার জন্য `@Input` এবং `@Output` আলাদাভাবে লেখার প্রয়োজন নেই। একটি `model()` ফাংশনই যথেষ্ট।
2.  **Signal-ভিত্তিক:** `model()` একটি `WritableSignal` রিটার্ন করে। তাই আপনি এর মান পড়তে (`count()`) এবং পরিবর্তন করতে (`count.set()` বা `count.update()`) পারেন। এই পরিবর্তন স্বয়ংক্রিয়ভাবে প্যারেন্ট কম্পোনেন্টে পৌঁছে যায়।
3.  **Required Model:** `model.required<number>()` ব্যবহার করে একে বাধ্যতামূলক করা যায়।

---

### সম্পূর্ণ উদাহরণ: একটি প্যারেন্ট ও চাইল্ড কম্পোনেন্ট

এখানে আমরা একটি `ProductEditor` চাইল্ড কম্পোনেন্ট তৈরি করব, যা প্যারেন্ট থেকে পণ্যের নাম (`input`), স্টকের পরিমাণ (`model` দিয়ে two-way binding) এবং একটি সেভ ইভেন্ট (`output`) ম্যানেজ করবে।

#### ধাপ ১: চাইল্ড কম্পোনেন্ট (`product-editor.component.ts`)

```typescript
import { Component, input, output, model, InputSignal, OutputEmitterRef, ModelSignal } from '@angular/core';
import { FormsModule } from '@angular/forms'; // ngModel ব্যবহারের জন্য

@Component({
  selector: 'app-product-editor',
  standalone: true,
  imports: [FormsModule],
  template: `
    <div class="editor">
      <h4>Product Editor (Child Component)</h4>
      
      <!-- 1. input() Signal এর ব্যবহার (Read-only) -->
      <p>Editing Product: <strong>{{ productName() }}</strong></p>

      <!-- 2. model() Signal এর ব্যবহার (Two-way binding) -->
      <div>
        <label for="stock">Stock Count: </label>
        <!-- model signal কে সরাসরি ngModel এর সাথে বাইন্ড করা যায় -->
        <input type="number" id="stock" [(ngModel)]="stockCount">
      </div>
      
      <!-- 3. output() Signal এর ব্যবহার -->
      <button (click)="onSave()">Save Changes</button>
    </div>
  `,
  styles: `.editor { border: 1px solid blue; padding: 10px; margin-top: 15px; }`
})
export class ProductEditorComponent {
  // প্যারেন্ট থেকে শুধু ডেটা আসবে (read-only signal)
  public productName: InputSignal<string> = input.required<string>();
  
  // প্যারেন্টের সাথে two-way binding হবে
  public stockCount: ModelSignal<number> = model.required<number>();

  // প্যারেন্টকে ইভেন্ট পাঠানো হবে
  public saved: OutputEmitterRef<{ name: string; stock: number }> = output();

  onSave() {
    // বর্তমান মানগুলো দিয়ে একটি অবজেক্ট তৈরি করে emit করা
    const productData = {
      name: this.productName(), // input signal পড়া
      stock: this.stockCount()  // model signal পড়া
    };
    this.saved.emit(productData);
    console.log('Child component emitted save event:', productData);
  }
}
```

#### ধাপ ২: প্যারেন্ট কম্পোনেন্ট (`app.component.ts`)

```typescript
import { Component, signal, WritableSignal } from '@angular/core';
import { ProductEditorComponent } from './product-editor/product-editor.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [ProductEditorComponent],
  template: `
    <div class="parent">
      <h1>Parent Component</h1>
      <p>Product Name: {{ currentProduct() }}</p>
      <p>Current Stock: {{ productStock() }}</p>
      
      <hr>

      <!-- চাইল্ড কম্পোনেন্ট ব্যবহার এবং Signal বাইন্ডিং -->
      <app-product-editor
        [productName]="currentProduct()"   
        [(stockCount)]="productStock"
        (saved)="onProductSaved($event)">
      </app-product-editor>

      <div *ngIf="savedMessage" class="message">{{ savedMessage }}</div>
    </div>
  `,
  styles: `
    .parent { border: 2px solid green; padding: 20px; }
    .message { margin-top: 15px; color: green; font-weight: bold; }
  `
})
export class AppComponent {
  // প্যারেন্টের state signal হিসেবে রাখা
  public currentProduct: WritableSignal<string> = signal('Angular Pro Book');
  public productStock: WritableSignal<number> = signal(50);
  
  public savedMessage: string = '';

  // চাইল্ড থেকে আসা ইভেন্ট হ্যান্ডেল করা
  onProductSaved(product: { name: string; stock: number }) {
    this.savedMessage = `Product "${product.name}" with stock ${product.stock} has been saved!`;
    console.log('Parent received event:', product);
  }
}
```

এই উদাহরণে:
1.  **`[productName]="currentProduct()"`:** প্যারেন্টের `currentProduct` Signal-এর মান চাইল্ডের `productName` `input()`-এ পাস করা হচ্ছে।
2.  **`[(stockCount)]="productStock"`:** প্যারেন্টের `productStock` Signal-টি চাইল্ডের `stockCount` `model()`-এর সাথে two-way bind করা হয়েছে। চাইল্ডে স্টকের মান পরিবর্তন করলে প্যারেন্টেও তা আপডেট হবে।
3.  **`(saved)="onProductSaved($event)"`:** চাইল্ডের `saved` `output()` থেকে আসা ইভেন্ট প্যারেন্টের `onProductSaved` মেথড দিয়ে ধরা হচ্ছে।

এই নতুন API গুলো Angular-এ কম্পোনেন্ট কমিউনিকেশনকে আরও বেশি শক্তিশালী, সংক্ষিপ্ত এবং Signal-এর reactivity মডেলের সাথে সামঞ্জস্যপূর্ণ করে তুলেছে।


# ===== Resource signal ============

চমৎকার প্রশ্ন! "Resource Signal" অ্যাঙ্গুলারে কোনো বিল্ট-ইন ফাংশন নয়, বরং এটি একটি **ডিজাইন প্যাটার্ন**। অ্যাসিঙ্ক্রোনাস ডেটা (যেমন API থেকে আনা ডেটা) ম্যানেজ করার জন্য সিগন্যাল ব্যবহার করে এই প্যাটার্নটি তৈরি করা হয়। এটি ডেটা লোডিং, সফলভাবে ডেটা পাওয়া, এবং এরর অবস্থা—এই তিনটি অবস্থাকে একটি মাত্র সিগন্যালের মধ্যে খুব সুন্দরভাবে ম্যানেজ করে।

সহজ কথায়, একটি Resource Signal হলো এমন একটি সিগন্যাল যা একটি অ্যাসিঙ্ক্রোনাস অপারেশনের সম্পূর্ণ জীবনচক্র (lifecycle) ধারণ করে।

---

### কেন এই প্যাটার্নটি দরকার?

সাধারণত, যখন আমরা API থেকে ডেটা আনি, তখন আমাদের তিনটি অবস্থা ম্যানেজ করতে হয়:

1.  **Loading:** ডেটা এখনো আসছে, ব্যবহারকারীকে একটি লোডার বা স্পিনার দেখাতে হবে।
2.  **Success:** ডেটা সফলভাবে চলে এসেছে, এখন UI-তে দেখাতে হবে।
3.  **Error:** কোনো কারণে ডেটা আনা সম্ভব হয়নি, একটি এরর মেসেজ দেখাতে হবে।

এই তিনটি অবস্থা ম্যানেজ করার জন্য আমরা আলাদা আলাদা ভ্যারিয়েবল বা সিগন্যাল ব্যবহার করতে পারি:

```typescript
isLoading = signal(true);
data = signal<User[] | null>(null);
error = signal<any | null>(null);
```

**সমস্যা:** এই পদ্ধতিতে বেশ কিছু সমস্যা আছে।
*   একসাথে একাধিক সিগন্যাল ম্যানেজ করা জটিল।
*   ভুলবশত `isLoading` `true` থাকা অবস্থায় `data`-তে মান চলে আসতে পারে, যা একটি অসামঞ্জস্যপূর্ণ অবস্থা (inconsistent state)।
*   কোড অগোছালো হয়ে যায়।

**সমাধান:** Resource Signal প্যাটার্ন এই তিনটি অবস্থাকে একটি মাত্র সিগন্যালের মধ্যে একটি অবজেক্ট হিসেবে রাখে, যা কোডকে অনেক বেশি পরিষ্কার, নিরাপদ এবং পরিচালনাযোগ্য করে তোলে।

---

### Resource Signal প্যাটার্নের গঠন

আমরা একটি `Resource` টাইপ তৈরি করব যা এই বিভিন্ন অবস্থাগুলোকে ধারণ করবে। TypeScript-এর Discriminated Unions ব্যবহার করে এটি খুব সুন্দরভাবে করা যায়।

**ধাপ ১: State Type গুলো ডিফাইন করা**

আমরা তিনটি অবস্থার জন্য আলাদা আলাদা টাইপ ডিফাইন করব:

```typescript
// যখন ডেটা লোড হচ্ছে
interface LoadingState {
  status: 'loading';
}

// যখন ডেটা সফলভাবে লোড হয়েছে
interface SuccessState<T> {
  status: 'success';
  value: T; // আমাদের আসল ডেটা এখানে থাকবে
}

// যখন কোনো এরর হয়েছে
interface ErrorState {
  status: 'error';
  error: unknown; // এরর অবজেক্ট
}

// এই তিনটি স্টেটকে একত্রিত করে একটি Union টাইপ তৈরি করা
export type Resource<T> = LoadingState | SuccessState<T> | ErrorState;
```

এই `Resource<T>` টাইপটি ব্যবহার করে আমরা এখন আমাদের সিগন্যাল তৈরি করতে পারব।

---

### একটি সম্পূর্ণ উদাহরণ: API থেকে Post ফেচ করা

ধরুন আমরা একটি API থেকে কিছু ব্লগ পোস্ট ফেচ করে দেখাব।

#### ধাপ ১: Resource টাইপ তৈরি করুন

উপরের টাইপ ডেফিনিশনগুলো একটি ফাইলে (`resource.model.ts`) রাখতে পারেন।

#### ধাপ ২: একটি সার্ভিস তৈরি করুন ডেটা আনার জন্য (`post.service.ts`)

সার্ভিসের মধ্যে আমরা Resource Signal রাখব এবং API কল করব।

```typescript
// src/app/post.service.ts
import { Injectable, signal, WritableSignal } from '@angular/core';
import { Resource } from './resource.model'; // আমাদের তৈরি করা টাইপ ইম্পোর্ট করুন

// পোস্টের ডেটার জন্য একটি ইন্টারফেস
export interface Post {
  id: number;
  title: string;
  body: string;
}

@Injectable({
  providedIn: 'root'
})
export class PostService {
  // আমাদের মূল Resource Signal। শুরুতে এটি 'loading' অবস্থায় থাকবে।
  public posts: WritableSignal<Resource<Post[]>> = signal({ status: 'loading' });

  constructor() {
    this.fetchPosts(); // সার্ভিস তৈরি হওয়ার সাথেই ডেটা আনা শুরু হবে
  }

  async fetchPosts(): Promise<void> {
    // পুনরায় ডেটা আনার আগে 'loading' state সেট করা
    this.posts.set({ status: 'loading' });

    try {
      const response = await fetch('https://jsonplaceholder.typicode.com/posts?_limit=10');
      
      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }
      
      const data: Post[] = await response.json();
      
      // সফল হলে 'success' state সেট করা
      this.posts.set({ status: 'success', value: data });

    } catch (err) {
      // এরর হলে 'error' state সেট করা
      this.posts.set({ status: 'error', error: err });
    }
  }
}
```

#### ধাপ ৩: কম্পোনেন্টে সার্ভিসটি ব্যবহার করুন (`posts.component.ts`)

এখন আমরা একটি কম্পোনেন্টে এই সার্ভিসটি ইনজেক্ট করব এবং UI তে ডেটা দেখানোর জন্য প্রস্তুত হব।

```typescript
// src/app/posts/posts.component.ts
import { Component, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { PostService } from '../post.service';

@Component({
  selector: 'app-posts',
  standalone: true,
  imports: [CommonModule],
  templateUrl: './posts.component.html',
  styleUrls: ['./posts.component.css']
})
export class PostsComponent {
  // সার্ভিস ইনজেক্ট করা
  private postService = inject(PostService);

  // সার্ভিস থেকে posts সিগন্যালটি কম্পোনেন্টে অ্যাক্সেস করা
  public posts = this.postService.posts;

  // ডেটা রিফ্রেশ করার জন্য একটি মেথড
  refresh() {
    this.postService.fetchPosts();
  }
}
```

#### ধাপ ৪: টেমপ্লেটে (`posts.component.html`) ডেটা দেখানো

এখানেই Resource Signal প্যাটার্নের আসল সৌন্দর্য প্রকাশ পায়। আমরা Angular-এর নতুন `@switch` কন্ট্রোল ফ্লো ব্যবহার করে খুব সহজেই তিনটি অবস্থা দেখাতে পারি।

```html
<!-- src/app/posts/posts.component.html -->

<div class="container">
  <h2>Blog Posts (Loaded with Resource Signal)</h2>
  <button (click)="refresh()">Refresh Posts</button>

  <div class="content">
    <!-- এখানে posts() সিগন্যালের status প্রপার্টির ওপর ভিত্তি করে UI দেখানো হচ্ছে -->
    @switch (posts().status) {

      <!-- কেস ১: যখন স্ট্যাটাস 'loading' -->
      @case ('loading') {
        <div class="loader">Loading posts...</div>
      }

      <!-- কেস ২: যখন স্ট্যাটাস 'success' -->
      @case ('success') {
        <!-- posts().value থেকে ডেটা অ্যাক্সেস করা হচ্ছে -->
        <ul class="post-list">
          @for (post of posts().value; track post.id) {
            <li>
              <h3>{{ post.title }}</h3>
              <p>{{ post.body }}</p>
            </li>
          }
        </ul>
      }

      <!-- কেস ৩: যখন স্ট্যাটাস 'error' -->
      @case ('error') {
        <div class="error">
          <p>Failed to load posts. Please try again.</p>
          <!-- posts().error থেকে এরর মেসেজ দেখানো যায় -->
          <pre>{{ posts().error | json }}</pre>
        </div>
      }
    }
  </div>
</div>
```

### Resource Signal প্যাটার্নের সুবিধা:

1.  **Single Source of Truth:** লোডিং, ডেটা এবং এরর—সবকিছু একটি মাত্র সিগন্যালের মধ্যে থাকে।
2.  **Type Safety:** TypeScript-এর Discriminated Union ব্যবহার করার কারণে, আপনি যখন `status` চেক করবেন, তখন টাইপস্কিপ্ট স্বয়ংক্রিয়ভাবে জানবে ওই ব্লকের মধ্যে কোন প্রপার্টিগুলো (`value` বা `error`) অ্যাভেইলেবল আছে। যেমন, `success` কেসে `error` প্রপার্টি অ্যাক্সেস করতে গেলে টাইপস্কিপ্ট এরর দেবে।
3.  **Declarative UI:** `@switch` ব্যবহার করে টেমপ্লেটের কোড অনেক বেশি ঘোষণামূলক (declarative) এবং পরিষ্কার থাকে। একাধিক `*ngIf` ব্যবহার করার ঝামেলা থেকে মুক্তি পাওয়া যায়।
4.  **No Inconsistent States:** `isLoading` `true` এবং `error` একই সাথে থাকার কোনো সুযোগই নেই, কারণ `status` একবারে কেবল একটি মান (`loading`, `success`, বা `error`) ধারণ করতে পারে।
5.  **Reusable and Clean:** এই প্যাটার্নটি পুরো অ্যাপ্লিকেশন জুড়ে যেকোনো অ্যাসিঙ্ক্রোনাস ডেটা লোডিং-এর জন্য পুনরায় ব্যবহার করা যেতে পারে।

আশা করি, এই ব্যাখ্যা এবং উদাহরণটি আপনাকে Resource Signal প্যাটার্নটি বুঝতে সাহায্য করেছে। এটি সিগন্যালের সাথে অ্যাসিঙ্ক্রোনাস কোড ম্যানেজ করার একটি অত্যন্ত কার্যকর এবং আধুনিক উপায়।

# ====== Linked Signal ======

খুব ভালো প্রশ্ন! "Linked Signal" অ্যাঙ্গুলারের আরেকটি চমৎকার **ডিজাইন প্যাটার্ন**, এটিও কোনো বিল্ট-ইন ফাংশন নয়। এই প্যাটার্নটি তখন ব্যবহার করা হয় যখন আপনার একটি গ্লোবাল স্টেট (যেমন, একটি সার্ভিসের সিগন্যাল) এবং একটি লোকাল কম্পোনেন্ট স্টেট (কম্পোনেন্টের নিজস্ব সিগন্যাল) সিঙ্ক্রোনাইজ (synchronize) করার প্রয়োজন হয়।

সহজ কথায়, একটি Linked Signal প্যাটার্ন আপনাকে একটি "সোর্স অফ ট্রুথ" (source of truth) সিগন্যালের একটি লোকাল, পরিবর্তনযোগ্য (mutable) কপি তৈরি করতে দেয়। আপনি লোকাল কপিতে ইচ্ছামতো পরিবর্তন করতে পারবেন এবং যখন চাইবেন, তখন সেই পরিবর্তনগুলোকে মূল সিগন্যালে "সেভ" বা "কমিট" করতে পারবেন।

---

### কেন এই প্যাটার্নটি দরকার? (The Problem)

ধরুন আপনার একটি `UserService`-এ ব্যবহারকারীর প্রোফাইল ডেটা একটি সিগন্যালে রাখা আছে।

```typescript
// user.service.ts
@Injectable({ providedIn: 'root' })
export class UserService {
  public currentUser = signal({ name: 'Sabbir Ahmed', email: 'sabbir@example.com' });
}
```

এখন আপনি একটি `ProfileEditorComponent` তৈরি করতে চান যেখানে ব্যবহারকারী তার নাম এবং ইমেইল পরিবর্তন করতে পারবে।

**ভুল পদ্ধতি (The Naive Approach):**
আপনি সরাসরি টেমপ্লেটে সার্ভিসের `currentUser` সিগন্যালটি `[(ngModel)]` দিয়ে বাইন্ড করতে পারেন।

```html
<!-- profile-editor.component.html -->
<input [(ngModel)]="userService.currentUser().name"> <!-- This is problematic! -->
```

**সমস্যা:**
এই পদ্ধতিতে, ইনপুট ফিল্ডে প্রতিটি অক্ষর টাইপ করার সাথে সাথেই **সরাসরি গ্লোবাল স্টেট (সার্ভিসের সিগন্যাল) আপডেট হয়ে যাবে**। এর অনেকগুলো অসুবিধা আছে:

1.  **কোনো "Cancel" অপশন নেই:** ব্যবহারকারী যদি ভুল করে কিছু টাইপ করে এবং আগের অবস্থায় ফিরে যেতে চায়, তার কোনো উপায় থাকবে না।
2.  **অপ্রয়োজনীয় আপডেট:** প্রতিটি কী-স্ট্রোক (keystroke) পুরো অ্যাপ্লিকেশনে একটি স্টেট পরিবর্তনের কারণ হতে পারে, যা অন্য কম্পোনেন্টগুলোতে অপ্রয়োজনীয় রি-রেন্ডার (re-render) ঘটাতে পারে।
3.  **অসম্পূর্ণ ডেটা:** ব্যবহারকারী ফর্ম পূরণ শেষ করার আগেই অ্যাপ্লিকেশনের অন্য অংশ অসম্পূর্ণ ডেটা পেয়ে যেতে পারে।

---

### সমাধান: Linked Signal প্যাটার্ন

এই প্যাটার্নটি উপরের সমস্যাগুলোর সমাধান করে। এর মূল ধারণা হলো:

1.  **লোকাল কপি তৈরি:** কম্পোনেন্টের ভেতরে একটি লোকাল `WritableSignal` তৈরি করুন যা সার্ভিসের সিগন্যাল থেকে প্রাথমিক মান নেবে।
2.  **একমুখী সিঙ্ক (One-way Sync):** একটি `effect` ব্যবহার করে সার্ভিসের সিগন্যালের পরিবর্তনগুলো লোকাল সিগন্যালে নিয়ে আসুন। এর ফলে যদি অন্য কোথাও থেকে গ্লোবাল স্টেট পরিবর্তন হয়, আপনার ফর্মটি আপ-টু-ডেট থাকবে।
3.  **ইউজার ইনপুট:** ব্যবহারকারীর সমস্ত পরিবর্তন শুধুমাত্র লোকাল সিগন্যালেই সীমাবদ্ধ থাকবে।
4.  **কমিট বা রিসেট:** ব্যবহারকারী "Save" বাটনে ক্লিক করলে লোকাল সিগন্যালের মানটি সার্ভিসের মূল সিগন্যালে আপডেট করা হবে। "Cancel" বা "Reset" বাটনে ক্লিক করলে লোকাল সিগন্যালটিকে আবার মূল সিগন্যালের মান দিয়ে রিসেট করা হবে।

---

### একটি সম্পূর্ণ উদাহরণ: প্রোফাইল এডিটর

#### ধাপ ১: ইউজার সার্ভিস (Global State)

সার্ভিসে আমরা একটি `updateUser` মেথড রাখব যা দিয়ে নিরাপদে স্টেট আপডেট করা যায়।

```typescript
// src/app/user.service.ts
import { Injectable, signal } from '@angular/core';

export interface UserProfile {
  name: string;
  email: string;
}

@Injectable({
  providedIn: 'root'
})
export class UserService {
  // Source of Truth
  public currentUser = signal<UserProfile>({ 
    name: 'Sabbir Ahmed', 
    email: 'sabbir@example.com' 
  });

  // Method to safely update the global state
  updateUser(updatedProfile: UserProfile) {
    this.currentUser.set(updatedProfile);
  }
}
```

#### ধাপ ২: প্রোফাইল এডিটর কম্পোনেন্ট (Local State)

এখানেই Linked Signal প্যাটার্নটি প্রয়োগ করা হবে।

```typescript
// src/app/profile-editor/profile-editor.component.ts
import { Component, signal, effect, inject } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { UserService, UserProfile } from '../user.service';

@Component({
  selector: 'app-profile-editor',
  standalone: true,
  imports: [FormsModule],
  templateUrl: './profile-editor.component.html',
  styleUrls: ['./profile-editor.component.css']
})
export class ProfileEditorComponent {
  private userService = inject(UserService);

  // ১. লোকাল সিগন্যাল (কম্পোনেন্টের নিজস্ব স্টেট)
  // এর প্রাথমিক মান সার্ভিসের সিগন্যাল থেকে নেওয়া হচ্ছে
  public userForm = signal<UserProfile>(this.userService.currentUser());

  constructor() {
    // ২. একমুখী সিঙ্ক (Linked Signal এর মূল অংশ)
    // যখনই সার্ভিসের currentUser সিগন্যাল পরিবর্তন হবে, আমাদের লোকাল userForm সিগন্যাল আপডেট হবে।
    effect(() => {
      console.log('Global user state changed. Syncing local form state.');
      this.userForm.set(this.userService.currentUser());
    });
  }

  // ৩. কমিট মেথড (লোকাল পরিবর্তন গ্লোবালে সেভ করা)
  saveProfile() {
    // লোকাল userForm সিগন্যালের মান দিয়ে সার্ভিসের updateUser মেথড কল করা
    this.userService.updateUser(this.userForm());
    console.log('Profile saved!', this.userForm());
  }

  // ৪. রিসেট মেথড (লোকাল পরিবর্তন বাতিল করা)
  resetForm() {
    // লোকাল সিগন্যালকে আবার সার্ভিসের বর্তমান মান দিয়ে সেট করা
    this.userForm.set(this.userService.currentUser());
    console.log('Form reset to original state.');
  }
}
```

#### ধাপ ৩: টেমপ্লেট (`profile-editor.component.html`)

টেমপ্লেটে আমরা শুধুমাত্র লোকাল `userForm` সিগন্যাল ব্যবহার করব।

```html
<!-- src/app/profile-editor/profile-editor.component.html -->
<div class="profile-card">
  <h3>Edit Your Profile</h3>

  <!-- ইনপুট ফিল্ডগুলো লোকাল userForm সিগন্যালের সাথে বাইন্ড করা -->
  <div class="form-group">
    <label for="name">Name:</label>
    <input id="name" type="text" [(ngModel)]="userForm().name">
  </div>

  <div class="form-group">
    <label for="email">Email:</label>
    <input id="email" type="email" [(ngModel)]="userForm().email">
  </div>
  
  <div class="buttons">
    <button (click)="saveProfile()">Save</button>
    <button (click)="resetForm()">Reset</button>
  </div>
</div>

<!-- শুধু দেখার জন্য সার্ভিসের মূল ডেটা দেখাচ্ছি -->
<div class="global-state-display">
  <h4>Current Global State (from Service)</h4>
  <p>Name: {{ userService.currentUser().name }}</p>
  <p>Email: {{ userService.currentUser().email }}</p>
</div>
```

এখন অ্যাপ্লিকেশনটি রান করলে আপনি দেখবেন:
1.  ইনপুট ফিল্ডে টাইপ করলে শুধুমাত্র উপরের `profile-card` অংশের ডেটা পরিবর্তন হচ্ছে। নিচের "Global State" অংশে কোনো পরিবর্তন হচ্ছে না।
2.  "Save" বাটনে ক্লিক করার পরেই নিচের "Global State" আপডেট হচ্ছে।
3.  কিছু পরিবর্তন করার পর "Reset" বাটনে ক্লিক করলে আপনার পরিবর্তনগুলো বাতিল হয়ে যাবে এবং ফর্মটি আবার গ্লোবাল স্টেটের মানে ফিরে আসবে।

### Linked Signal প্যাটার্নের সুবিধা:

1.  **Atomic Updates:** গ্লোবাল স্টেট শুধুমাত্র তখনই আপডেট হয় যখন ব্যবহারকারী নির্দিষ্ট কোনো অ্যাকশন (যেমন, Save) নেয়। এতে অ্যাপ্লিকেশনের স্টেট প্রেডিক্টেবল থাকে।
2.  **Decoupling:** কম্পোনেন্ট তার নিজস্ব স্টেটের ওপর কাজ করে, যা গ্লোবাল স্টেট থেকে বিচ্ছিন্ন (decoupled)। এটি কম্পোনেন্টকে আরও বেশি মডুলার এবং টেস্টিং-এর জন্য সহজ করে তোলে।
3.  **Improved UX:** ব্যবহারকারীকে পরিবর্তন বাতিল করার সুযোগ দিয়ে একটি ভালো ইউজার এক্সপেরিয়েন্স প্রদান করা যায়।
4.  **Clear Data Flow:** ডেটা প্রবাহের পথ খুব পরিষ্কার: গ্লোবাল থেকে লোকালে আসে `effect`-এর মাধ্যমে, এবং লোকাল থেকে গ্লোবালে যায় একটি নির্দিষ্ট মেথড কলের মাধ্যমে।

এই প্যাটার্নটি বিশেষ করে ফর্ম, এডিটর বা এমন যেকোনো ফিচারের জন্য খুবই উপকারী যেখানে ব্যবহারকারীকে ডেটা পরিবর্তন করার পর সেভ বা বাতিল করার অপশন দিতে হয়।

# ==== Computed Signal ======


অবশ্যই! `computed()` সিগন্যাল হলো Angular Signals ইকোসিস্টেমের একটি অত্যন্ত গুরুত্বপূর্ণ এবং শক্তিশালী অংশ।

সহজ কথায়, **`computed()` সিগন্যাল ব্যবহার করা হয় যখন একটি সিগন্যালের মান অন্য এক বা একাধিক সিগন্যালের মানের উপর নির্ভরশীল হয়।** এটি অনেকটা একটি read-only সিগন্যালের মতো, যার মান স্বয়ংক্রিয়ভাবে আপডেট হয় যখন তার উপর নির্ভরশীল (dependent) সিগন্যালগুলোর মান পরিবর্তন হয়।

---

### `computed()` সিগন্যালের মূল বৈশিষ্ট্য

1.  **Derived Value (উৎপন্ন মান):** এটি নিজে কোনো state ধারণ করে না। বরং অন্য সিগন্যাল থেকে এর মান হিসাব (calculate) করে বের করে।
2.  **Lazy Evaluation (অলস মূল্যায়ন):** `computed` সিগন্যালের মান শুধুমাত্র তখনই নতুন করে হিসাব করা হয় যখন কেউ এর মান পড়তে চায় (`myComputedSignal()`) এবং এর উপর নির্ভরশীল কোনো সিগন্যালের মান পরিবর্তন হয়েছে। যদি কেউ এর মান না পড়ে, তাহলে অপ্রয়োজনে কোনো হিসাব করা হয় না।
3.  **Memoization (ফলাফল মনে রাখা):** যখন একটি `computed` সিগন্যালের মান একবার হিসাব করা হয়, তখন সেই ফলাফলটি সে মনে রাখে (cache করে)। যতক্ষণ পর্যন্ত তার নির্ভরশীল সিগন্যালগুলোর মান পরিবর্তন না হয়, ততক্ষণ এটি পুরোনো ফলাফলটিই রিটার্ন করবে, বারবার হিসাব করবে না।

এই দুটি বৈশিষ্ট্য (`Lazy Evaluation` এবং `Memoization`) পারফরম্যান্সের জন্য অত্যন্ত গুরুত্বপূর্ণ।

---

### কেন এবং কখন `computed()` ব্যবহার করবেন?

আপনি `computed` ব্যবহার করবেন যখন:
*   আপনার UI-তে এমন কোনো ডেটা দেখানোর প্রয়োজন হয় যা অন্য কোনো state-এর উপর ভিত্তি করে তৈরি হয়।
*   আপনি অপ্রয়োজনীয় re-calculation এড়াতে চান।
*   আপনি আপনার কোডকে আরও ঘোষণামূলক (declarative) এবং পরিষ্কার রাখতে চান।

**উদাহরণ:**
*   `firstName` এবং `lastName` সিগন্যাল থেকে `fullName` তৈরি করা।
*   একটি শপিং কার্টের আইটেমগুলোর তালিকা (সিগন্যাল) থেকে মোট মূল্য (total price) হিসাব করা।
*   একটি `tasks` অ্যারে (সিগন্যাল) থেকে কয়টি টাস্ক সম্পন্ন হয়েছে তা গণনা করা।
*   একটি ফিল্টার করা তালিকা দেখানো, যেখানে মূল তালিকা এবং ফিল্টার স্ট্রিং দুটিই সিগন্যাল।

### একটি সম্পূর্ণ এবং সহজ উদাহরণ: শপিং কার্ট

ধরুন আমাদের একটি শপিং কার্ট আছে যেখানে ব্যবহারকারী বিভিন্ন প্রোডাক্ট যোগ করতে পারে। আমরা প্রোডাক্টের তালিকা, মোট আইটেমের সংখ্যা এবং মোট মূল্য দেখাব।

#### ধাপ ১: কম্পোনেন্ট তৈরি করুন

```typescript
// src/app/shopping-cart/shopping-cart.component.ts

import { Component, signal, computed, WritableSignal, Signal } from '@angular/core';
import { CommonModule } from '@angular/common'; // ngFor, ngIf এর জন্য

// প্রোডাক্টের জন্য একটি ইন্টারফেস
interface Product {
  id: number;
  name: string;
  price: number;
}

@Component({
  selector: 'app-shopping-cart',
  standalone: true,
  imports: [CommonModule],
  templateUrl: './shopping-cart.component.html',
  styleUrls: ['./shopping-cart.component.css']
})
export class ShoppingCartComponent {

  // ১. মূল state: কার্টে থাকা প্রোডাক্টের তালিকা একটি WritableSignal
  public cartItems: WritableSignal<Product[]> = signal([
    { id: 1, name: 'Angular T-Shirt', price: 25 },
    { id: 2, name: 'Signal Mug', price: 15 }
  ]);

  // ২. Computed Signal: মোট আইটেমের সংখ্যা গণনা করা
  // এই সিগন্যালটি `cartItems` এর উপর নির্ভরশীল।
  public totalItems: Signal<number> = computed(() => {
    console.log('Calculating total items...'); // কখন হিসাব হচ্ছে তা দেখার জন্য
    return this.cartItems().length;
  });

  // ৩. Computed Signal: মোট মূল্য গণনা করা
  // এই সিগন্যালটিও `cartItems` এর উপর নির্ভরশীল।
  public totalPrice: Signal<number> = computed(() => {
    console.log('Calculating total price...'); // কখন হিসাব হচ্ছে তা দেখার জন্য
    return this.cartItems().reduce((sum, item) => sum + item.price, 0);
  });
  
  // একটি নতুন প্রোডাক্ট যোগ করার মেথড
  addProduct() {
    const newProduct: Product = {
      id: Date.now(), // ইউনিক আইডি
      name: `New Item #${Math.floor(Math.random() * 100)}`,
      price: Math.floor(Math.random() * 50) + 10
    };

    // cartItems সিগন্যাল আপডেট করা
    this.cartItems.update(currentItems => [...currentItems, newProduct]);
  }

  // একটি প্রোডাক্ট মুছে ফেলার মেথড
  removeItem(productId: number) {
    this.cartItems.update(currentItems => 
      currentItems.filter(item => item.id !== productId)
    );
  }
}
```

#### ধাপ ২: টেমপ্লেট তৈরি করুন

```html
<!-- src/app/shopping-cart/shopping-cart.component.html -->

<div class="cart-container">
  <h2>My Shopping Cart</h2>
  <button (click)="addProduct()">Add Random Product</button>

  <!-- Computed Signal: totalItems এবং totalPrice ব্যবহার -->
  <div class="summary">
    <p>Total Items: <strong>{{ totalItems() }}</strong></p>
    <p>Total Price: <strong>${{ totalPrice() }}</strong></p>
  </div>

  <hr>

  <!-- মূল সিগন্যাল: cartItems এর তালিকা দেখানো -->
  <ul class="item-list">
    @for (item of cartItems(); track item.id) {
      <li>
        <span>{{ item.name }} - ${{ item.price }}</span>
        <button class="remove-btn" (click)="removeItem(item.id)">Remove</button>
      </li>
    } @empty {
      <p>Your cart is empty.</p>
    }
  </ul>
</div>
```

### কী ঘটছে এখানে?

1.  `cartItems` হলো আমাদের "source of truth"। এটি একটি `WritableSignal`, যার মান আমরা পরিবর্তন করতে পারি।
2.  `totalItems` এবং `totalPrice` হলো `computed` সিগন্যাল। তারা `cartItems` সিগন্যালের উপর "শুনছে" (listening)।
3.  যখন কম্পোনেন্ট প্রথম লোড হয়, Angular টেমপ্লেটে `totalItems()` এবং `totalPrice()` দেখে। তখন এই `computed` সিগন্যালগুলো তাদের মান হিসাব করে এবং cache করে রাখে। আপনি কনসোলে "Calculating..." লগগুলো দেখতে পাবেন।
4.  আপনি যদি কিছু না করে বসে থাকেন, তাহলে কোনো কিছুই আবার হিসাব হবে না, কারণ `cartItems`-এর মান পরিবর্তন হয়নি।
5.  যখন আপনি "Add Random Product" বাটনে ক্লিক করেন, তখন `cartItems` সিগন্যালটি আপডেট হয়।
6.  `cartItems` পরিবর্তন হওয়ার সাথে সাথেই Angular বুঝতে পারে যে এর উপর নির্ভরশীল `totalItems` এবং `totalPrice` সিগন্যালগুলো এখন "stale" (পুরোনো) হয়ে গেছে।
7.  পরবর্তীতে যখন Angular UI আপডেট করার জন্য `totalItems()` এবং `totalPrice()`-এর মান আবার পড়তে যায়, তখন `computed` ফাংশনগুলো নতুন করে রান হয়, নতুন মান হিসাব করে, এবং UI তে সেই নতুন মান দেখানো হয়।

**গুরুত্বপূর্ণ পর্যবেক্ষণ:** যদি `cartItems` পরিবর্তন না হয়, তাহলে `totalItems` এবং `totalPrice` ফাংশনগুলো কখনোই রান হবে না, যা পারফরম্যান্সের জন্য অসাধারণ। এটাই `computed`-এর মূল শক্তি। এটি নিশ্চিত করে যে শুধুমাত্র প্রয়োজনীয় হিসাবগুলোই করা হচ্ছে, এবং শুধুমাত্র তখনই করা হচ্ছে যখন দরকার।


# ===  Featch  Signal ====

চমৎকার! "Fetch Signal" বা ডেটা ফেচ করার জন্য সিগন্যাল ব্যবহার করা অ্যাঙ্গুলারের একটি খুবই সাধারণ এবং শক্তিশালী প্যাটার্ন। আপনি আগে যে "Resource Signal" প্যাটার্নটি দেখেছেন, এটি তারই একটি বাস্তব প্রয়োগ।

মূলত, "Fetch Signal" বলতে বোঝায় API থেকে ডেটা আনার পুরো প্রক্রিয়াটিকে (লোডিং,成功, এরর) একটি সিগন্যালের মধ্যে পরিচালনা করা। এতে কোড অনেক বেশি পরিষ্কার, অনুমানযোগ্য (predictable) এবং প্রতিক্রিয়াশীল (reactive) হয়।

আসুন, আমরা একটি ব্যবহারিক উদাহরণ দিয়ে ধাপে ধাপে দেখি কীভাবে একটি "Fetch Signal" তৈরি এবং ব্যবহার করতে হয়।

**আমাদের লক্ষ্য:** একটি বাটনে ক্লিক করলে একটি নির্দিষ্ট ইউজারের ডেটা API থেকে ফেচ করে আনা এবং UI-তে তার বিভিন্ন অবস্থা (loading, success, error) দেখানো।

### ধাপ ১: Resource State টাইপ তৈরি করা

প্রথমেই আমরা আমাদের সিগন্যালের বিভিন্ন অবস্থার জন্য একটি টাইপ ডিফাইন করব। এটি "Resource Signal" প্যাটার্নের ভিত্তি।

```typescript
// src/app/models/resource.model.ts

// যখন ডেটা লোড হচ্ছে
interface LoadingState {
  status: 'loading';
}

// যখন ডেটা সফলভাবে লোড হয়েছে
interface SuccessState<T> {
  status: 'success';
  value: T;
}

// যখন কোনো এরর হয়েছে
interface ErrorState {
  status: 'error';
  error: unknown;
}

// একটি অতিরিক্ত 'idle' স্টেট যোগ করা যেতে পারে, যা ডেটা ফেচ শুরু হওয়ার আগের অবস্থা বোঝায়
interface IdleState {
  status: 'idle';
}

// সবগুলোকে নিয়ে একটি Union Type
export type Resource<T> = IdleState | LoadingState | SuccessState<T> | ErrorState;
```

### ধাপ ২: একটি ডেটা সার্ভিস তৈরি করা

এই সার্ভিসটি API কলের লজিক এবং "Fetch Signal" ধারণ করবে।

```typescript
// src/app/user.service.ts
import { Injectable, signal, WritableSignal } from '@angular/core';
import { Resource } from './models/resource.model';

// ইউজারের ডেটার জন্য ইন্টারফেস
export interface User {
  id: number;
  name: string;
  email: string;
  phone: string;
}

@Injectable({
  providedIn: 'root'
})
export class UserService {
  // আমাদের "Fetch Signal" বা Resource Signal
  // শুরুতে এর অবস্থা 'idle' থাকবে
  public user: WritableSignal<Resource<User>> = signal({ status: 'idle' });

  // API থেকে ইউজার ডেটা আনার মেথড
  async fetchUser(userId: number): Promise<void> {
    // ১. ডেটা আনা শুরু করার আগে 'loading' স্টেট সেট করা
    this.user.set({ status: 'loading' });
    console.log(`Fetching user with ID: ${userId}...`);

    try {
      // ২. API কল করা
      const response = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);

      if (!response.ok) {
        throw new Error(`Failed to fetch user. Status: ${response.status}`);
      }

      const userData: User = await response.json();

      // ৩. সফল হলে 'success' স্টেট এবং ডেটা সেট করা
      this.user.set({ status: 'success', value: userData });
      console.log('User fetched successfully:', userData);

    } catch (err) {
      // ৪. কোনো সমস্যা হলে 'error' স্টেট এবং এরর অবজেক্ট সেট করা
      this.user.set({ status: 'error', error: err });
      console.error('Error fetching user:', err);
    }
  }

  // সিগন্যালকে আবার idle অবস্থায় রিসেট করার জন্য একটি মেথড
  reset() {
      this.user.set({ status: 'idle' });
  }
}
```

### ধাপ ৩: কম্পোনেন্টে সার্ভিসটি ব্যবহার করা

এখন আমরা একটি কম্পোনেন্ট তৈরি করব যেখানে ইউজার আইডি ইনপুট দেওয়া যাবে এবং ডেটা ফেচ করা হবে।

```typescript
// src/app/user-profile/user-profile.component.ts
import { Component, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { FormsModule } from '@angular/forms'; // ngModel এর জন্য
import { UserService } from '../user.service';

@Component({
  selector: 'app-user-profile',
  standalone: true,
  imports: [CommonModule, FormsModule],
  templateUrl: './user-profile.component.html',
  styleUrls: ['./user-profile.component.css']
})
export class UserProfileComponent {
  private userService = inject(UserService);

  // সার্ভিস থেকে user সিগন্যালটি সরাসরি কম্পোনেন্টে ব্যবহার করা হচ্ছে
  public user = this.userService.user;

  public userIdToFetch: number = 1;

  // ডেটা আনার জন্য মেথড
  loadUser() {
    this.userService.fetchUser(this.userIdToFetch);
  }
  
  // রিসেট করার জন্য মেথড
  resetView() {
    this.userService.reset();
  }
}
```

### ধাপ ৪: টেমপ্লেটে বিভিন্ন অবস্থা দেখানো

এখানে `@switch` ব্যবহার করে আমরা খুব সহজেই সিগন্যালের `status`-এর উপর ভিত্তি করে ভিন্ন ভিন্ন UI দেখাতে পারব।

```html
<!-- src/app/user-profile/user-profile.component.html -->

<div class="container">
  <h2>Fetch User Profile with Signal</h2>

  <div class="controls">
    <label for="userId">Enter User ID (1-10):</label>
    <input id="userId" type="number" [(ngModel)]="userIdToFetch" min="1" max="10">
    <button (click)="loadUser()">Fetch User</button>
    <button (click)="resetView()">Reset</button>
  </div>

  <div class="content-area">
    <!-- এখানে user() সিগন্যালের status প্রপার্টির ওপর ভিত্তি করে UI দেখানো হচ্ছে -->
    @switch (user().status) {

      @case ('idle') {
        <p class="idle-message">Enter a user ID and click "Fetch User" to start.</p>
      }

      @case ('loading') {
        <div class="loader">Loading...</div>
      }

      @case ('success') {
        <!-- user().value থেকে ডেটা অ্যাক্সেস করা হচ্ছে -->
        <div class="profile-card">
          <h3>{{ user().value.name }}</h3>
          <p><strong>Email:</strong> {{ user().value.email }}</p>
          <p><strong>Phone:</strong> {{ user().value.phone }}</p>
        </div>
      }

      @case ('error') {
        <div class="error-message">
          <p>Something went wrong!</p>
          <!-- user().error থেকে এরর মেসেজ দেখানো যায় -->
          <pre>{{ user().error | json }}</pre>
        </div>
      }
    }
  </div>
</div>
```

### এই প্যাটার্নের সুবিধাগুলো আবার দেখে নেওয়া যাক:

1.  **একক সত্যের উৎস (Single Source of Truth):** ডেটা, লোডিং অবস্থা এবং এরর—সবকিছু একটি মাত্র `user` সিগন্যালের মধ্যে আবদ্ধ। একাধিক `isLoading`, `userData`, `errorMessage` ভ্যারিয়েবল ম্যানেজ করার কোনো ঝামেলা নেই।
2.  **ক্লিন ও ঘোষণামূলক টেমপ্লেট (Clean & Declarative Template):** `@switch` ব্যবহার করার ফলে টেমপ্লেটের কোড পড়া এবং বোঝা অনেক সহজ। কোনো জটিল `*ngIf / else` চেইন তৈরি করতে হয় না।
3.  **টাইপ-সেফ (Type-Safe):** `Resource<T>` টাইপ ব্যবহারের কারণে আপনি `success` ব্লকের ভেতরে নিশ্চিতভাবে `user().value` পাবেন এবং `error` ব্লকের ভেতরে `user().error` পাবেন। টাইপস্ক্রিপ্ট আপনাকে ভুল প্রপার্টি অ্যাক্সেস করতে দেবে না।
4.  **কোনো অসামঞ্জস্যপূর্ণ অবস্থা নেই (No Inconsistent States):** `status` একবারে কেবল একটি মান (`idle`, `loading`, `success` বা `error`) ধারণ করতে পারে। তাই `loading` এবং `error` একই সাথে `true` হওয়ার কোনো সুযোগই নেই।
5.  **পরীক্ষা করা সহজ (Easy to Test):** আপনি সহজেই সার্ভিসের `user` সিগন্যালের মান মক (mock) করে কম্পোনেন্টের বিভিন্ন অবস্থা (loading, success, error) পরীক্ষা করতে পারবেন।

এই "Fetch Signal" বা "Resource Signal" প্যাটার্নটি অ্যাঙ্গুলারে আধুনিক উপায়ে অ্যাসিঙ্ক্রোনাস ডেটা ম্যানেজ করার জন্য একটি ইন্ডাস্ট্রি-স্ট্যান্ডার্ড পদ্ধতি হয়ে উঠছে।


# ==== Effect Signal =====

অবশ্যই! `effect()` ফাংশনটি Angular Signals ইকোসিস্টেমের একটি অপরিহার্য অংশ, যা মূলত **"side effects"** পরিচালনা করার জন্য ব্যবহৃত হয়।

সহজ কথায়, **`effect()` এমন একটি অপারেশন যা এক বা একাধিক সিগন্যালের মান পরিবর্তনের প্রতিক্রিয়ায় রান হয়, কিন্তু নিজে কোনো নতুন মান তৈরি করে না।** এর মূল উদ্দেশ্য হলো সিগন্যালের জগতের (reactive world) সাথে বাইরের জগতের (imperative world) সংযোগ স্থাপন করা।

---

### `effect()` কী করে?

একটি `effect` তৈরি করলে, Angular স্বয়ংক্রিয়ভাবে ট্র্যাক করে যে ওই `effect`-এর ভেতরের কোড কোন কোন সিগন্যাল পড়ছে (read করছে)। যখনই ওই সিগন্যালগুলোর কোনো একটির মান পরিবর্তন হয়, Angular স্বয়ংক্রিয়ভাবে `effect` ফাংশনটিকে আবার রান করে।

**উদাহরণ:**
```typescript
const count = signal(0);

effect(() => {
  console.log(`The current count is: ${count()}`);
});
// Console output: The current count is: 0

count.set(5);
// Console output: The current count is: 5
```
এখানে `effect` ফাংশনটি `count` সিগন্যালটিকে পড়ছে। তাই `count`-এর মান যখনই পরিবর্তন হচ্ছে, `effect`-এর ভেতরের `console.log` কোডটি আবার রান হচ্ছে।

---

### কখন `effect()` ব্যবহার করবেন? (Use Cases)

`effect` ব্যবহার করা হয় এমন সব কাজের জন্য যা সরাসরি UI রেন্ডারিং বা অন্য কোনো সিগন্যালের মান নির্ধারণের সাথে জড়িত নয়। এর কিছু সাধারণ ব্যবহার নিচে দেওয়া হলো:

1.  **ডেটা সিঙ্ক্রোনাইজেশন (Data Synchronization):**
    *   `localStorage` বা `sessionStorage`-এর সাথে ডেটা সিঙ্ক করা। যখনই কোনো সিগন্যালের মান পরিবর্তন হয়, সেটি `localStorage`-এ সেভ করা।
    *   ব্রাউজারের `document.title` আপডেট করা।

2.  **লগিং এবং অ্যানালিটিক্স (Logging and Analytics):**
    *   যখন কোনো নির্দিষ্ট সিগন্যালের মান পরিবর্তন হয়, তখন কনসোলে লগ করা বা কোনো অ্যানালিটিক্স সার্ভারে ইভেন্ট পাঠানো।

3.  **কাস্টম DOM ম্যানিপুলেশন (Custom DOM Manipulation):**
    *   যখন কোনো থার্ড-পার্টি লাইব্রেরি (যেমন, একটি চার্টিং লাইব্রেরি) ব্যবহার করার প্রয়োজন হয় যা Angular-এর রেন্ডারিং সিস্টেমের বাইরে কাজ করে। `effect`-এর ভেতরে আপনি সেই লাইব্রেরির API কল করে UI আপডেট করতে পারেন।

4.  **নেটওয়ার্ক রিকোয়েস্ট (Network Requests):**
    *   যদিও খুব সাধারণ নয়, তবে কিছু ক্ষেত্রে ফিল্টার বা সার্চ টার্ম সিগন্যালের পরিবর্তনের প্রতিক্রিয়ায় API কল করার জন্য ব্যবহার করা যেতে পারে। (তবে এর জন্য প্রায়ই RxJS-এর `switchMap` বেশি উপযুক্ত)।

---

### `effect()`-এর গুরুত্বপূর্ণ বৈশিষ্ট্য এবং নিয়ম

1.  **No Writes Allowed (বাই ডিফল্ট লেখা নিষেধ):** একটি `effect`-এর ভেতর থেকে সরাসরি অন্য কোনো সিগন্যালের মান পরিবর্তন (`set` বা `update`) করা উচিত নয়। এটি করলে একটি অসীম লুপ (infinite loop) তৈরি হতে পারে।
    *   **ভুল উদাহরণ:**
        ```typescript
        const count = signal(0);
        effect(() => {
          count.set(count() + 1); // ERROR! This will cause an infinite loop.
        });
        ```
    *   যদি একান্তই কোনো সিগন্যাল আপডেট করতে হয়, তবে `effect` তৈরির সময় `{ allowSignalWrites: true }` অপশনটি পাস করতে হবে। তবে এটি শুধুমাত্র বিশেষ প্রয়োজনে এবং খুব সতর্কতার সাথে ব্যবহার করা উচিত।

2.  **শুধুমাত্র `injection context`-এ তৈরি করা যায়:** `effect()` শুধুমাত্র একটি কম্পোনেন্ট, ডিরেক্টিভ বা সার্ভিসের `constructor`-এর ভেতরে অথবা কোনো ফিল্ড ইনিশিয়ালাইজার (field initializer) হিসেবে কল করা যায়। এর কারণ হলো `effect`-কে তার লাইফসাইকেল ম্যানেজ করার জন্য (যেমন, কম্পোনেন্ট ধ্বংস হলে `effect` টিও বন্ধ হয়ে যাওয়া) অ্যাঙ্গুলারের Dependency Injection সিস্টেমের সাথে যুক্ত থাকতে হয়।
    *   **সঠিক ব্যবহার:**
        ```typescript
        @Component({...})
        export class MyComponent {
          count = signal(0);

          constructor() {
            effect(() => {
              console.log(this.count());
            });
          }
        }
        ```
    *   **ভুল ব্যবহার:**
        ```typescript
        @Component({...})
        export class MyComponent {
          someMethod() {
            // ERROR: effect() can only be used within an injection context.
            effect(() => { ... }); 
          }
        }
        ```
      * **সমাধান:** যদি কনস্ট্রাক্টরের বাইরে `effect` ব্যবহার করতে হয়, তবে `Injector` পাস করতে হবে: `effect(() => {...}, { injector: this.injector });`।


3.  **ক্লিন-আপ ফাংশন (Cleanup Function):** `effect` একটি ক্লিনিং লজিক রেজিস্টার করার সুযোগ দেয়। `effect`-এর ভেতরের ফাংশন থেকে যদি আরেকটি ফাংশন রিটার্ন করা হয়, তবে সেই রিটার্ন করা ফাংশনটি পরবর্তীবার `effect` রান হওয়ার আগে অথবা `effect` টি ধ্বংস (destroy) হওয়ার সময় রান হবে। এটি ইভেন্ট লিসেনার বা টাইমার পরিষ্কার করার জন্য খুবই দরকারি।

    ```typescript
    effect((onCleanup) => {
      const timer = setInterval(() => {
        console.log('Timer running...');
      }, 1000);

      onCleanup(() => {
        clearInterval(timer); // কম্পোনেন্ট ধ্বংস হলে বা effect আবার রান হলে টাইমার বন্ধ হবে
        console.log('Timer stopped.');
      });
    });
    ```

### একটি সম্পূর্ণ উদাহরণ: `localStorage` সিঙ্ক করা

ধরুন আমরা একটি থিম সিলেকশন ফিচার তৈরি করছি, যেখানে ব্যবহারকারীর 선택 করা থিমটি `localStorage`-এ সেভ হবে যাতে পেজ রিফ্রেশ করলেও থিমটি মনে থাকে।

```typescript
// theme-switcher.component.ts
import { Component, signal, effect } from '@angular/core';

@Component({
  selector: 'app-theme-switcher',
  standalone: true,
  template: `
    <div>
      <h2>Select Theme</h2>
      <select (change)="onThemeChange($event)">
        <option value="light" [selected]="theme() === 'light'">Light</option>
        <option value="dark" [selected]="theme() === 'dark'">Dark</option>
      </select>
      <p>Current selected theme is: <strong>{{ theme() }}</strong></p>
    </div>
  `
})
export class ThemeSwitcherComponent {
  // ১. localStorage থেকে প্রাথমিক মান নিয়ে সিগন্যাল তৈরি করা
  public theme = signal<'light' | 'dark'>(
    (localStorage.getItem('app-theme') as 'light' | 'dark') || 'light'
  );

  constructor() {
    // ২. effect তৈরি করা যা theme সিগন্যালের পরিবর্তন ট্র্যাক করবে
    effect(() => {
      const currentTheme = this.theme();
      console.log(`Theme changed to: ${currentTheme}. Saving to localStorage.`);
      
      // ৩. localStorage-এ নতুন মান সেভ করা (Side Effect)
      localStorage.setItem('app-theme', currentTheme);

      // আরেকটি side effect: body-তে ক্লাস যোগ করা
      document.body.className = currentTheme;
    });
  }

  // UI থেকে থিম পরিবর্তন করার মেথড
  onThemeChange(event: Event) {
    const newTheme = (event.target as HTMLSelectElement).value as 'light' | 'dark';
    this.theme.set(newTheme);
  }
}
```

এই উদাহরণে:
*   `theme` সিগন্যালটি আমাদের অ্যাপ্লিকেশনের স্টেট ধারণ করছে।
*   যখনই `theme` সিগন্যালের মান পরিবর্তন হচ্ছে, `effect` ফাংশনটি রান হচ্ছে।
*   `effect`-এর ভেতরে আমরা দুটি "side effect" সম্পাদন করছি:
    1.  `localStorage`-এ ডেটা সেভ করছি।
    2.  `document.body`-এর ক্লাস পরিবর্তন করছি CSS স্টাইলিং-এর জন্য।

এভাবেই `effect()` সিগন্যালের প্রতিক্রিয়াশীল জগতের সাথে বাইরের জগতের কাজগুলোকে সুন্দরভাবে একত্রিত করে।
