### **Lesson 1: Reactive Programming - আসলে জিনিসটা খায় না মাথায় দেয়?**

শোনো, আমরা যারা জাভাস্ক্রিপ্ট ডেভেলপার, আমরা সাধারণত **Imperative** স্টাইলে কোড লিখি। মানে আমরা কোডকে বলে দেই—"এইটা করো, তারপর ওইটা করো, তারপর বসে থাকো।"

কিন্তু **Reactive Programming** হলো সম্পূর্ণ উল্টো। এখানে আমরা বসে থাকি এবং যখন কিছু ঘটে, তখন রিয়্যাক্ট (React) করি।

ব্যাপারটা মাথার উপর দিয়ে গেল? চলো সহজ করি।

#### **Scenario: বৃষ্টির দিন এবং তুমি** 🌧️

ধরো, তুমি ছাদে কাপড় শুকাতে দিয়েছ। এখন তোমার লক্ষ্য হলো বৃষ্টি আসলে কাপড় তোলা। এই কাজটা দুইভাবে করা যায়:

**১. Imperative Way (সাধারণ পদ্ধতি):**
তুমি প্রতি ৫ মিনিট পর পর ছাদে যাচ্ছ এবং চেক করছ—"বৃষ্টি কি হচ্ছে? না।", আবার ৫ মিনিট পর—"বৃষ্টি কি হচ্ছে? না।"
*   **সমস্যা:** তোমার পায়ের তলা ক্ষয় হয়ে যাবে (CPU waste), আর তুমি টেনশনে থাকবা। এটাকে বলে **Polling** বা **Pull based** সিস্টেম।

**২. Reactive Way (RxJS পদ্ধতি):**
তুমি জানালার পাশে কানে হেডফোন লাগিয়ে গান শুনছ (Chill mood)। তুমি আগে থেকেই ঠিক করে রেখেছ—**"যখনই (When) বৃষ্টির শব্দ কানে আসবে, তখনই আমি দৌড় দেব।"**
*   **সুবিধা:** তোমাকে বারবার চেক করতে হচ্ছে না। ইভেন্ট (বৃষ্টি) যখন ঘটবে, তুমি অটোমেটিক রেসপন্স করবে। এটাকে বলে **Push based** সিস্টেম।

> **RxJS এর মূল মন্ত্র:** ডাটা বা ইভেন্ট তোমাকে ধাক্কা (Push) দিবে, তুমি ডাটা টেনে (Pull) আনবে না।

### **Core Concept: Stream (স্রোত)** 🌊

RxJS বুঝতে হলে তোমাকে সবকিছুকে **"Stream"** বা নদীর স্রোত হিসেবে চিন্তা করতে হবে।

UI/UX ডিজাইনার হিসেবে চিন্তা করো। একটা অ্যাপে কী কী ঘটতে পারে?
1. ইউজার মাউস ক্লিক করছে।
2. সার্ভার থেকে ডাটা আসছে।
3. ইনপুট বক্সে টাইপ করছে।

Reactive Programming এ এই সব কিছুই হলো **Stream**।
*   **Stream** হলো এমন একটা পানির পাইপ, যার ভেতর দিয়ে ফোঁটায় ফোঁটায় পানি (Data) আসতেই থাকে।
*   এই পাইপ দিয়ে শুধু পানি (Value) আসে না, মাঝে মাঝে ময়লাও (Error) আসতে পারে, আবার পানি আসাও বন্ধ (Completed) হয়ে যেতে পারে।

#### **Excel Sheet এর উদাহরণ (The Best Example)** 📊

তুমি কি মাইক্রোসফট এক্সেল ব্যবহার করেছ?
*   Column C তে যদি ফর্মুলা দাও: `= A + B`
*   এখন যদি তুমি Column A এর ভ্যালু চেঞ্জ করো, Column C কি একা একাই চেঞ্জ হয়ে যায় না? তোমাকে কি বাটন টিপে বলতে হয় "Calculate"? না!

RxJS ঠিক এই কাজটাই জাভাস্ক্রিপ্টে করে। `A` এর ভ্যালু চেঞ্জ হওয়ার সাথে সাথে `C` রিয়্যাক্ট করে।

### **RxJS আসলে কী?**

RxJS কে বলা যায় **"Lodash for Events"**।
সহজ কথায়, এটা একটা টুলবক্স। তোমার অ্যাপ্লিকেশনে যত রকম **Async** ঘটনা ঘটে (যেমন: API Call, Click event, Timer), সেগুলোকে কন্ট্রোল করার জন্য RxJS হলো সুপারম্যান।

**কেন শিখব?**
ধরো তুমি একটা সার্চ বক্সে কোড লিখছ।
*   সাধারণ JS দিয়ে হ্যান্ডেল করতে গেলে তোমার মাথা খারাপ হয়ে যাবে (Race conditions, Callbacks)।
*   RxJS দিয়ে তুমি বলবে: "ভাই, ইউজার টাইপ করা বন্ধ করার ৫০০ মি.সে. পর আমাকে ডাটা দিও, আর যদি এর মধ্যে নতুন কিছু টাইপ করে, আগেরটা বাদ দাও।" (এটা আমরা Lesson 12-17 তে শিখব, জাস্ট ট্রেইলার দিলাম!)

### **হ্যালো ওয়ার্ল্ড! (আমাদের প্রথম কোড)**

এখন আমরা একটা কোড লিখব। ধরে নাও, তুমি একটা **রেডিও স্টেশন** (Observable) বানাচ্ছো, আর তোমার বন্ধু সেটা **রেডিও সেট** (Subscriber) দিয়ে শুনবে।

নিচের কোডটা StackBlitz বা তোমার `index.js` ফাইলে লিখো:

```javascript
import { Observable } from 'rxjs';

// ১. রেডিও স্টেশন তৈরি করা (Observable)
const radioStation$ = new Observable((subscriber) => {
  subscriber.next('হ্যালো বন্ধুরা!'); // প্রথম কথা
  subscriber.next('RxJS শেখা খুব সহজ।'); // দ্বিতীয় কথা
  subscriber.next('আজকের মতো বিদায়!'); // তৃতীয় কথা
  
  subscriber.complete(); // সম্প্রচার শেষ
});

// ২. রেডিও শোনা (Subscribe)
console.log('রেডিও চালু করছি...');

radioStation$.subscribe({
  next: (kotha) => console.log('শুনছি:', kotha),
  complete: () => console.log('স্টেশন বন্ধ হয়ে গেছে।'),
  error: (err) => console.log('ইশ! সিগনাল লস্ট:', err)
});

console.log('রেডিও শোনা শেষ?');
```

### **কোডের ময়নাতদন্ত (Code Breakdown) 🧐**

উপরের কোডে কী ঘটল? চলো ভেঙে দেখি:

**১. `new Observable(...)` :**
এটা হলো সেই রেডিও স্টেশন বা পানির পাইপ। এর কাজ হলো ডাটা তৈরি করা।
*   `subscriber.next('Some Data')`: এটার মানে হলো পাইপ দিয়ে এক ফোঁটা পানি (Data) ছাড়া হলো।
*   `subscriber.complete()`: মানে পানির ট্যাঙ্কি খালি, আর কিছু আসবে না।

**২. `radioStation$` (নামকরণের স্টাইল):**
খেয়াল করেছ আমি ভেরিয়েবলের নামের শেষে একটা `$` চিহ্ন দিয়েছি?
*   এটাকে বলে **"Finnish Notation"**।
*   RxJS ডেভেলপাররা ভেরিয়েবল দেখলেই যাতে বোঝে এটা একটা Stream বা Observable, তাই শেষে `$` চিহ্ন দেওয়া হয়। এটা দেওয়া বাধ্যতামূলক না, কিন্তু দিলে তোমাকে "কুল ডেভেলপার" মনে হবে। 😎

**৩. `.subscribe(...)` :**
এটা হলো আসল খেলা! মনে রাখবে:
> **"Observable অলস (Lazy)। তুমি যতক্ষণ না `subscribe` করবে, ততক্ষণ সে এক ফোঁটা ডাটাও পাঠাবে না।"**

তুমি যদি রেডিও স্টেশনের কোড লেখো কিন্তু রেডিও অন (Subscribe) না করো, গান কি বাজবে? বাজবে না। `subscribe` ফাংশন কল করার পরেই `Observable` তার `next` মেথডগুলো ফায়ার করা শুরু করে।

### **আজকের সারাংশ (Takeaway)**

1.  **Observable** হলো ডাটার সোর্স (রেডিও স্টেশন)।

ব্যাপারটা বুঝতে আমরা **"প্রেমিকা vs স্ত্রী"** বা আরও ভদ্রভাবে বললে **"পিৎজা vs নেটফ্লিক্স"** এর উদাহরণ দেব! 🍕📺

### **১. Promise: পিৎজা ডেলিভারি 🍕**

চিন্তা করো তুমি একটা পিৎজা অর্ডার করেছ।
*   তুমি অর্ডার দিলে (Request)।
*   ডেলিভারি বয় পিৎজা নিয়ে আসলো (Resolve)।
*   তুমি পিৎজা পেলে। **গল্প শেষ!**

**Promise এর বৈশিষ্ট্য:**
1.  **একবারই ডাটা দেয় (Single Value):** পিৎজা একবারই আসবে। ডেলিভারি বয় কি পিৎজা দিয়ে যাওয়ার ৫ মিনিট পর আবার এসে আরেক স্লাইস দিয়ে যায়? না!
2.  **Cancel করা যায় না:** একবার পিৎজা ওভেনে ঢুকে গেলে বা রাইডার রওনা দিলে তুমি সহজে বলতে পারো না "ভাই থাক, লাগবে না"। Promise একবার ফায়ার হলে থামানো কঠিন।
3.  **সাথে সাথে শুরু হয় (Eager):** তুমি অর্ডার করার সাথে সাথেই কাজ শুরু হয়ে যায়।

**Code (Promise):**
```javascript
const pizzaPromise = new Promise((resolve) => {
  console.log('পিৎজা রেডি হচ্ছে...');
  setTimeout(() => {
    resolve('গরম পিৎজা! 🍕');
  }, 2000);
});

pizzaPromise.then(pizza => console.log(pizza));
```

### **২. Observable: নেটফ্লিক্স সিরিজ 📺**

এবার চিন্তা করো তুমি নেটফ্লিক্সের সাবস্ক্রিপশন নিয়েছ।
*   তুমি `Subscribe` করলে।
*   প্রথম এপিসোড আসলো।
*   একটু পর দ্বিতীয় এপিসোড।
*   তারপর তৃতীয়... চলতেই থাকে!

**Observable এর বৈশিষ্ট্য:**
1.  **অনেকগুলো ডাটা দেয় (Multiple Values/Stream):** এটা একটা পিৎজা না, এটা এপিসোডের স্ট্রিম। সময়ের সাথে সাথে ডাটা আসতেই থাকে।
2.  **Cancel করা যায় (Cancellable):** তুমি চাইলেই মাঝপথে `Unsubscribe` করে দিতে পারো। মানে "ভাই, সিরিজ ভালো লাগছে না, দেখা বন্ধ।" তখন ডাটা আসা বন্ধ হয়ে যাবে।
3.  **অলস (Lazy):** যতক্ষণ তুমি `Subscribe` (প্লে বাটন) না টিপবে, ততক্ষণ ভিডিও শুরু হবে না।

**Code (Observable):**
```javascript
import { Observable } from 'rxjs';

const netflixSeries$ = new Observable((subscriber) => {
  console.log('সিরিজ শুরু!');
  subscriber.next('Episode 1 🎬'); // ১ম ডাটা
  subscriber.next('Episode 2 🎬'); // ২য় ডাটা
  
  setTimeout(() => {
    subscriber.next('Episode 3 (Season Finale) 🎬'); // দেরিতে আসা ৩য় ডাটা
  }, 2000);
});

// সাবস্ক্রাইব না করলে কিছুই হবে না
const subscription = netflixSeries$.subscribe(episode => console.log(episode));

// চাইলে মাঝপথে বন্ধ করা যায়
// subscription.unsubscribe(); 
```

### **পার্থক্য এক নজরে (Summary Table) 🥊**

| বৈশিষ্ট্য | Promise (পিৎজা) 🍕 | Observable (নেটফ্লিক্স) 📺 |
| :--- | :--- | :--- |
| **Data Count** | মাত্র ১টা ভ্যালু রিটার্ন করে। | ১ বা তার বেশি (অসংখ্য) ভ্যালু রিটার্ন করতে পারে। |
| **Execution** | **Eager** (ডিক্লেয়ার করলেই কাজ শুরু)। | **Lazy** (`subscribe` না করা পর্যন্ত কাজ শুরু করে না)। |
| **Cancellation** | অর্ডার দিলে ক্যানসেল করা কঠিন। | চাইলেই `unsubscribe()` করে থামানো যায়। |
| **Nature** | Push based (একবার)। | Push based (বারবার/Stream)। |

### **মজার উদাহরণ: প্রেমিকা vs স্ত্রী**

*   **Promise (প্রেমিকা):** তুমি বললে "চলো ঘুরতে যাই"। সে বলল "আচ্ছা যাব" (Resolve) অথবা "না যাব না" (Reject)। একবার উত্তর দিলো, কাহিনী শেষ।
*   **Observable (স্ত্রী):** তুমি বললে "কেমন আছো?"। সে উত্তর দেওয়া শুরু করল... "ভালো আছি... কিন্তু জানো পাশের বাসার ভাবি কি করেছে... তারপর দোকানদার কি বলল..." (চলতেই থাকল `next`, `next`, `next`...)। তুমি যতক্ষণ না কানে তুলা দিচ্ছ (`unsubscribe`), ততক্ষণ ডাটা আসতেই থাকবে! 😂

### **আজকের সারাংশ (Takeaway)**

*   যদি তোমার **একবার** ডাটা লাগে (যেমন: একটা সিম্পল API call), **Promise** ঠিক আছে।
*   কিন্তু যদি **বারবার** ডাটা আসে (যেমন: মাউস ক্লিক, সকেট কানেকশন, লাইভ স্কোর আপডেট, বা এমন API যেটা ক্যানসেল করা লাগতে পারে), তখন **Observable** হলো বস!

### **কনসেপ্ট: ইউটিউব চ্যানেল এবং তুমি**

মনে করো, `Observable` হলো তোমার **ইউটিউব চ্যানেল**। আর `Observer` (বা সাবস্ক্রাইবার) হলো তোমার **দর্শক**।

চ্যানেল মালিক হিসেবে তোমার হাতে ৩টি ক্ষমতা আছে:
১. **Video Upload (`next`):** তুমি ভিডিও ছাড়লে দর্শকরা নোটিফিকেশন পায়।
২. **Copyright Strike (`error`):** চ্যানেল ব্যান হয়ে গেলে দর্শকরা এরর মেসেজ দেখে।
৩. **Retirement (`complete`):** তুমি ঘোষণা দিলে—"বন্ধুরা, আমি আর ভিডিও বানাব না, আমি সন্ন্যাস নিচ্ছি।"

চলো কোড দিয়ে এই চ্যানেলটা বানাই!

---

### **Code: `new Observable()`**

টার্মিনাল বা StackBlitz এ নিচের কোডটা লিখে ফেলো:

```javascript
import { Observable } from 'rxjs';

// ১. চ্যানেল খোলা (Observable তৈরি)
const myYouTubeChannel$ = new Observable((subscriber) => {
  
  // প্রথম ভিডিও আপলোড
  console.log('ভিডিও ১ আপলোড হচ্ছে...');
  subscriber.next('Video 1: কিভাবে ডিম ভাজতে হয় 🍳');
  
  // দ্বিতীয় ভিডিও আপলোড
  console.log('ভিডিও ২ আপলোড হচ্ছে...');
  subscriber.next('Video 2: এলিয়েন দেখার গল্প 👽');

  // হঠাৎ একটা সমস্যা (Error) - এটা আনকমেন্ট করলে নিচের কোড আর চলবে না
  // subscriber.error('ব্যানড: ভুয়া খবর ছড়ানোর দায়ে চ্যানেল বন্ধ! 🚫');

  // তৃতীয় ভিডিও
  setTimeout(() => {
     subscriber.next('Video 3: ১ মিলিয়ন সাবস্ক্রাইবার স্পেশাল 🎉');
     
     // চ্যানেল থেকে বিদায় (Complete)
     subscriber.complete();
  }, 2000);

});

// ২. দর্শক হিসেবে দেখা (Subscribe)
console.log('--- সাবস্ক্রাইব করার আগে ---');

myYouTubeChannel$.subscribe({
  next: (videoTitle) => console.log(`নোটিফিকেশন: নতুন ভিডিও এসেছে -> ${videoTitle}`),
  error: (err) => console.error(`দুঃখিত: ${err}`),
  complete: () => console.log('চ্যানেল আপডেট: এই চ্যানেলে আর কোনো ভিডিও আসবে না। বিদায়! 👋')
});

console.log('--- সাবস্ক্রাইব করার পরে ---');
```

### **ভিতরের মেকানিজম (The 3 Super Powers)** 🛠️

`subscriber` অবজেক্টের সেই ৩টা মেথড আসলে কী করে?

#### **১. `next(value)` - শো মাস্ট গো অন!**
এটা হলো স্ট্রিমের মূল কাজ। তুমি যতবার `next()` কল করবে, ততবার সাবস্ক্রাইবারের কাছে ডাটা যাবে। এটা ১ বার হতে পারে, ১০০০ বারও হতে পারে।
*   *উদাহরণ:* ইউটিউবে ভিডিও আপলোড করতেই থাকা।

#### **২. `error(err)` - গেম ওভার! ❌**
যদি `error()` কল করো, সাথে সাথে স্ট্রিম **মরে যাবে**।
*   **গুরুত্বপূর্ণ:** এরর খাওয়ার পর যদি তুমি হাজারটা `next()` কল করো, আর কিছুই যাবে না। চ্যানেল ব্যান হলে কি আর ভিডিও আপলোড করা যায়? যায় না।

#### **৩. `complete()` - সসম্মানে বিদায় ✅**
এটা মানে হলো—সব কাজ সফলভাবে শেষ। আর কোনো ডাটা আসবে না।
*   `error` এর মতোই, `complete()` কল করার পর আর `next()` কাজ করবে না। পার্থক্য হলো, `error` মানে ফেইল, আর `complete` মানে সাকসেসফুল ফিনিশিং।

### **একটা লজিক্যাল কুইজ 🧠**

বলতো নিচের কোডের আউটপুট কী হবে?

```javascript
const tricky$ = new Observable(sub => {
  sub.next('A');
  sub.next('B');
  sub.complete(); // খেলা শেষ ঘোষণা
  sub.next('C'); // এটা কি আসবে?
  sub.error('Boom!'); // এটা কি ফাটবে?
});

tricky$.subscribe(val => console.log(val));
```

**উত্তর:** আউটপুট হবে শুধু `A` এবং `B`।
কারণ `complete()` কল করার পর `Observable` তার শাটার বন্ধ করে দেয়। এরপর `C` বা `Boom!` কিছুই আর সাবস্ক্রাইবারের কানে পৌঁছাবে না। একে বলে **"Observable Contract"**।

### **আজকের সারাংশ (Takeaway)**

1.  `new Observable()` দিয়ে আমরা কাস্টম স্ট্রিম বানাই।
2.  `next()` দিয়ে ডাটা পাঠাই।
3.  `error()` বা `complete()` কল করলে স্ট্রিম বন্ধ হয়ে যায় (Dead)।
4.  মৃত ঘোড়াকে চাবুক মেরে লাভ নেই (Dead Observable emits nothing)।

### **Observer আসলে কে?**

সহজ কথায়, **Observer** হলো একটা অবজেক্ট (Object), যার ভেতরে ৩টা ফাংশন থাকে। এই ৩টা ফাংশন ঠিক করে দেয় Observable থেকে আসা ডাটা নিয়ে আমরা কী করব।

মনে করো তোমার একটা রোবট আছে। তুমি রোবটকে বলে দিলে:
1.  **যদি বৃষ্টি হয়:** ছাতা ধরো (`next`)
2.  **যদি বজ্রপাত হয়:** ঘরে পালাও (`error`)
3.  **যদি বৃষ্টি থেমে যায়:** ছাতা বন্ধ করো (`complete`)

এই ইনস্ট্রাকশন সেটটাই হলো **Observer**।

### **Subscribe করার ৩টি উপায়**

RxJS এ `.subscribe()` করার কয়েকটা স্টাইল আছে। অনেক টিউটোরিয়ালে পুরনো স্টাইল দেখে তুমি কনফিউজড হতে পারো, তাই আজ সব ক্লিয়ার করব।

#### **১. The Modern Way (Recommended) ✅**
সবচেয়ে পরিষ্কার এবং লেটেস্ট পদ্ধতি হলো একটা অবজেক্ট পাস করা।

```javascript
myObservable$.subscribe({
  next: (data) => console.log('পেয়েছি:', data),
  error: (err) => console.error('সমস্যা:', err),
  complete: () => console.log('শেষ!')
});
```

#### **২. The "Only Next" Way (Shortcut) 🏃‍♂️**
যদি তোমার এরর বা কমপ্লিট নিয়ে মাথাব্যথা না থাকে, শুধু ডাটা পেলেই খুশি, তাহলে সরাসরি ফাংশন বসিয়ে দাও।

```javascript
// শুধু next এর কাজ করবে, error বা complete ইগনোর করবে
myObservable$.subscribe(data => console.log(data));
```

#### **৩. The Old School Way (Deprecated) 👴**
আগে এভাবে লেখা হতো (এখন আর লিখো না, RxJS এর নতুন ভার্সনে এটা ওয়ার্নিং দিতে পারে):

```javascript
// আর্গুমেন্ট ১: next, আর্গুমেন্ট ২: error, আর্গুমেন্ট ৩: complete
myObservable$.subscribe(
  (data) => console.log(data), 
  (err) => console.error(err),
  () => console.log('Done')
);
```

### **Subscription Object - রিমোট কন্ট্রোল 🎮**

যখন তুমি `subscribe()` কল করো, এটা রিটার্ন হিসেবে তোমাকে একটা **Subscription** অবজেক্ট দেয়। এটাকে তুমি **রিমোট কন্ট্রোল** ভাবতে পারো।

এই রিমোট দিয়ে তুমি স্ট্রিম বন্ধ করতে পারো।

**কেন বন্ধ করব? (Unsubscribe)**
ধরো তুমি বাসে উঠেছ, টিকিট কেটেছ (Subscribe)। গন্তব্যে পৌঁছানোর পর তুমি কি বাসেই বসে থাকবে? না, নেমে যাবে (Unsubscribe)। যদি না নামো, বাস তোমাকে নিয়ে গ্যারেজে চলে যাবে (Memory Leak)!

#### **কোড এক্সাম্পল: Unsubscribe**

```javascript
import { interval } from 'rxjs';

// ১. একটা টাইমার চালু করলাম (প্রতি ১ সেকেন্ডে ডাটা দিবে)
const timer$ = interval(1000); 

// ২. সাবস্ক্রাইব করলাম এবং রিমোটটা হাতে রাখলাম
const mySubscription = timer$.subscribe({
  next: (value) => console.log(`Time: ${value} sec`)
});

// ৩. ৫ সেকেন্ড পর আমরা বাস থেকে নেমে যাব (Unsubscribe)
setTimeout(() => {
  console.log('অনেক হয়েছে, আর না!');
  mySubscription.unsubscribe(); // রিমোট দিয়ে টিভি বন্ধ!
}, 5000);
```

**আউটপুট:**
```
Time: 0 sec
Time: 1 sec
Time: 2 sec
Time: 3 sec
Time: 4 sec
অনেক হয়েছে, আর না!
(আর কোনো ডাটা আসবে না)
```

### **Observer এর সাথে মানসিক সম্পর্ক**

মনে রাখবে:
1.  **Observable** হলো বক্তা (Speaker)।
2.  **Observer** হলো শ্রোতা (Listener)।
3.  **Subscription** হলো কানেকশন বা টিকিট।

যদি শ্রোতা (Observer) না থাকে, বক্তা (Observable) কথা বলবে না (Cold Observable হলে)। আর যদি শ্রোতা মাঝপথে উঠে চলে যায় (Unsubscribe), বক্তা কথা বলা থামিয়ে দিবে (যদি লজিক সেভাবে সেট করা থাকে)।

---

### **আজকের সারাংশ (Takeaway)**

*   `subscribe()` এর ভেতর আমরা একটা অবজেক্ট পাস করি যাতে `next`, `error`, আর `complete` থাকে।
*   `subscribe()` কল করলে রিটার্ন হিসেবে একটা `Subscription` পাওয়া যায়।
*   মেমোরি লিক বা অপ্রয়োজনীয় প্রসেস থামাতে `unsubscribe()` করা ফরজ! (বিশেষ করে React `useEffect` বা Angular `ngOnDestroy` তে)।
