সাধারণ জাভাস্ক্রিপ্টে আমরা `addEventListener` ব্যবহার করি। কিন্তু RxJS দিয়ে এটা করলে তুমি নিজেকে জাদুকর মনে করবে।

আজকের টপিক: **fromEvent - ক্লিকবাজি!** 🖱️🔫

### **fromEvent আসলে কী?**

`fromEvent` হলো এমন এক জাদুর কাঠি যা যেকোনো DOM Event (যেমন Click, Keyup, Scroll, MouseMove) কে **Observable** বানিয়ে ফেলে।

*   **সাধারণ JS:** ইভেন্ট ঘটলে একটা ফাংশন কল হয়।
*   **RxJS:** ইভেন্টগুলো একটা স্ট্রিম বা নদীর মতো প্রবাহিত হয়।

---

### **বাস্তব উদাহরণ: মেশিগান vs ক্লিক 🔫**

মনে করো তোমার ওয়েবসাইটে একটা বাটন আছে। ইউজার সেটাতে ক্লিক করবে।

**Step 1: HTML (Button)**
```html
<button id="magicButton">Click Me! 💣</button>
```

**Step 2: RxJS Code**

```javascript
import { fromEvent } from 'rxjs';

// ১. বাটনটা সিলেক্ট করো
const button = document.getElementById('magicButton');

// ২. ইভেন্টকে Observable বানাও
// fromEvent(টার্গেট, ইভেন্টের নাম)
const clickStream$ = fromEvent(button, 'click');

// ৩. সাবস্ক্রাইব করো (গুলি খাওয়া শুরু)
clickStream$.subscribe(event => {
  console.log('বুম! ক্লিক হয়েছে! 💥');
  console.log('Mouse X coordinate:', event.clientX);
});
```

এখন তুমি যতবার বাটনে ক্লিক করবে, ততবার কনসোলে "বুম!" দেখবে। কোনো `removeEventListener` এর প্যারা নাই (যদি তুমি `unsubscribe` করো, অটোমেটিক রিমুভ হয়ে যাবে)।

---

### **কেন fromEvent ব্যবহার করব?**

তুমি বলতে পারো, "ভাই `addEventListener` তো ভালোই ছিল।"
RxJS এর পাওয়ার দেখো। ধরো তুমি চাও:
> *"ইউজার ক্লিক করলে লগ হবে, কিন্তু প্রতি ২ বারের বেশি ক্লিক কাউন্ট হবে না, আর ক্লিক করার পর ১ সেকেন্ড দেরি করে লগ হবে।"*

সাধারণ JS দিয়ে এটা লিখতে গেলে কোড spaghetti হয়ে যাবে। RxJS দিয়ে দেখো পাইপলাইন কত সুন্দর:

```javascript
import { fromEvent } from 'rxjs';
import { map, take, delay } from 'rxjs/operators';

const btn = document.getElementById('magicButton');

fromEvent(btn, 'click').pipe(
  // ১. ইভেন্ট অবজেক্ট থেকে শুধু X,Y কোঅর্ডিনেট বের করো
  map(event => `X: ${event.clientX}, Y: ${event.clientY}`),

  // ২. মাত্র ২টা ক্লিক নেব, তারপর অটোমেটিক বন্ধ
  take(2),

  // ৩. ১ সেকেন্ড দেরিতে রেজাল্ট দেখাব
  delay(1000)
)
.subscribe(coords => console.log('ক্লিকের জায়গা:', coords));
```

**আউটপুট:**
১ম ক্লিক -> ১ সেকেন্ড পর লগ হবে।
২য় ক্লিক -> ১ সেকেন্ড পর লগ হবে।
৩য় ক্লিক -> আর কিছুই হবে না (কারণ `take(2)` স্ট্রিম কমপ্লিট করে দিয়েছে)।

### **আরেকটা উদাহরণ: মাউস ট্র্যাকিং (Drawing App) 🎨**

তুমি যদি একটা ড্রয়িং অ্যাপ বানাতে চাও, মাউস মুভমেন্ট ট্র্যাক করা লাগবে।

```javascript
import { fromEvent } from 'rxjs';
import { map } from 'rxjs/operators';

// পুরো ডকুমেন্ট জুড়ে মাউস মুভমেন্ট ধরব
const mouseMoves$ = fromEvent(document, 'mousemove');

mouseMoves$.pipe(
  // বিশাল ইভেন্ট অবজেক্ট থেকে শুধু পজিশন দরকার
  map(e => ({ x: e.clientX, y: e.clientY }))
)
.subscribe(pos => {
  // এটা দিয়ে তুমি ক্যানভাসে আঁকতে পারো
  console.log(`ব্রাশ পজিশন: ${pos.x}, ${pos.y}`);
});
```
*(সতর্কতা: মাউস মুভ করলে সেকেন্ডে শত শত ইভেন্ট ফায়ার হয়! কনসোল ভরে যাবে। এটাকে কন্ট্রোল করার জন্য পরের লেসনগুলো খুব জরুরি!)*

---

### **আজকের সারাংশ (Takeaway)**

*   `fromEvent(target, eventName)` দিয়ে যেকোনো ইভেন্টকে Observable বানানো যায়।
*   এটা সাধারণ `addEventListener` এর চেয়ে অনেক বেশি শক্তিশালী কারণ এর সাথে `pipe`, `map`, `filter` ইত্যাদি জুড়ে দেওয়া যায়।
*   Unsubscribe করলে ইভেন্ট লিসেনার অটোমেটিক মেমোরি থেকে মুছে যায় (Clean Code)।

### **সমস্যা: অতি উৎসাহী ইউজার ⌨️**

ধরো, তুমি গুগলের মতো একটা সার্চ বক্স বানিয়েছ। ইউজার সেখানে **"Apple"** টাইপ করবে।
ইউজার টাইপ করছে:
1.  `A` -> API Call (Search for A)
2.  `p` -> API Call (Search for Ap)
3.  `p` -> API Call (Search for App)
4.  `l` -> API Call (Search for Appl)
5.  `e` -> API Call (Search for Apple)

মাত্র একটা শব্দের জন্য তুমি ৫টা রিকোয়েস্ট পাঠালে! যদি ১০০০ ইউজার থাকে? সার্ভার ধুম করে ক্র্যাশ করবে। 🔥

আমাদের দরকার এমন কেউ যে বলবে: **"ইউজার টাইপ করা থামালে বা একটু বিরতি দিলে আমি রিকোয়েস্ট পাঠাব।"**

---

### **সমাধান: `debounceTime` (লিফটের দরজার টেকনিক) 🚪**

লিফটের দরজা কিভাবে কাজ করে?
*   তুমি লিফটে ঢুকলে, দরজা বন্ধ হতে যাচ্ছে...
*   হঠাৎ আরেকজন দৌড়ে আসলো, দরজা আবার খুলে গেল এবং টাইমার রিসেট হলো।
*   যতক্ষণ মানুষ আসতেই থাকবে, দরজা বন্ধ হবে না।
*   যখন শেষ মানুষটি ঢোকার পর ৫ সেকেন্ড কেউ আসবে না, তখনই দরজা বন্ধ হবে এবং লিফট চালু হবে।

`debounceTime(300)` ঠিক এটাই করে। ডাটা আসা বন্ধ হওয়ার ৩০০ মিলিসেকেন্ড পর সে ডাটাটা পাস করে।

---

### **কোড: স্মার্ট সার্চ বার 🧠**

```html
<input type="text" id="searchBox" placeholder="Type here...">
```

```javascript
import { fromEvent } from 'rxjs';
import { map, debounceTime, distinctUntilChanged } from 'rxjs/operators';

const searchInput = document.getElementById('searchBox');

// ১. ইনপুট ইভেন্টকে স্ট্রিম বানালাম
const searchStream$ = fromEvent(searchInput, 'input');

searchStream$.pipe(
  // ২. ইভেন্ট থেকে শুধু টেক্সট ভ্যালু বের করলাম
  map(event => event.target.value),
  
  // ৩. ম্যাজিক শুরু: ৩০০ মি.সে. এর মধ্যে নতুন কিছু টাইপ করলে আগেরটা বাতিল
  debounceTime(300),

  // ৪. বোনাস: যদি ইউজার টাইপ করে আবার মুছে আগেরটাই লেখে, রিকোয়েস্ট পাঠানোর দরকার নাই
  // (যেমন: "Apple" -> "Appl" -> "Apple")
  distinctUntilChanged() 
)
.subscribe(searchTerm => {
  console.log(`Searching for: ${searchTerm}`);
  // এখানে API Call হবে
});
```

---

### **পার্থক্যটা বুঝো (Visual Breakdown)**

**debounceTime ছাড়া:**
```
Input:  A ... Ap ... App ... Appl ... Apple
Call:   Call. Call. Call.. Call.. Call.. (৫টা কল)
```

**debounceTime(300) সহ:**
```
Input:  A (wait..) p (reset..) p (reset..) l (reset..) e (wait 300ms..)
Call:   ................................................... Call (Apple) (মাত্র ১টা কল!)
```

---

### **কখন `debounceTime` ব্যবহার করব?**

১. **Search Bar / Auto-complete:** টাইপিং শেষ হলে সার্চ করো।
২. **Window Resize:** উইন্ডো রিসাইজ করার সময় হাজারটা ইভেন্ট ফায়ার হয়। রিসাইজ শেষ হলে লেআউট ঠিক করো।
৩. **Save Button:** ইউজার যদি পাগলের মতো "Save" বাটনে ১০ বার ক্লিক করে, আমি শেষেরটাই কাউন্ট করব।

---

### **আজকের সারাংশ (Takeaway)**

*   **`debounceTime(ms)`** অপেক্ষা করে। যদি নির্দিষ্ট সময়ের মধ্যে নতুন ডাটা আসে, সে টাইমার রিসেট করে।
*   এটা সার্ভারের লোড কমায় এবং ব্রাউজারের পারফরম্যান্স বাড়ায়।
*   এটা "ধৈর্যশীল" অপারেটর।

### **সমস্যা: গেমার এবং মাউস ক্লিক 🖱️**

ধরো তুমি একটা শুটিং গেম বানাচ্ছো। ইউজার মাউস দিয়ে ক্লিক করলে গুলি বের হয়।
এখন ইউজার যদি সেকেন্ডে ৫০ বার ক্লিক করে, তুমি কি ৫০টা গুলি বের করবে?
1.  গেম ল্যাগ করবে।
2.  বন্দুক গরম হয়ে যাবে (লজিক্যালি)।
3.  সার্ভারে স্প্যাম হবে।

আমাদের এমন একটা মেকানিজম দরকার যেটা বলবে:
**"ভাই, তুমি যতই ক্লিক করো, আমি প্রতি ১ সেকেন্ডে সর্বোচ্চ ১ বারই গুলি বের হতে দিব।"**

---

### **সমাধান: `throttleTime` (Cool-down)**

মেশিনগানে যেমন "Cool-down" টাইম থাকে, `throttleTime` ঠিক তাই।
*   প্রথম ডাটা আসলে সাথে সাথে পাস করে দেয়। ✅
*   এরপর নির্দিষ্ট সময়ের জন্য "ব্লক" মোডে চলে যায়। 🚫
*   ওই সময়ের মধ্যে হাজারটা ডাটা আসলেও সেগুলোকে ইগনোর করে।
*   সময় শেষ হলে আবার রেডি হয় পরের ডাটার জন্য।

### **পার্থক্য: Debounce vs Throttle 🥊**

এটা বুঝতে অনেকে ভুল করে। ভালো করে বুঝো:

*   **Debounce (অপেক্ষা করে):** তুমি টাইপ করছ... করছ... থামলে। ৩ সেকেন্ড পর রেজাল্ট দেখাবে। (মাঝখানের সব বাদ, শেষেরটা আসল)।
    *   *উদাহরণ:* লিফটের দরজা, সার্চ বক্স।
*   **Throttle (বিরতি দেয়):** তুমি টাইপ করছ... সাথে সাথে ১ম টা দেখাবে। এরপর ৩ সেকেন্ড চুপ। এরপর আবার টাইপ করলে আবার দেখাবে। (শুরুরটা নেয়, মাঝখানের গুলো বাদ, নির্দিষ্ট সময় পর আবার নেয়)।
    *   *উদাহরণ:* মেশিনগান, স্ক্রলিং ইভেন্ট।

### **কোড: মাউস ট্র্যাকিং বা স্ক্রলিং 📜**

ওয়েবসাইটে স্ক্রল করলে সেকেন্ডে ১০০ বার ইভেন্ট ফায়ার হয়। আমরা যদি প্রতিবার ফাংশন কল করি, সাইট স্লো হয়ে যাবে। আমরা চাই প্রতি ১০০ মি.সে. এ মাত্র একবার আপডেট হোক।

```javascript
import { fromEvent } from 'rxjs';
import { throttleTime, map } from 'rxjs/operators';

// পুরো পেজে মাউস নাড়াচাড়া
const mouseMoves$ = fromEvent(document, 'mousemove');

mouseMoves$.pipe(
  // ১ সেকেন্ডে মাত্র ১ বার পজিশন আপডেট হবে (Cool-down 1000ms)
  throttleTime(1000)
)
.subscribe(event => {
  console.log(`Mouse Position Updated: ${event.clientX}, ${event.clientY}`);
});
```

**আউটপুট (Console):**
তুমি মাউস পাগলের মতো নাড়াও।
*   `00:00:00` -> আপডেট হবে।
*   `00:00:00.500` -> (ইগনোর)
*   `00:00:00.900` -> (ইগনোর)
*   `00:00:01.100` -> আপডেট হবে।
*   `00:00:02.200` -> আপডেট হবে।

### **Configuring Throttle (Advanced Tip) 🛠️**

ডিফল্টভাবে `throttleTime` **Leading** (শুরুরটা) নেয় এবং **Trailing** (শেষেরটা) বাদ দেয়।
তুমি চাইলে এটা উল্টাতে পারো।

```javascript
throttleTime(1000, asyncScheduler, {
  leading: true,  // শুরুতেই ফায়ার হবে (গুলি বের হবে)
  trailing: true  // কুলডাউন শেষ হওয়ার পর লাস্ট ক্লিকটাও কাউন্ট হবে
})
```
*(এটা একটু অ্যাডভান্সড, শুধু জেনে রাখো অপশন আছে)*

১. **Infinite Scroll:** ইউজার স্ক্রল করছে, পেজ লোড হবে। -> **Throttle** (কারণ কন্টিনিউয়াস চেক করতে হবে, কিন্তু ১ সেকেন্ড পর পর)।

৩. **Shooting Button:** ক্লিক করলে গুলি। -> **Throttle** (১ম ক্লিকেই গুলি বের হতে হবে, কিন্তু রেট লিমিট থাকবে)।

### **১. `take(n)` - গোনাগুনতি 🔢**

`take` খুব সহজ সরল। তুমি তাকে বলে দিবে কয়টা ভ্যালু লাগবে। সে ততোটা ভ্যালু নিয়ে শার্টার নামিয়ে দিবে (Complete)।

**উদাহরণ:** বিয়ের বাফেতে গিয়ে তুমি ঠিক করলে মাত্র ৩ পিস রোস্ট নিবে। ৩ পিস নেওয়া শেষ, বাফে বন্ধ।

**Code:**
```javascript
import { interval } from 'rxjs';
import { take } from 'rxjs/operators';

// ১ সেকেন্ড পর পর সংখ্যা আসবে (0, 1, 2, 3...)
const numbers$ = interval(1000);

numbers$.pipe(
  // মাত্র ৩টা ভ্যালু নিব
  take(3)
)
.subscribe({
  next: val => console.log(`নিলাম: ${val}`),
  complete: () => console.log('আর পেট চলবে না! (Completed)')
});
```

**আউটপুট:**
```
(১ সেকেন্ড পর) নিলাম: 0
(২ সেকেন্ড পর) নিলাম: 1
(৩ সেকেন্ড পর) নিলাম: 2
আর পেট চলবে না! (Completed)
(এরপর আর কোনো লগ হবে না, মেমোরিও ক্লিন!)
```

### **২. `takeUntil(notifier$)` - বসের ভয়! 😨**

এটা একটু বেশি স্মার্ট। এখানে তুমি সংখ্যা বলো না, বরং আরেকটা `Observable` কে কন্ডিশন হিসেবে দাও।
লজিকটা হলো: **"যতক্ষণ না ২য় স্ট্রিমটা ফায়ার করছে, ততক্ষণ ১ম স্ট্রিম চলতে থাকবে।"**

**উদাহরণ:** তুমি অফিসে আড্ডা দিচ্ছ (Source Stream)। তুমি ঠিক করলে—**"বস না আসা পর্যন্ত (Notifier Stream) আড্ডা চলবে।"** বস রুমে ঢোকার সাথে সাথে আড্ডা বন্ধ।

**Code (Scenario: Stop Timer on Button Click):**

```javascript
import { interval, fromEvent } from 'rxjs';
import { takeUntil } from 'rxjs/operators';

// ১. টাইমার (আড্ডা চলছে...)
const timer$ = interval(1000);

// ২. স্টপ বাটন (বস আসছে...)
const stopBtn = document.getElementById('stopButton');
const stopClick$ = fromEvent(stopBtn, 'click');

console.log('টাইমার শুরু...');

timer$.pipe(
  // টাইমার চলবে ততক্ষণ, যতক্ষণ না বাটনে ক্লিক পড়ছে
  takeUntil(stopClick$)
)
.subscribe({
  next: val => console.log(`Timer: ${val}`),
  complete: () => console.log('স্টপ বাটন চাপা হয়েছে! খেলা শেষ।')
});
```

**আউটপুট:**
*   `Timer: 0` ... `Timer: 1` ... `Timer: 2`
*   (তুমি বাটনে ক্লিক করলে) -> `স্টপ বাটন চাপা হয়েছে! খেলা শেষ।`
*   এরপর টাইমার আর চলবে না।

### **কেন `takeUntil` সেরা? (The Memory Leak Killer)**

Angular বা React এ কম্পোনেন্ট ডিলিট (Unmount/Destroy) হওয়ার সময় আমাদের সব সাবস্ক্রিপশন বন্ধ করতে হয়। ম্যানুয়ালি `unsubscribe` করতে ভুলে গেলে মেমোরি লিক হয়।

প্যাটার্নটা হলো:
```javascript
// কম্পোনেন্ট মরার সিগনাল (destroy$)
source$.pipe(
  takeUntil(this.destroy$) // কম্পোনেন্ট ধ্বংস হলে সাবস্ক্রিপশনও অটো ধ্বংস!
).subscribe(...);
```
এটা প্রো ডেভেলপারদের সিগনেচার মুভ! 😎

### **আরেকটা বোনাস: `takeWhile` 🤔**

এটা অনেকটা `filter` এর মতো, কিন্তু `filter` বাদ দিয়ে সামনে আগায়, আর `takeWhile` শর্ত মিথ্যা হলে স্ট্রিমই বন্ধ করে দেয়।

```javascript
import { of } from 'rxjs';
import { takeWhile } from 'rxjs/operators';

of(1, 2, 3, 100, 4, 5).pipe(
  // যতক্ষণ সংখ্যা ৫ এর কম, ততক্ষণ নাও। যেই ১০ আসলো, সব বন্ধ।
  takeWhile(n => n < 5)
).subscribe(val => console.log(val));
// আউটপুট: 1, 2, 3 (৪ আর ৫ আসবে না, কারণ ১০০ এসে খেলা নষ্ট করে দিয়েছে)
```

### **আজকের সারাংশ (Takeaway)**

*   **`take(n)`**: নির্দিষ্ট সংখ্যক ডাটা নিয়ে বন্ধ হয়ে যায়।
*   **`takeUntil(observable)`**: অন্য কোনো ঘটনা ঘটা পর্যন্ত ডাটা নিতে থাকে। ইভেন্ট বেসড স্টপ করার জন্য সেরা।
*   এগুলো ব্যবহার করলে ম্যানুয়ালি `unsubscribe()` করার প্যারা কমে যায়।
