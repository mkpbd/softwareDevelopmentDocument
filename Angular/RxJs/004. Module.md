### **সমস্যা: Observable এর পেটে Observable! 🤰**

ধরো, তুমি একটা ইউজারের আইডিতে ক্লিক করলে (Observable 1), তারপর সেই আইডি দিয়ে সার্ভার থেকে তার ডিটেইলস আনলে (Observable 2)।

```javascript
// সাধারণ পদ্ধতি (Bad Practice) ❌
click$.subscribe(id => {
  // আবার সাবস্ক্রাইব?! (Nested Subscription)
  getUserDetails(id).subscribe(user => {
    console.log(user);
  });
});
```
এটাকে বলে **"Callback Hell"** বা RxJS এর ভাষায় **"Subscribe Hell"**। কোড নোংরা হয়ে যায়।

আমাদের এমন একটা অপারেটর দরকার যেটা বাইরের স্ট্রিম (Click) আর ভেতরের স্ট্রিম (API Call) কে মিলিয়ে (Merge) দিবে। যাতে আমরা একবারই `subscribe` করতে পারি।

---

### **সমাধান: `mergeMap` (Flattening Operator)**

`mergeMap` এর কাজ হলো:
১. বাইরের ডাটা (আইডি) নেওয়া।
২. সেটা দিয়ে নতুন একটা Observable (API Call) তৈরি করা।
৩. সেই নতুন Observable কে অটোমেটিক সাবস্ক্রাইব করা এবং রেজাল্ট বের করে দেওয়া।

---

### **বাস্তব উদাহরণ: ব্যাংকের ক্যাশ কাউন্টার 🏦**

`mergeMap` হলো **প্যারালাল (Parallel) প্রসেসিং**।

*   ব্যাংকে ৫টা ক্যাশ কাউন্টার খোলা আছে।
*   **কাস্টমার ১** আসলো -> কাউন্টার ১ এ কাজ শুরু।
*   কাজ শেষ হওয়ার আগেই **কাস্টমার ২** আসলো -> কাউন্টার ২ এ কাজ শুরু।
*   কেউ কারোর জন্য অপেক্ষা করছে না। সবাই একসাথে সেবা পাচ্ছে।

---

### **কোড: মাল্টিটাস্কিং ক্লিক 🖱️**

ধরো একটা বাটন আছে। ক্লিক করলেই ১ সেকেন্ড দেরি করে "Done" দেখাবে। যদি তুমি দ্রুত ৩ বার ক্লিক করো, ৩টাই প্রসেস হবে এবং ৩টা রেজাল্ট পাবে।

```javascript
import { fromEvent, of } from 'rxjs';
import { mergeMap, delay } from 'rxjs/operators';

const button = document.getElementById('btn');
const click$ = fromEvent(button, 'click');

// সিমুলেটেড API কল (ডাটা পেতে ১ সেকেন্ড লাগে)
const fakeApiCall = (id) => {
  return of(`Request ${id} Completed! ✅`).pipe(delay(1000));
};

let count = 0;

click$.pipe(
  // এখানে ম্যাপ ব্যবহার করলে তুমি Observable পেতে।
  // mergeMap ব্যবহার করলে তুমি সেই Observable এর ভেতরের 'ডাটা' পাবে।
  mergeMap(() => {
    count++;
    console.log(`Request ${count} started...`);
    return fakeApiCall(count);
  })
)
.subscribe(res => console.log(res));
```

**আউটপুট (দ্রুত ৩ বার ক্লিক করলে):**
```
Request 1 started...
Request 2 started...
Request 3 started...
(১ সেকেন্ড পর...)
Request 1 Completed! ✅
Request 2 Completed! ✅
Request 3 Completed! ✅
```
সবগুলো রিকোয়েস্ট প্যারালালি (একসাথে) হ্যান্ডেল হয়েছে। অর্ডার উল্টাপাল্টা হতে পারে (যে আগে শেষ হবে সে আগে আসবে), কিন্তু কেউ আটকা পড়ে থাকবে না।

---

### **কখন `mergeMap` ব্যবহার করব?**

১. **Delete Items:** তুমি লিস্ট থেকে ৫টা আইটেম ডিলিট করতে চাও। ৫টা ক্লিক করলে ৫টা ডিলিট রিকোয়েস্ট একসাথে সার্ভারে যাবে।
২. **Chat Messages:** হোয়াটসঅ্যাপে মেসেজ পাঠানোর মতো। আগের মেসেজ ডেলিভারি না হলেও পরেরটা পাঠানো যায়।
৩. **Parallel API Calls:** যেখানে অর্ডারের চেয়ে স্পিড বেশি জরুরি।

---

### **সাবধানতা: মেমোরি লোড ⚠️**

`mergeMap` এর কোনো লিমিট নাই। ইউজার যদি ১০০০ বার ক্লিক করে, সে ১০০০টা রিকোয়েস্ট একসাথে ওপেন করবে। এটা ব্রাউজার হ্যাং করতে পারে।
*(সমাধান: `mergeMap` এর দ্বিতীয় আর্গুমেন্টে লিমিট দেওয়া যায়, অথবা `concatMap` ব্যবহার করা যায়, যেটা আমরা পরের লেসনে শিখব)*

            ↓     ↓     ↓

### **ConcatMap আসলে কী?**

`concat` মানে হলো জোড়া লাগানো। `concatMap` ঠিক তাই করে।
সে রিকোয়েস্টগুলোকে একটার পেছনে আরেকটা জোড়া লাগিয়ে দেয়।
*   ১ম কাজ শেষ না হওয়া পর্যন্ত ২য় কাজ শুরুই হবে না।
*   ২য় কাজ শেষ হলে ৩য় কাজ ধরবে।

---

### **বাস্তব উদাহরণ: এটিএম বুথ 🏧**

*   বুথের ভেতরে একজন টাকা তুলছে (**Active Subscription**)।
*   বাইরে তুমি দাঁড়িয়ে আছো (**Pending/Queued**)।
*   যতক্ষণ ভেতরের লোক বের না হবে, তুমি ঢুকতে পারবে না।
*   তুমি বের হলে, তোমার পেছনের জন ঢুকবে।

এটা সম্পূর্ণ **সিকোয়েন্সিয়াল (Sequential)** প্রসেস। এখানে **অর্ডার (Order)** গ্যারান্টিড। ১ নম্বর রিকোয়েস্টের রেজাল্ট ১ নম্বরেই আসবে।

---

### **কোড: সিরিয়াল কিলার (Sequential Processing) 🔪**

ধরো আমরা সেইম আগের বাটন ক্লিকের উদাহরণ দেখব। কিন্তু এবার `mergeMap` এর বদলে `concatMap` ব্যবহার করব।

```javascript
import { fromEvent, of } from 'rxjs';
import { concatMap, delay } from 'rxjs/operators';

const button = document.getElementById('btn');
const click$ = fromEvent(button, 'click');

// সিমুলেটেড স্লো কাজ (২ সেকেন্ড লাগে)
const slowTask = (id) => {
  return of(`Task ${id} Done! ✅`).pipe(delay(2000));
};

let count = 0;

click$.pipe(
  // concatMap ব্যবহার করছি
  concatMap(() => {
    count++;
    console.log(`Task ${count} Added to Queue...`);
    return slowTask(count);
  })
)
.subscribe(res => console.log(res));
```

**আউটপুট (দ্রুত ৩ বার ক্লিক করলে):**

```
Task 1 Added to Queue...
Task 2 Added to Queue...
Task 3 Added to Queue...

(২ সেকেন্ড পর...)
Task 1 Done! ✅  (১ম কাজ শেষ হলো, এখন ২য় শুরু হবে)

(আরও ২ সেকেন্ড পর...)
Task 2 Done! ✅

(আরও ২ সেকেন্ড পর...)
Task 3 Done! ✅
```

**পার্থক্য দেখলে?**
`mergeMap` এ সবাই একসাথে রেজাল্ট দিত। `concatMap` এ মোট ৬ সেকেন্ড লাগল (২+২+২), কারণ একজন শেষ হলে আরেকজন শুরু হয়েছে।

---

### **Visual Diagram 👁️**

```
Source: --- 1 --- 2 --- 3 ---> (Clicks)
            |     
concatMap:  Wait for 1 to finish... -> Then start 2... -> Then start 3
            |_______________________|___________________|
                       ↓                     ↓
Output:   --------- Result 1 ----------- Result 2 ----- Result 3 -->
```

### **কখন `concatMap` ব্যবহার করব?**

১. **Save/Update Operations:** তুমি ডাটা আপডেট করছ। আগের আপডেট শেষ না হলে পরেরটা করা বিপজ্জনক।
   *   উদাহরণ: ব্যাংক ব্যালেন্স আপডেট। আগে ১০০ টাকা জমা হোক, তারপর ২০০ টাকা তোলো। উল্টাপাল্টা হলে ব্যালেন্স নেগেটিভ হয়ে যাবে!
2. **Sequential Animation:** একটার পর একটা এনিমেশন দেখাতে চাইলে।
3. **Mobile Upload Queue:** ছবি আপলোড করছ। একটা শেষ হবে, তারপর পরেরটা আপলোড হবে।

---

### **MergeMap vs ConcatMap 🥊**

| বৈশিষ্ট্য | MergeMap (মামা) | ConcatMap (এটিএম) |
| :--- | :--- | :--- |
| **Execution** | Parallel (একসাথে) | Sequential (একটার পর একটা) |
| **Speed** | দ্রুত (Fastest) | ধীর (Slowest) |
| **Order** | গ্যারান্টি নাই (আগে আসলে আগে পাবে না, যে ছোট সে আগে) | ১০০% গ্যারান্টিড (১, ২, ৩ ক্রম বজায় থাকে) |
| **Use Case** | GET Requests, Chat, Delete | PUT/POST Requests, Banking logic |

---

### **আজকের সারাংশ (Takeaway)**

*   যদি **অর্ডার** মেইনটেইন করা জরুরি হয় -> **`concatMap`**।
*   যদি **স্পিড** জরুরি হয় এবং অর্ডারে কিছু যায় আসে না -> **`mergeMap`**।
*   `concatMap` রিকোয়েস্ট হারায় না, সেগুলোকে লাইনে দাঁড় করিয়ে রাখে (Queue)।

### **সমস্যা: সার্চ বারের গণ্ডগোল 🕵️‍♂️**

মনে করো তুমি গুগলে সার্চ করছ "Apple"।
১. তুমি `A` লিখলে -> রিকোয়েস্ট ১ গেল।
২. সাথে সাথে `p` লিখলে -> রিকোয়েস্ট ২ গেল।
৩. `Request 1` এর রেসপন্স আসতে দেরি হচ্ছে।
৪. `Request 2` এর রেসপন্স আগে চলে আসলো এবং স্ক্রিনে দেখালো।
৫. হুট করে `Request 1` এর রেসপন্স চলে আসলো এবং স্ক্রিন ওভাররাইট করে দিল!

**ফলাফল:** তুমি সার্চ দিলে "Ap" (Apple), কিন্তু রেজাল্ট দেখাচ্ছে "A" এর! একে বলে **Race Condition**।

আমাদের এমন কাউকে দরকার যে বলবে: **"নতুন রিকোয়েস্ট এসেছে? তাহলে আগের রিকোয়েস্ট সাথে সাথে ক্যানসেল! আমি শুধু লেটেস্টটার কথা শুনব।"**

---

### **সমাধান: `switchMap` (The Heartbreaker 💔)**

`switchMap` এর লজিক খুব নিষ্ঠুর কিন্তু কাজের:
*   সে নতুন ভ্যালু পেলে আগের **Inner Observable** কে `unsubscribe` করে দেয়।
*   শুধু নতুনটার সাথে সংসার করে।

**বাস্তব উদাহরণ:**
*   তুমি একজনকে প্রপোজ করেছ (Observable 1)। রিপ্লাই আসেনি।
*   এর মধ্যে আরেকজনকে ভালো লাগল (Observable 2)। তুমি তাকে প্রপোজ করলে।
*   `switchMap` আগেরজনকে বলবে: **"ব্রেকআপ! তোমার রিপ্লাই আর আমার লাগবে না।"** এবং নতুনজনের উত্তরের জন্য অপেক্ষা করবে।

---

### **কোড: পারফেক্ট সার্চ বার 👌**

```javascript
import { fromEvent } from 'rxjs';
import { switchMap, map, debounceTime } from 'rxjs/operators';
import { ajax } from 'rxjs/ajax'; // API কলের জন্য RxJS এর টুল

const searchBox = document.getElementById('search');

const searchStream$ = fromEvent(searchBox, 'input').pipe(
  // ১. একটু থামলাম (Debounce)
  debounceTime(300),
  
  // ২. ইনপুট টেক্সট নিলাম
  map(e => e.target.value),

  // ৩. আসল ম্যাজিক!
  switchMap(searchTerm => {
    // এই API কলটা একটা Observable রিটার্ন করে
    return ajax.getJSON(`https://api.github.com/users/${searchTerm}`);
  })
);

searchStream$.subscribe({
  next: (data) => console.log('Current User Data:', data),
  error: (err) => console.log('Error:', err)
});
```

**কি ঘটবে?**
*   তুমি `a` লিখলে -> API Call (Get 'a') শুরু হলো।
*   রেসপন্স আসার আগেই তুমি `b` লিখলে (`ab`) -> `switchMap` দেখল নতুন ইনপুট এসেছে। সে সাথে সাথে আগের API Call টা **Abort/Cancel** করে দিবে (Network tab এ দেখলে দেখবে স্ট্যাটাস `canceled`)।
*   তারপর সে নতুন `ab` এর জন্য কল পাঠাবে।

**লাভ:**
১. ইউজার সবসময় লেটেস্ট রেজাল্ট দেখবে।
২. নেটওয়ার্ক ব্যান্ডউইথ বাঁচবে (পুরনো রিকোয়েস্ট ক্যানসেল হওয়ার কারণে)।

---

### **Comparison: Merge vs Concat vs Switch 🥊**

| অপারেটর | আচরণ | উদাহরণ |
| :--- | :--- | :--- |
| **MergeMap** | কাউকে ক্যানসেল করে না, কাউকে ওয়েট করায় না। সবাই একসাথে। | **Delete All:** একসাথে সব ডিলিট হোক। |
| **ConcatMap** | কাউকে ক্যানসেল করে না, কিন্তু লাইনে দাঁড় করায়। | **Balance Transfer:** ট্রানজেকশন সিরিয়াল। |
| **SwitchMap** | নতুন আসলে পুরনোকে **ক্যানসেল** (Kill) করে দেয়। | **Search / Typeahead:** লেটেস্ট ডাটাই আসল। |

---

### **সাবধানতা! ⚠️**

`switchMap` ভুলেও **Create/Update/Delete** অপারেশনে ব্যবহার করবে না (যদি না তুমি বুঝেশুনে করো)।
*   ধরো ইউজার "Save" বাটনে ক্লিক করল। সেভ হতে একটু দেরি হচ্ছে।
*   ইউজার অধৈর্য হয়ে আবার "Save" দিল।
*   `switchMap` আগের সেভ রিকোয়েস্ট ক্যানসেল করে দিবে! ডাটাবেসে ডাটা সেভ হবে না।
*   এই ক্ষেত্রে `concatMap` বা `exhaustMap` ব্যবহার করা উচিত।

### **১. ForkJoin - শেষ ভালো যার, সব ভালো তার 🏁**

`forkJoin` অনেকটা `Promise.all` এর মতো।
সে অপেক্ষা করে **সবগুলো** Observable কখন `complete` হবে। যখন সবাই কাজ শেষ করে ডাটা দিবে, তখন সে সব ডাটা একসাথে একটা অ্যারে বা অবজেক্ট হিসেবে তোমাকে দিবে।

**ব্যবহার:** ড্যাশবোর্ড লোড করার সময়। ইউজার প্রোফাইল API এবং সেটিংস API—দুইটা কল শেষ হলে পেজ দেখাব।

**উদাহরণ:** খিচুড়ি রান্না।
*   চুলায় চাল দিয়েছ (১০ মিনিট লাগবে)।
*   ডালে দিয়েছ (৫ মিনিট লাগবে)।
*   মাংস দিয়েছ (২০ মিনিট লাগবে)।
*   সবকিছু যখন রান্না শেষ হবে, **কেবলমাত্র তখনই** তুমি পাতিলে মিক্স করবে এবং সার্ভ করবে।

**Code:**
```javascript
import { of, forkJoin } from 'rxjs';
import { delay } from 'rxjs/operators';

// সিমুলেটেড API কলস
const user$ = of({ name: 'Rahim' }).pipe(delay(1000)); // ১ সেকেন্ড লাগবে
const settings$ = of({ theme: 'Dark' }).pipe(delay(2000)); // ২ সেকেন্ড লাগবে
const friends$ = of(['Karim', 'Jabbar']).pipe(delay(500)); // ০.৫ সেকেন্ড লাগবে

console.log('লোডিং শুরু...');

forkJoin({
  user: user$,
  settings: settings$,
  friends: friends$
}).subscribe(response => {
  // সব শেষ হতে মোট ২ সেকেন্ড লাগবে (ম্যাক্সিমাম টাইম)
  console.log('সব ডাটা রেডি:', response);
});
```

**আউটপুট:**
```
(২ সেকেন্ড অপেক্ষার পর...)
সব ডাটা রেডি: {
  user: { name: 'Rahim' },
  settings: { theme: 'Dark' },
  friends: ['Karim', 'Jabbar']
}
```

**শর্ত:** সব Observable কে অবশ্যই `complete` হতে হবে। কেউ যদি `complete` না হয় (যেমন `interval`), তাহলে `forkJoin` অনন্তকাল অপেক্ষা করবে!

### **২. CombineLatest - লাইভ আপডেট 🔴**

`combineLatest` একটু আলাদা। সে অপেক্ষা করে না সব শেষ হওয়ার জন্য।
যখনই **যেকোনো একটা** ইনপুট Observable নতুন ডাটা দেয়, সে বাকিদের **লেটেস্ট** ভ্যালুর সাথে মিলিয়ে নতুন আউটপুট দেয়।

**উদাহরণ:** এক্সেল শিটের ফর্মুলা বা খিচুড়ির দাম নির্ধারণ।
*   চালের দাম (Stream A)
*   ডালের দাম (Stream B)
*   খিচুড়ির দাম = চাল + ডাল (Result)

যদি চালের দাম বাড়ে, সাথে সাথে খিচুড়ির দাম আপডেট হবে (ডালের আগের দামের সাথে যোগ করে)। আবার ডালের দাম বাড়লে, চালের লেটেস্ট দামের সাথে যোগ করে আপডেট হবে।

**Code:**
```javascript
import { combineLatest, of, fromEvent } from 'rxjs';
import { map } from 'rxjs/operators';

// ১. ইনপুট বক্স থেকে ভ্যালু নেওয়া (কালার এবং সাইজ)
// ধরে নাও HTML এ দুইটা সিলেক্ট বক্স আছে
const color$ = fromEvent(document.getElementById('color'), 'change').pipe(
    map(e => e.target.value)
); // Red, Blue...

const size$ = fromEvent(document.getElementById('size'), 'change').pipe(
    map(e => e.target.value)
); // Small, Large...

// ২. কম্বাইন করা
combineLatest([color$, size$]).subscribe(([color, size]) => {
  console.log(`শার্টের অর্ডার: ${color} রঙের এবং ${size} সাইজের।`);
});
```

**আউটপুট:**
*   শুরুতে ইউজার 'Red' সিলেক্ট করল (কিছুই হবে না, কারণ 'Size' এখনো আসেনি)।
*   ইউজার 'Large' সিলেক্ট করল -> **আউটপুট:** Red Large
*   ইউজার কালার চেঞ্জ করে 'Blue' করল -> **আউটপুট:** Blue Large (Size এর লাস্ট ভ্যালু মনে রেখেছে)
*   ইউজার সাইজ 'Small' করল -> **আউটপুট:** Blue Small

### **পার্থক্য এক নজরে (Summary Table) 🥊**

| বৈশিষ্ট্য | ForkJoin 🏁 | CombineLatest 🔴 |
| :--- | :--- | :--- |
| **কখন ডাটা দেয়?** | যখন **সবাই** `complete` হয় (শেষ মুহূর্তে)। | যখনই **যেকোনো একজন** নতুন ডাটা দেয় (শুরুর পর থেকে বারবার)। |
| **কতবার কল হয়?** | মাত্র ১ বার (Final Result)। | বারবার (Whenever inputs change)। |
| **ব্যবহার** | Initial Data Loading (Dashboard)। | Form validation, Live Filters, Calculator। |
| **শর্ত** | ইনপুটদের অবশ্যই শেষ (Complete) হতে হবে। | ইনপুটদের শেষ হওয়ার দরকার নাই, লাইভ ডাটা হতে পারে। |

### **আজকের সারাংশ (Takeaway)**

*   একাধিক API কল একসাথে শেষ করে রেজাল্ট দেখাতে চাইলে -> **`forkJoin`**।
*   একাধিক ফর্ম ফিল্ড বা ফিল্টারের কম্বিনেশনে রিয়েল-টাইম রেজাল্ট দেখাতে চাইলে -> **`combineLatest`**।
