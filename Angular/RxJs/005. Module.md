### **RxJS এ এরর আসলে কী হয়?**

RxJS এর নিয়ম খুব কড়া। কোনো একটা স্ট্রিমের মাঝপথে যদি `error` আসে (যেমন: নেটওয়ার্ক ফেইল, সার্ভার ক্র্যাশ), তাহলে সেই স্ট্রিম সাথে সাথে **মারা যায়** (Dead)। এরপর আর কোনো ডাটা আসবে না।

আমাদের কাজ হলো:
১. স্ট্রিম মরার আগে তাকে বাঁচানো (`catchError`)।
২. অথবা তাকে সিপিআর (CPR) দিয়ে আবার চেষ্টা করানো (`retry`)।

---

### **১. CatchError - বিকল্প রাস্তা 🛣️**

ধরো তুমি বাসে করে যাচ্ছ। হঠাৎ দেখলে রাস্তা বন্ধ (Error)। তুমি কি ওখানেই বসে থাকবে? না, তুমি বিকল্প রাস্তা (Alternative Observable) ধরবে।

`catchError` অপারেটর এরর ধরবে এবং নতুন একটা Observable রিটার্ন করবে যাতে অ্যাপ ক্র্যাশ না করে।

**Code:**
```javascript
import { of, throwError } from 'rxjs';
import { catchError, map } from 'rxjs/operators';

// একটা ফেইক API কল যেটা এরর দিবে
const apiCall$ = throwError(() => 'Server Boom! 💥');

apiCall$.pipe(
  catchError(err => {
    console.log(`সমস্যা ধরা পড়েছে: ${err}`);
    // এরর এর বদলে আমরা একটা "ফলব্যাক ডাটা" পাঠাব
    return of('Cached Data (Offline Mode) 📦');
  })
)
.subscribe({
  next: val => console.log(`পেয়েছি: ${val}`),
  error: e => console.log('App Crashed!'), // এটা কল হবে না, কারণ আমরা হ্যান্ডেল করেছি
  complete: () => console.log('Done')
});
```

**আউটপুট:**
```
সমস্যা ধরা পড়েছে: Server Boom! 💥
পেয়েছি: Cached Data (Offline Mode) 📦
Done
```
*দেখলে? সাবস্ক্রাইবারের `error` ব্লক কলই হয়নি। সাবস্ক্রাইবার মনে করেছে সব ঠিক আছে!*

### **২. Retry - একবার না পারিলে দেখো শতবার 🔄**

মাঝে মাঝে এররটা টেম্পোরারি হয় (যেমন: ওয়াইফাই একটু ফ্লিক করেছে)। সাথে সাথে হাল না ছেড়ে ২-৩ বার ট্রাই করা বুদ্ধিমানের কাজ।

`retry(n)` অপারেটর এরর পেলে আবার সাবস্ক্রাইব করে (রিস্টার্ট দেয়)।

**Code:**
```javascript
import { of, throwError } from 'rxjs';
import { mergeMap, retry, catchError } from 'rxjs/operators';

let attempt = 0;

const unstableApi$ = of('Request').pipe(
  mergeMap(req => {
    attempt++;
    console.log(`চেষ্টা নম্বর: ${attempt}...`);
    
    if (attempt < 3) {
      return throwError(() => 'Network Failed ❌');
    }
    return of('Success Data! ✅');
  })
);

unstableApi$.pipe(
  retry(2), // এরর খেলে আরও ২ বার ট্রাই করো
  catchError(err => of('সব চেষ্টা বিফল! 😔')) // সব চেষ্টার পর ফেল করলে এটা
)
.subscribe(val => console.log(val));
```

**আউটপুট:**
```
চেষ্টা নম্বর: 1... (ফেইল)
চেষ্টা নম্বর: 2... (ফেইল - Retry 1)
চেষ্টা নম্বর: 3... (সাকসেস - Retry 2)
Success Data! ✅
```
*আর যদি ৩ বারেই ফেইল করত, তাহলে `catchError` কল হতো এবং আউটপুট হতো "সব চেষ্টা বিফল!"।*

---

### **স্মার্ট Retry Strategy (Bonus Tip) 🧠**

`retry()` সাথে সাথে ট্রাই করে। কিন্তু সার্ভার ডাউন থাকলে ১ সেকেন্ড পর পর গুঁতো দিয়ে লাভ নেই। আমাদের দরকার **"Exponential Backoff"** (১ সেকেন্ড, তারপর ২ সেকেন্ড, তারপর ৫ সেকেন্ড পর ট্রাই)।

এটার জন্য `retryWhen` বা লেটেস্ট `retry({ delay: ... })` কনফিগারেশন ব্যবহার করা হয়। (এটা একটু এডভান্সড, জাস্ট জেনে রাখো)।

---

### **CatchError কোথায় বসাব?**

এটা খুব ট্রিকি।
*   **Inner Pipe:** তুমি যদি `switchMap` এর ভেতরের পাইপে `catchError` বসাও, তাহলে শুধু ওই রিকোয়েস্টটা ক্যানসেল হবে, কিন্তু মেইন স্ট্রিম (যেমন: বাটন ক্লিক লিসেনার) বেঁচে থাকবে।
*   **Outer Pipe:** যদি মেইন পাইপে বসাও, একবার এরর খেলেই পুরো বাটন অকেজো হয়ে যাবে।

**Rule of Thumb:** সবসময় `catchError` কে `switchMap/mergeMap` এর **ভেতরে** রাখবে যদি তুমি চাও স্ট্রিমটা বেঁচে থাকুক।

**Example:**
```javascript
// ✅ গুড প্র্যাকটিস (সার্চ বার মরবে না)
input$.pipe(
  switchMap(term => api.get(term).pipe(
      catchError(err => of(null)) // শুধু API কলটা হ্যান্ডেল করলাম
  ))
).subscribe();

// ❌ ব্যাড প্র্যাকটিস (একবার এরর হলে সার্চ বার আর কাজ করবে না)
input$.pipe(
  switchMap(term => api.get(term)),
  catchError(err => of(null))
).subscribe();
```

*   **`catchError`**: এরর ধরো এবং বিকল্প ডাটা দাও (Recovery)।
*   **`retry`**: হাল ছেড়ো না বন্ধু, আবার ট্রাই করো (Resubscribe)।

### **Observable এর একটা গোপন সমস্যা 🤫**

সাধারণ `Observable` হলো **Unicast** (একমুখী)। মানে হলো, তুমি যতবার `subscribe` করবে, সে ততবার নতুন করে কাজ শুরু করবে।

**উদাহরণ:** নেটফ্লিক্স।
*   তুমি প্লে করলে -> মুভি শুরু থেকে শুরু হলো।
*   তোমার বন্ধু প্লে করল -> তার জন্যও মুভি শুরু থেকে শুরু হলো।
*   তোমরা দুইজন কিন্তু "একই লাইভ স্ট্রিম" দেখছ না।

কিন্তু আমাদের মাঝে মাঝে **Multicast** দরকার।
**উদাহরণ:** ফুটবল খেলার লাইভ স্ট্রিম।
*   গোল হলে পৃথিবীর সবাই একসাথে দেখবে।
*   আমি ১০ মিনিট পর জয়েন করলে ১০ মিনিট পরের অংশ থেকেই দেখব (শুরু থেকে না)।

এই কাজের জন্য RxJS এ আছে **Subject**।

### **১. Subject - পাড়ার মাইক 📢**

`Subject` একাধারে **Observable** এবং **Observer**।
*   তুমি এতে `subscribe()` করতে পারো (যেমন Observable)।
*   তুমি এতে `next()` কল করে ডাটা পুশও করতে পারো (যেমন Observer)।

**Code:**
```javascript
import { Subject } from 'rxjs';

// ১. একটা মাইক (Subject) কিনলাম
const sportsNews$ = new Subject();

// ২. শ্রোতা ১ সাবস্ক্রাইব করল
sportsNews$.subscribe(data => console.log(`Listener 1: ${data}`));

// ৩. মাইকে ঘোষণা দিলাম
sportsNews$.next('গোল! ১-০ ⚽');

// ৪. শ্রোতা ২ সাবস্ক্রাইব করল (দেরিতে)
sportsNews$.subscribe(data => console.log(`Listener 2: ${data}`));

// ৫. আবার ঘোষণা
sportsNews$.next('হাফ টাইম শুরু! ⏸️');
```

**আউটপুট:**
```
Listener 1: গোল! ১-০ ⚽
(Listener 2 কিছুই শুনবে না কারণ সে তখনো জয়েন করেনি)

Listener 1: হাফ টাইম শুরু! ⏸️
Listener 2: হাফ টাইম শুরু! ⏸️
(এখন দুইজনই একসাথে শুনছে)
```

**সমস্যা:** Listener 2 আগের গোল মিস করেছে।

### **২. BehaviorSubject - স্মার্ট মাইক (State Store) 🧠**

`BehaviorSubject` হলো `Subject` এর বড় ভাই। এর একটা **মেমোরি** আছে। সে সবসময় **শেষ ভ্যালুটা** মনে রাখে।
কেউ নতুন সাবস্ক্রাইব করলেই সে বলে দেয়: *"ভাই, লেটেস্ট খবর হলো এইটা..."*

**ব্যবহার:**
*   ইউজার লগইন আছে কি না? (Current User State)
*   ডার্ক মোড অন না অফ? (Theme State)

**Code:**
```javascript
import { BehaviorSubject } from 'rxjs';

// ১. শুরুতে একটা ডিফল্ট ভ্যালু দিতে হয় (Initial State)
const userLoggedIn$ = new BehaviorSubject('Guest User 👤'); 

// ২. শ্রোতা ১ আসলো
userLoggedIn$.subscribe(u => console.log(`Header Component: ${u}`));

// ৩. ভ্যালু আপডেট করলাম (লগইন হলো)
console.log('--- ইউজার লগইন করছে ---');
userLoggedIn$.next('Rahim Bhai 😎');

// ৪. শ্রোতা ২ আসলো (অনেক পরে)
userLoggedIn$.subscribe(u => console.log(`Sidebar Component: ${u}`));
```

**আউটপুট:**
```
Header Component: Guest User 👤 (ডিফল্ট ভ্যালু পেল)

--- ইউজার লগইন করছে ---
Header Component: Rahim Bhai 😎 (আপডেট পেল)

Sidebar Component: Rahim Bhai 😎 (দেরিতে এসেও লেটেস্ট ভ্যালু পেল!)
```

### **RxJS দিয়ে স্টেট ম্যানেজমেন্ট (Mini Redux)**

তুমি খুব সহজেই একটা গ্লোবাল স্টোর বানাতে পারো:

```javascript
// store.js
import { BehaviorSubject } from 'rxjs';

// প্রাইভেট সাবজেক্ট (যাতে বাইরে থেকে কেউ next করতে না পারে)
const _counter = new BehaviorSubject(0);

// পাবলিক অবজারভেবল (সবাই শুধু দেখতে পারবে)
export const counter$ = _counter.asObservable();

// অ্যাকশন মেথড
export function increment() {
  const current = _counter.value; // বর্তমান ভ্যালু নেওয়া যায়
  _counter.next(current + 1);
}
```

---

### **Subject vs BehaviorSubject 🥊**

| বৈশিষ্ট্য | Subject 📢 | BehaviorSubject 🧠 |
| :--- | :--- | :--- |
| **Initial Value** | লাগে না। | অবশ্যই দিতে হয় `new BehaviorSubject(initial)`. |
| **Late Subscriber** | আগের ডাটা পায় না, শুধু নতুন ডাটা পায়। | সাবস্ক্রাইব করার সাথে সাথেই **সর্বশেষ** ডাটা পায়। |
| **Current Value** | দেখা যায় না। | `.value` প্রপার্টি দিয়ে দেখা যায়। |
| **Use Case** | Event Bus (Button Clicks, Notifications). | State Management (Auth, Settings, Data). |
