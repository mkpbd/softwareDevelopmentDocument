
7-2 Why Do We Require Data Pre Processing_With an Example Dataset

.মেশিন লার্নিং বা ডেটা সায়েন্সে একটি মডেল কতটা ভালো কাজ করবে, তার একটি বড় অংশ নির্ভর করে **ডেটার গুণমানের ওপর**। কাঁচা ডেটা (raw data) সাধারণত বিশৃঙ্খল, অসম্পূর্ণ এবং মডেল-রেডি থাকে না। তাই ডেটাকে পরিষ্কার করে সাজানো, রূপান্তর করা, এবং দরকারি অংশগুলো নির্বাচন করাই হলো **Data Pre-Processing**।

এই মডিউলে আমরা বুঝব—**কেন প্রিপ্রোসেসিং করা হয়**, এবং Titanic Dataset ব্যবহার করে দেখব কাঁচা ডেটায় কী কী সমস্যা থাকে।

## **কেন প্রিপ্রোসেসিং প্রয়োজন?**

Titanic Dataset-এর মতো ডেটা বিশ্লেষণ করতে গেলে সাধারণত কয়েকটি সমস্যা দেখা যায়—

### **1. Missing Values (খালি ডেটা) থাকে**

উদাহরণ: Titanic ডেটায় *Age*, *Cabin* ইত্যাদি কলামে অনেক মান নেই।

যদি আমরা missing values সরাসরি মডেলে দিই, মডেল ভুল শিখবে বা কাজই করবে না।

### **2. Inconsistent Formats (অসুসমত ফরম্যাট)**

যেমন—

sex → "male" / "female" (টেক্সট)

pclass → 1, 2, 3 (সংখ্যা)

মডেল সংখ্যাকে বুঝে, কিন্তু টেক্সটকে সরাসরি বুঝতে পারে না — তাই টেক্সটকে encode করতে হয়।

### **3. Categorical Data থাকে**

যেমন *embarked* → C, Q, S

এগুলোকে মডেল-ফ্রেন্ডলি সংখ্যায় রূপান্তর করতে হয়।

### **4. Outliers থাকতে পারে**

যেমন—*fare* কলামে কিছু যাত্রীর ভাড়া অস্বাভাবিকভাবে খুব বেশি, যা মডেলকে ভুল পথে নিয়ে যেতে পারে।

### **5. Scaling-এর প্রয়োজন হয়**

*Age* মান ~ 0 থেকে 80

*Fare* মান ~ 0 থেকে 500+

যদি স্কেল না করি, বড় ভ্যালুগুলো মডেলের ওজন নিয়ন্ত্রণে বেশি প্রভাব ফেলবে।

### **6. Duplicate / Irrelevant features থাকতে পারে**

যেমন—*ticket* বা *cabin* কখনও কখনও prediction-এ তেমন গুরুত্বপূর্ণ নয়, তাই মডেল building-এর আগে এগুলো বিশ্লেষণ করতে হয়।

## **Titanic Dataset দেখে Pre-Processing প্রয়োজনীয়তা বোঝা**

Titanic Dataset-এ দেওয়া প্রতিটি ভ্যারিয়েবল বিশ্লেষণ করলে সহজেই বোঝা যায় কেন প্রিপ্রোসেসিং দরকার।

Pre-Processing ছাড়া মডেল **কখনও ভালো accuracy পাবে না**, যত ভালো algorithm–ই ব্যবহার করুন না কেন।

# **Handling Missing Values – Titanic Dataset (Part 2)**

আগের অংশে আমরা দেখেছি:

*   কোন কোন কলামে missing values আছে
*   কেন numeric মান median দিয়ে পূরণ করা হয়
*   কেন categorical মান mode দিয়ে পূরণ করা হয়
*   Cabin কলাম বাদ দেওয়ার যুক্তি

এখন আমরা বাস্তবে missing values–গুলো ঠিক করবো।

এই ধাপগুলো মডেল তৈরির আগে খুব গুরুত্বপূর্ণ, কারণ missing data সরাসরি prediction quality–কে খারাপ করে দেয়।

## **১. Numeric Missing Values ঠিক করা (Age কলাম)**

Titanic Dataset–এ *Age* কলামে প্রায় **১৭৭টি** missing value আছে।

Age একটি numeric feature — তাই এটিকে median দিয়ে পূরণ করা হবে।

```python
# 1. Handle numeric missing values: Age
age_median = df_titanic["Age"].median()
df_titanic["Age"] = df_titanic["Age"].fillna(age_median)
```

### **ব্যাখ্যা**

| Code | Explanation |
| :--- | :--- |
| df_titanic["Age"].median() | Age কলামের **median** মান বের করা হয়। |
| age_median | median মানটি একটি ভেরিয়েবলে রাখা হয় যাতে পরবর্তী ধাপে ব্যবহার করা যায়। |
| .fillna(age_median) | Age কলামের যেখানে NaN ছিল, সেগুলো median দিয়ে পূরণ করে। |

**কেন median?**

Age ডেটা right-skewed, তাই mean ব্যবহার করলে বড় বয়সের মানগুলো mean–কে উপর দিকে টেনে নেবে। Median এতে প্রভাবিত হয় না।

## **২. Categorical Missing Values ঠিক করা (Embarked কলাম)**

Titanic Dataset–এ *Embarked* কলামে **মাত্র ২টি** missing value আছে।

এটি categorical, তাই আমরা mode ব্যবহার করবো।

### **কোড**

```python
# 2. Handle categorical missing values: Embarked
embarked_mode = df_titanic["Embarked"].mode()[0]
df_titanic["Embarked"] = df_titanic["Embarked"].fillna(embarked_mode)
```

### **ব্যাখ্যা**

| Code | Explanation |
| :--- | :--- |
| df_titanic["Embarked"].mode() | Embarked কলামে সবচেয়ে বেশি পাওয়া মান নির্ণয় করে। |
| mode()[0] | mode সাধারণত একটি সিরিজ হিসেবে আসে। আমরা প্রথম মানটি নিই। |
| .fillna(embarked_mode) | missing Embarked মানগুলো এই mode দিয়ে পূরণ করা হয়। |

**কেন mode?**

Mode ব্যবহার করলে আমরা dataset–এর distribution নষ্ট করি না।

যেখানে সবচেয়ে বেশি লোক উঠেছে (সাধারণত "S") সেই মানই দেওয়া হয়।

## **৩. Cabin কলাম Drop করা**

Titanic Dataset–এ Cabin কলামে missing মান রয়েছে **৬৮৭টি** — অর্থাৎ মোট ডেটার প্রায় ৭৭%।

এত বেশি missing থাকলে:

*   পূরণ করার জন্য উপযুক্ত মান পাওয়া যায় না
*   Bias তৈরি হয়
*   মডেল Cabin সবসময় ১-২ মানে default হয়ে পড়ে

তাই সাধারণত এই কলাম বাদ দেওয়া হয়।

### **কোড**

```python
# 3. Drop Cabin (too many missing values)
df_titanic = df_titanic.drop(columns=["Cabin"])
```

### **ব্যাখ্যা**

| Code | Explanation |
| :--- | :--- |
| .drop(columns=["Cabin"]) | Cabin কলাম dataframe থেকে সম্পূর্ণভাবে বাদ দেয়। |
| df_titanic = ... | নতুন dataframe–টি আবার df_titanic নামে রাখা হয়। |

# **Normalization এবং Scaling — কেন প্রয়োজন?**

### **বাস্তব উদাহরণ: Height বনাম Salary**

ধরুন, আপনার কাছে দুইটি ফিচার আছে—

*   **উচ্চতা (Height)**: সাধারণত ১৫০ থেকে ১৯০ সেন্টিমিটার
*   **বেতন (Salary)**: ২০,০০০ থেকে ৭০০,০০০ টাকা

যদি আপনি এগুলো সরাসরি মেশিন লার্নিং মডেলে দেন, বিশেষ করে *distance-based model* (KNN, K-Means, SVM), তখন Salary-এর মান অনেক বড় হওয়ায় সেটি distance গণনায় পুরো আধিপত্য করে ফেলবে।

তার মানে Height এর মতো ছোট স্কেলের ফিচার মডেল সঠিকভাবে বিবেচনাই করবে না।

এ কারণে আমাদের স্কেলিং প্রয়োজন—যাতে সব numeric ফিচার **একই ধরনের স্কেলে** আসে।

# **Scaling-এর দুটি সাধারণ পদ্ধতি**

*   Mean = 0

### **২. MinMaxScaler**

*   ফিচারকে 0 থেকে 1 রেঞ্জে নিয়ে আসে।
*   সূত্র:[Image]

শুধু **training set এ fit** করতে হবে — যাতে future data leakage না ঘটে।

এখন দেখব MinMax Scaling কিভাবে প্রয়োগ করা হয়।

## **Step 1: Train-Test Split (আগের মতোই)**

```python
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler, MinMaxScaler

target_col = "HeartDisease"

X = df_heart_encoded.drop(columns=[target_col])
y = df_heart_encoded[target_col]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, 
    test_size=0.25, 
    random_state=42
)
```

### ব্যাখ্যা:

*   X হলো সব features
*   y হলো target variable
*   ২৫% ডেটা test set
*   পরবর্তী scaling-এর জন্য X_train ও X_test আলাদা করা হলো

## **Step 2: MinMaxScaler fit ও transform**

```python
scaler_mm = MinMaxScaler()

# Fit only on training data
X_train_mm = scaler_mm.fit_transform(X_train)

# Transform test data using same scaling
X_test_mm = scaler_mm.transform(X_test)
```

### এখানে কী হলো?

#### **fit(X_train)**

*   প্রতিটি feature-এর min ও max নির্ণয় করা হলো *শুধু training data থেকে*
*   এগুলো scaler-এর ভেতরে store করা হলো

#### **transform(X_train / X_test)**

*   X_train ও X_test—দুটোকেই scaling করা হলো
*   কিন্তু scaling-এ ব্যবহৃত min ও max শুধুই training-এর, test-এর নয়
*   এটি data leakage বন্ধ করে

**কেন এটি গুরুত্বপূর্ণ?**

যদি test ডেটার min বা max ব্যবহার করা হয়, তবে model training-এর সময় future information *চুরি করে ফেলবে*, যা প্র্যাকটিক্যাল বাস্তবে ভুল।
