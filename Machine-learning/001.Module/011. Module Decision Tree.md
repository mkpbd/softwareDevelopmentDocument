# Introduction to Decision Trees

Decision Tree হল অন্যতম জনপ্রিয় এবং সহজবোধ্য Machine Learning মডেল। এটি এমনভাবে কাজ করে যেন আমরা ধাপে ধাপে প্রশ্ন করে কোনো সিদ্ধান্তে পৌঁছাচ্ছি। এই অধ্যায়ে আমরা বুঝব Decision Tree কী, কেন ব্যবহার করা হয়, এবং কীভাবে এটি কাজ করে।

## কেন Decision Trees ব্যবহার করবো?

### Simple & Intuitive
Decision Tree মানুষের স্বাভাবিক সিদ্ধান্ত নেওয়ার ধরনকে অনুকরণ করে। আমরা যেমন “যদি এমন হয় → তাহলে এমন করো” ধরনের নিয়ম অনুসরণ করি, Decision Tree তেমনি লজিক্যাল সিকোয়েন্স অনুসরণ করে।

### Easy to Visualize
এগুলো ফ্লোচার্টের মতো আঁকা যায়, যা খুব সহজে বোঝানো এবং ব্যাখ্যা করা যায়—even non-technical মানুষের জন্যও।

### Versatile Data Handling
Decision Tree numeric এবং categorical—দু’ধরনের ডেটার সঙ্গেই সমানভাবে কাজ করতে পারে।

### Minimal Preprocessing
অনেক মডেলের মত স্কেলিং বা normalization প্রয়োজন হয় না। কম প্রিপ্রসেসিং দিয়েই ভালোভাবে কাজ করে।

## Decision Tree কী?

Decision Tree একটি predictive model, যা একটি প্রশ্নের ধারাবাহিকতা ব্যবহার করে prediction করে।
প্রতিটি ধাপে “হ্যাঁ/না”, “True/False”, বা “≤ / >” ভিত্তিতে ডেটা ভাগ হয়ে যায়।
এটি মূলত একটি “বুদ্ধিমান ফ্লোচার্ট” যা আপনাকে শুরু থেকে শেষ পর্যন্ত গাইড করে নিয়ে যায়।

### Decision Tree–এর পথচলা
1. **Root node** থেকে শুরু
2. ডেটা অনুযায়ী কোনো branch নির্বাচন
3. শেষ পর্যন্ত **leaf node**–এ পৌঁছে prediction তৈরি করা

## একটি বাস্তব উদাহরণ – ক্রিকেট খেলবো কি না?

ধরুন আমরা চারটি ডেটা পেয়েছি:

| Weather | Windy | Play? |
| :--- | :--- | :--- |
| Sunny | No | Yes |
| Sunny | Yes | Yes |
| Rainy | No | No |
| Rainy | Yes | No |

এখান থেকে Decision Tree সহজ একটি নিয়ম শিখে নেয়:

### Decision Rule
* যদি Weather = Sunny → Play Cricket
* যদি Weather = Rainy → Don’t Play

মডেল এভাবেই ডেটা থেকে নিয়ম শিখে নেয়।

## Decision Tree–এর গঠন

Decision Tree–এর প্রতিটি অংশের আলাদা ভূমিকা আছে।

### 1. Root Node
শুরু বিন্দু। এখানে প্রথম এবং সবচেয়ে গুরুত্বপূর্ণ split ঘটে।

### 2. Internal Nodes
মাঝের decision পয়েন্ট, যেখানে আরও নতুন প্রশ্ন করে ডেটা ভাগ করা হয়।

### 3. Branches
Node থেকে node–এ যাওয়ার পথ।
প্রতিটি পথ একটি সিদ্ধান্তের ফলাফল নির্দেশ করে (যেমন “হ্যাঁ”, “না” বা “≤ 10” ইত্যাদি)।

### 4. Leaf Nodes
শেষের নোড, যেখানে চূড়ান্ত prediction বা class নির্ধারণ করা হয়।

## Tree কীভাবে একটি split নির্বাচন করে?

প্রতিটি node–এ Decision Tree ডেটা ভাগ করার জন্য অনেকগুলো সম্ভাব্য প্রশ্ন পরীক্ষা করে।
উদাহরণস্বরূপ—
* Is age > 45?
* Is cholesterol > 220?
* Is weather = sunny?
* Is income > 50,000?

মডেল সেই প্রশ্নটিকেই বেছে নেয় যা ডেটাকে সবচেয়ে বেশি **pure** (অর্থাৎ পরিষ্কারভাবে আলাদা) করে।

## Impurity কী? — একটি সহজ ধারণা

Impurity শব্দটি বোঝায় একটি গ্রুপ কতটা “মিশ্রিত”।
উদ্দেশ্য হলো: এমন split করা যাতে দুই পাশেই যতটা সম্ভব একজাতীয় ডেটা থাকে।

### Pure Group
যেমন:
* 10 Yes, 0 No
* এখানে সব একই—নিখুঁত শ্রেণি।

### Impure Group
যেমন:
* 5 Yes, 5 No
* একেবারেই মিশ্রিত—মডেলও নিশ্চিত হতে পারে না।

আগামী মডিউলগুলোতে আমরা Impurity–র গাণিতিক রূপ—**Entropy** এবং **Gini Index**—শিখব।

## Decision Tree–এর শক্তি

### Highly Explainable
প্রতিটি prediction–কে ধাপে ধাপে ব্যাখ্যা করা যায়। তাই stakeholder–রাও সহজে বুঝতে পারেন।

### No Feature Scaling Needed
Normalization বা Standardization দরকার নেই।

### Nonlinear Patterns
জটিল nonlinear সম্পর্ক ধরতে পারে, অতিরিক্ত feature engineering ছাড়াই।

### Excellent Baseline
দ্রুত ট্রেন হয়, সহজে ব্যাখ্যা করা যায়—প্রথম মডেল হিসেবে অসাধারণ।

## কিছু সীমাবদ্ধতা

### Overfitting
অনেক সময় Tree অতিরিক্ত বড় হয়ে যায় এবং ডেটার noise–ও শিখে ফেলে। এতে new data–তে পারফরম্যান্স কমে।

### High Variance
ডেটা সামান্য বদলালেই সম্পূর্ণ ভিন্ন Tree তৈরি হতে পারে।

### Requires Pruning
অপ্রয়োজনীয় বড় Tree কাটছাঁট করতে হয়।

### High Dimensional Data–তে দুর্বল
শত শত feature থাকলে Decision Tree দক্ষভাবে কাজ নাও করতে পারে।

# Entropy, Gini Index, and Information Gain

Decision Tree–এর সবচেয়ে গুরুত্বপূর্ণ ধারণা হলো Impurity Measures—যা বলে দেয় একটি গ্রুপ কতটা "পরিষ্কার" বা "মিশ্রিত"। এখন আমরা Entropy, Gini Index এবং Information Gain নিয়ে সহজভাবে আলোচনা করবো।

## কেন Impurity Measure প্রয়োজন?

Decision Tree প্রতিটি split চেক করে—**“এই প্রশ্নটি কি ডেটাকে ভালোভাবে ভাগ করতে পারবে?”**

সব split সমান কার্যকর নয়। তাই impurity measure দিয়ে split–এর কার্যকারিতা মাপা হয়।

## Purity সম্পর্কে সহজ ধারণা

নীচের টেবিলে হেডারসহ সব রো একই ডিজাইনে দেওয়া হয়েছে (plain text table)—

| Group | Yes | No | ব্যাখ্যা |
| :--- | :--- | :--- | :--- |
| A | 10 | 0 | সম্পূর্ণ Pure |
| B | 5 | 5 | সবচেয়ে Impure |
| C | 8 | 2 | মাঝারি Purity |

Decision Tree চায় B → C → A–এর দিকে অগ্রসর হতে।

## Entropy: বিশৃঙ্খলার পরিমাপ

Entropy বোঝায় একটি গ্রুপের অনিশ্চয়তা ও বিশৃঙ্খলার পরিমাণ।

*   যত বেশি ক্লাস মেশানো → entropy তত বেশি
*   যত বেশি ক্লাস একদিকে ঝুঁকে যায় → entropy কম

| Yes-No অনুপাত | Entropy লেভেল | ব্যাখ্যা |
| :--- | :--- | :--- |
| 4 Yes, 4 No | High | সম্পূর্ণ মিশ্রিত, অনিশ্চিত |
| 6 Yes, 2 No | Medium | কখনও হ্যাঁ, কখনও না – মাঝারি বিশৃঙ্খলা |
| 8 Yes, 0 No | Low | প্রায় pure, উচ্চ certainty |

Entropy কমলে গ্রুপ পরিষ্কার হয়।

## Gini Index: ভুল ক্লাসিফিকেশনের সম্ভাবনা

Gini Index বলে দেয়—
**গ্রুপ থেকে এলোমেলোভাবে একটি পয়েন্ট বাছলে কতবার ভুল হতে পারে?**

| Yes-No অনুপাত | Gini লেভেল | ব্যাখ্যা |
| :--- | :--- | :--- |
| 5 Yes, 5 No | High | ভুল হওয়ার সম্ভাবনা সবচেয়ে বেশি |
| 7 Yes, 3 No | Medium | বেশিরভাগ ক্ষেত্রে ঠিক, মাঝে মাঝে ভুল |
| 10 Yes, 0 No | Low | কোনো ভুল নয় – সম্পূর্ণ pure |

Entropy এবং Gini দুটোই impurity মাপার পদ্ধতি—সিদ্ধান্ত প্রায় একই হয়।

## Information Gain: সেরা split নির্বাচন

Entropy বা Gini দিয়ে গ্রুপের impurity বের করার পর প্রশ্ন হলো—**“split করলে impurity কতটা কমছে?”**

এটাই Information Gain:

> Information Gain = Parent Impurity − Weighted Children Impurity

Tree সেই split বেছে নেয় যার Information Gain সবচেয়ে বেশি।

## একটি বাস্তব উদাহরণ

**Parent গ্রুপ:**

| Group | Yes | No | Impurity (Gini) |
| :--- | :--- | :--- | :--- |
| Parent | 6 | 4 | 0.48 |

**Split করার পর:**

| Child | Yes | No | Gini | ব্যাখ্যা |
| :--- | :--- | :--- | :--- | :--- |
| Left | 5 | 0 | 0.00 | সম্পূর্ণ pure |
| Right | 1 | 4 | 0.32 | প্রায় পরিষ্কার |

অতঃপর—

*   দুই child–ই parent–এর চেয়ে পরিষ্কার
*   impurity উল্লেখযোগ্যভাবে কমেছে
*   তাই Information Gain বেশি
*   Decision Tree এই split–টিকে বেছে নেবে

## মূল শেখার পয়েন্ট

| Measure | যা বোঝায় |
| :--- | :--- |
| Entropy | বিশৃঙ্খলা ও অনিশ্চয়তার পরিমাণ |
| Gini Index | ভুল ক্লাসিফিকেশনের সম্ভাবনা |
| Information Gain | split করার পর impurity কত কমলো |

Decision Tree সর্বদা সেই প্রশ্নটাই বেছে নেয় যা impurity সবচেয়ে বেশি কমাতে পারে।

# 11.4 Building a Simple Decision Tree with Synthetic Data

এই সেকশনে আমরা 11.3-এ তৈরি করা একই synthetic ডেটা ব্যবহার করব, কিন্তু এবার আমরা পুরো decision tree-র কাজ আরও গভীরভাবে বুঝব — কিভাবে split হয়, কোন ফিচারকে preference দেওয়া হয়, এবং কেন।

## Decision Tree কীভাবে Split নির্বাচন করে?

Decision tree প্রতিটি step-এ দেখে:

*   কোন feature-এ split করলে impurity সবচেয়ে কম হবে?
*   impurity measure হিসেবে আমরা সাধারণত **Gini index** বা **Entropy** ব্যবহার করি।
*   Sklearn-এ default হলো **Gini**।

নিচের ছোট টেবিলটি synthetic dataset-এর একটি সারাংশ দেখাচ্ছে:

| Weather | Windy | Play |
| :--- | :--- | :--- |
| Sunny | 0 | 1 |
| Rainy | 1 | 0 |
| Sunny | 0 | 1 |
| Sunny | 1 | 1 |
| Rainy | 0 | 0 |
| Rainy | 1 | 0 |
| Sunny | 0 | 1 |
| Rainy | 1 | 0 |

এখানে model মূলত দুইটি feature পাচ্ছে:

*   Weather_num → (Sunny = 1, Rainy = 0)
*   Windy → 0 বা 1

Target: Play → 1 = Yes, 0 = No

## Tree কোন Feature কে আগে Split করল?

Tree visualization (11.3 থেকে) দেখলে দেখা যায় সাধারণত:

*   প্রথম split হয় **Weather_num** এ
*   কারণ এই feature impurity সবচেয়ে বেশি reduce করে

এটি manually যাচাই করার জন্য আমরা sklearn থেকে feature importance বের করতে পারি:

```python
tree_syn.feature_importances_
```

# কোড

## Step 1 — Feature importance দেখা

```python
# Feature importance দেখার জন্য
importances = tree_syn.feature_importances_
for feature, score in zip(['Weather_num', 'Windy'], importances):
    print(feature, ":", score)
```

### ব্যাখ্যা:
*   `tree_syn.feature_importances_` দেখায় model কোন feature-কে কতটা weight দিয়েছে।
*   মান যত বেশি হবে, সেই feature decision-এ তত বেশি গুরুত্বপূর্ণ।
*   সাধারণত আমাদের synthetic example-এ Weather বেশি important হয়, কারণ Sunny/Rainy সবচেয়ে প্রভাব ফেলে Play সিদ্ধান্তে।

## Step 2 — Prediction পরীক্ষা করা

```python
# Prediction test
test_points = np.array([[1,0],   # Sunny, Not Windy
                        [0,1]])  # Rainy, Windy

preds = tree_syn.predict(test_points)
print(preds)
```

### ব্যাখ্যা:
*   প্রথম sample → Weather=Sunny, Windy=0
*   দ্বিতীয় sample → Weather=Rainy, Windy=1
*   tree কোন rule শিখেছে সেটি test করে দেখা যায়।

## Step 3 — Decision Boundary Visualization (Extra Concept)

Synthetic data দুইটি feature বিশিষ্ট হওয়ায় আমরা পুরো decision boundary আঁকতে পারি।

```python
# Decision boundary drawing for intuition
x_min, x_max = X_syn['Weather_num'].min()-1, X_syn['Weather_num'].max()+1
y_min, y_max = X_syn['Windy'].min()-1, X_syn['Windy'].max()+1

xx, yy = np.meshgrid(
    np.linspace(x_min, x_max, 50),
    np.linspace(y_min, y_max, 50)
)

Z = tree_syn.predict(np.c_[xx.ravel(), yy.ravel()])
Z = Z.reshape(xx.shape)

plt.contourf(xx, yy, Z, alpha=0.3)
plt.scatter(X_syn['Weather_num'], X_syn['Windy'], c=y_syn)
plt.xlabel("Weather_num")
plt.ylabel("Windy")
plt.title("Decision Boundary of Synthetic Decision Tree")
plt.show()
```

### ব্যাখ্যা:
*   `meshgrid` তৈরি করে feature space-এর প্রতিটি পয়েন্ট কভার করা হয়।
*   model প্রতিটি পয়েন্টে prediction করে boundary আঁকে।
*   এতে স্পষ্ট দেখা যায় কোথায় Sunny হলে Play হবে, কোথায় Rainy হলে হবে না।

## Summary

এই পুরো সেকশনে আমরা শিখলাম:

*   Decision tree impurity কমানোর ভিত্তিতে split বেছে নেয়।
*   আমাদের synthetic dataset-এ সাধারণত Weather feature বেশি important।
*   Tree visualization ও prediction rules বুঝতে boundary plot খুব সাহায্য করে।
*   Synthetic data decision tree শেখানোর জন্য আদর্শ, কারণ প্রতিটি step manually ব্যাখ্যা করা যায়।

# 11.5 Overfitting and Pruning of Decision Tree

Decision Tree খুব সহজেই **overfit** করতে পারে—মানে, training data-তে খুব ভালো কাজ করলেও নতুন ডেটায় খারাপ perform করতে পারে।

এই অংশে আমরা দেখব:
*   Deep tree কীভাবে overfit করে
*   Pruned tree (যেমন max_depth=3) কীভাবে generalize করতে সাহায্য করে
*   Training vs Test accuracy তুলনা
*   দুটো tree visualization

এটি machine learning-এর একটি গুরুত্বপূর্ণ ধারণা—**simple model সাধারণত বেশি stable** হয়।

## বড় Synthetic Dataset তৈরি করা

আগের সেকশনে আমরা ছোট synthetic dataset ব্যবহার করেছি। কিন্তু overfitting বোঝাতে একটু বড় dataset দরকার—তাই `make_classification()` ব্যবহার করা হচ্ছে।

### কোড

```python
from sklearn.datasets import make_classification

# বড় synthetic dataset তৈরি
X_big, y_big = make_classification(
    n_samples=400,      # মোট 400 ডেটা পয়েন্ট
    n_features=5,       # মোট 5 টি feature
    n_informative=3,    # এর মধ্যে 3 টি সত্যিই গুরুত্বপূর্ণ feature
    n_redundant=0,      # কোনো duplicate/correlated feature নেই
    n_classes=2,        # binary classification
    random_state=42     # পুনরায় রান করলে একই dataset পেতে সাহায্য করে
)

# Train/test split
X_train_big, X_test_big, y_train_big, y_test_big = train_test_split(
    X_big, y_big, test_size=0.3, random_state=42
)

X_train_big.shape, X_test_big.shape
```

### ব্যাখ্যা:
*   `make_classification()` দিয়ে সহজ কিন্তু informative synthetic dataset তৈরি করা হয়।
*   ৭০% ডেটা training এবং ৩০% testing-এ যাচ্ছে।
*   এই ধরনের ডেটা overfitting ও pruning দেখানোর জন্য perfect।

## Deep Tree vs Pruned Tree Model

এখন দুইটি Decision Tree train করব:

### 1. **Deep Tree**
*   কোনো max_depth নেই
*   যত ইচ্ছা deep হতে পারে → overfit হওয়ার সম্ভাবনা বেশি

### 2. **Pruned Tree**
*   max_depth=3
*   সীমাবদ্ধ depth → model simple থাকে → সাধারণত ভালো generalization

### কোড

```python
# Deep tree (unrestricted)
deep_tree = DecisionTreeClassifier(random_state=42)
deep_tree.fit(X_train_big, y_train_big)

# Pruned tree (restricted)
pruned_tree = DecisionTreeClassifier(max_depth=3, random_state=42)
pruned_tree.fit(X_train_big, y_train_big)

# Predictions
y_train_pred_deep = deep_tree.predict(X_train_big)
y_test_pred_deep = deep_tree.predict(X_test_big)

y_train_pred_pruned = pruned_tree.predict(X_train_big)
y_test_pred_pruned = pruned_tree.predict(X_test_big)

# Accuracy comparison
print('Deep tree – train accuracy:', round(accuracy_score(y_train_big, y_train_pred_deep), 3))
print('Deep tree – test accuracy :', round(accuracy_score(y_test_big, y_test_pred_deep), 3))

print()
print('Pruned tree – train accuracy:', round(accuracy_score(y_train_big, y_train_pred_pruned), 3))
print('Pruned tree – test accuracy :', round(accuracy_score(y_test_big, y_test_pred_pruned), 3))
```

### ব্যাখ্যা:
*   Deep tree training data প্রায় perfect ভাবে fit করতে পারে → Training accuracy খুব বেশি।
*   কিন্তু test accuracy সাধারণত কম হয় → এটি overfitting।
*   Pruned tree training accuracy একটু কম হলেও test accuracy বেশি stable।
*   এটি generalization-এর উদাহরণ।

## Deep Tree vs Pruned Tree Visualization

Visualization করার মাধ্যমে ছাত্ররা আরও স্পষ্টভাবে দেখতে পারে:
*   Deep tree-এর split অনেক
*   Leaf node অনেক
*   Tree বড় → training ডেটায় সব noise পর্যন্ত শিখে ফেলে


### ব্যাখ্যা:
*   Deep tree diagram বেশি dense, বেশি branch → overfitting tendency
*   Pruned tree বেশ clean, readable → simple rules শিখেছে
*   বাস্তবে pruned model সাধারণত ভালো perform করে unseen ডেটায়

## Overfitting vs Pruning — Summary Table

| Model Type | Train Accuracy | Test Accuracy | Notes |
| :--- | :--- | :--- | :--- |
| Deep Tree | Very High | Often Lower | Overfits easily |
| Pruned Tree | Moderate–High | Higher/Stable | Good generalization |

## Summary

এই সেকশনে আমরা শিখলাম:

*   Decision tree যথেষ্ট deep হতে দিলে easily overfit করে।
*   Training accuracy খুব বেশি হলেও তা ভালো model প্রমাণ করে না।
*   Pruning (যেমন max_depth) tree-কে simple করে এবং better generalization দেয়।
*   Visualization model behavior বোঝায় সাহায্য করে।

## Heart-disease-এর মতো synthetic dataset তৈরি করা

আমরা তিনটি feature ব্যবহার করব:
*   age
*   chol (cholesterol)
*   thalach (maximum heart rate achieved)

Target (target) হবে —
**0 = কোনো disease নেই**,
**1 = disease আছে**

এখানে আমরা একটি rule-based "probability" তৈরি করেছি যেন dataset একটু বাস্তবসম্মত হয়।

```python
np.random.seed(42)
n_samples = 300

age = np.random.randint(30, 80, size=n_samples)
chol = np.random.randint(150, 300, size=n_samples)
thalach = np.random.randint(90, 200, size=n_samples)

# Disease probability 계산ের জন্য একটি সহজ formula
risk_score = 0.03 * (age - 40) + 0.02 * (chol - 200) - 0.02 * (thalach - 140)
prob = 1 / (1 + np.exp(-0.05 * risk_score))

target = (prob > np.median(prob)).astype(int)

df_heart = pd.DataFrame({
    'age': age,
    'chol': chol,
    'thalach': thalach,
    'target': target
})

df_heart.head(10)
```

### ব্যাখ্যা
*   `np.random.seed(42)` ব্যবহার করলে প্রতিবার একই random data তৈরি হবে — reproducibility-এর জন্য।
*   `randint` দিয়ে age, chol, thalach এর realistic value তৈরি করা হয়েছে।
*   `risk_score` একটি simple linear formula যা high age ও high cholesterol-এ disease probability বাড়ায় এবং high thalach (হার্ট ভালো) disease probability কমায়।
*   এরপর sigmoid function এর মত formula ব্যবহার করে probability তৈরি করা হয়েছে।
*   শেষে median probability-এর উপরে হলে 1, নাহলে 0 — অর্থাৎ disease label।

## Train-test split এবং Decision Tree train করা

এখন আমরা ডেটাকে train ও test-এ ভাগ করব।

```python

X_heart = df_heart[['age','chol','thalach']]
y_heart = df_heart['target']

X_train_h, X_test_h, y_train_h, y_test_h = train_test_split(

)

tree_heart = DecisionTreeClassifier(max_depth=4, random_state=42)
tree_heart.fit(X_train_h, y_train_h)

tree_heart
```

### ব্যাখ্যা
*   Feature matrix `X_heart` এবং target vector `y_heart` প্রস্তুত করা হয়েছে।
*   `train_test_split` ডেটাকে 80% train এবং 20% test-এ ভাগ করেছে।
*   `DecisionTreeClassifier(max_depth=4)` মানে tree-টি খুব deep হতে পারবে না।
    *   এটি overfitting কমায়
    *   generalization উন্নত করে
*   `.fit()` দিয়ে train ডেটার উপর model train করা হয়েছে।

## Accuracy, Precision, Recall, F1 Score হিসাব করা

এখন আমরা classification metric গুলো বের করব।

```python
# Accuracy, precision, recall, F1
acc = accuracy_score(y_test_h,y_pred_h)
prec = precision_score(y_test_h,y_pred_h)
rec = recall_score(y_test_h,y_pred_h)
f1 = f1_score(y_test_h,y_pred_h)

print('Accuracy :', round(acc, 3))
print('Precision:', round(prec, 3))
print('Recall   :', round(rec, 3))
print('F1 score :', round(f1, 3))
```

### ব্যাখ্যা

| Metric | অর্থ |
| :--- | :--- |
| **Accuracy** | মোট prediction-এর কত % সঠিক |
| **Precision** | model positive বললে সে কতবার সঠিক ছিল |
| **Recall** | মোট actual positive-এর কতটাকে model ধরতে পেরেছে |
| **F1 Score** | precision ও recall-এর balance করা harmonic mean |

### সামারি
*   **Recall কম হলে:** model অনেক disease case মিস করছে।
*   **Precision কম হলে:** model healthy রোগীকেও disease বলে দিচ্ছে।
*   **F1 score:** overall balance বোঝায়।

# ROC Curve, AUC, এবং Threshold Interpretation

Decision Tree classifier-এর পারফরম্যান্স মূল্যায়ন করার সময় accuracy বা F1-score পুরো গল্পটি বলে না।

অনেক ক্ষেত্রে **threshold পরিবর্তনের সঙ্গে সঙ্গে model-এর আচরণ কেমন বদলায়**— সেটি জানা খুব গুরুত্বপূর্ণ।

ROC curve এবং AUC এমন এক evaluation method যেটি **threshold-independent** এবং classifier-এর আলাদা দৃষ্টিভঙ্গি দেয়।

## Why ROC Curve?

Decision tree সাধারণভাবে prediction দেয় **0 বা 1**।
কিন্তু ROC curve তৈরি করতে আমাদের প্রয়োজন হয় **positive class-এর probability**
(যেমন: রোগী heart disease আছে কি না → class 1-এর probability)।

```python
# Predicted probabilities
y_proba_h = tree_heart.predict_proba(X_test_h)[:, 1]
y_proba_h[:10]
```

### ব্যাখ্যা
*   `predict_proba()` প্রতিটি sample-এর জন্য দুটি probability দেয় → class 0 এবং class 1
*   `[:, 1]` দিয়ে আমরা শুধু positive class (class 1)-এর probability নিচ্ছি
*   এগুলো ব্যবহার করেই ROC curve তৈরি হবে

## Understanding ROC Curve

ROC curve মূলত দেখায়:
*   Threshold পরিবর্তন করলে
    *   **True Positive Rate (TPR)** কীভাবে বদলায়
    *   **False Positive Rate (FPR)** কত বাড়ে বা কমে

### TPR (Recall)
TPR = TP / (TP + FN)
→ পজিটিভ কেস সঠিকভাবে ধরার ক্ষমতা

### FPR
FPR = FP / (FP + TN)
→ নেগেটিভ কেস ভুলভাবে পজিটিভ হিসেবে ধরা হচ্ছে কতটা

## Compute FPR, TPR, Thresholds and AUC

```python
# ROC curve and AUC
fpr, tpr, thresholds = roc_curve(y_test_h, y_proba_h)
roc_auc = auc(fpr, tpr)
print("AUC:", round(roc_auc, 3))
```

### ব্যাখ্যা
*   `fpr` → বিভিন্ন threshold-এ false positive rate
*   `tpr` → বিভিন্ন threshold-এ true positive rate
*   `thresholds` → কোন threshold ব্যবহার করলে সেই TPR, FPR পাওয়া যায়
*   `auc()` → ROC curve-এর নিচের entire area গণনা করে

**AUC এর মান:**
*   **1.0 → perfect classifier**
*   **0.7–0.9 → ভালো classifier**
*   **0.5 → random guessing**
*   **< 0.5 → খারাপ (উল্টো direction-এ predicts)**

## Plotting the ROC Curve

```python
# Plot
plt.figure()
plt.plot(fpr, tpr, label=f'ROC curve (AUC = {roc_auc:.3f})')
plt.plot([0, 1], [0, 1], linestyle='--', label='Random model')

plt.xlabel("False Positive Rate (FPR)")
plt.ylabel("True Positive Rate (TPR)")
plt.title("ROC Curve")
plt.legend()
plt.show()
```

### ব্যাখ্যা
*   বাম দিকের লাইন → মডেল যত বেশি top-left কোণ বরাবর উঠবে, তত ভালো
*   dotted লাইন → ৫০-৫০ random guessing
*   ROC curve যদি এর উপরে থাকে → মডেল random-এর চেয়ে ভালো performance দেয়

## Threshold Interpretation Table

| Threshold | TPR | FPR | কী বোঝায় |
| :--- | :--- | :--- | :--- |
| 0.9 | কম | খুব কম | শুধু খুব confident case-গুলোকে positive ধরে |
| 0.5 | মাঝারি | মাঝারি | default decision boundary |
| 0.1 | বেশি | বেশি | অনেক case positive ধরা হয় (false positive বাড়ে) |

*   Threshold কমালে model বেশি positive detect করে
*   Threshold বাড়ালে model conservative হয়

## Why ROC & AUC Matter?

**Accuracy** বা **F1-score** সব threshold-এর উপর নির্ভর করে না।
কিন্তু ROC curve আসলে সম্ভাব্য *সব threshold-এর performance* দেখায়।

এটি বিশেষভাবে গুরুত্বপূর্ণ:
1.  Medical diagnosis
2.  Fraud detection
3.  Sensitive classification problems

যেখানে false positive বা false negative— দুটোই গুরুত্বপূর্ণ।
