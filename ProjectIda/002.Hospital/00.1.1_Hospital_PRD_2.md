# 2. Master Business Principle of the Whole ERP

Every activity in the hospital follows this simple business truth:

**Someone requests something -> Someone approves it -> Someone performs it -> Someone records it -> Someone bills it -> Someone pays/reconciles it -> Someone audits it**

Examples:

- Doctor orders a lab test -> lab performs -> result entered -> bill generated -> patient/insurance pays
- Nurse administers medicine -> stock reduces -> patient bill updates -> inventory and finance reflect it
- Ward requests linens -> housekeeping fulfills -> stock reduces -> usage tracked
- Asset breaks down -> maintenance ticket raised -> engineer repairs -> cost posted

This is the core logic of the ERP.

# 3. Core Business Workflows

---

## 3.1 Patient Journey - OPD (Outpatient)

This is for patients who come, consult, and go home the same day.

### OPD Step-by-Step Journey

### A. Patient Arrival / Pre-Arrival

- Patient books appointment through:
    - Front desk
    - Call center
    - Patient portal
    - Mobile app
    - Corporate referral desk
    - Telemedicine booking
- If walk-in, appointment can be created instantly as walk-in registration

**Flow:**  
Patient inquiry -> search existing patient -> if found, reuse MRN -> if not found, create new patient profile

### B. Patient Registration

Front desk collects:

- Full name
- Age / date of birth
- Gender
- Mobile number
- Address
- National ID/passport if available
- Guardian details if needed
- Payer category:
    - Self-pay
    - Insurance
    - Corporate
    - Government scheme
    - Subscription package
- Branch/facility
- Specialty/doctor preference

**Business outputs:**

- Unique patient ID / MRN
- Encounter/visit number
- Financial class assigned
- Consent captured if required

### C. Appointment Creation / Queue Token

- Appointment date and slot selected
- Department and doctor selected
- Estimated consultation fee identified
- Queue token generated if needed
- Confirmation sent by SMS/email/app

**Status:** Pending -> Confirmed

### D. Arrival and Check-In

When patient reaches hospital:

- Reception marks patient as arrived
- Token activated in queue
- Identity verified
- Insurance eligibility checked if insured
- Co-pay, consultation advance, or registration fee may be collected

**Flow:**  
Confirmed -> Arrived -> Waiting

### E. Triage / Vitals (if hospital policy requires)

- Nurse/assistant records:
    - Blood pressure
    - Temperature
    - Pulse
    - Height/weight
    - Oxygen level
    - Chief complaint
- High-risk patients may be escalated to emergency or priority queue

### F. Doctor Consultation

Doctor opens patient encounter and reviews:

- Demographics
- Previous visits
- Allergies
- Chronic diseases
- Current medication
- Lab/radiology history
- Clinical notes

Doctor may perform:

- Examination
- Diagnosis
- Procedure
- Prescription
- Lab order
- Radiology order
- Follow-up advice
- Referral to another doctor
- Admission recommendation
- Tele-follow-up plan
- Sick leave / certificate issuance

### G. Orders and Service Execution

If doctor orders services:

#### Lab

Order created -> sample collected -> processed -> result verified -> result available to doctor/patient

#### Radiology

Order created -> scheduling if needed -> imaging performed -> report verified -> result released

#### Pharmacy

Prescription checked -> medicine dispensed -> inventory reduced -> charges posted

#### Procedure

Minor procedure room booked -> consumables used -> nursing documentation -> billing updated

### H. Billing and Payment

All consultation and services used during visit are accumulated.

Possible billing types:

- Immediate self-pay
- Insurance covered
- Corporate credit
- Subscription entitlement
- Mixed payment

### I. Visit Completion

Doctor finalizes consultation:

- Diagnosis completed
- Orders closed or marked pending
- Prescription given
- Follow-up date suggested
- Encounter closed

**OPD Flow Summary:**  
Registration -> Appointment -> Arrival -> Triage -> Consultation -> Orders -> Service Fulfillment -> Billing -> Payment/Claim -> Visit Closed

## 3.2 Patient Journey - IPD (Inpatient)

This is for patients admitted to stay in the hospital.

### IPD Step-by-Step Journey

### A. Admission Decision

Admission may come from:

- OPD doctor
- Emergency doctor
- Direct scheduled admission
- Surgery booking
- Transfer from another facility
- Corporate/insurance planned admission

Doctor issues admission order with:

- Provisional diagnosis
- Admission reason
- Bed class
- Specialty/unit
- Attending doctor
- Urgency level
- Isolation need if applicable

### B. Admission Desk Processing

Admission staff performs:

- Patient identity confirmation
- Insurance/corporate approval check
- Package/subscription eligibility check
- Bed requirement validation
- Consent collection
- Advance deposit collection if required
- Guarantor information capture

### C. Bed Allocation

Bed management checks:

- Bed class requested
- Gender restrictions if any
- Isolation requirement
- ICU/HDU/general ward need
- Infection control rules
- Equipment availability (oxygen, monitor, ventilator if needed)

**Flow:**  
Admission requested -> bed reserved -> patient admitted -> bed occupied

### D. Inpatient Record Opened

Once admitted:

- IPD encounter created
- Bed assigned
- Nursing case sheet opened
- Medication chart created
- Diet profile opened
- Billing account activated
- Clinical orders enabled

### E. Initial Clinical Assessment

- Doctor performs admission note
- Nurse performs nursing assessment
- Allergies confirmed
- Fall risk, pressure ulcer risk, infection risk, nutrition risk captured
- Initial care plan created

### F. Inpatient Care Delivery

During stay, many activities happen repeatedly:

#### Doctor activities

- Daily rounds
- Progress notes
- Medication orders
- Lab/radiology orders
- Procedure orders
- Surgery requests
- Transfer orders
- Discharge planning

#### Nurse activities

- Medication administration
- Vitals charting
- Intake/output charting
- Wound dressing documentation
- Care task completion
- Escalation of abnormal findings

#### Pharmacy activities

- Verify orders
- Dispense medicines/consumables
- Track returns/cancellations
- Charge patient account

#### Lab/Radiology

- Execute orders
- Return results
- Flag critical results

#### Diet

- Receive diet order
- Prepare meal plan based on diagnosis/allergies/restrictions
- Track meal delivery

#### Billing

- Every chargeable item posts to IPD bill:
    - Room rent
    - Nursing charges
    - Procedures
    - Medicines
    - Consumables
    - Investigations
    - Doctor visits
    - Surgery charges
    - Equipment use

### G. Transfer During Stay

Patient may move:

- Ward to ICU
- ICU to room
- One bed to another bed
- One specialty to another

Business effects:

- Bed release and re-allocation
- Tariff change
- Nursing team change
- Room charge rules change
- Clinical continuity maintained

### H. Discharge Planning

Doctor decides patient is ready for discharge.

Discharge preparation includes:

- Final diagnosis
- Discharge summary
- Final prescription
- Follow-up plan
- Medical certificates if needed
- Clearance from pharmacy, billing, nursing, procedures, assets if any rented equipment assigned

### I. Financial Clearance

Billing consolidates:

- All pending services
- Room charges until discharge time
- Insurance coverage
- Co-pay
- Deposits already paid
- Discounts if approved

### J. Discharge Execution

After medical and financial clearance:

- Nurse gives discharge education
- Pharmacy dispenses discharge meds
- Final bill settled or insurer accepted liability
- Bed marked vacant but not immediately reusable
- Housekeeping cleaning request created

### K. Post-Discharge

- Follow-up appointment may be booked
- Claim documents sent to insurer
- Patient portal updated
- Feedback request triggered
- Revenue and cost data finalized

**IPD Flow Summary:**  
Admission order -> Admission processing -> Bed assignment -> Initial assessment -> Ongoing treatment -> Orders/services -> Charge accumulation -> Discharge planning -> Financial clearance -> Discharge -> Bed cleaning -> Follow-up

## 3.3 Emergency / ER Patient Journey

Emergency is special because treatment comes first when needed.

### ER Flow

Arrival -> triage immediately -> severity classification -> emergency registration (full or temporary) -> doctor assessment -> stabilization -> emergency orders/procedures -> admission/discharge/referral/death handling -> billing and payer arrangement afterward as per policy

### ER Rules

- Critical patient cannot be delayed for payment
- Temporary patient ID can be created if identity unknown
- Medico-legal case flag if accident/assault/poisoning etc.
- Emergency deposit may be deferred based on policy and risk class
- If admitted, ER encounter converts into IPD admission trail

# 4. Procurement Cycle Workflow

This is how medicine or equipment enters the hospital.

## 4.1 Procurement Cycle - Step-by-Step

### A. Need Identification

Need may arise from:

- Low stock in pharmacy/store
- Department request
- New service launch
- Equipment replacement
- Minimum stock breach
- Emergency shortage
- Forecasted seasonal demand
- Asset failure requiring replacement

**Flow:**  
Stock reaches reorder level OR department needs item -> purchase request initiated

### B. Purchase Requisition (PR)

Requester raises requisition with:

- Item name/specification
- Quantity
- Needed by date
- Justification
- Department/cost center
- Urgency
- Preferred vendor if any
- Budget reference if applicable

Examples:

- Pharmacy asks for 500 vials of antibiotic
- OT asks for surgical gloves
- Biomedical team asks for patient monitor

### C. Approval Workflow

Approval depends on rules:

- By value
- By item type
- By urgency
- By budget ownership
- By criticality
- By branch

Possible approvers:

- Department head
- Store manager
- Procurement manager
- Finance manager
- Medical director
- CEO for high-value capital purchase

### D. Sourcing / RFQ

Procurement team:

- Checks approved vendors
- Requests quotations
- Compares price, quality, delivery time, warranty, compliance
- Negotiates terms

### E. Vendor Selection

Selection based on:

- Rate contract
- Lowest compliant bid
- Preferred/approved vendor
- Emergency procurement policy
- Technical committee recommendation

### F. Purchase Order (PO)

PO issued with:

- Item
- Quantity
- Unit price
- Tax
- Delivery schedule
- Payment terms
- Quality terms
- Batch/expiry requirements for medicines
- Warranty/AMC terms for equipment

### G. Goods Receipt / Delivery

Store receives items and checks:

- PO match
- Quantity
- Condition
- Batch number
- Expiry date
- Manufacturing date
- Temperature compliance if cold chain
- Serial number for assets
- Quality certificate if required

### H. Inspection and Acceptance

- Pharmacy/store/biomedical/quality team inspects
- Items may be:
    - Accepted
    - Partially accepted
    - Rejected
    - Quarantined pending verification

### I. Stock Addition

If accepted:

- Inventory updated
- Stock placed in correct location
- Batch-wise inventory created
- Asset register created for capital items
- Consumption/distribution enabled

### J. Invoice Processing

Vendor sends invoice -> matched with PO and receipt -> approved -> AP liability created -> payment scheduled

### K. Payment

Finance pays based on:

- Credit period
- Milestone payment
- Retention terms
- Tax deduction rules

### L. Post-Procurement Monitoring

- Vendor performance scored
- Expiry monitored
- Price trends tracked
- Consumption analyzed
- Contract compliance reviewed

**Procurement Summary:**  
Need identified -> requisition -> approval -> quotation -> vendor selection -> PO -> goods receipt -> inspection -> stock/asset entry -> invoice verification -> payment -> vendor evaluation

# 5. Revenue Cycle Management (RCM) Workflow

This is how hospital services become money.

## 5.1 RCM End-to-End

### A. Patient Financial Registration

At registration/admission, identify payer type:

- Self-pay
- Insurance
- Corporate credit
- Government
- Subscription package
- Mixed payer

### B. Eligibility and Authorization

For insurance/corporate:

- Check active policy/contract
- Verify covered services
- Confirm room entitlement
- Get pre-authorization if needed
- Capture approval number

### C. Charge Capture

Whenever service is used, charge should be generated.

Charge sources:

- Consultation
- Registration
- Lab
- Radiology
- Procedures
- Surgery
- Bed/room rent
- Pharmacy dispense
- Consumables
- Equipment use
- Nursing package
- Doctor round
- Ambulance
- Diet package if billable

### D. Charge Validation

Before final billing:

- Duplicate charges checked
- Canceled services removed
- Returned medicines reversed
- Package inclusions/exclusions applied
- Contract rates applied
- Discounts authorized

### E. Interim Billing / Running Bill

For IPD:

- Running statement available daily
- Deposits adjusted
- Additional deposit requested if needed
- Insurance estimate updated

### F. Claim Preparation

For insurance/corporate:

- Bill coded and compiled
- Medical records attached
- Authorization references attached
- Supporting documents validated

### G. Claim Submission

Claim sent to payer:

- Full cashless
- Reimbursement
- Corporate invoice
- Split bill with patient portion

### H. Adjudication

Payer reviews and may:

- Approve fully
- Partially approve
- Reject some items
- Ask for clarification/documents

### I. Payment Posting

Once money comes:

- Payment matched to invoice/claim
- Patient share and insurer share separated
- Short payment identified
- Outstanding AR tracked

### J. Denial Management

If rejected:

- Analyze reason
- Correct documentation/coding issue
- Appeal if valid
- Transfer non-covered amount to patient if contract allows

### K. Final Settlement

Final bill settled by:

- Cash
- Card
- bKash
- Nagad
- Bank transfer
- Insurance payment
- Corporate credit
- Deposit adjustment
- Refund if overpaid

**RCM Summary:**  
Patient registered with payer type -> eligibility check -> service provided -> charges captured -> bill validated -> claim/invoice generated -> payer review -> payment received -> denials handled -> final settlement and closure

# 7. Key Business Rules and Validations

Here are critical enterprise rules.

## 15 Important Business Rules

1. **A patient must have a unique identity record**
    
    - Duplicate patient creation should be prevented or merged through controlled process.
2. **No inpatient admission without a valid admission order**
    
    - Except defined emergency override cases.
3. **A bed cannot be assigned if its status is not available**
    
    - Beds under cleaning, maintenance, isolation restriction, or occupied cannot be allocated.
4. **A doctor cannot prescribe a drug that is documented as an allergy for the patient**
    
    - Override only with documented clinical justification and approval policy.
5. **A doctor cannot prescribe or a pharmacist cannot dispense an out-of-stock medicine**
    
    - Alternative medicine or backorder/substitution workflow must be used.
6. **Expired or expiring-today medicines must not be dispensed if policy prohibits same-day use**
    
    - Pharmacy must enforce expiry control based on institution policy.
7. **A lab test cannot be resulted before sample collection and processing are recorded**
    
    - Prevents false result release.
8. **Critical lab/radiology results must trigger immediate escalation**
    
    - Notification to responsible clinician/nurse and acknowledgment tracking required.
9. **No service should be billed without a valid order or authorized manual charge entry**
    
    - Prevents revenue leakage and fraudulent billing.
10. **Canceled services must not remain on final patient bill**
    

- If already billed, reversal/credit note process must occur.

11. **A patient cannot be discharged until medical clearance is complete**

- Discharge summary, final orders, and required instructions must exist.

12. **A patient cannot be financially closed if unresolved billable items remain**

- Pending medicine issue, unposted procedure, unbilled room charge, or unprocessed returns must be settled.

13. **Insurance-covered services requiring authorization cannot proceed as cashless without approval**

- If done in emergency, must follow emergency exception rules.

14. **Controlled drugs require stricter dispensing, administration, and reconciliation**

- Double verification, usage log, and wastage tracking required.

15. **Every stock-affecting transaction must be traceable**

- Receipt, transfer, dispense, consumption, adjustment, return, expiry, and disposal must be auditable.

Additional important rules:

16. **Doctor consultation cannot start unless patient is checked in or marked arrived**, except emergency/override cases.
    
17. **Operating room/surgery cannot proceed without required consents, pre-op checklist, and essential resource readiness**, unless life-saving emergency.
    
18. **Corporate and insurance tariffs override standard tariffs where contract exists**.
    
19. **Discounts above threshold require approval by authorized role**.
    
20. **No payroll processing for inactive or unapproved attendance records**, except approved adjustments.

# 9. State Machines / Lifecycle Statuses

These are “life journeys” of important hospital entities.

---

## 9.1 Appointment Lifecycle

Requested -> Pending Confirmation -> Confirmed -> Arrived -> Waiting -> In Consultation -> Completed

Possible alternate paths:

- Pending -> Cancelled
- Confirmed -> No Show
- Confirmed -> Rescheduled
- Arrived -> Left Without Consultation
- In Consultation -> Referred
- In Consultation -> Admitted

---

## 9.2 Patient Encounter Lifecycle

Registered -> Checked In -> Active Consultation/Treatment -> Orders In Progress -> Completed -> Closed

Alternate:

- Registered -> Cancelled
- Active -> Converted to Admission
- Active -> Referred Out

---

## 9.3 Admission Lifecycle

Admission Requested -> Financial/Administrative Review -> Bed Reserved -> Admitted -> Under Treatment -> Discharge Planned -> Medical Clearance -> Financial Clearance -> Discharged -> Closed

Alternate:

- Requested -> Cancelled
- Admitted -> Transferred
- Admitted -> Absconded
- Admitted -> Death
- Admitted -> Referred Out

---

## 9.4 Bed Lifecycle

Available -> Reserved -> Occupied -> Vacated -> Cleaning Pending -> Cleaned/Ready -> Available

Alternate:

- Available -> Maintenance Hold
- Occupied -> Blocked
- Cleaning Pending -> Maintenance Required
- Maintenance Hold -> Available

---

## 9.5 Prescription Lifecycle

Draft -> Submitted -> Pharmacist Review -> Approved -> Partially Dispensed / Fully Dispensed -> Administered / Collected -> Completed

Alternate:

- Draft -> Cancelled
- Submitted -> Rejected/Clarification Needed
- Dispensed -> Returned

# 10. Edge Cases and Exception Handling

These are very important because real hospitals are messy.

---

## 10.1 Emergency patient arrives without money

Business handling:

- Immediate life-saving care starts
- Temporary registration may be created
- Financial class marked as emergency pending
- Social service/administration informed if needed
- Deposit may be waived/deferred by policy
- Identity and payer details collected later
- Billing continues in background
- If patient remains admitted, normal financial workflow resumes later

**Rule:** Clinical stabilization first for true emergency.

---

## 10.2 Insurance claim is rejected

What happens:

- Rejection reason reviewed
- Check if documentation missing, authorization absent, non-covered service, coding mismatch, policy expired, late submission
- If correctable -> resubmit/appeal
- If partially payable -> insurer amount posted, remaining transferred to patient/corporate if contract allows
- If not recoverable -> write-off approval or patient collection action
- Denial trends monitored for process improvement

---

## 10.3 Prescribed medicine expires today

Business handling depends on hospital policy:

- If policy forbids same-day expiry dispensing -> block dispense
- Pharmacist must choose alternate batch or substitute
- If no alternate stock -> notify doctor for replacement medicine
- Expiring stock may be quarantined or prioritized for immediate in-hospital use only if policy and safety allow

Best practice: do not dispense to take-home patient if expiring today.

---

## 10.4 Unknown unconscious patient arrives

- Temporary emergency patient ID created
- Minimal demographic placeholder used
- Clinical care starts immediately
- Photo / physical identifiers may be recorded
- Later merge with real identity when confirmed
- Audit must preserve identity merge history

---

## 10.5 Duplicate patient records discovered

- Do not simply delete one
- Initiate merge request
- Verify identity with strict rules
- Merge clinical and financial records under governance
- Keep audit trail of original identifiers

---

## 10.6 Doctor orders test but patient leaves

- If sample not collected / service not performed -> cancel order and reverse unearned charge
- If sample collected but patient leaves -> test may still proceed depending on sample viability and payment rules
- Result can be released through portal/call center if appropriate

---

## 10.7 Patient dies during admission

- Death workflow activated
- Clinical documentation completed
- Bed released after protocol
- Mortuary/medico-legal process if required
- Final billing adjusted according to death policies
- Death certificate workflow handled
- Claims and reporting proceed under special rules

---

## 10.8 Medication dispensed but not administered

- Unused dose may be returned if policy allows and chain-of-custody valid
- Bill may be reversed fully/partially depending on dispense/admin charging rule
- Controlled drugs require stricter wastage documentation

---

## 10.9 Bed assigned but patient never arrives

- Reservation expiry time applies
- If patient not admitted within hold window, bed returns to available
- Admission request can remain pending or cancel

---

## 10.10 Equipment received but damaged

- Goods receipt marked discrepancy
- Stock not made available
- Vendor informed
- Replacement/return initiated
- AP payment held until resolution if policy allows

---

## 10.11 Lab sample hemolyzed / unsuitable

- Test status changed to sample rejected
- Recollection requested
- Billing decision depends on policy:
    - No charge if collection/lab fault
    - Charge may stand if patient-caused repeat not applicable, though usually recollection is not separately charged unless policy says so

---

## 10.12 Corporate patient uses non-entitled room category

- System applies room differential charge
- Corporate coverage calculated only up to entitlement
- Extra amount billed to patient or sponsoring company depending contract

---

## 10.13 Network or payment gateway issue during bKash/Nagad payment

- Bill stays unpaid until payment confirmation received
- Temporary pending payment status used
- Service should not be financially closed until reconciliation
- If amount debited but not acknowledged, exception reconciliation process required

---

## 10.14 Housekeeping marks bed clean but maintenance issue exists

- Bed should move to maintenance hold, not available
- Cleaning completion alone is not enough if room is unsafe/unusable

---

## 10.15 Doctor unavailable after appointment confirmation

- Appointment rescheduled, reassigned, or canceled
- Patient informed
- Fee differences adjusted
- Priority rebooking offered for inconvenience if policy allows

# 11. Cross-Module Mandatory Business Controls

These controls must exist across the whole ERP:

1. **Maker-checker control**
    
    - One user creates, another approves high-risk actions.
2. **Audit trail**
    
    - Every critical change must be traceable.
3. **Status-based action control**
    
    - Closed, canceled, verified, and discharged records must not be freely editable.
4. **Financial traceability**
    
    - Every revenue and expense item must have source origin.
5. **Patient safety alerts**
    
    - Allergy, infection risk, critical result, and isolation flags must be visible.
6. **Branch and payer applicability**
    
    - Tariffs, rules, and entitlements may vary by branch and payer.
7. **Time stamping**
    
    - Admission, transfer, discharge, billing, administration, and reporting all depend on time.
8. **Exception logging**
    
    - Emergency overrides must be captured and reviewed.

# PART 1: FULL BUSINESS RULES CATALOG

## 1. Enterprise-Wide Global Rules

These rules apply everywhere.

### 1.1 Patient Identity Rules

1. Every patient must have one primary enterprise identity.
2. Duplicate patient creation should be prevented as much as possible.
3. If duplicate records are found, they must be merged only through controlled approval.
4. Emergency unidentified patients may be registered with temporary identity.
5. Temporary identities must later be reconciled or merged when true identity is known.
6. Sensitive identity changes must be auditable.
7. A patient’s clinical, billing, and service records must always remain linked to the same identity trail.

### 1.2 Encounter Rules

8. Every clinical service must belong to a valid encounter or approved emergency event.
9. One patient may have multiple encounters, but each encounter must have one clear status.
10. Closed encounters should not allow unrestricted changes.
11. If post-closure correction is needed, it must happen through controlled amendment.

### 1.3 Branch / Multi-Tenant Rules

12. Users should only access branches or tenants they are authorized for.
13. Branch-specific tariffs, inventory, and contracts must follow local rules unless enterprise rules override them.
14. Patient continuity across branches should follow hospital policy and consent rules.
15. Consolidated reporting may combine branches, but operational control remains branch-specific.

### 1.4 Audit and Control Rules

16. Every critical change must be traceable.
17. High-risk actions must not be self-approved.
18. Deleted or corrected critical records must preserve an audit trail.
19. Emergency overrides must be specially flagged and reviewed.
20. Finalized financial and clinical records must not be silently edited.

---

## 2. Patient Management Rules

1. Search for an existing patient must happen before new registration.
2. Mandatory registration fields depend on policy and service type.
3. Guardian information is required for minors, unconscious patients, or dependent adults as per policy.
4. Contact details must be maintained for communication and billing follow-up.
5. VIP/confidential patients must have restricted visibility.
6. Deceased patients must be marked appropriately to prevent new routine registration misuse.
7. Patient merge must preserve all historical clinical and financial records.
8. Alert tags like allergy, infection risk, violence risk, or medico-legal flag must be visible across care points.

## 3. Appointment Management Rules

1. Appointment slots must follow doctor schedule availability.
2. Overbooking is allowed only where policy permits.
3. A canceled slot becomes reusable unless blocked by policy.
4. Repeated no-shows may trigger special booking restrictions if hospital policy defines this.
5. Follow-up appointments may use different tariff and validity rules than new visits.
6. Telemedicine appointments must be booked only for visit types allowed by regulation and hospital policy.
7. Appointment confirmation should depend on required payment or payer approval where applicable.
8. A patient marked arrived should enter queue flow.
9. A patient marked no-show should not remain in active queue.

## 4. Queue Management Rules

1. Every active queue token must belong to a valid appointment or walk-in visit.
2. Priority queue logic may override standard sequence for emergency, senior citizens, VIP, disability, or policy-defined categories.
3. Missed tokens may be recalled according to queue policy.
4. Queue status must reflect real patient stage: waiting, called, in consultation, completed, skipped.
5. One patient should not occupy multiple active queue positions for the same service unless specifically allowed.
6. Emergency patients may bypass the standard queue.

## 5. OPD Rules

2. Doctor consultation must be linked to a valid encounter.
3. Consultation note must include minimum mandatory medical documentation as per policy.

5. Consultation may end in:
    - Completed OPD visit
    - Follow-up advice
    - Referred consultation
    - Admission
    - Emergency referral
6. Charges should reflect actual completed services.
7. If patient leaves before consultation, consultation fee policy must determine whether charge applies.

    - Availability

    - Isolation rules
    - Specialty suitability
    - Equipment support requirement

6. A patient cannot occupy more than one active bed at the same time.
7. Discharge requires medical clearance.

9. Discharge summary should be completed before closure.
10. Absconded, expired, referred out, and discharged cases must follow separate closure rules.

# # PART 4: KPI DEFINITION PRINCIPLES

To avoid confusion, every KPI should have:

1. **Name**
2. **Business definition**
3. **Calculation logic**
4. **Inclusion / exclusion**
5. **Frequency**
6. **Owner**
7. **Action threshold**
8. **Escalation rule**

Example:

### KPI: Bed Occupancy %

- Meaning: How full the hospital is
- Logic: Occupied beds / available staffed beds
- Exclude: blocked maintenance beds if policy excludes them
- Frequency: hourly/daily
- Owner: operations head
- Threshold: >90% triggers capacity review

- print visit documents

### SOP Flow

-> search existing patient record  
-> if found, confirm identity  
-> if not found, create patient profile  
-> capture payer category  
-> verify appointment or create walk-in visit  
-> collect registration/consultation fee if applicable  
-> generate token / encounter slip  
-> direct patient to queue or department

### Mandatory Checks

- mobile number captured
- payer type captured

### Documents / Outputs

- appointment slip
- token
- payment receipt
- visit label/card if used

### Exceptions

- unconscious patient -> temporary emergency registration
- duplicate found -> raise merge request
- appointment doctor absent -> reschedule/escalate

# PART 1: BUSINESS REQUIREMENT TRACEABILITY MATRIX

A traceability matrix answers this simple question:

**For each business process, what is the related module, actor, rule, document, output, KPI, and exception?**

This helps ensure:

- nothing is missed
- every workflow has ownership
- every rule is testable
- every document is accounted for
- every KPI can be traced to operations

I will provide it in a business-friendly structure.

## 1. Traceability Matrix Structure

For each line item, we map:

- Business Process
- Module
- Trigger
- Primary Actor
- Key Business Rule
- Required Document/Register
- Expected Output
- Related KPI
- Common Exception
- Approval Need

## High-Risk Business Items

### 1. Duplicate patient creation

- Risk: fragmented clinical history and billing confusion
- Mitigation: strict duplicate search process

### 2. Incorrect tariff or contract setup

- Risk: revenue leakage or patient dispute
- Mitigation: tariff validation workshops and UAT

### 3. Incomplete discharge workflow

- Risk: delayed patient exit and missing charges
- Mitigation: discharge scenario testing

### 4. Poor insurance rule setup

- Risk: claim denial increase
- Mitigation: insurer-wise rule validation

### 5. Medicine/item master quality issues

- Risk: stock, dispense, and billing errors
- Mitigation: master data cleansing

### 6. User role mistakes

- Risk: security breach or workflow blockage
- Mitigation: role-based testing by department

### 7. Untrained staff

- Risk: operational slowdown and patient dissatisfaction
- Mitigation: role-based training and floor support

### 8. Opening stock inaccuracy

- Risk: wrong inventory and procurement disruption
- Mitigation: physical stock verification

### 9. Incomplete approval matrix

- Risk: process gets stuck
- Mitigation: approval owner mapping

### 10. Weak cutover planning

- Risk: service disruption
- Mitigation: detailed go-live and fallback plan
