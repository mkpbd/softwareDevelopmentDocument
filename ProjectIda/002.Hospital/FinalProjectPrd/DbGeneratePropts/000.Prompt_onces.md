## 📊 ANALYSIS SCOPE

Analyze the following aspects with deep technical insight:

### 1. SCHEMA DESIGN QUALITY (Score: /10)
- **Normalization**: Assess the normalization level (1NF, 2NF, 3NF, BCNF). Are there any 
  denormalization patterns and are they justified?
- **Data Integrity**: Evaluate foreign key relationships, constraints, check constraints, 
  and referential integrity
- **Entity Relationships**: Are relationships (1:1, 1:M, M:M) correctly modeled?
- **Table Granularity**: Is each table focused on a single responsibility?
- **Attribute Design**: Are data types appropriate? Are nullable fields correctly identified?

### 2. NAMING CONVENTIONS & STANDARDS (Score: /10)
- Consistency in naming (snake_case, prefixes, suffixes)
- Primary Key naming (`<table>_id`)
- Foreign Key naming (`<referenced_table>_id`)
- Index, constraint, and object naming standards
- Schema naming and logical grouping

### 3. PERFORMANCE & SCALABILITY (Score: /10)
- **Indexing Strategy**: Are indexes properly designed? Missing indexes? Over-indexing?
- **Partitioning**: Is partitioning used for large tables (audit logs, transactions)?
- **Query Optimization**: Are there computed columns, materialized views where needed?
- **Data Types**: Are data types optimized for storage and performance?
- **Expected Volume Handling**: Can this design handle millions of records?

### 4. SECURITY & COMPLIANCE (Score: /10)
- **Row-Level Security (RLS)**: Is RLS implemented for multi-tenancy?
- **Audit Trail**: Is there comprehensive audit logging?
- **PHI/PII Protection**: Are sensitive fields encrypted or masked?
- **Access Control**: Are roles and permissions properly designed?
- **HIPAA/Healthcare Compliance**: Does it meet healthcare data regulations?

### 5. MULTI-TENANCY ARCHITECTURE (Score: /10)
- **Tenant Isolation**: How is tenant data isolated?
- **Shared Schema Approach**: Is the multi-tenant strategy correct?
- **Performance Impact**: Will tenant filtering affect query performance?
- **Data Segregation**: Are branch-level and department-level restrictions in place?

### 6. BUSINESS LOGIC IMPLEMENTATION (Score: /10)
- **Triggers**: Are triggers used appropriately? Any performance concerns?
- **Stored Procedures**: Are complex workflows handled at DB level?
- **Functions**: Are reusable functions properly designed?
- **Constraints**: Are business rules enforced via constraints?

### 7. DATA CONSISTENCY & TRANSACTIONS (Score: /10)
- **ACID Compliance**: Are transactions properly handled?
- **Concurrency**: Are there potential deadlock scenarios?
- **Soft Deletes**: Is soft delete pattern correctly implemented?
- **Versioning**: Are clinical records versioned for audit purposes?

### 8. MODULE COMPLETENESS (Score: /10)

- Patient Management (Registration, Demographics, Insurance)

- CRM & Feedback
- Notifications & Alerts
- Document Management
- Compliance & Legal (Consent, MLC)

### 9. ERD RELATIONSHIP QUALITY (Score: /10)
- **Visual Clarity**: Is the ERD easy to understand?
- **Relationship Cardinality**: Are all relationships correctly marked?
- **Junction Tables**: Are many-to-many relationships properly handled?
- **Dependent Tables**: Are child tables correctly linked to parents?

### 10. POSTGRESQL BEST PRACTICES (Score: /10)
- Use of PostgreSQL-specific features (JSONB, Arrays, Enums, Partitioning)
- Extension usage (uuid-ossp, pgcrypto, pg_trgm)
- Materialized views for reporting
- Generated columns usage
- Proper use of schemas for logical separation
