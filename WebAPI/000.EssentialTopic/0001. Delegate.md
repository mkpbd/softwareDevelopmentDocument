

Delegate জিনিসটা C# এ নতুনেরা দেখলে একটু ভয় পায়, কিন্তু আসলে এটা পানির মতো সোজা। আসেন একদম খাঁটি বাংলায়, একটু ফানি ও মাস্তানি স্টাইলে বুঝি।

### Delegate কি? (The Definition)

সহজ কথায়: **Delegate হলো ফাংশনের "দালাল" বা "মিডিয়া" (Middleman)।**

আমরা সাধারণত ভেরিয়েবলের মধ্যে Data রাখি (যেমন: `int a = 10;`)।
আর Delegate এমন এক ধরণের ভেরিয়েবল যার মধ্যে আমরা কোনো **Data রাখি না**, বরং **একটা ফাংশন (Function/Method) ঢুকিয়ে রাখি।**

---

### রিয়েল লাইফ উদাহরণ: "এলাকার বড় ভাই ও তার চামচা"

ধরেন, আপনি এলাকার **"গডফাদার" (Main Program)**। আপনার অনেক শত্রু। এখন আপনি তো আর নিজে গিয়ে সবাইকে মারবেন না, আপনার প্রেস্টিজ ইস্যু আছে। আপনার একজন **"চামচা" (Delegate)** আছে, যার নাম "বল্টু"।

আপনি বল্টুকে বললেন: **"অ্যাকশন নে!"**

এখন এই "অ্যাকশন" মানে কি? এটা সিচুয়েশন অনুযায়ী চেঞ্জ হতে পারে:
1.  কখনো অ্যাকশন মানে = **"থাপ্পড় দে"** (Method 1)
2.  কখনো অ্যাকশন মানে = **"লাথি দে"** (Method 2)
3.  কখনো অ্যাকশন মানে = **"সরি বল"** (Method 3)

বল্টু (Delegate) নিজে কিছু করে না, আপনি তার ভেতরে যেই ইনস্ট্রাকশন (Method) লোড করে দেবেন, সে সেটাই এক্সিকিউট করবে।

### কোড দিয়ে বুঝি (Code Analogy)

#### ১. Delegate ডিক্লেয়ার করা (চামচাকে নিয়োগ দেওয়া)
প্রথমে আমরা ঠিক করবো চামচার যোগ্যতা কি হবে। ধরেন আমাদের চামচার কাজ হলো কাউকে ধোলাই দেওয়া।

```csharp
// এটা হলো দলিলে সই করা। 
// void মানে সে কোনো টাকা ফেরত আনবে না, শুধু পিটান দিয়ে আসবে।
// string name মানে সে কারো নাম নিয়ে তাকে পিটাবে।
public delegate void AttackDelegate(string enemyName);
```

#### ২. মেথড বা ফাংশন রেডি করা (মারামারি টেকনিক)
এখন আমাদের দুইটা মারার স্টাইল আছে।

```csharp
public void Slap(string name)
{
    Console.WriteLine(name + "-কে কানের নিচে থাপ্পড় দেওয়া হলো!");
}

public void Kick(string name)
{
    Console.WriteLine(name + "-কে উষ্ঠা মারা হলো!");
}
```

#### ৩. মেইন প্রোগ্রামে ব্যবহার (অ্যাকশন শুরু)

```csharp
public void GodfatherOrders()
{
    // ১. বল্টুকে ডাকলাম (Delegate Instance)
    AttackDelegate boltu;

    // ২. বল্টুকে বললাম, "আজকে শুধু থাপ্পড় দিবি" (Method Assign)
    boltu = Slap;
    
    // ৩. বল্টু অ্যাকশন নিল (Invoke)
    boltu("কুদ্দুস"); 
    // আউটপুট: কুদ্দুস-কে কানের নিচে থাপ্পড় দেওয়া হলো!

    // ৪. পরদিন মুড খারাপ, বললাম "আজকে লাথি দিবি" (Re-assign)
    boltu = Kick;
    
    // ৫. আবার অ্যাকশন
    boltu("কুদ্দুস");
    // আউটপুট: কুদ্দুস-কে উষ্ঠা মারা হলো!
}
```

### তাহলে লাভটা কি হলো? (Why use it?)

আপনি বলতে পারেন, *"ভাই, আমি তো ডাইরেক্ট `Slap("কুদ্দুস")` কল করলেই পারতাম, মাঝখানে বল্টুর (Delegate) কি দরকার?"*

দরকার আছে!
ধরেন আপনার Blazor কোডে একটা বাটন আছে। বাটনের কোড জানে না ইউজার ক্লিক করলে কি হবে। সেভ হবে? নাকি ডিলিট হবে? নাকি নাচবে?
বাটন শুধু জানে তার একটা `OnClick` ডেলিগেট আছে।
আপনি (ডেভেলপার) রানটাইমে ঠিক করে দেন—"এই পেজে ক্লিক করলে সেভ করো, ওই পেজে ক্লিক করলে ডিলিট করো"।

অর্থাৎ, **Calling Code (গডফাদার)** এবং **Target Method (মারার স্টাইল)** এর মধ্যে সরাসরি সম্পর্ক না রেখে মাঝখানে একটা লেয়ার রাখা।

### বোনাস: Multicast Delegate (গ্যাং তৈরি করা)

Delegate এর একটা জাদুকরী ক্ষমতা আছে। এক বল্টুর ঘাড়ে একসাথে অনেকগুলো কাজ চাপানো যায়।

```csharp
boltu = Slap;
boltu += Kick; // += দিয়ে আরো কাজ যোগ করা যায়

boltu("মফিজ");
```
**আউটপুট হবে:**
1. মফিজ থাপ্পড় খাবে।
2. **সাথে সাথে** মফিজ লাথিও খাবে।

এক কলেই সব কাজ খতম!

### সারাংশ (Summary)
**Delegate** হলো এমন এক ফাজিল ভেরিয়েবল, যে ভ্যালু ধরে রাখে না, ফাংশন ধরে রাখে। যখন খুশি তাকে দিয়ে ফাংশনটা কল করানো যায়।

### উদাহরণ ১: টং-এর দোকান ও পেমেন্ট সিস্টেম (Passing Method as Parameter)

ধরেন, আপনি টং-এ চা খেয়েছেন। মামা আপনাকে বলল, **"বিল দেন"**।
এখন বিল দেওয়ার অনেক উপায় আছে: **ক্যাশ**, **বিকাশ**, অথবা **বাকির খাতা**।

মামা (Main Method) জানে না আপনি কিভাবে টাকা দিবেন। মামা শুধু একটা **Delegate** ব্যবহার করবে যার নাম `PaymentHandler`।

**১. ডেলিগেট এবং মেথড রেডি করা:**
```csharp
// ডেলিগেট: এটা হলো পেমেন্ট নেওয়ার নিয়ম
public delegate void PaymentHandler(int amount);

// অপশন ১: ক্যাশ টাকা
public void PayCash(int taka)
{
    Console.WriteLine($"মামা, এই নেন {taka} টাকা ক্যাশ।");
}

// অপশন ২: বিকাশ
public void PayBkash(int taka)
{
    Console.WriteLine($"মামা, {taka} টাকা সেন্ড মানি করে দিছি। চেক করেন।");
}

// অপশন ৩: বাকি (সবচেয়ে জনপ্রিয়)
public void PayBaki(int taka)
{
    Console.WriteLine($"মামা, {taka} টাকা খাতায় লিখে রাখেন। পরে দিমুনে!");
}
```

**২. মামার লজিক (The Method that uses Delegate):**
মামা একটা ফাংশন বানাল যেটা প্যারামিটার হিসেবে ওই ডেলিগেট (পেমেন্ট মেথড) গ্রহণ করে।

```csharp
public void TakeBill(int billAmount, PaymentHandler paymentMethod)
{
    Console.WriteLine("--- বিল কালেকশন শুরু ---");
    
    // মামা কিন্তু জানে না মেথডটা কি (Cash? Bkash? Baki?)
    // সে শুধু মেথডটা কল করে দিল
    paymentMethod(billAmount);
    
    Console.WriteLine("--- লেনদেন শেষ ---");
}
```

**৩. ব্যবহারের পালা:**
```csharp
// মাসের শুরু (পকেটে টাকা আছে) -> ক্যাশ পেমেন্ট পাঠালাম
TakeBill(50, PayCash); 

// মাসের মাঝখনে -> বিকাশ পেমেন্ট পাঠালাম
TakeBill(100, PayBkash);

// মাসের শেষ (পকেট ফাঁকা) -> বাকি পেমেন্ট মেথড পাঠালাম
TakeBill(20, PayBaki);
```

**মজাটা বুঝলেন?** `TakeBill` ফাংশনের কোড চেঞ্জ না করেই আমরা বাইরে থেকে বলে দিচ্ছি পেমেন্ট কিভাবে হবে। এটাই ডেলিগেটের পাওয়ার!

### উদাহরণ ২: ঘটক পাখি ভাই (Filtering Logic)

ধরেন আপনি একজন ঘটক। আপনার কাছে ১০০টা বায়োডাটা (List) আছে। এখন ক্লায়েন্ট এসে একেক সময় একেক ডিমান্ড দেয়।
*   কেউ চায়: **"শুধু সরকারি চাকরিজীবী"**
*   কেউ চায়: **"শুধু লম্বা মানুষ"**

আপনি কি প্রতিবার নতুন করে লুপ বা ফাংশন লিখবেন? না! আপনি একটা ডেলিগেট বানাবেন যার নাম `CheckCriteria`।

**১. সেটআপ:**
```csharp
// ডেলিগেট: এটা একটা কন্ডিশন চেক করবে এবং True/False রিটার্ন করবে
public delegate bool GhotokCriteria(Person person);

public class Person 
{ 
    public string Name { get; set; } 
    public string Job { get; set; } 
    public int Height { get; set; } 
}
```

**২. ঘটকের সার্চ ফাংশন:**
```csharp
public void FindMatch(List<Person> people, GhotokCriteria criteria)
{
    foreach(var p in people)
    {
        // এখানে আমরা ডেলিগেট দিয়ে চেক করছি
        if(criteria(p) == true)
        {
            Console.WriteLine($"পাত্র পাওয়া গেছে: {p.Name}");
        }
    }
}
```

**৩. আসল খেলা (Lambda Expression - শর্টকাট):**
আগের উদাহরণে আমরা আলাদা `void PayCash` মেথড বানিয়েছিলাম। কিন্তু আধুনিক C#-এ আমরা অতো কষ্ট করি না। আমরা **Lambda Expression (=>)** দিয়ে অন-দ্য-স্পট ফাংশন বানিয়ে ফেলি। এটাকে বলে **"ইনস্ট্যান্ট নুডলস"** মেথড।

```csharp
List<Person> biodataList =GetPeople(); // ধরি এখানে অনেক মানুষ আছে

// ক্লায়েন্ট ১: সরকারি চাকরিজীবী চাই
// (p => p.Job == "Govt") -> এটাই সেই ইনস্ট্যান্ট ডেলিগেট মেথড
FindMatch(biodataList, p => p.Job == "Govt");

// ক্লায়েন্ট ২: লম্বা মানুষ চাই (Height > 5.8)
FindMatch(biodataList, p => p.Height > 5.8);
```

**Note:** আপনার Blazor কোডে `x => x.Id == model.Id` দেখেছেন? ওটা আসলে এই ঘটক পাখি ভাইয়ের ডেলিগেট প্যাটার্নই ব্যবহার করছে! `FirstOrDefault` ফাংশনটা একটা ডেলিগেট ডিমান্ড করে, আর আপনি =>`দিয়ে সেটা সাপ্লাই দিচ্ছেন।

### উদাহরণ ৩: Action এবং Func (রেডিমেড মশলা)

C# ডেভেলপাররা দেখল, আরে বারবার `public delegate void ...` এভাবে কাস্টম ডেলিগেট বানানো তো বোরিং। তাই তারা দুইটা রেডিমেড প্যাকেট মশলা বাজারে ছাড়লো: `Action` আর `Func`।

১. **Action:** যদি আপনার ফাংশন কিছু রিটার্ন না করে (void হয়)।
   *   *উদাহরণ:* কাউকে গালি দেওয়া (রিটার্ন পাওয়ার আশা নাই)।
   
2. **Func:** যদি আপনার ফাংশন কিছু রিটার্ন করে (int, bool, string ইত্যাদি)।
   *   *উদাহরণ:* দোকানদারের কাছে দাম জিজ্ঞেস করা (সে দাম রিটার্ন করবে)।

**আপনার Blazor কোডে দেখেন:**
```csharp
[Parameter]
public Action<object> SelectedItemChanged { get; set; }
```
এখানে `Action<object>` মানে হলো:
*"ভাই, আমি এমন একটা মেথড চাই যেটা একটা `object` ইনপুট নিবে, কিন্তু কোনো কিছু রিটার্ন করবে না (void)।"*

এজন্যই শুরুতে এরর আসছিল, কারণ আপনার `HandleSelectionChanged` মেথডটা কোনো ইনপুট নিচ্ছিল না, কিন্তু `Action<object>` ডিমান্ড করছিল একটা ইনপুট।

### সারমর্ম
*   **Delegate:** ফাংশন রাখার পাত্র।
*   **Parameter হিসেবে:** মেথডকে অন্য মেথডের পেটে ঢুকিয়ে দেওয়া যায়।
*   **Lambda (=>):** নাম ছাড়া ইনস্ট্যান্ট ডেলিগেট বানানো।
*   **Action/Func:** মাইক্রোসফটের দেওয়া রেডিমেড ডেলিগেট।

### উদাহরণ ৪: ফেইসবুক স্ট্যাটাস ও হরেক রকম রিয়েকশন (Multicast Delegate)

ধরেন আপনি ফেইসবুকে একটা স্ট্যাটাস দিলেন: **"আজকে অনেক বৃষ্টি, মনটা উদাস! 🌧️"**
এখন এই এক স্ট্যাটাসে একেকজন একেকভাবে রিয়েক্ট করবে।
*   **গার্লফ্রেন্ড:** লাভ রিয়েক্ট দিবে ❤️।
*   **হিংসুটে বন্ধু:** হা-হা রিয়েক্ট দিবে 😂।
*   **পাড়ার আন্টি:** কমেন্ট করবে "বাবা, পড়াশোনা করো" 😒।

এই যে **"এক ঘটনা, কিন্তু রিয়েকশন অনেকগুলো"**—এটা হ্যান্ডেল করার জন্য আমরা **Multicast Delegate** ব্যবহার করি।

**১. ডেলিগেট ডিক্লেয়ার:**
```csharp
// ডেলিগেট: স্ট্যাটাস দেখলে কি করবে
public delegate void ReactionHandler(string status);
```

**২. রিয়েকশন মেথডগুলো (Methods):**
```csharp
public void GirlfriendReact(string msg)
{
    Console.WriteLine("GF: ❤️❤️❤️ (Love React)");
}

public void HaterFriendReact(string msg)
{
    Console.WriteLine("Friend: 😂😂😂 হাহাহা, তোর আবার মন!");
}

public void AuntyReact(string msg)
{
    Console.WriteLine("Aunty: ফেসবুকে ঢং না করে পড়তে বস! 😒");
}
```

**৩. এখন মাল্টিকাস্টিং-এর খেলা (Chaining):**
```csharp
public void PostStatus()
{
    // ১. প্রথমে ডেলিগেট বানালাম
    ReactionHandler postReaction;

    // ২. সবাইকে সাবস্ক্রাইব করালাম (+= দিয়ে যোগ করা)
    postReaction = GirlfriendReact; // প্রথমে GF দেখল
    postReaction += HaterFriendReact; // তারপর বন্ধু দেখল
    postReaction += AuntyReact; // শেষে আন্টিও দেখে ফেলল

    // ৩. স্ট্যাটাস পোস্ট করলাম (একবার কল করবো, সবাই কাজ করবে)
    Console.WriteLine("--- স্ট্যাটাস আপলোড হলো ---");
    postReaction("আজকে অনেক বৃষ্টি..."); 

    /* আউটপুট হবে:
       GF: ❤️❤️❤️ (Love React)
       Friend: 😂😂😂 হাহাহা, তোর আবার মন!
       Aunty: ফেসবুকে ঢং না করে পড়তে বস! 😒
    */
    
    // ৪. আন্টিকে ব্লক মারলে কি হবে? (-= দিয়ে বাদ দেওয়া)
    Console.WriteLine("\n--- আন্টিকে ব্লক মারার পর ---");
    postReaction -= AuntyReact; 
    
    postReaction("আজকে বিরিয়ানি খাব");
    // এখন শুধু GF আর Friend রিয়েক্ট দিবে, আন্টি আর দেখবে না।
}
```

### উদাহরণ ৫: দর্জি এবং কলব্যাক (Callback Delegate)

ধরেন আপনি ঈদের সময় দর্জির দোকানে প্যান্ট বানাতে দিলেন। দর্জি বলল, **"ভাই রেডি হতে ৭ দিন লাগবে।"**
আপনি কি ৭ দিন দর্জির দোকানের সামনে দাঁড়িয়ে থাকবেন? না!

আপনি দর্জিকে বললেন: **"ভাই, প্যান্ট রেডি হলে আমার এই নাম্বারে কল দিয়েন, আমি এসে নিয়ে যাব।"**
এখানে **"কল দেওয়া"**-টাই হলো ডেলিগেট বা **Callback**। আপনি দর্জিকে বলে আসছেন কাজ শেষ হলে *কোন মেথডটা* কল করতে হবে।

**১. ডেলিগেট (ইনস্ট্রাকশন):**
```csharp
// কাজ শেষে দর্জি কি করবে, সেটার নিয়ম
public delegate void AfterWorkFinished(string itemName);
```

**২. দর্জির কাজ (Worker Method):**
```csharp
// দর্জি 'callback' নামে একটা ডেলিগেট ইনপুট নিচ্ছে
public void TailorShopWork(string cloth, AfterWorkFinished callback)
{
    Console.WriteLine($"{cloth} বানানোর কাজ চলছে... (Waiting 7 Days)");
    
    // ... ৭ দিন পর কাজ শেষ ...
    
    Console.WriteLine("কাজ শেষ!");
    
    // দর্জি জানে না এরপর কি হবে, সে শুধু আপনার দেওয়া মেথডটা কল করে দিবে
    callback(cloth); 
}
```

**৩. আপনার প্ল্যান (Client Logic):**
আপনি একেক সময় একেক ইনস্ট্রাকশন দিতে পারেন।

```csharp
// প্ল্যান A: নিজে গিয়ে নিয়ে আসবো
public void GoAndPickUp(string item)
{
    Console.WriteLine($"ভাই দৌড় দিলাম! আমার {item} টা দিয়ে দেন।");
}

// প্ল্যান B: পাঠাও দিয়ে আনিয়ে নিব
public void SendPathao(string item)
{
    Console.WriteLine($"পাঠাও রাইডার পাঠাচ্ছি, {item} টা তাকে বুঝিয়ে দিন।");
}

// মেইন প্রোগ্রাম
public void EidShopping()
{
    // সিনারিও ১: আপনি ফ্রি আছেন
    // দর্জিকে বললেন: কাজ শেষ হলে 'GoAndPickUp' মেথড চালাবেন
    TailorShopWork("Panjabi", GoAndPickUp);
    
    // সিনারিও ২: আপনি ব্যস্ত
    // দর্জিকে বললেন: কাজ শেষ হলে 'SendPathao' মেথড চালাবেন
    TailorShopWork("Sherwani", SendPathao);
}
```

### কেন এটা Blazor-এ লাগে?
Blazor এ যখন আপনি কোনো ডাটা লোড করেন বা `StateHasChanged` কল করেন, তখন এই কনসেপ্টটাই কাজ করে।
যেমন: **"ডাটাবেস থেকে ডাটা আনা শেষ হলে (Tailor finished), পেজটা রিফ্রেশ করো (GoAndPickUp/StateHasChanged)।"**

আশা করি ডেলিগেট এখন আর ভয়ের কিছু মনে হচ্ছে না! 😄

এতক্ষণ আমরা হাত দিয়ে মশলা বেটে রান্না করলাম (Custom Delegate)। কিন্তু প্রতিদিন মশলা বাটা তো কষ্টের কাজ, তাই না?

Microsoft এই কষ্ট কমানোর জন্য **C#-এ ৩টা রেডিমেড (Built-in) প্যাকেট মশলা** দিয়ে দিয়েছে। এগুলো দিয়ে ৯৯% কাজ হয়ে যায়, নিজের আলাদা করে `delegate` কিওয়ার্ড লিখে ডিফাইন করা লাগে না।

সেই ৩টা রেডিমেড হিরো হলো:
1.  **Action** (যে শুধু কাজ করে, রিটার্ন দেয় না)
2.  **Func** (যে কাজ করে আবার ফলাফল রিটার্ন দেয়)
3.  **Predicate** (যে শুধু সত্য/মিথ্যা যাচাই করে)

আসেন এদের চিনে নিই একদম সহজ ভাষায়।

---

### ১. Action (দ্য সাইলেন্ট কিলার)
**কাজ:** এর কোনো রিটার্ন টাইপ নাই (`void`)। ইনপুট নিবে, কাজ করবে, চুপচাপ চলে যাবে।
**স্বভাব:** অনেকটা "কামলা" বা "বউয়ের অর্ডার" এর মতো। শুধু কাজ করো, কোনো কথা (Return) হবে না।

**Syntax:** `Action<InputType>`

```csharp
// আগে আমরা লিখতাম: public delegate void MyDelegate(string name);
// এখন লিখবো ডাইরেক্ট Action:

// ১. ডিফাইন করা (Action<string> মানে একটা স্ট্রিং ইনপুট নিবে)
Action<string> galiDewa = (name) => 
{
    Console.WriteLine($"ওই {name}, তুই একটা ফাজিল!");
};

// ২. কল করা
galiDewa("আবুল"); 
// আউটপুট: ওই আবুল, তুই একটা ফাজিল!
```
*আপনার Blazor কোডে `Action<object>` ছিল, মানে সে একটা object ইনপুট নিবে, কিন্তু কিছু রিটার্ন করবে না।*

---

### ২. Func (দ্য বিজনেসম্যান)
**কাজ:** এর রিটার্ন টাইপ আছে। ইনপুট নিবে, প্রোসেস করবে, এবং একটা রেজাল্ট ফেরত দিবে।
**স্বভাব:** দোকানের মতো। টাকা (Input) দিবেন, পণ্য (Return) পাবেন।

**Syntax:** `Func<Input1, Input2, ..., Result>`
*(মনে রাখবেন: একদম শেষেরটা হলো রেজাল্ট বা রিটার্ন টাইপ, আগেরগুলো ইনপুট)*

```csharp
// ১. ডিফাইন করা 
// Func<int, int, int> মানে:
// প্রথম int = ইনপুট ১
// দ্বিতীয় int = ইনপুট ২
// শেষ int = যেটা রিটার্ন করবে (ফলাফল)
Func<int, int, int> calculator = (x, y) => 
{
    return x + y; 
};

// ২. কল করা
int result = calculator(10, 20);
Console.WriteLine(result); // আউটপুট: 30
```

---

### ৩. Predicate (দ্য পুলিশ সার্জেন্ট)
**কাজ:** এটা ইনপুট নিবে এবং চেক করে শুধু `True` অথবা `False` রিটার্ন করবে।
**স্বভাব:** চেকপোস্টের পুলিশের মতো। কাগজ ঠিক আছে? (True), নাই? (False)। মামলা খাও!

**Syntax:** `Predicate<InputType>`

```csharp
// ১. ডিফাইন করা
// ইনপুট নিবে int, রিটার্ন করবে bool (অটোমেটিক)
Predicate<int> isAdult = (age) => 
{
    return age >= 18; // ১৮ বা তার বেশি হলে True
};

// ২. কল করা
bool canVote = isAdult(15); 
Console.WriteLine(canVote); // আউটপুট: False
```

*নোট: `Func<int, bool>` আর `Predicate<int>` আসলে একই কাজ করে। কিন্তু `List.FindAll` বা ফিল্টারিং-এর সময় মানুষ `Predicate` শব্দটা বেশি ব্যবহার করে।*

### এক নজরে পার্থক্য (Cheat Sheet)

| নাম | কাজ (Role) | রিটার্ন করে? | কখন ব্যবহার করবেন? |
| :--- | :--- | :--- | :--- |
| **Action** | কাজের লোক (Worker) | **না (void)** | যখন শুধু কিছু ঘটাতে চান (Print, Save, Log, Update UI)। |
| **Func** | ক্যালকুলেটর (Solver) | **হ্যাঁ (Any Type)** | যখন ক্যালকুলেশন করে কিছু ফেরত দরকার। |
| **Predicate** | চেকার (Guard) | **হ্যাঁ (Boolean)** | যখন ফিল্টার বা কন্ডিশন চেক করতে হয় (Search, Find)। |

### আপনার Blazor কোডের ব্যাখ্যা
আপনার কোডে ছিল:
```csharp
[Parameter]
public Action<object> SelectedItemChanged { get; set; }
```
এখন নিশ্চয়ই বুঝতে পারছেন কেন?
কারণ `SelectedItemChanged` ইভেন্টটা যখন কল হবে, সে আপনাকে সিলেক্ট করা আইটেমটা (object) পাঠিয়ে দিবে, কিন্তু আপনার কাছ থেকে কোনো রেজাল্ট আশা করবে না (void)। তাই এখানে `Func` না ব্যবহার করে `Action` ব্যবহার করা হয়েছে।
