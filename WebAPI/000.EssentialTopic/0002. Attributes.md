
হ্যালো ফিউচার .NET রকস্টাররা! 👋

কেমন আছেন সবাই? আমি আপনাদের সিনিয়র ডেভেলপার ভাই। আজকে আমরা C# এর এমন একটা টপিক শিখবো যেটা দেখে বিগিনাররা প্রায়ই ভয় পায়, কিন্তু আসলে এটা **পানির মতো সোজা**।

টপিকটা হলো: **Attributes**।

অনেকে কোডের ওপর `[]` ব্র্যাকেটের ভেতর অদ্ভুত সব শব্দ দেখে ভাবেন, "ইহা কী? ইহা কি এলিয়েনদের টেকনোলজি?" 👽

আরে না ভাই! রিল্যাক্স। আজকের পর থেকে Attributes হবে আপনার বেস্ট ফ্রেন্ড। চলুন, একদম আড্ডা দিতে দিতে শিখে ফেলি।

### ১. Attribute আসলে কী? (What is an Attribute?)

এক লাইনে সহজ বাংলা সংগা:
> **"Attribute হলো কোডের গায়ে লাগিয়ে দেওয়া একটা স্টিকার, ট্যাগ বা লেবেল।"**

টেকনিক্যাল ভাষায় একে বলে **Metadata** (ডেটা সম্পর্কে ডেটা)।

**কেন লাগে?**
আমাদের কোড (Class, Property, Method) আসলে কী কাজ করবে বা রানটাইমে (Runtime) তার সাথে কেমন আচরণ করা উচিত, সেটা কম্পাইলার বা ফ্রেমওয়ার্ককে জানিয়ে দেওয়ার জন্য Attribute ব্যবহার করা হয়।

**Attribute vs Normal Class:**
Attribute নিজেও একটা ক্লাস! তফাৎ হলো, এটা `System.Attribute` থেকে জন্ম নেয় (Inherit করে) এবং একে আমরা সরাসরি `new` করে অবজেক্ট বানাই না, বরং `[]` দিয়ে অন্য ক্লাসের মাথায় বসিয়ে দিই।

### ২. রিয়েল লাইফ উদাহরণ (Real-life Analogy) 📦

ধরুন আপনি দারাজ বা আমাজন থেকে একটা কাঁচের গ্লাস অর্ডার করেছেন।

১. **Product (Box):** এটা হলো আপনার **Class** বা **Code**।
২. **Product-এর কাজ:** পানি খাওয়া। এটা হলো আপনার **Method/Logic**।
৩. **Box-এর ওপর স্টিকার:** বাক্সের গায়ে লাল স্টিকার মারা থাকে **"FRAGILE" (Handle with care)**।

এই যে "Fragile" স্টিকারটা, এটা কিন্তু গ্লাস না, আবার বাক্সও না। এটা ডেলিভারি ম্যানকে (Runtime/Compiler) বলে দিচ্ছে—"ভাই, সাবধান! এটা আছাড় মারলে ভেঙে যাবে।"

C#-এ **Attribute** হলো ঠিক এই "Fragile" স্টিকারের মতো।

### ৩. বিল্ট-ইন অ্যাট্রিবিউটস (Built-in Attributes - Basic)

Microsoft আমাদের জন্য প্রচুর কাজের স্টিকার (Attributes) রেডি করে রেখেছে। চলুন কয়েকটা পপুলার স্টিকার দেখি।

#### ক) `[Obsolete]` - "ভাই এটা এক্সপায়ার্ড!"
যখন কোনো মেথড পুরাতন হয়ে যায় এবং আপনি চান না কেউ সেটা ব্যবহার করুক, তখন এটা লাগান।

```csharp
public class PaymentService
{
    // কম্পাইলার ওয়ার্নিং দিবে: "এই মেথড পুরাতন, নতুনটা ব্যবহার করেন।"
    [Obsolete("Use MakeNewPayment instead. This is too old!")]
    public void MakePayment()
    {
        Console.WriteLine("Old payment logic...");
    }

    public void MakeNewPayment()
    {
        Console.WriteLine("Super fast secure payment!");
    }
}
```

#### খ) Data Annotations (Entity, MVC, API-তে লাগে)
ডেটাবেসে সেভ করার আগে ভ্যালিডেশনের জন্য এগুলো জাদুর মতো কাজ করে।

```csharp
using System.ComponentModel.DataAnnotations;

public class UserProfile
{
    [Key] // এটা ডাটাবেসের প্রাইমারি কি (Primary Key)
    public int Id { get; set; }

    [Required(ErrorMessage = "ভাই নাম না দিলে হবে না!")] // নাম দিতেই হবে
    [StringLength(50, ErrorMessage = "নাম খুব বেশি বড় হয়ে গেছে!")] // ৫০ ক্যারেক্টারের বেশি হতে পারবে না
    public string Name { get; set; }

    [Range(18, 99, ErrorMessage = "বাচ্চাদের এখানে এলাউড না!")] // ১৮ থেকে ৯৯ এর মধ্যে হতে হবে
    public int Age { get; set; }

    [Display(Name = "Email Address")] // UI তে দেখানোর সময় সুন্দর নাম দেখাবে
    public string Email { get; set; }
}
```

### ৪. অ্যাট্রিবিউট কোথায় কোথায় লাগানো যায়? (Attribute Usage Levels)

আপনি কোডের প্রায় সব জায়গায় স্টিকার মারতে পারেন।

```csharp
[Serializable] // 1. Class-level: ক্লাসের মাথায়
public class Student
{
    [Key] // 2. Property-level: প্রপার্টির মাথায়
    public int Id { get; set; }

    [Obsolete] // 3. Method-level: মেথডের মাথায়
    public void Study() { }

    // 4. Parameter-level: মেথডের প্যারামিটারের আগে
    public void UpdateScore([NotNull] int score) { }
}
```

### ৫. অ্যাট্রিবিউট টার্গেট ও রুলস (Attribute Targets & AttributeUsage)

এখন আপনি চাইলেই কি ফ্রিজের স্টিকার টিভিতে লাগাতে পারবেন? না! অ্যাট্রিবিউটেরও নিয়ম আছে। একে বলে `AttributeUsage`।

এটা দিয়ে আমরা বলে দিই—"আমার বানানো স্টিকারটা কোথায় কোথায় লাগানো যাবে।"

*   **AttributeTargets:** কোথায় বসবে? (Class, Method, All?)
*   **AllowMultiple:** এক জায়গায় কি একাধিকবার বসানো যাবে?
*   **Inherited:** বাপের ক্লাসের স্টিকার কি ছেলে পাবে?

```csharp
// এই স্টিকার শুধু ক্লাস আর মেথডে লাগানো যাবে।
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
public class MySpecialAttribute : Attribute
{
    // Logic here
}
```

### ৬. নিজের অ্যাট্রিবিউট বানানো (Creating Custom Attributes) 🛠️

চলুন, আমরা একটা কাস্টম অ্যাট্রিবিউট বানাই। নাম দেব `[DeveloperInfo]`। এটা দিয়ে আমরা ক্লাসে লিখে রাখব কে কোডটা লিখেছে।

**স্টেপ ১:** একটা ক্লাস বানাবো যেটা `Attribute` থেকে ইনহেরিট করবে।
**স্টেপ ২:** ক্লাসের নামের শেষে `Attribute` শব্দটা রাখবো (এটা কনভেনশন)।

```csharp
// ১. কাস্টম অ্যাট্রিবিউট ডিফাইন করা
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method)]
public class DeveloperInfoAttribute : Attribute
{
    public string Name { get; }
    public string Date { get; }
    public string Message { get; set; } // এটা অপশনাল

    // কনস্ট্রাক্টর
    public DeveloperInfoAttribute(string name, string date)
    {
        Name = name;
        Date = date;
    }
}

// ২. ব্যবহার করা
[DeveloperInfo("Rahim", "2025-10-10", Message = "Fixed major bug")]
public class OrderService
{
    [DeveloperInfo("Karim", "2025-11-01")]
    public void ProcessOrder()
    {
        Console.WriteLine("Processing order...");
    }
}
```

### ৭. রিফ্লেকশন দিয়ে অ্যাট্রিবিউট পড়া (Reading Attribute Using Reflection) 🔍

এতক্ষণ তো শুধু স্টিকার লাগালাম। এখন স্টিকার **পড়ব** কীভাবে?
এখানেই আসে **Reflection**। রিফ্লেকশন হলো .NET এর গোয়েন্দা (Detective)। সে রানটাইমে কোডের ভেতরের খবর বের করে আনতে পারে।

**কেন লাগে?**
আপনি যদি রিফ্লেকশন দিয়ে না পড়েন, তবে অ্যাট্রিবিউট কোনো কাজই করবে না (কিছু বিল্ট-ইন বাদে)। এটা শুধুই কমেন্ট হয়ে পড়ে থাকবে।

**সহজ কোড উদাহরণ:**

```csharp
using System.Reflection;

class Program
{
    static void Main()
    {
        // ১. টাইপ টা ধরি (OrderService ক্লাস)
        Type t = typeof(OrderService);

        // ২. ক্লাসের মাথার অ্যাট্রিবিউট খুঁজি
        var attributes = t.GetCustomAttributes(typeof(DeveloperInfoAttribute), false);

        foreach (DeveloperInfoAttribute attr in attributes)
        {
            Console.WriteLine($"Code written by: {attr.Name}");
            Console.WriteLine($"Date: {attr.Date}");
            Console.WriteLine($"Msg: {attr.Message}");
        }

        // আউটপুট:
        // Code written by: Rahim
        // Date: 2025-10-10
        // Msg: Fixed major bug
    }
}
```
*দেখেছেন? কোড রান হওয়ার সময় আমরা জানতে পারলাম এই ক্লাস কে লিখেছে!*

### ৮. রিয়েল ওয়ার্ল্ড ইউজ কেস (Real-world Use Cases)

বাস্তব প্রজেক্টে এগুলো কোথায় বেশি লাগে?

1.  **Validation:** `[Required]`, `[EmailAddress]` (আমরা ফর্ম সাবমিট করার সময় অহরহ ব্যবহার করি)।
2.  **Authorization:** `[Authorize(Roles = "Admin")]` -> কন্ট্রোলারের মাথায় লাগিয়ে দিলে এডমিন ছাড়া কেউ ঢুকতে পারবে না।
3.  **JSON Serialization:** `[JsonPropertyName("user_id")]` -> C# প্রপার্টি `UserId` কিন্তু JSON এ দেখাবে `user_id`।
4.  **Logging/Aspect Oriented Programming:** মেথড রান হওয়ার আগে অটোমেটিক লগ রাখা।

### ৯. সাধারণ ভুলসমূহ (Common Mistakes) ❌

1.  **বিজনেস লজিক ঢুকিয়ে দেওয়া:** অ্যাট্রিবিউটের কনস্ট্রাক্টরের ভেতর ডাটাবেস কল বা জটিল লজিক লিখবেন না। এটা জাস্ট ডেটা হোল্ডার।
2.  **অতিরিক্ত ব্যবহার:** সব জায়গায় অ্যাট্রিবিউট লাগালে কোড নোংরা হয়ে যায়।
3.  **ভুল ধারণা:** অনেকে ভাবে অ্যাট্রিবিউট লিখলেই কাজ হয়। না! ওটাকে পড়ার জন্য কাউকে (Framework বা Reflection) থাকতে হয়।

### ১০. বেস্ট প্র্যাকটিস (Best Practices) ✅

*   নামের শেষে সবসময় `Attribute` শব্দটা রাখবেন (যেমন: `MyLogAttribute`)।
*   `sealed` কিওয়ার্ড ব্যবহার করুন যদি ইনহেরিটেন্স দরকার না হয় (পারফরম্যান্স ভালো হয়)।
*   শুধুমাত্র মেটাডেটা (Metadata) রাখার জন্য ব্যবহার করুন।
*   ASP.NET Core এ ফিল্টার বা মিডলওয়্যার এর সাথে অ্যাট্রিবিউট ব্যবহার করা বেস্ট।

### ১১. ছোট প্র্যাকটিস টাস্ক (Mini Practice Task) 💻

বাসায় এই কোডটা রান করে দেখুন:

**Task:** একটা `[VipCustomer]` অ্যাট্রিবিউট বানাবেন। একটা `Customer` ক্লাসে সেটা লাগাবেন। রিফ্লেকশন দিয়ে চেক করবেন কাস্টমার VIP কি না।

```csharp
// ১. অ্যাট্রিবিউট
public class VipCustomerAttribute : Attribute { }

// ২. ক্লাস
[VipCustomer]
public class RahimShaheb { }

public class NormalPublic { }

// ৩. মেইন মেথড
class Program
{
    static void CheckIfVip(Type t)
    {
        bool isVip = Attribute.IsDefined(t, typeof(VipCustomerAttribute));
        if (isVip)
            Console.WriteLine($"{t.Name} is a VIP Customer! Sir, please come inside.");
        else
            Console.WriteLine($"{t.Name} is normal. Line e daran.");
    }

    static void Main()
    {
        CheckIfVip(typeof(RahimShaheb)); // VIP
        CheckIfVip(typeof(NormalPublic)); // Normal
    }
}
```

### কুইক সামারি (Summary) 📝

1.  **Attribute** = কোডের ওপর লাগানো স্টিকার/লেবেল।
2.  এটা `System.Attribute` ক্লাসকে ইনহেরিট করে।
3.  `[]` ব্র্যাকেট দিয়ে ব্যবহার করা হয়।
4.  **Reflection** ছাড়া কাস্টম অ্যাট্রিবিউট অচল।
5.  এরা কোডের বিহেভিয়ার কন্ট্রোল করতে সাহায্য করে (যেমন ভ্যালিডেশন, অথরাইজেশন)।

### ইন্টারভিউ প্রশ্ন (Interview Questions) 🎤

1.  **Attribute কী?** (Metadata যা রানটাইমে পড়া যায়)।
2.  **Reflection কী এবং কেন অ্যাট্রিবিউটের সাথে লাগে?** (Reflection কোড ইন্সপেক্ট করে, এটা দিয়েই অ্যাট্রিবিউট রিড করা হয়)।
3.  **Custom Attribute কীভাবে বানাবেন?** (Class inherit `Attribute` + `AttributeUsage`)।
4.  **`[Obsolete]` অ্যাট্রিবিউট কী করে?** (কোডকে এক্সপায়ার্ড বা ডেপ্রিকেটেড মার্ক করে)।
5.  **Attribute কি রানটাইমে নাকি কম্পাইল টাইমে কাজ করে?** (মেটাডেটা কম্পাইল টাইমে যুক্ত হয়, কিন্তু রিফ্লেকশন দিয়ে রানটাইমে এক্সেস করা হয়)।

আশা করি এখন থেকে Attributes দেখলে আর ভয় পাবেন না! কোড করতে থাকুন, আর কোডের গায়ে ইচ্ছেমতো স্টিকার লাগাতে থাকুন! হ্যাপি কোডিং! 🚀😎
