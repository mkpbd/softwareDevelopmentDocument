#### **Lesson 4.1: Dapper কেন? EF Core থাকার পরেও? (Ferrari vs Tank)**

**পার্থক্যটা বুঝো:**
*   **EF Core (The Tank):** অনেক ফিচার, অনেক পাওয়ারফুল, কিন্তু ভারী। সে নিজে নিজে SQL লেখে, তাই মাঝে মাঝে একটু স্লো হয় (Translation Overhead)।
*   **Dapper (The Ferrari):** একে বলে **Micro-ORM**। এর কাজ একটাই—ডাটাবেস থেকে র ডাটা এনে C# অবজেক্টে কনভার্ট করা। এর বাইরে সে কিচ্ছু জানে না। তাই সে EF Core এর চেয়ে অনেক ফাস্ট।

**কখন কোনটা ব্যবহার করবো?**
*   **EF Core:** যখন ডাটা সেভ (Create/Update) করতে হবে বা জটিল রিলেশনশিপ হ্যান্ডেল করতে হবে।
*   **Dapper:** যখন হাজার হাজার ডাটা পড়ার (Read/Report) দরকার হবে এবং সুপার ফাস্ট রেসপন্স লাগবে।

**Connection Setup:**

#### **Lesson 4.3: Raw SQL Queries with Dapper**

EF Core-এ আমরা LINQ লিখতাম, এখানে আমরা **বিশুদ্ধ SQL** লিখবো।

**Code Example:**
নতুন একটা কন্ট্রোলার বানাও `DapperStudentController.cs`।

```csharp
using Dapper;
using Microsoft.Data.SqlClient;

[Route("api/[controller]")]
[ApiController]
public class DapperStudentController : ControllerBase
{
    private readonly IConfiguration _config;

    public DapperStudentController(IConfiguration config)
    {
        _config = config; // appsettings.json থেকে কানেকশন স্ট্রিং পাওয়ার জন্য
    }

    [HttpGet]
    public async Task<IActionResult> GetAllStudents()
    {
        // কানেকশন তৈরি
        using var connection = new SqlConnection(_config.GetConnectionString("DefaultConnection"));
        
        // কুয়েরি লেখা
        var sql = "SELECT * FROM Students";
        
        // Dapper Magic: SQL চালাও আর রেজাল্ট Student লিস্টে কনভার্ট করো
        var students = await connection.QueryAsync<Student>(sql);
        
        return Ok(students);
    }
}
```
*খেয়াল করো: `QueryAsync<Student>` মেথডটাই হলো ড্যাপার। সে কলামের নামের সাথে প্রপার্টি নাম মিলিয়ে ডাটা ভরে দেয়।*

#### **Lesson 4.4: QuerySingle, QueryFirst, QueryMultiple**

Dapper-এ ডাটা আনার জন্য কয়েকটা মেথড আছে:

1.  **QueryAsync:** এক লিস্ট ডাটা (List) আনার জন্য।
2.  **QueryFirstAsync:** প্রথম ডাটাটা আনবে। না পেলে এরর দিবে।
3.  **QueryFirstOrDefaultAsync:** প্রথমটা আনবে, না পেলে `null` দিবে (সেফ অপশন)।
4.  **ExecuteAsync:** ডাটা Insert/Update/Delete করার জন্য (কোনো ডাটা রিটার্ন করে না, শুধু কয়টা রো এফেক্টেড হলো তা বলে)।

**Example (Get by ID):**
```csharp
[HttpGet("{id}")]
public async Task<IActionResult> GetStudent(int id)
{
    using var connection = new SqlConnection(_config.GetConnectionString("DefaultConnection"));
    
    // @Id হলো প্যারামিটার (SQL Injection ঠেকায়)
    var sql = "SELECT * FROM Students WHERE Id = @Id";
    
    var student = await connection.QueryFirstOrDefaultAsync<Student>(sql, new { Id = id });
    
    if (student == null) return NotFound();
    return Ok(student);
}
```

#### **Lesson 4.5: Dapper Contrib (Extension Methods)**

তুমি যদি অলস হও (আমার মতো) এবং `SELECT * FROM...` বারবার লিখতে না চাও, তাহলে `Dapper.Contrib` প্যাকেজটা ইন্সটল করতে পারো।

**Magic:**
```csharp
// SQL লেখা ছাড়াই সব আনবে!
var students = await connection.GetAllAsync<Student>(); 

// ID দিয়ে আনবে
var student = await connection.GetAsync<Student>(1);
```
*তবে আমরা Dapper শিখছি ম্যানুয়াল কন্ট্রোলের জন্য, তাই র (Raw) SQL শেখাই ভালো।*

#### **Lesson 4.6: Stored Procedures with Dapper**

বড় কোম্পানিতে ডাটাবেস অ্যাডমিনরা (DBA) লজিক সব **Stored Procedure (SP)**-এ লিখে রাখে। Dapper দিয়ে SP কল করা পানির মতো সহজ।

**Code:**
```csharp
[HttpGet("report")]
public async Task<IActionResult> GetReport()
{
    using var connection = new SqlConnection(_config.GetConnectionString("DefaultConnection"));
    
    var spName = "sp_GetStudentReport"; // ডাটাবেসে এই নামে SP থাকতে হবে
    
    var result = await connection.QueryAsync<Student>(
        spName, 
        commandType: CommandType.StoredProcedure // বলে দিলাম এটা SP
    );
    
    return Ok(result);
}
```

#### **Lesson 4.7: Performance Comparison: EF vs Dapper**

কেন Dapper ফাস্ট?
*   EF Core প্রথমে LINQ কে SQL-এ কনভার্ট করে।
*   তারপর SQL চালায়।
*   তারপর রেজাল্ট ট্র্যাক করে (Change Tracking)।

Dapper সরাসরি SQL চালায় আর রেজাল্ট দিয়ে দেয়। কোনো ট্র্যাকিং নাই, কনভার্শন নাই।

**Benchmarking (Mental):**
১০০০ ডাটা তুলতে EF Core-এর যদি ১০০ মিলি সেকেন্ড লাগে, Dapper-এর লাগবে ১০-১৫ মিলি সেকেন্ড। (Disclaimer: সিচুয়েশন ভেদে কমবেশি হতে পারে)।

#### **Lesson 4.8: Hybrid Approach (Best Practice)**

আমরা প্রজেক্টে **দুইটাই** ব্যবহার করবো। একে বলে হাইব্রিড এপ্রোচ।

*   **Commands (Insert/Update):** EF Core ব্যবহার করবো। কারণ ভ্যালিডেশন আর রিলেশনশিপ মেইনটেইন করা সহজ।
*   **Queries (Select/Search):** Dapper ব্যবহার করবো। বিশেষ করে ড্যাশবোর্ড বা রিপোর্টের জন্য যেখানে প্রচুর ডাটা লোড হয়।

#### **Lesson 4.9: SQL Injection Prevention (খবরদার!)**

কখনো এভাবে কোড লিখবে না:
`var sql = "SELECT * FROM Users WHERE Name = '" + userName + "'";` ❌

যদি কেউ `userName` এর জায়গায় `'; DROP TABLE Users; --` লিখে দেয়, তোমার ডাটাবেস গায়েব হয়ে যাবে! একে বলে **SQL Injection**।

**সঠিক নিয়ম (Parameterization):**
Dapper এ আমরা `@Parameter` ব্যবহার করবো।
```csharp
// Dapper এটা স্যানিটাইজ করে নিবে
connection.QueryAsync("SELECT * FROM Users WHERE Name = @Name", new { Name = userName }); ✅
```
