বস, এতক্ষণ আমরা কোড লিখেছি "Fat Controller" স্টাইলে। মানে কন্ট্রোলারের পেটের ভেতর ডাটাবেস লজিক, ভ্যালিডেশন, ক্যালকুলেশন সব ঢুকিয়ে দিয়েছি। এতে কন্ট্রোলার হয়ে গেছে মোটা (Fat) এবং আনফিট।

এখন আমরা কন্ট্রোলারকে জিমে পাঠাবো। কন্ট্রোলারের কাজ শুধু ট্রাফিক পুলিশের মতো—রিকোয়েস্ট নিবে আর সার্ভিসকে বলবে "কাজটা করে দাও"। নিজে কিছু করবে না।

একে বলে **Dependency Injection (DI)** এবং **Repository Pattern**। এটা শিখলে তোমার কোড হবে মডুলার, টেস্টেবল এবং ক্লিন।

#### **Lesson 8.1: DI Principle: Why loose is good? (The Socket Analogy)**

**সহজ ভাষায়:**
মনে করো তোমার ল্যাপটপের চার্জার ওয়াল সকেটে লাগানো যায়। এটা **Loosely Coupled**। তুমি চাইলে অ্যাপল চার্জার খুলে স্যামসাং লাগাতে পারো।
কিন্তু যদি চার্জারের তার সরাসরি ওয়ালের কারেন্টের তারের সাথে ঝালাই (Soldering) করা থাকতো? তাহলে চার্জার বদলাতে গেলে দেয়াল ভাঙা লাগতো! এটা **Tightly Coupled**।

**Coding Example:**
*খারাপ (Tightly Coupled):*
```csharp
public class StudentController
{
    // কন্ট্রোলার নিজেই সার্ভিস তৈরি করছে। সার্ভিস চেঞ্জ করলে কন্ট্রোলারও ভাঙতে হবে।
    private StudentService _service = new StudentService(); 
}
```

*ভালো (Loosely Coupled / DI):*
```csharp
public class StudentController
{
    private readonly IStudentService _service;
    
    // কন্ট্রোলার জানেই না কোন সার্ভিস আসছে, সে শুধু ইন্টারফেস চিনে।
    public StudentController(IStudentService service) 
    {
        _service = service;
    }
}
```

#### **Lesson 8.2: Service Lifetime: Transient (Use & Throw)**

DI কন্টেইনারে (Program.cs) সার্ভিস রেজিস্ট্রেশন করার সময় বলে দিতে হয় সার্ভিসটা কতক্ষণ বেঁচে থাকবে।

**Transient (ক্ষণস্থায়ী):**
*   **উদাহরণ:** টিস্যু পেপার। একবার নাক মুছে ফেলে দাও।
*   **কাজ:** প্রতিবার যখন কেউ সার্ভিস চাইবে, .NET **নতুন** একটা অবজেক্ট বানিয়ে দিবে।
*   **কোড:** `builder.Services.AddTransient<IEmailService, EmailService>();`
*   **ব্যবহার:** হালকা ছোটখাটো সার্ভিসের জন্য।

---

#### **Lesson 8.3: Service Lifetime: Scoped (Per Request)**

**Scoped (এক রিকোয়েস্টে এক পিস):**
*   **উদাহরণ:** রেস্টুরেন্টের প্লেট। তুমি যতক্ষণ খাচ্ছো (Request চলছে), প্লেট একটাই। খাওয়া শেষ হলে প্লেট ধুতে চলে যায়। অন্য কাস্টমার আসলে নতুন প্লেট পায়।
*   **কাজ:** একটা HTTP Request-এর শুরু থেকে শেষ পর্যন্ত একই অবজেক্ট থাকে।
*   **কোড:** `builder.Services.AddScoped<IStudentRepository, StudentRepository>();`
*   **ব্যবহার:** **DbContext**, Repository, Business Logic (সবচেয়ে বেশি ব্যবহৃত)।

---

#### **Lesson 8.4: Service Lifetime: Singleton (One for All)**

**Singleton (অমর):**
*   **উদাহরণ:** সূর্য। আমি তাকালেও যা, তুমি তাকালেও তাই। সবার জন্য একটাই সূর্য।
*   **কাজ:** অ্যাপ্লিকেশন স্টার্ট হওয়ার সময় একবার তৈরি হয়, আর বন্ধ হওয়ার আগ পর্যন্ত ওই **একটাই** অবজেক্ট সবাই শেয়ার করে।
*   **কোড:** `builder.Services.AddSingleton<ICacheService, CacheService>();`
*   **ব্যবহার:** Caching, Configuration Load। (সাবধান! ডাটাবেস কন্টেক্সট এখানে ব্যবহার করবে না!)

#### **Lesson 8.5: Interface Segregation (Don't force methods)**

**Solid Principles**-এর 'I'।

**গল্প:**
ধরো একটা `IWorker` ইন্টারফেস আছে যার মেথড: `Work()` এবং `Eat()`।
এখন তুমি একটা রোবট বানালে। রোবট `Work()` করে, কিন্তু `Eat()` করে না। কিন্তু ইন্টারফেসের চাপে তাকে জোর করে `Eat()` ইমপ্লিমেন্ট করতে হচ্ছে (Exception throw করে)। এটা অন্যায়!

**সমাধান:**
ইন্টারফেস ভেঙে ছোট করো: `IWorkable` এবং `IFeedable`। মানুষ দুইটাই নিবে, রোবট শুধু `IWorkable` নিবে।

#### **Lesson 8.6: Repository Pattern (The Abstraction Layer)**

সরাসরি কন্ট্রোলারে `DbContext` ব্যবহার করা পাপ! (ছোট প্রজেক্টে ঠিক আছে, বড় প্রজেক্টে পাপ)। কারণ কাল যদি SQL Server বদলে MongoDB লাগাও, সব কন্ট্রোলার চেঞ্জ করতে হবে।

**Step 1: Interface**
```csharp
public interface IStudentRepository
{
    Task<List<Student>> GetAllAsync();
    Task<Student> GetByIdAsync(int id);
    Task AddAsync(Student student);
    // ... SaveChanges এখানে থাকবে না
}
```

**Step 2: Implementation**
```csharp
public class StudentRepository : IStudentRepository
{
    private readonly AppDbContext _context;
    public StudentRepository(AppDbContext context)
    {
        _context = context; // এখানে ডিবি ইনজেক্ট হলো
    }

    public async Task<List<Student>> GetAllAsync()
    {
        return await _context.Students.ToListAsync();
    }
    // ... other methods implementation
}
```

#### **Lesson 8.7: Unit of Work Pattern (The Boss)**

**সমস্যা:**
ধরো `StudentRepository` তে একটা ডাটা অ্যাড করলে, আর `CourseRepository` তে আরেকটা। দুইটাই আলাদা করে `SaveChanges` কল করলো। মাঝখানে কারেন্ট গেল। স্টুডেন্ট সেভ হলো কিন্তু কোর্স হলো না। ডাটাবেসে জগাখিচুড়ি!

**সমাধান (Unit of Work):**
ইনি হলেন ম্যানেজার। সব রিপোজিটরির কাজ শেষ হলে ইনি **একবার** `SaveChanges` কল করবেন। সব হবে, নাহলে কিছুই হবে না (Transaction)।

```csharp
public interface IUnitOfWork
{
    IStudentRepository Students { get; }
    ICourseRepository Courses { get; }
    Task<int> CompleteAsync(); // এটাই আসল SaveChanges
}
```

#### **Lesson 8.8: Resolving Services in Middleware/Background Jobs**

সব সময় কনস্ট্রাক্টর ইনজেকশন কাজ করে না। বিশেষ করে মিডলওয়্যার বা স্ট্যাটিক মেথডে। তখন সার্ভিস লোকেটর প্যাটার্ন লাগে।

**Code:**
```csharp
using (var scope = app.Services.CreateScope())
{
    var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    // এখন তুমি dbContext দিয়ে কাজ করতে পারো
}
```
*টিপস: ডাটাবেস মাইগ্রেশন অটোমেটিক চালানোর জন্য `Program.cs` এ এটা আমরা প্রায়ই ব্যবহার করি।*

#### **Lesson 8.9: Keyed Services (.NET 8/9 Feature)**

একই ইন্টারফেস `INotificationService`। কিন্তু দুইটা ক্লাস: `SmsService` আর `EmailService`।
কন্ট্রোলার কিভাবে বুঝবে কোনটা চাই?

আগে অনেক ঝামেলা ছিল, এখন .NET 8/9 এ সহজ:

**Program.cs:**
```csharp
builder.Services.AddKeyedScoped<INotification, SmsService>("sms");
builder.Services.AddKeyedScoped<INotification, EmailService>("email");
```

**Controller:**
```csharp
public MyController([FromKeyedServices("sms")] INotification smsService)
{
    // এখন এটা SMS সার্ভিস
}
```

#### **Lesson 8.10: Module 8 Coding Exercise 🎯**

চলো আমাদের `StudentController` কে ডায়েট করাই।

**Task: Refactor to Repository Pattern**

1.  `Repositories` নামে ফোল্ডার বানাও।
2.  `IStudentRepository.cs` ইন্টারফেস বানাও (GetAll, GetById, Add, Delete মেথড রাখো)।
3.  `StudentRepository.cs` ক্লাস বানিয়ে ইমপ্লিমেন্ট করো (ভিতরে `AppDbContext` ব্যবহার করো)।
4.  `Program.cs`-এ রেজিস্টার করো: `builder.Services.AddScoped<IStudentRepository, StudentRepository>();`
5.  `StudentController`-এ `AppDbContext` ফেলে দিয়ে `IStudentRepository` ইনজেক্ট করো।

**Example Refactored Controller:**
```csharp
[Route("api/[controller]")]
[ApiController]
public class StudentController : ControllerBase
{
    private readonly IStudentRepository _repo; // DbContext নাই!

    public StudentController(IStudentRepository repo)
    {
        _repo = repo;
    }

    [HttpGet]
    public async Task<IActionResult> Get()
    {
        var data = await _repo.GetAllAsync();
        return Ok(data);
    }
}
```
