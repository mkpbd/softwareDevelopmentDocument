কিন্তু বড় এন্টারপ্রাইজ প্রজেক্টে (যেমন: বিকাশ বা ফুডপান্ডা), সব কোড এক জায়গায় থাকলে জগাখিচুড়ি (Spaghetti Code) হয়ে যায়। একটা ঠিক করলে আরেকটা ভাঙ্গে।

তাই আজ আমরা শিখবো **Clean Architecture** (Onion Architecture)। এখানে আমরা পেঁয়াজের খোসার মতো লেয়ারে লেয়ারে কোড সাজাবো। বাইরের লেয়ার ভিতরের লেয়ারের ওপর ডিপেন্ড করবে, কিন্তু ভিতরের লেয়ার বাইরের কাউকে চিনবে না।

#### **Lesson 9.1: Monolith vs Layered vs Clean Architecture**

**গল্প:**
১. **Monolith:** সব মশলা, চাল, ডাল একসাথে হাঁড়িতে দিয়ে খিচুড়ি। সুস্বাদু, কিন্তু ডাল আলাদা করতে পারবে না।
২. **Layered (N-Tier):** ভাত, ডাল, তরকারি আলাদা বাটিতে। কিন্তু তরকারির বাটি ভাতের ওপর বসানো। নিচেরটা সরালে উপরেরটা পড়ে যাবে।
3.  **Clean Architecture:** এটা একটা বৃত্ত বা চাকা।
    *   **কেন্দ্র (Core):** রাজা (Domain)। সে কাউকে কেয়ার করে না।
    *   **মধ্যভাগ:** মন্ত্রী (Application)। সে রাজার কথা শোনে।
    *   **বাইরের ভাগ:** প্রজা/সৈন্য (Infrastructure/API)। তারা মন্ত্রীর হুকুম তামিল করে।

**গোল্ডেন রুল:** ডিপেন্ডেন্সি সবসময় **বাইরে থেকে ভেতরে** আসবে। **ভিতর থেকে বাইরে না!**

#### **Lesson 9.2: Domain Layer (The Core / The King)**

এটা প্রজেক্টের **হৃদপিণ্ড**। এখানে কোনো ডাটাবেস কোড, কন্ট্রোলার কোড বা লাইব্রেরি থাকবে না। শুধু **Pure C# Class**।

**কি কি থাকে?**
*   Entities (Student, Course)
*   Enums (Gender, UserRole)
*   Exceptions (DomainSpecificException)

**Code (Class Library Project - `School.Domain`):**
```csharp
public class Student
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    // ডোমেইন লজিক (বিজনেস রুল) এখানেই থাকে
    public void UpdateName(string newName)
    {
        if(string.IsNullOrWhiteSpace(newName)) throw new Exception("নাম ছাড়া ছাত্র হয় না!");
        Name = newName;
    }
}
```
*দেখো, এখানে `[Key]` বা `DbContext` কিছুই নাই! রাজা কারো ওপর নির্ভরশীল না।*

#### **Lesson 9.3: Application Layer (The Logic / The Minister)**

এখানে থাকে বিজনেস লজিক এবং ইন্টারফেস। এই লেয়ার **Domain**-কে চেনে, কিন্তু ডাটাবেস বা API-কে চেনে না।

**কি কি থাকে?**
*   Interfaces (`IStudentRepository`)
*   DTOs (Data Transfer Objects - `StudentDto`)
*   Service/Handlers (CQRS Commands/Queries)
*   Validators

**Code (Class Library Project - `School.Application`):**
```csharp
// ইন্টারফেসটা এখানে, কিন্তু ইমপ্লিমেন্টেশন অন্য লেয়ারে হবে (Dependency Inversion)
public interface IStudentRepository
{
    Task<Student> GetByIdAsync(int id);
}
```

#### **Lesson 9.6: CQRS Pattern (Command Query Responsibility Segregation)**

**সহজ ভাষায়:**
ব্যাংকে গেলে দেখবে "টাকা জমা" (Deposit) আর "টাকা তোলা/ব্যালেন্স চেক" (Enquiry) এর লাইন আলাদা।
কোডিংয়েও আমরা **Read (Query)** এবং **Write (Command)** অপারেশন আলাদা করে ফেলি।

*   **Command:** ডাটা চেঞ্জ করবে (POST, PUT, DELETE)। রিটার্ন টাইপ সাধারণত `Void` বা `Id`।
*   **Query:** ডাটা শুধু পড়বে (GET)। ডাটা চেঞ্জ করবে না।

**কেন?** যাতে পড়ার স্পিড আর লেখার লজিক গুলিয়ে না যায়। রিডের জন্য Dapper, রাইটের জন্য EF Core ব্যবহার করা সহজ হয়।

#### **Lesson 9.7: MediatR Library (The Messenger)**

কন্ট্রোলার আর সার্ভিসের মধ্যে সরাসরি বিয়ে না দিয়ে আমরা একজন ঘটক (Mediator) রাখি। কন্ট্রোলার ঘটককে বলে "ভাই, স্টুডেন্ট তৈরি করো"। ঘটক সঠিক হ্যান্ডলার খুঁজে কাজটা করায়।

**Action:** `MediatR` প্যাকেজ ইন্সটল করতে হয় `Application` লেয়ারে।

**Flow:**
API -> Command -> MediatR -> Handler -> Repository -> DB

**Code Example (Create Student Command):**

1.  **Command (The Request):**
    ```csharp
    public class CreateStudentCommand : IRequest<int> 
    {
        public string Name { get; set; }
        public string Email { get; set; }
    }
    ```

2.  **Handler (The Logic):**
    ```csharp
    public class CreateStudentHandler : IRequestHandler<CreateStudentCommand, int>
    {
        private readonly IStudentRepository _repo;
        public CreateStudentHandler(IStudentRepository repo) => _repo = repo;

        public async Task<int> Handle(CreateStudentCommand request, CancellationToken token)
        {
            var student = new Student { Name = request.Name, Email = request.Email };
            await _repo.AddAsync(student);
            return student.Id;
        }
    }
    ```

3.  **Controller:**
    ```csharp
    [HttpPost]
    public async Task<IActionResult> Create(CreateStudentCommand command)
    {
        var id = await _mediator.Send(command); // কন্ট্রোলার জানেই না হ্যান্ডলার কে!
        return Ok(id);
    }
    ```

#### **Lesson 9.8: AutoMapper (Object Mapping)**

`Student` (Entity) থেকে `StudentDto` (ViewModel) এ ডাটা কপি করতে করতে হাত ব্যথা হয়ে যায়।
`dto.Name = student.Name; dto.Email = student.Email; ...`

**AutoMapper** এটা এক লাইনে করে দেয়।

**Setup:**
`CreateMap<Student, StudentDto>().ReverseMap();`

**Usage:**
`var dto = _mapper.Map<StudentDto>(student);`

#### **Lesson 9.9: SOLID Principles in Action**

আমরা যা বানালাম, তাতে SOLID সব মানা হয়েছে:
*   **S (SRP):** প্রতিটা হ্যান্ডলারের একটাই কাজ।
*   **O (OCP):** নতুন ফিচার অ্যাড করলে পুরনো কোড ভাঙতে হয় না (নতুন হ্যান্ডলার বানাও)।
*   **L (LSP):** ইন্টারফেস দিয়ে কাজ করায় রিপ্লেসমেন্ট সহজ।
*   **I (ISP):** ছোট ছোট ইন্টারফেস।
*   **D (DIP):** হাই লেভেল মডিউল (Domain/App) লো লেভেল (Infra) এর ওপর ডিপেন্ড করে না। উল্টোটা হয়।
