### **Lesson 11: ক্লাস এবং অবজেক্ট (Class & Object)**

*   **Learning Goal:** ক্লাস (নকশা) এবং অবজেক্ট (আসল জিনিস) এর পার্থক্য বোঝা।
*   **Simple Explanation:**
    *   **Class:** এটা হলো একটা ব্লু-প্রিন্ট বা নকশা। যেমন: গাড়ির ইঞ্জিনিয়ার খাতায় গাড়ির ছবি আঁকলেন—এটা হলো ক্লাস। এই খাতার ছবি চালানো যায় না।
    *   **Object:** ওই নকশা দেখে ফ্যাক্টরিতে যে আসল গাড়িটা বানানো হলো, সেটা হলো অবজেক্ট। একটা নকশা (Class) দিয়ে হাজার হাজার গাড়ি (Object) বানানো যায়।
*   **Funny Real-life Analogy:**
    পিঠা বানানোর **ছাঁচ** হলো **Class**। আর ছাঁচ দিয়ে বানানো সুস্বাদু **পিঠা** হলো **Object**। ছাঁচ খাওয়া যায় না, পিঠাই খেতে হয়! 🥟
*   **Code Example:**
    ```csharp
    // Car.cs (এটা হলো নকশা)
    public class Car
    {
        public string Model;  // Field (Variable inside class)
        public string Color;

        public void StartEngine() // Method (Function inside class)
        {
            Console.WriteLine($"{Model} engine start dilam... Vroom Vroom!");
        }
    }

    // Program.cs (এখানে ব্যবহার করব)
    Car myCar = new Car(); // 'new' মানে নতুন পিঠা (Object) বানালাম
    myCar.Model = "Toyota Allion";
    myCar.Color = "White";

    Car yourCar = new Car(); // একই নকশা দিয়ে আরেকটা গাড়ি
    yourCar.Model = "Honda Civic";

    myCar.StartEngine(); // Toyota স্টার্ট হবে
    yourCar.StartEngine(); // Honda স্টার্ট হবে
    ```
*   **File / Project Structure:**
    ```
    MyApp/
    ├── Car.cs
    └── Program.cs
    ```
*   **Mini Exercise:** `Mobile` নামে একটা ক্লাস বানাও। সেখানে `Brand` এবং `Price` ফিল্ড দাও। `CallMama()` নামে একটা মেথড দাও যা প্রিন্ট করবে "Calling Mama..."। মেইন প্রোগ্রামে ২টা মোবাইলের অবজেক্ট বানিয়ে কল দাও।
*   **Common Mistakes:** ক্লাস বানালে কিন্তু `new` দিয়ে অবজেক্ট তৈরি না করলে সেটা কাজ করবে না (Null Reference খাবে)।
*   **One-line Summary:** `Class` হলো টাইপ বা নকশা, আর `Object` হলো মেমোরিতে তৈরি হওয়া আসল ভ্যারিয়েবল।
*   **Why this matters:** রিয়েল প্রজেক্টে সব ডেটা (User, Product, Order) ক্লাস হিসেবেই থাকে।

### **Lesson 12: প্রপার্টিজ (Properties - Get/Set)**

*   **Learning Goal:** ভ্যারিয়েবল বা ফিল্ডকে সরাসরি খোলা না রেখে "প্রপার্টি" দিয়ে কন্ট্রোল করা।
*   **Simple Explanation:** ক্লাসের ভেতর ভ্যারিয়েবল (Field) সরাসরি `public` রাখা রিস্কি। কেউ ভুলভাল ডেটা ঢোকাতে পারে। তাই আমরা `Property` ব্যবহার করি। এটা গেট-কিপারের মতো কাজ করে।
*   **Funny Real-life Analogy:**
    বাড়ির মেইন দরজা (Public) আর বেডরুম (Private)। মেহমান ড্রয়িংরুমে (Property) বসবে, কিন্তু আলমারির টাকা (Private Field) সরাসরি ধরবে না। টাকা লাগলে তোমার কাছে চাইবে (Get), অথবা তোমাকে দিবে (Set)।
*   **Code Example:**
    ```csharp
    public class Student
    {
        // Private field (বাইরে থেকে দেখা যাবে না)
        private int _age;

        // Public Property (দারোয়ান)
        public int Age
        {
            get { return _age; } // কেউ বয়স জানতে চাইলে _age দিবে
            set
            {
                // লজিক: বয়স তো আর নেগেটিভ হতে পারে না!
                if (value >= 0)
                {
                    _age = value;
                }
                else
                {
                    Console.WriteLine("Boyos negative hoy na mama!");
                }
            }
        }

        // Auto-Property (শর্টকাট - যদি কোনো লজিক না লাগে)
        public string Name { get; set; }
    }

    // Usage in Program.cs
    Student s1 = new Student();
    s1.Name = "Rahim";
    s1.Age = -5; // এরর মেসেজ দিবে, সেট হবে না
    s1.Age = 20; // ঠিক আছে
    Console.WriteLine($"Student: {s1.Name}, Age: {s1.Age}");
    ```
*   **Mini Exercise:** `Product` নামে ক্লাস বানাও। `Price` প্রপার্টিতে এমন লজিক দাও যেন প্রাইস কখনোই ০-এর কম না হয়।
*   **Common Mistakes:** `get` বা `set` এর ভেতরে লুপ বা ভারী কোড লেখা (এটা সিম্পল রাখা উচিত)।
*   **One-line Summary:** প্রপার্টি ডেটা সেট বা গেট করার সময় ভ্যালিডেশন বা লজিক চেক করার সুযোগ দেয়।
*   **Why this matters:** ডেটাবেস টেবিলে যা যা কলাম থাকে, C# এ সেগুলো প্রপার্টি হিসেবেই ম্যাপ করা হয়।

### **Lesson 13: কনস্ট্রাক্টর (Constructors)**

*   **Learning Goal:** অবজেক্ট তৈরির মুহূর্তেই (Birth time) কিছু ডেটা সেট করে দেওয়া।
*   **Simple Explanation:** যখনই `new ClassName()` কল করা হয়, তখনই এই স্পেশাল মেথডটা রান করে। ক্লাসের নাম আর মেথডের নাম হুবহু এক হয়।
*   **Funny Real-life Analogy:**
    বিরিয়ানিখানায় বসে "এক প্লেট কাচ্চি" অর্ডার দিলে (new Object), ওয়েটার কি খালি প্লেট দেয়? না! প্লেটে মাংস আর চাল দেওয়াই থাকে। এই যে শুরুতেই প্লেট রেডি করে দেওয়া—এটাই কনস্ট্রাক্টর।
*   **Code Example:**
    ```csharp
    public class Person
    {
        public string Name { get; set; }
        public string City { get; set; }

        // Constructor (নাম ক্লাসের নামের মতোই, কোনো return type নাই)
        public Person(string name, string city)
        {
            Name = name;
            City = city;
            Console.WriteLine("Notun manush toiri hoilo!");
        }
    }

    // Usage
    // তৈরির সময়ই নাম আর শহর দিতে হবে, মিস করার চান্স নাই
    Person p = new Person("Sakib", "Dhaka");
    Console.WriteLine(p.Name);
    ```
*   **Mini Exercise:** `Book` ক্লাস বানাও। কনস্ট্রাক্টর দিয়ে `Title` আর `Author` সেট করো। মেইন প্রোগ্রামে বইয়ের নাম প্রিন্ট করো।
*   **Common Mistakes:** কনস্ট্রাক্টর `private` করে ফেলা (তাহলে `new` দিয়ে অবজেক্ট বানানো যাবে না)।
*   **One-line Summary:** কনস্ট্রাক্টর হলো ইনিশিয়ালাইজার, যা অবজেক্ট তৈরির সময় কল হয়।
*   **Why this matters:** কোনো সার্ভিস বা ক্লাস রান করতে যা যা এসেনশিয়াল (যেমন ডেটাবেস কানেকশন), তা কনস্ট্রাক্টরেই চাওয়া হয় (Dependency Injection)।

### **Lesson 14: স্ট্যাটিক (Static) মেম্বার**

*   **Learning Goal:** অবজেক্ট না বানিয়েও ক্লাসের মেম্বার ব্যবহার করা।
*   **Simple Explanation:** নরমাল ভ্যারিয়েবল/মেথড প্রতিটা অবজেক্টের জন্য আলাদা আলাদা হয়। কিন্তু `static` দিলে সেটা সবার জন্য একটাই (Common)। এটা মেমোরিতে একবারই লোড হয়।
*   **Funny Real-life Analogy:**
    তোমার পকেটের টাকা (Instance Variable) শুধু তোমার। কিন্তু আকাশে চাঁদ (Static Variable) সবার জন্য একটাই। তুমি চাঁদ দেখলে যা দেখবে, তোমার বন্ধুও তাই দেখবে।
*   **Code Example:**
    ```csharp
    public class Calculator
    {
        // Static field
        public static double Pi = 3.1416;

        // Static method (Calculator new না করেই কল করা যাবে)
        public static int Add(int a, int b)
        {
            return a + b;
        }
    }

    // Usage
    // Calculator c = new Calculator(); // এটা লাগবে না!
    Console.WriteLine(Calculator.Pi);
    int sum = Calculator.Add(10, 20);
    ```
*   **Mini Exercise:** `CurrencyConverter` নামে একটা স্ট্যাটিক ক্লাস বানাও। `DollarToTaka(double dollar)` নামে একটা স্ট্যাটিক মেথড লেখো যা টাকার পরিমাণ রিটার্ন করবে (১ ডলার = ১২০ টাকা ধরো)।
*   **Common Mistakes:** স্ট্যাটিক মেথডের ভেতর নন-স্ট্যাটিক (Instance) ভ্যারিয়েবল কল করা (এটা সম্ভব না)।
*   **One-line Summary:** `static` মানে ক্লাসের সম্পত্তি, অবজেক্টের না।
*   **Why this matters:** ইউটিলিটি বা হেল্পার ফাংশন (যেমন: `DateTime.Now`, `Math.Max`) সব স্ট্যাটিক হয়।

### **Lesson 15: এনক্যাপসুলেশন (Encapsulation - Access Modifiers)**

*   **Learning Goal:** কোডের নিরাপত্তা এবং সিকিউরিটি মেইনটেইন করা।
*   **Simple Explanation:** এনক্যাপসুলেশন মানে ক্যাপসুলের মতো মুড়িয়ে রাখা। ক্লাসের ভেতরের জটিল জিনিস `private` করে লুকিয়ে রাখা, আর যতটুকু দরকার ততটুকু `public` করে দেওয়া।
*   **Funny Real-life Analogy:**
    ঔষধের ক্যাপসুল। ভেতরে তিতা ঔষধ (Private logic), বাইরে প্লাস্টিকের খোলস (Public interface)। তুমি খোলস দেখছ, ভেতরের কেমিক্যাল রিয়েকশন দেখছ না, দেখার দরকারও নাই।
*   **Code Example:**
    ```csharp
    public class BankAccount
    {
        private double _balance = 0; // কেউ বাইরে থেকে হ্যাক করে চেঞ্জ করতে পারবে না

        public void Deposit(double amount)
        {
            if (amount > 0)
            {
                _balance += amount;
                Console.WriteLine($"Joma Holo: {amount}");
            }
        }

        public double GetBalance()
        {
            return _balance; // শুধু ব্যালেন্স দেখতে পারবে, চেঞ্জ করতে পারবে না
        }
    }

    // Usage
    BankAccount myAcc = new BankAccount();
    myAcc.Deposit(500);
    // myAcc._balance = 100000; // ❌ Error! বাইরে থেকে এক্সেস নাই।
    Console.WriteLine($"Current Balance: {myAcc.GetBalance()}");
    ```
*   **Mini Exercise:** একটা `WifiRouter` ক্লাস বানাও। `Password` ফিল্ডটি প্রাইভেট রাখো। একটা মেথড বানাও `Connect(string pass)` যা পাসওয়ার্ড মিললে "Connected" প্রিন্ট করবে, না মিললে "Wrong Password"।
*   **Common Mistakes:** সব কিছু `public` করে দেওয়া (এটা ব্যাড প্র্যাকটিস)।
*   **One-line Summary:** এনক্যাপসুলেশন অপ্রয়োজনীয় এক্সেস বন্ধ করে এবং কোডকে সেফ রাখে।
*   **Why this matters:** বড় টিমে কাজ করার সময় অন্য ডেভেলপার যেন তোমার কোডের ক্রিটিকাল ভ্যারিয়েবল ভুলে চেঞ্জ না করে দেয়, তা নিশ্চিত করা।

### **✅ Milestone Exercise: Mini Bkash System**

**Question:**
একটি `BkashAccount` ক্লাস বানাও।
1. এতে `MobileNumber` (public) এবং `_balance` (private) থাকবে।
2. কনস্ট্রাক্টর দিয়ে মোবাইল নাম্বার সেট করবে এবং ওপেনিং ব্যালেন্স ৫০ টাকা দিবে।
3. `CashIn(int amount)` মেথড টাকা যোগ করবে।
4. `SendMoney(string number, int amount)` মেথড টাকা পাঠাবে। শর্ত: ব্যালেন্স থাকতে হবে এবং সেন্ড মানি চার্জ ৫ টাকা কাটবে।
5. শেষে ব্যালেন্স দেখাও।

**Solution:**
```csharp
using System;

public class BkashAccount
{
    public string MobileNumber { get; set; }
    private double _balance;

    // Constructor
    public BkashAccount(string mobile)
    {
        MobileNumber = mobile;
        _balance = 50; // Welcome Bonus
        Console.WriteLine($"Account create hoise: {MobileNumber}. Bonus: 50 tk.");
    }

    public void CashIn(int amount)
    {
        if (amount > 0)
        {
            _balance += amount;
            Console.WriteLine($"Cash In: {amount} Tk.");
        }
    }

    public void SendMoney(string receiver, int amount)
    {
        double totalCost = amount + 5; // 5 tk charge
        if (_balance >= totalCost)
        {
            _balance -= totalCost;
            Console.WriteLine($"Sent {amount} Tk to {receiver}. Charge 5 Tk.");
        }
        else
        {
            Console.WriteLine("Insufficient Balance mama!");
        }
    }

    public void CheckBalance()
    {
        Console.WriteLine($"Current Balance: {_balance} Tk.");
    }
}

// Program.cs
class Program
{
    static void Main()
    {
        BkashAccount myBkash = new BkashAccount("01711000000");
        myBkash.CashIn(500);
        myBkash.SendMoney("01911000000", 200);
        myBkash.CheckBalance();
    }
}
```
