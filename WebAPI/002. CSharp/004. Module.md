### **Lesson 16: ইনহেরিটেন্স (Inheritance) - বাপ কা বেটা**

*   **Learning Goal:** কোড ডুপ্লিকেট না করে প্যারেন্ট ক্লাস থেকে বৈশিষ্ট্য ধার করা।
*   **Simple Explanation:** ইনহেরিটেন্স মানে উত্তরাধিকার। বাবার সম্পত্তি যেমন সন্তান পায়, তেমনি প্যারেন্ট (Base) ক্লাসের পাবলিক মেথড বা ভ্যারিয়েবল চাইল্ড (Derived) ক্লাস অটোমেটিক পেয়ে যায়।
*   **Funny Real-life Analogy:**
    বাবার চোখের রং বা চুলের স্টাইল যেমন ছেলের মধ্যে চলে আসে (বংশগত), প্রোগ্রামিংয়েও তাই। তোমাকে নতুন করে চোখের কোড লিখতে হবে না, বাবারটা কপি হয়ে যাবে।
*   **Code Example:**
    ```csharp
    // Parent Class (বাবা)
    public class Animal
    {
        public void Eat()
        {
            Console.WriteLine("Khabar khacchi... Yum yum!");
        }
    }

    // Child Class (সন্তান) - ':' চিহ্ন দিয়ে ইনহেরিট করে
    public class Dog : Animal
    {
        public void Bark()
        {
            Console.WriteLine("Ghew Ghew!");
        }
    }

    // Program.cs
    Dog myDog = new Dog();
    myDog.Eat();  // Animal থেকে পেয়েছে (Magic!)
    myDog.Bark(); // নিজের মেথড
    ```
*   **File Structure:**
    ```
    ZooApp/
    ├── Animal.cs
    ├── Dog.cs
    └── Program.cs
    ```
*   **Mini Exercise:** `Vehicle` নামে একটা প্যারেন্ট ক্লাস বানাও যেখানে `Speed` ভ্যারিয়েবল আছে। `Car` নামে একটা চাইল্ড ক্লাস বানাও। `Car` অবজেক্ট দিয়ে `Speed` সেট করে প্রিন্ট করো।
*   **Common Mistakes:** প্রাইভেট (`private`) মেম্বার ইনহেরিট করা যায় না। প্যারেন্টের গোপন কথা সন্তান জানে না!
*   **One-line Summary:** `:` (কোলন) ব্যবহার করে এক ক্লাসের শক্তি আরেক ক্লাসে নেওয়া যায়।
*   **Why this matters:** কোড রিপিটেশন কমায়। হাজার হাজার লাইনের কোড বারবার লিখতে হয় না।

### **Lesson 17: পলিমরফিজম (Polymorphism) - বহুরূপী**

*   **Learning Goal:** একই মেথড, কিন্তু পরিস্থিতি অনুযায়ী ভিন্ন কাজ।
*   **Simple Explanation:** পলিমরফিজম মানে "বহুরূপ"। প্যারেন্ট ক্লাসে একটা মেথড আছে, কিন্তু চাইল্ড ক্লাস সেটাকে নিজের মতো করে সাজিয়ে নেয় (Override)।
*   **Funny Real-life Analogy:**
    "কথা বলা" (Speak)। মানুষ কথা বলে, কুকুর ঘেউ ঘেউ করে, বিড়াল মিউ মিউ করে। কাজ একটাই—শব্দ করা, কিন্তু একেকজনের স্টাইল একেক রকম।
*   **Code Example:**
    ```csharp
    public class Animal
    {
        // virtual মানে: "সন্তান চাইলে এটা চেঞ্জ করতে পারবে"
        public virtual void MakeSound()
        {
            Console.WriteLine("Animal sound...");
        }
    }

    public class Cat : Animal
    {
        // override মানে: "বাবারটা বাদ, আমি আমার স্টাইলে করব"
        public override void MakeSound()
        {
            Console.WriteLine("Meow Meow!");
        }
    }

    public class Dog : Animal
    {
        public override void MakeSound()
        {
            Console.WriteLine("Ghew Ghew!");
        }
    }

    // Program.cs
    Animal myCat = new Cat();
    myCat.MakeSound(); // Output: Meow Meow
    ```
*   **Mini Exercise:** `Employee` ক্লাসে `CalculateBonus()` মেথড রাখো। `Manager` ক্লাসে সেটাকে ওভাররাইড করে ডাবল বোনাস রিটার্ন করো।
*   **Common Mistakes:** প্যারেন্ট মেথডে `virtual` না লিখলে চাইল্ডে `override` করা যায় না।
*   **One-line Summary:** `virtual` এবং `override` দিয়ে মেথডের আচরণ পরিবর্তন করা যায়।
*   **Why this matters:** সফটওয়্যার ফ্লেক্সিবল করতে। যেমন পেমেন্ট সিস্টেমে `Pay()` মেথড একেক ব্যাংকের জন্য একেক রকম কাজ করবে।

### **Lesson 18: অ্যাবস্ট্রাক্ট ক্লাস (Abstract Class) - অসম্পূর্ণ নকশা**

*   **Learning Goal:** এমন ক্লাস যা সরাসরি ব্যবহার করা যায় না, ইনহেরিট করতেই হয়।
*   **Simple Explanation:** এটা একটা অসম্পূর্ণ ব্লু-প্রিন্ট। এখানে বলা থাকে "কী করতে হবে", কিন্তু বলা থাকে না "কীভাবে করতে হবে"। চাইল্ড ক্লাসকে জোর করে কাজটা করিয়ে নেওয়া হয়।
*   **Funny Real-life Analogy:**
    পরীক্ষার প্রশ্নপত্র। টিচার প্রশ্ন (Abstract method) দিয়ে দিয়েছে, উত্তর ফাঁকা। ছাত্রকে (Child Class) উত্তর লিখতেই হবে, না লিখলে ফেল (Error)।
*   **Code Example:**
    ```csharp
    // abstract ক্লাস - এর অবজেক্ট বানানো যাবে না
    public abstract class Shape
    {
        // abstract মেথড - এর কোনো বডি {} নাই
        public abstract double GetArea();
    }

    public class Circle : Shape
    {
        public double Radius { get; set; }

        // বাধ্য হয়ে ইমপ্লিমেন্ট করতে হবে
        public override double GetArea()
        {
            return 3.14 * Radius * Radius;
        }
    }

    // Program.cs
    // Shape s = new Shape(); // ❌ Error! এটা সম্ভব না।
    Circle c = new Circle { Radius = 5 };
    Console.WriteLine($"Area: {c.GetArea()}");
    ```
*   **Mini Exercise:** `MobilePhone` নামে অ্যাবস্ট্রাক্ট ক্লাস বানাও যেখানে `Call()` মেথড অ্যাবস্ট্রাক্ট। `Samsung` ক্লাসে সেটা ইমপ্লিমেন্ট করো।
*   **Common Mistakes:** অ্যাবস্ট্রাক্ট মেথডে বডি `{ }` দেওয়ার চেষ্টা করা।
*   **One-line Summary:** অ্যাবস্ট্রাক্ট ক্লাস হলো এমন টেমপ্লেট যা চাইল্ড ক্লাস পূরণ করতে বাধ্য থাকে।
*   **Why this matters:** যখন তুমি চাও সব ডেভেলপার নির্দিষ্ট কিছু নিয়ম মেনে ক্লাস বানাক।

### **Lesson 19: ইন্টারফেস (Interface) - কড়া চুক্তিপত্র**

*   **Learning Goal:** মাল্টিপল ইনহেরিটেন্সের সুবিধা এবং কড়াকড়ি রুলস।
*   **Simple Explanation:** ক্লাসের মতো দেখতে কিন্তু এতে কোনো কোড থাকে না, শুধু মেথডের নাম থাকে। একটা ক্লাস একাধিক ইন্টারফেস ইমপ্লিমেন্ট করতে পারে (যেটা ক্লাস ইনহেরিটেন্সে পারে না)। নামের আগে `I` দেওয়া কনভেনশন।
*   **Funny Real-life Analogy:**
    মাল্টিপ্লাগ সকেট। সকেটের ছিদ্র (Interface) নির্দিষ্ট। ফ্যান, টিভি, বা চার্জার (Classes)—যার পিন ওই সাইজের, সেই চলবে। ভেতরে কী কারেন্ট যাচ্ছে তা দেখার বিষয় না, পিন মিললেই হলো।
*   **Code Example:**
    ```csharp
    // চুক্তিপত্র
    public interface IPlayer
    {
        void Play(); // ডিফল্ট public, কোনো বডি নাই
        void Pause();
    }

    // Mp3Player চুক্তি সই করল (Implement)
    public class Mp3Player : IPlayer
    {
        public void Play() => Console.WriteLine("Gaan bajche...");
        public void Pause() => Console.WriteLine("Gaan thamlo.");
    }

    public class VideoPlayer : IPlayer
    {
        public void Play() => Console.WriteLine("Movie cholche...");
        public void Pause() => Console.WriteLine("Movie thamlo.");
    }
    ```
*   **Mini Exercise:** `ICamera` ইন্টারফেস বানাও যাতে `TakePhoto()` মেথড থাকে। `Phone` ক্লাস এটি ইমপ্লিমেন্ট করুক।
*   **Common Mistakes:** ইন্টারফেসের মেথড ক্লাসে `public` না করা।
*   **One-line Summary:** ইন্টারফেস বলে দেয় "কী কী ফিচার থাকতে হবে", ক্লাস ঠিক করে "কীভাবে কাজ করবে"।
*   **Why this matters:** মডার্ন সফটওয়্যার ডিজাইনে (Dependency Injection) ইন্টারফেস ছাড়া কিচ্ছু করা যায় না।

### **Lesson 20: Structs এবং Enums (ছোট ডেটা ও ফিক্সড অপশন)**

*   **Learning Goal:** ক্লাস ছাড়াও ডেটা রাখার হালকা উপায় এবং কনস্ট্যান্ট লিস্ট।
*   **Simple Explanation:**
    *   **Enum:** ফিক্সড কিছু অপশন। যেমন সপ্তাহের দিন, অর্ডারের স্ট্যাটাস।
    *   **Struct:** ক্লাসের ছোট ভাই। ছোটখাটো ডেটা (যেমন পয়েন্ট X, Y) রাখার জন্য। এটা মেমোরিতে কম জায়গা নেয় (Stack memory)।
*   **Funny Real-life Analogy:**
    *   **Enum:** রেস্টুরেন্টের মেনু কার্ড। মেনুতে যা আছে তাই অর্ডার করতে হবে, "ইট-পাথর" অর্ডার করা যাবে না।
    *   **Struct:** একটা দিয়াশলাই বাক্স। ছোট, হালকা, পকেটে রাখা যায়। আর ক্লাস হলো আস্ত বাড়ি।
*   **Code Example:**
    ```csharp
    // Enum
    enum OrderStatus { Pending, Shipped, Delivered }

    // Struct
    struct Point
    {
        public int X;
        public int Y;
    }

    // Program.cs
    OrderStatus status = OrderStatus.Shipped;
    if (status == OrderStatus.Delivered)
    {
        Console.WriteLine("Product peye gechi!");
    }

    Point p;
    p.X = 10;
    p.Y = 20;
    Console.WriteLine($"Position: {p.X}, {p.Y}");
    ```
*   **Mini Exercise:** `TrafficLight` নামে Enum বানাও (Red, Yellow, Green)। একটি `if` কন্ডিশন দিয়ে চেক করো Red হলে "Stop" প্রিন্ট করবে।
*   **One-line Summary:** ছোট ডেটার জন্য `Struct` এবং ফিক্সড লিস্টের জন্য `Enum`।
*   **Why this matters:** কোড রিডেবল করতে (০, ১, ২ না লিখে `Pending`, `Success` লেখা ভালো) এবং মেমোরি বাঁচাতে।

### **✅ Milestone Exercise: Payment Gateway System**

**Question:**
OOP এর কনসেপ্ট ব্যবহার করে একটা পেমেন্ট সিস্টেম বানাও।
1. `IPayment` ইন্টারফেস থাকবে যাতে `Pay(int amount)` মেথড থাকে।
2. `BkashPayment` এবং `NagadPayment` দুটি ক্লাস এই ইন্টারফেস ইমপ্লিমেন্ট করবে।
3. বিকাশে পেমেন্ট করলে ১.৫% চার্জ কাটবে, নগদে ১%।
4. মেইন প্রোগ্রামে পলিমরফিজম ব্যবহার করে পেমেন্ট সম্পন্ন করো।

**Solution:**
```csharp
using System;

// 1. Interface
public interface IPayment
{
    void Pay(double amount);
}

// 2. Bkash Implementation
public class BkashPayment : IPayment
{
    public void Pay(double amount)
    {
        double charge = amount * 0.015; // 1.5% charge
        double total = amount + charge;
        Console.WriteLine($"Bkash Payment: {amount} Tk. Charge: {charge} Tk. Total Cut: {total}");
    }
}

// 3. Nagad Implementation
public class NagadPayment : IPayment
{
    public void Pay(double amount)
    {
        double charge = amount * 0.01; // 1% charge
        double total = amount + charge;
        Console.WriteLine($"Nagad Payment: {amount} Tk. Charge: {charge} Tk. Total Cut: {total}");
    }
}

// 4. Program Execution
class Program
{
    static void Main()
    {
        // পলিমরফিজম: ভ্যারিয়েবল টাইপ IPayment, কিন্তু অবজেক্ট ভিন্ন
        IPayment method1 = new BkashPayment();
        method1.Pay(1000);

        IPayment method2 = new NagadPayment();
        method2.Pay(1000);
    }
}
```
