### **Lesson 36: Span`<T> এবং Memory<T> - সুপার ফাস্ট স্লাইসিং**

*   **Learning Goal:** স্ট্রিং বা অ্যারেকে মেমোরি কপি না করে প্রসেস করা।
*   **Simple Explanation:** সাধারণত আমরা যখন `Substring` করি, সি-শার্প নতুন একটা স্ট্রিং তৈরি করে মেমোরিতে জায়গা নেয়। এটা স্লো। `Span<T>` ব্যবহার করলে নতুন কিছু তৈরি হয় না, সে শুধু মেইন মেমোরির দিকে আঙুল দিয়ে দেখিয়ে দেয়।
*   **Funny Real-life Analogy:**
    তোমার কাছে একটা বড় পিৎজা আছে।
    *   **String/Array Copy:** পিৎজার একটা স্লাইস খাওয়ার জন্য আলাদা করে নতুন একটা ছোট পিৎজা বানানো (সময় ও খরচ বেশি)।
    *   **Span:** বড় পিৎজা থেকেই একটা স্লাইস কেটে নেওয়া (কোনো এক্সট্রা খরচ নাই)।
*   **Code Example:**
    ```csharp
    string text = "Hello World C# 14";

    // Old Way (Memory Waste)
    string sub = text.Substring(0, 5); // নতুন মেমোরি এলোকেটেড হলো

    // Pro Way (Span - Zero Allocation)
    ReadOnlySpan<char> span = text.AsSpan();
    ReadOnlySpan<char> slice = span.Slice(0, 5); // কোনো নতুন মেমোরি খরচ নাই!

    // Span কনসোলে প্রিন্ট করা যায়
    Console.WriteLine(slice.ToString()); // Hello
    ```
*   **Mini Exercise:** একটি বড় স্ট্রিং নাও "I am learning High Performance C#"। `Span` ব্যবহার করে শুধু "High Performance" অংশটুকু আলাদা করে ভ্যারিয়েবলে নাও।
*   **One-line Summary:** `Span<T>` হিপ মেমোরি ব্যবহার না করে ডেটা প্রসেস করে, তাই এটা সুপার ফাস্ট।

### **Lesson 37: IDisposable এবং Using - প্লেট ধুয়ে রাখা**

*   **Learning Goal:** আন-ম্যানেজড রিসোর্স (ফাইল, ডাটাবেস কানেকশন) ক্লিন করা।
*   **Simple Explanation:** C# এর গারবেজ কালেক্টর (GC) অটোমেটিক মেমোরি ক্লিন করে, কিন্তু ফাইলের লক বা ডাটাবেস কানেকশন সে ক্লিন করতে পারে না। কাজ শেষে এগুলো ম্যানুয়ালি `Dispose` করতে হয়। `using` কিওয়ার্ড দিলে এটা অটোমেটিক হয়ে যায়।
*   **Funny Real-life Analogy:**
    রেস্টুরেন্টে খাওয়া (Coding)।
    *   **Managed Resource:** খাওয়ার পর প্লেট-গ্লাস ওয়েটার নিয়ে যাবে (GC)।
    *   **Unmanaged Resource:** হাত ধোয়া। ওয়েটার তোমার হাত ধুইয়ে দিবে না, তোমাকেই ধুতে হবে (Dispose)।
*   **Code Example:**
    ```csharp
    // Modern 'using' syntax (C# 8+)
    // ব্লকের শেষে অটোমেটিক file.Dispose() কল হবে
    using var file = new StreamWriter("log.txt");
    
    file.WriteLine("Log checking...");
    file.WriteLine("Done.");
    // এখানে ফাইল অটো ক্লোজ হয়ে যাবে। আলাদা করে Close() কল করতে হবে না।
    ```
*   **Mini Exercise:** `using` ব্যবহার করে একটি ফাইল ওপেন করো এবং তাতে তোমার নাম লেখো। কোড শেষে ফাইলটি ডিলিট করার চেষ্টা করো (ম্যানুয়ালি) দেখবে ফাইল লক হয়ে নেই।
*   **Common Mistakes:** ফাইল ওপেন করে ক্লোজ না করা (এতে ফাইল লক হয়ে থাকে, অন্য কেউ ওপেন করতে পারে না)।
*   **One-line Summary:** `using` কিওয়ার্ড এনশিওর করে যে কাজ শেষে রিসোর্স ক্লিন বা ডিসপোজ হয়েছে।

### **Lesson 38: অ্যাট্রিবিউট এবং রিফ্লেকশন - কোডের পোস্টমর্টেম**

*   **Learning Goal:** কোডের মেটাডেটা (Metadata) পড়া এবং রানটাইমে সিদ্ধান্ত নেওয়া।
*   **Simple Explanation:**
    *   **Attributes:** কোডের গায়ে স্টিকার বা লেবেল লাগানো। যেমন: `[Obsolete]` মানে এই মেথড মেয়াদোত্তীর্ণ।
    *   **Reflection:** আয়নায় নিজেকে দেখার মতো। কোড রান করার সময় চেক করে "আমার ক্লাসের নাম কী?", "আমার কী কী মেথড আছে?"।
*   **Funny Real-life Analogy:**
    *   **Attribute:** ওষুধের বোতলে লেবেল (দাম, মেয়াদ)।
    *   **Reflection:** ফার্মাসিস্ট বোতলের লেবেল পড়ে সিদ্ধান্ত নেয় ওষুধটা বিক্রি করবে কি না।
*   **Code Example:**
    ```csharp
    public class User 
    {
        [Obsolete("এই মেথড পুরাতন, দয়া করে NewPrint ব্যবহার করুন।")]
        public void OldPrint() => Console.WriteLine("Old Printing...");

        public void NewPrint() => Console.WriteLine("New Printing...");
    }

    // Program.cs
    User u = new User();
    u.OldPrint(); // ওয়ার্নিং দিবে, কিন্তু কোড রান করবে।
    
    // Reflection Example
    Type t = typeof(User);
    Console.WriteLine($"Class Name: {t.Name}"); // ক্লাসের নাম প্রিন্ট করবে
    ```
*   **Mini Exercise:** তোমার ক্লাসের যেকোনো একটা মেথডে `[Obsolete]` অ্যাট্রিবিউট লাগাও এবং দেখো কম্পাইলার কী বলে।
*   **One-line Summary:** অ্যাট্রিবিউট দিয়ে তথ্য দেওয়া হয়, আর রিফ্লেকশন দিয়ে সেই তথ্য পড়া হয়।

### **Lesson 39: মাল্টি-থ্রেডিং এবং লক (Lock) - ট্রাফিক পুলিশ**

*   **Learning Goal:** একাধিক থ্রেড বা প্রসেস একসাথে চললে সংঘর্ষ এড়ানো।
*   **Simple Explanation:** যখন একাধিক থ্রেড একই ভ্যারিয়েবল বা রিসোর্স মডিফাই করতে চায়, তখন ডেটা উল্টাপাল্টা হতে পারে (Race Condition)। `lock` ব্যবহার করলে একবারে একজনই ঢুকতে পারে।
*   **Funny Real-life Analogy:**
    পাবলিক টয়লেট।
    একসাথে ৫ জন টয়লেট ব্যবহার করতে পারে না। একজন ঢুকলে দরজা লক করে দেয় (Lock)। সে বের হলে লক খোলে, তখন আরেকজন ঢুকতে পারে। লক না থাকলে মহাবিপদ! 🚽
*   **Code Example:**
    ```csharp
    class Counter
    {
        private int _count = 0;
        private readonly object _lock = new(); // তালার চাবি

        public void Increment()
        {
            lock (_lock) // দরজা বন্ধ করলাম
            {
                _count++; // কাজ করছি
                Console.WriteLine($"Count: {_count}");
            } // দরজা খুললাম
        }
    }
    ```
*   **Mini Exercise:** `lock` ছাড়া এবং `lock` সহ লুপ চালিয়ে দেখো কাউন্ট ভ্যালু ঠিক থাকে কি না (Parallel Looping এ)।
*   **One-line Summary:** `lock` এনশিওর করে যে ক্রিটিকাল কোড একবারে একটি থ্রেডই এক্সিকিউট করবে।

### **Lesson 40: ডিপেন্ডেন্সি ইনজেকশন (DI) - ব্যাটারি সিস্টেম**

*   **Learning Goal:** ক্লাসগুলোকে একে অপরের সাথে লুজলি কানেক্ট করা (Loose Coupling)।
*   **Simple Explanation:** একটা ক্লাসের ভেতর আরেকটা ক্লাস `new` করে তৈরি করা খারাপ অভ্যাস (Tight Coupling)। এর বদলে কনস্ট্রাক্টরের মাধ্যমে বাইরে থেকে অবজেক্ট পাস করা উচিত। এটাই DI।
*   **Funny Real-life Analogy:**
    রিমোট কন্ট্রোল।
    *   **Bad Code:** ব্যাটারি রিমোটের ভেতরে ঝালাই করা (ফিক্সড)। ব্যাটারি নষ্ট হলে রিমোটও শেষ।
    *   **Good Code (DI):** ব্যাটারি বাইরে থেকে ঢুকানো যায়। তুমি চাইলে সনি ব্যাটারি লাগাও, বা নিপ্পো লাগাও—রিমোটের কিছু যায় আসে না।
*   **Code Example:**
    ```csharp
    // 1. Interface (ব্যাটারির সাইজ)
    interface IEngine { void Start(); }

    // 2. Implementations (বিভিন্ন ব্র্যান্ডের ব্যাটারি)
    class PetrolEngine : IEngine { public void Start() => Console.WriteLine("Petrol Start"); }
    class ElectricEngine : IEngine { public void Start() => Console.WriteLine("Silent Start"); }

    // 3. Consumer (রিমোট/গাড়ি)
    class Car 
    {
        private IEngine _engine;
        
        // Constructor Injection: বাইরে থেকে ইঞ্জিন আসছে
        public Car(IEngine engine) 
        {
            _engine = engine; 
        }

        public void Drive() => _engine.Start();
    }

    // Usage
    Car myCar = new Car(new ElectricEngine()); // আমি ঠিক করলাম কোন ইঞ্জিন দিব
    myCar.Drive();
    ```
*   **Mini Exercise:** `ILogger` ইন্টারফেস বানাও। `ConsoleLogger` এবং `FileLogger` বানাও। তোমার `App` ক্লাসে `ILogger` ইনজেক্ট করে মেসেজ লগ করো।
*   **One-line Summary:** DI কোডকে ফ্লেক্সিবল এবং টেস্ট-ফ্রেন্ডলি করে।

### **✅ Milestone Exercise: Thread-Safe Logger**

**Question:**
একটি `SafeLogger` ক্লাস বানাও যা ফাইল সিস্টেমে লগ লিখবে।
1. `WriteLog(string msg)` মেথড থাকবে।
2. মাল্টিপল থ্রেড একসাথে লগ লিখতে চাইলেও যেন ফাইলে লেখা ওলটপালট না হয়, তাই `lock` ব্যবহার করো।
3. ফাইল হ্যান্ডলিংয়ের জন্য `StreamWriter` এবং `using` ব্যবহার করো (প্রতিবার লেখার সময় ওপেন ও ক্লোজ করো সিম্পল রাখার জন্য)।

**Solution:**
```csharp
using System;
using System.IO;
using System.Threading;
using System.Threading.Tasks;

public class SafeLogger
{
    private readonly object _lockObj = new(); // তালা
    private string _filePath = "app_log.txt";

    public void WriteLog(string message)
    {
        // লক থাকার কারণে একবারে একজনই এই ব্লকে ঢুকবে
        lock (_lockObj)
        {
            try
            {
                // using: কাজ শেষে অটো ফাইল ক্লোজ হবে
                using var writer = new StreamWriter(_filePath, append: true);
                writer.WriteLine($"[{DateTime.Now}] : {message}");
                Console.WriteLine("Log written.");
            }
            catch (Exception ex)
            {
                Console.WriteLine("Logging failed: " + ex.Message);
            }
        }
    }
}

class Program
{
    static void Main()
    {
        SafeLogger logger = new SafeLogger();

        // Parallel এ ৫ জন ইউজার লগ করার চেষ্টা করছে
        Parallel.For(0, 5, i =>
        {
            logger.WriteLog($"User {i} clicked a button.");
        });
    }
}
```
*Note:* `Parallel.For` একসাথে অনেকগুলো থ্রেড চালায়। লক না থাকলে ফাইলে লেখাগুলো একটার উপর আরেকটা উঠে যেত বা এরর দিত।
