### **Lesson 41: ইউনিট টেস্টিং (xUnit) - কোডের কোয়ালিটি কন্ট্রোল**

*   **Learning Goal:** নিজের কোড ঠিকমতো কাজ করছে কি না, তা ম্যানুয়ালি চেক না করে অটোমেটিক চেক করা।
*   **Simple Explanation:** প্রতিবার কোড চেঞ্জ করে অ্যাপ রান করা এবং বাটন টিপে টিপে চেক করা বোকামি। আমরা এমন কিছু ছোট কোড লিখব (Test Code) যা আমাদের মেইন কোডকে পরীক্ষা করবে। C# এ `xUnit` বা `NUnit` জনপ্রিয়।
*   **Funny Real-life Analogy:**
    গাড়ি বানানোর ফ্যাক্টরি। গাড়ি রাস্তায় নামানোর আগে রোবট দিয়ে চেক করা হয় ব্রেক কাজ করে কি না। ড্রাইভার দিয়ে রাস্তায় নামিয়ে চেক করা রিস্কি! এই রোবট চেকিংটাই হলো **Unit Test**।
*   **Code Example:**
    1. প্রজেক্টে `xUnit` টেস্ট প্রজেক্ট অ্যাড করতে হয়।
    2. টেস্ট মেথডের উপরে `[Fact]` অ্যাট্রিবিউট দিতে হয়।
    ```csharp
    // মেইন কোড (Calculator.cs)
    public class Calculator
    {
        public int Add(int a, int b) => a + b;
    }

    // টেস্ট কোড (CalculatorTests.cs)
    using Xunit; // xUnit লাইব্রেরি

    public class CalculatorTests
    {
        [Fact] // এটা একটা টেস্ট কেস
        public void Add_ShouldReturnSum_WhenNumbersArePositive()
        {
            // Arrange (প্রস্তুতি)
            var calc = new Calculator();
            
            // Act (কাজ)
            int result = calc.Add(2, 3);
            
            // Assert (যাচাই) - রেজাল্ট ৫ না হলে টেস্ট ফেইল করবে
            Assert.Equal(5, result); 
        }
    }
    ```
*   **Mini Exercise:** তোমার ক্যালকুলেটরে `Multiply` মেথড যোগ করো। এরপর একটা টেস্ট লেখো যা চেক করবে `Multiply(3, 4)` এর রেজাল্ট `12` কি না।
*   **One-line Summary:** ইউনিট টেস্ট হলো কোডের সুরক্ষা কবচ; কোড চেঞ্জ করলে বা বাগ থাকলে সে লাল বাতি জ্বালাবে।

### **Lesson 42: SOLID প্রিন্সিপালস - ক্লিন কোডের ৫টি স্তম্ভ**

*   **Learning Goal:** কোড এমনভাবে লেখা যেন ভবিষ্যতে এডিট করতে গেলে পুরো সিস্টেম ভেঙে না পড়ে।
*   **Simple Explanation:** SOLID হলো ৫টি রুলসের আদ্যক্ষর।
    *   **S** (Single Responsibility): এক ক্লাসের এক কাজ।
    *   **O** (Open/Closed): এক্সটেনশন করা যাবে, কিন্তু মেইন কোড মডিফাই করা যাবে না।
    *   **L** (Liskov): চাইল্ড ক্লাস প্যারেন্টের মতোই আচরণ করবে।
    *   **I** (Interface Segregation): দরকারি ইন্টারফেস বানাও, বিশাল বড় না।
    *   **D** (Dependency Inversion): ক্লাসের ভেতর ক্লাস না বানিয়ে ইন্টারফেসের ওপর নির্ভর করো (DI)।
*   **Funny Real-life Analogy (S - SRP):**
    সুইসবয় চাকু। এতে ছুরি, কাঁচি, চামচ সব আছে। কিন্তু এটা দিয়ে কি ভালো রান্না করা যায়? না!
    ভালো শেফের কাছে মাংস কাটার ছুরি আলাদা, সবজির ছুরি আলাদা। কোডেও তাই—এক ক্লাস দিয়ে সব করাবে না।
*   **Code Example (SRP - Single Responsibility):**
    ```csharp
    // ❌ Bad Design: এক ক্লাসেই সব কাজ
    class Report
    {
        public void GenerateData() { /*...*/ }
        public void SaveToFile() { /*...*/ } // সেভ করা রিপোর্টের কাজ না
    }

    // ✅ Good Design: কাজ ভাগ করা
    class ReportGenerator 
    {
        public string GetData() => "Report Data";
    }

    class ReportSaver 
    {
        public void Save(string data) => File.WriteAllText("rep.txt", data);
    }
    ```
*   **Mini Exercise:** একটি `User` ক্লাস আছে যার ভেতর `Login()`, `Register()`, এবং `SendEmail()` মেথড আছে। SRP অনুযায়ী এটাকে ভেঙে আলাদা ক্লাস করো (`UserAuth`, `EmailService`)।
*   **One-line Summary:** SOLID প্রিন্সিপাল মানলে কোড মেনটেইন করা পানির মতো সহজ হয়।

### **Lesson 43: ডিজাইন প্যাটার্ন (Singleton & Factory)**

*   **Learning Goal:** কমন প্রবলেমের স্ট্যান্ডার্ড সমাধান শেখা।
*   **Simple Explanation:**
    *   **Singleton:** পুরো অ্যাপে একটি ক্লাসের মাত্র একটিই অবজেক্ট থাকবে। (যেমন: প্রধানমন্ত্রীর পদ)।
    *   **Factory:** অবজেক্ট তৈরির দায়িত্ব আলাদা ফ্যাক্টরি ক্লাসের। (যেমন: কেকের দোকানে তুমি বললেই কেক দেয়, তোমার বানাতে হয় না)।
*   **Code Example (Singleton):**
    ```csharp
    public sealed class DatabaseConnection
    {
        // 1. Static Instance
        private static DatabaseConnection _instance = null;
        private static readonly object _lock = new object();

        // 2. Private Constructor (বাইরে থেকে new করা যাবে না)
        private DatabaseConnection() 
        { 
            Console.WriteLine("Database Connected!"); 
        }

        // 3. Public access method
        public static DatabaseConnection Instance
        {
            get
            {
                lock(_lock) // Thread Safety
                {
                    if (_instance == null)
                    {
                        _instance = new DatabaseConnection();
                    }
                    return _instance;
                }
            }
        }
    }
    
    // Usage: যতবারই কল করো, অবজেক্ট একটাই
    var db1 = DatabaseConnection.Instance;
    var db2 = DatabaseConnection.Instance; // নতুন তৈরি হবে না, আগেরটাই দিবে
    ```
*   **Mini Exercise:** `Logger` নামে একটি সিঙ্গেলটন ক্লাস বানাও যাতে সব জায়গা থেকে একটাই লগ ফাইল অ্যাক্সেস হয়।
*   **One-line Summary:** ডিজাইন প্যাটার্ন হলো চাকা নতুন করে আবিষ্কার না করে পরীক্ষিত চাকা ব্যবহার করা।

### **Lesson 44: রিপোজিটরি প্যাটার্ন (Repository Pattern)**

*   **Learning Goal:** ডেটাবেস লজিক মেইন কোড থেকে আলাদা করা।
*   **Simple Explanation:** মেইন প্রজেক্ট (Controller/UI) সরাসরি ডাটাবেস বা ফাইল ধরবে না। মাঝখানে একজন "স্টোরকিপার" (Repository) থাকবে। মেইন কোড স্টোরকিপারকে বলবে "ডাটা দাও", স্টোরকিপার কোথা থেকে আনবে সেটা তার ব্যাপার।
*   **Funny Real-life Analogy:**
    ফার্মেসির দোকানদার। তুমি কাউন্টারে গিয়ে ওষুধ চাও। দোকানদার পেছনের র‍্যাক (Database) থেকে খুঁজে আনে। তুমি জানো না কোন তাকে ওষুধ আছে, জানার দরকারও নেই। দোকানদারই হলো **Repository**।
*   **Code Example:**
    ```csharp
    // Interface (চুক্তি)
    public interface IUserRepository
    {
        void AddUser(string name);
        List<string> GetAllUsers();
    }

    // Implementation (স্টোরকিপার)
    public class UserRepository : IUserRepository
    {
        private List<string> _db = new(); // এটা আসল DB হতে পারে

        public void AddUser(string name) => _db.Add(name);
        public List<string> GetAllUsers() => _db;
    }

    // Usage (Main Code)
    IUserRepository repo = new UserRepository(); // DI দিয়ে আসলে আরও ভালো হয়
    repo.AddUser("Rahim");
    ```
*   **Mini Exercise:** `IProductRepository` ইন্টারফেস বানাও এবং একটি `FakeProductRepository` ক্লাস দিয়ে সেটা ইমপ্লিমেন্ট করো।
*   **One-line Summary:** রিপোজিটরি প্যাটার্ন ব্যবহার করলে ভবিষ্যতে ডাটাবেস চেঞ্জ করা (SQL to MongoDB) সহজ হয়, মেইন কোডে হাত দিতে হয় না।

### **Lesson 45: প্রজেক্ট সেটআপ (Layered Architecture)**

*   **Learning Goal:** একটি রিয়েল-ওয়ার্ল্ড প্রজেক্টের ফোল্ডার স্ট্রাকচার সাজানো।
*   **Simple Explanation:** সব ফাইল এক জায়গায় না রেখে কাজের ধরণ অনুযায়ী আলাদা লেয়ার বা ফোল্ডারে রাখা। সাধারণত ৩-৪টি লেয়ার থাকে।
*   **File / Project Structure:**
    ```
    MyTodoApp/
    ├── MyTodoApp.sln (Solution File)
    │
    ├── src/
    │   ├── MyTodoApp.Core (Class Library)
    │   │   ├── Models/ (TodoItem.cs)
    │   │   └── Interfaces/ (ITodoRepository.cs)
    │   │
    │   ├── MyTodoApp.Data (Class Library)
    │   │   └── Repositories/ (TodoRepository.cs)
    │   │
    │   ├── MyTodoApp.Service (Class Library)
    │   │   └── TodoService.cs (Business Logic)
    │   │
    │   └── MyTodoApp.UI (Console App / Web API)
    │       └── Program.cs
    │
    └── tests/
        └── MyTodoApp.Tests (xUnit Project)
    ```
*   **Why this matters:**
    *   **Core:** প্রজেক্টের হার্ট। এখানে কোনো থার্ড পার্টি লাইব্রেরি থাকে না।
    *   **UI:** শুধু চেহারা। সে লজিক জানে না, সার্ভিসকে কল করে।
*   **Mini Exercise:** তোমার পিসিতে ফোল্ডার খুলে এবং `dotnet new classlib` কমান্ড দিয়ে এই স্ট্রাকচারটি বানানোর চেষ্টা করো।
*   **One-line Summary:** লেয়ার্ড আর্কিটেকচার বড় প্রজেক্টকে অর্গানাইজড এবং ক্লিন রাখে।

### **✅ Milestone Exercise: Tested Logic**

**Question:**
একটি `DiscountService` ক্লাস বানাও।
1. মেথড: `GetDiscountedPrice(double price)`.
2. লজিক: প্রাইস ৫০০ টাকার বেশি হলে ১০% ডিসকাউন্ট, নাহলে ০%।
3. এই লজিকটি টেস্ট করার জন্য একটি xUnit টেস্ট ক্লাস লেখো।

**Solution:**
```csharp
// 1. Service Code
public class DiscountService
{
    public double GetDiscountedPrice(double price)
    {
        if (price > 500)
        {
            return price - (price * 0.10); // 10% off
        }
        return price;
    }
}

// 2. Test Code (In Test Project)
using Xunit;

public class DiscountServiceTests
{
    [Fact]
    public void GetDiscountedPrice_ShouldApply10Percent_WhenPriceIsAbove500()
    {
        // Arrange
        var service = new DiscountService();
        double originalPrice = 1000;
        double expectedPrice = 900; // 1000 - 100

        // Act
        double actualPrice = service.GetDiscountedPrice(originalPrice);

        // Assert
        Assert.Equal(expectedPrice, actualPrice);
    }

    [Fact]
    public void GetDiscountedPrice_ShouldNotApplyDiscount_WhenPriceIsLow()
    {
        var service = new DiscountService();
        Assert.Equal(400, service.GetDiscountedPrice(400));
    }
}
```
