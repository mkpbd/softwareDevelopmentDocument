### 🎓 Lesson 1: Authentication vs Authorization - আসলে কাহিনীটা কি?

শুরুতেই কোডিং-এ ঝাঁপ দিব না। আগে কনসেপ্ট ক্লিয়ার করতে হবে। আমাদের পুরো কোর্সের মূল ভিত্তি হলো দুইটা শব্দ:
1.  **Authentication (AuthN)**
2.  **Authorization (AuthZ)**

অনেকে এই দুইটাকে গুলিয়ে ফেলে খিচুড়ি বানিয়ে দেয়। কিন্তু দুইটা সম্পূর্ণ আলাদা জিনিস।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Authentication (কে তুমি?):** সিস্টেম চেক করবে তুমি আসলে কে। তোমার ইউজারনেম আর পাসওয়ার্ড ঠিক আছে কিনা। মানে সিস্টেমে ঢোকার টিকিট তোমার কাছে আছে কিনা।
*   **Authorization (তোমার ক্ষমতা কতটুকু?):** সিস্টেমে তো ঢুকলে, এখন তুমি কি কি করতে পারবে? তুমি কি শুধু ডাটা দেখতে পারবে নাকি ডিলিটও করতে পারবে?

#### 🤣 ফানি অ্যানালজি (বিয়ে বাড়ির গল্প)

ধরো, তোমার এলাকায় একটা **বিয়ে বাড়ি (Wedding Ceremony)** চলছে। গেটে দারোয়ান মামা দাঁড়িয়ে আছে।

১. **Authentication (AuthN):**
তুমি গেটে গেলে। দারোয়ান বলল, *"মামা, দাওয়াত কার্ড দেখান।"*
তুমি কার্ড দেখালে। দারোয়ান দেখল কার্ডটা আসল। সে বলল, *"জি স্যার, ভেতরে যান।"*
👉 এই যে তুমি প্রমাণ করলে তুমি দাওয়াত পেয়েছ, এটাই **Authentication**। তুমি ভ্যালিড গেস্ট।

২. **Authorization (AuthZ):**
এখন তুমি ভেতরে ঢুকে সোজা **"বর-কনে"** এর স্টেজে গিয়ে বরের চেয়ারে বসে পড়তে চাইলে।
ম্যানেজার এসে বলল, *"ও ভাই! থামেন! আপনি গেস্ট, আপনার বসার জায়গা ওই কোণায়। বরের চেয়ারে বসার পারমিশন (Role) আপনার নাই।"*
অথবা, তুমি বাবুর্চিকে গিয়ে বললে, *"এক পিস খাসির লেগ রোস্ট এক্সট্রা দেন।"* বাবুর্চি দেখল তোমার ব্যাজে লেখা **"বর-যাত্রী"** (Role), তাই সে দিল।
👉 এই যে তোমার **Role** (গেস্ট নাকি বর-যাত্রী) দেখে ঠিক করা হলো তুমি কী পাবে আর কী পাবে না, এটাই **Authorization**।

#### 💻 Coding Example (.NET 10 Web API Setup)

আজকে আমরা শুধু প্রজেক্ট সেটআপ করব এবং প্যাকেজ ইন্সটল করব।

**Step 1:** তোমার টার্মিনাল (CMD/PowerShell) ওপেন করো এবং কমান্ড দাও:
*(ধরে নিচ্ছি তোমার পিসিতে .NET SDK ইন্সটল করা আছে)*

```bash
# ১. নতুন একটা Web API প্রজেক্ট খোলা
dotnet new webapi -n AuthMasterClass

# ২. ফোল্ডারে ঢোকা
cd AuthMasterClass

# ৩. Identity এবং Entity Framework এর প্যাকেজ নামানো (ইঞ্জিন আর চাকা)
dotnet add package Microsoft.AspNetCore.Identity.EntityFrameworkCore
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Tools
```

**Step 2:** `AuthMasterClass` ফোল্ডারটি VS Code বা Visual Studio তে ওপেন করো। দেখবে অনেক ফাইল তৈরি হয়েছে। ভয় পাওয়ার কিছু নেই।

আমরা জাস্ট চেক করব প্যাকেজগুলো ঠিকঠাক `AuthMasterClass.csproj` ফাইলে এসেছে কিনা। ফাইলটা ওপেন করলে নিচের মতো কিছু দেখতে পাবে:

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework> <!-- অথবা net9.0/8.0 -->
  </PropertyGroup>

  <ItemGroup>
    <!-- এইগুলো আমাদের মেইন অস্ত্র -->
    <PackageReference Include="Microsoft.AspNetCore.Identity.EntityFrameworkCore" Version="x.x.x" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" Version="x.x.x" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.Tools" Version="x.x.x" />
  </ItemGroup>
</Project>
```

### 🎓 Lesson 2: Database Connection & The Magic of `IdentityDbContext`

কোডিং-এ যাওয়ার আগে বুঝতে হবে আমরা ডাটাবেস এর সাথে আমাদের কোডকে কিভাবে কানেক্ট করব। এখানে আমাদের হিরো হলো **Entity Framework Core (EF Core)**।

কিন্তু যেহেতু আমরা **Authentication** নিয়ে কাজ করছি, আমরা সাধারণ `DbContext` ব্যবহার করব না। আমরা ব্যবহার করব `IdentityDbContext`।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
সাধারণত ডাটাবেসে টেবিল বানাতে হয় `CREATE TABLE...` লিখে। কিন্তু .NET-এ আমরা কোড লিখব, আর কোড জাদুর মতো ডাটাবেসে টেবিল বানিয়ে দিবে (Code First Approach)।

`IdentityDbContext` হলো মাইক্রোসফটের বানিয়ে দেওয়া একটা রেডিমেড টেম্পলেট। এটা ব্যবহার করলে `Users`, `Roles`, `Logins`, `Tokens`—এইসব জটিল টেবিলগুলো আমাদের কষ্ট করে বানাতে হবে না। অটোমেটিক তৈরি হয়ে যাবে।

#### 🤣 ফানি অ্যানালজি (দোকানের বাকি খাতা)

ধরো, তুমি একটা মুদি দোকান (App) দিয়েছ। কাস্টমারদের নাম আর বাকির হিসাব রাখার জন্য তোমার একটা **"লাল খাতা" (Database)** লাগবে।

১. **DbContext:** এটা হলো তোমার সেই **"লাল খাতা"**। তুমি কোডে যা লিখবে (Product, Order), খাতায় তা উঠে যাবে।
২. **IdentityDbContext:** এটা হলো এমন একটা স্পেশাল খাতা, যেটা বাজার থেকে কেনার সময় কোম্পানি আগে থেকেই **"নাম", "মোবাইল", "পাসওয়ার্ড"**—এসব ঘর (Column) প্রিন্ট করে দিয়েছে। তোমাকে আর রুলার দিয়ে দাগ টানতে হবে না।
৩. **Connection String:** এটা হলো ওই ড্রয়ারের চাবি বা লোকেশন, যেখানে তুমি খাতাটা লুকিয়ে রেখেছ। চাবি ভুল হলে দোকানদার (App) খাতা খুঁজে পাবে না।

#### 💻 Coding Example (.NET 10 Web API)

আজকে আমরা ৩টি ফাইলে হাত দিব। ফোল্ডার স্ট্রাকচার সুন্দর রাখা ভালো প্র্যাকটিস।

**Step 1: User Model বানানো**
প্রজেক্টে একটা `Models` ফোল্ডার বানাও। তার ভেতরে `AppUser.cs` নামে একটা ক্লাস বানাও।
আমরা `IdentityUser` কে ইনহেরিট করব, যাতে ডিফল্ট ফিচারের সাথে আমরা নিজেদের কিছু ফিল্ড (যেমন: FullName) যোগ করতে পারি।

```csharp
// Models/AppUser.cs
using Microsoft.AspNetCore.Identity;

namespace AuthMasterClass.Models
{
    // IdentityUser এর ভেতরে আগে থেকেই UserName, Email, PasswordHash, PhoneNumber আছে।
    // আমরা জাস্ট এক্সট্রা যা লাগে তা এড করব।
    public class AppUser : IdentityUser
    {
        public string? FullName { get; set; } // মামা, নাম তো জানতেই হবে!
    }
}
```

**Step 2: Database Context বানানো**
প্রজেক্টে `Data` ফোল্ডার বানাও। তার ভেতরে `AppDbContext.cs` ফাইল নাও।

```csharp
// Data/AppDbContext.cs
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;

namespace AuthMasterClass.Data
{
    // সাধারণ DbContext না, আমরা IdentityDbContext ব্যবহার করছি
    // <AppUser> বলে দিচ্ছি যাতে সে আমাদের কাস্টম ইউজার ক্লাস চিনে নেয়
    public class AppDbContext : IdentityDbContext<AppUser>
    {
        public AppDbContext(DbContextOptions<AppDbContext> options) : base(options)
        {
            
        }
    }
}
```

**Step 3: Connection String সেট করা (খাতার লোকেশন)**
তোমার প্রজেক্টের `appsettings.json` ফাইলটা ওপেন করো। সেখানে `ConnectionStrings` সেকশনটা এড করো। (তোমার পিসির SQL Server এর নাম দিবে)।

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  
  // এই অংশটুকু সাবধানে এড করো মামা
  "ConnectionStrings": {
    "DefaultConnection": "Server=YOUR_PC_NAME\\SQLEXPRESS;Database=AuthMasterDB;Trusted_Connection=True;TrustServerCertificate=True;"
  }
}
```
*(নোট: `YOUR_PC_NAME\\SQLEXPRESS` এর জায়গায় তোমার এস.কিউ.এল সার্ভারের নাম দিবে। যদি লোকাল ডিবি হয়, `(localdb)\\mssqllocaldb` দিতে পারো)*

**Step 4: Program.cs এ রেজিস্টার করা (Dependency Injection)**
এখন অ্যাপ চালু হওয়ার সময় বলে দিতে হবে যে আমরা এই ডাটাবেস আর আইডেন্টিটি ব্যবহার করতে চাই। `Program.cs` ফাইল ওপেন করো:

```csharp
using AuthMasterClass.Data;
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

// Add services to the container.

// ১. ডাটাবেস কানেকশন চিনিয়ে দেওয়া হলো
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

// ২. আইডেন্টিটি কনফিগারেশন (পাসওয়ার্ড রুলস, ইউজার টাইপ ইত্যাদি)
builder.Services.AddIdentity<AppUser, IdentityRole>(options =>
    {
        options.Password.RequireDigit = true;
        options.Password.RequireLowercase = true;
        options.Password.RequiredLength = 6;
    })
    .AddEntityFrameworkStores<AppDbContext>() // কোন ডিবিতে ডাটা রাখবে
    .AddDefaultTokenProviders(); // টোকেন জেনারেটর (পরে লাগবে)

builder.Services.AddControllers();
// ... বাকি কোড যেমন আছে
var app = builder.Build();
// ...
app.Run();
```

আজকে আমরা **জাদুকরী কমান্ড** দিয়ে সেই ডাটাবেস তৈরি করব। এই প্রসেসটাকে বলে **Migration**।

তুমি তোমার কোডে `AppUser` ক্লাস বানিয়েছ। এখন ডাটাবেসে হুবহু এরকম কলামসহ একটা টেবিল বানাতে হবে।
ম্যানুয়ালি `CREATE TABLE Users...` লেখা অনেক বোরিং এবং ভুলের সম্ভাবনা থাকে।
**Migration** তোমার C# ক্লাসগুলো দেখে অটোমেটিক একটা SQL স্ক্রিপ্ট রেডি করে দেয়, তারপর সেটা ডাটাবেসে চালিয়ে দেয়।

#### 🤣 ফানি অ্যানালজি (বাড়ি তৈরির নকশা ও রাজমিস্ত্রি)

ধরো, তুমি বাড়ি বানাবে।

১. **Model Classes:** এটা হলো আর্কিটেক্টের বানানো **বাড়ির নকশা (Blueprint)**। তুমি কাগজে এঁকেছ কোথায় রান্নাঘর হবে, কোথায় বেডরুম হবে। (কিন্তু জমি এখনো খালি)।
২. **Add Migration:** তুমি নকশাটা রাজমিস্ত্রির হাতে দিলে। রাজমিস্ত্রি নকশা দেখে একটা **ফর্দ (List)** বানালো—"আচ্ছা, ১০ বস্তা সিমেন্ট লাগবে, ৫০০০ ইট লাগবে, ৩টা দেয়াল হবে।" এই ফর্দটাই হলো মাইগ্রেশন ফাইল।
৩. **Update Database:** এবার রাজমিস্ত্রি কাজ শুরু করল—ইট, বালু দিয়ে **ঢালাই** দিয়ে বাড়িটা বাস্তবে দাঁড় করিয়ে ফেলল। এটা হলো ফাইনাল কমান্ড।

#### 💻 Action Time (Commands)

আজকে কোড লিখব না, টার্মিনালে কমান্ড দিব। তোমার VS Code এর টার্মিনাল বা CMD ওপেন করো। (অবশ্যই প্রজেক্ট ফোল্ডারের ভেতরে থাকতে হবে)।

**Step 1: টুলস চেক করা**
তোমার পিসিতে `dotnet ef` টুল ইন্সটল করা আছে কিনা চেক করো। না থাকলে নিচের কমান্ডটা দাও:

```bash
dotnet tool install --global dotnet-ef
```
*(যদি বলে already installed, তাহলে আলহামদুলিল্লাহ!)*

**Step 2: মাইগ্রেশন ফাইল তৈরি করা (রাজমিস্ত্রির ফর্দ)**
আমরা প্রথম মাইগ্রেশন তৈরি করব। কমান্ড দাও:

```bash
dotnet ef migrations add InitialAuthSetup
```
*এখানে `InitialAuthSetup` হলো মাইগ্রেশনের নাম। তুমি যা খুশি দিতে পারো (যেমন: FirstMigration), তবে অর্থপূর্ণ নাম দেওয়া ভালো।*

👉 **কি হলো?**
তোমার প্রজেক্টে `Migrations` নামে একটা ফোল্ডার তৈরি হয়েছে। ভেতরে ঢুকে দেখবে অদ্ভুত সব কোড। ভয় পাওয়ার কিছু নেই, ওটা অটোমেটিক জেনারেট হয়েছে। ওটাই রাজমিস্ত্রির ফর্দ।

**Step 3: ডাটাবেস আপডেট করা (বাড়ির ঢালাই)**
এখনো কিন্তু ডাটাবেস তৈরি হয়নি, জাস্ট ফাইল রেডি হয়েছে। আসল কাজ হবে এখন। কমান্ড দাও:

```bash
dotnet ef database update
```

👉 **কি হলো?**
টার্মিনালে যদি সবুজ কালারে `Done.` লেখা দেখো, তার মানে কেল্লাফতে! 🎉
তোমার SQL Server-এ `AuthMasterDB` নামে ডাটাবেস তৈরি হয়ে গেছে এবং তার ভেতরে Identity-র সব টেবিল চলে এসেছে।

#### 🕵️‍♂️ কি কি টেবিল তৈরি হলো?

যদি তুমি SQL Server Management Studio (SSMS) বা Azure Data Studio দিয়ে ডাটাবেস চেক করো, দেখবে নিচের টেবিলগুলো তৈরি হয়েছে:

1.  **AspNetUsers:** এটাই মেইন। ইউজারদের নাম, ইমেইল, পাসওয়ার্ড সব এখানে থাকবে।
2.  **AspNetRoles:** কে এডমিন, কে ইউজার—এসব রোল এখানে থাকবে।
3.  **AspNetUserRoles:** কোন ইউজারের কোন রোল আছে, সেই লিংক।
4.  **AspNetUserClaims:** ইউজারের এক্সট্রা ইনফরমেশন।
5.  **AspNetUserTokens:** ইমেইল ভেরিফিকেশন বা পাসওয়ার্ড রিসেট টোকেন।

*(খেয়াল করো: সব টেবিলের আগে `AspNet` প্রিফিক্স আছে। এটা আইডেন্টিটির সিগনেচার!)*

### 🎓 Lesson 4: DTO (Data Transfer Object) & Auth Controller Setup

আজকের টপিক খুব ইম্পরট্যান্ট। অনেকেই আলসেমি করে সরাসরি ডাটাবেস মডেল ব্যবহার করে, আর হ্যাকাররা সেই সুযোগে বাঁশ দিয়ে দেয়।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা (DTO কি?)
**DTO (Data Transfer Object)** হলো একটা সাধারণ ক্লাস, যার কাজ শুধু ডাটা আনা-নেওয়া করা। এতে কোনো লজিক থাকে না।

ধরো, তোমার `AppUser` ক্লাসে `PasswordHash`, `SecurityStamp`, `AccessFailedCount`—এসব ফিল্ড আছে।
এখন ইউজার যখন সাইন-আপ করবে, সে কি `AccessFailedCount` পাঠাবে? না! সে পাঠাবে শুধু **Email**, **Password** আর **FullName**।
তাই আমরা ইউজার থেকে ডাটা রিসিভ করার জন্য আলাদা একটা ছোট ক্লাস বানাব, সেটাই DTO।

#### 🤣 ফানি অ্যানালজি (ভর্তির ফর্ম)

ধরো, তুমি কলেজে ভর্তি হতে গেছ।

১. **AppUser (Database Model):** এটা হলো কলেজের মেইন রেজিস্টার খাতা। এখানে তোমার নাম, বাবার নাম, **গোপন রোল নাম্বার**, **পরীক্ষার রেজাল্ট**, **বেতন বাকি আছে কিনা**—সব লেখা থাকে।
২. **DTO (Admission Form):** তোমাকে কি কলেজ কর্তৃপক্ষ মেইন রেজিস্টার খাতাটা দিয়ে বলে—"নে বাবা, এখানে তোর সব ডিটেইলস লিখে দে"?
না! তোমাকে একটা **"ভর্তির ফর্ম"** দেয়। সেখানে শুধু নাম, ঠিকানা আর ফোন নাম্বার চাওয়া হয়। রেজাল্ট বা রোল নাম্বার লেখার জায়গা সেখানে থাকে না।

👉 এই **"ভর্তির ফর্ম"** টাই হলো **DTO**। বাইরের মানুষ (Client) শুধু ফর্মে লিখবে, মেইন খাতায় (Database) হাত দিবে না।

#### 💻 Coding Example

আজকে আমরা দুইটা জিনিস বানাব:
১. **RegisterDto:** ডাটা রিসিভ করার বাটি।
২. **AccountController:** যেখানে রিকোয়েস্ট আসবে।

**Step 1: DTO বানানো**
তোমার প্রজেক্টে একটা নতুন ফোল্ডার বানাও `DTOs` নামে। তার ভেতরে `RegisterDto.cs` ফাইল তৈরি করো।

```csharp
using System.ComponentModel.DataAnnotations;

namespace AuthMasterClass.DTOs
{
    public class RegisterDto
    {
        [Required] // মামা, নাম না দিলে হবে না
        public string FullName { get; set; }

        [Required]
        [EmailAddress] // এটা আসলেই ইমেইল কিনা চেক করবে
        public string Email { get; set; }

        [Required]
        [MinLength(6)] // পাসওয়ার্ড অন্তত ৬ সংখ্যার হতে হবে
        public string Password { get; set; }
    }
}
```

**Step 2: Controller সেটআপ করা**
`Controllers` ফোল্ডারের ভেতরে `AccountController.cs` নামে একটা ফাইল বানাও।
এখানে আমরা `UserManager` কে ডাকব। `UserManager` হলো আইডেন্টিটি ফ্রেমওয়ার্কের সেই বস, যে ইউজার তৈরি, ডিলিট বা পাসওয়ার্ড চেক করে।

```csharp
using AuthMasterClass.DTOs;
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Mvc;

namespace AuthMasterClass.Controllers
{
    [Route("api/[controller]")] // URL হবে: api/account
    [ApiController]
    public class AccountController : ControllerBase
    {
        // UserManager হলো আমাদের মেইন অস্ত্র
        private readonly UserManager<AppUser> _userManager;

        // কনস্ট্রাকটরের মাধ্যমে UserManager-কে ইনজেক্ট করা হলো (Dependency Injection)
        public AccountController(UserManager<AppUser> userManager)
        {
            _userManager = userManager;
        }

        // সাইন-আপ করার মেথড (এখনো লজিক লিখিনি, জাস্ট স্ট্রাকচার)
        [HttpPost("register")]
        public async Task<IActionResult> Register([FromBody] RegisterDto registerDto)
        {
            // ১. ডিটিও ঠিকঠাক আছে কিনা অটোমেটিক চেক হবে [ApiController] এর কারণে
            
            // ২. এখানে আমরা লজিক লিখব (পরের ক্লাসে)

            return Ok("API Hit success! Data Received: " + registerDto.Email);
        }
    }
}
```

---

#### 🧠 একটু বোঝার চেষ্টা করি (Dependency Injection)
উপরের কোডে `public AccountController(UserManager<AppUser> userManager)` লাইনটা খেয়াল করো।
আমরা কিন্তু `new UserManager()...` লিখিনি। আমরা শুধু কনস্ট্রাক্টরে চেয়েছি।
কারণ মনে আছে? **Lesson 2**-তে `Program.cs` ফাইলে আমরা `builder.Services.AddIdentity...` লিখেছিলাম। ওই লাইনটার কারণেই অ্যাপ এখন জানে কিভাবে `UserManager` সাপ্লাই দিতে হয়। এটাকেই বলে **Dependency Injection (DI)**।

#### 📝 আজকের হোমওয়ার্ক (Homework)

আজকে লজিক লিখব না, কিন্তু আমাদের সেটআপ কাজ করছে কিনা সেটা চেক করব।

১. কোডগুলো হুবহু লিখো।
২. প্রজেক্ট রান করো (`dotnet run`)।
৩. **Postman** (যদি না থাকে ইন্সটল করে নাও) ওপেন করো।
৪. একটা `POST` রিকোয়েস্ট পাঠাও এই ঠিকানায়: `http://localhost:xxxx/api/account/register` (xxxx হলো তোমার পোর্ট নাম্বার)।

### 🎓 Lesson 5: User Registration & Password Hashing

অনেকে ভুল করে ইউজারের পাসওয়ার্ড সরাসরি ডাটাবেসে সেভ করে দেয় (যেমন: "123456")। এটা করলে তোমার চাকরি থাকবে না মামা! 🚫

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা (Hashing কি?)
**Hashing** হলো পাসওয়ার্ডকে এমনভাবে গুলিয়ে ফেলা, যাতে এটা আর আগের অবস্থায় ফিরে না আসে।
তুমি যদি ডাটাবেসে "123456" সেভ করো, হ্যাকার ডাটাবেস হ্যাক করলে সবার পাসওয়ার্ড পেয়ে যাবে।
কিন্তু যদি "123456" কে গুলিয়ে "**Xy9#Lm@5...**" বানিয়ে রাখো, হ্যাকার সেটা দেখে কিচ্ছু বুঝবে না।

#### 🤣 ফানি অ্যানালজি (লেবুর শরবত)

ধরো, **পাসওয়ার্ড** হলো একটা আস্ত **লেবু**।

১. **Plain Text:** তুমি লেবুটা ফ্রিজে রেখে দিলে। যে কেউ ফ্রিজ খুলে আস্ত লেবুটা নিয়ে যেতে পারে। (এটা রিস্কি)।
২. **Hashing:** তুমি লেবু চিপে, চিনি আর পানি মিশিয়ে **শরবত** বানিয়ে ফেললে।
এখন কেউ যদি শরবতটা চুরিও করে, সে কি শরবত থেকে আবার **আস্ত লেবু** ফেরত পাবে?
না! সম্ভব না।
ঠিক তেমনি, হ্যাশ করা পাসওয়ার্ড থেকে আসল পাসওয়ার্ড বের করা যায় না। সিস্টেম শুধু লগইনের সময় নতুন লেবুর শরবতের সাথে পুরোনো শরবতের স্বাদ মিলিয়ে দেখে।

#### 💻 Coding Example (AccountController Update)

এখন আমরা `AccountController.cs` ফাইলে `Register` মেথডটা আপডেট করব।

**লজিক ফ্লো:**
১. চেক করব এই ইমেইলে আগে কেউ একাউন্ট খুলেছে কিনা।
২. যদি না থাকে, তাহলে `RegisterDto` থেকে ডাটা নিয়ে `AppUser` বানাব।
৩. `_userManager.CreateAsync` ফাংশন কল করব (এটাই পাসওয়ার্ড হ্যাশ করে সেভ করবে)।

```csharp
// Controllers/AccountController.cs এর Register মেথড আপডেট করো

[HttpPost("register")]
public async Task<IActionResult> Register([FromBody] RegisterDto registerDto)
{
    // ১. ভ্যালিডেশন: মডেল ঠিক আছে তো? (যেমন পাসওয়ার্ড ছোট কিনা)
    if (!ModelState.IsValid)
    {
        return BadRequest(ModelState);
    }

    // ২. চেক করি এই ইমেইল অলরেডি আছে কিনা
    var existingUser = await _userManager.FindByEmailAsync(registerDto.Email);
    if (existingUser != null)
    {
        return BadRequest("বস, এই ইমেইল দিয়ে অলরেডি একাউন্ট খোলা আছে! অন্য ইমেইল দেন।");
    }

    // ৩. DTO থেকে User মডেলে ডাটা ট্রান্সফার (ম্যাপিং)
    var user = new AppUser
    {
        UserName = registerDto.Email, // Identity তে UserName ইউনিক হতে হয়, তাই ইমেইলটাই দিলাম
        Email = registerDto.Email,
        FullName = registerDto.FullName
        // খবরদার! এখানে Password সেট করবে না। ওটা নিচে হবে।
    };

    // ৪. ইউজার তৈরি করা (পাসওয়ার্ড হ্যাশ সহ)
    // CreateAsync মেথডই পাসওয়ার্ডকে 'শরবত' (Hash) বানিয়ে ডাটাবেসে রাখবে।
    var result = await _userManager.CreateAsync(user, registerDto.Password);

    if (result.Succeeded)
    {
        // ৫. সব ঠিক থাকলে সাকসেস মেসেজ
        return Ok(new { message = "আলহামদুলিল্লাহ! রেজিস্ট্রেশন সফল হয়েছে।", user = registerDto.Email });
    }
    else
    {
        // ৬. কোনো ঘাপলা হলে (যেমন: পাসওয়ার্ডে @#$ নাই) এরর দেখাবে
        return BadRequest(result.Errors);
    }
}
```

#### 🧠 স্পেশাল নোট (খুবই গুরুত্বপূর্ণ)
কোডের এই লাইনটা খেয়াল করো:
`await _userManager.CreateAsync(user, registerDto.Password);`

এখানে আমরা `user` অবজেক্টের ভেতর পাসওয়ার্ড ঢুকাইনি। পাসওয়ার্ডটা আলাদা প্যারামিটার হিসেবে দিয়েছি।
কারণ `Identity Framework` পাসওয়ার্ডটা নিয়ে **Hash** করবে, তারপর `user.PasswordHash` ফিল্ডে সেটা বসাবে। তুমি ম্যানুয়ালি বসাতে গেলে ভুল হবে।

#### 📝 আজকের হোমওয়ার্ক (Homework)

আজকের কাজটা করলে তুমি নিজেকে হ্যাকার হ্যাকার ফিল করবে! 😎

১. কোড আপডেট করে প্রজেক্ট রান করো।
২. **Postman** দিয়ে আগের মতো একটা রিকোয়েস্ট পাঠাও (নতুন ইমেইল দিয়ে)।
   *   যদি `200 OK` আর "আলহামদুলিল্লাহ..." মেসেজ পাও, তাহলে কাজ হয়েছে।
৩. এবার **SQL Server (SSMS)** এ যাও।
৪. `AspNetUsers` টেবিলটা `Select` করে ডাটা দেখো।
   *   `Email` কলামে তোমার ইমেইল দেখবে।
   *   `PasswordHash` কলামটা চেক করো।
   *   দেখবে সেখানে হিজিবিজি অনেক বড় একটা টেক্সট (যেমন: `AQAAAAEAACcQAAAA...`)।
   *   তুমি কি কোথাও এই হিজিবিজি লিখেছিলে? না! এটাই আইডেন্টিটির জাদু।

৫. **বোনাস টাস্ক:** একই ইমেইল দিয়ে আবার রেজিস্ট্রেশন করার চেষ্টা করো। দেখো আমাদের এরর মেসেজটা ("...অলরেডি একাউন্ট খোলা আছে") আসে কিনা।
