### 🎓 Lesson 11: JWT Structure & Reading Claims - টোকেনের হাড়গোর

তুমি যখন টোকেনটা দেখো (`eyJh...`), মনে হয় এটা কোনো এলিয়েন ভাষা। কিন্তু আসলে এটা ৩টা অংশের সমষ্টি, যা `.` (ডট) দিয়ে আলাদা করা থাকে।

**Structure:** `Header` **.** `Payload` **.** `Signature`

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
1.  **Header (হেডার):** এখানে লেখা থাকে এটা কি ধরনের টোকেন (JWT) এবং কোন অ্যালগোরিদম দিয়ে লক করা হয়েছে (যেমন: HS256)।
2.  **Payload (পেলোড):** এটাই আসল মালমশলা। ইউজারের নাম, ইমেইল, রোল, এক্সপায়ার ডেট—সব এখানে থাকে। এটাকে আমরা **Claims** বলি।
3.  **Signature (সিগনেচার):** এটা হলো সিকিউরিটি সিল। সার্ভারের গোপন চাবি (Secret Key) দিয়ে এটা তৈরি হয়।

#### 🤣 ফানি অ্যানালজি (কাঁচের টিফিন বক্স)

ধরো, তোমার আম্মু তোমাকে ভার্সিটিতে একটা **স্বচ্ছ কাঁচের টিফিন বক্স** দিয়েছে।

১. **Header (ঢাকনা):** ঢাকনার গায়ে লেখা আছে "Made of Glass, Model: JWT"। মানে এটা কিসের তৈরি।
২. **Payload (খাবার):** বক্সটা স্বচ্ছ, তাই বাইরে থেকেই দেখা যাচ্ছে ভেতরে **পোলাও আর রোস্ট (Data/Claims)** আছে।
   *   👉 **সতর্কতা:** যেহেতু বক্সটা স্বচ্ছ, তাই ভেতরে কেউ **টাকা বা প্রেমপত্র (Password)** রাখে না। কারণ সবাই দেখে ফেলবে!
৩. **Signature (তালা):** বক্সটা এমন একটা জাদুকরী আঠা দিয়ে লাগানো, যেটা খুলতে হলে আম্মুর হাতের ছাপ লাগে। তুমি যদি স্কুল গেটে পোলাও সরিয়ে বালু ভরতে যাও, বক্সটা ভেঙে যাবে (Signature Invalid হবে)।

#### 💻 Coding Example: কোডের মাধ্যমে Claims পড়া

আমরা জানি `[Authorize]` অ্যাট্রিবিউট চেক করে টোকেন ঠিক আছে কিনা। কিন্তু কন্ট্রোলারের ভেতরে বসে আমরা বুঝব কিভাবে **কে লগইন করেছে?**

.NET অটোমেটিক্যালি টোকেন ভেঙে ভেতরের তথ্যগুলো `User` অবজেক্টের মধ্যে লোড করে দেয়।

চলো `AccountController.cs`-এ একটা নতুন API বানাই যেটা লগইন করা ইউজারের সব গোপন তথ্য ফাঁস করে দিবে!

```csharp
using System.Security.Claims; // এটা লাগবে

// ... AccountController এর ভেতরে

    [Authorize] // অবশ্যই টোকেন লাগবে
    [HttpGet("get-current-user-info")]
    public IActionResult GetCurrentUserInfo()
    {
        // User অবজেক্টটা .NET আমাদের গিফট দিয়েছে। এর ভেতরেই সব আছে।
        
        // ১. নাম বের করা (যদি ডিফল্ট Name ক্লেইম থাকে)
        var userName = User.Identity?.Name;

        // ২. নির্দিষ্ট ক্লেইম বের করা (যেমন: ইমেইল, আইডি)
        // মনে আছে? Lesson 8-এ আমরা JwtRegisteredClaimNames.Sub দিয়েছিলাম আইডির জন্য।
        var userId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value; 
        var userEmail = User.FindFirst(ClaimTypes.Email)?.Value;

        // ৩. আমাদের কাস্টম ক্লেইম (FullName) বের করা
        // টোকেন বানানোর সময় নাম দিয়েছিলাম "FullName"
        var fullName = User.FindFirst("FullName")?.Value;

        return Ok(new
        {
            Message = "আপনার টোকেন ভেঙে এই তথ্যগুলো পেয়েছি:",
            Id = userId,
            Name = userName,
            Email = userEmail,
            RealName = fullName,
            IsAuthenticated = User.Identity.IsAuthenticated // সত্য নাকি মিথ্যা?
        });
    }
```

#### 🧠 একটু টেকনিক্যাল জ্ঞান (Claims Mapping)
তুমি হয়তো ভাবছ, টোকেন বানানোর সময় লিখলাম `JwtRegisteredClaimNames.Sub`, কিন্তু পড়ার সময় `ClaimTypes.NameIdentifier` কেন খুঁজছি?

কারণ, .NET খুব স্মার্ট। সে যখন টোকেন পড়ে, তখন স্ট্যান্ডার্ড নামগুলোকে (যেমন `sub`) অটোমেটিক কনভার্ট করে .NET-এর নিজস্ব নামে (`http://schemas.xmlsoap.org/.../nameidentifier`) নিয়ে নেয়। তাই `ClaimTypes` ব্যবহার করাই সেইফ।

### 🎓 Lesson 12: Custom Middleware - গেটের ভেতরে আরেক চেকপোস্ট

**Middleware** হলো আমাদের অ্যাপ্লিকেশনের পাইপলাইন বা রাস্তায় বসানো চেকপোস্ট। রিকোয়েস্ট কন্ট্রোলারের কাছে পৌঁছানোর আগেই মিডলওয়্যার সেটাকে চেক করতে পারে, মডিফাই করতে পারে বা লাত্থি দিয়ে বের করে দিতে পারে।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
অথেনটিকেশন (AuthN) শুধু চেক করে টোকেন আসল কিনা। সে ডাটাবেস চেক করে না যে ইউজার এখনো জীবিত আছে কিনা।
আমরা এমন একটা **পুলিশ** (Middleware) বসাব, যে টোকেন ভ্যালিড হওয়ার পরেও ডাটাবেসে ফোন দিয়ে জিজ্ঞেস করবে—*"বস, এই টোকেনধারী লোকটা কি এখনো ভদ্র আছে, নাকি ব্যান খাইছে?"*

#### 🤣 ফানি অ্যানালজি (সিনেমার টিকিট ও মারামারি)

ধরো, তুমি **"Star Cineplex"**-এ সিনেমা দেখতে গেছ।

১. **Ticket (Token):** তুমি টিকিট কাটলে। গেটম্যান টিকিট চেক করে তোমাকে ভেতরে ঢুকতে দিল। (এটা Authentication)।
২. **Incident:** ইন্টারভালের সময় তুমি পপকর্ন ওয়ালার সাথে মারামারি করলে। ম্যানেজার রেগে গিয়ে তোমাকে **"Blacklist"** করে দিল।
৩. **The Loophole:** কিন্তু তোমার পকেটে তো টিকিট আছেই! তুমি আবার হলের ভেতরে ঢুকে সিনেমা দেখা শুরু করলে। গেটম্যান তোমাকে আটকাবে না কারণ টিকিট তো ভ্যালিড।
৪. **The Middleware:** ম্যানেজার তখন হলের দরজায় একজন **বডিগাউর্ড** দাঁড় করাল। এই বডিগাউর্ডের কাজ টিকিট দেখা না, তার কাজ হলো—যারাই ঢুকছে, তাদের চেহারা দেখে লিস্ট চেক করা যে **"এরা কি ব্যানড?"**
যদি ব্যানড হয়, টিকিট থাকা সত্ত্বেও ঘাড় ধাক্কা!

#### 💻 Coding Example: UserStatusMiddleware

আমরা একটা মিডলওয়্যার বানাব যেটা প্রতিটা রিকোয়েস্টে চেক করবে ইউজার ডাটাবেসে এক্টিভ আছে কিনা।

**Step 1: Middleware ক্লাস বানানো**
প্রজেক্টে একটা নতুন ফোল্ডার বানাও `Middlewares`। তার ভেতরে `UserStatusMiddleware.cs` ফাইল নাও।

```csharp
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;

namespace AuthMasterClass.Middlewares
{
    public class UserStatusMiddleware
    {
        private readonly RequestDelegate _next;

        public UserStatusMiddleware(RequestDelegate next)
        {
            _next = next;
        }

        // প্রতিটা রিকোয়েস্ট এই মেথডের ভেতর দিয়ে যাবে
        public async Task InvokeAsync(HttpContext context, UserManager<AppUser> userManager)
        {
            // ১. আগে চেক করি ইউজার লগইন অবস্থায় আছে কিনা (টোকেন আছে কিনা)
            if (context.User.Identity != null && context.User.Identity.IsAuthenticated)
            {
                // ২. টোকেন থেকে নাম বা আইডি বের করি
                var userName = context.User.Identity.Name;

                // ৩. ডাটাবেসে চেক করি এই ইউজার এখনো আছে কিনা
                var user = await userManager.FindByNameAsync(userName);

                // ৪. যদি ইউজার না পাওয়া যায় (ডিলিট হয়ে গেছে) অথবা লক করা থাকে
                if (user == null)
                {
                    // ৪.১ সাথে সাথে থামিয়ে দাও
                    context.Response.StatusCode = 401; // Unauthorized
                    await context.Response.WriteAsync("User no longer exists! (Boss deleted you)");
                    return; // আর সামনে এগুবে না, এখানেই খেলা শেষ
                }
                
                // এখানে চাইলে চেক করতে পারো: if (await userManager.IsLockedOutAsync(user)) ...
            }

            // ৫. সব ঠিক থাকলে পরের স্টেপে (Controller-এ) যেতে দাও
            await _next(context);
        }
    }
}
```

**Step 2: Program.cs এ রেজিস্টার করা**
মিডলওয়্যার বানালেই হবে না, পাইপলাইনে ফিট করতে হবে। এবং অবশ্যই **Authentication** এর পরে বসাতে হবে।

`Program.cs` ফাইলে যাও:

```csharp
// ...
using AuthMasterClass.Middlewares; // namespace add koro

var app = builder.Build();

// ...
app.UseHttpsRedirection();

// ⚠️ অর্ডার খুব গুরুত্বপূর্ণ!
app.UseAuthentication(); // ১. আগে টোকেন চেক
app.UseMiddleware<UserStatusMiddleware>(); // ২. তারপর আমাদের কাস্টম পুলিশ চেক করবে ইউজার ব্যানড কিনা
app.UseAuthorization(); // ৩. তারপর পারমিশন চেক

app.MapControllers();
app.Run();
```

#### 🧪 টেস্টিং (ব্যান খাওয়ার অভিজ্ঞতা)

আজকে আমরা নিজেদের ব্যান করে দেখব সিস্টেম কাজ করে কিনা।

১. **লগইন:** প্রথমে `/login` করে একটা ফ্রেশ টোকেন নাও।
২. **সফল চেক:** ওই টোকেন দিয়ে `/profile` বা `/get-current-user-info` তে হিট করো। দেখবে ডাটা আসছে।
৩. **ভিলেন মুড:** এখন SQL Server (SSMS) ওপেন করো। `AspNetUsers` টেবিলে যাও। যে ইমেইল দিয়ে লগইন করেছ, সেই রো (Row) টা ডিলিট করে দাও। (অথবা `LockoutEnabled` এবং `LockoutEnd` নিয়ে খেলতে পারো, তবে ডিলিট করা সহজ)।
   *   *SQL Query:* `DELETE FROM AspNetUsers WHERE Email = 'tomar@email.com'`
৪. **ব্যর্থ চেক:** এখন পোস্টম্যান বা সোয়েগারে ফিরে এসো। তোমার হাতে কিন্তু সেই ভ্যালিড টোকেনটাই আছে। আবার `/profile` এ হিট করো।
৫. **রেজাল্ট:** `401 Unauthorized` এবং মেসেজ আসবে: *"User no longer exists! (Boss deleted you)"*।

### 🎓 Lesson 13: CORS (Cross-Origin Resource Sharing) - বর্ডারের ভিসা প্রসেসিং

ব্রাউজার বাই ডিফল্ট খুব সন্দেহপ্রবণ। সে এক ডোমেইন (Origin) থেকে অন্য ডোমেইনে ডাটা আদান-প্রদান করতে দেয় না।
ধরো, তোমার ফ্রন্টএন্ড চলছে `localhost:3000` এ, আর ব্যাকএন্ড (API) চলছে `localhost:5000` এ। পোর্ট আলাদা মানেই তারা **ভিন্ন দেশ (Origin)**।

ব্রাউজার বলে—"৩০০০ থেকে ৫০০০-এ রিকোয়েস্ট যাবে? না মামা, ভিসা লাগবে!"

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
CORS হলো সার্ভারের পক্ষ থেকে দেওয়া একটা অনুমতি পত্র।
সার্ভার (API) ব্রাউজারকে বলে দেয়—"শোনো, `localhost:3000` আমার পরিচিত লোক, তাকে আমার বাড়িতে ঢুকতে দাও।"
এটা না বললে ব্রাউজার সিকিউরিটির দোহাই দিয়ে রিকোয়েস্ট আটকে দেয়।

#### 🤣 ফানি অ্যানালজি (প্রতিবেশীর বাড়িতে ঢিল)

ধরো, তুমি আর তোমার বন্ধু পাশাপাশি দুইটা বিল্ডিংয়ে থাকো।

১. **তোমার বিল্ডিং (API):** গেটে কড়া দারোয়ান (Browser) আছে।
২. **বন্ধুর বিল্ডিং (Frontend):** বন্ধু তার ছাদ থেকে তোমার ছাদে একটা **আম (Request)** ছুড়ে মারল।
৩. **CORS বন্ধ:** দারোয়ান দেখল আমটা অন্য বিল্ডিং থেকে আসছে। সে ভাবল এটা বোমা হতে পারে! সে শুন্যেই আমটা ধরে ফেলে দিল (Block)।
৪. **CORS চালু:** তুমি দারোয়ানকে আগে থেকেই বলে রাখলে—*"মামা, পাশের বিল্ডিংয়ের 'বল্টু' যদি কিছু মারে, তাহলে আটকাও না। ও আমার দোস্ত।"*
এখন দারোয়ান আমটা আসতে দিবে।

#### 💻 Coding Example (Program.cs Update)

CORS পলিসি সেট করার নিয়ম হলো—প্রথমে সার্ভিস এড করা, তারপর মিডলওয়্যার ইউজ করা।

**Step 1: Service Add করা**
`Program.cs` ফাইলে `builder.Services` এর সেকশনে এই কোডটুকু লিখো:

```csharp
var builder = WebApplication.CreateBuilder(args);

// ... অন্যান্য সার্ভিস

// ১. CORS পলিসি ডিফাইন করা
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowReactApp", policy =>
    {
        policy.WithOrigins("http://localhost:3000") // ফ্রন্টএন্ডের ঠিকানা (React/Angular)
              .AllowAnyHeader()  // সব ধরনের হেডার এলাও (যেমন: Authorization)
              .AllowAnyMethod(); // GET, POST, PUT, DELETE সব এলাও
    });
    
    // ডেভেলপমেন্টের জন্য চাইলে সব ওপেন রাখতে পারো (কিন্তু প্রোডাকশনে সাবধান!)
    options.AddPolicy("AllowAll", policy => 
    {
        policy.AllowAnyOrigin()
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});

// ...
```

**Step 2: Middleware Use করা (অর্ডার খুব গুরুত্বপূর্ণ!)**
এটা `app.UseAuthentication()` এর **আগে** বসাতে হবে। কেন? কারণ দারোয়ান আগে চেক করবে তুমি কোন দেশ থেকে এসেছ, তারপর চেক করবে তোমার টিকিট (Token) আছে কিনা।

```csharp
var app = builder.Build();

// ... Swagger, HttpsRedirection

// ⚠️ CORS অবশ্যই Auth এর উপরে হতে হবে!
app.UseCors("AllowReactApp"); 
// অথবা ডেভেলপমেন্টের সময়: app.UseCors("AllowAll");

app.UseAuthentication();
app.UseMiddleware<UserStatusMiddleware>(); // আমাদের গত ক্লাসের কাস্টম মিডলওয়্যার
app.UseAuthorization();

app.MapControllers();
app.Run();
```

#### 🧠 লজিক ব্রেকডাউন
*   **WithOrigins:** স্পেসিফিক করে বলে দেওয়া কে কে এক্সেস পাবে। প্রোডাকশনে এটাই ব্যবহার করা উচিত।
*   **AllowAnyHeader:** ফ্রন্টএন্ড থেকে আমরা `Authorization` হেডারে টোকেন পাঠাই, তাই এটা এলাও করতে হয়।
*   **AllowAnyMethod:** `GET`, `POST` সব চলবে।

### 🎓 Lesson 14: Change Password API - তালার চাবি বদলানো

পাসওয়ার্ড চেঞ্জ করার লজিকটা খুব স্ট্রেটফরোয়ার্ড। ইউজারকে প্রমাণ করতে হবে সে বর্তমান পাসওয়ার্ডটা জানে, তবেই তাকে নতুন পাসওয়ার্ড সেট করতে দেওয়া হবে।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
তুমি যখন ফেসবুকে পাসওয়ার্ড চেঞ্জ করতে যাও, তখন ফেসবুক তিনটা জিনিস চায়:
১. **Old Password:** মানে বর্তমান চাবিটা দাও (প্রমাণ করো তুমিই মালিক)।
২. **New Password:** নতুন কোন চাবি চাও?
৩. **Confirm Password:** নতুন চাবিটা আবার দাও (ভুল লিখলে কিনা চেক করার জন্য)।

আমরাও হুবহু এই কাজটাই করব। আর যেহেতু ইউজার **লগইন করা অবস্থায়** আছে, তাই আমরা তার ইমেইলটা **Token** থেকেই বের করে নেব। তাকে কষ্ট করে ইমেইল লিখতে হবে না।

#### 🤣 ফানি অ্যানালজি (পুরানো প্রেমিকা বনাম নতুন প্রেমিকা)

বিষয়টা একটু সেনসিটিভ, কিন্তু বুঝতে সুবিধা হবে! 😜

ধরো, তুমি তোমার বর্তমান প্রেমিকার (Old Password) সাথে ব্রেকআপ করে নতুন প্রেমিকার (New Password) সাথে রিলেশনে যেতে চাও।
তোমাকে দুইটা স্টেপ পার করতে হবে:
১. বর্তমান প্রেমিকাকে বুঝিয়ে বলতে হবে "আমরা আর একসাথে থাকতে পারছি না" (Verify Old Password)।
২. তারপর নতুন প্রেমিকাকে বরণ করে নিতে হবে (Set New Password)।

তুমি যদি বর্তমান প্রেমিকাকে না জানিয়েই নতুন কাউকে আনতে যাও, তাহলে **Conflict** বা **Error** খাবে! সিস্টেম মাইর দিবে!

#### 💻 Coding Example

**Step 1: DTO বানানো**
`DTOs` ফোল্ডারে `ChangePasswordDto.cs` নামে ফাইল বানাও।

```csharp
using System.ComponentModel.DataAnnotations;

namespace AuthMasterClass.DTOs
{
    public class ChangePasswordDto
    {
        [Required]
        public string CurrentPassword { get; set; } // বর্তমান চাবি

        [Required]
        [MinLength(6)]
        public string NewPassword { get; set; } // নতুন চাবি

        [Required]
        [Compare("NewPassword")] // এটা চেক করবে NewPassword এর সাথে মিল আছে কিনা
        public string ConfirmNewPassword { get; set; } 
    }
}
```

**Step 2: Controller এ মেথড বানানো**
`AccountController.cs`-এ যাও। এই API-টা অবশ্যই `[Authorize]` হতে হবে, কারণ লগইন ছাড়া পাসওয়ার্ড চেঞ্জ করা যায় না।

```csharp
    [Authorize] // ১. অবশ্যই লগইন থাকতে হবে
    [HttpPost("change-password")]
    public async Task<IActionResult> ChangePassword([FromBody] ChangePasswordDto model)
    {
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState);
        }

        // ২. টোকেন থেকে ইমেইল বের করি (ইউজারকে ইমেইল দিতে হবে না)
        // User.Identity.Name আমাদের ইমেইলটাই দিবে (কারণ আমরা Claim এ সেট করেছিলাম)
        var email = User.Identity?.Name; 
        
        var user = await _userManager.FindByEmailAsync(email);
        if (user == null)
        {
            return Unauthorized("User not found!");
        }

        // ৩. আসল ম্যাজিক: আইডেন্টিটির বিল্ট-ইন মেথড
        // এটা অটোমেটিক চেক করবে CurrentPassword ঠিক আছে কিনা।
        // যদি ঠিক থাকে, তাহলে NewPassword হ্যাশ করে সেট করে দিবে।
        var result = await _userManager.ChangePasswordAsync(user, model.CurrentPassword, model.NewPassword);

        if (!result.Succeeded)
        {
            // পাসওয়ার্ড ভুল হলে বা নতুন পাসওয়ার্ড দুর্বল হলে এখানে এরর আসবে
            return BadRequest(result.Errors);
        }

        return Ok(new { message = "পাসওয়ার্ড সফলভাবে পরিবর্তন করা হয়েছে! পরের বার নতুন পাসওয়ার্ড দিয়ে লগইন করবেন।" });
    }
```

#### 🧠 লজিক ব্রেকডাউন
*   `User.Identity.Name`: আমরা টোকেন বানানোর সময় `ClaimTypes.Name` বা ডিফল্ট নেমে ইমেইল রেখেছিলাম কি?
    *   *চেক:* Lesson 8-এ আমরা `JwtRegisteredClaimNames.Email` ব্যবহার করেছি। অনেক সময় `.NET` অটোমেটিক ম্যাপ করে না।
    *   *সেফটি টিপস:* যদি `User.Identity.Name` নাল (Null) আসে, তাহলে `User.FindFirst(ClaimTypes.Email)?.Value` ব্যবহার করবে।

*   `ChangePasswordAsync`: এই ফাংশনটা `Transaction` এর মতো কাজ করে। পুরাতন পাসওয়ার্ড না মিললে সে নতুনটা সেট করবে না। আমাদের ম্যানুয়ালি `CheckPassword` কল করার দরকার নেই।

আজকে আমরা এই মোটু কন্ট্রোলারকে ডায়েট করিয়ে স্লিম বানাব এবং রান্নার কাজটা **Service** এর হাতে তুলে দিব।

### 🎓 Lesson 15: Service Pattern - ওয়েটার বনাম বাবুর্চি

ভালো কোডের লক্ষণ হলো—যার কাজ তাকে দিয়ে করানো (Separation of Concerns)।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Controller:** এর কাজ হলো **ওয়েটার (Waiter)** এর মতো। কাস্টমার (React/Postman) থেকে অর্ডার (Request) নিবে এবং রান্নাঘর (Service) এ পাস করে দিবে। খাবার রেডি হলে কাস্টমারকে সার্ভ করবে।
*   **Service:** এর কাজ হলো **বাবুর্চি (Chef)** এর মতো। সে জানে কিভাবে মশলা (Logic) মিশিয়ে রান্না করতে হয়। সে ডাটাবেসের সাথে কথা বলবে, টোকেন বানাবে, তারপর খাবারটা ওয়েটারকে দিবে।

বর্তমানে আমাদের ওয়েটার নিজেই রান্নাঘরে গিয়ে হাড়ি ঠেলছে, যা খুবই খারাপ প্র্যাকটিস।

#### 🤣 ফানি অ্যানালজি (বিয়ের গেট)

ধরো, তুমি বিয়ের গেটে দাঁড়িয়ে আছো (Controller)।

১. **বর্তমান অবস্থা:** মেহমান আসলে তুমিই দৌড়ে গিয়ে শরবত বানাচ্ছো, তুমিই গিয়ে চেয়ার দিচ্ছো, আবার তুমিই গেটে এসে ওয়েলকাম করছ। ফলে গেটে জ্যাম লেগে যাচ্ছে।
২. **Service Pattern:** তুমি গেটে শুধু দাঁড়িয়ে থাকবে। মেহমান আসলে তুমি তোমার ছোট ভাই **"বল্টু" (Service)** কে ইশারা দিবে। বল্টু সব এরেঞ্জ করবে। তুমি শুধু মেহমানকে বলবে—"ভেতরে যান স্যার"।

#### 💻 Coding Example: Refactoring

আজকে আমরা লজিকগুলো `AccountController` থেকে কেটে `AuthService` এ নিয়ে যাব।

**Step 1: Response Model বানানো**
মেথডগুলো কী রিটার্ন করবে, তার জন্য একটা সুন্দর প্যাকেট বানাই। `DTOs` ফোল্ডারে `AuthResponseDto.cs` বানাও।

```csharp
namespace AuthMasterClass.DTOs
{
    public class AuthResponseDto
    {
        public bool IsSuccess { get; set; } // কাজ হয়েছে কি হয়নি?
        public string Message { get; set; } // মেসেজ
        public string? Token { get; set; } // টোকেন (শুধু লগইনের সময় থাকবে)
    }
}
```

**Step 2: Interface বানানো**
প্রজেক্টে `Services` নামে একটা ফোল্ডার বানাও। ভেতরে `IAuthService.cs` (Interface) বানাও। এটা হলো মেনু কার্ড।

```csharp
using AuthMasterClass.DTOs;

namespace AuthMasterClass.Services
{
    public interface IAuthService
    {
        Task<AuthResponseDto> RegisterAsync(RegisterDto registerDto);
        Task<AuthResponseDto> LoginAsync(LoginDto loginDto);
    }
}
```

**Step 3: Service Class বানানো (আসল রান্নাঘর)**
`Services` ফোল্ডারে `AuthService.cs` বানাও। `AccountController` থেকে `UserManager`, `IConfiguration` এবং `GenerateToken` মেথড সব এখানে নিয়ে আসো।

```csharp
using AuthMasterClass.DTOs;
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;
using Microsoft.IdentityModel.Tokens;
using System.IdentityModel.Tokens.Jwt;
using System.Security.Claims;
using System.Text;

namespace AuthMasterClass.Services
{
    public class AuthService : IAuthService
    {
        private readonly UserManager<AppUser> _userManager;
        private readonly IConfiguration _configuration;

        public AuthService(UserManager<AppUser> userManager, IConfiguration configuration)
        {
            _userManager = userManager;
            _configuration = configuration;
        }

        public async Task<AuthResponseDto> RegisterAsync(RegisterDto registerDto)
        {
            var user = new AppUser
            {
                UserName = registerDto.Email,
                Email = registerDto.Email,
                FullName = registerDto.FullName
            };

            var result = await _userManager.CreateAsync(user, registerDto.Password);

            if (result.Succeeded)
            {
                return new AuthResponseDto { IsSuccess = true, Message = "User Registered Successfully!" };
            }
            
            // এররগুলো স্ট্রিং-এ কনভার্ট করে পাঠাচ্ছি
            return new AuthResponseDto { IsSuccess = false, Message = result.Errors.First().Description };
        }

        public async Task<AuthResponseDto> LoginAsync(LoginDto loginDto)
        {
            var user = await _userManager.FindByEmailAsync(loginDto.Email);

            if (user == null || !await _userManager.CheckPasswordAsync(user, loginDto.Password))
            {
                return new AuthResponseDto { IsSuccess = false, Message = "Invalid Email or Password" };
            }

            var token = GenerateToken(user);
            return new AuthResponseDto { IsSuccess = true, Message = "Login Successful", Token = token };
        }

        // সেই প্রাইভেট মেথডটা এখানে নিয়ে আসলাম
        private string GenerateToken(AppUser user)
        {
            // ... (Lesson 8 এর GenerateToken কোড হুবহু এখানে বসবে)
            // জায়গার অভাবে লিখলাম না, তুমি কপি-পেস্ট করে নিও মামা।
            // Claims, Key, Token creation logic same thakbe.
            
             var claims = new List<Claim>
            {
                new Claim(JwtRegisteredClaimNames.Sub, user.Id),
                new Claim(JwtRegisteredClaimNames.Email, user.Email),
                new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
                new Claim("FullName", user.FullName ?? "")
            };
            
            var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_configuration["JwtSettings:securityKey"]));
            var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

            var token = new JwtSecurityToken(
                issuer: _configuration["JwtSettings:issuer"],
                audience: _configuration["JwtSettings:audience"],
                claims: claims,
                expires: DateTime.Now.AddSeconds(Convert.ToDouble(_configuration["JwtSettings:expireSeconds"])),
                signingCredentials: creds
            );

            return new JwtSecurityTokenHandler().WriteToken(token);
        }
    }
}
```

**Step 4: Program.cs এ বাবুর্চি নিয়োগ দেওয়া**
সার্ভিস বানালে হবে না, `Program.cs` এ রেজিস্টার করতে হবে (Dependency Injection)। `AddIdentity` এর নিচে কোথাও লিখো:

```csharp
// বাবুর্চি নিয়োগ
builder.Services.AddScoped<IAuthService, AuthService>();
```

**Step 5: Controller আপডেট করা (ডায়েট কন্ট্রোল)**
এখন `AccountController.cs` একদম হালকা হয়ে যাবে।

```csharp
using AuthMasterClass.DTOs;
using AuthMasterClass.Services; // Namespace add
using Microsoft.AspNetCore.Mvc;

namespace AuthMasterClass.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class AccountController : ControllerBase
    {
        private readonly IAuthService _authService; // এখন আমরা শুধু সার্ভিসের সাথে কথা বলব

        public AccountController(IAuthService authService)
        {
            _authService = authService;
        }

        [HttpPost("register")]
        public async Task<IActionResult> Register([FromBody] RegisterDto model)
        {
            if (!ModelState.IsValid) return BadRequest(ModelState);

            var result = await _authService.RegisterAsync(model);

            if (result.IsSuccess) return Ok(result);
            return BadRequest(result);
        }

        [HttpPost("login")]
        public async Task<IActionResult> Login([FromBody] LoginDto model)
        {
            var result = await _authService.LoginAsync(model);

            if (result.IsSuccess) return Ok(result);
            return Unauthorized(result);
        }

        // Profile, ChangePassword এগুলোও এভাবে সার্ভিসে নিয়ে যাওয়া উচিত, তবে আপাতত থাক।
    }
}
```
