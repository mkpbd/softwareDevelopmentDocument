### 🎓 Lesson 16: Roles Introduction & Setup - ক্ষমতার চেয়ার

সফটওয়্যারে সব ইউজার সমান না। কারো ক্ষমতা বেশি, কারো কম। এই ক্ষমতা নির্ধারণ করার ট্যাগ-ই হলো **Role**।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
Identity Framework-এ **Role** মানে হলো একটা সাধারণ গ্রুপ বা ট্যাগ।
আমরা ডাটাবেসে কিছু রোলের নাম সেভ করব (যেমন: "Admin", "User")। তারপর ইউজারদের ধরে ধরে বলব—"তুই এডমিন, আর তুই সাধারণ প্রজা (User)।"

#### 🤣 ফানি অ্যানালজি (বাসের সিট)

ধরো, তুমি একটা লোকাল বাসে (App) উঠেছ।

১. **User (Passenger):** তুমি টিকিট কেটেছ, তাই বাসে ওঠার অধিকার আছে। তুমি পেছনের সিটে বসবে।
২. **Admin (Driver):** ড্রাইভারও বাসে উঠেছে। কিন্তু তার বসার জায়গা আলাদা (ড্রাইভিং সিট)। তার হাতে স্টিয়ারিং, ব্রেক, হর্ন সব আছে।
৩. **Manager (Helper):** এর কাজ ভাড়া তোলা। সে ড্রাইভারের সিটে বসতে পারবে না, আবার যাত্রীদের মতো চুপচাপ বসেও থাকবে না।

এখন যদি প্যাসেঞ্জার গিয়ে ড্রাইভারের সিটে বসে স্টিয়ারিং ঘোরাতে চায়, তাহলে তো অ্যাক্সিডেন্ট হবে! তাই আমাদের কোডে বলে দিতে হবে—**"Only Driver Can Drive"**।

### 💻 Coding Example

রোল নিয়ে কাজ করতে হলে আমাদের একটু কনফিগারেশন চেঞ্জ করতে হবে এবং নতুন একটা কন্ট্রোলার বানাতে হবে।

#### **Step 1: Program.cs আপডেট করা (খুবই গুরুত্বপূর্ণ ⚠️)**

এতদিন আমরা শুধু `AddIdentity<AppUser, ...>` ব্যবহার করেছি। কিন্তু আমরা রোলের কথা উল্লেখ করিনি। `Program.cs` ফাইলে `AddIdentity` লাইনটা খুঁজে বের করো এবং নিচের মতো আপডেট করো:

```csharp
// Program.cs

// আগে ছিল: builder.Services.AddIdentity<AppUser, IdentityRole>() ...
// অথবা শুধু: builder.Services.AddIdentity<AppUser, IdentityRole>(...)

// সঠিকভাবে লিখো:
builder.Services.AddIdentity<AppUser, IdentityRole>(options =>
    {
        options.Password.RequireDigit = true;
        options.Password.RequiredLength = 6;
        // ... অন্যান্য অপশন
    })
    .AddEntityFrameworkStores<AppDbContext>()
    .AddDefaultTokenProviders();
```

👉 **নোট:** খেয়াল করো `<AppUser, IdentityRole>`—এখানে `IdentityRole` কথাটা থাকতেই হবে। না থাকলে রোল কাজ করবে না।

#### **Step 2: RolesController বানানো**

আমরা এখন রোল তৈরি করা এবং ইউজারকে রোল দেওয়ার জন্য একটা টেম্পোরারি কন্ট্রোলার বানাব। (সাধারণত এগুলো সিডিং বা এডমিন প্যানেল দিয়ে হয়, কিন্তু শেখার জন্য আমরা API বানাচ্ছি)।

`Controllers` ফোল্ডারে `RolesController.cs` বানাও।

```csharp
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Mvc;

namespace AuthMasterClass.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class RolesController : ControllerBase
    {
        // UserManager এর মতো রোলের জন্যও আলাদা বস আছে: RoleManager
        private readonly RoleManager<IdentityRole> _roleManager;
        private readonly UserManager<AppUser> _userManager;

        public RolesController(RoleManager<IdentityRole> roleManager, UserManager<AppUser> userManager)
        {
            _roleManager = roleManager;
            _userManager = userManager;
        }

        // ১. নতুন রোল তৈরি করার API (যেমন: Admin, User, HR)
        [HttpPost("create-role")]
        public async Task<IActionResult> CreateRole([FromBody] string roleName)
        {
            if (string.IsNullOrEmpty(roleName)) return BadRequest("রোলের নাম দেন মামা!");

            // চেক করি এই রোল আগে থেকেই আছে কিনা
            var roleExist = await _roleManager.RoleExistsAsync(roleName);
            if (roleExist) return BadRequest("এই রোল অলরেডি আছে!");

            // নতুন রোল বানালাম
            var result = await _roleManager.CreateAsync(new IdentityRole(roleName));

            if (result.Succeeded) return Ok($"Role '{roleName}' created successfully!");
            
            return BadRequest(result.Errors);
        }

        // ২. ইউজারকে রোল দেওয়ার API (Assign Role)
        [HttpPost("assign-role")]
        public async Task<IActionResult> AssignRole([FromBody] RoleAssignDto model) // নিচে DTO টা বানাচ্ছি
        {
            // ইউজার খুঁজি
            var user = await _userManager.FindByEmailAsync(model.Email);
            if (user == null) return BadRequest("ইউজার পাওয়া যায়নি!");

            // রোল আছে কিনা চেক করি
            if (!await _roleManager.RoleExistsAsync(model.RoleName))
                return BadRequest("এমন কোনো রোল নাই মামা!");

            // রোল এসাইন করি
            var result = await _userManager.AddToRoleAsync(user, model.RoleName);

            if (result.Succeeded) return Ok($"User '{model.Email}' is now a '{model.RoleName}'!");

            return BadRequest(result.Errors);
        }
    }
    
    // ছোট্ট একটা DTO এখানেই দিয়ে দিলাম (তুমি চাইলে আলাদা ফাইলে রাখতে পারো)
    public class RoleAssignDto
    {
        public string Email { get; set; }
        public string RoleName { get; set; }
    }
}
```

### 🎓 Lesson 17: Role-Based Authorization - টোকেনে ক্ষমতার সিল

আমাদের টোকেন জেনারেশন লজিক আপডেট করতে হবে। যাতে লগইন করার সময় সিস্টেম চেক করে—"এই লোকের রোল কি?" এবং সেটা টোকেনের পেটের ভেতর ঢুকিয়ে দেয়।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
Identity Framework-এ আমরা `[Authorize(Roles = "Admin")]` ব্যবহার করি।
এটা কাজ করার জন্য টোকেনের ভেতর `role` নামে একটা প্রপার্টি থাকতেই হবে। যদি টোকেনে রোল না থাকে, তাহলে তুমি ডাটাবেসে হাজার বার এডমিন হলেও লাভ নেই। কারণ API প্রতিবার ডাটাবেস চেক করে না, সে টোকেন বিশ্বাস করে।

#### 🤣 ফানি অ্যানালজি (অফিসের আইডি কার্ড)

ধরো, তুমি একটা বড় কোম্পানির **GM (General Manager)**।

১. **Scenario A (পুরাতন টোকেন):** তোমার আইডি কার্ডে শুধু নাম লেখা "মিস্টার কুদ্দুস"। তুমি এমডি স্যারের কেবিনে ঢুকতে গেলে পিয়ন আটকে দিল—*"ভাই, এখানে শুধু জিএম-রা ঢুকতে পারবে।"*
তুমি চিৎকার করে বললে—*"আরে ব্যাটা আমিই তো জিএম!"*
পিয়ন বলল—*"কার্ডে তো লেখা নাই। আমি কি জানি?"*

২. **Scenario B (নতুন টোকেন):** তুমি HR এর কাছে গিয়ে কার্ডটা আপডেট করলে। এখন নামের নিচে বড় করে লেখা **"DESIGNATION: GM"**।
এবার পিয়ন কার্ড দেখেই স্যালুট দিয়ে দরজা খুলে দিল।

👉 আজকের ক্লাসে আমরা ওই **"DESIGNATION"** টা কার্ডে প্রিন্ট করব।

#### 💻 Coding Example

আজকে আমাদের **রান্নাঘর (AuthService)** এ একটু মশলা বাড়াতে হবে।

**Step 1: AuthService আপডেট করা**
`Services/AuthService.cs` ফাইলে `GenerateToken` মেথডটা আপডেট করতে হবে। খেয়াল করে দেখো কোথায় চেঞ্জ হচ্ছে।

```csharp
// AuthService.cs এর ভেতরে

// ১. LoginAsync মেথড আপডেট করা লাগবে না, কারণ সে GenerateToken কল করে।
// আমরা সোজা GenerateToken মেথডেই হাত দিব।

// কিন্তু তার আগে GenerateToken মেথডকে async বানাতে হবে কারণ আমরা ডাটাবেস থেকে রোল আনব।
// তাই LoginAsync-কেও একটু আপডেট করতে হবে।

public async Task<AuthResponseDto> LoginAsync(LoginDto loginDto)
{
    var user = await _userManager.FindByEmailAsync(loginDto.Email);
    // ... পাসওয়ার্ড চেকিং লজিক (আগের মতোই)

    // টোকেন জেনারেশন এখন async, তাই await দিতে হবে
    var token = await GenerateToken(user); 

    return new AuthResponseDto { IsSuccess = true, Message = "Login Successful", Token = token };
}

// ২. GenerateToken মেথড আপডেট (Task<string> রিটার্ন করবে)
private async Task<string> GenerateToken(AppUser user)
{
    var claims = new List<Claim>
    {
        new Claim(JwtRegisteredClaimNames.Sub, user.Id),
        new Claim(JwtRegisteredClaimNames.Email, user.Email),
        new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
        new Claim("FullName", user.FullName ?? "")
    };

    // 🔥 নতুন মশলা: ইউজারের রোলগুলো বের করে ক্লেইমে ঢুকাচ্ছি
    var roles = await _userManager.GetRolesAsync(user);
    
    foreach (var role in roles)
    {
        // ClaimTypes.Role ব্যবহার করা জরুরি, কারণ [Authorize] এটাকেই খোঁজে
        claims.Add(new Claim(ClaimTypes.Role, role));
    }

    // ... বাকি কোড (Key, SigningCredentials, Token creation) হুবহু আগের মতো
    
    var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_configuration["JwtSettings:securityKey"]));
    var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

    var token = new JwtSecurityToken(
        issuer: _configuration["JwtSettings:issuer"],
        audience: _configuration["JwtSettings:audience"],
        claims: claims,
        expires: DateTime.Now.AddSeconds(Convert.ToDouble(_configuration["JwtSettings:expireSeconds"])),
        signingCredentials: creds
    );

    return new JwtSecurityTokenHandler().WriteToken(token);
}
```

**Step 2: AdminOnly Controller বানানো**
এখন আমরা চেক করব রোল আসলে কাজ করছে কিনা। `Controllers` ফোল্ডারে `AdminController.cs` বানাও।

```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace AuthMasterClass.Controllers
{
    // এই কন্ট্রোলারে ঢুকতে হলে দুইটা শর্ত:
    // ১. লগইন করা থাকতে হবে (Authorize)
    // ২. রোল অবশ্যই "Admin" হতে হবে (Roles = "Admin")
    
    [Authorize(Roles = "Admin")] 
    [Route("api/[controller]")]
    [ApiController]
    public class AdminController : ControllerBase
    {
        [HttpGet("dashboard")]
        public IActionResult GetAdminDashboard()
        {
            return Ok("স্বাগতম বস! আপনি এডমিন, তাই এটা দেখতে পাচ্ছেন। সাধারণ জনগণ এখানে নিষিদ্ধ। 🚫");
        }
    }
}
```

#### 🧪 টেস্টিং (বসের পাওয়ার)

১. **Admin Login:** তোমার যে ইউজারকে গত ক্লাসে "Admin" রোল দিয়েছিলে, তাকে দিয়ে `/login` করো।
   *   টোকেনটা কপি করে **jwt.io** তে চেক করো। দেখবে `role`: `Admin` লেখা আছে।
2. **Access Admin API:** ওই টোকেনটা Swagger-এ সেট করো এবং `/api/admin/dashboard` এ হিট করো।
   *   **Result:** `200 OK` (স্বাগতম বস...)।
3. **User Login:** এবার এমন একটা ইউজার দিয়ে লগইন করো যার কোনো রোল নাই বা শুধু "User" রোল আছে।
   *   নতুন টোকেনটা Swagger-এ সেট করো।
4. **Fail Check:** আবার `/api/admin/dashboard` এ হিট করো।
   *   **Result:** `403 Forbidden`।

#### 🧠 401 Unauthorized vs 403 Forbidden
ইন্টারভিউতে এটা ধরবে মামা!
*   **401 Unauthorized:** আমি চিনি না তুমি কে। (লগইন করা নাই বা টোকেন ভুল)।

### 🎓 Lesson 18: Data Seeding - অ্যাপের বিসমিল্লাহ সেটআপ

**Data Seeding** মানে হলো ডাটাবেসে কিছু ডিফল্ট ডাটা আগে থেকেই ঢুকিয়ে রাখা। যেমন: ফিক্সড রোল (Admin, User) এবং একজন ডিফল্ট এডমিন ইউজার।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
অ্যাপ রান হওয়ার সাথে সাথে কোড চেক করবে—"ডাটাবেসে কি 'Admin' রোল আছে?"
*   যদি না থাকে, বানিয়ে ফেলবে।
*   এরপর চেক করবে—"admin@gmail.com নামে কেউ কি আছে?"
*   না থাকলে, সে এই নামে একটা ইউজার বানাবে এবং তাকে 'Admin' রোল দিয়ে দিবে।
ফলে তুমি অ্যাপ রান করেই সরাসরি `admin@gmail.com` দিয়ে লগইন করতে পারবে। সাইন-আপ করার দরকারই নেই।

#### 🤣 ফানি অ্যানালজি (দোকানের মহরত)

ধরো, তুমি একটা **মিঠাইর দোকান** দিয়েছ।

১. **Without Seeding:** দোকান ওপেন করার সময় কাউন্টার খালি, ক্যাশবাক্স খালি, মিষ্টির ট্রে খালি। কাস্টমার এসে বলল—"ভাই মিষ্টি দেন"। তুমি বললে—"দাঁড়ান ভাই, আগে চুলাটা জ্বালাই, তারপর বানিয়ে দিচ্ছি।" (বিরক্তিকর!)
২. **With Seeding:** মহরতের দিন দোকান খোলার আগেই তুমি কাউন্টারে কিছু খুচরা টাকা (Roles) আর ডিসপ্লেতে কিছু স্পেশাল লাড্ডু (Admin User) সাজিয়ে রাখলে।
শাটার খোলার সাথে সাথেই কাস্টমার দেখল দোকান রেডি! একেই বলে **Seeding** বা **"হাতের লক্ষ্মী"**।

### 💻 Coding Example

আমরা একটা আলাদা ক্লাস বানাব যার কাজ হবে শুধু ডাটা সিড করা।

**Step 1: Seeder Class বানানো**
`Data` ফোল্ডারের ভেতরে `AppDbSeeder.cs` নামে একটা ক্লাস বানাও।

```csharp
using AuthMasterClass.Constants; // এটা নিচে বানাচ্ছি
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;

namespace AuthMasterClass.Data
{
    public static class AppDbSeeder
    {
        // এই মেথডটা আমরা Program.cs থেকে কল করব
        public static async Task SeedRolesAndAdminAsync(IServiceProvider serviceProvider)
        {
            // ১. রোল ম্যানেজার আর ইউজার ম্যানেজারকে ডেকে আনলাম
            var roleManager = serviceProvider.GetRequiredService<RoleManager<IdentityRole>>();
            var userManager = serviceProvider.GetRequiredService<UserManager<AppUser>>();

            // ২. রোলগুলো তৈরি করি (যদি না থাকে)
            string[] roleNames = { "Admin", "User", "Manager" };
            
            foreach (var roleName in roleNames)
            {
                // চেক করি রোলটা আছে কিনা
                if (!await roleManager.RoleExistsAsync(roleName))
                {
                    await roleManager.CreateAsync(new IdentityRole(roleName));
                }
            }

            // ৩. একটা ডিফল্ট এডমিন ইউজার বানাই
            var adminEmail = "admin@auth.com";
            var adminUser = await userManager.FindByEmailAsync(adminEmail);

            if (adminUser == null)
            {
                var newAdmin = new AppUser
                {
                    UserName = adminEmail,
                    Email = adminEmail,
                    FullName = "Super Admin Mama",
                    EmailConfirmed = true // ধরে নিলাম ইমেইল ভেরিফাইড
                };

                // এডমিন তৈরি করছি (পাসওয়ার্ড অবশ্যই স্ট্রং দিবে)
                var result = await userManager.CreateAsync(newAdmin, "Admin@1234");

                if (result.Succeeded)
                {
                    // সাথে সাথে তাকে Admin রোল দিয়ে দিলাম
                    await userManager.AddToRoleAsync(newAdmin, "Admin");
                }
            }
        }
    }
}
```

**Step 2: Program.cs এ কানেকশন দেওয়া**
এখন অ্যাপ স্টার্ট হওয়ার ঠিক আগে এই মেথডটা কল করতে হবে। `Program.cs` এ `app.Run()` এর ঠিক আগে এই কোডটুকু বসাও।

```csharp
var app = builder.Build();

// ... Middleware (Swagger, Auth, Cors) configuration ...

// 👇 Seeding Logic Start (অ্যাপ রান হওয়ার আগে চলবে)
using (var scope = app.Services.CreateScope())
{
    var services = scope.ServiceProvider;
    try
    {
        // আমাদের জাদুকরী মেথড কল করছি
        await AppDbSeeder.SeedRolesAndAdminAsync(services);
    }
    catch (Exception ex)
    {
        // লগিং করা ভালো, যদি সিডিং এর সময় কোনো এরর হয়
        var logger = services.GetRequiredService<ILogger<Program>>();
        logger.LogError(ex, "An error occurred while seeding the database.");
    }
}
// 👆 Seeding Logic End

app.Run();
```

এখানে "User" বা "Admin" রোল দিয়ে কাজ হবে না। এখানে লাগবে **Claims** এবং **Policy**।

আজকে আমরা শিখব **Policy Based Authorization**—যেখানে আমরা সুনির্দিষ্ট তথ্য (Claims) চেক করে সিদ্ধান্ত নিব।

### 🎓 Lesson 19: Claims Based Authorization & Policy - রোলের বাইরেও ক্ষমতা

Role হলো একটা বড় গ্রুপ (যেমন: বরযাত্রী)। আর Claim হলো সেই গ্রুপের ভেতরের মানুষের স্পেসিফিক বৈশিষ্ট্য (যেমন: কারো হাতে গিফট আছে, কারো হাতে নাই)।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Claims:** টোকেনের পেটের ভেতর থাকা তথ্য (যেমন: `DateOfBirth`, `EmployeeCode`, `VIPStatus`)।
*   **Policy:** এটা হলো গেটের দারোয়ানের কাছে দেওয়া নতুন নিয়ম।
    *   *Role Based Rule:* "শুধু বরযাত্রীদের ঢুকতে দাও।"
    *   *Policy Based Rule:* "বরযাত্রী হোক বা না হোক, আমি জানি না। **যাদের পকেটে লাল রুমাল (Claim) আছে**, শুধু তাদের ঢুকতে দাও।"

#### 🤣 ফানি অ্যানালজি (ক্লাবের বাউন্সার)

ধরো, একটা নাইট ক্লাব আছে।

১. **Role Check:** বাউন্সার দেখছে তুমি "Member" কিনা। মেম্বার কার্ড থাকলেই এন্ট্রি।
২. **Policy Check:** ক্লাবের নিয়ম হলো—**"Must Have Beard"** (দাড়ি থাকতে হবে)।
এখন তুমি "Member" (Role) হতে পারো, এমনকি তুমি ক্লাবের মালিকের বন্ধুও হতে পারো। কিন্তু তোমার গালে যদি দাড়ি না থাকে (Missing Claim), বাউন্সার তোমাকে ঢুকতে দিবে না।
এখানে **"Member"** হলো রোল, আর **"Beard"** হলো ক্লেইম। আর নিয়মটা হলো **পলিসি**।

### 💻 Coding Example

#### **Step 1: Program.cs এ পলিসি ডিফাইন করা**
গেটের দারোয়ানকে (ASP.NET Core) নিয়মটা শিখিয়ে দিতে হবে। `builder.Services.AddIdentity...` এর পরে এবং `builder.Build()` এর আগে এই কোড লিখো:

```csharp
builder.Services.AddAuthorization(options =>
```

এখন আমাদের টোকেন মেশিনে (AuthService) ওই ক্লেইমটা ঢোকাতে হবে।
ধরে নিচ্ছি, আমাদের সুপার এডমিন একজন এমপ্লয়ি। তাই তার টোকেনে আমরা `EmployeeCode` দিয়ে দিব।

```csharp
        new Claim("FullName", user.FullName ?? "")

    // ... Role adding logic ...

    // 🔥 নতুন মশলা: পলিসি পাস করার জন্য ক্লেইম দিচ্ছি

    }

    // ... Key and Token generation same as before
    // ...
    return new JwtSecurityTokenHandler().WriteToken(token);
}
```

#### **Step 3: Controller এ পলিসি ব্যবহার করা**
এখন আমরা `AdminController` বা নতুন কোনো কন্ট্রোলারে এই পলিসি বসাব।

`Controllers/AdminController.cs` এ নতুন একটা মেথড নাও:

```csharp
// Controllers/AdminController.cs

    // এই API তে ঢুকতে হলে রোল তো এডমিন হতেই হবে (ক্লাসের উপরে লেখা আছে),
    // সাথে "EmployeeOnly" পলিসিও মানতে হবে।
    
    [Authorize(Policy = "EmployeeOnly")] // ⛔ পলিসি চেকপোস্ট
    [HttpGet("employee-lounge")]
    public IActionResult GetEmployeeLounge()
    {
        return Ok("ওয়েলকাম কলিগ! আপনার এমপ্লয়ি কোড আছে, তাই ঢুকতে পেরেছেন।");
    }
```

একে বলে **Permission Based Authorization**। এটা রোলের চেয়েও অনেক বেশি সুক্ষ্ম (Granular)।

### 🎓 Lesson 20: Permission Based Authorization - চাবির গোছা

**Role** হলো একটা বড় বস্তা, আর **Permission** হলো সেই বস্তার ভেতরের ছোট ছোট প্যাকেট।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Role (পদবি):** ম্যানেজার।
*   **Permission (কাজ):** ম্যানেজার কি কি করতে পারবে?
    *   `Permissions.Users.Create` (ইউজার বানাতে পারবে)
    *   `Permissions.Users.Delete` (ইউজার ডিলিট করতে পারবে)

অনেক সময় দেখা যায়, দুইজনই "ম্যানেজার", কিন্তু একজনকে ডিলিট করার পাওয়ার দেওয়া হয়নি। তখন রোল দিয়ে কাজ হয় না, পারমিশন চেক করতে হয়। আমরা টোকেনের ভেতর এই পারমিশনগুলো **Claim** হিসেবে ঢুকিয়ে দিব।

#### 🤣 ফানি অ্যানালজি (অফিসের চাবির গোছা)

ধরো, তুমি আর তোমার বন্ধু দুইজনেই অফিসের **"পিয়ন" (Role)**।

১. **Role Check:** গেটম্যান দেখল তোমরা দুইজনেই পিয়ন, তাই অফিসে ঢুকতে দিল।
২. **Permission Check:**
    *   তোমার কোমরে ঝোলানো চাবির গোছায় **"ক্যান্টিন"** আর **"স্টোর রুমের"** চাবি আছে।
    *   তোমার বন্ধুর গোছায় শুধু **"ক্যান্টিনের"** চাবি আছে, স্টোর রুমের চাবি নাই।

এখন বস বলল—*"স্টোর রুম থেকে কলম নিয়ে আসো।"*
তুমিও পিয়ন, বন্ধুও পিয়ন। কিন্তু স্টোর রুমের তালা (Policy) শুধু তোমার চাবি (Permission) দিয়েই খুলবে। বন্ধুর চাবি দিয়ে খুলবে না।

### 💻 Coding Example

আমরা হার্ডকোড স্ট্রিং ব্যবহার না করে একটা কনস্ট্যান্ট ক্লাস ব্যবহার করব, যাতে বানান ভুল না হয়।

#### **Step 1: Permissions এর তালিকা বানানো**
একটা ফাইল বানাও `Constants/AppPermissions.cs`। এখানে আমরা সব ক্ষমতার নাম লিখে রাখব।

```csharp
namespace AuthMasterClass.Constants
{
    public static class AppPermissions
    {
        public const string CreateProducts = "Permissions.Products.Create";
        public const string ViewProducts   = "Permissions.Products.View";
        public const string DeleteProducts = "Permissions.Products.Delete";
    }
}
```

#### **Step 2: AuthService আপডেট (টোকেনে চাবি ঢোকানো)**
এখন আমরা টোকেন জেনারেট করার সময় ইউজারের রোল অনুযায়ী তাকে পারমিশন (চাবি) দিব।

`Services/AuthService.cs` এর `GenerateToken` মেথড আপডেট করো:

```csharp
using AuthMasterClass.Constants; // এটা এড করো

// ... GenerateToken মেথডের ভেতরে ...

    var claims = new List<Claim>
    {
        new Claim(JwtRegisteredClaimNames.Sub, user.Id),
        new Claim(JwtRegisteredClaimNames.Email, user.Email),
        new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
        new Claim("FullName", user.FullName ?? "")
    };

    // রোলগুলো এড করা (আগের মতোই)
    var userRoles = await _userManager.GetRolesAsync(user);
    foreach (var role in userRoles)
    {
        claims.Add(new Claim(ClaimTypes.Role, role));
    }

    // 🔥 নতুন মশলা: পারমিশন বা চাবি দেওয়া
    // (রিয়েল লাইফে আমরা ডাটাবেস থেকে RolePermission টেবিল চেক করে আনব)
    // কিন্তু শেখার জন্য আমরা সিম্পল লজিক দিচ্ছি:
    
    if (userRoles.Contains("Admin"))
    {
        // এডমিন সব চাবি পাবে
        claims.Add(new Claim("Permission", AppPermissions.CreateProducts));
        claims.Add(new Claim("Permission", AppPermissions.ViewProducts));
        claims.Add(new Claim("Permission", AppPermissions.DeleteProducts));
    }
    else if (userRoles.Contains("User"))
    {
        // ইউজার শুধু দেখার চাবি পাবে
        claims.Add(new Claim("Permission", AppPermissions.ViewProducts));
    }

    // ... বাকি কোড (Key, Token Generation) আগের মতোই
```

#### **Step 3: Program.cs এ পলিসি সেট করা**
এখন আমরা `AppPermissions` এর নাম ধরে পলিসি বানাব।

```csharp
// Program.cs

builder.Services.AddAuthorization(options =>
{
    // ১. পলিসি: পণ্য বানানোর ক্ষমতা
    // শর্ত: "Permission" ক্লেইমের ভ্যালু অবশ্যই "Permissions.Products.Create" হতে হবে।
    options.AddPolicy("CanCreateProduct", policy => 
        policy.RequireClaim("Permission", AppPermissions.CreateProducts));

    // ২. পলিসি: পণ্য ডিলিট করার ক্ষমতা
    options.AddPolicy("CanDeleteProduct", policy => 
        policy.RequireClaim("Permission", AppPermissions.DeleteProducts));
});
```

#### **Step 4: Controller এ ব্যবহার করা**
আমরা `ProductController` নামে একটা ডামি কন্ট্রোলার বানাব।

`Controllers/ProductController.cs`:

```csharp
using AuthMasterClass.Constants;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace AuthMasterClass.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class ProductController : ControllerBase
    {
        // সবাই দেখতে পাবে (যাদের View পারমিশন আছে)
        [Authorize(Policy = "CanViewProduct")] // (যদি পলিসিটা Program.cs এ এড করে থাকো)
        // অথবা সহজ করার জন্য আপাতত রোল বা শুধু Authorize রাখলাম
        [Authorize] 
        [HttpGet]
        public IActionResult GetProducts()
        {
            return Ok("List of Products: Laptop, Mobile, Tablet");
        }

        // শুধু যাদের ক্রিয়েট পারমিশন আছে
        [Authorize(Policy = "CanCreateProduct")] 
        [HttpPost]
        public IActionResult CreateProduct()
        {
            return Ok("Product Created Successfully! (আপনার চাবি কাজ করেছে)");
        }

        // শুধু যাদের ডিলিট পারমিশন আছে
        [Authorize(Policy = "CanDeleteProduct")]
        [HttpDelete]
        public IActionResult DeleteProduct()
        {
            return Ok("Product Deleted! (পাওয়ারফুল চাবি)");
        }
    }
}
```

### 🧪 টেস্টিং (চাবির জোর)

১. **Admin Login:** এডমিন দিয়ে লগইন করো। টোকেন কপি করে **jwt.io** তে দেখো।
   *   দেখবে `Permission` নামে ৩টা ক্লেইম আছে (Create, View, Delete)।
   *   এই টোকেন দিয়ে `/api/product` এর `POST` (Create) এবং `DELETE` মেথডে হিট করো।
   *   **Result:** `200 OK`।

2. **User Login:** সাধারণ ইউজার দিয়ে লগইন করো।
   *   jwt.io তে দেখো, শুধু `View` পারমিশন আছে।
   *   এবার `/api/product` এর `POST` বা `DELETE` মেথডে হিট করো।
   *   **Result:** `403 Forbidden`। (দারোয়ান বলবে: "মামা, তোমার রোল 'User' ঠিক আছে, কিন্তু ডিলিট করার চাবি (Claim) তো নাই!")।
