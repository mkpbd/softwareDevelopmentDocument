

## ***Phase 5: Advanced Authorization (Lesson 21-25)** - Claims কি, Policy based Auth, Custom Requirement, Handler.

স্বাগতম মামা! 🎉
আজ থেকে আমাদের **Phase 5: Advanced Authorization** শুরু। আমরা বেসিক রোল আর ক্লেইম দিয়ে অনেক কাজ সেরেছি।

কিন্তু দুনিয়াটা এত সহজ না। ধরো, তোমার সিস্টেমে নিয়ম আছে—**"যাদের বয়স ১৮ বছরের নিচে, তারা হরর মুভি দেখতে পারবে না।"**
এখন রোল (User) বা ক্লেইম (DateOfBirth) দিয়ে সরাসরি এটা চেক করা যায় না। কারণ সিস্টেমে লেখা নেই "User is 18+"। সিস্টেমে লেখা আছে তার জন্ম তারিখ "2010-01-01"।

তোমাকে **অঙ্ক কষে** বের করতে হবে তার বয়স ১৮ হয়েছে কিনা। এই "অঙ্ক কষা" বা লজিক চেক করার কাজটা যেখানে করা হয়, তাকেই বলে **Custom Requirement Handler**।

আজকে আমরা নিজেদের আইন নিজেরাই বানাব এবং ইমপ্লিমেন্ট করব! 👨‍⚖️

### 🎓 Lesson 21: Custom Requirement & Handler - নিজের আইন, নিজের বিচার

এখানে দুইটা পার্ট থাকে:
১. **Requirement (আইন):** এটা একটা সাধারণ ক্লাস, যেখানে আইনের শর্ত লেখা থাকে। (যেমন: বয়স ১৮ হতে হবে)।
২. **Handler (বিচারক):** এখানে আসল লজিক থাকে। সে টোকেন থেকে ডাটা নিয়ে হিসাব করে দেখে শর্ত পূরণ হয়েছে কিনা।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
স্ট্যান্ডার্ড পলিসি শুধু চেক করে—"তোমার কি ক্লেইম আছে?" (হ্যাঁ/না)।
আর কাস্টম হ্যান্ডলার চেক করে—"তোমার ক্লেইমের ভ্যালু কত? সেটা দিয়ে কি কাজ হবে?"

#### 🤣 ফানি অ্যানালজি (বিয়ে বাড়ির গেট ও পিচ্চি বাহিনী)

ধরো, বিয়ে বাড়িতে নিয়ম করা হলো—**"১০ বছরের নিচের বাচ্চারা স্টেজে উঠতে পারবে না।"**

১. **Requirement (আইন):** নোটিশ বোর্ডে লেখা "Minimum Age: 10"।
২. **Token (Claim):** বাচ্চার কপালে জন্ম তারিখ লেখা নেই। কিন্তু তার আইডি কার্ডে লেখা "জন্ম সাল: ২০১৫"।
৩. **Handler (দারোয়ান):** দারোয়ান কার্ড দেখল। সে মনে মনে অঙ্ক কষল:
   *   এখন সাল ২০২৫।
   *   বাচ্চার জন্ম ২০১৫।
   *   তাহলে বয়স = ২০২৫ - ২০১৫ = ১০ বছর।
   *   **সিদ্ধান্ত:** ১০ বছর হয়েছে? আচ্ছা যাও, স্টেজে ওঠো। (Succeed)।

যদি অঙ্ক কষে দেখত বয়স ৯, তাহলে ঘাড় ধাক্কা (Fail)।

### 💻 Coding Example

আমরা একটা পলিসি বানাব **"AtLeast18"**।

#### **Step 1: Requirement ক্লাস বানানো**
একটা ফোল্ডার বানাও `Requirements` নামে। তার ভেতরে `MinimumAgeRequirement.cs` ফাইল নাও।
এটা জাস্ট একটা ডাটা হোল্ডার।

```csharp
using Microsoft.AspNetCore.Authorization;

namespace AuthMasterClass.Requirements
{
    // এটা IAuthorizationRequirement ইন্টারফেস ইমপ্লিমেন্ট করবে
    public class MinimumAgeRequirement : IAuthorizationRequirement
    {
        public int MinimumAge { get; }

        public MinimumAgeRequirement(int minimumAge)
        {
            MinimumAge = minimumAge;
        }
    }
}
```

#### **Step 2: Handler ক্লাস বানানো (আসল বিচারক)**
একই ফোল্ডারে `MinimumAgeHandler.cs` বানাও। এখানে আমরা বয়সের হিসাব করব।

```csharp
using Microsoft.AspNetCore.Authorization;
using System.Security.Claims;

namespace AuthMasterClass.Requirements
{
    public class MinimumAgeHandler : AuthorizationHandler<MinimumAgeRequirement>
    {
        protected override Task HandleRequirementAsync(AuthorizationHandlerContext context, MinimumAgeRequirement requirement)
        {
            // ১. টোকেনের ভেতর "DateOfBirth" নামে কোনো ক্লেইম আছে কিনা দেখি
            var dobClaim = context.User.FindFirst("DateOfBirth");

            if (dobClaim == null)
            {
                return Task.CompletedTask; // জন্ম তারিখ না থাকলে সোজা ফেইল
            }

            // ২. জন্ম তারিখ পার্স করে বয়স বের করি
            if (DateTime.TryParse(dobClaim.Value, out DateTime dateOfBirth))
            {
                var age = DateTime.Today.Year - dateOfBirth.Year;
                
                // লিপ ইয়ার বা জন্মদিনের মাস/দিন এডজাস্টমেন্ট
                if (dateOfBirth.Date > DateTime.Today.AddYears(-age)) age--;

                // ৩. চেক করি বয়স রিকোয়ারমেন্টের সমান বা বেশি কিনা
                if (age >= requirement.MinimumAge)
                {
                    context.Succeed(requirement); // পাস! বিচারক খুশি।
                }
            }

            return Task.CompletedTask;
        }
    }
}
```

#### **Step 3: AuthService এ জন্ম তারিখ ক্লেইম এড করা**
হ্যান্ডলার কাজ করার জন্য টোকেনের ভেতর `DateOfBirth` থাকতে হবে। `AuthService.cs` এর `GenerateToken` মেথডে একটা ফেক জন্ম তারিখ দিয়ে দাও (টেস্ট করার জন্য)।

```csharp
// AuthService.cs -> GenerateToken মেথডের claims লিস্টে এড করো:

// আপাতত হার্ডকোড করে দিচ্ছি যাতে বয়স ২০+ হয় (2000 সাল)
claims.Add(new Claim("DateOfBirth", "2000-01-01")); 

// টেস্ট করার সময় পরে এটা চেঞ্জ করে "2020-01-01" দিও (তখন বয়স কম হবে)
```

#### **Step 4: Program.cs এ রেজিস্ট্রেশন**
এখন বিচারক (Handler) এবং আইন (Policy) সরকারকে (App) জানাতে হবে।

```csharp
using AuthMasterClass.Requirements;
using Microsoft.AspNetCore.Authorization;

// ...

// ১. হ্যান্ডলার রেজিস্টার করা (অবশ্যই করতে হবে)
builder.Services.AddSingleton<IAuthorizationHandler, MinimumAgeHandler>();

// ২. পলিসি তৈরি করা
builder.Services.AddAuthorization(options =>
{
    // আগের পলিসিগুলো...

    // নতুন পলিসি: "AtLeast18"
    options.AddPolicy("AtLeast18", policy =>
        policy.Requirements.Add(new MinimumAgeRequirement(18))); // ১৮ বছর মিনিমাম
});
```

#### **Step 5: Controller এ ব্যবহার**
`AdminController` বা `ProductController` এ নতুন একটা মেথড নাও।

```csharp
    [Authorize(Policy = "AtLeast18")]
    [HttpGet("adult-content")]
    public IActionResult GetAdultContent()
    {
        return Ok("সাবধান! এখানে ১৮+ কন্টেন্ট আছে। আপনি দেখতে পাচ্ছেন কারণ আপনার বয়স ১৮ এর বেশি। 🔞");
    }
```

### 🧪 টেস্টিং (আইন প্রয়োগ)

১. **Happy Path:**
   *   `AuthService` এ জন্ম সাল দাও `2000-01-01` (বয়স প্রায় ২৫)।
   *   লগইন করে টোকেন নাও।
   *   `/api/admin/adult-content` এ হিট করো।
   *   **Result:** `200 OK` (দেখতে দিবে)।

২. **Sad Path (Unlucky):**
   *   `AuthService` এ গিয়ে জন্ম সাল চেঞ্জ করে দাও `2015-01-01` (বয়স ১০ বছর)।
   *   আবার লগইন করে **নতুন টোকেন** নাও (কারণ আগের টোকেনে পুরোনো বয়স রয়ে গেছে)।
   *   এবার `/api/admin/adult-content` এ হিট করো।
   *   **Result:** `403 Forbidden` (বাচ্চা পোলাপান নট এলাউড!)।

স্বাগতম মামা! 🎉
গত ক্লাসে আমরা **Custom Requirement** দিয়ে বয়স চেক করেছি। কিন্তু সেটা ছিল সাধারণ চেক।

আজকে আমরা শিখব অথরাইজেশনের সবচেয়ে বাস্তবসম্মত এবং ক্রিটিক্যাল পার্ট। ধরো, তোমার সিস্টেমে ১০০ জন ইউজার আছে। সবাই "User" রোলের। সবাই "Document Edit" করতে পারে।
কিন্তু নিয়ম হলো—**"নিজের ডকুমেন্ট শুধু নিজেই এডিট করতে পারবে। অন্যের ডকুমেন্টে হাত দেওয়া যাবে না।"**

এটাকে বলে **Resource-Based Authorization**। এখানে `[Authorize]` অ্যাট্রিবিউট কাজ করে না, কারণ অ্যাট্রিবিউট জানে না তুমি ডাটাবেসের কোন রো (Row) টা এডিট করতে চাইছ।

### 🎓 Lesson 22: Resource-Based Authorization - নিজের মালে হাত দাও

এতদিন আমরা গেটে (Controller এর মাথায়) চেক করেছি। এখন আমাদের চেক করতে হবে ঘরের ভেতরে ঢুকে আলমারি খোলার সময়।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Role/Policy:** এটা চেক করে—"তোমার কি গাড়ি চালানোর লাইসেন্স আছে?"
*   **Resource Auth:** এটা চেক করে—"লাইসেন্স তো আছে, কিন্তু **এই গাড়িটা** কি তোমার? নাকি অন্যের গাড়িতে চাবি ঢুকাচ্ছো?"

এখানে আমাদের কোডের ভেতর ম্যানুয়ালি `AuthorizationService` কে ডাকতে হবে এবং বলতে হবে—*"বিচারক সাহেব, এই ইউজার (User) এই নির্দিষ্ট ডাটা (Resource) টা এডিট করতে চাইছে। সে কি মালিক? চেক করে বলেন।"*

#### 🤣 ফানি অ্যানালজি (মোবাইল ফোনের গ্যালারি)

ধরো, এক আড্ডায় ৫ জন বন্ধু আছে। সবার কাছেই স্মার্টফোন আছে এবং সবাই জানে কিভাবে গ্যালারি ওপেন করতে হয় (Permission: ViewGallery)।

১. **Scenario:** বল্টু তার নিজের ফোন বের করে গ্যালারি দেখল। (ওকে)।
২. **Violation:** বল্টু এবার পাশ থেকে মন্টুর পকেট থেকে ফোন বের করে গ্যালারি দেখতে চাইল।
৩. **Defense:** মন্টু বলল—*"ঐ মিয়া! তুমি ফোন ইউজ করতে পারো ঠিক আছে, কিন্তু এটা **আমার ফোন (Resource)**। হাত দিবা না!"*

এখানে "ফোন" হলো রিসোর্স, আর "মন্টু" হলো মালিক (Owner)।

### 💻 Coding Example

আমরা একটা ডামি রিসোর্স বানাব `UserNote` নামে। এবং চেক করব যে লগইন করা ইউজার এটার মালিক কিনা।

#### **Step 1: Resource Model (যাকে রক্ষা করব)**
`Models` ফোল্ডারে `UserNote.cs` বানাও।

```csharp
namespace AuthMasterClass.Models
{
    public class UserNote
    {
        public int Id { get; set; }
        public string NoteText { get; set; }
        public string OwnerId { get; set; } // এইটাই আসল। মালিকের আইডি।
    }
}
```

#### **Step 2: Requirement বানানো (শর্ত)**
`Requirements` ফোল্ডারে `SameAuthorRequirement.cs` বানাও। এটা জাস্ট একটা মার্কার।

```csharp
using Microsoft.AspNetCore.Authorization;

namespace AuthMasterClass.Requirements
{
    public class SameAuthorRequirement : IAuthorizationRequirement { }
}
```

#### **Step 3: Handler বানানো (বিচারক)**
একই ফোল্ডারে `SameAuthorHandler.cs` বানাও। এখানে আমরা চেক করব `User.Id` আর `Note.OwnerId` সেইম কিনা।

```csharp
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Authorization;
using System.Security.Claims;

namespace AuthMasterClass.Requirements
{
    // এখানে লক্ষ্য করো: <SameAuthorRequirement, UserNote>
    // অর্থাৎ এই বিচারক শুধু 'UserNote' টাইপের জিনিসের বিচার করবে।
    public class SameAuthorHandler : AuthorizationHandler<SameAuthorRequirement, UserNote>
    {
        protected override Task HandleRequirementAsync(AuthorizationHandlerContext context, 
                                                       SameAuthorRequirement requirement, 
                                                       UserNote resource)
        {
            // ১. টোকেন থেকে ইউজারের আইডি বের করি (আমরা 'sub' বা 'Id' দিয়ে সেভ করেছিলাম)
            // Lesson 8/17 এ আমরা JwtRegisteredClaimNames.Sub ব্যবহার করেছি
            var userId = context.User.FindFirst(ClaimTypes.NameIdentifier)?.Value 
                         ?? context.User.FindFirst("sub")?.Value;

            if (userId == null) return Task.CompletedTask;

            // ২. আসল চেক: টোকেনের আইডি আর নোটের মালিকের আইডি মিল আছে?
            if (resource.OwnerId == userId)
            {
                context.Succeed(requirement); // হ্যাঁ, নিজের মাল!
            }

            return Task.CompletedTask;
        }
    }
}
```

#### **Step 4: Program.cs এ রেজিস্টার করা**

```csharp
// Program.cs

// হ্যান্ডলার রেজিস্টার
builder.Services.AddSingleton<IAuthorizationHandler, SameAuthorHandler>();

// পলিসি রেজিস্টার
builder.Services.AddAuthorization(options =>
{
    // ... আগের পলিসি
    
    // রিসোর্স পলিসি
    options.AddPolicy("MustBeOwner", policy =>
        policy.AddRequirements(new SameAuthorRequirement()));
});
```

#### **Step 5: Controller এ ম্যানুয়ালি চেক করা (Imperative Check)**
এখন আমরা `NotesController` বানাব। এখানে আমরা `[Authorize]` দিয়ে মেথড আটকাব না (পুরোপুরি)। ভেতরে ঢুকে চেক করব।

```csharp
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Authorization; // এটা লাগবেই
using Microsoft.AspNetCore.Mvc;
using System.Security.Claims;

namespace AuthMasterClass.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class NotesController : ControllerBase
    {
        private readonly IAuthorizationService _authorizationService; // জাজ সাহেব

        // বিচারককে ইনজেক্ট করলাম
        public NotesController(IAuthorizationService authorizationService)
        {
            _authorizationService = authorizationService;
        }

        [Authorize] // লগইন থাকতে হবে
        [HttpGet("{noteId}")]
        public async Task<IActionResult> GetNote(int noteId)
        {
            // ১. ধরে নিই ডাটাবেস থেকে নোটটা আনলাম (হার্ডকোড করলাম শেখার জন্য)
            // রিয়েল লাইফে: var note = await _db.Notes.FindAsync(noteId);
            
            // সিনারিও: এই নোটের মালিকের আইডি "user-123" (উদাহরণ)
            // টেস্ট করার সময় তোমার নিজের টোকেনের ID টা এখানে বসাবে।
            var note = new UserNote 
            { 
                Id = noteId, 
                NoteText = "আমার গোপন ডায়েরি...", 
                OwnerId = "e2d3..." // ⚠️ তোমার টোকেন থেকে আইডি কপি করে এখানে বসাবে টেস্টের জন্য
            };

            // ২. ম্যানুয়াল বিচার ডাকছি
            // (User = বর্তমান ইউজার, note = রিসোর্স, "MustBeOwner" = পলিসি নাম)
            var authResult = await _authorizationService.AuthorizeAsync(User, note, "MustBeOwner");

            if (!authResult.Succeeded)
            {
                // ৩. যদি মালিক না হয় -> ভাগাও!
                return Forbid(); // 403 Forbidden
            }

            return Ok(note);
        }
    }
}
```

### 🎓 Lesson 23: Custom Authorization Response - সুন্দর করে "না" বলা

ডিফল্ট বিহেভিয়ার খুব রুক্ষ। দরজা মুখের ওপর বন্ধ করে দেয়। আমরা চাই দরজা বন্ধ করার আগে একটা চিঠি ধরিয়ে দিতে।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Default Behavior:** তুমি টিকেট ছাড়া হলে ঢুকলে, দারোয়ান তোমাকে ঘাড় ধাক্কা দিয়ে বের করে দিল। কোনো কথা বলল না। (খুবই অপমানজনক!)
*   **Custom Behavior:** দারোয়ান তোমাকে স্যালুট দিয়ে একটা চিঠি দিল—*"স্যার, আমরা অত্যন্ত দুঃখিত। আপনার টিকেটের মেয়াদ শেষ হয়ে গেছে। দয়া করে কাউন্টার থেকে নতুন টিকেট নিন।"*

এটা দেখতে প্রফেশনাল লাগে এবং ফ্রন্টএন্ডের কাজ সহজ করে দেয়।

#### 🤣 ফানি অ্যানালজি (প্রেমের প্রস্তাব প্রত্যাখ্যান)

ধরো, তুমি কাউকে প্রপোজ করলে।

১. **Default 403:** মেয়েটা কোনো কথা না বলে তোমাকে ব্লক করে দিল। (তুমি কনফিউজড—কি হলো?)
২. **Custom 403:** মেয়েটা বলল—*"দেখো, তুমি খুব ভালো ছেলে (Authenticated), কিন্তু আমি তোমাকে ভাই হিসেবে দেখি (Not Authorized for Boyfriend Role)।"*
অন্তত তুমি কারণটা জানলে এবং মনে শান্তি পেলে! 😂

### 💻 Coding Example

আমরা `Program.cs` ফাইলে `AddJwtBearer` কনফিগারেশনের ভেতরে **Event** হ্যান্ডেল করব।

#### **Step 1: Program.cs আপডেট করা**

`builder.Services.AddAuthentication...` সেকশনটা খুঁজে বের করো এবং `AddJwtBearer` এর ভেতরে `Events` প্রপার্টি যোগ করো।

```csharp
using Microsoft.AspNetCore.Authentication.JwtBearer;
// ... অন্যান্য ইউজিং

builder.Services.AddAuthentication(options => {
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options => {
    // ... আগের কনফিগারেশন (SaveToken, TokenValidationParameters) ...
    options.TokenValidationParameters = new TokenValidationParameters
    {
        // ... তোমার আগের সেটিংস ...
        ValidateIssuer = true,
        ValidateAudience = true,
        // ...
    };

    // 🔥 এই নতুন অংশটুকু যোগ করো: ইভেন্ট হ্যান্ডেলিং
    options.Events = new JwtBearerEvents
    {
        // ১. যখন টোকেন নাই বা ভুল (401 Unauthorized)
        OnChallenge = async context =>
        {
            // ডিফল্ট বিহেভিয়ার বন্ধ করো
            context.HandleResponse();

            // রেসপন্স স্ট্যাটাস কোড সেট করো
            context.Response.StatusCode = 401;
            context.Response.ContentType = "application/json";

            // আমাদের কাস্টম মেসেজ
            var response = new 
            { 
                isSuccess = false,
                message = "ভাই, আপনার টোকেন নাই অথবা মেয়াদ শেষ! দয়া করে আবার লগইন করেন। (401)", 
                errorCode = "AUTH_TOKEN_INVALID"
            };

            // JSON কনভার্ট করে রাইট করো
            await context.Response.WriteAsJsonAsync(response);
        },

        // ২. যখন টোকেন আছে কিন্তু পারমিশন নাই (403 Forbidden)
        OnForbidden = async context =>
        {
            context.Response.StatusCode = 403;
            context.Response.ContentType = "application/json";

            var response = new 
            { 
                isSuccess = false,
                message = "আপনি লগইন করেছেন ঠিকই, কিন্তু এই রুমে ঢোকার পারমিশন আপনার নাই! (403)", 
                errorCode = "AUTH_PERMISSION_DENIED"
            };

            await context.Response.WriteAsJsonAsync(response);
        }
    };
});
```

### 🎓 Lesson 24: Dynamic Authorization Attributes - অন-ডিমান্ড পলিসি

আজকে আমরা এমন একটা সিস্টেম বানাব যেটা **"Factory"** এর মতো কাজ করবে। যখন যে বয়সের রিকোয়ারমেন্ট আসবে, সে অটোমেটিক সেই পলিসি বানিয়ে সাপ্লাই দিবে। আগে থেকে বানিয়ে রাখার দরকার নেই।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
*   **Static Policy (আগের নিয়ম):** তুমি রেস্টুরেন্টে গিয়ে বললে "মেনু ১ দেন"। রান্নাঘরে মেনু ১ (১৮ বছর) আগে থেকেই রান্না করা আছে।
*   **Dynamic Policy (আজকের নিয়ম):** তুমি শেফকে বললে "ভাই, ঝাল একটু বাড়িয়ে, লবণ কমিয়ে স্পেশাল কিছু দেন"।
    শেফ (PolicyProvider) তোমার মুখের কথা শুনে সাথে সাথে ওই স্টাইলের রান্না করে দিল। আগে থেকে রান্না করা ছিল না।

#### 🤣 ফানি অ্যানালজি (টেইলার্স এর দোকান)

১. **Readymade Shop (Static):** দোকানে S, M, L, XL সাইজের শার্ট ঝুলানো আছে। তোমার সাইজ যদি মিডিয়াম আর লার্জের মাঝখানে হয়, তুমি বিপদে। (আলাদা আলাদা পলিসি ডিফাইন করা)।
২. **Tailor Shop (Dynamic):** তুমি দর্জিকে গিয়ে বললে—*"মামা, কলার ১৫ ইঞ্চি, হাতা ২২ ইঞ্চি দেন।"*
দর্জি তোমার মাপ (Parameter) শুনে সাথে সাথে কাপড় কেটে জামা বানিয়ে দিল। আমাদের `[MinimumAge(25)]` হলো সেই মাপ।

### 💻 Coding Example

এটা একটু এডভান্সড, তাই মন দিয়ে দেখো। আমাদের ৩টা স্টেপ পার করতে হবে।

*(ধরে নিচ্ছি Lesson 21 এর `MinimumAgeRequirement` এবং `MinimumAgeHandler` তোমার প্রজেক্টে আছে)*

#### **Step 1: Custom Attribute বানানো**
প্রথমে আমরা একটা অ্যাট্রিবিউট বানাব যেটা `AuthorizeAttribute` কে ইনহেরিট করবে।
`Attributes` ফোল্ডার বানাও এবং `MinimumAgeAuthorizeAttribute.cs` ফাইল নাও।

```csharp
using Microsoft.AspNetCore.Authorization;

namespace AuthMasterClass.Attributes
{
    // আমরা চাই কোডে [MinimumAge(18)] এভাবে লিখতে
    public class MinimumAgeAttribute : AuthorizeAttribute
    {
        // কনস্ট্রাক্টরে আমরা বয়স নিব
        public MinimumAgeAttribute(int age)
        {
            // পলিসির নাম ডাইনামিকালি সেট করছি।
            // যেমন: age=18 হলে Policy="MinimumAge_18"
            // age=21 হলে Policy="MinimumAge_21"
            Policy = $"MinimumAge_{age}";
        }
    }
}
```

#### **Step 2: Custom Policy Provider বানানো (আসল দর্জি)**
এখন আমাদের এমন একটা ক্লাস লাগবে, যে দেখবে—"পলিসির নাম কি `MinimumAge_` দিয়ে শুরু হয়েছে?" যদি হয়, সে পলিসিটা বানিয়ে দিবে।

`Requirements` ফোল্ডারে `AppAuthorizationPolicyProvider.cs` বানাও।

```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.Extensions.Options;

namespace AuthMasterClass.Requirements
{
    // এটা DefaultAuthorizationPolicyProvider কে ইনহেরিট করবে
    public class AppAuthorizationPolicyProvider : DefaultAuthorizationPolicyProvider
    {
        public AppAuthorizationPolicyProvider(IOptions<AuthorizationOptions> options) : base(options)
        {
        }

        // যখনই কোনো কন্ট্রোলারে [Authorize] দেখবে, কোড এই মেথডকে ডাকবে
        public override async Task<AuthorizationPolicy> GetPolicyAsync(string policyName)
        {
            // ১. চেক করি পলিসির নাম "MinimumAge_" দিয়ে শুরু কিনা
            if (policyName.StartsWith("MinimumAge_", StringComparison.OrdinalIgnoreCase))
            {
                // ২. নাম থেকে বয়সটা বের করি (যেমন "MinimumAge_21" থেকে 21)
                var agePart = policyName.Substring("MinimumAge_".Length);
                
                if (int.TryParse(agePart, out int age))
                {
                    // ৩. ডাইনামিকালি পলিসি বানাচ্ছি
                    var policy = new AuthorizationPolicyBuilder();
                    policy.AddRequirements(new MinimumAgeRequirement(age)); // Lesson 21 এর ক্লাস
                    return policy.Build();
                }
            }

            // যদি আমাদের ফরম্যাটের না হয়, তাহলে ডিফল্ট সিস্টেমে পাঠাও (যেমন "Admin" রোল)
            return await base.GetPolicyAsync(policyName);
        }
    }
}
```

### 🎓 Lesson 25: Security Stamp - টোকেন বাতিল করার অস্ত্র

**Security Stamp** হলো ডাটাবেসের ইউজার টেবিলে থাকা একটা অদ্ভুত স্ট্রিং (Column), যেটা প্রতিবার পাসওয়ার্ড বা ক্রিটিক্যাল ইনফো চেঞ্জ হলে অটোমেটিক বদলে যায়।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
টোকেন হলো একটা **ফটোকপি**। আর ডাটাবেস হলো **আসল দলিল**।
আমরা টোকেনের ভেতর দলিলের একটা গোপন কোড (Security Stamp) প্রিন্ট করে দিব।
প্রতিবার রিকোয়েস্ট আসার পর আমরা চেক করব—"টোকেনের কোড আর ডাটাবেসের বর্তমান কোড কি এক?"

যদি ইউজার পাসওয়ার্ড চেঞ্জ করে, ডাটাবেসের কোড বদলে যাবে। কিন্তু পুরোনো টোকেনের কোড তো আগেরটাই থাকবে। ব্যাস! ধরা খেয়ে যাবে।

#### 🤣 ফানি অ্যানালজি (সিম কার্ড রিপ্লেসমেন্ট)

ধরো, তোমার মোবাইল চুরি হয়ে গেছে। চোরের কাছে তোমার **সিম (Old Token)** আছে এবং সে দিব্যি কথা বলছে।

১. **Action:** তুমি কাস্টমার কেয়ারে গিয়ে নতুন সিম তুললে (Change Password)।
২. **Result:** কোম্পানি তোমার নাম্বারের বিপরীতে একটা নতুন **সিরিয়াল কোড (Security Stamp)** জেনারেট করল।
৩. **Consequence:** চোরের কাছে থাকা সিমটা ফিজিক্যালি ঠিক থাকলেও নেটওয়ার্ক আর সেটা চিনবে না। কারণ কোম্পানি জানে—"এই নাম্বারের বর্তমান সিরিয়াল কোড চেঞ্জ হয়ে গেছে।" চোরের সিম সাথে সাথে **Invalid** হয়ে যাবে।

### 💻 Coding Example

এটা ইমপ্লিমেন্ট করতে আমাদের ২টা জায়গায় হাত দিতে হবে।

#### **Step 1: AuthService এ Stamp যোগ করা**
প্রথমে টোকেন বানানোর সময় বর্তমান স্ট্যাম্পটা ক্লেইম হিসেবে ঢুকিয়ে দিতে হবে।

`Services/AuthService.cs` এর `GenerateToken` মেথডে যাও:

```csharp
private async Task<string> GenerateToken(AppUser user)
{
    var claims = new List<Claim>
    {
        new Claim(JwtRegisteredClaimNames.Sub, user.Id),
        new Claim(JwtRegisteredClaimNames.Email, user.Email),
        new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
        new Claim("FullName", user.FullName ?? ""),
        
        // 🔥 এই লাইনটা যোগ করো: সিকিউরিটি স্ট্যাম্প
        // এটা ডাটাবেস থেকে বর্তমান স্ট্যাম্পটা টোকেনে ভরে দিবে
        new Claim("SecurityStamp", user.SecurityStamp) 
    };

    // ... বাকি কোড আগের মতোই
}
```

#### **Step 2: Middleware আপডেট করা (চেকপোস্ট)**
মনে আছে **Lesson 12**-তে আমরা `UserStatusMiddleware` বানিয়েছিলাম? সেটা শুধু চেক করত ইউজার ডাটাবেসে আছে কিনা।
এখন আমরা চেক করব—**স্ট্যাম্প মিলছে কিনা?**

`Middlewares/UserStatusMiddleware.cs` আপডেট করো:

```csharp
using AuthMasterClass.Models;
using Microsoft.AspNetCore.Identity;
using System.Security.Claims;

namespace AuthMasterClass.Middlewares
{
    public class UserStatusMiddleware
    {
        private readonly RequestDelegate _next;

        public UserStatusMiddleware(RequestDelegate next)
        {
            _next = next;
        }

        public async Task InvokeAsync(HttpContext context, UserManager<AppUser> userManager)
        {
            if (context.User.Identity != null && context.User.Identity.IsAuthenticated)
            {
                var userId = context.User.FindFirst(ClaimTypes.NameIdentifier)?.Value 
                             ?? context.User.FindFirst("sub")?.Value;

                if (string.IsNullOrEmpty(userId))
                {
                    await _next(context);
                    return;
                }

                var user = await userManager.FindByIdAsync(userId);

                // ১. ইউজার না থাকলে ভাগাও
                if (user == null)
                {
                    context.Response.StatusCode = 401;
                    await context.Response.WriteAsync("User not found!");
                    return;
                }

                // ২. 🔥 নতুন লজিক: টোকেনের স্ট্যাম্প আর ডাটাবেসের স্ট্যাম্প মিলছে তো?
                var tokenStamp = context.User.FindFirst("SecurityStamp")?.Value;
                var dbStamp = user.SecurityStamp;

                if (tokenStamp != null && tokenStamp != dbStamp)
                {
                    // মিলেনি! তার মানে ইউজার পাসওয়ার্ড চেঞ্জ করেছে বা লগআউট অল ডিভাইসেস দিয়েছে।
                    context.Response.StatusCode = 401;
                    await context.Response.WriteAsJsonAsync(new { 
                        message = "Security Stamp changed! Please login again.",
                        isSuccess = false
                    });
                    return;
                }
            }

            await _next(context);
        }
    }
}
```
*(নোট: `Program.cs`-এ এই মিডলওয়্যারটা কিন্তু `UseAuthentication` এর পরে রেজিস্টার করা থাকতে হবে, যা আমরা লেসন ১২-তেই করেছি)*

### 🧪 টেস্টিং (চোর ধরা)

এই টেস্টটা করলে তুমি ফিল পাবে যে তোমার সিস্টেম কতটা সিকিউর!

১. **Login:** প্রথমে লগইন করো এবং টোকেনটা কপি করো। (ধরি এটা `Token_A`)।
   *   টোকেনটা দিয়ে `/api/account/profile` এ হিট করো।
   *   **Result:** `200 OK`।

২. **Change Password:** এবার `Token_A` ব্যবহার করেই `/api/account/change-password` এ হিট করো এবং পাসওয়ার্ড বদলে ফেলো।
   *   এই মেথডটা `UserManager.ChangePasswordAsync` কল করে, যেটা অটোমেটিক ডাটাবেসে `SecurityStamp` বদলে দেয়।

৩. **Attack with Old Token:** এবার হ্যাকার সাজার পালা। তোমার হাতে এখনো `Token_A` আছে। এটা দিয়ে আবার `/api/account/profile` এ হিট করো।
   *   **Result:** `401 Unauthorized`।
   *   **Message:** "Security Stamp changed! Please login again."

👉 **ম্যাজিক:** টোকেনের মেয়াদ ১ ঘণ্টা থাকলেও, পাসওয়ার্ড চেঞ্জ করার **১ সেকেন্ডের** মধ্যেই পুরোনো টোকেন বাতিল হয়ে গেছে! 😎

৪. **বোনাস চিন্তা:** এই মেকানিজম ব্যবহার করেই ফেসবুকে **"Log out of all devices"** বাটন কাজ করে। ওই বাটনে চাপ দিলে ফেসবুক জাস্ট ডাটাবেসে তোমার `SecurityStamp` টা চেঞ্জ করে দেয়। ফলে দুনিয়ার সব ডিভাইসের টোকেন একসাথে বাতিল হয়ে যায়! 💡
