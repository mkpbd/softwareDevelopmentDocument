### 🎓 Lesson 26: Refresh Token (Introduction & Setup) - মেম্বারশিপ কার্ড

এতদিন আমরা যে JWT টোকেন ব্যবহার করেছি, তার একটা বড় সমস্যা আছে।
নিরাপত্তার খাতিরে অ্যাক্সেস টোকেনের মেয়াদ কম রাখতে হয় (যেমন ৫-১০ মিনিট)।
কিন্তু ৫ মিনিট পর পর যদি ইউজারকে বলি—*"ভাই, আবার লগইন করেন"*—তাহলে ইউজার বিরক্ত হয়ে অ্যাপ আন-ইন্সটল করে দিবে।

এই সমস্যার সমাধান হলো **Refresh Token**।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
আমরা ইউজারকে একসাথে দুইটা টোকেন দিব:
১. **Access Token:** মেয়াদ ৫ মিনিট। এটা দিয়ে সে ডাটা আনবে।
২. **Refresh Token:** মেয়াদ ৭ দিন। এটা সে সিন্দুক (Database) এ লুকিয়ে রাখবে।

৫ মিনিট পর যখন Access Token মরে যাবে, অ্যাপ অটোমেটিক ব্যাকগ্রাউন্ডে সার্ভারকে বলবে—*"ভাই, আমার টিকিট শেষ, কিন্তু এই দেখেন আমার মেম্বারশিপ কার্ড (Refresh Token)। আমাকে নতুন একটা টিকিট দেন।"*
ইউজার টেরও পাবে না যে ব্যাকগ্রাউন্ডে নতুন টোকেন জেনারেট হয়ে গেছে।

#### 🤣 ফানি অ্যানালজি (সিনেমার টিকিট বনাম মেম্বারশিপ কার্ড)

ধরো, তুমি স্টার সিনেপ্লেক্সে সিনেমা দেখছ।

১. **Access Token (Movie Ticket):** এটার মেয়াদ ৩ ঘণ্টা। সিনেমা শেষ হলে টিকিটের দাম শেষ। দারোয়ান তোমাকে বের করে দিবে।
২. **Refresh Token (Gold Membership Card):** সিনেমা শেষ হওয়ার পর তুমি কাউন্টারে গিয়ে এই কার্ড দেখালে।
কাউন্টার থেকে বলল—*"স্যার, যেহেতু আপনার কার্ড (Refresh Token) আছে, আপনাকে লাইন ধরা লাগবে না। এই নিন পরের শো-এর ফ্রি টিকিট (New Access Token)।"*

যদি তোমার কার্ড না থাকত, তাহলে তোমাকে আবার গেটের বাইরে গিয়ে লাইনে দাঁড়িয়ে টিকেট কাটতে হতো (Login Again)।

### 💻 Coding Example: Database Setup

রিফ্রেশ টোকেন ইমপ্লিমেন্ট করার প্রথম ধাপ হলো—এটাকে ডাটাবেসে সেভ করার ব্যবস্থা করা। কারণ রিফ্রেশ টোকেন চুরি হলে আমাদের সেটাকে **Revoke (বাতিল)** করার ক্ষমতা থাকতে হবে।

আজকে আমরা শুধু টেবিল স্ট্রাকচার রেডি করব।

**Step 1: RefreshToken মডেল বানানো**
`Models` ফোল্ডারে `RefreshToken.cs` নামে একটা ক্লাস বানাও।

```csharp
using System.ComponentModel.DataAnnotations.Schema;

namespace AuthMasterClass.Models
{
    public class RefreshToken
    {
        public int Id { get; set; }
        public string Token { get; set; } // সেই সিক্রেট রিফ্রেশ টোকেন স্ট্রিং
        public string JwtId { get; set; } // কোন অ্যাক্সেস টোকেনের সাথে এটা লিংকড?
        public bool IsUsed { get; set; } // এটা কি অলরেডি ব্যবহার হয়ে গেছে?
        public bool IsRevoked { get; set; } // এটা কি আমরা বাতিল করেছি? (চুরি হলে)
        public DateTime AddedDate { get; set; }
        public DateTime ExpiryDate { get; set; } // মেয়াদ (যেমন ৭ দিন)

        // কার টোকেন?
        public string UserId { get; set; }
        
        [ForeignKey(nameof(UserId))]
        public AppUser User { get; set; }
    }
}
```

**Step 2: DbContext আপডেট করা**
এখন ডাটাবেসকে বলতে হবে এই নতুন টেবিলটা বানাতে। `Data/AppDbContext.cs` এ যাও।

```csharp
// ...
public class AppDbContext : IdentityDbContext<AppUser>
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options)
    {
    }

    // এই লাইনটা যোগ করো

```

**Step 3: Migration চালানো (রাজমিস্ত্রি ডাকা)**

তুমি বলতে পারো—"মামা, অ্যাক্সেস টোকেন তো ডাটাবেসে রাখি না, রিফ্রেশ টোকেন কেন রাখব?"
কারণ **Access Token** কন্ট্রোল করা যায় না (একবার ইস্যু হলে মেয়াদ শেষ না হওয়া পর্যন্ত ভ্যালিড)।

### 🎓 Lesson 27: Generating & Saving Refresh Token - কম্বো অফার

রিফ্রেশ টোকেন আসলে আহামরি কিছু না। এটা জাস্ট একটা **Random String** (যেমন: `xk39...`). কিন্তু এটা ইউনিক হতে হয়।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
Access Token-এর ভেতরে অনেক ডাটা (Claims) থাকে, তাই ওটা সাইজে বড় হয়।
কিন্তু Refresh Token-এর ভেতরে কিছু থাকে না। এটা জাস্ট একটা এলোমেলো কোড।
আমরা ডাটাবেসে লিখে রাখব: **"এই কোডটা মিস্টার কুদ্দুসের। মেয়াদ ৭ দিন।"**

#### 🤣 ফানি অ্যানালজি (সিনেমার টিকিট ও কুপন)

ধরো, তুমি টিকিট কাউন্টারে গেলে।

১. **Access Token:** কাউন্টার থেকে সিনেমা দেখার টিকিট দিল। এটা দিয়ে তুমি এখনই হলে ঢুকতে পারবে।
২. **Refresh Token:** টিকিটের সাথে একটা ছোট **লাল কুপন** দিল। কাউন্টার ম্যান বলল—*"স্যার, এই কুপনটা যত্ন করে পকেটে রাখেন। সিনেমার টিকিট ৩ ঘণ্টা পর নষ্ট হয়ে যাবে। কিন্তু এই কুপন দেখালে আগামী ৭ দিনের মধ্যে আপনি ফ্রি আরেকটা টিকিট নিতে পারবেন।"*

আমাদের কাজ হলো ইউজারের পকেটে ওই **লাল কুপন**টা ঢুকিয়ে দেওয়া।

### 💻 Coding Example

আমাদের `AuthService` এ একটু বড়সড় চেঞ্জ হবে। ধাপে ধাপে আগাই।

#### **Step 1: DTO আপডেট করা**
আমাদের `AuthResponseDto` তে রিফ্রেশ টোকেন পাঠানোর জায়গা করতে হবে।
`DTOs/AuthResponseDto.cs`:

```csharp
namespace AuthMasterClass.DTOs
{
    public class AuthResponseDto
    {
        public bool IsSuccess { get; set; }
        public string Message { get; set; }
        public string Token { get; set; } // Access Token
        
        // 🔥 নতুন মেহমান
        public string RefreshToken { get; set; } 
    }
}
```

#### **Step 2: AuthService এ DbContext ইনজেক্ট করা**
রিফ্রেশ টোকেন সেভ করার জন্য আমাদের সরাসরি ডাটাবেস এক্সেস লাগবে। `UserManager` দিয়ে রিফ্রেশ টোকেন টেবিল হ্যান্ডেল করা যায় না।

`Services/AuthService.cs` এর শুরুতে:

```csharp
using AuthMasterClass.Data; // namespace add করো
using System.Security.Cryptography; // র‍্যান্ডম নাম্বার জেনারেটরের জন্য

// ...

public class AuthService : IAuthService
{
    private readonly UserManager<AppUser> _userManager;
    private readonly IConfiguration _configuration;
    private readonly AppDbContext _context; // 🔥 নতুন: ডাটাবেস কানেকশন

    // কনস্ট্রাকটরে ইনজেক্ট করো
    public AuthService(UserManager<AppUser> userManager, IConfiguration configuration, AppDbContext context)
    {
        _userManager = userManager;
        _configuration = configuration;
        _context = context; // সেট করলাম
    }

    // ... বাকি মেথডগুলো নিচে ...
```

#### **Step 3: র‍্যান্ডম টোকেন জেনারেটর মেথড**
`AuthService` ক্লাসের নিচে একটা প্রাইভেট হেল্পার মেথড বানাও। এটা হুবহু কপি করো।

```csharp
    private string GenerateRefreshToken()
    {
        var randomNumber = new byte[32];
        using (var rng = RandomNumberGenerator.Create())
        {
            rng.GetBytes(randomNumber);
            return Convert.ToBase64String(randomNumber);
        }
    }
```

#### **Step 4: Login মেথড আপডেট (আসল কাজ)**
এখন `LoginAsync` মেথডে আমরা রিফ্রেশ টোকেন বানাব এবং সেভ করব।

```csharp
public async Task<AuthResponseDto> LoginAsync(LoginDto loginDto)
{
    var user = await _userManager.FindByEmailAsync(loginDto.Email);

    if (user == null || !await _userManager.CheckPasswordAsync(user, loginDto.Password))
    {
        return new AuthResponseDto { IsSuccess = false, Message = "Invalid Email or Password" };
    }

    // ১. অ্যাক্সেস টোকেন বানালাম
    // (GenerateToken মেথড এখন শুধু স্ট্রিং না দিয়ে JwtSecurityToken অবজেক্ট দিলে ভালো হতো, 
    // কিন্তু আপাতত আমরা সিম্পল রাখছি। টোকেন জেনারেশনের লজিকটা একটু নিচে চেঞ্জ করছি)
    
    var token = await GenerateJwtToken(user); // নামটা একটু চেঞ্জ করলাম বোঝার সুবিধার্থে

    // ২. রিফ্রেশ টোকেন বানালাম
    var refreshToken = GenerateRefreshToken();

    // ৩. ডাটাবেসে সেভ করার জন্য অবজেক্ট রেডি করি
    var refreshTokenEntity = new RefreshToken
    {
        JwtId = token.Id, // অ্যাক্সেস টোকেনের একটা ইউনিক আইডি (jti)
        IsUsed = false,
        IsRevoked = false,
        UserId = user.Id,
        AddedDate = DateTime.UtcNow,
        ExpiryDate = DateTime.UtcNow.AddDays(7), // মেয়াদ ৭ দিন
        Token = refreshToken
    };

    // ৪. সিন্দুকে জমা রাখি
    await _context.RefreshTokens.AddAsync(refreshTokenEntity);
    await _context.SaveChangesAsync();

    // ৫. কম্বো অফার রিটার্ন করি
    return new AuthResponseDto 
    { 
        IsSuccess = true, 
        Message = "Login Successful", 
        Token = new JwtSecurityTokenHandler().WriteToken(token), // স্ট্রিং বানালাম
        RefreshToken = refreshToken // কুপন দিয়ে দিলাম
    };
}
```

#### **⚠️ গুরুত্বপূর্ণ আপডেট: `GenerateJwtToken` মেথড**
আগের `GenerateToken` মেথডটা `string` রিটার্ন করত। এখন আমাদের `JwtSecurityToken` অবজেক্ট লাগবে, কারণ আমাদের `token.Id` (jti) দরকার রিফ্রেশ টোকেনের সাথে লিংক করার জন্য।

নিচের মেথডটা আপডেট করো:

```csharp
// রিটার্ন টাইপ চেঞ্জ: Task<string> থেকে Task<JwtSecurityToken>
private async Task<JwtSecurityToken> GenerateJwtToken(AppUser user)
{
    // ... আগের ক্লেইমস তৈরির কোড হুবহু সেইম ...
    var claims = new List<Claim> 
    {
        // ... sub, email, role, securitystamp ...
        new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()), // এই Jti খুব ইম্পরট্যান্ট
    };

    // ... Role Claims adding logic ...
    
    // ... Key creation logic ...

    var token = new JwtSecurityToken(
        issuer: _configuration["JwtSettings:issuer"],
        audience: _configuration["JwtSettings:audience"],
        claims: claims,
        expires: DateTime.UtcNow.AddMinutes(5), // ⚠️ অ্যাক্সেস টোকেনের মেয়াদ কমিয়ে ৫ মিনিট করে দাও
        signingCredentials: creds
    );

    return token; // স্ট্রিং না, পুরো অবজেক্ট পাঠাচ্ছি
}
```

### 🎓 Lesson 28: Refresh Token Logic - কুপন ভাঙিয়ে নতুন টিকিট

এই প্রসেসটা একটু সেনসিটিভ। কারণ এখানে আমরা **Expired Token** (মেয়াদ শেষ হওয়া টোকেন) হ্যান্ডেল করব। সাধারণত মেয়াদ শেষ টোকেন দেখলে সার্ভার এরর দেয়, কিন্তু এই স্পেসিফিক API-তে আমরা সেটাকে এলাউ করব শুধু চেক করার জন্য যে—"এটা কি আসলেই আমাদের ইস্যু করা টোকেন ছিল?"

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
১. ক্লায়েন্ট (React/App) দেখবে টোকেন কাজ করছে না (401 Error)।
২. সে ব্যাকগ্রাউন্ডে একটা রিকোয়েস্ট পাঠাবে: "ভাই, এই নাও আমার **পুরানো টোকেন** আর **রিফ্রেশ টোকেন**। আমাকে নতুন সেট দাও।"
৩. সার্ভার চেক করবে:
   *   রিফ্রেশ টোকেনটা কি ডাটাবেসে আছে?
   *   এটার মেয়াদ আছে তো?
   *   এটা কি আগে ব্যবহার (Used) বা বাতিল (Revoked) হয়েছে?
   *   পুরানো টোকেনের আইডি (Jti) আর রিফ্রেশ টোকেনের আইডির মিল আছে তো?
৪. সব ঠিক থাকলে সার্ভার **নতুন Access Token** এবং **নতুন Refresh Token** দিবে। আগের রিফ্রেশ টোকেনটাকে **"Used"** মার্ক করে দিবে।

#### 🤣 ফানি অ্যানালজি (পুরানো টাকা পরিবর্তন)

ধরো, তোমার কাছে একটা ছেঁড়া ১০০ টাকার নোট (Expired Token) আছে। তুমি ব্যাংকে গেলে।
ম্যানেজার বলল—*"ভাই, ছেঁড়া নোট বদলাতে হলে আপনার এনআইডি কার্ড (Refresh Token) লাগবে।"*

তুমি এনআইডি দিলে। ম্যানেজার চেক করল:
১. এনআইডি আসল কিনা।
২. এই এনআইডি দিয়ে আজকেই একবার টাকা তোলা হয়েছে কিনা (IsUsed Check)।

সব ঠিক থাকলে ম্যানেজার তোমার ছেঁড়া নোট রেখে নতুন কড়কড়ে নোট দিবে। আর খাতায় লিখে রাখবে—"এই এনআইডি দিয়ে একবার এক্সচেঞ্জ করা হয়েছে।"

**১. মেয়াদ শেষ হওয়া টোকেন পড়ার মেথড:**
সাধারণত টোকেন ভ্যালিডেট করতে গেলে মেয়াদ শেষ হলে এরর দেয়। আমাদের এমন একটা মেথড লাগবে যেটা মেয়াদ চেক করবে না, শুধু টোকেনের ভেতরের তথ্য (Principal) বের করে দিবে।

```csharp
// AuthService.cs এর ভেতরে হেল্পার মেথড

private ClaimsPrincipal GetPrincipalFromExpiredToken(string token)
{
    var tokenValidationParameters = new TokenValidationParameters
    {
        ValidateAudience = false,
        ValidateIssuer = false,
        ValidateIssuerSigningKey = true,
        IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_configuration["JwtSettings:securityKey"])),
        ValidateLifetime = false // 🔥 এইটাই ট্রিক! মেয়াদ চেক করব না।
    };

    var tokenHandler = new JwtSecurityTokenHandler();
    
    // টোকেন ভ্যালিডেট করে প্রিন্সিপাল বের করছি
    var principal = tokenHandler.ValidateToken(token, tokenValidationParameters, out SecurityToken securityToken);

    // চেক করছি এটা কি আসলেই HmacSha256 দিয়ে বানানো কিনা (নকল টোকেন কিনা)
    if (securityToken is not JwtSecurityToken jwtSecurityToken || 
        !jwtSecurityToken.Header.Alg.Equals(SecurityAlgorithms.HmacSha256, StringComparison.InvariantCultureIgnoreCase))
    {
        throw new SecurityTokenException("Invalid token");
    }

    return principal;
}
```

**২. আসল রিফ্রেশ টোকেন লজিক:**
এবার `IAuthService` ইন্টারফেসে `VerifyAndGenerateToken` মেথড ডিক্লেয়ার করো এবং `AuthService` ক্লাসে ইমপ্লিমেন্ট করো।

```csharp
// AuthService.cs

public async Task<AuthResponseDto> VerifyAndGenerateToken(TokenRequestDto tokenRequest)
{
    var jwtTokenHandler = new JwtSecurityTokenHandler();

    try 
    {
        // ১. অ্যাক্সেস টোকেন থেকে তথ্য বের করি (মেয়াদ চেক ছাড়া)
        // (এখানে একটু ট্রাই-ক্যাচ ব্লক রাখা ভালো যদি টোকেন একদমই ভুয়া হয়)
        var principal = GetPrincipalFromExpiredToken(tokenRequest.Token);
        var userId = principal.Claims.FirstOrDefault(x => x.Type == JwtRegisteredClaimNames.Sub)?.Value; // আমরা Sub এ আইডি রেখেছিলাম

        // ২. ডাটাবেস থেকে রিফ্রেশ টোকেন খুঁজি
        var storedRefreshToken = await _context.RefreshTokens
            .FirstOrDefaultAsync(x => x.Token == tokenRequest.RefreshToken);

        // ৩. হাজার রকমের চেক (Validation)
        if (storedRefreshToken == null)
        {
            return new AuthResponseDto { IsSuccess = false, Message = "Refresh token does not exist" };
        }

        // মেয়াদ শেষ?
        if (storedRefreshToken.ExpiryDate < DateTime.UtcNow)
        {
            return new AuthResponseDto { IsSuccess = false, Message = "Refresh token has expired" };
        }

        // অলরেডি ব্যবহার হয়েছে?
        if (storedRefreshToken.IsUsed)
        {
            return new AuthResponseDto { IsSuccess = false, Message = "Refresh token has been used" };
        }

        // বাতিল করা হয়েছে? (যেমন চোর ধরলে)
        if (storedRefreshToken.IsRevoked)
        {
            return new AuthResponseDto { IsSuccess = false, Message = "Refresh token has been revoked" };
        }

        // অ্যাক্সেস টোকেনের আইডির সাথে কি মিল আছে? (Jti Match)
        var jti = principal.Claims.FirstOrDefault(x => x.Type == JwtRegisteredClaimNames.Jti)?.Value;
        if (storedRefreshToken.JwtId != jti)
        {
            return new AuthResponseDto { IsSuccess = false, Message = "Token does not match" };
        }

        // ৪. সব ঠিক আছে! এখন পুরোনো কুপন মার্ক করো "Used"
        storedRefreshToken.IsUsed = true;
        _context.RefreshTokens.Update(storedRefreshToken);
        await _context.SaveChangesAsync();

        // ৫. নতুন এক সেট টোকেন বানাও (Rotation)
        var user = await _userManager.FindByIdAsync(userId);
        var newJwtToken = await GenerateJwtToken(user); // নতুন টিকেট
        var newRefreshToken = GenerateRefreshToken(); // নতুন কুপন

        // ৬. নতুন কুপন ডাটাবেসে রাখো
        var refreshTokenEntity = new RefreshToken
        {
            JwtId = newJwtToken.Id,
            IsUsed = false,
            IsRevoked = false,
            UserId = user.Id,
            AddedDate = DateTime.UtcNow,
            ExpiryDate = DateTime.UtcNow.AddDays(7),
            Token = newRefreshToken
        };

        await _context.RefreshTokens.AddAsync(refreshTokenEntity);
        await _context.SaveChangesAsync();

        // ৭. ইউজারকে নতুন সেট পাঠিয়ে দাও
        return new AuthResponseDto
        {
            IsSuccess = true,
            Token = new JwtSecurityTokenHandler().WriteToken(newJwtToken),
            RefreshToken = newRefreshToken,
            Message = "Token refreshed successfully!"
        };
    }
    catch(Exception ex)
    {
        return new AuthResponseDto { IsSuccess = false, Message = "Something went wrong: " + ex.Message };
    }
}
```

{

    {

    }

#### 🤣 ফানি অ্যানালজি (সিম কার্ড কেনা)

ধরো, তুমি দোকানে গিয়ে একটা সিম কার্ড কিনলে।

১. **রেজিস্ট্রেশন:** দোকানদার তোমার নাম-ঠিকানা নিল। সিম দিল। কিন্তু সিমে নেটওয়ার্ক নাই।
২. **ভেরিফিকেশন:** কাস্টমার কেয়ার থেকে তোমার ফোনে একটা কোড পাঠাল।
৩. **কনফার্মেশন:** তোমাকে বলল—*"ভাই, ওই কোডটা আমাকে বলেন।"*
তুমি যদি কোডটা বলতে পারো, তবেই সিম চালু হবে। না পারলে সিম বন্ধ।

আমাদের সিস্টেমে ওই **"লিংকে ক্লিক করা"** মানেই হলো কোড বলে দেওয়া।

### 💻 Coding Example

আজকে আমরা ইমেইল পাঠানোর কোড (SMTP) লিখব না, কারণ ওটা আলাদা টপিক। আমরা লিংকটা জেনারেট করে **API Response**-এ দেখিয়ে দিব, যাতে তুমি টেস্ট করতে পারো।

#### **Step 1: ইমেইল কনফার্মেশন বাধ্যতামূলক করা**
`Program.cs` ফাইলে যাও। যেখানে `AddIdentity` কনফিগার করা আছে, সেখানে একটা লাইন যোগ করো।

```csharp
builder.Services.AddIdentity<AppUser, IdentityRole>(options =>
{
    options.Password.RequireDigit = true;
    options.Password.RequiredLength = 6;
    
    // 🔥 এই লাইনটা যোগ করো: ইমেইল কনফার্ম না হলে লগইন করতে দিবে না
    options.SignIn.RequireConfirmedEmail = true; 
})
.AddEntityFrameworkStores<AppDbContext>()
.AddDefaultTokenProviders(); // টোকেন জেনারেটর অবশ্যই লাগবে
```

**⚠️ সতর্কবার্তা:** এই লাইন যোগ করার পর, তোমার পুরোনো ইউজাররা (যারা কনফার্মড না) আর লগইন করতে পারবে না। টেস্ট করার জন্য ডাটাবেস থেকে তাদের `EmailConfirmed` কলাম `True` করে দিও, অথবা নতুন ইউজার বানাও।

#### **Step 2: লিংক জেনারেশন (AuthService)**
`AuthService.cs` এর `RegisterAsync` মেথড আপডেট করতে হবে। ইউজার তৈরির পর আমরা টোকেন জেনারেট করব।

*(উপরে `using Microsoft.AspNetCore.WebUtilities;` এবং `using System.Text;` এড করে নিও)*

```csharp
public async Task<AuthResponseDto> RegisterAsync(RegisterDto registerDto)
{
    var user = new AppUser
    {
        UserName = registerDto.Email,
        Email = registerDto.Email,
        FullName = registerDto.FullName
    };

    var result = await _userManager.CreateAsync(user, registerDto.Password);

    if (result.Succeeded)
    {
        // ১. ইমেইল কনফার্মেশন টোকেন জেনারেট করা
        var token = await _userManager.GenerateEmailConfirmationTokenAsync(user);

        // ২. টোকেনটা URL-Safe করার জন্য এনকোড করা (খুবই জরুরি!)
        // টোকেনে +, / বা = থাকতে পারে যা URL এ ঝামেলা করে। তাই এনকোডিং।
        var encodedToken = WebEncoders.Base64UrlEncode(Encoding.UTF8.GetBytes(token));

        // ৩. লিংক তৈরি করা (লোকালহোস্টের পোর্ট তোমারটা বসাবে)
        // রিয়েল লাইফে এখানে ফ্রন্টএন্ডের URL থাকে। আমরা সরাসরি API এর লিংক দিচ্ছি।
        var confirmationLink = $"https://localhost:7001/api/account/confirm-email?userId={user.Id}&token={encodedToken}";

        // ৪. ইমেইল পাঠানো (Mocking)
        // এখানে আসলে SendEmailAsync(user.Email, confirmationLink) কল হবে।
        // শেখার জন্য আমরা লিংকটা মেসেজেই রিটার্ন করছি।
        
        return new AuthResponseDto 
        { 
            IsSuccess = true, 
            Message = $"User Registered! Please confirm email. Link: {confirmationLink}" 
        };
    }
    
    return new AuthResponseDto { IsSuccess = false, Message = result.Errors.First().Description };
}
```

#### **Step 3: কনফার্মেশন লজিক (AuthService)**
এখন ইউজার যখন লিংকে ক্লিক করবে, তখন কি হবে? সেটা হ্যান্ডেল করতে হবে।

`AuthService` এ নতুন মেথড বানাও:

```csharp
// ইন্টারফেসেও এড করে নিও: Task<AuthResponseDto> ConfirmEmail(string userId, string token);

public async Task<AuthResponseDto> ConfirmEmail(string userId, string token)
{
    var user = await _userManager.FindByIdAsync(userId);
    if (user == null) return new AuthResponseDto { IsSuccess = false, Message = "User not found" };

    // ১. টোকেন ডিকোড করা (যেহেতু আমরা এনকোড করে পাঠিয়েছিলাম)
    var decodedToken = Encoding.UTF8.GetString(WebEncoders.Base64UrlDecode(token));

    // ২. আইডেন্টিটির মেথড কল করা: এটাই চেক করবে টোকেন ঠিক আছে কিনা
    var result = await _userManager.ConfirmEmailAsync(user, decodedToken);

    if (result.Succeeded)
    {
        return new AuthResponseDto { IsSuccess = true, Message = "Email confirmed successfully! Now you can login." };
    }

    return new AuthResponseDto { IsSuccess = false, Message = "Email confirmation failed" };
}
```

#### **Step 4: Controller এ API বানানো**
`AccountController.cs` এ নতুন এন্ডপয়েন্ট:

```csharp
[HttpGet("confirm-email")] // এটা GET মেথড, কারণ ব্রাউজার বা ইমেইল থেকে হিট হবে
public async Task<IActionResult> ConfirmEmail(string userId, string token)
{
    if (string.IsNullOrWhiteSpace(userId) || string.IsNullOrWhiteSpace(token))
        return BadRequest("Invalid request");

    var result = await _authService.ConfirmEmail(userId, token);

    if (result.IsSuccess)
    {
        return Ok(result.Message); // বা ফ্রন্টএন্ডের "Success Page" এ রিডাইরেক্ট করতে পারো
    }

    return BadRequest(result.Message);
}
```

### 🧪 টেস্টিং (সত্যতা যাচাই)

১. **Register:** নতুন একটা ইমেইল দিয়ে `/register` API কল করো।
   *   **Response:** দেখবে মেসেজের ভেতর একটা বিশাল লিংক এসেছে। (যেমন: `...confirm-email?userId=xyz&token=abc...`)
   
২. **Try Login (Fail):** লিংকটা ক্লিক করার **আগে** ওই ইমেইল দিয়ে `/login` করার চেষ্টা করো।
   *   **Result:** `401` বা `Invalid login attempt`। (কারণ `RequireConfirmedEmail = true` করা আছে)।

৩. **Confirm:** রেসপন্স থেকে পাওয়া লিংকটা কপি করে ব্রাউজারের ট্যাবে পেস্ট করো এবং এন্টার দাও।
   *   **Result:** "Email confirmed successfully!" মেসেজ দেখাবে।
   *   **DB Check:** ডাটাবেসে `AspNetUsers` টেবিলে দেখো ওই ইউজারের `EmailConfirmed` কলাম `1` (True) হয়ে গেছে।

৪. **Try Login (Success):** এবার আবার `/login` করো।
   *   **Result:** `200 OK` এবং টোকেন পাবে। 🎉

### 🎓 Lesson 30: Google Login & Course Wrap-up - বড় ভাইয়ের সুপারিশ

Google Login মানে হলো—আমরা ইউজারের পাসওয়ার্ড চেক করব না। আমরা গুগলকে জিজ্ঞেস করব—"এই লোকটাকে কি তুমি চিনো?" গুগল যদি বলে "হ্যাঁ", তাহলে আমরা তাকে ঢুকতে দিব।

#### 🇧🇩 সহজ বাংলায় ব্যাখ্যা
তুমি একটা ক্লাবে ঢুকতে চাও।
*   **Normal Auth:** ফর্ম ফিলাপ করে, আইডি জমা দিয়ে মেম্বারশিপ কার্ড বানাতে হবে। (বিরক্তিকর)।
*   **Google Auth:** তুমি গেটে গিয়ে বললে—"আমি **গুগল মামার** ছোট ভাই।"
    দারোয়ান গুগল মামাকে ফোন দিল। গুগল মামা বলল—*"হ্যাঁ, ও আমার পরিচিত। ওকে ঢুকতে দাও।"*
    দারোয়ান তোমাকে স্যালুট দিয়ে ঢুকতে দিল। তোমার কোনো কার্ড বা পাসওয়ার্ড লাগল না।

#### 💻 Step-by-Step Google Auth Setup

এটা করার জন্য আমাদের গুগল ক্লাউড কনসোল থেকে পারমিশন নিতে হবে।

**Step 1: Google Console Setup (খুবই জরুরি)**
১. [Google Cloud Console](https://console.cloud.google.com/)-এ যাও।
২. নতুন একটা **Project** ক্রিয়েট করো।
৩. **"APIs & Services"** -> **"Credentials"** এ যাও।
৪. **"Create Credentials"** -> **"OAuth client ID"** সিলেক্ট করো।
৫. Application Type: **Web Application**।
৬. **Redirect URI:** এখানে লজিক আছে। আমাদের অ্যাপের ব্যাকএন্ডের একটা ঠিকানা দিতে হবে যেখানে গুগল রেজাল্ট পাঠাবে।
   *   লিখো: `https://localhost:7001/signin-google` (তোমার পোর্ট অনুযায়ী)।
৭. ক্রিয়েট করলে তুমি দুইটা জিনিস পাবে:
   *   **Client ID**
   *   **Client Secret**
   *(এই দুইটা নোটপ্যাডে কপি করে রাখো)*

**Step 2: Package Install**
VS Code টার্মিনালে কমান্ড দাও:

```bash
dotnet add package Microsoft.AspNetCore.Authentication.Google
```

**Step 3: AppSettings আপডেট**
`appsettings.json` ফাইলে গুগলের সিক্রেট রাখো।

```json
  "Authentication": {
    "Google": {
      "ClientId": "তোমার-কপি-করা-আইডি.apps.googleusercontent.com",
      "ClientSecret": "তোমার-কপি-করা-সিক্রেট"
    }
  }
```

**Step 4: Program.cs কনফিগারেশন**
`builder.Services.AddAuthentication` এর চেইনে গুগল এড করতে হবে।

```csharp
// Program.cs

builder.Services.AddAuthentication(options => {
    // ... আগের ডিফল্ট স্কিম
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options => { /* ... আগের কনফিগ ... */ })
.AddGoogle(googleOptions =>
{
    // appsettings থেকে ভ্যালুগুলো নিচ্ছি
    googleOptions.ClientId = builder.Configuration["Authentication:Google:ClientId"];
    googleOptions.ClientSecret = builder.Configuration["Authentication:Google:ClientSecret"];
});
```

**Step 5: AccountController (লজিক হ্যান্ডেলিং)**
Web API তে সোশ্যাল লগইন একটু ট্রিকি। সাধারণত ফ্রন্টএন্ড (React) গুগলের সাথে কথা বলে একটা টোকেন এনে ব্যাকএন্ডে দেয়।
কিন্তু আমরা যেহেতু শুধু ব্যাকএন্ড শিখছি, আমরা **Redirect Flow** দেখব।

`AccountController.cs` এ দুইটা নতুন মেথড নাও:

```csharp
    // ১. ইউজার এই লিংকে ক্লিক করলে আমরা তাকে গুগলের লগইন পেজে পাঠিয়ে দিব
    [HttpGet("login-google")]
    public IActionResult LoginGoogle()
    {
        var properties = new AuthenticationProperties { RedirectUri = Url.Action("GoogleResponse") };
        // গুগলকে বলছি: লগইন শেষ হলে "GoogleResponse" মেথডে ফেরত পাঠাবা
        return Challenge(properties, GoogleDefaults.AuthenticationScheme);
    }

    // ২. গুগল লগইন শেষে ইউজারকে এই মেথডে ফেরত পাঠাবে
    [HttpGet("google-response")]
    public async Task<IActionResult> GoogleResponse()
    {
        // গুগলের পাঠানো কুকি থেকে ইনফো বের করি
        var result = await HttpContext.AuthenticateAsync(CookieAuthenticationDefaults.AuthenticationScheme);
        
        // নোট: রিয়েল এপিআইতে এখানে একটু ভিন্ন কনফিগারেশন লাগে (Cookie vs Token)।
        // শেখার খাতিরে ধরে নিচ্ছি আমরা ইউজারের ইমেইলটা ক্লেইম থেকে পাচ্ছি।
        
        var claims = result.Principal.Identities.FirstOrDefault().Claims;
        var email = claims.FirstOrDefault(c => c.Type == ClaimTypes.Email)?.Value;

        if (email == null) return BadRequest("Google authentication failed");

        // ৩. এখন আমাদের সিস্টেমে চেক করি এই ইমেইল আছে কিনা
        var user = await _userManager.FindByEmailAsync(email);

        if (user == null)
        {
            // ইউজার না থাকলে অটোমেটিক রেজিস্ট্রেশন করিয়ে দিই
            user = new AppUser { UserName = email, Email = email, FullName = "Google User" };
            await _userManager.CreateAsync(user); // পাসওয়ার্ড ছাড়াই বানালাম (বা ডামি পাসওয়ার্ড দিতে পারো)
        }

        // ৪. আমাদের অ্যাপের JWT টোকেন জেনারেট করি
        // (কারণ গুগলের টোকেন দিয়ে আমাদের অ্যাপের অথরাইজেশন হবে না)
        var token = GenerateToken(user); 

        return Ok(new { Token = token, Message = "Logged in with Google!" });
    }
```

### 📜 The Master Checklist: Best Practices (গুরুমন্ত্র)

মামা, কোর্স শেষ করার আগে এই উপদেশগুলো মনে রেখো। ইন্টারভিউতে এবং রিয়েল লাইফে এগুলোই তোমাকে সিনিয়রের সম্মান দিবে।

1.  **Never Commit Secrets:** `appsettings.json` এ আসল পাসওয়ার্ড বা সিক্রেট কি রেখে গিটহাবে পুশ করবে না। রিয়েল প্রজেক্টে **User Secrets** বা **Azure Key Vault** ব্যবহার করবে।
2.  **Use HTTPS:** প্রোডাকশনে অবশ্যই HTTPS ব্যবহার করবে। নইলে টোকেন হ্যাক হতে পারে।
3.  **Short Lived Access Token:** অ্যাক্সেস টোকেনের মেয়াদ কখনো ১৫-২০ মিনিটের বেশি দিবে না। রিফ্রেশ টোকেন ব্যবহার করবে।
4.  **Validate Inputs:** ইউজার যা দিবে, তা চোখ বন্ধ করে বিশ্বাস করবে না। DTO তে সবসময় `[Required]`, `[EmailAddress]` এগুলো ব্যবহার করবে।
5.  **Keep Controllers Thin:** কন্ট্রোলারে লজিক লিখবে না। সব লজিক **Service Layer** এ থাকবে। (Lesson 15 মনে আছে তো?)
6.  **Use Async/Await:** ডাটাবেস কলে সবসময় `await` ব্যবহার করবে। অ্যাপ ফাস্ট থাকবে।
7.  **Generic Response:** লগইনে ফেইল করলে বলবেনা "পাসওয়ার্ড ভুল"। বলবে "ইমেইল বা পাসওয়ার্ড ভুল"। হ্যাকারকে ক্লু দেওয়া যাবে না।
