### ১. লগিং সেটআপ (NLog Integration)
আমরা যখন ডেভেলপমেন্ট করি, তখন এরর দেখার জন্য `Console` ব্যবহার করি। কিন্তু লাইভ সার্ভারে (Production) কী সমস্যা হচ্ছে তা বোঝার জন্য একটি টেক্সট ফাইলে লগ বা রেকর্ড রাখা জরুরি।

*   **কেন দরকার:** অ্যাপ ক্র্যাশ করলে বা স্লো হলে আপনি লগ ফাইল দেখে বুঝতে পারবেন কোথায় সমস্যা হয়েছে।
*   **কি ব্যবহার করা হয়েছে:** বইটিতে **NLog** লাইব্রেরি ব্যবহার করা হয়েছে।
*   **অ্যাবস্ট্রাকশন (Abstraction):** বইটির লেখক সরাসরি NLog ব্যবহার করেননি। তিনি প্রথমে একটি ইন্টারফেস `ILoggerManager` তৈরি করেছেন।
    *   *সুবিধা:* ভবিষ্যতে যদি আপনি NLog বাদ দিয়ে Serilog বা অন্য কিছু ব্যবহার করতে চান, তবে পুরো প্রজেক্টের কোড পরিবর্তন করতে হবে না, শুধু কনফিগারেশন পাল্টালেই হবে।

### ২. প্রজেক্ট আর্কিটেকচার (Layered/Onion Architecture)
এটি এই চ্যাপ্টারের সবচেয়ে গুরুত্বপূর্ণ অংশ। সব কোড এক জায়গায় না লিখে বিভিন্ন লেয়ারে ভাগ করা হয়েছে। একে **Separation of Concerns** বলা হয়।

বইটিতে প্রজেক্টটিকে কয়েকটি আলাদা Class Library-তে ভাগ করা হয়েছে:

1.  **Entities (Domain Layer):**
    *   এখানে ডাটাবেসের মডেলগুলো থাকে (যেমন: `Employee`, `Company` ক্লাস)।
    *   এখানে `Exceptions` (কাস্টম এরর মেসেজ) থাকে।
    *   এই লেয়ারটি অন্য কোনো লেয়ারের ওপর নির্ভর করে না। এটি সবার কেন্দ্রে থাকে।

2.  **Contracts (Interfaces):**
    *   এখানে শুধু ইন্টারফেসগুলো থাকে (যেমন: `IRepositoryManager`, `ILoggerManager`)।
    *   এটি ডিফাইন করে যে অ্যাপটি কী কী কাজ করবে, কিন্তু *কীভাবে* করবে তা এখানে লেখা থাকে না।

3.  **Repository (Infrastructure Layer):**
    *   এখানে ডাটাবেসের সাথে যোগাযোগের কোড থাকে (EF Core)।
    *   ডাটা আনা-নেওয়ার আসল কাজ এখানেই হয়।

4.  **Service (Business Logic Layer):**
    *   এখানে আসল লজিক থাকে।
    *   কন্ট্রোলার ডাটা চায় সার্ভিসের কাছে, সার্ভিস ডাটা আনে রিপোজিটরির কাছ থেকে। আবার ডাটা পাওয়ার পর যদি কোনো প্রসেসিং (Validation, Check) দরকার হয়, তা এখানে করা হয়।

5.  **Presentation (Controllers):**
    *   লেখক `Program.cs` ওয়ালা মেইন প্রজেক্ট থেকে কন্ট্রোলারগুলোকে বের করে একটি আলাদা লাইব্রেরিতে (`CompanyEmployees.Presentation`) নিয়ে গেছেন।
    *   এর ফলে API প্রজেক্টটি খুবই হালকা থাকে এবং কন্ট্রোলারগুলো অন্য প্রজেক্টের ওপর নির্ভরশীল থাকে না।

### ৩. Entity Framework Core এবং Database কানেকশন
ডাটাবেসের সাথে কাজ করার জন্য এই চ্যাপ্টারে SQL Server এবং EF Core কনফিগার করা হয়েছে।

*   **DbContext:** `RepositoryContext` নামে একটি ক্লাস তৈরি করা হয়েছে যা ডাটাবেসের সাথে ব্রিজ হিসেবে কাজ করে।
*   **DbSet:** `DbSet<Company>` এবং `DbSet<Employee>` প্রপার্টি ডিক্লেয়ার করা হয়েছে যাতে আমরা টেবিলে কুয়েরি করতে পারি।
*   **Context Configuration:** `Program.cs`-এ (বা এক্সটেনশন মেথডে) SQL কানেকশন স্ট্রিং বলে দেওয়া হয়েছে।

### ৪. Repository Pattern (Generic Repository)
সাধারণত আমরা কন্ট্রোলারের ভেতরেই সরাসরি `DbContext` কল করে ডাটা আনি। কিন্তু বড় প্রজেক্টে এটি খারাপ প্র্যাকটিস। তাই লেখক **Repository Pattern** ব্যবহার করেছেন।

*   **RepositoryBase:** একটি জেনেরিক ক্লাস তৈরি করা হয়েছে যেখানে কমন কাজগুলো (Create, Update, Delete, FindAll) একবার লেখা হয়েছে।
    *   *সুবিধা:* প্রতিটা টেবিলের জন্য বারবার `Add` বা `Remove` কোড লিখতে হয় না।
*   **Specific Repository:** `CompanyRepository` বা `EmployeeRepository` তৈরি করা হয়েছে যা `RepositoryBase` কে ইনহেরিট করে। স্পেশাল কোনো কুয়েরি দরকার হলে এখানে লেখা হয়।

---

### ৫. Repository Manager (Unit of Work)
আপনার যদি একই রিকোয়েস্টে `Company` এবং `Employee` দুটো টেবিলে সেভ করার দরকার হয়, তবে দুবার `SaveChanges` কল করা উচিত নয়।

*   **RepositoryManager:** এটি একটি র‍্যাপার (Wrapper) ক্লাস। এটি সব রিপোজিটরির অবজেক্ট তৈরি করে এবং সবার শেষে একবার মাত্র `SaveChanges` মেথড কল করে। এতে ডাটাবেস ট্রানজেকশন ঠিক থাকে।

---

### ৬. Dependency Injection (DI)
সবশেষে, এই আলাদা আলাদা লেয়ার বা ক্লাসগুলোকে `Program.cs` ফাইলে যুক্ত করা হয়েছে **Dependency Injection** কন্টেইনারের মাধ্যমে।

*   উদাহরণ: `builder.Services.AddScoped<IRepositoryManager, RepositoryManager>();`
*   এর মানে হলো, অ্যাপের যেখানেই `IRepositoryManager` চাওয়া হবে, সেখানেই `RepositoryManager` এর একটি অবজেক্ট পাঠিয়ে দেওয়া হবে।

### ২. লগিং সেটআপ (Logging with NLog)

আমরা কনসোল লগের বদলে টেক্সট ফাইলে লগ রাখব।

**ধাপ ১: ইন্টারফেস তৈরি (Contracts)**
**ফাইল:** `Contracts/ILoggerManager.cs`
```csharp
namespace Contracts
{
    public interface ILoggerManager
    {
        void LogInfo(string message);
        void LogWarn(string message);
        void LogDebug(string message);
        void LogError(string message);
    }
}
```

**ধাপ ২: ইমপ্লিমেন্টেশন (LoggerService)**
প্রথমে `NLog.Extensions.Logging` প্যাকেজটি ইন্সটল করুন।

**ফাইল:** `LoggerService/LoggerManager.cs`
```csharp
using Contracts;
using NLog;

namespace LoggerService
{
    public class LoggerManager : ILoggerManager
    {
        private static ILogger logger = LogManager.GetCurrentClassLogger();

        public LoggerManager() { }

        public void LogDebug(string message) => logger.Debug(message);
        public void LogError(string message) => logger.Error(message);
        public void LogInfo(string message) => logger.Info(message);
        public void LogWarn(string message) => logger.Warn(message);
    }
}
```

**ধাপ ৩: কনফিগারেশন ফাইল (Main Project)**
মেইন প্রজেক্টে `nlog.config` নামে একটি ফাইল তৈরি করুন।

```xml
<?xml version="1.0" encoding="utf-8" ?>
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
      autoReload="true"
      internalLogLevel="Trace"
      internalLogFile=".\internal_logs\internallog.txt">

  <targets>
    <target name="logfile" xsi:type="File"
            fileName=".\logs\${shortdate}_logfile.txt"
            layout="${longdate} ${level:uppercase=true} ${message}"/>
  </targets>

  <rules>
    <logger name="*" minlevel="Debug" writeTo="logfile" />
  </rules>
</nlog>
```

### ৫. রিপোজিটরি প্যাটার্ন (Repository Pattern)

আমরা কমন কোডগুলো এক জায়গায় লিখব।

**ফাইল:** `Repository/RepositoryBase.cs`
```csharp
using Contracts;
using Microsoft.EntityFrameworkCore;
using System.Linq.Expressions;

namespace Repository
{
    public abstract class RepositoryBase<T> : IRepositoryBase<T> where T : class
    {
        protected RepositoryContext RepositoryContext;

        public RepositoryBase(RepositoryContext repositoryContext)
            => RepositoryContext = repositoryContext;

        public IQueryable<T> FindAll(bool trackChanges) =>
            !trackChanges ?
              RepositoryContext.Set<T>().AsNoTracking() :
              RepositoryContext.Set<T>();

        public IQueryable<T> FindByCondition(Expression<Func<T, bool>> expression,
        bool trackChanges) =>
            !trackChanges ?
              RepositoryContext.Set<T>().Where(expression).AsNoTracking() :
              RepositoryContext.Set<T>().Where(expression);

        public void Create(T entity) => RepositoryContext.Set<T>().Add(entity);
        public void Update(T entity) => RepositoryContext.Set<T>().Update(entity);
        public void Delete(T entity) => RepositoryContext.Set<T>().Remove(entity);
    }
}
```

### ৬. সার্ভিস রেজিস্ট্রেশন (ServiceExtensions.cs)

এখন মেইন প্রজেক্টে `Extensions/ServiceExtensions.cs` ফাইলে ডাটাবেস এবং রিপোজিটরি ম্যানেজার রেজিস্টার করতে হবে।

**ফাইল:** `Extensions/ServiceExtensions.cs`

```csharp
// ১. লগার সার্ভিস
public static void ConfigureLoggerService(this IServiceCollection services) =>
    services.AddSingleton<ILoggerManager, LoggerManager>();

// ২. SQL কানেকশন
public static void ConfigureSqlContext(this IServiceCollection services, IConfiguration configuration) =>
    services.AddDbContext<RepositoryContext>(opts =>
        opts.UseSqlServer(configuration.GetConnectionString("sqlConnection")));

// ৩. রিপোজিটরি ম্যানেজার (Unit of Work)
public static void ConfigureRepositoryManager(this IServiceCollection services) =>
    services.AddScoped<IRepositoryManager, RepositoryManager>();
```

**appsettings.json এ কানেকশন স্ট্রিং:**
```json
"ConnectionStrings": {
    "sqlConnection": "server=.; database=CompanyEmployeeDB; Integrated Security=true; TrustServerCertificate=true"
}
```
