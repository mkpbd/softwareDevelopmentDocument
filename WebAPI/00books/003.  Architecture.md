
**Chapter 3**-এর নাম সাধারণত **"Handling GET Requests"** বা **"Basic CRUD & Layers"** হয়ে থাকে।

Chapter 2-তে আমরা প্রোজেক্টের **কাঠামো (Architecture)** এবং **ডাটাবেস লেয়ার (Repository)** তৈরি করেছিলাম। কিন্তু কন্ট্রোলার থেকে সরাসরি রিপোজিটরি কল করা ভালো প্র্যাকটিস নয়।

Chapter 3-তে মূলত **Service Layer** তৈরি করা হয় এবং **Controller** ও **Repository**-র মাঝখানে **Business Logic** বসানো হয়। এছাড়াও **DTO** এবং **Global Error Handling** নিয়ে বিস্তারিত কাজ করা হয়।

নিচে চ্যাপ্টার ৩-এর মূল বিষয়গুলো বিস্তারিত আলোচনা করা হলো:

### ১. সার্ভিস লেয়ার (Service Layer) তৈরি
আগের চ্যাপ্টারে আমাদের `RepositoryManager` ছিল। কিন্তু আর্কিটেকচারাল নিয়ম অনুযায়ী, কন্ট্রোলার বা প্রেজেন্টেশন লেয়ার সরাসরি ডাটাবেস লেয়ারের (Repository) সাথে কথা বলবে না।

*   **কেন দরকার:** কন্ট্রোলারের কাজ শুধু রিকোয়েস্ট নেওয়া এবং রেসপন্স দেওয়া। যদি কোনো লজিক থাকে (যেমন: ডেটা চেক করা, ক্যালকুলেশন করা), তবে সেটা **Service Layer**-এ করতে হবে।
*   **ServiceManager:** রিপোজিটরির মতো এখানেও একটি `ServiceManager` তৈরি করা হয়, যা সব সার্ভিসকে (CompanyService, EmployeeService) এক জায়গায় রাখে।
*   **ফ্লো:** Controller -> **ServiceManager** -> RepositoryManager -> Database.

### ২. DTO (Data Transfer Objects) এর ব্যবহার
আমরা ডাটাবেসের মডেল বা এনটিটি (যেমন `Company` ক্লাস) সরাসরি ইউজারকে রিটার্ন করি না।

*   **সমস্যা:** এনটিটি সরাসরি রিটার্ন করলে সিকিউরিটি সমস্যা হতে পারে (পাসওয়ার্ড বা ইন্টারনাল ফিল্ড ফাঁস হতে পারে) এবং "Circular Reference" এরর হতে পারে।
*   **সমাধান (DTO):** আমরা `CompanyDto` নামে একটি ক্লাস বানাই যেখানে শুধু সেই প্রপার্টিগুলো থাকে যা আমরা ইউজারকে দেখাতে চাই।
*   **AutoMapper:** এনটিটি (Database Model) থেকে DTO-তে ডাটা কপি করার জন্য ম্যানুয়ালি কোড না লিখে **AutoMapper** লাইব্রেরি ব্যবহার করা হয়। এটি অটোমেটিক্যালি ডাটা কনভার্ট করে দেয়।

### ৩. কন্ট্রোলার সেটআপ (Presentation Layer)
এই চ্যাপ্টারে প্রথম API কন্ট্রোলার তৈরি করা হয়। লেখক কন্ট্রোলারগুলোকে মেইন প্রজেক্টে না রেখে `Presentation` নামক আলাদা ক্লাস লাইব্রেরিতে রেখেছেন।

*   **Dependency Injection:** কন্ট্রোলারের কনস্ট্রাক্টরে `IServiceManager` ইনজেক্ট করা হয়।
*   **Routing:** `[Route("api/companies")]` অ্যাট্রিবিউট ব্যবহার করে API এর ঠিকানা ঠিক করা হয়।
*   **Action Methods:** `GetCompanies` মেথড তৈরি করা হয় যা সার্ভিস লেয়ার থেকে ডাটা এনে `Ok()` রেসপন্স রিটার্ন করে।

### ৪. গ্লোবাল এরর হ্যান্ডলিং (Global Error Handling)
ডেভেলপাররা সাধারণত প্রতিটা মেথডে `try-catch` ব্লক ব্যবহার করে এরর হ্যান্ডেল করেন। কিন্তু এতে কোড দেখতে খারাপ হয় এবং বারবার একই কোড লিখতে হয়।

*   **সমাধান:** একটি **Global Exception Handler** বা মিডলওয়্যার তৈরি করা হয়।
*   **কীভাবে কাজ করে:** অ্যাপ্লিকেশনের যেকোনো জায়গায় এরর হলে, এই মিডলওয়্যার সেটি ধরে ফেলে এবং ইউজারকে একটি সুন্দর JSON ফরম্যাটে এরর মেসেজ (যেমন: "Internal Server Error") রিটার্ন করে।
*   **.NET 8 Feature:** বইটির নতুন এডিশনে .NET 8 এর `IExceptionHandler` ইন্টারফেস ব্যবহার করে এটি আরও আধুনিক উপায়ে করা হয়েছে।

### ৫. পুরো প্রসেসটির একটি উদাহরণ (Data Flow)
ধরা যাক, একজন ইউজার সব কোম্পানির লিস্ট চাইল (`GET /api/companies`)। তখন ডাটা ফ্লো কেমন হবে?

1.  **User:** ব্রাউজার বা পোস্টম্যান থেকে রিকোয়েস্ট পাঠাল।
2.  **Middleware:** রিকোয়েস্ট রিসিভ করে **Controller**-এ পাঠাল।
3.  **Controller:** `Service.Company.GetAllCompanies()` মেথড কল করল।
4.  **Service Layer:** বিজনেস লজিক চেক করে `Repository.Company.FindAll()` কল করল।
5.  **Repository Layer:** ডাটাবেস থেকে `Company` এনটিটিগুলোর লিস্ট নিয়ে এল।
6.  **Service Layer:** `AutoMapper` ব্যবহার করে `Company` এনটিটিগুলোকে `CompanyDto`-তে কনভার্ট করল এবং কন্ট্রোলারে ফেরত দিল।
7.  **Controller:** `Ok(companyDtos)` রিটার্ন করল।
8.  **Response:** ইউজার JSON ডাটা দেখতে পেল।

### সারসংক্ষেপ (Summary of Chapter 3)
এই চ্যাপ্টার শেষ করার পর আপনি শিখবেন:
1.  কীভাবে **Service Layer** ইমপ্লিমেন্ট করে কন্ট্রোলার থেকে লজিক আলাদা করতে হয়।
2.  কেন এবং কীভাবে **DTO** ব্যবহার করতে হয়।
3.  **AutoMapper** দিয়ে ডাটা ম্যাপ করা।
4.  **Global Error Handling** সেটআপ করা, যাতে `try-catch` ব্লক বারবার লিখতে না হয়।

এটি মূলত একটি প্রফেশনাল API-এর "রিকোয়েস্ট প্রসেসিং পাইপলাইন" বা কাজের ধারা তৈরি করে দেয়।

### ১. DTO (Data Transfer Object) তৈরি
আমরা ডাটাবেসের এনটিটি সরাসরি রিটার্ন করব না। আমরা ক্লায়েন্টের জন্য `Shared/DataTransferObjects` ফোল্ডারে DTO বানাব।

**ফাইল:** `Shared/DataTransferObjects/CompanyDto.cs`
```csharp
// 'record' টাইপ ব্যবহার করা হয়েছে কারণ এটি ইমিউটেবল এবং দ্রুত কাজ করে (.NET ফিচার)
public record CompanyDto(Guid Id, string Name, string FullAddress);
```
*(এখানে লক্ষ্য করুন, এনটিটিতে `Address` এবং `Country` আলাদা ছিল, কিন্তু DTO তে আমরা `FullAddress` দিচ্ছি। আমরা এটি পরে কনক্যাটেনেট করব)*

### ২. সার্ভিস ইন্টারফেস (Contracts Layer)
সার্ভিস লেয়ারে কী কী মেথড থাকবে তা ডিফাইন করা।

**ফাইল:** `Contracts/ICompanyService.cs`
```csharp
using Shared.DataTransferObjects;

namespace Contracts
{
    public interface ICompanyService
    {
        // ট্র্যাক চেঞ্জেস প্যারামিটার নেওয়া হচ্ছে পারফরম্যান্স টিউনিংয়ের জন্য
        IEnumerable<CompanyDto> GetAllCompanies(bool trackChanges);
    }
}
```

### ৩. সার্ভিস ইমপ্লিমেন্টেশন (Service Layer)
এখানেই আসল লজিক এবং ম্যাপিং হবে।

**ফাইল:** `Service/CompanyService.cs`
```csharp
using AutoMapper;
using Contracts;
using Service.Contracts;
using Shared.DataTransferObjects;

namespace Service
{
    internal sealed class CompanyService : ICompanyService
    {
        private readonly IRepositoryManager _repository;
        private readonly ILoggerManager _logger;
        private readonly IMapper _mapper; // AutoMapper ইনজেক্ট করা হলো

        public CompanyService(IRepositoryManager repository, ILoggerManager logger, IMapper mapper)
        {
            _repository = repository;
            _logger = logger;
            _mapper = mapper;
        }

        public IEnumerable<CompanyDto> GetAllCompanies(bool trackChanges)
        {
            // ১. রিপোজিটরি থেকে ডাটা (Entity) আনা
            var companies = _repository.Company.GetAllCompanies(trackChanges);

            // ২. AutoMapper দিয়ে Entity -> DTO তে কনভার্ট করা
            var companiesDto = _mapper.Map<IEnumerable<CompanyDto>>(companies);

            // ৩. DTO রিটার্ন করা
            return companiesDto;
        }
    }
}
```

### ৪. AutoMapper প্রোফাইল সেটআপ
এনটিটির ডাটা কীভাবে DTO তে ম্যাপ হবে তা এখানে বলে দেওয়া হয়।

**ফাইল:** `MappingProfile.cs` (এটি মেইন প্রজেক্টে বা আলাদা ফোল্ডারে থাকতে পারে)
```csharp
using AutoMapper;
using Entities.Models;
using Shared.DataTransferObjects;

public class MappingProfile : Profile
{
    public MappingProfile()
    {
        CreateMap<Company, CompanyDto>()
            // Address এবং Country জোড়া লাগিয়ে FullAddress বানানো হচ্ছে
            .ForMember(c => c.FullAddress, 
                opt => opt.MapFrom(x => string.Join(' ', x.Address, x.Country)));
    }
}
```

### ৫. সার্ভিস ম্যানেজার (Service Layer)
রিপোজিটরি ম্যানেজারের মতো সার্ভিসগুলোকেও এক জায়গায় ম্যানেজ করা হয়।

**ফাইল:** `Service/ServiceManager.cs`
```csharp
using Contracts;
using Service.Contracts;
using AutoMapper;

namespace Service
{
    public sealed class ServiceManager : IServiceManager
    {
        private readonly Lazy<ICompanyService> _companyService;
        // EmployeeService ও একইভাবে থাকবে...

        public ServiceManager(IRepositoryManager repositoryManager, ILoggerManager logger, IMapper mapper)
        {
            // Lazy Loading ব্যবহার করা হচ্ছে
            _companyService = new Lazy<ICompanyService>(() => 
                new CompanyService(repositoryManager, logger, mapper));
        }

        public ICompanyService CompanyService => _companyService.Value;
    }
}
```

### ৬. কন্ট্রোলার (Presentation Layer)
সবশেষে, আমরা কন্ট্রোলার তৈরি করব যা সার্ভিস লেয়ারকে কল করবে।

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
using Microsoft.AspNetCore.Mvc;
using Service.Contracts;

namespace Presentation.Controllers
{
    [Route("api/companies")]
    [ApiController]
    public class CompaniesController : ControllerBase
    {
        private readonly IServiceManager _service;

        public CompaniesController(IServiceManager service)
        {
            _service = service;
        }

        [HttpGet]
        public IActionResult GetCompanies()
        {
            // ১. সার্ভিস লেয়ার কল করা (trackChanges: false কারণ আমরা শুধু রিড করছি)
            var companies = _service.CompanyService.GetAllCompanies(trackChanges: false);

            // ২. রেসপন্স রিটার্ন করা
            return Ok(companies);
        }
    }
}
```

### ৭. Program.cs কনফিগারেশন
সবকিছু কাজ করানোর জন্য `Program.cs` ফাইলে সার্ভিস এবং অটোম্যাপার রেজিস্টার করতে হবে।

**ফাইল:** `Program.cs` (বা ServiceExtensions.cs)

```csharp
// AutoMapper রেজিস্টার করা
builder.Services.AddAutoMapper(typeof(Program));

// ServiceManager রেজিস্টার করা
builder.Services.AddScoped<IServiceManager, ServiceManager>();

// কন্ট্রোলারগুলো যেহেতু আলাদা প্রজেক্টে (Presentation Assembly), তাই ওটা চিনিয়ে দিতে হবে
builder.Services.AddControllers()
    .AddApplicationPart(typeof(Presentation.AssemblyReference).Assembly);
```

### সারমর্ম (কী ঘটল এখানে?)
1.  ইউজার `GET api/companies` হিট করল।
2.  **CompaniesController** রিকোয়েস্ট পেল এবং `_service.CompanyService.GetAllCompanies` কল করল।
3.  **CompanyService** ডাটাবেস থেকে `Company` এনটিটি আনল।
4.  **AutoMapper** সেই এনটিটিকে `CompanyDto` তে কনভার্ট করল (Address + Country = FullAddress)।
5.  কন্ট্রোলার সেই DTO বা প্রসেস করা ডাটা ইউজারকে JSON আকারে দেখাল।

এভাবেই **Service Layer** ডাটাবেস এবং কন্ট্রোলারের মাঝে একটি দেওয়াল বা লজিক লেয়ার হিসেবে কাজ করে।
