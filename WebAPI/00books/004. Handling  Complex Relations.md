
**Chapter 4**-এর নাম সাধারণত **"Handling Complex Relations"** বা **"Getting Single Resources and Child Resources"**।

Chapter 3-তে আমরা শুধু সব ডাটা একসাথে আনা (`GetAll`) শিখেছিলাম। Chapter 4-এ আমরা শিখব কীভাবে **একটি নির্দিষ্ট ডাটা** (Single Resource) আনা যায় এবং **প্যারেন্ট-চাইল্ড** (Parent-Child) রিলেশনশিপ হ্যান্ডেল করা যায়।

নিচে বিস্তারিত আলোচনা করা হলো:

---

### ১. নির্দিষ্ট একটি রিসোর্স আনা (Getting a Single Resource)
সব কোম্পানি আনার বদলে, ক্লায়েন্ট চাইতে পারে "আমাকে শুধু ID: 123 ওয়ালা কোম্পানিটা দাও"।

*   **Repository Layer:** এখানে `GetCompany` মেথড যোগ করা হয় যা `FindByCondition` ব্যবহার করে নির্দিষ্ট ID দিয়ে ডাটা খোঁজে।
*   **Service Layer:** এখানে লজিক থাকে। সার্ভিস লেয়ার রিপোজিটরি থেকে ডাটা আনার চেষ্টা করে।
*   **Handling Null:** যদি ডাটাবেসে ওই ID দিয়ে কোনো কোম্পানি না থাকে, তাহলে কী হবে?
    *   সাধারণত কন্ট্রোলারে `if (company == null) return NotFound();` লেখা হয়।
    *   কিন্তু এই বইয়ের লেখক **Clean Code** এর জন্য একটি চমৎকার পদ্ধতি দেখিয়েছেন। তিনি **Custom Exception** ব্যবহার করেছেন।

### ২. কাস্টম এক্সেপশন (Custom Exceptions for NotFound)
প্রতিবার কন্ট্রোলারে নাল (Null) চেক না করে, লেখক `NotFoundException` নামে একটি বেইস ক্লাস বানিয়েছেন।

*   **CompanyNotFoundException:** এই ক্লাসটি `NotFoundException` কে ইনহেরিট করে।
*   **Service Layer এর লজিক:** সার্ভিস লেয়ারে কোড এমনভাবে লেখা হয়—
    > "যদি কোম্পানি না পাওয়া যায়, তবে `throw new CompanyNotFoundException(id)` ছুঁড়ে মারো।"
*   **Global Error Handler:** Chapter 3-এ আমরা যে গ্লোবাল এরর হ্যান্ডলার বানিয়েছিলাম, সে অটোমেটিক এই এক্সেপশন ধরবে এবং ক্লায়েন্টকে **404 Not Found** স্ট্যাটাস কোড পাঠিয়ে দেবে। এতে কন্ট্রোলারের কোড খুব ক্লিন থাকে।

---

### ৩. চাইল্ড রিসোর্স হ্যান্ডেল করা (Handling Child Resources - Employees)
এই প্রজেক্টে `Employee` হলো চাইল্ড এবং `Company` হলো প্যারেন্ট। অর্থাৎ, একজন এমপ্লয়ি হুট করে থাকতে পারে না, তাকে কোনো না কোনো কোম্পানির অধীনে থাকতে হবে।

*   **RESTful Routing:** এই সম্পর্কের কারণে URL বা রাউটটি দেখতে এমন হয়:
    `GET api/companies/{companyId}/employees`
    *(এর মানে: এই কোম্পানির ভেতরের সব এমপ্লয়িকে দাও)*

*   **Repository:** `GetEmployees` মেথড তৈরি করা হয় যা `CompanyId` দিয়ে ফিল্টার করে এমপ্লয়িদের নিয়ে আসে।

*   **Service Layer Logic:**
    1. প্রথমে চেক করা হয় `companyId` ভ্যালিড কিনা (কোম্পানিটি আসলেই আছে কিনা)।
    2. যদি কোম্পানি না থাকে, তবে `CompanyNotFoundException` থ্রো করা হয়।
    3. যদি কোম্পানি থাকে, তবেই কেবল এমপ্লয়িদের ডাটা আনা হয়।

---

### ৪. নির্দিষ্ট একটি চাইল্ড রিসোর্স আনা (Single Child Resource)
ক্লায়েন্ট চাইতে পারে নির্দিষ্ট একটি কোম্পানির, নির্দিষ্ট একজন এমপ্লয়ির ডিটেইলস।
*   **Route:** `GET api/companies/{companyId}/employees/{employeeId}`

*   **Service Layer Logic (Validation):** এখানে তিনটি চেকিং হয়—
    1. কোম্পানিটি কি ডাটাবেসে আছে? (না থাকলে 404)।
    2. এমপ্লয়িটি কি ডাটাবেসে আছে? (না থাকলে `EmployeeNotFoundException` -> 404)।
    3. **গুরুত্বপূর্ণ:** এই এমপ্লয়ি কি আসলেই ওই কোম্পানির? নাকি অন্য কোম্পানির এমপ্লয়ি আইডি দিয়ে রিকোয়েস্ট করা হয়েছে? এটি চেক করা জরুরি।

---

### ৫. DTO তে পরিবর্তন (Handling Response)
আমরা যখন `GetCompany` কল করি, তখন আমরা ডাটাবেস থেকে `Company` মডেল পাই। কিন্তু ক্লায়েন্টকে দেই `CompanyDto`।

*   **EmployeeDto:** এমপ্লয়িদের ডাটা দেখানোর জন্য নতুন `EmployeeDto` তৈরি করা হয়।
*   **AutoMapper:** `Employee` এনটিটি থেকে `EmployeeDto`-তে কনভার্ট করার রুলস `MappingProfile`-এ সেট করা হয়।

### সারসংক্ষেপ (Summary of Chapter 4)
এই চ্যাপ্টার শেষে আপনি শিখবেন:
1.  কীভাবে **ID দিয়ে ডাটা** খুঁজতে হয় (`GetById`)।
2.  **কাস্টম এক্সেপশন** বানিয়ে কীভাবে লজিক লেয়ার থেকেই 404 হ্যান্ডেল করতে হয় (কন্ট্রোলার ক্লিন রাখার জন্য)।
3.  **Nested Resources** বা একটার পেটের ভেতর আরেকটা রিসোর্স (Company -> Employee) কীভাবে ডিজাইন করতে হয়।
4.  কীভাবে চেক করতে হয় যে **চাইল্ড ডাটাটি সঠিক প্যারেন্টের অধীনে আছে কিনা**।

এটি একটি REST API-এর স্ট্যান্ডার্ড বা আদর্শ কাঠামো, যেখানে ডাটার রিলেশনশিপ বা সম্পর্ককে গুরুত্ব দেওয়া হয়।

### ২. রিপোজিটরি লেয়ার আপডেট (Repository Project)

নির্দিষ্ট আইডি দিয়ে ডাটা খোঁজার মেথড যোগ করতে হবে।

**ফাইল:** `Repository/CompanyRepository.cs`
```csharp
// SingleOrDefault ব্যবহার করে একটি কোম্পানি রিটার্ন করা
public Company GetCompany(Guid companyId, bool trackChanges) =>
    FindByCondition(c => c.Id.Equals(companyId), trackChanges)
    .SingleOrDefault();
```

**ফাইল:** `Repository/EmployeeRepository.cs`
```csharp
// নির্দিষ্ট কোম্পানির সব এমপ্লয়ি আনা
public IEnumerable<Employee> GetEmployees(Guid companyId, bool trackChanges) =>
    FindByCondition(e => e.CompanyId.Equals(companyId), trackChanges)
    .OrderBy(e => e.Name)
    .ToList();

// নির্দিষ্ট কোম্পানির নির্দিষ্ট এমপ্লয়ি আনা
public Employee GetEmployee(Guid companyId, Guid id, bool trackChanges) =>
    FindByCondition(e => e.CompanyId.Equals(companyId) && e.Id.Equals(id), trackChanges)
    .SingleOrDefault();
```

### ৪. সার্ভিস লেয়ার আপডেট (Service Project)

এখানে আমরা লজিক লিখব। ডাটা না পেলে এক্সেপশন থ্রো করব।

**ফাইল:** `Service/CompanyService.cs`
```csharp
public CompanyDto GetCompany(Guid id, bool trackChanges)
{
    var company = _repository.Company.GetCompany(id, trackChanges);
    
    // ডাটা না পেলে Custom Exception থ্রো করা
    if (company is null)
        throw new CompanyNotFoundException(id);

    var companyDto = _mapper.Map<CompanyDto>(company);
    return companyDto;
}
```

**ফাইল:** `Service/EmployeeService.cs`
```csharp
public IEnumerable<EmployeeDto> GetEmployees(Guid companyId, bool trackChanges)
{
    // ১. প্যারেন্ট (কোম্পানি) আছে কি না চেক করা
    var company = _repository.Company.GetCompany(companyId, trackChanges);
    if (company is null)
        throw new CompanyNotFoundException(companyId);

    // ২. চাইল্ড (এমপ্লয়ি) আনা
    var employees = _repository.Employee.GetEmployees(companyId, trackChanges);

    var employeesDto = _mapper.Map<IEnumerable<EmployeeDto>>(employees);
    return employeesDto;
}

public EmployeeDto GetEmployee(Guid companyId, Guid id, bool trackChanges)
{
    // ১. কোম্পানি চেক
    var company = _repository.Company.GetCompany(companyId, trackChanges);
    if (company is null)
        throw new CompanyNotFoundException(companyId);

    // ২. এমপ্লয়ি চেক
    var employee = _repository.Employee.GetEmployee(companyId, id, trackChanges);
    if (employee is null)
        throw new EmployeeNotFoundException(id);

    var employeeDto = _mapper.Map<EmployeeDto>(employee);
    return employeeDto;
}
```

### ৬. গ্লোবাল এরর হ্যান্ডলিং (Global Exception Handler)

কন্ট্রোলারে `try-catch` নেই। তাই আমাদের একটি গ্লোবাল মিডলওয়্যার লাগবে যা এক্সেপশন ধরবে।

**ফাইল:** `Extensions/ExceptionMiddlewareExtensions.cs`

```csharp
using Entities.ErrorModel; // ErrorDetails ক্লাস বানাতে হবে
using Entities.Exceptions; // কাস্টম এক্সেপশন
using Microsoft.AspNetCore.Diagnostics;

public static void ConfigureExceptionHandler(this WebApplication app, ILoggerManager logger)
{
    app.UseExceptionHandler(appError =>
    {
        appError.Run(async context =>
        {
            context.Response.ContentType = "application/json";
            
            var contextFeature = context.Features.Get<IExceptionHandlerFeature>();
            if (contextFeature != null)
            {
                // স্ট্যাটাস কোড সেট করা
                context.Response.StatusCode = contextFeature.Error switch
                {
                    NotFoundException => StatusCodes.Status404NotFound,
                    _ => StatusCodes.Status500InternalServerError
                };

                logger.LogError($"Something went wrong: {contextFeature.Error}");

                // জেসন এরর রিটার্ন করা
                await context.Response.WriteAsync(new ErrorDetails()
                {
                    StatusCode = context.Response.StatusCode,
                    Message = contextFeature.Error.Message,
                }.ToString());
            }
        });
    });
}
```
*( `ErrorDetails` ক্লাসে শুধু StatusCode, Message প্রপার্টি এবং `ToString()` মেথডে `JsonSerializer.Serialize(this)` থাকে)*

**Program.cs এ কল করা:**
```csharp
var app = builder.Build();
var logger = app.Services.GetRequiredService<ILoggerManager>();
app.ConfigureExceptionHandler(logger); // <--- নতুন লাইন
// ...
```
