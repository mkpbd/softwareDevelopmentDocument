
**Chapter 7**-এর নাম হলো **"Handling PATCH Requests"**।

Chapter 6-এ আমরা `PUT` রিকোয়েস্ট দেখেছি, যা দিয়ে একটি রিসোর্সের **সব তথ্য** পরিবর্তন করা হয়। কিন্তু ধরুন, একজন এমপ্লয়ির শুধু বয়স (Age) পরিবর্তন করা দরকার, বাকি সব ঠিক থাকবে। সে ক্ষেত্রে পুরো অবজেক্ট পাঠানো বা আপডেট করাটা লস প্রজেক্ট (Bandwidth waste)।

এই সমস্যা সমাধানের জন্য **PATCH** রিকোয়েস্ট ব্যবহার করা হয়। এটি **Partial Update** বা আংশিক পরিবর্তনের জন্য ব্যবহৃত হয়।

নিচে বিস্তারিত টপিকগুলো আলোচনা করা হলো:

---

### ১. PUT বনাম PATCH (PUT vs. PATCH)
*   **PUT (Full Update):** আপনি যদি শুধু নাম পরিবর্তন করতে চান, তবুও আপনাকে নাম, বয়স, পজিশন—সব পাঠাতে হবে। যদি কিছু না পাঠান, সেটা নাল (Null) বা ডিফল্ট হয়ে যাবে।
*   **PATCH (Partial Update):** আপনি শুধু বলে দেবেন "বয়স পরিবর্তন করো", বাকি তথ্যে হাত দেওয়ার দরকার নেই। এটি অনেক বেশি এফিশিয়েন্ট।

---

### ২. JSON Patch ডকুমেন্ট (RFC 6902)
PATCH রিকোয়েস্টের বডি সাধারণ JSON অবজেক্টের মতো হয় না (যেমন: `{ "age": 30 }` এমন নয়)। এটি একটি অপারেশন লিস্টের মতো হয়।

*   **ফরমেট:** এটি একটি অ্যারে `[]` যাতে বলে দেওয়া হয় কী অপারেশন করতে হবে।
*   **উদাহরণ:**
    ```json
    [
      { "op": "replace", "path": "/age", "value": 35 }
    ]
    ```
*   **Property ব্যাখ্যা:**
    *   `op`: কী করতে চান? (replace, add, remove, copy, move, test)।
    *   `path`: কোন ফিল্ডটি পরিবর্তন করবেন? (যেমন: `/age` বা `/name`)।
    *   `value`: নতুন মান কী হবে?

---

### ৩. কনফিগারেশন (NewtonsoftJson)
.NET Core-এর ডিফল্ট `System.Text.Json` লাইব্রেরি দিয়ে `JSON Patch` পুরোপুরি সাপোর্ট করে না। তাই এই চ্যাপ্টারে **Microsoft.AspNetCore.Mvc.NewtonsoftJson** লাইব্রেরি ব্যবহার করা হয়।

*   **কাজ:** `Program.cs`-এ `AddNewtonsoftJson()` মেথড কল করতে হয়, যাতে অ্যাপটি PATCH রিকোয়েস্টের ওই বিশেষ ফরম্যাট বুঝতে পারে।

---

### ৪. ইমপ্লিমেন্টেশন ফ্লো (Implementation Flow)
PATCH রিকোয়েস্ট হ্যান্ডেল করা একটু ট্রিকি। কারণ আমরা সরাসরি ডাটাবেসের এনটিটির ওপর প্যাচ চালাই না।

**ধাপগুলো:**
1.  **ডাটা আনা:** ডাটাবেস থেকে `Employee` এনটিটি তুলে আনা হয়।
2.  **DTO তে নেওয়া:** এনটিটি থেকে ডাটা `EmployeeForUpdateDto`-তে ম্যাপ করা হয়।
3.  **প্যাচ অ্যাপ্লাই করা:** ইউজারের পাঠানো প্যাচ ডকুমেন্টটি এই DTO-র ওপর অ্যাপ্লাই করা হয় (`patchDoc.ApplyTo(dto)`).
    *   *ফলে DTO-তে শুধু কাঙ্ক্ষিত ফিল্ডটি চেঞ্জ হয়ে যায়।*
4.  **ভ্যালিডেশন:** প্যাচ করার পর চেক করা হয় DTO-টি ভ্যালিড কি না (যেমন: বয়স ১৮-এর নিচে হয়ে গেল কি না)।
5.  **ফেরত পাঠানো:** আপডেট হওয়া DTO-টি আবার এনটিটিতে ম্যাপ করা হয় (`_mapper.Map(dto, entity)`).
6.  **সেভ:** ডাটাবেসে `SaveChanges` করা হয়।

---

### ৫. প্যাচ ভ্যালিডেশন (Validation after Patch)
সাধারণত কন্ট্রোলারে ঢোকার আগেই `[ApiController]` অটোমেটিক ভ্যালিডেশন চেক করে। কিন্তু PATCH-এর ক্ষেত্রে সমস্যা হলো, শুরুতে আমাদের কাছে থাকে `JsonPatchDocument`, আসল DTO নয়।

তাই, `ApplyTo` মেথড চালানোর পর **ম্যানুয়ালি** ভ্যালিডেশন ট্রিগার করতে হয়।
*   **উদাহরণ:** যদি কেউ প্যাচ করে `age` মুছে ফেলে (Remove Operation), তখন DTO ইনভ্যালিড হয়ে যাবে। এটি চেক করার জন্য `TryValidateModel(dto)` ব্যবহার করা হয়।

### ১. Partial Update (আংশিক পরিবর্তন) কী এবং কেন দরকার?

**কী (What):**
Partial Update মানে হলো পুরো অবজেক্ট পরিবর্তন না করে শুধুমাত্র যেটুকু দরকার, সেটুকুই পরিবর্তন করা।

**পার্থক্য (PUT vs PATCH):**
ধরুন, আপনার `Employee` টেবিলে তথ্য আছে: `{ Name: "Rahim", Age: 25, Position: "Dev" }`। আপনি শুধু বয়স (Age) ৩০ করতে চান।

*   **PUT (Full Update):** আপনাকে সার্ভারে পাঠাতে হবে: `{ Name: "Rahim", Age: 30, Position: "Dev" }`।
    *   *সমস্যা:* আপনি শুধু বয়স পাল্টাতে চান, কিন্তু নাম আর পজিশনও পাঠাতে হচ্ছে। এটা ব্যান্ডউইথ নষ্ট করে।
*   **PATCH (Partial Update):** আপনি সার্ভারে পাঠাবেন: "শুধু `Age` কে `30` করো"। বাকি তথ্যে হাত দেওয়ার দরকার নেই।

**কেন দরকার (Why):**
1.  **Efficiency:** ডাটা কম পাঠাতে হয়, তাই নেটওয়ার্ক ফাস্ট কাজ করে।
2.  **Safety:** ভুলে অন্য ফিল্ড (যেমন: Name) চেঞ্জ হয়ে যাওয়ার ভয় থাকে না।

---

### ২. JSON Patch ডকুমেন্ট কী এবং কীভাবে লিখতে হয়?

PATCH রিকোয়েস্টে আমরা সাধারণ JSON অবজেক্ট পাঠাই না। আমরা একটি **List of Operations** পাঠাই। এর স্ট্যান্ডার্ড হলো **RFC 6902**।

**স্ট্রাকচার (Structure):**
এটি একটি অ্যারে `[]` দিয়ে শুরু হয়। এর ভেতরে অবজেক্ট থাকে।

```json
[
  {
    "op": "replace",
    "path": "/age",
    "value": 30
  }
]
```

**ব্যাখ্যা:**
*   **"op" (Operation):** আপনি কী করতে চান?
    *   `replace`: ভ্যালু পাল্টানো (সবচেয়ে বেশি ব্যবহৃত)।
    *   `remove`: কোনো ফিল্ড মুছে ফেলা।
    *   `add`: নতুন ফিল্ড যোগ করা।
*   **"path":** কোন প্রপার্টি চেঞ্জ হবে? (যেমন: `/age`, `/name`)।
*   **"value":** নতুন মান কী হবে?

---

### ৩. .NET এ NewtonsoftJson কনফিগার করা

.NET Core-এর ডিফল্ট `System.Text.Json` লাইব্রেরি `JSON Patch` ঠিকমতো সাপোর্ট করে না। তাই আমাদের `Microsoft.AspNetCore.Mvc.NewtonsoftJson` প্যাকেজটি ব্যবহার করতে হয়।

**ধাপ ১: NuGet Package ইন্সটল করা**
Package Manager Console এ কমান্ড দিন:
```powershell
Install-Package Microsoft.AspNetCore.Mvc.NewtonsoftJson
```

**ধাপ ২: Program.cs এ কনফিগার করা**
```csharp
var builder = WebApplication.CreateBuilder(args);

// AddControllers এর সাথে AddNewtonsoftJson চেইন করতে হবে
builder.Services.AddControllers()
    .AddNewtonsoftJson()  // এই লাইনটি যোগ করতে হবে
    .AddXmlDataContractSerializerFormatters(); 
```

### ৪. এনটিটি -> DTO -> Patch Apply -> এনটিটি -> সেভ প্রসেস

PATCH ইমপ্লিমেন্ট করা একটু জটিল কারণ আমরা সরাসরি ডাটাবেস এনটিটির ওপর প্যাচ চালাই না। আমরা DTO-র ওপর প্যাচ চালাই, তারপর সেটা ভ্যালিডেট করে এনটিটিতে বসাই।

**পুরো কোড ফ্লো (Code Flow):**

#### A. Service Layer (ডাটা আনা এবং DTO দেওয়া)
সার্ভিস লেয়ার আমাদের দুটি জিনিস দেবে: (১) DTO (যাতে প্যাচ অ্যাপ্লাই করব) এবং (২) অরিজিনাল Entity (যাতে পরে সেভ করব)।

**ফাইল:** `Service/EmployeeService.cs`
```csharp
// রিটার্ন টাইপ খেয়াল করুন: একটি Tuple রিটার্ন করছি (DTO, Entity)
public (EmployeeForUpdateDto employeeToPatch, Employee employeeEntity) GetEmployeeForPatch(Guid companyId, Guid id, bool trackChanges)
{
    // ১. ডাটাবেস থেকে অরিজিনাল এনটিটি আনা
    var employeeEntity = _repository.Employee.GetEmployee(companyId, id, trackChanges);
    if (employeeEntity is null)
        throw new EmployeeNotFoundException(id);

    // ২. এনটিটি থেকে DTO তে কনভার্ট করা (কারণ প্যাচ DTO এর ওপর হবে)
    var employeeToPatch = _mapper.Map<EmployeeForUpdateDto>(employeeEntity);

    // ৩. দুটোই রিটার্ন করা
    return (employeeToPatch, employeeEntity);
}

public void SaveChangesForPatch(EmployeeForUpdateDto employeeToPatch, Employee employeeEntity)
{
    // ৫. প্যাচ হওয়ার পর DTO থেকে আবার এনটিটিতে ডাটা বসানো
    _mapper.Map(employeeToPatch, employeeEntity);
    
    // ৬. ডাটাবেসে সেভ করা
    _repository.Save();
}
```

#### B. Controller (প্যাচ অ্যাপ্লাই এবং ভ্যালিডেশন)
কন্ট্রোলারেই মূলত `ApplyTo` মেথডটি কল করা হয়।

**ফাইল:** `Presentation/Controllers/EmployeesController.cs`
```csharp
[HttpPatch("{id:guid}")]
public IActionResult PartiallyUpdateEmployeeForCompany(Guid companyId, Guid id, 
    [FromBody] JsonPatchDocument<EmployeeForUpdateDto> patchDoc)
{
    if (patchDoc is null)
        return BadRequest("patchDoc object sent from client is null.");

    // ১. সার্ভিস থেকে DTO এবং Entity আনা
    var result = _service.EmployeeService.GetEmployeeForPatch(companyId, id, trackChanges: true);

    // result.employeeToPatch -> এটি DTO
    // result.employeeEntity -> এটি ডাটাবেস অবজেক্ট

    // ২. প্যাচ অ্যাপ্লাই করা (Apply To DTO)
    // patchDoc-এর রুলসগুলো employeeToPatch-এর ওপর প্রয়োগ হচ্ছে
    patchDoc.ApplyTo(result.employeeToPatch, ModelState);

    // ৩. ভ্যালিডেশন চেক (Validation)
    // প্যাচ করার পর ডাটা ভ্যালিড আছে তো? (যেমন বয়স ১৮ এর নিচে করে দিল কি না)
    TryValidateModel(result.employeeToPatch);

    if (!ModelState.IsValid)
        return UnprocessableEntity(ModelState);

    // ৪. সেভ করা (সার্ভিস মেথড কল)
    _service.EmployeeService.SaveChangesForPatch(result.employeeToPatch, result.employeeEntity);

    return NoContent(); // 204
}
```

### ২. AutoMapper সেটআপ
PATCH রিকোয়েস্টে আমরা এনটিটি থেকে DTO তে ডাটা নেই, আবার আপডেটের পর DTO থেকে এনটিটিতে ডাটা ফেরত পাঠাই। তাই `ReverseMap` বা রিভার্স ম্যাপিং দরকার।

**ফাইল:** `MappingProfile.cs`
```csharp
// EmployeeForUpdateDto এবং Employee এর মধ্যে দুই দিকেই ম্যাপিং হবে
CreateMap<EmployeeForUpdateDto, Employee>().ReverseMap();
```

### ৩. সার্ভিস লেয়ার (Service Layer)
PATCH এর লজিক একটু ভিন্ন। কন্ট্রোলারকে প্যাচ অ্যাপ্লাই করার জন্য আমাদের **Entity** এবং **DTO** দুটোই সাপ্লাই দিতে হবে। তাই আমরা C# এর **Tuple** ফিচার ব্যবহার করব।

**ইন্টারফেস:** `Contracts/IEmployeeService.cs`
```csharp
// রিটার্ন টাইপ খেয়াল করুন: (DTO, Entity)
(EmployeeForUpdateDto employeeToPatch, Employee employeeEntity) GetEmployeeForPatch(Guid companyId, Guid id, bool trackChanges);

void SaveChangesForPatch(EmployeeForUpdateDto employeeToPatch, Employee employeeEntity);
```

**ইমপ্লিমেন্টেশন:** `Service/EmployeeService.cs`
```csharp
public (EmployeeForUpdateDto employeeToPatch, Employee employeeEntity) GetEmployeeForPatch(Guid companyId, Guid id, bool trackChanges)
{
    // ১. কোম্পানি চেক
    var company = _repository.Company.GetCompany(companyId, trackChanges: false);
    if (company is null)
        throw new CompanyNotFoundException(companyId);

    // ২. এমপ্লয়ি চেক (trackChanges: true কারণ আমরা পরে আপডেট করব)
    var employeeEntity = _repository.Employee.GetEmployee(companyId, id, trackChanges);
    if (employeeEntity is null)
        throw new EmployeeNotFoundException(id);

    // ৩. এনটিটি থেকে DTO তে কনভার্ট (প্যাচ অ্যাপ্লাই করার জন্য)
    var employeeToPatch = _mapper.Map<EmployeeForUpdateDto>(employeeEntity);

    // ৪. দুটোই রিটার্ন করা
    return (employeeToPatch, employeeEntity);
}

public void SaveChangesForPatch(EmployeeForUpdateDto employeeToPatch, Employee employeeEntity)
{
    // ৫. প্যাচ করা DTO থেকে আবার এনটিটিতে ডাটা ম্যাপ করা
    _mapper.Map(employeeToPatch, employeeEntity);
    
    // ৬. ডাটাবেসে সেভ করা
    _repository.Save();
}
```

### ৪. কন্ট্রোলার (Controller Layer) - *সবচেয়ে গুরুত্বপূর্ণ*
এখানে `ApplyTo` এবং `TryValidateModel` মেথড ব্যবহার করা হয়।

**ফাইল:** `Presentation/Controllers/EmployeesController.cs`
```csharp
using Microsoft.AspNetCore.JsonPatch; // এই নেমস্পেস জরুরি

[HttpPatch("{id:guid}")]
public IActionResult PartiallyUpdateEmployeeForCompany(Guid companyId, Guid id, 
    [FromBody] JsonPatchDocument<EmployeeForUpdateDto> patchDoc)
{
    // ১. নাল চেক
    if (patchDoc is null)
        return BadRequest("patchDoc object sent from client is null.");

    // ২. সার্ভিস থেকে DTO এবং Entity আনা
    var result = _service.EmployeeService.GetEmployeeForPatch(companyId, id, trackChanges: true);

    // ৩. প্যাচ অ্যাপ্লাই করা (Apply Patch)
    // patchDoc এর রুলসগুলো result.employeeToPatch এর ওপর প্রয়োগ হবে
    // কোনো এরর হলে ModelState এ জমা হবে
    patchDoc.ApplyTo(result.employeeToPatch, ModelState);

    // ৪. ভ্যালিডেশন চেক (ApplyTo অটোমেটিক ভ্যালিডেট করে না, তাই ম্যানুয়ালি করতে হয়)
    TryValidateModel(result.employeeToPatch);

    if (!ModelState.IsValid)
        return UnprocessableEntity(ModelState);

    // ৫. সব ঠিক থাকলে সেভ করো
    _service.EmployeeService.SaveChangesForPatch(result.employeeToPatch, result.employeeEntity);

    return NoContent(); // 204
}
```

### ৫. উদাহরণ (Example Usage)

ধরি, ডাটাবেসে একজন এমপ্লয়ি আছে যার তথ্য:
*   Name: "Rahim"
*   Age: 25
*   Position: "Junior Developer"

আমরা তার **বয়স (Age)** এবং **পজিশন (Position)** বদলাতে চাই, কিন্তু নাম ঠিক থাকবে।

**Request Details (Postman):**
*   **Method:** `PATCH`
*   **URL:** `https://localhost:5001/api/companies/{companyId}/employees/{employeeId}`
*   **Header:** `Content-Type: application/json-patch+json` (এটি না দিলেও কাজ করতে পারে, তবে দেওয়া ভালো)
*   **Body (JSON):**
    ```json
    [
      {
        "op": "replace",
        "path": "/age",
        "value": 28
      },
      {
        "op": "replace",
        "path": "/position",
        "value": "Senior Developer"
      }
    ]
    ```

**ফলাফল (Outcome):**
*   API `204 No Content` রিটার্ন করবে।
*   ডাটাবেসে এখন তথ্য হবে: `{ Name: "Rahim", Age: 28, Position: "Senior Developer" }`।

**ভ্যালিডেশন এরর উদাহরণ:**
যদি কেউ `Remove` অপারেশন চালায় এমন ফিল্ডে যা `Required`:
```json
[
  { "op": "remove", "path": "/age" }
]
```
*   `TryValidateModel` তখন ফেইল করবে কারণ `Age` রিকোয়্যারড ফিল্ড।
*   API `422 Unprocessable Entity` রিটার্ন করবে এবং বলবে "Age is required"।
