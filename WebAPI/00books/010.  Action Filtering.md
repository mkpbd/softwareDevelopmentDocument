
**Chapter 10**-এর নাম হলো **"Action Filters"**।

ASP.NET Core-এ **Action Filter** একটি অত্যন্ত শক্তিশালী ফিচার। সহজ কথায়, কন্ট্রোলারের কোনো মেথড (Action) রান করার **ঠিক আগে** এবং **ঠিক পরে** কোনো লজিক চালানোর জন্য এটি ব্যবহার করা হয়।

বইটিতে মূলত **Code Duplication** বা একই কোড বারবার লেখা কমানোর জন্য অ্যাকশন ফিল্টার ব্যবহার করা হয়েছে। নিচে বিস্তারিত আলোচনা করা হলো:

---

### ১. অ্যাকশন ফিল্টার কী? (What is an Action Filter?)

**কি কাজ করে:**
এটি একটি ইন্টারসেপ্টর (Interceptor) বা দারোয়ানের মতো কাজ করে।
১. যখন ক্লায়েন্ট রিকোয়েস্ট পাঠায়, কন্ট্রোলারে ঢোকার **আগে** ফিল্টারটি চেক করতে পারে (যেমন: ডাটা ভ্যালিড কি না)।
২. আবার কন্ট্রোলার কাজ শেষ করার **পরে** রেসপন্স পাঠানোর আগেও এটি কাজ করতে পারে।

**কেন দরকার (Why):**
আমাদের কন্ট্রোলারে প্রায়ই কিছু কমন কোড থাকে যা বারবার লিখতে হয়। যেমন:
*   `if (model == null) return BadRequest();`
*   `if (!ModelState.IsValid) return UnprocessableEntity(ModelState);`
*   `if (entity == null) return NotFound();`

এই কোডগুলো বিজনেস লজিক না, এগুলো হলো **Validation Logic**। এগুলো কন্ট্রোলারের ভেতর থাকলে কোড নোংরা (Messy) দেখায়। ফিল্টার ব্যবহার করে এই কোডগুলো আলাদা ফাইলে সরিয়ে নেওয়া হয়।

---

### ২. ভ্যালিডেশন ফিল্টার (Validation Filter Attribute)

বইটিতে `ValidationFilterAttribute` নামে একটি কাস্টম ফিল্টার তৈরি করা হয়েছে।

**সমস্যা (Before Filter):**
প্রতিটা POST এবং PUT মেথডে আমাদের নিচের কোডটি লিখতে হতো:
```csharp
[HttpPost]
public IActionResult CreateCompany([FromBody] CompanyForCreationDto company)
{
    // ১. নাল চেক
    if (company == null)
        return BadRequest("Object is null");

    // ২. মডেল ভ্যালিডেশন চেক (Required ফিল্ড ঠিক আছে কি না)
    if (!ModelState.IsValid)
        return UnprocessableEntity(ModelState);

    // ... আসল লজিক ...
}
```

**সমাধান (After Filter):**
ফিল্টার ব্যবহারের ফলে কন্ট্রোলারের চেহারা এমন হয়ে যায়:
```csharp
[HttpPost]
[ServiceFilter(typeof(ValidationFilterAttribute))] // এক লাইনে সব চেক হয়ে গেল
public IActionResult CreateCompany([FromBody] CompanyForCreationDto company)
{
    // শুধু আসল লজিক থাকবে এখানে
    var createdCompany = _service.CreateCompany(company);
    return CreatedAtRoute(...)
}
```

**কিভাবে কাজ করে:**
ফিল্টারটি `OnActionExecutionAsync` মেথড ব্যবহার করে। সে রিকোয়েস্টের আর্গুমেন্ট চেক করে। যদি দেখে `param` নাল অথবা `ModelState` ইনভ্যালিড, সে কন্ট্রোলারে ঢুকতেই দেয় না, ওখান থেকেই `400 Bad Request` বা `422` রিটার্ন করে দেয়।

### ৩. এনটিটি এক্সিস্টেন্স ফিল্টার (Validate Entity Exists Filter)

এটি আরেকটি চমৎকার ব্যবহার। `GET`, `PUT`, `DELETE` করার সময় আমাদের চেক করতে হয় আইডি দিয়ে ডাটাবেসে ডাটা আছে কি না।

**সমস্যা:**
```csharp
public IActionResult GetCompany(Guid id)
{
    var company = _service.GetCompany(id);
    if (company == null) return NotFound(); // এই লাইন বারবার লিখতে হয়
    return Ok(company);
}
```

**সমাধান:**
`ValidateCompanyExistsAttribute` নামে ফিল্টার বানালে, সেই ফিল্টার আগেই ডাটাবেস চেক করে।
*   যদি ডাটা না থাকে -> ফিল্টার `404 NotFound` রিটার্ন করে।
*   যদি ডাটা থাকে -> ফিল্টার `HttpContext.Items`-এ ডাটাটি রেখে দেয়, যাতে কন্ট্রোলার সেটি ব্যবহার করতে পারে (আবার ডাটাবেস কল করার দরকার নেই)।

---

### ৪. ডিপেন্ডেন্সি ইনজেকশন এবং ফিল্টার (ServiceFilter)

সাধারণত অ্যাট্রিবিউট (Attribute)-এ কনস্ট্রাক্টর ইনজেকশন কাজ করে না। কিন্তু আমাদের ফিল্টারে ডাটাবেস চেক করার জন্য `IRepositoryManager` বা লগিংয়ের জন্য `ILoggerManager` দরকার হতে পারে।

**কিভাবে কাজ করে:**
এই সমস্যা সমাধানের জন্য .NET Core-এ `ServiceFilter` ব্যবহার করা হয়।
১. প্রথমে ফিল্টার ক্লাসটি সাধারণ ক্লাসের মতো বানাতে হয়।
২. `Program.cs` ফাইলে সেটি রেজিস্টার করতে হয় (`builder.Services.AddScoped<ValidationFilterAttribute>()`)।
৩. কন্ট্রোলারের মাথায় `[ServiceFilter(typeof(...))]` লিখতে হয়।

---

### সুবিধা একনজরে (Benefits)

১. **DRY Principle (Don't Repeat Yourself):** একই ভ্যালিডেশন কোড ১০০টা কন্ট্রোলারে লেখার বদলে এক জায়গায় (Filter Class) লিখলেই হয়।
২. **Clean Controller:** কন্ট্রোলার মেথডগুলো ছোট এবং পরিষ্কার থাকে। শুধু হ্যাপি পাথ (Happy Path) বা মেইন লজিক থাকে।
৩. **Separation of Concerns:** ভ্যালিডেশনের দায়িত্ব ফিল্টারের, আর প্রসেসিংয়ের দায়িত্ব কন্ট্রোলারের। কাজ ভাগ করে দেওয়া হলো।
৪. **Reusability:** একবার ফিল্টার বানালে পুরো প্রজেক্টের যেকোনো জায়গায় ব্যবহার করা যায়।

### সহজ উদাহরণ (Simple Example)

ধরুন একটি মুভি থিয়েটার (Controller)।
*   **Action Filter** হলো টিকিট চেকার।
*   সে দরজায় দাঁড়িয়ে টিকিট চেক করে (**Validation**)।
*   টিকিট না থাকলে সে ওখান থেকেই ফেরত পাঠিয়ে দেয় (**BadRequest**), আপনাকে সিটে বসতে দেয় না (**Controller Action Execute হয় না**)।
*   টিকিট থাকলে সে আপনাকে ভেতরে যেতে দেয় (`next()`)।

এই চ্যাপ্টারটি প্রফেশনাল কোডিং এবং আর্কিটেকচারের জন্য অত্যন্ত গুরুত্বপূর্ণ।

### ২. ভ্যালিডেশন ফিল্টার (Validation Filter)

এটি চেক করবে ক্লায়েন্ট কোনো `null` অবজেক্ট পাঠিয়েছে কি না এবং `ModelState` ভ্যালিড কি না।

**ফাইল:** `ActionFilters/ValidationFilterAttribute.cs`
```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;

namespace CompanyEmployees.ActionFilters
{
    public class ValidationFilterAttribute : IActionFilter
    {
        public void OnActionExecuting(ActionExecutingContext context)
        {
            // ১. অ্যাকশন মেথডটি কোন কন্ট্রোলারের এবং কোন অ্যাকশনের তা বের করা (লগিংয়ের জন্য কাজে লাগতে পারে)
            var action = context.RouteData.Values["action"];
            var controller = context.RouteData.Values["controller"];

            // ২. DTO প্যারামিটারটি ধরা
            // আমাদের মেথডে প্যারামিটারের নাম সাধারণত "company" বা "employeeDto" থাকে।
            // তাই আমরা অ্যাকশন আর্গুমেন্ট থেকে ভ্যালু খুঁজছি।
            var param = context.ActionArguments
                .SingleOrDefault(x => x.Value.ToString().Contains("Dto")).Value;

            // ৩. নাল চেক (Null Check)
            if (param is null)
            {
                context.Result = new BadRequestObjectResult($"Object is null. Controller: {controller}, action: {action}");
                return; // এখানেই কাজ শেষ, কন্ট্রোলারে আর যাবে না
            }

            // ৪. মডেল স্টেট ভ্যালিডেশন (Model State Check)
            if (!context.ModelState.IsValid)
            {
                context.Result = new UnprocessableEntityObjectResult(context.ModelState);
            }
        }

        public void OnActionExecuted(ActionExecutedContext context)
        {
            // অ্যাকশন শেষ হওয়ার পরে আমাদের কোনো কাজ নেই, তাই খালি
        }
    }
}
```

### ৩. এনটিটি এক্সিস্টেন্স ফিল্টার (Entity Existence Filter)

এটি চেক করবে আইডি দিয়ে ডাটাবেসে ডাটা আছে কি না। আমরা জেনেরিক বা স্পেসিফিক ফিল্টার বানাতে পারি। এখানে স্পেসিফিক উদাহরণ দেওয়া হলো।

**ফাইল:** `ActionFilters/ValidateCompanyExistsAttribute.cs`
```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;
using Contracts; // IRepositoryManager এর জন্য

namespace CompanyEmployees.ActionFilters
{
    public class ValidateCompanyExistsAttribute : IActionFilter
    {
        private readonly IRepositoryManager _repository;
        private readonly ILoggerManager _logger;

        public ValidateCompanyExistsAttribute(IRepositoryManager repository, ILoggerManager logger)
        {
            _repository = repository;
            _logger = logger;
        }

        public void OnActionExecuting(ActionExecutingContext context)
        {
            // ১. রিকোয়েস্ট ইউআরএল থেকে আইডি বের করা
            var trackChanges = context.HttpContext.Request.Method.Equals("PUT");
            var id = (Guid)context.ActionArguments["id"];

            // ২. ডাটাবেস চেক করা
            var company = _repository.Company.GetCompany(id, trackChanges);

            if (company is null)
            {
                _logger.LogInfo($"Company with id: {id} doesn't exist in the database.");
                context.Result = new NotFoundResult(); // 404 রিটার্ন
            }
            else
            {
                // ৩. যদি ডাটা পাওয়া যায়, তবে তা HttpContext এ স্টোর করা
                // যাতে কন্ট্রোলার আবার ডাটাবেস কল না করে এটা ব্যবহার করতে পারে
                context.HttpContext.Items.Add("company", company);
            }
        }

        public void OnActionExecuted(ActionExecutedContext context) { }
    }
}
```

### ৪. কন্ট্রোলারে ব্যবহার (Using in Controller)

এখন আমরা দেখব ফিল্টার ব্যবহারের আগে এবং পরে কন্ট্রোলার কেমন দেখায়।

**POST Request (Validation Filter):**

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
[HttpPost]
[ServiceFilter(typeof(ValidationFilterAttribute))] // <--- ম্যাজিক লাইন
public IActionResult CreateCompany([FromBody] CompanyForCreationDto company)
{
    // কোনো if (company == null) বা if (!ModelState.IsValid) চেক নেই!
    // সব ফিল্টার হ্যান্ডেল করছে।
    
    var createdCompany = _service.CompanyService.CreateCompany(company);
    return CreatedAtRoute("CompanyById", new { id = createdCompany.Id }, createdCompany);
}
```

**GET/PUT/DELETE Request (Entity Exists Filter):**

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
[HttpGet("{id:guid}", Name = "CompanyById")]
[ServiceFilter(typeof(ValidateCompanyExistsAttribute))] // <--- চেক করছে কোম্পানি আছে কিনা
public IActionResult GetCompany(Guid id)
{
    // আমাদের আর _service.GetCompany কল করে নাল চেক করতে হবে না।
    // ফিল্টার অলরেডি চেক করেছে এবং HttpContext.Items এ ডাটা রেখে দিয়েছে।
    
    // আইটেম থেকে ডাটা বের করা
    var company = HttpContext.Items["company"] as Company;
    
    // এনটিটি থেকে DTO তে কনভার্ট (Mapper লাগবে এখানে অথবা সার্ভিস লেয়ারে লজিক সরাতে হবে)
    // বইতে ফিল্টার ব্যবহারের সময় কন্ট্রোলার কিছুটা মডিফাই হয়।
    // তবে সহজ কথায়, এখানে আপনি নিশ্চিত যে 'company' নাল নয়।
    
    var companyDto = _mapper.Map<CompanyDto>(company);
    return Ok(companyDto);
}
```
*(দ্রষ্টব্য: বইয়ের লেটেস্ট এডিশনে ফিল্টার সাধারণত সার্ভিসের `GetCompany` মেথডকে বাইপাস করে না, বরং ফিল্টার শুধু অস্তিত্ব চেক করে, আর সার্ভিস তার স্বাভাবিক ফ্লোতেই ডাটা রিটার্ন করে। অথবা `HttpContext.Items` ব্যবহার করে অপটিমাইজ করা হয়)*

### ৫. উদাহরণ (Example Scenarios)

**Scenario 1: Creating Company with Invalid Data**
*   **Request:** `POST` `{ "Name": "" }` (Name required but empty)
*   **Action:** `ValidationFilterAttribute` এর `OnActionExecuting` রান হবে।
*   **Logic:** `ModelState.IsValid` ফলস হবে।
*   **Result:** `422 Unprocessable Entity` রিটার্ন করবে। কন্ট্রোলারের `CreateCompany` মেথড কলই হবে না।

**Scenario 2: Getting a Non-Existent Company**
*   **Request:** `GET /api/companies/wrong-id`
*   **Action:** `ValidateCompanyExistsAttribute` রান হবে।
*   **Logic:** রিপোজিটরিতে `GetCompany` কল করবে -> `null` পাবে।
*   **Result:** `404 Not Found` রিটার্ন করবে। কন্ট্রোলারের `GetCompany` মেথড কলই হবে না।

এভাবেই **Action Filters** আমাদের কোডকে করে তোলে আরও ক্লিন, রিডেবল এবং মেইনটেইনেবল।
