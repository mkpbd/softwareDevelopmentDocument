**Chapter 11**-এর নাম হলো **"Versioning APIs"**।

আপনার API যখন একবার লাইভ বা প্রোডাকশনে চলে যায় এবং মানুষ সেটা ব্যবহার করা শুরু করে, তখন আপনি হুট করে API পরিবর্তন করতে পারেন না। করলে ক্লায়েন্টের অ্যাপ ভেঙে যাবে। এই সমস্যা সমাধানের জন্যই **API Versioning** দরকার।

নিচে বিস্তারিত আলোচনা করা হলো:

---

### ১. এপিআই ভার্সনিং কী? (What is API Versioning?)

**কি কাজ করে:**
একই এপিআই-এর একাধিক সংস্করণ (Version) একসাথে চালু রাখা।
যেমন:
*   `v1`: পুরোনো ভার্সন (যা সবাই ব্যবহার করছে)।
*   `v2`: নতুন ভার্সন (যেখানে হয়তো নতুন কোনো ফিচার আছে বা কোনো ফিল্ডের নাম পাল্টেছে)।

**কেন দরকার (Why):**
ধরি, `v1` এ এমপ্লয়ির নাম ছিল `FullName`। আপনি `v2` তে সেটাকে ভেঙে `FirstName` ও `LastName` করলেন।
যদি ভার্সনিং না করেন, তবে পুরোনো অ্যাপগুলো (যারা `FullName` খুঁজছে) ক্র্যাশ করবে।
ভার্সনিং করলে পুরোনো ইউজাররা `v1` চালাবে, আর নতুনরা `v2` চালাবে।

---

### ২. ভার্সনিং করার উপায় (Ways to Version)

বইটিতে প্রধানত তিনটি জনপ্রিয় উপায়ের কথা বলা হয়েছে:

**ক. Query String Versioning**
*   ইউজার ইউআরএল এর শেষে ভার্সন বলে দেয়।
*   **উদাহরণ:** `https://localhost:5001/api/companies?api-version=2.0`
*   *সুবিধা:* সেটআপ করা সহজ।
*   *অসুবিধা:* ইউআরএল দেখতে একটু বড় হয়।

**খ. URL Path Versioning (সবচেয়ে জনপ্রিয়)**
*   ইউআরএল এর ভেতরেই ভার্সন লেখা থাকে।
*   **উদাহরণ:** `https://localhost:5001/api/v2/companies`
*   *সুবিধা:* দেখলেই বোঝা যায় কোন ভার্সন।
*   *অসুবিধা:* রাউটিং স্ট্রাকচার বদলাতে হয়।

**গ. Header Versioning (Custom Header)**
*   ইউআরএল পরিষ্কার থাকে, ভার্সন থাকে হেডারে।
*   **উদাহরণ:** Header: `X-Version: 2.0`
*   *সুবিধা:* ইউআরএল ক্লিন থাকে।
*   *অসুবিধা:* ব্রাউজার দিয়ে টেস্ট করা কঠিন (পোস্টম্যান লাগে)।

*(আরেকটি উপায় আছে: Media Type Versioning, যা GitHub ব্যবহার করে)*

---

### ৩. Deprecation (বাতিল ঘোষণা করা)

**কি কাজ করে:**
কোনো ভার্সন যদি আপনি আর সাপোর্ট করতে না চান, তবে সেটাকে `Deprecated` ঘোষণা করা হয়।
এপিআই রেসপন্স হেডারে তখন লেখা আসে `api-deprecated-versions: 1.0`।

**কেন দরকার:**
ক্লায়েন্টকে সতর্ক করা যে, "ভাই, এই ভার্সন ১.০ জলদি ছেড়ে ২.০ তে আসো, এটা যেকোনো সময় বন্ধ হয়ে যাবে।"

---

### ৪. কনভেনশন (Conventions)

**কি কাজ করে:**
আপনি যদি প্রতিটা কন্ট্রোলারের মাথায় `[ApiVersion("1.0")]` লিখতে না চান, তবে কনভেনশন ব্যবহার করতে পারেন।
এতে বলা যায়: "Controllers/V1 ফোল্ডারের সব কন্ট্রোলার ভার্সন ১.০ হবে" এবং "Controllers/V2 সব ২.০ হবে"।

---

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Versioning** | ব্রেকিং চেঞ্জ (Breaking Change) হ্যান্ডেল করা। | পুরোনো ক্লায়েন্টদের সাপোর্ট দেওয়া এবং নতুন ফিচার আনা। |
| **Deprecated** | পুরোনো ভার্সন বাতিলের নোটিশ দেওয়া। | ক্লায়েন্টদের নতুন ভার্সনে মাইগ্রেট করতে উৎসাহিত করা। |

**সহজ উদাহরণ:**
ফেসবুকের মোবাইল অ্যাপ আপডেট না করলেও চলে, আবার নতুন অ্যাপেও চলে। কারণ তাদের সার্ভারে `v10.0`, `v11.0` সব ভার্সনের এপিআই রেডি থাকে। আপনার অ্যাপ যেটা কল করে, সার্ভার সেটাই রেসপন্স দেয়।

নিচে ধাপে ধাপে সেটআপ, কোড এবং উদাহরণ দেওয়া হলো।

### ১. সেটআপ (Setup)

**ধাপ ১: প্যাকেজ ইন্সটল**
Package Manager Console এ নিচের কমান্ডটি দিন:
```powershell
Install-Package Asp.Versioning.Mvc
```
*(নোট: পুরোনো বইতে `Microsoft.AspNetCore.Mvc.Versioning` থাকতে পারে, কিন্তু .NET 8 এর জন্য `Asp.Versioning.Mvc` রিকমেন্ডেড)*

**ধাপ ২: সার্ভিস কনফিগারেশন**
`Program.cs` বা `ServiceExtensions.cs` ফাইলে ভার্সনিং সার্ভিস কনফিগার করতে হবে।

**ফাইল:** `Extensions/ServiceExtensions.cs`
```csharp
using Asp.Versioning;

public static void ConfigureVersioning(this IServiceCollection services)
{
    services.AddApiVersioning(opt =>
    {
        // ১. রেসপন্স হেডারে এপিআই ভার্সন রিপোর্ট করা (api-supported-versions)
        opt.ReportApiVersions = true;
        
        // ২. ক্লায়েন্ট যদি ভার্সন না বলে, তবে ডিফল্ট ভার্সন ধরে নেওয়া
        opt.AssumeDefaultVersionWhenUnspecified = true;
        
        // ৩. ডিফল্ট ভার্সন সেট করা (১.০)
        opt.DefaultApiVersion = new ApiVersion(1, 0);

        // ৪. ভার্সন রিডার সেট করা (কোন জায়গা থেকে ভার্সন পড়বে?)
        // আমরা এখানে Query String এবং Header দুটোই সাপোর্ট দিচ্ছি
        opt.ApiVersionReader = new UrlSegmentApiVersionReader(); 
        // অথবা কম্বাইন করতে পারেন:
        // opt.ApiVersionReader = ApiVersionReader.Combine(
        //    new QueryStringApiVersionReader("api-version"),
        //    new HeaderApiVersionReader("X-Version"));
    })
    .AddMvc() // MVC এর জন্য ভার্সনিং সাপোর্ট
    .AddApiExplorer(options =>
    {
        // Swagger এর জন্য ভার্সন ফরমেট (v1, v2)
        options.GroupNameFormat = "'v'VVV";
        options.SubstituteApiVersionInUrl = true;
    });
}
```

**ধাপ ৩: Program.cs এ কল করা**
```csharp
builder.Services.ConfigureVersioning();
```

### ২. কন্ট্রোলার ভার্সনিং (V1 and V2 Controllers)

এখন আমরা দুটি ভার্সনের কন্ট্রোলার তৈরি করব।

**ভার্সন ১.০ কন্ট্রোলার (V1):**
এটি আমাদের আগের কন্ট্রোলারই, শুধু ভার্সন অ্যাট্রিবিউট যোগ করব।

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
using Asp.Versioning;

[ApiVersion("1.0")] // এই কন্ট্রোলারটি ভার্সন ১.০ সাপোর্ট করে
[Route("api/v{version:apiVersion}/companies")] // URL Path Versioning
// [Route("api/companies")] // Query String Versioning এর জন্য
[ApiController]
public class CompaniesController : ControllerBase
{
    [HttpGet]
    public IActionResult GetCompanies()
    {
        var companies = _service.CompanyService.GetAllCompanies(trackChanges: false);
        return Ok(companies);
    }
}
```

**ভার্সন ২.০ কন্ট্রোলার (V2):**
ধরি, ভার্সন ২ তে আমরা ডাটা একটু অন্যভাবে (যেমন: নামের সাথে suffix যোগ করে) রিটার্ন করব।

**ফাইল:** `Presentation/Controllers/CompaniesV2Controller.cs`
```csharp
using Asp.Versioning;

[ApiVersion("2.0")] // এটি ভার্সন ২.০
// [ApiVersion("2.0", Deprecated = true)] // যদি বাতিল করতে চান
[Route("api/v{version:apiVersion}/companies")]
[ApiController]
public class CompaniesV2Controller : ControllerBase
{
    private readonly IServiceManager _service;

    public CompaniesV2Controller(IServiceManager service) => _service = service;

    [HttpGet]
    public IActionResult GetCompanies()
    {
        var companies = _service.CompanyService.GetAllCompanies(trackChanges: false);
        
        // V2 এর জন্য একটু মডিফাই করা হলো (ডেমো হিসেবে)
        var companiesV2 = companies.Select(x => $"{x.Name} V2");
        
        return Ok(companiesV2);
    }
}
```

### ৩. উদাহরণ (Testing Scenarios)

আমরা যেহেতু **URL Path Versioning** (`api/v{version}/companies`) কনফিগার করেছি, তাই নিচের মতো রিকোয়েস্ট হবে।

**Scenario 1: Call API Version 1.0**
*   **Request:** `GET https://localhost:5001/api/v1/companies`
*   **Response:**
    ```json
    [
        { "name": "Google", "address": "USA" },
        { "name": "Microsoft", "address": "USA" }
    ]
    ```
*   **Headers:** `api-supported-versions: 1.0, 2.0` (হেডারে দেখা যাবে কোন কোন ভার্সন আছে)

**Scenario 2: Call API Version 2.0**
*   **Request:** `GET https://localhost:5001/api/v2/companies`
*   **Response:**
    ```json
    [
        "Google V2",
        "Microsoft V2"
    ]
    ```
    *(দেখুন, V2 তে ডাটার ফরম্যাট বদলে স্ট্রিং অ্যারে হয়ে গেছে)*

**Scenario 3: Deprecated Version (Optional)**
যদি `[ApiVersion("1.0", Deprecated = true)]` দেওয়া থাকত:
*   V1 কল করলে রেসপন্স আসত ঠিকই, কিন্তু হেডারে লেখা থাকত:
    `api-deprecated-versions: 1.0`

### ৪. Query String Versioning (বিকল্প পদ্ধতি)
যদি আপনি ইউআরএল ক্লিন রাখতে চান (`/api/companies`), তবে কনফিগারেশনে `QueryStringApiVersionReader` ব্যবহার করবেন এবং কন্ট্রোলারের রাউট হবে `[Route("api/companies")]`।

তখন রিকোয়েস্ট হবে:
*   `GET /api/companies?api-version=1.0`
*   `GET /api/companies?api-version=2.0`

এভাবেই খুব সহজে অল্প কিছু কনফিগারেশনের মাধ্যমে আপনার এপিআই ভার্সনিং সাপোর্ট করতে পারে।
