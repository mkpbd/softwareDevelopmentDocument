
**Chapter 12**-এর নাম হলো **"Caching"**।

এপিআই পারফরম্যান্স বাড়ানোর জন্য ক্যাশিং হলো জাদুর মতো। বারবার ডাটাবেস থেকে একই ডাটা না এনে, মেমোরি থেকে ডাটা দেওয়ার পদ্ধতিই হলো ক্যাশিং।

বইটিতে মূলত দুই ধরনের ক্যাশিং নিয়ে আলোচনা করা হয়েছে:
১. **Response Caching (Old way)**
২. **Output Caching (New in .NET 7/8)**

এছাড়াও **Validation (ETag)** এবং **Expiration** মডেল নিয়ে আলোচনা করা হয়েছে।

---

### ১. ক্যাশিং কেন দরকার? (Why Caching?)

**সমস্যা:**
ধরি, `GET /api/companies` এপিআইটি প্রতি সেকেন্ডে ১০০০ জন ইউজার কল করে।
ক্যাশিং না থাকলে ১০০০ বারই ডাটাবেসে কুয়েরি চলবে। এতে ডাটাবেস স্লো হয়ে যাবে এবং সার্ভার ক্র্যাশ করতে পারে।

**সমাধান (Caching):**
প্রথমবার ডাটাবেস থেকে এনে সেই ডাটা সার্ভারের মেমোরিতে (RAM) রেখে দেওয়া হয়। পরের ৯৯৯ জন ইউজারকে সরাসরি মেমোরি থেকে ডাটা দেওয়া হয়। এটা ১০০ গুণ বেশি ফাস্ট।

---

### ২. রেসপন্স ক্যাশিং (Response Caching)

এটি ক্লায়েন্ট সাইড (Browser) এবং ইন্টারমিডিয়েট প্রক্সি সার্ভারের জন্য নির্দেশিকা পাঠায়।

**কি কাজ করে:**
হেডারে `Cache-Control` যুক্ত করে দেয়।
*   `public`: ডাটা যে কেউ (ইন্টারনেট প্রভাইডার, সিডিএন) ক্যাশ করতে পারে।
*   `private`: ডাটা শুধু ইউজারের ব্রাউজারেই ক্যাশ হবে (পার্সোনাল ডাটা)।
*   `max-age`: কত সেকেন্ড পর্যন্ত এই ডাটা ফ্রেশ থাকবে।

**উদাহরণ:**
`[ResponseCache(Duration = 60)]` দিলে হেডারে যাবে `Cache-Control: public, max-age=60`।
এর মানে আগামী ৬০ সেকেন্ড ব্রাউজার আর সার্ভারে রিকোয়েস্ট পাঠাবে না, নিজের মেমোরি থেকে ডাটা দেখাবে।

---

### ৩. ক্যাশ ভ্যালিডেশন (Cache Validation & ETag)

**সমস্যা:**
ধরি ক্যাশের মেয়াদ ৬০ সেকেন্ড। কিন্তু ১০ সেকেন্ডের মাথায় ডাটাবেসে ডাটা আপডেট হলো। ইউজার তো পুরাতন ডাটা দেখছে! একে বলে **Stale Data**।

**সমাধান (ETag):**
ETag হলো ডাটার একটি ফিঙ্গারপ্রিন্ট বা হ্যাশ কোড।
১. সার্ভার ডাটার সাথে একটি ETag পাঠায় (যেমন: `"12345"`).
২. পরের বার ক্লায়েন্ট রিকোয়েস্ট করার সময় বলে: `If-None-Match: "12345"`.
৩. সার্ভার চেক করে ডাটা চেঞ্জ হয়েছে কি না।
    *   চেঞ্জ না হলে: সার্ভার ডাটা পাঠায় না, শুধু বলে **304 Not Modified** (ব্যান্ডউইথ বাঁচে)।
    *   চেঞ্জ হলে: নতুন ডাটা এবং নতুন ETag পাঠায়।

বইটিতে `Marvin.Cache.Headers` লাইব্রেরি ব্যবহার করে এটি অটোমেটিক হ্যান্ডেল করা হয়েছে।

---

### ৪. আউটপুট ক্যাশিং (Output Caching - New in .NET)

এটি সার্ভার সাইড ক্যাশিংয়ের আধুনিক উপায়।

**কি কাজ করে:**
পুরো রেসপন্স বডি সার্ভারের মেমোরিতে স্টোর করে রাখে।

**সুবিধা:**
*   **Tagging:** আপনি ক্যাশকে ট্যাগ করতে পারেন। যেমন সব কোম্পানি ডাটাকে `tag-companies` নাম দিলেন।
*   **Eviction:** যখনই নতুন কোম্পানি তৈরি হবে (POST), তখন আপনি `EvictByTag("tag-companies")` কল করে পুরোনো ক্যাশ মুছে ফেলতে পারেন। এতে ইউজার সবসময় ফ্রেশ ডাটা পায়।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Response Cache** | ক্লায়েন্টকে বলে কতক্ষণ ডাটা ধরে রাখতে হবে। | ব্রাউজারের লোডিং টাইম কমানোর জন্য। |
| **ETag** | ডাটা পরিবর্তন হয়েছে কি না চেক করা। | ব্যান্ডউইথ বাঁচাতে (ডাটা না পাঠিয়ে শুধু স্ট্যাটাস কোড পাঠানো)। |
| **Output Cache** | সার্ভারে রেসপন্স জমা রাখা। | ডাটাবেস কল কমানোর জন্য এবং সুপার ফাস্ট রেসপন্সের জন্য। |

**সহজ উদাহরণ:**
আপনি একটি রেস্টুরেন্টে গেলেন (সার্ভার)।
*   **No Cache:** ওয়েটার প্রতিবার কিচেনে গিয়ে রাঁধুনির কাছ থেকে খাবার আনছে।
*   **Cache:** ওয়েটার খাবারগুলো আগেই একটা হটপটে (Cache) রেখে দিয়েছে। আপনি চাইলেই সাথে সাথে দিয়ে দিচ্ছে। রাঁধুনিকে (Database) বিরক্ত করতে হচ্ছে না।

১. **Marvin.Cache.Headers** (ক্লায়েন্ট সাইড ক্যাশিং এবং ETag এর জন্য)
২. **Output Caching** (সার্ভার সাইড ক্যাশিং এবং .NET এর বিল্ট-ইন ফিচার)

নিচে ধাপে ধাপে সেটআপ এবং কোড দেওয়া হলো।

### ১. Marvin.Cache.Headers সেটআপ (Validation Model)
এটি সবচেয়ে সহজ উপায় কারণ এটি অটোমেটিক ETag এবং Cache-Control হেডার হ্যান্ডেল করে।

**ধাপ ১: প্যাকেজ ইন্সটল**
```powershell
Install-Package Marvin.Cache.Headers
```

**ধাপ ২: সার্ভিস কনফিগারেশন**
`ServiceExtensions.cs` ফাইলে ক্যাশ কনফিগার করা।

**ফাইল:** `Extensions/ServiceExtensions.cs`
```csharp
public static void ConfigureResponseCaching(this IServiceCollection services) =>
    services.AddResponseCaching(); // এটি .NET এর বেসিক রেসপন্স ক্যাশিং

public static void ConfigureHttpCacheHeaders(this IServiceCollection services) =>
    services.AddHttpCacheHeaders(
        (expirationModelOptions) =>
        {
            expirationModelOptions.MaxAge = 60; // ৬০ সেকেন্ড ফ্রেশ থাকবে
            expirationModelOptions.CacheLocation = Marvin.Cache.Headers.CacheLocation.Private;
        },
        (validationModelOptions) =>
        {
            validationModelOptions.MustRevalidate = true; // মেয়াদ শেষ হলে অবশ্যই সার্ভারে চেক করতে হবে
        });
```

**ধাপ ৩: মিডলওয়্যার যুক্ত করা**
`Program.cs` ফাইলে পাইপলাইনে মিডলওয়্যার বসাতে হবে।

**ফাইল:** `Program.cs`
```csharp
// সার্ভিস অ্যাড করা
builder.Services.ConfigureResponseCaching();
builder.Services.ConfigureHttpCacheHeaders();

var app = builder.Build();

// ... অন্যান্য মিডলওয়্যার ...

app.UseResponseCaching(); // রেসপন্স ক্যাশিং মিডলওয়্যার
app.UseHttpCacheHeaders(); // Marvin মিডলওয়্যার (ETag হ্যান্ডেল করবে)

app.MapControllers();
app.Run();
```

**ধাপ ৪: কন্ট্রোলারে ব্যবহার**
কন্ট্রোলারের ওপর `[HttpCacheExpiration]` বা `[HttpCacheValidation]` অ্যাট্রিবিউট ব্যবহার করে মেথড-লেভেলে ক্যাশ কন্ট্রোল করা যায়। তবে গ্লোবালি কনফিগার করলে সব `GET` রিকোয়েস্টে এটি অটোমেটিক কাজ করে।

### ২. Output Caching সেটআপ (Server Side - .NET 7/8 Feature)
এটি সার্ভারে ডাটা স্টোর করে রাখে এবং ডাটাবেস হিট কমায়।

**ধাপ ১: সার্ভিস কনফিগারেশন**
`Program.cs` বা `ServiceExtensions.cs` এ।

```csharp
public static void ConfigureOutputCaching(this IServiceCollection services) =>
    services.AddOutputCache(options =>
    {
        // একটি বেস পলিসি তৈরি করা
        options.AddBasePolicy(builder => 
            builder.Expire(TimeSpan.FromSeconds(10))); // ১০ সেকেন্ড পর ক্যাশ মুছে যাবে
            
        // কাস্টম পলিসি (Tagging সহ)
        options.AddPolicy("120SecondsDuration", builder => 
            builder.Expire(TimeSpan.FromSeconds(120)).Tag("tag-companies"));
    });
```

**ধাপ ২: মিডলওয়্যার যুক্ত করা**
`Program.cs` ফাইলে `UseCors` এর পরে এবং `MapControllers` এর আগে।

```csharp
builder.Services.ConfigureOutputCaching(); // সার্ভিস

var app = builder.Build();

app.UseCors("CorsPolicy");

app.UseOutputCache(); // <--- এই মিডলওয়্যারটি জরুরি

app.MapControllers();
```

**ধাপ ৩: কন্ট্রোলারে ব্যবহার (Caching)**

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
[HttpGet]
// [OutputCache(Duration = 60)] // সরাসরি এখানেও বলে দেওয়া যায়
[OutputCache(PolicyName = "120SecondsDuration")] // পলিসি ব্যবহার করা
public IActionResult GetCompanies()
{
    var companies = _service.CompanyService.GetAllCompanies(trackChanges: false);
    return Ok(companies);
}
```

### ৩. উদাহরণ (Testing Scenarios)

**Scenario 1: Testing Marvin.Cache.Headers (ETag)**

*   **১ম রিকোয়েস্ট:** `GET /api/companies`
    *   **Response:** `200 OK` (ডাটাবেস থেকে ডাটা আসবে)
    *   **Header:** `ETag: "some-long-hash-string"`, `Cache-Control: private, max-age=60`
*   **২য় রিকোয়েস্ট (৬০ সেকেন্ডের মধ্যে):**
    *   ব্রাউজার সার্ভারেই যাবে না, লোকাল ক্যাশ থেকে দেখাবে (Status: 200 (from disk cache))।
*   **৩য় রিকোয়েস্ট (৬০ সেকেন্ড পর):**
    *   ক্লায়েন্ট রিকোয়েস্ট পাঠাবে: `If-None-Match: "some-long-hash-string"`
    *   সার্ভার চেক করবে ডাটা চেঞ্জ হয়েছে কিনা।
    *   **Response:** `304 Not Modified` (বডি খালি)। ডাটাবেস থেকে ডাটা আনার দরকার হয়নি, ব্যান্ডউইথ সেভ হলো।

**Scenario 2: Testing Output Caching (Server Side)**

*   **১ম রিকোয়েস্ট:** `GET /api/companies`
    *   সার্ভার ডাটাবেস কুয়েরি করবে।
    *   রেসপন্স ক্যাশে স্টোর করবে।
    *   **Time Taken:** 500ms.
*   **২য় রিকোয়েস্ট:** `GET /api/companies`
    *   সার্ভার কন্ট্রোলারেই ঢুকবে না। মেমোরি থেকে রেসপন্স দিয়ে দেবে।
    *   **Time Taken:** 5ms (১০০ গুণ ফাস্ট!)।

### বোনাস: ক্যাশ ক্লিন করা (Eviction)

নতুন কোম্পানি এড করলে পুরোনো ক্যাশ মুছে ফেলা উচিত। `OutputCache` দিয়ে এটি সহজে করা যায়।

```csharp
[HttpPost]
public async Task<IActionResult> CreateCompany([FromBody] CompanyDto company, [FromServices] IOutputCacheStore cacheStore)
{
    var createdCompany = _service.CreateCompany(company);
    
    // "tag-companies" ট্যাগযুক্ত সব ক্যাশ মুছে ফেলো
    await cacheStore.EvictByTagAsync("tag-companies", CancellationToken.None);
    
    return CreatedAtRoute(...)
}
```
*এতে পরের বার `GetCompanies` কল করলে ফ্রেশ ডাটা আসবে।*
