
**Chapter 13**-এর নাম হলো **"Rate Limiting and Throttling"**।

আপনার এপিআই খুব ভালো, খুব ফাস্ট। কিন্তু একদিন হঠাৎ দেখলেন একজন হ্যাকার বা দুষ্টু ইউজার একটা স্ক্রিপ্ট চালিয়ে প্রতি সেকেন্ডে ১০,০০০ রিকোয়েস্ট পাঠাচ্ছে। এতে আপনার সার্ভার বসে যাবে (DDoS Attack)।

এই সমস্যা ঠেকানোর জন্যই **Rate Limiting** ব্যবহার করা হয়। এটি নির্ধারণ করে দেয় একজন ইউজার নির্দিষ্ট সময়ে কতবার এপিআই কল করতে পারবে।

বইটিতে **Asp.Net Core Rate Limiting Middleware** (যা .NET 7 এ নতুন এসেছে) ব্যবহার করা হয়েছে।

### ১. রেট লিমিটিং কী? (What is Rate Limiting?)

**কি কাজ করে:**
এটি ট্রাফিক পুলিশের মতো।
এটি বলে দেয়: "তুমি ১ মিনিটে সর্বোচ্চ ১০টা রিকোয়েস্ট পাঠাতে পারবে। ১১ নম্বর রিকোয়েস্ট পাঠালে আমি তোমাকে ব্লক করে দেব।"

**কেন দরকার (Why):**
১. **Security:** DDoS (Distributed Denial of Service) অ্যাটাক থেকে বাঁচা।
২. **Fair Usage:** কোনো একজন ইউজার যেন সব সার্ভার রিসোর্স দখল করে না ফেলে, সবাই যেন সমান সুযোগ পায়।
৩. **Cost Control:** ক্লাউড সার্ভারে (Azure/AWS) বেশি রিকোয়েস্ট মানে বেশি বিল। রেট লিমিটিং বিল কমাতে সাহায্য করে।

### ২. রেট লিমিটিং অ্যালগরিদম (Algorithms)

বইটিতে চারটি প্রধান অ্যালগরিদম নিয়ে আলোচনা করা হয়েছে:

**ক. Fixed Window (স্থির জানালা)**
*   **নিয়ম:** "প্রতি ১ মিনিটে ১০টি রিকোয়েস্ট।"
*   **সমস্যা:** দুপুর ১২:০০ থেকে ১২:০১ পর্যন্ত ১০টা রিকোয়েস্ট শেষ করলে, ১২:০১ বাজার আগ পর্যন্ত আর কোনো রিকোয়েস্ট নেওয়া হবে না।
*   **Edge Case:** ১২:০০:৫৯ এ ১০টা আর ১২:০১:০১ এ ১০টা রিকোয়েস্ট পাঠালে ২ সেকেন্ডে ২০টা রিকোয়েস্ট ঢুকে যায়, যা সার্ভারে চাপ ফেলে।

**খ. Sliding Window (চলমান জানালা)**
*   এটি ফিক্সড উইন্ডোর সমস্যা সমাধান করে। সময়টি স্থির না থেকে রিকোয়েস্টের সাথে সাথে সরে (slide করে)। এটি বেশি স্মুথ।

**গ. Token Bucket (টোকেন বালতি)**
*   **নিয়ম:** আপনার কাছে একটা বালতি আছে যাতে ১০টা টোকেন ধরে। প্রতি রিকোয়েস্টে ১টা টোকেন খরচ হয়।
*   **রিফিল:** প্রতি ১ মিনিটে বালতিতে আবার ২টা করে টোকেন জমা হয়।
*   **সুবিধা:** ইউজার মাঝে মাঝে একসাথে অনেক রিকোয়েস্ট (Burst) পাঠাতে পারে, আবার টোকেন শেষ হলে অপেক্ষা করতে হয়।

**ঘ. Concurrency Limiter (একসাথে কয়জন?)**
*   এটি সময়ের ওপর নির্ভর করে না। এটি দেখে **এই মুহূর্তে** কয়টা রিকোয়েস্ট প্রসেসিংয়ে আছে।
*   **নিয়ম:** "একসাথে সর্বোচ্চ ৫টা রিকোয়েস্ট প্রসেস করব।" ৬ নম্বর জন কিউতে (Queue) থাকবে।

### ৩. স্ট্যাটাস কোড (Status Code 429)

যখন কেউ লিমিট ক্রস করে ফেলে, তখন এপিআই তাকে **429 Too Many Requests** স্ট্যাটাস কোড রিটার্ন করে।
সাথে হেডারে বলে দেওয়া যায় `Retry-After: 60` (৬০ সেকেন্ড পর আবার চেষ্টা করো)।

### ৪. সেটআপ এবং কনফিগারেশন

.NET 7/8 এ এটি সেটআপ করা খুব সহজ।

**উদাহরণ:**
```csharp
builder.Services.AddRateLimiter(opt => {
    opt.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(context =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: context.Connection.RemoteIpAddress.ToString(), // আইপি অ্যাড্রেস অনুযায়ী আলাদা আলাদা লিমিট
            factory: partition => new FixedWindowRateLimiterOptions
            {
                AutoReplenishment = true,
                PermitLimit = 10,   // ১০টি রিকোয়েস্ট
                Window = TimeSpan.FromMinutes(1) // ১ মিনিটে
            }));
});
```

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Fixed Window** | নির্দিষ্ট সময়ে নির্দিষ্ট রিকোয়েস্ট। | বেসিক প্রোটেকশনের জন্য। |
| **Token Bucket** | টোকেন সিস্টেমে রিকোয়েস্ট কন্ট্রোল। | যারা হঠাৎ বেশি রিকোয়েস্ট পাঠায় তাদের হ্যান্ডেল করতে। |
| **Concurrency** | একসাথে কয়টা রিকোয়েস্ট চলবে। | সার্ভার হ্যাং হওয়া থেকে বাঁচাতে। |
| **429 Error** | ইউজারকে ওয়ার্নিং দেওয়া। | ইউজার যেন বোঝে তাকে কেন ব্লক করা হয়েছে। |

**সহজ উদাহরণ:**
এটিএম বুথে ঢোকার নিয়ম।
*   **Concurrency Limiter:** বুথের ভেতর একসাথে ১ জনের বেশি ঢুকতে পারবে না।
*   **Fixed Window:** আপনি ১ দিনে ৩ বারের বেশি টাকা তুলতে পারবেন না।

### ১. সার্ভিস কনফিগারেশন (Service Configuration)

আমরা `Extensions/ServiceExtensions.cs` ফাইলে রেট লিমিটিং কনফিগার করব। এখানে আমরা **Fixed Window** অ্যালগরিদম ব্যবহার করব।

**ফাইল:** `Extensions/ServiceExtensions.cs`
```csharp
using Microsoft.AspNetCore.RateLimiting;
using System.Threading.RateLimiting;

public static void ConfigureRateLimitingOptions(this IServiceCollection services)
{
    services.AddRateLimiter(opt =>
    {
        // ১. স্ট্যাটাস কোড সেট করা (ডিফল্ট ৫-০-৩ থাকে, আমরা ৪-২-৯ চাই)
        opt.RejectionStatusCode = StatusCodes.Status429TooManyRequests;

        // ২. গ্লোবাল লিমিট সেট করা (পুরো অ্যাপের জন্য)
        opt.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(context =>
        {
            return RateLimitPartition.GetFixedWindowLimiter(
                // আইপি অ্যাড্রেস অনুযায়ী ইউজারদের আলাদা করা (Partition Key)
                partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? context.Request.Headers.Host.ToString(),
                
                factory: partition => new FixedWindowRateLimiterOptions
                {
                    AutoReplenishment = true, // অটোমেটিক টাইম রিসেট হবে
                    PermitLimit = 30,         // ১ মিনিটে সর্বোচ্চ ৩০টি রিকোয়েস্ট
                    QueueLimit = 2,           // লিমিট শেষ হলে আরো ২টি রিকোয়েস্ট লাইনে (Queue) রাখা যাবে
                    QueueProcessingOrder = QueueProcessingOrder.OldestFirst,
                    Window = TimeSpan.FromMinutes(1) // ১ মিনিটের জানালা
                });
        });

        // ৩. রিজেকশন হ্যান্ডলিং (ইউজারকে সুন্দর মেসেজ দেওয়া)
        opt.OnRejected = async (context, token) =>
        {
            await context.HttpContext.Response.WriteAsync(
                $"Too many requests. Please try again later. " +
                $"Limit: 30 requests per minute.", token);
        };
    });
}
```

### ২. মিডলওয়্যার যুক্ত করা (Middleware Setup)

`Program.cs` ফাইলে রেট লিমিটিং মিডলওয়্যারটি সঠিক জায়গায় বসাতে হবে। সাধারণত এটি `UseRouting` এর পরে এবং `MapControllers` এর আগে বসে।

**ফাইল:** `Program.cs`
```csharp
// ১. সার্ভিস কল করা
builder.Services.ConfigureRateLimitingOptions();

var app = builder.Build();

// ... অন্যান্য মিডলওয়্যার ...
app.UseHttpsRedirection();

// ২. রেট লিমিটার মিডলওয়্যার চালু করা
app.UseRateLimiter(); 

app.UseAuthorization();
app.MapControllers();
app.Run();
```

### ৩. নির্দিষ্ট কন্ট্রোলারে স্পেশাল রুলস (Specific Policy)

মাঝে মাঝে গ্লোবাল লিমিট সব কন্ট্রোলারের জন্য খাটে না। ধরুন `Authentication` কন্ট্রোলারে আপনি চান ১ মিনিটে মাত্র ৩ বার ট্রাই করা যাবে (ব্রুট ফোর্স অ্যাটাক ঠেকাতে)।

**ধাপ ১: পলিসি তৈরি করা (Service Extensions এ)**
```csharp
services.AddRateLimiter(opt =>
{
    // ... আগের কোড ...

    // স্পেসিফিক পলিসি: "login-policy"
    opt.AddPolicy("login-policy", context =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: context.Connection.RemoteIpAddress?.ToString(),
            factory: partition => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 3,  // মাত্র ৩ বার
                Window = TimeSpan.FromMinutes(1)
            }));
});
```

**ধাপ ২: কন্ট্রোলারে অ্যাপ্লাই করা**
```csharp
[HttpPost("login")]
[EnableRateLimiting("login-policy")] // <--- এই পলিসি এখানে কাজ করবে
public IActionResult Login(...)
{
    // ...
}
```
*আবার কোনো কন্ট্রোলারে লিমিট না চাইলে `[DisableRateLimiting]` ব্যবহার করা যায়।*

### ৪. উদাহরণ (Testing Scenarios)

আমরা পোস্টম্যান বা একটি লুপ চালিয়ে এটি টেস্ট করতে পারি।

**Scenario 1: Normal Usage (Within Limit)**
*   **Action:** ১ মিনিটে ১০ বার রিকোয়েস্ট পাঠানো হলো।
*   **Result:** `200 OK`. সব ডাটা ঠিকঠাক আসবে।

**Scenario 2: Exceeding Limit (Attack Simulation)**
*   **Action:** ১ মিনিটের মধ্যে ৩১তম রিকোয়েস্ট পাঠানো হলো।
*   **Result:** `429 Too Many Requests`.
*   **Body:** "Too many requests. Please try again later. Limit: 30 requests per minute."

**Scenario 3: Queue Test**
*   **Action:** ৩০টি রিকোয়েস্ট শেষ। এরপর সাথে সাথে আরও ২টি রিকোয়েস্ট পাঠানো হলো।
*   **Result:** সার্ভার সাথে সাথে এরর দেবে না। রিকোয়েস্ট দুটিকে `Queue` তে রাখবে এবং ১ মিনিট পার হওয়ার পর প্রসেস করবে। কিন্তু ৩য় রিকোয়েস্ট পাঠালে সাথে সাথে `429` খাবে।

### টিপস (Best Practice)
*   **IP Address:** আমরা এখানে আইপি অ্যাড্রেস ব্যবহার করেছি। কিন্তু আইপি স্পুফিং হতে পারে। অথেনটিকেটেড অ্যাপে `UserId` বা `ClientId` দিয়ে পার্টিশন করা বেশি নিরাপদ।
*   **Reverse Proxy:** আপনি যদি Nginx বা IIS এর পেছনে অ্যাপ চালান, তবে আসল আইপি পাওয়ার জন্য `ForwardedHeaders` কনফিগার করতে হবে (যা আমরা Chapter 1 এ করেছি)। নইলে সবার আইপি `localhost` বা `127.0.0.1` দেখাবে এবং একজনের দোষে সবাই ব্লক হয়ে যাবে।
