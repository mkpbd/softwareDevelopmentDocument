
**Chapter 16**-এর নাম হলো **"Deployment to IIS"**।

আমরা এতক্ষণ ধরে আমাদের কম্পিউটারে (Localhost) কোড রান করেছি। কিন্তু আপনি যখন অ্যাপটি বানিয়ে ফেলবেন, তখন সেটি আপনার ল্যাপটপে চললে হবে না, সেটি এমন একটা সার্ভারে রাখতে হবে যেন পৃথিবীর সবাই সেটা ব্যবহার করতে পারে। এই সার্ভারে কোড রাখার নামই হলো **ডিপ্লয়মেন্ট (Deployment)**।

এই চ্যাপ্টারে মূলত উইন্ডোজ সার্ভারের **IIS (Internet Information Services)**-এ কীভাবে অ্যাপ্লিকেশন হোস্ট করতে হয়, তা দেখানো হয়েছে।

---

### ১. আইআইএস কী? (What is IIS?)

**কি কাজ করে:**
IIS হলো মাইক্রোসফটের তৈরি একটি **Web Server** সফটওয়্যার। এটি আপনার অ্যাপ্লিকেশনকে চালায় এবং ইন্টারনেটের রিকোয়েস্ট (HTTP Request) রিসিভ করে অ্যাপ্লিকেশনের কাছে পৌঁছে দেয়।

**কেন দরকার (Why):**
আপনার কনসোল অ্যাপ্লিকেশন (Kestrel) একা একা ইন্টারনেটে লাইভ চালানো নিরাপদ নয় এবং কঠিন। IIS একটি ম্যানেজারের মতো কাজ করে। এটি সিকিউরিটি, রিস্টার্ট, লগিং এবং পোর্ট ম্যানেজমেন্ট হ্যান্ডেল করে।

---

### ২. পাবলিশিং (Publishing)

**কি কাজ করে:**
আমরা যখন কোড লিখি, তখন হাজার হাজার `.cs` ফাইল থাকে। এগুলো সরাসরি সার্ভারে দেওয়া যায় না।
পাবলিশ করলে কোডগুলো কম্পাইল হয়ে `.dll` (Dynamic Link Library) ফাইলে পরিণত হয়। অপ্রয়োজনীয় ফাইল বাদ দিয়ে একটি ছোট ফোল্ডারে শুধু কাজের ফাইলগুলো জমা হয়।

**কেন দরকার:**
১. কোড সিকিউর থাকে (সোর্স কোড কেউ দেখতে পায় না)।
২. ফাইল সাইজ ছোট হয়।
৩. অপটিমাইজড রানটাইম পারফরম্যান্স পাওয়া যায়।

**কিভাবে করে:**
Visual Studio-তে রাইট ক্লিক করে `Publish` -> `Folder` সিলেক্ট করলে একটি ফোল্ডারে সব ফাইল রেডি হয়ে যায়।

---

### ৩. হোস্টিং মডেল (Hosting Models)

IIS এ দুইভাবে অ্যাপ চালানো যায়:

**ক. In-Process (ডিফল্ট এবং ফাস্ট)**
*   **কাজ:** IIS এর নিজস্ব প্রসেস (`w3wp.exe`) এর ভেতরেই আপনার অ্যাপ চলে।
*   **সুবিধা:** খুব ফাস্ট, কারণ নেটওয়ার্ক হপ (Hop) বা মাঝখানের রাস্তা নেই।

**খ. Out-of-Process**
*   **কাজ:** IIS শুধু রিকোয়েস্ট রিসিভ করে এবং আপনার অ্যাপের নিজস্ব প্রসেস (`dotnet.exe`) এ পাঠিয়ে দেয় (Reverse Proxy)।
*   **সুবিধা:** অ্যাপ ক্র্যাশ করলে IIS ক্র্যাশ করে না। আলাদাভাবে চালানো যায়।

---

### ৪. এনভায়রনমেন্ট ভেরিয়েবল (Environment Variables)

**কি কাজ করে:**
সার্ভারে অ্যাপ চালানোর সময় আমাদের বলে দিতে হয় এটা কি `Development` নাকি `Production`।
সাধারণত সার্ভারে `ASPNETCORE_ENVIRONMENT = Production` সেট করা থাকে।

**কেন দরকার:**
ডেভেলপমেন্ট মোডে আমরা ডিটেইলড এরর মেসেজ দেখাই, কিন্তু প্রোডাকশনে দেখাই না (সিকিউরিটির জন্য)। এই ভেরিয়েবল দিয়েই অ্যাপ বোঝে এখন সে কোথায় আছে।

---

### ৫. web.config ফাইল

**কি কাজ করে:**
এটি IIS এর জন্য একটি কনফিগারেশন ফাইল। এতে বলা থাকে অ্যাপটি কীভাবে স্টার্ট হবে, কোন প্রসেস চলবে, লগ কোথায় থাকবে ইত্যাদি।
পাবলিশ করার সময় এটি অটোমেটিক তৈরি হয়।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Publishing** | কোডকে প্রোডাকশন-রেডি ফাইলে রূপান্তর করা। | সার্ভারে আপলোড করার জন্য। |
| **IIS** | উইন্ডোজ ওয়েব সার্ভার। | অ্যাপ হোস্ট বা লাইভ করার জন্য। |
| **In-Process** | IIS এর পেটের ভেতর অ্যাপ চালানো। | সেরা পারফরম্যান্স পাওয়ার জন্য। |
| **web.config** | IIS এর নির্দেশনামা। | সার্ভার কনফিগার করার জন্য। |

**সহজ উদাহরণ:**
*   **Coding:** রান্নাঘরে রান্না করা।
*   **Publishing:** খাবার টিফিন বক্সে প্যাক করা।
*   **Deployment (IIS):** টিফিন বক্সটি দোকানের তাকে (Server Shelf) সাজিয়ে রাখা, যাতে কাস্টমাররা এসে নিতে পারে।

নিচে ধাপ অনুযায়ী সেটআপ, কোড এবং প্রসেস দেওয়া হলো।

### ১. কোড কনফিগারেশন (IIS Integration)

চ্যাপ্টার ১-এ আমরা `ConfigureIISIntegration` মেথড বানিয়েছিলাম, সেটি নিশ্চিত করুন ঠিক আছে কি না।

**ফাইল:** `Extensions/ServiceExtensions.cs`
```csharp
public static void ConfigureIISIntegration(this IServiceCollection services) =>
    services.Configure<IISOptions>(options =>
    {
        // ডিফল্ট সেটিংস রাখা হয়েছে। 
        // আপনি চাইলে এখানে AuthenticationDisplayName বা AutomaticAuthentication পরিবর্তন করতে পারেন।
    });
```

**ফাইল:** `Program.cs`
```csharp
builder.Services.ConfigureIISIntegration();
// ...
app.UseForwardedHeaders(new ForwardedHeadersOptions
{
    ForwardedHeaders = ForwardedHeaders.All
});
```
*(এই `UseForwardedHeaders` জরুরি কারণ প্রক্সি সার্ভারের পেছনে থাকলে আসল আইপি চেনার জন্য এটি লাগে)*

### ২. পাবলিশিং (Publishing the App)

এখন আমরা আমাদের অ্যাপটিকে একটি ফোল্ডারে পাবলিশ করব।

**ধাপ ১: ভিজ্যুয়াল স্টুডিও থেকে**
১. Solution Explorer-এ মেইন প্রজেক্টে (`CompanyEmployees`) রাইট ক্লিক করুন।
২. **Publish**-এ ক্লিক করুন।
৩. **Target:** `Folder` সিলেক্ট করুন।
৪. **Location:** ডিফল্ট ফোল্ডার বা আপনার পছন্দমতো ফোল্ডার দিন (যেমন: `C:\Publish\CompanyEmployees`).
৫. **Finish** এবং **Close**.
৬. এবার **Publish** বাটনে ক্লিক করুন।

**ফাইল চেক:**
পাবলিশ ফোল্ডারে গিয়ে দেখবেন অনেকগুলো `.dll` ফাইল, একটি `CompanyEmployees.exe`, `appsettings.json` এবং একটি `web.config` ফাইল তৈরি হয়েছে।

**web.config ফাইলটি দেখতে এমন হয় (অটোমেটিক তৈরি হয়):**
```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <location path="." inheritInChildApplications="false">
    <system.webServer>
      <handlers>
        <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
      </handlers>
      <aspNetCore processPath="dotnet" arguments=".\CompanyEmployees.dll" stdoutLogEnabled="false" stdoutLogFile=".\logs\stdout" hostingModel="inprocess" />
    </system.webServer>
  </location>
</configuration>
```

### ৩. IIS সেটআপ (Server Setup)

আপনার পিসিতে বা সার্ভারে IIS ইন্সটল এবং কনফিগার করতে হবে।

**ধাপ ১: IIS ইন্সটল করা (উইন্ডোজ ফিচার থেকে)**
১. Start Menu -> "Turn Windows features on or off".
২. **Internet Information Services** বক্সে টিক দিন।
৩. **World Wide Web Services** -> **Application Development Features** -> **.NET Extensibility 4.8** এবং **ASP.NET 4.8** সিলেক্ট করুন (এটি সাধারণত লাগে)।
৪. OK দিন।

**ধাপ ২: Hosting Bundle ইন্সটল করা**
সার্ভারে .NET Core অ্যাপ চালানোর জন্য **.NET Core Hosting Bundle** ইন্সটল করতে হবে। এটি মাইক্রোসফটের সাইট থেকে ডাউনলোড করে ইন্সটল করুন।

### ৪. IIS এ সাইট তৈরি করা (Deploy)

**ধাপ ১: IIS Manager ওপেন করা**
Start Menu -> `inetmgr` লিখে এন্টার দিন।

**ধাপ ২: নতুন সাইট যোগ করা**
১. বাম প্যানেলে `Sites`-এ রাইট ক্লিক করুন -> **Add Website**.
২. **Site name:** `CompanyEmployees`.
৩. **Physical path:** আপনি যেখানে পাবলিশ করেছেন সেই ফোল্ডারটি দেখিয়ে দিন (যেমন: `C:\Publish\CompanyEmployees`).
৪. **Binding:** Port `80` বা অন্য কোনো পোর্ট (যেমন `8080`) দিন।
৫. OK.

**ধাপ ৩: অ্যাপলিকেশন পুল (Application Pool) চেক করা**
১. বাম প্যানেলে `Application Pools`-এ ক্লিক করুন।
২. `CompanyEmployees` পুলটিতে ডাবল ক্লিক করুন।
৩. **.NET CLR version:** `No Managed Code` সিলেক্ট করুন (কারণ .NET Core নিজের রানটাইমে চলে, IIS এর CLR লাগে না)।
৪. OK.

### ৫. ডাটাবেস পারমিশন (Database Permission)

আপনার অ্যাপটি এখন `IIS AppPool\CompanyEmployees` নামে একটি স্পেশাল ইউজারের আন্ডারে চলছে। এই ইউজারের SQL Server এ এক্সেস নাও থাকতে পারে।

**সমাধান:**
SQL Server Management Studio (SSMS) এ গিয়ে `Security` -> `Logins` এ রাইট ক্লিক করে `New Login` এ এই ইউজারকে অ্যাড করুন এবং আপনার ডাটাবেসের পারমিশন দিন।
অথবা কানেকশন স্ট্রিংয়ে SQL ইউজারনেম-পাসওয়ার্ড ব্যবহার করুন।

### ৬. টেস্ট করা (Testing)

ব্রাউজার ওপেন করুন এবং লিখুন: `http://localhost:8080/api/companies` (বা আপনার দেওয়া পোর্টে)।
যদি জেসন ডাটা আসে, তার মানে আপনার ডিপ্লয়মেন্ট সফল!

**Common Error (500.19 or 500.30):**
যদি এরর আসে, তবে সাধারণত ২ কারণে হয়:
১. Hosting Bundle ইন্সটল করা নেই।
২. ডাটাবেস কানেকশন পাচ্ছে না (পারমিশন সমস্যা)।
সেক্ষেত্রে `logs` ফোল্ডার চেক করে বা ইভেন্ট ভিউয়ার দেখে সমাধান করতে হয়।
