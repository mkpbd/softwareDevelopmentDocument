
**Chapter 17**-এর নাম হলো **"CQRS and MediatR"**।

আমরা এতক্ষণ ধরে যে প্যাটার্নে কাজ করছিলাম (Controller -> Service -> Repository), তাকে বলা হয় **Layered Architecture**। এটি ছোট বা মাঝারি প্রজেক্টের জন্য ঠিক আছে। কিন্তু প্রজেক্ট যখন অনেক বড় ও জটিল হয়ে যায়, তখন **CQRS** প্যাটার্ন ব্যবহার করা হয়।

বইটিতে একটি বোনাস বা অ্যাডভান্সড টপিক হিসেবে এটি দেখানো হয়েছে। এখানে **MediatR** লাইব্রেরি ব্যবহার করে কীভাবে কন্ট্রোলারকে আরও হালকা এবং ক্লিন করা যায়, তা শেখানো হয়েছে।

---

### ১. CQRS কী? (What is CQRS?)

**CQRS** মানে হলো **Command Query Responsibility Segregation**।
সহজ বাংলায়: "পড়ার কাজ (Read) এবং লেখার কাজ (Write) আলাদা করা।"

*   **Queries:** ডাটা শুধু দেখবে, কোনো পরিবর্তন করবে না। (যেমন: `GetCompanies`, `GetEmployeeById`)।
*   **Commands:** ডাটা পরিবর্তন করবে। (যেমন: `Create`, `Update`, `Delete`)।

**কেন দরকার (Why):**
সাধারণত একটা অ্যাপ্লিকেশনে পড়ার চাপ (Read Load) লেখার চাপের (Write Load) চেয়ে অনেক বেশি থাকে। CQRS করলে আপনি রিড এবং রাইট মডেল আলাদা করতে পারেন, এমনকি আলাদা ডাটাবেসও ব্যবহার করতে পারেন (রিডের জন্য ফাস্ট NoSQL, রাইটের জন্য SQL)।

---

### ২. মেডিয়েটর প্যাটার্ন (Mediator Pattern & MediatR)

**সমস্যা:**
আমাদের কন্ট্রোলারে `IServiceManager` ইনজেক্ট করতে হতো। সার্ভিস ম্যানেজারের ভেতর আবার অনেকগুলো সার্ভিস থাকত। সব ক্লাস সবার সাথে সরাসরি কথা বলত (Tight Coupling)।

**সমাধান (MediatR):**
MediatR হলো মাঝখানের একজন দালাল বা মধ্যস্থতাকারী (Mediator)।
*   **Controller** এর আর সার্ভিস চেনার দরকার নেই। সে শুধু MediatR-কে একটা মেসেজ পাঠায়।
*   **MediatR** সেই মেসেজটি সঠিক হ্যান্ডলারে (Handler) পৌঁছে দেয়।

**ফ্লো:**
Controller -> **Send Command** -> **MediatR** -> **Handler** -> Database.

---

### ৩. রিকোয়েস্ট এবং হ্যান্ডলার (Request & Handler)

MediatR এ কাজ করার জন্য আমাদের দুটি ক্লাস লাগে:
১. **Request (Message):** এটি একটি ছোট ক্লাস যা ডাটা বহন করে। (যেমন: `GetCompaniesQuery`)।
২. **Handler:** এটি আসল কাজ করে। এটি রিকোয়েস্ট পায়, ডাটাবেস থেকে ডাটা আনে এবং রিটার্ন করে।

---

### ৪. পাইপলাইন বিহেভিয়ার (Pipeline Behaviors)

**কি কাজ করে:**
আমরা আগে **Action Filter** ব্যবহার করে ভ্যালিডেশন বা লগিং করতাম। MediatR এ একই কাজের জন্য **Pipeline Behavior** ব্যবহার করা হয়।
হ্যান্ডলারে মেসেজ পৌঁছানোর **আগে** এবং **পরে** এটি কাজ করে।

**উদাহরণ:**
আমরা `ValidationBehavior` বানাতে পারি। যখনই কোনো কমান্ড আসবে, হ্যান্ডলারে যাওয়ার আগেই `FluentValidation` চেক করবে ডাটা ঠিক আছে কি না। ঠিক না থাকলে এক্সেপশন থ্রো করবে।

---

### ৫. নোটিফিকেশন (Notifications)

MediatR দিয়ে **One-to-Many** কমিউনিকেশনও করা যায়।
একই মেসেজ একাধিক হ্যান্ডলার রিসিভ করতে পারে।
*   **উদাহরণ:** `EmployeeCreatedNotification`।
    *   Handler 1: ইমেইল পাঠাবে।
    *   Handler 2: লগ ফাইলে লিখবে।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **CQRS** | রিড এবং রাইট অপারেশন আলাদা করা। | পারফরম্যান্স এবং স্কেলেবিলিটি বাড়ানোর জন্য। |
| **MediatR** | কন্ট্রোলার এবং লজিক লেয়ারের মাঝে দেওয়াল তোলা। | লুজলি কাপলড (Loosely Coupled) আর্কিটেকচারের জন্য। |
| **Handlers** | ছোট ছোট লজিক ব্লক। | কোড মেইনটেইন করা সহজ করার জন্য (Single Responsibility)। |
| **Behaviors** | গ্লোবাল ভ্যালিডেশন বা লগিং। | কোড ডুপ্লিকেশন কমানোর জন্য। |

**সহজ উদাহরণ:**
*   **আগের পদ্ধতি:** আপনি রেস্টুরেন্টে গিয়ে সরাসরি রাঁধুনিকে (Service) বলছেন কী রান্না করতে হবে।
*   **MediatR:** আপনি ওয়েটারকে (Mediator) অর্ডার দিচ্ছেন। ওয়েটার জানে না কীভাবে রান্না করতে হয়, সে শুধু অর্ডারটি কিচেনে সঠিক শেফ-এর (Handler) কাছে পৌঁছে দেয়। শেফ রান্না করে ওয়েটারকে দেয়, ওয়েটার আপনাকে দেয়।

**Chapter 17**-এ আমরা **CQRS** প্যাটার্ন ইমপ্লিমেন্ট করব **MediatR** লাইব্রেরি ব্যবহার করে। এটি আমাদের প্রজেক্টের আর্কিটেকচারকে আরও ক্লিন এবং মডার্ন করবে।

### ১. সেটআপ (Setup)

**ধাপ ১: প্যাকেজ ইন্সটল**
আমাদের `MediatR` প্যাকেজটি লাগবে।
```powershell
Install-Package MediatR
```

**ধাপ ২: MediatR রেজিস্টার করা**
`Program.cs` ফাইলে MediatR সার্ভিস রেজিস্টার করতে হবে। একে বলে দিতে হয় হ্যান্ডলারগুলো কোন অ্যাসেম্বলিতে আছে।

**ফাইল:** `Program.cs`
```csharp
// অ্যাপ্লিকেশন অ্যাসেম্বলি থেকে সব হ্যান্ডলার খুঁজে রেজিস্টার করবে
builder.Services.AddMediatR(cfg => cfg.RegisterServicesFromAssembly(typeof(Program).Assembly));
```

### ২. কুয়েরি এবং হ্যান্ডলার তৈরি (Implementing Query)

আমরা `GetCompanies` এপিআইটিকে CQRS এ কনভার্ট করব।

**ধাপ ১: Query রেকর্ড তৈরি (Request)**
এটি একটি মেসেজ বা প্যাকেট যা বলবে "আমি সব কোম্পানি চাই"। এটি `IRequest` ইন্টারফেস ইমপ্লিমেন্ট করে এবং কী রিটার্ন করবে তা বলে দেয়।

**ফাইল:** `Application/Queries/GetCompaniesQuery.cs`
```csharp
using MediatR;
using Shared.DataTransferObjects;

// এটি একটি রিকোয়েস্ট যা IEnumerable<CompanyDto> রিটার্ন করবে
public record GetCompaniesQuery(bool TrackChanges) : IRequest<IEnumerable<CompanyDto>>;
```

**ধাপ ২: হ্যান্ডলার তৈরি (Handler)**
এটি রিকোয়েস্টটি রিসিভ করবে এবং লজিক এক্সিকিউট করবে।

**ফাইল:** `Application/Handlers/GetCompaniesHandler.cs`
```csharp
using MediatR;
using Contracts; // IRepositoryManager
using AutoMapper;
using Shared.DataTransferObjects;

public class GetCompaniesHandler : IRequestHandler<GetCompaniesQuery, IEnumerable<CompanyDto>>
{
    private readonly IRepositoryManager _repository;
    private readonly IMapper _mapper;

    public GetCompaniesHandler(IRepositoryManager repository, IMapper mapper)
    {
        _repository = repository;
        _mapper = mapper;
    }

    public async Task<IEnumerable<CompanyDto>> Handle(GetCompaniesQuery request, CancellationToken cancellationToken)
    {
        // ১. রিপোজিটরি থেকে ডাটা আনা
        var companies = await _repository.Company.GetAllCompaniesAsync(request.TrackChanges);
        
        // ২. ম্যাপ করা
        var companiesDto = _mapper.Map<IEnumerable<CompanyDto>>(companies);
        
        // ৩. রিটার্ন করা
        return companiesDto;
    }
}
```
*(নোট: রিপোজিটরিতে `GetAllCompaniesAsync` মেথডটি `async` হতে হবে)*

### ৩. কমান্ড এবং হ্যান্ডলার তৈরি (Implementing Command)

এখন আমরা `CreateCompany` (POST) অপারেশন করব।

**ধাপ ১: Command রেকর্ড (Request)**
এখানে ইনপুট ডাটা (`CompanyForCreationDto`) থাকবে।

**ফাইল:** `Application/Commands/CreateCompanyCommand.cs`
```csharp
using MediatR;
using Shared.DataTransferObjects;

public record CreateCompanyCommand(CompanyForCreationDto Company, bool TrackChanges) 
    : IRequest<CompanyDto>;
```

**ধাপ ২: হ্যান্ডলার (Handler)**

**ফাইল:** `Application/Handlers/CreateCompanyHandler.cs`
```csharp
public class CreateCompanyHandler : IRequestHandler<CreateCompanyCommand, CompanyDto>
{
    private readonly IRepositoryManager _repository;
    private readonly IMapper _mapper;

    public CreateCompanyHandler(IRepositoryManager repository, IMapper mapper)
    {
        _repository = repository;
        _mapper = mapper;
    }

    public async Task<CompanyDto> Handle(CreateCompanyCommand request, CancellationToken cancellationToken)
    {
        var companyEntity = _mapper.Map<Company>(request.Company);
        
        _repository.Company.CreateCompany(companyEntity);
        await _repository.SaveAsync(); // SaveChangesAsync() ব্যবহার করতে হবে
        
        var companyToReturn = _mapper.Map<CompanyDto>(companyEntity);
        return companyToReturn;
    }
}
```

### ৪. কন্ট্রোলার আপডেট (Controller Update)

এখন কন্ট্রোলারে আর `IServiceManager` লাগবে না, বরং `ISender` (MediatR এর ইন্টারফেস) লাগবে।

**ফাইল:** `Presentation/Controllers/CompaniesController.cs`
```csharp
using MediatR; // namespace

[Route("api/companies")]
[ApiController]
public class CompaniesController : ControllerBase
{
    private readonly ISender _sender; // MediatR Sender

    public CompaniesController(ISender sender) => _sender = sender;

    [HttpGet]
    public async Task<IActionResult> GetCompanies()
    {
        // কুয়েরি তৈরি করে সেন্ড করা
        var companies = await _sender.Send(new GetCompaniesQuery(TrackChanges: false));
        return Ok(companies);
    }

    [HttpPost]
    public async Task<IActionResult> CreateCompany([FromBody] CompanyForCreationDto company)
    {
        if (company is null) return BadRequest("Object is null");

        // কমান্ড তৈরি করে সেন্ড করা
        var createdCompany = await _sender.Send(new CreateCompanyCommand(company, TrackChanges: false));

        return CreatedAtRoute("CompanyById", new { id = createdCompany.Id }, createdCompany);
    }
}
```

### ৫. নোটিফিকেশন (Notifications - Optional)

যদি আমরা চাই কোম্পানি তৈরি হলে ইমেইল যাবে এবং লগ হবে (একই সাথে দুটি কাজ), তখন নোটিফিকেশন ব্যবহার করি।

**ধাপ ১: নোটিফিকেশন ক্লাস**
```csharp
public record CompanyCreatedNotification(CompanyDto Company) : INotification;
```

**ধাপ ২: ইমেইল হ্যান্ডলার**
```csharp
public class EmailHandler : INotificationHandler<CompanyCreatedNotification>
{
    public Task Handle(CompanyCreatedNotification notification, CancellationToken cancellationToken)
    {
        // Fake Email Logic
        Console.WriteLine($"Email sent for company: {notification.Company.Name}");
        return Task.CompletedTask;
    }
}
```

**ধাপ ৩: লগ হ্যান্ডলার**
```csharp
public class LogHandler : INotificationHandler<CompanyCreatedNotification>
{
    public Task Handle(CompanyCreatedNotification notification, CancellationToken cancellationToken)
    {
        Console.WriteLine($"Log: Company created with Id: {notification.Company.Id}");
        return Task.CompletedTask;
    }
}
```

**ব্যবহার:** `CreateCompanyHandler` এর শেষে `await _publisher.Publish(new CompanyCreatedNotification(...))` কল করতে হয়।
