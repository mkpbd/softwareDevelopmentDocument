
**Chapter 18**-এর নাম হলো **"Working with GraphQL"** (বইয়ের কিছু সংস্করণে এটি থাকতে পারে, আবার কিছু সংস্করণে এটি আলাদা বই হিসেবেও থাকতে পারে। তবে যদি এটি এই বইয়ের অংশ হয়, তবে এখানে মূল আলোচনা করা হয়েছে REST API এর বিকল্প হিসেবে GraphQL ব্যবহার নিয়ে)।

**বিঃদ্রঃ:** মূল "Ultimate ASP.NET Core Web API" বইটিতে সাধারণত GraphQL নিয়ে আলাদা চ্যাপ্টার থাকে না, বরং বইটি REST API এর ওপর ফোকাসড। তবে লেখক Marinko Spasojevic-এর আলাদা একটি বই/সিরিজ আছে GraphQL নিয়ে। যদি আপনার বইয়ের ভার্সনে চ্যাপ্টার ১৮ তে অন্য কোনো টপিক থাকে (যেমন Unit Testing বা Deployment এর পরবর্তী অংশ), দয়া করে জানাবেন।

তবে ধরে নিচ্ছি আপনি **GraphQL** সম্পর্কে জানতে চাইছেন যা অনেক সময় অ্যাডভান্সড API টপিক হিসেবে শেষে থাকে।

---

### ১. গ্রাফকিউএল কী? (What is GraphQL?)

**কি কাজ করে:**
এটি এপিআই-এর জন্য একটি কুয়েরি ল্যাঙ্গুয়েজ।
REST API-তে আমরা সার্ভারকে বলি "কোন ইউআরএল" (`/api/users`), আর GraphQL-এ আমরা বলি "কী ডাটা দরকার" (`{ user { name } }`)।

**কেন দরকার (Why):**
REST API-এর দুটি বড় সমস্যা আছে:
১. **Over-fetching:** দরকারের চেয়ে বেশি ডাটা দেয়। (নাম চাইলাম, পুরো ডিটেইলস দিয়ে দিল)।
২. **Under-fetching:** দরকারের চেয়ে কম ডাটা দেয়। (ইউজার আর তার কোম্পানির নাম দরকার। একবার ইউজারের জন্য কল করতে হয়, আবার কোম্পানির জন্য কল করতে হয়)।

GraphQL এই দুটি সমস্যারই সমাধান করে। এক রিকোয়েস্টে ঠিক যতটুকু দরকার ততটুকুই দেয়।

---

### ২. স্কিমা এবং টাইপস (Schema & Types)

**কি কাজ করে:**
GraphQL এ সব কিছু টাইপ দিয়ে ডিফাইন করা থাকে। এটি স্ট্রংলি টাইপড (Strongly Typed)।
সার্ভারে বলে দেওয়া থাকে `Company` মানে কী, `Employee` মানে কী।

**উদাহরণ:**
```graphql
type Company {
  id: ID
  name: String
  employees: [Employee]
}
```

---

### ৩. কুয়েরি (Query)

**কি কাজ করে:**
এটি REST এর `GET` রিকোয়েস্টের মতো। ডাটা পড়ার জন্য ব্যবহৃত হয়।
কিন্তু এখানে ক্লায়েন্ট নিজেই সিলেক্ট করে কোন ফিল্ডগুলো তার লাগবে।

**উদাহরণ:**
```graphql
query {
  companies {
    name
    address
    employees {
      name
    }
  }
}
```
*এই কুয়েরিটি কোম্পানি, তার ঠিকানা এবং সেই কোম্পানির এমপ্লয়িদের নাম একসাথে নিয়ে আসবে।*

---

### ৪. মিউটেশন (Mutation)

**কি কাজ করে:**
এটি REST এর `POST`, `PUT`, `DELETE` এর মতো। ডাটা পরিবর্তন করার জন্য ব্যবহৃত হয়।

**উদাহরণ:**
```graphql
mutation {
  createCompany(company: { name: "Google", address: "USA" }) {
    id
    name
  }
}
```

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **GraphQL** | ক্লায়েন্ট-ড্রিভেন এপিআই। | নেটওয়ার্ক রিকোয়েস্ট কমানো এবং মোবাইল অ্যাপের পারফরম্যান্স বাড়ানোর জন্য। |
| **Query** | ডাটা চাওয়া। | এক রিকোয়েস্টে নেস্টেড ডাটা (Parent + Child) আনার জন্য। |
| **Mutation** | ডাটা তৈরি বা আপডেট করা। | ডাটাবেস পরিবর্তনের জন্য। |

**সহজ উদাহরণ:**
*   **REST API:** আপনি দোকানে গিয়ে বললেন "আমাকে বার্গার দাও"। দোকানদার বার্গারের সাথে জোর করে চিপস আর ড্রিংকস ধরিয়ে দিল (Over-fetching)।
*   **GraphQL:** আপনি দোকানে গিয়ে বললেন "আমাকে শুধু বার্গারের রুটি আর মাংস দাও, চিজ দিও না"। দোকানদার ঠিক সেটুকুই দিল।

### ১. ইউনিট টেস্টিং কী? (What is Unit Testing?)

**কি কাজ করে:**
আমরা সাধারণত এপিআই বানানোর পর পোস্টম্যান (Postman) দিয়ে ম্যানুয়ালি চেক করি ডাটা আসছে কি না। ইউনিট টেস্টিং-এ আমরা কোড লিখি যা আমাদের এপিআই-এর ছোট ছোট অংশ (Unit) অটোমেটিক চেক করে।

**কেন দরকার (Why):**
১. **Reliability:** ভবিষ্যতে কোডে কোনো পরিবর্তন করলে আগের ফিচার ভেঙে গেল কি না, তা এক সেকেন্ডেই বোঝা যায়।
২. **Speed:** ম্যানুয়ালি ১০০টা এপিআই টেস্ট করতে ১ ঘণ্টা লাগে, ইউনিট টেস্টে সেটা ১০ সেকেন্ডে হয়।

**টুলস (Tools):**
*   **xUnit:** টেস্ট রান করার ফ্রেমওয়ার্ক।
*   **Moq:** নকল (Mock) অবজেক্ট বানানোর লাইব্রেরি। (যেমন: টেস্ট করার সময় আসল ডাটাবেস কল না করে নকল রিপোজিটরি ব্যবহার করা)।

### ৩. কোড এবং উদাহরণ (Testing Logic)

আমরা `CompaniesController` এর `GetCompanies` মেথডটি টেস্ট করব।

**দৃশ্যপট (Scenario):**
আমরা চেক করব:
১. কন্ট্রোলার সফলভাবে `200 OK` রিটার্ন করছে কি না।
২. রিটার্ন করা ডাটা আসলেই `List<CompanyDto>` কি না।

**ফাইল:** `CompanyEmployees.Tests/CompaniesControllerTests.cs`

```csharp
using Microsoft.AspNetCore.Mvc;
using Moq; // Mocking এর জন্য
using Presentation.Controllers; // আমাদের কন্ট্রোলার
using Service.Contracts; // IServiceManager
using Shared.DataTransferObjects; // DTOs
using Xunit; // টেস্টিং ফ্রেমওয়ার্ক

namespace CompanyEmployees.Tests
{
    public class CompaniesControllerTests
    {
        // ১. মক অবজেক্ট ডিক্লেয়ার করা
        private readonly Mock<IServiceManager> _service;
        private readonly CompaniesController _controller;

        public CompaniesControllerTests()
        {
            // ২. সার্ভিসের একটি নকল (Mock) তৈরি করা
            _service = new Mock<IServiceManager>();

            // ৩. কন্ট্রোলারের কনস্ট্রাক্টরে সেই নকল সার্ভিস ইনজেক্ট করা
            _controller = new CompaniesController(_service.Object);
        }

        [Fact] // এটি একটি টেস্ট মেথড
        public void GetCompanies_ReturnsOkResult_WithListOfCompanies()
        {
            // --- Arrange (প্রস্তুতি) ---
            
            // আমরা বলে দিচ্ছি: যখন Service.Company.GetAllCompanies কল হবে, 
            // তখন যেন একটি ডামি লিস্ট রিটার্ন করে (আসল ডাটাবেসে যাবে না)।
            var companiesList = new List<CompanyDto>
            {
                new CompanyDto(Guid.NewGuid(), "Test Company 1", "Address 1"),
                new CompanyDto(Guid.NewGuid(), "Test Company 2", "Address 2")
            };

            _service.Setup(s => s.CompanyService.GetAllCompanies(false))
                    .Returns(companiesList);

            // --- Act (কাজ) ---
            
            // কন্ট্রোলারের মেথড কল করা
            var result = _controller.GetCompanies();

            // --- Assert (ফলাফল যাচাই) ---

            // ১. রেজাল্ট কি OkObjectResult টাইপের? (মানে 200 OK)
            var okResult = Assert.IsType<OkObjectResult>(result);

            // ২. রিটার্ন করা ডাটা কি লিস্ট অব কোম্পানি?
            var returnCompanies = Assert.IsType<List<CompanyDto>>(okResult.Value);

            // ৩. লিস্টে কি ঠিক ২টি কোম্পানি আছে?
            Assert.Equal(2, returnCompanies.Count);
        }
    }
}
```
