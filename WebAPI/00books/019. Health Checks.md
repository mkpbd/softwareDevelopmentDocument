**Chapter 19**-এর নাম সাধারণত **"Health Checks"** (হেলথ চেকস) হয়ে থাকে। (যদি আপনার বইয়ে এটি অন্য টপিক হয়, তবে সেটি কোনো অ্যাডভান্সড কনসেপ্ট যেমন Docker বা Microservices হতে পারে, তবে স্ট্যান্ডার্ড .NET Web API বইয়ের ফ্লো অনুযায়ী হেলথ চেক অত্যন্ত গুরুত্বপূর্ণ)।

আমরা একটি এপিআই বানিয়েছি, ডাটাবেস কানেক্ট করেছি, ডিপ্লয় করেছি। কিন্তু সার্ভার চালু থাকার মানেই এই না যে অ্যাপ সুস্থ আছে। ডাটাবেস ডাউন থাকতে পারে, র‍্যাম ফুল হয়ে যেতে পারে। অ্যাপের "স্বাস্থ্য" বা অবস্থা চেক করার জন্যই **Health Checks** ব্যবহার করা হয়।

---

### ১. হেলথ চেক কী? (What is Health Check?)

**কি কাজ করে:**
এটি একটি স্পেশাল এপিআই এন্ডপয়েন্ট (সাধারণত `/health`)।
যখনই কেউ এই লিংকে হিট করে, অ্যাপ তার নিজের ভেতরের সব পার্টস (Database, Cache, External API) চেক করে এবং বলে:
*   **Healthy:** "আমি সুস্থ আছি, সব ঠিক আছে।" (Status 200)
*   **Unhealthy:** "আমি অসুস্থ, ডাটাবেস কানেক্ট হচ্ছে না।" (Status 503)

**কেন দরকার (Why):**
১. **মনিটরিং:** সিস্টেম অ্যাডমিনরা ড্যাশবোর্ডে দেখতে পায় কোন সার্ভিস ডাউন।
২. **লোড ব্যালেন্সার:** যদি আপনার ৩টা সার্ভার থাকে এবং ১টা অসুস্থ (Unhealthy) হয়, লোড ব্যালেন্সার অটোমেটিক সেই সার্ভারে ট্রাফিক পাঠানো বন্ধ করে দেয়।
৩. **অটো-হিলিং:** কুবারনেটিস (Kubernetes) বা ক্লাউড এনভায়রনমেন্টে কোনো পড (Pod) আনহেলদি হলে সেটাকে রিস্টার্ট করে ঠিক করার জন্য হেলথ চেক লাগে।

---

### ২. বেসিক হেলথ চেক

.NET Core এ এটি বিল্ট-ইন থাকে।

**উদাহরণ:**
`program.cs` এ শুধু `builder.Services.AddHealthChecks();` এবং `app.MapHealthChecks("/health");` লিখলেই হয়।
ব্রাউজারে `/health` এ গেলে দেখাবে: `Healthy`.

### ৩. ডাটাবেস হেলথ চেক (Database Health Check)

অ্যাপ চালু থাকলেও যদি SQL Server ডাউন থাকে, তবে অ্যাপটি অকেজো। তাই আমরা হেলথ চেকের সাথে ডাটাবেস চেকিং যুক্ত করি।

**কি কাজ করে:**
যখন `/health` কল করা হয়, তখন অ্যাপটি ব্যাকগ্রাউন্ডে ডাটাবেসে একটি ছোট কুয়েরি (যেমন: `SELECT 1`) চালায়।
*   কুয়েরি সফল হলে -> Healthy.
*   কুয়েরি ফেইল করলে -> Unhealthy.

**সুবিধা:**
ইউজার এরর খাওয়ার আগেই আমরা বুঝতে পারি ডাটাবেস ডাউন।

### ৪. কাস্টম হেলথ চেক (Custom Health Check)

মাঝে মাঝে আমাদের নিজেদের লজিক দিয়ে চেক করতে হয়।
যেমন: "যদি রেসপন্স টাইম ৫০০ms এর বেশি হয়, তবে Degraded (অসুস্থতার পথে) দেখাও।"

**লজিক:**
আমরা `IHealthCheck` ইন্টারফেস ইমপ্লিমেন্ট করে একটি ক্লাস বানাই। সেখানে আমাদের লজিক লিখি।

### ৫. হেলথ চেক ইউআই (Health Check UI)

শুধু টেক্সট (`Healthy`) দেখার চেয়ে একটি সুন্দর গ্রাফিক্যাল ড্যাশবোর্ড দেখা অনেক ভালো।
`AspNetCore.HealthChecks.UI` লাইব্রেরি ব্যবহার করে আমরা একটি চমৎকার ড্যাশবোর্ড পাই যেখানে সব সার্ভিসের স্ট্যাটাস সবুজ/লাল বাতি দিয়ে দেখানো হয়।

### ২. সার্ভিস কনফিগারেশন (Service Configuration)

আমরা `ServiceExtensions.cs` ফাইলে হেলথ চেক কনফিগার করব।

**ফাইল:** `Extensions/ServiceExtensions.cs`
```csharp
public static void ConfigureHealthChecks(this IServiceCollection services, IConfiguration configuration)
{
    // ১. বেসিক হেলথ চেক অ্যাড করা
    services.AddHealthChecks()
        // ২. SQL Server চেক অ্যাড করা
        .AddSqlServer(
            connectionString: configuration.GetConnectionString("sqlConnection"),
            healthQuery: "SELECT 1;", // ডাটাবেস চেক করার কুয়েরি
            name: "SQL Server",
            failureStatus: Microsoft.Extensions.Diagnostics.HealthChecks.HealthStatus.Unhealthy,
            tags: new[] { "db", "sql", "sqlserver" }
        );
    
    // ৩. হেলথ চেক ইউআই কনফিগার করা
    services.AddHealthChecksUI(opt =>
    {
        opt.SetEvaluationTimeInSeconds(10); // প্রতি ১০ সেকেন্ডে চেক করবে
        opt.MaximumHistoryEntriesPerEndpoint(60);
        opt.SetApiMaxActiveRequests(1);
        
        // আমাদের নিজস্ব এপিআই এর হেলথ এন্ডপয়েন্ট বলে দেওয়া
        // (লোকালহোস্টে পোর্ট নম্বর আপনার launchSettings.json অনুযায়ী দিন)
        opt.AddHealthCheckEndpoint("API Health", "/api/health"); 
    })
    .AddInMemoryStorage(); // ডাটা টেম্পোরারি মেমোরিতে রাখবে
}
```

### ৩. প্রোগ্রাম ফাইলে যুক্ত করা (Program.cs)

`Program.cs` ফাইলে মিডলওয়্যার এবং রাউটিং ঠিক করতে হবে।

**ফাইল:** `Program.cs`
```csharp
using HealthChecks.UI.Client;
using Microsoft.AspNetCore.Diagnostics.HealthChecks;

// ১. সার্ভিস কল করা
builder.Services.ConfigureHealthChecks(builder.Configuration);

var app = builder.Build();

// ... অন্যান্য মিডলওয়্যার ...

// ২. হেলথ চেক এন্ডপয়েন্ট ম্যাপ করা (JSON রেসপন্স)
app.MapHealthChecks("/api/health", new HealthCheckOptions
{
    // UI যাতে পড়তে পারে এমন ফরম্যাটে রেসপন্স দিবে
    ResponseWriter = UIResponseWriter.WriteHealthCheckUIResponse 
});

// ৩. হেলথ চেক ইউআই ম্যাপ করা (HTML ড্যাশবোর্ড)
app.MapHealthChecksUI(options =>
{
    options.UIPath = "/health-ui"; // ড্যাশবোর্ডের ইউআরএল
});

app.Run();
```

            }

    *দেখুন, এখানে বলে দিচ্ছে SQL Server ও "Healthy"।*

**Scenario 2: UI Dashboard**
*   **URL:** `https://localhost:5001/health-ui`
*   **Result:** একটি সুন্দর গ্রিন ড্যাশবোর্ড দেখতে পাবেন।

    *   কখন শেষ চেক হয়েছে তা দেখাবে।

**Scenario 3: Simulating Failure**
*   SQL Server সার্ভিসটি বন্ধ করে দিন অথবা কানেকশন স্ট্রিং ভুল করে দিন।
*   ড্যাশবোর্ডে বাতি **লাল (Unhealthy)** হয়ে যাবে এবং ডিটেইলসে ক্লিক করলে দেখা যাবে "SQL Server Connection Failed"।

এভাবেই **Health Checks** ব্যবহার করে আপনি আপনার অ্যাপ্লিকেশনের পালস বা হার্টবিট সবসময় মনিটর করতে পারবেন।
