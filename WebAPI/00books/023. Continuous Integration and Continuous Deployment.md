**Chapter 23**-এর নাম সাধারণত **"Continuous Integration and Continuous Deployment (CI/CD)"** হয়ে থাকে।

আমরা Chapter 22-এ অ্যাপ ডকারাইজ করেছি। কিন্তু প্রতিবার কোড চেঞ্জ করার পর ম্যানুয়ালি বিল্ড করা, টেস্ট করা এবং সার্ভারে আপলোড করা অনেক সময়সাপেক্ষ এবং বিরক্তিকর।

এই সমস্যা সমাধানের জন্যই **CI/CD** দরকার। এটি এমন একটি অটোমেটেড সিস্টেম যা আপনার কোড গিটহাবে (GitHub) পুশ করার সাথে সাথে অটোমেটিক টেস্ট করবে, বিল্ড করবে এবং সার্ভারে ডিপ্লয় করে দেবে।

বইটিতে সাধারণত **GitHub Actions** ব্যবহার করে এটি দেখানো হয়।

---

### ১. সিআই/সিডি কী? (What is CI/CD?)

**CI (Continuous Integration):**
কোড পুশ করার পর সেটি অটোমেটিক বিল্ড এবং টেস্ট করার প্রক্রিয়া।
*   **কাজ:** চেক করা যে নতুন কোড আগের কোডকে ভেঙে দিল কি না।

**CD (Continuous Deployment/Delivery):**
CI পাস করার পর অ্যাপটি অটোমেটিক সার্ভারে (Azure, AWS, Docker Hub) পাঠিয়ে দেওয়া।
*   **কাজ:** নতুন ফিচার সাথে সাথে ইউজারদের কাছে পৌঁছে দেওয়া।

---

### ২. গিটহাব অ্যাকশনস (GitHub Actions)

**কি কাজ করে:**
এটি গিটহাবের একটি ফিচার যা আপনার রিপোজিটরিতে কোনো ইভেন্ট (যেমন: Push, Pull Request) ঘটলে অটোমেটিক কিছু কাজ (Workflow) করে দেয়।

**কেন দরকার (Why):**
আলাদা কোনো সার্ভার (যেমন Jenkins) সেটআপ করতে হয় না। গিটহাবের ভেতরেই সব কনফিগার করা যায় `YAML` ফাইল দিয়ে।

---

### ৩. ওয়ার্কফ্লো ফাইল (Workflow File)

এটি একটি `.yml` বা `.yaml` ফাইল যা `.github/workflows` ফোল্ডারে থাকে।

**এর প্রধান অংশগুলো:**
১. **Triggers (on):** কখন রান হবে? (যেমন: `push` to `master` branch)।
২. **Jobs:** কী কাজ করবে? (যেমন: `build`, `test`, `deploy`)।
৩. **Steps:** প্রতিটা জবের ভেতরের ছোট ছোট ধাপ। (যেমন: কোড চেকআউট করা, ডটনেট ইন্সটল করা, টেস্ট রান করা)।

---

### ৪. উদাহরণ (CI Pipeline)

ধরুন আমরা চাই যখনই কেউ `master` ব্রাঞ্চে পুশ করবে, গিটহাব চেক করবে কোড কম্পাইল হয় কি না এবং সব ইউনিট টেস্ট পাস করে কি না।

**ফাইল:** `.github/workflows/ci.yml`

```yaml
name: .NET Core CI

on:
  push:
    branches: [ master ]

jobs:
  build:
    runs-on: ubuntu-latest # লিনাক্স পিসিতে রান হবে

    steps:
    - uses: actions/checkout@v2 # ১. কোড ডাউনলোড

    - name: Setup .NET
      uses: actions/setup-dotnet@v1 # ২. ডটনেট ইন্সটল
      with:
        dotnet-version: 8.0.x

    - name: Restore dependencies
      run: dotnet restore # ৩. প্যাকেজ রিস্টোর

    - name: Build
      run: dotnet build --no-restore # ৪. বিল্ড

    - name: Test
      run: dotnet test --no-build --verbosity normal # ৫. টেস্ট রান
```

### ৫. সিডি পাইপলাইন (CD Pipeline - Docker Hub)

টেস্ট পাস করলে আমরা ডকার ইমেজ বিল্ড করে **Docker Hub**-এ পাঠিয়ে দেব।

**কোড অংশ:**
```yaml
    - name: Login to Docker Hub
      uses: docker/login-action@v1
      with:
        username: ${{ secrets.DOCKER_HUB_USERNAME }} # সিক্রেট ভেরিয়েবল
        password: ${{ secrets.DOCKER_HUB_ACCESS_TOKEN }}

    - name: Build and push
      uses: docker/build-push-action@v2
      with:
        context: .
        push: true
        tags: user/companyemployees:latest
```

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **CI** | কোড ইন্টিগ্রেশন এবং টেস্টিং। | বাগ-মুক্ত কোড নিশ্চিত করার জন্য। |
| **CD** | অটোমেটিক ডিপ্লয়মেন্ট। | দ্রুত রিলিজ দেওয়ার জন্য। |
| **YAML** | কনফিগারেশন ল্যাঙ্গুয়েজ। | গিটহাব অ্যাকশন লেখার জন্য। |
| **Secrets** | পাসওয়ার্ড লুকানো। | গিটহাবে পাসওয়ার্ড সেফ রাখার জন্য। |

**সহজ উদাহরণ:**
*   **Manual:** আপনি হাতে চিঠি লিখলেন, খামে ভরলেন, পোস্ট অফিসে গিয়ে পোস্ট করলেন।
*   **CI/CD:** আপনি শুধু চিঠিটা টাইপ করে সেন্ড বাটন চাপলেন। বাকি কাজ (প্রিন্ট করা, খামে ভরা, ডেলিভারি দেওয়া) একটি রোবট অটোমেটিক করে দিল।
===========================================================


**Chapter 23**-এ আমরা **GitHub Actions** ব্যবহার করে একটি **CI/CD Pipeline** তৈরি করব। আমাদের লক্ষ্য হলো:
১. গিটহাবে কোড পুশ করার সাথে সাথে সেটি অটোমেটিক বিল্ড এবং টেস্ট হবে (**CI**)।
২. টেস্ট পাস করলে সেটি ডকার ইমেজে কনভার্ট হয়ে **Docker Hub**-এ আপলোড হবে (**CD**)।

নিচে সেটআপ এবং কোড ধাপে ধাপে দেওয়া হলো।

---

### ১. সেটআপ (Setup)

কোড লেখার আগে আমাদের গিটহাব এবং ডকার হাবে কিছু কনফিগারেশন করতে হবে। কারণ আমরা আমাদের পাসওয়ার্ড কোডের মধ্যে হার্ডকোড করে রাখব না (এটা অনিরাপদ)।

**ধাপ ১: Docker Hub একাউন্ট এবং টোকেন**
১. [hub.docker.com](https://hub.docker.com)-এ গিয়ে একাউন্ট খুলুন (যদি না থাকে)।
২. Profile -> Account Settings -> Security -> **New Access Token** এ ক্লিক করুন।
৩. টোকেনের একটা নাম দিন (যেমন `github-action`) এবং টোকেনটি কপি করে রাখুন।

**ধাপ ২: GitHub Secrets সেট করা**
১. আপনার প্রজেক্টের GitHub Repository-তে যান।
২. **Settings** ট্যাবে যান।
৩. বাম পাশে **Secrets and variables** -> **Actions** এ ক্লিক করুন।
৪. **New repository secret** বাটনে ক্লিক করে দুটি সিক্রেট তৈরি করুন:
    *   Name: `DOCKER_USERNAME`, Value: আপনার ডকার হাব ইউজারনেম।
    *   Name: `DOCKER_PASSWORD`, Value: কপি করা এক্সেস টোকেনটি।

### ২. ওয়ার্কফ্লো ফাইল তৈরি (Creating Workflow)

আপনার প্রজেক্টের রুট ফোল্ডারে একটি নির্দিষ্ট ফোল্ডার স্ট্রাকচার তৈরি করতে হবে।

**ফোল্ডার:** `.github/workflows`
**ফাইল:** `.github/workflows/main.yml` (নাম যা খুশি হতে পারে, এক্সটেনশন `.yml` হতে হবে)

এই ফাইলে আমরা গিটহাবকে ইনস্ট্রাকশন দেব।

**কোড (YAML):**

```yaml
name: Build, Test and Deploy to Docker Hub

# ১. ট্রিগার: কখন এই অ্যাকশনটি রান হবে?
on:
  push:
    branches: [ "master" ] # মাস্টার ব্রাঞ্চে পুশ করলে
  pull_request:
    branches: [ "master" ]

jobs:
  build-and-push:
    runs-on: ubuntu-latest # লিনাক্স সার্ভারে রান হবে

    steps:
    # ২. গিটহাব থেকে কোড চেকআউট করা (Download Code)
    - name: Checkout code
      uses: actions/checkout@v3

    # ৩. ডটনেট সেটআপ করা
    - name: Setup .NET
      uses: actions/setup-dotnet@v3
      with:
        dotnet-version: '8.0.x'

    # ৪. ডিপেন্ডেন্সি রিস্টোর করা
    - name: Restore dependencies
      run: dotnet restore

    # ৫. ইউনিট টেস্ট রান করা (টেস্ট ফেইল করলে এখানেই থামবে)
    - name: Run Tests
      run: dotnet test --no-restore --verbosity normal

    # --- সিআই (CI) শেষ, এখন সিডি (CD) শুরু ---

    # ৬. ডকার হাবে লগইন করা (সিক্রেট ব্যবহার করে)
    - name: Login to Docker Hub
      if: github.event_name != 'pull_request' # পুল রিকোয়েস্টে ডিপ্লয় হবে না
      uses: docker/login-action@v2
      with:
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_PASSWORD }}

    # ৭. ডকার মেটাডাটা সেট করা (ট্যাগ জেনারেট করার জন্য)
    - name: Extract metadata (tags, labels) for Docker
      id: meta
      uses: docker/metadata-action@v4
      with:
        images: mydockerusername/companyemployees # আপনার ডকার ইউজারনেম/ইমেজনেম দিন

    # ৮. ইমেজ বিল্ড এবং পুশ করা
    - name: Build and push Docker image
      if: github.event_name != 'pull_request'
      uses: docker/build-push-action@v4
      with:
        context: .
        file: ./Dockerfile
        push: true
        tags: ${{ steps.meta.outputs.tags }}
        labels: ${{ steps.meta.outputs.labels }}
```

### ৩. কোডের ব্যাখ্যা (Explanation)

*   **on: push:** এটি বলে দেয় যে যখনই আপনি `git push` করবেন, তখনই গিটহাবের রোবট জেগে উঠবে।
*   **runs-on: ubuntu-latest:** গিটহাব আপনাকে ফ্রিতে একটি লিনাক্স পিসি দেয় এই কাজটি করার জন্য।
*   **dotnet test:** এটি আপনার Chapter 18 এর ইউনিট টেস্টগুলো চালাবে। যদি কোনো টেস্ট ফেইল করে, তাহলে পাইপলাইন লাল হয়ে যাবে এবং ডকার ইমেজ তৈরি হবে না (খারাপ কোড সার্ভারে যাবে না)।
*   **docker/build-push-action:** এটি আপনার `Dockerfile` (Chapter 22) পড়ে ইমেজ তৈরি করে এবং Docker Hub এ পাঠিয়ে দেয়।

### ৪. উদাহরণ (Testing the Pipeline)

এখন আমরা দেখব এটি আসলে কাজ করে কি না।

**ধাপ ১: কোড পুশ করা**
আপনার লোকাল পিসি থেকে গিট কমান্ড দিন:
```bash
git add .
git commit -m "Added CI/CD pipeline"
git push origin master
```

**ধাপ ২: গিটহাবে চেক করা**
১. আপনার গিটহাব রিপোজিটরিতে যান।
২. **Actions** ট্যাবে ক্লিক করুন।
৩. দেখবেন "Added CI/CD pipeline" নামে একটি ওয়ার্কফ্লো চলছে (হলুদ বাতি)।
৪. কিছুক্ষণ পর এটি সবুজ (✅ Success) হয়ে যাবে।

**ধাপ ৩: ডকার হাবে চেক করা**
১. [hub.docker.com](https://hub.docker.com) এ যান।
২. আপনার রিপোজিটরি চেক করুন। দেখবেন `Just now` বা `Few seconds ago` একটি নতুন ইমেজ ট্যাগ `master` বা `latest` আপলোড হয়েছে।
