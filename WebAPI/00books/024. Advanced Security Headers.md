**Chapter 24** হলো সাধারণত এই বইয়ের শেষ অধ্যায় বা উপসংহারমূলক একটি বোনাস অধ্যায়। এর নাম হতে পারে **"Deploying to Azure"** অথবা **"Advanced Security Headers"**।

যেহেতু আমরা Chapter 23-এ Docker এবং CI/CD দেখেছি, তাই এর লজিক্যাল নেক্সট স্টেপ হলো **Cloud Deployment** (বিশেষ করে Azure, কারণ এটি .NET এর জন্য সেরা)।

আমরা ধরে নিচ্ছি এই চ্যাপ্টারে **Azure Web App for Containers** নিয়ে আলোচনা করা হয়েছে। অর্থাৎ, আমাদের তৈরি করা ডকার ইমেজটি কীভাবে ক্লাউডে রান করানো যায়।

---

### ১. অ্যাজিউর ওয়েব অ্যাপ (Azure Web App)

**কি কাজ করে:**
এটি মাইক্রোসফট অ্যাজিউরের একটি সার্ভিস (PaaS - Platform as a Service)।
আপনাকে সার্ভার সেটআপ, ওএস ইন্সটল বা প্যাচিং নিয়ে ভাবতে হয় না। আপনি শুধু আপনার কোড বা ডকার ইমেজটি একে ধরিয়ে দেবেন, সে রান করে আপনাকে একটি লাইভ ওয়েবসাইট ইউআরএল (`https://myapi.azurewebsites.net`) দেবে।

**কেন দরকার (Why):**
১. **Auto Scaling:** ট্রাফিক বাড়লে সার্ভার অটোমেটিক বড় হয় (Scale Up) বা সংখ্যায় বাড়ে (Scale Out)।
২. **Zero Downtime:** আপডেট করার সময় ওয়েবসাইট বন্ধ হয় না।
৩. **SSL/HTTPS:** ফ্রি সিকিউরিটি সার্টিফিকেট দেয়।

---

### ২. কন্টেইনার ডিপ্লয়মেন্ট (Deploying Container)

**প্রসেস:**
আমরা Chapter 23-এ আমাদের অ্যাপের ইমেজ **Docker Hub**-এ রেখেছি।
এখন আমরা Azure-কে বলব: "তুমি Docker Hub থেকে আমার ইমেজটি নাও এবং রান করো।"

**সুবিধা:**
আমাদের আর ম্যানুয়ালি কোড কপি করতে হবে না। যখনই CI/CD পাইপলাইন নতুন ইমেজ পুশ করবে, Azure অটোমেটিক সেটি পুল (Pull) করে সাইট আপডেট করে দেবে। একে বলে **Continuous Deployment**।

---

### ৩. কনফিগারেশন এবং পরিবেশ ভেরিয়েবল

**সমস্যা:**
লোকাল পিসিতে আমাদের ডাটাবেস কানেকশন স্ট্রিং ছিল `Server=localhost` বা `Server=db`। কিন্তু ক্লাউডে তো আর লোকালহোস্ট নেই। সেখানে আমাদের আসল **Azure SQL Database** ব্যবহার করতে হবে।

**সমাধান:**
Azure পোর্টালে `Configuration` বা `Environment Variables` সেকশনে আমরা আসল কানেকশন স্ট্রিং সেট করে দিই। কোড পরিবর্তন করার দরকার নেই, অ্যাপ রান হওয়ার সময় সেখান থেকে ভ্যালু নিয়ে নেয়।

---

### ৪. মনিটরিং (Azure Monitor & Application Insights)

**কি কাজ করে:**
অ্যাপ লাইভ হওয়ার পর যদি কোনো এরর হয়, আমরা তো আর কনসোল দেখতে পাব না।
**Application Insights** আপনার অ্যাপের সব লগ, এরর, রেসপন্স টাইম এবং ইউজার বিহেভিয়ার রেকর্ড করে।

**সুবিধা:**
১. লাইভ ডিবাগিং করা যায়।
২. মেইল বা এসএমএস অ্যালার্ট পাওয়া যায় যদি অ্যাপ স্লো হয়ে যায়।

এর জন্য কোনো কোড লিখতে হবে না, সব কাজ হবে **Azure Portal**-এ এবং কমান্ড লাইনে (Azure CLI)।

### ১. পূর্বশর্ত (Prerequisites)

১. একটি **Microsoft Azure Account** থাকতে হবে (ফ্রি ট্রায়াল একাউন্ট দিয়েও হবে)।
২. আমাদের ডকার ইমেজটি **Docker Hub**-এ থাকতে হবে (যা আমরা Chapter 23-এ করেছি)।
৩. একটি **Azure SQL Database** তৈরি করতে হবে (অথবা টেস্ট করার জন্য ইন-মেমোরি বা SQLite ব্যবহার করা যেতে পারে, তবে প্রোডাকশনের জন্য SQL Database লাগবে)।

---

### ২. রিসোর্স গ্রুপ তৈরি (Create Resource Group)

সবকিছু গুছিয়ে রাখার জন্য একটি ফোল্ডার বা গ্রুপ লাগে।

**Azure Portal:**
১. সার্চ বারে লিখুন "Resource groups"।
২. **Create** এ ক্লিক করুন।
৩. নাম দিন: `CompanyEmployees-RG`।
৪. রিজিয়ন: আপনার কাছের কোনো রিজিয়ন (যেমন: `South East Asia`)।
৫. **Review + create** -> **Create**.

---

### ৩. ওয়েব অ্যাপ তৈরি (Create Web App)

এখন আমরা আসল সার্ভারটি তৈরি করব।

**Azure Portal:**
১. সার্চ বারে লিখুন "App Services"।
২. **Create** -> **Web App**.
৩. **Subscription:** আপনার সাবস্ক্রিপশন সিলেক্ট করুন।
৪. **Resource Group:** `CompanyEmployees-RG`।
৫. **Name:** একটি ইউনিক নাম দিন (যেমন: `company-api-prod`). এটিই হবে ইউআরএল (`company-api-prod.azurewebsites.net`)।
৬. **Publish:** `Docker Container` সিলেক্ট করুন।
৭. **Operating System:** `Linux`.
৮. **Region:** আগেরটাই দিন।
৯. **Pricing Plan:** ফ্রি টায়ার (`F1`) বা বেসিক (`B1`) সিলেক্ট করুন।
১০. **Next: Docker** বাটনে ক্লিক করুন।

**Docker Tab:**
১. **Options:** `Single Container`.
২. **Image Source:** `Docker Hub`.
৩. **Access Type:** `Public` (যদি আপনার ইমেজ পাবলিক হয়) অথবা `Private` (লগইন লাগলে)।
৪. **Image and tag:** আপনার ইমেজের নাম লিখুন (যেমন: `johndoe/companyemployees:latest`).
৫. **Review + create** -> **Create**.

কিছুক্ষণ সময় নেবে, তারপর আপনার অ্যাপ লাইভ হয়ে যাবে!

---

### ৪. কনফিগারেশন (Environment Variables)

এখন আমাদের ডাটাবেস কানেকশন স্ট্রিং সেট করতে হবে। কারণ কোডে আমরা `db` হোস্টনেম দিয়েছিলাম যা শুধু ডকার কম্পোজে কাজ করে, ক্লাউডে নয়।

**Azure Portal:**
১. আপনার তৈরি করা Web App-এ যান।
২. বাম প্যানেলে **Configuration**-এ ক্লিক করুন।
৩. **Application settings** ট্যাবে **New application setting**-এ ক্লিক করুন।
৪. **Name:** `ConnectionStrings__sqlConnection` (এটি .NET এর কনভেনশন, `:` এর বদলে `__` ব্যবহার হয় লিনাক্সে)।
৫. **Value:** আপনার Azure SQL Database এর কানেকশন স্ট্রিং।
   *(উদাহরণ: `Server=tcp:myserver.database.windows.net,1433;Initial Catalog=CompanyDB;Persist Security Info=False;User ID=myadmin;Password=MyPass123!;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;`)*
৬. **OK** এবং ওপরে **Save** বাটনে ক্লিক করুন।

অ্যাপটি রিস্টার্ট হবে।

### ৫. কন্টিনিউয়াস ডিপ্লয়মেন্ট (CD Setup - Webhook)

আমরা চাই যখনই Docker Hub এ নতুন ইমেজ আসবে, Azure যেন সাথে সাথে আপডেট হয়ে যায়।

**Azure Portal:**
১. Web App এর মেনু থেকে **Deployment Center** এ যান।
২. **Settings** ট্যাবে `Continuous deployment` অপশনটি **On** করে দিন।
৩. **Save** করুন।

এতে Azure একটি **Webhook** ইউআরএল তৈরি করে এবং ব্যাকগ্রাউন্ডে Docker Hub এর সাথে লিংক করে দেয়। এখন GitHub Actions যখনই নতুন ইমেজ পুশ করবে, Azure অটোমেটিক সেটি পুল করে নেবে।

ব্রাউজার ওপেন করুন এবং আপনার অ্যাপের ইউআরএল এ যান:
`https://company-api-prod.azurewebsites.net/api/companies`

যদি সব ঠিক থাকে, তবে আপনি জেসন ডাটা দেখতে পাবেন।

### ৭. ট্রাবলশুটিং (লগ দেখা)

যদি অ্যাপ ক্র্যাশ করে বা এরর দেয় (500 Error), তবে লগ দেখতে হবে।

**Log Stream:**
১. Web App মেনু থেকে **Log stream** এ যান।
২. এখানে আপনি রিয়েল-টাইম কনসোল লগ দেখতে পাবেন।
৩. সাধারণত ডাটাবেস কানেকশন এরর বা মাইগ্রেশন ফেইল করলে এখানে ডিটেইলস দেখা যায়।

এভাবেই আমরা আমাদের লোকাল পিসির কোডকে গিটহাব -> ডকার হাব -> অ্যাজিউর ক্লাউড পর্যন্ত নিয়ে এসে একটি পূর্ণাঙ্গ **DevOps Pipeline** সম্পন্ন করলাম। অভিনন্দন! 🚀
