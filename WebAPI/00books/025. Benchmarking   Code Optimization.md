

আমরা এত কষ্ট করে এপিআই বানালাম, কিন্তু সেটা কি ফাস্ট? নাকি স্লো? এটা বুঝব কীভাবে? "আমার মনে হচ্ছে এটা স্লো"—এই কথার কোনো দাম নেই। আমাদের প্রমাণ বা সংখ্যা দরকার।

এই চ্যাপ্টারে আমরা **BenchmarkDotNet** লাইব্রেরি ব্যবহার করে কোডের পারফরম্যান্স মাপা শিখব।

---

### ১. বেঞ্চমার্কিং কী? (What is Benchmarking?)

**কি কাজ করে:**
বেঞ্চমার্কিং হলো কোডের গতি (Speed) এবং মেমোরি (RAM) ব্যবহারের পরিমাণ মাপা। এটি সায়েন্টিফিক উপায়ে বলে দেয় একটি মেথড রান করতে কত ন্যানোসেকেন্ড সময় লেগেছে।

**কেন দরকার (Why):**
ধরি, আপনি স্ট্রিং যোগ করার জন্য `+` অপারেটর ব্যবহার করছেন। আপনার সিনিয়য় বলল `StringBuilder` ব্যবহার করতে। আপনি তর্ক না করে বেঞ্চমার্ক রান করে দেখিয়ে দিতে পারেন আসলেই কোনটা ফাস্ট এবং কতটুকু ফাস্ট।

---

### ২. BenchmarkDotNet

**কি কাজ করে:**
এটি .NET দুনিয়ার সবচেয়ে জনপ্রিয় এবং শক্তিশালী বেঞ্চমার্কিং টুল। মাইক্রোসফট নিজেও তাদের .NET রানটাইম টেস্ট করার জন্য এটি ব্যবহার করে।

**সুবিধা:**
১. **Warm-up:** কোড রান করার আগে এটি প্রসেসরকে "গরম" (Warm-up) করে নেয় যাতে সঠিক রেজাল্ট পাওয়া যায়।
২. **Memory Diagnoser:** এটি বলে দেয় কোডটি রান করতে কত বাইট মেমোরি খরচ হয়েছে এবং গারবেজ কালেকশন (GC) কতবার হয়েছে।
৩. **Report:** শেষে এটি একটি সুন্দর টেবিল বা এক্সেল শিট জেনারেট করে।

---

### ৩. সাধারণ কোড বনাম অপটিমাইজড কোড

**উদাহরণ:**
আমরা দুটি মেথড তুলনা করব:
১. **String Concatenation:** লুপের ভেতর স্ট্রিং যোগ করা (`str = str + "a"`).
২. **StringBuilder:** লুপের ভেতর `sb.Append("a")` ব্যবহার করা।

সাধারণত ছোট ডাটার জন্য পার্থক্য বোঝা যায় না, কিন্তু লুপ যদি ১০০০ বার চলে, তখন `StringBuilder` হাজার গুণ ফাস্ট হতে পারে। বেঞ্চমার্কিং আমাদের সেই পার্থক্যটাই চোখে আঙুল দিয়ে দেখিয়ে দেয়।

---

### ৪. গারবেজ কালেকশন (Garbage Collection - Gen 0, 1, 2)

**কি কাজ করে:**
.NET এ মেমোরি অটোমেটিক ম্যানেজ হয়। যখন কোনো অবজেক্ট আর দরকার হয় না, তখন গারবেজ কালেক্টর (GC) এসে সেটা মুছে মেমোরি খালি করে।
কিন্তু GC যখন চলে, তখন অ্যাপ কিছুক্ষণের জন্য থমকে যায় (Freeze)।

**কেন দরকার:**
বেঞ্চমার্কিং টুল আমাদের দেখায় কোন কোডে কত বেশি "ময়লা" (Unused Objects) তৈরি হচ্ছে। কোড যত কম ময়লা করবে, অ্যাপ তত ফাস্ট চলবে।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Benchmarking** | কোডের স্পিড টেস্ট করা। | স্লো কোড খুঁজে বের করে ফিক্স করার জন্য। |
| **BenchmarkDotNet** | অটোমেটেড টেস্টিং টুল। | নির্ভুল রেজাল্ট (ন্যানোসেকেন্ড) পাওয়ার জন্য। |
| **Memory Diagnoser** | র‍্যাম ব্যবহারের হিসাব। | মেমোরি লিক (Leak) এবং ওয়েস্ট কমানোর জন্য। |

**সহজ উদাহরণ:**
*   **Normal:** আপনি দৌড়ালেন এবং বললেন "আমি খুব জোরে দৌড়েছি"।
*   **Benchmarking:** আপনি স্টপওয়াচ (Stopwatch) হাতে নিয়ে দৌড়ালেন এবং বললেন "আমি ৯.৫৮ সেকেন্ডে ১০০ মিটার দৌড়েছি"।

#### ২. টেস্ট ক্লাস তৈরি (Test Logic)

আমরা `StringBuilder` বনাম `String Concat` এর যুদ্ধ দেখব।

**ফাইল:** `StringBenchmark.cs`

```csharp
using BenchmarkDotNet.Attributes; // বেঞ্চমার্ক অ্যাট্রিবিউট
using System.Text;

// MemoryDiagnoser মেমোরি ব্যবহারের রিপোর্ট দেবে
[MemoryDiagnoser]
public class StringBenchmark
{
    private const int Iterations = 1000; // ১০০০ বার লুপ চলবে

    // সাধারণ স্ট্রিং যোগ (Bad Practice for loop)
    [Benchmark]
    public string StringConcat()
    {
        string result = "";
        for (int i = 0; i < Iterations; i++)
        {
            result += i.ToString(); 
        }
        return result;
    }

    // স্ট্রিং বিল্ডার (Good Practice)
    [Benchmark]
    public string StringBuilder()
    {
        var sb = new StringBuilder();
        for (int i = 0; i < Iterations; i++)
        {
            sb.Append(i);
        }
        return sb.ToString();
    }
}
```

#### ৩. রান করা (Program.cs)

বেঞ্চমার্ক রান করার জন্য `Program.cs` ফাইলে রানার কল করতে হয়।

**ফাইল:** `Program.cs`
```csharp
using BenchmarkDotNet.Running;
using CompanyEmployees.Performance;

// বেঞ্চমার্ক রানার চালানো

```

#### ৪. এক্সিকিউশন (Execution)

**খুব গুরুত্বপূর্ণ:** বেঞ্চমার্কিং সবসময় **Release** মোডে চালাতে হয় (Debug মোডে নয়), কারণ ডিবাগ মোডে কোড স্লো থাকে।

১. Visual Studio-র টুলবার থেকে `Debug` এর বদলে `Release` সিলেক্ট করুন।
২. `Ctrl + F5` দিয়ে কনসোল অ্যাপটি রান করুন।

#### ৫. ফলাফল (The Result)

কনসোলে কিছুক্ষণ অনেক কিছু লেখা আসবে (Warmup, Running...)। শেষে একটি টেবিল আসবে। দেখতে অনেকটা এরকম হবে:

| Method | Mean (Time) | Allocated (Memory) |
| :--- | :--- | :--- |
| **StringConcat** | 250.5 us | 4,500 KB |
| **StringBuilder** | **3.2 us** | **12 KB** |

**ব্যাখ্যা:**
*   **Mean:** `StringConcat` নিয়েছে ২৫০ মাইক্রোসেকেন্ড, আর `StringBuilder` নিয়েছে মাত্র ৩.২ মাইক্রোসেকেন্ড! (প্রায় ৮০ গুণ ফাস্ট)।
*   **Allocated:** `StringConcat` ৪.৫ মেগাবাইট মেমোরি খেয়েছে, আর `StringBuilder` মাত্র ১২ কিলোবাইট!

এভাবেই বেঞ্চমার্কিং আপনাকে একজন **সিনিয়র ডেভেলপার** হিসেবে গড়ে তোলে, কারণ আপনি তখন শুধু কোড লেখেন না, আপনি "এফিশিয়েন্ট" কোড লেখেন।

### ২. বেঞ্চমার্ক ক্লাস তৈরি (Writing Benchmark Code)

আমরা একটি ক্লাস বানাব যেখানে আমরা দুটি মেথডকে কম্পেয়ার করব। একটিতে আমরা সাধারণ `+` অপারেটর দিয়ে স্ট্রিং যোগ করব, আরেকটিতে `StringBuilder` ব্যবহার করব।

**ফাইল:** `StringOperationBenchmark.cs`

```csharp
using BenchmarkDotNet.Attributes; // বেঞ্চমার্কিং অ্যাট্রিবিউট
using System.Text;

namespace PerformanceTester
{
    // [MemoryDiagnoser] অ্যাট্রিবিউট দিলে মেমোরি (RAM) ব্যবহারের রিপোর্টও দেখাবে
    [MemoryDiagnoser]
    [RankColumn] // র‍্যাঙ্কিং কলাম দেখাবে (১ম, ২য়...)
    public class StringOperationBenchmark
    {
        // কতবার লুপ চলবে
        [Params(100, 1000)] 
        public int N; 

        // ১. সাধারণ স্ট্রিং কনক্যাটেনেশন (সাধারণত স্লো)
        [Benchmark]
        public string UsingStringConcat()
        {
            string result = "";
            for (int i = 0; i < N; i++)
            {
                result += i.ToString(); 
            }
            return result;
        }

        // ২. স্ট্রিং বিল্ডার ব্যবহার (সাধারণত ফাস্ট)
        [Benchmark]
        public string UsingStringBuilder()
        {
            var sb = new StringBuilder();
            for (int i = 0; i < N; i++)
            {
                sb.Append(i);
            }
            return sb.ToString();
        }
    }
}
```

### ৩. প্রোগ্রাম ফাইলে রানার কল করা (Running the Benchmark)

`Program.cs` ফাইলে আমাদের বেঞ্চমার্ক রানারটি চালাতে হবে।

**ফাইল:** `Program.cs`

```csharp
using BenchmarkDotNet.Running;
using PerformanceTester;

Console.WriteLine("Starting Benchmark...");

// আমাদের তৈরি করা ক্লাসটি রান করছি
var summary = BenchmarkRunner.Run<StringOperationBenchmark>();

Console.WriteLine("Benchmark Finished.");
```

### ৪. রান করার নিয়ম (Important Rule)

BenchmarkDotNet সঠিক রেজাল্ট দেওয়ার জন্য অপটিমাইজড কোড চায়। তাই এটি **Debug** মোডে কাজ করে না। আপনাকে অবশ্যই **Release** মোডে রান করতে হবে।

**ধাপ ১: কনফিগারেশন পরিবর্তন**
Visual Studio-র ওপরের টুলবার থেকে `Debug` ড্রপডাউনটি পরিবর্তন করে `Release` করে দিন।

**ধাপ ২: রান করা**
`Ctrl + F5` চাপুন (অথবা `Start without Debugging`)।

### ৫. ফলাফল (The Result)

কনসোল উইন্ডোতে অনেকক্ষণ ধরে টেস্ট চলবে (১-২ মিনিট লাগতে পারে)। শেষে একটি সুন্দর টেবিল আসবে।

**Sample Output:**

```text
|             Method |    N |         Mean |      Error |     StdDev | Rank |   Gen0 | Allocated |
|------------------- |----- |-------------:|-----------:|-----------:|-----:|-------:|----------:|
|  UsingStringConcat |  100 |     560.5 ns |    4.52 ns |    4.23 ns |    2 | 0.1192 |    1504 B |
| UsingStringBuilder |  100 |     140.2 ns |    1.15 ns |    1.08 ns |    1 | 0.0534 |     672 B |
|                    |      |              |            |            |      |        |           |
|  UsingStringConcat | 1000 |  25,430.1 ns |  150.23 ns |  140.54 ns |    2 | 8.8501 |  112344 B |
| UsingStringBuilder | 1000 |   1,250.5 ns |    8.45 ns |    7.90 ns |    1 | 0.3548 |    4488 B |
```

**ফলাফল বিশ্লেষণ (Analysis):**

১. **N = 1000 এর ক্ষেত্রে:**
   *   `StringConcat` সময় নিয়েছে **২৫,৪৩০ ন্যানোসেকেন্ড**।
   *   `StringBuilder` সময় নিয়েছে মাত্র **১,২৫০ ন্যানোসেকেন্ড**।
   *   অর্থাৎ `StringBuilder` প্রায় **২০ গুণ ফাস্ট**!

২. **Allocated (Memory):**
   *   `StringConcat` মেমোরি খেয়েছে **১১২ কিলোবাইট** (প্রচুর গারবেজ তৈরি করেছে)।
   *   `StringBuilder` মেমোরি খেয়েছে মাত্র **৪.৪ কিলোবাইট**।

এভাবেই আপনি আপনার এপিআই-এর যেকোনো ভারী মেথড বা লজিক টেস্ট করে সিদ্ধান্ত নিতে পারেন কোনটি ব্যবহার করা উচিত।
