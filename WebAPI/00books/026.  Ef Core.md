
সাধারণত **Chapter 25**-এ আমরা কোডের পারফরম্যান্স মেপেছি (Benchmarking)। এখন **Chapter 26**-এ আমরা শিখব সেই পারফরম্যান্স কীভাবে বাড়ানো যায়, বিশেষ করে **Entity Framework Core (EF Core)** অপটিমাইজেশনের মাধ্যমে।

এপিআই স্লো হওয়ার ৯০% কারণ থাকে ডাটাবেস কুয়েরি। এই চ্যাপ্টারের নাম হতে পারে **"EF Core Performance Tuning"**।

নিচে বিস্তারিত আলোচনা করা হলো:

---

### ১. AsNoTracking (রিড-অনলি মোড)

**কি কাজ করে:**
EF Core ডিফল্টভাবে ডাটাবেস থেকে কোনো ডাটা আনলে সেটাকে মেমোরিতে ট্র্যাক করে রাখে (যাতে পরে আপডেট করা যায়)।
`AsNoTracking()` মেথড ব্যবহার করলে EF Core ডাটা আনে ঠিকই, কিন্তু মেমোরিতে ট্র্যাক করে না।

**কেন কাজ করে (Why):**
ট্র্যাকিং বন্ধ থাকলে EF Core-এর ওভারহেড কমে যায়। এটি মেমোরি কম খায় এবং সিপিইউ সাইকেল বাঁচায়।

**কখন ব্যবহার করব:**
যখন আমরা ডাটা শুধু দেখাব (GET Request), কোনো পরিবর্তন করব না।

**উদাহরণ:**
*   **Normal (Slow):** `_context.Companies.ToList();`
*   **Optimized (Fast):** `_context.Companies.AsNoTracking().ToList();`

---

### ২. প্রোজেকশন বা সিলেক্ট লোডিং (Projection / Select)

**কি কাজ করে:**
ডাটাবেস টেবিলের সব কলাম (`SELECT *`) না এনে, শুধু যেটুকু দরকার সেটুকু আনা।

**কেন কাজ করে:**
আপনার টেবিলে ৫০টি কলাম থাকতে পারে। কিন্তু এপিআই রেসপন্সে হয়তো মাত্র ২টি কলাম (Name, Id) দরকার। পুরো ৫০ কলাম আনা মানে নেটওয়ার্ক ব্যান্ডউইথ এবং মেমোরির অপচয়।

**উদাহরণ:**
*   **Bad:** `_context.Employees.ToList();` (সব কলাম আনছে)
*   **Good:** `_context.Employees.Select(e => new { e.Name, e.Id }).ToList();` (শুধু নাম আর আইডি আনছে)

### ৩. বাল্ক অপারেশন (Bulk Operations - .NET 7/8 Feature)

**কি কাজ করে:**
আগে ১০ জন এমপ্লয়ির বয়স বাড়াতে হলে, ১০ জনকে ডাটাবেস থেকে আনতে হতো, লুপ চালিয়ে বয়স বাড়াতে হতো, তারপর `SaveChanges` দিতে হতো।
.NET 7/8 এ `ExecuteUpdate` এবং `ExecuteDelete` এসেছে যা ডাটা মেমোরিতে না এনেই সরাসরি ডাটাবেসে কুয়েরি চালায়।

**কেন কাজ করে:**
এটি SQL এর `UPDATE Employees SET Age = Age + 1` কুয়েরির মতো কাজ করে। মেমোরিতে ডাটা লোড আনলোডের সময় বাঁচে।

**উদাহরণ:**
*   **Old Way:**
    ```csharp
    var emps = context.Employees.Where(e => e.Age < 20).ToList();
    foreach(var e in emps) e.Age += 1;
    context.SaveChanges();
    ```
*   **New Way (Super Fast):**
    ```csharp
    context.Employees
        .Where(e => e.Age < 20)
        .ExecuteUpdate(s => s.SetProperty(e => e.Age, e => e.Age + 1));
    ```

### ৪. স্প্লিট কুয়েরি (Split Queries)

**কি কাজ করে:**
যখন আমরা `Include` ব্যবহার করে অনেকগুলো টেবিল জয়েন করি (যেমন: Company + Employee + Department), তখন SQL Server একটি বিশাল বড় কুয়েরি চালায় (Cartesian Explosion)।
`AsSplitQuery()` ব্যবহার করলে EF Core এটাকে ভেঙে ছোট ছোট ৩টা কুয়েরি চালায়।

**কেন কাজ করে:**
মাঝে মাঝে বিশাল একটা জয়েন কুয়েরির চেয়ে ছোট ছোট ৩টা কুয়েরি অনেক বেশি ফাস্ট এবং কম ডাটা ট্রান্সফার করে।

---

### ৫. কম্পাইলড কুয়েরি (Compiled Queries)

**কি কাজ করে:**
প্রতিবার কুয়েরি চালানোর সময় EF Core সেটাকে SQL এ কনভার্ট করে। `Compiled Query` ব্যবহার করলে এই কনভার্শন একবারই হয় এবং পরের বার সেই ক্যাশ করা প্ল্যান ব্যবহার করা হয়।

**সুবিধা:**
হাই-পারফরম্যান্স অ্যাপ্লিকেশনে (যেখানে প্রতি সেকেন্ডে হাজার হাজার রিকোয়েস্ট আসে) এটি ১০-১৫% স্পিড বাড়াতে পারে।

### সারসংক্ষেপ

| টপিক | কাজ | ফলাফল |
| :--- | :--- | :--- |
| **AsNoTracking** | ট্র্যাকিং বন্ধ রাখা। | রিড অপারেশন ফাস্ট হয়। |
| **Select** | নির্দিষ্ট কলাম আনা। | মেমোরি ও ব্যান্ডউইথ বাঁচে। |
| **ExecuteUpdate** | সরাসরি ডাটাবেসে আপডেট। | ডাটা লোড না করেই কাজ সারে। |
| **SplitQuery** | জয়েন ভেঙে ফেলা। | জটিল কুয়েরি সহজ হয়। |

**সহজ উদাহরণ:**
*   **Normal:** আপনি বাজার করতে গিয়ে পুরো দোকান (Table) ট্রাকে করে বাড়িতে নিয়ে আসলেন, তারপর সেখান থেকে আলু আর পেঁয়াজ নিলেন (**Select ***)।
*   **Projection:** আপনি দোকানে গিয়ে শুধু আলু আর পেঁয়াজ পকেটে করে নিয়ে আসলেন (**Select Name, Id**)।
*   **Bulk Update:** আপনি দোকানের মালিককে ফোন করে বললেন "সব আলুর দাম ২ টাকা বাড়িয়ে দাও" (দোকানে যাওয়ার দরকারই হলো না)।

নিচে বিভিন্ন অপটিমাইজেশন টেকনিকের কোড এবং উদাহরণ দেওয়া হলো।

### ১. AsNoTracking ব্যবহার (Read Optimization)

আমরা আমাদের `RepositoryBase` ক্লাসে `trackChanges` প্যারামিটার ব্যবহার করেছি। কিন্তু সেটা সঠিকভাবে ইমপ্লিমেন্ট করা আছে কি না চেক করি।

**ফাইল:** `Repository/RepositoryBase.cs`
```csharp
public IQueryable<T> FindAll(bool trackChanges) =>
    !trackChanges ?
      RepositoryContext.Set<T>().AsNoTracking() : // <--- অপটিমাইজেশন
      RepositoryContext.Set<T>();

public IQueryable<T> FindByCondition(Expression<Func<T, bool>> expression, bool trackChanges) =>
    !trackChanges ?
      RepositoryContext.Set<T>().Where(expression).AsNoTracking() :
      RepositoryContext.Set<T>().Where(expression);
```

**ব্যবহার:**
কন্ট্রোলারে যখন আমরা `GET` রিকোয়েস্ট পাঠাই, তখন `trackChanges: false` পাঠাই। এতে EF Core এর স্পিড বেড়ে যায়।

```csharp
// Presentation/Controllers/CompaniesController.cs
var companies = _service.CompanyService.GetAllCompanies(trackChanges: false);
```

### ২. প্রোজেকশন বা সিলেক্ট (Select Projection)

ধরুন আমাদের `Employee` টেবিলে ৫০টি কলাম আছে, কিন্তু ড্রপডাউন লিস্টের জন্য শুধু `Id` এবং `Name` দরকার।

**নন-অপটিমাইজড কোড (Slow):**
```csharp
var employees = context.Employees.ToList(); // সব কলাম আনবে
var result = employees.Select(e => new { e.Id, e.Name });
```

**অপটিমাইজড কোড (Fast - Repository Layer):**
```csharp
public IEnumerable<object> GetEmployeesNameAndId(Guid companyId)
{
    return FindByCondition(e => e.CompanyId.Equals(companyId), trackChanges: false)
        .Select(e => new { e.Id, e.Name }) // <--- ডাটাবেস থেকেই শুধু এই দুটি কলাম আসবে
        .ToList();
}
```

### ৩. বাল্ক আপডেট এবং ডিলিট (.NET 7/8 Feature)

ধরি, আমরা চাই একটি নির্দিষ্ট কোম্পানির সব এমপ্লয়ির বয়স ১ বছর বাড়িয়ে দিতে।

**ওল্ড ওয়ে (Slow):**
```csharp
public async Task IncreaseAgeForCompany(Guid companyId)
{
    // ১. সব এমপ্লয়ি মেমোরিতে আনো (RAM খরচ)
    var employees = await FindByCondition(e => e.CompanyId == companyId, trackChanges: true).ToListAsync();
    
    // ২. লুপ চালিয়ে চেঞ্জ করো (CPU খরচ)
    foreach(var emp in employees)
    {
        emp.Age += 1;
    }
    
    // ৩. সেভ করো (DB Roundtrip)
    await RepositoryContext.SaveChangesAsync();
}
```

**নিউ ওয়ে (Fast - ExecuteUpdate):**
```csharp
public async Task IncreaseAgeForCompanyOptimized(Guid companyId)
{
    // সরাসরি ডাটাবেসে কুয়েরি চলবে: UPDATE Employees SET Age = Age + 1 WHERE CompanyId = ...
    await RepositoryContext.Employees
        .Where(e => e.CompanyId == companyId)
        .ExecuteUpdateAsync(s => s.SetProperty(e => e.Age, e => e.Age + 1));
}
```

**বাল্ক ডিলিট (ExecuteDelete):**
```csharp
public async Task DeleteAllEmployeesOfCompany(Guid companyId)
{
    // কোনো ডাটা লোড না করেই ডিলিট
    await RepositoryContext.Employees
        .Where(e => e.CompanyId == companyId)
        .ExecuteDeleteAsync();
}
```

### ৪. স্প্লিট কুয়েরি (Split Queries)

যখন আমরা `Include` ব্যবহার করে `Company` এর সাথে তার `Employees` লোড করি।

**ডিফল্ট বিহেভিয়ার (Single Query):**
```sql
SELECT c.*, e.* FROM Companies c LEFT JOIN Employees e ON ...
```
*(এতে ডাটা ডুপ্লিকেশন হয় এবং রেসপন্স ভারী হয়)*

**অপটিমাইজড (Split Query):**
```csharp
public async Task<Company> GetCompanyWithEmployees(Guid id)
{
    return await RepositoryContext.Companies
        .Include(c => c.Employees)
        .AsSplitQuery() // <--- এই মেথডটি ম্যাজিক করে
        .FirstOrDefaultAsync(c => c.Id == id);
}
```
*এটি দুটি ছোট কুয়েরি চালাবে: ১. কোম্পানি আনো, ২. এমপ্লয়ি আনো। এটি অনেক ক্ষেত্রে ফাস্ট।*

### ৫. গ্লোবাল সেটিংস (Program.cs)

আমরা চাইলে পুরো প্রজেক্টের জন্যই স্প্লিট কুয়েরি এনাবল করতে পারি।

**ফাইল:** `Extensions/ServiceExtensions.cs`

```csharp
public static void ConfigureSqlContext(this IServiceCollection services, IConfiguration configuration) =>
    services.AddDbContext<RepositoryContext>(opts =>
        opts.UseSqlServer(configuration.GetConnectionString("sqlConnection"),
            // গ্লোবাল কনফিগারেশন
            o => o.UseQuerySplittingBehavior(QuerySplittingBehavior.SplitQuery))
    );
```

### ৬. উদাহরণ (Comparison Example)

ধরি আমাদের ডাটাবেসে ১০,০০০ এমপ্লয়ি আছে। তাদের সবার বয়স বাড়াতে হবে।

*   **Old Way (Loop & Save):** সময় লাগতে পারে **২-৩ সেকেন্ড**।
*   **New Way (ExecuteUpdate):** সময় লাগবে **৫০-১০০ মিলিসেকেন্ড**।

কারণ নতুন পদ্ধতিতে ডাটা নেটওয়ার্ক দিয়ে সার্ভারে আসেই না, ডাটাবেস ইঞ্জিনের ভেতরেই কাজ শেষ হয়ে যায়।

এভাবেই EF Core-এর এই ফিচারগুলো ব্যবহার করে আমরা আমাদের এপিআইকে সুপার ফাস্ট করতে পারি।
