

আমরা Chapter 18-এ **Unit Testing** শিখেছিলাম, যেখানে আমরা ডাটাবেস এবং অন্যান্য সার্ভিসকে নকল (Mock) করে শুধু লজিক চেক করেছিলাম। কিন্তু **Integration Testing**-এ আমরা কোনো কিছু নকল করব না, বরং পুরো সিস্টেমটি একসাথে ঠিকমতো কাজ করছে কি না তা চেক করব।

নিচে বিস্তারিত আলোচনা করা হলো:

---

### ১. ইন্টিগ্রেশন টেস্টিং কী? (What is Integration Testing?)

**কি কাজ করে:**
এটি চেক করে অ্যাপ্লিকেশনের বিভিন্ন অংশ (Controller, Service, Database, Authentication) একসাথে মিলে কাজ করছে কি না।
ইউনিট টেস্টে আমরা চেক করি "মেথডটি ঠিক আছে কি না"। আর এখানে আমরা চেক করি "এপিআই কল করলে ডাটাবেস থেকে ডাটা এসে রেসপন্স ঠিকমতো জেনারেট হচ্ছে কি না"।

**কেন দরকার (Why):**
*   ইউনিট টেস্ট পাস করার পরেও অ্যাপ ক্র্যাশ করতে পারে যদি ডাটাবেস কানেকশন স্ট্রিং ভুল থাকে বা মিডলওয়্যার ঠিকমতো কাজ না করে।
*   ইন্টিগ্রেশন টেস্ট এই "কমিউনিকেশন গ্যাপ" গুলো ধরে ফেলে।

---

### ২. WebApplicationFactory

**কি কাজ করে:**
এটি .NET Core-এর একটি পাওয়ারফুল টুল (`Microsoft.AspNetCore.Mvc.Testing` প্যাকেজে থাকে)।
এটি টেস্ট রান করার সময় ব্যাকগ্রাউন্ডে একটি **Test Server** চালু করে। আপনাকে আলাদা করে `dotnet run` দিয়ে এপিআই চালু রাখতে হয় না।

**সুবিধা:**
এটি অটোমেটিক একটি `HttpClient` তৈরি করে দেয়, যা দিয়ে আমরা কোডের ভেতর থেকেই আমাদের এপিআই (`GET /api/companies`) কল করতে পারি।

---

### ৩. ইন-মেমোরি ডাটাবেস (In-Memory Database)

**সমস্যা:**
আসল প্রোডাকশন ডাটাবেস (SQL Server) দিয়ে টেস্ট করা রিস্কি। টেস্ট করতে গিয়ে ডাটা ডিলিট হয়ে যেতে পারে। তাছাড়া আসল ডাটাবেস স্লো।

**সমাধান:**
ইন্টিগ্রেশন টেস্টিংয়ের সময় আমরা আসল ডাটাবেস সরিয়ে **In-Memory Database** ব্যবহার করি।
এটি র‍্যামের (RAM) ওপর চলে। টেস্ট শুরু হলে ডাটাবেস তৈরি হয়, টেস্ট শেষ হলে ডাটাবেস মুছে যায়। ফলে প্রতিবার ফ্রেশ টেস্ট করা যায়।

### ৪. ইউনিট টেস্ট বনাম ইন্টিগ্রেশন টেস্ট

| বৈশিষ্ট্য | ইউনিট টেস্ট (Unit Test) | ইন্টিগ্রেশন টেস্ট (Integration Test) |
| :--- | :--- | :--- |
| **স্কোপ** | একটি মেথড বা ক্লাস। | পুরো রিকোয়েস্ট পাইপলাইন। |
| **ডিপেন্ডেন্সি** | সব মক (Mock) করা হয়। | আসল বা ইন-মেমোরি ডিপেন্ডেন্সি ব্যবহার হয়। |
| **ডাটাবেস** | ডাটাবেসে যায় না। | ডাটাবেসে রিড/রাইট করে। |
| **স্পিড** | সুপার ফাস্ট (মিলি সেকেন্ড)। | একটু স্লো (সেকেন্ড)। |

### ৫. টেস্টিং ফ্লো (Testing Flow)

একটি ইন্টিগ্রেশন টেস্ট সাধারণত ৩টি ধাপে হয় (AAA Pattern):

1.  **Arrange:** টেস্ট সার্ভার চালু করা এবং ডাটাবেসে কিছু ডামি ডাটা ইনসার্ট করা।
2.  **Act:** এপিআই কল করা (যেমন: `client.GetAsync("/api/companies")`)।
3.  **Assert:** রেসপন্স কোড `200 OK` কি না এবং ডাটাবেসের ডাটার সাথে রেসপন্স মিলছে কি না তা চেক করা।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Integration Testing** | পুরো সিস্টেম চেক করা। | এন্ড-টু-এন্ড (End-to-End) নির্ভরযোগ্যতার জন্য। |
| **Test Server** | মেমোরিতে সার্ভার চালানো। | রিয়েল ব্রাউজার বা পোস্টম্যান ছাড়াই টেস্ট করার জন্য। |
| **HttpClient** | কোড দিয়ে এপিআই কল করা। | অটোমেটিক রিকোয়েস্ট পাঠানোর জন্য। |

**সহজ উদাহরণ:**
*   **Unit Test:** আপনি চেক করলেন গাড়ির টায়ার গোল কি না, ইঞ্জিন স্টার্ট হয় কি না (আলাদা আলাদা)।
*   **Integration Test:** আপনি টায়ার লাগালেন, ইঞ্জিন স্টার্ট করলেন এবং গাড়িটি রাস্তায় চালিয়ে দেখলেন ব্রেক কষলে গাড়ি থামে কি না (সব একসাথে)।

### ২. টেস্টিং ফ্যাক্টরি তৈরি (Custom WebApplicationFactory)

আমাদের মেইন প্রজেক্টে SQL Server কনফিগার করা আছে। কিন্তু টেস্টের সময় আমরা সেটা চাই না। আমরা চাই টেস্টের সময় **In-Memory Database** চলুক।

এর জন্য আমাদের `WebApplicationFactory` ক্লাসটিকে কাস্টমাইজ করতে হবে।

**ফাইল:** `CompanyEmployees.IntegrationTests/CustomWebApplicationFactory.cs`

```csharp
using Microsoft.AspNetCore.Hosting;
using Microsoft.AspNetCore.Mvc.Testing;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Repository; // RepositoryContext যেখানে আছে

// Program ক্লাসটি মেইন প্রজেক্টের এন্ট্রি পয়েন্ট
public class CustomWebApplicationFactory<TProgram> 
    : WebApplicationFactory<TProgram> where TProgram : class
{
    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.ConfigureServices(services =>
        {
            // ১. মেইন প্রজেক্টের SQL Server কনফিগারেশন রিমুভ করা
            var descriptor = services.SingleOrDefault(
                d => d.ServiceType == typeof(DbContextOptions<RepositoryContext>));

            if (descriptor != null)
                services.Remove(descriptor);

            // ২. ইন-মেমোরি ডাটাবেস অ্যাড করা
            services.AddDbContext<RepositoryContext>(options =>
            {
                options.UseInMemoryDatabase("InMemoryDbForTesting");
            });

            // ৩. ডাটাবেস তৈরি এবং সিড করা (Seed Data)
            var sp = services.BuildServiceProvider();
            using (var scope = sp.CreateScope())
            {
                var scopedServices = scope.ServiceProvider;
                var db = scopedServices.GetRequiredService<RepositoryContext>();

                db.Database.EnsureCreated();

                // কিছু ডামি ডাটা ইনসার্ট করা
                if (!db.Companies.Any())
                {
                    db.Companies.Add(new Entities.Models.Company { Id = Guid.NewGuid(), Name = "Test Corp", Address = "Test Address", Country = "Test Country" });
                    db.SaveChanges();
                }
            }
        });
    }
}
```
*(নোট: `Program` ক্লাসটি এক্সেস করার জন্য মেইন প্রজেক্টের `Program.cs` ফাইলের নিচে `public partial class Program { }` লাইনটি যোগ করতে হতে পারে যদি .NET 6+ টপ লেভেল স্টেটমেন্ট ব্যবহার করেন)*

### ৩. টেস্ট ক্লাস তৈরি (Writing Integration Test)

এখন আমরা `CompaniesController` টেস্ট করব।

**ফাইল:** `CompanyEmployees.IntegrationTests/CompaniesControllerIntegrationTests.cs`

```csharp
using System.Net;
using System.Net.Http.Json;
using Xunit;

// IClassFixture ব্যবহার করা হচ্ছে যাতে ফ্যাক্টরি একবারই তৈরি হয়
public class CompaniesControllerIntegrationTests 
    : IClassFixture<CustomWebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public CompaniesControllerIntegrationTests(CustomWebApplicationFactory<Program> factory)
    {
        // ১. টেস্ট ক্লায়েন্ট তৈরি (এটি অটোমেটিক ইন-মেমোরি সার্ভারে রিকোয়েস্ট পাঠাবে)
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task GetCompanies_ReturnsSuccessResult_AndCorrectContentType()
    {
        // --- Act ---
        // এপিআই কল করা
        var response = await _client.GetAsync("/api/companies");

        // --- Assert ---
        // ১. স্ট্যাটাস কোড 200 OK কি না?
        response.EnsureSuccessStatusCode(); 

        // ২. কনটেন্ট টাইপ জেসন কি না?
        Assert.Equal("application/json; charset=utf-8", 
            response.Content.Headers.ContentType.ToString());
            
        // ৩. ডাটা চেক করা (Optional)
        var companies = await response.Content.ReadFromJsonAsync<List<dynamic>>();
        Assert.NotNull(companies);
        Assert.True(companies.Count > 0);
    }
    
    [Fact]
    public async Task GetCompany_ReturnsNotFound_GivenInvalidId()
    {
        // ভুল আইডি দিয়ে চেক করা
        var response = await _client.GetAsync($"/api/companies/{Guid.NewGuid()}");
        
        Assert.Equal(HttpStatusCode.NotFound, response.StatusCode);
    }
}
```

### ৫. কী ঘটছে এখানে? (Behind the Scenes)

১. যখন টেস্ট রান হয়, `CustomWebApplicationFactory` একটি নকল ওয়েব সার্ভার চালু করে।
২. এটি মেইন ডাটাবেসের বদলে র‍্যামে একটি ডাটাবেস তৈরি করে এবং সেখানে "Test Corp" নামে কোম্পানি ইনসার্ট করে।
৩. `_client.GetAsync` যখন কল হয়, তখন রিকোয়েস্টটি ওই নকল সার্ভারে যায়।
৪. সার্ভার ইন-মেমোরি ডাটাবেস থেকে ডাটা এনে রেসপন্স দেয়।
৫. `Assert` মেথডগুলো চেক করে রেসপন্স ঠিক আছে কি না।

এভাবেই আমরা আসল সার্ভার বা ডাটাবেসে হাত না দিয়েই পুরো এপিআই ফ্লো টেস্ট করতে পারি।
