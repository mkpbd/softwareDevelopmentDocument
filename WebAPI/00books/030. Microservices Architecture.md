**Chapter 30** সাধারণত বইয়ের একদম শেষ চ্যাপ্টার বা উপসংহার হতে পারে। যদি বইটিতে ৩০টি টেকনিক্যাল চ্যাপ্টার থাকে, তবে এটি হতে পারে **"Microservices Architecture"** এর একটি ইন্ট্রোডাকশন অথবা **"Clean Architecture"** নিয়ে বিস্তারিত আলোচনা।

যেহেতু আমরা এর আগে মনোলিথিক (Monolithic) এপিআই বানিয়েছি (সব কোড এক সল্যুশনে), তাই লজিক্যালি পরের ধাপ হলো এই বিশাল অ্যাপকে ভেঙে ছোট ছোট টুকরো (Microservices) করা।

আসুন ধরে নিই এই চ্যাপ্টারটি **"Introduction to Microservices"** নিয়ে।

---

### ১. মনোলিথ বনাম মাইক্রোসার্ভিসেস (Monolith vs Microservices)

**Monolith (আমরা যা বানালাম):**
*   **কি:** পুরো অ্যাপ্লিকেশন (কোম্পানি, এমপ্লয়ি, অথেনটিকেশন) একটি মাত্র প্রজেক্ট বা সল্যুশনে থাকে।
*   **সমস্যা:** প্রজেক্ট যখন খুব বড় হয়, তখন কোড মেইনটেইন করা কঠিন হয়ে পড়ে। একটা ছোট চেঞ্জ করতে গেলে পুরো অ্যাপ রিবিল্ড এবং ডিপ্লয় করতে হয়। একটা পার্ট ক্র্যাশ করলে পুরো অ্যাপ বন্ধ হয়ে যায়।

**Microservices (নতুন আর্কিটেকচার):**
*   **কি:** অ্যাপকে ভেঙে ছোট ছোট স্বাধীন সার্ভিসে ভাগ করা।
    *   Service A: Authentication Service (শুধু লগইন দেখবে)।
    *   Service B: Company Service (শুধু কোম্পানি দেখবে)।
    *   Service C: Employee Service (শুধু এমপ্লয়ি দেখবে)।
*   প্রতিটি সার্ভিসের নিজস্ব ডাটাবেস থাকতে পারে।

---

### ২. এপিআই গেটওয়ে (API Gateway - Ocelot)

**কি কাজ করে:**
মাইক্রোসার্ভিসে ১০টা আলাদা সার্ভিস থাকলে ১০টা আলাদা ইউআরএল হবে (`localhost:5001`, `localhost:5002`...)। ক্লায়েন্টের পক্ষে এতগুলো ইউআরএল মনে রাখা সম্ভব না।
**API Gateway** হলো একটি মেইন দরজা। ক্লায়েন্ট শুধু গেটওয়েকে চেনে (`localhost:5000`)। গেটওয়ে ডিসাইড করে রিকোয়েস্টটি কোন সার্ভিসের কাছে পাঠাবে।

**কেন দরকার:**
১. **Security:** সব সার্ভিসকে পাবলিক করার দরকার নেই, শুধু গেটওয়ে পাবলিক থাকে।
২. **Routing:** রিকোয়েস্ট রাউট করা।

.NET এ **Ocelot** লাইব্রেরি দিয়ে এটি করা হয়।

---

### ৩. কমিউনিকেশন (Sync vs Async)

সার্ভিসগুলো একে অপরের সাথে কথা বলবে কীভাবে?

*   **Synchronous (HTTP/REST/gRPC):** সার্ভিস A সরাসরি সার্ভিস B কে কল করে। (যেমন: শপে অর্ডার দিলে পেমেন্ট সার্ভিস কল হয়)।
*   **Asynchronous (Message Bus - RabbitMQ/Azure Service Bus):** সার্ভিস A একটি মেসেজ কিউতে (Queue) ফেলে দেয়। সার্ভিস B সময়মতো সেটা পিক করে নেয়। (যেমন: অর্ডার কনফার্ম হলে ইমেইল পাঠানো)।

---

### ৪. ডিস্ট্রিবিউটেড ট্রেসিং (Distributed Tracing)

**সমস্যা:**
মাইক্রোসার্ভিসে একটা রিকোয়েস্ট ৫টা সার্ভার ঘুরে আসতে পারে। এরর হলে বুঝব কীভাবে কোথায় সমস্যা হয়েছে?

**সমাধান:**
আমরা **Zipkin** বা **Jaeger** বা **OpenTelemetry** ব্যবহার করি। এটি রিকোয়েস্টের সাথে একটি `TraceId` জুড়ে দেয়। লগ দেখে বোঝা যায় রিকোয়েস্টটি কোন পথ দিয়ে গেছে।

---

### ৫. কখন মাইক্রোসার্ভিস ব্যবহার করব?

*   যখন টিম অনেক বড় (৫০+ ডেভেলপার)।
*   যখন অ্যাপ অনেক জটিল এবং বড়।
*   যখন অ্যাপের বিভিন্ন অংশের স্কেলিং আলাদা (যেমন: চ্যাট সার্ভিসে প্রচুর লোড, কিন্তু প্রোফাইল সার্ভিসে কম লোড)।

ছোট অ্যাপের জন্য মাইক্রোসার্ভিস ব্যবহার করা বোকামি (Over-engineering)। সেখানে মনোলিথই সেরা।

### সারসংক্ষেপ

| টপিক | কাজ | কেন শিখব? |
| :--- | :--- | :--- |
| **Microservices** | অ্যাপ ভেঙে ছোট করা। | বড় অ্যাপ সহজে ম্যানেজ এবং স্কেল করার জন্য। |
| **API Gateway** | এন্ট্রি পয়েন্ট। | ক্লায়েন্টকে জটিলতা থেকে আড়াল করার জন্য। |
| **Message Broker** | ইভেন্ট বাস (RabbitMQ)। | সার্ভিসদের মধ্যে লুজলি কাপলড যোগাযোগের জন্য। |
| **Tracing** | ট্র্যাকিং। | ডিস্ট্রিবিউটেড সিস্টেম ডিবাগ করার জন্য। |

**সহজ উদাহরণ:**
*   **Monolith:** একটি সুপার শপ যেখানে এক কাউন্টারেই সব পাওয়া যায়। ভিড় হলে সব আটকে যায়।
*   **Microservices:** একটি বাজার যেখানে মাছের দোকান আলাদা, সবজির দোকান আলাদা। মাছের দোকানে ভিড় হলেও সবজির দোকান ঠিকই চলছে।

আমরা একটি নতুন খালি প্রজেক্ট তৈরি করব যা গেটওয়ে হিসেবে কাজ করবে।

২. `ASP.NET Core Empty` প্রজেক্ট সিলেক্ট করুন।
৩. নাম দিন: `ApiGateway`।

**ধাপ ২: প্যাকেজ ইন্সটল**
Ocelot প্যাকেজটি ইন্সটল করতে হবে। Package Manager Console এ (ApiGateway সিলেক্ট করে) চালান:
```powershell
Install-Package Ocelot
```

### ২. ওসেলট কনফিগারেশন (ocelot.json)

প্রজেক্টের রুট ফোল্ডারে একটি নতুন ফাইল তৈরি করুন `ocelot.json`। এখানে আমরা রাউটিং রুলস লিখব।

**ফাইল:** `ocelot.json`

```json
{
  "Routes": [
    {
      // ১. কোন সার্ভিসে রিকোয়েস্ট যাবে (Downstream)
      "DownstreamPathTemplate": "/api/companies",
      "DownstreamScheme": "https",
      "DownstreamHostAndPorts": [
        {
          "Host": "localhost",
          "Port": 5001 // আমাদের মেইন এপিআই এর পোর্ট
        }
      ],
      // ২. ক্লায়েন্ট কোন ইউআরএল এ হিট করবে (Upstream)
      "UpstreamPathTemplate": "/gateway/companies",
      "UpstreamHttpMethod": [ "GET", "POST" ]
    },
    {
      // আরেকটি রাউট (যেমন: Employees)
      "DownstreamPathTemplate": "/api/companies/{id}/employees",
      "DownstreamScheme": "https",
      "DownstreamHostAndPorts": [
        {
          "Host": "localhost",
          "Port": 5001
        }
      ],
      "UpstreamPathTemplate": "/gateway/companies/{id}/employees",
      "UpstreamHttpMethod": [ "GET" ]
    }
  ],
  "GlobalConfiguration": {
    "BaseUrl": "https://localhost:5050" // গেটওয়ের নিজের ইউআরএল
  }
}
```

### ৩. প্রোগ্রাম ফাইলে কনফিগারেশন (Program.cs)

`ApiGateway` প্রজেক্টের `Program.cs` ফাইলে Ocelot সার্ভিস চালু করতে হবে।

**ফাইল:** `ApiGateway/Program.cs`

```csharp
using Ocelot.DependencyInjection;
using Ocelot.Middleware;

var builder = WebApplication.CreateBuilder(args);

// ১. কনফিগারেশন ফাইল লোড করা
builder.Configuration.AddJsonFile("ocelot.json", optional: false, reloadOnChange: true);

// ২. ওসেলট সার্ভিস অ্যাড করা
builder.Services.AddOcelot(builder.Configuration);

var app = builder.Build();

// ৩. ওসেলট মিডলওয়্যার চালু করা
await app.UseOcelot();

app.Run();
```

*(নোট: `launchSettings.json` এ গেটওয়ের পোর্ট `5050` বা আপনার পছন্দমতো সেট করে নিন)*

### ৪. রান এবং টেস্ট (Execution)

এখন আমাদের দুটি প্রজেক্ট একসাথে রান করতে হবে।
১. Solution এ রাইট ক্লিক -> `Set Startup Projects`.
২. `Multiple startup projects` সিলেক্ট করুন।
৩. `CompanyEmployees` (Main API) এবং `ApiGateway` দুটোর অ্যাকশন `Start` করে দিন।
৪. `OK` এবং `F5` চাপুন।

**Testing with Postman/Browser:**

*   **Direct Call (Old Way):** `https://localhost:5001/api/companies` -> কাজ করবে।
*   **Gateway Call (New Way):** `https://localhost:5050/gateway/companies` -> এটিও কাজ করবে!

**কি ঘটল?**
আপনি `5050` (Gateway) এ হিট করলেন। Ocelot দেখল কনফিগারেশনে বলা আছে `/gateway/companies` আসলে তাকে `localhost:5001/api/companies` এ পাঠাতে হবে। সে রিকোয়েস্টটি ফরওয়ার্ড করল, রেসপন্স আনল এবং আপনাকে দিল। আপনি আসল সার্ভারের পোর্ট বা আইপি জানলেনই না।

### ৫. বোনাস: রেট লিমিটিং এবং ক্যাশিং

গেটওয়ের একটি বড় সুবিধা হলো এখানেই রেট লিমিটিং বা ক্যাশিং বসানো যায়, ভেতরের সার্ভিসে হাত না দিয়েই।

**ocelot.json এ আপডেট:**
```json
{
  "Routes": [
    {
      "DownstreamPathTemplate": "/api/companies",
      // ... আগের কনফিগারেশন ...
      
      // রেট লিমিটিং অ্যাড করা
      "RateLimitOptions": {
        "ClientWhitelist": [],
        "EnableRateLimiting": true,
        "Period": "1s",
        "PeriodTimespan": 1,
        "Limit": 1 // ১ সেকেন্ডে ১টির বেশি রিকোয়েস্ট এলাউড না
      }
    }
  ]
}
```

এভাবেই আপনি **API Gateway** ব্যবহার করে আপনার সিস্টেমকে মাইক্রোসার্ভিস আর্কিটেকচারের দিকে নিয়ে যেতে পারেন।
