### 🎓 Lesson 1: ADO.NET কী এবং কেন? (The Waiter Analogy)

**সহজ বাংলায়:**
ধরো তুমি একটা রেস্টুরেন্টে গিয়েছ। তুমি টেবিলে বসে আছো (C# Application), আর কিচেনে বাবুর্চি আছে (SQL Server Database)। তুমি কি নিজে দৌড়ে কিচেনে গিয়ে বাবুর্চিকে বলবে "মামা এক প্লেট কাচ্চি দেন"? না! তুমি ওয়েটারকে ডাকবে।
এখানে **ADO.NET হলো সেই ওয়েটার**। সে তোমার অ্যাপ থেকে অর্ডার (Query) নিয়ে ডাটাবেসে যায়, আর ডাটাবেস থেকে খাবার (Data) নিয়ে তোমার টেবিলে আসে।

**কেন শিখব?**
- **স্পিড:** এটা রকেটের গতিতে কাজ করে।
- **কন্ট্রোল:** ডাটাবেসের প্রতিটি শ্বাস-প্রশ্বাস তুমি নিয়ন্ত্রণ করতে পারবে।

### 🎓 Lesson 3: SqlConnection - ডাটাবেসের সাথে হ্যান্ডশেক (The Bridge)

**মামা-ভাগ্নে এনালজি:**
ডাটাবেস হলো তোমার গার্লফ্রেন্ডের বাসা। কথা বলতে গেলে আগে ফোন করতে হবে (Connection)। ফোন কানেক্ট না হলে হ্যালো (Command) বলা যাবে না।

**Real Project Folder Structure:**
```text
MyConsoleApp/
├── Program.cs
├── App.config (বা appsettings.json)
```

**Real C# Code:**
```csharp
using System;
using System.Data.SqlClient; // এইটা হলো ADO.NET এর চাবি

namespace AdoNetSeries
{
    class Program
    {
        static void Main(string[] args)
        {
            // কানেকশন স্ট্রিং (গার্লফ্রেন্ডের ফোন নাম্বার)
            string cs = "Server=YOUR_SERVER_NAME;Database=TechShopDB;Trusted_Connection=True;";

            // কানেকশন অবজেক্ট তৈরি
            SqlConnection con = new SqlConnection(cs);

            try
            {
                con.Open(); // কল দিলাম (Connection Open)
                Console.WriteLine("Mama! Connection Successful! 🚀");
            }
            catch (Exception ex)
            {
                Console.WriteLine("Mama, Connection fel marse: " + ex.Message);
            }
            finally
            {
                con.Close(); // কথা শেষ, ফোন রাখো। এটা মাস্ট!
                Console.WriteLine("Connection Closed.");
            }
        }
    }
}
```

**Beginner Mistake:**
অনেকে `con.Close()` দিতে ভুলে যায়। ফলে লাইন বিজি থাকে, পরে আর কেউ ঢুকতে পারে না। সব সময় `finally` ব্লকে ক্লোজ করবে।

### 🎓 Lesson 4: Connection String - সিক্রেট চাবি (Security)

**সহজ কথা:**
কোডের ভেতরে পাসওয়ার্ড বা সার্ভারের নাম হার্ডকোড করা পাপ। বস দেখলে চাকরি নট করে দিবে। এটা রাখতে হয় কনফিগারেশন ফাইলে।

**Real Implementation:**
তোমার প্রজেক্টে `appsettings.json` (Core এর জন্য) অথবা `App.config` (.NET Framework) ফাইল বানাও।

**File: appsettings.json**
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=.\\SQLEXPRESS;Database=TechShopDB;Trusted_Connection=True;TrustServerCertificate=True;"
  }
}
```

**Why Important?**
ভবিষ্যতে সার্ভার চেঞ্জ হলে শুধু এই ফাইলে চেঞ্জ করলেই হবে, পুরো কোড ঘাঁটতে হবে না। একে বলে "স্মার্ট ডেভেলপার"।

### 🎓 Lesson 5: SqlCommand - হুকুম দেওয়া (The Order)

**মামা-ভাগ্নে এনালজি:**
কানেকশন তো হলো (ওয়েটার আসল)। এখন তো অর্ডার দিতে হবে—"মামা, এক প্লেট কাচ্চি আনেন"। এই অর্ডারটাই হলো `SqlCommand`।

**Scenario:** আমরা জানব আমাদের দোকানে কয়টা প্রোডাক্ট আছে।

**Real C# Code:**
```csharp
using System;
using System.Data.SqlClient;

class Program
{
    static void Main()
    {
        string cs = "Server=.\\SQLEXPRESS;Database=TechShopDB;Trusted_Connection=True;";

        // Best Practice: 'using' ব্লক ব্যবহার করা।
        // এটা অটোমেটিক কানেকশন ক্লোজ করে দেয়। ফোন কাটার টেনশন নাই!
        using (SqlConnection con = new SqlConnection(cs))
        {
            // কুয়েরি লিখলাম
            string query = "SELECT COUNT(*) FROM Products";

            // কমান্ড রেডি করলাম (কি চাই, কার কাছে চাই)
            SqlCommand cmd = new SqlCommand(query, con);

            con.Open(); // দরজা খুললাম

            // ExecuteScalar মানে হলো শুধু একটা রেজাল্ট চাই (Total count)
            int totalProducts = (int)cmd.ExecuteScalar(); 

            Console.WriteLine($"Mama, amader dokane total {totalProducts} ta item ache!");
        } 
        // এখানে আসার সাথে সাথে কানেকশন অটো ক্লোজ হয়ে গেছে। মাজিক!
    }
}
```

**Common Error:**
`ExecuteScalar` ব্যবহার না করে `ExecuteReader` ব্যবহার করা যখন তোমার শুধু একটা ভ্যালু দরকার। পারফর্মেন্স কমে যাবে।

### 🎓 Lesson 6: ExecuteNonQuery - ইনসার্ট, আপডেট, ডিলিট (Action Mode)

**বিষয়:**
ডাটা আনা তো দেখলাম। এবার ডাটা ঢোকাবো। ধরো নতুন একটা আইটেম এসেছে দোকানে।

**C# Code:**
```csharp
using (SqlConnection con = new SqlConnection(cs))
{
    // হার্ডকোড ভ্যালু (খারাপ অভ্যাস, পরে ঠিক করব Lesson 8 এ)
    string query = "INSERT INTO Products (ProductName, Price, Stock) VALUES ('Headphone', 800, 20)";

    SqlCommand cmd = new SqlCommand(query, con);
    
    con.Open();
    
    // ExecuteNonQuery ব্যবহার হয় যখন আমরা ডাটাবেস থেকে কিছু ফেরত চাই না,
    // শুধু জানতে চাই কয়টা রো (Row) এফেক্ট হলো।
    int rowsAffected = cmd.ExecuteNonQuery();

    if(rowsAffected > 0)
    {
        Console.WriteLine($"Success Mama! {rowsAffected} ta product dhukse.");
    }
    else
    {
        Console.WriteLine("Kono kaj hoy nai mama.");
    }
}
```

### 🎓 Lesson 7 & 8: Parameterized Queries - হ্যাকার ঠেকানো (SQL Injection)

**Danger Zone:**
তুমি যদি ইউজারের ইনপুট সরাসরি কুয়েরিতে বসাও, হ্যাকার তোমার ডাটাবেস ডিলিট করে দিতে পারে। এটাকে বলে **SQL Injection**।
উদাহরণ: ইউজার ইনপুটে লিখল `' OR 1=1 --`। ব্যাস, তোমার পাসওয়ার্ড চেকিং বাইপাস হয়ে যাবে।

**Solution: Parameters (The Shield)**

**ভুল কোড (Don't do this):**
```csharp
string query = "SELECT * FROM Users WHERE Name = '" + userName + "'"; // ❌ পাপ! মহাপাপ!
```

**সঠিক কোড (Do this):**
```csharp
Console.Write("Product Name den: ");
string pName = Console.ReadLine(); // ধরি ইউজার দিল: USB Cable
Console.Write("Price den: ");
decimal pPrice = Convert.ToDecimal(Console.ReadLine());

using (SqlConnection con = new SqlConnection(cs))
{
    string query = "INSERT INTO Products (ProductName, Price, Stock) VALUES (@n, @p, 0)";
    
    SqlCommand cmd = new SqlCommand(query, con);
    
    // ভ্যালু বাইন্ডিং (নিরাপদ উপায়)
    cmd.Parameters.AddWithValue("@n", pName);
    cmd.Parameters.AddWithValue("@p", pPrice);

    con.Open();
    cmd.ExecuteNonQuery();
    Console.WriteLine("Safe Insert Mama!");
}
```

**Why Important?**
`@n` এবং `@p` হলো প্লেসহোল্ডার। ADO.NET এখানে চেক করে কোনো খারাপ কোড আছে কিনা। থাকলে সে সেটাকে টেক্সট হিসেবেই ট্রিট করে, এক্সিকিউট করে না।

### 🎓 Lesson 9: SqlDataReader - ডাটা পড়া (The Firehose)

**Scenario:**
দোকানের সব প্রোডাক্টের লিস্ট দেখব। `ExecuteScalar` দিয়ে হবে না, কারণ অনেকগুলো রো আসবে। এখানে লাগবে `SqlDataReader`।

**Real World Analogy:**
এটা হলো পানির পাইপ (Firehose)। যতক্ষণ ট্যাপ খোলা, ততক্ষণ পানি (Data) আসবে। এটা মেমোরিতে ডাটা জমায় না, একটার পর একটা রিড করে। তাই এটা সুপার ফাস্ট।

**C# Code:**
```csharp
using (SqlConnection con = new SqlConnection(cs))
{
    string query = "SELECT ProductID, ProductName, Price FROM Products";
    SqlCommand cmd = new SqlCommand(query, con);
    
    con.Open();
    
    // রিডার চালু করলাম
    using (SqlDataReader reader = cmd.ExecuteReader())
    {
        // লুপ চলবে যতক্ষণ ডাটা আছে
        Console.WriteLine("ID \t Name \t\t Price");
        Console.WriteLine("------------------------------");
        
        while (reader.Read())
        {
            // ডাটা ইনডেক্স ধরে বা কলামের নাম ধরে আনা যায়
            int id = reader.GetInt32(0); // 0 মানে প্রথম কলাম
            string name = reader["ProductName"].ToString(); // নাম দিয়ে আনা ভালো
            decimal price = (decimal)reader["Price"];

            Console.WriteLine($"{id} \t {name} \t {price} Taka");
        }
    }
}
```

**Beginner Mistake:**
Reader ওপেন থাকা অবস্থায় কানেকশন দিয়ে অন্য কাজ করা যায় না। আগে Reader ক্লোজ করতে হয় (using ব্লক অটো ক্লোজ করে দেয়)।

### 🎓 Lesson 10: Connection Pooling - ট্রাফিক কমানো

**Concept:**
বারবার `new SqlConnection()` বানিয়ে `Open()` করা খুব ব্যয়বহুল (Expensive)। সার্ভারের অনেক রিসোর্স খায়।
ADO.NET ডিফল্টভাবে **Connection Pooling** ব্যবহার করে। মানে হলো, যখন তুমি `con.Close()` দাও, সে আসলে কানেকশনটা ছিঁড়ে ফেলে না। সে একটা পুলে (Pool) জমা রাখে। পরের বার যখন আবার `Open()` দাও, সে নতুন কানেকশন না বানিয়ে ওই পুল থেকে একটা অ্যাক্টিভ কানেকশন তোমাকে ধরিয়ে দেয়।

**কিভাবে বুঝব?**
Connection String এ এটা ডিফল্ট থাকে। চাইলে কনফিগার করা যায়:
`"Server=...; Max Pool Size=100; Min Pool Size=5;"`

**Tip:**
সব সময় `using` ব্লক ব্যবহার করো। তাহলে কানেকশন পুলিং ঠিকমত কাজ করবে। ম্যানুয়ালি হ্যান্ডেল করতে গেলে লিক হওয়ার চান্স থাকে।
