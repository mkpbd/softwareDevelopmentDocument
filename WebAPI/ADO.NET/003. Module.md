### 🎓 Lesson 16: Stored Procedures - প্রি-কুকড বিরিয়ানি (Efficiency)

**সহজ বাংলায়:**
আগে আমরা C# কোডের ভেতর `SELECT * FROM...` লিখতাম। এটাকে বলে "Raw Query"। এতে সমস্যা হলো, প্রতিবার কুয়েরি রান করার সময় SQL Server-কে ভাবতে হয় (Compiling/Parsing) কুয়েরিটা ঠিক আছে কিনা।

**Stored Procedure (SP)** হলো ডাটাবেসের ভেতরেই সেভ করে রাখা কুয়েরি। এটা আগে থেকেই কম্পাইল (Pre-compiled) করা থাকে।
**Analogy:**
- **Raw Query:** মেহমান আসার পর বাজার করে, কুটাবাছা করে বিরিয়ানি রান্না করা। (সময় বেশি লাগে)
- **Stored Procedure:** ফ্রিজ থেকে "প্রি-কুকড" বিরিয়ানি বের করে ওভেনে গরম দেওয়া। (সুপার ফাস্ট)

**Step 1: SQL Server এ SP বানানো (Run this in SSMS)**
```sql
CREATE PROCEDURE spGetAllProducts
AS
BEGIN
    -- ভালো প্র্যাকটিস: সবসময় SET NOCOUNT ON রাখা
    -- এতে ডাটাবেস "1 row affected" মেসেজটা পাঠায় না, নেটওয়ার্ক ট্রাফিক কমে।
    SET NOCOUNT ON; 
    
    SELECT * FROM Products;
END
```

**Step 2: C# দিয়ে SP কল করা**
```csharp
using (SqlConnection con = new SqlConnection(cs))
{
    // কুয়েরির জায়গায় শুধু SP এর নামটা দিব
    SqlCommand cmd = new SqlCommand("spGetAllProducts", con);
    
    // এই লাইনটা মেইন! বলতেই হবে এটা টেক্সট না, এটা SP
    cmd.CommandType = CommandType.StoredProcedure; 

    con.Open();
    using (SqlDataReader rdr = cmd.ExecuteReader())
    {
        while (rdr.Read())
        {
            Console.WriteLine(rdr["ProductName"]);
        }
    }
}
```

**Why Important?**
১. পারফর্মেন্স বাড়ে।
২. হ্যাকাররা সহজে কোড হ্যাক করতে পারে না (Security)।
৩. বারবার C# কোড চেঞ্জ করতে হয় না, শুধু DB তে SP চেঞ্জ করলেই হয়।

### 🎓 Lesson 17: Stored Procedure with Parameters

**Scenario:**
আমরা চাই এমন একটা SP বানাতে যেটা দিয়ে নতুন প্রোডাক্ট ইনসার্ট করা যাবে। মানে "কাচ্চি বিরিয়ানি" অর্ডার দিব, কিন্তু বলে দিব "আলু ছাড়া"। এই "আলু ছাড়া" টাই হলো প্যারামিটার।

**Step 1: SQL Script**
```sql
CREATE PROCEDURE spInsertProduct
    @PName NVARCHAR(100),
    @PPrice DECIMAL(18,2)
AS
BEGIN
    SET NOCOUNT ON;
    
    INSERT INTO Products (ProductName, Price, Stock)
    VALUES (@PName, @PPrice, 0); -- ডিফল্ট স্টক ০
END
```

**Step 2: C# Code**
```csharp
using (SqlConnection con = new SqlConnection(cs))
{
    SqlCommand cmd = new SqlCommand("spInsertProduct", con);
    cmd.CommandType = CommandType.StoredProcedure;

    // প্যারামিটার পাঠানো (ঠিক আগের মতই)
    cmd.Parameters.AddWithValue("@PName", "Wireless Mouse");
    cmd.Parameters.AddWithValue("@PPrice", 650.00);

    con.Open();
    cmd.ExecuteNonQuery();
    
    Console.WriteLine("Mama, SP diye product dhukse!");
}
```

**Mistake to Avoid:**
প্যারামিটারের নাম ভুল করা যাবে না। SQL এ `@PName` থাকলে C# এও `@PName` ই হতে হবে। স্পেলিং মিস্টেক করলে ক্র্যাশ খাবে।

### 🎓 Lesson 18: Transactions - সব হবে, নয়তো কিছুই না (All or Nothing)

**সবচেয়ে গুরুত্বপূর্ণ লেসন!**

**Scenario:**
ধরো তুমি বিকাশ থেকে মোবাইলে টাকা রিচার্জ করছ।
১. তোমার ব্যালেন্স থেকে ১০০ টাকা কাটল।
২. সার্ভার ক্র্যাশ করল।
৩. মোবাইলে টাকা ঢুকল না।
তোমার ১০০ টাকা হাওয়া! তুমি কি খুশি হবে? একদম না!

এখানেই আসে **Transaction**। এর নীতি হলো: **"হলে সব কাজ হবে, না হলে কিছুই হবে না।"** যদি মাঝপথে এরর খায়, তাহলে আগের সব কাজ ক্যান্সেল (Rollback) হয়ে যাবে।

**Real C# Code (Bank Transfer Logic):**
```csharp
using (SqlConnection con = new SqlConnection(cs))
{
    con.Open();

    // ১. ট্রানজ্যাকশন শুরু
    SqlTransaction transaction = con.BeginTransaction();

    try
    {
        // কমান্ডে ট্রানজ্যাকশন লিংক করে দিতে হবে
        SqlCommand cmd = new SqlCommand("UPDATE Accounts SET Balance = Balance - 500 WHERE UserID = 1", con, transaction);
        cmd.ExecuteNonQuery(); // ১ নম্বর ইউজারের টাকা কাটলাম

        // ইচ্ছা করে একটা এরর জেনারেট করি (বোঝার জন্য)
        // throw new Exception("Server Down Mama!");

        SqlCommand cmd2 = new SqlCommand("UPDATE Accounts SET Balance = Balance + 500 WHERE UserID = 2", con, transaction);
        cmd2.ExecuteNonQuery(); // ২ নম্বর ইউজারকে টাকা দিলাম

        // ২. সব ঠিক থাকলে কমিট (Confirm)
        transaction.Commit();
        Console.WriteLine("Taka Transfer Successful!");
    }
    catch (Exception ex)
    {
        // ৩. কোনো সমস্যা হলে রোলব্যাক (Undo)
        transaction.Rollback();
        Console.WriteLine("Error: " + ex.Message);
        Console.WriteLine("Don't worry, taka kete ney nai. Sob undo hoye geche.");
    }
}
```

**Key Point:**
`SqlCommand` তৈরির সময় `transaction` অবজেক্ট পাস করতে ভুলবে না। না হলে ওই কুয়েরিটা ট্রানজ্যাকশনের বাইরে চলে যাবে।

### 🎓 Lesson 19: Bulk Operations - একসাথে হাজার ডাটা (The Truck)

**সমস্যা:**
ধরো তোমার কাছে একটা এক্সেল ফাইল আছে যেখানে ১০,০০০ প্রোডাক্টের লিস্ট আছে। তুমি যদি `Loop` চালিয়ে ১০,০০০ বার `INSERT` কুয়েরি মারো, তাহলে ডাটাবেস কান্নাকাটি শুরু করবে। সময় লাগবে ১০ মিনিট।

**সমাধান: `SqlBulkCopy`**
এটা হলো লরি বা ট্রাকের মতো। একটা একটা ইট (Data) না নিয়ে, পুরো ট্রাক ভরে একসাথে ডাম্প করে দেয়। ১০,০০০ ডাটা ইনসার্ট হতে সময় লাগবে ১ সেকেন্ডেরও কম!

**Real C# Code:**
```csharp
// ধরো আমাদের একটা মেমোরি টেবিল (DataTable) রেডি আছে ১০,০০০ ডাটা সহ
DataTable dtProducts = GetHugeProductList(); // এটা একটা কাল্পনিক মেথড

using (SqlConnection con = new SqlConnection(cs))
{
    con.Open();

    // বাল্ক কপি অবজেক্ট
    using (SqlBulkCopy bulkCopy = new SqlBulkCopy(con))
    {
        // ডাটাবেসের কোন টেবিলে ঢোকাবো?
        bulkCopy.DestinationTableName = "Products";

        // কলাম ম্যাপিং (Source -> Destination)
        // যদি DataTable আর DB Table এর কলাম নাম সেম হয়, তাহলে এটা না দিলেও চলে।
        // কিন্তু দেওয়াটা গুড প্র্যাকটিস।
        bulkCopy.ColumnMappings.Add("Name", "ProductName");
        bulkCopy.ColumnMappings.Add("Price", "Price");
        bulkCopy.ColumnMappings.Add("Stock", "Stock");

        try
        {
            // ধুমধাম সব ডাটা ফেলে দাও
            bulkCopy.WriteToServer(dtProducts);
            Console.WriteLine("Mama! 10,000 products uploaded in blink of an eye!");
        }
        catch (Exception ex)
        {
            Console.WriteLine("Bulk copy error: " + ex.Message);
        }
    }
}
```

### 🎓 Lesson 20: Connection Pooling - ট্রাফিক জ্যাম কমানো (Deep Dive)

**ভাতিজা, এটা নিয়ে আগে একটু বলেছি, এখন বিস্তারিত জানব।**

**রিকশা স্ট্যান্ড এনালজি:**
ধরো ঢাকা শহরে ১ লাখ মানুষ রিকশায় চড়বে। এখন যদি ১ লাখ মানুষের জন্য ১ লাখ নতুন রিকশা বানানো হয়, রাস্তা জ্যামে আটকে যাবে।
এর বদলে কী হয়? ১০০০ রিকশা স্ট্যান্ডে থাকে। তুমি একটা নাও, গন্তব্যে যাও, ভাড়া দিয়ে রিকশা ছেড়ে দাও। সেই রিকশা আবার আরেকজন নেয়। এটাই **Pooling**।

**ADO.NET এর ব্যাকগ্রাউন্ড কাজ:**
তুমি যখন `con.Open()` দাও, ADO.NET চেক করে পুলে কোনো ফ্রি কানেকশন আছে কিনা।
- থাকলে সেটা দিয়ে দেয় (সময় লাগে ০.০০১ সেকেন্ড)।
- না থাকলে নতুন বানায় (সময় লাগে ০.৫ সেকেন্ড)।
কাজ শেষ হলে `con.Close()` দিলে কানেকশনটা নষ্ট না হয়ে পুলে ফিরে যায়।

**Connection Leak (ভয়ংকর বিপদ):**
তুমি যদি `con.Close()` না দাও, রিকশাটা আর স্ট্যান্ডে ফিরবে না। তুমি সেটা বাসায় নিয়ে আটকে রাখলে। এভাবে যদি ১০০ জন ১০০টা রিকশা আটকে রাখে, ১০১ নম্বর লোক আর রিকশা পাবে না (Error: Connection Timeout)।

**Configuration (Connection String):**
```text
"Server=...; Database=...; Max Pool Size=100; Min Pool Size=5;"
```
- `Max Pool Size=100`: সর্বোচ্চ ১০০টা কানেকশন একসাথে এক্টিভ থাকতে পারবে। এর বেশি হলে ইউজারকে ওয়েট করাবে।

**Raju Mama’s Tip:**
Pooling নিয়ে তোমার কিচ্ছু করতে হবে না, শুধু একটা নিয়ম মানবে: **"Always use `using` block for SqlConnection."**
`using` ব্লক গ্যারান্টি দেয় যে কাজ শেষে রিকশা (Connection) স্ট্যান্ডে (Pool) ফেরত যাবেই যাবে।
