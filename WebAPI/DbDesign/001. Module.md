### 🎓 Lesson 1: ডেটাবেস কী এবং কেন? (What is a Database?)

**সহজ বাংলা ব্যাখ্যা:**
ডেটাবেস হলো তথ্যের একটি সুশৃঙ্খল গুদামঘর। যেখানে তুমি ইচ্ছেমতো তথ্য রাখতে পারো, সাজাতে পারো এবং চোখের পলকে খুঁজে বের করতে পারো। তোমার মোবাইলের ফোনবুক, ফেসবুকের ফ্রেন্ডলিস্ট, ব্যাংকের হিসাব—সবই ডেটাবেস।

**🤣 Funny Real-life Analogy:**
মনে করো তোমার আম্মুর **মশলার কৌটাগুলো**।
- যদি আম্মু সব মশলা (লবণ, হলুদ, মরিচ) একটা বড় ড্রামে মিশিয়ে রাখে, তবে রান্না করার সময় "লবণ" খুঁজতে গিয়ে জান বের হয়ে যাবে! এটা হলো **Unorganized Data**।
- আর যদি আম্মু ছোট ছোট কৌটায় নাম লিখে তাকে তাকে সাজিয়ে রাখে, তবে চোখ বন্ধ করেও লবণের কৌটা পাওয়া যাবে। এটাই হলো **Database**।

**কেন ব্যবহার করব? (Why use DB instead of Excel?)**
এক্সেল শিট ছোটখাটো কাজের জন্য ঠিক আছে (যেমন: তোমার বাজারের ফর্দ)। কিন্তু যখন ডেটা লক্ষ লক্ষ হয়ে যায়, কিংবা একসাথে ১০০ জন মানুষ একই ফাইলে কাজ করতে চায়, তখন এক্সেল ক্র্যাশ করবে। ডেটাবেস সেখানে রকেটের গতিতে কাজ করে।

**Best Practice:**
শুরুতেই ঠিক করা যে তুমি কোন ধরনের ডেটাবেস শিখবে। আমরা শিখব **RDBMS** (Relational Database Management System) যেমন: SQL Server, MySQL, বা PostgreSQL। কারণ এগুলোই ইন্ডাস্ট্রিতে বেশি চলে।

**Mini Task:**
তোমার আশেপাশে ৩টি জিনিসের নাম খাতায় লেখো যা আসলে একটা ডেটাবেস। (Hint: স্কুলের হাজিরা খাতা)।

### 🎓 Lesson 2: টেবিল, রো এবং কলাম (Tables, Rows, Columns)

**সহজ বাংলা ব্যাখ্যা:**
ডেটাবেসের ভেতর তথ্যগুলো এলোমেলো থাকে না, এগুলো থাকে **Table**-এর ভেতর।
- **Table:** তথ্যের পাত্র (যেমন: Student Table)।
- **Column (Attribute):** তথ্যের ধরণ (যেমন: নাম, রোল, বয়স)। এগুলো হলো টেবিলের হেডিং।
- **Row (Record):** একেকটি মানুষের বা বস্তুর পুরো তথ্য।

**🤣 Funny Real-life Analogy:**
চিন্তা করো একটা **আলমারির** কথা।
- পুরো আলমারিটা হলো **Database**।
- আলমারির একেকটা ড্রয়ার হলো **Table** (একটা শার্টের ড্রয়ার, একটা প্যান্টের ড্রয়ার)।
- ড্রয়ারের ভেতর শার্টগুলো যেভাবে ভাজ করা থাকে, একেকটা শার্ট হলো **Row**।

**ASCII Table Example:**
ধরি, আমরা একটা চায়ের দোকানের (Tong er Dokan) বাকি খাতার টেবিল বানাচ্ছি।

| CustomerID (Column) | Name (Column) | Tea_Type (Column) | Bill_Due (Column) |
| :--- | :--- | :--- | :--- |
| 101 | Rahim | Rong Cha | 50 |
| 102 | Karim | Dudh Cha | 80 |
| 103 | Solim | Masala Cha | 120 |
| ^-- **(This represents a ROW)** | | | |

**SQL Example:**
চলো কোড দিয়ে একটা টেবিল বানাই।

```sql
CREATE TABLE Tea_Stall_Customers (
    CustomerID int,
    Name varchar(50),
    Tea_Type varchar(20),
    Bill_Due int
);
```

**Common Mistake:**
অনেকে কলামের নাম দেয় `Column1`, `Column2`। খবরদার! কলামের নাম দেখেই যেন বোঝা যায় ভেতরে কী আছে। যেমন: `FirstName`, `DateOfBirth`।

**Mini Task:**
তোমার পরিবারের সদস্যদের জন্য একটা টেবিল কল্পনা করো। সেখানে কী কী কলাম থাকবে? (যেমন: নাম, সম্পর্ক, বয়স)।

### 🎓 Lesson 3: ডেটা টাইপস - কোনটা কার জন্য? (Data Types)

**সহজ বাংলা ব্যাখ্যা:**
কম্পিউটার একটু বোকা, তাকে বলে দিতে হয় কোনটা কী ধরণের ডেটা। তুমি চাইলেই বয়সের ঘরে "করিম" লিখতে পারবে না, বা নামের ঘরে "৫০" লিখলে লজিক মিলবে না। একেই বলে **Data Type**।

**🤣 Funny Real-life Analogy:**
মনে করো তোমার কাছে ৩টি ব্যাগ আছে:
1. **পাটের বস্তা** (ভারী চালের জন্য)।
2. **পানির বোতল** (তরল জিনিসের জন্য)।
3. **মানিব্যাগ** (টাকার জন্য)।

তুমি কি পানির বোতলে চাল রাখবে? বা মানিব্যাগে পানি রাখবে? না!
তেমনি:
- সংখ্যার জন্য **INT** (Integer).
- লেখা বা নামের জন্য **VARCHAR** (Variable Character).
- তারিখের জন্য **DATE**.
- দশমিক সংখ্যার (টাকা) জন্য **DECIMAL** বা **FLOAT**.

**SQL Example:**

```sql
-- সঠিক ডেটা টাইপ ব্যবহার
CREATE TABLE Employee (
    EmpID int,              -- পূর্ণ সংখ্যা
    EmpName varchar(100),   -- নাম (অক্ষর)
    JoinDate date,          -- তারিখ
    Salary decimal(10, 2)   -- টাকা (দশমিক হতে পারে)
);
```

**When/Why to use:**
সঠিক ডেটা টাইপ না দিলে মেমোরি নষ্ট হয়। যেমন: কারো নামের জন্য যদি `VARCHAR(5000)` দিয়ে রাখো, তার মানে তুমি মশা মারতে কামান দাগাচ্ছো!

**Common Mistake:**
ফোন নাম্বারের জন্য `INT` ব্যবহার করা।
*কেন ভুল?* কারণ `INT` সামনের শূন্য (0) মুছে দেয়। `01711...` হয়ে যাবে `1711...`। তাই ফোন নাম্বারের জন্য সব সময় `VARCHAR` ব্যবহার করবে।

**Mini Task:**
নিচের তথ্যগুলোর জন্য কোন ডেটা টাইপ হবে বলো?
1. ফেইসবুক পাসওয়ার্ড
2. জুতার সাইজ
3. আজকের তাপমাত্রা
4. জন্ম তারিখ

---
সাবাশ! তুমি খুব দ্রুত শিখছো। আগের লেসনে আমরা টেবিল বানিয়েছি, এখন সেই টেবিল থেকে ডেটা বের করে আনা এবং ফিল্টার করা শিখব। ডেটাবেসের জগতে এই দুটো কাজই আমরা সারাদিন করি।

### 🎓 Lesson 4: প্রথম কুয়েরি - SELECT (ডেটা দেখা)

**সহজ বাংলা ব্যাখ্যা:**
`SELECT` মানে হলো "বেছে নেওয়া"। ডেটাবেসকে কোনো কিছু দেখাতে বললেই এই কমান্ড ব্যবহার করতে হয়। তুমি যখন ফেইসবুকে স্ক্রল করো, তখন আসলে ব্যাকগ্রাউন্ডে হাজার হাজার `SELECT` কুয়েরি রান হয়।

**🤣 Funny Real-life Analogy:**
মনে করো তুমি একটা **রেস্টুরেন্টে** গিয়েছো।
- মেনু কার্ডটা হলো তোমার **Table**।
- তুমি ওয়েটারকে বললে, "ভাই, আমাকে শুধু বার্গার আর কোক দিন।"
- এটা হলো: `SELECT Burger, Coke FROM Menu;`
- আর যদি তুমি খুব ক্ষুধার্ত হও এবং বলো, "মেনুতে যা আছে সব নিয়ে আসেন!", তখন সেটা হলো: `SELECT * FROM Menu;` (এখানে `*` বা স্টার মানে হলো "সবকিছু")।

**SQL Example:**
ধরি আমাদের `Students` নামে একটা টেবিল আছে।

**১. নির্দিষ্ট তথ্য দেখতে চাইলে:**
```sql
SELECT Name, Roll FROM Students;
```
*(শুধুমাত্র নাম এবং রোল দেখাবে)*

**২. সব তথ্য দেখতে চাইলে:**
```sql
SELECT * FROM Students;
```
*(নাম, রোল, বাবার নাম, ফোন নম্বর—সব কলাম দেখাবে)*

**ASCII Output (Result):**
`SELECT Name, Roll FROM Students;` চালালে এমন দেখাবে:

| Name | Roll |
| :--- | :--- |
| Rahim | 01 |
| Karim | 02 |
| Mina | 03 |

**When/Why to use:**
ডেটাবেস থেকে যেকোনো তথ্য পড়ার জন্য এটি ব্যবহার হয়। এটি ডেটাবেসের কোনো পরিবর্তন করে না, শুধু ডেটা রিড (Read) করে।

**Best Practice:**
প্রফেশনাল কাজে অকারণে `SELECT *` ব্যবহার করবে না। কারণ টেবিলে যদি ১০০টি কলাম থাকে আর ১ কোটি রো (Row) থাকে, তবে `*` দিলে সার্ভার স্লো হয়ে যাবে। সব সময় কলামের নাম উল্লেখ করবে (যেমন: `SELECT Name, Age...`)।

**Mini Task:**
ধরো `Mobile_Phone` নামে একটা টেবিল আছে। সেখান থেকে শুধু `Brand` এবং `Price` দেখার জন্য কুয়েরিটি কেমন হবে? খাতায় লেখো।

### 🎓 Lesson 5: ফিল্টারিং - WHERE ক্লজ (Filtering)

**সহজ বাংলা ব্যাখ্যা:**
`SELECT` দিয়ে তো সব ডেটা চলে আসে। কিন্তু আমাদের সব দরকার নেই। আমরা চাই **শর্তসাপেক্ষে** ডেটা। যেমন: "যাদের বাড়ি ঢাকায় শুধু তাদের দেখাও"। এই "শর্ত" জুড়ে দেওয়ার কাজটা করে `WHERE`।

**🤣 Funny Real-life Analogy:**
বিয়ের জন্য পাত্র/পাত্রী খোঁজা! 💍
ঘটককে বাবা বলে দিলেন:
- "আমাকে পাত্রের বায়োডাটা দেখান" (`SELECT BioData`)
- "কিন্তু..." (`FROM Matrimony_Table`)
- "শর্ত হলো: ছেলে সরকারি চাকরিজীবী হতে হবে **এবং** উচ্চতা ৫ ফুটের বেশি হতে হবে।"
- এই যে শর্ত দিলেন, এটাই হলো `WHERE` ক্লজ।

**SQL Example:**
ধরি আমাদের `Employee` টেবিলে সবার স্যালারি আছে।

**১. যাদের বেতন ৫০,০০০ এর বেশি:**
```sql
SELECT Name, Salary
FROM Employee
WHERE Salary > 50000;
```

**২. যার নাম 'Rahim':**
```sql
SELECT *
FROM Employee
WHERE Name = 'Rahim';
```
*(লক্ষ করো: নামের দুই পাশে কোটেশন মার্ক `' '` দিয়েছি। টেক্সট হলে এটা দিতেই হবে!)*

**৩. ঢাকায় থাকে না যারা (Not Equal):**
```sql
SELECT Name, City
FROM Employee
WHERE City <> 'Dhaka';
```

 `<> বা `!=` মানে হলো সমান নয়

**ASCII Table Example:**

`Employee` টেবিল:

| Name | City | Salary |
| --- | --- | --- |
| Rahim | Dhaka | 40000 |
| Karim | Chittagong | 60000 |
| Jobbar| Dhaka | 70000 |

Query: `SELECT Name FROM Employee WHERE City = 'Dhaka';`
**Output:**

| Name |
| :--- |
| Rahim |
| Jobbar|

**Common Mistakes:**
1.  **Text-এ কোটেশন না দেওয়া:** `WHERE Name = Rahim` লিখলে এরর খাবে। লিখতে হবে `WHERE Name = 'Rahim'`।
2.  **বানান ভুল:** ডেটাবেসে আছে `'Dhaka'`, তুমি খুঁজছ `'Daka'`। কম্পিউটার একদম এক্সাক্ট ম্যাচ খোঁজে, তাই পাবে না।

**Mini Task:**
তোমার `Friends` টেবিলে `Age` কলাম আছে। এখন সেই সব বন্ধুদের খুঁজে বের করার কুয়েরি লেখো যাদের `Age` ১৮ বছরের নিচে (`< 18`)।

চমৎকার! আমরা এখন ডেটা খুঁজে বের করতে পারি (SELECT) এবং ফিল্টার করতে পারি (WHERE)। কিন্তু ডেটাগুলো যদি উল্টাপাল্টা থাকে? অথবা যদি নতুন ডেটা টেবিলে ঢোকানোর দরকার হয়?

চিন্তা নেই! আজকের ক্লাসে আমরা শিখব কীভাবে ডেটাকে সুন্দর করে **সাজাতে হয়** এবং **নতুন ডেটা এন্ট্রি** দিতে হয়।

### 🎓 Lesson 6: সাজানো (ORDER BY) এবং ডুপ্লিকেট বাদ দেওয়া (DISTINCT)

**সহজ বাংলা ব্যাখ্যা:**
১. **ORDER BY:** ডেটাকে ছোট থেকে বড় (Ascending) বা বড় থেকে ছোট (Descending) ক্রমে সাজানো। যেমন: পরীক্ষার রেজাল্ট শিট।
২. **DISTINCT:** অনেকগুলো ডুপ্লিকেট ডেটা থেকে শুধুমাত্র ইউনিক (Unique) বা অনন্য ডেটাগুলো দেখা।

**🤣 Funny Real-life Analogy:**
- **ORDER BY:** স্কুলের অ্যাসেম্বলি লাইনের কথা মনে আছে? স্যাররা বলতেন, "সবাই ছোট থেকে বড় হয়ে দাঁড়াও!" এটা হলো `ORDER BY Height ASC`। আবার ক্লাসের ফার্স্ট বয় খোঁজার সময় নম্বরের ভিত্তিতে বড় থেকে ছোট সাজানো হয়, সেটা হলো `ORDER BY Marks DESC`।
- **DISTINCT:** ধরো তোমার বিয়ের দাওয়াত কার্ড বিলি হচ্ছে। তোমার বন্ধু 'রহিম' কে তুমি একবার দাওয়াত দিলে, তোমার বাবা একবার দিলেন, আবার তোমার ভাইও একবার দিলেন। কিন্তু বিয়েতে কি ৩টা রহিম আসবে? না, **রহিম একটাই**। এই ডুপ্লিকেট বাদ দিয়ে আসল লিস্ট বের করাই হলো `DISTINCT`।

**SQL Example:**

**১. সাজানো (Sorting):**
আমরা স্যালারি অনুযায়ী বড়লোক থেকে গরিব সাজাব।
```sql
SELECT Name, Salary
FROM Employee
ORDER BY Salary DESC;
```
*(DESC = Descending বা বড় থেকে ছোট। ছোট থেকে বড় চাইলে ASC বা কিছুই না লিখলেও চলে, কারণ ডিফল্ট হলো ASC)*

**২. ডুপ্লিকেট বাদ দেওয়া (Unique Values):**
আমাদের এমপ্লয়িরা কোন কোন শহরে থাকে, শুধু শহরের নামগুলো চাই (একই নাম বারবার নয়)।
```sql
SELECT DISTINCT City
FROM Employee;
```

**ASCII Table Example:**
**Raw Data:**

| Name | City | Salary |
| :--- | :--- | :--- |
| A | Dhaka | 500 |
| B | Khulna | 900 |
| C | Dhaka | 200 |

**Query:** `SELECT * FROM Table ORDER BY Salary ASC;`
**Result:**

| Name | City | Salary |
| :--- | :--- | :--- |
| C | Dhaka | 200 |
| A | Dhaka | 500 |
| B | Khulna | 900 |

**Best Practice:**
সবসময় `ORDER BY` কুয়েরির একদম শেষে লিখতে হয়। মাঝখানে লিখলে এরর খাবে!

**Mini Task:**
তোমার `Result_Sheet` টেবিলে সবার মার্কস আছে। এখন এমন একটা কুয়েরি লেখো যেন যার মার্কস সবচেয়ে কম, সে সবার ওপরে থাকে (ফেল করা ছাত্রকে আগে খোঁজা!)।

### 🎓 Lesson 7: ডেটা ঢোকানো (INSERT INTO)

**সহজ বাংলা ব্যাখ্যা:**
এতক্ষণ আমরা শুধু ডেটা দেখেছি। এখন আমরা **নতুন ডেটা তৈরি** করব। কোনো টেবিলে নতুন রেকর্ড বা রো (Row) যুক্ত করার কমান্ড হলো `INSERT INTO`।

**🤣 Funny Real-life Analogy:**
ফোনে নতুন কন্টাক্ট সেভ করা। 📱
তুমি যখন নতুন কারো নম্বর সেভ করো, তখন কী করো?
১. **Name** এর ঘরে নাম লেখো।
২. **Number** এর ঘরে নম্বর লেখো।
৩. **Save** বাটনে চাপ দাও।

SQL-এ `INSERT INTO` ঠিক এই কাজটাই করে। তুমি বলে দাও কোন কলামে কী ভ্যালু বসবে।

**SQL Example:**
ধরি আমাদের `Students` টেবিলে (Name, Age, Class) কলাম আছে।

**১. নিয়ম মেনে ডেটা এন্ট্রি:**
```sql
INSERT INTO Students (Name, Age, Class)
VALUES ('Mintu', 14, 8);
```

**২. মাল্টিপল ডেটা এন্ট্রি (একসাথে অনেকে):**
```sql
INSERT INTO Students (Name, Age, Class)
VALUES
('Boltu', 13, 8),
('Poltu', 15, 9);
```

**Common Mistakes (খুব সাবধান!):**
১. **সাজসজ্জা ভুল:** কলামের নামের সিরিয়াল আর ভ্যালুর সিরিয়াল মিল থাকতে হবে।
   - *ভুল:* `(Name, Age)` -> `VALUES (14, 'Mintu')`
   - এখানে নামের ঘরে বয়স ঢুকে যাবে, আর বয়সের ঘরে নাম! কম্পিউটার কনফিউজড হয়ে এরর দিবে।
২. **কোটেশন মিস:** টেক্সট বা স্ট্রিং ভ্যালুর দুই পাশে কোটেশন `' '` না দিলে কাজ করবে না। সংখ্যার জন্য কোটেশন লাগে না।

**When/Why to use:**
যেকোনো রেজিস্ট্রেশন ফর্ম (যেমন ফেইসবুক সাইন আপ), শপিং কার্টে পণ্য যোগ করা—সব জায়গাতেই ব্যাকগ্রাউন্ডে `INSERT` কুয়েরি চলে।

**Mini Task:**
ধরো তোমার `My_Dreams` নামে একটা টেবিল আছে, যেখানে `Dream_Name` (লেখা) এবং `Target_Year` (সংখ্যা) নামে দুটি কলাম আছে। সেখানে "Learn SQL" এবং "2025" ইনসার্ট করার কোডটি খাতায় লেখো।

---

চমৎকার! তুমি এখন ডেটা দেখতে পারো (SELECT) এবং ডেটা ঢোকাতে পারো (INSERT)।

কিন্তু জীবন তো আর সরল রেখা নয়, ভুল তো মানুষই করে। তাই না? ভুল হলে সেটা **সংশোধন (UPDATE)** করতে হয়, আর অপ্রয়োজনীয় জিনিস **ফেলে দিতে (DELETE)** হয়।

তবে সাবধান! আজকের লেসন দুটো খুবই **পাওয়ারফুল কিন্তু বিপজ্জনক**। ভুল করলেই সর্বনাশ! ⚠️

### 🎓 Lesson 8: ডেটা আপডেট করা (UPDATE)

**সহজ বাংলা ব্যাখ্যা:**
টেবিলে আগের কোনো ডেটা আছে, কিন্তু সেটা ভুল বা পুরনো হয়ে গেছে। সেটাকে ঠিক করাই হলো `UPDATE`। যেমন: কারো নামের বানান ভুল ছিল, কিংবা কারো স্যালারি বেড়েছে।

**🤣 Funny Real-life Analogy:**
ফেইসবুকের **Relationship Status** পরিবর্তনের কথা ভাবো! 💔➡️💍
- আগে ছিল: **"Single"**
- এখন প্রেম হয়েছে, তাই করতে হবে: **"In a Relationship"**
- এই যে পুরনো স্ট্যাটাস মুছে নতুনটা বসালে, এটাই `UPDATE`।

**SQL Example:**
ধরি `Employee` টেবিলে 'Rahim'-এর বেতন বাড়াতে হবে।

```sql
UPDATE Employee
SET Salary = 55000
WHERE Name = 'Rahim';
```
*(অর্থ: রহিম যেখানে আছে, সেখানে স্যালারি ৫৫,০০০ করে দাও)*

**⚠️ The "Silent Killer" Mistake (মহা বিপদ):**
সবচেয়ে বড় ভুল যেটা জুনিয়ররা করে—`WHERE` ক্লজ দিতে ভুলে যাওয়া!

যদি তুমি লেখো:
```sql
UPDATE Employee
SET Salary = 500;
```
*(এখানে আমি `WHERE` দেইনি)*

**ফলাফল:** কোম্পানির সিইও (CEO) থেকে শুরু করে পিয়ন পর্যন্ত **সবার** বেতন এখন ৫০০ টাকা হয়ে যাবে! তোমার চাকরি তো যাবেই, কোম্পানিও ডুবে যাবে। 😱

**ASCII Table Example:**

**Before Update:**

| ID | Name | Salary |
| :--- | :--- | :--- |
| 1 | Rahim | 40000 |

**After Update (Rahim Only):**

| ID | Name | Salary |
| :--- | :--- | :--- |
| 1 | Rahim | **55000** |

**Best Practice:**
আপডেট কুয়েরি চালানোর আগে সবসময় সেই `WHERE` কন্ডিশন দিয়ে একবার `SELECT` করে দেখে নিবে যে, তুমি সঠিক মানুষটাকেই টার্গেট করছ কি না।

**Mini Task:**
তোমার `Friends` টেবিলে বন্ধুর নাম ভুল করে 'Kuddus' লেখা হয়েছে। তার আসল নাম 'Kaddus'। এটা ঠিক করার কুয়েরি খাতায় লেখো।

### 🎓 Lesson 9: ডেটা ডিলিট করা (DELETE - বিপদজনক!)

**সহজ বাংলা ব্যাখ্যা:**
টেবিল থেকে কোনো রো (Row) বা রেকর্ড চিরতরে মুছে ফেলার জন্য `DELETE` ব্যবহার করা হয়। এটা রিসাইকেল বিন বা ট্র্যাশ ফোল্ডারে যায় না, একদম হাওয়া হয়ে যায়!

**🤣 Funny Real-life Analogy:**
মনে করো তোমার এক্স-গার্লফ্রেন্ড বা বয়ফ্রেন্ডের ছবি ডিলিট করা। 🗑️
- রাগের মাথায় "Delete" চাপলে।
- কিছুক্ষণ পর মনে পড়ল, "আরে! ছবিটা তো সুন্দর ছিল!"
- কিন্তু আর ফিরে পাওয়া সম্ভব না (যদি না ব্যাকআপ থাকে)। ডেটাবেসের `DELETE` ঠিক এতটাই নিষ্ঠুর।

**SQL Example:**
ধরি আমাদের `Students` টেবিল থেকে রোল নম্বর ১০-কে বের করে দেব।

```sql
DELETE FROM Students
WHERE Roll = 10;
```

**⚠️ The "Thanos Snap" Mistake (ভয়ংকর বিপদ):**
এখানেও যদি তুমি `WHERE` দিতে ভুলে যাও...

```sql
DELETE FROM Students;
```

**ফলাফল:** থ্যানোসের তুড়ির মতো এক নিমেষে স্কুলের **সব ছাত্রের** নাম গায়েব হয়ে যাবে! টেবিল থাকবে, কিন্তু টেবিল ফাঁকা হয়ে যাবে। ☠️

**ASCII Table Example:**

**Before Delete:**

| ID | Name | Type |
| :--- | :--- | :--- |
| 1 | Hero | Good |
| 2 | Villain| Bad |

**Query:** `DELETE FROM Table WHERE Type = 'Bad';`

**After Delete:**

| ID | Name | Type |
| :--- | :--- | :--- |
| 1 | Hero | Good |
*(Villain গায়েব)*

**Senior Architect Tip (Pro Level):**
বাস্তব প্রজেক্টে আমরা সচরাচর `DELETE` কমান্ড চালাই না। আমরা একটা কলাম রাখি `IsActive` বা `IsDeleted` নামে।
- যখন ডিলিট করতে হয়, আমরা আসলে `UPDATE` করি: `SET IsDeleted = 1`।
- এতে ডেটা ইউজারের সামনে থেকে চলে যায়, কিন্তু ডেটাবেসে থেকে যায় (যাতে ভবিষ্যতে রিকভার করা যায়)। একে বলে **Soft Delete**।

**Mini Task:**
তোমার `Bazaar_List` টেবিলে 'Alu', 'Potol', 'Piaj' আছে। বাজার করা শেষ, তাই 'Alu' লিস্ট থেকে ডিলিট করার কুয়েরি লেখো। সাবধান! `WHERE` দিতে ভুলবে না!

### 🎓 Lesson 10: NULL ভ্যালু কী? (শূন্য নাকি ফাঁকা?)

**সহজ বাংলা ব্যাখ্যা:**
অনেক নতুন শিক্ষার্থী ভাবে `NULL` মানে বুঝি `0` (শূন্য) বা ফাঁকা স্পেস (Space)। **একদম ভুল!**

- **0 (Zero):** এটি একটি নির্দিষ্ট সংখ্যা। (তোমার পকেটে ০ টাকা আছে, মানে পকেট আছে কিন্তু টাকা নেই)।
- **Empty String (' '):** এটি একটি টেক্সট, কিন্তু ভেতরে কিছু লেখা নেই। (একটা সাদা কাগজ)।
- **NULL:** এর মানে হলো **"অজানা" (Unknown)** বা **"অস্তিত্বহীন" (Does not exist)**। ডেটাবেস জানেই না এখানে কী আছে।

**🤣 Funny Real-life Analogy:**
ধরো পরীক্ষার রেজাল্ট শিট: 📝
1. **করিম:** পরীক্ষায় অংশ নিয়েছে এবং কিছুই পারেনি। সে পেয়েছে **০ (Zero)**।
2. **রহিম:** পরীক্ষার দিন অসুস্থ ছিল, তাই আসেইনি। তার মার্কস হলো **NULL**।

এখন যদি তুমি করিম আর রহিমের গড় (Average) করো:
- করিমের ০ যোগ হবে।
- কিন্তু রহিমের NULL কি যোগ হবে? না! কারণ সে তো পরীক্ষাই দেয়নি।

**আরেকটি উদাহরণ:**
- **Zero (0):** টয়লেট টিস্যুর রোল আছে, কিন্তু কাগজ শেষ।
- **NULL:** টয়লেট টিস্যুর হোল্ডারই নাই! 😂

**ASCII Table Example:**
`Employee` টেবিলে কার ফোন নম্বর আছে আর কার নেই।

| ID | Name | Phone_Number | Comment |
| :--- | :--- | :--- | :--- |
| 1 | Pintu | 01711... | নম্বর আছে |
| 2 | Mintu | 0 | নম্বরটি ভুল করে ০ দিয়েছে |
| 3 | Jhontu | NULL | **এর কোনো ফোনই নেই!** |

**SQL Example:**

**১. NULL ভ্যালু খোঁজা (সঠিক নিয়ম):**
তুমি যদি লেখো `WHERE Phone = NULL`, এটা কাজ করবে না! কারণ NULL কোনো ভ্যালু না যে তুমি `Equal (=)` দিয়ে ম্যাপ করবে। তোমাকে লিখতে হবে `IS NULL`।

```sql
-- যাদের ফোন নম্বর ডেটাবেসে নেই
SELECT * FROM Employee
WHERE Phone_Number IS NULL;
```

**২. যারা NULL নয় (IS NOT NULL):**
```sql
-- যাদের ফোন নম্বর আছে
SELECT * FROM Employee
WHERE Phone_Number IS NOT NULL;
```

**Common Mistake (The "Equal" Trap):**
সবচেয়ে বেশি যে ভুলটা সবাই করে:
❌ `SELECT * FROM Table WHERE Column = NULL;` (ভুল!)
✅ `SELECT * FROM Table WHERE Column IS NULL;` (সঠিক!)

**Why/When to use:**
যখন কোনো তথ্য তোমার কাছে এই মুহূর্তে নেই, কিন্তু ভবিষ্যতে আসতে পারে, তখন সেই ঘরটি `NULL` রাখা হয়। যেমন: একজন ইউজার সাইন-আপ করল কিন্তু এখনো প্রোফাইল পিকচার দেয়নি। তখন `Profile_Pic` কলামে `NULL` থাকবে।

**A Scary Fact about NULL:**
গণিতে: `5 + 0 = 5`।
কিন্তু ডেটাবেসে: `5 + NULL = NULL`।
*(কারণ: ৫ এর সাথে "অজানা" কিছু যোগ করলে ফলাফল "অজানাই" থাকে!)*

**Mini Task:**
