### 🎓 Lesson 21: Aggregate Functions (হিসাব-নিকাশের জাদু)

**সহজ বাংলা ব্যাখ্যা:**
Aggregate মানে হলো "সমষ্টি"। যখন অনেকগুলো রো (Row) বা ডেটা থেকে হিসাব করে **একটি মাত্র** ফলাফল বের করতে হয়, তখন এই ফাংশনগুলো ব্যবহার করা হয়।
SQL-এ প্রধান ৫টি জাদুকর হলো:
1.  **COUNT:** গোনা (কয়টা আছে?)
2.  **SUM:** যোগ করা (মোট কত?)
3.  **AVG:** গড় বের করা (গড় কত?)
4.  **MAX:** সবচেয়ে বড়টা বের করা।
5.  **MIN:** সবচেয়ে ছোটটা বের করা।

**🤣 Funny Real-life Analogy:**
ক্রিকেট খেলার স্কোরবোর্ড! 🏏
সাকিব আল হাসানের ক্যারিয়ার স্ট্যাটাস:
- **COUNT:** সে কয়টা ম্যাচ খেলেছে? (Total Matches)
- **SUM:** মোট কত রান করেছে? (Total Runs)
- **AVG:** প্রতি ম্যাচে গড় রান কত? (Batting Average)
- **MAX:** তার সর্বোচ্চ স্কোর কত? (Highest Score)
- **MIN:** সবচেয়ে কম কত রানে আউট হয়েছে? (Duck/0)

**SQL Example:**
ধরি `Sales` টেবিলে আজকের বিক্রির হিসাব আছে।

```sql
-- ১. মোট কয়টা অর্ডার পড়েছে?
SELECT COUNT(*) FROM Sales;

-- ২. আজ টোটাল কত টাকার বিক্রি হলো?
SELECT SUM(Amount) FROM Sales;

-- ৩. গড় বিক্রি কত টাকা?
SELECT AVG(Amount) FROM Sales;

-- ৪. সবচেয়ে বড় ও ছোট অর্ডার কত টাকার ছিল?
SELECT MAX(Amount), MIN(Amount) FROM Sales;
```

**ASCII Output:**
`Sales` Table:

| ID | Amount |
| :--- | :--- |
| 1 | 500 |
| 2 | 1000 |
| 3 | 1500 |

Query: `SELECT SUM(Amount) FROM Sales;`
**Result:**

| (No Column Name) |
| :--- |
| 3000 |

**Common Mistake:**
`SELECT Name, MAX(Salary) FROM Employee;` — এটা লিখলে এরর খাবে!
*কেন?* কারণ `MAX(Salary)` একটা রেজাল্ট দেয় (যেমন: ৫০,০০০), কিন্তু `Name` তো অনেকের হতে পারে। ডেটাবেস কনফিউজড হয়ে যায় যে কার নাম দেখাবে। (এর সমাধান পরের লেসনে!)

### 🎓 Lesson 22: GROUP BY এবং HAVING

**সহজ বাংলা ব্যাখ্যা:**
১. **GROUP BY:** যখন আমরা ডেটাকে বিভিন্ন গ্রুপ বা দলে ভাগ করে হিসাব করতে চাই। যেমন: "ছেলেদের মোট নম্বর কত আর মেয়েদের মোট নম্বর কত?"
২. **HAVING:** গ্রুপের ওপর ফিল্টার বা শর্ত বসানো। `WHERE` কাজ করে রো-এর ওপর, আর `HAVING` কাজ করে গ্রুপের ওপর।

**🤣 Funny Real-life Analogy:**
বিয়ে বাড়ির খাওয়ার টেবিল! 🍛
- **GROUP BY:** মেহমানদের ভাগ করে বসানো হলো—বরপক্ষ এক টেবিলে, কনেপক্ষ এক টেবিলে, আর বন্ধুদের গ্রুপ এক টেবিলে।
- **Aggregate:** এখন প্রতি টেবিলে কয়টা করে রোস্ট দেওয়া হলো তা গোনা হচ্ছে (`COUNT`).
- **HAVING:** ওয়েটারকে বলা হলো, "যেই টেবিলে ১০ জনের বেশি মানুষ আছে (`HAVING Count > 10`), শুধু সেই টেবিলেই এক্সট্রা দই দাও।"

**SQL Example:**
ধরি `Employee` টেবিলে `Department` এবং `Salary` আছে। আমরা দেখতে চাই কোন ডিপার্টমেন্টে মোট কত বেতন দেওয়া হয়।

```sql
SELECT Department, SUM(Salary) as Total_Cost
FROM Employee
GROUP BY Department;
```

**HAVING এর ব্যবহার:**
এখন আমরা শুধু সেই ডিপার্টমেন্ট দেখতে চাই যাদের মোট খরচ ১ লাখ টাকার বেশি।

```sql
SELECT Department, SUM(Salary) as Total_Cost
FROM Employee
GROUP BY Department
HAVING SUM(Salary) > 100000;
```

**⚠️ The Great Confusion (WHERE vs HAVING):**
এটা ইন্টারভিউতে ১০০% জিজ্ঞেস করবে!
- **WHERE:** ডেটা গ্রুপ করার **আগে** ফিল্টার করে। (যেমন: শুধু যারা ঢাকায় থাকে তাদের নাও)।
- **HAVING:** ডেটা গ্রুপ করার **পরে** রেজাল্টের ওপর ফিল্টার করে। (যেমন: যোগফল বের করার পর চেক করো)।

**Code Example (Both together):**
```sql
SELECT City, COUNT(*)
FROM Customers
WHERE Age > 18        -- আগে ফিল্টার: শুধু প্রাপ্তবয়স্করা
GROUP BY City         -- তারপর গ্রুপিং: শহর অনুযায়ী ভাগ করো
HAVING COUNT(*) >= 5; -- শেষে ফিল্টার: যেই শহরে অন্তত ৫ জন কাস্টমার আছে
```

**Best Practice:**
`SELECT`-এ তুমি যেই কলামগুলোর নাম লিখবে (Aggregate Function ছাড়া), সেই সবগুলো কলামকে অবশ্যই `GROUP BY`-এর নিচে লিখতে হবে। না হলে এরর খাবে!

**Mini Task:**

তোমাকে বের করতে হবে: কোন কাস্টমার মোট কত টাকার বাজার করেছে? (Hint: `GROUP BY CustomerName` এবং `SUM(BillAmount)` ব্যবহার করো)।

### 🎓 Lesson 23: JOINS পরিচিতি - INNER JOIN

**সহজ বাংলা ব্যাখ্যা:**
`INNER JOIN` হলো সবচেয়ে কমন জয়েন। এটি দুটি টেবিল থেকে **শুধুমাত্র সেই ডেটাগুলোই** দেখাবে, যা দুই টেবিলে **মিল (Match)** আছে।
যদি কোনো ডেটা এক টেবিলে থাকে কিন্তু অন্য টেবিলে না থাকে, তবে `INNER JOIN` তাকে নির্দয়ভাবে বাদ দিয়ে দেবে।

**🤣 Funny Real-life Analogy:**
**ঘটক পাখির ভাই এবং বিয়ে!** 💍
- **Table A (পাত্র পক্ষ):** ১০ জন পাত্র রেডি।
- **Table B (পাত্রী পক্ষ):** ১০ জন পাত্রী রেডি।
- **Condition (ON):** পাত্রের চাহিদার সাথে পাত্রীর চাহিদা মিলতে হবে।
- **INNER JOIN:** শুধুমাত্র সেই ৩টি জুটির নাম দেখাবে যাদের বিয়ে ঠিক হয়েছে (Match Found)। বাকি ১৭ জন (যাদের মিলল না), তারা লিস্ট থেকে বাদ! তারা মন খারাপ করে বাড়ি চলে যাবে।

**ASCII Table Example:**

**Table A: Customers** (ক্রেতা)
| CustID | Name |
| :--- | :--- |
| 1 | Rahim |
| 2 | Karim |
| 3 | **Solim** | <-- (বেচারা কিছুই কেনেনি)

**Table B: Orders** (অর্ডার)
| OrderID | Item | CustID |
| :--- | :--- | :--- |
| 101 | Burger | 1 |
| 102 | Pizza | 2 |

**Query:** `Customers INNER JOIN Orders`
**Result:**
| Name | Item |
| :--- | :--- |
| Rahim | Burger |
| Karim | Pizza |

*(লক্ষ করো: সলিম (Solim) লিস্টে নেই! কারণ সে অর্ডার টেবিলে অনুপস্থিত। ইনার জয়েন তাকে পাত্তা দেয়নি।)*

**SQL Example:**
```sql
SELECT Customers.Name, Orders.Item
FROM Customers
INNER JOIN Orders
ON Customers.CustID = Orders.CustID;
```
*(এখানে `ON` এর পরে আমরা বলে দিচ্ছি কোন চাবি (Key) দিয়ে তালা খুলতে হবে)*

**When/Why to use:**
যখন তুমি চাও রেজাল্টে কোনো **NULL** বা ফাঁকা ভ্যালু না আসুক। যেমন: "শুধুমাত্র যারা অর্ডার করেছে, তাদের নাম দেখাও।"

**Mini Task:**
`Student` টেবিল এবং `Exam_Result` টেবিল আছে। এমন ছাত্রদের নাম ও নম্বর বের করো যারা পরীক্ষায় অংশ নিয়েছে (যারা অ্যাবসেন্ট ছিল, তারা আসবে না)। কোন জয়েন ব্যবহার করবে? (উত্তর: INNER JOIN)।

### 🎓 Lesson 24: LEFT JOIN এবং RIGHT JOIN

**সহজ বাংলা ব্যাখ্যা:**
এখানেই আসল মজা!
- **LEFT JOIN:** বাম পাশের টেবিলের **সবাইকে** দেখাবে। ডান পাশের টেবিলে যদি ম্যাচ থাকে ভালো, না থাকলে সেখানে **NULL** বসিয়ে দেবে। (বাম পাশ হলো বস!)
- **RIGHT JOIN:** ঠিক উল্টো। ডান পাশের টেবিলের সবাইকে দেখাবে। বাম পাশে না পেলে NULL।

**🤣 Funny Real-life Analogy:**
**বিয়ের দাওয়াত!** 💌
- **LEFT JOIN (তুমি যখন হোস্ট):**
তুমি তোমার সব বন্ধুকে (Left Table) দাওয়াত দিলে।
কেউ কেউ গিফট (Right Table) নিয়ে এল, কেউ কেউ খালি হাতে এল।
রেজাল্ট শিটে **তোমার সব বন্ধুর নাম** থাকবে। যারা গিফট এনেছে তাদের গিফটের নাম থাকবে, আর যারা আনেনি তাদের নামের পাশে লেখা থাকবে **"NULL"** (মানে কিছুই দেয়নি, ফকিন্নির দল! 😜)।

**ASCII Table Example (LEFT JOIN):**
(সলিমকে মনে আছে? যে কিছুই কেনেনি?)

**Query:** `Customers LEFT JOIN Orders`
**Result:**
| Name | Item |
| :--- | :--- |
| Rahim | Burger |
| Karim | Pizza |
| **Solim** | **NULL** |

*(দেখো! সলিম কিছুই কেনেনি, তবুও সে লিস্টে এসেছে। কিন্তু আইটেমের ঘরে NULL বসেছে। কারণ এটা LEFT JOIN, আর কাস্টমার টেবিল বামে ছিল।)*

**SQL Example:**
```sql
SELECT Customers.Name, Orders.Item
FROM Customers         -- এটা বাম (Left) টেবিল
LEFT JOIN Orders       -- এটা ডান (Right) টেবিল
ON Customers.CustID = Orders.CustID;
```

**RIGHT JOIN:**
বাস্তব জীবনে `RIGHT JOIN` খুব কম ব্যবহার হয়। কারণ তুমি চাইলেই টেবিল অদলবদল করে `LEFT JOIN` দিয়েই কাজ সারতে পারো।
*টিপস:* প্রফেশনালরা সবসময় `LEFT JOIN` ব্যবহার করতেই পছন্দ করে।

**Best Practice:**
জয়েন করার সময় সবসময় টেবিলের **Alias** (ডাকনাম) ব্যবহার করবে। কোড ছোট ও সুন্দর দেখাবে।
উদাহরণ:
```sql
SELECT c.Name, o.Item
FROM Customers AS c      -- Customers এর ডাকনাম c
LEFT JOIN Orders AS o    -- Orders এর ডাকনাম o
ON c.CustID = o.CustID;
```

**Common Mistake:**
`LEFT JOIN` করার পর `WHERE` ক্লজে ডান টেবিলের কলামে ফিল্টার করা।
যেমন: `WHERE o.Item = 'Burger'`। এটা করলে `LEFT JOIN` ভেঙে `INNER JOIN`-এর মতো আচরণ শুরু করবে (কারণ NULL ভ্যালুগুলো ফিল্টার হয়ে বাদ পড়ে যাবে)।

**Mini Task:**
তোমার `Employees` (বাম) টেবিল এবং `Projects` (ডান) টেবিল আছে।
ম্যানেজার বলল: "সব এমপ্লয়ির নাম দেখাও, এবং তারা কে কোন প্রজেক্টে আছে সেটাও দেখাও। যাদের প্রজেক্ট নেই, তাদের নামের পাশে ফাঁকা (NULL) থাকুক।"
তুমি এখানে কোন জয়েন ব্যবহার করবে? (উত্তর: LEFT JOIN)।

---

স্বাগতম আমাদের **জয়েন পার্টির (Join Party)** শেষ পর্বে! 🥳

আগের পর্বে আমরা দেখেছি কীভাবে কমন ডেটা (INNER) এবং একপাক্ষিক ডেটা (LEFT/RIGHT) বের করতে হয়। কিন্তু যদি আমরা **সবাইকে** চাই? অথবা যদি **প্রত্যেককে প্রত্যেকের সাথে** মিশিয়ে দিতে চাই?

আজকের লেসন দুটি একটু অদ্ভুত, কিন্তু লজিক ক্লিয়ার থাকলে খুবই মজার। চলো **Lesson 25** এবং **Lesson 26** শিখে ফেলি!

### 🎓 Lesson 25: FULL OUTER JOIN এবং CROSS JOIN

এই লেসনে আমরা দুটি ভিন্ন দানবকে দেখব।

#### **১. FULL OUTER JOIN (সবাই আসবে!)**

**সহজ বাংলা ব্যাখ্যা:**
এটি হলো `LEFT JOIN` এবং `RIGHT JOIN`-এর যোগফল।
বাম টেবিলের সব ডেটা আসবে, ডান টেবিলের সব ডেটা আসবে। যেখানে মিলবে সেখানে ডেটা দেখাবে, আর যেখানে মিলবে না সেখানে দুই পাশেই **NULL** দেখাবে। কেউ বাদ যাবে না!

**🤣 Funny Real-life Analogy:**
**ডিভোর্সের পর বাচ্চার জন্মদিনের পার্টি!** 🎂
- বাবার বাড়ির সবাই এসেছে (Left Table)।
- মায়ের বাড়ির সবাই এসেছে (Right Table)।
- যারা কমন আত্মীয় (উভয় পক্ষ চেনে), তারা মিলেমিশে গল্প করছে।
- যারা শুধু বাবার আত্মীয়, তারা এক কোণায় খাচ্ছে (মায়ের দিক NULL)।
- যারা শুধু মায়ের আত্মীয়, তারা অন্য কোণায় খাচ্ছে (বাবার দিক NULL)।
কিন্তু পার্টিতে **সবাই** উপস্থিত!

**SQL Example:**
```sql
SELECT Customers.Name, Orders.Item
FROM Customers
FULL OUTER JOIN Orders
ON Customers.CustID = Orders.CustID;
```
*(নোট: MySQL-এ সরাসরি FULL JOIN নেই, সেখানে LEFT JOIN আর RIGHT JOIN কে `UNION` করে এটা বানাতে হয়। কিন্তু SQL Server বা Oracle-এ এটা সরাসরি কাজ করে।)*

---

#### **২. CROSS JOIN (গণিতের গুণ)**

**সহজ বাংলা ব্যাখ্যা:**
এটাকে বলা হয় **Cartesian Product**। এখানে কোনো `ON` কন্ডিশন বা শর্ত থাকে না।
প্রথম টেবিলের **প্রতিটি** রো, দ্বিতীয় টেবিলের **প্রতিটি** রো-এর সাথে জোড়া লাগবে।
রেজাল্ট হবে: (Table A-এর রো সংখ্যা) গুন (Table B-এর রো সংখ্যা)।

**🤣 Funny Real-life Analogy:**
**লটারির টিকিট বা টি-শার্টের কম্বিনেশন!** 👕
ধরো তোমার কাছে ২টা রঙের টি-শার্ট আছে (লাল, নীল) এবং ৩টা সাইজ আছে (S, M, L)।
টোটাল কম্বিনেশন কয়টি?
- লাল-S, লাল-M, লাল-L
- নীল-S, নীল-M, নীল-L
মোট ৬টি। এটাই CROSS JOIN। সব কালারের সাথে সব সাইজ মিশিয়ে দেওয়া।

**ASCII Table Example (CROSS JOIN):**

**Table A: Color**

| Color |
| :--- |
| Red |
| Blue |

**Table B: Size**

| Size |
| :--- |
| S |
| M |

**Query:** `SELECT * FROM Color CROSS JOIN Size;`

**Result (2x2 = 4 Rows):**

| Color | Size |
| :--- | :--- |
| Red | S |
| Red | M |
| Blue | S |
| Blue | M |

**Warning (বিপদ!):**
যদি টেবিল A-তে ১০০০ রো থাকে এবং টেবিল B-তে ১০০০ রো থাকে, তবে রেজাল্ট হবে ১,০০০,০০০ (দশ লক্ষ) রো! সার্ভার ক্র্যাশ করার জন্য এটি যথেষ্ট। তাই কারণ ছাড়া এটা ব্যবহার করবে না।

**Mini Task:**
তোমার কাছে `IceCream_Flavor` (ভ্যানিলা, চকোলেট) এবং `Toppings` (বাদাম, জেলি) নামের দুটো টেবিল আছে। সব ধরণের কম্বিনেশন বের করার কুয়েরি কী হবে?

### 🎓 Lesson 26: Self Join - নিজের সাথেই সম্পর্ক

**সহজ বাংলা ব্যাখ্যা:**
এতদিন আমরা এক টেবিলের সাথে **অন্য** টেবিল জয়েন করেছি। কিন্তু মাঝে মাঝে টেবিলকে **নিজের সাথেই** জয়েন করতে হয়। একে বলে **Self Join**।
এটা মূলত তখন লাগে যখন এক টেবিলে এমন ডেটা থাকে যা একে অপরের সাথে সম্পর্কিত (Hierarchy)।

**🤣 Funny Real-life Analogy:**
**অফিসের বস এবং এমপ্লয়ি!** 💼
বস নিজেও তো একজন এমপ্লয়ি, তাই না?
- `Employee` টেবিলে সবার নাম আছে।
- রহিমের বস হলো করিম।
- করিমের বস হলো জব্বার।
সবাই একই টেবিলে আছে। এখন যদি বলি "রহিমের বসের নাম কী?", তখন টেবিলকে নিজের দিকেই আয়না ধরতে হবে।

**ASCII Table Example:**

**Table: Employees**

| EmpID | Name | ManagerID |
| :--- | :--- | :--- |
| 1 | **Boss Man** | NULL (সে সবার বস) |
| 2 | Rahim | **1** (তার বস ১ নম্বর) |
| 3 | Karim | **1** (তার বস ১ নম্বর) |
| 4 | Poltu | **2** (তার বস ২/রহিম) |

এখন আমরা দেখতে চাই: **Employee Name -- Manager Name**

**SQL Example:**
এখানে ট্রিকটা হলো টেবিল একটাই, কিন্তু আমরা ভাবব টেবিল দুটো। তাই আমরা **আলাদা ডাকনাম (Alias)** ব্যবহার করব: `E` (Employee-এর জন্য) এবং `M` (Manager-এর জন্য)।

```sql
SELECT E.Name AS EmployeeName, M.Name AS ManagerName
FROM Employees AS E        -- এমপ্লয়ি হিসেবে টেবিলটা নাও
INNER JOIN Employees AS M  -- ম্যানেজার হিসেবে আবার ওই টেবিলটাই নাও
ON E.ManagerID = M.EmpID;  -- সূত্র: এমপ্লয়ির ম্যানেজার আইডি = ম্যানেজারের নিজের আইডি
```

**Result:**

| EmployeeName | ManagerName |
| :--- | :--- |
| Rahim | Boss Man |
| Karim | Boss Man |
| Poltu | Rahim |

*(দেখো পল্টুর বস হিসেবে রহিমকে দেখাচ্ছে, আবার রহিম নিজেও একজন এমপ্লয়ি। ম্যাজিক!)*

**When/Why to use:**
যেকোনো **Hierarchy** বা পদমর্যাদা সাজাতে। যেমন: ক্যাটাগরি এবং সাব-ক্যাটাগরি (Electronics -> Mobile -> Samsung)।

**Common Mistake:**
Alias (E, M) ব্যবহার না করা। একই টেবিল দুইবার কল করলে কম্পিউটার কনফিউজড হয়ে যায় "কোনটা কে?"। তাই নাম আলাদা দেওয়া ফরজ।

**Mini Task:**
চিন্তা করো একটা `Family` টেবিল আছে যেখানে `PersonID`, `Name` এবং `FatherID` আছে।
তুমি কি এমন একটা কুয়েরি লিখতে পারবে যা দেখাবে: **"Son Name -- Father Name"**? (লজিকটা হুবহু ম্যানেজারের মতো)।

---

স্বাগতম **অ্যাডভান্সড কুয়েরি**-র জগতে! 🕵️‍♂️

আমরা জয়েন (JOIN) দিয়ে টেবিলকে **পাশাপাশি (Horizontally)** জোড়া লাগিয়েছি। আজ শিখব কীভাবে টেবিলকে **উপর-নিচ (Vertically)** জোড়া লাগাতে হয় এবং কীভাবে এক কুয়েরির পেটের ভেতর আরেক কুয়েরি ঢুকিয়ে দিতে হয়!

ব্যাপারটা শুনতে একটু জগাখিচুড়ি মনে হলেও, এটা আসলে ডেটাবেসের সুপারপাওয়ার। চলো **Lesson 27** এবং **Lesson 28** একদম পানির মতো সহজ করে ফেলি।

### 🎓 Lesson 27: UNION এবং UNION ALL

**সহজ বাংলা ব্যাখ্যা:**
ধরো তোমার কাছে দুটি আলাদা লিস্ট আছে। তুমি চাও দুটি লিস্টকে মিলিয়ে একটা লম্বা লিস্ট বানাতে। এটাই **UNION**।
এটি মূলত দুটি `SELECT` কুয়েরির রেজাল্টকে একটার নিচে আরেকটা বসিয়ে দেয়।

এর দুটি ভার্সন আছে:
১. **UNION:** ডুপ্লিকেট বাদ দিয়ে ইউনিক লিস্ট দেয় (একটু স্লো, কারণ সে চেক করে)।
২. **UNION ALL:** ডুপ্লিকেটসহ সব দিয়ে দেয় (সুপার ফাস্ট, কারণ সে চেক করার কষ্ট করে না)।

**🤣 Funny Real-life Analogy:**
**বিয়ে বাড়ির দাওয়াত লিস্ট!** 📝
- **বরপক্ষ (List A):** ১০ জন।
- **কনেপক্ষ (List B):** ১০ জন।
- কমন মেহমান: "খালা" (যিনি দুই পক্ষেই আছেন)।

- **UNION:** তুমি বসে বসে চেক করলে যে খালা দুই লিস্টেই আছেন কি না। থাকলে নামটা একবারই লিখলে। (খালা ১ প্লেট বিরিয়ানি পাবেন)।
- **UNION ALL:** তুমি কোনো চেক না করে দুই লিস্ট স্ট্যাপল করে দিলে। খালা লিস্টে দুইবার থাকবেন। (খালা খুশিমনে ২ প্লেট বিরিয়ানি খাবেন!) 🍗🍗

**ASCII Example:**

**Table A (Cricket Team):**

| Name |
| :--- |
| Shakib |
| Tamim |

**Table B (Football Team):**

| Name |
| :--- |
| Jamal |
| Shakib | (সে দুই খেলাতেই আছে)

**Query 1: UNION**
*(ডুপ্লিকেট সাকিব বাদ যাবে)*

| Name |
| :--- |
| Shakib |
| Tamim |
| Jamal |

**Query 2: UNION ALL**
*(সবাই আসবে)*

| Name |
| :--- |
| Shakib |
| Tamim |
| Jamal |
| **Shakib** |

**SQL Example:**
```sql
-- ডুপ্লিকেট বাদ দিয়ে সব নাম দেখাও
SELECT Name FROM CricketTeam
UNION
SELECT Name FROM FootballTeam;

-- ডুপ্লিকেটসহ সব দেখাও (দ্রুত কাজ করে)
SELECT Name FROM CricketTeam
UNION ALL
SELECT Name FROM FootballTeam;
```

**⚠️ Strict Rules (কড়া নিয়ম):**
১. দুটি কুয়েরিতে **কলামের সংখ্যা** সমান হতে হবে। (একটায় ২ কলাম, আরেকটায় ৩ কলাম হলে হবে না)।
২. **ডেটা টাইপ** মিলতে হবে। (একটায় নাম, আরেকটায় বয়স জোড়া লাগানো যাবে না)।

**Best Practice:**
যদি তুমি নিশ্চিত থাকো যে ডুপ্লিকেট ডেটা নেই, অথবা ডুপ্লিকেট থাকলেও সমস্যা নেই—তবে সবসময় **UNION ALL** ব্যবহার করবে। কারণ `UNION` ডুপ্লিকেট চেক করতে গিয়ে সার্ভারের সময় নষ্ট করে।

**Mini Task:**
তোমার কাছে `Old_Students` এবং `New_Students` নামের দুটি টেবিল আছে। সব ছাত্রের একটা কম্বাইন্ড লিস্ট বানানোর কুয়েরি কী হবে? (ধরে নাও কেউ কেউ ফেল করে আবার নতুন ক্লাসে আছে, তাই ডুপ্লিকেট হতে পারে)।

### 🎓 Lesson 28: Subqueries (Nested Queries)

**সহজ বাংলা ব্যাখ্যা:**
সাব-কুয়েরি (Subquery) মানে হলো **কুয়েরির পেটের ভেতর আরেকটা কুয়েরি**। একে নেস্টেড কুয়েরিও বলে।
ভেতরের কুয়েরি (Inner Query) আগে রান হয়, তার রেজাল্ট নিয়ে বাইরের কুয়েরি (Outer Query) কাজ করে।

**🤣 Funny Real-life Analogy:**
**আম্মুর কাছে টাকা চাওয়া!** 💸
তুমি আম্মুকে বললে: "আম্মু, আইসক্রিম খাওয়ার টাকা দাও।"
আম্মু: "আইসক্রিমের দাম কত?" (আম্মু জানে না)।
তুমি ছোট ভাইকে জিজ্ঞেস করলে: "আইসক্রিম কত?" (ভাই বলল: ৫০ টাকা)।
তারপর আম্মু তোমাকে ৫০ টাকা দিল।

এখানে:
1. **Inner Query:** ভাইয়ের কাছে দাম জানা (Result: 50)।
2. **Outer Query:** আম্মুর কাছে ওই ৫০ টাকা চাওয়া।

**SQL Example:**
আমরা বের করতে চাই: **কার বেতন কোম্পানির গড় (Average) বেতনের চেয়ে বেশি?**

আমরা জানি না গড় বেতন কত। তাই দুই ধাপে কাজ হবে:
১. আগে গড় বের করো।
২. তারপর তুলনা করো।

```sql
SELECT Name, Salary
FROM Employee
WHERE Salary > (
    -- এটা হলো Subquery (আগে রান হবে)
    SELECT AVG(Salary) FROM Employee
);
```
*(ধরি গড় বেতন ৪০,০০০। তাহলে কুয়েরিটা মনে মনে হয়ে যাবে: `WHERE Salary > 40000`)*

**Types of Subquery:**
১. **Scalar:** যখন ১টি মাত্র ভ্যালু রিটার্ন করে (উপরের উদাহরণের মতো)। এখানে `=` বা `>` ব্যবহার হয়।
২. **Multi-row:** যখন একটা লিস্ট রিটার্ন করে। তখন `IN` ব্যবহার করতে হয়।

**Example (Multi-row with IN):**
"যেসব স্টুডেন্ট 'Science' ডিপার্টমেন্টে পড়ে, তাদের নাম দেখাও।"

```sql
SELECT Name
FROM Students
WHERE DeptID IN (
    -- সায়েন্স ডিপার্টমেন্টের আইডি খুঁজে বের করো
    SELECT DeptID FROM Departments WHERE DeptName = 'Science'
);
```

**Common Mistake (The "Equal" Trap):**
যদি সাব-কুয়েরি একাধিক রেজাল্ট দেয় (যেমন: ১, ২, ৩), আর তুমি লেখো `WHERE ID = (...)`, তবে এরর খাবে! কারণ `ID` একই সাথে ১, ২, ৩ হতে পারে না।
তখন `IN` ব্যবহার করতে হয়।

**When to use:**
ছোটখাটো লজিকের জন্য সাব-কুয়েরি দারুণ। কিন্তু খুব জটিল হলে এটা স্লো হয়ে যায়। তখন আমরা `JOIN` ব্যবহার করি। (তবে শেখার জন্য সাব-কুয়েরি বস!)

**Mini Task:**
ধরো `Product` টেবিলে সব পণ্যের দাম আছে।
সবচেয়ে দামি পণ্যটির (Max Price) নাম খুঁজে বের করার কুয়েরি লেখো।
(Hint: `WHERE Price = (SELECT MAX(Price)...)`)

আমরা আগের লেসনে **Subquery** শিখেছি। কিন্তু সমস্যা হলো, কুয়েরির ভেতর কুয়েরি, তার ভেতর আবার কুয়েরি লিখলে কোডটা **নুডলস বা স্প্যাগেটির** মতো জট পাকিয়ে যায়। এক মাস পর নিজের কোড দেখে নিজেই ভয় পাবে! 🍜

এই সমস্যা সমাধান করতেই এসেছে **CTE (Common Table Expressions)**। আর শেষে আমরা শিখব কীভাবে টেক্সট আর সময় নিয়ে খেলতে হয়।

### 🎓 Lesson 29: CTE (Common Table Expressions) - WITH ক্লজ

**সহজ বাংলা ব্যাখ্যা:**
CTE হলো একটা **অস্থায়ী রেজাল্ট** যা তুমি কুয়েরির শুরুতেই বানিয়ে নাও।
মনে করো, তুমি একটা জটিল অংক করছ। তুমি কি সব ক্যালকুলেশন মূল খাতায় করো? না! তুমি পাশের পৃষ্ঠায় **রাফ (Rough)** করো, তারপর সেই রাফ থেকে রেজাল্টটা মূল অংকে বসাও।
CTE হলো সেই **রাফ খাতা**। এটি কোডকে পরিষ্কার ও সুন্দর রাখে।

**🤣 Funny Real-life Analogy:**
**বিরিয়ানি রান্না!** 🍗
রান্না করার সময় তুমি কি সরাসরি পাতিলে আস্ত পেঁয়াজ, আস্ত আলু ছেড়ে দাও? না!
1. আগে পেঁয়াজ কাটো, আলু ভাজো, মশলা রেডি করো (এটা হলো **CTE** বা প্রস্তুতি)।
2. তারপর সব একসাথে পাতিলে দিয়ে রান্না করো (এটা হলো **Main Query**)।

যদি সব একসাথে করতে যাও, রান্নাঘর যুদ্ধক্ষেত্র হয়ে যাবে! (Subquery-র সমস্যা)।

**SQL Example:**
আমরা বের করতে চাই: **কোন ডিপার্টমেন্টের মোট স্যালারি কোম্পানির গড় স্যালারির চেয়ে বেশি?**

```sql
-- ১. আগে ডিপার্টমেন্ট অনুযায়ী মোট স্যালারি বের করে একটা টেম্পোরারি নাম দিলাম 'Dept_Salaries'
WITH Dept_Salaries AS (
    SELECT Department, SUM(Salary) as TotalSal
    FROM Employee
    GROUP BY Department
)

-- ২. এবার সেই টেম্পোরারি টেবিল থেকে মেইন কুয়েরি চালাও
SELECT *
FROM Dept_Salaries
WHERE TotalSal > 500000;
```

**Why Better than Subquery?**
একই কাজ সাব-কুয়েরি দিয়ে করলে কোডটা জগাখিচুড়ি লাগত। CTE দিয়ে কোডটা গল্পের মতো উপর থেকে নিচে পড়া যায়।
১. `WITH` দিয়ে নাম দাও।
২. `AS (...)` এর ভেতর লজিক লেখো।
৩. শেষে `SELECT` করো।

**Mini Task:**
তোমার `Sales` টেবিলে `Product` এবং `Quantity` আছে।
`WITH` ব্যবহার করে প্রথমে সব প্রোডাক্টের মোট বিক্রি (Sum) বের করো, তারপর সেখান থেকে শুধু তাদের দেখাও যাদের বিক্রি ১০০-এর বেশি।

### 🎓 Lesson 30: String এবং Date Functions (সাজগোজ ও সময় ভ্রমণ)

**সহজ বাংলা ব্যাখ্যা:**
ডেটাবেসে ডেটা সবসময় সুন্দরভাবে থাকে না। কারো নাম ছোট হাতের, কারো বড় হাতের, আবার কারো নামের পাশে স্পেস। এগুলোকে সাইজ করার জন্য **String Functions** লাগে।
আর বয়স বের করা বা ডেট ফরম্যাট করার জন্য **Date Functions** লাগে।

**🤣 Funny Real-life Analogy:**
১. **String Function:** মেকআপ বক্স! 💄
চেহারা (Text) যেমনই হোক, মেকআপ (Function) দিয়ে সেটা সুন্দর করা যায়।
২. **Date Function:** টাইম মেশিন! ⏰
তুমি চাইলেই আজকের তারিখ থেকে ২০ বছর পেছনে গিয়ে বয়স বের করতে পারো, বা ১০ দিন পরের তারিখ বের করতে পারো।

**Most Useful Functions Cheat Sheet:**

#### **A. String Functions (টেক্সট সাইজ করা):**

1.  **UPPER / LOWER:** সব বড় হাতের বা ছোট হাতের করা।
    ```sql
    SELECT UPPER(Name) FROM Employee; -- RAHIM
    ```
2.  **CONCAT:** জোড়া লাগানো (First Name + Last Name).
    ```sql
    SELECT CONCAT(FirstName, ' ', LastName) FROM Employee;
    ```
3.  **TRIM:** আশপাশের ফালতু স্পেস (Space) কেটে ফেলা।
    *(সবচেয়ে জরুরি! ইউজাররা প্রায়ই ভুলে স্পেস দিয়ে রাখে)*
    ```sql
    SELECT TRIM(Name) FROM Users; -- ' Rahim ' হয়ে যাবে 'Rahim'
    ```
4.  **SUBSTRING:** মাঝখান থেকে কেটে নেওয়া।
    ```sql
    SELECT SUBSTRING('Hello World', 1, 5); -- Result: 'Hello'
    ```

#### **B. Date Functions (সময় নিয়ে খেলা):**

1.  **GETDATE() / NOW():** আজকের তারিখ ও সময়।
    ```sql
    SELECT GETDATE(); -- 2023-10-25 10:30:00
    ```
2.  **DATEDIFF:** দুটি তারিখের পার্থক্য (বয়স বের করার বস!)।
    ```sql
    -- জন্মতারিখ থেকে আজকের দিনের পার্থক্য (বছরে)
    SELECT DATEDIFF(YEAR, '1995-01-01', GETDATE()) AS Age;
    ```
3.  **DATEADD:** তারিখ যোগ করা।
    ```sql
    -- আজ থেকে ১০ দিন পর কী বার?
    SELECT DATEADD(DAY, 10, GETDATE());
    ```

**ASCII Example (Age Calculation):**

| Name | DOB | Query Result (Age) |
| :--- | :--- | :--- |
| Rahim | 2000-01-01 | **25** |
| Karim | 1990-05-05 | **35** |

**Common Mistake:**
ডেট ফরম্যাট নিয়ে গন্ডগোল। একেক দেশে একেক নিয়ম (MM-DD-YYYY vs DD-MM-YYYY)।
*Tip:* ডেটাবেসে সবসময় স্ট্যান্ডার্ড ফরম্যাট `YYYY-MM-DD` ব্যবহার করবে। দেখানোর সময় যা ইচ্ছা দেখাও।

**Mini Task:**
১. তোমার নিজের নাম সব **UPPERCASE**-এ দেখার কুয়েরি লেখো।
২. তোমার জন্ম তারিখ ব্যবহার করে আজকের দিনে তোমার বয়স (মাসে) বের করার কুয়েরি লেখো। (Hint: `DATEDIFF(MONTH, 'Your-DOB', GETDATE())`)
