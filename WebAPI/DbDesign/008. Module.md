### 💞 **Lesson 11: রিলেশনশিপ বা সম্পর্ক আসলে কী? (Intro to Relationships)**

**🗣️ সহজ বাংলা:**
ধরো, তুমি ফেসবুকে আছো। তোমার ফ্রেন্ডলিস্টে বন্ধুরা আছে, তুমি পোস্টে কমেন্ট করছো, গ্রুপে জয়েন করছো। সব কিছুই একে অপরের সাথে কানেক্টেড।
ডাটাবেসেও তাই। আমরা সব ডাটা একটা বিশাল বড় টেবিলে রাখি না (রাখলে সেটা এক্সেল হয়ে যেত)। আমরা ডাটাকে ছোট ছোট টেবিলে ভাগ করি এবং তাদের মধ্যে সুতোর মতো কানেকশন তৈরি করি। এই কানেকশনকেই বলে **Relationship**।

**🤣 ফানি এনালজি (Real-life):**
রিলেশনশিপ হলো **আত্মীয়তার সম্পর্কের** মতো।
*   বাপের সাথে ছেলের সম্পর্ক।
*   জামাইয়ের সাথে বউয়ের সম্পর্ক।
*   দোকানদারের সাথে কাস্টমারের সম্পর্ক।
সম্পর্ক ছাড়া সমাজ চলে না, ডাটাবেসও চলে না।

**🤔 কেন সম্পর্ক দরকার?**
*   **ডাটা ডুপ্লিকেশন কমানোর জন্য:** কাস্টমারের নাম ও ঠিকানা প্রতিটা অর্ডারের সাথে বারবার না লিখে, কাস্টমার টেবিলে একবারই লিখব।
*   **ডাটার ইন্টিগ্রিটি:** যাতে ভুলভাল ডাটা একটার সাথে আরেকটা মিশে না যায়।

### 💍 **Lesson 12: ওয়ান-টু-ওয়ান (One-to-One / 1:1) সম্পর্ক**

**🗣️ সহজ বাংলা:**
সবচেয়ে সহজ সম্পর্ক। টেবিল A-এর একটি রো, টেবিল B-এর ঠিক একটি রো-এর সাথেই যুক্ত থাকবে।
"আমার তুমি ছাড়া কেউ নেই, তোমার আমি ছাড়া কেউ নেই।"

**🤣 ফানি এনালজি (Real-life):**
**মানুষ এবং তার NID কার্ড।**
একজন মানুষের একটাই ভ্যালিড NID থাকে। আবার একটা NID কার্ড একজন মানুষেরই হয়।

**🎨 ASCII Art Example:**
```text
[ Person Table ]           [ NID_Details Table ]
+----+-------+             +---------+-------------+
| ID | Name  | <---1:1---> | NID_No  | Issue_Date  |
+----+-------+             +---------+-------------+
  1  : Rahim                 123456     2020...
```

**💻 SQL Example:**
এখানে `Users` টেবিলের `UserID` হবে প্রাইমারি কি, আর `UserProfiles` টেবিলে `UserID` হবে ফরেন কি + ইউনিক কি (যাতে ডুপ্লিকেট না হয়)।

```sql
CREATE TABLE Users (
    UserID int PRIMARY KEY,
    Username varchar(50)
);

CREATE TABLE UserProfiles (
    ProfileID int PRIMARY KEY,
    UserID int UNIQUE, -- Unique না দিলে 1:1 হবে না
    Address varchar(100),
    FOREIGN KEY (UserID) REFERENCES Users(UserID)
);
```

**🤔 কখন ব্যবহার করব?**
*   খুব কম ব্যবহার হয়।
*   যখন একটা টেবিল অনেক বড় হয়ে যায় (৫০টা কলাম), তখন কম প্রয়োজনীয় কলামগুলো (যেমন: বাপের নাম, মায়ের নাম, ৩য় ঠিকানা) আলাদা টেবিলে সরিয়ে ১:১ সম্পর্ক করা হয়। একে **Vertical Partitioning** বলে।

### 👨‍👧‍👦 **Lesson 13: ওয়ান-টু-মেনি (One-to-Many / 1:N) সম্পর্ক**

**🗣️ সহজ বাংলা:**
ডাটাবেস দুনিয়ার **সবচেয়ে জনপ্রিয়** সম্পর্ক। রাজত্ব করে বেড়ায়!
এখানে টেবিল A-এর একজন, টেবিল B-এর অনেকের সাথে যুক্ত হতে পারে। কিন্তু টেবিল B-এর একজন, টেবিল A-এর মাত্র একজনের সাথেই যুক্ত থাকবে।

**🤣 ফানি এনালজি (Real-life):**
**বাবা এবং সন্তান।**
একজন বাবার অনেকগুলো সন্তান থাকতে পারে (১:N)।
কিন্তু একজন সন্তানের (বায়োলজিক্যাল) বাবা একজনই হয় (N:1)।

**আরেকটা:** **ফেসবুক পোস্ট এবং কমেন্ট।**
একটা পোস্টে হাজারটা কমেন্ট থাকে, কিন্তু একটা নির্দিষ্ট কমেন্ট ওই একটা পোস্টেরই অংশ।

**🎨 ASCII Art Example:**
```text
[ Customer ] (One)                    [ Orders ] (Many)
+----+-------+                        +-----+---------+--------+
| ID | Name  |                        | OID | Product | CustID |
+----+-------+                        +-----+---------+--------+
| 1  | Guru  | --+------------------> | 101 | Laptop  |   1    |
|    |       |   +------------------> | 102 | Mouse   |   1    |
+----+-------+                        +-----+---------+--------+
```

**💻 SQL Example:**
*Child টেবিলে (Orders) আমরা Parent-এর (Customer) আইডি রাখি।*

```sql
CREATE TABLE Orders (
    OrderID int PRIMARY KEY,
    ProductName varchar(50),
    CustomerID int, -- ১ জন কাস্টমার অনেক অর্ডার দিতে পারে
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)
);
```

**✅ Best Practice:**
*   সবসময় "Many" সাইডে (Child Table) ফরেন কি (Foreign Key) রাখতে হয়। বাবার পকেটে বাচ্চার আইডি থাকে না, বাচ্চার সনদে বাবার নাম থাকে।

**🏆 Mini Practice Task:**
`Department` এবং `Employee` - এদের মধ্যে সম্পর্ক কী? ১ জন এমপ্লয়ি কি ১০টা ডিপার্টমেন্টে কাজ করে? নাকি ১টা ডিপার্টমেন্টে অনেক এমপ্লয়ি থাকে? উত্তরটা ভাবো। (উত্তর: 1:N)।

### 🕸️ **Lesson 14: মেনি-টু-মেনি (Many-to-Many / M:N) সম্পর্ক**

**🗣️ সহজ বাংলা:**
সবচেয়ে জটিল কিন্তু মজার সম্পর্ক।
টেবিল A-এর অনেকে টেবিল B-এর অনেকের সাথে যুক্ত।
সরাসরি দুইটা টেবিল দিয়ে এই সম্পর্ক বানানো যায় না। মাঝখানে একজন **"ঘটক" (Middleman/Junction Table)** লাগে।

**🤣 ফানি এনালজি (Real-life):**
**ছাত্র এবং সাবজেক্ট (Course)।**
একজন ছাত্র অনেকগুলো সাবজেক্ট নিতে পারে (যেমন: বাংলা, ইংরেজি, অংক)।
আবার একটা সাবজেক্টে (যেমন: অংকে) অনেকগুলো ছাত্র থাকতে পারে।
কেউ কারো একার না!

**🎨 ASCII Art Example:**
আমরা সরাসরি কানেক্ট করতে পারি না। মাঝখানে `Student_Course` নামে একটা টেবিল লাগবে।

```text
[ Student ]       [ Junction Table ]       [ Course ]
(Rahim, ID=1) <-----> (StdID=1, CrsID=101) <-----> (Math, ID=101)
                  <-----> (StdID=1, CrsID=102) <-----> (English, ID=102)
(Karim, ID=2) <-----> (StdID=2, CrsID=101) <-----> (Math, ID=101)
```

**💻 SQL Example:**
```sql
-- টেবিল ১
CREATE TABLE Students (StudentID int PRIMARY KEY, Name varchar(50));

-- টেবিল ২
CREATE TABLE Courses (CourseID int PRIMARY KEY, Title varchar(50));

-- ঘটক টেবিল (Junction Table)
CREATE TABLE StudentCourses (
    StudentID int,
    CourseID int,
    FOREIGN KEY (StudentID) REFERENCES Students(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Courses(CourseID),
    PRIMARY KEY (StudentID, CourseID) -- Composite Key
);
```

**❌ Common Mistakes:**
*   অনেকে `Students` টেবিলে একটা কলামে `Math, English, Physics` এভাবে কমা দিয়ে লিখে দেয়। খবরদার! এটা ডাটাবেসের জঘন্যতম পাপ! সবসময় আলাদা টেবিল (Junction Table) বানাবে।

### 🗺️ **Lesson 15: ইআর ডায়াগ্রাম - আর্কিটেক্টের নকশা (ER Diagram)**

**🗣️ সহজ বাংলা:**
বাড়ি বানানোর আগে যেমন ইঞ্জিনিয়াররা ব্লু-প্রিন্ট বা নকশা করে, ডাটাবেস বানানোর আগে আমাদের **ERD (Entity Relationship Diagram)** আঁকতে হয়।
কোড লেখার আগে খাতা-কলমে বা সফটওয়্যারে (Draw.io, Visio) টেবিলগুলোর বক্স এঁকে দাগ টেনে সম্পর্ক দেখানোই হলো ERD।

**🤣 ফানি এনালজি (Real-life):**
ERD হলো **ফুটবল ম্যাচের স্ট্র্যাটেজি বোর্ড**। কোচ যেমন বোর্ডে আঁকেন কে কোথায় দাঁড়াবে, বল কার কাছে পাস দিবে—ERD-তে আমরা ঠিক করি কোন টেবিল কোথায় থাকবে আর কার সাথে কার লিংক হবে।

**কিভাবে আঁকবে? (Basic Symbols):**
1.  ⬜ **Rectangle (আয়তক্ষেত্র):** টেবিল বা Entity (যেমন: User, Product)।
2.  💎 **Diamond (রম্বস):** সম্পর্ক বা Relationship (যেমন: Buys, Enrolls)।
3.  🥚 **Oval (ডিম্বাকৃতি):** কলাম বা Attribute (যেমন: Name, Price)। (আধুনিক ERD-তে সরাসরি টেবিল বক্সের ভেতরেই নাম লেখা হয়)।
4.  Crow’s Foot Notation (কাকের পা): 1:N বোঝাতে তিনকোনা দাগ ব্যবহার হয়।

**🎨 ASCII Mini ERD:**

```text
  +-------------+                     +-------------+
  |  Customer   |                     |    Order    |
  +-------------+                     +-------------+
  | PK: CustID  |-------||------o<----| PK: OrderID |
  |     Name    |   (1)        (Many) | FK: CustID  |
  +-------------+                     +-------------+
```
*(বাম পাশে ১ জন, ডান পাশে কাকের পায়ের মতো চিহ্ন মানে Many)*

**🏆 Mini Practice Task (হোমওয়ার্ক):**
একটা সাদা কাগজ নাও।
একটা `Library` ম্যানেজমেন্ট সিস্টেমের ERD আঁকো।
*   Entity: `Book`, `Member`
*   Relationship: একজন মেম্বার অনেক বই নিতে পারে, একটা বই অনেক কপি থাকতে পারে।
*   মাঝখানে কি কোনো ঘটক টেবিল (`Loan` বা `Issue`) লাগবে? ভাবো এবং আঁকো!
