### 🤝 **Lesson 21: ইনার জয়েন (Inner Join) - শুধু মিললেই খেলা হবে**

**🗣️ সহজ বাংলা:**
দুইটা টেবিলের মধ্যে **কমন (Common)** ডাটা খুঁজে বের করাই হলো Inner Join।
টেবিল 'A' এবং টেবিল 'B'-এর মধ্যে যাদের আইডি মিলবে, শুধু তারাই রেজাল্টে আসবে। বাকিরা বাদ!

**🤣 ফানি এনালজি (Real-life):**
**বিয়ের ঘটকালি।**
ছেলে পক্ষ (Table A) আর মেয়ে পক্ষ (Table B)।
ছেলে পছন্দ করল, মেয়ে পছন্দ করল না = বিয়ে হবে না।
মেয়ে পছন্দ করল, ছেলে করল না = বিয়ে হবে না।
যখন **উভয় পক্ষ রাজি** (Match Found), তখনই বিয়ে (Inner Join Result)!

**🎨 ASCII Art Example:**

```text
   Table A (Users)       Table B (Orders)
  +----+-------+        +-----+--------+
  | ID | Name  |        | OID | UserID |
  +----+-------+        +-----+--------+
  | 1  | Rahim |        | 101 |   1    | (Rahim bought this)
  | 2  | Karim |        | 102 |   1    | (Rahim bought this)
  | 3  | Babu  |        | 103 |   5    | (Who is 5? Not in A!)
  +----+-------+        +-----+--------+

  [ RESULT of INNER JOIN ]
  (Rahim, Order 101)
  (Rahim, Order 102)
  *(Karim বাদ কারণ সে কিছু কেনেনি, Order 103 বাদ কারণ ইউজার ৫ নেই)*
```

**💻 SQL Example:**
```sql
SELECT Users.Name, Orders.OrderID
FROM Users
INNER JOIN Orders ON Users.ID = Orders.UserID;
```

**🤔 কখন ব্যবহার করব?**
*   যখন তুমি শুধু এমন ডাটা চাও যেটা দুই টেবিলেই আছে। যেমন: "কোন কোন কাস্টমার অর্ডার করেছে তাদের নাম দাও।" (যারা অর্ডার করেনি তাদের নাম আমার দরকার নেই)।

**✅ Best Practice:**
*   সবসময় `TableName.ColumnName` বা `Alias` (u.Name, o.OrderID) ব্যবহার করবে। নতুবা ডাটাবেস কনফিউজড হয়ে যাবে কোন আইডি কার।

### 👈 **Lesson 22: লেফট এবং রাইট জয়েন (Left & Right Join) - একতরফা ভালোবাসা**

**🗣️ সহজ বাংলা:**
**Left Join:** বাম পাশের টেবিলের **সবাই** থাকবে, ডান পাশের টেবিল থেকে শুধু যারা মিলবে তারা আসবে। যারা মিলবে না, তাদের জায়গায় `NULL` দেখাবে।
**Right Join:** ঠিক উল্টোটা। ডান পাশের সবাই থাকবে।

**🤣 ফানি এনালজি (Real-life):**
**ক্লাসের হাজিরা খাতা (Attendance)।**
স্টুডেন্ট লিস্ট (Left Table) হলো মেইন।
আজকে যারা এসেছে (Right Table) তাদের নামের পাশে "Present" বসবে।
আর যারা আসেনি, তাদের নাম কি খাতা থেকে মুছে যাবে? না! তাদের নাম থাকবে, কিন্তু পাশে "Absent" (NULL) বসবে।

**🎨 ASCII Art Example (Left Join):**
`Users` (Left) - `Orders` (Right)

```text
  [ RESULT ]
  | Name  | OrderID |
  +-------+---------+
  | Rahim | 101     | (Matched)
  | Rahim | 102     | (Matched)
  | Karim | NULL    | (Karim আছে, কিন্তু অর্ডার নাই)
  | Babu  | NULL    | (Babu আছে, কিন্তু অর্ডার নাই)
```

**💻 SQL Example:**
```sql
SELECT Users.Name, Orders.OrderID
FROM Users
LEFT JOIN Orders ON Users.ID = Orders.UserID;
```

**🤔 কখন ব্যবহার করব?**
*   যখন জানতে চাইবে "কোন কাস্টমাররা **এখনো কোনো অর্ডার করেনি**?" (যাদের OrderID = NULL)।

**❌ Common Mistakes:**
*   `Left Join` আর `Right Join` গুলিয়ে ফেলা। মনে রাখবে: `FROM` এর পরে যে টেবিল থাকে সেটা LEFT, আর `JOIN` এর পরে যেটা থাকে সেটা RIGHT। সাধারণত `Right Join` কম ব্যবহার হয়, `Left Join` দিয়েই সব কাজ করা যায় (টেবিলের পজিশন ঘুরিয়ে)।

### 🌐 **Lesson 23: ফুল আউটার জয়েন (Full Outer Join) - সবাই আমন্ত্রিত**

**🗣️ সহজ বাংলা:**
Inner, Left, Right—সবাইকে একসাথে নিয়ে যেটা হয়, সেটাই Full Outer Join।
বাম পাশের ডাটা, ডান পাশের ডাটা, এবং কমন ডাটা—সব রেজাল্টে আসবে। কেউ বাদ যাবে না। যার জোড়া নেই, তার পাশে `NULL` বসবে।

**🤣 ফানি এনালজি (Real-life):**
**ঈদের দাওয়াত।**
তোমার বন্ধুরাও আসবে (Table A), তোমার কাজিনরাও আসবে (Table B)।
কিছু মানুষ আছে যারা তোমার বন্ধু + কাজিন (Common)।
সবাই মিলে এক বিশাল গ্যাদারিং। কেউ বাদ নেই!

**💻 SQL Example:**
```sql
SELECT Users.Name, Orders.OrderID
FROM Users
FULL OUTER JOIN Orders ON Users.ID = Orders.UserID;
```
*(এখানে এমন অর্ডারও আসবে যার কোনো ইউজার নেই - যদি ডাটাবেসে এতিম ডাটা থাকে)*

**বোনাস: Cross Join (বিপদজনক!) ⚠️**
এটা কোনো কন্ডিশন ছাড়া গুণ করে (Cartesian Product)।
টেবিল A তে ৫ জন, টেবিল B তে ৪ জন থাকলে রেজাল্ট হবে ৫ x ৪ = ২০ জন।
*   **Analogy:** টি-শার্টের কালার (লাল, নীল) আর সাইজ (M, L)। সব কম্বিনেশন (লাল-M, লাল-L, নীল-M, নীল-L)।

**🏆 Mini Practice Task:**
তোমার `Employee` টেবিল আর `Department` টেবিল আছে।
এমন একটা কুয়েরি ভাবো যেটা দিয়ে বের করা যাবে—"কোন ডিপার্টমেন্টে কোনো এমপ্লয়ি নাই" এবং "কোন এমপ্লয়ি কোনো ডিপার্টমেন্টে নাই"। (Hint: Full Outer Join)।

### ➕ **Lesson 24: ইউনিয়ন বনাম ইউনিয়ন অল (UNION vs UNION ALL)**

**🗣️ সহজ বাংলা:**
JOIN কলামকে পাশাপাশি জোড়া লাগায় (Horizontal)।
UNION রো-কে নিচে নিচে জোড়া লাগায় (Vertical)।

*   **UNION:** ডুপ্লিকেট বাদ দিয়ে রেজাল্ট দেয়।
*   **UNION ALL:** যা আছে সব ঢেলে দেয় (ডুপ্লিকেটসহ)।

**🤣 ফানি এনালজি (Real-life):**
*   **UNION (ফ্রুট সালাদ):** তুমি ১ বাটি আপেল দিলে, আমি ১ বাটি আপেল দিলাম। মিক্স করলে বাটিতে শুধুই "আপেল" থাকবে (ডুপ্লিকেট রিমুভড)।
*   **UNION ALL (টাকার বা বান্ডিল):** তুমি ১০০ টাকা দিলে, আমি ১০০ টাকা দিলাম। মোট ২০০ টাকা হলো (ডুপ্লিকেট থাকলেও সমস্যা নেই, সব কাউন্ট হবে)।

**🎨 ASCII Art Example:**

```text
Query 1: [A, B]
Query 2: [B, C]

UNION Result:     [A, B, C]    (B একবারই এসেছে)
UNION ALL Result: [A, B, B, C] (B দুইবার এসেছে)
```

**💻 SQL Example:**
```sql
-- ২টা টেবিল থেকে সব ফোন নম্বর এক লিস্টে চাই
SELECT Phone FROM Customers
UNION ALL
SELECT Phone FROM Suppliers;
```

**🤔 কখন ব্যবহার করব?**
*   যখন দুইটা আলাদা টেবিল থেকে একই ধরণের ডাটা এক লিস্টে দেখাতে হয়।

**✅ Best Practice:**
*   যদি ডুপ্লিকেট থাকার চান্স না থাকে বা ডুপ্লিকেট থাকলেও সমস্যা না হয়, তবে সবসময় `UNION ALL` ব্যবহার করবে। কারণ `UNION` ডুপ্লিকেট চেক করতে গিয়ে সময় নষ্ট করে (স্লো কাজ করে)।

### 🐢 **Lesson 25: সাব-কুয়েরি (Subqueries) - পেটের ভেতর প্যাঁচ**

**🗣️ সহজ বাংলা:**
একটা কুয়েরির পেটের ভেতর আরেকটা কুয়েরি ঢুকিয়ে দেওয়াকে বলে **Subquery** বা **Nested Query**।
ভেতরের কুয়েরি (Inner Query) আগে রান করে, তার রেজাল্ট নিয়ে বাইরের কুয়েরি (Outer Query) কাজ করে।

**🤣 ফানি এনালজি (Real-life):**
**ইনসেপশন মুভি (Dream inside a dream)।**
অথবা ধরো তুমি ছোট ভাই। আম্মুর কাছে পকেট মানি চাওয়ার সাহস নাই।
তুমি -> আম্মুকে বললে (Outer Query) -> আম্মু আব্বুকে বলল (Inner Query)।
আব্বুর উত্তর আম্মুর কাছে আসবে, তারপর আম্মু তোমাকে জানাবে।

**💻 SQL Example:**
প্রশ্ন: *সবচেয়ে দামি প্রোডাক্ট কোনটা?*
```sql
SELECT Name, Price 
FROM Products 
WHERE Price = (SELECT MAX(Price) FROM Products);
```
*(ব্র্যাকেটের অংশটুকু আগে বের করবে ম্যাক্সিমাম প্রাইস কত, ধরো ৫০০০। তারপর মেইন কুয়েরি খুঁজবে ৫০০০ দামের প্রোডাক্ট কোনটা।)*

**🤔 কখন/কেন ব্যবহার করব?**
*   যখন একটা প্রশ্নের উত্তর জানার জন্য আগে আরেকটা ছোট প্রশ্নের উত্তর জানা দরকার হয়।

**✅ Best Practice:**
*   Subquery মাঝে মাঝে স্লো হয়। সম্ভব হলে `JOIN` দিয়ে কাজ করার চেষ্টা করবে। তবে ছোটখাটো কাজের জন্য Subquery বস!

**❌ Common Mistakes:**
*   সাবকুয়েরি যদি একাধিক রেজাল্ট দেয় আর তুমি `WHERE ID = ...` ব্যবহার করো, তাহলে এরর খাবে। তখন `WHERE ID IN (...)` ব্যবহার করতে হয়।

**🏆 Mini Practice Task:**
"যাদের স্যালারি গড় স্যালারির (Average Salary) চেয়ে বেশি, তাদের নাম দেখাও।"
এটা করার জন্য:
১. আগে `AVG(Salary)` বের করো।
২. তারপর সেটাকে মেইন কুয়েরির `WHERE` কন্ডিশনে বসাও।
চেষ্টা করো!
