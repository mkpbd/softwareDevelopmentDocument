### 🖼️ **Lesson 31: ভিউ (Views) - মেকআপ দেওয়া টেবিল**

**🗣️ সহজ বাংলা:**
ভিউ (View) কোনো আসল টেবিল না। এটা হলো একটা **ভার্চুয়াল টেবিল** বা একটা **সেভ করা কুয়েরি**।
ধরো, তোমার টেবিলে ৫০টা কলাম আছে, কিন্তু তুমি জুনিয়র ডেভেলপারকে মাত্র ৩টা কলাম দেখাতে চাও (বাকিগুলো সিক্রেট)। তুমি একটা ভিউ বানিয়ে তাকে দিবে। সে মনে করবে এটাই টেবিল, কিন্তু আসলে সে একটা জানলা দিয়ে ডাটা দেখছে।

**🤣 ফানি এনালজি (Real-life):**
**রঙিন চশমা বা জানলা।**
বাইরে রোদ (Real Data), কিন্তু তুমি সানগ্লাস পরলে সব ঠান্ডা দেখছো (View)।
অথবা রেস্টুরেন্টের **মেনু কার্ড**। মেনু কার্ডে খাবারের ছবি আর দাম আছে, কিন্তু মেনু কার্ডটা নিজে খাবার না। ওটা কিচেন (Database) এর একটা রিপ্রেজেন্টেশন মাত্র।

**🎨 ASCII Art Example:**
```text
  [ Real Table: Employees ]       [ VIEW: Public_Emp ]
  +----+-------+---------+       +-------+
  | ID | Name  | Salary  |  -->  | Name  |
  +----+-------+---------+       +-------+
  | 1  | Rahim | 50000   |       | Rahim |
  | 2  | Karim | 60000   |       | Karim |
  +----+-------+---------+       +-------+
  (Salary লুকানো আছে)
```

**💻 SQL Example:**
```sql
CREATE VIEW v_EmployeeNames AS
SELECT Name, Department
FROM Employees
WHERE IsActive = 1;

-- ব্যবহার করার নিয়ম (হুবহু টেবিলের মতো)
SELECT * FROM v_EmployeeNames;
```

**🤔 কখন ব্যবহার করব?**
*   **সিকিউরিটি:** সেনসিটিভ ডাটা (স্যালারি, পাসওয়ার্ড) লুকানোর জন্য।
*   **সরলীকরণ:** বিশাল বড় `JOIN` কুয়েরি বারবার না লিখে একটা ভিউতে সেভ করে রাখা।

**✅ Best Practice:**
*   ভিউ-এর নামের আগে `v_` বা `vw_` লাগানো ভালো। তাহলে বোঝা যায় এটা আসল টেবিল না।

### ⚙️ **Lesson 32: স্টোরড প্রসিডিউর (Stored Procedures / SP) - কাজের বুয়া**

**🗣️ সহজ বাংলা:**
এসপি (SP) হলো ডাটাবেসের **সবচেয়ে শক্তিশালী অস্ত্র**।
এটা হলো একগুচ্ছ SQL কোডের প্যাকেট। তুমি কোডগুলো লিখে একটা নাম দিয়ে সেভ করে রাখবে। যখনই দরকার হবে, শুধু নাম ধরে ডাক দিবে (Execute), সে সব কাজ করে দিবে।
এতে লজিক, লুপ, কন্ডিশন (If-Else), ইনসার্ট, আপডেট—সব করা যায়।

**🤣 ফানি এনালজি (Real-life):**
**কফি মেশিন বা সেট মেনু।**
*   **Raw SQL:** তুমি ওয়েটারকে বলছ—"ভাই ভাত দাও, ডাল দাও, মুরগি দাও, লেবু দাও..." (বারবার বলা লাগে)।
*   **Stored Procedure:** তুমি বলছ—"ভাই, **সেট মেনু ১** দাও।" (এক কমান্ডেই সব চলে আসলো)।

**💻 SQL Example:**
```sql
-- প্রসিডিউর বানানো
CREATE PROCEDURE sp_GetStudentByClass
    @ClassID int -- প্যারামিটার (ইনপুট)
AS
BEGIN
    SELECT Name, Roll FROM Students WHERE Class = @ClassID;
END;

-- প্রসিডিউর চালানো (Call করা)
EXEC sp_GetStudentByClass @ClassID = 5;
```

**🤔 কেন ব্যবহার করব?**
*   **Security:** হ্যাকাররা সহজে `SQL Injection` অ্যাটাক করতে পারে না।
*   **Performance:** এটা সার্ভারে আগে থেকেই কম্পাইল হয়ে থাকে, তাই রকেটের গতিতে রান হয়।
*   **Network Traffic:** ১০টা কুয়েরি না পাঠিয়ে ১টা SP কল করলেই কাজ শেষ।

**❌ Common Mistakes:**
*   SP-এর ভেতরে `SELECT *` ব্যবহার করা। সবসময় কলামের নাম উল্লেখ করবে।

### 🧮 **Lesson 33: ইউজার ডিফাইন্ড ফাংশন (Functions / UDF) - ক্যালকুলেটর**

**🗣️ সহজ বাংলা:**
ফাংশন আর প্রসিডিউর দেখতে প্রায় একই, কিন্তু কাজ আলাদা।
ফাংশনের একমাত্র কাজ হলো—**কিছু ইনপুট নিবে, হিসাব-নিকাশ করবে, আর একটা রেজাল্ট ফেরত (Return) দিবে।**
ফাংশন ডাটাবেসে কোনো পরিবর্তন (Insert/Update/Delete) করতে পারে না। সে খুব নিরীহ, শুধু হিসাব করে।

**🤣 ফানি এনালজি (Real-life):**
**জুস ব্লেন্ডার।**
তুমি ফল (Input) দিলে, সে প্রসেস করে জুস (Output) দিল।
ব্লেন্ডার দিয়ে তুমি ফল কাটতে পারো (Process), কিন্তু ব্লেন্ডার দিয়ে তুমি বাজার করতে যেতে পারবে না (No Database Change)।

**💻 SQL Example:**
বয়স বের করার একটা ফাংশন:
```sql
CREATE FUNCTION fn_CalculateAge (@DOB datetime)
RETURNS int
AS
BEGIN
    DECLARE @Age int;
    SET @Age = DATEDIFF(YEAR, @DOB, GETDATE());
    RETURN @Age;
END;

-- ব্যবহার (কুয়েরির ভেতরেই কল করা যায়!)
SELECT Name, dbo.fn_CalculateAge(BirthDate) as Age 
FROM Students;
```

**🤔 কখন ব্যবহার করব?**
*   যখন একই হিসাব বারবার দরকার হয়। যেমন: ট্যাক্স ক্যালকুলেশন, বয়স বের করা, ফুল নেম জোড়া লাগানো।

**✅ Best Practice:**
*   ফাংশন খুব সাবধানে ব্যবহার করতে হয়। বড় টেবিলে প্রতি রো-তে ফাংশন কল করলে কুয়েরি স্লো হয়ে যেতে পারে।

### 🔫 **Lesson 34: ট্রিগার (Triggers) - গোপন স্নাইপার**

**🗣️ সহজ বাংলা:**
ট্রিগার হলো এমন কোড যা তুমি নিজে কল করো না। এটা **অটোমেটিক ফায়ার** হয়।
তুমি বলে দিবে—"যদি `Users` টেবিলে নতুন ডাটা ঢুকে (INSERT), তাহলে সাথে সাথে তাকে একটা ওয়েলকাম ইমেইল পাঠাও।"
অথবা—"যদি কেউ ডাটা ডিলিট করে, তাহলে ব্যাকআপ টেবিলে সেটা সেভ করে রাখো।"

**🤣 ফানি এনালজি (Real-life):**
**চোরের অ্যালার্ম বা রিফ্লেক্স অ্যাকশন।**
আগুন স্পর্শ করলেই হাত অটোমেটিক সরে আসে (Trigger)। তোমাকে ভাবতে হয় না।
অথবা, দোকানের দরজায় কেউ ঢুকলেই "টুং টাং" শব্দ হয়। কাস্টমার ঢোকাটা হলো `Event`, আর শব্দ হওয়াটা হলো `Trigger`।

**🎨 ASCII Flow:**
```text
[ User Action ] --> [ INSERT Data ] --> [ 🔥 TRIGGER FIRES! ] --> [ Audit Log Saved ]
```

**💻 SQL Example:**
কেউ ডাটা ডিলিট করলে আমরা `Deleted_Log` টেবিলে রেখে দিব।
```sql
CREATE TRIGGER trg_AfterDeleteUser
ON Users
AFTER DELETE
AS
BEGIN
    INSERT INTO Deleted_Log (UserID, DeletedDate)
    SELECT ID, GETDATE() FROM deleted; -- 'deleted' একটা ম্যাজিক টেবিল
END;
```

**⚠️ সতকর্তা (Warning):**
*   ট্রিগার ডিবাগ করা খুব কঠিন। ডাটাবেস স্লো হওয়ার অন্যতম কারণ হলো ফালতু ট্রিগার লেখা। খুব দরকার না হলে ট্রিগার এভয়েড করা ভালো।

### ⚔️ **Lesson 35: এসপি বনাম ফাংশন (SP vs Function) - কার ক্ষমতা কত?**

**🗣️ সহজ বাংলা:**
এটা ইন্টারভিউয়ের হট টপিক! বস আর কর্মচারীর পার্থক্য।

| বৈশিষ্ট্য | Stored Procedure (SP) | Function (UDF) |
| :--- | :--- | :--- |
| **কাজ** | বস/ম্যানেজার (সব করতে পারে) | একাউন্টেন্ট (শুধু হিসাব করে) |
| **Return** | কিছু রিটার্ন করতেও পারে, নাও পারে | **অবশ্যই** ভ্যালু রিটার্ন করতে হবে |
| **DML (Insert/Update)** | করতে পারে ✅ | করতে পারে না ❌ |
| **ব্যবহার** | `EXEC sp_Name` দিয়ে চালাতে হয় | `SELECT` বা `WHERE` এর ভেতরে ব্যবহার হয় |
| **Try/Catch** | এরর হ্যান্ডেল করতে পারে | পারে না |

**🤣 ফানি এনালজি (Real-life):**
*   **SP:** বিয়ের আয়োজক। সে প্যান্ডেল সাজাতে পারে, খাবার দিতে পারে, টাকা নিতে পারে (All rounder)।
*   **Function:** ওই বিয়ের ক্যামেরাম্যান। সে শুধু ছবি তোলে আর আউটপুট দেয়। সে গিয়ে বিরিয়ানি রান্না করতে পারবে না।

**🏆 Mini Practice Task:**
তোমার ডাটাবেসে একটা `Orders` টেবিল আছে।
১. একটা **View** বানাও যেটা শুধু আজকের অর্ডারের লিস্ট দেখাবে।
২. একটা **SP** বানাও যেটা `OrderID` নিবে এবং ওই অর্ডার শিপিং হয়েছে কি না চেক করবে।
৩. একটা **Function** বানাও যেটা `Price` আর `Quantity` গুণ করে `TotalAmount` দিবে।
