ধরো, তুমি তোমার বন্ধুকে ৫০০ টাকা পাঠালে। তোমার অ্যাকাউন্ট থেকে টাকা কাটল, কিন্তু কারেন্ট চলে যাওয়ায় বন্ধুর অ্যাকাউন্টে টাকা ঢুকল না। টাকাটা কি হাওয়ায় মিলিয়ে যাবে?

### 💳 **Lesson 36: ট্রানজ্যাকশন - সব অথবা কিছুই না (Transaction Basics)**

**🗣️ সহজ বাংলা:**
ট্রানজ্যাকশন হলো একগুচ্ছ কাজের প্যাকেট।
শর্ত হলো: প্যাকেটের সব কাজ সফল হতে হবে। যদি একটাও ফেইল করে, তাহলে আগের সব কাজ বাতিল (Undo) করে আগের অবস্থায় ফিরে যেতে হবে।
একে SQL-এর ভাষায় বলে **Rollback**। আর সব সফল হলে বলে **Commit**।

**🤣 ফানি এনালজি (Real-life):**
**অনলাইনে পিৎজা অর্ডার।**
১. পিৎজা সিলেক্ট করলে।
২. পেমেন্ট করলে (টাকা কাটল)।
৩. অর্ডার কনফার্ম হলো।
যদি পেমেন্ট করার পর সার্ভার ক্র্যাশ করে এবং অর্ডার কনফার্ম না হয়, তবে তোমার টাকা ফেরত আসতে হবে (Rollback)। টাকা কেটে নিল কিন্তু পিৎজা দিল না—এটা ডাটাবেস হতে দিবে না।

**💻 SQL Example:**
```sql
BEGIN TRY
    BEGIN TRANSACTION -- ট্রানজ্যাকশন শুরু
    
        -- ১. রহিম থেকে ৫০০ টাকা কাটো
        UPDATE Accounts SET Balance = Balance - 500 WHERE Name = 'Rahim';
        
        -- ২. করিমকে ৫০০ টাকা দাও
        UPDATE Accounts SET Balance = Balance + 500 WHERE Name = 'Karim';
        
    COMMIT TRANSACTION -- সব ঠিক থাকলে সেভ করো
    PRINT 'টাকা পাঠানো সফল!'
END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION -- কোথাও ভুল হলে সব বাতিল (Undo)
    PRINT 'এরর! টাকা ফেরত দেওয়া হলো।'
END CATCH
```

**🤔 কখন ব্যবহার করব?**
*   যখনই একাধিক টেবিলে একসাথে ডাটা ইনসার্ট বা আপডেট করতে হয় (যেমন: ইনভয়েস এবং ইনভয়েস ডিটেইলস)।

### 🧪 **Lesson 37: ACID প্রপার্টি - ডাটাবেসের সংবিধান**

**🗣️ সহজ বাংলা:**
একটা ভালো ট্রানজ্যাকশনের ৪টি গুণ থাকতেই হবে। সংক্ষেপে **ACID**।
1.  **A - Atomicity (পরমাণু):** ভাঙা যাবে না। কাজ হলে পুরোটা হবে, না হলে হবে না। (0% or 100%)।
2.  **C - Consistency (নিয়ম):** ডাটাবেসের নিয়ম (Constraints) মানতে হবে। ব্যালেন্স নেগেটিভ হতে পারবে না।
3.  **I - Isolation (গোপনীয়তা):** আমার ট্রানজ্যাকশন চলাকালীন অন্য কেউ নাক গলাবে না।
4.  **D - Durability (স্থায়িত্ব):** একবার সেভ (Commit) বললে, সেটা আজীবনের জন্য সেভ। ভূমিকম্প হলেও ডাটা মুছবে না।

**🤣 ফানি এনালজি (Real-life):**
**ATM বুথ থেকে টাকা তোলা।**
*   **A:** টাকা মেশিনের মুখে এসে আটকে গেলে, একাউন্ট থেকে টাকা কাটবে না। (All or nothing).
*   **C:** তোমার একাউন্টে আছে ৫০০ টাকা, তুমি ১০০০ টাকা তুলতে পারবে না। (Rules).
*   **I:** তুমি যখন পিন দিচ্ছো, অন্য কেউ তোমার ব্যালেন্স চেক করতে পারবে না। (Privacy).
*   **D:** টাকা তোলার পর রিসিট বের হলো, এরপর ব্যাংকে আগুন লাগলেও তোমার ট্রানজ্যাকশন রেকর্ড থাকবে। (Permanent).

**🏆 Mini Practice Task:**
ভাবো তো, নোটপ্যাডে কিছু লেখার পর কারেন্ট চলে গেলে লেখা থাকে না (Not Durable)। কিন্তু ডাটাবেসে থাকে। কেন? (কারণ ডাটাবেস ডিস্কে লগ লিখে রাখে)।

### 🔒 **Lesson 38: লকস (Locks) - বাথরুমের দরজা**

**🗣️ সহজ বাংলা:**
যখন একজন ইউজার কোনো ডাটা এডিট (Update) করে, ডাটাবেস সেই রো-তে একটা **তালা (Lock)** লাগিয়ে দেয়। যাতে অন্য কেউ এসে একই সময়ে ওই ডাটা এডিট করতে না পারে।
কাজ শেষ হলে তালা খুলে দেয়।

**🤣 ফানি এনালজি (Real-life):**
**পাবলিক টয়লেট।**
কেউ ভেতরে ঢুকলে দরজা লক করে দেয় (Exclusive Lock)। বাইরে "Occupied" লেখা থাকে।
যতক্ষণ সে বের না হচ্ছে, অন্য কেউ ঢুকতে পারবে না। যদি লক না থাকত, তাহলে... বুঝতেই পারছ, কেলেঙ্কারি হতো! 💩

**🎨 ASCII Lock Visual:**
```text
User A (Updating Row 5) -----> [ 🔒 LOCK ] -----> Row 5 (Busy)
User B (Trying to Read) -----> [ ✋ WAIT ] -----> ...Waiting...
User A (Commit/Done)    -----> [ 🔓 UNLOCK ]
User B                  -----> [ Access Granted ]
```

**🤔 লকের প্রকারভেদ:**
*   **Shared Lock (S):** পড়ার জন্য। অনেকে একসাথে পড়তে পারে।
*   **Exclusive Lock (X):** লেখার জন্য। একজন লিখলে আর কেউ হাত দিতে পারবে না।

### 🕵️ **Lesson 39: কনকারেন্সি ও আইসোলেশন (Concurrency & Isolation Levels)**

**🗣️ সহজ বাংলা:**
একই ডাটাবেসে হাজার হাজার মানুষ একসাথে কাজ করছে (Concurrency)। এখন প্রশ্ন হলো, আমরা কতটা কড়াকড়ি করব?
SQL Server-এ ডাটা পড়ার কিছু লেভেল আছে:
1.  **Read Uncommitted (Dirty Read):** লক থাকলেও পড়া যায়। (সবচেয়ে রিস্কি)।
2.  **Read Committed (Default):** লক থাকলে পড়া যাবে না, অপেক্ষা করতে হবে। (স্ট্যান্ডার্ড)।
3.  **Serializable:** সবচেয়ে কড়া। আমি যখন পড়ব, কেউ লিখতেও পারবে না।

**🤣 ফানি এনালজি (Real-life):**
**পরীক্ষার হলে নকল করা।**
*   **Dirty Read:** তোমার বন্ধু খাতায় লিখছে (Confirm করেনি), তুমি উঁকি দিয়ে সেটা দেখে লিখলে। পরে সে কেটে ঠিক করে দিল, কিন্তু তুমি ভুলটাই লিখে বসে আছ।
*   **Read Committed:** বন্ধু লেখা শেষ করে খাতা জমা দেওয়ার পরেই তুমি দেখতে পাবে। (নিরাপদ)।

**💻 SQL Example:**
```sql
-- নোংরা পড়া (Dirty Read) - লক মানি না!
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT * FROM Accounts; 
-- (যে ডাটা এখনো কমিট হয়নি, তাও দেখাবে। রিপোর্ট ভুল হতে পারে!)
```

**✅ Best Practice:**
*   ডিফল্ট (`Read Committed`) ব্যবহার করাই ভালো। রিপোর্টিংয়ের জন্য মাঝে মাঝে `NOLOCK` ব্যবহার করা হয় যাতে কুয়েরি ফাস্ট হয়, কিন্তু ডাটা একটু এদিক-সেদিক হতে পারে।

### 💀 **Lesson 40: ডেডলক (Deadlocks) - দুই ছাগলের লড়াই**

**🗣️ সহজ বাংলা:**
ডেডলক হলো এমন পরিস্থিতি যখন দুইজন একে অপরের জন্য অপেক্ষা করে, কিন্তু কেউ সরে না। ফলে সিস্টেম হ্যাং হয়ে যায়।
User A ধরে আছে টেবিল ১, চায় টেবিল ২।
User B ধরে আছে টেবিল ২, চায় টেবিল ১।
কেউ কাউকে ছাড়ছে না। অনন্তকাল ধরে অপেক্ষা...

**🤣 ফানি এনালজি (Real-life):**
**সরু রাস্তায় রিক্সা জ্যাম।**
দুইটা রিক্সা মুখোমুখি।
রিক্সা ১: "তুই পিছে যা, আমি যাব।"
রিক্সা ২: "না, তুই পিছে যা, আমি যাব।"
কেউ পিছে যায় না, জ্যাম লেগে থাকে।
তখন ট্রাফিক পুলিশ (SQL Server) এসে যেকোনো একটা রিক্সাকে লাথি মেরে সরিয়ে দেয় (Victim), যাতে অন্যজন যেতে পারে।

**🎨 ASCII Art Example:**

```text
      (Holds Key A)           (Holds Key B)
      [ Process 1 ] --------> [ Process 2 ]
            ^                       |
            |                       |
            +-----(Wants Key A)-----+
                  (Wants Key B)
      
      💀 DEADLOCK! (Cycle Created)
```

**কিভাবে বাঁচব?**
*   সবাইকে একই সিরিয়ালে টেবিলে এক্সেস করতে হবে। (আগে টেবিল A, পরে টেবিল B)।
*   ট্রানজ্যাকশন যত ছোট রাখা যায়, তত ভালো।
*   `NOLOCK` ব্যবহার করলে ডেডলক কমে (কিন্তু ডাটা রিস্ক বাড়ে)।

**🏆 Mini Practice Task:**
তোমার বন্ধুকে বলো তোমার মোবাইলটা ধরতে। তুমি তার মোবাইল ধরো।
এবার শর্ত হলো: "আমার মোবাইল দিলে আমি তোমারটা ছাড়ব।"
সে-ও বলল: "আমারটা দিলে আমি তোমারটা ছাড়ব।"
তোমরা কি কখনো মোবাইল বদল করতে পারবে? এটাই ডেডলক! 😂
