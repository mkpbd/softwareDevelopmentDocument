### 🆔 **Lesson 41: অথেনটিকেশন বনাম অথরাইজেশন (Authentication vs. Authorization)**

**🗣️ সহজ বাংলা:**
এই দুইটা শব্দ শুনতে এক রকম লাগলেও কাজ আলাদা।
১. **Authentication (তুমি কে?):** সিস্টেমে ঢোকার অনুমতি। (Login)।
২. **Authorization (তোমার ক্ষমতা কতটুকু?):** ভেতরে ঢুকে তুমি কী কী করতে পারবে। (Permission)।

**🤣 ফানি এনালজি (Real-life):**
**অফিস বিল্ডিং।**
*   **Authentication:** গেটের দারোয়ান তোমার আইডি কার্ড দেখল এবং ঢুকতে দিল। (Login Successful).
*   **Authorization:** তুমি কি এখন MD স্যারের রুমে ঢুকে তার চেয়ারে বসতে পারবে? না! তোমার এক্সেস শুধু নিজের ডেস্কে। (Permission Denied).

**🎨 ASCII Art:**
```text
[ LOGIN GATE ] --> (User/Pass Check) --> ✅ Success (Authentication)
       |
       v
[ INSIDE DB ] --> Try to Delete Table? --> ❌ STOP! (Authorization Failed)
```

**💻 SQL Example:**
```sql
-- ১.Login বানানো (Authentication)
CREATE LOGIN Rahim WITH PASSWORD = 'StrongPassword123';

-- ২. User বানানো (Authorization এর শুরু)
CREATE USER RahimUser FOR LOGIN Rahim;
```

**🤔 কখন ব্যবহার করব?**
*   সবার জন্য আলাদা আলাদা লগিন তৈরি করবে। সবাইকে `sa` (System Admin) পাসওয়ার্ড দিবে না।

### 👮 **Lesson 42: রোলস এবং পারমিশন (Roles & Permissions)**

**🗣️ সহজ বাংলা:**
অফিসে ৫০ জন এমপ্লয়ি থাকলে তুমি কি ৫০ জনকে ধরে ধরে বলবে—"তুমি এই ফাইল পড়তে পারবে, তুমি ওটা পারবে না"? পাগল হয়ে যাবে!
এর চেয়ে ভালো, একটা গ্রুপ বা **Role** বানাও। নাম দাও "HR Team"। তারপর পারমিশন দাও—"HR Team সব ফাইল দেখতে পারবে"। এবার নতুন এমপ্লয়ি আসলে তাকে শুধু ওই গ্রুপে ঢুকিয়ে দাও। ব্যাস!

**🤣 ফানি এনালজি (Real-life):**
**চাবির ছড়া।**
ক্লিনারকে প্রতিটা রুমের চাবি আলাদা আলাদা না দিয়ে, একটা **মাস্টার চাবি** (Role) দিয়ে দাও যেটা দিয়ে সব বাথরুম খোলা যায়, কিন্তু লকার খোলা যায় না।

**💻 SQL Example:**
```sql
-- Role: যারা শুধু ডাটা পড়তে পারবে (লিখতে পারবে না)
-- SQL Server এ ডিফল্ট রোল আছে: db_datareader

-- Rahim কে শুধু পড়ার পারমিশন দাও
EXEC sp_addrolemember 'db_datareader', 'RahimUser';
```

**✅ Best Practice (Principle of Least Privilege):**
*   যার যতটুকু দরকার, তাকে ঠিক ততটুকুই পাওয়ার দিবে। অযথা কাউকে `db_owner` বা `admin` বানাবে না। ইন্টার্নকে ডিলিট করার ক্ষমতা দেওয়া মানে নিজের পায়ে কুড়াল মারা।

### 💉 **Lesson 43: এসকিউএল ইঞ্জেকশন (SQL Injection) - হ্যাকারের প্রিয় অস্ত্র**

**🗣️ সহজ বাংলা:**
এটা হলো হ্যাকারদের ডাটাবেস হ্যাক করার ১ নম্বর টেকনিক।
তুমি যদি ইউজারের ইনপুট সরাসরি কুয়েরিতে জোড়া লাগাও, হ্যাকার সেখানে দুষ্টু কোড ঢুকিয়ে পুরো ডাটাবেস ডিলিট বা চুরি করতে পারে।
একে আটকানোর উপায় হলো **প্যারামিটার (Parameter)** ব্যবহার করা (আমরা Lesson 32 তে SP তে দেখেছি)।

**🤣 ফানি এনালজি (Real-life):**
**বোকা দারোয়ান।**
তুমি দারোয়ানকে বললে: "যার নাম রহিম, তাকে ঢুকতে দাও।"
হ্যাকারের নাম রহিম না। হ্যাকার দারোয়ানকে বলল: "আমার নাম জদু **অথবা ১=১ (যা সবসময় সত্য)**"।
বোকা দারোয়ান ভাবল, ১=১ তো সত্যই! যাও ঢুকে পড়ো!

**🎨 ASCII Attack:**
```text
User Input:  ' OR '1'='1
Query becomes: SELECT * FROM Users WHERE Name = '' OR '1'='1'
Result: শোলে সিনেমার মতো সব ডাকাত (Data) বেরিয়ে আসবে!
```

**💻 SQL Example:**
❌ **ভুল পদ্ধতি (Dangerous):**
```sql
SET @sql = 'SELECT * FROM Users WHERE Name = ' + @InputName; -- সর্বনাশ!
```

✅ **সঠিক পদ্ধতি (Safe):**
```sql
SELECT * FROM Users WHERE Name = @InputName; -- Parameterized Query
```

**🏆 Mini Practice Task:**
ইউটিউবে "SQL Injection Computerphile" লিখে সার্চ দিয়ে ৫ মিনিটের একটা ভিডিও দেখো। দেখলে গায়ের লোম দাঁড়িয়ে যাবে যে কত সহজে সাইট হ্যাক করা যায়!

### 💾 **Lesson 44: ব্যাকআপের প্রকারভেদ (Backup Types) - বিপদের বন্ধু**

**🗣️ সহজ বাংলা:**
ডাটাবেস যেকোনো সময় ক্র্যাশ করতে পারে। তাই ব্যাকআপ রাখা ফরজ। তিন ধরণের ব্যাকআপ হয়:
1.  **Full Backup:** পুরো ডাটাবেসের কপি। (অনেক জায়গা খায়)।
2.  **Differential Backup:** শেষ ফুল ব্যাকআপের পর **যেটুকু পরিবর্তন হয়েছে**, শুধু সেটুকু। (জায়গা কম খায়)।
3.  **Transaction Log Backup:** প্রতিটা ছোট ছোট কাজের (Transaction) রেকর্ড। (প্রতি ১০-১৫ মিনিট পর পর নেওয়া হয়)।

**🤣 ফানি এনালজি (Real-life):**
**মুভি শুটিং।**
*   **Full:** পুরো সিনেমার রিল। (সপ্তাহে একবার)।
*   **Diff:** গতকালের পর আজ যেই সিনগুলো শুট হয়েছে। (প্রতিদিন রাতে)।
*   **Log:** বিহাইন্ড দ্য সিন বা প্রতিটা শটের ফুটেজ। (প্রতি ঘণ্টায়)।

**🎨 ASCII Strategy:**
```text
Sunday: [ FULL BACKUP 📦 ]
Monday: [ Diff ░ ] (Changes since Sun)
Tuesday:[ Diff ▒ ] (Changes since Sun)
...
Hourly: [ Log ][ Log ][ Log ]...
```

**💻 SQL Example:**
```sql
-- ফুল ব্যাকআপ
BACKUP DATABASE MyShopDB 
TO DISK = 'D:\Backups\MyShopDB_Full.bak';
```

**🤔 কেন ব্যবহার করব?**
*   Full Backup নিতে অনেক সময় লাগে, তাই রোজ রোজ নেওয়া যায় না। তাই আমরা Full + Diff + Log এর কম্বিনেশন ব্যবহার করি।

### 🚑 **Lesson 45: রিকভারি মডেল (Recovery Models) - বাঁচার উপায়**

**🗣️ সহজ বাংলা:**
রিকভারি মডেল ঠিক করে তুমি ডাটা কতটা নিখুঁতভাবে ফেরত চাও।
1.  **Simple Model:** লগ ফাইল জমিয়ে রাখে না। ব্যাকআপ নেওয়া শেষ? লগ ডিলিট। (সহজ, কিন্তু নির্দিষ্ট সময়ের ডাটা ফেরত পাওয়া যায় না)।
2.  **Full Model:** সব কিছুর লগ রাখে। তুমি চাইলে বলতে পারো—"গতকাল দুপুর ২টা বেজে ৩ মিনিটের অবস্থায় ডাটাবেসকে ফিরিয়ে দাও।" (Point-in-time recovery)।

**🤣 ফানি এনালজি (Real-life):**
**সিসিটিভি (CCTV) ক্যামেরা।**
*   **Simple:** আগের দিনের ফুটেজ ডিলিট করে নতুন ফুটেজ রেকর্ড করা। জায়গা বাঁচে, কিন্তু চুরির ২ দিন পর গেলে ফুটেজ পাবে না।
*   **Full:** গত ১ বছরের সব ফুটেজ হার্ডডিস্কে আছে। তুমি যেকোনো সেকেন্ডের ঘটনা দেখতে পারবে।

**🤔 কখন কোনটা ব্যবহার করব?**
*   **Bank/Finance:** অবশ্যই `FULL` মডেল। ১ টাকার হিসাবও হারানো যাবে না।
*   **Test/Dev DB:** `SIMPLE` মডেল। লগ ফাইল বড় হয়ে ডিস্ক ফুল হওয়ার দরকার নেই।

**✅ Best Practice:**
*   ডাটাবেস বানানোর পর চেক করো সেটা কোন মডেলে আছে। প্রোডাকশন সার্ভারে `SIMPLE` থাকলে কিন্তু বিপদ! ডাটা হারালে আর ফিরে পাবে না।

**🏆 Mini Practice Task (Serious Task):**
তোমার কম্পিউটারে একটা ফোল্ডার বানাও `C:\SQLBackups`।
SQL Server এ একটা কুয়েরি লিখে তোমার প্র্যাকটিস ডাটাবেসটার একটা `FULL BACKUP` নাও। ব্যাকআপ ফাইলটা ফোল্ডারে জমা হয়েছে কি না চেক করো।
(বি:দ্র: জীবনে একবার হলেও ব্যাকআপ রিস্টোর করে প্র্যাকটিস করবে, নতুবা বিপদের সময় হাত কাঁপবে!)
