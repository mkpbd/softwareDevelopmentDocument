
## 🚀 Module 1: শুরু ও বেসিক (Getting Started)

#### Lesson 1: EF Core কী এবং প্রোজেক্ট সেটআপ

**👨‍🏫 কোড রান টিপ:** আপনার পিসিতে `.NET 8 SDK` ইনস্টল থাকতে হবে। আমরা `Console App` দিয়ে শুরু করব। টার্মিনাল বা কমান্ড প্রম্পট ওপেন রাখুন।

**🎉 ভূমিকা:**
EF Core (Entity Framework Core) হলো .NET-এর জন্য একটি জাদুকরী দোভাষী (Translator)। আপনি C# কোড লিখবেন, আর EF Core সেটাকে ডাটাবেজের (যেমন SQL Server) ভাষায় বুঝিয়ে দেবে। আপনাকে `SELECT * FROM...` এর মতো বোরিং SQL লিখতে হবে না!

**🎯 শেখার লক্ষ্য:**
1. ORM (Object-Relational Mapper) ধারণা বোঝা।
2. নতুন কনসোল অ্যাপ তৈরি করা।
3. প্রয়োজনীয় NuGet প্যাকেজ ইনস্টল করা।

**📖 প্রধান বিষয়বস্তু:**
আমরা একটি সিম্পল কনসোল অ্যাপ্লিকেশন তৈরি করব এবং সেখানে EF Core-এর লাইব্রেরি বা প্যাকেজ যুক্ত করব। আমরা এখানে `Microsoft.EntityFrameworkCore.SqlServer` ব্যবহার করব কারণ এটি খুব জনপ্রিয়। সাথে `Tools` প্যাকেজও লাগবে মাইগ্রেশনের জন্য।

**💻 কোড এবং সেটআপ:**

প্রথমে একটি ফোল্ডার বানিয়ে টার্মিনালে নিচের কমান্ডগুলো দিন:

```bash
# ১. সলিউশন ফোল্ডার তৈরি ও প্রবেশ
mkdir EfCoreCourse
cd EfCoreCourse

# ২. কনসোল প্রজেক্ট তৈরি
dotnet new console -n Lesson01_Intro
cd Lesson01_Intro

# ৩. EF Core SQL Server প্যাকেজ ইনস্টল
dotnet add package Microsoft.EntityFrameworkCore.SqlServer

# ৪. EF Core Tools প্যাকেজ ইনস্টল (মাইগ্রেশনের জন্য জরুরি)
dotnet add package Microsoft.EntityFrameworkCore.Tools
```

```text

```

```csharp
            Console.WriteLine("প্যাকেজ সাকসেসফুলি ইনস্টল হয়েছে।");

```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
1. টার্মিনালে `dotnet list package` কমান্ড দিয়ে চেক করুন প্যাকেজগুলো ঠিকঠাক ইনস্টল হয়েছে কি না।
2. `.csproj` ফাইলটি ওপেন করে দেখুন সেখানে `<PackageReference ... />` অংশটি যুক্ত হয়েছে কি না।

#### Lesson 2: প্রথম এন্টিটি ও DbContext তৈরি

**👨‍🏫 কোড রান টিপ:** আগের লেসনের প্রজেক্টেই আমরা কাজ করব।

**🎉 ভূমিকা:**
ডাটাবেজে টেবিল বানাতে চান? SQL ভুলে যান! C# এ শুধু একটা ক্লাস (Class) বানাবেন, EF Core সেটাকে টেবিলে রূপান্তর করবে। এই ক্লাসকে আমরা বলি **Entity**। আর ডাটাবেজের সাথে যোগাযোগের প্রধান গেটওয়ে হলো **DbContext**।

**🎯 শেখার লক্ষ্য:**
1. POCO (Plain Old CLR Object) বা এনটিটি ক্লাস তৈরি করা।
2. DbContext ক্লাস তৈরি ও ইনহেরিট করা।
3. DbSet প্রপার্টি ডিক্লেয়ার করা।

**📖 প্রধান বিষয়বস্তু:**
আমরা একটি `Product` ক্লাস বানাবো যা ডাটাবেজে `Products` টেবিল হবে। এরপর `AppDbContext` বানাবো যা ডাটাবেজ ম্যানেজ করবে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Product.cs`
```csharp
namespace Lesson01_Intro.Models
{
    // এটি আমাদের এনটিটি ক্লাস, যা ডাটাবেজে টেবিল হবে
    public class Product
    {
        public int Id { get; set; } // কনভেনশন অনুযায়ী এটি হবে Primary Key
        public string Name { get; set; } // প্রোডাক্টের নাম
        public decimal Price { get; set; } // প্রোডাক্টের দাম
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    // DbContext হলো ডাটাবেজের সাথে সেশনের মতো
    public class AppDbContext : DbContext
    {
        // DbSet<Product> মানে হলো ডাটাবেজে Products নামে একটি টেবিল থাকবে
        // এবং আমরা এই প্রপার্টি দিয়ে ডাটা আদান-প্রদান করব
        public DbSet<Product> Products { get; set; }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
1. `Customer` নামে আরেকটি ক্লাস তৈরি করুন যার `Id` (int) এবং `Email` (string) প্রপার্টি আছে।
2. `AppDbContext` এ `Customers` নামে নতুন একটি `DbSet` যোগ করুন।

**🧠 কুইজ:**
১. EF Core এ ডাটাবেজ টেবিল রিপ্রেজেন্ট করে কোনটি?

   A. Foreign Key
   B. Primary Key (উত্তর: B)

৩. আমাদের কাস্টম কন্টেক্সট ক্লাস কোন ক্লাসকে ইনহেরিট করে?

**⚠️ খুব জরুরি নোট:** এনটিটি ক্লাস অবশ্যই `public` হতে হবে এবং প্রপার্টিগুলোর `get; set;` থাকতে হবে, নইলে EF Core ডাটা রিড/রাইট করতে পারবে না।

#### Lesson 3: ডাটাবেজ কানেকশন ও প্রোভাইডার কনফিগারেশন

**👨‍🏫 কোড রান টিপ:** নিশ্চিত করুন আপনার পিসিতে SQL Server (Developer/Express) অথবা LocalDB ইনস্টল আছে।

**🎉 ভূমিকা:**
আপনার কোড রেডি, কিন্তু সে জানে না ডাটাবেজ কোথায়! ফোন করতে গেলে যেমন নাম্বার লাগে, তেমনি ডাটাবেজের সাথে কথা বলতে **Connection String** লাগে।

**🎯 শেখার লক্ষ্য:**
1. `OnConfiguring` মেথড ওভাররাইড করা।
2. কানেকশন স্ট্রিং লেখা (LocalDB বা SQL Server)।
3. `UseSqlServer` মেথড ব্যবহার করা।

**📖 প্রধান বিষয়বস্তু:**
আমরা `AppDbContext` ক্লাসের ভেতর বলে দেব কোন ডাটাবেজ সার্ভারে কানেক্ট করতে হবে। শেখার সুবিধার জন্য আমরা সরাসরি `OnConfiguring` মেথডে হার্ডকোড করব (বাস্তব প্রজেক্টে এটা কনফিগারেশন ফাইলে থাকে)।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        public DbSet<Product> Products { get; set; }

        // এই মেথডটি ডাটাবেজ কনফিগার করতে ব্যবহার হয়
        protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
        {
            // আমরা SQL Server LocalDB ব্যবহার করছি
            // "Server=(localdb)\\mssqllocaldb" - এটি ডিফল্ট লোকাল সার্ভার
            // "Database=EfCoreCourseDb" - ডাটাবেজের নাম যা তৈরি হবে
            // "Trusted_Connection=True" - উইন্ডোজ অথেনটিকেশন ব্যবহার করবে
            optionsBuilder.UseSqlServer(
                @"Server=(localdb)\mssqllocaldb;Database=EfCoreCourseDb;Trusted_Connection=True;TrustServerCertificate=True"
            );
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
1. কানেকশন স্ট্রিং-এ ডাটাবেজের নাম পরিবর্তন করে `MyFirstShopDb` দিন।
2. `TrustServerCertificate=True` অংশটি মুছে দিয়ে দেখুন কোনো এরর আসে কি না (লেটেস্ট ড্রাইভার সিকিউরিটি চেক করে)।

**🧠 কুইজ:**
১. ডাটাবেজ প্রোভাইডার নির্বাচন করতে কোন অবজেক্ট ব্যবহার করা হয়?
   A. DbContextOptionsBuilder (উত্তর: A)
   B. ModelBuilder
   C. ServiceProvider

২. `(localdb)\mssqllocaldb` কী?

৩. কানেকশন স্ট্রিং প্রোডাকশন অ্যাপে কোথায় রাখা উচিত?
   A. C# কোডের ভেতরে
   B. appsettings.json বা Environment Variable-এ (উত্তর: B)
   C. টেক্সট ফাইলে

**⚠️ খুব জরুরি নোট:** কানেকশন স্ট্রিং-এ `Server` বা `Data Source` একই কাজ করে। পাসওয়ার্ড থাকলে `User Id=...;Password=...` ব্যবহার করতে হয়।

#### Lesson 4: মাইগ্রেশন (Migrations) এর জাদুকরী জগত

**👨‍🏫 কোড রান টিপ:** টার্মিনাল ওপেন করুন এবং প্রজেক্ট ফোল্ডারে থাকুন।

**🎉 ভূমিকা:**
এখন পর্যন্ত আমরা শুধু কোড লিখেছি, ডাটাবেজ কিন্তু এখনো তৈরি হয়নি! **Migration** হলো সেই জাদুকরী প্রক্রিয়া যা আপনার C# কোডের পরিবর্তনগুলো ট্র্যাক করে এবং ডাটাবেজ তৈরি বা আপডেট করার জন্য নির্দেশাবলী (Instructions) প্রস্তুত করে।

**🎯 শেখার লক্ষ্য:**
1. EF Core CLI টুলস ব্যবহার করা।
2. প্রথম মাইগ্রেশন তৈরি করা (`add`).
3. ডাটাবেজ আপডেট করা (`update`).

**📖 প্রধান বিষয়বস্তু:**
আমরা CLI কমান্ড ব্যবহার করে EF Core-কে বলব, "ভাই, আমার `AppDbContext` আর `Product` ক্লাস দেখে একটা মাইগ্রেশন ফাইল বানাও এবং সেই অনুযায়ী ডাটাবেজ তৈরি করে ফেলো।"

**💻 কমান্ড লাইন টিউটোরিয়াল:**

১. **মাইগ্রেশন তৈরি:**
টার্মিনালে লিখুন:
```bash
dotnet ef migrations add InitialCreate
```
*ব্যাখ্যা:* এটি `Migrations` ফোল্ডারে কিছু C# ফাইল তৈরি করবে যা টেবিল তৈরির নির্দেশ ধারণ করে। `InitialCreate` হলো মাইগ্রেশনের নাম।

২. **ডাটাবেজ আপডেট (টেবিল তৈরি):**
টার্মিনালে লিখুন:
```bash
dotnet ef database update
```
*ব্যাখ্যা:* এটি ডাটাবেজে SQL কমান্ড চালাবে এবং টেবিল তৈরি করবে। সফল হলে "Done." দেখাবে।

**ফোল্ডার স্ট্রাকচার (নতুন):**
```text
Lesson01_Intro/
  └── Migrations/
       ├── 202310..._InitialCreate.cs (টাইমস্ট্যাম্প সহ)
       ├── AppDbContextModelSnapshot.cs
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
1. SQL Server Management Studio (SSMS) বা Visual Studio-র SQL Server Object Explorer দিয়ে চেক করুন `EfCoreCourseDb` নামে ডাটাবেজ তৈরি হয়েছে কি না।
2. `Product` ক্লাসে নতুন প্রপার্টি `public string Description { get; set; }` যোগ করুন এবং আবার `dotnet ef migrations add AddDescription` কমান্ড দিন।

   B. বর্তমান মডেলের অবস্থা মনে রাখা যাতে পরবর্তী পরিবর্তন ধরা যায় (উত্তর: B)
   C. ডাটা ডিলিট করা

**⚠️ খুব জরুরি নোট:** কোডে মডেল (Entity) পরিবর্তন করলে *অবশ্যই* নতুন মাইগ্রেশন অ্যাড করতে হবে এবং ডাটাবেজ আপডেট করতে হবে। নাহলে কোড আর ডাটাবেজের মিল থাকবে না (Sync Error)।

#### Lesson 5: ডাটা সেভ করা (Create Operation)

**👨‍🏫 কোড রান টিপ:** `Program.cs` ফাইলে আমরা এখন কোড লিখব।

**🎉 ভূমিকা:**
ডাটাবেজ আছে, টেবিল আছে। কিন্তু টেবিল তো খালি! চলুন আমাদের প্রথম প্রোডাক্ট ডাটাবেজে ইনসার্ট করি। EF Core-এ এটা খুবই সহজ, ঠিক যেন লিস্টে `Add` করা।

**🎯 শেখার লক্ষ্য:**
1. `DbContext` ইনস্ট্যানশিয়েট করা।
2. `Add` মেথড ব্যবহার করা।
3. `SaveChanges` মেথডের গুরুত্ব বোঝা।

**📖 প্রধান বিষয়বস্তু:**
আমরা `using` ব্লক ব্যবহার করে `AppDbContext` এর একটি ইনস্ট্যান্স তৈরি করব (যাতে কাজ শেষে মেমোরি ক্লিন হয়)। এরপর একটি `Product` অবজেক্ট তৈরি করে `DbSet`-এ অ্যাড করব এবং সবশেষে `SaveChanges` কল করব। `SaveChanges` কল না করলে ডাটাবেজে কিছুই যাবে না!

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("--- EF Core Create Operation ---");

            // ১. DbContext তৈরি (using ব্লক ব্যবহার করছি যাতে অটোমেটিক ডিসপোজ হয়)
            using (var context = new AppDbContext())
            {
                // এই লাইনটি নিশ্চিত করে যে ডাটাবেজ তৈরি আছে (যদি মাইগ্রেশন কমান্ড না দিয়ে থাকেন)
                // তবে প্রোডাকশনে আমরা সাধারণত মাইগ্রেশন ব্যবহার করি।
                // context.Database.EnsureCreated(); 

                // ২. নতুন প্রোডাক্ট অবজেক্ট তৈরি
                var product = new Product
                {
                    Name = "Gaming Laptop",
                    Price = 120000.50m
                };

                // ৩. কনটেক্সট-এ প্রোডাক্ট যোগ করা (মেমোরিতে ট্র্যাক হচ্ছে)
                context.Products.Add(product);
                Console.WriteLine($"Product '{product.Name}' is added to context state: {context.Entry(product).State}");

                // ৪. ডাটাবেজে সেভ করা (SQL INSERT কমান্ড জেনারেট হবে)
                context.SaveChanges();

                Console.WriteLine($"Product Saved! New ID: {product.Id}"); 
                // লক্ষ্য করুন: সেভ হওয়ার পর EF Core অটোমেটিক Id আপডেট করে দেয়।
            }
        }
    }
}
```

**রান করার কমান্ড:** `dotnet run`

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
1. কোডে `SaveChanges()` লাইনটি কমেন্ট করে রান করুন। দেখুন ডাটাবেজে ডাটা যায় কি না। (যাবে না)।
2. লুপ ব্যবহার করে একসাথে ৫টি ভিন্ন প্রোডাক্ট অ্যাড করুন এবং লুপের বাইরে একবার `SaveChanges()` কল করুন (একে বলে ব্যাচিং, যা পারফরম্যান্স বাড়ায়)।

**🧠 কুইজ:**
১. `SaveChanges()` কল করার আগ পর্যন্ত ডাটা কোথায় থাকে?
   A. ডাটাবেজে
   B. মেমোরিতে (Change Tracker-এ) (উত্তর: B)
   C. হার্ডডিস্কে

২. ডাটাবেজে ডাটা সেভ হওয়ার পর `Id` প্রপার্টিতে কী হয়?
   A. এটি শূন্য হয়ে যায়
   B. ডাটাবেজ থেকে জেনারেট হওয়া প্রাইমারি কি অটোমেটিক সেট হয়ে যায় (উত্তর: B)
   C. কিছুই হয় না

৩. `using` ব্লক কেন ব্যবহার করা হয়?
   A. কোড দ্রুত রান করার জন্য
   B. DbContext সঠিকভাবে ডিসপোজ (Connection close) করার জন্য (উত্তর: B)
   C. ডাটাবেজ ডিলিট করার জন্য

**⚠️ খুব জরুরি নোট:** `SaveChanges()` হলো একটি "Transaction"। অর্থাৎ, আপনি ১০টা ডাটা অ্যাড করলেন, কিন্তু সেভ করার সময় ১টাতে এরর হলো—তাহলে কোনোটিই সেভ হবে না (All or Nothing)। এটি ডাটা ইন্টিগ্রিটি রক্ষা করে।

### Lesson 5: ডাটা সেভ করা (Create Operation)

**👨‍🏫 কোড রান টিপ:** আমরা `Program.cs` ফাইলে কোড লিখব। টার্মিনালে প্রজেক্ট ফোল্ডারে (`Lesson01_Intro`) অবস্থান করুন।

**🎉 ভূমিকা:**
ডাটাবেজ আছে, টেবিলও আছে, কিন্তু সব ফাঁকা! এটা অনেকটা নতুন আলমারি কেনার মতো—এখনও কাপড় রাখা হয়নি। EF Core-এ ডাটাবেজে ডাটা ইনসার্ট করা খুবই সহজ। আপনাকে `INSERT INTO...` এর মতো জটিল SQL লিখতে হবে না, শুধু C# লিস্টে আইটেম যোগ করার মতোই সহজ!

**🎯 শেখার লক্ষ্য:**
১. `DbContext` ইনস্ট্যানশিয়েট করা (তৈরি করা)।
২. `DbSet.Add()` মেথড ব্যবহার করে ডাটা প্রস্তুত করা।
৩. `SaveChanges()` মেথডের মাধ্যমে ডাটাবেজে চূড়ান্তভাবে সেভ করা।

**📖 প্রধান বিষয়বস্তু:**
ডাটা সেভ করার প্রক্রিয়াটি ৩টি ধাপে সম্পন্ন হয়:
1. **Add:** প্রথমে আপনি একটি নতুন অবজেক্ট তৈরি করেন এবং `Context`-কে বলেন "এটাকে ট্র্যাক করো"। তখন ডাটাটি শুধু মেমোরিতে (RAM) থাকে, ডাটাবেজে যায় না।
2. **Track:** EF Core এর `ChangeTracker` লক্ষ্য রাখে যে একটি নতুন ডাটা যোগ হয়েছে।
3. **Save:** যখন আপনি `SaveChanges()` কল করেন, তখন EF Core ডাটাবেজে একটি `INSERT` SQL কমান্ড পাঠায়।

**💻 কোড উদাহরণ:**

আপনার `Program.cs` ফাইলের আগের কোড মুছে নিচের কোডটি লিখুন:

**ফাইল:** `src/Lesson01_Intro/Program.cs`
```csharp
using System;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("--- EF Core Create Operation শুরু ---");

            // ১. DbContext তৈরি করা
            // 'using' স্টেটমেন্ট ব্যবহার করছি যাতে কাজ শেষে কানেকশন অটোমেটিক ক্লোজ হয়ে যায়
            using (var context = new AppDbContext())
            {
                // ২. একটি নতুন Product অবজেক্ট তৈরি (সাধারণ C# অবজেক্ট)
                var newProduct = new Product
                {
                    Name = "Smart Watch Pro",
                    Price = 5500.00m
                };

                // ৩. কনটেক্সট-এ প্রোডাক্ট যোগ করা
                // এই মুহূর্তে ডাটাবেজে কিছুই হয়নি, শুধু মেমোরিতে 'Added' স্টেটে আছে
                context.Products.Add(newProduct);
                
                Console.WriteLine($"সেভ করার আগে ID: {newProduct.Id} (State: {context.Entry(newProduct).State})");

                // ৪. ডাটাবেজে সেভ করা (Transaction)
                // এই লাইনেই মূলত SQL INSERT কমান্ড জেনারেট এবং এক্সিকিউট হয়
                context.SaveChanges();

                // ৫. সেভ হওয়ার পর EF Core অটোমেটিক জেনারেট হওয়া ID অবজেক্টে সেট করে দেয়
                Console.WriteLine($"সফলভাবে সেভ হয়েছে! নতুন Product ID: {newProduct.Id} (State: {context.Entry(newProduct).State})");
            }
        }
    }
}
```

### 💡 বোনাস: একসাথে অনেক ডাটা সেভ করা (Batch Insert)

লুপ চালিয়ে বারবার `SaveChanges()` কল করবেন না! এটা পারফরম্যান্সের জন্য খারাপ। দেখুন কিভাবে একসাথে অনেক ডাটা সেভ করতে হয়:

```csharp
// Program.cs এর ভেতরে (using ব্লকের মধ্যে)
var productsList = new List<Product>
{
    new Product { Name = "Keyboard", Price = 800 },
    new Product { Name = "Mouse", Price = 450 },
    new Product { Name = "Monitor", Price = 12000 }
};

// AddRange ব্যবহার করে পুরো লিস্ট একসাথে মেমোরিতে নেওয়া
context.Products.AddRange(productsList);

// একবার মাত্র SaveChanges কল করা (মাত্র ১টি ডাটাবেজ রাউন্ড ট্রিপ হবে)
context.SaveChanges(); 
Console.WriteLine("৩টি প্রোডাক্ট একসাথে সেভ হয়েছে!");
```

---

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Product` ক্লাসে `StockQuantity` (int) নামে একটি নতুন প্রপার্টি যোগ করুন। মাইগ্রেশন কমান্ড (`add` এবং `update`) চালিয়ে ডাটাবেজ আপডেট করুন। তারপর `Program.cs` এ স্টকসহ একটি প্রোডাক্ট সেভ করুন।
২. একটি `for` লুপ ব্যবহার করে ১০টি প্রোডাক্ট তৈরি করুন (যেমন: Product 1, Product 2...), কিন্তু লুপের ভেতরে `SaveChanges()` কল না করে লুপের **বাইরে** একবার কল করুন।

**🧠 কুইজ:**
১. `context.Products.Add(product)` কল করার সাথে সাথেই কি ডাটাবেজে ডাটা ঢুকে যায়?
   A. হ্যাঁ, সাথে সাথে।
   B. না, `SaveChanges()` কল করার পর যায়। (উত্তর: B)
   C. ডাটাবেজ রিস্টার্ট দিলে যায়।

২. ডাটাবেজে সেভ হওয়ার পর আমাদের C# অবজেক্টের `Id` প্রপার্টির কী পরিবর্তন হয়?
   A. কিছুই হয় না।
   B. ডাটাবেজ থেকে তৈরি হওয়া অটো-ইনক্রিমেন্ট ভ্যালু দিয়ে আপডেট হয়ে যায়। (উত্তর: B)
   C. নাল (Null) হয়ে যায়।

৩. একসাথে ১০টি ডাটা সেভ করার জন্য `SaveChanges()` কতবার কল করা ভালো?
   A. ১০ বার (লুপের ভেতরে)।
   B. ১ বার (লুপের বাইরে)। (উত্তর: B)
   C. কোনোবারই না।

**⚠️ খুব জরুরি নোট (Pro Tip):** `SaveChanges()` হলো একটি **"Transaction"**। মানে হলো, যদি আপনি ৫টি আইটেম অ্যাড করেন এবং সেভ করার সময় ৪ নম্বরটিতে কোনো সমস্যা হয়, তবে **কোনোটিই** সেভ হবে না। এটি ডাটাবেজের সুস্থতা (Integrity) বজায় রাখে।
