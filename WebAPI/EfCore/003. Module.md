### Lesson 11: কনফিগারেশন প্যাটার্ন: Data Annotations

**👨‍🏫 কোড রান টিপ:** এই লেসনের জন্য `System.ComponentModel.DataAnnotations` এবং `System.ComponentModel.DataAnnotations.Schema` নেমস্পেস প্রয়োজন হবে।

**🎉 ভূমিকা:**
Data Annotations হলো আপনার ক্লাসের প্রপার্টির ওপর "স্টিকি নোট" লাগিয়ে দেওয়ার মতো। আপনি ক্লাসের মাথার ওপর লিখে দেবেন "এটা টেবিলের নাম", আবার প্রপার্টির ওপর লিখে দেবেন "এটা আবশ্যিক (Required)"। এটি খুবই সহজ এবং কোড দেখলেই বোঝা যায় ডাটাবেজ কেমন হবে।

**🎯 শেখার লক্ষ্য:**
১. এনটিটি ক্লাসে অ্যাট্রিবিউট (Attribute) ব্যবহার করা।
২. টেবিল ও কলামের নাম পরিবর্তন করা (`[Table]`, `[Column]`)।
৩. ডাটা ভ্যালিডেশন ও স্কিমা ঠিক করা (`[Required]`, `[MaxLength]`)।

**📖 প্রধান বিষয়বস্তু:**
আমরা `Product` ক্লাসটিকে মডিফাই করব অথবা নতুন একটি `Student` ক্লাস তৈরি করব। কিছু জনপ্রিয় অ্যানোটেশন:
- `[Table("Name")]`: টেবিলের নাম পরিবর্তন করে।
- `[Key]`: যদি প্রপার্টির নাম `Id` না হয়, তবে এটিকে প্রাইমারি কি হিসেবে চেনার জন্য।
- `[Required]`: ডাটাবেজে কলামটি `NOT NULL` হবে।
- `[MaxLength(50)]`: `nvarchar(max)` এর বদলে `nvarchar(50)` হবে।
- `[Column("Name")]`: ডাটাবেজ কলামের নাম পরিবর্তন করে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Student.cs`
```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace Lesson01_Intro.Models
{
    // ১. টেবিলের নাম 'Students' এর বদলে 'tbl_Student_Info' হবে
    [Table("tbl_Student_Info")]
    public class Student
    {
        // ২. প্রপার্টির নাম 'StudentId', কিন্তু EF বুঝবে এটাই প্রাইমারি কি [Key] এর কারণে
        [Key]
        public int StudentId { get; set; }

        // ৩. এই ফিল্ডটি নাল হতে পারবে না এবং কলামের নাম হবে 'Full_Name'
        // সর্বোচ্চ ১০০ ক্যারেক্টার
        [Required]
        [Column("Full_Name")]
        [MaxLength(100)]
        public string Name { get; set; }

        // ৪. এটি ডাটাবেজে সেভ হবে না (Ignored)
        [NotMapped]
        public string TemporaryRemarks { get; set; }
        
        public string Email { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
public DbSet<Student> Students { get; set; }
```

```bash
dotnet ef migrations add AddedStudentWithAnnotations
dotnet ef database update
```
*(এরপর ডাটাবেজ চেক করলে দেখবেন টেবিলের নাম `tbl_Student_Info` হয়েছে এবং কলামগুলো কনফিগার অনুযায়ী তৈরি হয়েছে)*

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Student` ক্লাসে `Email` প্রপার্টিতে `[Required]` এবং `[MaxLength(50)]` যুক্ত করুন। আবার মাইগ্রেশন কমান্ড চালিয়ে পরিবর্তন দেখুন।
২. `[Column(Order = 1)]` ব্যবহার করে কলামের ক্রম পরিবর্তন করার চেষ্টা করুন (নোট: সব ডাটাবেজ প্রোভাইডার এটি সাপোর্ট করে না, তবে জেনে রাখা ভালো)।

**🧠 কুইজ:**
১. একটি প্রপার্টিকে ডাটাবেজে তৈরি হওয়া থেকে আটকাতে কোন অ্যানোটেশন ব্যবহার হয়?
   A. [Ignore]
   B. [NotMapped] (উত্তর: B)
   C. [Hidden]

২. `[Required]` অ্যানোটেশন ডাটাবেজে কী প্রভাব ফেলে?
   A. কলামটি `NULL` অ্যালাউ করে
   B. কলামটি `NOT NULL` হয়ে যায় (উত্তর: B)
   C. এটি একটি প্রাইমারি কি হয়ে যায়

৩. Data Annotations ব্যবহার করার জন্য কোন নেমস্পেস দরকার?

   B. System.ComponentModel.DataAnnotations (উত্তর: B)

**⚠️ খুব জরুরি নোট:** Data Annotations সহজ, কিন্তু এটি আপনার এনটিটি ক্লাসকে একটু "নোংরা" করে ফেলে (Clean Code ভায়োলেশন)। এছাড়াও সব কনফিগারেশন (যেমন কম্পোজিট কি) অ্যানোটেশন দিয়ে করা যায় না।

### Lesson 12: কনফিগারেশন প্যাটার্ন: Fluent API

**👨‍🏫 কোড রান টিপ:** আমরা এখন `AppDbContext.cs` ফাইলের `OnModelCreating` মেথডে কাজ করব।

**🎉 ভূমিকা:**
Data Annotations যদি হয় "স্টিকি নোট", তবে **Fluent API** হলো "অফিসিয়াল রুলবুক"। এটি অনেক বেশি শক্তিশালী। এর মাধ্যমে আপনি এনটিটি ক্লাসকে একদম পরিষ্কার (Clean POCO) রাখতে পারেন এবং `DbContext`-এর ভেতরে বসে বলে দিতে পারেন ডাটাবেজ কেমন হবে। জটিল কনফিগারেশনের জন্য এটাই সেরা।

**🎯 শেখার লক্ষ্য:**
১. `OnModelCreating` মেথড ওভাররাইড করা।
২. `ModelBuilder` ব্যবহার করে কনফিগারেশন লেখা।
৩. Fluent API এবং Data Annotations-এর পার্থক্য বোঝা।

**📖 প্রধান বিষয়বস্তু:**
Fluent API লেখার সিনট্যাক্স চেইন করা যায় (এজন্যই নাম Fluent)।
প্যাটার্ন: `modelBuilder.Entity<ClassName>().Property(p => p.Name).ConfigMethod();`

আমরা একটি নতুন ক্লাস `Course` বানাবো কোনো অ্যাট্রিবিউট ছাড়া, এবং `DbContext`-এ সেটা কনফিগার করব।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Course.cs` (পরিষ্কার ক্লাস)
```csharp
namespace Lesson01_Intro.Models
{
    public class Course
    {
        public int Id { get; set; }
        public string Title { get; set; }
        public decimal Fees { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        public DbSet<Product> Products { get; set; }
        public DbSet<Student> Students { get; set; }
        public DbSet<Course> Courses { get; set; } // নতুন সেট

        protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
        {
            optionsBuilder.UseSqlServer(@"Server=(localdb)\mssqllocaldb;Database=EfCoreCourseDb;Trusted_Connection=True;TrustServerCertificate=True");
        }

        // ⚡ Fluent API কনফিগারেশনের জায়গা
        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            // ১. টেবিলের নাম কনফিগারেশন
            modelBuilder.Entity<Course>()
                        .ToTable("tbl_Courses");

            // ২. প্রপার্টি কনফিগারেশন
            modelBuilder.Entity<Course>()
                        .Property(c => c.Title)
                        .IsRequired()       // [Required] এর বিকল্প
                        .HasMaxLength(200)  // [MaxLength] এর বিকল্প
                        .HasColumnName("Course_Title"); // [Column] এর বিকল্প

            // ৩. ডিফল্ট ভ্যালু সেট করা (যা অ্যানোটেশন দিয়ে সহজে হয় না)
            modelBuilder.Entity<Course>()
                        .Property(c => c.Fees)
                        .HasDefaultValue(5000.00m);
        }
    }
}
```

**মাইগ্রেশন কমান্ড:** (টার্মিনালে রান করুন)
```bash
dotnet ef migrations add AddedCourseWithFluentAPI
dotnet ef database update
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Course` ক্লাসে `Description` নামে একটি প্রপার্টি যোগ করুন। Fluent API ব্যবহার করে সেট করুন যেন ডাটাবেজে কলামটির টাইপ `varchar(500)` হয় (`.HasColumnType("varchar(500)")` ব্যবহার করুন)।
২. `Product` এনটিটির জন্যও `OnModelCreating` এ কিছু রুলস লিখুন। (মনে রাখবেন: Fluent API এর ক্ষমতা Data Annotations এর চেয়ে বেশি, তাই কনফ্লিক্ট হলে Fluent API জিতে যাবে)।

**🧠 কুইজ:**
১. Fluent API কনফিগারেশন কোথায় লিখতে হয়?
   A. Program.cs ফাইলে
   B. এনটিটি ক্লাসের ভেতরে
   C. DbContext-এর OnModelCreating মেথডে (উত্তর: C)

২. যদি এনটিটিতে `[MaxLength(50)]` থাকে আর Fluent API-তে `.HasMaxLength(100)` থাকে, কোনটি কাজ করবে?
   A. Data Annotations (50)
   B. Fluent API (100) (উত্তর: B - Fluent API সবসময় অগ্রাধিকার পায়)

৩. `ModelBuilder` অবজেক্টটি কোন মেথডের প্যারামিটার হিসেবে পাওয়া যায়?
   A. OnConfiguring

**⚠️ খুব জরুরি নোট:** বড় প্রোজেক্টে `OnModelCreating` অনেক বড় হয়ে যায়। তখন আমরা প্রতিটি এনটিটির কনফিগারেশন আলাদা ফাইলে (`IEntityTypeConfiguration` ইন্টারফেস ব্যবহার করে) ভাগ করে ফেলি। এটা আমরা পরবর্তীতে বেস্ট প্র্যাকটিস লেসনে দেখব।

### Lesson 13: প্রাইমারি কি (Primary Key) ও কম্পোজিট কি

**👨‍🏫 কোড রান টিপ:** এই লেসনের কোডগুলো `AppDbContext.cs` এর `OnModelCreating` মেথডে লিখতে হবে।

**🎉 ভূমিকা:**
প্রত্যেকটি মানুষের যেমন একটি ইউনিক NID বা পাসপোর্ট নাম্বার থাকে, ডাটাবেজের প্রতিটা রো (Row)-এর একটি ইউনিক পরিচয় দরকার। একে বলে **Primary Key (PK)**। সাধারণত একটি কলাম (Id) দিয়ে এটা হয়। কিন্তু মাঝে মাঝে দুই বা ততোধিক কলাম মিলে একটি ইউনিক পরিচয় তৈরি করে—একে বলে **Composite Key**।

**🎯 শেখার লক্ষ্য:**
১. প্রাইমারি কি কাস্টমাইজ করা (যদি নাম `Id` না হয়)।
২. কম্পোজিট কি (Composite Key) কী তা বোঝা।
৩. Fluent API দিয়ে কম্পোজিট কি তৈরি করা।

**📖 প্রধান বিষয়বস্তু:**
- **Single Primary Key:** EF Core ডিফল্টভাবে `Id` বা `ClassId` কে PK ধরে নেয়। কিন্তু আপনি চাইলে `Code` বা `Username` কেও PK বানাতে পারেন `HasKey()` দিয়ে।
- **Composite Key:** ধরুন, একজন ছাত্র (`StudentId`) অনেক ক্লাসে (`ClassId`) ভর্তি হতে পারে। কিন্তু একই ছাত্র একই ক্লাসে দুইবার ভর্তি হতে পারবে না। এখানে `StudentId` + `ClassId` মিলে হবে ইউনিক চাবি। **EF Core-এ Composite Key শুধুমাত্র Fluent API দিয়েই কনফিগার করা সবচেয়ে নিরাপদ এবং স্ট্যান্ডার্ড (যদিও EF Core 7+ এ অ্যাট্রিবিউট এসেছে)।**

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/StudentCourse.cs` (নতুন ক্লাস)
```csharp

    // এটি একটি লিংকিং টেবিল (Many-to-Many রিলেশনের জন্য ব্যবহৃত হয়)
    public class StudentCourse
    {
        public int StudentId { get; set; }
        public int CourseId { get; set; }
        
        // কবে ভর্তি হয়েছে
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp

using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        public DbSet<StudentCourse> StudentCourses { get; set; }
        // আগের DbSet গুলো থাকবে...
```

### Lesson 14: প্রপার্টি কনফিগারেশন (Required, MaxLength, Column Name)

**👨‍🏫 কোড রান টিপ:** আগের মতোই `OnModelCreating` মেথডে কাজ করব।

**🎉 ভূমিকা:**
ডিফল্টভাবে EF Core স্ট্রিং-কে `nvarchar(max)` বানিয়ে দেয়—যা স্টোরেজ নষ্ট করতে পারে। আবার `decimal` টাইপের প্রিসিশন ঠিক না করলে টাকার হিসাবে গন্ডগোল হতে পারে। চলুন আমাদের ডাটাবেজকে একদম পারফেক্ট সাইজ ও শেপে নিয়ে আসি।

**🎯 শেখার লক্ষ্য:**
১. `IsRequired()` দিয়ে `NOT NULL` কনস্ট্রেইন্ট সেট করা।
২. `HasMaxLength()` দিয়ে স্ট্রিং লিমিট করা।
৩. `HasColumnType()` দিয়ে স্পেসিফিক SQL টাইপ (যেমন money, date) বলে দেওয়া।

**📖 প্রধান বিষয়বস্তু:**
আমরা Fluent API ব্যবহার করে নিচের কাজগুলো করব:
- **IsRequired:** ডাটা মাস্ট দিতেই হবে।
- **HasMaxLength:** টেক্সটের দৈর্ঘ্য কমানো (পারফরম্যান্স বাড়ায়)।
- **HasColumnType:** `decimal(18,2)` এর মতো স্পেসিফিক টাইপ সেট করা। বিশেষ করে টাকার অংকের জন্য এটি খুব জরুরি।

### Lesson 15: Enums এবং ডাটা টাইপ কনভার্সন

**👨‍🏫 কোড রান টিপ:** এই লেসনে আমরা একটি নতুন এনটিটি `Order` তৈরি করব।

**🎉 ভূমিকা:**
C# এ আমরা নির্দিষ্ট কিছু অপশন ফিক্স করার জন্য **Enum** ব্যবহার করি (যেমন: Status = Pending/Shipped)। কিন্তু ডাটাবেজ তো আর C# বোঝে না!
ডিফল্টভাবে, EF Core এনুমের ভ্যালুকে সংখ্যা (0, 1, 2) হিসেবে সেভ করে। কিন্তু ডাটাবেজ খুলে `Status = 1` দেখলে কি বুঝবেন এটা "Shipped" নাকি "Cancelled"? এর চেয়ে যদি সরাসরি লেখা থাকত "Shipped", তবে জীবনটা সহজ হতো না? **Value Conversion** দিয়ে আমরা ঠিক এটাই করব!

**🎯 শেখার লক্ষ্য:**
১. এনটিটি ক্লাসে Enum প্রপার্টি ব্যবহার করা।
২. ডিফল্ট ম্যাপিং (int) বনাম স্ট্রিং কনভার্সন বোঝা।
৩. Fluent API এর `HasConversion` মেথড ব্যবহার করা।

**📖 প্রধান বিষয়বস্তু:**
- **Default Behavior:** EF Core এনুমকে `int` কলাম হিসেবে ম্যাপ করে। এটি স্টোরেজ সাশ্রয়ী কিন্তু মানুষের পড়ার অযোগ্য।
- **String Conversion:** আমরা চাই ডাটাবেজে `Active` বা `Inactive` টেক্সট হিসেবে সেভ হোক।
- **How to:** `modelBuilder...HasConversion<string>()` ব্যবহার করে আমরা EF Core কে বলি—"ভাই, সেভ করার সময় স্ট্রিং বানাও, আর ডাটাবেজ থেকে পড়ার সময় আবার এনুমে কনভার্ট করে দিও।"

৩. আপনি যদি Enum-এর কোনো আইটেমের নাম পরিবর্তন করেন (যেমন `Pending` থেকে `Waiting`), আর ডাটাবেজে স্ট্রিং হিসেবে সেভ করা থাকে, তবে কী সমস্যা হবে?
   A. কোনো সমস্যা হবে না
   B. পুরানো ডাটা রিড করার সময় এরর হবে (কারণ ডাটাবেজে আছে 'Pending', কিন্তু কোডে খুঁজছে 'Waiting') (উত্তর: B)
   C. ডাটাবেজ অটোমেটিক আপডেট হয়ে যাবে

**⚠️ খুব জরুরি নোট:** স্ট্রিং হিসেবে Enum সেভ করলে ভবিষ্যতে Enum-এর নাম পরিবর্তন করার সময় খুব সাবধান থাকতে হবে। কোডে নাম পাল্টালে ডাটাবেজের পুরানো টেক্সট আর ম্যাচ করবে না। সেক্ষেত্রে ডাটা মাইগ্রেশন স্ক্রিপ্ট লিখে ডাটাবেজের ভ্যালুও আপডেট করতে হবে (`UPDATE Orders SET Status = 'Waiting' WHERE Status = 'Pending'`)।
