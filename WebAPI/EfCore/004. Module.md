### Lesson 16: রিলেশনশিপ পরিচিতি ও ফরেন কি

**👨‍🏫 কোড রান টিপ:** এই লেসনে আমরা নতুন দুটি ক্লাস `Blog` এবং `Post` তৈরি করব।

**🎉 ভূমিকা:**
রিলেশনশিপ মানে হলো এক টেবিলের সাথে আরেক টেবিলের সংযোগ। রিলেশনাল ডাটাবেজে (RDBMS) এই সংযোগ তৈরি হয় **Foreign Key (FK)** দিয়ে। EF Core-এ আমরা C# ক্লাসের ভেতরে **Navigation Property** ব্যবহার করে এই সম্পর্ক তৈরি করি, যাতে আমরা `blog.Posts` লিখলেই ঐ ব্লগের সব পোস্ট পেয়ে যাই।

**🎯 শেখার লক্ষ্য:**
১. Principal (Parent) এবং Dependent (Child) এন্টিটি চেনা।
২. Foreign Key এবং Navigation Property বোঝা।
৩. EF Core-এর কনভেনশন ব্যবহার করে রিলেশন তৈরি করা।

**📖 প্রধান বিষয়বস্তু:**
সবচেয়ে কমন রিলেশনশিপ দিয়ে শুরু করা যাক। একটি ব্লগে অনেক পোস্ট থাকে।
- **Principal Entity:** `Blog` (Parent)। এর নিজের `Id` আছে।
- **Dependent Entity:** `Post` (Child)। এটি ব্লগের ওপর নির্ভরশীল।
- **Foreign Key:** `Post` টেবিলে `BlogId` নামে একটি কলাম থাকবে যা `Blog` টেবিলকে পয়েন্ট করবে।
- **Navigation Property:** `Blog` ক্লাসে থাকবে `List<Post>` এবং `Post` ক্লাসে থাকবে `Blog` অবজেক্ট। এগুলো ডাটাবেজে কলাম হয় না, কিন্তু কোডে চলাফেরা (Navigate) করতে সাহায্য করে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Blog.cs`
```csharp
using System.Collections.Generic; // List এর জন্য

namespace Lesson01_Intro.Models
{
    // Principal Entity
    public class Blog
    {
        public int Id { get; set; }
        public string Url { get; set; }

        // Collection Navigation Property
        // একটি ব্লগে অনেকগুলো পোস্ট থাকতে পারে
        public List<Post> Posts { get; set; } = new List<Post>();
    }
}
```

**ফাইল:** `src/Models/Post.cs`
```csharp
namespace Lesson01_Intro.Models
{
    // Dependent Entity
    public class Post
    {
        public int Id { get; set; }
        public string Title { get; set; }
        public string Content { get; set; }

        // Foreign Key (Convention: [EntityName]Id)
        // এটি ডাটাবেজে একটি কলাম হবে এবং রিলেশন তৈরি করবে
        public int BlogId { get; set; }

        // Reference Navigation Property
        // এই পোস্টটি কোন ব্লগের আন্ডারে, তা এক্সেস করার জন্য
        public Blog Blog { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
public DbSet<Blog> Blogs { get; set; }
public DbSet<Post> Posts { get; set; }
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Category` এবং `Product` এর মধ্যে রিলেশন তৈরি করুন (একটি ক্যাটাগরিতে অনেক প্রোডাক্ট থাকে)।
২. `Post` ক্লাসে `BlogId` প্রপার্টিটি রিমুভ করে মাইগ্রেশন অ্যাড করার চেষ্টা করুন। দেখুন EF Core তবুও রিলেশন তৈরি করে কি না (Shadow Property)। (ইঙ্গিত: EF Core স্মার্ট, সে নেভিগেশন প্রপার্টি দেখে ব্যাকগ্রাউন্ডে ফরেন কি বানিয়ে নেয়)।

**🧠 কুইজ:**
১. রিলেশনশিপে "Foreign Key" সাধারণত কোন টেবিলে থাকে?
   A. Principal / Parent টেবিলে
   B. Dependent / Child টেবিলে (উত্তর: B)
   C. কোনোটাতেই না

২. `public Blog Blog { get; set; }` - এই প্রপার্টিকে কী বলা হয়?
   A. Foreign Key
   B. Primary Key
   C. Navigation Property (উত্তর: C)

৩. EF Core-এ রিলেশনশিপ তৈরি করতে কোনটি অপরিহার্য?
   A. শুধু Foreign Key প্রপার্টি
   B. অন্তত একটি Navigation Property (উত্তর: B)
   C. Fluent API

**⚠️ খুব জরুরি নোট:** সবসময় `Foreign Key` প্রপার্টি (যেমন `BlogId`) এবং `Navigation Property` (যেমন `Blog`) দুটোই রাখা বেস্ট প্র্যাকটিস। এতে কোড লেখা এবং কুয়েরি করা সহজ হয়।

### Lesson 17: One-to-One রিলেশনশিপ

**👨‍🏫 কোড রান টিপ:** আমরা `AppDbContext`-এর `OnModelCreating`-এ কনফিগারেশন লিখব।

**🎉 ভূমিকা:**
One-to-One রিলেশনশিপ মানে হলো: "একজনের জন্য শুধু একটা"। যেমন: একজন মানুষের একটাই পাসপোর্ট থাকে, আর ঐ পাসপোর্টটি শুধুই ওই মানুষের। সাধারণত ডাটাবেজ স্প্লিট করার জন্য (যেমন: `User` টেবিলে লগইন ইনফো, আর `UserProfile` টেবিলে বিস্তারিত তথ্য) এটি ব্যবহার হয়।

**🎯 শেখার লক্ষ্য:**
১. 1:1 রিলেশনশিপের কনসেপ্ট বোঝা।
২. Fluent API ব্যবহার করে 1:1 কনফিগার করা।
৩. `HasForeignKey` মেথড দিয়ে প্যারেন্ট-চাইল্ড ঠিক করা।

**📖 প্রধান বিষয়বস্তু:**
1:1 রিলেশনে টেকনিক্যালি যেকোনো টেবিলই ফরেন কি রাখতে পারে। তাই EF Core কনফিউজড হয়ে যায় কে প্যারেন্ট আর কে চাইল্ড। এই কনফিউশন দূর করতে **Fluent API** ব্যবহার করা সবচেয়ে নিরাপদ।
- আমরা `.HasOne(...)` এবং `.WithOne(...)` ব্যবহার করব।
- `.HasForeignKey<ChildEntity>(...)` দিয়ে বলে দেব কার কাছে চাবি (Key) থাকবে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Person.cs`
```csharp
namespace Lesson01_Intro.Models
{
    public class Person
    {
        public int Id { get; set; }
        public string Name { get; set; }

        // Navigation Property (একজন ব্যক্তির একটি পাসপোর্ট)
        public Passport Passport { get; set; }
    }
}
```

**ফাইল:** `src/Models/Passport.cs`
```csharp
namespace Lesson01_Intro.Models
{
    public class Passport
    {
        public int Id { get; set; }
        public string PassportNumber { get; set; }

        // Foreign Key
        public int PersonId { get; set; }
        
        // Navigation Property (এই পাসপোর্টটি একজন ব্যক্তির)
        public Person Person { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        // ... অন্যান্য DbSet
        public DbSet<Person> People { get; set; }
        public DbSet<Passport> Passports { get; set; }

        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            // আগের কোডগুলো...

            // --- Lesson 17: One-to-One Configuration ---
            modelBuilder.Entity<Person>()
                .HasOne(p => p.Passport)      // Person এর একটি Passport আছে
                .WithOne(Pp => Pp.Person)     // Passport এর একটি Person আছে
                .HasForeignKey<Passport>(Pp => Pp.PersonId); // ফরেন কি থাকবে Passport টেবিলে
            
            // নোট: EF Core অটোমেটিক PersonId এর ওপর Unique Index তৈরি করবে
            // যাতে একই PersonId দুইবার Passports টেবিলে না আসে।
        }
    }
}
```

**মাইগ্রেশন কমান্ড:**
```bash
dotnet ef migrations add AddedPersonAndPassport
dotnet ef database update
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Program.cs` এ একটি `Person` এবং তার `Passport` অবজেক্ট তৈরি করে ডাটাবেজে সেভ করুন।
২. একই `PersonId` ব্যবহার করে দ্বিতীয় একটি পাসপোর্ট সেভ করার চেষ্টা করুন। দেখুন কোনো এরর (Exception) দেয় কি না (Unique Constraint Violation)।

**🧠 কুইজ:**
১. One-to-One রিলেশনশিপে Foreign Key কলামে ডাটাবেজ লেভেলে অটোমেটিক কী তৈরি হয়?
   A. কিছুই না
   B. Unique Index (উত্তর: B)
   C. Primary Key

২. Fluent API তে `.HasOne().WithOne()` চেইনে `.HasForeignKey<T>()` কেন জরুরি?
   A. প্রাইমারি কি সেট করার জন্য
   B. কোন টেবিলে ফরেন কি কলামটি বসবে তা নির্দিষ্ট করার জন্য (উত্তর: B)
   C. রিলেশনশিপ ডিলিট করার জন্য

৩. One-to-One রিলেশনশিপের একটি বাস্তব উদাহরণ কোনটি?

**⚠️ খুব জরুরি নোট:** One-to-One রিলেশনে **Lazy Loading** সাবধানে ব্যবহার করতে হয়। কারণ প্যারেন্ট লোড করার সময় প্রায়ই চাইল্ডের দরকার হয়, সেক্ষেত্রে `Include` (Eager Loading) ব্যবহার করাই ভালো।

### Lesson 18: One-to-Many রিলেশনশিপ

**👨‍🏫 কোড রান টিপ:** এই লেসনের জন্য আমরা নতুন দুটি এন্টিটি `Author` (লেখক) এবং `Book` (বই) তৈরি করব।

**🎉 ভূমিকা:**
এটিই ডাটাবেজের দুনিয়ায় সবচেয়ে জনপ্রিয় সম্পর্ক। চিন্তা করুন:
- একজন লেখকের অনেকগুলো বই থাকতে পারে।
- কিন্তু একটি বইয়ের (সাধারণত) একজনই মূল লেখক থাকে।
এটাকে বলে **One-to-Many (1:N)**। এখানে "One" হলো প্যারেন্ট (Author) আর "Many" হলো চাইল্ড (Book)।

**🎯 শেখার লক্ষ্য:**
১. Collection Navigation এবং Reference Navigation বোঝা।
২. Fluent API দিয়ে ১:N কনফিগার করা (`HasOne`...`WithMany`)।
৩. ডাটা ইনসার্ট করার সময় রিলেশনশিপ মেইনটেইন করা।

**📖 প্রধান বিষয়বস্তু:**
কনভেনশন অনুযায়ী, আপনি যদি চাইল্ড ক্লাসে একটি ফরেন কি (`AuthorId`) এবং প্যারেন্ট ক্লাসে একটি লিস্ট (`List<Book>`) রাখেন, EF Core একাই সব বুঝে নেয়। কিন্তু আমরা বস (Boss) ডেভেলপার হতে চাই, তাই আমরা **Fluent API** দিয়ে স্পষ্টভাবে বলে দেব কে কার সাথে সম্পর্কিত।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Author.cs`
```csharp
using System.Collections.Generic;

namespace Lesson01_Intro.Models
{
    public class Author
    {
        public int Id { get; set; }
        public string Name { get; set; }

        // Navigation Property: One Author has Many Books
        // লিস্ট ইনিশিয়ালাইজ করে রাখা ভালো প্র্যাকটিস, যাতে Null Reference Error না হয়
        public ICollection<Book> Books { get; set; } = new List<Book>();
    }
}
```

**ফাইল:** `src/Models/Book.cs`
```csharp
namespace Lesson01_Intro.Models
{
    public class Book
    {
        public int Id { get; set; }
        public string Title { get; set; }

        // Foreign Key
        public int AuthorId { get; set; }
        
        // Navigation Property: One Book has One Author
        public Author Author { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
// ... imports
namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        // ... previous DbSets
        public DbSet<Author> Authors { get; set; }
        public DbSet<Book> Books { get; set; }

        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            // আগের কনফিগারেশন...

            // --- Lesson 18: One-to-Many Configuration ---
            modelBuilder.Entity<Book>()
                .HasOne(b => b.Author)       // একটি বইয়ের একজন লেখক আছে
                .WithMany(a => a.Books)      // একজন লেখকের অনেক বই আছে
                .HasForeignKey(b => b.AuthorId) // ফরেন কি বইয়ের টেবিলে থাকবে
                .OnDelete(DeleteBehavior.Cascade); // লেখক ডিলিট হলে বইও ডিলিট হবে
        }
    }
}
```

**মাইগ্রেশন কমান্ড:**
```bash
dotnet ef migrations add AddedAuthorBookRelation
dotnet ef database update
```

### Lesson 19: Many-to-Many রিলেশনশিপ (Skip Navigation)

**👨‍🏫 কোড রান টিপ:** আমরা `Actor` এবং `Movie` এন্টিটি নিয়ে কাজ করব।

**🎉 ভূমিকা:**
চিন্তা করুন: একজন অভিনেতা অনেক সিনেমায় অভিনয় করেন, আবার একটি সিনেমায় অনেক অভিনেতা থাকেন। একে বলে **Many-to-Many (M:N)** সম্পর্ক।
আগে (EF Core 5 এর আগে) আমাদের হাতে ধরে মাঝখানে একটি `ActorMovie` টেবিল বানাতে হতো। কিন্তু এখন EF Core এত স্মার্ট যে, সে নিজেই মাঝখানের টেবিল বানিয়ে নেয় এবং আমাদের সেটা দেখতেও হয় না! আমরা সরাসরি `Actor` থেকে `Movie` তে জাম্প করতে পারি। একে বলে **Skip Navigation**।

**🎯 শেখার লক্ষ্য:**
১. Many-to-Many কনসেপ্ট বোঝা।
২. Skip Navigation ব্যবহার করে রিলেশন তৈরি করা।
৩. Fluent API দিয়ে জয়েন টেবিল কাস্টমাইজ করা।

**📖 প্রধান বিষয়বস্তু:**
আমাদের শুধু দুই পাশে দুটি `List` বা `ICollection` রাখতে হবে।
- Actor: `public ICollection<Movie> Movies { get; set; }`
- Movie: `public ICollection<Actor> Actors { get; set; }`

EF Core ব্যাকগ্রাউন্ডে `ActorMovie` নামে একটি টেবিল বানাবে যেখানে দুটি ফরেন কি থাকবে।

### Lesson 20: ক্যাস্কেড ডিলিট (Cascade Delete) ও রেফারেন্সিয়াল অ্যাকশন

**👨‍🏫 কোড রান টিপ:** এই লেসনের কনসেপ্টগুলো আমরা `AppDbContext`-এর `OnModelCreating`-এ পরীক্ষা করব।

**🎉 ভূমিকা:**
ভাবুন তো, আপনি ফেসবুক থেকে আপনার অ্যাকাউন্ট ডিলিট করে দিলেন। এখন আপনার পোস্টগুলোর কী হবে?
- **অপশন ১:** পোস্টগুলোও সাথে সাথে ডিলিট হয়ে যাবে। (এটাকে বলে **Cascade Delete**)
- **অপশন ২:** পোস্টগুলো থেকে যাবে, কিন্তু লেখকের নাম দেখাবে না বা নাল (Null) হয়ে যাবে। (Set Null)
- **অপশন ৩:** সিস্টেম আপনাকে অ্যাকাউন্ট ডিলিট করতেই দেবে না যতক্ষণ না আপনি ম্যানুয়ালি সব পোস্ট ডিলিট করছেন। (Restrict)

EF Core এবং ডাটাবেজ মিলে এই আচরণ নিয়ন্ত্রণ করে।

**🎯 শেখার লক্ষ্য:**
১. `DeleteBehavior` এনামের বিভিন্ন অপশন (Cascade, SetNull, Restrict) বোঝা।
২. Required এবং Optional রিলেশনশিপে ডিফল্ট আচরণ জানা।
৩. Fluent API দিয়ে ডিলিট বিহেভিয়ার কাস্টমাইজ করা।

**📖 প্রধান বিষয়বস্তু:**
যখন প্যারেন্ট (Principal) ডিলিট করা হয়, তখন চাইল্ডের (Dependent) কী হবে?
1. **Cascade (Default for Required FK):** প্যারেন্ট মরলে চাইল্ডও মরবে। (যেমন: `Blog` ডিলিট করলে সব `Post` ডিলিট)।
2. **ClientSetNull (Default for Optional FK):** চাইল্ডের FK নাল হয়ে যাবে। (যেমন: `Employee` চলে গেলে তার `Task` গুলো আন-এসাইনড হয়ে যাবে)।
3. **Restrict / NoAction:** ডাটাবেজ ডিলিট করতে বাধা দেবে এবং এরর থ্রো করবে। এটি ডাটা সুরক্ষার জন্য সবচেয়ে নিরাপদ।

**💻 কোড উদাহরণ:**

আমরা `Blog` এবং `Post` এর সম্পর্ক মডিফাই করব।

**ফাইল:** `src/Data/AppDbContext.cs` (আপডেট)
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        // ... অন্যান্য কনফিগারেশন

        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            // --- Lesson 20: Cascade Delete Configuration ---

            // ১. Cascade (ডিফল্ট, তবুও আমরাExplicitly লিখছি)
            // ব্লগ ডিলিট করলে পোস্টগুলোও অটো ডিলিট হয়ে যাবে
            modelBuilder.Entity<Post>()
                .HasOne(p => p.Blog)
                .WithMany(b => b.Posts)
                .HasForeignKey(p => p.BlogId)
                .OnDelete(DeleteBehavior.Cascade); 

            // ২. Restrict (উদাহরণ: লেখক এবং বই)
            // লেখক ডিলিট করতে চাইলে ডাটাবেজ বাধা দেবে যদি তার লেখা বই থাকে
            modelBuilder.Entity<Book>()
                .HasOne(b => b.Author)
                .WithMany(a => a.Books)
                .HasForeignKey(b => b.AuthorId)
                .OnDelete(DeleteBehavior.Restrict); 
                
            // ৩. SetNull (উদাহরণ: যদি আমরা চাইতাম ব্লগ ডিলিট হলেও পোস্ট থাকুক)
            // এর জন্য ফরেন কি (BlogId) অবশ্যই Nullable int? হতে হবে
            /*
            modelBuilder.Entity<Post>()
                .HasOne(p => p.Blog)
                .WithMany(b => b.Posts)
                .HasForeignKey(p => p.BlogId)
                .OnDelete(DeleteBehavior.ClientSetNull);
            */
        }
    }
}
```

**মাইগ্রেশন কমান্ড:** (বিহেভিয়ার চেঞ্জ করলে মাইগ্রেশন দরকার হয় কারণ এটি ডাটাবেজে FK Constraint আপডেট করে)
```bash
dotnet ef migrations add UpdateDeleteBehaviors
dotnet ef database update
```

**প্র্যাকটিক্যাল টেস্ট (Program.cs):**
```csharp
using (var context = new AppDbContext())
{
    // --- টেস্ট ১: Cascade Delete ---
    // একটি ব্লগ এবং পোস্ট তৈরি করি
    var blog = new Blog { Url = "http://test-cascade.com" };
    blog.Posts.Add(new Post { Title = "Post 1" });
    context.Blogs.Add(blog);
    context.SaveChanges();
    int blogId = blog.Id;

    Console.WriteLine("ব্লগ ডিলিট করার চেষ্টা করছি...");
    context.Blogs.Remove(blog);
    context.SaveChanges();
    
    // চেক করি পোস্ট আছে কি না
    var postsCount = context.Posts.Count(p => p.BlogId == blogId);
    Console.WriteLine($"ব্লগ ডিলিট করার পর পোস্ট সংখ্যা: {postsCount}"); // আউটপুট হবে ০

    // --- টেস্ট ২: Restrict ---
    // একজন লেখক এবং বই তৈরি
    var author = new Author { Name = "JK Rowling" };
    author.Books.Add(new Book { Title = "Harry Potter" });
    context.Authors.Add(author);
    context.SaveChanges();

    Console.WriteLine("লেখক ডিলিট করার চেষ্টা করছি...");
    try
    {
        context.Authors.Remove(author);
        context.SaveChanges(); // এখানে এক্সেপশন খাবে
    }
    catch (DbUpdateException ex)
    {
        Console.WriteLine($"ডিলিট ব্যর্থ! কারণ: {ex.InnerException?.Message}");
        // মেসেজে FK Constraint Violation এর কথা থাকবে
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `SetNull` বিহেভিয়ার টেস্ট করার জন্য `Post` ক্লাসের `BlogId` কে `int?` (Nullable) করুন এবং কনফিগারেশন চেঞ্জ করে `ClientSetNull` দিন। তারপর ব্লগ ডিলিট করে দেখুন পোস্টের `BlogId` নাল হয় কি না।
২. আপনার প্রোজেক্টে ভুলবশত ডাটা ডিলিট হওয়া রোধ করতে কোন বিহেভিয়ারটি সবচেয়ে নিরাপদ? (Restrict)। এটি সব রিলেশনে অ্যাপ্লাই করার চেষ্টা করুন।

**🧠 কুইজ:**
১. `int` (Not Nullable) ফরেন কি-র ক্ষেত্রে ডিফল্ট ডিলিট বিহেভিয়ার কী?
   A. SetNull
   B. Cascade (উত্তর: B)
   C. Restrict

২. `DeleteBehavior.Restrict` সেট করলে প্যারেন্ট ডিলিট করতে চাইলে ডাটাবেজ কী করে?
   A. চাইল্ড ডিলিট করে দেয়
   B. চাইল্ডের FK নাল করে দেয়
   C. এরর দেয় এবং ডিলিট আটকায়ে দেয় (উত্তর: C)

৩. ডাটাবেজ লেভেলে `SetNull` কাজ করার জন্য ফরেন কি কলামটি কেমন হতে হবে?
   A. Primary Key
   B. Nullable (উত্তর: B)
   C. Unique

**⚠️ খুব জরুরি নোট:** `Cascade Delete` খুব শক্তিশালী কিন্তু বিপজ্জনক। ভুলবশত প্যারেন্ট ডিলিট করলে হাজার হাজার চাইল্ড ডাটা নিমিষেই মুছে যেতে পারে। সেনসিটিভ ডাটার ক্ষেত্রে সবসময় `Restrict` ব্যবহার করা এবং সফট ডিলিট (IsDeleted flag) ব্যবহার করা ভালো (যা আমরা লেসন ৩০-এ শিখব)।
