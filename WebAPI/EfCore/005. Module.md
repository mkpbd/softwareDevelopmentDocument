### Lesson 21: Eager Loading (Include/ThenInclude) – দাওয়াতের প্লেট সাজানো

**👨‍🏫 কোড রান টিপ:** `Program.cs` ফাইলে কোড লিখুন। `System.Linq` এবং `Microsoft.EntityFrameworkCore` ইউজিং থাকতে হবে।

**🎉 মজার ভূমিকা:**
কল্পনা করুন আপনি বিয়ের দাওয়াতে গেছেন।
1. **Bad Way:** আপনি প্লেটে শুধু পোলাও নিলেন। টেবিলে এসে খেলেন। তারপর আবার গিয়ে রোস্ট আনলেন। আবার খেলেন। আবার গিয়ে বোরহানি আনলেন... (এটা হলো লুপের ভেতর বারবার কুয়েরি করা বা **N+1 Problem**)। বাবুর্চি (Database) আপনাকে খুন করে ফেলবে! 🔪
2. **Eager Loading Way:** আপনি একবারে বড় প্লেটে পোলাও, রোস্ট, কাবাব, বোরহানি সব সাজিয়ে নিয়ে টেবিলে বসলেন। বাবুর্চি খুশি, আপনিও খুশি।

EF Core-এ একবারে সব রিলেটেড ডাটা লোড করাকে বলে **Eager Loading**।

**🎯 শেখার লক্ষ্য:**
১. `Include` মেথড দিয়ে চাইল্ড ডাটা লোড করা।
২. `ThenInclude` দিয়ে নাতি-পুতি (Grandchild) ডাটা লোড করা।
৩. N+1 সমস্যা সমাধান করা।

**📖 প্রধান বিষয়বস্তু:**
- **Include:** সরাসরি রিলেশন লোড করতে। (যেমন: `Blog` এর সাথে `Posts`)।
- **ThenInclude:** রিলেশনের রিলেশন লোড করতে। (যেমন: `Blog` -> `Posts` -> `Comments`)।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using Microsoft.EntityFrameworkCore; // Include এর জন্য মাস্ট!
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                // ডাটা সিডিং (বোঝার সুবিধার জন্য)
                if (!context.Blogs.Any())
                {
                    var blog = new Blog { Url = "http://food-vlog.com" };
                    blog.Posts.Add(new Post { Title = "Kacchi Biryani Recipe" });
                    blog.Posts.Add(new Post { Title = "Best Burger in Town" });
                    context.Blogs.Add(blog);
                    context.SaveChanges();
                }

                Console.WriteLine("--- Eager Loading: বিফোর (ভুল পদ্ধতি) ---");
                var blogs = context.Blogs.ToList(); // শুধু ব্লগ আনলাম
                foreach (var b in blogs)
                {
                    // Posts লোড করা হয়নি, তাই এটি খালি থাকবে অথবা নাল হবে
                    Console.WriteLine($"Blog: {b.Url}, Posts Count: {b.Posts?.Count ?? 0}"); 
                }

                Console.WriteLine("\n--- Eager Loading: আফটার (সঠিক পদ্ধতি) ---");
                
                // এক কুয়েরিতে সব নিয়ে আসা (Join Query)
                var blogsWithPosts = context.Blogs
                                            .Include(b => b.Posts) // "ভাই, ব্লগ তো দেবেনই, সাথে পোস্টগুলোও প্যাকেট করে দেন"
                                            .ToList();

                foreach (var b in blogsWithPosts)
                {
                    Console.WriteLine($"Blog: {b.Url}");
                    foreach (var p in b.Posts)
                    {
                        Console.WriteLine($"   - Post: {p.Title}");
                    }
                }
            }
        }
    }
}
```

**🤔 ThenInclude কী?**
যদি আমাদের `Post` এর নিচে `Comments` থাকত, তবে আমরা লিখতাম:
```csharp
var fullPackage = context.Blogs
                         .Include(b => b.Posts)
                             .ThenInclude(p => p.Comments) // পোস্টের ভেতরের কমেন্ট
                         .ToList();
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Author` এবং `Book` রিলেশন ব্যবহার করে `Include` প্র্যাকটিস করুন। এমনভাবে কুয়েরি লিখুন যেন লেখকের নাম এবং তার সব বইয়ের নাম প্রিন্ট করা যায়।
২. `ThenInclude` ব্যবহার করার চেষ্টা করুন (যদি ৩ লেভেলের ডাটা না থাকে, তবে কাল্পনিকভাবে কোডটি লিখুন)।

**🧠 কুইজ:**
১. `Include` মেথড ব্যবহার করলে ব্যাকগ্রাউন্ডে SQL এ কী ঘটে?
   A. অনেকগুলো ছোট কুয়েরি রান হয়
   B. একটি `JOIN` কুয়েরি তৈরি হয় (উত্তর: B)
   C. কিছুই হয় না

২. `ThenInclude` কখন ব্যবহার করা হয়?
   A. যখন ফিল্টার করতে হয়
   B. যখন নেস্টেড (Nested) রিলেশন লোড করতে হয় (উত্তর: B)
   C. ডাটা সর্ট করতে

৩. রিলেটেড ডাটা লোড না করে এক্সেস করতে গেলে সাধারণত কী রেজাল্ট আসে?
   A. Error
   B. Empty List or Null (উত্তর: B)
   C. All Data

**⚠️ খুব জরুরি নোট:** `Include` বেশি ব্যবহার করলে "Cartesian Explosion" হতে পারে (বিশাল বড় ডাটা চলে আসা)। তাই প্রয়োজনের অতিরিক্ত `Include` দেবেন না।

### Lesson 22: Explicit Loading এবং Lazy Loading – অলস বনাম হিসেবি

**👨‍🏫 কোড রান টিপ:** Lazy Loading এর জন্য একটি প্যাকেজ লাগবে: `Microsoft.EntityFrameworkCore.Proxies`।

**🎉 মজার ভূমিকা:**
- **Explicit Loading (হিসেবি):** আপনি দোকানে মোবাইল কিনলেন। বাসায় এসে মনে পড়ল "আরে! কভার তো কিনিনি!"। আপনি আবার দোকানে গিয়ে বললেন, "ভাই, এই মোবাইলের কভারটা আলাদাভাবে লোড করে দেন।" (প্রয়োজন হলে চেয়ে নেওয়া)।
- **Lazy Loading (অলস/জাদুকর):** এটা অনেকটা জাদুর মতো। আপনি টেবিলের দিকে তাকালেন, খাবার চলে এল! গ্লাসে হাত দিলেন, পানি ভরে গেল! দেখতে খুব কুল, কিন্তু ব্যাকগ্রাউন্ডে আপনার জাদুকর চাকরটি (Database) প্রতিবার দৌড়াদৌড়ি করে জান শেষ করে ফেলছে।

**🎯 শেখার লক্ষ্য:**
১. `Entry().Collection().Load()` দিয়ে Explicit Loading করা।
২. Lazy Loading এর সেটআপ (`Proxies` প্যাকেজ ও `virtual` কিওয়ার্ড)।
৩. Lazy Loading এর বিপদ (N+1 Problem) বোঝা।

**📖 প্রধান বিষয়বস্তু:**

**১. Explicit Loading:**
আমি মেইন ডাটা এনেছি, কিন্তু রিলেশন আনিনি। পরে লজিক চেক করে মনে হলো রিলেশন দরকার।
```csharp
// ১. ব্লগ আনলাম
var blog = context.Blogs.First(); 

// ২. এখন আমার পোস্ট দরকার
context.Entry(blog)
       .Collection(b => b.Posts) // কালেকশন লোড করো
       .Load(); // ডাটাবেজে গিয়ে নিয়ে এসো
```

**২. Lazy Loading:**
এটি অটোমেটিক কাজ করে। সেটআপ করার পর, আপনি যখনই `blog.Posts` এ হাত দেবেন, EF Core চুপিচুপি ডাটাবেজে কুয়েরি চালিয়ে ডাটা নিয়ে আসবে।

**💻 কোড উদাহরণ (Lazy Loading Setup):**

১. প্যাকেজ ইনস্টল করুন:
```bash
dotnet add package Microsoft.EntityFrameworkCore.Proxies
```

২. `AppDbContext.cs` কনফিগারেশন আপডেট:
```csharp
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
{
    optionsBuilder
        .UseLazyLoadingProxies() // ১. এই লাইনটি যোগ করুন
        .UseSqlServer(@"..."); 
}
```

৩. মডেল ক্লাস আপডেট (`virtual` কিওয়ার্ড যোগ করুন):
**ফাইল:** `src/Models/Blog.cs`
```csharp
public class Blog
{
    public int Id { get; set; }
    public string Url { get; set; }

    // ২. virtual না দিলে Lazy Loading কাজ করবে না!
    public virtual ICollection<Post> Posts { get; set; } = new List<Post>(); 
}
```

৪. **Program.cs** এ যাদু দেখুন:
```csharp
Console.WriteLine("--- Lazy Loading Magic ---");
// আমরা কোনো Include দেইনি!
var lazyBlog = context.Blogs.First(); 

Console.WriteLine($"Blog: {lazyBlog.Url}");

// যেই মুহূর্তে আমরা .Posts এক্সেস করলাম, EF Core ব্যাকগ্রাউন্ডে কুয়েরি চালাবে
foreach (var post in lazyBlog.Posts) 
{
    Console.WriteLine($" - {post.Title}");
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. Explicit Loading ব্যবহার করে একটি `Post` লোড করুন এবং পরে তার `Blog` টি লোড করুন (`Reference(p => p.Blog).Load()` ব্যবহার করে)।
২. Lazy Loading অন থাকা অবস্থায় ১০টি ব্লগের টাইটেল এবং পোস্ট প্রিন্ট করার লুপ চালান। কনসোলের লগে বা SQL Profiler এ দেখুন কয়টি কুয়েরি রান হয়েছে (১০টি ব্লগের জন্য ১১টি কুয়েরি = N+1 disaster!)।

**🧠 কুইজ:**
১. Lazy Loading চালু করতে প্রপার্টিগুলোতে কোন কিওয়ার্ড ব্যবহার করতে হয়?
   A. static
   B. abstract
   C. virtual (উত্তর: C)

২. Explicit Loading কোন অবজেক্টের মাধ্যমে করা হয়?
   A. context.Entry() (উত্তর: A)
   B. context.Include()
   C. context.Database

৩. Lazy Loading এর সবচেয়ে বড় অসুবিধা কোনটি?
   A. কোড কঠিন হয়ে যায়
   B. N+1 কুয়েরি সমস্যা তৈরি হতে পারে (পারফরম্যান্স ড্রপ) (উত্তর: B)
   C. ডাটা লোড হয় না

**⚠️ খুব জরুরি নোট:** Lazy Loading সুবিধাজনক মনে হলেও ওয়েব অ্যাপ্লিকেশনে (API) এটি এড়িয়ে চলাই ভালো। কারণ, সিরিয়ালাইজার (JSON converter) সব প্রপার্টি টাচ করে, ফলে পুরো ডাটাবেজ লোড হয়ে যেতে পারে! **Eager Loading (Include)** ইজ বেস্ট ফ্রেন্ড।

### Lesson 23: Select Loading (প্রজেকশন/DTO তে ডাটা নেওয়া)

**👨‍🏫 কোড রান টিপ:** আমরা `Select` মেথড ব্যবহার করব।

**🎉 ভূমিকা:**
দোকানে গিয়ে কি আপনি পুরো বস্তা চাল কেনেন, নাকি ১ কেজি? ডাটাবেজেও একই কথা। `SELECT * FROM Users` মানে পুরো বস্তা কেনা (সব কলাম)। কিন্তু আপনার যদি শুধু নাম আর ইমেইল দরকার হয়?
তখন আমরা ব্যবহার করি **Projection**। অর্থাৎ, পুরো এনটিটি ক্লাস লোড না করে শুধু প্রয়োজনীয় প্রপার্টিগুলো নিয়ে একটি হালকা ক্লাসে (DTO - Data Transfer Object) রাখা। এতে অ্যাপ্লিকেশন সুপার ফাস্ট হয়! 🚀

**🎯 শেখার লক্ষ্য:**
১. `Select` মেথড দিয়ে নির্দিষ্ট কলাম বেছে নেওয়া।
২. অ্যানোনিমাস টাইপ (Anonymous Type) ব্যবহার করা।
৩. DTO (Data Transfer Object) ক্লাসে ডাটা ম্যাপ করা।

**📖 প্রধান বিষয়বস্তু:**
- **Anonymous:** `Select(x => new { x.Name, x.Price })`। এটি দ্রুত কাজের জন্য ভালো, কিন্তু মেথডের বাইরে পাস করা যায় না।
- **DTO:** একটি আলাদা ক্লাস বানিয়ে সেখানে ডাটা রাখা। এটি প্রফেশনাল অ্যাপ্রোচ।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/DTOs/ProductSummaryDto.cs` (নতুন ফোল্ডার ও ক্লাস)
```csharp
namespace Lesson01_Intro.DTOs
{
    // এটি এনটিটি নয়, সাধারণ ক্লাস
    public class ProductSummaryDto
    {
        public string ProductName { get; set; }
        public decimal Price { get; set; }
        public string CategoryName { get; set; } // রিলেটেড টেবিল থেকে আনব
    }
}
```

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using Lesson01_Intro.Data;
using Lesson01_Intro.DTOs; // DTO নেমস্পেস

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                Console.WriteLine("--- Projection / Select Loading ---");

                // ১. Anonymous Type (নামহীন ক্লাস)
                // SQL: SELECT Name, Price FROM Products
                var simpleList = context.Products
                                        .Select(p => new 
                                        { 
                                            Name = p.Name, 
                                            Cost = p.Price 
                                        })
                                        .ToList();

                Console.WriteLine("Anonymous List:");
                foreach (var item in simpleList)
                {
                    Console.WriteLine($"{item.Name} - {item.Cost}");
                }

                // ২. Strongly Typed DTO (বেস্ট প্র্যাকটিস)
                // আমরা রিলেশনশিপ (Category) থেকেও ডাটা আনছি এক কুয়েরিতে!
                /* মনে করি Product এর Category রিলেশন আছে */
                
                var dtoList = context.Products
                                     .Select(p => new ProductSummaryDto
                                     {
                                         ProductName = p.Name,
                                         Price = p.Price,
                                         // Category নাল কি না চেক করা ভালো (Null propagation)
                                         // CategoryName = p.Category.Name 
                                     })
                                     .Where(d => d.Price > 500) // DTO এর ওপর ফিল্টার!
                                     .ToList();

                Console.WriteLine("\nDTO List:");
                foreach (var dto in dtoList)
                {
                    Console.WriteLine($"Product: {dto.ProductName}, Price: {dto.Price}");
                }
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `BlogDto` নামে একটি ক্লাস তৈরি করুন যাতে `Url` এবং `TotalPosts` (int) থাকবে। `Select` কুয়েরি লিখুন যা প্রতিটি ব্লগের `Url` এবং `Posts.Count()` নিয়ে আসবে।
২. `Select` ব্যবহার করে ডাটা আনার সময় `Include` ব্যবহার করার প্রয়োজন আছে কি? পরীক্ষা করে দেখুন। (উত্তর: না, `Select` ব্যবহার করলে EF Core স্মার্টলি জয়েন করে নেয়, `Include` লাগে না)।

**🧠 কুইজ:**
১. `SELECT *` এর বদলে শুধু নির্দিষ্ট কলাম সিলেক্ট করলে কী লাভ?
   A. ডাটাবেজ সুন্দর দেখায়
   B. নেটওয়ার্ক ট্রাফিক কমে এবং মেমোরি বাঁচে (উত্তর: B)
   C. কোড বেশি লিখতে হয়

২. প্রোজেকশন (Projection) ব্যবহার করলে `Include()` মেথড কি বাধ্যতামূলক?
   A. হ্যাঁ
   B. না, EF Core প্রয়োজনীয় জয়েন অটোমেটিক করে নেয় (উত্তর: B)

৩. Anonymous Type এর সীমাবদ্ধতা কী?
   A. এটি রিড-অনলি
   B. এটি বর্তমান মেথডের বাইরে রিটার্ন করা যায় না (সহজে) (উত্তর: B)
   C. এটি খুব স্লো

**⚠️ খুব জরুরি নোট:** `Select` দিয়ে ডাটা আনলে সেই অবজেক্টগুলো **Tracked** হয় না। অর্থাৎ, আপনি যদি DTO-র ভ্যালু চেঞ্জ করে `SaveChanges` কল করেন, ডাটাবেজে কিছু আপডেট হবে না। আপডেটের জন্য এনটিটিই আনতে হবে।

### Lesson 24: Raw SQL কুয়েরি (FromSql, ExecuteSql)

**👨‍🏫 কোড রান টিপ:** SQL ইনজেকশন থেকে সাবধান!

**🎉 ভূমিকা:**
মাঝে মাঝে EF Core-এর জাদুকরী LINQ কুয়েরি যথেষ্ট হয় না। হয়তো আপনাকে খুব জটিল একটি রিপোর্ট জেনারেট করতে হবে বাStored Procedure কল করতে হবে। তখন আমরা "পুরানো দিনের" SQL কুয়েরি লিখব।
EF Core আমাদের সেই সুযোগ দেয়, কিন্তু টাইপ সেফটি বজায় রেখে।

**🎯 শেখার লক্ষ্য:**
১. `FromSql` দিয়ে ডাটা রিটার্ন করা।
২. `ExecuteSql` দিয়ে INSERT/UPDATE/DELETE কমান্ড চালানো।
৩. প্যারামিটারাইজড কুয়েরি (SQL Injection প্রতিরোধ)।

**📖 প্রধান বিষয়বস্তু:**
- **FromSql (বা FromSqlRaw/Interpolated):** এটি `DbSet` রিটার্ন করে। অর্থাৎ রেজাল্ট অবশ্যই আপনার এনটিটি টাইপের হতে হবে।
- **ExecuteSql (EF Core 7+):** ডাটাবেজে সরাসরি কমান্ড চালানোর জন্য।
- **SqlQuery (EF Core 8+):** প্রিমিটিভ টাইপ (যেমন শুধু `int` বা `string` লিস্ট) রিটার্ন করার জন্য।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using Microsoft.EntityFrameworkCore; // FromSql এর জন্য জরুরি
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                Console.WriteLine("--- Raw SQL Magic ---");

                // ১. FromSqlInterpolated (Safe way)
                // ব্যবহারকারীর ইনপুট
                decimal minPrice = 500;
                
                // এখানে {0} বা ইন্টারপোলেশন ব্যবহার করলে EF Core অটোমেটিক প্যারামিটার তৈরি করে
                // তাই SQL Injection এর ভয় নেই।
                var expensiveProducts = context.Products
                    .FromSqlInterpolated($"SELECT * FROM Products WHERE Price > {minPrice}")
                    .ToList(); // এর সাথে LINQ ও মেশানো যায়! .OrderBy(...)

                Console.WriteLine($"Count: {expensiveProducts.Count}");

                // ২. ExecuteSql (Update/Delete without loading)
                // আইডি ১ এর নাম আপডেট করি সরাসরি SQL দিয়ে
                int idToUpdate = 1;
                string newName = "Updated by SQL";

                context.Database.ExecuteSqlInterpolated(
                    $"UPDATE Products SET Name = {newName} WHERE Id = {idToUpdate}"
                );
                
                Console.WriteLine("SQL Update Done!");

                // ৩. Stored Procedure কল করা
                // var data = context.Products.FromSqlInterpolated($"EXEC GetProductsByCategory {catId}").ToList();
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `FromSqlRaw` ব্যবহার করে `SELECT * FROM Products` কুয়েরি চালান এবং রেজাল্ট প্রিন্ট করুন।
২. একটি ভুল SQL কুয়েরি (যেমন টেবিলের নাম ভুল) দিয়ে `try-catch` ব্লকে রান করুন এবং এক্সেপশন মেসেজটি পড়ুন।

**🧠 কুইজ:**
১. SQL Injection এড়াতে কোন মেথডটি নিরাপদ?
   A. FromSqlRaw($"SELECT * FROM tbl WHERE Name = '{name}'")
   B. FromSqlInterpolated($"SELECT * FROM tbl WHERE Name = {name}") (উত্তর: B)
   C. স্ট্রিং কনক্যাটেনেশন

২. `FromSql` মেথডটি কী রিটার্ন করে?
   A. DataTable
   B. IQueryable`<Entity> (যা পরে ফিল্টার করা যায়) (উত্তর: B)
   C. int

৩. ডাটাবেজ স্কিমা পরিবর্তন (যেমন `ALTER TABLE`) করতে কোন মেথড ব্যবহার করবেন?
   A. FromSql
   B. ExecuteSql (বা ExecuteSqlRaw) (উত্তর: B)
   C. SaveChanges

**⚠️ খুব জরুরি নোট:** `FromSql` ব্যবহার করলে অবশ্যই `SELECT *` বা এনটিটির সব কলাম সিলেক্ট করতে হবে। যদি কলাম মিস থাকে, তবে রানটাইমে এরর খাবেন। কাস্টম কলামের জন্য `SqlQuery` (EF Core 8) বা DTO প্রোজেকশন ব্যবহার করুন।

### Lesson 25: No-Tracking কুয়েরি (পারফরম্যান্স বুস্ট)

**👨‍🏫 কোড রান টিপ:** `Program.cs` ফাইলে কোড লিখুন।

**🎉 ভূমিকা:**
EF Core ডিফল্টভাবে "CCTV ক্যামেরা"র মতো আচরণ করে। আপনি ডাটাবেজ থেকে ডাটা আনলেই সে সেটার ওপর নজরদারি (Tracking) শুরু করে—"ভ্যালু চেঞ্জ হলো কি না? সেভ করতে হবে কি না?"।
কিন্তু আপনি যদি শুধু ডাটা **দেখতে** চান (যেমন: ওয়েবসাইটের হোমপেজে প্রোডাক্ট লিস্ট), তাহলে এই নজরদারি একদম অপ্রয়োজনীয় এবং মেমোরি নষ্ট করে। এই CCTV ক্যামেরা বন্ধ করার উপায় হলো **No-Tracking**।

**🎯 শেখার লক্ষ্য:**
১. Change Tracker-এর ওভারহেড (Overhead) বোঝা।
২. `.AsNoTracking()` মেথড ব্যবহার করা।
৩. রিড-অনলি (Read-Only) অপারেশনের জন্য সেরা পদ্ধতি জানা।

**📖 প্রধান বিষয়বস্তু:**
যখন আপনি ডাটা আনেন:
- **Tracking (Default):** EF Core ডাটার একটি কপি (Snapshot) মেমোরিতে রাখে। `SaveChanges` কল করলে সে বর্তমান ডাটার সাথে স্ন্যাপশট মিলিয়ে দেখে কিছু চেঞ্জ হয়েছে কি না।
- **No-Tracking:** EF Core শুধু ডাটা এনে আপনাকে দিয়ে দেয়। কোনো স্ন্যাপশট রাখে না, কোনো নজরদারি করে না। ফলে এটি **দ্রুত (Faster)** এবং **কম মেমোরি (Less Memory)** ব্যবহার করে।

সিনট্যাক্স: `context.Products.AsNoTracking().ToList()`

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using Microsoft.EntityFrameworkCore; // AsNoTracking এর জন্য জরুরি
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                // ডাটা নিশ্চিত করা
                if (!context.Products.Any())
                {
                    context.Products.Add(new Product { Name = "Test Product", Price = 100 });
                    context.SaveChanges();
                }

                Console.WriteLine("--- 1. Tracking Query (Normal) ---");
                // এটি ডিফল্ট বিহেভিয়ার
                var trackedProduct = context.Products.FirstOrDefault(p => p.Name == "Test Product");
                
                // ভ্যালু চেঞ্জ করলাম
                trackedProduct.Price = 200; 
                
                // সেভ করলাম (কাজ করবে, কারণ এটি ট্র্যাকড)
                context.SaveChanges(); 
                Console.WriteLine("Tracked product price updated to 200.");


                Console.WriteLine("\n--- 2. No-Tracking Query (Fast) ---");
                // AsNoTracking ব্যবহার করছি
                var untrackedProduct = context.Products
                                              .AsNoTracking() // ⚡ কোনো ট্র্যাকিং হবে না
                                              .FirstOrDefault(p => p.Name == "Test Product");

                // ভ্যালু চেঞ্জ করলাম
                untrackedProduct.Price = 500; 

                // সেভ করলাম
                context.SaveChanges(); 
                
                // ডাটাবেজ থেকে আবার চেক করি
                var checkDb = context.Products.AsNoTracking().FirstOrDefault(p => p.Name == "Test Product");
                
                Console.WriteLine($"Untracked product price in DB: {checkDb.Price}"); 
                // আউটপুট ২০০-ই থাকবে, ৫০০ হবে না। কারণ EF Core জানেই না আপনি ভ্যালু চেঞ্জ করেছেন!
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. আপনার `AppDbContext`-এর কনস্ট্রাক্টরে বা `OnConfiguring`-এ `QueryTrackingBehavior.NoTracking` গ্লোবাললি সেট করে দেখুন। তখন ডিফল্ট সব কুয়েরি No-Tracking হয়ে যাবে।
২. `AsNoTracking` দিয়ে ডাটা আনার পর যদি সেটা আপডেট করতেই চান, তবে `context.Products.Update(untrackedProduct)` কল করে দেখুন কাজ হয় কি না (হ্যাঁ হবে, কারণ `Update` মেথড ম্যানুয়ালি ট্র্যাকিং শুরু করায়)।

**🧠 কুইজ:**
১. `AsNoTracking()` মূলত কোন ধরনের অপারেশনের জন্য ব্যবহার করা উচিত?
   A. ডাটা আপডেট বা ডিলিট করার জন্য
   B. শুধু ডাটা পড়া বা দেখার জন্য (Read-Only) (উত্তর: B)
   C. ডাটা ইনসার্ট করার জন্য

২. No-Tracking কুয়েরি কেন ফাস্ট হয়?
   A. এটি ইনডেক্স ব্যবহার করে না
   B. এটি চেঞ্জ ট্র্যাকার এবং স্ন্যাপশট সেটআপ করে না (উত্তর: B)
   C. এটি ডাটাবেজ স্কিপ করে

৩. আপনি `AsNoTracking` দিয়ে ডাটা এনে `SaveChanges` কল করলে কী হবে?
   A. ডাটা আপডেট হবে
   B. ডাটা ডিলিট হবে
   C. ডাটাবেজে কোনো পরিবর্তন হবে না (উত্তর: C)

**⚠️ খুব জরুরি নোট:** ওয়েব অ্যাপ্লিকেশনে (API) যখন আপনি শুধু লিস্ট রিটার্ন করছেন (GET Request), তখন **সবসময়** `.AsNoTracking()` ব্যবহার করবেন। এটি সার্ভারের মেমোরি অনেক বাঁচায়।
