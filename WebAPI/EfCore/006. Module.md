### Lesson 26: Shadow Properties (অদৃশ্য প্রপার্টি)

**👨‍🏫 কোড রান টিপ:** `AppDbContext` এবং `Program.cs`-এ কাজ করব।

**🎉 ভূমিকা:**
ভাবুন তো, আপনার ডাটাবেজে এমন একটি কলাম আছে (যেমন: `LastUpdated`), কিন্তু আপনার C# ক্লাসে সেই প্রপার্টিটি নেই। এটাকে বলে **Shadow Property**।
এটি "ছায়ার" মতো—ডাটাবেজে আছে, EF Core-এর ট্র্যাকার জানে, কিন্তু আপনার ক্লাসের কোডে দৃশ্যমান নয়। সাধারণত অডিট ফিল্ড (CreatedBy, UpdatedTime) বা ফরেন কি লুকানোর জন্য এটি ব্যবহার হয়।

**🎯 শেখার লক্ষ্য:**
১. Shadow Property কনফিগার করা।
২. Shadow Property-র ভ্যালু সেট এবং গেট করা।
৩. কুয়েরিতে Shadow Property ব্যবহার করা।

**📖 প্রধান বিষয়বস্তু:**
- **তৈরি:** `modelBuilder.Entity<T>().Property<string>("ShadowPropName");`
- **সেট:** `context.Entry(entity).Property("Name").CurrentValue = ...`
- **গেট:** `EF.Property<Type>(entity, "Name")`

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AppDbContext.cs` (কনফিগারেশন)
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // আমরা Product ক্লাসে কোনো পরিবর্তন না করেই 'LastUpdated' কলাম যোগ করছি
    modelBuilder.Entity<Product>()
                .Property<DateTime>("LastUpdated"); 
                // এটি ডাটাবেজে একটি datetime কলাম তৈরি করবে
}

// সেভ করার সময় অটোমেটিক ভ্যালু বসানোর জন্য SaveChanges ওভাররাইড করি
public override int SaveChanges()
{
    // যারা চেঞ্জ হয়েছে তাদের খুঁজি
    var entries = ChangeTracker
        .Entries<Product>()
        .Where(e => e.State == EntityState.Added || e.State == EntityState.Modified);

    foreach (var entry in entries)
    {
        // শ্যাডো প্রপার্টিতে বর্তমান সময় বসিয়ে দিই
        entry.Property("LastUpdated").CurrentValue = DateTime.Now;
    }

    return base.SaveChanges();
}
```

**মাইগ্রেশন:** `dotnet ef migrations add AddedShadowProperty` -> `update`

**ফাইল:** `src/Program.cs` (ব্যবহার)
```csharp
using System;
using System.Linq;
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                // ১. প্রোডাক্ট আপডেট করি
                var product = context.Products.First();
                product.Price += 10;
                context.SaveChanges(); // এখানে অটোমেটিক LastUpdated সেট হবে

                Console.WriteLine("Product Updated!");

                // ২. শ্যাডো প্রপার্টি দিয়ে কুয়েরি করা
                // গত ১ মিনিটের মধ্যে আপডেট হওয়া প্রোডাক্ট খুঁজি
                var recentProducts = context.Products
                    .Where(p => EF.Property<DateTime>(p, "LastUpdated") > DateTime.Now.AddMinutes(-1))
                    .ToList();

                foreach (var p in recentProducts)
                {
                    // ভ্যালু পড়ার নিয়ম
                    var updatedTime = context.Entry(p).Property("LastUpdated").CurrentValue;
                    Console.WriteLine($"Product: {p.Name}, Updated At: {updatedTime}");
                }
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Product` এনটিটিতে `CreatedBy` (string) নামে একটি শ্যাডো প্রপার্টি যোগ করুন এবং `SaveChanges` এ হার্ডকোড করে "Admin" ভ্যালু সেট করুন।
২. এমন একটি ফরেন কি (যেমন `BlogId` in Post) শ্যাডো প্রপার্টি হিসেবে ব্যবহার করুন (অর্থাৎ `Post` ক্লাসে `BlogId` প্রপার্টি থাকবে না, কিন্তু কনফিগারেশনে থাকবে)। এটি EF Core-এর ডিফল্ট বিহেভিয়ার যদি আপনি FK প্রপার্টি না লেখেন।

**🧠 কুইজ:**

২. LINQ কুয়েরিতে Shadow Property এক্সেস করতে কোন মেথড লাগে?

   B. EF.Property`<T>() (উত্তর: B)

৩. Shadow Property কখন সবচেয়ে বেশি কাজে লাগে?

   B. যখন প্রাইমারি কি দরকার নেই

### Lesson 27: Backing Fields (এনক্যাপসুলেশন)

**👨‍🏫 কোড রান টিপ:** নতুন একটি এনটিটি `Voucher` তৈরি করব।

**🎉 ভূমিকা:**
OOP (Object-Oriented Programming)-এর একটি মূল নীতি হলো **Encapsulation**। আপনি চান না বাইরের কেউ সরাসরি আপনার প্রপার্টি চেঞ্জ করুক। যেমন: ডিসকাউন্ট ভাউচারের কোড সেট করার সময় আপনি ভ্যালিডেশন করতে চান।
কিন্তু EF Core তো ডাটাবেজ থেকে ডাটা লোড করার সময় সরাসরি প্রপার্টিতে ভ্যালু বসাতে চায়। তাহলে উপায়?
উত্তর: **Backing Field**। EF Core ডাটাবেজ থেকে প্রাইভেট ফিল্ডে (`_code`) ডাটা লোড করবে, আর পাবলিক প্রপার্টি (`Code`) দিয়ে আপনি লজিক কন্ট্রোল করবেন।

**🎯 শেখার লক্ষ্য:**
১. প্রাইভেট ফিল্ড এবং পাবলিক প্রপার্টির সম্পর্ক বোঝা।
২. Fluent API দিয়ে ব্যাকিং ফিল্ড কনফিগার করা।
৩. রিচ ডোমেইন মডেল (Rich Domain Model) তৈরি করা।

**📖 প্রধান বিষয়বস্তু:**
ডিফল্ট কনভেনশন: EF Core যদি `_camelCase` নামের প্রাইভেট ফিল্ড পায়, সে অটোমেটিক সেটা ব্যবহার করে। নাহলে `.HasField("_fieldName")` দিয়ে বলে দিতে হয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Voucher.cs`
```csharp
using System;

namespace Lesson01_Intro.Models
{
    public class Voucher
    {
        public int Id { get; set; }
        
        // ১. প্রাইভেট ফিল্ড (Backing Field)
        private string _code;

        // ২. পাবলিক প্রপার্টি (শুধু পড়ার জন্য বা লজিকসহ সেট করার জন্য)
        public string Code
        {
            get => _code;
            // সেট করার সময় লজিক অ্যাপ্লাই করছি
            set 
            {
                if (string.IsNullOrEmpty(value)) throw new Exception("Code cannot be empty");
                _code = value.ToUpper(); // সবসময় আপারকেস করে দিচ্ছি
            }
        }

        // কনস্ট্রাক্টর দিয়েও সেট করা যায়
        public Voucher(string code)
        {
            Code = code; // লজিক অ্যাপ্লাই হবে
        }

        // EF Core এর জন্য একটি খালি কনস্ট্রাক্টর লাগতে পারে (যদি প্যারামিটারওয়ালা কনস্ট্রাক্টর থাকে)
        private Voucher() { } 
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // কনফিগারেশন (যদিও _code কনভেনশন অনুযায়ী অটো ডিটেক্ট হয়)
    modelBuilder.Entity<Voucher>()
                .Property(v => v.Code)
                .HasField("_code") // স্পষ্টভাবে বলে দেওয়া
                .UsePropertyAccessMode(PropertyAccessMode.Field); 
                // মানে হলো: EF Core যখন ডাটা রিড/রাইট করবে, সে সরাসরি _code ফিল্ড ব্যবহার করবে,
                // সেটার (setter) মেথড কল করবে না। এটি দরকারি যদি সেটারে সাইড এফেক্ট থাকে।
}
```

**ফাইল:** `src/Program.cs`
```csharp
using (var context = new AppDbContext())
{
    // লজিক চেক: ছোট হাতের দিচ্ছি, কিন্তু ক্লাসের লজিক বড় হাতের করবে
    var v = new Voucher("promo2024"); 
    context.Add(v);
    context.SaveChanges();
    
    // ডাটাবেজ থেকে তোলার সময় EF সরাসরি _code এ ভ্যালু বসাবে
    var loadedVoucher = context.Set<Voucher>().First();
    Console.WriteLine($"Voucher Code: {loadedVoucher.Code}"); // PROMO2024
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `BankAccount` ক্লাসে `_balance` ফিল্ড রাখুন। পাবলিক মেথড `Deposit(amount)` দিয়ে ব্যালেন্স বাড়ান, কিন্তু ব্যালেন্স প্রপার্টি `private set` রাখুন। EF Core কনফিগার করে ডাটা সেভ ও লোড করে দেখুন।
২. `PropertyAccessMode.Property` ব্যবহার করে দেখুন কী হয় (সেক্ষেত্রে EF Core লোড করার সময়ও পাবলিক সেটার কল করবে, ফলে আপনার ভ্যালিডেশন লজিক রান হবে)।

**🧠 কুইজ:**
১. এনক্যাপসুলেশন (Encapsulation) বজায় রাখতে EF Core কোন ফিচারটি ব্যবহার করে?
   A. Shadow Property

   C. Data Annotations

২. `PropertyAccessMode.Field` মানে কী?

৩. প্রাইভেট ফিল্ডের নাম কনভেনশন অনুযায়ী সাধারণত কী হয়?

### Lesson 28: Owned Entity Types (Value Objects)

**👨‍🏫 কোড রান টিপ:** আমরা `AppDbContext` এবং `Program.cs` মডিফাই করব।

**🎉 ভূমিকা:**
ধরুন, আপনার `User` ক্লাসে `Address` আছে, আবার `Order` ক্লাসেও `ShippingAddress` আছে। অ্যাড্রেসের প্রপার্টিগুলো (Street, City, Zip) একই।
DDD (Domain Driven Design)-এ এগুলোকে বলা হয় **Value Object**। এগুলোর নিজস্ব কোনো `Id` থাকে না, এরা যার আন্ডারে থাকে (Owner), তার পরিচয়েই পরিচিত হয়।
EF Core-এ এগুলোকে **Owned Entity** বলা হয়। মজার ব্যাপার হলো, ডাটাবেজে আলাদা `Address` টেবিল তৈরি না করে, EF Core এগুলোকে `User` টেবিলের কলাম হিসেবেই ঢুকিয়ে দেয়!

**🎯 শেখার লক্ষ্য:**
১. Owned Entity Type তৈরি করা।
২. `OwnsOne` মেথড দিয়ে কনফিগার করা।
৩. ডাটাবেজ স্কিমা (কলামের নাম) পরিবর্তন দেখা।

**📖 প্রধান বিষয়বস্তু:**
- **কনফিগারেশন:** `modelBuilder.Entity<User>().OwnsOne(u => u.Address);`
- **ডাটাবেজ রেজাল্ট:** `Users` টেবিলে কলাম হবে `Address_Street`, `Address_City` ইত্যাদি।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/Address.cs` (এটি Value Object)
```csharp
namespace Lesson01_Intro.Models
{
    // কোনো Id প্রপার্টি নেই
    public class Address
    {
        public string Street { get; set; }
        public string City { get; set; }
        public string ZipCode { get; set; }
    }
}
```

**ফাইল:** `src/Models/Customer.cs` (নতুন ক্লাস)
```csharp
namespace Lesson01_Intro.Models
{
    public class Customer
    {
        public int Id { get; set; }
        public string Name { get; set; }
        
        // Navigation Property (কিন্তু কনফিগারেশন হবে Owned)
        public Address HomeAddress { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Customer>(entity =>
    {
        entity.OwnsOne(c => c.HomeAddress, address =>
        {
            // কলামের নাম কাস্টমাইজ করা (অপশনাল)
            address.Property(a => a.Street).HasColumnName("StreetName");
            address.Property(a => a.City).HasColumnName("CityName");
            address.Property(a => a.ZipCode).HasColumnName("Zip");
        });
    });
}
```

**মাইগ্রেশন:** `dotnet ef migrations add AddedOwnedAddress` -> `update`
*(ডাটাবেজে `Customers` টেবিলে `StreetName`, `CityName` কলামগুলো দেখুন। আলাদা `Addresses` টেবিল তৈরি হয়নি!)*

**ফাইল:** `src/Program.cs`
```csharp
using (var context = new AppDbContext())
{
    var customer = new Customer
    {
        Name = "Kashem Ali",
        HomeAddress = new Address // সাধারণ অবজেক্টের মতোই ব্যবহার
        {
            Street = "123 Mirpur Road",
            City = "Dhaka",
            ZipCode = "1216"
        }
    };

    context.Add(customer);
    context.SaveChanges();
    Console.WriteLine("Customer with Address Saved!");
}
```

### Lesson 29: Table Splitting এবং Entity Splitting

**👨‍🏫 কোড রান টিপ:** Table Splitting বেশি জনপ্রিয়।

**🎉 ভূমিকা:**
- **Table Splitting:** আপনার ডাটাবেজে একটি বিশাল টেবিল আছে (১০০ কলাম)। কিন্তু সচরাচর আপনার লাগে মাত্র ১০টি কলাম। বাকি ৯০টি কলাম (যেমন: ব্যবহারকারীর বায়োগ্রাফি, ছবি) লোড করে মেমোরি নষ্ট করার দরকার নেই।
  আমরা কোডে **দুটি আলাদা ক্লাস** বানাবো (`User` এবং `UserDetails`), কিন্তু ডাটাবেজে **একটিই টেবিল** থাকবে। যখন `User` লোড করবেন, তখন ভারী কলামগুলো আসবে না।
- **Entity Splitting:** (বিপরীত) আপনার একটি ক্লাস (`Product`), কিন্তু ডাটাবেজে ডাটা ছড়িয়ে আছে দুটি টেবিলে (`Products` এবং `ProductDetails`)। এটি খুব কম ব্যবহৃত হয়।

**🎯 শেখার লক্ষ্য:**
১. Table Splitting এর মাধ্যমে পারফরম্যান্স অপটিমাইজ করা।
২. ১:১ রিলেশন ব্যবহার করে একই টেবিলে ম্যাপ করা।
৩. `ToTable` মেথড দিয়ে টেবিল শেয়ার করা।

**📖 প্রধান বিষয়বস্তু:**
Table Splitting এর শর্ত:
1. দুটি এন্টিটির মধ্যে ১:১ রিলেশন থাকতে হবে।
2. ফরেন কি এবং প্রাইমারি কি একই হতে হবে।
3. `ToTable("TableName")` দুই ক্লাসের জন্যই **একই নাম** হতে হবে।

**💻 কোড উদাহরণ (Table Splitting):**

**ফাইল:** `src/Models/UserModels.cs`
```csharp
namespace Lesson01_Intro.Models
{
    // ১. মেইন এনটিটি (হালকা)
    public class SystemUser
    {
        public int Id { get; set; }
        public string Username { get; set; }
        
        // রিলেশন
        public SystemUserDetails Details { get; set; }
    }

    // ২. ডিটেইল এনটিটি (ভারী ডাটা)
    public class SystemUserDetails
    {
        public int Id { get; set; } // PK + FK (Shared)
        public string Biography { get; set; } // বড় টেক্সট
        public byte[] ProfilePicture { get; set; } // ভারী ইমেজ
        
        public SystemUser User { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // আগের কোড...

    // --- Table Splitting ---
    // উভয় এনটিটি একই টেবিল 'AppUsers' এ ম্যাপ হবে
    modelBuilder.Entity<SystemUser>()
                .ToTable("AppUsers")
                .HasOne(u => u.Details)
                .WithOne(d => d.User)
                .HasForeignKey<SystemUserDetails>(d => d.Id); // Id শেয়ার করছে

    modelBuilder.Entity<SystemUserDetails>()
                .ToTable("AppUsers"); // একই টেবিল নাম!
                
    // দরকারি কনফিগারেশন: ডিটেইলস অপশনাল হতে পারে
    modelBuilder.Entity<SystemUser>().Navigation(u => u.Details).AutoInclude(false);
}
```

**মাইগ্রেশন:** `dotnet ef migrations add AddedTableSplitting` -> `update`
*(ডাটাবেজে `AppUsers` টেবিল চেক করুন। সব কলাম (Username, Biography) এক টেবিলে আছে!)*

২. Table Splitting এ `SystemUserDetails` এর ডাটা আপডেট করে সেভ করুন। দেখুন একই টেবিলে আপডেট হয় কি না।

### Lesson 30: Global Query Filters (Soft Delete ইমপ্লিমেন্টেশন)

**👨‍🏫 কোড রান টিপ:** `AppDbContext`-এর `OnModelCreating` মেথডে আমরা কাজ করব।

**🎉 ভূমিকা:**
আপনার বস বলল, "কোনো ডাটা কখনো ডিলিট করা যাবে না! যদি কেউ ডিলিট করে, তবে সেটা শুধু লুকিয়ে রাখতে হবে।"
একে বলে **Soft Delete**। আমরা ডাটাবেজ থেকে `DELETE` কমান্ড চালাবো না, বরং `IsDeleted = true` করে দেব।
সমস্যা হলো, এরপর থেকে আপনাকে *প্রতিটি* কুয়েরিতে `Where(x => !x.IsDeleted)` লিখতে হবে। একবার ভুলে গেলেই ডিলিট হওয়া ডাটা ইউজারকে দেখিয়ে দেবেন! 😱
এই সমস্যার সমাধান হলো **Global Query Filter**। একবার সেট করবেন, সারা জীবন অটোমেটিক ফিল্টার হবে।

**🎯 শেখার লক্ষ্য:**
১. Global Query Filter কী তা বোঝা।
২. Soft Delete ইমপ্লিমেন্ট করা।
৩. প্রয়োজনে ফিল্টার বাইপাস করা (`IgnoreQueryFilters`)।

**📖 প্রধান বিষয়বস্তু:**
- **সেটআপ:** `modelBuilder.Entity<T>().HasQueryFilter(x => !x.IsDeleted);`
- **সুবিধা:** `ToList()`, `Count()`, `Find()`—সব মেথডেই এই ফিল্টার অটোমেটিক অ্যাপ্লাই হয়।
- **বাইপাস:** এডমিন প্যানেলে সব ডাটা দেখতে চাইলে `IgnoreQueryFilters()` ব্যবহার করতে হয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/SoftDeleteProduct.cs` (বা বিদ্যমান Product ক্লাসে ফিল্ড যোগ করুন)
```csharp
namespace Lesson01_Intro.Models
{
    // ইন্টারফেস ব্যবহার করা ভালো প্র্যাকটিস
    public interface ISoftDelete
    {
        bool IsDeleted { get; set; }
    }

    public class Product : ISoftDelete // Product ক্লাস আপডেট করছি
    {
        public int Id { get; set; }
        public string Name { get; set; }
        public decimal Price { get; set; }
        public bool IsDeleted { get; set; } // নতুন ফ্ল্যাগ
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // আগের কোড...

    // --- Global Filter ---
    modelBuilder.Entity<Product>().HasQueryFilter(p => !p.IsDeleted);
}

// আমরা Remove মেথডকে Soft Delete বানাতে পারি
public override int SaveChanges()
{
    foreach (var entry in ChangeTracker.Entries<ISoftDelete>())
    {
        switch (entry.State)
        {
            case EntityState.Deleted:
                entry.State = EntityState.Modified; // ডিলিট না করে মডিফাই করছি
                entry.Entity.IsDeleted = true;      // ফ্ল্যাগ ট্রু করছি
                break;
        }
    }
    return base.SaveChanges();
}
```

**মাইগ্রেশন:** `dotnet ef migrations add AddedSoftDelete` -> `update`

**ফাইল:** `src/Program.cs`
```csharp
using (var context = new AppDbContext())
{
    // ১. ডাটা তৈরি
    var p1 = new Product { Name = "Live Product", Price = 100 };
    var p2 = new Product { Name = "Deleted Product", Price = 50, IsDeleted = true }; // ম্যানুয়ালি ডিলিটেড মার্ক করলাম
    context.AddRange(p1, p2);
    context.SaveChanges();

    Console.WriteLine("--- Normal Query (Filter Active) ---");
    // আমরা কোনো Where লিখিনি, তবুও p2 আসবে না
    var activeProducts = context.Products.ToList();
    Console.WriteLine($"Total Active: {activeProducts.Count}"); // আউটপুট: 1

    foreach (var p in activeProducts)
    {
        Console.WriteLine($" - {p.Name}");
    }

    Console.WriteLine("\n--- Admin Query (Filter Ignored) ---");
    // ফিল্টার বাইপাস করে সব দেখছি
    var allProducts = context.Products.IgnoreQueryFilters().ToList();
    Console.WriteLine($"Total All: {allProducts.Count}"); // আউটপুট: 2 (বা আগের ডাটাসহ বেশি)

    Console.WriteLine("\n--- Soft Delete Test ---");
    // p1 কে রিমুভ করি
    context.Products.Remove(p1);
    context.SaveChanges(); // আমাদের ওভাররাইড করা লজিকে এটি হার্ড ডিলিট হবে না
    
    // চেক
    var check = context.Products.IgnoreQueryFilters().FirstOrDefault(p => p.Name == "Live Product");
    Console.WriteLine($"'Live Product' IsDeleted status: {check.IsDeleted}"); // True হবে
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. Multi-tenant অ্যাপ্লিকেশনের জন্য একটি ফিল্টার তৈরি করুন। `User` ক্লাসে `TenantId` রাখুন এবং গ্লোবাল ফিল্টারে `HasQueryFilter(u => u.TenantId == _currentTenantId)` সেট করুন। (এখানে `_currentTenantId` কনস্ট্রাক্টরের মাধ্যমে পাস করতে হবে)।
২. `Find(id)` মেথড ব্যবহার করে একটি সফট ডিলিটেড আইটেম খোঁজার চেষ্টা করুন। দেখবেন নাল রিটার্ন করে। তারপর `IgnoreQueryFilters` দিয়ে চেষ্টা করুন (নোট: `Find` এর সাথে `IgnoreQueryFilters` সরাসরি চেইন করা যায় না, সেক্ষেত্রে `FirstOrDefault` ব্যবহার করতে হবে)।
