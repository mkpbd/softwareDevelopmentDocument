OOP-তে ইনহেরিটেন্স (Inheritance) খুব স্বাভাবিক বিষয়। যেমন: `Person` ক্লাস থেকে `Student` এবং `Teacher` ক্লাস ইনহেরিট করে। কিন্তু রিলেশনাল ডাটাবেজে (SQL) ইনহেরিটেন্স বলে কিছু নেই। সেখানে শুধুই টেবিল।

EF Core-এ এর জন্য ৩টি কৌশল আছে: **TPH, TPT, TPC**।

আজ আমরা শিখব সবচেয়ে সহজ এবং ডিফল্ট কৌশলটি।

### Lesson 31: ইনহেরিটেন্স ম্যাপিং: TPH (Table Per Hierarchy)

**👨‍🏫 কোড রান টিপ:** নতুন কিছু ক্লাস তৈরি করতে হবে।

**🎉 ভূমিকা:**
**TPH (Table Per Hierarchy)** মানে হলো: "এক পরিবার, এক ছাদ"।
বাবা, ছেলে, মেয়ে—সবাই এক টেবিলেই থাকবে। ডাটাবেজে `People` নামে একটি বিশাল টেবিল তৈরি হবে। সেখানে `Student` এবং `Teacher`-এর সব কলাম থাকবে।
তাহলে বুঝবেন কীভাবে কোনটা টিচার আর কোনটা স্টুডেন্ট?
EF Core চালাকি করে `Discriminator` নামে একটি এক্সট্রা কলাম যোগ করে, যেখানে লেখা থাকে "Student" বা "Teacher"।

**🎯 শেখার লক্ষ্য:**
১. ইনহেরিটেন্স ক্লাস স্ট্রাকচার তৈরি করা।
২. TPH প্যাটার্ন কীভাবে একটি টেবিলে সব ডাটা রাখে তা দেখা।
৩. `Discriminator` কলামের কাজ বোঝা।

**📖 প্রধান বিষয়বস্তু:**
- **সুবিধা:** পারফরম্যান্স খুব ভালো (কোনো JOIN লাগে না)।
- **অসুবিধা:** টেবিলে অনেক `NULL` ভ্যালু থাকে (যেমন: স্টুডেন্টের রো-তে টিচারের স্যালারি কলাম নাল থাকে)।
- **কনফিগারেশন:** কোনো কনফিগারেশন লাগে না! EF Core ডিফল্টভাবে এটাই ব্যবহার করে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/InheritanceModels.cs`
```csharp
namespace Lesson01_Intro.Models
{
    // ১. বেস ক্লাস (Base Class)
    public class PersonBase
    {
        public int Id { get; set; }
        public string Name { get; set; }
    }

    // ২. চাইল্ড ক্লাস ১
    public class Student : PersonBase
    {
        public double CGPA { get; set; } // শুধু স্টুডেন্টের আছে
    }

    // ৩. চাইল্ড ক্লাস ২
    public class Teacher : PersonBase
    {
        public decimal Salary { get; set; } // শুধু টিচারের আছে
        public string Subject { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
public DbSet<PersonBase> People { get; set; } // শুধু বেস ক্লাস দিলেই হয়
public DbSet<Student> Students { get; set; }  // আলাদা করেও দেওয়া যায়
public DbSet<Teacher> Teachers { get; set; }

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // TPH এর জন্য স্পেশাল কোনো কনফিগারেশন লাগে না।
    // তবে আপনি চাইলে Discriminator কলামের নাম বদলাতে পারেন:
    /*
    modelBuilder.Entity<PersonBase>()
        .HasDiscriminator<string>("UserType")
        .HasValue<Student>("Stud")
        .HasValue<Teacher>("Tchr");
    */
}
```

**মাইগ্রেশন:** `dotnet ef migrations add TphInheritance` -> `update`
*(ডাটাবেজে `People` টেবিলটি চেক করুন। সেখানে `CGPA`, `Salary`, `Subject` এবং `Discriminator` সব কলাম এক টেবিলে আছে)*

**ফাইল:** `src/Program.cs`
```csharp
using (var context = new AppDbContext())
{
    Console.WriteLine("--- TPH Inheritance ---");

    // ১. ডাটা সেভ
    var s = new Student { Name = "Rahim", CGPA = 3.5 };
    var t = new Teacher { Name = "Zafar Sir", Salary = 50000, Subject = "Physics" };

    context.AddRange(s, t);
    context.SaveChanges();

    // ২. পলিমরফিক কুয়েরি (সব মানুষ আনো)
    var allPeople = context.People.ToList();
    foreach (var p in allPeople)
    {
        // C# এর প্যাটার্ন ম্যাচিং
        switch (p)
        {
            case Student student:
                Console.WriteLine($"Student: {student.Name}, CGPA: {student.CGPA}");
                break;
            case Teacher teacher:
                Console.WriteLine($"Teacher: {teacher.Name}, Subject: {teacher.Subject}");
                break;
        }
    }

    // ৩. স্পেসিফিক কুয়েরি (শুধু টিচার আনো)
    // EF Core অটোমেটিক 'WHERE Discriminator = Teacher' যোগ করে দেবে
    var teachers = context.Teachers.Where(tr => tr.Salary > 40000).ToList();
    Console.WriteLine($"Rich Teachers Found: {teachers.Count}");
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Student` এর জন্য `Salary` কলামে ডাটাবেজে কী ভ্যালু আছে? (NULL)। আবার `Teacher` এর জন্য `CGPA` কী? (NULL)। SSMS বা টেবিল ভিউয়ার দিয়ে চেক করুন।
২. `PersonBase` ক্লাসটিকে `abstract` করে দেখুন। EF Core তবুও কাজ করবে এবং `Discriminator` কলামে শুধু চাইল্ড ক্লাসের নাম থাকবে।

**🧠 কুইজ:**
১. TPH এর পূর্ণরূপ কী?
   A. Table Per Hierarchy (উত্তর: A)
   B. Table Per History
   C. Two People House

২. TPH প্যাটার্নে কয়টি টেবিল তৈরি হয়?
   A. যতগুলো ক্লাস ততগুলো
   B. মাত্র ১টি (উত্তর: B)
   C. ২টি

৩. `Discriminator` কলামের কাজ কী?
   A. ডাটা ডিলিট করা
   B. একই টেবিলে বিভিন্ন ধরণের ডাটাকে আলাদা করে চেনা (উত্তর: B)
   C. পাসওয়ার্ড রাখা

**⚠️ খুব জরুরি নোট:** যদি আপনার সাব-ক্লাসগুলোতে (Student/Teacher) অনেক অনেক আলাদা কলাম থাকে, তবে TPH ব্যবহার করলে টেবিলটি বিশাল এবং ফাঁকা (Sparse) হয়ে যাবে। সেক্ষেত্রে TPT বা TPC ভালো। তবে ছোটখাটো পার্থক্যের জন্য TPH সেরা এবং ফাস্টেস্ট।

### Lesson 32: ইনহেরিটেন্স ম্যাপিং: TPT (Table Per Type)

**👨‍🏫 কোড রান টিপ:** আমরা আগের লেসনের ক্লাসগুলোই ব্যবহার করব, শুধু কনফিগারেশন পাল্টে দেব।

**🎉 ভূমিকা:**
**TPT (Table Per Type)** মানে হলো: "যার যার ঘর তার তার"।
- `Person` এর জন্য একটি টেবিল (Id, Name)।
- `Student` এর জন্য আলাদা টেবিল (Id, CGPA)।
- `Teacher` এর জন্য আলাদা টেবিল (Id, Salary)।
মজার ব্যাপার হলো, `Student` এবং `Teacher` টেবিলগুলো `Person` টেবিলের `Id` শেয়ার করে (Foreign Key হিসেবে)। অর্থাৎ ডাটাবেজ নরমালাইজড থাকে।

**🎯 শেখার লক্ষ্য:**
১. TPT প্যাটার্ন কনফিগার করা (`ToTable`).
২. ডাটাবেজ স্কিমা পরিবর্তন দেখা (৩টি টেবিল)।
৩. কুয়েরি পারফরম্যান্স (JOIN) বোঝা।

**📖 প্রধান বিষয়বস্তু:**
- **কনফিগারেশন:** প্রতিটি এনটিটিকে আলাদা টেবিলের নাম বলে দিতে হয় (`ToTable`)।
- **সুবিধা:** ডাটাবেজ ক্লিন থাকে, কোনো নাল ভ্যালু থাকে না।
- **অসুবিধা:** ডাটা লোড করার সময় অনেক `JOIN` কুয়েরি চলে, তাই এটি TPH-এর চেয়ে স্লো।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AppDbContext.cs`
(আগের TPH কোড মুছে বা কমেন্ট করে আপডেট করুন)
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // --- TPT Configuration ---
    
    // ১. বেস টেবিল
    modelBuilder.Entity<PersonBase>().ToTable("People_TPT");

    // ২. চাইল্ড টেবিল ১
    // যেই মুহূর্তে আপনি চাইল্ডকে আলাদা টেবিল নাম দেবেন, EF বুঝবে এটা TPT
    modelBuilder.Entity<Student>().ToTable("Students_TPT");

    // ৩. চাইল্ড টেবিল ২
    modelBuilder.Entity<Teacher>().ToTable("Teachers_TPT");
}
```

**মাইগ্রেশন:** `dotnet ef migrations add TptInheritance` -> `update`
*(ডাটাবেজ চেক করুন: তিনটি আলাদা টেবিল তৈরি হয়েছে। `Students_TPT` টেবিলে শুধু `Id` (যা People_TPT এর FK) এবং `CGPA` আছে।)*

**ফাইল:** `src/Program.cs` (ব্যবহার আগের মতোই)
```csharp
using (var context = new AppDbContext())
{
    Console.WriteLine("--- TPT Inheritance ---");

    // ১. সেভ (EF Core ৩টি টেবিলে ডাটা ভাগ করে ইনসার্ট করবে)
    // Student সেভ করলে -> People টেবিলে নাম যাবে, Students টেবিলে CGPA যাবে
    var s = new Student { Name = "Karim", CGPA = 3.9 };
    context.Add(s);
    context.SaveChanges();
    Console.WriteLine("Student Saved!");

    // ২. কুয়েরি (ব্যাকগ্রাউন্ডে INNER JOIN চলে)
    var students = context.Students.ToList(); 
    // SQL: SELECT s.Id, p.Name, s.CGPA 
    //      FROM Students_TPT s 
    //      INNER JOIN People_TPT p ON s.Id = p.Id
    
    foreach(var st in students)
    {
        Console.WriteLine($"{st.Name} - {st.CGPA}");
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `context.People.ToList()` কল করে দেখুন SQL কুয়েরিটি কেমন হয়। (এটি `LEFT JOIN` ব্যবহার করবে সব চাইল্ড টেবিলের সাথে, যা বেশ ভারী কুয়েরি)।
২. `Teacher` ডিলিট করলে `Person` টেবিল থেকে ডাটা ডিলিট হয় কি না পরীক্ষা করুন (হবে, কারণ ক্যাসকেড ডিলিট থাকে)।

**🧠 কুইজ:**
১. TPT প্যাটার্নে `Student` টেবিলের প্রাইমারি কি (Id) একই সাথে আর কী হিসেবে কাজ করে?
   A. শুধু প্রাইমারি কি
   B. ফরেন কি (বেস টেবিলের রেফারেন্স) (উত্তর: B)
   C. ডিসক্রিমিনেটর

২. TPT এর প্রধান অসুবিধা কী?
   A. ডাটাবেজ বড় হয়ে যায়
   B. কুয়েরি পারফরম্যান্স স্লো হতে পারে (অতিরিক্ত জয়েন এর কারণে) (উত্তর: B)
   C. কনফিগার করা কঠিন

৩. TPT কনফিগার করার জন্য কোন মেথডটি ব্যবহার করা হয়?
   A. ToTable("TableName") (উত্তর: A)
   B. HasDiscriminator()
   C. OwnsOne()

**⚠️ খুব জরুরি নোট:** যদি আপনার সিস্টেমে পলিমরফিক কুয়েরি (যেমন `context.People.ToList()`) খুব বেশি লাগে, তবে TPT এড়িয়ে চলুন। কারণ ১০টি চাইল্ড ক্লাস থাকলে ১০টি জয়েন হবে! সেক্ষেত্রে TPH ভালো। আর যদি শুধু স্পেসিফিক কুয়েরি (`context.Students`) বেশি লাগে, তবে TPT ব্যবহার করতে পারেন।

### Lesson 33: ইনহেরিটেন্স ম্যাপিং: TPC (Table Per Concrete Type)

**👨‍🏫 কোড রান টিপ:** এই ফিচারটি ব্যবহারের জন্য **.NET 7 বা তার পরবর্তী** ভার্সন আবশ্যক।

**🎉 ভূমিকা:**
**TPC (Table Per Concrete Type)** মানে হলো: "সম্পূর্ণ আলাদা সংসার"।
- `Person` টেবিল বলে কিছু থাকবে না (যদি এটি অ্যাবস্ট্রাক্ট হয়)।
- `Student` টেবিল হবে সম্পূর্ণ স্বাধীন (Id, Name, CGPA সব নিজের কাছে থাকবে)।
- `Teacher` টেবিলও স্বাধীন (Id, Name, Salary সব নিজের)।
কারো সাথে কারো জয়েন করার দরকার নেই, তাই কুয়েরি সুপার ফাস্ট! 🚀

**🎯 শেখার লক্ষ্য:**
১. TPC এবং TPT এর পার্থক্য বোঝা।
২. `UseTpcMappingStrategy` মেথড ব্যবহার করা।
৩. আইডেন্টিটি কলাম (Auto Increment) এর সমস্যা ও সমাধান।

**📖 প্রধান বিষয়বস্তু:**
- **TPT vs TPC:** TPT-তে `Name` থাকে বেস টেবিলে, TPC-তে `Name` ডুপ্লিকেট হয়ে সব চাইল্ড টেবিলে চলে যায়।
- **সমস্যা:** যেহেতু টেবিলগুলো স্বাধীন, তাই `Student` এর আইডি ১ এবং `Teacher` এর আইডি ১ হলে কনফ্লিক্ট হবে (যদি আমরা তাদের `Person` হিসেবে ডাকি)।
- **সমাধান:** TPC তে আইডেন্টিটি কলাম বা অটো-ইনক্রিমেন্ট ব্যবহার করা একটু ট্রিকি। সাধারণত আমরা `Sequence` বা `Guid` ব্যবহার করি যাতে আইডি ইউনিক থাকে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // --- TPC Configuration ---
    
    // ১. স্ট্যাটেজি বলে দেওয়া
    modelBuilder.Entity<PersonBase>()
                .UseTpcMappingStrategy(); 
                // নোট: PersonBase কে abstract class বানানো ভালো

    // ২. টেবিল কনফিগারেশন (আলাদা টেবিল হবে)
    modelBuilder.Entity<Student>().ToTable("Students_TPC");
    modelBuilder.Entity<Teacher>().ToTable("Teachers_TPC");

    // ৩. TPC তে আইডি জেনারেশন সমস্যা সমাধান
    // আমরা SQL Sequence ব্যবহার করব যাতে সব টেবিল মিলে আইডি ইউনিক থাকে
    // (যেমন: Student পেল ১, Teacher পেল ২, আবার Student পেল ৩)
    /*
    modelBuilder.HasSequence<int>("PersonSequence");
    modelBuilder.Entity<PersonBase>()
                .Property(e => e.Id)
                .UseHiLo("PersonSequence"); // HiLo অ্যালগরিদম ব্যবহার
    */
    // সহজ উপায়ের জন্য আমরা ম্যানুয়ালি আইডি দিতে পারি অথবা কনভেনশন ফলো করতে পারি।
}
```

**মাইগ্রেশন:** `dotnet ef migrations add TpcInheritance` -> `update`
*(ডাটাবেজে দেখুন: `Students_TPC` টেবিলে `Name` কলাম আছে, `Teachers_TPC` টেবিলেও `Name` কলাম আছে। `People` নামে কোনো টেবিল নেই!)*

**ফাইল:** `src/Program.cs`
```csharp
using (var context = new AppDbContext())
{
    Console.WriteLine("--- TPC Inheritance ---");

    // ১. সেভ (সরাসরি সংশ্লিষ্ট টেবিলে ইনসার্ট হয়)
    var s = new Student { Name = "TPC Student", CGPA = 4.0 };
    context.Add(s);
    context.SaveChanges();

    // ২. পলিমরফিক কুয়েরি (UNION ALL)
    // EF Core সব টেবিল থেকে ডাটা এনে জোড়া লাগায় (UNION ALL), যা JOIN এর চেয়ে ফাস্ট
    var allPeople = context.People.ToList();
    // SQL: SELECT ... FROM Students UNION ALL SELECT ... FROM Teachers

    foreach (var p in allPeople)
    {
        Console.WriteLine($"Person: {p.Name} (ID: {p.Id})");
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Student` টেবিলে সরাসরি SQL দিয়ে একটি ডাটা ইনসার্ট করুন। তারপর কোড দিয়ে সব `Person` ফেচ করুন।
২. TPC মডেলে `PersonBase` টেবিলটি যদি ডাটাবেজে না থাকে, তবে ফরেন কি রিলেশনশিপ (যেমন `Order` -> `Person`) কীভাবে কাজ করবে? (উত্তর: এটি জটিল। সাধারণত TPC তখন ব্যবহার করবেন যখন বেস ক্লাসের সাথে অন্য কারো সরাসরি রিলেশন নেই)।

**⚠️ খুব জরুরি নোট:** TPC সব ক্ষেত্রে ভালো নয়। যদি আপনার বেস ক্লাসের ওপর ফরেন কি থাকে (অন্য টেবিল রেফারেন্স দেয়), তবে TPC ঝামেলা করবে। তখন TPT বা TPH ভালো। TPC সেরা যখন আপনার ডাটাগুলো সম্পূর্ণ আলাদা এবং আপনি শুধু কোড শেয়ারিং (Inheritance) এর জন্য বেস ক্লাস ব্যবহার করছেন।
