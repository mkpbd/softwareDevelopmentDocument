### Lesson 34: বাল্ক আপডেট ও ডিলিট (ExecuteUpdate/Delete)

**👨‍🏫 কোড রান টিপ:** .NET 7 বা তার ওপরের ভার্সন লাগবে।

**🎉 ভূমিকা:**
SQL এ আমরা লিখতাম `UPDATE Products SET Price = Price + 10 WHERE CategoryId = 1`।
EF Core-এ এখন ঠিক এই কাজটিই করা যায় C# কোড দিয়ে, কোনো ডাটা মেমোরিতে না এনে। একে বলে **Bulk Operations**।

**🎯 শেখার লক্ষ্য:**
১. `ExecuteUpdate` দিয়ে একসাথে অনেক ডাটা আপডেট করা।
২. `ExecuteDelete` দিয়ে শর্ত সাপেক্ষে ডাটা ডিলিট করা।
৩. `SetProperty` মেথডের ব্যবহার।

**📖 প্রধান বিষয়বস্তু:**
- **ExecuteDelete:** `context.Products.Where(...).ExecuteDeleteAsync();`
- **ExecuteUpdate:** `context.Products.Where(...).ExecuteUpdateAsync(s => s.SetProperty(...));`

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static async Task Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                // ১. বাল্ক ডিলিট (Bulk Delete)
                Console.WriteLine("Deleting old products...");
                
                // শর্ত: দাম ১০০ এর কম প্রোডাক্ট ডিলিট করো
                // এটি সরাসরি SQL DELETE কমান্ড চালাবে: DELETE FROM Products WHERE Price < 100
                int deletedCount = await context.Products
                                                .Where(p => p.Price < 100)
                                                .ExecuteDeleteAsync();
                
                Console.WriteLine($"{deletedCount} products deleted directly!");

                // ২. বাল্ক আপডেট (Bulk Update)
                Console.WriteLine("Increasing price for products...");

                // শর্ত: যাদের নামের মধ্যে 'Pro' আছে, তাদের দাম ১০% বাড়াও এবং নাম আপডেট করো
                // SQL: UPDATE Products SET Price = Price * 1.1, Name = Name + ' (Updated)' WHERE Name LIKE '%Pro%'
                int updatedCount = await context.Products
                                                .Where(p => p.Name.Contains("Pro"))
                                                .ExecuteUpdateAsync(setters => setters
                                                    .SetProperty(p => p.Price, p => p.Price * 1.10m) // ১০% বৃদ্ধি
                                                    .SetProperty(p => p.Name, p => p.Name + " (Updated)") // নামের শেষে যুক্ত করা
                                                );

                Console.WriteLine($"{updatedCount} products updated directly!");
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `ExecuteUpdate` ব্যবহার করে সব ইউজারের `IsActive` প্রপার্টি `true` করে দিন।
২. একটি ভুল শর্ত দিয়ে `ExecuteDelete` চালানোর চেষ্টা করুন (সাবধান! আগে ব্যাকআপ বা টেস্ট ডাটাবেজ ব্যবহার করুন)।

**🧠 কুইজ:**
১. `ExecuteUpdate` মেথড কল করার আগে কি ডাটা মেমোরিতে লোড করতে হয়?
   A. হ্যাঁ, `ToList` দিয়ে
   B. না, সরাসরি কুয়েরির ওপর চালানো যায় (উত্তর: B)
   C. শুধু `Find` দিয়ে

২. বাল্ক অপারেশনে `SaveChanges()` কল করার প্রয়োজন আছে কি?
   A. হ্যাঁ
   B. না, মেথডটি নিজেই ডাটাবেজে কমান্ড এক্সিকিউট করে (উত্তর: B)

৩. `SetProperty` মেথডটি কোন অপারেশনের জন্য ব্যবহৃত হয়?
   A. ExecuteDelete
   B. ExecuteUpdate (উত্তর: B)
   C. SaveChanges

**⚠️ খুব জরুরি নোট:**
১. এই অপারেশনগুলো **Change Tracker** আপডেট করে না। অর্থাৎ, আপনি যদি একই কনটেক্সটে আগে ডাটা লোড করে থাকেন এবং পরে `ExecuteUpdate` চালান, তবে লোড করা অবজেক্টগুলো পুরানো ভ্যালুই দেখাবে।
২. এটি **Transactions** সাপোর্ট করে, তাই প্রয়োজনে রোলব্যাক করা যায়।

### Lesson 35: ট্রানজ্যাকশন ম্যানেজমেন্ট (Transactions)

**👨‍🏫 কোড রান টিপ:** আমরা `System.Transactions` বা EF Core এর `BeginTransaction` ব্যবহার করব।

**🎉 ভূমিকা:**
ব্যাংকিং অ্যাপের কথা ভাবুন। আপনি বন্ধুকে ৫০০ টাকা পাঠালেন।
১. আপনার অ্যাকাউন্ট থেকে ৫০০ টাকা কমবে।
২. বন্ধুর অ্যাকাউন্টে ৫০০ টাকা বাড়বে।
যদি ১ নম্বর হওয়ার পর বিদ্যুৎ চলে যায় আর ২ নম্বর না হয়? সর্বনাশ! আপনার টাকা গেল, বন্ধুও পেল না।
**Transaction** নিশ্চিত করে যে, "হয় সব কাজ হবে, নাহলে কিছুই হবে না (All or Nothing)"।

**🎯 শেখার লক্ষ্য:**
১. `SaveChanges` কীভাবে ডিফল্ট ট্রানজ্যাকশন হিসেবে কাজ করে তা জানা।
২. একাধিক `SaveChanges` কে একটি ট্রানজ্যাকশনে মোড়ানো।
৩. `Commit` এবং `Rollback` বোঝা।

**📖 প্রধান বিষয়বস্তু:**
- **Implicit:** একটি `SaveChanges()` কল নিজেই একটি ট্রানজ্যাকশন। যদি ৫টা ইনসার্টের মধ্যে ৩য়টাতে এরর হয়, তবে কোনোটিই ইনসার্ট হবে না।
- **Explicit:** যদি আপনার লজিকে ২ বার `SaveChanges` কল করতে হয়, তবে আপনাকে ম্যানুয়ালি `BeginTransaction` শুরু করতে হবে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        static void Main(string[] args)
        {
            using (var context = new AppDbContext())
            {
                // ১. ট্রানজ্যাকশন শুরু
                using (var transaction = context.Database.BeginTransaction())
                {
                    try
                    {
                        Console.WriteLine("Transaction Started...");

                        // ধাপ ১: ব্লগ তৈরি
                        var blog = new Blog { Url = "http://secure-blog.com" };
                        context.Blogs.Add(blog);
                        context.SaveChanges(); // প্রথম সেভ (ডাটাবেজে যাবে কিন্তু লক থাকবে)

                        Console.WriteLine($"Blog Saved with ID: {blog.Id}");

                        // ধাপ ২: পোস্ট তৈরি (ইচ্ছাকৃত এরর তৈরি করছি)
                        var post = new Post 
                        { 
                            Title = "Intro", 
                            BlogId = blog.Id 
                        };
                        context.Posts.Add(post);
                        
                        // সিমুলেশন: ধরুন এখানে কোডে ক্র্যাশ হলো বা লজিক্যাল এরর হলো
                        bool simulateError = true; 
                        if (simulateError)
                        {
                            throw new Exception("ওহ না! সার্ভার ক্র্যাশ করেছে!");
                        }

                        context.SaveChanges(); // দ্বিতীয় সেভ

                        // ৩. সব ঠিক থাকলে কমিট (Commit)
                        transaction.Commit();
                        Console.WriteLine("সব ডাটা সফলভাবে সেভ হয়েছে!");
                    }
                    catch (Exception ex)
                    {
                        // ৪. সমস্যা হলে রোলব্যাক (Rollback)
                        // আগের SaveChanges() এর কাজও বাতিল হয়ে যাবে
                        transaction.Rollback();
                        Console.WriteLine($"Error: {ex.Message}");
                        Console.WriteLine("Rollback! ডাটাবেজে কোনো পরিবর্তন হয়নি।");
                    }
                }
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `simulateError = false` করে কোডটি রান করুন। দেখুন ডাটাবেজে ব্লগ এবং পোস্ট দুটোই সেভ হয়েছে।
২. `transaction.Rollback()` কল না করলেও `using` ব্লকের কারণে এক্সেপশন হলে অটোমেটিক রোলব্যাক হয় কি না যাচাই করুন (EF Core ডিফল্টভাবে ডিসপোজের সময় রোলব্যাক করে যদি কমিট না হয়ে থাকে)।

**🧠 কুইজ:**
১. `SaveChanges()` মেথড কি নিজে থেকে ট্রানজ্যাকশন ব্যবহার করে?
   A. না, ম্যানুয়ালি করতে হয়
   B. হ্যাঁ, প্রতিটি `SaveChanges` একটি ট্রানজ্যাকশন (উত্তর: B)
   C. শুধু SQL Server এ করে

২. ট্রানজ্যাকশনের মধ্যে এরর হলে আগের ডাটা আগের অবস্থায় ফিরিয়ে আনার কমান্ড কোনটি?
   A. Commit
   B. Delete
   C. Rollback (উত্তর: C)

৩. কখন ম্যানুয়াল ট্রানজ্যাকশন (`BeginTransaction`) দরকার হয়?
   A. একটি মাত্র ডাটা সেভ করতে
   B. একাধিক `SaveChanges` বা অপারেশনকে এক ইউনিটে বাঁধতে (উত্তর: B)
   C. ডাটা রিড করতে

**⚠️ খুব জরুরি নোট:** ট্রানজ্যাকশন চলাকালীন ডাটাবেজ টেবিল **লক (Lock)** হয়ে থাকতে পারে। তাই ট্রানজ্যাকশনের ভেতরে দীর্ঘ সময় লাগতে পারে এমন কাজ (যেমন: ইমেইল পাঠানো, ফাইল আপলোড) করবেন না। শুধু ডাটাবেজ অপারেশনগুলো দ্রুত শেষ করে কমিট করবেন।

### Lesson 36: ডাটা সিডিং (Data Seeding)

**👨‍🏫 কোড রান টিপ:** আমরা `OnModelCreating` মেথডে কোড লিখব এবং মাইগ্রেশন চালাব।

**🎉 ভূমিকা:**
**Data Seeding** হলো ডাটাবেজ তৈরির সময় কিছু প্রাথমিক ডাটা (Initial Data) ইনসার্ট করার প্রক্রিয়া।
যেমন:
- ডিফল্ট ইউজার: `Admin` (Password: `123456`)
- ড্রপডাউন লিস্ট: `Countries` (Bangladesh, India, USA)
- স্ট্যাটাস লিস্ট: `Pending`, `Approved`

**🎯 শেখার লক্ষ্য:**
১. `HasData` মেথড ব্যবহার করে সিডিং করা।
২. মাইগ্রেশনের মাধ্যমে ডাটা ইনসার্ট করা।
৩. কাস্টম ইনিশিয়ালাইজার মেথড তৈরি করা (বিকল্প উপায়)।

**📖 প্রধান বিষয়বস্তু:**
EF Core-এ সিডিং দুইভাবে করা যায়:
1. **Model Seeding (HasData):** এটি মাইগ্রেশনের অংশ। ডাটাবেজ তৈরির সময় ডাটা চলে যায়। এটি স্ট্যাটিক ডাটার জন্য সেরা (যেমন: দেশ, ক্যাটাগরি)।
2. **Custom Initialization:** `Program.cs` থেকে মেথড কল করে ডাটা চেক করে ইনসার্ট করা। এটি ডাইনামিক ডাটার জন্য ভালো।

**💻 কোড উদাহরণ (Model Seeding):**

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // আগের কনফিগারেশন...

    // --- Data Seeding ---
    // আমরা ৩টি ক্যাটাগরি সিড করব
    // নোট: সিডিং এর জন্য অবশ্যই প্রাইমারি কি (Id) দিতে হবে!
    modelBuilder.Entity<Category>().HasData(
        new Category { Id = 1, Name = "Electronics" },
        new Category { Id = 2, Name = "Books" },
        new Category { Id = 3, Name = "Clothing" }
    );
    
    // রিলেটেড ডাটা সিড করা (Product)
    modelBuilder.Entity<Product>().HasData(
        new Product { Id = 1, Name = "Samsung S24", Price = 90000, IsDeleted = false, CategoryId = 1 }, 
        new Product { Id = 2, Name = "C# Programming", Price = 500, IsDeleted = false, CategoryId = 2 }
    );
}
```
*(নোট: `Category` এবং `CategoryId` যদি আপনার মডেলে না থাকে তবে `Blog` এবং `Post` দিয়ে ট্রাই করুন)*

**মাইগ্রেশন কমান্ড:**
```bash
dotnet ef migrations add SeedInitialData
dotnet ef database update
```
*(মাইগ্রেশন ফাইলে দেখবেন `InsertData` কমান্ড জেনারেট হয়েছে)*

**💻 কোড উদাহরণ (Custom Initialization - ভালো প্র্যাকটিস):**

**ফাইল:** `src/Data/DbInitializer.cs` (নতুন ক্লাস)
```csharp
using System.Linq;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data
{
    public static class DbInitializer
    {
        public static void Seed(AppDbContext context)
        {
            // ১. ডাটাবেজ নিশ্চিত করা
            context.Database.EnsureCreated(); // অথবা Migrate()

            // ২. চেক করা ডাটা আছে কি না
            if (context.Blogs.Any())
            {
                return; // ডাটা আছে, তাই কিছু করার দরকার নেই
            }

            // ৩. নতুন ডাটা অ্যাড করা
            var blogs = new Blog[]
            {
                new Blog { Url = "http://seed-blog-1.com" },
                new Blog { Url = "http://seed-blog-2.com" }
            };

            context.Blogs.AddRange(blogs);
            context.SaveChanges();
        }
    }
}
```

### Lesson 37: জেনারেটেড ভ্যালু (Identity, Computed Columns)

**👨‍🏫 কোড রান টিপ:** `OnModelCreating` মেথডে কনফিগারেশন লিখব।

**🎉 ভূমিকা:**
EF Core-এ আমরা ডাটা সেভ করার সময় কিছু কলামের মান ডাটাবেজকে জেনারেট করতে দিতে পারি।
১. **Identity:** সাধারণত প্রাইমারি কি (১, ২, ৩...)।
২. **Default Value:** ডাটা না দিলে ডিফল্ট মান বসবে (যেমন: `CreatedDate = GETDATE()`)।
৩. **Computed Column:** দুটি কলামের যোগফল বা গুণফল (যেমন: `Total = Price * Quantity`)।

**🎯 শেখার লক্ষ্য:**
১. `ValueGeneratedOnAdd` এবং `ValueGeneratedOnAddOrUpdate` বোঝা।
২. SQL এর ডিফল্ট ভ্যালু (`HasDefaultValueSql`) ব্যবহার করা।
৩. কম্পিউটেড কলাম কনফিগার করা (`HasComputedColumnSql`)।

**📖 প্রধান বিষয়বস্তু:**
- **OnAdd:** শুধু ইনসার্টের সময় ভ্যালু জেনারেট হবে (যেমন: CreatedAt)।
- **OnAddOrUpdate:** ইনসার্ট এবং আপডেটের সময় জেনারেট হবে (যেমন: LastUpdated)।
- **Computed:** ডাটাবেজে এই কলামে কোনো ডাটা সেভ হয় না, রানটাইমে ক্যালকুলেট হয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/InvoiceItem.cs` (নতুন ক্লাস)
```csharp
using System;

namespace Lesson01_Intro.Models
{
    public class InvoiceItem
    {
        public int Id { get; set; }
        public string ItemName { get; set; }
        public decimal Price { get; set; }
        public int Quantity { get; set; }
        
        // এটি ডাটাবেজ ক্যালকুলেট করবে
        public decimal TotalAmount { get; private set; } 
        
        // এটি ডাটাবেজ অটোমেটিক বসাবে
        public DateTime CreatedAt { get; private set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
public DbSet<InvoiceItem> InvoiceItems { get; set; }

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<InvoiceItem>(entity =>
    {
        // ১. ডিফল্ট ভ্যালু (SQL Function ব্যবহার করে)
        entity.Property(e => e.CreatedAt)
              .HasDefaultValueSql("GETDATE()") // SQL Server এর ফাংশন
              .ValueGeneratedOnAdd();

        // ২. কম্পিউটেড কলাম (Price * Quantity)
        entity.Property(e => e.TotalAmount)
              .HasComputedColumnSql("[Price] * [Quantity]"); 
              // ডাটাবেজে এটি একটি ভার্চুয়াল কলাম হবে
    });
}
```

**মাইগ্রেশন:** `dotnet ef migrations add GeneratedColumns` -> `update`

```csharp
    };

    // সেভ করার পর EF Core অটোমেটিক জেনারেটেড ভ্যালুগুলো রিড করে আনবে

    Console.WriteLine($"Created At: {item.CreatedAt}"); // বর্তমান সময় দেখাবে
    Console.WriteLine($"Total Amount: {item.TotalAmount}"); // ২০০০ দেখাবে (১০০০ * ২)

```

১. `User` টেবিলে `DisplayName` নামে একটি কম্পিউটেড কলাম তৈরি করুন যা `FirstName + ' ' + LastName` জোড়া লাগাবে।
২. `LastUpdated` কলামের জন্য ট্রিগার বা `ValueGeneratedOnAddOrUpdate` কনফিগার করার চেষ্টা করুন (SQL Server এ এটি একটু জটিল, ট্রিগার লাগে)।

**🧠 কুইজ:**
১. `HasComputedColumnSql` দিয়ে তৈরি কলামে কি কোড থেকে ডাটা সেভ করা যায়?
   A. হ্যাঁ
   B. না, এটি ডাটাবেজ ক্যালকুলেট করে (উত্তর: B)

২. `HasDefaultValueSql("GETDATE()")` কোন অপারেশনের সময় কাজ করে?
   A. Update
   B. Insert (উত্তর: B)
   C. Delete

৩. কম্পিউটেড কলাম কি ইনডেক্স করা যায়?
   A. হ্যাঁ (যদি এটি Persisted হয়) (উত্তর: A)
   B. কখনোই না

**⚠️ খুব জরুরি নোট:** কম্পিউটেড কলামের লজিক ডাটাবেজ প্রোভাইডারের ওপর নির্ভরশীল (যেমন: SQL Server এ `GETDATE()`, কিন্তু PostgreSQL এ `NOW()`)। তাই ডাটাবেজ পাল্টালে এই লজিকগুলোও পাল্টাতে হবে।

### Lesson 38: কনকারেন্সি কনফ্লিক্ট হ্যান্ডলিং (Concurrency Tokens)

**👨‍🏫 কোড রান টিপ:** এই লেসনটি সিমুলেট করার জন্য দুটি আলাদা `DbContext` ইনস্ট্যান্স লাগবে।

**🎉 ভূমিকা:**

১. আবির স্টক দেখল ১০০।
২. বাবুও স্টক দেখল ১০০।
৩. আবির ১০টি বিক্রি করল, স্টক সেট করল ৯০। সেভ করল।
৪. বাবু ৫টি বিক্রি করল, সেও স্টক ৯০ সেট করল (কারণ সে ১০০ দেখেছিল)। সেভ করল।
ফলাফল: মোট ১৫টি বিক্রি হলো, কিন্তু স্টক দেখাচ্ছে ৯০! হওয়ার কথা ছিল ৮৫। একে বলে **Lost Update** বা **Concurrency Conflict**।

EF Core-এ এর সমাধান হলো **Concurrency Token** (বা RowVersion)।

**🎯 শেখার লক্ষ্য:**
১. Optimistic Concurrency কী তা বোঝা।
২. `RowVersion` বা `Timestamp` কলাম যোগ করা।
৩. `DbUpdateConcurrencyException` হ্যান্ডেল করা।

**📖 প্রধান বিষয়বস্তু:**
আমরা টেবিলে একটি বিশেষ কলাম রাখব (যেমন: `byte[] RowVersion`)। যখনই কেউ রো আপডেট করবে, ডাটাবেজ অটোমেটিক এই ভার্সন চেঞ্জ করে দেবে।
সেভ করার সময় EF Core চেক করবে: "আমি যেই ভার্সন নিয়েছিলাম, ডাটাবেজে কি এখনো সেটাই আছে?"
- যদি মিলে যায় -> আপডেট হবে।
- যদি না মিলে (মানে অন্য কেউ চেঞ্জ করেছে) -> `DbUpdateConcurrencyException` থ্রো করবে।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Models/InventoryItem.cs`
```csharp
using System.ComponentModel.DataAnnotations;

namespace Lesson01_Intro.Models
{
    public class InventoryItem
    {
        public int Id { get; set; }
        public string Name { get; set; }
        public int Stock { get; set; }

        // কনকারেন্সি টোকেন
        [Timestamp] // এটি SQL Server এ rowversion কলাম তৈরি করবে
        public byte[] Version { get; set; }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
public DbSet<InventoryItem> InventoryItems { get; set; }
// কনফিগারেশন: [Timestamp] অ্যাট্রিবিউট ব্যবহার করায় Fluent API না লিখলেও চলবে
```

**মাইগ্রেশন:** `dotnet ef migrations add AddedConcurrencyToken` -> `update`

**ব্যবহার (Program.cs):**
```csharp
using (var context = new AppDbContext())
{
    // ১. টেস্ট ডাটা তৈরি
    if (!context.InventoryItems.Any())
    {
        context.InventoryItems.Add(new InventoryItem { Name = "Laptop", Stock = 100 });
        context.SaveChanges();
    }
}

// ২. কনফ্লিক্ট সিমুলেশন
Console.WriteLine("--- Concurrency Test ---");

// ইউজার ১ ডাটা লোড করল
using var context1 = new AppDbContext();
var item1 = context1.InventoryItems.First(); // Stock = 100, Version = v1

// ইউজার ২ ডাটা লোড করল (একই সময়ে)
using var context2 = new AppDbContext();
var item2 = context2.InventoryItems.First(); // Stock = 100, Version = v1

// ইউজার ১ আপডেট করল
item1.Stock -= 10; // 90
context1.SaveChanges(); 
Console.WriteLine("User 1 Updated Stock to 90. (Version changed in DB)");

// ইউজার ২ আপডেট করার চেষ্টা করছে
item2.Stock -= 5; // 95 (সে জানে ১০০ আছে)
try
{
    // এখানে এরর খাবে, কারণ item2.Version (v1) != DB Version (v2)
    context2.SaveChanges(); 
    Console.WriteLine("User 2 Success!");
}
catch (DbUpdateConcurrencyException ex)
{
    Console.WriteLine("🚨 User 2 Failed! Someone else updated the record.");
    
    // হ্যান্ডলিং (অপশনাল): নতুন ডাটা রিড করে আবার ট্রাই করা
    var entry = ex.Entries.Single();
    var dbValues = entry.GetDatabaseValues();
    Console.WriteLine($"Current DB Value: {dbValues["Stock"]}");
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `[ConcurrencyCheck]` অ্যাট্রিবিউটটি সাধারণ কোনো ফিল্ডে (যেমন `Name`) লাগিয়ে দেখুন। তাহলে শুধু নাম চেঞ্জ হলেই কনফ্লিক্ট চেক হবে।
২. ক্যাচ ব্লকের ভেতরে `entry.Reload()` ব্যবহার করে লেটেস্ট ডাটা এনে পুনরায় ক্যালকুলেশন করে সেভ করার লজিক লিখুন (একে বলে "Client Wins" বা "Merge" স্ট্র্যাটেজি)।
