### Lesson 39: রিভার্স ইঞ্জিনিয়ারিং (Scaffolding Existing DB)

**👨‍🏫 কোড রান টিপ:** এই লেসনের জন্য আপনার একটি বিদ্যমান ডাটাবেজ থাকা দরকার। আমরা আমাদের তৈরি করা `EfCoreCourseDb` কেই রিভার্স ইঞ্জিনিয়ার করব। একটি **নতুন ফোল্ডারে** নতুন কনসোল অ্যাপ খুলুন।

**🎉 ভূমিকা:**
হাতে ধরে ১০০টি টেবিলের জন্য ১০০টি ক্লাস লেখা বোকামি। EF Core-এর `Scaffold-DbContext` কমান্ড এক নিমেষেই আপনার পুরো ডাটাবেজ রিড করে হুবহু ক্লাস স্ট্রাকচার বানিয়ে দেয়।

**🎯 শেখার লক্ষ্য:**
১. `dotnet ef dbcontext scaffold` কমান্ড ব্যবহার করা।
২. আউটপুট ফোল্ডার ও নেমস্পেস ঠিক করা।
৩. কানেকশন স্ট্রিং নিরাপদে রাখা।

**📖 প্রধান বিষয়বস্তু:**
কমান্ড প্যাটার্ন:
`dotnet ef dbcontext scaffold "Connection String" Provider --output-dir Models`

আমরা এখানে **EF Core Tools** ব্যবহার করব।

**💻 টিউটোরিয়াল ও কমান্ড:**

১. **নতুন প্রোজেক্ট তৈরি:**
```bash
mkdir EfCoreDbFirst
cd EfCoreDbFirst
dotnet new console
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Tools
dotnet add package Microsoft.EntityFrameworkCore.Design
```

২. **স্ক্যাফোল্ডিং কমান্ড (জাদু!):**
*(টার্মিনালে এই এক লাইনের কমান্ডটি দিন)*
```bash
dotnet ef dbcontext scaffold "Server=(localdb)\mssqllocaldb;Database=EfCoreCourseDb;Trusted_Connection=True;TrustServerCertificate=True" Microsoft.EntityFrameworkCore.SqlServer --output-dir Models --context-dir Data --context AppDbContext --force
```

**কমান্ড ব্যাখ্যা:**
- `"Connection String"`: কোন ডাটাবেজ রিড করবে।
- `Microsoft...SqlServer`: ডাটাবেজ প্রোভাইডার।
- `--output-dir Models`: এনটিটি ক্লাসগুলো `Models` ফোল্ডারে যাবে।
- `--context-dir Data`: DbContext ফাইলটি `Data` ফোল্ডারে যাবে।
- `--context AppDbContext`: কনটেক্সট ক্লাসের নাম হবে `AppDbContext`।
- `--force`: যদি ফাইল আগে থেকে থাকে, তবে ওভাররাইট করবে।

**ফলাফল:**
আপনার প্রজেক্টে দেখবেন অটোমেটিক `Models/Product.cs`, `Models/Blog.cs` ইত্যাদি তৈরি হয়ে গেছে এবং `Data/AppDbContext.cs`-এ সব কনফিগারেশন (`OnModelCreating`) চলে এসেছে।

**💻 কোড উদাহরণ (জেনারেটেড কোড ব্যবহার):**

**ফাইল:** `Program.cs`
```csharp
using System;
using System.Linq;
using EfCoreDbFirst.Data; // জেনারেটেড নেমস্পেস
using EfCoreDbFirst.Models;

namespace EfCoreDbFirst
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("--- Database First Approach ---");

            // স্ক্যাফোল্ডেড কনটেক্সট ব্যবহার করছি
            using (var context = new AppDbContext())
            {
                // ডাটা রিড করা
                var products = context.Products.Take(5).ToList();
                
                Console.WriteLine($"Found {products.Count} products from existing DB.");
                foreach (var p in products)
                {
                    Console.WriteLine($"- {p.Name} ({p.Price})");
                }
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `--table Products --table Blogs` অপশন ব্যবহার করে কমান্ডটি আবার রান করুন। দেখুন এবার শুধু এই দুটি টেবিলের জন্য ক্লাস তৈরি হয়।
২. `--data-annotations` ফ্ল্যাগ যোগ করে কমান্ড চালান। দেখুন Fluent API এর বদলে ক্লাসগুলোর মাথায় `[Table]`, `[Key]` অ্যাট্রিবিউট চলে এসেছে।

**🧠 কুইজ:**
১. বিদ্যমান ডাটাবেজ থেকে কোড জেনারেট করার প্রক্রিয়াকে কী বলে?
   A. Code First
   B. Reverse Engineering / Scaffolding (উত্তর: B)
   C. Migration

২. ডাটাবেজে নতুন কলাম যোগ করলে Scaffolding প্রজেক্টে কী করতে হয়?
   A. অটোমেটিক আপডেট হয়ে যায়
   B. আবার Scaffold কমান্ড চালাতে হয় (বা ম্যানুয়ালি কোড আপডেট করতে হয়) (উত্তর: B)
   C. মাইগ্রেশন অ্যাড করতে হয়

৩. Scaffold কমান্ডে `--force` ফ্ল্যাগের কাজ কী?
   A. জোর করে ডাটাবেজ ডিলিট করা
   B. বিদ্যমান ফাইল ওভাররাইট করা (উত্তর: B)
   C. ডাটাবেজ কানেকশন ফোর্স করা

**⚠️ খুব জরুরি নোট:** Database First অ্যাপ্রোচে জেনারেটেড ফাইলগুলো (`Product.cs`) ম্যানুয়ালি এডিট করবেন না। কারণ ডাটাবেজ আপডেট হলে আবার স্ক্যাফোল্ড চালালে আপনার কোড মুছে যাবে। কাস্টম লজিক যোগ করতে `partial class` ব্যবহার করুন।

### Lesson 40: মাল্টিপল DbContext এবং মাইগ্রেশন ম্যানেজমেন্ট

**👨‍🏫 কোড রান টিপ:** আমরা একই প্রজেক্টে দুটি আলাদা কনটেক্সট তৈরি করব।

**🎉 ভূমিকা:**
ধরুন, আপনার অ্যাপে দুটি আলাদা মডিউল:
১. **AuthModule:** ইউজার লগইন, রোল ম্যানেজমেন্ট (Identity)।
২. **StoreModule:** প্রোডাক্ট, অর্ডার ম্যানেজমেন্ট।
আপনি চান না প্রোডাক্ট টেবিলের সাথে ইউজার টেবিলের জগাখিচুড়ি হোক। তাই আমরা দুটি আলাদা `DbContext` ব্যবহার করব, এমনকি তারা আলাদা ডাটাবেজেও পয়েন্ট করতে পারে!

**🎯 শেখার লক্ষ্য:**
১. একাধিক DbContext কনফিগার করা।
২. আলাদা আলাদা মাইগ্রেশন ফোল্ডার তৈরি করা।
৩. কমান্ড লাইনে কনটেক্সট সিলেক্ট করা।

**📖 প্রধান বিষয়বস্তু:**
যখন একাধিক কনটেক্সট থাকে, তখন মাইগ্রেশন কমান্ড চালানোর সময় EF Core কনফিউজড হয়ে যায়—"ভাই, কোন কনটেক্সটের জন্য মাইগ্রেশন বানাবো?"
তখন `--context` এবং `--output-dir` ফ্ল্যাগ ব্যবহার করে পথ দেখিয়ে দিতে হয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AuthDbContext.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models; // User মডেল এখানে থাকবে

namespace Lesson01_Intro.Data
{
    public class AuthDbContext : DbContext
    {
        public DbSet<SystemUser> Users { get; set; }

        protected override void OnConfiguring(DbContextOptionsBuilder options)
            => options.UseSqlServer(@"Server=(localdb)\mssqllocaldb;Database=AuthDb;...");
    }
}
```

**ফাইল:** `src/Data/StoreDbContext.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Models; // Product মডেল এখানে

namespace Lesson01_Intro.Data
{
    public class StoreDbContext : DbContext
    {
        public DbSet<Product> Products { get; set; }

        protected override void OnConfiguring(DbContextOptionsBuilder options)
            => options.UseSqlServer(@"Server=(localdb)\mssqllocaldb;Database=StoreDb;...");
    }
}
```

**মাইগ্রেশন কমান্ড (গুরুত্বপূর্ণ):**

১. **AuthDbContext এর জন্য মাইগ্রেশন:**
```bash
dotnet ef migrations add InitialAuth --context AuthDbContext --output-dir Migrations/Auth
dotnet ef database update --context AuthDbContext
```

২. **StoreDbContext এর জন্য মাইগ্রেশন:**
```bash
dotnet ef migrations add InitialStore --context StoreDbContext --output-dir Migrations/Store
dotnet ef database update --context StoreDbContext
```

**ফাইল:** `src/Program.cs`
```csharp
using (var authContext = new AuthDbContext())
{
    authContext.Users.Add(new SystemUser { Username = "Admin" });
    authContext.SaveChanges();
    Console.WriteLine("User Saved in AuthDb");
}

using (var storeContext = new StoreDbContext())
{
    storeContext.Products.Add(new Product { Name = "Pen", Price = 10 });
    storeContext.SaveChanges();
    Console.WriteLine("Product Saved in StoreDb");
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `AuthDbContext` এবং `StoreDbContext` উভয়কেই একই ডাটাবেজ (`SingleDb`) পয়েন্ট করুন। কিন্তু টেবিলের নাম প্রিফিক্স (Prefix) দিন (যেমন: `Auth_Users`, `Store_Products`)। দেখুন একই ডাটাবেজে দুটি কনটেক্সট কাজ করে কি না (হ্যাঁ করবে, কিন্তু `__EFMigrationsHistory` টেবিল নিয়ে কনফ্লিক্ট হতে পারে, তাই আলাদা করাই ভালো)।
২. একটি কনটেক্সট থেকে মাইগ্রেশন রিমুভ করার কমান্ড কী হবে? (`dotnet ef migrations remove --context AuthDbContext`)।

**🧠 কুইজ:**
১. একাধিক DbContext থাকলে মাইগ্রেশন কমান্ডে কোনটি বাধ্যতামূলক?
   A. --force
   B. --context `<ContextName> (উত্তর: B)
   C. --verbose

২. আলাদা আলাদা কনটেক্সটের মাইগ্রেশন ফাইলগুলো কি একই ফোল্ডারে রাখা উচিত?
   A. হ্যাঁ, সমস্যা নেই
   B. না, আলাদা ফোল্ডারে রাখা ভালো (Clean Architecture) (উত্তর: B)

৩. একই অ্যাপে কি একটি কনটেক্সট SQL Server এ এবং আরেকটি PostgreSQL এ কানেক্ট করা সম্ভব?
   A. হ্যাঁ, অবশ্যই (উত্তর: A)
   B. না

**⚠️ খুব জরুরি নোট:** একাধিক কনটেক্সট থাকলে **Dependency Injection** (ASP.NET Core) সেটআপ করার সময় সাবধান থাকতে হবে। `AddDbContext<AuthDbContext>(...)` এবং `AddDbContext<StoreDbContext>(...)` আলাদাভাবে কল করতে হবে।

### Lesson 41: SQL স্ক্রিপ্ট জেনারেশন (Script-Migration)

**👨‍🏫 কোড রান টিপ:** আমরা টার্মিনালে কাজ করব।

**🎉 ভূমিকা:**
`Script-Migration` কমান্ডটি আপনার মাইগ্রেশন ফাইলগুলো পড়ে একটি বিশাল SQL ফাইল তৈরি করে। এই ফাইলে টেবিল তৈরির `CREATE`, কলাম যোগ করার `ALTER` এবং মাইগ্রেশন হিস্ট্রি আপডেটের `INSERT` কমান্ড থাকে।
সবচেয়ে মজার বিষয় হলো, এটি **Idempotent** স্ক্রিপ্ট তৈরি করতে পারে—অর্থাৎ, এই স্ক্রিপ্ট যতবার খুশি রান করুন, এটি চেক করে নেবে মাইগ্রেশনটি আগে অ্যাপ্লাই করা আছে কি না।

**🎯 শেখার লক্ষ্য:**
১. `script-migration` কমান্ড ব্যবহার করা।
২. নির্দিষ্ট রেঞ্জ (From...To) এর স্ক্রিপ্ট তৈরি করা।
৩. Idempotent স্ক্রিপ্ট জেনারেশন।

**📖 প্রধান বিষয়বস্তু:**
কমান্ড সিনট্যাক্স:
`dotnet ef migrations script [FromMigration] [ToMigration] [Options]`

**💻 কমান্ড লাইন টিউটোরিয়াল:**

১. **সব মাইগ্রেশনের স্ক্রিপ্ট তৈরি (শুরু থেকে শেষ পর্যন্ত):**
```bash
dotnet ef migrations script --output full_script.sql
```
*ব্যাখ্যা:* এটি `full_script.sql` নামে একটি ফাইল তৈরি করবে যাতে ডাটাবেজ তৈরির পুরো ইতিহাস থাকবে।

২. **Idempotent স্ক্রিপ্ট (বেস্ট প্র্যাকটিস):**
```bash
dotnet ef migrations script --idempotent --output smart_script.sql
```
*ব্যাখ্যা:* এটি প্রতিটি ব্লকের আগে চেক করবে:
`IF NOT EXISTS(SELECT * FROM __EFMigrationsHistory WHERE MigrationId = '...')`
তাহলে শুধু দরকারি অংশটুকুই রান হবে। প্রোডাকশনের জন্য এটি নিরাপদ।

৩. **নির্দিষ্ট আপডেট স্ক্রিপ্ট (From Migration X to Y):**
ধরুন, আপনি লাস্ট রিলিজে `InitialCreate` দিয়েছেন। এখন শুধু নতুন চেঞ্জগুলো (`AddProductTable`) দিতে চান।
```bash
dotnet ef migrations script InitialCreate --output update_script.sql
```
*ব্যাখ্যা:* `InitialCreate` এর **পর** থেকে যা যা হয়েছে, শুধু সেগুলোর স্ক্রিপ্ট তৈরি হবে।

**💻 কোড উদাহরণ (SQL ফাইল ভিউ):**

জেনারেটেড `smart_script.sql` ফাইলটি ওপেন করলে অনেকটা এমন দেখাবে:

```sql
IF OBJECT_ID(N'[__EFMigrationsHistory]') IS NULL
BEGIN
    CREATE TABLE [__EFMigrationsHistory] (
        [MigrationId] nvarchar(150) NOT NULL,
        [ProductVersion] nvarchar(32) NOT NULL,
        CONSTRAINT [PK___EFMigrationsHistory] PRIMARY KEY ([MigrationId])
    );
END;
GO

BEGIN TRANSACTION;
GO

IF NOT EXISTS(SELECT * FROM [__EFMigrationsHistory] WHERE [MigrationId] = N'20231025_InitialCreate')
BEGIN
    CREATE TABLE [Blogs] (
        [Id] int NOT NULL IDENTITY,
        [Url] nvarchar(max) NOT NULL,
        CONSTRAINT [PK_Blogs] PRIMARY KEY ([Id])
    );
END;
GO

IF NOT EXISTS(SELECT * FROM [__EFMigrationsHistory] WHERE [MigrationId] = N'20231025_InitialCreate')
BEGIN
    INSERT INTO [__EFMigrationsHistory] ([MigrationId], [ProductVersion])
    VALUES (N'20231025_InitialCreate', N'7.0.0');
END;
GO

COMMIT;
GO
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. আপনার প্রজেক্টে একটি নতুন মাইগ্রেশন অ্যাড করুন (যেমন: `AddRatingToBlog`)। এরপর `dotnet ef migrations script` চালিয়ে দেখুন নতুন কলাম যোগ করার `ALTER TABLE` কুয়েরি জেনারেট হয়েছে কি না।
২. Idempotent স্ক্রিপ্টটি আপনার লোকাল ডাটাবেজে (যেখানে অলরেডি মাইগ্রেশন দেওয়া আছে) রান করার চেষ্টা করুন (SSMS দিয়ে)। দেখবেন কোনো এরর ছাড়াই রান হবে কিন্তু কোনো চেঞ্জ হবে না (কারণ চেক লজিক আছে)।

**🧠 কুইজ:**
১. Idempotent স্ক্রিপ্ট এর সুবিধা কী?
   A. এটি ফাস্ট রান করে
   B. এটি যেকোনো ডাটাবেজে রান করা যায় এবং ডুপ্লিকেট মাইগ্রেশন আটকায় (উত্তর: B)
   C. এটি অটোমেটিক ব্যাকআপ নেয়

২. `script` কমান্ডে যদি `FromMigration` আর্গুমেন্ট না দেওয়া হয়, তবে কোথা থেকে স্ক্রিপ্ট জেনারেট হয়?
   A. শেষ মাইগ্রেশন থেকে
   B. একদম শুরু (শূন্য) থেকে (উত্তর: B)
   C. র্যান্ডমলি

৩. প্রোডাকশন ডেপ্লয়মেন্টের জন্য কোনটি ভালো?
   A. `dotnet ef database update` সার্ভারে চালানো
   B. জেনারেটেড SQL স্ক্রিপ্ট DBA কে দেওয়া বা CI/CD পাইপলাইনে রান করা (উত্তর: B)

**⚠️ খুব জরুরি নোট:** কখনো কখনো মাইগ্রেশনে কাস্টম C# কোড থাকে (যেমন ডেটা প্রসেসিং), যা SQL স্ক্রিপ্টে কনভার্ট করা সম্ভব নয়। তাই মাইগ্রেশনে জটিল C# লজিক না লিখে SQL বা `ExecuteSql` ব্যবহার করাই নিরাপদ।

### Lesson 42: Logging এবং Diagnostics

**👨‍🏫 কোড রান টিপ:** `AppDbContext`-এর `OnConfiguring` মেথডে আমরা লগিং সেটআপ করব।

**🎉 ভূমিকা:**
EF Core ডিফল্টভাবে চুপচাপ কাজ করে। কিন্তু আপনি চাইলে তাকে "বাচাল" বানাতে পারেন। সে কনসোলে প্রিন্ট করে দেবে:
- কোন SQL কুয়েরি রান হলো।
- প্যারামিটারগুলোর ভ্যালু কী ছিল।
- কুয়েরি রান করতে কত মিলিসেকেন্ড সময় লাগল।

**🎯 শেখার লক্ষ্য:**
১. `LogTo` মেথড ব্যবহার করে সিম্পল লগিং।
২. সেনসিটিভ ডাটা (পাসওয়ার্ড, প্যারামিটার) লগ করা (`EnableSensitiveDataLogging`)।
৩. ডিটেইলড এরর দেখা (`EnableDetailedErrors`)।

**📖 প্রধান বিষয়বস্তু:**
- **LogTo:** কোথায় লগ দেখাবেন (Console, File, Debug Window)।
- **Sensitive Data:** ডিফল্টভাবে EF Core প্যারামিটার ভ্যালু (`?`) দেখায়। ডিবাগিংয়ের সময় আসল ভ্যালু দেখতে চাইলে এটি অন করতে হয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
using System;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Logging; // LogLevel এর জন্য

namespace Lesson01_Intro.Data
{
    public class AppDbContext : DbContext
    {
        // ... DbSets

        protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
        {
            optionsBuilder
                .UseSqlServer(@"Server=(localdb)\mssqllocaldb;Database=EfCoreCourseDb;Trusted_Connection=True;TrustServerCertificate=True")
                
                // ১. লগিং কনফিগারেশন
                // Console.WriteLine মানে কনসোলে লগ দেখাও
                // LogLevel.Information মানে সাধারণ ইনফো এবং কুয়েরি দেখাও
                .LogTo(Console.WriteLine, LogLevel.Information)

                // ২. সেনসিটিভ ডাটা লগিং (সতর্কতা: প্রোডাকশনে এটি ব্যবহার করবেন না!)
                // এটি কুয়েরির প্যারামিটার ভ্যালু দেখাবে (যেমন: WHERE Id = 5)
                .EnableSensitiveDataLogging()

                // ৩. ডিটেইলড এরর
                // কোন প্রপার্টি বা এনটিটির জন্য এরর হচ্ছে তা বিস্তারিত বলবে
                .EnableDetailedErrors();
        }
    }
}
```

**ফাইল:** `src/Program.cs` (লগ টেস্ট করার জন্য)
```csharp
using (var context = new AppDbContext())
{
    Console.WriteLine("--- Logging Demo ---");

    // একটি কুয়েরি চালাই
    var name = "Laptop";
    var product = context.Products
                         .Where(p => p.Name == name)
                         .FirstOrDefault();

    // কনসোল আউটপুট লক্ষ্য করুন:
    // info: Microsoft.EntityFrameworkCore.Database.Command[20101]
    //       Executed DbCommand (4ms) [Parameters=[@__name_0='Laptop'], CommandType='Text', CommandTimeout='30']
    //       SELECT TOP(1) [p].[Id], [p].[Name], ... FROM [Products] AS [p] WHERE [p].[Name] = @__name_0
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `LogLevel.Warning` দিয়ে রান করে দেখুন। তখন সাধারণ `SELECT` কুয়েরি আর লগ হবে না, শুধু ওয়ার্নিং বা এরর লগ হবে।
২. `LogTo` মেথডে একটি ল্যাম্বডা ফাংশন দিয়ে ফাইল রাইটার ব্যবহার করুন, যাতে লগগুলো টেক্সট ফাইলে সেভ হয় (`msg => File.AppendAllText("log.txt", msg)`).

**🧠 কুইজ:**
১. `EnableSensitiveDataLogging` প্রোডাকশন এনভায়রনমেন্টে কেন বিপজ্জনক?
   A. এটি পারফরম্যান্স কমিয়ে দেয়
   B. এটি ব্যবহারকারীর গোপন তথ্য (যেমন পাসওয়ার্ড, ক্রেডিট কার্ড নম্বর) লগে লিখে দিতে পারে (উত্তর: B)
   C. এটি ডাটাবেজ ডিলিট করে দেয়

২. `LogTo(Console.WriteLine)` এর কাজ কী?
   A. ডাটাবেজে লগ সেভ করা
   B. অ্যাপ্লিকেশনের কনসোলে (টার্মিনালে) EF Core এর কার্যক্রম প্রিন্ট করা (উত্তর: B)
   C. উইন্ডোজ ইভেন্ট লগে লেখা

৩. `EnableDetailedErrors` কী সুবিধা দেয়?
   A. এরর অটোমেটিক ফিক্স করে
   B. স্ট্যাক ট্রেস এবং নির্দিষ্ট এনটিটির তথ্যসহ বিস্তারিত এরর মেসেজ দেয় (উত্তর: B)
   C. ডাটাবেজ কানেকশন চেক করে

**⚠️ খুব জরুরি নোট:** `LogTo` এবং `EnableSensitiveDataLogging` পারফরম্যান্সের ওপর প্রভাব ফেলে। তাই ডেভেলপমেন্টে এটি ব্যবহার করুন, কিন্তু প্রোডাকশনে লগ লেভেল কমিয়ে (`Warning` বা `Error`) রাখুন এবং সেনসিটিভ লগিং বন্ধ রাখুন।
