### Lesson 43: EF Core বেস্ট প্র্যাকটিস ও টিপস

**👨‍🏫 কোড রান টিপ:** এটি থিওরিটিক্যাল এবং কোড স্নিপেট ভিত্তিক লেসন।

**🎉 ভূমিকা:**
EF Core একটি শক্তিশালী হাতিয়ার, কিন্তু ভুলভাবে ব্যবহার করলে এটি আপনার অ্যাপকে কচ্ছপের মতো স্লো করে দিতে পারে। এই লেসনে আমরা সেই "Do's and Don'ts" শিখব যা আপনার ইন্টারভিউ এবং প্রজেক্টে জীবন বাঁচাবে।

**🎯 শেখার লক্ষ্য:**
১. পারফরম্যান্স টিপস (AsNoTracking, Pagination)।
২. সিকিউরিটি টিপস (SQL Injection)।
৩. আর্কিটেকচার টিপস (DbContext Lifetime)।

**📖 প্রধান বিষয়বস্তু:**

**১. DbContext এর আয়ুষ্কাল (Lifetime):**
- ওয়েব অ্যাপে (ASP.NET Core) `DbContext` সবসময় **Scoped** হওয়া উচিত। অর্থাৎ, একটি রিকোয়েস্টের জন্য একটি কনটেক্সট।
- কখনোই `static DbContext` বানাবেন না! এটি থ্রেড সেফ নয় এবং মেমোরি লিক ঘটাবে।
- `using` ব্লক ব্যবহার করুন (কনসোল অ্যাপে) যাতে কাজ শেষে ডিসপোজ হয়।

**২. N+1 সমস্যা এড়ানো:**
- **ভুল:** লুপের ভেতর রিলেটেড ডাটা এক্সেস করা।
- **সঠিক:** `Include` দিয়ে আগে লোড করা (Eager Loading)।

**৩. বড় ডাটা লোড না করা:**
- কখনোই `ToList()` দিয়ে ১০,০০০ ডাটা আনবেন না।
- **সঠিক:** পেজিনেশন ব্যবহার করুন (`Skip(10).Take(10)`) অথবা ফিল্টার করুন।

**৪. রিড-অনলি কুয়েরি:**
- শুধু ডাটা দেখানোর জন্য সবসময় `.AsNoTracking()` ব্যবহার করুন। এটি অনেক ফাস্ট।

**৫. কনফিগারেশন আলাদা ফাইলে রাখা:**
- `OnModelCreating` মেথড পরিষ্কার রাখতে `IEntityTypeConfiguration<T>` ব্যবহার করুন।

**💻 কোড উদাহরণ (Configuration Separation):**

**ফাইল:** `src/Data/Config/ProductConfiguration.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;
using Lesson01_Intro.Models;

namespace Lesson01_Intro.Data.Config
{
    // কনফিগারেশন আলাদা ক্লাসে সরিয়ে নেওয়া
    public class ProductConfiguration : IEntityTypeConfiguration<Product>
    {
        public void Configure(EntityTypeBuilder<Product> builder)
        {
            builder.HasKey(p => p.Id);
            builder.Property(p => p.Name).IsRequired().HasMaxLength(200);
            builder.HasIndex(p => p.Name); // ইনডেক্সিং পারফরম্যান্স বাড়ায়
        }
    }
}
```

**ফাইল:** `src/Data/AppDbContext.cs`
```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // এক লাইনে সব কনফিগারেশন অ্যাপ্লাই করা
    modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. আপনার আগের প্রজেক্টের `OnModelCreating` থেকে সব কনফিগারেশন সরিয়ে আলাদা আলাদা ফাইলে (`UserConfiguration`, `BlogConfiguration`) নিয়ে যান এবং `ApplyConfigurationsFromAssembly` ব্যবহার করে রান করুন।
২. একটি লুপের ভেতর ডাটাবেজ কুয়েরি লিখে (N+1) রান টাইম চেক করুন, তারপর সেটাকে `Include` দিয়ে ফিক্স করে রান টাইম চেক করুন। পার্থক্যটা দেখুন।

**🧠 কুইজ:**
১. `DbContext` ওয়েব অ্যাপ্লিকেশনে সাধারণত কোন লাইফটাইমে রেজিস্টার করা হয়?
   A. Singleton
   B. Scoped (Request level) (উত্তর: B)
   C. Transient

২. `modelBuilder.ApplyConfigurationsFromAssembly(...)` এর সুবিধা কী?
   A. এটি কুয়েরি ফাস্ট করে
   B. এটি অটোমেটিক সব কনফিগারেশন ক্লাস খুঁজে অ্যাপ্লাই করে, কোড ক্লিন রাখে (উত্তর: B)
   C. এটি মাইগ্রেশন বন্ধ করে দেয়

৩. ১০ লক্ষ ডাটা থেকে পেজ ১-এর ১০টি ডাটা আনার সঠিক কুয়েরি কোনটি?
   A. ToList().Take(10)
   B. Skip(0).Take(10).ToList() (উত্তর: B)
   C. Find(10)

**⚠️ খুব জরুরি নোট:** কখনো ক্লায়েন্ট সাইড ইভালুয়েশন হতে দেবেন না। যেমন: `Where(p => SomeCsharpMethod(p.Name))`। এটি ডাটাবেজে কনভার্ট হতে পারে না, ফলে *সব* ডাটা মেমোরিতে এনে ফিল্টার হয় (EF Core 3.0+ এ এটি এরর দেয়, কিন্তু সাবধান থাকা ভালো)।

খুব হাই-ট্রাফিক অ্যাপে (যেমন: প্রতি সেকেন্ডে হাজার হাজার রিকোয়েস্ট), এই অনুবাদের সময়টুকু বাঁচানোও জরুরি। সেখানেই আসে **Compiled Queries**।

### Lesson 44: কম্পাইল্ড কুয়েরি (Compiled Queries)

**👨‍🏫 কোড রান টিপ:** `Program.cs` ফাইলে কোড লিখুন।

**🎉 ভূমিকা:**
ভাবুন, আপনি একজন দোভাষী। কেউ আপনাকে বারবার একই বাংলা বাক্য বলছে, আর আপনি বারবার সেটা ইংরেজিতে অনুবাদ করছেন। বিরক্তিকর, তাই না?
যদি আপনি একবার অনুবাদ করে কাগজে লিখে রাখেন, পরের বার শুধু কাগজটা পড়ে দেবেন—অনেক দ্রুত হবে!
**Compiled Query** ঠিক এটাই করে। LINQ থেকে SQL অনুবাদের রেজাল্ট মেমোরিতে ক্যাশ (Cache) করে রাখে।

**🎯 শেখার লক্ষ্য:**
১. `EF.CompileQuery` (Sync) এবং `EF.CompileAsyncQuery` (Async) ব্যবহার করা।
২. সাধারণ কুয়েরি বনাম কম্পাইল্ড কুয়েরির পার্থক্য বোঝা।
৩. কখন এটি ব্যবহার করবেন আর কখন করবেন না।

**📖 প্রধান বিষয়বস্তু:**
এটি একটি `static` ফিল্ডে সংরক্ষণ করতে হয়। এটি মূলত একটি ডেলিগেট (Delegate) যা `DbContext` এবং প্যারামিটার নেয়।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Program.cs`
```csharp
using System;
using System.Linq;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Data;
using Lesson01_Intro.Models;

namespace Lesson01_Intro
{
    class Program
    {
        // ১. কম্পাইল্ড কুয়েরি ডিফাইন করা (Static Field হিসেবে)
        // এটি ইনপুট হিসেবে (DbContext, int) নেয় এবং আউটপুট হিসেবে Product দেয়
        private static readonly Func<AppDbContext, int, Task<Product>> _getProductById =
            EF.CompileAsyncQuery((AppDbContext context, int id) =>
                context.Products
                       .AsNoTracking() // অপটিমাইজেশন
                       .FirstOrDefault(p => p.Id == id));

        // আরেকটি উদাহরণ: প্রাইসের ওপর ভিত্তি করে লিস্ট আনা
        private static readonly Func<AppDbContext, decimal, IAsyncEnumerable<Product>> _getProductsByPrice =
            EF.CompileAsyncQuery((AppDbContext context, decimal minPrice) =>
                context.Products.Where(p => p.Price > minPrice));

        static async Task Main(string[] args)
        {
            Console.WriteLine("--- Compiled Query Performance ---");

            using (var context = new AppDbContext())
            {
                // ওয়ার্মআপ (প্রথমবার রান হতে একটু সময় নেয়)
                await _getProductById(context, 1);

                // ২. ব্যবহার করা (সুপার ফাস্ট)
                var product = await _getProductById(context, 1);
                
                if (product != null)
                {
                    Console.WriteLine($"Found: {product.Name}");
                }
                else
                {
                    Console.WriteLine("Product not found.");
                }

                // লিস্ট ফেচ করা
                await foreach (var p in _getProductsByPrice(context, 500))
                {
                    Console.WriteLine($"Expensive Item: {p.Name} - {p.Price}");
                }
            }
        }
    }
}
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `Stopwatch` ব্যবহার করে সাধারণ কুয়েরি এবং কম্পাইল্ড কুয়েরি ১০,০০০ বার লুপে চালিয়ে সময়ের পার্থক্য মাপুন। (ছোট ডাটাবেজে পার্থক্য কম হতে পারে, কিন্তু জটিল কুয়েরিতে বেশি হবে)।
২. একটি কম্পাইল্ড কুয়েরি লিখুন যা একটি নির্দিষ্ট ক্যাটাগরির নাম দিয়ে প্রোডাক্ট কাউন্ট (`int`) রিটার্ন করবে।

**🧠 কুইজ:**
১. কম্পাইল্ড কুয়েরি কোথায় স্টোর করে রাখা উচিত?
   A. লোকাল ভেরিয়েবল হিসেবে
   B. স্ট্যাটিক ফিল্ড হিসেবে (যাতে একবারই কম্পাইল হয়) (উত্তর: B)
   C. ডাটাবেজে

২. কম্পাইল্ড কুয়েরি কোন কাজটি বাঁচায়?
   A. ডাটাবেজ থেকে ডাটা আনার সময়
   B. LINQ থেকে SQL অনুবাদের সময় (Query Compilation Overhead) (উত্তর: B)
   C. নেটওয়ার্ক ল্যাটেন্সি

৩. সব কুয়েরি কি কম্পাইল করা উচিত?
   A. হ্যাঁ
   B. না, শুধু যে কুয়েরিগুলো খুব ঘনঘন রান হয় (High Frequency Hot Path) (উত্তর: B)

**⚠️ খুব জরুরি নোট:** EF Core এর আধুনিক ভার্সনগুলো (6/7/8) অটোমেটিক কুয়েরি ক্যাশিং করে (Auto Caching)। তাই সাধারণ অ্যাপে ম্যানুয়ালি কম্পাইল্ড কুয়েরি লেখার খুব একটা দরকার হয় না। এটি শুধু এক্সট্রিম পারফরম্যান্স অপটিমাইজেশনের জন্য। কোড জটিল না করাই ভালো।

EF Core-এর **Interceptor** হলো ডাটাবেজ এবং আপনার কোডের মাঝখানের "চেকপোস্ট"। 🛑

### Lesson 45: ইন্টারসেপ্টর (Interceptors) - অডিট লগিং

**👨‍🏫 কোড রান টিপ:** আমরা `AppDbContext`-এ একটি কাস্টম ইন্টারসেপ্টর রেজিস্টার করব।

**🎉 ভূমিকা:**
Interceptor-এর মাধ্যমে আপনি SQL কমান্ড এক্সিকিউট হওয়ার **আগে** বা **পরে** বা **ফেইল হলে** মাঝখানে ঢুকে কাস্টম লজিক চালাতে পারেন।
সবচেয়ে জনপ্রিয় ব্যবহার:
- স্লো কুয়েরি লগ করা।
- `CommandText` মডিফাই করা (যেমন: সব কুয়েরিতে কমেন্ট যোগ করা)।
- অডিট লগ রাখা (কে ডিলিট করল)।

**🎯 শেখার লক্ষ্য:**
১. `DbCommandInterceptor` ইনহেরিট করে ক্লাস বানানো।
২. `ReaderExecuting` মেথড ওভাররাইড করা।
৩. DbContext-এ ইন্টারসেপ্টর অ্যাড করা (`AddInterceptors`).

**📖 প্রধান বিষয়বস্তু:**
আমরা একটি ইন্টারসেপ্টর বানাবো যা কনসোলে ওয়ার্নিং দেবে যদি কোনো কুয়েরিতে `DELETE` কিওয়ার্ড থাকে। (এটি শুধু ডেমো, বাস্তবে আমরা অডিট টেবিলে লগ রাখব)।

**💻 কোড উদাহরণ:**

**ফাইল:** `src/Data/Interceptors/AuditInterceptor.cs`
```csharp
using System;
using System.Data.Common;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore.Diagnostics;

namespace Lesson01_Intro.Data.Interceptors
{
    public class AuditInterceptor : DbCommandInterceptor
    {
        // সিঙ্ক্রোনাস কুয়েরির জন্য
        public override InterceptionResult<DbDataReader> ReaderExecuting(
            DbCommand command, 
            CommandEventData eventData, 
            InterceptionResult<DbDataReader> result)
        {
            CheckForDelete(command);
            return base.ReaderExecuting(command, eventData, result);
        }

        // অ্যাসিনক্রোনাস কুয়েরির জন্য (অবশ্যই ওভাররাইড করতে হবে)
        public override ValueTask<InterceptionResult<DbDataReader>> ReaderExecutingAsync(
            DbCommand command, 
            CommandEventData eventData, 
            InterceptionResult<DbDataReader> result, 
            CancellationToken cancellationToken = default)
        {
            CheckForDelete(command);
            return base.ReaderExecutingAsync(command, eventData, result, cancellationToken);
        }

        private void CheckForDelete(DbCommand command)
        {
            if (command.CommandText.ToUpper().Contains("DELETE"))
            {
                Console.ForegroundColor = ConsoleColor.Red;
                Console.WriteLine($"[AUDIT ALERT]: A DELETE command is being executed!");
                Console.WriteLine($"Query: {command.CommandText}");
                Console.ResetColor();
                
                // আপনি চাইলে এখানে কুয়েরি আটকাতেও পারেন এক্সপশন দিয়ে
                // throw new Exception("DELETE is not allowed!");
            }
        }
    }
}
```

### Lesson 46: ইউনিট টেস্টিং (In-Memory Database)

**👨‍🏫 কোড রান টিপ:** একটি নতুন xUnit টেস্ট প্রজেক্ট তৈরি করলে ভালো হয়, অথবা বর্তমান প্রজেক্টে প্যাকেজটি যোগ করে টেস্ট করতে পারেন।
প্যাকেজ: `Microsoft.EntityFrameworkCore.InMemory`

**🎉 ভূমিকা:**
ইউনিট টেস্টিং-এর মূল শর্ত হলো এটি **দ্রুত** এবং **আইসোলেটেড** হতে হবে। আসল ডাটাবেজে টেস্ট করলে তা স্লো হয় এবং ডাটা ডিলিট/আপডেট হয়ে জঞ্জাল তৈরি করে।
In-Memory প্রোভাইডার ব্যবহার করলে আপনার কোড মনে করবে সে ডাটাবেজেই কথা বলছে, কিন্তু আসলে সব মেমোরিতে হচ্ছে।

**🎯 শেখার লক্ষ্য:**
১. InMemory প্যাকেজ ইনস্টল করা।
২. টেস্ট মেথড সেটআপ করা।
৩. `DbContextOptions` ব্যবহার করে ডাটাবেজ সুইচ করা।

**📖 প্রধান বিষয়বস্তু:**
সাধারণত আমরা `OnConfiguring` মেথডে SQL Server হার্ডকোড করে রেখেছি। টেস্টিংয়ের জন্য আমাদের কনস্ট্রাক্টরের মাধ্যমে `DbContextOptions` পাস করার ব্যবস্থা রাখতে হবে।

### Lesson 47: ইউনিট টেস্টিং (SQLite In-Memory Mode)

**👨‍🏫 কোড রান টিপ:** প্যাকেজ লাগবে: `Microsoft.EntityFrameworkCore.Sqlite`।

**🎉 ভূমিকা:**
SQLite একটি হালকা ফাইল-বেসড ডাটাবেজ। কিন্তু এর একটি "In-Memory" মোড আছে যেখানে ফাইল তৈরি না হয়ে সব মেমোরিতে থাকে। এটি টেস্টিংয়ের জন্য পারফেক্ট কারণ এটি SQL কমান্ড সাপোর্ট করে এবং আসল ডাটাবেজের (SQL Server) খুব কাছাকাছি আচরণ করে।

**🎯 শেখার লক্ষ্য:**
১. SQLite কানেকশন তৈরি ও ওপেন করা।
২. স্কিমা তৈরি করা (`EnsureCreated`).
৩. কানেকশন লাইফটাইম ম্যানেজ করা।

**📖 প্রধান বিষয়বস্তু:**
In-Memory প্রোভাইডারের মতো এটি অটোমেটিক কাজ করে না।
গুরুত্বপূর্ণ নিয়ম: **কানেকশন ওপেন রাখতে হবে।** যদি কানেকশন ক্লোজ হয়ে যায়, তবে মেমোরি থেকে ডাটাবেজ মুছে যাবে।

public class SqliteTests
{
    public void Test_With_Sqlite()
    {
        Console.WriteLine("--- SQLite In-Memory Testing ---");

        // ১. কানেকশন তৈরি (DataSource=:memory:)
        var connection = new SqliteConnection("DataSource=:memory:");
        connection.Open(); // ⚡ কানেকশন ওপেন রাখতেই হবে!

        {
            // ২. অপশন কনফিগার করা

                context.SaveChanges();

            // ৪. ডাটা যাচাই (আলাদা স্কোপে)
            using (var context = new AppDbContext(options))
            {
                var item = context.Products.FirstOrDefault();
                Console.WriteLine($"Found: {item.Name}"); // Real Test Item

        {

৩. `DataSource=:memory:` এর মানে কী?
   A. ডাটাবেজ হার্ডডিস্কে সেভ হবে না, র‍্যামে হবে (উত্তর: A)
   B. মেমোরি কার্ডে সেভ হবে

**⚠️ খুব জরুরি নোট:** SQLite এবং SQL Server এর মধ্যে কিছু পার্থক্য আছে (যেমন: Date ফাংশন, String Comparison)। তাই ১০০% একুরেট টেস্টিংয়ের জন্য **Testcontainers** (Docker ভিত্তিক SQL Server) ব্যবহার করা বর্তমানে ইন্ডাস্ট্রি স্ট্যান্ডার্ড।

### Lesson 48: রিপোজিটরি প্যাটার্ন বনাম ডিরেক্ট DbContext

**👨‍🏫 কোড রান টিপ:** এটি আর্কিটেকচারাল লেসন।

**🎉 ভূমিকা:**
- **Direct DbContext:** আপনি কন্ট্রোলারে বা সার্ভিসে সরাসরি `_context.Products.Add(...)` লিখছেন।
- **Repository Pattern:** আপনি একটি আলাদা ক্লাস (`ProductRepository`) বানাচ্ছেন যার মেথড আছে `AddProduct(...)`। কন্ট্রোলার শুধু রিপোজিটরি চেনে, DbContext চেনে না।

**🎯 শেখার লক্ষ্য:**
১. জেনেরিক রিপোজিটরি (Generic Repository) তৈরি করা।
২. ইউনিট অব ওয়ার্ক (Unit of Work) প্যাটার্ন বোঝা।
৩. কখন কোনটি ব্যবহার করবেন তা সিদ্ধান্ত নেওয়া।

**📖 প্রধান বিষয়বস্তু:**
EF Core নিজেই একটি **Repository (DbSet)** এবং **Unit of Work (DbContext)** প্যাটার্ন ইমপ্লিমেন্ট করে। তাই এর ওপর আবার রিপোজিটরি লেয়ার বসালে সেটাকে "Abstractions over Abstractions" বলা হয়, যা অনেক সময় অপ্রয়োজনীয় জটিলতা বাড়ায়।
তবে, কোড টেস্টিং এবং লজিক সেন্ট্রালাইজ করার জন্য রিপোজিটরি কাজে আসে।

**💻 কোড উদাহরণ (Generic Repository):**

**ফাইল:** `src/Repositories/IRepository.cs`
```csharp
using System.Collections.Generic;
using System.Threading.Tasks;

namespace Lesson01_Intro.Repositories
{
    public interface IRepository<T> where T : class
    {
        Task<IEnumerable<T>> GetAllAsync();
        Task<T> GetByIdAsync(int id);
        Task AddAsync(T entity);
        // Update/Delete...
    }
}
```

**ফাইল:** `src/Repositories/Repository.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using Lesson01_Intro.Data;
using System.Collections.Generic;
using System.Threading.Tasks;

namespace Lesson01_Intro.Repositories
{
    public class Repository<T> : IRepository<T> where T : class
    {
        protected readonly AppDbContext _context;
        private readonly DbSet<T> _dbSet;

        public Repository(AppDbContext context)
        {
            _context = context;
            _dbSet = context.Set<T>();
        }

        public async Task<IEnumerable<T>> GetAllAsync()
        {
            return await _dbSet.ToListAsync();
        }

        public async Task<T> GetByIdAsync(int id)
        {
            return await _dbSet.FindAsync(id);
        }

        public async Task AddAsync(T entity)
        {
            await _dbSet.AddAsync(entity);
            // নোট: SaveChanges এখানে কল করা উচিত নয়, UnitOfWork এ করা উচিত
        }
    }
}
```

**ব্যবহার (Program.cs):**
```csharp
// DI কনটেইনারে রেজিস্টার করতে হয় (ওয়েব অ্যাপে)
// services.AddScoped(typeof(IRepository<>), typeof(Repository<>));

using (var context = new AppDbContext())
{
    var productRepo = new Repository<Product>(context);
    
    // রিপোজিটরি ব্যবহার করে ডাটা আনা
    var product = await productRepo.GetByIdAsync(1);
}
```

**🥊 কোনটা জিতবে?**
1. **ছোট/মাঝারি প্রজেক্ট:** সরাসরি `DbContext` ব্যবহার করুন। এটি সহজ, দ্রুত এবং EF Core-এর সব ফিচার (LINQ, Include) সরাসরি পাওয়া যায়।
2. **বিশাল/জটিল প্রজেক্ট (DDD):** ডোমেইন লজিক এনক্যাপসুলেট করার জন্য `Repository` ব্যবহার করুন। তবে জেনেরিক রিপোজিটরি এড়িয়ে স্পেসিফিক রিপোজিটরি (`IProductRepository`) বানানোই ভালো।

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. `IUnitOfWork` নামে একটি ইন্টারফেস তৈরি করুন যার একটি মেথড থাকবে `CompleteAsync()` (যা `SaveChanges` কল করবে)। রিপোজিটরির সাথে এটি ইন্টিগ্রেট করার চেষ্টা করুন।
২. রিপোজিটরি প্যাটার্নের একটি বড় অসুবিধা হলো `IQueryable` রিটার্ন না করা। ফলে কন্ট্রোলারে ফিল্টারিং করা যায় না। `GetAllAsync` মেথডে `Expression<Func<T, bool>> predicate` প্যারামিটার যোগ করে এটি সমাধান করার চেষ্টা করুন।

**🧠 কুইজ:**
১. EF Core এর `DbSet` কোন প্যাটার্নের সমতুল্য?
   A. Singleton
   B. Repository (উত্তর: B)
   C. Factory

২. রিপোজিটরি প্যাটার্ন ব্যবহারের একটি সুবিধা কী?
   A. কোড কমে যায়
   B. ইউনিট টেস্টিং সহজ হয় (Mocking এর মাধ্যমে) (উত্তর: B)
   C. পারফরম্যান্স বাড়ে

৩. `DbContext` সরাসরি ব্যবহার করলে কী সমস্যা হতে পারে?

   B. ডাটাবেজ কানেক্ট হয় না

### Lesson 49: EF Core Performance Tuning চেকলিস্ট

**👨‍🏫 কোড রান টিপ:** এটি একটি চেকলিস্ট লেসন। নোটপ্যাডে বা মাথায় টুকে নিন।

**🎉 ভূমিকা:**
EF Core স্লো হয় না, আমরা এটাকে স্লো বানাই! ভুল কুয়েরি, ইনডেক্স না থাকা, বা অতিরিক্ত ডাটা লোড করা—এসব কারণে পারফরম্যান্স খারাপ হয়। নিচের চেকলিস্ট ফলো করলে আপনার অ্যাপ রকেটের গতিতে চলবে। 🚀

**🎯 শেখার লক্ষ্য:**
১. ইনডেক্সিং এবং কুয়েরি অপটিমাইজেশন।
২. সঠিক লোডিং স্ট্র্যাটেজি নির্বাচন।
৩. মনিটরিং টুলস ব্যবহার।

**✅ দ্য আল্টিমেট চেকলিস্ট:**

**১. ডাটাবেজ ইনডেক্সিং (Indexing):**
- [ ] `WHERE`, `ORDER BY`, `JOIN` এ ব্যবহৃত কলামগুলোতে ইনডেক্স আছে তো?
- [ ] ফরেন কি (FK) কলামে ইনডেক্স আছে তো? (EF Core অটোমেটিক বানালেও চেক করে নিন)।

**২. লোডিং স্ট্র্যাটেজি (Loading):**
- [ ] রিড-অনলি কুয়েরির জন্য `.AsNoTracking()` ব্যবহার করেছেন তো? (সবচেয়ে বড় পারফরম্যান্স গেইন)।
- [ ] `Include` দিয়ে অতিরিক্ত ডাটা আনছেন না তো? (Cartesian Explosion)।
- [ ] লুপের ভেতরে কুয়েরি (N+1 Problem) নেই তো?

**৩. সিলেক্টিভ ফেচিং (Projection):**
- [ ] `SELECT *` বা পুরো এনটিটি না এনে, `Select(x => new DTO { ... })` ব্যবহার করেছেন তো? (নেটওয়ার্ক ব্যান্ডউইথ বাঁচাবে)।

**৪. প্যাজিনেশন (Pagination):**
- [ ] হাজার হাজার ডাটা একবারে না এনে `Skip().Take()` ব্যবহার করেছেন তো?

**৫. ডেটা টাইপ ম্যাচিং:**
- [ ] C# এর `string` (Unicode) এবং SQL এর `varchar` (Non-Unicode) এর মিসম্যাচ নেই তো? এটি ইনডেক্স ফেইল করায়। (Fluent API তে `.IsUnicode(false)` দিয়ে ঠিক করুন)।

**৬. ব্যাচিং (Batching):**
- [ ] লুপের ভেতর `SaveChanges()` কল না করে, লুপের বাইরে একবার কল করছেন তো?

**৭. ডিবাগিং ও লগিং:**
- [ ] স্লো কুয়েরি ধরার জন্য ইন্টারসেপ্টর বা `LogTo` চালু আছে তো? (কিন্তু প্রোডাকশনে সেনসিটিভ লগ অফ রাখবেন)।

**💻 কোড উদাহরণ (Performance Fix):**

**Bad Practice ❌:**
```csharp
// সব কলাম আনছে, ট্র্যাকিং অন, লুপে কুয়েরি
var users = context.Users.ToList(); 
foreach(var u in users) {
    var orders = context.Orders.Where(o => o.UserId == u.Id).ToList(); // N+1 Disaster!
}
```

**Good Practice ✅:**
```csharp
// শুধু দরকারি কলাম, ট্র্যাকিং অফ, এক কুয়েরিতে সব ডাটা
var report = context.Users
    .AsNoTracking()
    .Select(u => new 
    { 
        u.Username, 
        OrderCount = u.Orders.Count() // Aggregation in SQL
    })
    .Where(x => x.OrderCount > 0)
    .Take(100) // Pagination
    .ToList();
```

**🏋️‍♂️ প্র্যাকটিস এক্সারসাইজ:**
১. আপনার প্রজেক্টের সবচেয়ে জটিল কুয়েরিটি খুঁজে বের করুন। `ToQueryString()` মেথড ব্যবহার করে জেনারেটেড SQL দেখুন। তারপর সেই SQL টি SSMS বা ডাটাবেজ টুলে রান করে Execution Plan চেক করুন।
২. `Microsoft.EntityFrameworkCore.Tools` প্যাকেজের `dotnet ef dbcontext optimize` কমান্ডটি রান করে দেখুন (এটি মডেল স্টার্টআপ টাইম কমায়)।

### 💻 ২. ডাটা লেয়ার ও কনফিগারেশন

**ফাইল:** `Data/ShopDbContext.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using ShopApi.Models;

namespace ShopApi.Data
{
    public class ShopDbContext : DbContext
    {
        public ShopDbContext(DbContextOptions<ShopDbContext> options) : base(options) { }

        public DbSet<Product> Products { get; set; }
        public DbSet<Category> Categories { get; set; }

        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            // ১. ক্যাটাগরি কনফিগারেশন ও সিডিং
            modelBuilder.Entity<Category>().HasData(
                new Category { Id = 1, Name = "Electronics" },
                new Category { Id = 2, Name = "Fashion" }
            );

            // ২. প্রোডাক্ট কনফিগারেশন
            modelBuilder.Entity<Product>(entity =>
            {
                entity.Property(p => p.Name).IsRequired().HasMaxLength(100);
                entity.Property(p => p.Price).HasColumnType("decimal(18,2)");
                
                // গ্লোবাল ফিল্টার (শুধু একটিভ প্রোডাক্ট দেখাবে)
                entity.HasQueryFilter(p => p.IsActive);
            });
        }
    }
}
```

### 💻 ৪. API এন্ডপয়েন্ট ও লজিক (Program.cs)
এখানেই সব ম্যাজিক ঘটবে!

**ফাইল:** `Program.cs`
```csharp
using Microsoft.EntityFrameworkCore;
using ShopApi.Data;
using ShopApi.DTOs;
using ShopApi.Models;

var builder = WebApplication.CreateBuilder(args);

// ১. DbContext সেটআপ
var connectionString = builder.Configuration.GetConnectionString("DefaultConnection") 
    ?? "Server=(localdb)\\mssqllocaldb;Database=ShopApiDb;Trusted_Connection=True;MultipleActiveResultSets=true";

builder.Services.AddDbContext<ShopDbContext>(options =>
    options.UseSqlServer(connectionString)
           .LogTo(Console.WriteLine, LogLevel.Information)); // ডেভেলপমেন্টে লগ দেখব

var app = builder.Build();

// ২. ডাটাবেজ মাইগ্রেশন ও সিডিং (অটোমেটিক)
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<ShopDbContext>();
    db.Database.Migrate();
}

// ৩. API Endpoints (Minimal API)
var api = app.MapGroup("/api/products");

// GET: Products (with Filter, Sort, Pagination)
api.MapGet("/", async (ShopDbContext db, [AsParameters] ProductQuery query) =>
{
    // বেস কুয়েরি (No Tracking for Performance)
    var productsQuery = db.Products
                          .AsNoTracking()
                          .Include(p => p.Category) // জয়েন
                          .AsQueryable();

    // ১. ফিল্টারিং
    if (!string.IsNullOrEmpty(query.Search))
    {
        productsQuery = productsQuery.Where(p => p.Name.Contains(query.Search));
    }
    if (query.MinPrice.HasValue)
    {
        productsQuery = productsQuery.Where(p => p.Price >= query.MinPrice.Value);
    }

    // ২. সর্টিং (ডিফল্ট: নাম অনুযায়ী)
    productsQuery = productsQuery.OrderBy(p => p.Name);

    // ৩. পেজিনেশন ও প্রজেকশন (DTO তে কনভার্ট)
    var result = await productsQuery
        .Skip((query.Page - 1) * query.Size)
        .Take(query.Size)
        .Select(p => new ProductResponse(p.Id, p.Name, p.Price, p.Category.Name))
        .ToListAsync();

    return Results.Ok(result);
});

// POST: Create Product
api.MapPost("/", async (ShopDbContext db, CreateProductRequest req) =>
{
    // ভ্যালিডেশন (সিম্পল)
    if (string.IsNullOrEmpty(req.Name)) return Results.BadRequest("Name is required");

    var product = new Product
    {
        Name = req.Name,
        Price = req.Price,
        CategoryId = req.CategoryId
    };

    db.Products.Add(product);
    await db.SaveChangesAsync();

    return Results.Created($"/api/products/{product.Id}", product);
});

// DELETE: Soft Delete
api.MapDelete("/{id}", async (ShopDbContext db, int id) =>
{
    // ExecuteUpdate দিয়ে বাল্ক আপডেট (Lesson 34)
    var affected = await db.Products
                           .Where(p => p.Id == id)
                           .ExecuteUpdateAsync(s => s.SetProperty(p => p.IsActive, false));

    return affected > 0 ? Results.NoContent() : Results.NotFound();
});

app.Run();
```

[Fact]
public async Task GetProducts_Should_Return_Filtered_Data()
{
    // Arrange
    var options = new DbContextOptionsBuilder<ShopDbContext>()
        .UseInMemoryDatabase("ShopTestDb")
        .Options;

    using var db = new ShopDbContext(options);
    db.Products.Add(new Product { Name = "Laptop", Price = 50000, CategoryId = 1 });
    db.Products.Add(new Product { Name = "Mouse", Price = 500, CategoryId = 1 });
    await db.SaveChangesAsync();

    // Act
    var query = db.Products.Where(p => p.Price > 1000);
    var result = await query.ToListAsync();

    // Assert
    Assert.Single(result); // শুধু ১টি প্রোডাক্ট (Laptop) আসার কথা
    Assert.Equal("Laptop", result[0].Name);
}
