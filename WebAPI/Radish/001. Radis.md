
আসসালামু আলাইকুম, কোড লাভার ভাই-ব্রাদার! আমি তোমাদের সেই "বড় ভাই" আর্কিটেক্ট, যে জটিল জিনিস পানির মতো সহজ করে (এবং একটু মশলা মাখিয়ে) বোঝাতে পছন্দ করি।

আজকের টপিক **Redis**। এটা কোনো সাধারণ ডেটাবেজ না, এটা হলো ডেটাবেজ জগতের "উসাইন বোল্ট"। চলো, ২০টি এপিসোডের এই ওয়েব-সিরিজ শুরু করি। খাতা-কলম বা ভিএস কোড—যা খুশি নিয়ে রেডি হয়ে যাও!

### **Module 1: The Basics (Redis কি এবং কেন?)**

#### **Lesson 1: Redis কি? (The Kitchen Analogy)**
মনে করো তুমি বিরিয়ানি রান্না করছো।
*   **Hard Disk (SQL Server):** এটা হলো তোমার বাড়ির ৫ কিলোমিটার দূরের গ্রোসারি শপ। আলু আনতে হলে রিকশা নিয়ে যেতে হয়, জ্যামে বসে থাকতে হয়, তারপর আলু নিয়ে ফিরতে হয়। অনেক সময় লাগে।
*   **RAM (Memory):** এটা হলো তোমার রান্নাঘরের কাউন্টার-টপ বা টেবিল। হাত বাড়ালেই সব পাওয়া যায়।
*   **Redis:** Redis হলো এমন এক স্মার্ট অ্যাসিস্ট্যান্ট, যে আগে থেকেই জানে তোমার কী কী লাগবে এবং সেগুলো ওই দূরের দোকান (Hard Disk) থেকে এনে তোমার রান্নাঘরের টেবিলে (RAM) সাজিয়ে রাখে।

**সংজ্ঞা:** Redis (Remote Dictionary Server) হলো একটি **In-Memory** Data Structure Store। অর্থাৎ, সে ডেটা হার্ড ডিস্কে না রেখে RAM-এ রাখে। তাই এর স্পিড রকেটের মতো।

#### **Lesson 2: কেন আমাদের Redis দরকার? (The Dhaka Traffic Analogy)**
ধরা যাক, তোমার একটা ওয়েবসাইট আছে।
ইউজার রিকোয়েস্ট করলো: "ভাই, 'Laptop' এর লিস্ট দেখান।"
তোমার কোড সাধারণ ডেটাবেজে (SQL) গেল। SQL সার্ভার যেন ঢাকার ফার্মগেট। রিকোয়েস্ট জ্যামে আটকা পড়ে আছে। ইউজার লোডিং চাকা ঘুরতে দেখে বিরক্ত হয়ে সাইট বন্ধ করে দিল।

Redis থাকলে কি হতো?
প্রথমবার কেউ 'Laptop' খুঁজলে Redis সেটা SQL থেকে এনে নিজের পকেটে (RAM) রেখে দেয়। পরের বার যেই খুঁজবে, Redis বলবে—"আরে মামা, জ্যামে যাওয়া লাগবে না, এই নাও ডেটা!"
**Result:** মিলিসেকেন্ডে রেসপন্স!

#### **Lesson 3: ইন্সটলেশন (Docker - কারণ আমরা আধুনিক)**
উইন্ডোজের নেটিভ ইন্সটলার এখন ব্যাকডেটেড। আমরা স্মার্ট ডেভেলপার, আমরা Docker ব্যবহার করবো।
তোমার পিসিতে Docker Desktop থাকলে টার্মিনালে গিয়ে জাস্ট এই মন্ত্রটা পড়ো:

```bash
docker run --name my-redis -p 6379:6379 -d redis
```
*   `6379`: এটা Redis এর পোর্ট নম্বর (মনে রেখো, এটা ভাইভা প্রশ্ন হতে পারে)।
ব্যাস! তোমার পিসিতে এখন সুপারফাস্ট Redis ইঞ্জিন চলছে।

### **Module 2: Data Types (কোন ডেটা দেখতে কেমন?)**

#### **Lesson 4: Strings (চিরকুটে লেখা নাম্বার)**
Redis-এর সবচেয়ে বেসিক টাইপ।
**Analogy:** পকেটে একটা ছোট চিরকুট রাখা।
*   **Key:** "CrushName"
*   **Value:** "Zorina"
একটার বেশি ভ্যালু রাখা যাবে না। রিপ্লেস করলে আগেরটা গায়েব।

#### **Lesson 5: Lists (টিকিট কাউন্টারের লাইন)**
**Analogy:** সিনেমার টিকিটের লাইন বা বাসের লাইন।
তুমি চাইলে লাইনের সামনে (Left Push) বা পেছনে (Right Push) লোক ঢুকাতে পারো।
*   **Use Case:** কেউ তোমার ব্লগে কমেন্ট করলো, লাস্ট ১০টা কমেন্ট দেখাতে হবে।
*   **Structure:** ["Comment 1", "Comment 2", "Comment 3"]

#### **Lesson 6: Sets (বিয়ের দাওয়াত লিস্ট)**
**Analogy:** বিয়ের গেস্ট লিস্ট। তুমি কি একই বন্ধুকে দুইবার দাওয়াত কার্ড দিবা? না!
Sets-এ ডুপ্লিকেট এলাউড না। তুমি ১০ বার "Rahim" ঢুকালেও Redis বলবে, "মামা, রহিম তো অলরেডি আছে, পেরা নিও না।"
*   **Use Case:** ইউনিক আইপি অ্যাড্রেস বা ট্যাগ স্টোর করা।

#### **Lesson 7: Hashes (বায়োডাটা বা প্রোফাইল)**
**Analogy:** এটা একটা কমপ্লিট অবজেক্ট বা মানুষের আইডি কার্ড।
একটা মেইন Key থাকবে (যেমন: User:101), তার ভেতরে ছোট ছোট পকেট থাকবে।
*   Name: "Abul"
*   Age: "25"
*   City: "Dhaka"
C# এর `Dictionary<string, string>` এর মতো।

#### **Lesson 8: Sorted Sets (Leaderboard বা মেরিট লিস্ট)**
**Analogy:** বিসিএস পরীক্ষার রেজাল্ট বা পাবজি গেমের লিডারবোর্ড।
এখানে নামের সাথে একটা "Score" থাকে। যার স্কোর বেশি, সে অটোমেটিক উপরে উঠে যাবে। তোমাকে কষ্ট করে সর্ট করতে হবে না।
*   Key: "Player1", Score: 500
*   Key: "Player2", Score: 700 (এ আগে থাকবে)

### **Module 3: .NET Integration (কোড যখন কথা বলে)**

#### **Lesson 9: Connecting C# to Redis**
প্রথমে একটা নতুন Console App বা Web API প্রোজেক্ট নাও।
NuGet Package ইন্সটল করো: `StackExchange.Redis` (এটাই ইন্ডাস্ট্রিতে চলে)।

```csharp
using StackExchange.Redis;

// কানেকশন তৈরি করা (যেন মামার সাথে হাত মেলানো)
var multiplexer = ConnectionMultiplexer.Connect("localhost:6379");
// ডেটাবেজ এক্সেস নেয়া
IDatabase db = multiplexer.GetDatabase();

Console.WriteLine("Redis মামা কানেক্টেড!");
```

#### **Lesson 10: Basic Set/Get Code**
চলো কিছু ডেটা রাখি এবং বের করি।

```csharp
// ডেটা রাখা (Set)
db.StringSet("Greeting", "Assalamu Alaikum, Redis!");

// ডেটা আনা (Get)
string value = db.StringGet("Greeting");
Console.WriteLine(value); // আউটপুট: Assalamu Alaikum, Redis!
```
*টিপস:* `StringGet` যদি নাল (null) পায়, মানে ডেটা নাই।

#### **Lesson 11: Handling Objects (JSON এর জাদু)**
Redis সরাসরি C# Object চিনে না। সে চিনে শুধু স্ট্রিং বা বাইট। তাই আমাদের অবজেক্টকে JSON বানাতে হবে।

```csharp
using System.Text.Json;

public class User {
    public int Id { get; set; }
    public string Name { get; set; }
}

var user = new User { Id = 1, Name = "Kashem" };

// Serialize (Object -> String)
string jsonString = JsonSerializer.Serialize(user);
db.StringSet("user:1", jsonString);

// Deserialize (String -> Object)
string savedJson = db.StringGet("user:1");
var savedUser = JsonSerializer.Deserialize<User>(savedJson);

Console.WriteLine($"User Name: {savedUser.Name}");
```

#### **Lesson 12: Expiration/TTL (মিশন ইম্পসিবল মেসেজ)**
কিছু ডেটা আছে যা সারাজীবন রাখার দরকার নাই। যেমন: OTP কোড। ২ মিনিট পর ভ্যানিশ হয়ে যাওয়া উচিত।
একে বলে **TTL (Time To Live)**।

```csharp
// ১০ সেকেন্ড পর এই ডেটা অটো ডিলেট হয়ে যাবে
db.StringSet("OTP:12345", "9988", TimeSpan.FromSeconds(10));

Console.WriteLine("Data saved, but it will die in 10 seconds...");
```

### **Module 4: Real-world Scenarios (বাস্তব যুদ্ধ)**

#### **Lesson 13: Caching Strategy (Cache-Aside Pattern)**
সবচেয়ে জনপ্রিয় প্যাটার্ন।
**লজিক:**
১. পকেটে (Cache) হাত দাও, টাকা আছে? থাকলে নিয়ে যাও।
২. না থাকলে, ব্যাংকে (SQL DB) যাও, টাকা তোলো।
৩. টাকাটা পকেটে (Cache) রাখো (পরের বারের জন্য)।
৪. তারপর খরচ করো।

```csharp
string cacheKey = "product:101";
string productData = db.StringGet(cacheKey);

if (string.IsNullOrEmpty(productData))
{
    // ক্যাশে নাই, ডাটাবেজ থেকে আনো (Simulated)
    Console.WriteLine("Database থেকে আনছি...");
    productData = "MacBook Pro"; // SQL Call here
    
    // ক্যাশে সেট করে দাও ৫ মিনিটের জন্য
    db.StringSet(cacheKey, productData, TimeSpan.FromMinutes(5));
}
else
{
    Console.WriteLine("Cache (Redis) থেকে পেয়েছি!");
}
```

#### **Lesson 14: Session Storage**
তোমার অ্যাপ লোড ব্যালেন্সারে চলছে (৩টা সার্ভার)। ইউজার সার্ভার-১ এ লগিন করলো। পরের রিকোয়েস্ট গেল সার্ভার-২ তে। সার্ভার-২ তো চিনে না ইউজার কে!
**সমাধান:** সেশন ডেটা সার্ভারের মেমোরিতে না রেখে Redis-এ রাখো। সব সার্ভার Redis থেকে চেক করবে "এই ইউজার লগিন করা কি না"। এটাকে বলে **Distributed Session**।

#### **Lesson 15: Pub/Sub (এলাকার মাইকিং)**
**Analogy:** মসজিদের মাইক বা এলাকার মেম্বারের মাইকিং।
একজন বলবে (Publisher), আর যারা যারা চ্যানেল টিউন করে আছে (Subscribers), সবাই শুনবে।
*   **Use Case:** রিয়েল টাইমে চ্যাট অ্যাপ্লিকেশন বা নোটিফিকেশন।

```csharp
// Subscriber (যে শুনবে)
var sub = multiplexer.GetSubscriber();
sub.Subscribe("news_channel", (channel, message) => {
    Console.WriteLine($"ব্রেকিং নিউজ: {message}");
});

// Publisher (যে বলবে)
sub.Publish("news_channel", "আগামীকাল হরতাল!");
```

### **Module 5: Advanced but Simple (প্রো লেভেল)**

#### **Lesson 16: Transactions (সব হবে, নাহলে কিছুই না)**
**Analogy:** ব্যাংকে টাকা পাঠানো। তোমার অ্যাকাউন্ট থেকে কমবে এবং বন্ধুর অ্যাকাউন্টে বাড়বে। মাঝপথে কারেন্ট গেলে তোমার টাকা কমলো কিন্তু বন্ধুর বাড়লো না—এটা হতে দেওয়া যাবে না।
Redis এ `MULTI` কমান্ড দিয়ে এটা হ্যান্ডেল করা হয়।

```csharp
var trans = db.CreateTransaction();
trans.StringSetAsync("key1", "value1");
trans.StringSetAsync("key2", "value2");
bool committed = trans.Execute(); // সব একসাথে এক্সিকিউট হবে
```

#### **Lesson 17: Pipelines (ওয়েটারকে একবার পাঠানো)**
তুমি রেস্টুরেন্টে গিয়ে একবার পানি, একবার টিস্যু, একবার মেনু চাইলে ওয়েটার বিরক্ত হবে।
একবারে বলো: "পানি, টিস্যু, আর মেনু আনেন।"
**Pipeline** দিয়ে তুমি ১০০টা রিকোয়েস্ট একবারে পাঠাও, Redis ১০০টা কাজ করে একবারে রেজাল্ট দিবে। নেটওয়ার্ক ট্রিপ বাঁচে।

#### **Lesson 18: Persistence (লোডশেডিং প্রটেকশন)**
Redis তো RAM-এ থাকে। পিসি রিস্টার্ট দিলে সব শেষ?
না! Redis এর দুইটা ব্যাকআপ প্ল্যান আছে:
1.  **RDB (Snapshot):** নির্দিষ্ট সময় পর পর পুরো ডেটার ছবি তুলে রাখে (Backup file).
2.  **AOF (Append Only File):** তুমি যা যা কমান্ড দিচ্ছো, সব একটা ডায়রীতে লিখে রাখে। রিস্টার্ট হলে ডায়রী দেখে সব রিকভার করে।

### **Module 6: Best Practices (শেষের কথা)**

#### **Lesson 19: Common Mistakes (Keys * মারবা না!)**
কখনো প্রোডাকশনে `KEYS *` কমান্ড দিবা না।
**কেন?** মনে করো গুলশান মোড়ে পুলিশ সব গাড়ি থামিয়ে চেক করছে "চোর কে?"। পুরো ঢাকা জ্যাম লেগে যাবে।
`KEYS *` পুরো ডেটাবেজ স্ক্যান করে, অন্য সব রিকোয়েস্ট ব্লক করে দেয়। এর বদলে `SCAN` কমান্ড ব্যবহার করতে হয়।

#### **Lesson 20: Final Summary (বিদায় বেলা)**
তাহলে মামা, আমরা কি শিখলাম?
১. Redis হলো সুপারফাস্ট ইন-মেমোরি স্টোর।
২. ডেটাবেজের লোড কমাতে এবং অ্যাপ ফাস্ট করতে এর জুড়ি নেই।
৩. স্ট্রিং, লিস্ট, সেট—কাজের ধরন বুঝে ডেটা টাইপ ইউজ করতে হবে।
