### ১. ডিজাইন প্যাটার্ন (Design Pattern) কী?
ডিজাইন প্যাটার্ন হলো সফটওয়্যার ডেভেলপমেন্টের সাধারণ সমস্যাগুলোর পরীক্ষিত এবং প্রমাণিত সমাধান। এটি কোনো নির্দিষ্ট কোড নয়, বরং কোড লেখার একটি ব্লু-প্রিন্ট বা নকশা।

*   **কিভাবে কাজ করে:** লেখক একে **LEGO** ব্লকের সাথে তুলনা করেছেন। আপনি যেমন ছোট ছোট লেগো ব্লক দিয়ে একটি বড় ক্যাসেল বা দুর্গ তৈরি করেন, তেমনি ডিজাইন প্যাটার্ন ব্যবহার করে ছোট ছোট কোড ব্লক দিয়ে একটি বড় এবং মজবুত সফটওয়্যার তৈরি করা হয়।
*   **কেন কাজ করে:** কারণ এই প্যাটার্নগুলো অভিজ্ঞ ডেভেলপাররা বহুবার ব্যবহার করে সফল হয়েছেন। এটি চাকা নতুন করে আবিষ্কার (Reinventing the wheel) করার বদলে চাকাটি কীভাবে সেরা উপায়ে ব্যবহার করা যায় তা শেখায়।
*   **সুবিধা:**
    *   কোড বোঝা ও মেইনটেইন করা সহজ হয়।
    *   টিমের অন্য সদস্যদের সাথে কাজ করা সহজ হয় কারণ সবাই একই "ভাষা" বা প্যাটার্ন বোঝে।
*   **সহজ উদাহরণ:** মনে করুন আপনি একটি বাড়ি বানাচ্ছেন। বাড়ির দরজা কোথায় হবে, জানালা কোথায় হবে—এর একটা স্ট্যান্ডার্ড নকশা আছে। আপনি যদি ছাদের ওপর দরজা বানান, তবে তা ব্যবহারের অযোগ্য হবে। ডিজাইন প্যাটার্ন হলো সেই স্ট্যান্ডার্ড নকশা যা নিশ্চিত করে বাড়িটি (সফটওয়্যারটি) ঠিকঠাক কাজ করবে।

### ২. অ্যান্টি-প্যাটার্ন এবং কোড স্মেল (Anti-patterns & Code Smells)
ভালো কোড শেখার পাশাপাশি খারাপ কোড চেনাটাও জরুরি।

#### ক. অ্যান্টি-প্যাটার্ন (Anti-pattern)
এটি এমন এক ধরনের সমাধান যা প্রথমে ভালো মনে হলেও ভবিষ্যতে বড় সমস্যার সৃষ্টি করে।
*   **God Class:** একটি ক্লাস বা অবজেক্ট যখন সব কাজ একা করে। এটি একটি অ্যান্টি-প্যাটার্ন।
    *   *সমস্যা:* সব লজিক এক জায়গায় থাকায় কোড পরিবর্তন করা খুব কঠিন হয়ে পড়ে।
    *   *উদাহরণ:* একটি রেস্টুরেন্টে একজন ব্যক্তিই যদি রান্না করে, অর্ডার নেয়, এবং ক্যাশ কাউন্টার সামলায়—তবে সিস্টেমটি ভেঙে পড়বে। কোডেও প্রতিটি ক্লাসের দায়িত্ব আলাদা হওয়া উচিত।

#### খ. কোড স্মেল (Code Smell)
এটি সরাসরি কোনো এরর (Error) নয়, কিন্তু এটি ইঙ্গিত দেয় যে কোডে গভীর কোনো সমস্যা আছে।
*   **Control Freak (New keyword):** কোডের ভেতরে সরাসরি `new` কিওয়ার্ড ব্যবহার করে অবজেক্ট তৈরি করা।
    *   *কেন খারাপ:* এতে আপনার কোড নির্দিষ্ট একটি ক্লাসের ওপর খুব বেশি নির্ভরশীল (Tightly Coupled) হয়ে পড়ে। ভবিষ্যতে ওই ক্লাস পরিবর্তন করলে পুরো কোড ভাঙতে পারে। (এর সমাধান হলো Dependency Injection, যা পরে শেখানো হয়েছে)।
*   **Long Methods:** একটি ফাংশন বা মেথড যদি অনেক বড় (১০-১৫ লাইনের বেশি) হয়।
    *   *সমাধান:* বড় মেথডকে ভেঙে ছোট ছোট লজিক্যাল টুকরোয় ভাগ করা।

### ৩. ওয়েব কিভাবে কাজ করে (Request/Response)
ওয়েব অ্যাপ্লিকেশন আর্কিটেকচার বুঝতে হলে HTTP প্রোটোকল বোঝা জরুরি।

*   **কিভাবে কাজ করে:** ক্লায়েন্ট (যেমন: ব্রাউজার) সার্ভারের কাছে একটি **Request** পাঠায়। সার্ভার সেই রিকোয়েস্ট প্রসেস করে এবং একটি **Response** ফেরত দেয়। একবার রেসপন্স পাঠানোর পর সার্ভার ভুলে যায় কে রিকোয়েস্ট করেছিল (Stateless)।
*   **HTTP মেথড:**
    *   `GET`: ডেটা আনার জন্য।
    *   `POST`: নতুন ডেটা তৈরি করার জন্য।
    *   `PUT/PATCH`: ডেটা আপডেট করার জন্য।
    *   `DELETE`: ডেটা মুছে ফেলার জন্য।
*   **কেন কাজ করে:** এটি একটি স্ট্যান্ডার্ড নিয়ম যা সারা বিশ্বের সব ওয়েব সার্ভার এবং ব্রাউজার মেনে চলে।
*   **সুবিধা:** ক্লায়েন্ট এবং সার্ভার একে অপরের অভ্যন্তরীণ বিষয় না জেনেই যোগাযোগ করতে পারে।
*   **সহজ উদাহরণ:** আপনি রেস্টুরেন্টে গিয়ে ওয়েটারকে মেনু দেখে অর্ডার দিলেন (Request)। ওয়েটার কিচেন থেকে খাবার এনে আপনাকে দিল (Response)। আপনি খেয়ে চলে যাওয়ার পর ওয়েটার আর মনে রাখে না আপনি কে ছিলেন বা কি খেয়েছিলেন (Stateless Nature)।

### ৪. .NET ইকোসিস্টেম (Getting Started with .NET)
এখানে .NET এর টুলস এবং ভার্সন নিয়ে আলোচনা করা হয়েছে।

#### ক. SDK vs Runtime
*   **SDK (Software Development Kit):** এতে কোড লেখা, বিল্ড করা এবং রান করার সব টুল থাকে। ডেভেলপার হিসেবে আপনার এটি দরকার।
*   **Runtime:** এটি কেবল তৈরি করা সফটওয়্যার বা অ্যাপ রান করতে পারে, কোড কম্পাইল করতে পারে না। সার্ভারে সাধারণত শুধু রানটাইম ইন্সটল করা থাকে (কারণ এটি হালকা)।
*   **উদাহরণ:** SDK হলো একটি সম্পূর্ণ রান্নাঘর যেখানে সব মশলা ও চুলা আছে (শেফ বা ডেভলপারের জন্য)। Runtime হলো ডাইনিং টেবিল যেখানে কেবল খাবার পরিবেশন করা হয় (কাস্টমার বা ইউজারের জন্য)।

#### খ. .NET CLI (Command Line Interface)
ভিজ্যুয়াল স্টুডিওর বোতাম না চেপে কমান্ড লিখে প্রজেক্ট তৈরি বা রান করা।
*   **কেন ব্যবহার করবেন:** এটি অটোমেশন বা CI/CD পাইপলাইনের জন্য খুব জরুরি। তাছাড়া সব এডিটরে (যেমন VS Code) ভিজ্যুয়াল ইন্টারফেস থাকে না, সেখানে CLI ভরসা।
*   **কয়েকটি কমান্ড:**
    *   `dotnet new webapi` - নতুন ওয়েব API প্রজেক্ট তৈরি করে।
    *   `dotnet run` - অ্যাপ রান করে।
    *   `dotnet build` - কোড কম্পাইল করে।

### ২. CLI কমান্ড কোড (CLI Commands)
অধ্যায়টিতে মাউস দিয়ে ক্লিক না করে, কমান্ড লিখে কিভাবে প্রজেক্ট তৈরি ও রান করা যায় তা দেখানো হয়েছে। আপনি আপনার টার্মিনাল (CMD বা PowerShell) ওপেন করে নিচের কোডগুলো প্র্যাকটিস করতে পারেন।

**ক. নতুন প্রজেক্ট তৈরি করা:**
```bash
dotnet new webapi -n MyFirstApp
```
*   **ব্যাখ্যা:** `dotnet new` হলো নতুন কিছু তৈরির কমান্ড। `webapi` হলো প্রজেক্টের ধরন (আমরা API বানাবো)। `-n MyFirstApp` মানে প্রজেক্টের নাম হবে "MyFirstApp"।

**খ. ফোল্ডারে ঢোকা:**
```bash
cd MyFirstApp
```

**গ. প্রজেক্ট রান করা:**
```bash
dotnet run
```
*   **ব্যাখ্যা:** এটি আপনার অ্যাপটি চালু করে দেবে এবং একটি লোকাল সার্ভার লিংক (যেমন: `http://localhost:5000`) দেখাবে।

### ৩. কোড কনসেপ্ট ও উদাহরণ (Code Concepts from Chapter 1)
বইটিতে ভালো আর্কিটেকচার বোঝাতে গিয়ে একটি **Code Smell** (খারাপ কোড)-এর উদাহরণ দেওয়া হয়েছে, যার নাম **"Control Freak"**।

#### ক. খারাপ কোড (The Bad Way - Control Freak)
এখানে একটি ক্লাস নিজেই আরেকটি ক্লাসের অবজেক্ট তৈরি করছে `new` কিওয়ার্ড দিয়ে।

```csharp
public class OrderService
{
    public void PlaceOrder()
    {
        // সমস্যা: এখানে 'new' ব্যবহার করা হয়েছে।
        // OrderService এখন সরাসরি EmailSender-এর ওপর নির্ভরশীল।
        var emailSender = new EmailSender();
        emailSender.Send("Order placed successfully!");
    }
}
```
*   **কেন খারাপ:** আপনি যদি ভবিষ্যতে `EmailSender` পরিবর্তন করতে চান বা টেস্টিং করতে চান, তবে `OrderService` ক্লাসটিও পরিবর্তন করতে হবে। এটি **Tight Coupling** তৈরি করে।

#### খ. ভালো কোড (The Better Way - Dependency Injection)
বইটিতে বলা হয়েছে, `new` কিওয়ার্ড ব্যবহার না করে কনস্ট্রাক্টরের মাধ্যমে ডিপেন্ডেন্সি ইনজেক্ট করা উচিত (এটি পরবর্তী অধ্যায়গুলোতে বিস্তারিত শেখানো হবে, এখানে ধারণা দেওয়া হয়েছে)।

```csharp
public class OrderService
{
    private readonly IEmailSender _emailSender;

    // সমাধান: অবজেক্ট বাইরে থেকে (কনস্ট্রাক্টর দিয়ে) আসছে।
    // OrderService-এর আর চিন্তা নেই EmailSender কিভাবে তৈরি হলো।
    public OrderService(IEmailSender emailSender)
    {
        _emailSender = emailSender;
    }

    public void PlaceOrder()
    {
        _emailSender.Send("Order placed successfully!");
    }
}
```
*   **কেন ভালো:** কোডটি এখন ফ্লেক্সিবল। টেস্টিং করার সময় আপনি আসল ইমেইল সেন্ডারের বদলে নকল (Mock) ইমেইল সেন্ডার পাঠাতে পারবেন।

### ৪. HTTP রিকোয়েস্টের উদাহরণ (HTTP Request Example)
ওয়েব কিভাবে কাজ করে তা বোঝাতে বইটিতে একটি **Raw HTTP Request** এর কোড দেখানো হয়েছে। এটি মূলত ব্রাউজার এবং সার্ভারের মধ্যে চলা কথোপকথন।

**কোড:**
```http
GET http://www.forevolve.com/ HTTP/1.1
Host: www.forevolve.com
Connection: keep-alive
User-Agent: Mozilla/5.0
Accept: text/html
```

*   **ব্যাখ্যা:**
    *   `GET`: সার্ভারকে বলা হচ্ছে "আমাকে তথ্য দাও"।
    *   `Host`: কোন ওয়েবসইটে রিকোয়েস্ট পাঠানো হচ্ছে।
    *   `User-Agent`: কোন ব্রাউজার ব্যবহার করা হচ্ছে।
