**Chapter 2: Automated Testing**-এ লেখক কোড লেখার পাশাপাশি সেই কোডটি ঠিকঠাক কাজ করছে কি না, তা স্বয়ংক্রিয়ভাবে (Automatically) চেক করার পদ্ধতির ওপর গুরুত্ব দিয়েছেন। আধুনিক সফটওয়্যার ডেভেলপমেন্টে টেস্টিং ছাড়া ভালো অ্যাপ্লিকেশন বানানো অসম্ভব।

নিচে এই অধ্যায়ের বিস্তারিত আলোচনা, টপিকগুলোর কাজ, কেন জরুরি এবং কোড উদাহরণ দেওয়া হলো:

---

### ১. টেস্টিং পিরামিড (The Testing Pyramid)
বইটিতে টেস্টিংয়ের ৩টি প্রধান স্তর বা লেভেলের কথা বলা হয়েছে। একে একটি পিরামিডের সাথে তুলনা করা হয়।

#### ক. ইউনিট টেস্টিং (Unit Testing) - পিরামিডের ভিত্তি
এটি হলো সবচেয়ে ছোট লেভেলের টেস্ট। এখানে পুরো অ্যাপ টেস্ট না করে, কোডের একটি ছোট অংশ (যেমন: একটি ফাংশন বা মেথড) টেস্ট করা হয়।
*   **কিভাবে কাজ করে:** এটি ডাটাবেস বা ইন্টারনেটের ওপর নির্ভর করে না। ইনপুট দেবেন এবং আউটপুট চেক করবেন।
*   **উদাহরণ:** আপনি একটি ক্যালকুলেটর অ্যাপ বানাচ্ছেন। `Add(2, 2)` ফাংশন কল করলে সেটি `4` রিটার্ন করছে কি না—এটা চেক করাই ইউনিট টেস্ট।

#### খ. ইন্টিগ্রেশন টেস্টিং (Integration Testing) - মাঝখানের স্তর
এখানে চেক করা হয় একাধিক ছোট ছোট ইউনিট বা কম্পোনেন্ট একসাথে মিলে ঠিকমতো কাজ করছে কি না।
*   **কিভাবে কাজ করে:** এখানে ডাটাবেস বা API কল জড়িত থাকতে পারে।
*   **উদাহরণ:** আপনার অ্যাপ থেকে ডাটাবেসে ইউজার সেভ করার কমান্ড দিলে তা আসলেই ডাটাবেসে সেভ হচ্ছে কি না, তা চেক করা।

#### গ. এন্ড-টু-এন্ড টেস্টিং (E2E Testing) - সবার উপরের স্তর
এটি একদম ইউজারের মতো করে পুরো সিস্টেম টেস্ট করে।
*   **কিভাবে কাজ করে:** একটি ব্রাউজার ওপেন করে, বাটনে ক্লিক করে, ফর্ম ফিলাপ করে—সবকিছু চেক করা হয়। এটি সবচেয়ে ধীরগতির।

---

### ২. টেস্টিং অ্যাপ্রোচ (TDD - Test Driven Development)
এটি কোড লেখার একটি বিশেষ পদ্ধতি। একে **Red-Green-Refactor** সাইকেল বলা হয়।
1.  **Red (Fail):** প্রথমে টেস্ট লিখুন (কোড লেখার আগেই!)। যেহেতু কোড নেই, টেস্টটি ফেইল করবে (লাল দেখাবে)।
2.  **Green (Pass):** টেস্টটি পাস করার জন্য যতটুকু দরকার, ঠিক ততটুকু কোড লিখুন। এখন টেস্ট পাস করবে (সবুজ দেখাবে)।
3.  **Refactor:** কোডটিকে সাজান বা সুন্দর করুন (কিন্তু লজিক বদলাবেন না)।

*   **সুবিধা:** আপনি নিশ্চিত থাকেন যে আপনার প্রতিটি লাইনের জন্য টেস্ট আছে এবং অপ্রয়োজনীয় কোড লেখা হয় না।

---

### ৩. xUnit ফ্রেমওয়ার্ক (xUnit Framework)
.NET-এ টেস্টিং করার জন্য **xUnit** সবচেয়ে জনপ্রিয় টুল। বইটিতে এটি ব্যবহার করেই সব উদাহরণ দেওয়া হয়েছে।

#### প্রধান দুটি অ্যাট্রিবিউট:
1.  `[Fact]`: যখন আপনি জানেন ইনপুট কী হবে এবং আউটপুট কী হবে (ফিক্সড ভ্যালু)।
2.  `[Theory]`: যখন আপনি একই টেস্টে বিভিন্ন ইনপুট দিয়ে চেক করতে চান (ডাটা-ড্রিভেন টেস্ট)।

### ৪. কোড উদাহরণ ও সেটআপ (Code Example & Setup)

ধরা যাক, আমাদের একটি `Calculator` ক্লাস আছে। আমরা xUnit দিয়ে এটি টেস্ট করব।

**ধাপ ১: প্রজেক্ট তৈরি**
টার্মিনালে লিখুন:
```bash
dotnet new xunit -n MyCalculator.Tests
```

**ধাপ ২: কোড লেখা (AAA প্যাটার্ন)**
টেস্টিং-এ **AAA** (Arrange, Act, Assert) নিয়ম মানা হয়।
*   **Arrange:** ভেরিয়েবল বা অবজেক্ট রেডি করা।
*   **Act:** আসল ফাংশনটি কল করা।
*   **Assert:** ফলাফল যা আশা করেছিলেন, তার সাথে মিলেছে কি না তা চেক করা।

**কোড:**
```csharp
using Xunit;

public class CalculatorTests
{
    // [Fact] ব্যবহার করা হয় সাধারণ টেস্টের জন্য
    [Fact]
    public void Add_ShouldReturnCorrectSum()
    {
        // 1. Arrange (প্রস্তুতি)
        int number1 = 5;
        int number2 = 10;
        int expectedResult = 15;

        // 2. Act (কাজ)
        int actualResult = number1 + number2; // ধরুন এটি ক্যালকুলেটরের মেথড

        // 3. Assert (যাচাই)
        Assert.Equal(expectedResult, actualResult); // 15 আর actualResult সমান কি না?
    }

    // [Theory] ব্যবহার করা হয় একাধিক ইনপুট দিয়ে টেস্ট করার জন্য
    [Theory]
    [InlineData(2, 2, 4)]  // 2+2 = 4
    [InlineData(5, 5, 10)] // 5+5 = 10
    [InlineData(0, 5, 5)]  // 0+5 = 5
    public void Add_MultipleNumbers_ShouldReturnSum(int n1, int n2, int expected)
    {
        int result = n1 + n2;
        Assert.Equal(expected, result);
    }
}
```

### ৫. ASP.NET Core ইন্টিগ্রেশন টেস্টিং (WebApplicationFactory)
এই অধ্যায়ের একটি গুরুত্বপূর্ণ অংশ হলো **`WebApplicationFactory`**।
সাধারণত API টেস্ট করতে হলে অ্যাপ রান করতে হয়, তারপর পোস্টম্যান (Postman) দিয়ে রিকোয়েস্ট পাঠাতে হয়। কিন্তু `WebApplicationFactory` ব্যবহার করলে কোডের ভেতরই একটি **ভার্চুয়াল মেমোরি সার্ভার** তৈরি হয়।

*   **সুবিধা:** আসল সার্ভার রান না করেই আপনি আপনার API-এর `GET`, `POST` রিকোয়েস্ট টেস্ট করতে পারবেন। এটি খুব দ্রুত কাজ করে।

**উদাহরণ (সংক্ষিপ্ত):**
```csharp
public class BasicTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public BasicTests(WebApplicationFactory<Program> factory)
    {
        // মেমোরিতে একটি ভার্চুয়াল ক্লায়েন্ট তৈরি হলো
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task Get_EndpointsReturnSuccessAndCorrectContentType()
    {
        // Act: API-তে রিকোয়েস্ট পাঠানো হচ্ছে
        var response = await _client.GetAsync("/weatherforecast");

        // Assert: স্ট্যাটাস কোড 200 (OK) কি না চেক করা হচ্ছে
        response.EnsureSuccessStatusCode(); 
    }
}
```

### ধাপ ১: সলিউশন এবং প্রোজেক্ট সেটআপ (Unit Testing)

প্রথমে আমরা একটি সলিউশন এবং একটি লজিক ক্লাস তৈরি করব, তারপর সেটির জন্য টেস্ট লিখব।

**১. ফোল্ডার ও সলিউশন তৈরি:**
```bash
mkdir Chapter2Testing
cd Chapter2Testing
dotnet new sln -n TestingDemo
```

**২. মূল কোড (Class Library) তৈরি:**
এটি হবে আমাদের মেইন প্রোজেক্ট যেখানে লজিক থাকবে।
```bash
dotnet new classlib -n MyApp.Logic
```

**৩. টেস্ট প্রোজেক্ট (xUnit) তৈরি:**

**৪. টেস্ট প্রোজেক্টে মেইন প্রোজেক্টের রেফারেন্স দেওয়া:**
যাতে টেস্ট প্রোজেক্ট আমাদের লজিক চিনতে পারে।

```bash
cd MyApp.Tests
```

### ধাপ ২: কোড লেখা (Unit Test)

এখন আমরা `MyApp.Logic` ফোল্ডারে একটি ক্লাস বানাবো এবং `MyApp.Tests` ফোল্ডারে সেটি টেস্ট করব।

#### ১. মেইন লজিক কোড
`MyApp.Logic` ফোল্ডারের ভেতর `Calculator.cs` নামে একটি ফাইল তৈরি করুন এবং এই কোড লিখুন:

```csharp
// MyApp.Logic/Calculator.cs
namespace MyApp.Logic;

public class Calculator
{
    // দুটি সংখ্যা যোগ করার সাধারণ মেথড
    public int Add(int a, int b)
    {
        return a + b;
    }

    // সংখ্যাটি জোড় কি না তা চেক করার মেথড
    public bool IsEven(int number)
    {
        return number % 2 == 0;
    }
}
```

#### ২. টেস্ট কোড (xUnit)
`MyApp.Tests` ফোল্ডারের ভেতর `CalculatorTests.cs` ফাইলে নিচের কোড লিখুন। এখানে বইয়ের `[Fact]` এবং `[Theory]` কনসেপ্ট ব্যবহার করা হয়েছে।

```csharp
// MyApp.Tests/CalculatorTests.cs
using Xunit;
using MyApp.Logic;

public class CalculatorTests
{
    // [Fact] - একটি নির্দিষ্ট ঘটনার সত্যতা যাচাই করে
    [Fact]
    public void Add_ShouldReturnCorrectSum()
    {
        // Arrange (প্রস্তুতি)
        var calculator = new Calculator();
        
        // Act (কাজ)
        int result = calculator.Add(5, 6);

        // Assert (যাচাই)
        Assert.Equal(11, result); // 5+6 = 11 হওয়ার কথা
    }

    // [Theory] - একই টেস্ট ভিন্ন ভিন্ন ইনপুট দিয়ে যাচাই করে (Data Driven Test)
    [Theory]
    [InlineData(2, true)]  // ২ জোড়, তাই true আসা উচিত
    [InlineData(3, false)] // ৩ বিজোড়, তাই false আসা উচিত
    [InlineData(10, true)]
    public void IsEven_ShouldDetectEvenNumbers(int number, bool expected)
    {
        // Arrange
        var calculator = new Calculator();

        // Act
        bool result = calculator.IsEven(number);

        // Assert
        Assert.Equal(expected, result);
    }
}
```

**টেস্ট রান করুন:**
টার্মিনালে রুট ফোল্ডারে (Chapter2Testing) ফিরে এসে কমান্ড দিন:
```bash
dotnet test
```
*আউটপুট:* আপনি দেখবেন সবুজ রঙে লেখা আসবে `Passed!`।

### ধাপ ৩: ইন্টিগ্রেশন টেস্টিং সেটআপ (Integration Testing)

বইয়ের দ্বিতীয় গুরুত্বপূর্ণ অংশ হলো **ASP.NET Core Integration Test**। এটার জন্য আমাদের একটি Web API প্রোজেক্ট লাগবে।

**১. API প্রোজেক্ট তৈরি:**
```bash
dotnet new webapi -n MySimpleApi
dotnet sln add MySimpleApi
```

**২. API-এর `Program.cs` ঠিক করা:**
ইন্টিগ্রেশন টেস্টিং করার জন্য টেস্ট প্রোজেক্টকে `Program.cs` এক্সেস করতে দিতে হয়। তাই `MySimpleApi` ফোল্ডারের `Program.cs` ফাইলের একদম শেষে নিচের লাইনটি যোগ করুন:

```csharp
// MySimpleApi/Program.cs এর একদম নিচে এই লাইনটি যোগ করুন
public partial class Program { }
```

**৩. ইন্টিগ্রেশন টেস্ট প্রোজেক্ট তৈরি:**
```bash
dotnet new xunit -n MySimpleApi.IntegrationTests
dotnet sln add MySimpleApi.IntegrationTests
```

**৪. প্রয়োজনীয় প্যাকেজ ইনস্টল করা:**
ইন্টিগ্রেশন টেস্টিংয়ের জন্য মাইক্রোসফটের একটি বিশেষ প্যাকেজ লাগে।

### ধাপ ৪: ইন্টিগ্রেশন টেস্ট কোড

এখন আমরা দেখব API সার্ভার চালু না করেও কিভাবে কোডের মাধ্যমে API কল চেক করা যায়।

`MySimpleApi.IntegrationTests` ফোল্ডারে `WeatherApiTests.cs` নামে ফাইল তৈরি করুন:

```csharp
// MySimpleApi.IntegrationTests/WeatherApiTests.cs
using Microsoft.AspNetCore.Mvc.Testing;
using Xunit;

// WebApplicationFactory আমাদের জন্য মেমোরিতে একটা নকল সার্ভার বানাবে
public class WeatherApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public WeatherApiTests(WebApplicationFactory<Program> factory)
    {
        // একটি ভার্চুয়াল ক্লায়েন্ট তৈরি করা হলো
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task Get_WeatherForecast_ReturnsSuccess()
    {
        // Act: ডিফল্ট API রাউটে রিকোয়েস্ট পাঠানো
        var response = await _client.GetAsync("/weatherforecast");

        // Assert: রেসপন্স কোড 200 (OK) কি না চেক করা
        response.EnsureSuccessStatusCode(); 
        
        // রেসপন্স খালি নেই তো? সেটা চেক করা
        var responseString = await response.Content.ReadAsStringAsync();
        Assert.NotEmpty(responseString);
    }
}
```

**টেস্ট রান করুন:**
টার্মিনালে লিখুন:
```bash
dotnet test
```

### কি শিখলাম এবং কোডের ব্যাখ্যা (Summary):

1.  **Unit Test (CalculatorTests):**
    *   আমরা `Calculator` ক্লাস বানিয়েছি।
    *   `[Fact]` দিয়ে চেক করেছি যোগফল ঠিক আছে কি না।
    *   `[Theory]` এবং `[InlineData]` ব্যবহার করে এক কোড দিয়েই ২, ৩, ১০ সংখ্যার জোড়/বিজোড় চেক করেছি। এতে কোড রিপিট করা লাগেনি।

2.  **Integration Test (WeatherApiTests):**
    *   আমরা `WebApplicationFactory` ব্যবহার করেছি। এটি আসল সার্ভার রান না করেই মেমোরিতে অ্যাপটি লোড করে।
    *   `HttpClient` দিয়ে `/weatherforecast` এ রিকোয়েস্ট পাঠিয়েছি এবং দেখেছি স্ট্যাটাস কোড **200 OK** আসে কি না।
