স্বাগতম! আমি আপনাদের ইনস্ট্রাক্টর। আজ আমরা **Chapter 4: REST APIs** নিয়ে বিস্তারিত আলোচনা করব।

আধুনিক ওয়েব অ্যাপ্লিকেশনের প্রাণ হলো **REST API**। ফ্রন্টএন্ড (React, Angular, Mobile App) এবং ব্যাকএন্ড (Database, Server) এর মধ্যে যোগাযোগের মাধ্যম হলো এই API। এই অধ্যায়ে আমরা শিখব কিভাবে একটি **স্ট্যান্ডার্ড এবং সিকিউর** API ডিজাইন করতে হয়।

চলুন, প্রতিটি টপিক ধাপে ধাপে শিখি।

### ১. REST এবং HTTP (REST & HTTP Basics)

**এটি কী:**
REST (Representational State Transfer) হলো ওয়েব যোগাযোগের একটি নিয়ম। এটি **HTTP প্রোটোকল** ব্যবহার করে ডেটা আদান-প্রদান করে। ওয়েব ব্রাউজার এবং সার্ভার একে অপরের সাথে কথা বলার জন্য কিছু নির্দিষ্ট **Verb (ক্রিয়া)** এবং **Status Code** ব্যবহার করে।

**HTTP মেথডসমূহ (Verbs):**
1.  **GET:** ডেটা পড়ার জন্য (Read)।
2.  **POST:** নতুন ডেটা তৈরি করার জন্য (Create)।
3.  **PUT:** পুরাতন ডেটা সম্পূর্ণ পরিবর্তন করার জন্য (Update/Replace)।
4.  **PATCH:** পুরাতন ডেটার আংশিক পরিবর্তন করার জন্য (Partial Update)।
5.  **DELETE:** ডেটা মুছে ফেলার জন্য (Delete)।

**HTTP স্ট্যাটাস কোড:**
*   `200 OK`: সব ঠিক আছে।
*   `201 Created`: নতুন কিছু সফলভাবে তৈরি হয়েছে।
*   `400 Bad Request`: ক্লায়েন্ট ভুল ডেটা পাঠিয়েছে।
*   `404 Not Found`: যা খুঁজছেন তা নেই।
*   `500 Internal Server Error`: সার্ভারে কোনো সমস্যা হয়েছে।

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি একটি বিশ্বজনীন স্ট্যান্ডার্ড। আপনি যদি এই নিয়ম মেনে API বানান, তবে পৃথিবীর যেকোনো ডেভেলপার বা সফটওয়্যার আপনার API সহজেই ব্যবহার করতে পারবে।

**সমস্যা (Problems):**
অনেকে নিয়ম না মেনে সব কাজের জন্য `POST` বা `GET` ব্যবহার করেন। যেমন: ডেটা ডিলিট করার জন্য `GET` রিকোয়েস্ট পাঠানো। এটি **নিরাপত্তার ঝুঁকি** তৈরি করে এবং ব্রাউজার ক্যাশিং-এ সমস্যা করে।

**সমাধান:**
সঠিক কাজের জন্য সঠিক HTTP মেথড ব্যবহার করুন।

**কোড উদাহরণ (Controller):**
```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    // 1. GET: সব প্রোডাক্ট আনা
    [HttpGet]
    public IActionResult GetAll() 
    {
        return Ok(new List<string> { "Laptop", "Mobile" }); // 200 OK
    }

    // 2. POST: নতুন প্রোডাক্ট যোগ করা
    [HttpPost]
    public IActionResult Create(string name)
    {
        // ডেটাবেসে সেভ করার কোড...
        return CreatedAtAction(nameof(GetAll), new { id = 1 }, name); // 201 Created
    }
}
```

### ২. Data Transfer Object (DTO)

**এটি কী:**
DTO হলো এমন একটি ক্লাস বা অবজেক্ট যা শুধুমাত্র ডেটা পরিবহনের জন্য ব্যবহার করা হয়। এটি আমাদের ডাটাবেসের আসল টেবিল (Entity/Domain Model) থেকে আলাদা।

**কেন এটি কাজ করে ও কেন জরুরি:**
সরাসরি ডাটাবেস মডেল ইউজারের কাছে পাঠানো বা ইউজারের কাছ থেকে নেওয়া বিপজ্জনক।
*   **Security:** মনে করুন আপনার `User` টেবিলে `Password` এবং `IsAdmin` ফিল্ড আছে। আপনি যদি সরাসরি `User` মডেল রিটার্ন করেন, তবে পাসওয়ার্ডও চলে যাবে।
*   **Over-posting Attack:** ইউজার যদি রেজিষ্ট্রেশনের সময় `IsAdmin = true` পাঠিয়ে দেয় এবং আপনি সরাসরি সেই মডেল রিসিভ করেন, তবে হ্যাকার অ্যাডমিন হয়ে যেতে পারে।

**সমস্যা (Problems):**
DTO ব্যবহার না করলে আপনার ইন্টারনাল ডাটাবেস স্ট্রাকচার বাইরে প্রকাশ হয়ে পড়ে এবং হ্যাকিংয়ের ঝুঁকি বাড়ে।

**সমাধান:**
সর্বদা ইউজারের কাছ থেকে ডেটা নেওয়ার জন্য `InputDTO` এবং ডেটা দেখানোর জন্য `OutputDTO` ব্যবহার করুন।

**কোড উদাহরণ:**

**Domain Model (ডাটাবেস টেবিল):**
```csharp
public class User
{
    public int Id { get; set; }
    public string Username { get; set; }
    public string Password { get; set; } // এটা কখনো বাইরে পাঠানো যাবে না
    public bool IsAdmin { get; set; }    // এটা ইউজার সেট করতে পারবে না
}
```

**DTO (নিরাপদ ক্লাস):**
```csharp
// ইউজার যা দেখবে
public class UserDto
{
    public string Username { get; set; }
}

// ইউজার যা পাঠাবে
public class RegisterDto
{
    public string Username { get; set; }
    public string Password { get; set; }
}
```

**Controller-এ ব্যবহার:**
```csharp
[HttpPost]
public IActionResult Register(RegisterDto input) // DTO নিচ্ছি
{
    // এখানে input থেকে ডেটা নিয়ে আসল User মডেলে কনভার্ট করে সেভ করব।
    // IsAdmin বা অন্য ফিল্ড হ্যাক করার সুযোগ নেই।
    return Ok();
}
```

### ৩. API Versioning (ভার্সনিং)

**এটি কী:**
সময়ের সাথে সাথে অ্যাপ্লিকেশনের রিকুয়ারমেন্ট বদলায়। API Versioning হলো এমন একটি পদ্ধতি যার মাধ্যমে পুরাতন API চালু রেখে নতুন ফিচার যোগ করা হয়।

**কেন এটি কাজ করে ও কেন জরুরি:**
ধরুন, আপনার একটি মোবাইল অ্যাপ আছে যা `api/products` ব্যবহার করে। আপনি হঠাৎ API-এর স্ট্রাকচার বদলে দিলেন। এখন যারা অ্যাপটি আপডেট করেনি, তাদের অ্যাপ ক্র্যাশ করবে (Breaking Change)। ভার্সনিং করলে পুরাতন অ্যাপও চলবে, নতুন অ্যাপও চলবে।

**সমস্যা (Problems):**
ভার্সনিং না করলে সামান্য পরিবর্তনেও হাজার হাজার ক্লায়েন্ট বা ইউজারের অ্যাপ অকেজো হয়ে যেতে পারে।

**সমাধান:**
API-এর ইউআরএল বা হেডারে ভার্সন নম্বর ব্যবহার করা।

**বাস্তব ব্যবহার (৩টি উপায়):**
1.  **URL Versioning (সবচেয়ে জনপ্রিয়):** `api/v1/products`, `api/v2/products`
2.  **Query String:** `api/products?api-version=1.0`
3.  **Header Versioning:** রিকোয়েস্ট হেডারে ভার্সন বলে দেওয়া।

**কোড উদাহরণ (URL Versioning):**
```csharp
[ApiVersion("1.0")]
[Route("api/v{version:apiVersion}/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public string Get() => "This is Version 1 data";
}

[ApiVersion("2.0")]
[Route("api/v{version:apiVersion}/[controller]")]
public class ProductsV2Controller : ControllerBase
{
    [HttpGet]
    public string Get() => "This is Version 2 data (Improved)";
}
```

### ৪. API Contracts (Swagger/OpenAPI)

**এটি কী:**
এটি হলো আপনার API-এর একটি ডকুমেন্টেশন বা ম্যানুয়াল। এটি বলে দেয় আপনার API-এ কোন কোন ইউআরএল আছে, কী ইনপুট দিতে হবে এবং কী আউটপুট আসবে। .NET-এ এর জন্য **Swagger** ব্যবহার করা হয়।

**কেন এটি কাজ করে ও কেন জরুরি:**
ফ্রন্টএন্ড ডেভেলপাররা আপনার ব্যাকএন্ড কোড দেখবে না। তারা Swagger ডকুমেন্টেশন দেখে বুঝবে কিভাবে API কল করতে হয়।

**সুবিধা:**
*   মানুষ এবং মেশিন উভয়ই এটি পড়তে পারে।
*   এটি ব্যবহার করে অটোমেটিক ক্লায়েন্ট কোড জেনারেট করা যায়।
*   API টেস্টিং সহজ হয়।

**বাস্তব ব্যবহার:**
ASP.NET Core-এ `Swashbuckle` লাইব্রেরি ব্যবহার করে এটি অটোমেটিক তৈরি করা হয়। প্রোজেক্ট রান করলেই `/swagger` লিংকে গিয়ে পুরো API-এর লিস্ট দেখা যায়।

### অধ্যায়ের সারসংক্ষেপ (Summary)

এই অধ্যায়টি একটি প্রফেশনাল API তৈরির গাইডলাইন।

১. **REST & HTTP:** সঠিক কাজের জন্য সঠিক মেথড (GET, POST, PUT, DELETE) এবং সঠিক স্ট্যাটাস কোড (200, 404, 500) ব্যবহার করুন। এটি API-কে স্ট্যান্ডার্ড করে।
২. **DTO:** কখনোই ডাটাবেস মডেল সরাসরি এক্সপোজ করবেন না। DTO ব্যবহার করলে হ্যাকিংয়ের ঝুঁকি কমে এবং কোড মেইনটেইন করা সহজ হয়।
৩. **Versioning:** ভবিষ্যতে অ্যাপ ক্র্যাশ হওয়া আটকাতে API-এর ভার্সন (`v1`, `v2`) মেইনটেইন করা জরুরি।
৪. **API Contracts:** Swagger ব্যবহার করুন যাতে আপনার API ব্যবহারকারীরা সহজেই ডকুমেন্টেশন বুঝতে পারে।

এই নিয়মগুলো মানলে আপনার API হবে **Secure (নিরাপদ)**, **Scalable (বড় করা সম্ভব)** এবং **Maintainable (সহজে পরিবর্তনযোগ্য)**।

### ১. সেটআপ এবং প্রয়োজনীয় টুলস (Setup & Tools)

এই অধ্যায়ে কাজ করার জন্য আমাদের একটি **ASP.NET Core Web API** প্রোজেক্ট সেটআপ করতে হবে।

**প্রয়োজনীয় সফটওয়্যার:**
1.  **.NET 8 SDK** (লেটেস্ট ভার্সন)।
2.  **Visual Studio 2022** অথবা **Visual Studio Code** (কোড এডিটর)।
3.  **Postman** (API টেস্ট করার জন্য, যদিও আমরা ব্রাউজার বা Swagger দিয়েও করতে পারি)।

**ধাপসমূহ (Steps):**

1.  **প্রোজেক্ট তৈরি:** আপনার টার্মিনাল বা কমান্ড প্রম্পট ওপেন করুন এবং নিচের কমান্ডটি দিন:
    ```bash
    dotnet new webapi -n MyRestApi
    cd MyRestApi
    ```
    *কেন:* `webapi` টেম্পলেটটি আমাদের জন্য কন্ট্রোলার, Swagger কনফিগারেশন এবং একটি ডামি `WeatherForecast` API তৈরি করে দেয়, যা শুরু করার জন্য সেরা।

2.  **প্রোজেক্ট রান করা:**
    ```bash
    dotnet run
    ```
    *কেন:* এটি নিশ্চিত করে যে আপনার এনভায়রনমেন্ট ঠিক আছে। ব্রাউজারে একটি লিংক আসবে (যেমন: `http://localhost:5XXX/swagger`), সেখানে গেলে আপনি API-এর ডকুমেন্টেশন দেখতে পাবেন।

### ২. কোড ইমপ্লিমেন্টেশন (Code Implementation)

এই অধ্যায়ের মূল শিক্ষা হলো **Resource** (যেমন: Product, User) ম্যানেজ করা এবং **DTO (Data Transfer Object)** ব্যবহার করা। আমরা একটি **Product Management API** তৈরি করব।

#### ক. মডেল এবং DTO তৈরি (The Model & DTO)

সরাসরি ডাটাবেস মডেল ইউজারের কাছে এক্সপোজ করা উচিত নয়। তাই আমরা DTO ব্যবহার করব।

```csharp
// 1. Domain Model (ডাটাবেসের টেবিল কেমন হবে)
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public bool IsInStock { get; set; }
    public string InternalCode { get; set; } // এটি আমরা ইউজারকে দেখাব না
}

// 2. DTO (যা ইউজারকে দেখানো হবে বা ইউজারের থেকে নেওয়া হবে)
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

public class CreateProductDto
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

**লজিক (Why DTO?):**
*   `InternalCode` একটি সেনসিটিভ তথ্য হতে পারে। আমরা DTO ব্যবহার করে এটি লুকিয়ে রাখলাম।
*   `CreateProductDto`-তে আমরা `Id` রাখিনি, কারণ `Id` ডাটাবেস জেনারেট করবে। ইউজার এটি পাঠাতে পারবে না। এটি **Over-posting Attack** প্রতিরোধ করে।

#### খ. কন্ট্রোলার তৈরি (The Controller)

এখন আমরা `Controllers` ফোল্ডারে `ProductsController.cs` নামে একটি ফাইল তৈরি করব।

```csharp
using Microsoft.AspNetCore.Mvc;
using System.Collections.Generic;
using System.Linq;

[ApiController] // এটি বলে দেয় যে এটি একটি API কন্ট্রোলার
[Route("api/[controller]")] // URL হবে: api/products
public class ProductsController : ControllerBase
{
    // সিম্পলিসিটির জন্য আমরা ডাটাবেসের বদলে একটি স্ট্যাটিক লিস্ট ব্যবহার করছি
    private static List<Product> _products = new List<Product>
    {
        new Product { Id = 1, Name = "Laptop", Price = 50000, InternalCode = "SECURE_1" },
        new Product { Id = 2, Name = "Mouse", Price = 500, InternalCode = "SECURE_2" }
    };

    // ১. GET: সব প্রোডাক্ট আনা
    [HttpGet]
    public ActionResult<IEnumerable<ProductDto>> GetAll()
    {
        // Domain Model থেকে DTO তে কনভার্ট করা হচ্ছে
        var productsDto = _products.Select(p => new ProductDto
        {
            Id = p.Id,
            Name = p.Name,
            Price = p.Price
        }).ToList();

        return Ok(productsDto); // 200 OK স্ট্যাটাসসহ ডেটা রিটার্ন করবে
    }

    // ২. GET: নির্দিষ্ট আইডির প্রোডাক্ট আনা
    [HttpGet("{id}")]
    public ActionResult<ProductDto> GetById(int id)
    {
        var product = _products.FirstOrDefault(p => p.Id == id);

        if (product == null)
        {
            return NotFound(); // 404 Not Found স্ট্যাটাস রিটার্ন করবে
        }

        // DTO তে কনভার্ট
        var dto = new ProductDto 
        { 
            Id = product.Id, 
            Name = product.Name, 
            Price = product.Price 
        };

        return Ok(dto);
    }

    // ৩. POST: নতুন প্রোডাক্ট তৈরি করা
    [HttpPost]
    public ActionResult<ProductDto> Create(CreateProductDto input)
    {
        // ইনপুট ভ্যালিডেশন (Optional, [ApiController] এটা অটোমেটিক করে)
        if (string.IsNullOrWhiteSpace(input.Name))
        {
            return BadRequest("Name is required"); // 400 Bad Request
        }

        // নতুন আইডি জেনারেট করা
        var newId = _products.Max(p => p.Id) + 1;

        var newProduct = new Product
        {
            Id = newId,
            Name = input.Name,
            Price = input.Price,
            IsInStock = true,
            InternalCode = "GENERATED_CODE"
        };

        _products.Add(newProduct);

        // রেসপন্স হিসেবে তৈরি হওয়া প্রোডাক্টটি ফেরত দেওয়া
        var responseDto = new ProductDto
        {
            Id = newProduct.Id,
            Name = newProduct.Name,
            Price = newProduct.Price
        };

        // 201 Created স্ট্যাটাস এবং নতুন রিসোর্সের লোকেশন রিটার্ন করা
        return CreatedAtAction(nameof(GetById), new { id = newId }, responseDto);
    }
}
```

**কোডের পেছনের লজিক (Why write it this way?):**

1.  **`[ApiController]` & `[Route]`:*** এটি ফ্রেমওয়ার্ককে বলে দেয় এটি সাধারণ ওয়েব পেজ নয়, বরং একটি API। `[controller]` অংশটি ক্লাসের নাম (`Products`) অটোমেটিক নিয়ে নেয়।
2.  **`ActionResult<T>`:** এটি আমাদের ফ্লেক্সিবিলিটি দেয়। আমরা সফল হলে ডেটা (`ProductDto`) এবং ব্যর্থ হলে HTTP স্ট্যাটাস (`NotFound`, `BadRequest`) পাঠাতে পারি।
3.  **Status Codes:**
    *   ডেটা পাওয়া গেলে `Ok()` (200)।
    *   না পাওয়া গেলে `NotFound()` (404)।
    *   ভুল ইনপুট দিলে `BadRequest()` (400)।
    *   নতুন কিছু বানালে `CreatedAtAction()` (201)। এটি হেডার ফাইলে নতুন ডেটার লিংকও দিয়ে দেয়, যা RESTful স্ট্যান্ডার্ড।

### ৩. সাধারণ সমস্যা এবং সমাধান (Common Problems & Solutions)

**সমস্যা ১: Over-posting / Mass Assignment**
হ্যাকাররা অনেক সময় রিকোয়েস্টের সাথে এমন ডেটা পাঠিয়ে দেয় যা তাদের দেওয়ার কথা না (যেমন: `IsAdmin: true` বা `Price: 0`)।
*   **সমাধান:** সরাসরি ডোমেইন মডেল (`Product`) প্যারামিটার হিসেবে ব্যবহার করবেন না। সবসময় `CreateProductDto` ব্যবহার করুন যেখানে শুধুমাত্র প্রয়োজনীয় ফিল্ডগুলো থাকবে।

**সমস্যা ২: Naming Convention**
C#-এ আমরা `PascalCase` (যেমন: `FirstName`) ব্যবহার করি, কিন্তু JSON স্ট্যান্ডার্ড হলো `camelCase` (যেমন: `firstName`)।
*   **সমাধান:** ASP.NET Core অটোমেটিক্যালি এটি হ্যান্ডেল করে। আপনি C# স্টাইলে কোড লিখবেন, আউটপুট অটোমেটিক JSON স্ট্যান্ডার্ডে হবে।

**সমস্যা ৩: Breaking Changes**
আপনি যদি হঠাৎ API-এর কোনো ফিল্ডের নাম পরিবর্তন করেন, মোবাইল অ্যাপগুলো ক্র্যাশ করবে।
*   **সমাধান:** **API Versioning** ব্যবহার করুন (যেমন: `api/v1/products`, `api/v2/products`)।

### ৪. বাস্তব উদাহরণ (Real-World Scenario)

মনে করুন আপনি একটি ই-কমার্স সাইটের ব্যাকএন্ড বানাচ্ছেন।

1.  **অ্যাডমিন:** অ্যাডমিন যখন প্রোডাক্ট আপলোড করবে, সে `POST /api/products` কল করবে। সে `Name` আর `Price` পাঠাবে। আপনার কোড `201 Created` রেসপন্স দেবে।
2.  **কাস্টমার:** কাস্টমার যখন অ্যাপ ওপেন করবে, অ্যাপ `GET /api/products` কল করবে। আপনার কোড `InternalCode` লুকিয়ে রেখে শুধু নাম ও দামের লিস্ট পাঠাবে।
3.  **সার্চ:** কাস্টমার কোনো প্রোডাক্টে ক্লিক করলে অ্যাপ `GET /api/products/5` কল করবে। যদি প্রোডাক্ট না থাকে, আপনার কোড `404 Not Found` দেখাবে, যাতে অ্যাপ সুন্দর একটি এরর মেসেজ দেখাতে পারে।

### ৫. অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

এই অধ্যায়ে আমরা যা শিখলাম এবং বাস্তব জীবনে এর গুরুত্ব:

1.  **REST Principles:** HTTP মেথড (GET, POST, PUT, DELETE) এবং স্ট্যাটাস কোডগুলো হলো API-এর ভাষা। এগুলো সঠিকভাবে ব্যবহার করলে ফ্রন্টএন্ড ডেভেলপাররা সহজেই আপনার API বুঝতে পারবে।
2.  **DTO (Data Transfer Objects):** এটি আপনার অ্যাপ্লিকেশনের **Security Shield**। এটি নিশ্চিত করে যে আপনি ঠিক যতটুকু ডেটা চান, ততটুকুই আদান-প্রদান হচ্ছে।
3.  **API Contracts (Swagger):** সেটআপ করার সময় আমরা দেখেছি Swagger অটোমেটিক ডকুমেন্টেশন তৈরি করে। এটি টিমের মধ্যে যোগাযোগ সহজ করে দেয়।
4.  **Action Results:** সঠিক রেসপন্স টাইপ ব্যবহার করা (যেমন `CreatedAtAction`) একটি ভালো API-এর লক্ষণ, যা ক্লায়েন্টকে পরবর্তী পদক্ষেপ নিতে সাহায্য করে।

এই সেটআপ এবং কোডিং প্যাটার্ন অনুসরণ করলে আপনার তৈরি করা API হবে **Secure**, **Maintainable**, এবং **Industry Standard**।
