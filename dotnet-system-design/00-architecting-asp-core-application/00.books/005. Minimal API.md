
স্বাগতম! আমি আপনাদের ইনস্ট্রাক্টর হিসেবে **Chapter 5: Minimal API** নিয়ে বিস্তারিত আলোচনা করব।

ASP.NET Core-এর ইতিহাসে **Minimal API** হলো একটি গেম-চেঞ্জার। আগে আমরা `Controller` এবং `MVC` প্যাটার্ন ব্যবহার করে বড় বড় ক্লাস লিখতাম। কিন্তু .NET 6 থেকে Microsoft আমাদের দিল Minimal API—যার মাধ্যমে মাত্র কয়েক লাইনেই শক্তিশালী API তৈরি করা সম্ভব।

আসুন, ধাপে ধাপে সব টপিক শিখে নিই।

### ১. Top-level Statements

**এটি কী:**
আগে C# কোড লিখতে হলে `namespace`, `class Program`, `static void Main()`—এসব অনেক কিছু লিখতে হতো। Top-level Statements-এর মাধ্যমে এই সব অপ্রয়োজনীয় কোড বাদ দিয়ে সরাসরি লজিক লেখা যায়।

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি কোডকে পরিষ্কার (Clean) এবং ছোট (Concise) করে। বিশেষ করে ছোট মাইক্রোসার্ভিস বা ল্যাম্বডা ফাংশন লেখার সময় এটি খুব কার্যকর।

**সমস্যা (Problems):**
বড় প্রজেক্টে যদি সব কোড `Program.cs`-এ লেখা হয়, তবে কোড অগোছালো হয়ে যেতে পারে।

**সমাধান:**
কোডগুলোকে আলাদা আলাদা ফাইলে বা ক্লাসে ভাগ করে নিতে হবে।

**কোড উদাহরণ:**

**আগে (Old Way):**
```csharp
using System;
namespace MyApp 
{
    class Program 
    {
        static void Main(string[] args) 
        {
            Console.WriteLine("Hello World!");
        }
    }
}
```

**এখন (Minimal API Way):**
```csharp
Console.WriteLine("Hello World!");
```
*(ব্যাস! এই এক লাইনেই কাজ শেষ)*

### ২. Minimal Hosting

**এটি কী:**
এটি হলো অ্যাপ্লিকেশন স্টার্টআপের নতুন পদ্ধতি। আগে `Startup.cs` এবং `Program.cs` দুটি আলাদা ফাইল লাগত। এখন সব কনফিগারেশন `WebApplicationBuilder` ব্যবহার করে এক জায়গায় করা যায়।

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি সার্ভার কনফিগারেশনকে অনেক সহজ করে ফেলে। ডিপেন্ডেন্সি ইনজেকশন (DI), লগিং, এবং কনফিগারেশন সেটআপ করা এখন অনেক দ্রুত হয়।

**বাস্তব ব্যবহার:**
```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.Run();
```
*(এই ৩ লাইনেই একটি সার্ভার তৈরি হয়ে গেল!)*

### ৩. Minimal APIs (মূল অংশ)

**এটি কী:**
Minimal API হলো কন্ট্রোলার ছাড়াই API এন্ডপয়েন্ট তৈরি করার পদ্ধতি। আমরা সরাসরি `MapGet`, `MapPost`, `MapPut`, `MapDelete` মেথড ব্যবহার করে API বানাতে পারি।

**কেন এটি কাজ করে ও কেন জরুরি:**
*   **Performance:** কন্ট্রোলারের তুলনায় এটি অনেক ফাস্ট কারণ এতে প্রসেসিং লেয়ার কম।
*   **Simplicity:** ছোট বা মাঝারি অ্যাপ্লিকেশনের জন্য এটি বেস্ট।

**সমস্যা (Problems):**
যখন অ্যাপ অনেক বড় হয়ে যায় এবং হাজার হাজার এন্ডপয়েন্ট থাকে, তখন `Program.cs` ফাইলটি বিশাল হয়ে যায় এবং মেইনটেইন করা কঠিন হয়।

**সমাধান:**
আমরা কোডকে আলাদা স্ট্যাটিক ক্লাস বা এক্সটেনশন মেথডে ভাগ করে নেব (যা পরে "Organizing Endpoints" টপিকে দেখানো হবে)।

**কোড উদাহরণ:**
```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// ১. সাধারণ GET রিকোয়েস্ট
app.MapGet("/", () => "Hello Minimal API!");

// ২. ডাইনামিক রাউট
app.MapGet("/user/{name}", (string name) => $"Hello {name}");

app.Run();
```

### ৪. Map route-to-delegate & Configuring Endpoints

**এটি কী:**
এখানে দেখানো হয়েছে কিভাবে রিকোয়েস্ট হ্যান্ডেল করার লজিক (Delegate) লিখতে হয় এবং এন্ডপয়েন্ট কনফিগার করতে হয়।

**কেন এটি কাজ করে:**
আপনি চাইলে লজিক সরাসরি ল্যাম্বডা এক্সপ্রেশন `() => ...` দিয়ে লিখতে পারেন, অথবা আলাদা মেথড বানিয়ে কল করতে পারেন।

**কোড উদাহরণ:**
```csharp
// ল্যাম্বডা স্টাইল
app.MapGet("/hello", () => "Hi there!");

// মেথড রেফারেন্স স্টাইল (Clean Code)
string SayHi() => "Hi from Method!";
app.MapGet("/hi", SayHi);
```

### ৫. Endpoint Filters (খুব গুরুত্বপূর্ণ)

**এটি কী:**
কন্ট্রোলারে যেমন `Filter` বা `Middleware` থাকে, Minimal API-তে তেমনি `EndpointFilter` থাকে। এটি রিকোয়েস্ট প্রসেস করার আগে বা পরে কিছু লজিক রান করতে দেয় (যেমন: লগিং, ভ্যালিডেশন)।

**কেন এটি কাজ করে ও কেন জরুরি:**
মনে করুন, আপনি চান সব এন্ডপয়েন্টে লগিং হোক। প্রতি মেথডে লগিং কোড না লিখে, একটি ফিল্টার বানালে সব জায়গায় কাজ করবে।

**সমস্যা:**
ফিল্টার চেইন বেশি জটিল হলে ডিবাগ করা কঠিন হতে পারে।

**সমাধান:**
ফিল্টারের লজিক ছোট এবং সহজ রাখা উচিত।

**কোড উদাহরণ:**
```csharp
app.MapGet("/secret", () => "This is secret data")
   .AddEndpointFilter(async (context, next) => 
   {
       Console.WriteLine("Before Request"); // রিকোয়েস্টের আগে
       var result = await next(context);   // আসল কাজ
       Console.WriteLine("After Request");  // রিকোয়েস্টের পরে
       return result;
   });
```

### ৬. Organizing Endpoints (কোড গোছানো)

**এটি কী:**
সব API যদি `Program.cs` ফাইলে লিখি, তবে কোড হিজিবিজি হয়ে যাবে। তাই আমরা এক্সটেনশন মেথড ব্যবহার করে কোড আলাদা ফাইলে রাখব।

**কেন এটি কাজ করে:**
এটি কোডকে মডুলার করে এবং বড় প্রজেক্টে কাজ করা সহজ হয়।

**কোড উদাহরণ:**

**আলাদা ফাইল (UserEndpoints.cs):**
```csharp
public static class UserEndpoints
{
    public static void MapUserRoutes(this WebApplication app)
    {
        app.MapGet("/users", () => new[] { "Ali", "Hasan" });
    }
}
```

**Main ফাইল (Program.cs):**
```csharp
var app = builder.Build();

app.MapUserRoutes(); // কত সুন্দর ক্লিন কোড!

app.Run();
```

### ৭. Using Minimal APIs with DTOs

**এটি কী:**
চ্যাপ্টার ৪-এ আমরা DTO (Data Transfer Object) শিখেছিলাম। Minimal API-তেও আমরা সরাসরি এনটিটি রিটার্ন না করে DTO ব্যবহার করব।

**কেন এটি কাজ করে:**
এটি সিকিউরিটি বাড়ায় এবং ক্লায়েন্টকে অপ্রয়োজনীয় ডেটা পাঠানো থেকে বিরত রাখে।

**কোড উদাহরণ:**

**DTO:**
```csharp
public record UserDto(string Name, int Age);
```

**API:**
```csharp
app.MapPost("/create-user", (UserDto user) => 
{
    return Results.Ok($"User {user.Name} created!");
});
```

### ২. Top-level Statements এবং Minimal Hosting

**বিষয়বস্তু:**
আগে `Program.cs` ফাইলে `namespace`, `class Program`, `static void Main(string[] args)`—এই সব লিখতে হতো। C# 9 এবং .NET 6 থেকে এগুলো আর লিখতে হয় না। সরাসরি কোড লিখলেই চলে। একে বলা হয় **Top-level Statements**।

**কোড উদাহরণ:**
আপনার `Program.cs` ফাইলে নিচের কোডটুকু লিখুন (আগের সব মুছে দিন):

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello, Minimal API!");

app.Run();
```

**লজিক ব্যাখ্যা:**
1.  `WebApplication.CreateBuilder(args)`: এটি অ্যাপ্লিকেশনের বিল্ডার তৈরি করে। এখান থেকেই আমরা **Dependency Injection (DI)**, **Configuration**, এবং **Logging** সেটআপ করি।
2.  `app.Build()`: এটি আমাদের অ্যাপটি তৈরি (Build) করে।
3.  `app.MapGet("/", ...)`: এটি একটি **Endpoint**। যখন কেউ ব্রাউজারে রুট URL-এ যাবে, তখন সে "Hello, Minimal API!" দেখতে পাবে।
4.  `app.Run()`: সার্ভার চালু করে।

### ৩. Minimal APIs: Endpoints তৈরি এবং কনফিগারেশন

**বিষয়বস্তু:**
Minimal API তে কন্ট্রোলার ছাড়াই সরাসরি `MapGet`, `MapPost`, `MapPut`, `MapDelete` মেথড ব্যবহার করে CRUD অপারেশন করা যায়।

**কোড উদাহরণ (একটি Todo List API):**

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// একটি ইন-মেমোরি ডাটাবেস হিসেবে লিস্ট
var todos = new List<TodoItem>();

// ১. GET: সব ডাটা দেখা
app.MapGet("/todos", () => todos);

// ২. POST: নতুন ডাটা যোগ করা
app.MapPost("/todos", (TodoItem task) =>
{
    todos.Add(task);
    return Results.Created($"/todos/{task.Id}", task);
});

// ৩. GET by ID: নির্দিষ্ট ডাটা খোঁজা
app.MapGet("/todos/{id}", (int id) =>
{
    var task = todos.FirstOrDefault(t => t.Id == id);
    return task is not null ? Results.Ok(task) : Results.NotFound();
});

app.Run();

// মডেল ক্লাস (ফাইলের নিচে লিখুন)
public record TodoItem(int Id, string Title, bool IsCompleted);
```

**লজিক ব্যাখ্যা:**
*   **প্যারামিটার বাইন্ডিং:** `MapPost`-এ আমরা `(TodoItem task)` প্যারামিটার দিয়েছি। ASP.NET Core অটোমেটিক্যালি ইনকামিং JSON রিকোয়েস্ট বডি থেকে ডাটা নিয়ে এই অবজেক্টে কনভার্ট করে দেয়।
*   **রিটার্ন টাইপ (`Results`):** আমরা `Results.Ok`, `Results.NotFound`, `Results.Created` ব্যবহার করেছি। এগুলো সঠিক HTTP Status Code (200, 404, 201) পাঠাতে সাহায্য করে।

### ৪. Endpoint Filters (এন্ডপয়েন্ট ফিল্টার)

**বিষয়বস্তু:**
ফিল্টার হলো এমন একটি লজিক যা আপনার API-তে রিকোয়েস্ট ঢোকার আগে বা রেসপন্স বের হওয়ার পরে রান করে। এটি কন্ট্রোলারের `Middleware` বা `ActionFilter`-এর মতো।

**কেন জরুরি:** লগিং, ভ্যালিডেশন বা অথেনটিফিকেশনের জন্য প্রতিটি এন্ডপয়েন্টে আলাদা কোড না লিখে একবার ফিল্টার বানালেই হয়।

**কোড উদাহরণ:**

```csharp
app.MapGet("/secure-data", () => "This is secret!")
   .AddEndpointFilter(async (context, next) =>
   {
       // ১. রিকোয়েস্টের আগে (Before Request)
       Console.WriteLine($"Request path: {context.HttpContext.Request.Path}");

       // ২. আসল লজিক এক্সিকিউট করা
       var result = await next(context);

       // ৩. রিকোয়েস্টের পরে (After Request)
       Console.WriteLine("Response sent.");

       return result;
   });
```

**লজিক:** `next(context)` কল করার মাধ্যমে রিকোয়েস্টটি পরবর্তী ধাপে পাঠানো হয়। এর আগে বা পরে আপনি আপনার কাস্টম লজিক বসাতে পারেন।

### ৫. Organizing Endpoints (কোড সাজানো)

**সমস্যা:**
সব API যদি `Program.cs` ফাইলে লিখি, তবে অ্যাপ বড় হলে ফাইলটি বিশাল ও অপরিচ্ছন্ন হয়ে যাবে।

**সমাধান:**
আমরা **Extension Methods** ব্যবহার করে কোডগুলো আলাদা ফাইলে রাখব।

**ধাপ ১: আলাদা ফাইল তৈরি করুন `TodoEndpoints.cs`**

```csharp
public static class TodoEndpoints
{
    public static void MapTodoRoutes(this WebApplication app)
    {
        app.MapGet("/api/items", () => "Item List");
        app.MapPost("/api/items", () => "Item Created");
    }
}
```

**ধাপ ২: `Program.cs` ক্লিন রাখা**

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// এক্সটেনশন মেথড কল করা হলো
app.MapTodoRoutes();

app.Run();
```

**কেন এটি জরুরি:** এটি আপনার প্রোজেক্টকে মডুলার করে এবং পড়তে সুবিধা দেয় (Clean Architecture)।

### ৬. Minimal API এবং DTO (Data Transfer Objects)

**বিষয়বস্তু:**
চ্যাপ্টার ৪-এ আমরা শিখেছিলাম যে ডাটাবেস এনটিটি সরাসরি ইউজারের কাছে পাঠানো নিরাপদ নয়। Minimal API-তেও আমরা DTO ব্যবহার করব।

**বাস্তব জীবনের উদাহরণ:**
ধরুন, একটি ইউজার রেজিস্ট্রেশন API। আমরা ইউজারের `Password` ইনপুট নেব, কিন্তু আউটপুটে পাসওয়ার্ড ফেরত দেব না।

**কোড উদাহরণ:**

```csharp
// DTOs
public record UserRegisterDto(string Username, string Password);
public record UserResponseDto(int Id, string Username);

// Fake Database
var users = new List<UserResponseDto>();

app.MapPost("/register", (UserRegisterDto userDto) =>
{
    // লজিক: পাসওয়ার্ড ছাড়া রেসপন্স তৈরি করা
    var newUser = new UserResponseDto(users.Count + 1, userDto.Username);
    users.Add(newUser);

    return Results.Ok(newUser);
});
```

**লজিক:** এখানে ইনপুট হিসেবে `UserRegisterDto` নেওয়া হয়েছে (যাতে পাসওয়ার্ড আছে), কিন্তু রিটার্ন করা হয়েছে `UserResponseDto` (যাতে পাসওয়ার্ড নেই)। এটি সিকিউরিটি নিশ্চিত করে।

### সাধারণ সমস্যা এবং সমাধান (Common Problems & Solutions)

**সমস্যা ১: Dependency Injection (DI) কিভাবে কাজ করে?**
*Minimal API তে কনস্ট্রাক্টর নেই, তাহলে সার্ভিস ইনজেক্ট করব কিভাবে?*
**সমাধান:** ল্যাম্বডা ফাংশনের প্যারামিটার হিসেবে সার্ভিস পাস করতে হয়।
```csharp
// সার্ভিস রেজিস্টার
builder.Services.AddSingleton<MyService>();

// ব্যবহার
app.MapGet("/do-work", (MyService service) => service.DoSomething());
```

**সমস্যা ২: কোড অনেক বড় হয়ে যাওয়া।**
*সমাধান:* উপরে দেখানো `Organizing Endpoints` পদ্ধতি ব্যবহার করে কোড আলাদা ফাইলে ভাগ করে ফেলুন।

### অধ্যায়ের সারসংক্ষেপ (Summary)

এই অধ্যায়ে আমরা যা শিখলাম:

১. **Minimal API** ব্যবহার করে মাত্র ৩-৪ লাইনে সার্ভার এবং API তৈরি করা সম্ভব, যা মাইক্রোসার্ভিসের জন্য চমৎকার।
২. **CRUD অপারেশন** (Get, Post, Put, Delete) খুব সহজেই `Map` মেথড দিয়ে করা যায়।
৩. **Endpoint Filters** ব্যবহার করে আমরা লগিং বা ভ্যালিডেশনের মতো ক্রস-কাটিং কনসার্ন হ্যান্ডেল করতে পারি।
৪. **Organization:** বড় প্রোজেক্টের জন্য সব কোড `Program.cs`-এ না লিখে আলাদা ফাইলে সাজানো উচিত।
৫. **DTO:** সব সময় ইনপুট এবং আউটপুটের জন্য আলাদা মডেল (DTO) ব্যবহার করা উচিত, যা অ্যাপ্লিকেশনের নিরাপত্তা ও পারফরম্যান্স বাড়ায়।

এই পদ্ধতিটি আধুনিক .NET অ্যাপ্লিকেশনের স্ট্যান্ডার্ড এবং এটি আপনার ডেভেলপমেন্ট স্পিড অনেক বাড়িয়ে দেবে।
