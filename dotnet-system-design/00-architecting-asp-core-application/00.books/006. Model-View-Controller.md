স্বাগতম! আমি আপনার ইনস্ট্রাক্টর। আজ আমরা **Chapter 6: Model-View-Controller (MVC)** নিয়ে বিস্তারিত আলোচনা করব।

চ্যাপ্টার ৫-এ আমরা **Minimal API** দেখেছিলাম যা ছোট এবং দ্রুত অ্যাপ্লিকেশনের জন্য দারুণ। কিন্তু এন্টারপ্রাইজ লেভেলের বড় অ্যাপ্লিকেশন, যেখানে শত শত API এন্ডপয়েন্ট এবং জটিল লজিক থাকে, সেখানে **MVC প্যাটার্ন** হলো ইন্ডাস্ট্রির স্ট্যান্ডার্ড। এটি কোডকে সুশৃঙ্খলভাবে সাজাতে সাহায্য করে।

আসুন, এই চ্যাপ্টারের প্রতিটি বিষয় সহজ বাংলায় বুঝে নিই।

### ১. MVC ডিজাইন প্যাটার্ন (The MVC Pattern)

**এটি কী:**
MVC হলো একটি আর্কিটেকচারাল প্যাটার্ন যা অ্যাপ্লিকেশনের দায়িত্বকে তিনটি প্রধান অংশে ভাগ করে:
1.  **Model (মডেল):** এটি অ্যাপ্লিকেশনের ডেটা এবং বিজনেস লজিক ধারণ করে। (যেমন: `Product` ক্লাস, ডাটাবেস লজিক)।
2.  **View (ভিউ):** ব্যবহারকারী যা দেখে। ওয়েব API-এর ক্ষেত্রে এটি সাধারণত **JSON** রেসপন্স। (প্রথাগত ওয়েব অ্যাপে এটি HTML পেজ)।
3.  **Controller (কন্ট্রোলার):** এটি হলো "ম্যানেজার"। এটি ইউজারের রিকোয়েস্ট গ্রহণ করে, মডেলের সাথে কথা বলে ডেটা প্রসেস করে এবং শেষে ভিউ (বা JSON) রিটার্ন করে।

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি **Separation of Concerns (SoC)** নীতি মেনে চলে। অর্থাৎ, ডেটা সেভ করার কোড এবং ডেটা দেখানোর কোড এক জায়গায় মিশে থাকে না।

**বাস্তব উদাহরণ (রেস্টুরেন্ট):**
*   **User:** আপনি (কাস্টমার)।
*   **Controller:** ওয়েটার (যে আপনার অর্ডার নেয় এবং কিচেনে জানায়)।
*   **Model:** কিচেন এবং শেফ (যেখানে খাবার বা ডেটা তৈরি হয়)।
*   **View:** সাজানো খাবার যা আপনার টেবিলে আসে (JSON Response)।

### ২. Anatomy of a Controller (কন্ট্রোলার কিভাবে কাজ করে)

**এটি কী:**
ASP.NET Core-এ কন্ট্রোলার হলো একটি C# ক্লাস যা `ControllerBase` থেকে ইনহেরিট করে।

**কেন এটি কাজ করে:**
`ControllerBase` ক্লাসে HTTP রিকোয়েস্ট হ্যান্ডেল করার জন্য অনেক বিল্ট-ইন মেথড থাকে (যেমন: `Ok()`, `NotFound()`, `BadRequest()`)।

**সমস্যা (Problems):**
নতুনরা অনেক সময় `ControllerBase`-এর বদলে `Controller` ক্লাস ইনহেরিট করে। `Controller` ক্লাসটি মূলত **MVC Views (HTML)** রেন্ডার করার জন্য, যা Web API-তে অপ্রয়োজনীয় মেমোরি খরচ করে।

**সমাধান:**
Web API বানানোর সময় সবসময় `ControllerBase` ব্যবহার করুন। আর ক্লাসের ওপরে `[ApiController]` অ্যাট্রিবিউট দিন।

**কোড উদাহরণ:**

```csharp
[ApiController] // এটি অটোমেটিক ভ্যালিডেশন চালু করে
[Route("api/[controller]")] // URL হবে api/products
public class ProductsController : ControllerBase
{
    // অ্যাকশন মেথড
    [HttpGet]
    public IActionResult GetAll()
    {
        return Ok("All products"); // 200 OK
    }
}
```

### ৩. Returning Values & Action Results

**এটি কী:**
কন্ট্রোলার থেকে আমরা কী ফেরত দেব? স্ট্রিং, অবজেক্ট নাকি স্ট্যাটাস কোড? ASP.NET Core-এ এর জন্য `IActionResult` বা `ActionResult<T>` ব্যবহার করা হয়।

**কেন এটি জরুরি:**
শুধু ডেটা পাঠালে হবে না, সাথে ব্রাউজারকে বলতে হবে রিকোয়েস্টটি সফল নাকি ব্যর্থ।
*   `Ok()` = 200 (সফল)
*   `NotFound()` = 404 (পাওয়া যায়নি)
*   `BadRequest()` = 400 (ভুল রিকোয়েস্ট)

**সুবিধা:**
এটি API-কে স্ট্যান্ডার্ড করে তোলে এবং ফ্রন্টএন্ড ডেভেলপারদের বুঝতে সুবিধা দেয় কী ঘটেছে।

**কোড উদাহরণ:**

```csharp
[HttpGet("{id}")]
public ActionResult<ProductDto> GetProduct(int id)
{
    var product = _service.Find(id);

    if (product == null)
    {
        return NotFound(); // 404 রিটার্ন করবে
    }

    return Ok(product); // 200 এবং ডেটা রিটার্ন করবে
}
```

### ৪. Using MVC with DTOs (DTO ব্যবহার করা)

**এটি কী:**
আমরা আগেই জেনেছি **DTO (Data Transfer Object)** হলো এমন একটি ক্লাস যা শুধু ডেটা আনা-নেওয়ার কাজ করে। এই চ্যাপ্টারে দেখানো হয়েছে কিভাবে কন্ট্রোলারে সরাসরি ডাটাবেস মডেল ব্যবহার না করে DTO ব্যবহার করতে হয়।

**কেন এটি কাজ করে:**
এটি আমাদের ডাটাবেস স্কিমাকে লুকিয়ে রাখে এবং API-এর কন্ট্রাক্ট ঠিক রাখে।

**সমস্যা (Problems - Over-posting Attack):**
যদি আপনি সরাসরি ডাটাবেস মডেল (Entity) ইনপুট হিসেবে নেন, তবে হ্যাকাররা এমন ফিল্ড আপডেট করে ফেলতে পারে যা তাদের করার কথা না (যেমন: `IsAdmin = true`)।

**সমাধান:**
ইনপুট এবং আউটপুটের জন্য আলাদা DTO ক্লাস ব্যবহার করুন।

**কোড উদাহরণ:**

**ভুল পদ্ধতি (সরাসরি মডেল ব্যবহার):**
```csharp
[HttpPost]
public IActionResult Create(User user) // সমস্যা: ইউজার IsAdmin ফিল্ড পাঠিয়ে দিতে পারে
{
    _db.Users.Add(user);
    return Ok();
}
```

**সঠিক পদ্ধতি (DTO ব্যবহার):**
```csharp
public record CreateUserDto(string Name, string Email); // এখানে IsAdmin ফিল্ড নেই

[HttpPost]
public IActionResult Create(CreateUserDto input)
{
    var user = new User 
    { 
        Name = input.Name, 
        Email = input.Email,
        IsAdmin = false // কোডে আমরা ফিক্সড করে দিলাম
    };
    
    _db.Users.Add(user);
    return Ok();
}
```

### ৫. Routing (রাউটিং)

**এটি কী:**
রাউটিং হলো ঠিকানা নির্ধারণ করা। ব্রাউজারের বারে কোন URL লিখলে কোন মেথডটি কল হবে, তা ঠিক করাই রাউটিং।

**কেন এটি কাজ করে:**
ASP.NET Core-এ আমরা **Attribute Routing** ব্যবহার করি। অর্থাৎ মেথডের ওপরেই বলে দিই তার ঠিকানা কী হবে।

**বাস্তব ব্যবহার:**
*   `[HttpGet("list")]` -> URL হবে `/api/products/list`
*   `[HttpGet("{id}")]` -> URL হবে `/api/products/5` (এখানে 5 হলো id)

### ৬. Dependency Injection in Controllers

**এটি কী:**
কন্ট্রোলার নিজে কোনো কাজ করে না, সে সার্ভিসের সাহায্য নেয়। আমরা `new` কিওয়ার্ড ব্যবহার না করে কনস্ট্রাক্টরের মাধ্যমে সার্ভিস ইনজেক্ট করি।

**সুবিধা:**
এতে কোডটি লুজলি কাপলড (Loosely Coupled) হয় এবং ইউনিট টেস্টিং করা খুব সহজ হয়।

**কোড উদাহরণ:**
```csharp
public class UsersController : ControllerBase
{
    private readonly IUserService _userService;

    // কনস্ট্রাক্টরে সার্ভিস চাওয়া হচ্ছে
    public UsersController(IUserService userService)
    {
        _userService = userService;
    }

    [HttpGet]
    public IActionResult Get()
    {
        // সার্ভিস ব্যবহার করা হচ্ছে
        return Ok(_userService.GetAllUsers());
    }
}
```

### অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

১. **MVC প্যাটার্ন:** বড় অ্যাপ্লিকেশনের জন্য কোডকে Model, View এবং Controller-এ ভাগ করে সাজানো সবচেয়ে ভালো উপায়।
২. **ControllerBase:** API তৈরির সময় `Controller` ক্লাসের বদলে `ControllerBase` ব্যবহার করতে হবে যাতে অপ্রয়োজনীয় ভিউ ফিচার লোড না হয়।
৩. **ActionResult:** সবসময় সঠিক HTTP Status Code (200, 404, 201) রিটার্ন করতে হবে, যা `ActionResult` দিয়ে সহজেই করা যায়।
৪. **DTO is Must:** সিকিউরিটি এবং মেইনটেইনেবিলিটির জন্য কন্ট্রোলারে সরাসরি ডাটাবেস মডেল ব্যবহার না করে DTO ব্যবহার করতে হবে।
৫. **Routing:** Attribute routing ব্যবহার করে URL-কে পরিষ্কার এবং বোধগম্য রাখতে হবে।

এই অধ্যায়টি আপনাকে শেখায় কিভাবে একটি **Production-Grade** বা পেশাদার মানের API স্ট্রাকচার তৈরি করতে হয়।

### ১. সেটআপ এবং প্রয়োজনীয় টুলস (Setup & Tools)

MVC প্যাটার্নে কাজ করার জন্য আমাদের প্রোজেক্টে কন্ট্রোলার সার্ভিস যুক্ত করতে হয়।

**প্রয়োজনীয় সফটওয়্যার:**
1.  **.NET 8 SDK**
2.  **Visual Studio 2022** বা **VS Code**
3.  **Postman** (API টেস্ট করার জন্য)

**প্রোজেক্ট সেটআপ ধাপ:**

১. টার্মিনাল ওপেন করুন এবং নিচের কমান্ডটি দিন:
```bash
dotnet new webapi -n MyMvcDemo
cd MyMvcDemo
```

২. **`Program.cs` কনফিগারেশন:**
Minimal API তে আমরা সরাসরি `app.MapGet` ব্যবহার করতাম। কিন্তু MVC তে আমাদের কন্ট্রোলারগুলো রেজিস্টার করতে হয়। `Program.cs` ফাইলে নিচের লাইনগুলো আছে কি না নিশ্চিত করুন (বা লিখুন):

```csharp
var builder = WebApplication.CreateBuilder(args);

// ১. কন্টেইনারে কন্ট্রোলার সার্ভিস যুক্ত করা হচ্ছে
builder.Services.AddControllers(); 

var app = builder.Build();

// ২. রাউটিং এবং কন্ট্রোলার ম্যাপ করা হচ্ছে
app.MapControllers(); 

app.Run();
```

*   **কেন এটি জরুরি:** `AddControllers()` মেথডটি ASP.NET Core-কে বলে যে আমরা এই অ্যাপে কন্ট্রোলার ভিত্তিক আর্কিটেকচার ব্যবহার করব। আর `MapControllers()` মেথডটি অ্যাপ রান করার সময় অটোমেটিক্যালি সব কন্ট্রোলার খুঁজে বের করে তাদের রাউট বা URL তৈরি করে দেয়।

### ২. কোড ইমপ্লিমেন্টেশন: MVC প্যাটার্ন

MVC মানে হলো **Model**, **View**, এবং **Controller**। তবে Web API-তে **View** বলতে সাধারণত **JSON ডেটা** বোঝায় যা ক্লায়েন্টকে পাঠানো হয়।

আমরা একটি **Product API** তৈরি করব।

#### ধাপ ১: মডেল এবং DTO তৈরি (Model & DTO)

বইটিতে বারবার বলা হয়েছে, কখনোই ডাটাবেস এনটিটি (Model) সরাসরি ইউজারের কাছে পাঠাবেন না। এর জন্য **DTO (Data Transfer Object)** ব্যবহার করতে হবে।

```csharp
namespace MyMvcDemo.Models;

// ১. ডোমেইন মডেল (ডাটাবেসের আসল টেবিল)
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public bool IsInStock { get; set; }
    public string SecretSupplierCode { get; set; } // সিক্রেট তথ্য
}

// ২. DTO (যা ইউজারকে দেখানো হবে)
public record ProductDto(int Id, string Name, decimal Price);

// ৩. ইনপুট DTO (প্রোডাক্ট তৈরির জন্য)
public record CreateProductDto(string Name, decimal Price);
```

**লজিক:** `Product` ক্লাসে `SecretSupplierCode` আছে যা আমরা ইউজারকে দেখাতে চাই না। তাই `ProductDto` তে আমরা শুধু প্রয়োজনীয় তথ্য রেখেছি। এটি **Security** এবং **Abstraction** নিশ্চিত করে।

#### ধাপ ২: কন্ট্রোলার তৈরি (The Controller)

`Controllers` ফোল্ডারে `ProductsController.cs` নামে একটি ফাইল তৈরি করুন।

```csharp
using Microsoft.AspNetCore.Mvc;
using MyMvcDemo.Models;

namespace MyMvcDemo.Controllers;

[ApiController] // ১. এটি এপিআই বিহেভিয়ার (যেমন ভ্যালিডেশন) চালু করে
[Route("api/[controller]")] // ২. URL প্যাটার্ন: api/products
public class ProductsController : ControllerBase // ৩. ControllerBase ইনহেরিট করা
{
    // সিম্পলিসিটির জন্য স্ট্যাটিক লিস্ট (বাস্তবে এটি ডাটাবেস হবে)
    private static readonly List<Product> _products = new()
    {
        new Product { Id = 1, Name = "Laptop", Price = 50000, IsInStock = true, SecretSupplierCode = "X123" }
    };

    // GET: api/products
    [HttpGet]
    public ActionResult<IEnumerable<ProductDto>> GetAll()
    {
        // ডোমেইন মডেল থেকে DTO তে কনভার্ট করা
        var dtoList = _products.Select(p => new ProductDto(p.Id, p.Name, p.Price));
        
        return Ok(dtoList); // 200 OK স্ট্যাটাস
    }

    // GET: api/products/1
    [HttpGet("{id}")]
    public ActionResult<ProductDto> GetById(int id)
    {
        var product = _products.FirstOrDefault(p => p.Id == id);

        if (product == null)
        {
            return NotFound(); // 404 Not Found
        }

        return Ok(new ProductDto(product.Id, product.Name, product.Price));
    }

    // POST: api/products
    [HttpPost]
    public ActionResult<ProductDto> Create([FromBody] CreateProductDto input)
    {
        // ইনপুট ভ্যালিডেশন (যেমন: নাম খালি কি না) [ApiController] অটোমেটিক চেক করে
        
        // নতুন আইডি জেনারেট
        var newId = _products.Max(p => p.Id) + 1;

        // DTO থেকে ডোমেইন মডেলে কনভার্ট
        var newProduct = new Product
        {
            Id = newId,
            Name = input.Name,
            Price = input.Price,
            IsInStock = true, // ডিফল্ট লজিক
            SecretSupplierCode = "GEN_CODE" // ইন্টারনাল লজিক
        };

        _products.Add(newProduct);

        var responseDto = new ProductDto(newProduct.Id, newProduct.Name, newProduct.Price);

        // 201 Created স্ট্যাটাস এবং নতুন আইটেমের লিংক রিটার্ন করা
        return CreatedAtAction(nameof(GetById), new { id = newId }, responseDto);
    }
}
```

### ৩. কোডের পেছনের লজিক ও ব্যাখ্যা

**১. `ControllerBase` বনাম `Controller`:**
কোডে খেয়াল করুন আমরা `ControllerBase` ইনহেরিট করেছি, `Controller` নয়।
*   **কারণ:** `Controller` ক্লাসটি মূলত MVC ভিউ (HTML) রেন্ডার করার জন্য ব্যবহৃত হয়। যেহেতু আমরা API বানাচ্ছি, তাই `ControllerBase` ব্যবহার করা হালকা এবং দ্রুত।

**২. `[ApiController]` অ্যাট্রিবিউট:**
এটি একটি ম্যাজিকের মতো কাজ করে। যদি ইউজার ভুল ডেটা পাঠায় (যেমন `Price`-এ টেক্সট), তবে কন্ট্রোলারের ভেতরে কোড ঢোকার আগেই এটি অটোমেটিক `400 Bad Request` রিটার্ন করে দেয়। ম্যানুয়ালি `if (!ModelState.IsValid)` লেখার দরকার হয় না।

**৩. `ActionResult<T>`:**
এটি আমাদের ফ্লেক্সিবিলিটি দেয়। আমরা চাইলে সফল হলে `ProductDto` অবজেক্ট পাঠাতে পারি, আবার ভুল হলে `NotFound()` বা `BadRequest()` এর মতো HTTP স্ট্যাটাস পাঠাতে পারি।

**৪. Mapping (মডেল টু DTO):**
আমরা ম্যানুয়ালি `Select` ব্যবহার করে ম্যাপ করেছি। বড় প্রোজেক্টে আমরা **AutoMapper** বা **Mapperly** (চ্যাপ্টার ১৫-তে বিস্তারিত আছে) ব্যবহার করি যাতে বারবার এই কনভার্সন কোড লিখতে না হয়।

### ৪. সাধারণ সমস্যা এবং সমাধান (Common Problems & Solutions)

**সমস্যা ১: Fat Controllers (মোটা কন্ট্রোলার)**
অনেক সময় ডেভেলপাররা সব বিজনেস লজিক (যেমন ডিসকাউন্ট হিসাব করা, ইনভেন্টরি চেক করা) কন্ট্রোলারের ভেতরে লিখে ফেলে। এতে কন্ট্রোলার অনেক বড় হয়ে যায়।
*   **সমাধান:** কন্ট্রোলারের কাজ শুধু রিকোয়েস্ট নেওয়া এবং রেসপন্স দেওয়া। জটিল লজিকের জন্য **Service Layer** ব্যবহার করুন এবং Dependency Injection (DI) এর মাধ্যমে তা কন্ট্রোলারে ব্যবহার করুন।

**সমস্যা ২: Over-Posting**
যদি `Create` মেথডে সরাসরি `Product` ক্লাস প্যারামিটার হিসেবে নিতেন, তবে হ্যাকার `SecretSupplierCode` বা `Id` ম্যানুয়ালি সেট করে পাঠাতে পারত।
*   **সমাধান:** সবসময় `CreateProductDto` বা আলাদা ইনপুট ক্লাস ব্যবহার করুন যেখানে শুধু প্রয়োজনীয় ফিল্ডগুলো থাকবে।

### ৫. বাস্তব উদাহরণ (Real-World Scenario)

কল্পনা করুন একটি **ফুড ডেলিভারি অ্যাপ** (যেমন Foodpanda বা Pathao Food):

1.  **Model:** `Order` টেবিলে কাস্টমারের নাম, খাবার, দাম, ডেলিভারি বয় আইডি, এবং পেমেন্ট স্ট্যাটাস আছে।
2.  **Controller:** যখন আপনি "Order Now" বাটনে চাপ দেন, অ্যাপটি `OrdersController`-এর `PlaceOrder` মেথডে হিট করে।
3.  **DTO:** আপনি যখন অর্ডার করেন, তখন শুধু খাবারের নাম আর পরিমাণ পাঠান। পেমেন্ট স্ট্যাটাস বা ডেলিভারি বয়ের আইডি আপনি সেট করেন না। কন্ট্রোলার আপনার পাঠানো `OrderDto` রিসিভ করে।
4.  **Logic:** কন্ট্রোলার `OrderService`-কে ডাকে। সার্ভিস চেক করে রেস্টুরেন্ট খোলা আছে কি না। সব ঠিক থাকলে ডাটাবেসে সেভ করে।
5.  **Response:** সবশেষে কন্ট্রোলার আপনাকে একটি `OrderConfirmedDto` পাঠায়, যেখানে লেখা থাকে "অর্ডার সফল, ৩০ মিনিটের মধ্যে পৌঁছাবে"।

### ৬. অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

এই অধ্যায়ের মূল শিক্ষণীয় বিষয়গুলো হলো:

*   **স্ট্রাকচার:** Minimal API ছোট প্রজেক্টের জন্য ভালো হলেও, বড় এবং জটিল প্রজেক্টের জন্য **MVC Controller** ব্যবহার করা ভালো কারণ এটি কোডকে সুশৃঙ্খল রাখে।
*   **ControllerBase:** API তৈরির জন্য সব সময় `ControllerBase` ব্যবহার করুন, `Controller` নয়।
*   **DTO প্যাটার্ন:** সিকিউরিটি এবং লজিক আলাদা রাখার জন্য ডাটাবেস মডেল এবং API মডেল (DTO) সব সময় আলাদা রাখুন।
*   **HTTP স্ট্যান্ডার্ড:** সঠিক স্ট্যাটাস কোড (`200`, `201`, `404`) এবং মেথড (`GET`, `POST`) ব্যবহার করা প্রফেশনাল API-এর লক্ষণ।
*   **Separation of Concerns:** কন্ট্রোলারে বিজনেস লজিক না লিখে, কন্ট্রোলারকে শুধু ট্রাফিক পুলিশ (Traffic Cop) হিসেবে ব্যবহার করুন যে রিকোয়েস্ট রিসিভ করে সঠিক সার্ভিসের কাছে পাঠিয়ে দেয়।

এই চ্যাপ্টারটি আপনাকে একটি প্রোডাকশন-গ্রেড API আর্কিটেকচার দাঁড় করানোর আত্মবিশ্বাস দেবে।
