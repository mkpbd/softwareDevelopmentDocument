
স্বাগতম! আমি আপনার ইনস্ট্রাক্টর। আজ আমরা **Chapter 9: Options, Settings, and Configuration** নিয়ে বিস্তারিত আলোচনা করব।

যেকোনো প্রফেশনাল অ্যাপ্লিকেশনে কিছু **Settings** বা **Configuration** থাকে (যেমন: ডাটাবেস কানেকশন স্ট্রিং, ইমেইল সার্ভার কনফিগারেশন, বা API Key)। এই চ্যাপ্টারটি আমাদের শেখায় কিভাবে এই সেটিংসগুলো কোডের ভেতরে হার্ডকোড না করে, বাইরের ফাইল (`appsettings.json`) বা এনভায়রনমেন্ট ভেরিয়েবল থেকে নিরাপদে এবং স্মার্টলি ম্যানেজ করা যায়।

একে বলা হয় **The Options Pattern**। আসুন ধাপে ধাপে শিখি।

### ১. The Options Pattern (অপশনস প্যাটার্ন)

**এটি কী:**
Options Pattern হলো এমন একটি টেকনিক যার মাধ্যমে আমরা `appsettings.json` ফাইলের কনফিগারেশন ডেটাকে C# ক্লাসের (Class) সাথে ম্যাপ (Map) বা বাইন্ডিং করি। একে **Strongly Typed Configuration** বলা হয়।

**কেন এটি কাজ করে ও কেন জরুরি:**
সাধারণত আমরা `Configuration["MySetting"]` লিখে স্ট্রিং হিসেবে ডেটা পড়ি। এতে বানান ভুল হওয়ার সম্ভাবনা থাকে। Options Pattern ব্যবহার করলে আমরা সেটিংসগুলোকে একটি ক্লাসের প্রপার্টি হিসেবে পাই, যা নিরাপদ এবং Intellisense সাপোর্ট করে।

**কোড উদাহরণ:**

১. `appsettings.json` ফাইলে সেটিংস:
```json
{
  "EmailSettings": {
    "SmtpServer": "smtp.gmail.com",
    "Port": 587
  }
}
```

২. C# ক্লাস তৈরি (POCO Class):
```csharp
public class EmailOptions
{
    public string SmtpServer { get; set; }
    public int Port { get; set; }
}
```

৩. `Program.cs`-এ কনফিগারেশন বাইন্ডিং:
```csharp
builder.Services.Configure<EmailOptions>(
    builder.Configuration.GetSection("EmailSettings"));
```

### ২. Options Interfaces (IOptions, IOptionsSnapshot, IOptionsMonitor)

এটি এই চ্যাপ্টারের **সবচেয়ে গুরুত্বপূর্ণ** অংশ। কনফিগারেশন ডেটা পড়ার জন্য .NET আমাদের ৩টি ইন্টারফেস দেয়। এদের কাজ এবং পার্থক্য বোঝা জরুরি।

#### ক. `IOptions<T>`
*   **কাজ:** অ্যাপ্লিকেশন চালু হওয়ার সময় (Startup) একবার কনফিগারেশন পড়ে এবং ক্যাশ (Cache) করে রাখে।
*   **লাইফটাইম:** Singleton (পুরো অ্যাপে একটাই কপি থাকে)।
*   **সমস্যা:** অ্যাপ চলাকালীন যদি আপনি `appsettings.json` ফাইল পরিবর্তন করেন, `IOptions` সেই পরিবর্তন বুঝতে পারে না। এটি পুরাতন ভ্যালুই দেখাতে থাকে।
*   **কখন ব্যবহার করবেন:** যেসব সেটিংস অ্যাপ রিস্টার্ট ছাড়া পরিবর্তন হয় না (যেমন: অ্যাপের নাম)।

#### খ. `IOptionsSnapshot<T>`
*   **কাজ:** প্রতিবার নতুন HTTP রিকোয়েস্ট আসলে এটি কনফিগারেশন ফাইল আবার পড়ে দেখে।
*   **লাইফটাইম:** Scoped (প্রতি রিকোয়েস্টে নতুন)।
*   **সুবিধা:** অ্যাপ রিস্টার্ট না করেই কনফিগারেশন পরিবর্তন করা যায়।
*   **সমস্যা:** এটি Singleton সার্ভিসের ভেতরে ইনজেক্ট করা যায় না।
*   **কখন ব্যবহার করবেন:** যখন আপনি চান অ্যাপ রিস্টার্ট না করেই সেটিংস আপডেট হোক।

#### গ. `IOptionsMonitor<T>`
*   **কাজ:** এটি রিয়েল-টাইমে কনফিগারেশন পরিবর্তন মনিটর করে।
*   **লাইফটাইম:** Singleton.
*   **সুবিধা:** এটি Singleton সার্ভিসের ভেতরেও ব্যবহার করা যায় এবং চেঞ্জ নোটিফিকেশন দেয়।
*   **কখন ব্যবহার করবেন:** হাই-পারফরম্যান্স এবং ডাইনামিক কনফিগারেশনের জন্য।

**কোড উদাহরণ (Controller-এ ব্যবহার):**

```csharp
public class HomeController : ControllerBase
{
    private readonly EmailOptions _options;

    // এখানে IOptions, IOptionsSnapshot বা IOptionsMonitor ব্যবহার করা যাবে
    public HomeController(IOptionsSnapshot<EmailOptions> options)
    {
        _options = options.Value; // .Value দিয়ে ডেটা নিতে হয়
    }

    [HttpGet]
    public IActionResult Get()
    {
        return Ok($"Server: {_options.SmtpServer}");
    }
}
```

### ৩. Options Validation (সেটিংস যাচাইকরণ)

**এটি কী:**
অ্যাপ্লিকেশন চালু হওয়ার আগেই কনফিগারেশন ডেটা সঠিক কি না তা যাচাই করা।

**কেন এটি জরুরি:**
ধরুন, কেউ `appsettings.json` এ `Port` নম্বর দিতে ভুলে গেল। ভ্যালিডেশন না থাকলে অ্যাপটি রান করবে, কিন্তু ইমেইল পাঠানোর সময় ক্র্যাশ করবে। ভ্যালিডেশন থাকলে অ্যাপ চালু হওয়ার সময়ই এরর দেবে, যা ডিবাগ করা সহজ।

**সমাধান (Data Annotations):**

১. ক্লাসে অ্যানোটেশন যোগ করুন:
```csharp
public class EmailOptions
{
    [Required] // অবশ্যই থাকতে হবে
    public string SmtpServer { get; set; }

    [Range(0, 65535)] // পোর্ট নম্বর এই রেঞ্জের মধ্যে হতে হবে
    public int Port { get; set; }
}
```

২. `Program.cs` এ ভ্যালিডেশন চালু করুন:
```csharp
builder.Services.AddOptions<EmailOptions>()
    .Bind(builder.Configuration.GetSection("EmailSettings"))
    .ValidateDataAnnotations() // ভ্যালিডেশন চেক করবে
    .ValidateOnStart(); // অ্যাপ চালুর শুরুতেই চেক করবে
```

### ৪. Post-Configuration (কনফিগারেশনের পরে মডিফিকেশন)

**এটি কী:**
কনফিগারেশন ফাইল থেকে ডেটা পড়ার **পর** কিন্তু অ্যাপে ব্যবহার করার **আগে** যদি আপনি কোনো লজিক দিয়ে ভ্যালু পরিবর্তন করতে চান।

**বাস্তব ব্যবহার:**
ধরুন, ইউজার যদি `Port` নম্বর না দেয়, আপনি কোডের মাধ্যমে ডিফল্ট পোর্ট ৮০ সেট করে দিতে চান।

**কোড উদাহরণ:**
```csharp
builder.Services.PostConfigure<EmailOptions>(options =>
{
    if (options.Port == 0)
    {
        options.Port = 80; // ডিফল্ট ভ্যালু সেট করা হলো
    }
});
```

### ৫. Configuration Providers (কনফিগারেশনের উৎস)

**এটি কী:**
ASP.NET Core শুধু `json` ফাইল থেকেই নয়, আরও অনেক জায়গা থেকে সেটিংস পড়তে পারে। একে বলা হয় কনফিগারেশন প্রোভাইডার।

**অর্ডার (Hierarchy):**
ASP.NET Core নিচের ক্রমানুসারে সেটিংস পড়ে (নিচেরটি উপরেরটিকে ওভাররাইড করে):
1.  `appsettings.json`
2.  `appsettings.Development.json` (এনভায়রনমেন্ট ভিত্তিক)
3.  **User Secrets** (লোকাল পিসির সিক্রেট স্টোরেজ)
4.  **Environment Variables** (সার্ভার বা ডকার কন্টেইনারের ভেরিয়েবল)
5.  **Command Line Arguments**

**কেন এটি জরুরি:**
পাসওয়ার্ড বা সিক্রেট কি (Secret Key) কখনো কোডে বা `json` ফাইলে রাখা উচিত নয়। ডেভেলপমেন্টের সময় **User Secrets** এবং প্রোডাকশনে **Environment Variables** বা **Azure Key Vault** ব্যবহার করা নিরাপদ।

### অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

১. **Options Pattern:** হার্ডকোড না করে ক্লাস এবং অবজেক্টের মাধ্যমে কনফিগারেশন ম্যানেজ করুন।
২. **Interface Choice:**
    *   স্থির ডেটার জন্য `IOptions`।
    *   ডাইনামিক আপডেটের জন্য `IOptionsSnapshot`।
    *   সিঙ্গেলটন সার্ভিসে আপডেটের জন্য `IOptionsMonitor`।
৩. **Validation:** `ValidateDataAnnotations` এবং `ValidateOnStart` ব্যবহার করুন যাতে ভুল কনফিগারেশন থাকলে অ্যাপ শুরুতেই সতর্ক করে দেয়।
৪. **Security:** পাসওয়ার্ড কখনোই `appsettings.json`-এ রাখবেন না, `User Secrets` বা `Environment Variables` ব্যবহার করুন।

এই চ্যাপ্টারটি আপনাকে শেখায় কিভাবে একটি অ্যাপ্লিকেশনের "সেটিংস" বা "কনফিগারেশন" পেশাদার উপায়ে এবং নিরাপদে পরিচালনা করতে হয়।

চলুন, সেটআপ থেকে শুরু করে কোডিং পর্যন্ত সবকিছু হাতে-কলমে শিখি।

### ২. কোড ইমপ্লিমেন্টেশন: The Options Pattern

আমরা একটি **Email Service Configuration** তৈরি করব। আমরা দেখব কিভাবে JSON ফাইল থেকে ডেটা C# ক্লাসে আনা যায়।

#### ধাপ ১: `appsettings.json` ফাইলে সেটিংস যোগ করা

প্রজেক্টের `appsettings.json` ফাইলটি খুলুন এবং নিচের অংশটি যোগ করুন:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  // আমাদের নতুন কনফিগারেশন সেকশন
  "EmailSettings": {
    "SenderName": "My Support Team",
    "SmtpServer": "smtp.example.com",
    "Port": 587,
    "EnableSsl": true
  }
}
```
*   **কেন:** আমরা কনফিগারেশন ডেটা কোড থেকে আলাদা রাখছি যাতে অ্যাপ রিকম্পাইল না করেই সেটিংস বদলানো যায়।

#### ধাপ ২: C# ক্লাস তৈরি (POCO Class)

এখন এই JSON স্ট্রাকচারের সাথে মিল রেখে একটি ক্লাস বানাতে হবে। একটি নতুন ফাইল `EmailOptions.cs` তৈরি করুন:

```csharp
public class EmailOptions
{
    // নামগুলো JSON প্রপার্টির সাথে হুবহু মিলতে হবে
    public string SenderName { get; set; }
    public string SmtpServer { get; set; }
    public int Port { get; set; }
    public bool EnableSsl { get; set; }
}
```
*   **লজিক:** এটি একটি সাধারণ ক্লাস যা আমাদের কনফিগারেশন ডেটা ধারণ করবে। একে বলা হয় **Strongly Typed Configuration**।

#### ধাপ ৩: কনফিগারেশন বাইন্ডিং (Program.cs)

এখন আমাদের DI (Dependency Injection) কন্টেইনারকে বলতে হবে যে, `EmailSettings` সেকশনটি `EmailOptions` ক্লাসের সাথে যুক্ত।

`Program.cs` ফাইলে `builder.Build()` এর আগে লিখুন:

```csharp
// ১. কনফিগারেশন বাইন্ডিং
builder.Services.Configure<EmailOptions>(
    builder.Configuration.GetSection("EmailSettings"));

// ২. কন্ট্রোলার এবং সোয়াগার সেটআপ (ডিফল্ট থাকে)
builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
```

### ৩. কনফিগারেশন ব্যবহার করা (The 3 Interfaces)

ASP.NET Core আমাদের ৩টি ইন্টারফেস দেয় কনফিগারেশন পড়ার জন্য। এদের পার্থক্য বোঝা খুব জরুরি। আমরা একটি কন্ট্রোলার বানিয়ে এগুলো টেস্ট করব।

`Controllers` ফোল্ডারে `ConfigTestController.cs` নামে একটি ফাইল তৈরি করুন:

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.Options;

[ApiController]
[Route("api/[controller]")]
public class ConfigTestController : ControllerBase
{
    // ৩টি ভিন্ন ইন্টারফেস ডিক্লেয়ার করা হলো
    private readonly IOptions<EmailOptions> _options;
    private readonly IOptionsSnapshot<EmailOptions> _snapshot;
    private readonly IOptionsMonitor<EmailOptions> _monitor;

    public ConfigTestController(
        IOptions<EmailOptions> options,
        IOptionsSnapshot<EmailOptions> snapshot,
        IOptionsMonitor<EmailOptions> monitor)
    {
        _options = options;
        _snapshot = snapshot;
        _monitor = monitor;
    }

    [HttpGet]
    public IActionResult GetConfig()
    {
        var response = new
        {
            // ১. IOptions: অ্যাপ চালুর সময়ের ভ্যালু দেখাবে (Singleton)
            IOptionsValue = _options.Value.SenderName,

            // ২. IOptionsSnapshot: প্রতি রিকোয়েস্টে লেটেস্ট ভ্যালু দেখাবে (Scoped)
            SnapshotValue = _snapshot.Value.SenderName,

            // ৩. IOptionsMonitor: রিয়েল-টাইম লেটেস্ট ভ্যালু দেখাবে (Singleton)
            MonitorValue = _monitor.CurrentValue.SenderName
        };

        return Ok(response);
    }
}
```

**লজিক ও ব্যাখ্যা:**
1.  `IOptions<T>`: এটি **Singleton**। অ্যাপ চালু হওয়ার সময় একবার কনফিগারেশন পড়ে এবং মেমোরিতে রেখে দেয়। অ্যাপ চলাকালীন `appsettings.json` বদলালে এটি আপডেট হয় না।
2.  `IOptionsSnapshot<T>`: এটি **Scoped**। প্রতিবার ব্রাউজার রিফ্রেশ বা নতুন রিকোয়েস্ট আসলে এটি ফাইল চেক করে। এটি লাইভ আপডেট নিতে পারে।
3.  `IOptionsMonitor<T>`: এটি **Singleton** কিন্তু এটি ফাইলের পরিবর্তন মনিটর করে। ফাইল সেভ করলেই এটি আপডেট হয়ে যায়।

### ৪. ভ্যালিডেশন (Configuration Validation)

ভুল কনফিগারেশন দিলে যেন অ্যাপ শুরুতেই এরর দেয়, তার জন্য আমরা **Data Annotations** ব্যবহার করব।

১. `EmailOptions.cs` আপডেট করুন:
```csharp
using System.ComponentModel.DataAnnotations;

public class EmailOptions
{
    [Required] // নাম খালি রাখা যাবে না
    public string SenderName { get; set; }
    
    [Required]
    public string SmtpServer { get; set; }

    [Range(1, 65535)] // পোর্ট নম্বর অবশ্যই ভ্যালিড রেঞ্জ হতে হবে
    public int Port { get; set; }
    
    public bool EnableSsl { get; set; }
}
```

২. `Program.cs` আপডেট করুন:
```csharp
builder.Services.AddOptions<EmailOptions>()
    .Bind(builder.Configuration.GetSection("EmailSettings"))
    .ValidateDataAnnotations() // ভ্যালিডেশন চালু হলো
    .ValidateOnStart(); // অ্যাপ স্টার্ট হওয়ার সময় চেক করবে
```

### ৫. সাধারণ সমস্যা এবং সমাধান (Common Problems)

**সমস্যা ১: কনফিগারেশন আপডেট হচ্ছে না**
*   **কারণ:** আপনি `IOptions<T>` ব্যবহার করেছেন এবং অ্যাপ রান অবস্থায় ফাইল এডিট করেছেন।
*   **সমাধান:** `IOptionsSnapshot<T>` (কন্ট্রোলারের জন্য) অথবা `IOptionsMonitor<T>` ব্যবহার করুন।

**সমস্যা ২: Scoped Service in Singleton Error**
*   **কারণ:** আপনি একটি **Singleton** সার্ভিসের কনস্ট্রাক্টরে `IOptionsSnapshot` ইনজেক্ট করার চেষ্টা করেছেন। `Snapshot` হলো Scoped, তাই এটি Singleton-এ ঢুকতে পারে না।
*   **সমাধান:** Singleton সার্ভিসের ভেতরে লাইভ আপডেট চাইলে `IOptionsMonitor` ব্যবহার করুন।

**সমস্যা ৩: সিকিউরিটি (পাসওয়ার্ড ফাঁস)**
*   **কারণ:** `appsettings.json` গিটহাবে পুশ করলে পাসওয়ার্ড লিক হতে পারে।
*   **সমাধান:** লোকাল ডেভেলপমেন্টের জন্য **User Secrets** (Right click project -> Manage User Secrets) এবং প্রোডাকশনের জন্য **Environment Variables** বা **Azure Key Vault** ব্যবহার করুন।

### ৬. বাস্তব উদাহরণ (Real-World Scenario)

মনে করুন আপনি একটি অ্যাপ চালাচ্ছেন এবং হঠাৎ করে আপনার ইমেইল প্রোভাইডারের নাম পরিবর্তন করতে হবে বা সাইটের মেইনটেইনেন্স মোড অন করতে হবে।

1.  অ্যাপ স্টপ না করেই আপনি `appsettings.json` ফাইলে `SenderName` পরিবর্তন করে সেভ করলেন।
2.  যেহেতু আপনি `IOptionsSnapshot` ব্যবহার করেছেন, পরবর্তী ইউজার যখন পেজ রিফ্রেশ করবে, সে সাথে সাথে নতুন নাম দেখতে পাবে। সার্ভার রিস্টার্ট বা ডাউনটাইমের প্রয়োজন হবে না।
3.  যদি ভুল করে পোর্টের জায়গায় `-1` দেন, তবে অ্যাপ স্টার্ট হওয়ার সময় `ValidateOnStart` আপনাকে লাল এরর মেসেজ দিয়ে জানিয়ে দেবে, ফলে প্রোডাকশনে গিয়ে অ্যাপ ক্র্যাশ করবে না।

### ৭. অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

এই অধ্যায় থেকে আমরা যা শিখলাম:

*   **Options Pattern:** হার্ডকোডেড ভ্যালুর বদলে আমরা কনফিগারেশনকে C# ক্লাসে রূপান্তর (Bind) করি।
*   **ইন্টারফেস চয়েস:**
    *   `IOptions`: স্ট্যাটিক কনফিগারেশন (একবার লোড হয়)।
    *   `IOptionsSnapshot`: ডাইনামিক কনফিগারেশন (প্রতি রিকোয়েস্টে আপডেট)।
    *   `IOptionsMonitor`: ডাইনামিক কনফিগারেশন + সিঙ্গেলটন সাপোর্ট।
*   **Validation:** `ValidateDataAnnotations` এবং `ValidateOnStart` ব্যবহার করে ভুল কনফিগারেশন আটকানো যায়।
*   **Security:** সেনসিটিভ তথ্য JSON ফাইলে না রেখে User Secrets বা Environment Variable-এ রাখা উচিত।

এই পদ্ধতিগুলো আপনার অ্যাপ্লিকেশনকে **Flexible**, **Maintainable**, এবং **Secure** করে তোলে।
