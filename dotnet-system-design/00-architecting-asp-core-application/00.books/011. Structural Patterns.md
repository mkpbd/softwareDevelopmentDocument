### ১. Decorator Design Pattern

**এটি কী:**
Decorator প্যাটার্ন হলো এমন একটি টেকনিক যা আপনাকে কোনো একটি ক্লাসের কোড পরিবর্তন না করেই রানটাইমে (Runtime) সেই ক্লাসের বা অবজেক্টের আচরণ (Behavior) বা ফিচার যুক্ত করতে দেয়। এটি মূলত একটি অবজেক্টকে আরেকটি অবজেক্ট দিয়ে "র‍্যাপ" (Wrap) বা মুড়িয়ে ফেলার মাধ্যমে কাজ করে।

**সহজ উদাহরণ (কফি শপ):**
মনে করুন আপনার একটি `SimpleCoffee` ক্লাস আছে। এখন আপনি এতে দুধ (Milk) বা চিনি (Sugar) মেশাতে চান।
*   আপনি `SimpleCoffee` ক্লাসটি এডিট করবেন না।
*   বরং, একটি `MilkDecorator` ক্লাস দিয়ে কফিটিকে মুড়িয়ে দেবেন। এখন এটি হয়ে গেল "দুধসহ কফি"।

**কোড উদাহরণ:**

```csharp
// ১. ইন্টারফেস
public interface ICoffee
{
    string GetDescription();
    double GetCost();
}

// ২. মূল ক্লাস
public class SimpleCoffee : ICoffee
{
    public string GetDescription() => "Simple Coffee";
    public double GetCost() => 50.0;
}

// ৩. ডেকোরেটর ক্লাস
public class MilkDecorator : ICoffee
{
    private readonly ICoffee _coffee; // মূল কফিকে মুড়িয়ে রাখা হচ্ছে

    public MilkDecorator(ICoffee coffee)
    {
        _coffee = coffee;
    }

    public string GetDescription() => _coffee.GetDescription() + ", Milk";
    public double GetCost() => _coffee.GetCost() + 10.0; // দাম বাড়ানো হলো
}
```

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি **OCP (Open/Closed Principle)** মেনে চলে। অর্থাৎ, নতুন ফিচার যোগ করার জন্য পুরাতন কোড ভাঙার দরকার নেই। ইনহেরিটেন্স (Inheritance) ব্যবহার করলে অনেক সাব-ক্লাস তৈরি করতে হতো, কিন্তু ডেকোরেটর দিয়ে সহজেই ফিচার মিক্স-এন্ড-ম্যাচ করা যায়।

**সমস্যা (Problems):**
*   অনেকগুলো ছোট ছোট ক্লাস তৈরি হতে পারে।
*   অনেকগুলো ডেকোরেটর একটার ওপর আরেকটা জড়ালে ডিবাগ করা কঠিন হতে পারে।

**সমাধান:**
কোড পরিষ্কার রাখুন এবং **Scrutor**-এর মতো লাইব্রেরি ব্যবহার করুন যা ASP.NET Core-এ ডেকোরেটর রেজিস্টার করা সহজ করে দেয়।

### ২. Composite Design Pattern

**এটি কী:**
Composite প্যাটার্ন আমাদের অবজেক্টগুলোকে একটি **ট্রি (Tree)** বা গাছের মতো স্ট্রাকচারে সাজাতে সাহায্য করে। এই প্যাটার্নে একক অবজেক্ট (Leaf) এবং অবজেক্টের গ্রুপ (Composite)-কে একইভাবে ব্যবহার করা যায়।

**সহজ উদাহরণ (ফাইল সিস্টেম):**
কম্পিউটারে একটি **ফাইল** (যেমন: resume.docx) এবং একটি **ফোল্ডার** (যা অনেকগুলো ফাইল ধারণ করে)—উভয়ের ওপরই আপনি ডাবল ক্লিক করতে পারেন বা ডিলিট করতে পারেন। ফোল্ডার এবং ফাইল উভয়েই "ফাইল সিস্টেম আইটেম" হিসেবে কাজ করে।

**কোড উদাহরণ:**

```csharp
// ১. কম্পোনেন্ট (কমন ইন্টারফেস)
public interface IFileSystemItem
{
    void Display();
}

// ২. লিফ (একক ফাইল)
public class File : IFileSystemItem
{
    public string Name { get; set; }
    public void Display() => Console.WriteLine($"File: {Name}");
}

// ৩. কম্পোজিট (ফোল্ডার - যার ভেতরে আরও আইটেম থাকে)
public class Folder : IFileSystemItem
{
    private List<IFileSystemItem> _items = new List<IFileSystemItem>();

    public void Add(IFileSystemItem item) => _items.Add(item);

    public void Display()
    {
        Console.WriteLine("Folder Contents:");
        foreach (var item in _items)
        {
            item.Display(); // রিকার্সিভলি কল হচ্ছে
        }
    }
}
```

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি ক্লায়েন্টকে (যে কোড ব্যবহার করছে) জানতে দেয় না সে কি একটি সিঙ্গেল অবজেক্ট নিয়ে কাজ করছে নাকি পুরো গ্রুপের সাথে। কোড অনেক সিম্পল হয়ে যায়।

**বাস্তব ব্যবহার:**
গ্রাফিকাল ইউজার ইন্টারফেস (GUI) তৈরিতে, মেনু এবং সাব-মেনু তৈরিতে।

### ৩. Adapter Design Pattern

**এটি কী:**
Adapter প্যাটার্ন দুটি অমিল (Incompatible) ইন্টারফেসের মধ্যে সেতু বন্ধন হিসেবে কাজ করে। এটি এক ফরম্যাটের ডেটাকে অন্য ফরম্যাটে রূপান্তর করে যাতে দুটি ভিন্ন সিস্টেম একে অপরের সাথে কথা বলতে পারে।

**সহজ উদাহরণ (পাওয়ার প্লাগ):**
আপনি ইউরোপে ল্যাপটপ চার্জ দিতে গেছেন, কিন্তু আপনার প্লাগ আমেরিকান। তখন আপনি একটি **অ্যাডাপ্টার** ব্যবহার করেন। ল্যাপটপ বদলান না, আবার দেয়ালের সকেটও বদলান না। মাঝখানে অ্যাডাপ্টার লাগিয়ে কাজ চালান।

**কোড উদাহরণ:**

```csharp
// ১. টার্গেট (আমরা যা চাই)
public interface ILogger
{
    void Log(string message);
}

// ২. এডাপ্টি (থার্ড পার্টি লাইব্রেরি যা আমাদের ইন্টারফেসের সাথে মিলে না)
public class ThirdPartyLogger
{
    public void WriteToCloud(string msg) => Console.WriteLine($"Cloud: {msg}");
}

// ৩. অ্যাডাপ্টার (সেতু)
public class LoggerAdapter : ILogger
{
    private readonly ThirdPartyLogger _thirdPartyLogger;

    public LoggerAdapter(ThirdPartyLogger thirdPartyLogger)
    {
        _thirdPartyLogger = thirdPartyLogger;
    }

    public void Log(string message)
    {
        // আমাদের মেথড কলকে থার্ড পার্টি মেথডে কনভার্ট করা হলো
        _thirdPartyLogger.WriteToCloud(message);
    }
}
```

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি পুরানো সিস্টেম (Legacy Code) বা থার্ড-পার্টি লাইব্রেরির সাথে নতুন কোড ইন্টিগ্রেট করতে সাহায্য করে।

**সমস্যা:**
অতিরিক্ত অ্যাডাপ্টার ব্যবহার করলে কোডের জটিলতা বাড়ে।

### ৪. Façade Design Pattern

**এটি কী:**
Façade (ফাসাদ) মানে হলো "সম্মুখভাগ" বা বাইরের চেহারা। এই প্যাটার্নটি একটি জটিল সাব-সিস্টেমের সামনে একটি সহজ ইন্টারফেস প্রদান করে। এটি ভেতরের জটিলতাকে লুকিয়ে রাখে।

**সহজ উদাহরণ (গাড়ি স্টার্ট দেওয়া):**
গাড়ি স্টার্ট দিতে আপনি শুধু চাবি ঘোরান বা বাটন চাপেন। কিন্তু ভেতরে ফুয়েল ইনজেকশন, ইঞ্জিন ইগনিশন, ব্যাটারি কানেকশন—অনেক কিছু ঘটে। এই "স্টার্ট বাটন" হলো Façade।

**কোড উদাহরণ:**

```csharp
// জটিল সাব-সিস্টেম
public class Inventory { public bool CheckStock() => true; }
public class Payment { public bool ProcessPayment() => true; }
public class Shipping { public void ShipProduct() => Console.WriteLine("Shipped"); }

// Façade (সহজ ইন্টারফেস)
public class OrderFacade
{
    private Inventory _inventory = new();
    private Payment _payment = new();
    private Shipping _shipping = new();

    public void PlaceOrder()
    {
        if (_inventory.CheckStock() && _payment.ProcessPayment())
        {
            _shipping.ShipProduct();
            Console.WriteLine("Order placed successfully!");
        }
    }
}

// ক্লায়েন্ট শুধু এই এক লাইন লিখবে
new OrderFacade().PlaceOrder();
```

**কেন এটি কাজ করে ও কেন জরুরি:**
এটি ক্লায়েন্ট কোডকে সিস্টেমের ভেতরের জটিল লজিক থেকে দূরে রাখে (Loosely Coupled)। ফলে ভেতরের লজিক বদলালেও ক্লায়েন্ট কোডে হাত দিতে হয় না।

**বাস্তব ব্যবহার:**
যেকোনো লাইব্রেরি বা API-এর র‍্যাপার (Wrapper) তৈরিতে এটি ব্যবহৃত হয়।

### অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

১. **Decorator:** ক্লাসের কোড না বদলিয়ে রানটাইমে নতুন ফিচার যোগ করার জন্য ব্যবহৃত হয় (যেমন: Scrutor লাইব্রেরি দিয়ে ASP.NET Core-এ এটি করা সহজ)।
২. **Composite:** একক অবজেক্ট এবং অবজেক্টের গ্রুপকে একইভাবে ট্রি স্ট্রাকচারে ব্যবহার করার জন্য।
৩. **Adapter:** দুটি অমিল ইন্টারফেসের মধ্যে যোগাযোগ স্থাপন করার জন্য (যেমন: থার্ড-পার্টি লাইব্রেরি ইন্টিগ্রেশন)।
৪. **Façade:** একটি জটিল সিস্টেমকে সহজ ইন্টারফেসের মাধ্যমে ব্যবহার করার জন্য।

এই প্যাটার্নগুলো আপনার কোডকে **Flexible (নমনীয়)**, **Reusable (পুনঃব্যবহারযোগ্য)** এবং **Maintainable (রক্ষণাবেক্ষণযোগ্য)** করতে সাহায্য করে।

### ২. Decorator Pattern (Scrutor সহ)

**বিষয়বস্তু:**
Decorator প্যাটার্ন আমাদের কোনো ক্লাসের কোড পরিবর্তন না করেই রানটাইমে তার কার্যক্ষমতা (Functionality) বাড়ানোর সুযোগ দেয়। একে **"Wrapper"**-ও বলা হয়।

**বাস্তব উদাহরণ:**
মনে করুন আপনার একটি `MessageService` আছে যা মেসেজ পাঠায়। আপনি চান মেসেজ পাঠানোর আগে একটি লগ (Log) রাখা হোক। আপনি মূল সার্ভিস ক্লাসে হাত না দিয়ে একটি `LoggingDecorator` দিয়ে সার্ভিসটিকে মুড়িয়ে দেবেন।

**কোড ইমপ্লিমেন্টেশন:**

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

// ১. ইন্টারফেস (Contract)
public interface IMessageService
{
    void Send(string message);
}

// ২. মূল সার্ভিস (Concrete Implementation)
public class EmailService : IMessageService
{
    public void Send(string message)
    {
        Console.WriteLine($"Sending Email: {message}");
    }
}

// ৩. ডেকোরেটর (Decorator)
public class LoggingDecorator : IMessageService
{
    private readonly IMessageService _innerService;

    // মূল সার্ভিসটি কনস্ট্রাক্টরের মাধ্যমে ইনজেক্ট করা হচ্ছে
    public LoggingDecorator(IMessageService innerService)
    {
        _innerService = innerService;
    }

    public void Send(string message)
    {
        // নতুন বিহেভিয়ার যোগ করা হলো
        Console.WriteLine($"[LOG]: Message is about to be sent at {DateTime.Now}");
        
        // মূল কাজ করা হলো
        _innerService.Send(message);
        
        Console.WriteLine("[LOG]: Message sent successfully.");
    }
}

// ৪. সেটআপ (Program.cs) - Scrutor ব্যবহার করে
var host = Host.CreateDefaultBuilder()
    .ConfigureServices(services =>
    {
        // প্রথমে মূল সার্ভিস রেজিস্টার করুন
        services.AddTransient<IMessageService, EmailService>();

        // Scrutor-এর 'Decorate' মেথড ব্যবহার করে ডেকোরেটর যোগ করা
        services.Decorate<IMessageService, LoggingDecorator>();
    })
    .Build();

// রান করা
var service = host.Services.GetRequiredService<IMessageService>();
service.Send("Hello patterns!");
```

**লজিক:**
*   যখন আপনি `IMessageService` চাইবেন, কন্টেইনার আপনাকে `EmailService` সরাসরি না দিয়ে, `LoggingDecorator`-এর ভেতরে মোড়ানো `EmailService` দেবে।
*   `Decorate` মেথডটি Scrutor লাইব্রেরি থেকে এসেছে, যা ম্যানুয়াল রেজিস্ট্রেশনের ঝামেলা কমায়।

### ৩. Composite Pattern

**বিষয়বস্তু:**
যখন আমাদের অবজেক্টগুলোর মধ্যে **Parent-Child** বা **Tree Structure** সম্পর্ক থাকে (যেমন ফোল্ডার এবং ফাইল), তখন আমরা Composite প্যাটার্ন ব্যবহার করি। এটি আমাদের সিঙ্গেল অবজেক্ট এবং অবজেক্টের গ্রুপকে একইভাবে ট্রিট করতে দেয়।

**কোড উদাহরণ (গিফট বক্স):**
একটি গিফট বক্সে একটি প্রোডাক্ট থাকতে পারে, অথবা আরেকটি ছোট গিফট বক্স থাকতে পারে।

```csharp
// ১. কম্পোনেন্ট
public interface IGift
{
    int CalculatePrice();
}

// ২. লিফ (Leaf) - সিঙ্গেল প্রোডাক্ট
public class Phone : IGift
{
    public int CalculatePrice() => 50000;
}

public class EarBuds : IGift
{
    public int CalculatePrice() => 5000;
}

// ৩. কম্পোজিট (Composite) - বক্স
public class GiftBox : IGift
{
    private readonly List<IGift> _gifts = new();

    public void AddGift(IGift gift) => _gifts.Add(gift);

    public int CalculatePrice()
    {
        int total = 0;
        Console.WriteLine("Opening a box...");
        foreach (var gift in _gifts)
        {
            total += gift.CalculatePrice();
        }
        return total;
    }
}

// ব্যবহার
var phone = new Phone();
var buds = new EarBuds();

var smallBox = new GiftBox();
smallBox.AddGift(buds); // ছোট বক্সে ইয়ারবাড

var bigBox = new GiftBox();
bigBox.AddGift(phone);    // বড় বক্সে ফোন
bigBox.AddGift(smallBox); // এবং ছোট বক্সটি

Console.WriteLine($"Total Price: {bigBox.CalculatePrice()}");
```

**লজিক:**
`GiftBox` নিজেই `IGift` ইমপ্লিমেন্ট করে এবং তার ভেতরে `IGift` এর একটি লিস্ট রাখে। ফলে বক্সের ভেতরে বক্স রাখলেও কোড একই থাকে।

### ৪. Adapter Pattern

**বিষয়বস্তু:**
যখন দুটি ইন্টারফেস একে অপরের সাথে মেলে না, তখন তাদের কানেক্ট করার জন্য অ্যাডাপ্টার ব্যবহার করা হয়। এটি সাধারণত **Third-party Library** ইন্টিগ্রেশনে লাগে।

**কোড উদাহরণ:**
ধরুন আপনার অ্যাপ `IXmlLogger` সাপোর্ট করে, কিন্তু আপনি একটি থার্ড-পার্টি `JsonLogger` ব্যবহার করতে চান।

```csharp
// ১. আপনার অ্যাপের ইন্টারফেস (Target)
public interface IXmlLogger
{
    void LogXml(string xmlData);
}

// ২. থার্ড-পার্টি লাইব্রেরি (Adaptee) - যা আপনি বদলাতে পারবেন না
public class JsonLogger
{
    public void LogJson(string jsonData) 
    {
        Console.WriteLine($"Logging JSON: {jsonData}");
    }
}

// ৩. অ্যাডাপ্টার (Adapter)
public class JsonToXmlAdapter : IXmlLogger
{
    private readonly JsonLogger _jsonLogger;

    public JsonToXmlAdapter(JsonLogger jsonLogger)
    {
        _jsonLogger = jsonLogger;
    }

    public void LogXml(string xmlData)
    {
        // XML কে JSON এ কনভার্ট করার সিমুলেশন
        string convertedJson = $"{{ \"data\": \"{xmlData}\" }}";
        
        // থার্ড-পার্টি মেথড কল করা
        _jsonLogger.LogJson(convertedJson);
    }
}
```

### ৫. Façade Pattern

**বিষয়বস্তু:**
একটি জটিল সিস্টেমের সামনে একটি সহজ ইন্টারফেস দাঁড় করানো। এটি সিস্টেমের জটিলতা লুকিয়ে রাখে।

**কোড উদাহরণ (অনলাইন অর্ডার):**
অর্ডার করতে গেলে ইনভেন্টরি চেক, পেমেন্ট প্রসেস এবং শিপিং—অনেক কাজ করতে হয়।

```csharp
// জটিল সাব-সিস্টেম
public class InventorySystem { public bool Check(string id) => true; }
public class PaymentSystem { public bool Charge(string id) => true; }
public class ShippingSystem { public void Ship(string id) => Console.WriteLine("Shipped!"); }

// Façade (সহজ ইন্টারফেস)
public class OrderFacade
{
    private InventorySystem _inventory = new();
    private PaymentSystem _payment = new();
    private ShippingSystem _shipping = new();

    public void PlaceOrder(string productId)
    {
        if (_inventory.Check(productId) && _payment.Charge(productId))
        {
            _shipping.Ship(productId);
            Console.WriteLine("Order process complete successfully.");
        }
    }
}

// ব্যবহার
var facade = new OrderFacade();
facade.PlaceOrder("Product-101"); // ক্লায়েন্টকে ভেতরের জটিলতা জানতে হলো না
```

### ৬. সাধারণ সমস্যা এবং সমাধান

**সমস্যা ১: Decorator Hell**
*   *বিবরণ:* যদি অনেকগুলো ডেকোরেটর একটার ওপর একটা র‍্যাপ করেন, তবে কোড ডিবাগ করা কঠিন হয়ে যায়।
*   *সমাধান:* ডেকোরেটরের সংখ্যা সীমিত রাখুন এবং **Scrutor** লাইব্রেরি ব্যবহার করুন যাতে `Program.cs` ক্লিন থাকে।

**সমস্যা ২: God Façade**
*   *বিবরণ:* অনেকে পুরো অ্যাপ্লিকেশনের জন্য একটিই ফাসাদ ক্লাস তৈরি করেন, যা বিশাল বড় হয়ে যায় (God Class)।
*   *সমাধান:* প্রতিটি মডিউল বা ফিচারের জন্য আলাদা ছোট ছোট ফাসাদ তৈরি করুন।

### ৭. অধ্যায়ের সারসংক্ষেপ (Summary of Key Points)

এই অধ্যায়ে আমরা শিখলাম কিভাবে ক্লাসগুলোকে সাজিয়ে (Structure) শক্তিশালী আর্কিটেকচার তৈরি করা যায়:

১. **Decorator:** মূল কোড না ছুঁয়ে নতুন ফিচার যোগ করা (যেমন: লগিং, ক্যাশিং)। ASP.NET Core-এ এটি **Scrutor** দিয়ে খুব সহজে করা যায়।
২. **Composite:** ট্রি স্ট্রাকচার বা হায়ারার্কিকাল ডেটা হ্যান্ডেল করার জন্য সেরা।
৩. **Adapter:** দুটি ভিন্ন বা অমিল ইন্টারফেসের মধ্যে সংযোগকারী সেতু।
৪. **Façade:** জটিল সিস্টেমকে সহজ করার জন্য একটি সিম্পল এন্ট্রি পয়েন্ট।

এই প্যাটার্নগুলো আপনার কোডকে **Reusable (পুনঃব্যবহারযোগ্য)** এবং **Maintainable (রক্ষণাবেক্ষণযোগ্য)** করে তোলে, যা বড় প্রজেক্টের জন্য অপরিহার্য।
