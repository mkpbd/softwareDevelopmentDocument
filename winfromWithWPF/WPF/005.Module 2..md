### **Module 2: The Core Concepts - The "WPF Way"**

**Goal:** Refactor our "Hello WPF" application to use the **MVVM (Model-View-ViewModel)** pattern and **Data Binding**. This will separate our UI from our logic, making our code cleaner, more testable, and easier to manage.

#### **The Problem with Code-Behind**

In Module 1, we wrote this in our `MainWindow.xaml.cs`:

```csharp
// This creates a TIGHT COUPLING between the View and the Code-Behind.
private void MyButton_Click(object sender, RoutedEventArgs e)
{
    // Our code directly knows about and manipulates a UI control named "GreetingText".
    GreetingText.Text = "Welcome to your first WPF App!";
}
```

What's wrong with this?
*   **It's fragile:** If a designer renames `GreetingText` in the XAML, the C# code breaks.
*   **It's hard to test:** How can you write an automated test for this logic without actually creating and clicking a button in a real window? You can't.
*   **It mixes concerns:** The code for *what* the application does is mixed up with the code for *how* it looks.

#### **The Solution: The MVVM Pattern**

MVVM is a design pattern that solves these problems by splitting our application into three distinct parts:

1.  **Model:** The raw data. Simple C# classes that represent the "things" in your application (e.g., a `User`, a `Product`, an `Order`). It knows nothing about the UI.
2.  **View:** The XAML (`.xaml` file). Its job is to *look* pretty and display data. It should contain almost **no logic**. It simply binds to the ViewModel.
3.  **ViewModel:** The "brain" of the View. It's a C# class that prepares data from the Model and exposes it as properties for the View to bind to. It also contains the logic (like what happens when a button is clicked). The ViewModel knows nothing about specific UI controls like `TextBlock` or `Button`.

**The glue that connects the View and the ViewModel is Data Binding.**

---

### **Let's Refactor Our App to MVVM**

We're going to change our "Hello WPF" app to use this new pattern.

#### **Step 1: Create the ViewModel**

1.  In the Solution Explorer, right-click on your project (`HelloWpfApp`).
2.  Select **Add > Class...**.
3.  Name the new class `MainViewModel.cs` and click **Add**.

Now, we need to make this class capable of notifying the UI when its data changes. To do this, it must implement the `INotifyPropertyChanged` interface.

Replace the contents of `MainViewModel.cs` with this code:

```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HelloWpfApp
{
    public class MainViewModel : INotifyPropertyChanged
    {
        // 1. The private backing field for our property.
        private string _greetingText;

        // 2. The public property that the UI will bind to.
        public string GreetingText
        {
            get { return _greetingText; }
            set
            {
                _greetingText = value;
                OnPropertyChanged(); // 3. Notify the UI that this property has changed!
            }
        }

        // Constructor
        public MainViewModel()
        {
            // Set the initial value.
            GreetingText = "Hello, from the ViewModel!";
        }

        // --- INotifyPropertyChanged Implementation ---
        public event PropertyChangedEventHandler? PropertyChanged;

        protected void OnPropertyChanged([CallerMemberName] string? propertyName = null)
        {
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
        }
        // You will reuse this exact implementation in almost every ViewModel you ever make.
    }
}
```

**What did we just do?**
*   We created a property `GreetingText`. This will hold the string for our UI.
*   We implemented `INotifyPropertyChanged`. The `OnPropertyChanged()` method is the magic part.
*   Whenever the `GreetingText` property is changed (in the `set` block), it calls `OnPropertyChanged()`. This sends a message to the UI saying, "Hey! The `GreetingText` property was just updated. You should re-read its value."

#### **Step 2: Connect the View to the ViewModel**

How does `MainWindow.xaml` know that it should get its data from `MainViewModel`? We set its `DataContext`.

1.  Open `MainWindow.xaml.cs` (the code-behind).
2.  In the constructor, right after `InitializeComponent();`, add the following line:

```csharp
public MainWindow()
{
    InitializeComponent();
    this.DataContext = new MainViewModel(); // <-- ADD THIS LINE
}
```
This creates a new instance of our ViewModel and sets it as the data source for the entire `MainWindow` and all of its children.

#### **Step 3: Update the XAML to Use Data Binding**

Now we can change our XAML to listen to the ViewModel instead of having hard-coded values.

1.  Open `MainWindow.xaml`.
2.  Find the `<TextBlock>`.
3.  **Remove** the `x:Name="GreetingText"` property. We don't need it anymore because we won't be touching this control from the code-behind.
4.  **Change** the `Text` property to use a Binding.

The new `TextBlock` should look like this:

```xaml
<!-- The Text is now BOUND to the GreetingText property on our DataContext (the MainViewModel) -->
<TextBlock Grid.Row="0"
           Text="{Binding GreetingText}"
           FontSize="24"
           HorizontalAlignment="Center"
           Margin="20" />
```
The `{Binding GreetingText}` syntax tells WPF: "Find a public property named `GreetingText` on the current `DataContext` and display its value here. Also, listen for `PropertyChanged` notifications for this property and update automatically if it changes."

#### **Step 4: Move the Button Logic to the ViewModel**

Our final step is to move the button's action from the code-behind into the ViewModel.

1.  First, add a method to `MainViewModel.cs` that contains the logic:

    ```csharp
    // In MainViewModel.cs
    public void ChangeGreeting()
    {
        GreetingText = "The ViewModel changed the text!";
    }
    ```

2.  Now, go back to `MainWindow.xaml.cs`. Change the `MyButton_Click` event handler to call this new method on the ViewModel.

    ```csharp
    // In MainWindow.xaml.cs
    private void MyButton_Click(object sender, RoutedEventArgs e)
    {
        // Get the ViewModel from the DataContext and call its method.
        var viewModel = (MainViewModel)this.DataContext;
        viewModel.ChangeGreeting();
    }
    ```
    Notice we are no longer directly touching `GreetingText.Text`. We are telling the ViewModel to perform an action, and the ViewModel changes its own data. Data Binding takes care of updating the UI automatically.

**Run the application (F5).**

It will look the same, but the internal wiring is now completely different and vastly superior.

*   The initial text "Hello, from the ViewModel!" is displayed.
*   When you click the button, the `Click` event fires, calls the `ChangeGreeting` method on the ViewModel, which updates the `GreetingText` property.
*   The `OnPropertyChanged` notification fires, and the `TextBlock` in the UI updates automatically.

---

### **Summary of Benefits**

You have now successfully separated your application's concerns:

*   **View (`MainWindow.xaml`):** Knows only how to display data.
*   **ViewModel (`MainViewModel.cs`):** Contains the application state (`GreetingText`) and logic (`ChangeGreeting`). It knows nothing about `TextBlock`s.
*   **Code-Behind (`MainWindow.xaml.cs`):** Is now almost empty! Its only job is to wire things together. (Later, we will learn about **Commands** to remove even this last bit of code).

This is the foundation of modern WPF development.
